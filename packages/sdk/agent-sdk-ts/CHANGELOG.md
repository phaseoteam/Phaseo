# @phaseo/agent-sdk

## 0.4.0

### Minor Changes

- [#3286](https://github.com/phaseoteam/Phaseo/pull/3286) [`4d14671`](https://github.com/phaseoteam/Phaseo/commit/4d1467182e68d4b4a4a96fa21323004ebdb9fcb2) Thanks [@DanielButler1](https://github.com/DanielButler1)! - Keep agent runs usable after failures:
  - With `onError: "return-to-model"`, unknown tools, unreadable tool arguments (`AgentToolCall.inputError`) and invalid inputs come back to the model as error results.
  - Continuing a run answers any tool call a failure left without a result (`history.repaired` event, `repairToolHistory`).
  - `maxSteps` counts the steps of each run or continue call, so a run that used its budget can be continued.
  
  Model retries now back off exponentially with full jitter and honour `Retry-After`. Only retryable errors are retried (`agentErrorIsRetryable`, or `modelRetry.retryOn`), and never after output has streamed. A `model.retrying` event reports each wait.
  
  The gateway client treats these as failures (`AgentStreamError`), not completed answers:
  - error events;
  - failed, incomplete and cancelled responses;
  - connections dropped partway through;
  - streams that end without completing.
  
  `streamIdleTimeoutMs` abandons a stream that goes quiet.
  
  New options:
  - `toolExecution.maxOutputChars` keeps the start and end of long tool output.
  - `activeTools` offers a subset of the registered tools.
  - `prepareMessages` can compact the history before each request, and once after a context-overflow error (`agentErrorIsContextOverflow`).
  - `takeMessages` adds steering messages at the next step.
  - `parallelSafe` tools run side by side.
  
  Tool output that isn't a string is now sent as compact JSON.

- [#3286](https://github.com/phaseoteam/Phaseo/pull/3286) [`4d14671`](https://github.com/phaseoteam/Phaseo/commit/4d1467182e68d4b4a4a96fa21323004ebdb9fcb2) Thanks [@DanielButler1](https://github.com/DanielButler1)! - Support structured initial and continuation conversation messages and user text/image parts. Preserve cloned message history through run checkpoints, append follow-up messages after pending tool results, and map image parts to Responses input instead of coercing them to text.

### Patch Changes

- [#3286](https://github.com/phaseoteam/Phaseo/pull/3286) [`4d14671`](https://github.com/phaseoteam/Phaseo/commit/4d1467182e68d4b4a4a96fa21323004ebdb9fcb2) Thanks [@DanielButler1](https://github.com/DanielButler1)! - Tools that run side by side no longer lose each other's context changes: a tool that leaves the context alone keeps the change another tool in the same batch made.

- [#3286](https://github.com/phaseoteam/Phaseo/pull/3286) [`4d14671`](https://github.com/phaseoteam/Phaseo/commit/4d1467182e68d4b4a4a96fa21323004ebdb9fcb2) Thanks [@DanielButler1](https://github.com/DanielButler1)! - Read each step's cost from the Phaseo gateway's price in usage (`pricing` on Chat Completions, `pricing_breakdown` on Responses), so streamed runs report their cost and `maxCost` stop conditions see it.

- [#3108](https://github.com/phaseoteam/Phaseo/pull/3108) [`5865e00`](https://github.com/phaseoteam/Phaseo/commit/5865e001bf6beba88b95016614c293a27f27ba58) Thanks [@DanielButler1](https://github.com/DanielButler1)! - Run the Agent SDK and the core SDK in Cloudflare Workers and other runtimes without Node globals: devtools load Node modules only when enabled, `process` reads and exit handlers are guarded, and run IDs come from Web Crypto. Agent runs also treat gateway server-tool calls such as `phaseo:web_search` as already handled, keeping their calls and results in items and stream events instead of failing with "Tool not found".
  
  Streamed answers now contain only text and reasoning deltas. Tool-call argument deltas and the full text that `.done` events repeat no longer leak into them, and streamed items are taken from their done event, not the still-empty added one.
  
  String `instructions` now reach the gateway once per request. Before, the gateway client sent them twice in the `instructions` field, because the run also keeps them as its first system message.
  
  Gateway HTTP failures of a streamed turn are now `AgentGatewayError`s with their request ID and diagnostics, like non-streamed ones. Before, `@phaseo/sdk`'s own error came through unwrapped, because the SDK sends a streamed request on the first read rather than in `create()`.
  
  A failed `agent.stream()` no longer leaves an unhandled promise rejection when the caller reads only a stream and never awaits the result. A resume that is missing a decision now fails before it runs any of the approved tools.
  
  `@phaseo/sdk` has a new `modelLifecycleChecks` option (default `true`). Set it to `false` to skip the `GET /models` lookup before a model's first request. Concurrent first requests for a model now share one lookup. The Agent SDK's gateway client turns the lookup off unless `clientOptions.modelLifecycleChecks` is `true`, so each new client no longer sends an extra `GET /models`. Retired models are still refused, by the gateway, with an `AgentGatewayError`.
  
  A stream that reports an error after it started (the gateway's `error` frame, a Responses `error` event or `response.failed`) now fails the run with a 502 `AgentGatewayError`, instead of completing with partial text.
