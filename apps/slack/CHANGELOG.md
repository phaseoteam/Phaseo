# @phaseo/slack-agent

## 0.1.0

### Minor Changes

- [#3284](https://github.com/phaseoteam/Phaseo/pull/3284) [`8d30037`](https://github.com/phaseoteam/Phaseo/commit/8d30037916b869d19b2a5486eec026b2c394f23d) Thanks [@DanielButler1](https://github.com/DanielButler1)! - The Slack agent can ask another of the models allowed under **Model choice** for a second opinion while it answers (`ask_model`, up to 3 times an answer), and a message that starts with `compare <model>, <model>[, <model>]: <question>` is answered by each of those 2 or 3 models at once, in one reply with a section per model and its cost. Both count toward the answer's $0.50 limit (a compared model's share only decides whether it's asked), a comparison counts as one answer, and the footer names every model used. Names that can't be compared get the same private reply as `with <model>:`, before anything is counted. Settings → Slack mentions both under **Model choice**.

- [#3285](https://github.com/phaseoteam/Phaseo/pull/3285) [`bd3f8b0`](https://github.com/phaseoteam/Phaseo/commit/bd3f8b05967eb5bf8da30d7cc2596fb913902192) Thanks [@DanielButler1](https://github.com/DanielButler1)! - The Slack agent can post charts and images in the thread, and read images and PDFs shared with it. `make_chart` draws a bar, line or pie chart from a small spec and uploads it as a PNG; `generate_image` makes an image with GPT Image 2 through the installation's key, its cost counted in the answer's $0.50 limit and footer. Images (up to 5 MB) and PDFs (up to 10 MB) shared with the message or earlier in the thread are downloaded for the answer and sent to the model when it reads them, and never stored. The app asks for the new `files:read` and `files:write` scopes; `slack_installations.bot_scopes` records what Slack granted, each feature checks it, and Settings → Slack offers **Update Slack permissions**, which reruns the install for the same installation and keeps its key, settings and data. The Slack agent guide describes it in every language.

- [#3282](https://github.com/phaseoteam/Phaseo/pull/3282) [`25514a8`](https://github.com/phaseoteam/Phaseo/commit/25514a8eb93da56c06b6f55da0d617230c7d72a6) Thanks [@DanielButler1](https://github.com/DanielButler1)! - The Slack agent can ask the person a question with buttons when it needs a choice or an approval: a short question and 2 to 5 options, optionally with Other for an answer in their own words. Only the person it's answering can answer (others get a private note), and a reply in the thread also counts. The answer pauses, waits up to an hour in a Cloudflare Workflow, and continues from where it stopped; it stays one answer, and the 12-step and $0.50 limits span the whole of it. Slack's stop button still works while it waits. The app also gets a Home tab showing how to use the agent, its model, whether the person's Phaseo account is connected (with the Connect button) and, for linked members, this month's answers. The manifest adds `app_home_opened` and turns on the Home tab, and the Slack agent guide describes both in every language.

- [#3279](https://github.com/phaseoteam/Phaseo/pull/3279) [`09339e7`](https://github.com/phaseoteam/Phaseo/commit/09339e749a95bfe41a3485f61a7667f297b9cf56) Thanks [@DanielButler1](https://github.com/DanielButler1)! - The Slack agent can answer a message with a model the person chooses: admins turn on **Model choice** in Settings → Slack and allow up to 10 catalogue models (and Auto, with Auto Routing), and a message that starts with `with <model>:` is answered by that model. A model that isn't allowed gets a private reply listing the choices, and isn't counted. The reply footer now links each model's name to its Phaseo page and the cost to that answer's requests in Logs.

- [#3292](https://github.com/phaseoteam/Phaseo/pull/3292) [`eed8c67`](https://github.com/phaseoteam/Phaseo/commit/eed8c6705edb05cb85a2fc2c1045fed79e1a316f) Thanks [@DanielButler1](https://github.com/DanielButler1)! - The Slack agent can search Slack for the person asking. `search_slack` uses Slack's real-time search with the action token Slack sends with the message, so it finds only what that person can see, in public channels (and files shared there), and the model links every message it uses. It is offered where `slack_installations.search_mode` allows it (direct messages only by default, or channels too, or off, under **Slack search** in Settings → Slack), to members of the organisation who aren't guests, once Slack has granted the new `search:read.public` and `search:read.files` scopes (**Update Slack permissions**). Results are never stored: working memory keeps the query and count, an answer that has searched asks no questions and saves no notes or skills (so nothing the model writes after a search is kept), each answer makes at most 4 searches across its runs and retries, and the action token is dropped with the turn. Slack allows this API only for apps in its directory and for a company's own apps, so the hosted app can search once its Slack Marketplace listing is approved. The Slack agent guide describes it in every language.

- [#3293](https://github.com/phaseoteam/Phaseo/pull/3293) [`47ebdbb`](https://github.com/phaseoteam/Phaseo/commit/47ebdbbed6c0c85d95992498d83f5201c0f92c07) Thanks [@DanielButler1](https://github.com/DanielButler1)! - The Slack agent can publish a static web page (a report, a table or a chart, in HTML and CSS with inline SVG) with `publish_page` and link it in its reply. Scripts, links, forms and anything loaded from elsewhere are taken out before a page is kept, and again before it is shown, so a page can't run scripts or send anything anywhere. An answer that has searched Slack publishes no page. Pages are served from `slack.phaseo.app/p/…` in a sandboxed frame that runs no scripts and can't load anything or navigate away, open to anyone with the link or, where Sign in with Slack is set up for the app, only to members of the Slack workspace (checked again every 10 minutes while a sign-in lasts). They are kept 7, 30 (default) or 90 days and deleted at expiry and on uninstall; each answer can publish 3 and each installation keeps 200, at no extra charge. People from other organisations can't publish. Settings → Slack has a **Shared pages** section: turn pages off, choose how long new ones are kept and who can view them, and open or delete published pages.

- [#3135](https://github.com/phaseoteam/Phaseo/pull/3135) [`891f5f1`](https://github.com/phaseoteam/Phaseo/commit/891f5f10d2d752a84a047f18c3627a2c6a8895fd) Thanks [@DanielButler1](https://github.com/DanielButler1)! - The Slack agent now answers. Each turn runs as a Cloudflare Workflow. It streams the answer into the Slack thread through the gateway, with the installation's managed key, model and instructions, and adds a footer with the model and the turn's cost. Every request asks for providers that don't keep or train on data, and is labelled `app=slack-agent`. Retried steps update the same Slack message instead of posting again, and a failed Slack write is retried on its own without running the model again; a retried answer counts every attempt's cost against the per-turn limit and in the footer. Stop and Cancel end a turn between steps. Out-of-credits, spending-limit and unavailable-model errors become plain replies. Linked workspace members can ask about the workspace's spend, credit balance, key usage and models in direct messages, or in channels the admins allow. Two new database functions add the spend up per day, week or month and per API key.

- [#3134](https://github.com/phaseoteam/Phaseo/pull/3134) [`ccf8394`](https://github.com/phaseoteam/Phaseo/commit/ccf83948d9a0627a81cbe6c0b40e7a08ffc13d5d) Thanks [@DanielButler1](https://github.com/DanielButler1)! - Add the Slack agent's Cloudflare Worker (`apps/slack`). It verifies and acknowledges Slack events and button clicks for the hosted app and for a company's own app, ignores bots, and dedupes Slack's retries. A meter per installation decides who gets an answer under the installation's limits and counts each month's people and answers for billing. A coordinator per Slack thread runs one turn at a time and deletes its working memory after 7 days. Unlinked people get a Connect account button when the installation requires linked accounts. Removing the app inside Slack uninstalls it in Phaseo: its gateway key is deleted, its guardrail removed and the change recorded in the audit log. Turns are acknowledged but not answered yet. The Slack secrets format now comes from one shared module used by web-api and the Worker.

### Patch Changes

- [#3320](https://github.com/phaseoteam/Phaseo/pull/3320) [`dc67a8f`](https://github.com/phaseoteam/Phaseo/commit/dc67a8f95c1f8ff1cc2423bf0d77a2b0251b77c8) Thanks [@DanielButler1](https://github.com/DanielButler1)! - The Slack agent can search Slack with Auto. After a search, Auto requests carry `require_zero_data_retention` like any other, and the gateway's auto router then picks only among models with a provider that keeps no data (its classifier request carries the flag too). `ask_model` can ask Auto after a search. When zero data retention is what leaves Auto no model, the gateway refuses with `model_region_unavailable` and `unmet_requirements.zero_data_retention`, and the answer ends with the usual "no provider that keeps no data" message; other refusals get their usual message.

- [#3176](https://github.com/phaseoteam/Phaseo/pull/3176) [`043d3eb`](https://github.com/phaseoteam/Phaseo/commit/043d3ebaf1d16c8fcff3dbe3911fbc1842eb4bfa) Thanks [@DanielButler1](https://github.com/DanielButler1)! - The Slack agent no longer takes other bots' and apps' messages in a thread for its own. Only its installation's bot user, or its own Slack app, is "You" in the prompt; other bots and apps are shown as "Another app", with their name when Slack gives one. When Slack answers a thread read with 429, the installation's meter keeps the `Retry-After`, and every thread in that installation skips its read and works from its working memory until it has passed, instead of asking Slack again.

- [#3290](https://github.com/phaseoteam/Phaseo/pull/3290) [`88c73db`](https://github.com/phaseoteam/Phaseo/commit/88c73db6cd0820e98db17a6f48d640531cc12c3b) Thanks [@DanielButler1](https://github.com/DanielButler1)! - The Slack agent runs recurring tasks. People ask it to do something hourly, daily, on weekdays, weekly or monthly at a local time in their Slack time zone, and it saves a self-contained prompt for that conversation with `schedule_task`, confirming the next run; `list_schedules` and `cancel_schedule` list and cancel them. Each run posts a short "Scheduled: …" message and answers in its thread as a normal answer from the person who set it up: the same access checks, one answer in the meter, the $0.50 and 12-step limits and the usual footer.   A run is skipped and its schedule paused when the creator can no longer use the agent, the agent is paused, or it can't post in the conversation; after 3 failures in a row the schedule pauses and the creator is told privately. Owners and admins turn recurring tasks on or off, set the most per workspace (20 by default) and who can set them up under **Recurring tasks** in Settings → Slack, where they also see every schedule and pause, resume or delete it. A model that `ask_model` can't use after a search returns a tool error that says why. The Slack agent guide explains this in all nine languages.
