今天，我们推出 **Phaseo CLI**：一种通过终端使用 Phaseo 的新方式。

CLI 将开发者最常用的工具——身份验证、API 密钥、额度、模型、工作区控制和请求日志——放在工作正在发生的地方。无论是本地终端、远程 shell，还是智能体工作流，它都能胜任。

我们的目标很简单：大幅缩短从想法到可运行、可观测的 AI 应用之间的距离。

## 从登录到发送第一个请求

开始使用新的 AI 网关，通常需要在文档、控制台、环境变量和终端之间来回切换，才能发送第一个请求。现在，Phaseo 将这些设置整合为一个连贯流程。

安装 CLI，使用 Phaseo 账户登录，然后创建密钥：

<CliInstallTabs packageName="@phaseo/cli" />

```bash
phaseo login
phaseo keys create --name "My first Phaseo key"
```

在笔记本电脑上，`phaseo login` 会打开浏览器。在 SSH 会话、远程环境和其他无头工作流中，设备代码登录无需本地回调，也能提供相同的体验。

```bash
phaseo login --device-code
```

接下来，CLI 可以显示当前工作区、额度余额、可用模型、提供商、定价、预设和防护规则。你还可以管理 API 密钥和工作区设置，无需中断工作去打开控制台。

这个初始流程体现了我们希望 CLI 带给用户的感受：直接、易于探索，而且实用；开发者无需先弄清每个 API 端点的形式。命令自带帮助；交互使用时输出便于阅读，需要传给其他工具时则可输出 JSON。

## 一个界面连接整个 Phaseo 平台

首个版本涵盖的远不止身份验证。它将多种 Phaseo 工作流整合到一个命令行界面中：

- 创建、查看、更新、停用和删除 API 密钥
- 创建具有明确权限、供可信自动化使用的管理密钥
- 列出工作区、查看成员并管理工作区成员资格
- 查看和配置预设、设置及防护规则
- 浏览模型、提供商和定价
- 查看额度、活动、分析数据和生成记录
- 检查网关请求，并按 ID 获取单个请求
- 尚无专用命令时，直接调用经过身份验证的 Phaseo API 端点

CLI 已经可以支持项目从初始设置走到日常运维。开发者可以在同一个终端会话中完成身份验证、创建受限密钥、确认账户额度、选择模型并检查生成的流量。

对团队而言，它也提供了一套一致的运维界面。本地开发中使用的命令可以延伸到脚本、运行手册、远程环境和经过审慎授权的自动化流程，无需依赖控制台操作。

## 为人和智能体打造

开发者和编程智能体越来越多地通过终端了解项目。为他们提供 Phaseo 的官方入口后，他们就不只是生成集成代码，还能确认当前工作区、创建合适的密钥、检查可用额度，并调查请求运行后发生了什么。

大多数命令都支持结构化 JSON 输出，因此同一套界面既适合在命令行中工作的用户，也适合执行任务的智能体：

```bash
phaseo whoami --json
phaseo credits get --json
phaseo models list --limit 20 --json
```

这也为 Phaseo CLI 技能奠定了基础，让兼容的智能体能够在项目中安全、一致地使用这些工作流。

这一区别很重要。智能体不应该猜测某项设置在哪个控制台页面，也不应该抓取用户界面，或要求开发者在工具之间复制信息。通过经过身份验证且结构化的 CLI，它可以检查获准查看的状态，并通过开发者使用的同一套受支持界面执行明确操作。

我们正在与产品同步开发 CLI 技能，让智能体了解可用命令、优先使用机器可读输出、避免暴露新建的密钥，并在需要诊断集成问题时按需获取单个请求的信息。

## 了解每一个请求

AI 开发并不会在请求成功时结束。开发者还需要了解请求由哪个模型和提供商处理、耗时多久、花费多少，以及失败的原因。

Phaseo CLI 可直接在终端提供这些上下文。你可以筛选最近的请求，找到需要关注的记录，再详细查看单个请求：

```bash
phaseo logs list --since 1h --status error --json
phaseo logs get <request-id> --json
```

请求详情包含调查路由、状态、延迟、模型、提供商和成本所需的运行信息。开发者和智能体因此可以在同一处更快地形成反馈循环：构建、运行、检查并改进。

我们首先支持筛选请求列表和查询单个请求。实时追踪功能将在之后推出。

随着时间推移，我们希望 CLI 成为 Phaseo 的完整可观测性助手。这包括更丰富的筛选条件、更方便地在相关请求和生成记录之间切换、更清晰的成本与延迟摘要，以及在开发或调试应用时跟踪流量的实时工作流。

我们的原则始终不变：提供解决问题所需的运行上下文，同时避免在通用 CLI 输出中泄露敏感应用数据。

## 我们的方向：与 API 和控制台保持功能一致

这次发布是 CLI 的起点，而不是它的边界。

我们的长期目标是，让 API 或控制台中提供的每一项重要 Phaseo 工作流，都能通过设计良好的 CLI 路径完成。如果某项操作可以在 Phaseo 中执行，开发者就应该能在终端中发现它、运行它并将其自动化。

我们计划将 CLI 扩展到整个平台，包括：

- 更全面的工作区、成员和访问权限管理
- 完整的 API 密钥和管理密钥生命周期控制
- 完整的预设、路由、提供商和防护规则配置
- 更丰富的用量、支出、额度和性能报告
- 更全面的生成和请求可观测性
- 可导出的诊断信息，让支持和事故调查更迅速
- 为 CI、部署系统和智能体改进非交互式工作流
- Phaseo 新功能发布时提供对应的一流命令

功能一致不意味着机械地暴露一长串 API 路由。CLI 应让常见任务比手动拼装原始请求更简单。我们会继续添加目标明确的命令，提供实用的默认值、清晰的帮助、可预测的错误和稳定的 JSON 输出。

在专用命令推出之前，经过身份验证的 `phaseo api` 命令可作为调用受支持 API 端点的备用方式。高级用户可以继续通过 CLI 工作，同时等待更高层级的命令逐步完善。

控制台仍将是交互式探索数据和配置 Phaseo 的最佳可视化界面。CLI 将成为它的运维搭档：调用迅速、便于自动化，并且只要能运行 shell，就可以使用。

## 默认安全

CLI 使用我们正在 Phaseo 内构建的同一套 OAuth 基础设施，支持安全的浏览器登录、设备授权、短期访问令牌和轮换刷新令牌。系统支持时，会将会话存储在操作系统的安全凭据库中；退出登录会撤销已存储的会话。

访问权限会实时遵循工作区成员关系。如果用户被移出某个工作区，其 CLI 会话便无法再读取或更改该工作区的信息。

请求检查有意只展示元数据。CLI 日志命令不会公开提示词、请求正文、标头、追踪数据或终端用户标识符。

管理密钥使用明确权限，确保自动化只获得所需访问权。常规网关密钥仍受工作区策略、路由配置、限制和防护规则约束。新创建的密钥只显示一次，应保存在密钥管理器中，而不应提交到代码仓库或写入日志。

随着 CLI 逐步扩展到更多功能，这些边界仍然重要。新命令会继承 API 和控制台相同的工作区授权模型，而不会建立一个权限更高的独立控制通道。

## 今日即可使用

Phaseo CLI 现已推出。默认情况下，它连接到 `https://api.phaseo.app`；也可通过 `PHASEO_API_URL` 将其指向本地或预览部署。

用户创建的 OAuth 应用仍处于私有测试阶段。本次发布专注于为开发者、团队和智能体打造可靠的第一方 CLI 体验。

为 CLI 提供支持的共享 OAuth 功能，最终用途将不止于我们的终端体验。我们计划以此为基础，支持经过批准的第三方应用，让它们可以申请明确的权限、获得用户同意，并遵循同一套面向工作区的授权模型。在通过第一方 CLI 验证这些控制措施期间，OAuth 应用创建功能仍保持私有。

安装后，CLI 会在有更新时通知你。你也可以随时手动更新：

终端应该成为使用 Phaseo 的一等方式。本次发布奠定了基础：安全登录、丰富实用的命令、面向智能体和自动化的结构化输出，以及贴近源代码的请求上下文。
