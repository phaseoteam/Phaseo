本日、ターミナルから Phaseo を使う新しい方法として **Phaseo CLI** を提供開始します。

CLI を使うと、認証、API キー、クレジット、モデル、ワークスペースの管理、リクエストログなど、開発者がよく使うツールを作業中の場所から利用できます。ローカルターミナル、リモートシェル、エージェントのワークフローのどれでも活躍します。

目指しているのはシンプルです。アイデアから、実行できて状況も把握できる AI アプリケーションまでの道のりを短くします。

## サインインから最初のリクエストまで

新しい AI ゲートウェイを使い始めるときは、最初のリクエストを送るまでにドキュメント、ダッシュボード、環境変数、ターミナルを行き来することがよくあります。Phaseo では、そのセットアップを一続きの流れで完了できます。

CLI をインストールし、Phaseo アカウントでサインインして、キーを作成します。

<CliInstallTabs packageName="@phaseo/cli" />

```bash
phaseo login
phaseo keys create --name "My first Phaseo key"
```

ノートパソコンでは、`phaseo login` を実行するとブラウザーが開きます。SSH セッション、リモート環境、その他のヘッドレスなワークフローでは、デバイスコードログインを使えばローカルコールバックがなくても同じようにサインインできます。

```bash
phaseo login --device-code
```

その後 CLI で、現在のワークスペース、クレジット残高、利用可能なモデルやプロバイダー、料金、プリセット、ガードレールを確認できます。作業を中断してダッシュボードを開かなくても、API キーやワークスペースの設定を管理できます。

この最初の流れには、CLI で実現したい使い心地が表れています。操作がわかりやすく、必要なことを見つけやすく、すぐ役に立つこと。開発者が API エンドポイントの構成を一つずつ覚える必要はありません。コマンドにはヘルプが組み込まれており、対話的な操作では人が読みやすい形式で、別のツールに結果を渡すときは JSON 形式で出力できます。

## Phaseo プラットフォームを一つのインターフェースで

最初のリリースでできることは、認証だけではありません。幅広い Phaseo のワークフローを、一つのコマンドラインインターフェースにまとめました。

- API キーの作成、確認、更新、無効化、削除
- 信頼できる自動化に必要な権限を明示した管理キーの作成
- ワークスペースの一覧表示、メンバーの確認、メンバーシップの管理
- プリセット、設定、ガードレールの確認と構成
- モデル、プロバイダー、料金の検索
- クレジット、アクティビティ、分析、生成結果の確認
- ゲートウェイリクエストの調査と、ID を指定した個別リクエストの取得
- 専用コマンドがまだない場合に、認証済みの Phaseo API エンドポイントを直接呼び出す

CLI を使えば、プロジェクトの初期設定から日々の運用まで進められます。開発者は一度のターミナルセッションで、サインインし、権限を絞ったキーを作り、アカウントのクレジットを確認し、モデルを選び、発生したトラフィックを調べることができます。

チームにとっても、運用のための一貫したインターフェースになります。ローカル開発で使うコマンドを、ダッシュボードの操作に頼らず、スクリプト、手順書、リモート環境、権限を適切に絞った自動化に引き継げます。

## 人とエージェントのために

開発者もコーディングエージェントも、プロジェクトを理解するためにターミナルを使うことが増えています。Phaseo の公式インターフェースがあれば、連携コードを生成するだけでなく、現在のワークスペースを確認し、適切なキーを作成し、利用可能なクレジットを調べ、リクエスト実行後に何が起きたかを確認できます。

ほとんどのコマンドは構造化された JSON 出力に対応しています。同じインターフェースを、コマンドを入力する人にも、タスクを進めるエージェントにも使えます。

```bash
phaseo whoami --json
phaseo credits get --json
phaseo models list --limit 20 --json
```

これを基盤として Phaseo CLI スキルを開発し、対応するエージェントがプロジェクト内でこれらのワークフローを安全かつ一貫して使えるようにします。

ここには大切な違いがあります。エージェントが設定の場所を探してダッシュボードのページを当てずっぽうに開いたり、ユーザーインターフェースを読み取ったり、開発者にツール間の情報コピーを頼んだりする必要はありません。認証済みの構造化された CLI なら、許可された状態を確認し、開発者と同じサポート対象のインターフェースを通じて、明示的な操作を実行できます。

製品と並行して CLI スキルも開発しています。これによりエージェントは、利用可能なコマンドを理解し、機械で読み取れる出力を優先し、新しく作成した秘密情報の露出を避け、連携の問題を診断する際には必要な個別リクエストの情報を取得できます。

## すべてのリクエストを把握する

AI アプリの開発は、リクエストが成功した時点で終わりではありません。どのモデルとプロバイダーが処理したか、所要時間や料金、失敗の理由を知る必要があります。

Phaseo CLI なら、その情報をターミナル上で確認できます。最近のリクエストを絞り込み、調べたいものを個別に詳しく確認できます。

```bash
phaseo logs list --since 1h --status error --json
phaseo logs get <request-id> --json
```

リクエストの詳細には、ルーティング、ステータス、レイテンシ、モデル、プロバイダー、料金を調査するための運用情報が含まれます。開発者もエージェントも、同じ場所で「作る、実行する、調べる、改善する」という流れをすばやく回せます。

まずはリクエスト一覧の絞り込みと、個別リクエストの取得から始めます。ライブでの追跡機能は今後追加する予定です。

将来的には CLI を Phaseo の包括的なオブザーバビリティツールにしたいと考えています。絞り込み機能の強化、関連するリクエストや生成結果への移動、料金とレイテンシの明確な要約、アプリの開発やデバッグ中にトラフィックを追うライブワークフローなどを予定しています。

これからも原則は変わりません。問題の解決に必要な運用情報を提供しつつ、一般的な CLI 出力に機密性の高いアプリケーションデータを含めないことです。

## 目指すのは API やダッシュボードとの機能の一致

今回のリリースは CLI の出発点であり、限界ではありません。

長期的には、API やダッシュボードで利用できる重要な Phaseo のワークフローすべてに、よく設計された CLI の操作方法を用意したいと考えています。Phaseo で実行できる操作は、開発者がターミナルを離れずに見つけ、実行し、自動化できるべきです。

今後、次のような機能をプラットフォーム全体に拡張していく予定です。

- ワークスペース、メンバー、アクセス権の管理強化
- API キーと管理キーのライフサイクル全体の管理
- プリセット、ルーティング、プロバイダー、ガードレールの完全な構成
- 使用量、支出、クレジット、パフォーマンスに関する詳しいレポート
- 生成結果とリクエストのオブザーバビリティ強化
- サポートやインシデント調査を迅速にする、エクスポート可能な診断情報
- CI、デプロイシステム、エージェント向けの非対話型ワークフロー改善
- Phaseo の新機能に合わせた専用コマンド

機能をそろえるために、API ルートを機械的に並べるわけではありません。CLI では、一般的な作業を生のリクエストを手作業で組み立てるより簡単にすることが重要です。役立つ既定値、わかりやすいヘルプ、予測しやすいエラー、安定した JSON 出力を備えた目的別のコマンドを追加していきます。

専用コマンドができるまでは、認証済みの `phaseo api` コマンドから、対応する API エンドポイントを呼び出せます。上位のコマンドが増える間も、詳しいユーザーは CLI で作業を続けられます。

ダッシュボードは、データを視覚的に確認し、Phaseo を対話的に構成するための最適なインターフェースであり続けます。CLI は運用面を担う相棒です。すばやく実行でき、自動化しやすく、シェルを実行できる場所ならどこでも利用できます。

## 初期設定から安全に

CLI は Phaseo 全体で構築している OAuth の基盤を利用します。安全なブラウザーログイン、デバイス認証、有効期間の短いアクセス、ローテーションするリフレッシュトークンを備えています。利用可能な場合、セッションは OS の安全な認証情報ストレージに保存され、サインアウトすると保存済みセッションが失効します。

アクセス権はワークスペースのメンバーシップにリアルタイムで連動します。ユーザーがワークスペースから削除されると、その CLI セッションからワークスペースの情報を読み取ったり変更したりできなくなります。

リクエストの調査では、意図的にメタデータのみを表示します。CLI のログコマンドからプロンプト、リクエスト本文、ヘッダー、トレース、エンドユーザー識別子が公開されることはありません。

管理キーには明示的な権限を設定でき、自動化に必要なアクセスだけを許可できます。通常のゲートウェイキーには、ワークスペースのポリシー、ルーティング設定、制限、ガードレールが引き続き適用されます。新しく作成した秘密情報は一度だけ表示されます。リポジトリへのコミットやログへの記録は避け、シークレットマネージャーに保存してください。

CLI の機能が増えても、こうした境界は重要です。新しいコマンドも API やダッシュボードと同じワークスペース認可モデルを引き継ぎ、別個の特権的な管理経路を作ることはありません。

## 本日から利用可能

Phaseo CLI は本日から利用できます。デフォルトでは `https://api.phaseo.app` に接続し、`PHASEO_API_URL` を設定すればローカル環境やプレビュー環境を指定できます。

ユーザーが作成する OAuth アプリは、引き続き非公開テスト中です。今回のリリースでは、開発者、チーム、エージェントが安心して使えるファーストパーティ CLI の提供に重点を置いています。

CLI を支える共通 OAuth の仕組みは、将来的には自社のターミナル環境以外でも利用される予定です。明確なスコープを申請してユーザーの同意を得た、承認済みのサードパーティアプリが、同じワークスペース対応の認可モデルで動作するための基盤にしたいと考えています。まずはファーストパーティ CLI で制御を検証するため、OAuth アプリの作成は非公開にしています。

インストール後は、更新が利用可能になると CLI が通知します。いつでも手動で更新できます。

今後も CLI、API、ダッシュボードの距離を縮め、開発者が選んだ場所で Phaseo のワークフロー全体を扱えるようにしていきます。
