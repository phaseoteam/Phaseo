# Phaseo Web

The Phaseo website, dashboard, and internal catalog editor: a TanStack Start app that runs as a Cloudflare Worker.

## Development

From the repository root, run `pnpm install`, then `pnpm --filter @phaseo/web dev`. The local site runs at http://localhost:3100 inside the Workers runtime (workerd), so it behaves like production. Use `pnpm dev:cloudflare-web` from the root to run it against a local web API Worker. Configure the required local environment and backend services before using authenticated features; never commit credentials.

`src/routeTree.gen.ts` is generated by `dev` and `build`. In a fresh checkout, run one of them before `pnpm --filter @phaseo/web typecheck`.

## Environment

| Kind | Where it is read | Local file | Production |
| --- | --- | --- | --- |
| `PUBLIC_*` (Supabase URL and anon key, site URLs, Stripe publishable key, PostHog, Statsig client key and gate names) | Inlined into browser and server code at build time | `.env.local` | Build step of the "Deploy Web" CI job, mapped from the GitHub secrets and variables named `NEXT_PUBLIC_*` |
| Server settings and secrets (service role key, Stripe secret, Resend, Upstash, ...) | `process.env` on the server | `.dev.vars` or `.env.local` | Worker variables in `wrangler.jsonc` and Worker secrets set with `wrangler secret put` (deploys keep them) |

`PUBLIC_*` values are public: never give a secret that prefix.

## Build and deploy

`pnpm --filter @phaseo/web build` writes the Worker and its static assets to `dist/`. `pnpm --filter @phaseo/web preview` serves that build locally in the Workers runtime, and `pnpm --filter @phaseo/web run deploy` uploads it as the `phaseo-web` Worker (`wrangler.jsonc`).

CI deploys `main` automatically ("Deploy Web" in `.github/workflows/ci.yml`). The `phaseo.app` route in `wrangler.jsonc` stays disabled until the production cutover, so deploys reach workers.dev only until it is enabled.

## Catalog management

The database is the catalog source of truth. Admins use `/internal/data` to manage models, organisations, providers, routes, prices, and benchmark results. `/internal/data/registries` manages supporting catalog settings, and `/internal/data/imports` reviews provider price proposals.

Public visitors should [report incorrect information](https://github.com/phaseoteam/Phaseo/issues/new?template=incorrect-info.yml) or [request missing data](https://github.com/phaseoteam/Phaseo/issues/new?template=data-request.yml) with the affected record and official sources. Maintainers review the issue and apply approved updates in the editor.

The production database is the only copy of the catalog. The repository holds no catalog JSON, exports, or import path.

## Validation

Run `pnpm --filter @phaseo/web lint`, `pnpm --filter @phaseo/web typecheck`, and the relevant tests. Run `pnpm --filter @phaseo/web build` for rendering or routing changes. Follow [AGENTS.md](AGENTS.md) and the root [contribution guide](../../CONTRIBUTING.md).

## Translation payloads

The site renders with the locale's full catalog. The server reads it from the catalog files served as static assets; browsers load the same catalog once from `/api/i18n-full/<locale>?v=<build id>`, which is immutable, so dictionaries never sit in the HTML. Keep dictionary imports out of client components.

`pnpm --filter @phaseo/web validate:i18n` checks the catalogs in every locale and the docs search index. Review computed translation keys and newly shared components as well, since static checks cannot determine every runtime key. See [LOCALISATION.md](LOCALISATION.md) for the UI audit.

## Server catalogue loading

The models page has one 15-second server budget covering session resolution, provider previews, catalogue pages, pricing and private data. Its signal reaches each request, including Auth requests, and server prefetch retries are disabled. Browser query policies remain independent. If the account scope is already known when the deadline expires, the browser can recover the catalogue request; an unresolved session is never silently treated as anonymous.

The shared authentication header loader also has one 15-second budget, forwards cancellation to Auth and the account API, and makes one attempt. Its callers retain their existing error fallbacks.
