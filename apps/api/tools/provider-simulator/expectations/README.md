# Expectations

Declarative expected outcomes for the provider simulator, kept as data so they can be reviewed in PRs.

- `sources.json`: named citations (`{ "kind": "ref", "ref": "<id>" }` points here).
- `gateway.json`: Phaseo client-surface semantics (finish reasons, usage fields, stream grammar, error mapping, billing rules), each with a source in Phaseo's docs or the upstream API docs the surface mirrors.
- `params.json`: where each documented client parameter must land in each upstream dialect, and how its value is transformed.
- `providers/<id>.json`: per-provider facts: base URL, auth header, dialect per route, unsupported parameters, usage semantics. Generated by `scripts/build-expectations.ts` from `specs/` and then reviewed; hand edits go in `overrides` and survive regeneration.
- `e2e/*.json`: end-to-end cases (failover, error mapping, BYOK, presets, billed cost, non-text families).
- `pricing/*.json`: pricing sweep expectations.
- `allowlist.json`: justified mismatches. Every entry names the AUDIT finding and the proposed fix group. A mismatch that no entry matches fails the run.

## Sources

Every expectation carries a `source`:

| kind | meaning |
|---|---|
| `spec` | a provider spec under `specs/`, with the schema path |
| `docs` | a provider documentation URL |
| `gateway-docs` | a page under `apps/docs` describing Phaseo's own behaviour |
| `assumed` | documentation is silent; `reason` says why this is the expected outcome |
| `ref` | a named citation in `sources.json` |

## Mismatch kinds

`dropped`, `invented`, `renamed`, `wrong_value`, `wrong_type`, `billing_over`, `billing_under` (with the delta in nanos and tokens), `stream_order`, `error_mapping`, `nondeterminism`. The shared types are in `src/expect/types.ts`; the gate is `src/expect/allowlist.ts`.
