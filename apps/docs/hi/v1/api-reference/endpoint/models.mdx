डिफ़ॉल्ट रूप से यह एंडपॉइंट केवल वही मॉडल लौटाता है जिन्हें अभी रूट किया जा सकता है। ज्ञात लेकिन फ़िलहाल अनुपलब्ध मॉडल भी शामिल करने के लिए `availability=all` सेट करें।

कैटलॉग प्रतिक्रियाएँ पाँच मिनट कैश की जाती हैं और कैश के दोबारा सत्यापन के दौरान अगले पाँच मिनट भी दी जा सकती हैं। यह वर्तमान कैटलॉग के JSON, RSS और Atom रूपों पर लागू है; रिलीज़ फ़ीड का अपना कम अवधि वाला पोलिंग कैश है।

`GET /models/me` भविष्य में मौजूदा कॉल करने वाले के लिए गार्डरेल-आधारित मॉडल फ़िल्टरिंग के लिए आरक्षित है। अभी यह `501 not implemented` लौटाता है, इसलिए साझा Gateway कैटलॉग के लिए फ़िलहाल `GET /models` का उपयोग करें।

## OpenAI प्रारूप

जो क्लाइंट OpenAI की मॉडल-सूची प्रतिक्रिया की अपेक्षा करते हैं, उनके लिए `GET /v1/models?format=openai` का उपयोग करें। डिफ़ॉल्ट `format=json`, Phaseo का अधिक विस्तृत मॉडल मेटाडेटा लौटाता है।

```bash
curl 'https://api.phaseo.app/v1/models?format=openai' \
  -H 'Authorization: Bearer YOUR_PHASEO_API_KEY'
```

```json
{
  "object": "list",
  "data": [
    { "id": "openai/gpt-4o-mini", "object": "model", "created": 1721260800, "owned_by": "openai" }
  ]
}
```

OpenAI प्रारूप में नेटिव JSON वाला ही प्रमाणीकरण, क्षेत्रीय उपलब्धता, वर्कस्पेस के निजी मॉडल और फ़िल्टर लागू होते हैं। जब तक आप `limit` न दें, यह सभी मेल खाने वाले मॉडल लौटाता है; `offset` फिर भी लागू रहता है। इन्फ़रेंस के लिए ID, Phaseo के कैनोनिकल रूप में ही रहती हैं। `created` कैटलॉग की रिलीज़ तिथि का उपयोग करता है, या अज्ञात होने पर `0`; `owned_by` कैटलॉग के संगठन का उपयोग करता है, वर्कस्पेस मॉडल के लिए `private`, या अज्ञात होने पर `phaseo`।

## उपयोगी फ़िल्टर

- `endpoints` में `chat.completions`, `responses` और `messages` जैसे सार्वजनिक नाम आते हैं
- `status` मॉडल जीवनचक्र के आधार पर फ़िल्टर करता है, जैसे `active`, `deprecated` या `retired`
- `provider` सार्वजनिक प्रदाता ID से फ़िल्टर करता है, जैसे `openai`, `anthropic` या `google_vertex`
- `provider_status` प्रदाता के रोलआउट स्तर से फ़िल्टर करता है, जैसे `active`, `beta`, `alpha` या `not_ready`
- `provider_routing_status` प्रदाता-स्तर की रूटिंग स्थिति से फ़िल्टर करता है
- `model_routing_status` मॉडल-स्तर की रूटिंग स्थिति से फ़िल्टर करता है
- `capability_status` अनुरोधित एंडपॉइंट मैपिंग के लिए प्रदाता की क्षमता-स्थिति से फ़िल्टर करता है
- `provider_availability_status` प्रदाता की ओर की उपलब्धता से फ़िल्टर करता है, जैसे `active`, `coming_soon` या `inactive`
- `provider_availability_reason` प्रदाता की ओर की उपलब्धता के कारण से फ़िल्टर करता है, जैसे `preview_only`, `provider_not_ready`, `gated`, `access_limited` या `region_limited`
- `organisation` सार्वजनिक मॉडल ID के उपसर्ग से फ़िल्टर करता है, जैसे `anthropic/claude-3-haiku` में `anthropic`
- `availability=active` डिफ़ॉल्ट है
- `availability=all` में ऐसे मॉडल या प्रदाता भी शामिल होते हैं जो `coming_soon`, `inactive` हैं या अभी सार्वजनिक रूप से रूट नहीं किए जा सकते
- `input_modalities`, `input_types` का उपनाम है
- `output_modalities`, `output_types` का उपनाम है
- `supported_parameters`, `params` का उपनाम है

किसी मॉडल का एंडपॉइंट अनुबंध देखने के लिए `GET /models/{author}/{slug}/endpoints` कॉल करें। प्रतिक्रिया में हर प्रदाता रूट अलग रहता है और प्रत्येक पंक्ति में सार्वजनिक पथ, मोडैलिटी, समर्थित पैरामीटर का विवरण, उपलब्धता, रूटिंग स्थिति, प्रदाता मॉडल स्लग और मूल्य सारांश दिया जाता है।

प्रदाता प्रविष्टियों में ये फ़ील्ड भी हो सकते हैं:

- `availability_status`
- `availability_reason`
- `provider_status`
- `provider_routing_status`
- `model_routing_status`
- `capability_status`
