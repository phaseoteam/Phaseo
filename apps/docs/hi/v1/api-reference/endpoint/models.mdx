जिन मॉडलों पर आप अभी रूट कर सकते हैं, उनकी सूची के लिए `GET /v1/models` कॉल करें। जो मॉडल ज्ञात हैं लेकिन अभी उपलब्ध नहीं हैं, उन्हें भी शामिल करने के लिए `availability=all` सेट करें।

```bash
curl "https://api.phaseo.app/v1/models?limit=50" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

हर मॉडल `offers` में हर प्रदाता रूट के लिए एक प्रविष्टि दिखाता है (संक्षिप्त, मान उदाहरण के लिए):

```json
{
  "ok": true,
  "availability_mode": "active",
  "limit": 50,
  "offset": 0,
  "total": 412,
  "models": [
    {
      "id": "anthropic/claude-sonnet-5.5",
      "name": "Claude Sonnet 5.5",
      "organization": { "id": "anthropic", "name": "Anthropic", "color": "#d97757" },
      "lifecycle": { "status": "active", "released_at": "2026-09-28", "replacement_id": null },
      "modalities": { "input": ["text", "image"], "output": ["text"] },
      "capabilities": { "endpoints": ["chat.completions", "messages", "responses"] },
      "availability": { "status": "active", "provider_count": 3, "active_provider_count": 3 },
      "offers": [
        {
          "provider": { "id": "anthropic", "name": "Anthropic" },
          "model": "claude-sonnet-5-5",
          "status": "active",
          "status_reason": null,
          "routable": true,
          "service_tiers": ["standard"],
          "routing": { "provider": "active", "model": "active", "capability": "active" }
        }
      ]
    }
  ]
}
```

प्रोडक्शन ट्रैफ़िक सिर्फ़ उसी ऑफ़र पर रूट करें जिसका `routable` `true` हो। `status_reason` बताता है कि कोई ऑफ़र सिर्फ़ पूर्वावलोकन या निष्क्रिय क्यों है। पूरी स्कीमा नीचे है।

`GET /models/me` वही सूची आपकी कुंजी के गार्डरेल लागू करके लौटाता है: आपके वर्कस्पेस के गोपनीयता और प्रदाता नियम, और कुंजी के विभागों, उसके सदस्य और स्वयं कुंजी पर लगे गार्डरेल। जिन मॉडलों को कोई मॉडल नियम रोकता है, और जिनका कोई अनुमत प्रदाता नहीं है, वे शामिल नहीं होते, और हर मॉडल में केवल वे ऑफ़र रहते हैं जिन तक उसके अनुरोध भेजे जा सकते हैं। यह `GET /models` वाले ही फ़िल्टर लेता है। प्रतिक्रिया में `access` भी होता है: क्या कोई नियम लागू है (`restricted`), नियम किन मॉडलों को बाहर रखते हैं (`hidden_model_count` और `hidden_models`, आईडी और नामों के साथ) और सूचीबद्ध कितने मॉडलों के कुछ प्रदाता हट गए (`limited_model_count`), ताकि आप बता सकें कि कोई मॉडल क्यों नहीं दिख रहा।

## सूची फ़िल्टर करें

जो फ़िल्टर कई मान लेते हैं, वे दोहराए गए पैरामीटर या कॉमा से अलग की गई सूची स्वीकार करते हैं।

| पैरामीटर | किसके आधार पर फ़िल्टर करता है |
| --- | --- |
| `availability` | सार्वजनिक रूप से रूट होने योग्य मॉडलों के लिए `active` (डिफ़ॉल्ट), या `coming_soon`, `inactive` और अभी रूट न होने योग्य मॉडल और प्रदाता जोड़ने के लिए `all` |
| `endpoints` | सार्वजनिक एंडपॉइंट नाम, जैसे `chat.completions`, `responses` और `messages` |
| `status` | मॉडल का लाइफ़साइकल, जैसे `active`, `deprecated` या `retired` |
| `organisation` | मॉडल ID का प्रीफ़िक्स, जैसे `anthropic/claude-3-haiku` में `anthropic` |
| `provider` | सार्वजनिक प्रदाता ID, जैसे `openai`, `anthropic` या `google_vertex` |
| `provider_status` | प्रदाता का रोलआउट स्तर, जैसे `active`, `beta`, `alpha` या `not_ready` |
| `provider_routing_status` | प्रदाता स्तर की रूटिंग स्थिति |
| `model_routing_status` | मॉडल स्तर की रूटिंग स्थिति |
| `capability_status` | मांगे गए एंडपॉइंट मैपिंग के लिए प्रदाता क्षमता की स्थिति |
| `provider_availability_status` | प्रदाता की ओर से उपलब्धता, जैसे `active`, `coming_soon` या `inactive` |
| `provider_availability_reason` | प्रदाता अनुपलब्ध क्यों है, जैसे `preview_only`, `provider_not_ready`, `gated`, `access_limited` या `region_limited` |
| `input_types` (उपनाम `input_modalities`) | इनपुट मोडैलिटी |
| `output_types` (उपनाम `output_modalities`) | आउटपुट मोडैलिटी |
| `params` (उपनाम `supported_parameters`) | समर्थित अनुरोध पैरामीटर |

किसी एक मॉडल के प्रदाता रूट, पैरामीटर विवरण और कीमतें देखने के लिए [`GET /models/{author}/{slug}/endpoints`](./model-endpoints.mdx) कॉल करें।

## हर ऑफ़र के सर्विस टियर जांचें

`offers` की हर प्रविष्टि में `service_tiers` होता है, यानी वे [सर्विस टियर](../../guides/service-tiers.mdx) जिन्हें वह प्रदाता ऑफ़र स्वीकार करता है। यह `flex`, `priority`, `standard` और `ultrafast` का वर्णानुक्रम में क्रमबद्ध उपसमूह है, जिसमें `priority` Fast टियर है। कोई टियर तब सूचीबद्ध होता है जब प्रदाता रूट के पास उसके लिए सक्रिय, अभी प्रभावी कीमतें हों, और जो रूट एक ही टियर देता है वह सिर्फ़ वही टियर सूचीबद्ध करता है। कुछ टियर अलग टियर-विशिष्ट प्रदाता रूट से भी उपलब्ध होते हैं, जो सूचीबद्ध नहीं होते। `pricing` के अंतर्गत कीमतें standard टियर की कीमतें ही रहती हैं।

## सूची OpenAI फ़ॉर्मैट में पाएं

जो क्लाइंट OpenAI की model-list प्रतिक्रिया की अपेक्षा करते हैं, उनके लिए `GET /v1/models?format=openai` का उपयोग करें। डिफ़ॉल्ट `format=json` Phaseo का ज़्यादा विस्तृत मॉडल मेटाडेटा लौटाता है।

```bash
curl "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

```json
{
  "object": "list",
  "data": [
    { "id": "openai/gpt-6-astra", "object": "model", "created": 1788393600, "owned_by": "openai" }
  ]
}
```

OpenAI फ़ॉर्मैट नेटिव JSON वाला ही प्रमाणीकरण, क्षेत्रीय उपलब्धता, वर्कस्पेस के निजी मॉडल और फ़िल्टर इस्तेमाल करता है। जब तक आप `limit` न दें, यह सभी मेल खाने वाले मॉडल लौटाता है; `offset` फिर भी लागू होता है। इन्फ़रेंस के लिए ID Phaseo के मानक रूप में ही रहते हैं। `created` कैटलॉग की रिलीज़ तारीख इस्तेमाल करता है, या अज्ञात होने पर `0`; `owned_by` कैटलॉग का संगठन, वर्कस्पेस मॉडलों के लिए `private`, या अज्ञात होने पर `phaseo` इस्तेमाल करता है।

## मॉडल सूची कैश करें

कैटलॉग प्रतिक्रियाएं पांच मिनट के लिए कैश होती हैं, और कैश के पुनः सत्यापन के दौरान अगले पांच मिनट तक भी दी जा सकती हैं। यह मौजूदा कैटलॉग के JSON, RSS और Atom रूपों पर लागू होता है; रिलीज़ फ़ीड का अपना छोटा पोलिंग कैश है।

JSON और OpenAI-फ़ॉर्मैट प्रतिक्रियाओं में एक weak `ETag` हेडर (`W/"…"`) होता है। यह तब बदलता है जब पेज के मॉडल, `limit`, `offset`, `total` या फ़ॉर्मैट बदलते हैं। यह `gateway_region` को अनदेखा करता है, इसलिए किसी दूसरे क्षेत्र से दिए गए उसी कैटलॉग का `ETag` भी वही होता है। इसी कारण यह weak है: जिन प्रतिक्रियाओं का यह साझा है वे समान हैं, लेकिन उनके बाइट अलग हो सकते हैं। RSS, Atom और त्रुटि प्रतिक्रियाओं में यह नहीं होता।

सहेजा गया मान बिना बदले `If-None-Match` में वापस भेजें। अगर कैटलॉग नहीं बदला है, तो प्रतिक्रिया बिना बॉडी के `304 Not Modified` होती है और `ETag`, `Cache-Control` और `Vary` हेडर दोहराती है। वरना आपको नई सूची और नए `ETag` के साथ सामान्य `200` मिलता है। `If-None-Match` कॉमा से अलग की गई सूची और `*` भी स्वीकार करता है, और तुलना weak होती है, इसलिए मान `W/` प्रीफ़िक्स के साथ या बिना, दोनों तरह मेल खाता है।

```ts
let etag: string | null = null;
let models: unknown[] = [];

async function refreshModels() {
  const response = await fetch("https://api.phaseo.app/v1/models?limit=250", {
    headers: {
      Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
      ...(etag ? { "If-None-Match": etag } : {}),
    },
  });
  if (response.status === 304) return models; // कोई बदलाव नहीं; 304 में बॉडी नहीं होती।
  if (!response.ok) throw new Error(`Model list request failed: ${response.status}`);
  etag = response.headers.get("ETag");
  models = (await response.json()).models;
  return models;
}
```

`304` ट्रांसफ़र और पार्सिंग बचाता है। सर्वर फिर भी अनुरोध का मूल्यांकन करता है: वह कैटलॉग लोड करता है और `ETag` दोबारा निकालता है। लगभग हर 15 मिनट में पोल करना काफ़ी है, और सूची सिर्फ़ तब दोबारा डाउनलोड होती है जब कैटलॉग बदलता है। हर अनुरोध URL के लिए एक `ETag` रखें, क्योंकि हर पेज, फ़िल्टर सेट और फ़ॉर्मैट का अपना मान होता है।
