अपने वर्कस्पेस के किसी अनुरोध का संग्रहीत ऑडिट रिकॉर्ड पाने के लिए `GET /v1/generations?id=<request_id>` कॉल करें। इसके लिए `generations:read` स्कोप चाहिए; `id` न होने पर `400` `missing_id` लौटता है।

नए अनुरोधों को सर्वर द्वारा बनाया गया `G-` जनरेशन ID मिलता है, जो `x-request-id` प्रतिक्रिया हेडर और जनरेशन प्रतिक्रिया में लौटाया जाता है। अनुरोध लॉग, जनरेशन लुकअप और सपोर्ट के लिए इसी ID का उपयोग करें। कॉलर द्वारा दिया गया `x-request-id` जनरेशन ID की जगह नहीं लेता। पुराने UUID लॉग ID अब भी लुकअप के लिए काम करते हैं।

## अनुरोध को दोबारा चलाएं

हर प्रतिक्रिया में `replay_supported` होता है। जब I/O लॉगिंग ने अनुरोध बॉडी संग्रहीत की हो और आपको संग्रहीत सामग्री पढ़ने की अनुमति हो, तो `replay_supported` `true` होता है और `replay_request` में वह बॉडी होती है जिसे नियंत्रित रूप से दोबारा चलाने के लिए वापस भेजा जा सकता है:

<Steps>
  <Step title="जनरेशन पढ़ें">
    `GET /v1/generations?id=<request_id>` कॉल करें।
  </Step>
  <Step title="जांचें कि इसे दोबारा चलाया जा सकता है">
    तभी आगे बढ़ें जब `replay_supported` `true` हो।
  </Step>
  <Step title="इसे फिर से भेजें">
    `replay_request` को `endpoint` में बताए गए एंडपॉइंट पर भेजें, जैसे `/v1/chat/completions` या `/v1/responses`।
  </Step>
</Steps>

कोई वर्कस्पेस संग्रहीत सामग्री को सिर्फ़ मालिकों और एडमिन तक सीमित कर सकता है। तब बाकी कॉलर, जिनमें सदस्यों द्वारा बनाई गई API कुंजियां भी शामिल हैं, को `replay_request: null` और बिना सामग्री वाला अनुरोध विवरण मिलता है।
