Gateway के हर अनुरोध के लिए Bearer API कुंजी आवश्यक है।

कुंजियाँ Phaseo डैशबोर्ड में बनाएँ और प्रबंधित करें।

<Note>
`:free` मॉडल के कॉल बिना जमा किए गए क्रेडिट के चल सकते हैं। पेड मॉडल के कॉल के लिए वॉलेट में उपलब्ध बैलेंस चाहिए।
</Note>

## API कुंजी का उपयोग

`Bearer` स्कीम के साथ अपनी API कुंजी `Authorization` हेडर में शामिल करें:

```bash
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5-nano",
    "input": "Hello!"
  }'
```

## कुंजी का प्रारूप और सुरक्षित उपयोग

- कुंजी का प्रारूप: `phaseo_v1_sk_<kid>_<secret>`
- कुंजियाँ secrets manager में रखें, ब्राउज़र कोड में नहीं।
- सुरक्षित रोटेशन के लिए हर ऐप और वातावरण की अलग कुंजी रखें।

## प्रबंधन कुंजियाँ

Management API कुंजियाँ Phaseo डैशबोर्ड में बनाई और प्रबंधित की जाती हैं, सार्वजनिक API के ज़रिए नहीं।

इनका उपयोग अधिक अधिकार वाले प्रशासनिक endpoints, जैसे [क्रेडिट](./endpoint/credits.mdx) और [गतिविधि](./endpoint/activity.mdx), तथा भविष्य के control-plane APIs—जैसे guardrails, कुंजी प्रबंधन और workspace प्रबंधन—के लिए करें।

## प्रमाणीकरण विफलताएँ

- `401`: API कुंजी मौजूद नहीं है, गलत प्रारूप में है या अमान्य है।
- `403`: कुंजी मान्य है, लेकिन अनुरोधित क्षमता तक पहुँच नहीं है।

यदि आप एजेंट के रूप में प्रमाणीकरण प्रवाह लागू कर रहे हैं:

- secrets और वातावरण सेटअप के लिए repository skills का उपयोग करें।

- frontend और backend के बीच कम समय तक मान्य आंतरिक tokens को प्राथमिकता दें; Gateway कुंजियाँ केवल सर्वर पर रहें।
