अपने सर्वर से Phaseo के प्रशासन API कॉल करने के लिए मैनेजमेंट कुंजी बनाएँ: क्रेडिट, गतिविधि, वर्कस्पेस, कुंजियाँ, प्रीसेट, सेटिंग और गार्डरेल। मैनेजमेंट कुंजियों से इन्फ़रेंस अनुरोध नहीं भेजे जा सकते।

```bash
phaseo management-keys create --name <name> --template read-only --json
```

या डैशबोर्ड में **सेटिंग्स → प्रबंधन कुंजियाँ** के तहत एक कुंजी बनाएँ। सीक्रेट केवल एक बार दिखता है, इसलिए इसे अपने सीक्रेट मैनेजर में सेव करें। इसे केवल सर्वर-साइड कोड से, Gateway वाले ही बेस URL (`https://api.phaseo.app/v1`) पर भेजें:

```http
Authorization: Bearer phaseo_v1_mk_<kid>_<secret>
```

## मैनेजमेंट कुंजियाँ, API कुंजियाँ और OAuth टोकन

| क्रेडेंशियल | फ़ॉर्मैट | किसके लिए उपयोग करें | किससे सीमित |
| --- | --- | --- | --- |
| Gateway API कुंजी | `phaseo_v1_sk_<kid>_<secret>` | मॉडल और जनरेशन अनुरोध | रूटिंग नीति, बजट, सीमाएँ और जुड़े हुए गार्डरेल |
| मैनेजमेंट API कुंजी | `phaseo_v1_mk_<kid>_<secret>` | प्रशासन अनुरोध | उसकी क्षमताएँ और आपकी वर्कस्पेस भूमिका |
| OAuth एक्सेस टोकन | | किसी उपयोगकर्ता की ओर से प्रशासन | स्वीकृत OAuth स्कोप और उपयोगकर्ता की वर्कस्पेस भूमिका |

मैनेजमेंट रूट केवल मैनेजमेंट कुंजियाँ (या OAuth टोकन) स्वीकार करते हैं; Gateway API कुंजी उन्हें कॉल नहीं कर सकती।

[गार्डरेल](../cookbook/guardrails-for-api-keys.mdx) एक अलग नियंत्रण हैं: वे Gateway API कुंजियों पर लागू होते हैं और इन्फ़रेंस ट्रैफ़िक को नियंत्रित करते हैं, जैसे रूटिंग प्रतिबंध, बजट, प्रॉम्प्ट-इंजेक्शन से निपटना और संवेदनशील जानकारी के नियम। मैनेजमेंट कुंजी की क्षमताएँ तय करती हैं कि वह कौन से प्रशासन API कॉल कर सकती है।

## ऐक्सेस स्तर चुनें

कुंजी बनाते समय हर टेम्पलेट क्षमताओं की एक स्पष्ट सूची में बदल जाता है। Phaseo कभी `all` जैसा वाइल्डकार्ड सेव नहीं करता, इसलिए कुंजी को बाद में जोड़ी गई अनुमति कभी नहीं मिलती।

| टेम्पलेट | `--template` | क्या देता है |
| --- | --- | --- |
| **पढ़ना** | `read-only` | हर मौजूदा `*:read` क्षमता |
| **लिखना** | `read-write` | हर मौजूदा `*:read` और `*:write` क्षमता, डिलीट नहीं |
| **सभी** | `full-control` | हर मौजूदा पढ़ने, लिखने और डिलीट करने की क्षमता |

किसी भी टेम्पलेट में `billing:write` शामिल नहीं है, जो क्रेडिट टॉप-अप शुरू करती है; इसे `--scopes` के साथ स्पष्ट रूप से माँगें। **सभी** का उपयोग केवल भरोसेमंद प्रशासनिक ऑटोमेशन के लिए करें।

छोटी अनुमति के लिए, अपनी ज़रूरत की क्षमताएँ `--scopes scope_a,scope_b` के साथ दें:

| क्षेत्र | पढ़ना | लिखना | डिलीट |
| --- | --- | --- | --- |
| पहचान और कैटलॉग | `me:read`, `models:read`, `providers:read`, `pricing:read` | | |
| उपयोग और ऑब्ज़र्वेबिलिटी | `credits:read`, `activity:read`, `analytics:read`, `generations:read`, `feedback:read` | `feedback:write` | |
| बिलिंग | | `billing:write` (ऑप्ट-इन) | |
| वर्कस्पेस | `workspaces:read` | `workspaces:write` | `workspaces:delete` |
| Gateway API कुंजियाँ | `keys:read` | `keys:write` | `keys:delete` |
| मैनेजमेंट API कुंजियाँ | `management_keys:read` | `management_keys:write` | `management_keys:delete` |
| प्रीसेट | `presets:read` | `presets:write` | `presets:delete` |
| सेटिंग | `settings:read` | `settings:write` | |
| प्रदाता क्रेडेंशियल | `provider_credentials:read` | `provider_credentials:write` | `provider_credentials:delete` |
| निजी मॉडल | `private_models:read` | `private_models:write` | `private_models:delete` |
| गार्डरेल | `guardrails:read` | `guardrails:write` | `guardrails:delete` |
| बजट | `budgets:read` | `budgets:write` | `budgets:delete` |
| रेट लिमिट | `rate_limits:read` | `rate_limits:write` | `rate_limits:delete` |
| क्लासिफ़ायर | `classifiers:read` | `classifiers:write` | `classifiers:delete` |
| खर्च नियम | `spend_rules:read` | `spend_rules:write` | `spend_rules:delete` |
| OAuth क्लाइंट | `oauth_clients:read` | `oauth_clients:write` | `oauth_clients:delete` |

## क्षमताएँ वर्कस्पेस भूमिकाओं को ओवरराइड नहीं करतीं

Phaseo हर कॉल पर दो चीज़ें जाँचता है: कुंजी के पास क्षमता है, और कुंजी या OAuth उपयोगकर्ता उस वर्कस्पेस में उस भूमिका के साथ है जिसकी कार्रवाई को ज़रूरत है। उदाहरण के लिए, `keys:write` कुंजी प्रबंधन की अनुमति देती है, लेकिन भूमिका जाँच फिर भी तय करती है कि कॉल करने वाला उस वर्कस्पेस में कुंजियाँ प्रबंधित कर सकता है या नहीं। कोई कुंजी किसी क्षमता के सहारे दूसरे वर्कस्पेस तक नहीं पहुँच सकती और न ही ओनर और एडमिन जाँच छोड़ सकती है।

## कुंजियाँ सुरक्षित रखें

- मैनेजमेंट कुंजियों को ब्राउज़र, डेस्कटॉप लॉग, सोर्स कंट्रोल और चैट से दूर रखें।
- हर इंटीग्रेशन के लिए एक कुंजी रखें, और सबसे सीमित टेम्पलेट चुनें जो काम करे।
- जब इंटीग्रेशन को अनिश्चितकालीन ऐक्सेस की ज़रूरत न हो, तो समाप्ति तिथि सेट करें।
- अनुपयोगी कुंजियों को तुरंत रोकें या डिलीट करें।
- लीक हुई कुंजी को आगे जाँच करने से पहले रोटेट करें।
