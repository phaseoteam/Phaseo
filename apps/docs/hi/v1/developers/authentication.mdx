[Phaseo CLI](../guides/integrations/phaseo-cli) में `phaseo keys create --name <name> --json` से या [डैशबोर्ड](https://phaseo.app/settings/keys) में एक कुंजी बनाएँ, उसे अपने सर्वर पर रखें, और हर Gateway अनुरोध के साथ उसे bearer टोकन के रूप में भेजें। एजेंट को CLI का उपयोग करना चाहिए; [एजेंट से Phaseo प्रबंधित करें](./manage-from-an-agent) देखें।

```http
Authorization: Bearer phaseo_v1_sk_<kid>_<secret>
```

अपने क्लाइंट पर हेडर एक बार सेट करें। उदाहरण के लिए, `fetch` के साथ:

```ts
const response = await fetch("https://api.phaseo.app/v1/chat/completions", {
	method: "POST",
	headers: {
		Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
		"Content-Type": "application/json",
	},
	body: JSON.stringify({
		model: "openai/gpt-6-astra",
		messages: [
			{ role: "system", content: "You are a helpful assistant." },
			{ role: "user", content: "Summarize the drawbacks to AI." },
		],
	}),
});
```

<Note>
आप क्रेडिट जमा किए बिना `:free` मॉडल कॉल कर सकते हैं। पेड मॉडल के लिए वॉलेट में उपलब्ध बैलेंस चाहिए।
</Note>

## क्रेडेंशियल चुनें

| क्रेडेंशियल | फ़ॉर्मेट | इसका उपयोग करें |
| --- | --- | --- |
| Gateway API कुंजी | `phaseo_v1_sk_<kid>_<secret>` | आपके वर्कस्पेस के लिए उपलब्ध मॉडल, प्रदाता और जनरेशन एंडपॉइंट के लिए। |
| [मैनेजमेंट API कुंजी](./management-api-keys.mdx) | `phaseo_v1_mk_<kid>_<secret>` | प्रशासनिक API के लिए। |
| [भरोसेमंद वर्कलोड](./trusted-workloads.mdx) (बीटा) | प्लेटफ़ॉर्म से मिला कम अवधि वाला OIDC टोकन | Vercel, GitHub Actions, GitLab, Google Cloud, Buildkite, CircleCI, AWS या आपके अपने OIDC जारीकर्ता पर डिप्लॉयमेंट और CI जॉब के लिए, बिना कोई कुंजी सहेजे। |

कुंजियों को पासवर्ड की तरह संभालें: उन्हें क्लाइंट-साइड कोड और सार्वजनिक रिपॉज़िटरी से दूर रखें।

## कुंजियों को सुरक्षित रूप से संभालें

- **हर ऐप और एनवायरनमेंट के लिए एक कुंजी**, ताकि आप दूसरी सेवाओं पर असर डाले बिना एक को रोटेट कर सकें।
- **कुंजियाँ सीक्रेट मैनेजर में रखें**, जो उन्हें लॉग और एरर ट्रैकिंग से दूर रखता है।
- **हर कुंजी का उपयोग डैशबोर्ड में देखें**, ताकि असामान्य गतिविधि पकड़ सकें।
- **जिन कुंजियों का अब उपयोग नहीं करते, उन्हें मिटा दें।**

किसी कुंजी को रोटेट करने के लिए, पुरानी कुंजी अमान्य करने से पहले अपने ऐप्लिकेशन को नई कुंजी पर ले जाएँ। [कुंजी रोटेशन एंडपॉइंट](../api-reference/endpoint/keys-rotate.mdx) देखें।

## प्रमाणीकरण त्रुटियाँ ठीक करें

| स्टेटस | कारण | क्या करें |
| --- | --- | --- |
| `401` | कुंजी मौजूद नहीं है, अमान्य है, या किसी बंद वर्कस्पेस की है। बॉडी का `reason` बताता है कौन सा। | हेडर और कुंजी जाँचें। |
| `403` | कुंजी मान्य है लेकिन माँगे गए प्रदाता या मॉडल का उपयोग नहीं कर सकती। | कुंजी के गार्डरेल और वर्कस्पेस की प्रदाता सेटिंग्स जाँचें। |
| `429` | कुंजी या वर्कस्पेस किसी सीमा तक पहुँच गया। | [रेट लिमिट](../api-reference/limits.mdx) देखें। |
| `5xx` | Phaseo या प्रदाता विफल हुआ। | एक्सपोनेंशियल बैकऑफ़ के साथ दोबारा कोशिश करें, और समस्या बनी रहे तो [सपोर्ट](https://phaseo.app/help) से संपर्क करें। |

हर त्रुटि कोड के लिए [त्रुटियाँ और डीबगिंग](../api-reference/errors.mdx) देखें।
