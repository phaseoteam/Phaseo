[डैशबोर्ड](https://phaseo.app/gateway/keys) में कुंजी बनाएँ, उसे सर्वर पर रखें और Gateway अनुरोधों में Bearer टोकन के रूप में भेजें।

---

## कुंजी के प्रकार

- **Gateway API keys** आपके workspace में उपलब्ध मॉडल, प्रोवाइडर और जनरेशन endpoints को कॉल करती हैं।
- **प्रबंधन API कुंजियाँ** प्रशासन API को कॉल करती हैं। [प्रबंधन API कुंजियाँ](./management-api-keys.mdx) देखें।

पुराना क्रेडेंशियल अमान्य करने से पहले एप्लिकेशन को नई कुंजी पर बदलकर कुंजी रोटेट करें। [कुंजी रोटेशन एंडपॉइंट](../api-reference/endpoint/keys-rotate.mdx) देखें।

Keys का फ़ॉर्मैट `phaseo_v1_sk_<kid>_<secret>` होता है। इन्हें पासवर्ड की तरह सुरक्षित रखें और client-side कोड या सार्वजनिक repositories में न रखें।

<Note>
बिना क्रेडिट जमा किए `:free` मॉडल कॉल कर सकते हैं। पेड मॉडल के लिए वॉलेट में उपलब्ध बैलेंस चाहिए।
</Note>

---

## हेडर का फ़ॉर्मैट

हर अनुरोध के `Authorization` header में key जोड़ें:

```http
Authorization: Bearer phaseo_v1_sk_<kid>_<secret>
```

ज़्यादातर HTTP clients में इसे एक बार सेट किया जा सकता है। उदाहरण के लिए, `fetch` के साथ:

```ts
const response = await fetch("https://api.phaseo.app/v1/chat/completions", {
	method: "POST",
	headers: {
		Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
		"Content-Type": "application/json",
	},
	body: JSON.stringify({
		model: "openai/gpt-5-nano",
		messages: [
			{ role: "system", content: "You are a helpful assistant." },
			{
				role: "user",
				content: "Summarize the drawbacks to AI.",
			},
		],
	}),
});
```

## कुंजी प्रबंधन की जाँच-सूची

| तरीका            | यह क्यों ज़रूरी है                                                           |
| ------------------- | ------------------------------------------------------------------------ |
| हर ऐप के लिए अलग key रखें | इससे दूसरी सेवाओं को प्रभावित किए बिना key बदली जा सकती है।                |
| Keys को सुरक्षित रखें | Secrets manager, logs या error-tracking में key गलती से दिखने से बचाते हैं।  |
| उपयोग पर नज़र रखें       | Dashboard में हर key के metrics दिखते हैं, जिससे आप जल्दी असामान्य गतिविधि पकड़ सकते हैं। |
| बेकार keys हटाएँ  | पुरानी keys हटाने से संभावित दुरुपयोग की गुंजाइश कम होती है।        |

---

## प्रमाणीकरण की आम गड़बड़ियाँ

- **401 अनुमति नहीं है**: key मौजूद नहीं है, मान्य नहीं है या बंद workspace से जुड़ी है।
- **403 निषिद्ध**: key है, लेकिन अनुरोधित प्रोवाइडर या मॉडल तक पहुँच नहीं है।
- **429 Too Many Requests**: कुंजी या कार्यक्षेत्र ने सीमा पार की। [अनुरोध सीमाएँ](../api-reference/limits.mdx) देखें।
- **5xx त्रुटियाँ**: exponential backoff के साथ फिर कोशिश करें और समस्या बनी रहने पर [सहायता](https://phaseo.app/help) से संपर्क करें।
