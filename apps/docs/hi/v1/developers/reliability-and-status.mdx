Phaseo स्वस्थ है या नहीं, यह देखने के लिए [स्थिति पेज](https://status.phaseo.app) और `GET /v1/health` जांचें; कोई मॉडल अभी रूट हो सकता है या नहीं, यह देखने के लिए `GET /v1/models`; और कोई रूट आपके विश्वसनीयता लक्ष्य पर खरा उतरता है या नहीं, यह देखने के लिए अपना टेस्ट रन चलाएँ।

## सेवा की मौजूदा स्थिति जांचें

1. मौजूदा घटनाओं और घटनाओं के इतिहास के लिए [Phaseo स्थिति पेज](https://status.phaseo.app) खोलें।
2. Gateway की न्यूनतम स्वास्थ्य जांच के लिए `GET /v1/health` कॉल करें।
3. अगर एक अनुरोध विफल हुआ है, तो पूरी सेवा को डाउन मानने से पहले उसकी अनुरोध ID रखें और उसकी गतिविधि या जनरेशन रिकॉर्ड जांचें।

```bash
curl https://api.phaseo.app/v1/health
```

```json
{
  "status": "ok"
}
```

<Note>
सार्वजनिक स्थिति पेज सेवा का स्वास्थ्य बताता है। Phaseo फ़िलहाल किसी अनुबंधित सार्वजनिक अपटाइम SLA का दावा नहीं करता।
</Note>

## पक्का करें कि मॉडल रूट हो सकता है

Phaseo कैटलॉग में उससे ज़्यादा मॉडल हैं जितने Gateway रूट कर सकता है: कैटलॉग में किसी मॉडल का होना बताता है कि Phaseo उसे ट्रैक करता है, यह नहीं कि उसका सार्वजनिक रूट मौजूद है। `GET /v1/models` डिफ़ॉल्ट रूप से सिर्फ़ वही मॉडल लौटाता है जो अभी रूट हो सकते हैं:

```bash
curl https://api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

जल्द आने वाले और निष्क्रिय मैपिंग भी देखने के लिए `availability=all` जोड़ें। प्रोडक्शन ट्रैफ़िक किसी प्रदाता पंक्ति पर तभी भेजें जब उसका `availability_status` `active` हो और `is_active_gateway` `true` हो। मॉडल पेजों पर स्टेटस आइकन का मतलब जानने के लिए [प्रदाता और Phaseo स्थितियां](../guides/provider-statuses.mdx) देखें।

| स्थिति | इसका अर्थ |
| --- | --- |
| `active` | कम से कम एक सार्वजनिक Gateway रूट अभी उपलब्ध है। |
| `coming_soon` | Phaseo किसी नियोजित या पूर्वावलोकन रूट को ट्रैक करता है, लेकिन वह सार्वजनिक रूप से रूट नहीं हो सकता। |
| `inactive` | कोई ज्ञात रूट अक्षम, अनुपलब्ध, समाप्त या किसी और कारण से रूट होने लायक नहीं है। |
| `not_listed` | इस मॉडल के लिए फ़िलहाल कोई Gateway प्रदाता मैपिंग सूचीबद्ध नहीं है। |

`active` अपटाइम, हर क्षेत्र में ऐक्सेस, या हर वर्कस्पेस के लिए एक जैसी व्यावसायिक शर्तों की गारंटी नहीं देता।

## परफ़ॉर्मेंस मेट्रिक्स समझें

Phaseo का परफ़ॉर्मेंस डेटा Gateway से होकर गए असली अनुरोधों का सारांश है; यह नियंत्रित लैब बेंचमार्क नहीं है।

| मेट्रिक | परिभाषा |
| --- | --- |
| Gateway TTFT | Gateway अनुरोध शुरू होने से लेकर कंटेंट वाले पहले जनरेट किए गए आउटपुट तक। |
| प्रदाता TTFT | प्रदाता को भेजे जाने से लेकर कंटेंट वाले पहले जनरेट किए गए आउटपुट तक। |
| प्रदाता अवधि | प्रदाता को भेजे जाने से लेकर अंतिम प्रतिक्रिया तक। |
| Gateway E2E | Gateway अनुरोध शुरू होने से लेकर पूरा होने तक। |
| Phaseo ओवरहेड | Gateway E2E और प्रदाता अवधि के बीच का गैर-ऋणात्मक अंतर। |
| प्रभावी थ्रूपुट | सभी आउटपुट टोकन को प्रदाता की पूरी अवधि से भाग देकर। |
| आउटपुट गति | पहले के बाद के आउटपुट टोकन को TTFT के बाद के प्रदाता समय से भाग देकर। |

TTFT और आउटपुट गति के लिए ऐसी स्ट्रीमिंग प्रतिक्रिया चाहिए जिसका पहला आउटपुट कंटेंट वाला हो। नॉन-स्ट्रीमिंग अनुरोध फिर भी अवधि और प्रभावी थ्रूपुट में योगदान देता है, लेकिन TTFT में नहीं।

हर मेट्रिक को उसकी समय-सीमा, रूट, क्षेत्र, स्ट्रीमिंग मोड और पर्सेंटाइल के साथ पढ़ें। प्रदाता का लोड, प्रॉम्प्ट की लंबाई, आउटपुट की लंबाई, रीट्राई और नेटवर्क की स्थिति, ये सब नतीजा बदलते हैं।

पूरी परिभाषाओं के लिए [मूल्य और परफ़ॉर्मेंस](../exploring/pricing-performance) और [Phaseo लेटेंसी और थ्रूपुट कैसे मापता है](https://phaseo.app/how-phaseo-measures-latency-throughput) देखें।

## अपने वर्कलोड पर परखें

सार्वजनिक मेट्रिक्स दिशा दिखाते हैं; वे यह साबित नहीं करते कि कोई रूट आपके प्रोडक्शन लक्ष्य पर खरा उतरता है। रोलआउट से पहले एक छोटा, दोहराने योग्य टेस्ट चलाएँ:

1. संवेदनशील प्रोडक्शन डेटा हटाएँ और प्रॉम्प्ट का प्रतिनिधि मिश्रण रखें।
2. मॉडल ID, एंडपॉइंट, प्रदाता प्रतिबंध, क्षेत्र, स्ट्रीमिंग मोड और कंकरेंसी दर्ज करें।
3. एक अनुरोध के बजाय वितरणों की तुलना करने लायक पर्याप्त दोहराव चलाएँ।
4. सफलता दर, Gateway TTFT, प्रदाता अवधि, Gateway E2E, आउटपुट टोकन और अंतिम लागत दर्ज करें।
5. अमान्य कुंजियाँ, अमान्य मॉडल, रेट लिमिट और अनुपलब्ध-प्रदाता विफलताएँ टेस्ट करें।
6. अनुरोध ID और सटीक समय-सीमा सेव करें ताकि कोई दूसरा इंजीनियर नतीजा दोहरा सके।

अनुमति और दर्ज की गई विधि के बिना किसी ग्राहक का नाम, उद्धरण, वर्कलोड नतीजा या विश्वसनीयता प्रतिशत प्रकाशित न करें।

## विफल अनुरोध की जांच करें

1. [सेवा की स्थिति](https://status.phaseo.app) जांचें।
2. पक्का करें कि मॉडल अब भी डिफ़ॉल्ट [`GET /v1/models`](../api-reference/endpoint/models) प्रतिक्रिया में दिखता है, और उसके [एंडपॉइंट](../api-reference/endpoint/model-endpoints) जांचें।
3. [त्रुटियाँ और डीबगिंग](../api-reference/errors) में HTTP स्टेटस और त्रुटि कोड देखें।
4. अस्थायी `429` और `5xx` प्रतिक्रियाओं को सीमित एक्सपोनेंशियल बैकऑफ़ के साथ फिर से आज़माएँ; [रेट लिमिट](../api-reference/limits.mdx) देखें।
5. [सहायता](https://phaseo.app/help) से संपर्क करते समय अनुरोध ID साथ रखें।

किसी एक प्रदाता के विफल होने पर भी अनुरोध चलते रहें, इसके लिए [रूटिंग और फ़ॉलबैक](../guides/routing-and-fallbacks) सेट करें।
