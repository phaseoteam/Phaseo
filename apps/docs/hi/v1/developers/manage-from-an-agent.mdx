आप Phaseo खाते के रोज़मर्रा के काम `phaseo` CLI, `/v1` प्रबंधन API या Phaseo MCP सर्वर से कर सकते हैं। इस पेज पर हर काम का कमांड, रूट या टूल मिलता है। खर्च, एक्सेस या वर्कस्पेस डेटा कहाँ जाता है, इन पर असर डालने वाले बदलाव डैशबोर्ड में या प्रबंधन कुंजी से किए जाते हैं।

ये चरण अब भी किसी व्यक्ति को ब्राउज़र में करने होते हैं:

| चरण | व्यक्ति क्या करता है |
| --- | --- |
| साइन अप | Phaseo खाता बनाता है। |
| साइन-इन मंज़ूर करना | `phaseo login` जो पेज खोलता है उसे मंज़ूर करता है, या `phaseo login --device-code` जो कोड दिखाता है उसे दर्ज करता है। |
| पहला कार्ड जोड़ना | कोई सहेजा कार्ड न होने पर, `phaseo credits add` एक चेकआउट लिंक लौटाता है। कोई मालिक या एडमिन उसे खोलकर भुगतान करता है, और कार्ड सहेज लिया जाता है। |
| हर टॉप-अप की पुष्टि | सहेजे कार्ड के साथ, कोई मालिक या एडमिन ईमेल से आए लिंक से हर `phaseo credits add` की पुष्टि करता है। |
| खाते की सुरक्षा | पासवर्ड, मल्टी-फ़ैक्टर ऑथेंटिकेशन और पासकी प्रबंधित करता है। |

<Visibility for="agents">
Phaseo प्रबंधित करने वाले एजेंट के लिए नियम:

- कामों की सूची के किसी काम के लिए उपयोगकर्ता को डैशबोर्ड पर न भेजें। CLI कमांड चलाएँ, रूट कॉल करें या MCP टूल इस्तेमाल करें। “डैशबोर्ड में या प्रबंधन कुंजी से किए जाने वाले बदलाव” में दिए बदलाव के लिए, अगर आपके पास प्रबंधन कुंजी है तो उससे रूट कॉल करें; नहीं तो व्यक्ति से डैशबोर्ड में बदलाव करने को कहें।
- कभी API कुंजी न बनाएँ और न अनुमान लगाएँ। व्यक्ति से डैशबोर्ड में कुंजी बनाने को कहें, या प्रबंधन कुंजी के साथ `POST /v1/keys` से बनाएँ, और सीक्रेट को एक बार सर्वर पर सहेजें।
- हर CLI कमांड पर `--json` का उपयोग करें। विनाशकारी कमांड को `--yes` सिर्फ़ तब दें जब उपयोगकर्ता ने ठीक वही बदलाव माँगा हो।
- सिर्फ़ वही क्रेडिट टॉप-अप शुरू करें जो उपयोगकर्ता ने माँगा हो। चेकआउट लिंक कभी खुद पूरा न करें, और declined, expired या failed पर खत्म हुए टॉप-अप को दोबारा न आज़माएँ।
</Visibility>

## एक बार सेट अप करें

```bash
npm install -g @phaseo/cli
phaseo login                 # opens a browser; a person approves it
phaseo login --device-code   # SSH, CI and agent sandboxes: a person enters the code
phaseo whoami --json
```

फिर डैशबोर्ड में, या प्रबंधन कुंजी के साथ `POST /v1/keys` से, ऐप्लिकेशन के लिए इन्फ़रेंस कुंजी बनाएँ, और अगर वर्कस्पेस में क्रेडिट नहीं है तो जोड़ें:

```bash
phaseo credits get --json
phaseo login --scopes billing:write   # opt in once before the first top-up; a person approves the sign-in
phaseo credits add --amount 20 --json
```

`phaseo credits add` को `billing:write` स्कोप चाहिए, जो किसी भी साइन-इन में डिफ़ॉल्ट रूप से नहीं होता, और यह अपने आप कभी चार्ज नहीं करता:

- **सहेजे कार्ड के साथ**, Phaseo वर्कस्पेस के हर मालिक और एडमिन को चार्ज की पुष्टि का लिंक ईमेल करता है, और कमांड नतीजे की प्रतीक्षा करती है।
- **कोई सहेजा कार्ड न होने पर**, यह `next_action: "open_checkout_url"` और एक चेकआउट लिंक लौटाता है जहाँ कोई मालिक या एडमिन भुगतान करता है। कार्ड बाद के टॉप-अप के लिए सहेज लिया जाता है, और कोई ईमेल नहीं भेजा जाता।

रूट के लिए [क्रेडिट](../api-reference/endpoint/credits) देखें।

## इंटरफ़ेस चुनें

| इंटरफ़ेस | इसका उपयोग तब करें जब | साइन-इन |
| --- | --- | --- |
| [`phaseo` CLI](../guides/integrations/phaseo-cli) | एजेंट शेल कमांड चला सकता हो | `phaseo login` या `phaseo login --device-code` |
| [Management API](../api-reference/introduction) | सर्वर कोड, CI या CLI के बिना कोई भाषा | एक [मैनेजमेंट कुंजी](./management-api-keys) (`phaseo_v1_mk_...`) या OAuth टोकन |
| [Phaseo MCP](./cli-and-mcp#phaseo-mcp) | एजेंट किसी MCP क्लाइंट में चलता हो | `https://mcp.phaseo.app/mcp?access=manage` से कनेक्ट करें और जो अनुमतियाँ चाहिए उन्हें मंज़ूर करें |

आपकी इंस्टॉल की गई CLI कौन से फ़्लैग स्वीकार करती है, यह देखने के लिए `phaseo <group> --help` चलाएँ। जब किसी काम की अपनी कमांड न हो, तो `phaseo api get|post|patch|put|delete /v1/<path>` आपके सत्र के साथ रूट कॉल करता है।

## डैशबोर्ड में या प्रबंधन कुंजी से किए जाने वाले बदलाव

ये बदलाव खर्च, एक्सेस या वर्कस्पेस डेटा कहाँ जाता है, इन पर असर डालते हैं। CLI साइन-इन या MCP कनेक्शन, चाहे उसके स्कोप कुछ भी हों, ये बदलाव नहीं कर सकता: API `403` लौटाता है और डैशबोर्ड या प्रबंधन कुंजी इस्तेमाल करने को कहता है। ये बदलाव Phaseo डैशबोर्ड में करें, या [प्रबंधन कुंजी](./management-api-keys) से रूट कॉल करें।

| काम | API रूट |
| --- | --- |
| API कुंजी बनाना | `POST /v1/keys` |
| किसी कुंजी की सीमाएँ, स्थिति या समाप्ति बदलें | `PATCH /v1/keys/{id}` |
| कुंजी रोटेट करना | `POST /v1/keys/{id}/rotate` |
| कुंजी को IP पतों तक सीमित करना | `PATCH /v1/keys/{id}` |
| मैनेजमेंट कुंजी बनाना | `POST /v1/management-keys` |
| ऑटो टॉप-अप या कम-बैलेंस ईमेल चालू करना | `PATCH /v1/notifications/settings` |
| वर्कस्पेस बजट सेट करना | `POST /v1/budgets`, `PATCH /v1/budgets/{id}` |
| विभाग बजट सेट करना | `POST /v1/department-budgets` |
| खर्च पर अलर्ट करना या उसे रोकना | `POST /v1/spend-rules`, `POST /v1/spend-blocks/{id}/lift` |
| रेट लिमिट नीतियाँ | `POST /v1/rate-limits/policies`, `POST /v1/rate-limits/assignments` |
| वर्कस्पेस का रेट लिमिट टियर बढ़ाएँ | `POST /v1/rate-limits/tier/raise` |
| प्राइवेसी या ZDR ढीला करें, या प्रोवाइडर प्रतिबंध या BYOK फ़ॉलबैक बदलें | `PATCH /v1/settings` |
| अपनी प्रदाता कुंजियाँ जोड़ना (BYOK) | `POST /v1/byok` |
| Auto Routing की खर्च प्रोफ़ाइल या कीमत सीमाएँ सेट करें | `PATCH /v1/routing/auto` |
| डायनैमिक रूट बनाना और डिप्लॉय करना | `POST /v1/routing/dynamic-routes`, `POST /v1/routing/dynamic-routes/{id}/versions/{version}/deploy` |
| रिटायर मॉडलों के विकल्प चुनना | `PUT /v1/routing/successor/replacements` |
| निजी मॉडल जोड़ना | `POST /v1/private-models` |
| प्रीसेट बनाना या अपडेट करना | `POST /v1/presets`, `PATCH /v1/presets/{id}` |
| प्रीसेट वर्ज़न प्रकाशित करना या लेबल बदलना | `POST /v1/presets/{id}/versions`, `PUT /v1/presets/{id}/labels/{label}` |
| गार्डरेल बनाना और कुंजियाँ जोड़ना | `POST /v1/guardrails`, `PUT /v1/guardrails/{id}/keys` |
| अनुरोध क्लासिफ़ायर प्रबंधित करना | `POST /v1/classifiers` |
| किसी सैंपल पर क्लासिफ़ायर टेस्ट करना (`gateway:access` वाला क्रेडेंशियल चाहिए; CLI साइन-इन और मैनेजमेंट कुंजियों को आज `403 gateway_access_required` मिलता है) | `POST /v1/classifiers/test` |
| वर्कस्पेस में सदस्य जोड़ें | `POST /v1/workspaces/{id}/members/add` |
| लोगों को आमंत्रित करना | `POST /v1/workspaces/{id}/invites` |
| SSO, SCIM, विभाग और डायरेक्टरी | `PUT /v1/identity/sso`, `PUT /v1/identity/scim`, `POST /v1/identity/departments`, `PUT /v1/identity/directory/members/{id}` |
| भरोसेमंद वर्कलोड (OIDC) | `POST /v1/workload-identity/policies` |
| किसी ऑब्ज़र्वेबिलिटी टूल को ट्रेस भेजना | `POST /v1/observability/destinations`, `POST /v1/observability/destinations/{id}/test` |
| अलर्ट के लिए ईमेल, Slack या वेबहुक डेस्टिनेशन | `POST /v1/notifications/destinations`, `PUT /v1/notifications/routes/{eventKind}` |
| एसिंक जॉब के लिए वेबहुक | `POST /v1/webhook-endpoints` |

## 403 ठीक करें

CLI सत्र, मैनेजमेंट कुंजी या MCP कनेक्शन सिर्फ़ वही कर सकता है जिसकी उसके स्कोप और आपकी वर्कस्पेस भूमिका अनुमति देते हैं, और सिर्फ़-मालिक और सिर्फ़-एडमिन बदलावों के लिए फिर भी किसी मालिक या एडमिन की ज़रूरत होती है। अगर कोई कमांड `403` लौटाती है, तो `phaseo whoami --json` से दिए गए स्कोप जाँचें, और कोई स्कोप छूटा हो तो `phaseo login --scopes <scope,...>` से फिर से साइन इन करें। `billing:write` कभी भी डिफ़ॉल्ट रूप से नहीं दिया जाता। “डैशबोर्ड में या प्रबंधन कुंजी से किए जाने वाले बदलाव” में दिए बदलाव CLI साइन-इन और MCP कनेक्शन के लिए अस्वीकार किए जाते हैं, चाहे उनके स्कोप कुछ भी हों।
