प्रोडक्शन वर्कलोड में Gateway अपनाना आसान है, अगर आपकी बुनियाद मज़बूत हो। रेज़िलिएंस, सुरक्षा और रखरखाव बेहतर करने के लिए नीचे दिए सुझाव अपनाएँ।

---

## आर्किटेक्चर

-   **प्रोवाइडर लॉजिक अलग रखें।** Gateway कॉल को किसी समर्पित service या SDK में रखें ताकि बदलाव सीमित रहें।
-   **संभव हो तो responses को stream करें।** Tokens आते ही UI में भेजकर assistant की latency घटाएँ।
-   **गैर-ज़रूरी jobs को batch करें।** ट्रैफ़िक के अचानक बढ़ने को संभालने के लिए बैकग्राउंड generation या evaluation को queue करें।

---

## सुरक्षा

-   प्रोडक्शन में API keys को `.env` फ़ाइलों के बजाय secrets manager (AWS Secrets Manager, Doppler, 1Password) में रखें।
-   अपने API पर request signing चालू करें ताकि client apps Gateway keys उजागर न करें।
-   Credentials लीक होने से बचाने के लिए logs में केवल छोटी की हुई keys रखें (जैसे `sk_prod_abcd...`)।

---

## विश्वसनीयता

-   सभी retry किए जा सकने वाले errors (HTTP 429 या 5xx) के लिए jitter के साथ exponential backoff लागू करें।
-   रेट-लिमिट वाले अनुरोध को फिर भेजने से पहले [`Retry-After`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Retry-After) header का सम्मान करें।
-   एक provider से दूसरे पर अपने-आप हुए failover पहचानने के लिए provider metadata देखें।
