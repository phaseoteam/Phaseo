किसी एक TypeScript अनुरोध को `phaseo:web_search` टूल और एक JSON Schema दें, ताकि मॉडल जवाब देने से पहले खोज करे और अपने स्रोतों के साथ एक ब्रीफ़ लौटाए। अंत में आपके पास एक स्क्रिप्ट होगी जो वैलिडेट किया गया `{ summary, sources }` ऑब्जेक्ट और डीबग करने के लिए ज़रूरी ID और सर्च काउंटर प्रिंट करती है।

प्रीसेट और डोमेन को अपने से बदलने के बाद स्क्रिप्ट प्रोडक्शन के लिए तैयार है। सर्च के नतीजे अविश्वसनीय वेब कंटेंट हैं: आउटपुट वैलिडेट करें और उनमें मिले निर्देशों का पालन न करें।

## इसे बनाएँ

<Steps>
<Step title="प्रीसेट बनाएँ">

**सेटिंग्स → प्रीसेट** में `research-brief` बनाएँ, जिसमें मॉडल, प्रदाता प्राथमिकताएँ, रीज़निंग सेटिंग्स और सिस्टम प्रॉम्प्ट हों जिन्हें हर कॉलर को साझा करना चाहिए। मॉडल को टूल और JSON Schema आउटपुट सपोर्ट करने चाहिए।

</Step>
<Step title="SDK इंस्टॉल करें">

```bash
npm install @phaseo/sdk zod
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="स्क्रिप्ट लिखें">

```ts research-brief.ts
import Phaseo from "@phaseo/sdk";
import { z } from "zod";

const gateway = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const Brief = z
  .object({
    summary: z.string().min(1),
    sources: z
      .array(z.object({ title: z.string(), url: z.string().url() }).strict())
      .min(1),
  })
  .strict();

const response = await gateway.generateResponse({
  model: "@research-brief",
  input: "Find the latest public changes to Phaseo webhook delivery behavior and summarize them.",
  tools: [
    {
      type: "phaseo:web_search",
      parameters: {
        allowed_domains: ["phaseo.app"],
        max_results: 5,
        include_highlights: true,
      },
    },
  ],
  tool_choice: "phaseo:web_search",
  text: {
    format: {
      type: "json_schema",
      name: "research_brief",
      strict: true,
      schema: {
        type: "object",
        required: ["summary", "sources"],
        properties: {
          summary: { type: "string" },
          sources: {
            type: "array",
            minItems: 1,
            items: {
              type: "object",
              required: ["title", "url"],
              properties: {
                title: { type: "string" },
                url: { type: "string", format: "uri" },
              },
              additionalProperties: false,
            },
          },
        },
        additionalProperties: false,
      },
    },
  },
  plugins: [{ id: "response-healing" }],
  meta: true,
});

const text = (response.output ?? [])
  .filter((item) => item.type === "message")
  .flatMap((item) => item.content ?? [])
  .filter((part) => part.type === "output_text")
  .map((part) => part.text ?? "")
  .join("");

const brief = Brief.parse(JSON.parse(text));

console.log({
  responseId: response.id,
  model: response.model,
  routing: response.meta?.routing,
  pluginExecutions: response.meta?.plugin_executions,
  serverToolUse: response.usage?.server_tool_use,
});
console.log(brief);
```

| फ़ील्ड | क्या करता है |
| --- | --- |
| `phaseo:web_search` के साथ `tools` | सर्च Phaseo चलाता है, चाहे प्रदाता के पास अपनी सर्च हो या न हो। क्वेरी मॉडल लिखता है। |
| `allowed_domains` | नतीजों को आपके अपने स्रोतों तक सीमित करता है। हर पैरामीटर [वेब सर्च गाइड](../guides/server-tools/web-search#parameters) में है। |
| `tool_choice: "phaseo:web_search"` | मॉडल को याददाश्त से जवाब देने के बजाय खोज करने पर मजबूर करता है। |
| `text.format` | जवाब के लिए JSON Schema। |
| `plugins` | लगभग-मान्य JSON ठीक करता है; [रिस्पॉन्स हीलिंग](./response-healing-for-structured-json) देखें। |
| `meta: true` | `meta.routing` और `meta.plugin_executions` जोड़ता है। |

</Step>
<Step title="इसे चलाएँ">

```bash
npx tsx research-brief.ts
```

</Step>
</Steps>

## जाँचें कि यह काम कर गया

- `serverToolUse.web_search_requests` कम से कम `1` है, यानी सर्च चली।
- `brief.sources` में `phaseo.app` के URL हैं।
- `routing.selected_provider` प्रदाता का नाम बताता है, और `pluginExecutions` दिखाता है कि हीलिंग ने कुछ बदला या नहीं।
- **सेटिंग्स → उपयोग → लॉग्स** में, अनुरोध का **Web search observability** सेक्शन मैनेज्ड सर्च, नतीजे और उद्धरण दिखाता है।

अगर नतीजे गलत लगें, तो ओवरराइड जोड़ने के बजाय लॉग में दिखी जानकारी के आधार पर प्रीसेट या टूल पैरामीटर ठीक करें। [वेब सर्च डीबग करें](./web-search-debugging) आम मामलों की सूची देता है। खोजबीन वाली, ऊँचे temperature वाली रिसर्च को इस निर्धारित प्रीसेट से अलग प्रीसेट में रखें, ताकि उनकी रूटिंग की तुलना आसान रहे।
