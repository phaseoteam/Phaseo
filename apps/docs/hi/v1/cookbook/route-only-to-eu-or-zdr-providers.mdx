किसी एक अनुरोध के `provider` ऑब्जेक्ट में रेज़िडेंसी और <Tooltip tip="ज़ीरो डेटा रिटेंशन: प्रदाता प्रॉम्प्ट या आउटपुट नहीं रखता।">ZDR</Tooltip> आवश्यकताएँ जोड़ें, और Phaseo बाकी को रैंक करने से पहले हर उस प्रदाता ऑफ़र को हटा देता है जो उन्हें पूरा नहीं करता। अंत में एक वर्कफ़्लो सिर्फ़ EU या ZDR-सक्षम प्रदाताओं पर चलेगा, पूरे वर्कस्पेस की नीति बदले बिना।

यह अनुरोध प्रोडक्शन के लिए तैयार है। अगर मॉडल का कोई भी प्रदाता हर आवश्यकता पूरी नहीं करता, तो किसी भी प्रदाता को कॉल किए जाने से पहले अनुरोध विफल हो जाता है, इसलिए पहले उपलब्धता जाँचें।

| फ़ील्ड | सिर्फ़ ऐसे प्रदाता रखता है जो |
| --- | --- |
| `required_execution_region: "eu"` | मॉडल को EU में चलाते हैं |
| `required_data_region: "eu"` | प्रॉम्प्ट और कम्प्लीशन डेटा को EU में संभालते हैं |
| `require_zero_data_retention: true` | ज़ीरो-डेटा-रिटेंशन आवश्यकताएँ पूरी करते हैं |

## प्रतिबंधित अनुरोध भेजें

<Steps>
<Step title="जाँचें कि कोई प्रदाता योग्य है">

मॉडल के पेज पर, प्रदाता कार्ड **OpenAI EU** या **Google Vertex EU** जैसे क्षेत्रीय ऑफ़र, ZDR सपोर्ट, और हर प्रदाता के डेटा-नीति नोट और स्रोत दिखाते हैं। EU के लिए, आप यह भी सूचीबद्ध कर सकते हैं कि EU गेटवे क्या सर्व करता है:

```bash
curl https://eu.api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

</Step>
<Step title="सिर्फ़ ज़रूरी आवश्यकताएँ जोड़ें">

हर आवश्यकता पूल को छोटा करती है, इसलिए अनुरोध किसी महँगे क्षेत्रीय ऑफ़र पर जा सकता है या कोई प्रदाता बचे ही नहीं। सिर्फ़ वही भेजें जो आपकी नीति माँगती है:

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5.6-luna",
    "input": "Summarize the ticket in one line.",
    "provider": {
      "required_execution_region": "eu",
      "required_data_region": "eu"
    },
    "meta": true
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "openai/gpt-5.6-luna",
  input: "Summarize the ticket in one line.",
  provider: {
    required_execution_region: "eu",
    required_data_region: "eu",
  },
  meta: true,
});

console.log(response.meta?.routing);
```

```python Python
import os

from phaseo import Phaseo

client = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

response = client.generate_response(
    {
        "model": "openai/gpt-5.6-luna",
        "input": "Summarize the ticket in one line.",
        "provider": {
            "required_execution_region": "eu",
            "required_data_region": "eu",
        },
        "meta": True,
    }
)

print(response["meta"]["routing"]["selected_provider"])
```
</CodeGroup>

ZDR भी ज़रूरी करने के लिए, `"require_zero_data_retention": true` जोड़ें। तीनों के साथ, मॉडल के पास कम से कम एक ऐसा EU प्रदाता होना चाहिए जो ZDR भी पूरा करता हो।

</Step>
<Step title="जाँचें कि यह कहाँ चला">

`meta.routing.selected_provider` उस प्रदाता का नाम बताता है जिसने इसे सर्व किया, उदाहरण के लिए `openai-eu`। **सेटिंग्स → उपयोग → लॉग्स** में अनुरोध ज़रूरी क्षेत्र और चुना गया प्रदाता दर्ज करता है।

</Step>
</Steps>

## अनुरोध फ़ील्ड, EU गेटवे या वर्कस्पेस सेटिंग्स में से चुनें

| उपयोग करें | कब |
| --- | --- |
| `api.phaseo.app` पर ये अनुरोध फ़ील्ड | नियम किसी एक वर्कफ़्लो, ग्राहक या अनुरोध पर लागू होता है। हर एंडपॉइंट और सुविधा उपलब्ध रहती है। |
| [`eu.api.phaseo.app`](../guides/regional-routing) | किसी सेवा का हर टेक्स्ट अनुरोध EU में ही रहना चाहिए। होस्टनेम क्षेत्र लागू करता है और मीडिया इनपुट, Phaseo सर्वर टूल और प्रदाता-होस्टेड टूल भी अस्वीकार करता है। वहाँ किसी दूसरे क्षेत्र के लिए `required_execution_region` या `required_data_region` भेजने पर `deployment_region_conflict` वजह के साथ `400 validation_error` लौटता है। |
| **सेटिंग्स → गोपनीयता** | नियम वर्कस्पेस के हर अनुरोध पर लागू होता है। |

क्षेत्रीय रूटिंग यह सीमित करती है कि मॉडल कॉल कौन से प्रदाता संभालें। यह अभी शुरू से अंत तक डेटा रेज़िडेंसी की गारंटी नहीं है; [क्षेत्र से बाहर क्या रहता है](../guides/regional-routing#what-stays-outside-the-region) साझा सिस्टम सूचीबद्ध करता है। रेज़िडेंसी नियम के बिना प्रदाताओं को सीमित करने के लिए, [प्रदाता पिन करें या अनदेखा करें](./pin-or-ignore-providers-per-request) देखें।
