अपनी रिपॉज़िटरी में एक `SKILL.md` जोड़ें ताकि कोडिंग एजेंट Phaseo को उसी तरह कॉल करें जैसा आपका प्रोजेक्ट चाहता है: वही बेस URL, कुंजी वेरिएबल, एंडपॉइंट, मंज़ूर मॉडल और लॉगिंग। अंत में आपके पास सार्वजनिक Phaseo स्किल इंस्टॉल होंगी, उनके ऊपर एक प्रोजेक्ट स्किल होगी, और एक साझा क्लाइंट मॉड्यूल होगा जिसकी ओर स्किल इशारा करती है।

नीचे दी गई स्किल और मॉड्यूल, मॉडल ID और प्रीसेट नामों को अपने नामों से बदलने के बाद प्रोडक्शन के लिए तैयार हैं।

<Steps>
<Step title="सार्वजनिक Phaseo स्किल इंस्टॉल करें">

<Visibility for="humans">
सार्वजनिक स्किल Gateway, SDK, प्रीसेट, रूटिंग और माइग्रेशन को कवर करती हैं। उन्हें [`phaseo.app/docs`](https://phaseo.app/docs/.well-known/agent-skills/index.json) से इंस्टॉल करें:
</Visibility>

<Visibility for="agents">
प्रोजेक्ट-लोकल निर्देश लिखने से पहले [`phaseo.app/docs`](https://phaseo.app/docs/.well-known/agent-skills/index.json) से सार्वजनिक Phaseo स्किल इंस्टॉल करें:
</Visibility>

```bash
npx skills add https://phaseo.app/docs --agent codex --skill '*'
```

`--agent` को उस एजेंट में बदलें जिसे आपकी टीम इस्तेमाल करती है। अपनी `SKILL.md` में सिर्फ़ प्रोजेक्ट-विशेष नियम रखें।

</Step>
<Step title="SDK इंस्टॉल करें">

<CodeGroup>
```bash npm
npm install @phaseo/sdk
```

```bash pnpm
pnpm add @phaseo/sdk
```

```bash yarn
yarn add @phaseo/sdk
```

```bash bun
bun add @phaseo/sdk
```

```bash Python
pip install phaseo
```
</CodeGroup>

</Step>
<Step title="एक साझा क्लाइंट जोड़ें">

एजेंट बड़े रैपर की तुलना में छोटे, साफ़ हेल्पर का ज़्यादा भरोसेमंद ढंग से दोबारा उपयोग करते हैं। क्लाइंट को एक मॉड्यूल में रखें और हर जगह उसी को इंपोर्ट करें:

```ts src/lib/phaseo.ts
import Phaseo from "@phaseo/sdk";

export const gateway = new Phaseo({
  apiKey: process.env.PHASEO_API_KEY!,
});
```

आप जिस भी सरफ़ेस का उपयोग करते हैं, जैसे टेक्स्ट जनरेशन, एम्बेडिंग, इमेज जनरेशन या एसिंक वीडियो, हर एक के लिए एक ही कॉल पाथ रखें।

</Step>
<Step title="प्रोजेक्ट स्किल लिखें">

रिपॉज़िटरी रूट पर या उस स्किल फ़ोल्डर में `SKILL.md` बनाएँ जिसे आपका एजेंट पढ़ता है (उदाहरण के लिए `.agents/skills/phaseo-project/SKILL.md`)। एजेंट `name` और `description` फ़्रंटमैटर पढ़कर तय करता है कि स्किल कब लोड करनी है:

```md SKILL.md
---
name: phaseo-project
description: "How this repository calls Phaseo Gateway: client module, endpoint, approved models and presets, logging and async jobs. Use when adding or changing any Phaseo call in this repo."
---

# Phaseo in this repository

- Import the client from `src/lib/phaseo.ts`. Never create another one.
- The base URL is `https://api.phaseo.app/v1`. The key is in `PHASEO_API_KEY`; never hard-code it or send it to the browser.
- Use the Responses API (`POST /v1/responses`) for new text features.
- Approved models: `openai/gpt-6-astra` for drafts, `anthropic/claude-sonnet-5.5` for reviews. Ask before adding another.
- Prefer the `@support-triage` preset for support features; pass it as `model`.
- Log the response `id` and `model` on every call, and `generation_id` from error bodies.
- For async video jobs, store the returned ID and poll status until it is terminal.
- Validate any model-generated tool arguments before acting on them.
```

</Step>
</Steps>

## जाँचें कि यह काम कर गया

अपने एजेंट से कोई छोटी Phaseo सुविधा जोड़ने को कहें, जैसे "summarise a ticket with Phaseo"। बदलाव में `src/lib/phaseo.ts` इंपोर्ट होना चाहिए, `PHASEO_API_KEY` पढ़ा जाना चाहिए, कोई मंज़ूर मॉडल या प्रीसेट इस्तेमाल होना चाहिए, और प्रतिक्रिया ID लॉग होना चाहिए। अगर ऐसा नहीं होता, तो शायद स्किल का `description` अनुरोध से मेल नहीं खाता: उसमें वे काम वाले शब्द लिखें जिन्हें आपकी टीम इस्तेमाल करती है।

## स्किल में क्या रखें

उन सवालों के जवाब दें जिनमें एजेंट का सबसे ज़्यादा समय लगता है, और कुछ नहीं:

| सवाल | उदाहरण जवाब |
| --- | --- |
| कौन सा एंडपॉइंट परिवार? | टेक्स्ट के लिए Responses, खोज के लिए Embeddings |
| क्रेडेंशियल कहाँ हैं? | `PHASEO_API_KEY`, सिर्फ़ सर्वर-साइड |
| कौन से मॉडल ID या प्रीसेट मंज़ूर हैं? | `org/model` रूप में एक छोटी सूची |
| क्या लॉग होता है? | प्रतिक्रिया का `id`, `model`, और त्रुटियों पर `generation_id` |
| एसिंक जॉब कैसे ट्रैक होते हैं? | ID सहेजें, अंतिम स्थिति तक पोल करें |
