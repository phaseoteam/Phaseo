`toolExecution.toolConcurrency` सेट करें, ताकि TypeScript Agent SDK एक मॉडल टर्न की कई स्वतंत्र टूल कॉल एक के बाद एक चलाने के बजाय एक साथ चलाए। अंत में आपके पास ऐसा एजेंट होगा जो दस्तावेज़, स्टेटस और इंसिडेंट का संदर्भ समानांतर रूप से जुटाता है, और फिर भी नतीजों को उसी क्रम में दर्ज करता है जिसमें मॉडल ने उन्हें माँगा था।

टूल तय नमूना डेटा लौटाते हैं, इसलिए यह स्क्रिप्ट उदाहरण के लिए है; इन्हें अपने सिर्फ़ पढ़ने वाले lookup से बदलें। पैकेज किया गया संस्करण `packages/sdk/agent-sdk-ts/examples/parallel-tool-agent.ts` में है।

## इसे बनाएँ

<Steps>
<Step title="इंस्टॉल करें">

```bash
npm install @phaseo/agent-sdk zod
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="एजेंट लिखें">

```ts parallel-agent.ts
import { z } from "zod";
import { createAgent, createGatewayAgentClient, defineTool } from "@phaseo/agent-sdk";

const fetchDocs = defineTool({
  id: "fetch-docs",
  description: "Return a short summary of one Phaseo docs page by slug.",
  parameters: {
    type: "object",
    properties: { slug: { type: "string" } },
    required: ["slug"],
    additionalProperties: false,
  },
  inputSchema: z.object({ slug: z.string().regex(/^[a-z0-9/-]{1,80}$/) }).strict(),
  parallelSafe: true,
  timeoutMs: 5_000,
  async execute({ slug }) {
    return { slug, summary: `Docs summary for ${slug}` };
  },
});

const fetchStatus = defineTool({
  id: "fetch-status",
  description: "Return the status of one Phaseo component.",
  parameters: {
    type: "object",
    properties: { component: { type: "string", enum: ["gateway", "dashboard", "async-jobs"] } },
    required: ["component"],
    additionalProperties: false,
  },
  inputSchema: z.object({ component: z.enum(["gateway", "dashboard", "async-jobs"]) }).strict(),
  parallelSafe: true,
  timeoutMs: 5_000,
  async execute({ component }) {
    return { component, status: "operational" };
  },
});

const fetchIncidents = defineTool({
  id: "fetch-incidents",
  description: "Return the open incident count for one service.",
  parameters: {
    type: "object",
    properties: { service: { type: "string", enum: ["gateway", "dashboard", "async-jobs"] } },
    required: ["service"],
    additionalProperties: false,
  },
  inputSchema: z.object({ service: z.enum(["gateway", "dashboard", "async-jobs"]) }).strict(),
  parallelSafe: true,
  timeoutMs: 5_000,
  async execute({ service }) {
    return { service, openIncidents: 0 };
  },
});

const agent = createAgent({
  id: "parallel-tool-agent",
  model: "openai/gpt-6-astra",
  instructions:
    "Use the available tools to gather context, then return one concise operational summary.",
  tools: [fetchDocs, fetchStatus, fetchIncidents],
  toolExecution: { toolConcurrency: 3 },
  maxSteps: 4,
});

const result = await agent.run({
  input:
    "Fetch the presets docs, the gateway status, and the async-jobs incident digest, then summarize the current state.",
  client: createGatewayAgentClient({
    clientOptions: { apiKey: process.env.PHASEO_API_KEY! },
    parallelToolCalls: true,
  }),
  onEvent(event) {
    if (event.type === "tool.started" || event.type === "tool.completed") {
      console.log(event.type, event.toolName, event.timestamp);
    }
  },
});

console.log(result.output);
```

</Step>

## जाँचें कि यह काम किया

- जब मॉडल एक ही टर्न में तीनों टूल माँगता है, तो तीनों `tool.started` लाइनें मेल खाती `tool.completed` लाइनों से पहले, करीबी टाइमस्टैम्प के साथ, प्रिंट होती हैं।
- `result.messages` टूल नतीजों को मॉडल की टूल कॉल के क्रम में दिखाता है, चाहे वे किसी भी क्रम में पूरे हुए हों।
- रन `result.output` में एक सारांश के साथ खत्म होता है।

## क्या साथ-साथ चलता है

| सेटिंग | असर |
| --- | --- |
| `toolExecution.toolConcurrency` | एक टर्न की इतनी टूल कॉल तक एक साथ चलती हैं। डिफ़ॉल्ट `1`। |
| टर्न के हर टूल पर `parallelSafe: true` | 8 तक एक साथ चलती हैं, या `toolConcurrency` अगर वह ज़्यादा है। इसे सिर्फ़ सिर्फ़-पढ़ने वाले टूल के लिए इस्तेमाल करें। |
| किसी टूल पर `timeoutMs` | इतने समय के बाद वह कॉल विफल हो जाती है, ताकि एक अटकी हुई निर्भरता सारे स्लॉट न रोक सके। |
| गेटवे क्लाइंट पर `parallelToolCalls` | मॉडल को एक टर्न में कई टूल कॉल माँगने देता है; वह ऐसा करता है या नहीं, यह मॉडल पर निर्भर है। |

`tool.started` और `tool.completed` अब भी हर कॉल के लिए चलते हैं, और टूल चरण पूरा होने पर रन चेकपॉइंट बनाता है।

## इसे सुरक्षित रखें

समवर्तिता सिर्फ़ उन टूल के लिए इस्तेमाल करें जो एक-दूसरे के आउटपुट पर निर्भर नहीं हैं और साझा स्थिति नहीं बदलते। `2` या `3` से शुरू करें, टूल को कम साइड इफ़ेक्ट वाला और idempotent रखें, और ऊपर की तरह हर आर्ग्युमेंट को `inputSchema` से सत्यापित करें। `state` एक्सेसर, जैसा [टिकाऊ लूप](./agent-sdk-durable-loop) में है, सिर्फ़ तब जोड़ें जब आपको रन फिर से शुरू करने हों। इस पर भरोसा करने से पहले, कई टूल वाले टर्न को कवर करने वाले अपने टेस्ट चलाएँ और नतीजों का क्रम जाँचें।
