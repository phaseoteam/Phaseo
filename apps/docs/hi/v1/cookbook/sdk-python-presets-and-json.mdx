Python से JSON Schema के साथ एक डैशबोर्ड प्रीसेट कॉल करें, फिर जवाब को वैलिडेट करें और डीबग करने के लिए ज़रूरी ID लॉग करें। अंत में आपके पास एक स्क्रिप्ट होगी जो `"model": "@release-summary"` भेजती है, `{"summary": ..., "risk_level": ...}` वापस पाती है, और उस अनुरोध के प्रदाता और प्लगइन विवरण प्रिंट करती है।

प्रीसेट और स्कीमा को अपने से बदलने के बाद स्क्रिप्ट प्रोडक्शन के लिए तैयार है। वैलिडेशन वाला चरण रहने दें: हीलिंग सिंटैक्स ठीक करती है, कंटेंट नहीं।

## इसे बनाएँ

<Steps>
<Step title="प्रीसेट बनाएँ">

**सेटिंग्स → प्रीसेट** में, `release-summary` बनाएँ, जिसमें सिस्टम प्रॉम्प्ट, मॉडल या मंज़ूर मॉडल, प्रदाता प्राथमिकताएँ, रीज़निंग सेटिंग्स और `temperature` हों जिन्हें हर कॉलर को साझा करना चाहिए। तब Python कोड सिर्फ़ वही भेजता है जो बदलता है। [प्रीसेट](../guides/presets) बताता है कि प्रीसेट अनुरोध के साथ कैसे मिलता है।

</Step>
<Step title="SDK इंस्टॉल करें">

```bash
pip install phaseo
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="स्क्रिप्ट लिखें">

```python release_summary.py
import json
import os

from phaseo import Phaseo

# Create one client and reuse it.
gateway = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

SCHEMA = {
    "type": "object",
    "properties": {
        "summary": {"type": "string"},
        "risk_level": {"type": "string", "enum": ["low", "medium", "high"]},
    },
    "required": ["summary", "risk_level"],
    "additionalProperties": False,
}


def output_text(response: dict) -> str:
    return "".join(
        part.get("text", "")
        for item in response.get("output", [])
        if item.get("type") == "message"
        for part in item.get("content", [])
        if part.get("type") == "output_text"
    )


def validate(payload: dict) -> dict:
    if set(payload) != {"summary", "risk_level"}:
        raise ValueError(f"unexpected keys: {sorted(payload)}")
    if not isinstance(payload["summary"], str) or not payload["summary"]:
        raise ValueError("summary must be a non-empty string")
    if payload["risk_level"] not in ("low", "medium", "high"):
        raise ValueError("risk_level must be low, medium or high")
    return payload


response = gateway.generate_response(
    {
        "model": "@release-summary",
        "input": "Summarize the last 24 hours of deployment activity.",
        "text": {
            "format": {
                "type": "json_schema",
                "name": "release_summary",
                "strict": True,
                "schema": SCHEMA,
            }
        },
        "plugins": [{"id": "response-healing"}],
        "meta": True,
    }
)

if response.get("status") != "completed":
    raise RuntimeError(f"response {response.get('id')} ended as {response.get('status')}")

payload = validate(json.loads(output_text(response)))
meta = response.get("meta", {})

print("response_id:", response.get("id"))
print("model:", response.get("model"))
print("selected_provider:", meta.get("routing", {}).get("selected_provider"))
print("plugin_executions:", meta.get("plugin_executions"))
print(payload)
```

| फ़ील्ड | क्या करता है |
| --- | --- |
| `"model": "@release-summary"` | प्रीसेट का उपयोग करता है। कोई अलग `preset` फ़ील्ड नहीं है। |
| `text.format` | यह JSON Schema माँगता है। Chat Completions पर यह `response_format` में जाता है; [संरचित आउटपुट](../guides/structured-outputs) देखें। |
| `plugins` | लगभग-मान्य JSON ठीक करता है; [रिस्पॉन्स हीलिंग](./response-healing-for-structured-json) देखें। |
| `meta: true` | प्रतिक्रिया में `meta.routing` और `meta.plugin_executions` जोड़ता है। |

## जाँचें कि यह काम कर गया

स्क्रिप्ट प्रतिक्रिया ID, जवाब देने वाला मॉडल और प्रदाता, प्लगइन रिकॉर्ड, और `summary` तथा `low`, `medium` या `high` में से एक वाली dict प्रिंट करती है। रूटिंग विवरण के साथ वही अनुरोध देखने के लिए **सेटिंग्स → उपयोग → लॉग्स** में प्रतिक्रिया ID खोजें।

प्रीसेट के मंज़ूर मॉडलों से बाहर का मॉडल `validation_error` (कीवर्ड `preset_model_not_allowed`) के साथ विफल होता है। `validate()` से आया `ValueError` का मतलब है कि JSON पार्स हो गया लेकिन कंटेंट गलत था: रीट्राई जोड़ने के बजाय स्कीमा या प्रॉम्प्ट को सख्त करें।

## ओवरराइड करने से पहले डीबग करें

अगर कोई अनुरोध आपकी उम्मीद से अलग रूट होता है, तो उसे लॉग में खोलें, **Routing observability** और प्लगइन रिकॉर्ड पढ़ें, और प्रीसेट तभी बदलें जब लॉग से पता चल जाए कि क्या हुआ। एक अनुरोध पर इनलाइन ओवरराइड का ढेर लगाने से प्रीसेट का मकसद ही खत्म हो जाता है; अगर किसी कॉलर को सच में अलग व्यवहार चाहिए, तो उसे उसका अपना प्रीसेट दें।
