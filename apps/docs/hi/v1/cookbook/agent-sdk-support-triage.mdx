एक TypeScript ट्राइएज एजेंट बनाएँ जिसका मॉडल, प्रॉम्प्ट और प्रदाता नियम डैशबोर्ड प्रीसेट से आते हैं, ताकि कोड सिर्फ़ वर्कफ़्लो संभाले। अंत में यह सख्त JSON ट्राइएज निर्णय लौटाता है, जिन मामलों में किसी व्यक्ति की ज़रूरत है उन्हें रोकता है, मॉडल कॉल को सीमित बार दोबारा आज़माता है, और गेटवे विफलताओं को उन ID के साथ लॉग करता है जिनसे आप उन्हें खोज सकें।

प्रीसेट बन जाने और रुके हुए रन संग्रहीत करने के बाद, जैसा [टिकाऊ लूप](./agent-sdk-durable-loop) में है, यह स्क्रिप्ट प्रोडक्शन के लिए तैयार है। पैकेज किया गया संस्करण `packages/sdk/agent-sdk-ts/examples/support-triage-agent.ts` में है।

## इसे बनाएँ

<Steps>
<Step title="प्रीसेट बनाएँ">

**सेटिंग → प्रीसेट** में `support-triage` बनाएँ, जिसमें रूट किया गया मॉडल, प्रदाता प्राथमिकताएँ, सपोर्ट सिस्टम प्रॉम्प्ट और स्थिर डिकोडिंग पैरामीटर हों। मॉडल को JSON Schema आउटपुट का समर्थन करना चाहिए। [प्रीसेट](../guides/presets) बताता है कि प्रीसेट हर अनुरोध के साथ कैसे मिलता है।

</Step>
<Step title="इंस्टॉल करें">

<Step title="एजेंट लिखें">

```ts triage-agent.ts
import { z } from "zod";
import { AgentGatewayError, createAgent, createGatewayAgentClient } from "@phaseo/agent-sdk";

const SupportTriageDecision = z
  .object({
    queue: z.enum(["billing", "reliability", "product", "security"]),
    severity: z.enum(["low", "medium", "high"]),
    needsHumanReview: z.boolean(),
    summary: z.string().min(1),
  })
  .strict();
type SupportTriageDecision = z.infer<typeof SupportTriageDecision>;

// `preset` हर टर्न पर मॉडल `@support-triage` बन जाता है।
const supportTriageAgent = createAgent<string, SupportTriageDecision>({
  id: "support-triage-agent",
  preset: "support-triage",
  maxSteps: 3,
  parseOutput: (text) => JSON.parse(text),
  outputSchema: SupportTriageDecision,
  humanReview: ({ parsedOutput }) =>
    parsedOutput?.needsHumanReview
      ? { reason: "support_triage_review_required", payload: parsedOutput }
      : null,
});

const client = createGatewayAgentClient({
  clientOptions: { apiKey: process.env.PHASEO_API_KEY! },
  responseFormat: {
    type: "json_schema",
    name: "support_triage_decision",
    schema: {
      type: "object",
      properties: {
        queue: { type: "string", enum: ["billing", "reliability", "product", "security"] },
        severity: { type: "string", enum: ["low", "medium", "high"] },
        needsHumanReview: { type: "boolean" },
        summary: { type: "string" },
      },
      required: ["queue", "severity", "needsHumanReview", "summary"],
      additionalProperties: false,
    },
  },
  plugins: [{ id: "response-healing", mode: "strict" }],
});

try {
  const result = await supportTriageAgent.run({
    input: "Customer says webhook deliveries failed overnight and asks whether data was lost.",
    client,
    modelRetry: { maxRetries: 2, backoffMs: 250 },
    onEvent(event) {
      if (event.type === "model.retrying") console.log("retrying", event.attempt, event.error);
    },
  });

  if (result.run.status === "waiting_for_human") {
    // `result` संग्रहीत करें, फिर किसी सपोर्ट एजेंट की समीक्षा के बाद आगे बढ़ें।
    console.log("Needs review:", result.run.pause?.payload);
  } else {
    console.log(result.output);
  }
} catch (error) {
  if (error instanceof AgentGatewayError) {
    console.error("Gateway request failed", {
      status: error.status,
      requestId: error.requestId,
      generationId: error.generationId,
      reason: error.reason,
      providerFailureDiagnostics: error.providerFailureDiagnostics,
      routingDiagnostics: error.routingDiagnostics,
    });
  }
  throw error;
}
```

## जाँचें कि यह काम किया

एक सामान्य टिकट और एक जोखिम भरा टिकट चलाएँ, फिर जाँचें:

- **सेटिंग → उपयोग → लॉग्स** में अनुरोध का मॉडल दिखाता है कि प्रीसेट इस्तेमाल हुआ।
- जोखिम भरा मामला `waiting_for_human` पर रुकता है, और निर्णय `pause.payload` में होता है।
- दोबारा आज़माई गई मॉडल कॉल चरण पर `modelAttempts` के रूप में दर्ज होती है, और हर दोबारा कोशिश `model.retrying` लॉग करती है।
- ब्लॉक किया गया अनुरोध अपने `requestId` और `reason` के साथ लॉग होता है, और लॉग में वही अनुरोध कारण दिखाता है।

## गेटवे विफलताओं को दिखाई देने लायक रखें

एजेंट कॉलबैक के अंदर त्रुटियों को दबाएँ नहीं। `AgentGatewayError` को सीमा पर पकड़ें, उसकी ID लॉग करें, और उसे फिर से throw करें। रन विफल होने के बाद, उसकी सहेजी गई स्थिति वही जानकारी `run.errorDetails` और `steps[n].errorDetails` में रखती है, ताकि बाद में कोई रिकवरी जॉब exception खत्म होने के बाद भी उन्हें पढ़ सके।

ये विफलताएँ एजेंट से नहीं, Gateway नीति से आती हैं, इसलिए लॉग में अनुरोध ही देखने की जगह है:

| विफलता | कहाँ दिखती है |
| --- | --- |
| कोई गार्डरेल अनुरोध को ब्लॉक करता है | अनुरोध का **गार्डरेल प्रवर्तन** सेक्शन |
| प्रीसेट के अनुमत मॉडल इस मॉडल को अस्वीकार करते हैं | कीवर्ड `preset_model_not_allowed` के साथ `validation_error` |
| प्रदाता क्रेडेंशियल या सक्षम करने की सेटिंग की वजह से कोई प्रदाता नहीं बचता | `providerFailureDiagnostics` और **रूटिंग अवलोकन** |
| healing स्कीमा-वैध JSON नहीं बना पाती | प्लगइन रिकॉर्ड, फिर `outputSchema` से `AgentSchemaValidationError` |
