एक वर्गीकरण, जैसे विभाग, दर्शक या कार्य का प्रकार, और उसे लागू करने वाला मॉडल तय करें, और Phaseo हर पूरे हुए अनुरोध पर उस मॉडल के जवाबों का लेबल लगा देगा। हर जवाब एक [अनुरोध लेबल](/hi/v1/guides/request-labels) के रूप में सेव होता है, इसलिए आप अपने कोड से भेजे गए लेबल की तरह ही लॉग, उपयोग और एनालिटिक्स को इसके आधार पर फ़िल्टर और समूहित करते हैं। क्लासिफ़ायर तब उपयोग करें जब श्रेणी आपके कोड को पता न हो: प्रॉम्प्ट किसके लिए लिखा गया था, एजेंट किस तरह का काम कर रहा है, या अनुरोध किसी विनियमित विषय से जुड़ा है या नहीं।

<Note>
अनुरोध क्लासिफ़ायर बीटा में हैं। मालिक और एडमिन इन्हें **सेटिंग्स → क्लासिफ़ायर** में, या `classifiers:*` स्कोप वाली [प्रबंधन कुंजी](/hi/v1/developers/management-api-keys) के साथ `/v1/classifiers` प्रबंधन API से प्रबंधित करते हैं।
</Note>

## अनुरोध को कैसे वर्गीकृत किया जाता है

1. अनुरोध पूरा होता है और उसकी प्रतिक्रिया आपके ऐप्लिकेशन को लौटा दी जाती है। वर्गीकरण से कभी लेटेंसी नहीं बढ़ती।
2. Phaseo अनुरोध का ट्रांसक्रिप्ट बनाता है: सिस्टम निर्देश, संदेश, टूल के नाम (उनके स्कीमा नहीं) और टूल परिणाम। हर टर्न 4,000 अक्षरों तक सीमित है, और API कुंजियों जैसे सीक्रेट छिपा दिए जाते हैं। अगर क्लासिफ़ायर प्रतिक्रिया को शामिल करता है, तो जनरेट किया गया आउटपुट भी जोड़ा जाता है।
3. क्लासिफ़ायर मॉडल आपके मानों में से चुनता है। उनके बाहर का कोई भी जवाब हटा दिया जाता है ([मॉडल चुनें](#choose-a-model) देखें)।
4. जवाब, हर जवाब के कॉन्फ़िडेंस के साथ, अनुरोध पर लेबल के रूप में सेव होते हैं, और उसके बाद अनुरोध आपके लॉग में दिखता है।

क्लासिफ़ायर सफल `chat/completions`, `responses` और `messages` अनुरोधों पर चलते हैं। अगर वर्गीकरण विफल हो जाए या उसका समय खत्म हो जाए, तब भी अनुरोध लॉग होता है, बस उन लेबल के बिना।

## क्लासिफ़ायर बनाएँ

डैशबोर्ड में किसी प्रीसेट से शुरू करें या वर्गीकरण खुद भेजें:

```bash
curl https://api.phaseo.app/v1/classifiers \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Department",
    "model": "google/gemini-2.5-flash-lite",
    "dimensions": [{
      "key": "department",
      "name": "Department",
      "allow_other": true,
      "values": [
        { "value": "engineering", "description": "Writing, reviewing, or debugging code" },
        { "value": "legal", "description": "Contracts, policies, and compliance" },
        { "value": "sales" },
        { "value": "support" }
      ]
    }],
    "sample_rate": 0.25,
    "monthly_budget_usd": 20
  }'
```

| फ़ील्ड | अर्थ |
| --- | --- |
| `dimensions` | 1 से 12 सवाल। हर `key` लेबल की बनती है; हर आयाम में 2 से 50 मान होते हैं (`allow_other` के साथ 1)। |
| `multiple` | किसी आयाम के लिए एक से ज़्यादा मान की अनुमति दें। हर मान उसी की के साथ अपना अलग लेबल बनता है। |
| `allow_other` | जब कुछ भी फ़िट न हो, तो मॉडल को `other` जवाब देने दें। |
| `instructions` | वर्गीकरण प्रॉम्प्ट में जोड़ा गया अतिरिक्त मार्गदर्शन, अधिकतम 8,000 अक्षर। |
| `sample_rate` | वर्गीकृत किए जाने वाले योग्य अनुरोधों का हिस्सा, `0.0001` से `1` तक। |
| `sample_by` | `request` हर अनुरोध का सैंपल लेता है। `session` पूरे सत्र को एक साथ शामिल या बाहर रखता है और उसके जवाब एक घंटे तक दोबारा उपयोग करता है, ताकि लंबे एजेंट रन का वर्गीकरण एक ही बार हो। |
| `input_scope` | `prompt` अनुरोध को वर्गीकृत करता है। `prompt_and_response` मॉडल को प्रतिक्रिया भी दिखाता है। |
| `scope` | सिर्फ़ इन `key_ids`, `app_ids` या `models` से आए अनुरोध वर्गीकृत करें, हर एक के अधिकतम 50। |
| `monthly_budget_usd` | इतना खर्च हो जाने पर UTC महीने के बाकी समय के लिए क्लासिफ़ायर रोक दें। |

एक वर्कस्पेस में अधिकतम पाँच क्लासिफ़ायर हो सकते हैं। बदलाव लगभग एक मिनट में Gateway तक पहुँच जाते हैं।

## मॉडल चुनें

कोई भी टेक्स्ट मॉडल या [निर्णय मॉडल](/hi/v1/api-reference/endpoint/decisions) वर्गीकरण कर सकता है। Phaseo मॉडल के प्रदाता जो सपोर्ट करते हैं, उसके आधार पर तय करता है कि उससे कैसे पूछा जाए:

| मॉडल | कैसे पूछा जाता है |
| --- | --- |
| संरचित आउटपुट वाला टेक्स्ट मॉडल | सख्त JSON स्कीमा के साथ `responses` अनुरोध, ताकि हर जवाब आपके मानों में से एक हो। |
| निर्णय मॉडल | हर आयाम के लिए एक विकल्प-प्रश्न के साथ `decisions` अनुरोध। `multiple` वाला आयाम हर मान के लिए हाँ/ना सवाल पूछता है और कम से कम 0.5 संभावना वाला हर मान रखता है (अगर किसी क्लासिफ़ायर को 128 से ज़्यादा सवालों की ज़रूरत हो, तो ऐसे आयाम को इसके बजाय उसका एक सबसे अच्छा मान मिलता है)। कॉन्फ़िडेंस मॉडल की अपनी संभावना होती है। |
| अन्य टेक्स्ट मॉडल | एक `responses` अनुरोध जो प्रॉम्प्ट में वही JSON माँगता है। आपके मानों से बाहर के जवाब हटा दिए जाते हैं, इसलिए कोई आयाम ज़्यादा बार बिना लेबल रह सकता है। जब कोई प्रदाता स्कीमा अस्वीकार करता है, तो यही फ़ॉलबैक भी है। |

आमतौर पर एक छोटा, तेज़ मॉडल काफ़ी होता है। सेव करने से पहले मॉडल जाँचने के लिए क्लासिफ़ायर एडिटर में **किसी नमूने पर आज़माएँ** का उपयोग करें।

## नतीजों से फ़िल्टर और समूहित करें

क्लासिफ़ायर के जवाब सामान्य अनुरोध लेबल हैं:

- **लॉग** और **उपयोग** में, `department` = `legal` जैसे लेबल से फ़िल्टर करें।
- API में `label_key` और `label_value` का उपयोग करें:

```text
GET /v1/analytics?label_key=department&label_value=legal
```

- [प्रसारण](/hi/v1/guides/integrations/observability) गंतव्यों को लेबल `phaseo.label.<key>` स्पैन एट्रिब्यूट के रूप में मिलते हैं।

अगर आपका कोड पहले से किसी आयाम की की वाला लेबल भेजता है, तो Phaseo आपका मान रखता है और उस आयाम को छोड़ देता है। जब दो क्लासिफ़ायर एक ही की का उपयोग करते हैं, तो पहले बनाया गया क्लासिफ़ायर लागू होता है।

## लागत और गोपनीयता

- हर वर्गीकरण क्लासिफ़ायर मॉडल को भेजा गया एक अलग अनुरोध है, जो मूल अनुरोध वाली API कुंजी या OAuth टोकन से किया जाता है। इसका बिल उस मॉडल की सामान्य कीमत पर बनता है और यह आपके वर्कस्पेस की प्रदाता, डेटा रिटेंशन और BYOK सेटिंग का पालन करता है।
- क्लासिफ़ायर अनुरोधों पर `phaseo.classifier` लेबल होता है, जिसका मान क्लासिफ़ायर ID होता है, ताकि आप **उपयोग** में उनका खर्च देख सकें। उन्हें खुद वर्गीकृत नहीं किया जाता और वे आपकी रेट लिमिट नीतियों में नहीं गिने जाते।
- छोटे, तेज़ मॉडल, सैंपल दर, सत्र सैंपलिंग, स्कोप या मासिक बजट से लागत कम रखें।
- ट्रांसक्रिप्ट सिर्फ़ क्लासिफ़ायर मॉडल को जाता है। क्लासिफ़ायर अनुरोध किसी भी दूसरे अनुरोध की तरह लॉग होता है, इसलिए उसका इनपुट सेव होगा या नहीं, यह आपके वर्कस्पेस की लॉगिंग सेटिंग पर निर्भर करता है।
