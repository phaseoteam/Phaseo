<Note>
रिक्वेस्ट क्लासिफ़ायर बीटा में हैं। मालिक और एडमिन इन्हें **सेटिंग्स → क्लासिफ़ायर** में या `classifiers:*` स्कोप वाली [मैनेजमेंट कुंजी](../developers/management-api-keys.mdx) के साथ मैनेजमेंट API `/v1/classifiers` से प्रबंधित करते हैं।
</Note>

क्लासिफ़ायर एक वर्गीकरण बताता है, जैसे विभाग, दर्शक या कार्य का प्रकार, और उस मॉडल का नाम देता है जो इसे लागू करता है। हर योग्य रिक्वेस्ट पूरी होने के बाद Phaseo उस रिक्वेस्ट को इस मॉडल को भेजता है, जो हर डाइमेंशन के लिए एक मान चुनता है। हर जवाब रिक्वेस्ट में [रिक्वेस्ट लेबल](./request-labels.mdx) के रूप में जुड़ जाता है, इसलिए आप अपने कोड से भेजे गए लेबल की तरह ही लॉग्स, उपयोग और एनालिटिक्स को इसके आधार पर फ़िल्टर और ग्रुप कर सकते हैं।

क्लासिफ़ायर तब इस्तेमाल करें जब श्रेणी आपके कोड को पता न हो: प्रॉम्प्ट किसके लिए लिखा गया था, एजेंट किस तरह का काम कर रहा है, या रिक्वेस्ट किसी विनियमित विषय से जुड़ी है या नहीं।

## रिक्वेस्ट को कैसे वर्गीकृत किया जाता है

1. रिक्वेस्ट पूरी होती है और उसका रिस्पॉन्स आपके ऐप्लिकेशन को लौटा दिया जाता है। वर्गीकरण से कभी लेटेंसी नहीं बढ़ती।
2. Phaseo रिक्वेस्ट का ट्रांसक्रिप्ट बनाता है: सिस्टम निर्देश, संदेश, टूल के नाम (उनके स्कीमा नहीं) और टूल के नतीजे। हर टर्न 4,000 अक्षरों तक सीमित है, और API कुंजियों जैसे गोपनीय डेटा को छिपा दिया जाता है। अगर क्लासिफ़ायर रिस्पॉन्स भी शामिल करता है, तो जनरेट किया गया आउटपुट भी जोड़ा जाता है।
3. क्लासिफ़ायर मॉडल ऐसे स्ट्रक्चर्ड आउटपुट से जवाब देता है जिसमें सिर्फ़ आपके मान ही चुने जा सकते हैं।
4. जवाब, हर जवाब के कॉन्फ़िडेंस के साथ, रिक्वेस्ट पर लेबल के रूप में सहेजे जाते हैं, और उसके बाद रिक्वेस्ट आपके लॉग्स में दिखती है।

क्लासिफ़ायर `chat/completions`, `responses` और `messages` पर सफल रिक्वेस्ट्स के लिए चलते हैं। अगर वर्गीकरण विफल हो जाए या उसका समय खत्म हो जाए, तब भी रिक्वेस्ट लॉग होती है, बस उन लेबल के बिना।

## क्लासिफ़ायर बनाएँ

डैशबोर्ड में किसी प्रीसेट से शुरू करें या वर्गीकरण खुद भेजें:

```bash
curl https://api.phaseo.app/v1/classifiers \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Department",
    "model": "google/gemini-2.5-flash-lite",
    "dimensions": [{
      "key": "department",
      "name": "Department",
      "allow_other": true,
      "values": [
        { "value": "engineering", "description": "Writing, reviewing, or debugging code" },
        { "value": "legal", "description": "Contracts, policies, and compliance" },
        { "value": "sales" },
        { "value": "support" }
      ]
    }],
    "sample_rate": 0.25,
    "monthly_budget_usd": 20
  }'
```

| फ़ील्ड | अर्थ |
| --- | --- |
| `dimensions` | 1 से 12 सवाल। हर `key` लेबल की कुंजी बनती है; हर डाइमेंशन में 2 से 50 मान होते हैं (`allow_other` के साथ 1)। |
| `multiple` | एक डाइमेंशन के लिए एक से ज़्यादा मान की अनुमति देता है। हर मान उसी कुंजी के साथ अपना अलग लेबल बनता है। |
| `allow_other` | जब कुछ भी फ़िट न हो, तो मॉडल को `other` जवाब देने देता है। |
| `instructions` | वर्गीकरण प्रॉम्प्ट में जोड़े जाने वाले अतिरिक्त निर्देश। |
| `sample_rate` | योग्य रिक्वेस्ट्स का वह हिस्सा जिसे वर्गीकृत करना है, `0.0001` से `1` तक। |
| `sample_by` | `request` हर रिक्वेस्ट को अलग से सैंपल करता है। `session` पूरे सेशन को एक साथ शामिल या बाहर रखता है और उसके जवाब एक घंटे तक दोबारा इस्तेमाल करता है, ताकि एजेंट का लंबा रन सिर्फ़ एक बार वर्गीकृत हो। |
| `input_scope` | `prompt` रिक्वेस्ट को वर्गीकृत करता है। `prompt_and_response` मॉडल को रिस्पॉन्स भी दिखाता है। |
| `scope` | सिर्फ़ इन `key_ids`, `app_ids` या `models` से आने वाली रिक्वेस्ट्स को वर्गीकृत करता है। |
| `monthly_budget_usd` | इतनी राशि खर्च होते ही UTC महीने के बाकी समय के लिए क्लासिफ़ायर को रोक देता है। |

एक वर्कस्पेस में ज़्यादा से ज़्यादा पाँच क्लासिफ़ायर हो सकते हैं। बदलाव लगभग एक मिनट में गेटवे तक पहुँच जाते हैं।

## नतीजों के आधार पर फ़िल्टर और ग्रुप करें

क्लासिफ़ायर के जवाब सामान्य रिक्वेस्ट लेबल होते हैं:

- **लॉग्स** और **उपयोग** में `department` = `legal` जैसे लेबल से फ़िल्टर करें।
- API में `label_key` और `label_value` का उपयोग करें:

```text
GET /v1/analytics?label_key=department&label_value=legal
```

- [Broadcast](./integrations/observability.mdx) डेस्टिनेशन लेबल को स्पैन एट्रिब्यूट `phaseo.label.<key>` के रूप में पाते हैं।

अगर आपका कोड पहले से किसी डाइमेंशन की कुंजी वाला लेबल भेजता है, तो Phaseo आपका मान रखता है और उस डाइमेंशन को छोड़ देता है। जब दो क्लासिफ़ायर एक ही कुंजी इस्तेमाल करते हैं, तो पहले बनाया गया क्लासिफ़ायर मान्य होता है।

## लागत और गोपनीयता

- हर वर्गीकरण क्लासिफ़ायर मॉडल को भेजी गई एक अलग रिक्वेस्ट है, जो मूल रिक्वेस्ट वाली उसी API कुंजी या OAuth टोकन से भेजी जाती है। इसका बिल उस मॉडल की सामान्य कीमत पर बनता है और यह आपके वर्कस्पेस की प्रोवाइडर, डेटा रिटेंशन और BYOK सेटिंग्स का पालन करती है।
- क्लासिफ़ायर रिक्वेस्ट्स पर `phaseo.classifier` लेबल होता है जिसका मान क्लासिफ़ायर ID है, इसलिए आप **उपयोग** में उनका खर्च देख सकते हैं। इन्हें खुद वर्गीकृत नहीं किया जाता और ये आपकी दर सीमा नीतियों में नहीं गिनी जातीं।
- छोटे, तेज़ मॉडल, सैंपल दर, सेशन सैंपलिंग, स्कोप या मासिक बजट से लागत कम रखें।
- ट्रांसक्रिप्ट सिर्फ़ क्लासिफ़ायर मॉडल को भेजा जाता है। क्लासिफ़ायर रिक्वेस्ट किसी भी दूसरी रिक्वेस्ट की तरह लॉग होती है, इसलिए उसका इनपुट सहेजा जाएगा या नहीं, यह आपके वर्कस्पेस की लॉगिंग सेटिंग्स पर निर्भर करता है।
