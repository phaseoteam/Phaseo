अपने संदेशों को `{{variables}}` के साथ किसी [प्रीसेट](/hi/v1/guides/presets) पर सेव करें, और आपका ऐप्लिकेशन सिर्फ़ प्रीसेट का संदर्भ और वेरिएबल के मान भेजेगा। Phaseo मानों की जाँच करता है, संदेश भरता है और अनुरोध को प्रीसेट के मॉडल पर भेजता है। डैशबोर्ड में प्रॉम्प्ट बदलने के लिए कोई डिप्लॉय नहीं चाहिए, और हर कॉलर को एक जैसे शब्द, टूल और प्रतिक्रिया फ़ॉर्मैट मिलते हैं।

टेम्पलेट `POST /v1/chat/completions`, `POST /v1/responses` और `POST /v1/messages` पर काम करते हैं।

## टेम्पलेट बनाएँ और कॉल करें

<Steps>
<Step title="टेम्पलेट लिखें">

**सेटिंग्स -> प्रीसेट** खोलें, कोई प्रीसेट बनाएँ या खोलें, उसका मॉडल चुनें और **प्रॉम्प्ट टेम्पलेट** टैब खोलें। संदेश जोड़ें और वेरिएबल दोहरे ब्रेस में लिखें:

```text
System: You triage support tickets for {{company}}. Reply in a {{tone}} tone.
User:   Ticket: {{ticket}}
```

एडिटर अपने द्वारा खोजे गए हर वेरिएबल की सूची देता है। उसका प्रकार, वह ज़रूरी है या नहीं, एक डिफ़ॉल्ट और एक विवरण सेट करें। Gateway ठीक कौन-से संदेश भेजेगा, यह देखने के लिए **आज़माएं** पैनल भरें, फिर सेव करें।

प्रीसेट सेव होने के बाद, **सेव किया गया प्रीसेट चलाएँ** आपके टेस्ट मानों के साथ एक असली अनुरोध भेजता है और जवाब, मॉडल और टोकन गिनती दिखाता है। यह आपके वर्कस्पेस के क्रेडिट का उपयोग करता है। उसी पैनल में अनुरोध के लिए cURL, TypeScript और Python कोड है, जिसमें आपके टेस्ट मान भरे होते हैं।

</Step>

<Step title="वेरिएबल भेजें">

`prompt.id` में प्रीसेट का संदर्भ दें और मान `prompt.variables` में रखें। `model` छोड़ दें, या उसे उसी संदर्भ पर सेट करें।

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "prompt": {
      "id": "@support-triage",
      "variables": {
        "company": "Acme",
        "tone": "friendly",
        "ticket": "I was charged twice this month."
      }
    }
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const completion = await client.generateText({
	model: "@support-triage",
	messages: [],
	prompt: {
		id: "@support-triage",
		variables: {
			company: "Acme",
			tone: "friendly",
			ticket: "I was charged twice this month.",
		},
	},
});
```

```python Python
from phaseo import Phaseo

client = Phaseo(api_key="YOUR_API_KEY")

completion = client.generate_text({
    "prompt": {
        "id": "@support-triage",
        "variables": {
            "company": "Acme",
            "tone": "friendly",
            "ticket": "I was charged twice this month.",
        },
    },
})
```
</CodeGroup>

</Step>

<Step title="अनुरोध जाँचें">

अनुरोध, उसे सर्व करने वाला मॉडल और उसकी लागत देखने के लिए **Gateway -> लॉग** खोलें। अनुरोध का मेटाडेटा प्रीसेट, वेरिएबल के नाम और रेंडर किए गए संदेशों की संख्या दर्ज करता है, लेकिन वेरिएबल के मान नहीं।

</Step>
</Steps>

## हर एंडपॉइंट से टेम्पलेट का उपयोग करें

एक ही `prompt` ऑब्जेक्ट तीनों एंडपॉइंट पर काम करता है। टेम्पलेट के सिस्टम और डेवलपर संदेश एंडपॉइंट के सिस्टम निर्देश बन जाते हैं, और उसके बाकी संदेश आपके अनुरोध द्वारा भेजी गई किसी भी बातचीत से पहले जाते हैं।

| एंडपॉइंट | टेम्पलेट के सिस्टम संदेश कहाँ जाते हैं | टेम्पलेट की बातचीत किससे पहले जाती है |
| --- | --- | --- |
| `/v1/chat/completions` | `messages` (सिस्टम संदेशों के रूप में रखे जाते हैं) | आपके `messages` |
| `/v1/responses` | `instructions` | आपका `input` |
| `/v1/messages` | `system` | आपके `messages` |

आप टेम्पलेट के साथ बातचीत भेज सकते हैं। उदाहरण के लिए, एक चैट अनुरोध टेम्पलेट के संदेशों के बाद उपयोगकर्ता के आगे के टर्न जोड़ सकता है:

```json
{
  "prompt": { "id": "@support-triage", "variables": { "company": "Acme", "ticket": "Refund request" } },
  "messages": [
    { "role": "assistant", "content": "Can you share the order number?" },
    { "role": "user", "content": "It is 10482." }
  ]
}
```

## टेम्पलेट सिंटैक्स

टेम्पलेट Mustache के एक छोटे, लॉजिक-रहित उपसमूह का उपयोग करते हैं। टेम्पलेट में कुछ भी कभी कोड के रूप में नहीं चलाया जाता।

| सिंटैक्स | यह क्या करता है |
| --- | --- |
| `{{name}}` | एक मान डालता है। टेक्स्ट जैसा है वैसा डाला जाता है, संख्याएँ और बूलियन टेक्स्ट के रूप में, और सूचियाँ व ऑब्जेक्ट JSON के रूप में। गायब वैकल्पिक मान कुछ नहीं डालता। |
| `{{customer.name}}` | ऑब्जेक्ट वेरिएबल का एक फ़ील्ड डालता है। |
| `{{#name}}...{{/name}}` | जब मान सेट हो और `false` न हो तो ब्लॉक एक बार रेंडर करता है, या सूची के हर आइटम के लिए एक बार। अंदर, `{{.}}` मौजूदा आइटम है और उसके फ़ील्ड नाम से उपयोग किए जा सकते हैं। |
| `{{^name}}...{{/name}}` | जब मान गायब, `false`, खाली टेक्स्ट या खाली सूची हो तो ब्लॉक रेंडर करता है। |
| `{{! note }}` | एक टिप्पणी। इसे हटा दिया जाता है। |
| `\{{` | शाब्दिक `{{`। |

मान HTML एस्केपिंग के बिना सादे टेक्स्ट के रूप में डाले जाते हैं। कोई मान संदेश का टेक्स्ट बदल सकता है, लेकिन अनुरोध की संरचना कभी नहीं।

अगर कोई संदेश सिर्फ़ खाली जगह में रेंडर होता है, तो उसे हटा दिया जाता है। पूरे संदेश को वैकल्पिक बनाने के लिए इसका उपयोग करें:

```text
{{#notes}}Notes from the account manager: {{notes}}{{/notes}}
```

सूची के हर आइटम के लिए टेक्स्ट दोहराने के लिए, सूची पर एक सेक्शन खोलें और मौजूदा आइटम के लिए `{{.}}` का उपयोग करें:

```text
Examples of good replies:
{{#examples}}- {{.}}
{{/examples}}
```

पार्शियल (`{{> name}}`), बिना एस्केप वाले टैग (`{{{name}}}` और `{{& name}}`), डेलिमिटर बदलाव और लैम्डा समर्थित नहीं हैं, और एडिटर व API इनका उपयोग करने वाले टेम्पलेट अस्वीकार करते हैं।

## वेरिएबल

हर वेरिएबल का एक प्रकार होता है। किसी वेरिएबल को सिर्फ़ उसके डिफ़ॉल्ट बदलने के लिए घोषित करना पड़ता है; संदेशों में उपयोग हुए लेकिन घोषित न किए गए वेरिएबल ज़रूरी टेक्स्ट होते हैं।

| प्रकार | क्या स्वीकार करता है |
| --- | --- |
| `string` | टेक्स्ट। इसकी लंबाई सीमित करने के लिए `max_length` सेट करें। |
| `number` | एक संख्या। |
| `boolean` | `true` या `false`। |
| `enum` | `enum` में सूचीबद्ध स्ट्रिंग में से एक। |
| `array` | एक सूची। |
| `object` | एक JSON ऑब्जेक्ट। |
| `any` | कोई भी JSON मान। |
| `image` | उपयोगकर्ता संदेश के लिए एक इमेज। [इमेज वेरिएबल](#image-variables) देखें। |

हर वेरिएबल में ये भी हो सकते हैं:

- `required`: मान गायब होने पर अनुरोध विफल होता है। ज़रूरी वेरिएबल का डिफ़ॉल्ट नहीं हो सकता।
- `default`: जब अनुरोध मान छोड़ देता है तब उपयोग होता है। यह प्रकार से मेल खाना चाहिए।
- `description`: एडिटर और त्रुटि संदेशों में दिखता है, अधिकतम 500 अक्षर।

सिर्फ़ सेक्शन खोलने के लिए उपयोग होने वाला नाम, जैसे ऊपर `notes` और `examples`, वैकल्पिक होता है और कोई भी मान स्वीकार करता है।

अनुरोधों की जाँच सख्ती से होती है। गायब ज़रूरी मान, गलत प्रकार का मान, या ऐसा नाम जो टेम्पलेट में नहीं है, एक `400` लौटाता है जो सभी समस्याओं को एक साथ सूचीबद्ध करता है, ताकि कोई टाइपो चुपचाप प्रॉम्प्ट का हिस्सा न हटा दे।

<span id="image-variables"></span>
## इमेज वेरिएबल

इमेज वेरिएबल उपयोगकर्ता संदेश के पूरे कंटेंट हिस्से को भरता है, इसलिए टेम्पलेट तय करता है कि इमेज कहाँ जाएगी। एडिटर में, किसी उपयोगकर्ता संदेश के अंदर **इमेज जोड़ें** चुनें। API में `variable` हिस्से का उपयोग करें:

```json
{
  "role": "user",
  "content": [
    { "type": "text", "text": "Before:" },
    { "type": "variable", "name": "before" },
    { "type": "text", "text": "After:" },
    { "type": "variable", "name": "after" },
    { "type": "text", "text": "What changed?" }
  ]
}
```

अनुरोध हर इमेज को `https` URL, `data:image/...` URL, या chat completions, Responses या Messages के आकार वाले इमेज हिस्से के रूप में भेज सकता है। Phaseo उसे आपके द्वारा कॉल किए गए एंडपॉइंट के फ़ॉर्मैट में बदल देता है। चुने गए मॉडल को इमेज इनपुट स्वीकार करना चाहिए।

## टूल और प्रतिक्रिया फ़ॉर्मैट

टेम्पलेट में `tools`, `tool_choice` और `response_format` शामिल हो सकते हैं, जो chat completions के आकार में लिखे जाते हैं ([टूल कॉलिंग](./tool-calling.mdx) और [संरचित आउटपुट](./structured-outputs.mdx) देखें)। Phaseo उन्हें Responses और Messages एंडपॉइंट के लिए बदल देता है।

जब दोनों एक ही चीज़ सेट करते हैं, तो अनुरोध हमेशा लागू होता है:

- टूल फ़ंक्शन नाम से जोड़े जाते हैं। अगर अनुरोध उसी नाम का टूल परिभाषित करता है, तो अनुरोध की परिभाषा उपयोग होती है।
- अनुरोध का `tool_choice` और प्रतिक्रिया फ़ॉर्मैट (`response_format`, `text.format` या `output_config.format`) टेम्पलेट वाले की जगह लेते हैं।

`temperature` और `max_tokens` जैसे अनुरोध पैरामीटर हमेशा की तरह काम करते हैं। प्रीसेट के अपने डिफ़ॉल्ट सिर्फ़ वे फ़ील्ड भरते हैं जिन्हें अनुरोध छोड़ देता है।

## API से टेम्पलेट बनाएँ

टेम्पलेट प्रीसेट के `config.prompt` में सेव होते हैं। `presets:write` वाली [प्रबंधन API कुंजी](/hi/v1/developers/management-api-keys) से प्रीसेट बनाएँ या अपडेट करें:

```bash
curl https://api.phaseo.app/v1/presets \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "@support-triage",
    "visibility": "team",
    "config": {
      "models": ["anthropic/claude-haiku-5.5"],
      "prompt": {
        "messages": [
          { "role": "system", "content": "You triage support tickets for {{company}}. Reply in a {{tone}} tone." },
          { "role": "user", "content": "Ticket: {{ticket}}" }
        ],
        "variables": {
          "company": { "type": "string", "required": true },
          "tone": { "type": "enum", "enum": ["formal", "friendly"], "default": "formal" },
          "ticket": { "type": "string", "required": true, "max_length": 4000 }
        }
      }
    }
  }'
```

Phaseo सेव होते समय टेम्पलेट की जाँच करता है। सिंटैक्स त्रुटि, अज्ञात प्रकार, या अपने प्रकार से मेल न खाने वाले डिफ़ॉल्ट वाला टेम्पलेट `400 invalid_prompt_template` और हर समस्या की जगह के साथ अस्वीकार किया जाता है, यहाँ भी और एडिटर में भी।

सेव किए गए बदलाव लगभग दो मिनट में अनुरोधों तक पहुँचते हैं।

<span id="versions-and-labels"></span>
## संस्करण और लेबल

हर बार जब आप कोई प्रीसेट प्रकाशित करते हैं, Phaseo एक अपरिवर्तनीय संस्करण सेव करता है ([प्रीसेट](/hi/v1/guides/presets#version-and-roll-back) देखें)। अनुरोध नवीनतम प्रकाशित संस्करण चलाते हैं, जब तक वे कोई संस्करण पिन न करें। पिन किया गया अनुरोध उस संस्करण के मॉडल, पैरामीटर और टेम्पलेट को एक साथ उपयोग करता है।

`prompt.version` से संस्करण पिन करें:

```json
{
  "prompt": {
    "id": "@support-triage",
    "version": "production",
    "variables": { "company": "Acme", "ticket": "My invoice is wrong" }
  }
}
```

`prompt.version` एक संस्करण लेबल लेता है, जैसे `v3`, `1.2.0` या `2026.10.27`, या `production` जैसा कोई लेबल। आप संस्करण को मॉडल ID में भी डाल सकते हैं, टेम्पलेट के साथ या उसके बिना:

```json
{
  "model": "@support-triage@production",
  "messages": [{ "role": "user", "content": "My invoice is wrong" }]
}
```

सार्वजनिक प्रीसेट `@publisher/support-triage@production` का उपयोग करते हैं। अगर `model` और `prompt.version` दोनों कोई संस्करण पिन करते हैं, तो दोनों को एक ही संस्करण का नाम देना होगा।

### लेबल

लेबल एक नाम है, जैसे `production` या `staging`, जो एक प्रकाशित संस्करण की ओर इशारा करता है। लेबल 1 से 32 छोटे अक्षर, अंक, हाइफ़न या अंडरस्कोर होते हैं, अक्षर से शुरू होते हैं, और संस्करण लेबल (`v1`, `v2`) जैसे नहीं दिख सकते।

**सेटिंग्स -> प्रीसेट** में प्रीसेट खोलें। **ड्राफ़्ट सहेजें** के बगल में **प्रकाशित करें** आपके बदलाव सेव करता है और उन्हें अगले संस्करण के रूप में प्रकाशित करता है। लेबल प्रबंधित करने के लिए **संस्करण और लेबल** खोलें: हर लेबल का एक संस्करण पिकर होता है, इसलिए दूसरा संस्करण चुनने से लेबल वहाँ चला जाता है और पिछला संस्करण चुनने से वापसी हो जाती है। नए लेबल के लिए **लेबल जोड़ें** का उपयोग करें। किसी संस्करण के मॉडल और टेम्पलेट संदेश, और वे डिफ़ॉल्ट संस्करण (वह जिसे अनुरोध तब चलाते हैं जब वे कोई संस्करण पिन नहीं करते) से कैसे अलग हैं, यह देखने के लिए उस संस्करण को खोलें, और **प्रॉम्प्ट टेम्पलेट** के टेस्ट मानों के साथ उस संस्करण को आज़माने के लिए **चलाएँ** का उपयोग करें। प्रीसेट बनाने वाला उसके लेबल बदल सकता है, और प्रीसेट साझा होने पर वर्कस्पेस के मालिक और एडमिन भी। `presets:write` वाली [प्रबंधन API कुंजी](/hi/v1/developers/management-api-keys) के साथ:

```bash
curl -X PUT https://api.phaseo.app/v1/presets/support-triage/labels/production \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "version": "v3" }'
```

बॉडी `version` (एक संस्करण लेबल, या कोई दूसरा लेबल जिसकी जगह कॉपी करनी हो) या `version_id` लेती है। `GET /v1/presets/{id}/labels` लेबल की सूची देता है, और `DELETE /v1/presets/{id}/labels/{label}` एक लेबल हटाता है। हटाए गए लेबल को पिन करने वाले अनुरोध तब तक विफल होते हैं जब तक उसे दोबारा न जोड़ा जाए।

### वापस लौटें

वापस लौटने के लिए लेबल को पिछले संस्करण पर ले जाएँ: **संस्करण और लेबल** में लेबल के संस्करण पिकर में वह संस्करण चुनें, या वही अनुरोध `"version": "v2"` के साथ भेजें। `production` पिन करने वाले अनुरोध आपके ऐप्लिकेशन में कोई बदलाव किए बिना फिर से v2 चलाते हैं।

लेबल का बदलाव, दूसरे प्रीसेट बदलावों की तरह, लगभग दो मिनट में अनुरोधों तक पहुँचता है।

## त्रुटियाँ

अनुरोध में टेम्पलेट की समस्याएँ कोड `validation_error` के साथ `400` लौटाती हैं। `reason` में पहली समस्या का कोड होता है और `details` सभी समस्याओं को उनके पाथ के साथ सूचीबद्ध करता है:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Template \"@support-triage\" needs variable \"ticket\" (string)",
    "type": "invalid_request_error"
  },
  "code": "validation_error",
  "reason": "template_variable_required",
  "description": "Template \"@support-triage\" needs variable \"ticket\" (string)",
  "details": [
    {
      "message": "Template \"@support-triage\" needs variable \"ticket\" (string)",
      "path": ["prompt", "variables", "ticket"],
      "keyword": "template_variable_required"
    }
  ]
}
```

| कारण | वजह |
| --- | --- |
| `template_variable_required` | एक ज़रूरी वेरिएबल गायब है। |
| `template_variable_type` | कोई मान अपने प्रकार, enum सूची या `max_length` से मेल नहीं खाता। |
| `template_variable_unknown` | अनुरोध ने ऐसा वेरिएबल भेजा जो टेम्पलेट में नहीं है, या प्रीसेट में कोई टेम्पलेट नहीं है। |
| `template_variables_invalid` | `prompt.variables` ऑब्जेक्ट नहीं है। |
| `template_limit_exceeded` | वेरिएबल या रेंडर किया गया टेक्स्ट नीचे दी गई सीमाओं से बड़ा है। |
| `template_rendered_empty` | टेम्पलेट ने कोई उपयोगकर्ता या असिस्टेंट संदेश रेंडर नहीं किया और अनुरोध ने भी कोई नहीं भेजा। |
| `template_endpoint_unsupported` | प्रीसेट में टेम्पलेट है और उसे ऊपर के तीन एंडपॉइंट के अलावा किसी दूसरे एंडपॉइंट से कॉल किया गया। |
| `prompt_model_conflict` | `model` में `prompt.id` से अलग प्रीसेट या मॉडल का नाम है, या यह `prompt.version` से अलग संस्करण पिन करता है। |
| `prompt_version_invalid` | `prompt.version` खाली है, 64 अक्षरों से लंबा है, या उसमें अक्षरों, अंकों, `.`, `_`, `+` और `-` के अलावा दूसरे अक्षर हैं। |
| `prompt_model_fallbacks_unsupported` | अनुरोध ने `models` फ़ॉलबैक सेट किए। इसके बजाय फ़ॉलबैक मॉडल प्रीसेट में सूचीबद्ध करें। |

ऐसा `prompt.id` जो आपके वर्कस्पेस में किसी प्रीसेट का नाम नहीं है, `404` लौटाता है।

ऐसा पिन किया गया संस्करण या लेबल जो मौजूद नहीं है, या जिसे कुंजी उपयोग नहीं कर सकती, कारण `preset_version_not_found` के साथ `404` लौटाता है।

## गार्डरेल और लॉग

[गार्डरेल](/hi/v1/cookbook/guardrails-for-api-keys) वेरिएबल मानों को उपयोगकर्ता कंटेंट के रूप में जाँचते हैं, तब भी जब टेम्पलेट उन्हें सिस्टम संदेश में डालता है। किसी मान को रिडैक्ट करने वाला गार्डरेल उसे हर उस जगह रिडैक्ट करता है जहाँ टेम्पलेट ने उसे डाला, और किसी मान को ब्लॉक करने वाला गार्डरेल अनुरोध को ब्लॉक करता है।

अनुरोध मेटाडेटा प्रीसेट, वेरिएबल के नाम और रेंडर किए गए संदेशों की संख्या दर्ज करता है। मान खुद सिर्फ़ वहीं रखे जाते हैं जहाँ अनुरोध बॉडी रखी जाती है, आपके वर्कस्पेस की सामान्य लॉगिंग सेटिंग के तहत।
