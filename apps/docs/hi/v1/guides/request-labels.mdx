किसी अनुरोध को `team=support` जैसे की/वैल्यू लेबल से टैग करने के लिए `X-Phaseo-Metadata` हेडर भेजें, फिर उन लेबल से खर्च और लॉग फ़िल्टर करें। जब आपको API कुंजी या ऐप से ज़्यादा बारीक लागत आयाम चाहिए, तब लेबल का उपयोग करें। ये मॉडल अनुरोध को नहीं बदलते और प्रदाताओं को फ़ॉरवर्ड नहीं किए जाते।

```bash
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -H 'X-Phaseo-Metadata: {"labels":[{"key":"team","value":"support"},{"key":"environment","value":"production"}]}' \
  -d '{
    "model": "openai/gpt-6-astra",
    "input": "Summarize this ticket."
  }'
```

TypeScript और Python SDK कस्टम हेडर स्वीकार करते हैं, इसलिए आप यही हेडर क्लाइंट पर एक बार सेट कर सकते हैं।

अनुरोधों को उनके कंटेंट के आधार पर अपने आप लेबल करने के लिए [अनुरोध क्लासिफ़ायर](/hi/v1/guides/request-classifiers) का उपयोग करें। उनके जवाब अनुरोध लेबल के रूप में सेव होते हैं और उसी तरह फ़िल्टर होते हैं।

## लेबल के नियम

| नियम | सीमा |
| --- | --- |
| प्रति अनुरोध लेबल | अधिकतम 32, हर एक की की अलग हो |
| की | 1 से 64 अक्षर: अक्षर, अंक, `_`, `.`, `:`, `-` |
| वैल्यू | स्ट्रिंग, 1 से 256 अक्षर, कोई कंट्रोल कैरेक्टर नहीं |
| हेडर का आकार | अधिकतम 8 KiB |
| आरक्षित की | `phaseo.classifier` सिर्फ़ Phaseo के क्लासिफ़ायर कॉल सेट करते हैं |

की और वैल्यू के आगे-पीछे की खाली जगह हटा दी जाती है। गलत बना हेडर, दोहराई गई की, या इन नियमों को तोड़ने वाला लेबल किसी भी मॉडल को कॉल करने से पहले अनुरोध को `400 validation_error`, कारण `invalid_request_metadata`, के साथ विफल कर देता है।

लेबल में प्रॉम्प्ट, सीक्रेट, ईमेल पते या अन्य व्यक्तिगत डेटा न रखें।

## लेबल से खर्च फ़िल्टर करें

एनालिटिक्स एंडपॉइंट को `label_key` और `label_value` दोनों भेजें:

```text
GET /v1/analytics?label_key=team&label_value=support
```

प्रतिक्रिया का फ़ॉर्मैट बिना फ़िल्टर वाले एनालिटिक्स जैसा ही समूहबद्ध खर्च होता है, लेकिन इसमें सिर्फ़ वे अनुरोध गिने जाते हैं जिन पर ठीक वही लेबल जोड़ी हो। दोनों में से सिर्फ़ एक पैरामीटर भेजने पर `400 invalid_request` मिलता है।
