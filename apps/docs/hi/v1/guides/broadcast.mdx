**सेटिंग्स → प्रसारण** में एक गंतव्य जोड़ें, और Phaseo बिना किसी कोड बदलाव के उसे हर Gateway अनुरोध का ट्रेस भेजता है। ट्रेस OpenTelemetry GenAI कन्वेंशन का पालन करता है: अनुरोध के लिए एक span, और हर प्रदाता प्रयास के लिए एक span, जिनमें मॉडल, प्रदाता, टोकन उपयोग, लागत, समय और (जब तक आप इसे बंद न करें) प्रॉम्प्ट और आउटपुट शामिल होते हैं।

Broadcast मुफ़्त है। ओनर और एडमिन **सेटिंग्स → प्रसारण** में, या [observability destinations API](/hi/v1/api-reference/endpoint/observability-destinations-create) और `settings:write` वाली [मैनेजमेंट कुंजी](/hi/v1/developers/management-api-keys) से गंतव्य प्रबंधित करते हैं। एक वर्कस्पेस में हर प्रकार के अधिकतम पाँच गंतव्य हो सकते हैं। इसके बजाय अपने क्लाइंट से ट्रेस करने के लिए [ऑब्ज़र्वेबिलिटी इंटीग्रेशन](./integrations/observability.mdx) देखें।

## गंतव्य जोड़ें

1. **सेटिंग्स → प्रसारण** खोलें और एक गंतव्य चुनें।
2. उसके क्रेडेंशियल डालें। वे सेव होने से पहले एन्क्रिप्ट किए जाते हैं और दोबारा कभी नहीं दिखाए जाते।
3. चुनें कि क्या भेजा जाए ([चुनें कि क्या भेजा जाए](#choose-what-is-sent) देखें)।
4. **कनेक्शन का परीक्षण करें** चुनें। Phaseo एक नमूना ट्रेस उसी तरह भेजता है जैसे असली डिलीवरी भेजी जाती हैं, इसलिए यहाँ विफलता होने पर गंतव्य की अपनी त्रुटि दिखती है।
5. सेव करें। इसके बाद पूरे होने वाले अनुरोध लगभग एक मिनट के भीतर भेजे जाते हैं।

| प्रकार | गंतव्य |
| --- | --- |
| OpenTelemetry टूल | Arize AI, Axiom, Braintrust, Comet Opik, Datadog, Dynatrace, Elastic, Grafana Cloud, Honeycomb, Langfuse, LangSmith, New Relic, PostHog, Respan, Sentry, W&B Weave |
| कोई भी OTLP एंडपॉइंट | OpenTelemetry Collector (OTLP/HTTP, JSON या protobuf, वैकल्पिक gzip) |
| आपकी अपनी सेवा | वेबहुक |
| ऑब्जेक्ट स्टोरेज | Amazon S3 और S3-संगत स्टोर, Cloudflare R2, Google Cloud Storage |
| डेटाबेस और वेयरहाउस | ClickHouse, Google BigQuery, Snowflake |

हर फ़ॉर्म सिर्फ़ वही माँगता है जिसकी उस टूल को ज़रूरत है, जैसे एक API कुंजी और एक प्रोजेक्ट या क्षेत्र। OpenTelemetry टूल को एक जैसे span मिलते हैं; Phaseo हर वेंडर का एंडपॉइंट, हेडर और एन्कोडिंग भरता है।

<span id="choose-what-is-sent"></span>
## चुनें कि क्या भेजा जाए

हर गंतव्य की अपनी सेटिंग होती हैं:

- **गोपनीयता मोड** हर ट्रेस से प्रॉम्प्ट, आउटपुट, सिस्टम निर्देश और टूल परिभाषाएँ बाहर रखता है। जो API कुंजी कभी कंटेंट सेव नहीं करती, उससे किए गए अनुरोध कभी कंटेंट के साथ आगे नहीं भेजे जाते, चाहे यह सेटिंग कुछ भी कहे।
- **जनरेशन मेटाडेटा**, **लागत**, **पहचान** और **अनुरोध संदर्भ** में से हर एक span एट्रिब्यूट के एक समूह को चालू या बंद करता है। **अनुरोध संदर्भ** बंद करने से [अनुरोध मेटाडेटा](#add-your-own-trace-context) भी हट जाता है।
- **दर** योग्य अनुरोधों का एक हिस्सा भेजती है, 0 से 1 तक। यह चुनाव हर अनुरोध और गंतव्य के लिए स्थिर रहता है, इसलिए दोबारा भेजी गई डिलीवरी कभी अलग तरह से सैंपल नहीं होती।
- **API कुंजी फ़िल्टर** खास कुंजियों से किए गए अनुरोधों को शामिल या बाहर करता है।
- **फ़िल्टर नियम** सिर्फ़ मेल खाने वाले अनुरोध भेजते हैं। नियम मॉडल, प्रदाता, उपयोगकर्ता ID, समाप्ति का कारण, लागत या टोकन संख्या जैसे फ़ील्ड की तुलना करते हैं, और उन्हें **और** तथा **या** से समूहबद्ध किया जा सकता है। **रेगुलर एक्सप्रेशन से मेल खाता है** एक लीनियर-टाइम इंजन इस्तेमाल करता है: बैक-रेफ़रेंस और लुकअराउंड समर्थित नहीं हैं, और बहुत बड़ा पैटर्न सेव करते समय अस्वीकार कर दिया जाता है।

<span id="add-your-own-trace-context"></span>
## अपना ट्रेस संदर्भ जोड़ें

ट्रेस को नाम देने और अपने फ़ील्ड जोड़ने के लिए अनुरोध बॉडी में एक `metadata` ऑब्जेक्ट रखें। Phaseo इसे Broadcast के लिए पढ़ता है:

```json
{
  "model": "openai/gpt-6-astra",
  "messages": [{ "role": "user", "content": "Summarise this ticket" }],
  "metadata": {
    "trace_id": "ticket-48213",
    "trace_name": "support-summary",
    "generation_name": "summarise",
    "customer_tier": "enterprise"
  }
}
```

| कुंजी | असर |
| --- | --- |
| `trace_id` | वह ट्रेस जिसका अनुरोध हिस्सा है। 32 अक्षरों की हेक्स ID या UUID जैसी है वैसी इस्तेमाल होती है; कोई भी दूसरी स्ट्रिंग हैश की जाती है, इसलिए एक ही मान वाले सभी अनुरोध एक ही ट्रेस में जुड़ते हैं। |
| `parent_span_id` | 16 अक्षरों की हेक्स span ID, जिसके नीचे अनुरोध को नेस्ट करना है। `trace_id` के साथ इस्तेमाल होती है। |
| `trace_name`, `span_name` | अनुरोध के span का नाम। दोनों सेट हों तो `span_name` जीतता है। |
| `generation_name` | हर प्रदाता प्रयास के span का नाम। |
| कोई भी दूसरी कुंजी | `phaseo.metadata.<key>` नाम के span एट्रिब्यूट के रूप में भेजी जाती है। |

मान स्ट्रिंग, संख्या या बूलियन हो सकते हैं; नेस्टेड ऑब्जेक्ट छोड़ दिए जाते हैं। Phaseo अधिकतम 64 अक्षरों की अधिकतम 64 कुंजियाँ रखता है, और मानों को 512 अक्षरों पर काट देता है। W3C `traceparent` हेडर मौजूद होने पर, `trace_id` और `parent_span_id` के बजाय वही ट्रेस तय करता है।

`metadata` में सीक्रेट या व्यक्तिगत डेटा न डालें: यह हर उस गंतव्य को भेजा जाता है जिसमें **अनुरोध संदर्भ** चालू है।

[अनुरोध लेबल](./request-labels.mdx) भी भेजे जाते हैं, `phaseo.label.<key>` नाम के span एट्रिब्यूट के रूप में।

## वेबहुक डिलीवरी

वेबहुक को हर अनुरोध पर एक `POST` (या `PUT`, अगर आप उसे चुनें) मिलता है। बॉडी एक OTLP/JSON एक्सपोर्ट है, `{"resourceSpans": [...]}`, जिसमें उस अनुरोध के span होते हैं। अपने हेडर जोड़ने के लिए **Headers JSON** इस्तेमाल करें, जैसे वह `Authorization` हेडर जिसकी आपके एंडपॉइंट को उम्मीद है।

हर डिलीवरी, टेस्ट और नमूने पर हस्ताक्षर करवाने के लिए एक **Signing Secret** (16 से 256 अक्षर, बिना स्पेस) जोड़ें। तब Phaseo दो हेडर जोड़ता है:

```http
x-phaseo-timestamp: 1792569600
x-phaseo-signature: 5d2a…e41f
```

`x-phaseo-signature` टाइमस्टैम्प, एक पूर्णविराम (`.`) और बिना बदली अनुरोध बॉडी का हेक्साडेसिमल HMAC-SHA256 है, जिसकी कुंजी आपका सीक्रेट है। यह सूचना वेबहुक वाली ही योजना है, इसलिए आप उनका [सत्यापन कोड](./workspace-notifications.mdx#verify-webhook-signatures) दोबारा इस्तेमाल कर सकते हैं। Broadcast डिलीवरी में कोई इवेंट ID हेडर नहीं होता: बॉडी में मौजूद span ID पर डुप्लिकेट हटाएँ।

**कनेक्शन का परीक्षण करें** `X-Test-Connection: true` हेडर के साथ `{"resourceSpans": []}` भेजता है। `400` प्रतिक्रिया को पहुँच योग्य माना जाता है, इसलिए खाली एक्सपोर्ट अस्वीकार करने वाला रिसीवर भी पास हो जाता है।

## ऑब्जेक्ट स्टोरेज और वेयरहाउस पंक्तियाँ

ऑब्जेक्ट स्टोरेज, ClickHouse, BigQuery और Snowflake को ट्रेस के बजाय हर span के लिए एक पंक्ति मिलती है। हर बैच एक अनुरोध में लिखा जाता है: एक ऑब्जेक्ट, या एक insert।

| कॉलम | प्रकार | सामग्री |
| --- | --- | --- |
| `event_id` | string | अनुरोध की इवेंट ID। किसी अनुरोध के सभी span इसे साझा करते हैं। |
| `trace_id` | string | 32 अक्षरों की हेक्स ट्रेस ID। |
| `span_id` | string | 16 अक्षरों की हेक्स span ID। |
| `parent_span_id` | string या null | पैरेंट span, या अनुरोध के span के लिए null। |
| `name` | string | span का नाम। |
| `kind` | string | अनुरोध के लिए `server`, प्रदाता प्रयासों के लिए `client`। |
| `start_time`, `end_time` | timestamp | UTC में RFC 3339, माइक्रोसेकंड तक। |
| `duration_ms` | number | अंत घटा शुरुआत, मिलीसेकंड में। |
| `status_code` | string | `unset`, `ok` या `error`। |
| `status_message` | string या null | त्रुटि संदेश, अगर कोई हो। |
| `service_name` | string या null | `phaseo-gateway`। |
| `attributes` | object | नाम के अनुसार span एट्रिब्यूट, जैसे `gen_ai.request.model` या `gen_ai.usage.input_tokens`, उनके प्रकार बनाए रखते हुए। |
| `resource_attributes` | object | रिसोर्स एट्रिब्यूट, जैसे `service.name`। |

एक पंक्ति अधिकतम 512 KB की होती है। जब किसी span में इससे ज़्यादा डेटा हो, जैसे कोई इनलाइन इमेज, तो जगह बाँटने के लिए उसके सबसे बड़े एट्रिब्यूट मान काटे जाते हैं; हर मान अपनी शुरुआत रखता है और `…[truncated]` पर खत्म होता है, और उनके नाम `phaseo.truncated_attributes` एट्रिब्यूट में सूचीबद्ध होते हैं।

विफल बैच दोबारा भेजा जाता है। अगर गंतव्य ने उसे सेव कर लिया लेकिन प्रतिक्रिया खो गई, तो रीट्राई कुछ पंक्तियाँ दो बार लिख सकता है; डुप्लिकेट हटाने के लिए `event_id` और `span_id` इस्तेमाल करें। BigQuery और Snowflake ऐसी अनुरोध ID इस्तेमाल करते हैं जो इनमें से ज़्यादातर डुप्लिकेट रोकती हैं।

### ऑब्जेक्ट स्टोरेज

हर बैच एक gzip की हुई JSON lines फ़ाइल होती है। **Path Template** उसकी कुंजी सेट करता है, डिफ़ॉल्ट रूप से `phaseo/{year}/{month}/{day}/{hour}/{uuid}`, और Phaseo अंत में `.jsonl.gz` जोड़ता है। टेम्पलेट `{year}`, `{month}`, `{day}`, `{hour}`, `{date}` (`YYYY-MM-DD`) और `{uuid}` इस्तेमाल कर सकता है, और इसमें `{uuid}` होना ज़रूरी है ताकि फ़ाइलें कभी एक-दूसरे को ओवरराइट न करें। समय UTC में होते हैं।

- **Amazon S3**: एक ऐक्सेस कुंजी जो बकेट पर `s3:PutObject` कर सके, और बकेट का क्षेत्र। S3-संगत स्टोर के लिए **S3-Compatible Endpoint** सेट करें।
- **Cloudflare R2**: R2 API टोकन की ऐक्सेस कुंजी ID और सीक्रेट, आपकी अकाउंट ID, और अधिकार-क्षेत्र अगर बकेट किसी में है (`eu` या `fedramp`)।
- **Google Cloud Storage**: ऐसे सर्विस अकाउंट की HMAC कुंजी जो बकेट में ऑब्जेक्ट बना सके।

ऑब्जेक्ट `Content-Encoding` हेडर के बिना, कंप्रेस करके सेव किए जाते हैं, इसलिए Athena, BigQuery और Snowflake की एक्सटर्नल टेबल उन्हें उनके `.gz` एक्सटेंशन से पढ़ती हैं।

### ClickHouse

पंक्तियाँ HTTPS इंटरफ़ेस के ज़रिए `JSONEachRow` के रूप में, असिंक्रोनस insert के साथ डाली जाती हैं। जो कॉलम टेबल में नहीं हैं वे छोड़ दिए जाते हैं, इसलिए आप सिर्फ़ ज़रूरी कॉलम रख सकते हैं:

```sql
CREATE TABLE phaseo_traces (
  event_id String, trace_id String, span_id String, parent_span_id Nullable(String),
  name String, kind LowCardinality(String),
  start_time DateTime64(6, 'UTC'), end_time DateTime64(6, 'UTC'), duration_ms Float64,
  status_code LowCardinality(String), status_message Nullable(String), service_name Nullable(String),
  attributes String, resource_attributes String
) ENGINE = MergeTree ORDER BY (start_time, trace_id);
```

ClickHouse Cloud के लिए पोर्ट 8443 वाला एंडपॉइंट इस्तेमाल करें। `attributes` और `resource_attributes` `JSON` कॉलम भी हो सकते हैं।

### BigQuery

पंक्तियाँ `insertAll` से स्ट्रीम होती हैं, इवेंट और span ID को insert ID के रूप में इस्तेमाल करते हुए। टेबल पर **BigQuery Data Editor** वाला एक सर्विस अकाउंट बनाएँ, फिर उसकी JSON कुंजी फ़ाइल फ़ॉर्म में पेस्ट करें। `attributes` और `resource_attributes` का `JSON` कॉलम होना ज़रूरी है:

```sql
CREATE TABLE observability.phaseo_traces (
  event_id STRING, trace_id STRING, span_id STRING, parent_span_id STRING,
  name STRING, kind STRING, start_time TIMESTAMP, end_time TIMESTAMP, duration_ms FLOAT64,
  status_code STRING, status_message STRING, service_name STRING,
  attributes JSON, resource_attributes JSON
) PARTITION BY DATE(start_time) CLUSTER BY trace_id;
```

### Snowflake

हर बैच SQL API के ज़रिए एक `INSERT` होता है, जिसमें की-पेयर प्रमाणीकरण से साइन इन किया जाता है, इसलिए यह आपके बताए वेयरहाउस पर चलता है। Phaseo के लिए एक उपयोगकर्ता बनाएँ और उसे एक RSA कुंजी दें:

```sql
CREATE TABLE PHASEO.OBSERVABILITY.PHASEO_TRACES (
  EVENT_ID STRING, TRACE_ID STRING, SPAN_ID STRING, PARENT_SPAN_ID STRING,
  NAME STRING, KIND STRING, START_TIME TIMESTAMP_TZ, END_TIME TIMESTAMP_TZ, DURATION_MS FLOAT,
  STATUS_CODE STRING, STATUS_MESSAGE STRING, SERVICE_NAME STRING,
  ATTRIBUTES VARIANT, RESOURCE_ATTRIBUTES VARIANT
);
-- openssl genrsa 2048 | openssl pkcs8 -topk8 -nocrypt -out phaseo_key.p8
-- openssl rsa -in phaseo_key.p8 -pubout
ALTER USER PHASEO_BROADCAST SET RSA_PUBLIC_KEY = 'MIIBIjANBgkqh...';
```

प्राइवेट कुंजी (`BEGIN PRIVATE KEY`, बिना एन्क्रिप्शन) फ़ॉर्म में पेस्ट करें, और org-account पहचानकर्ता इस्तेमाल करें, जैसे `myorg-myaccount`। उपयोगकर्ता की भूमिका को टेबल पर `INSERT` और वेयरहाउस, डेटाबेस और स्कीमा पर `USAGE` चाहिए।

## डिलीवरी, स्थिति और अलर्ट

टाइमआउट, रेट लिमिट या सर्वर त्रुटि से विफल होने वाली डिलीवरी बैकऑफ़ के साथ, अधिकतम आठ प्रयासों तक, दोबारा भेजी जाती हैं। दूसरी त्रुटियाँ, जैसे अस्वीकार की गई कुंजी या गायब टेबल, दोबारा नहीं भेजी जातीं।

**सेटिंग्स → प्रसारण** हर गंतव्य की स्थिति दिखाता है: **ठीक है**, **विफल हो रहा है**, **अभी तक कोई डिलीवरी नहीं** या **अक्षम**, साथ में आख़िरी त्रुटि और पिछले 24 घंटों में डिलीवर और विफल हुए अनुरोध।

किसी गंतव्य के काम बंद करने पर सूचना पाने के लिए **प्रसारण अलर्ट** को किसी [सूचना गंतव्य](./workspace-notifications.mdx) पर रूट करें। अलर्ट तब भेजा जाता है जब कोई गंतव्य लगातार कम से कम पाँच अनुरोधों में विफल रहा हो और 15 मिनट से कुछ भी डिलीवर न किया हो। यह हर विफलता के सिलसिले में एक बार भेजा जाता है, और दोबारा तभी जब गंतव्य ठीक हो जाए और कम से कम छह घंटे बीत जाएँ।
