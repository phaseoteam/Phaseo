Broadcast आपके कोड में कोई बदलाव किए बिना हर गेटवे अनुरोध का ट्रेस आपके चुने हुए गंतव्यों पर भेजता है। ट्रेस OpenTelemetry GenAI कन्वेंशन का पालन करता है: अनुरोध के लिए एक span, और हर प्रदाता प्रयास के लिए एक span, जिनमें मॉडल, प्रदाता, टोकन उपयोग, लागत, समय और (जब तक आप इसे बंद न करें) प्रॉम्प्ट और आउटपुट शामिल होते हैं।

Broadcast मुफ़्त है। मालिक और एडमिन गंतव्यों को **सेटिंग्स → Broadcast** में, या [ऑब्ज़र्वेबिलिटी गंतव्य API](../api-reference/endpoint/observability-destinations-create.mdx) और `settings:write` वाली [मैनेजमेंट कुंजी](../developers/management-api-keys.mdx) से प्रबंधित करते हैं। एक वर्कस्पेस में हर प्रकार के अधिकतम पाँच गंतव्य हो सकते हैं।

## गंतव्य जोड़ें

1. **सेटिंग्स → Broadcast** खोलें और कोई गंतव्य चुनें।
2. उसके क्रेडेंशियल दर्ज करें। इन्हें सहेजने से पहले एन्क्रिप्ट किया जाता है और फिर कभी नहीं दिखाया जाता।
3. चुनें कि क्या भेजना है (नीचे "चुनें कि क्या भेजा जाए" देखें)।
4. **कनेक्शन का परीक्षण करें** चुनें। Phaseo एक नमूना ट्रेस उसी तरह भेजता है जैसे असली डिलीवरी भेजी जाती हैं, इसलिए यहाँ विफलता होने पर गंतव्य की अपनी त्रुटि दिखती है।
5. सहेजें। इसके बाद पूरे होने वाले अनुरोध लगभग एक मिनट के भीतर भेजे जाते हैं।

| प्रकार | गंतव्य |
| --- | --- |
| OpenTelemetry टूल | Arize AI, Axiom, Braintrust, Comet Opik, Datadog, Dynatrace, Elastic, Grafana Cloud, Honeycomb, Langfuse, LangSmith, New Relic, PostHog, Respan, Sentry, W&B Weave |
| कोई भी OTLP एंडपॉइंट | OpenTelemetry Collector (OTLP/HTTP, JSON या protobuf, वैकल्पिक gzip) |
| आपकी अपनी सेवा | Webhook |
| ऑब्जेक्ट स्टोरेज | Amazon S3 और S3-संगत स्टोर, Cloudflare R2, Google Cloud Storage |
| डेटाबेस और वेयरहाउस | ClickHouse, Google BigQuery, Snowflake |

हर फ़ॉर्म केवल वही माँगता है जिसकी उस टूल को ज़रूरत होती है, जैसे API कुंजी और प्रोजेक्ट या क्षेत्र। सभी OpenTelemetry टूल एक जैसे spans पाते हैं; Phaseo हर विक्रेता का एंडपॉइंट, हेडर और एन्कोडिंग खुद भरता है।

## चुनें कि क्या भेजा जाए

हर गंतव्य की अपनी सेटिंग्स होती हैं:

- **गोपनीयता मोड** हर ट्रेस से प्रॉम्प्ट, आउटपुट, सिस्टम निर्देश और टूल परिभाषाएँ हटा देता है। ऐसी API कुंजी से किए गए अनुरोध जो कभी सामग्री संग्रहित नहीं करती, इस सेटिंग से कोई फ़र्क नहीं पड़ता, कभी भी सामग्री के साथ आगे नहीं भेजे जाते।
- **जनरेशन मेटाडेटा**, **लागत**, **पहचान** और **अनुरोध संदर्भ** में से हर एक span एट्रिब्यूट के एक समूह को चालू या बंद करता है। **अनुरोध संदर्भ** बंद करने पर अनुरोध मेटाडेटा (नीचे "अपना ट्रेस संदर्भ जोड़ें" देखें) भी हट जाता है।
- **दर** योग्य अनुरोधों का एक हिस्सा भेजती है, 0 से 1 तक। यह चुनाव हर अनुरोध और गंतव्य के लिए स्थिर रहता है, इसलिए दोबारा की गई डिलीवरी का सैंपल कभी अलग तरीके से नहीं लिया जाता।
- **API कुंजी फ़िल्टर** खास कुंजियों से किए गए अनुरोधों को शामिल या बाहर करता है।
- **फ़िल्टर नियम** केवल मेल खाने वाले अनुरोध भेजते हैं। नियम मॉडल, प्रदाता, उपयोगकर्ता ID, समाप्ति कारण, लागत या टोकन संख्या जैसे फ़ील्ड की तुलना करते हैं, और इन्हें **और** तथा **या** से समूहित किया जा सकता है। **रेगुलर एक्सप्रेशन से मेल खाता है** एक लीनियर-टाइम इंजन का उपयोग करता है: बैक-रेफ़रेंस और लुकअराउंड समर्थित नहीं हैं, और बहुत बड़ा पैटर्न सहेजते समय अस्वीकार कर दिया जाता है।

## अपना ट्रेस संदर्भ जोड़ें

ट्रेस को नाम देने और अपने फ़ील्ड जोड़ने के लिए अनुरोध बॉडी में `metadata` ऑब्जेक्ट रखें। Phaseo इसे Broadcast के लिए पढ़ता है:

```json
{
  "model": "openai/gpt-5-nano",
  "messages": [{ "role": "user", "content": "Summarise this ticket" }],
  "metadata": {
    "trace_id": "ticket-48213",
    "trace_name": "support-summary",
    "generation_name": "summarise",
    "customer_tier": "enterprise"
  }
}
```

| कुंजी | प्रभाव |
| --- | --- |
| `trace_id` | वह ट्रेस जिससे अनुरोध जुड़ा है। 32 अक्षरों की hex ID या UUID को जैसा है वैसा इस्तेमाल किया जाता है; किसी भी दूसरी स्ट्रिंग को हैश किया जाता है, इसलिए एक ही मान वाले सभी अनुरोध एक ही ट्रेस में जुड़ते हैं। |
| `parent_span_id` | 16 अक्षरों की hex span ID, जिसके नीचे अनुरोध को नेस्ट करना है। `trace_id` के साथ इस्तेमाल होती है। |
| `trace_name`, `span_name` | अनुरोध के span का नाम। दोनों सेट होने पर `span_name` लागू होता है। |
| `generation_name` | हर प्रदाता प्रयास के span का नाम। |
| कोई भी दूसरी कुंजी | `phaseo.metadata.<key>` नाम के span एट्रिब्यूट के रूप में भेजी जाती है। |

मान स्ट्रिंग, संख्या या बूलियन हो सकते हैं; नेस्टेड ऑब्जेक्ट छोड़ दिए जाते हैं। Phaseo अधिकतम 64 अक्षरों वाली 64 कुंजियों तक रखता है, और मानों को 512 अक्षरों पर काट देता है। W3C `traceparent` हेडर मौजूद होने पर, `trace_id` और `parent_span_id` के बजाय वही ट्रेस तय करता है।

`metadata` में सीक्रेट या निजी डेटा न रखें: इसे हर उस गंतव्य पर भेजा जाता है जिसमें **अनुरोध संदर्भ** चालू है।

## वेबहुक डिलीवरी

वेबहुक को हर अनुरोध के लिए एक `POST` (या `PUT`, अगर आप इसे चुनें) मिलता है। बॉडी एक OTLP/JSON एक्सपोर्ट, `{"resourceSpans": [...]}`, होती है जिसमें उस अनुरोध के spans होते हैं। अपने हेडर जोड़ने के लिए **Headers JSON** का उपयोग करें, जैसे वह `Authorization` हेडर जिसकी आपके एंडपॉइंट को ज़रूरत है।

हर डिलीवरी, परीक्षण और नमूने को साइन करवाने के लिए **Signing Secret** (16 से 256 अक्षर, बिना स्पेस) जोड़ें। तब Phaseo दो हेडर जोड़ता है:

```http
x-phaseo-timestamp: 1792569600
x-phaseo-signature: 5d2a…e41f
```

`x-phaseo-signature` टाइमस्टैम्प, एक पूर्ण विराम (`.`) और बिना बदली गई अनुरोध बॉडी का HMAC-SHA256 है, जो आपके सीक्रेट को कुंजी बनाकर निकाला जाता है और hexadecimal में होता है। यह सूचना वेबहुक वाली ही योजना है, इसलिए आप उनका [सत्यापन कोड](./workspace-notifications.mdx) फिर से इस्तेमाल कर सकते हैं। Broadcast डिलीवरी में कोई इवेंट ID हेडर नहीं होता: बॉडी में मौजूद span IDs के आधार पर डुप्लिकेट हटाएँ।

**कनेक्शन का परीक्षण करें** `X-Test-Connection: true` हेडर के साथ `{"resourceSpans": []}` भेजता है। `400` प्रतिक्रिया को भी पहुँच योग्य माना जाता है, इसलिए खाली एक्सपोर्ट अस्वीकार करने वाला रिसीवर भी पास हो जाता है।

## ऑब्जेक्ट स्टोरेज और वेयरहाउस पंक्तियाँ

ऑब्जेक्ट स्टोरेज, ClickHouse, BigQuery और Snowflake को ट्रेस के बजाय हर span के लिए एक पंक्ति मिलती है। हर बैच एक ही अनुरोध में लिखा जाता है: एक ऑब्जेक्ट, या एक इंसर्ट।

| कॉलम | प्रकार | सामग्री |
| --- | --- | --- |
| `event_id` | स्ट्रिंग | अनुरोध की इवेंट ID। किसी अनुरोध के सभी spans में यही होती है। |
| `trace_id` | स्ट्रिंग | 32 अक्षरों की hex ट्रेस ID। |
| `span_id` | स्ट्रिंग | 16 अक्षरों की hex span ID। |
| `parent_span_id` | स्ट्रिंग या null | पैरेंट span, या अनुरोध के span के लिए null। |
| `name` | स्ट्रिंग | span का नाम। |
| `kind` | स्ट्रिंग | अनुरोध के लिए `server`, प्रदाता प्रयासों के लिए `client`। |
| `start_time`, `end_time` | टाइमस्टैम्प | UTC में RFC 3339, माइक्रोसेकंड तक। |
| `duration_ms` | संख्या | समाप्ति में से शुरुआत घटाकर, मिलीसेकंड में। |
| `status_code` | स्ट्रिंग | `unset`, `ok` या `error`। |
| `status_message` | स्ट्रिंग या null | त्रुटि संदेश, यदि कोई हो। |
| `service_name` | स्ट्रिंग या null | `phaseo-gateway`। |
| `attributes` | ऑब्जेक्ट | नाम के अनुसार span एट्रिब्यूट, जैसे `gen_ai.request.model` या `gen_ai.usage.input_tokens`, उनके प्रकार बरकरार रखते हुए। |
| `resource_attributes` | ऑब्जेक्ट | रिसोर्स एट्रिब्यूट, जैसे `service.name`। |

एक पंक्ति अधिकतम 512 KB की होती है। जब किसी span में इससे ज़्यादा डेटा हो, जैसे कोई इनलाइन इमेज, तो उसके सबसे बड़े एट्रिब्यूट मानों को जगह बाँटने के लिए काटा जाता है; हर मान की शुरुआत बनी रहती है और वह `…[truncated]` पर खत्म होता है, और उनके नाम `phaseo.truncated_attributes` एट्रिब्यूट में सूचीबद्ध होते हैं।

विफल बैच को दोबारा आज़माया जाता है। अगर गंतव्य ने बैच सहेज लिया लेकिन प्रतिक्रिया खो गई, तो दोबारा कोशिश करने पर कुछ पंक्तियाँ दो बार लिखी जा सकती हैं; डुप्लिकेट हटाने के लिए `event_id` और `span_id` का उपयोग करें। BigQuery और Snowflake ऐसी अनुरोध IDs का उपयोग करते हैं जो इनमें से ज़्यादातर डुप्लिकेट को रोकती हैं।

### ऑब्जेक्ट स्टोरेज

हर बैच एक gzip की हुई JSON lines फ़ाइल होता है। **Path Template** उसकी कुंजी सेट करता है, जो डिफ़ॉल्ट रूप से `phaseo/{year}/{month}/{day}/{hour}/{uuid}` होती है, और Phaseo अंत में `.jsonl.gz` जोड़ता है। टेम्पलेट में `{year}`, `{month}`, `{day}`, `{hour}`, `{date}` (`YYYY-MM-DD`) और `{uuid}` इस्तेमाल किए जा सकते हैं, और इसमें `{uuid}` होना ज़रूरी है ताकि फ़ाइलें कभी एक-दूसरे को ओवरराइट न करें। समय UTC में होते हैं।

- **Amazon S3**: एक एक्सेस कुंजी जो बकेट पर `s3:PutObject` कर सके, और बकेट का क्षेत्र। S3-संगत स्टोर के लिए **S3-Compatible Endpoint** सेट करें।
- **Cloudflare R2**: R2 API टोकन की एक्सेस कुंजी ID और सीक्रेट, आपकी अकाउंट ID, और अगर बकेट किसी क्षेत्राधिकार में है तो वह क्षेत्राधिकार (`eu` या `fedramp`)।
- **Google Cloud Storage**: ऐसे सर्विस अकाउंट की HMAC कुंजी जो बकेट में ऑब्जेक्ट बना सके।

ऑब्जेक्ट `Content-Encoding` हेडर के बिना संपीड़ित रूप में संग्रहित होते हैं, इसलिए Athena, BigQuery और Snowflake की external tables उन्हें उनके `.gz` एक्सटेंशन से पढ़ती हैं।

### ClickHouse

पंक्तियाँ HTTPS इंटरफ़ेस के ज़रिए `JSONEachRow` के रूप में, एसिंक्रोनस इंसर्ट के साथ डाली जाती हैं। जो कॉलम टेबल में नहीं हैं उन्हें छोड़ दिया जाता है, इसलिए आप केवल वही कॉलम रख सकते हैं जिनकी आपको ज़रूरत है:

```sql
CREATE TABLE phaseo_traces (
  event_id String, trace_id String, span_id String, parent_span_id Nullable(String),
  name String, kind LowCardinality(String),
  start_time DateTime64(6, 'UTC'), end_time DateTime64(6, 'UTC'), duration_ms Float64,
  status_code LowCardinality(String), status_message Nullable(String), service_name Nullable(String),
  attributes String, resource_attributes String
) ENGINE = MergeTree ORDER BY (start_time, trace_id);
```

ClickHouse Cloud के लिए पोर्ट 8443 वाला एंडपॉइंट इस्तेमाल करें। `attributes` और `resource_attributes` `JSON` कॉलम भी हो सकते हैं।

### BigQuery

पंक्तियाँ `insertAll` से स्ट्रीम की जाती हैं, और इवेंट व span IDs को इंसर्ट IDs के रूप में इस्तेमाल किया जाता है। टेबल पर **BigQuery Data Editor** वाला एक सर्विस अकाउंट बनाएँ, फिर उसकी JSON कुंजी फ़ाइल फ़ॉर्म में पेस्ट करें। `attributes` और `resource_attributes` का `JSON` कॉलम होना ज़रूरी है:

```sql
CREATE TABLE observability.phaseo_traces (
  event_id STRING, trace_id STRING, span_id STRING, parent_span_id STRING,
  name STRING, kind STRING, start_time TIMESTAMP, end_time TIMESTAMP, duration_ms FLOAT64,
  status_code STRING, status_message STRING, service_name STRING,
  attributes JSON, resource_attributes JSON
) PARTITION BY DATE(start_time) CLUSTER BY trace_id;
```

### Snowflake

हर बैच SQL API के ज़रिए एक `INSERT` होता है, जो की-पेयर ऑथेंटिकेशन से साइन इन करता है, इसलिए यह आपके बताए गए वेयरहाउस पर चलता है। Phaseo के लिए एक उपयोगकर्ता बनाएँ और उसे एक RSA कुंजी दें:

```sql
CREATE TABLE PHASEO.OBSERVABILITY.PHASEO_TRACES (
  EVENT_ID STRING, TRACE_ID STRING, SPAN_ID STRING, PARENT_SPAN_ID STRING,
  NAME STRING, KIND STRING, START_TIME TIMESTAMP_TZ, END_TIME TIMESTAMP_TZ, DURATION_MS FLOAT,
  STATUS_CODE STRING, STATUS_MESSAGE STRING, SERVICE_NAME STRING,
  ATTRIBUTES VARIANT, RESOURCE_ATTRIBUTES VARIANT
);
-- openssl genrsa 2048 | openssl pkcs8 -topk8 -nocrypt -out phaseo_key.p8
-- openssl rsa -in phaseo_key.p8 -pubout
ALTER USER PHASEO_BROADCAST SET RSA_PUBLIC_KEY = 'MIIBIjANBgkqh...';
```

प्राइवेट कुंजी (`BEGIN PRIVATE KEY`, बिना एन्क्रिप्शन) फ़ॉर्म में पेस्ट करें, और org-account पहचानकर्ता इस्तेमाल करें, जैसे `myorg-myaccount`। उपयोगकर्ता की भूमिका को टेबल पर `INSERT` और वेयरहाउस, डेटाबेस और स्कीमा पर `USAGE` की ज़रूरत होती है।

## डिलीवरी, स्थिति और अलर्ट

टाइमआउट, रेट लिमिट या सर्वर त्रुटि से विफल होने वाली डिलीवरी को बैकऑफ़ के साथ, अधिकतम आठ प्रयासों तक, दोबारा आज़माया जाता है। अन्य त्रुटियाँ, जैसे अस्वीकार की गई कुंजी या मौजूद न होने वाली टेबल, दोबारा नहीं आज़माई जातीं।

**सेटिंग्स → Broadcast** हर गंतव्य की स्थिति दिखाता है: **ठीक है**, **विफल हो रहा है**, **अभी तक कोई डिलीवरी नहीं** या **अक्षम**, साथ में आखिरी त्रुटि और पिछले 24 घंटों में डिलीवर और विफल हुए अनुरोध।

किसी गंतव्य के काम करना बंद करने पर सूचना पाने के लिए, **प्रसारण अलर्ट** को किसी [सूचना गंतव्य](./workspace-notifications.mdx) पर भेजें। अलर्ट तब भेजा जाता है जब कोई गंतव्य लगातार कम से कम पाँच अनुरोधों में विफल हो चुका हो और 15 मिनट से कुछ भी डिलीवर न किया हो। यह विफलताओं के हर सिलसिले में एक बार भेजा जाता है, और दोबारा तभी भेजा जाता है जब गंतव्य ठीक हो जाए और कम से कम छह घंटे बीत चुके हों।
