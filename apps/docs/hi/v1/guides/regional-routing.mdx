सिर्फ़ उन प्रदाता रूट का उपयोग करने के लिए जो उस क्षेत्र में मॉडल चलाते हैं और प्रॉम्प्ट व कम्प्लीशन डेटा संभालते हैं, टेक्स्ट अनुरोध `eu.api.phaseo.app` या `us.api.phaseo.app` पर भेजें। मॉडल ID और API कुंजियाँ वही रहती हैं। Chat Completions, Responses और Messages समर्थित हैं।

| क्षेत्र | बेस URL | उपयोग होने वाले प्रदाता रूट |
| --- | --- | --- |
| यूरोपीय संघ | `https://eu.api.phaseo.app/v1` | सिर्फ़ वे रूट जो EU में निष्पादन और EU में डेटा संभालने की घोषणा करते हैं |
| संयुक्त राज्य | `https://us.api.phaseo.app/v1` | सिर्फ़ वे रूट जो US में निष्पादन और US में डेटा संभालने की घोषणा करते हैं |
| ग्लोबल | `https://api.phaseo.app/v1` | सामान्य ग्लोबल रूटिंग नीति |

<Warning>
क्षेत्रीय रूटिंग अभी शुरू से अंत तक डेटा रेज़िडेंसी की गारंटी नहीं है। Phaseo प्रदाता चयन को सीमित करता है और Gateway को क्षेत्र के पास रखता है, लेकिन साझा खाता, बिलिंग, कैश और ऑपरेशनल सिस्टम क्षेत्र के बाहर डेटा प्रोसेस कर सकते हैं। [क्षेत्र के बाहर क्या रहता है](#what-stays-outside-the-region) देखें।
</Warning>

## क्षेत्रीय अनुरोध भेजें

<CodeGroup>
```ts TypeScript
import { Phaseo } from "@phaseo/sdk";

const phaseo = new Phaseo({
  apiKey: process.env.PHASEO_API_KEY!,
  region: "eu",
});

const response = await phaseo.responses.create({
  model: "openai/gpt-5.6-luna",
  input: "Summarize this note in one sentence.",
});

console.log(response.output_text);
```

```python Python
import os
from phaseo import Phaseo

phaseo = Phaseo(
    api_key=os.environ["PHASEO_API_KEY"],
    region="eu",
)

response = phaseo.responses.create({
    "model": "openai/gpt-5.6-luna",
    "input": "Summarize this note in one sentence.",
})

print(response.get("output_text"))
```

```bash Chat Completions
curl https://eu.api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5.6-luna",
    "messages": [
      {"role": "user", "content": "Write a two-line status update."}
    ]
  }'
```

```bash Responses
curl https://eu.api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5.6-luna",
    "input": "Extract the three most important actions from this note."
  }'
```

```bash Messages
curl https://us.api.phaseo.app/v1/messages \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -H "anthropic-version: 2023-06-01" \
  -d '{
    "model": "anthropic/claude-sonnet-5.5",
    "max_tokens": 256,
    "messages": [
      {"role": "user", "content": "Summarize this incident report."}
    ]
  }'
```
</CodeGroup>

SDK में `region` को `"eu"` या `"us"` पर सेट करें; ग्लोबल रूटिंग के लिए इसे छोड़ दें, या `"global"` का उपयोग करें। अगर आप `region` और कस्टम `baseUrl` (Python में `base_url`) दोनों सेट करते हैं, तो SDK त्रुटि देता है, क्योंकि दोनों अलग-अलग होस्ट चुनते हैं।

होस्टनेम ही नीति है। अनुरोध या प्रीसेट में किसी दूसरे क्षेत्र का नाम लेने वाला `required_execution_region` या `required_data_region` `400 validation_error`, कारण `deployment_region_conflict`, के साथ विफल होता है। प्रीसेट और डायनैमिक रूटिंग नियम पहले लागू होते हैं और क्षेत्रीय नियम सबसे बाद में, इसलिए वे इसे कमज़ोर नहीं कर सकते। Phaseo कभी क्षेत्र के बाहर के प्रदाता से दोबारा प्रयास नहीं करता।

## क्षेत्रीय अनुरोध में क्या हो सकता है

| समर्थित | अस्वीकृत |
| --- | --- |
| टेक्स्ट इनपुट और टेक्स्ट आउटपुट | इमेज, ऑडियो, वीडियो, दस्तावेज़, फ़ाइलें और अटैचमेंट |
| स्ट्रीमिंग और नॉन-स्ट्रीमिंग | गैर-टेक्स्ट आउटपुट मोडैलिटी |
| सिस्टम और डेवलपर निर्देश | प्रदाता-होस्टेड टूल, जैसे वेब सर्च, फ़ाइल सर्च, कोड निष्पादन, कंप्यूटर उपयोग और इमेज जनरेशन, और `web_search_options` |
| आपके अपने `function` और `custom` टूल, और टेक्स्ट टूल परिणाम | Phaseo [सर्वर टूल](./server-tools) (`phaseo:` प्रकार) |
| संरचित टेक्स्ट और JSON आउटपुट, जहाँ मॉडल सपोर्ट करता है | इमेज, ऑडियो, वीडियो, एम्बेडिंग, मॉडरेशन, बैच, फ़ाइल, वेबहुक और रियलटाइम एंडपॉइंट |
| प्रीसेट, प्रदाता क्रम, फ़ॉलबैक और कीमत सीमाएँ जो क्षेत्र से टकराती नहीं | |

आपके अपने टूल अनुमत हैं क्योंकि वे आपके ऐप्लिकेशन में चलते हैं। होस्टेड और सर्वर टूल ऐसी जगह चलते हैं जिसे क्षेत्रीय नियम नियंत्रित नहीं कर सकता।

## किसी क्षेत्र में उपलब्ध मॉडल खोजें

उसी होस्टनेम पर `/v1/models` कॉल करें जिस पर आप अनुरोध भेजते हैं। EU, US और ग्लोबल एंडपॉइंट के बीच उपलब्धता अलग होती है।

```bash
curl https://eu.api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

सूची में सिर्फ़ वे मॉडल होते हैं जिनका कोई सक्रिय प्रदाता रूट है और जिसके घोषित निष्पादन और डेटा क्षेत्र दोनों में वह क्षेत्र शामिल है, और यह टेक्स्ट इनपुट व आउटपुट के साथ सिर्फ़ Chat Completions, Responses और Messages दिखाती है। हर ऑफ़र अपने क्षेत्र दिखाता है:

```json
{
  "provider": { "id": "example-eu", "name": "Example EU" },
  "residency": {
    "execution_regions": ["eu"],
    "data_regions": ["eu"]
  }
}
```

## देखें कि किस Gateway ने अनुरोध संभाला

क्षेत्रीय प्रतिक्रियाओं में `X-Phaseo-Gateway-Region: eu` (या `us`) होता है। यह हेडर उस क्षेत्रीय नीति का नाम बताता है जिसने अनुरोध संभाला; यह इसका सबूत नहीं है कि Cloudflare ने उसे कहाँ चलाया। अनुरोध विवरण में आवश्यक निष्पादन और डेटा क्षेत्र, चुना गया प्रदाता और उस प्रदाता के घोषित क्षेत्र भी दर्ज होते हैं।

## त्रुटियाँ

क्षेत्रीय नियम के उल्लंघन पर `400 not_supported` इनमें से किसी `reason` मान के साथ लौटता है:

| `reason` | कारण | समाधान |
| --- | --- | --- |
| `regional_endpoint_not_supported` | पाथ क्षेत्रीय रूप से उपलब्ध नहीं है | Chat Completions, Responses या Messages, या ग्लोबल API का उपयोग करें |
| `regional_non_text_content` | अनुरोध में मीडिया, फ़ाइल या अटैचमेंट है | उसे हटाएँ, या ग्लोबल API का उपयोग करें |
| `regional_non_text_output` | गैर-टेक्स्ट आउटपुट मोडैलिटी का अनुरोध किया गया | टेक्स्ट माँगें, या ग्लोबल API का उपयोग करें |
| `regional_hosted_tool_not_supported` | `function` या `custom` के अलावा कोई टूल | अपना फ़ंक्शन टूल, या ग्लोबल API का उपयोग करें |

कारण `deployment_region_conflict` के साथ `400 validation_error` का मतलब है कि अनुरोध या किसी प्रीसेट में दूसरे क्षेत्र का नाम है; वह सेटिंग हटाएँ। अगर कोई स्वस्थ प्रदाता रूट मॉडल और क्षेत्र दोनों को पूरा नहीं करता, तो अनुरोध किसी प्रदाता को कॉल करने से पहले ही रुक जाता है; क्षेत्रीय `/v1/models` में सूचीबद्ध कोई मॉडल चुनें।

## क्षेत्र के बाहर क्या रहता है

क्षेत्रीय नियम यह तय करता है कि कौन-सा प्रदाता मॉडल चलाता है और प्रॉम्प्ट व कम्प्लीशन डेटा संभालता है। यह अभी पूरे अनुरोध लाइफ़साइकल को कवर नहीं करता:

- Cloudflare प्लेसमेंट Gateway को क्षेत्र के पास रखता है, लेकिन यह अनुपालन सीमा नहीं है।
- खाता, प्रमाणीकरण, बिलिंग और अनुरोध मेटाडेटा साझा Supabase इन्फ़्रास्ट्रक्चर पर रहते हैं।
- Cloudflare KV और Worker इनवोकेशन लॉग किसी क्षेत्र से बंधे नहीं हैं।
- प्रदाता को कॉल उस प्रदाता के क्षेत्रीय एंडपॉइंट पर जाती हैं, चाहे Cloudflare ने Gateway कहीं भी रखा हो।
- सपोर्ट और ऑपरेशंस स्टाफ़ क्षेत्र तक सीमित नहीं हैं।

Phaseo इसे शुरू से अंत तक डेटा रेज़िडेंसी तभी कहेगा जब Gateway, स्टोरेज, लॉगिंग, प्रदाता और ऑपरेशनल पाथ, सभी पर लागू करने योग्य क्षेत्रीय नियंत्रण होंगे।
