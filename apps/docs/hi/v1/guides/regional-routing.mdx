प्रदाता का निष्पादन और उसकी डेटा प्रोसेसिंग Phaseo द्वारा दस्तावेज़ित EU या US रूट के भीतर रखने के लिए क्षेत्रीय Phaseo एंडपॉइंट इस्तेमाल करें। मॉडल ID या API कुंजियाँ बदले बिना Chat Completions, Responses और Messages के साथ क्षेत्रीय रूटिंग इस्तेमाल कर सकते हैं।

<Warning>
क्षेत्रीय रूटिंग अभी आरंभ से अंत तक डेटा के उसी क्षेत्र में रहने की गारंटी नहीं है। Phaseo प्रदाता चयन सीमित करता है और चुने हुए क्षेत्र के पास Cloudflare का प्लेसमेंट संकेत इस्तेमाल करता है, लेकिन साझा खाता, बिलिंग, कैश और संचालन प्रणालियाँ उस क्षेत्र के बाहर डेटा प्रोसेस कर सकती हैं।
</Warning>

## एंडपॉइंट चुनें

| क्षेत्र | बेस URL | व्यवहार |
| --- | --- | --- |
| यूरोपीय संघ | `https://eu.api.phaseo.app/v1` | निष्पादन और डेटा क्षेत्र EU वाले प्रदाता रूट आवश्यक हैं |
| संयुक्त राज्य अमेरिका | `https://us.api.phaseo.app/v1` | निष्पादन और डेटा क्षेत्र US वाले प्रदाता रूट आवश्यक हैं |
| वैश्विक | `https://api.phaseo.app/v1` | मानक वैश्विक रूटिंग नीति इस्तेमाल होती है |

क्षेत्रीय होस्टनाम नीति की सीमा है। अनुरोध विरोधी `required_execution_region` या `required_data_region` मान देकर इसे ओवरराइड नहीं कर सकता।

## Phaseo SDK इस्तेमाल करें

क्लाइंट बनाते समय `region` सेट करें। उस क्लाइंट से किया गया हर समर्थित अनुरोध संबंधित क्षेत्रीय बेस URL इस्तेमाल करता है।

<CodeGroup>
```ts TypeScript
import { Phaseo } from "@phaseo/sdk";

const phaseo = new Phaseo({
  apiKey: process.env.PHASEO_API_KEY!,
  region: "eu",
});

const response = await phaseo.responses.create({
  model: "openai/gpt-5-mini",
  input: "Summarize this note in one sentence.",
});

console.log(response.output_text);
```

```python Python
import os
from phaseo import Phaseo

phaseo = Phaseo(
    api_key=os.environ["PHASEO_API_KEY"],
    region="eu",
)

response = phaseo.responses.create({
    "model": "openai/gpt-5-mini",
    "input": "Summarize this note in one sentence.",
})

print(response.get("output_text"))
```
</CodeGroup>

US रूटिंग के लिए `"us"` इस्तेमाल करें। वैश्विक रूटिंग के लिए `region` छोड़ दें या `"global"` इस्तेमाल करें। SDK उन कॉन्फ़िगरेशन को अस्वीकार करता है जो `region` के साथ कस्टम `baseUrl` या `base_url` जोड़ते हैं, क्योंकि दोनों विकल्प परस्पर विरोधी होस्ट चुनेंगे।

## Chat Completions इस्तेमाल करें

```bash
curl https://eu.api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5-mini",
    "messages": [
      {"role": "user", "content": "Write a two-line status update."}
    ]
  }'
```

## Responses इस्तेमाल करें

```bash
curl https://eu.api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5-mini",
    "input": "Extract the three most important actions from this note."
  }'
```

## Messages इस्तेमाल करें

Messages एंडपॉइंट Anthropic का अनुरोध प्रारूप स्वीकार करता है और वही क्षेत्रीय प्रदाता प्रतिबंध बनाए रखता है।

```bash
curl https://us.api.phaseo.app/v1/messages \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -H "anthropic-version: 2023-06-01" \
  -d '{
    "model": "anthropic/claude-sonnet-4.6",
    "max_tokens": 256,
    "messages": [
      {"role": "user", "content": "Summarize this incident report."}
    ]
  }'
```

## समर्थित अनुरोध सुविधाएँ

क्षेत्रीय रूटिंग अभी इनका समर्थन करती है:

- टेक्स्ट इनपुट और टेक्स्ट आउटपुट
- स्ट्रीमिंग और बिना स्ट्रीमिंग के जवाब
- सिस्टम और डेवलपर निर्देश
- क्लाइंट द्वारा परिभाषित फ़ंक्शन टूल और कस्टम टूल
- टेक्स्ट वाले टूल परिणाम
- मॉडल के समर्थन पर संरचित टेक्स्ट और JSON आउटपुट
- क्षेत्रीय नीति से न टकराने वाले प्रीसेट, प्रदाता क्रम, फ़ॉलबैक और कीमत सीमाएँ

क्षेत्रीय एंडपॉइंट इन्हें अस्वीकार करते हैं:

- चित्र, ऑडियो, वीडियो, दस्तावेज़, फ़ाइलें और अटैचमेंट
- टेक्स्ट के अलावा अन्य आउटपुट माध्यम
- प्रदाता द्वारा होस्ट किए गए टूल, जैसे वेब खोज, फ़ाइल खोज, कोड निष्पादन, कंप्यूटर इस्तेमाल और चित्र जनरेशन
- चित्र, ऑडियो, वीडियो, एम्बेडिंग, मॉडरेशन, बैच, फ़ाइल, वेबहुक और रीयलटाइम एंडपॉइंट

फ़ंक्शन टूल स्वीकार हैं क्योंकि वे आपकी ऐप्लिकेशन में चलते हैं। प्रदाता द्वारा होस्ट किया गया टूल रोक दिया जाता है क्योंकि उसका निष्पादन स्थान क्षेत्रीय नीति से मेल न खा सकता है।

## किसी क्षेत्र में उपलब्ध मॉडल खोजें

जनरेशन के लिए इस्तेमाल होने वाले उसी क्षेत्रीय होस्टनाम से `/v1/models` कॉल करें:

```bash
curl https://eu.api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

जवाब में केवल वे मॉडल होते हैं जिनका प्रदाता रूट सक्रिय है और जिनके घोषित निष्पादन तथा डेटा क्षेत्र, दोनों, चुने हुए क्षेत्र को शामिल करते हैं। इसमें केवल टेक्स्ट इनपुट और आउटपुट वाले Chat Completions, Responses और Messages घोषित होते हैं।

हर ऑफ़र में उसका क्षेत्रीय मेटाडेटा होता है:

```json
{
  "provider": { "id": "example-eu", "name": "Example EU" },
  "residency": {
    "execution_regions": ["eu"],
    "data_regions": ["eu"]
  }
}
```

EU, US और वैश्विक एंडपॉइंट के बीच मॉडल उपलब्धता अलग हो सकती है। हमेशा उसी एंडपॉइंट से मॉडल खोजें जिसे आपकी ऐप्लिकेशन कॉल करेगी।

## चुना गया गेटवे सत्यापित करें

क्षेत्रीय जवाबों में शामिल है:

```http
X-Phaseo-Gateway-Region: eu
```

इस हेडर से पुष्टि करें कि अनुरोध अपेक्षित Phaseo डिप्लॉयमेंट तक पहुँचा। अनुरोध विवरण में आवश्यक निष्पादन क्षेत्र, आवश्यक डेटा क्षेत्र, चुना गया प्रदाता और प्रदाता का घोषित क्षेत्रीय मेटाडेटा दर्ज होता है।

<Note>
हेडर अनुरोध संभालने वाली Phaseo की क्षेत्रीय नीति पहचानता है। यह Cloudflare के निष्पादन के उसी क्षेत्र में रहने की गारंटी का प्रमाण नहीं है।
</Note>

## विफलता का व्यवहार

क्षेत्रीय रूटिंग नीति पूरी न होने पर बंद हो जाती है। Phaseo होस्टनाम के क्षेत्र से बाहर के प्रदाता के माध्यम से अनुरोध का चुपचाप पुनः प्रयास कभी नहीं करता।

| त्रुटि | अर्थ | क्या करें |
| --- | --- | --- |
| `regional_endpoint_not_supported` | पथ क्षेत्रीय Workers पर उपलब्ध नहीं है | तीन समर्थित टेक्स्ट एंडपॉइंट में से एक या वैश्विक API इस्तेमाल करें |
| `regional_non_text_content` | अनुरोध में मीडिया, फ़ाइल या अटैचमेंट है | गैर-टेक्स्ट सामग्री हटाएँ या वैश्विक API इस्तेमाल करें |
| `regional_non_text_output` | अनुरोध गैर-टेक्स्ट जवाब माँगता है | टेक्स्ट आउटपुट माँगें या वैश्विक API इस्तेमाल करें |
| `regional_hosted_tool_not_supported` | प्रदाता द्वारा होस्ट किया गया टूल माँगा गया है | क्लाइंट द्वारा परिभाषित फ़ंक्शन टूल या वैश्विक API इस्तेमाल करें |
| `deployment_region_conflict` | अनुरोध या प्रीसेट दूसरा क्षेत्र बताता है | विरोधी सेटिंग हटाएँ |
| कोई प्रदाता रूट उपलब्ध नहीं | कोई स्वस्थ प्रदाता मॉडल और क्षेत्रीय नीति की शर्तें पूरी नहीं करता | क्षेत्रीय `/v1/models` एंडपॉइंट से लौटाया गया दूसरा मॉडल चुनें |

## क्षेत्रीय रूटिंग का दायरा

स्वीकृत जनरेशन अनुरोध के लिए Phaseo चाहता है कि चुना गया प्रदाता रूट दोनों घोषित करे:

1. चुने हुए क्षेत्र में मॉडल निष्पादन
2. चुने हुए क्षेत्र में प्रॉम्प्ट और जवाब डेटा का प्रसंस्करण

Phaseo प्रीसेट और डायनेमिक रूटिंग नियमों के मिल जाने के बाद ये शर्तें लागू करता है, इसलिए ये सुविधाएँ होस्टनाम नीति कमजोर नहीं कर सकतीं। कोई प्रदाता मेल न खाने पर अनुरोध अपस्ट्रीम मॉडल निष्पादन से पहले रुक जाता है।

## वर्तमान सीमाएँ

यह शुरुआती रिलीज़ गारंटी नहीं देती कि अनुरोध का पूरा जीवनचक्र चुने हुए क्षेत्र के भीतर रहेगा:

- Cloudflare Workers प्लेसमेंट संकेत कॉन्फ़िगर किए गए क्लाउड क्षेत्र के पास स्थान चुनते हैं, लेकिन अनुपालन की सीमा नहीं बनाते।
- Phaseo के खाते, प्रमाणीकरण, बिलिंग और अनुरोध मेटाडेटा साझा Supabase बुनियादी ढाँचा इस्तेमाल करते हैं।
- Cloudflare KV और Worker इनवोकेशन लॉग क्षेत्र से बँधे नहीं हैं।
- प्रदाता उप-अनुरोध चुने गए प्रदाता एंडपॉइंट से सीमित होते हैं, Cloudflare की प्लेसमेंट सेटिंग से नहीं।
- सहायता और संचालन पहुँच चुने हुए क्षेत्र के कर्मचारियों तक सीमित नहीं है।

Phaseo इस सुविधा को आरंभ से अंत तक डेटा रेज़िडेंसी तभी बताएगा जब गेटवे, स्टोरेज, लॉगिंग, प्रदाता और संचालन पथ लागू किए जा सकने वाले क्षेत्रीय नियंत्रणों से सुरक्षित होंगे।
