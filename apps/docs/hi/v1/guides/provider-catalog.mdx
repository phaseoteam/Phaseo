स्वीकृत प्रदाता अपने कैटलॉग फ़ीड या प्रदाता सेटिंग्स के ज़रिए मौजूदा सार्वजनिक कैनोनिकल मॉडल के ऑफ़र अपडेट कर सकते हैं। नए कैनोनिकल मॉडल के लिए स्वीकृति आवश्यक है। हर कैटलॉग एक पूर्ण स्नैपशॉट होता है: कोई ऑफ़र हटाने पर फ़ीड से प्रबंधित वह ऑफ़र निष्क्रिय हो जाता है और उसका मूल्य इतिहास सुरक्षित रहता है।

## प्रारूप चुनें

मौजूदा V1 फ़ीड बिना किसी बदलाव के काम करते रहते हैं। बिना संस्करण वाला `{"data": [...]}` दस्तावेज़, या `"schema_version": "1.0"` घोषित करने वाला दस्तावेज़, मौजूदा मानक-स्तर प्रारूप का उपयोग करता है।

V1.1 में `"schema_version": "1.1"` घोषित किया जाता है और हर मॉडल के भीतर `service_tiers` प्रकाशित किए जाते हैं। आयातक प्रारूप दस्तावेज़ से तय करता है। `?format=phaseo-v1.1` जैसे URL क्वेरी पैरामीटर आपके एंडपॉइंट की वैकल्पिक परिपाटियाँ हैं; Phaseo URL से संस्करण का अनुमान नहीं लगाता।

[V1 स्कीमा](https://phaseo.app/api/internal/provider-catalog/schema) या [V1.1 स्कीमा](https://phaseo.app/api/internal/provider-catalog/schema?version=1.1) डाउनलोड करें। असमर्थित संस्करण स्पष्ट रूप से अस्वीकार किए जाते हैं।

## मानकीकृत स्तर प्रकाशित करें

| स्तर | अर्थ |
| --- | --- |
| `standard` | सामान्य सिंक्रोनस निष्पादन; हर मॉडल के लिए आवश्यक। |
| `fast` | तेज़ या प्राथमिकता वाला ऑफ़र। HighSpeed जैसे प्रदाता के अपने नाम अपस्ट्रीम मॉडल ID में ही रहते हैं। |
| `ultrafast` | समर्थित होने पर अलग, और भी तेज़ गति वाला ऑफ़र। |
| `flex` | लचीला, कम प्राथमिकता वाला सिंक्रोनस ऑफ़र। |
| `batch` | Batch API के ज़रिए एसिंक्रोनस निष्पादन। इसके लिए बैच क्षमता आवश्यक है। |

प्रदाता-विशिष्ट स्तर नामों को मानकीकृत ID के रूप में इस्तेमाल न करें। कॉल करने वालों के लिए `priority` अब भी Fast का समर्थित उपनाम है; कैटलॉग `fast` प्रकाशित करते हैं।

Fast, Ultrafast और Flex का चयन टेक्स्ट जनरेशन अनुरोधों पर समर्थित है। Batch अलग Batch API से चलता है और उसके लिए अब भी प्रदाता का Batch एकीकरण इंस्टॉल होना आवश्यक है; स्तर प्रकाशित करने से वह एकीकरण इंस्टॉल नहीं होता। अपलोड की गई प्रदाता-नेटिव फ़ाइलों के लिए घोषित Batch मॉडल ID का उपयोग करें, या अनुरोध इनलाइन भेजें ताकि Phaseo उसे रूपांतरित कर सके।

किसी मॉडल के सभी सेवा स्तरों के लिए उसी कैनोनिकल मॉडल ID का उपयोग करें। अलग-अलग मॉडल के लिए अलग कैनोनिकल पहचान आवश्यक है। स्तर मॉडल की क्षमताएँ, सीमाएँ और रिलीज़ कार्यक्रम विरासत में लेते हैं। हर स्तर अपनी अपस्ट्रीम मॉडल ID, उपलब्धता और प्रभावी मूल्य स्वयं घोषित करता है।

```json
{
  "schema_version": "1.1",
  "data": [{
    "id": "your-provider/example-model",
    "name": "Example model",
    "capabilities": ["chat.completions"],
    "service_tiers": [{
      "service_tier": "standard",
      "provider_model_slug": "example-model",
      "availability": "ready",
      "pricing": [{
        "meter_key": "input_text_tokens",
        "modality": "text",
        "direction": "input",
        "unit": "token",
        "unit_quantity": 1000000,
        "price_nanos": 100000000,
        "display_label": "Input",
        "display_unit": "1M tokens"
      }, {
        "meter_key": "output_text_tokens",
        "modality": "text",
        "direction": "output",
        "unit": "token",
        "unit_quantity": 1000000,
        "price_nanos": 200000000,
        "display_label": "Output",
        "display_unit": "1M tokens"
      }]
    }]
  }]
}
```

Fast जोड़ने के लिए `"service_tier": "fast"`, उसके प्रभावी मूल्यों और उस ऑफ़र की अलग अपस्ट्रीम मॉडल ID के साथ एक और स्तर ऑब्जेक्ट जोड़ें। अगर प्रदाता इसके बजाय अपनी लेन किसी नेटिव पैरामीटर से चुनता है, तो वही अपस्ट्रीम मॉडल ID रखें और `"upstream_service_tier": "priority"` या `"fast"` घोषित करें। जब मॉडल ID से ही लेन चुनी जाती हो, तो यह फ़ील्ड छोड़ दें। Standard `default` या `standard` स्वीकार करता है; Flex और Ultrafast अपने संगत मान स्वीकार करते हैं। जिन गैर-मानक सिंक्रोनस स्तरों के पास न अलग मॉडल ID है और न नेटिव चयनकर्ता, उन्हें Phaseo अस्वीकार करता है।

हर स्तर के लिए स्पष्ट मूल्य आवश्यक हैं, जिनमें आउटपुट और आपके द्वारा बिल किए जाने वाले सभी कैश/मीडिया मीटर शामिल हैं। शून्य मूल्य मान्य हैं; ऋणात्मक मूल्य, अज्ञात मीटर, दोहराए गए स्तर और सशर्त दरें अस्वीकार की जाती हैं। `price_nanos` छूट के बाद का प्रभावी मूल्य ही रहता है। दरें बदलने पर नया स्नैपशॉट प्रकाशित करें; Phaseo पिछले प्रभावी मूल्य सुरक्षित रखता है।

## रेट सीमाएँ घोषित करें

आपका प्लेटफ़ॉर्म Phaseo के खाते पर जो अनुरोध और टोकन सीमाएँ लागू करता है, उन्हें वैकल्पिक शीर्ष-स्तरीय `rate_limits` ऐरे में घोषित करें। यह V1 और V1.1 दोनों दस्तावेज़ों में एक ही तरह काम करता है। अपने सभी मॉडल पर लागू सीमा के लिए `model` छोड़ दें, या इसे उसी दस्तावेज़ के किसी मॉडल या स्तर के अपस्ट्रीम `provider_model_slug` पर सेट करें।

```json
{
  "schema_version": "1.1",
  "data": [{ "id": "your-provider/example-model", "...": "..." }],
  "rate_limits": [
    { "requests_per_minute": 600, "tokens_per_minute": 2000000 },
    { "model": "example-model", "requests_per_day": 100000, "tokens_per_day": 500000000 }
  ]
}
```

हर प्रविष्टि `requests_per_minute`, `requests_per_day`, `tokens_per_minute` और `tokens_per_day` स्वीकार करती है। हर मान धनात्मक पूर्णांक या `null` होता है, और हर प्रविष्टि में कम से कम एक मान आवश्यक है। Phaseo हर सीमा को आपकी ओर जाने वाले अपने पूरे ट्रैफ़िक पर वैश्विक रूप से गिनता है। मॉडल सीमा, सभी मॉडल की सीमा के अतिरिक्त लागू होती है।

सीमाएँ कभी अनुरोध ब्लॉक नहीं करतीं। जैसे-जैसे किसी ऑफ़र का ट्रैफ़िक सीमा के करीब पहुँचता है, Phaseo उसे धीरे-धीरे कम हिस्सा भेजता है। सीमा तक पहुँचने पर, सीमा रीसेट होने तक Phaseo उस ऑफ़र को अन्य प्रदाताओं से नीचे रैंक करता है। बहुत कम मान केवल ट्रैफ़िक में आपका अपना हिस्सा घटाता है। इसी कारण, आपका प्रदाता आवेदन स्वीकृत होने के बाद सीमाएँ बिना समीक्षा के लागू होती हैं, आमतौर पर एक मिनट के भीतर।

ऐरे मौजूद होने पर, बदले हुए फ़ीड के हर सफल आयात पर यह आपकी घोषित सीमाओं को बदल देता है। खाली ऐरे उन्हें हटा देता है। प्रदाता सेटिंग्स में प्रबंधित सीमाएँ बनाए रखने के लिए `rate_limits` छोड़ दें। अगर कोई प्रविष्टि ऐसे मॉडल का नाम ले जो दस्तावेज़ में नहीं है, कोई दायरा दोहराए, या ऐसा मान इस्तेमाल करे जो धनात्मक पूर्णांक नहीं है, तो Phaseo पूरा स्नैपशॉट अस्वीकार करता है और आपका मौजूदा कैटलॉग तथा सीमाएँ बनाए रखता है। यह अस्वीकृति **बदलाव आवश्यक** के रूप में दिखती है।

आप **प्रदाता सेटिंग्स → आपके मॉडल → रेट सीमाएँ** में भी सीमाएँ संपादित कर सकते हैं। ये संपादन कैटलॉग बदलावों से अलग सहेजे जाते हैं। कैटलॉग संपादक `rate_limits` स्वीकार नहीं करता।

## अपडेट करें और सत्यापित करें

पोलिंग और हस्ताक्षरित कैटलॉग-परिवर्तन वेबहुक एक ही ऑनबोर्डिंग और रीफ़्रेश प्रक्रिया से दोनों संस्करण स्वीकार करते हैं। प्रदाता सेटिंग्स में किसी स्तर की अपस्ट्रीम ID, उपलब्धता या मूल्य संपादित करने से पहले वह स्तर चुनें। एक और स्तर जोड़ने पर सहेजा गया कैटलॉग V1.1 में बदल जाता है।

कैटलॉग कोई इन्फ़रेंस एडैप्टर या क्रेडेंशियल नहीं जोड़ता। रूटिंग सक्षम होने से पहले प्रदाता और उसकी घोषित क्षमताओं का एकीकरण आवश्यक है। Batch मूल्य निर्धारण से सिंक्रोनस चैट एंडपॉइंट पर Batch उपलब्ध नहीं हो जाता।

अनुपलब्ध कैनोनिकल मॉडल या अज्ञात प्रकाशक मैपिंग **बदलाव आवश्यक** के रूप में दिखाई जाती है, लेकिन इससे मान्य मॉडल का आयात नहीं रुकता। मॉडल-विशिष्ट कारणों के लिए प्रदाता डैशबोर्ड देखें।

API से भरे जाने वाले कैटलॉग में डैशबोर्ड के संपादन स्थायी ओवरराइड होते हैं। आयात केवल बिना ओवरराइड वाले फ़ील्ड अपडेट करता है। ओवरराइड हटाकर उस फ़ील्ड के लिए फिर से फ़ीड का पालन शुरू करने के लिए **फ़ीड का मान उपयोग करें** चुनें। डैशबोर्ड नवीनतम फ़ीड मान, प्रभावी मान, संपादक और समय दिखाता है; कैटलॉग गतिविधि संपादन और बहाली दर्ज करती है। मैन्युअल रूप से जोड़े गए मॉडल स्थानीय ऑफ़र बने रहते हैं। फ़ीड से कोई मॉडल हटाने पर उसका फ़ीड ऑफ़र निष्क्रिय हो जाता है, भले ही उसके कुछ फ़ील्ड संपादित किए गए हों। मौजूदा केवल-मैन्युअल कैटलॉग समर्थित बने रहते हैं।
