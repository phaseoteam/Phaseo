`phaseo:advisor` जोड़ें ताकि मुख्य मॉडल जवाब देने से पहले किसी दूसरे मॉडल से समीक्षा, योजना, सही-गलत की जाँच या विशेषज्ञ राय माँग सके। मुख्य मॉडल Advisor को किसी भी दूसरे टूल की तरह कॉल करता है; Phaseo Advisor मॉडल चलाता है और उसकी सलाह टूल परिणाम के रूप में लौटाता है।

```bash
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [
      { "role": "user", "content": "Design a rate limiter for a distributed API gateway." }
    ],
    "tools": [
      {
        "type": "phaseo:advisor",
        "parameters": {
          "model": "anthropic/claude-opus-5",
          "max_uses": 1,
          "max_completion_tokens": 1400
        }
      }
    ]
  }'
```

Advisor किसी भी समर्थित टेक्स्ट मॉडल के साथ काम करता है। Phaseo इसे ख़ुद चलाता है; यह Anthropic के नेटिव Advisor टूल में सिर्फ़ तब बदला जाता है जब आप Anthropic का नेटिव टूल आकार भेजते हैं।

## पैरामीटर

```json
{
  "type": "phaseo:advisor",
  "parameters": {
    "name": "reviewer",
    "model": "anthropic/claude-opus-5",
    "instructions": "Review plans for correctness, missing edge cases, and implementation risk.",
    "forward_transcript": true,
    "max_uses": 2,
    "max_completion_tokens": 1400,
    "reasoning": { "effort": "high" },
    "temperature": 0.2
  }
}
```

| पैरामीटर | प्रकार | डिफ़ॉल्ट | विवरण |
| --- | --- | --- | --- |
| `name` | string | कोई नहीं | 1 से 64 अक्षर, अंक, स्पेस, अंडरस्कोर या डैश। एक से ज़्यादा Advisor जोड़ने पर ज़रूरी। |
| `model` | string | नीचे देखें | Advisor मॉडल। |
| `instructions` | string | बिल्ट-इन Advisor निर्देश | Advisor के लिए अतिरिक्त निर्देश। |
| `forward_transcript` | boolean | `false` | मौजूदा बातचीत Advisor को भेजें। |
| `max_uses` | integer | `1` | हर अनुरोध में इस Advisor को कितनी बार कॉल किया जा सकता है। |
| `max_completion_tokens` | integer | `1400` | हर Advisor जवाब के आउटपुट टोकन। `1024` से कम मान `1024` कर दिए जाते हैं। `max_tokens` पुराने उपनाम के रूप में स्वीकार किया जाता है। |
| `reasoning` | object | प्रदाता डिफ़ॉल्ट | रीज़निंग सेटिंग्स, जहाँ Advisor मॉडल उन्हें सपोर्ट करता है वहाँ आगे भेजी जाती हैं। |
| `temperature` | number | प्रदाता डिफ़ॉल्ट | Advisor कॉल के लिए सैंपलिंग तापमान। |

Advisor मॉडल `parameters.model` होता है अगर वह सेट है; नहीं तो वह `model` जो मुख्य मॉडल अपनी कॉल में भेजता है; नहीं तो अनुरोध का अपना मॉडल।

## मॉडल क्या भेजता है

आम तौर पर एक `prompt`। अगर टूल कोई मॉडल तय नहीं करता, तो कॉल ख़ुद भी मॉडल चुन सकती है:

```json
{
  "model": "anthropic/claude-opus-5",
  "prompt": "Check this security design for missing controls."
}
```

`forward_transcript: true` होने पर मॉडल बिना प्रॉम्प्ट के Advisor को कॉल कर सकता है, और Advisor आगे भेजी गई बातचीत की समीक्षा करता है।

## कई Advisor जोड़ें

हर Advisor के लिए एक `phaseo:advisor` एंट्री जोड़ें। हर नाम वाला Advisor मॉडल के लिए अपना अलग टूल बन जाता है, जैसे `phaseo_advisor_security_reviewer`।

```json
{
  "tools": [
    {
      "type": "phaseo:advisor",
      "parameters": {
        "name": "security-reviewer",
        "model": "anthropic/claude-opus-5",
        "instructions": "Review for vulnerabilities, abuse cases, and missing mitigations."
      }
    },
    {
      "type": "phaseo:advisor",
      "parameters": {
        "name": "architect",
        "model": "openai/gpt-5",
        "instructions": "Review system design tradeoffs and operational risks."
      }
    }
  ]
}
```

आगे-पीछे के स्पेस हटाने और बड़े-छोटे अक्षरों का फ़र्क़ अनदेखा करने के बाद नाम अद्वितीय होने चाहिए, और ज़्यादा से ज़्यादा एक एंट्री में `name` छोड़ा जा सकता है; नहीं तो अनुरोध अस्वीकार कर दिया जाता है। कई Advisor होने पर `tool_choice: "phaseo:advisor"` पहले वाले को ज़बरदस्ती चुनता है।

## टूल क्या लौटाता है

```json
{
  "status": "ok",
  "name": "reviewer",
  "model": "anthropic/claude-opus-5",
  "advice": "Start with a smaller migration slice and define rollback criteria before changing traffic routing."
}
```

अगर कॉल नहीं चल पाती, तो मॉडल को इसकी जगह एक त्रुटि परिणाम मिलता है: `advisor_invalid_request` (कोई प्रॉम्प्ट या कोई मॉडल नहीं), `advisor_max_uses_exceeded` या `advisor_request_failed`।

Advisor अनुरोधों के बीच कोई स्थिति नहीं रखता। अगर आप पहले के मैसेज और टूल परिणाम दोबारा भेजते हैं, तो मुख्य मॉडल पहले की सलाह देखता है; Advisor बातचीत सिर्फ़ तभी देखता है जब `forward_transcript` चालू हो। सलाह स्ट्रीम नहीं होती, और Advisor ख़ुद टूल कॉल नहीं कर सकता।

## उपयोग और कीमत

हर कॉल `usage.server_tool_use.advisor_requests` में 1 जोड़ती है और उसका बिल `server_tool_advisor_requests` के साथ बन सकता है। Advisor के टोकन अनुरोध के उपयोग में जोड़े जाते हैं और Advisor मॉडल की दरों पर गिने जाते हैं।
