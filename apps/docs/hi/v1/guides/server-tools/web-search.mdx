`phaseo:web_search` जोड़ें, ताकि मॉडल को नवीनतम या स्रोत-आधारित जानकारी चाहिए तो वह वेब खोज सके। मॉडल query लिखता है और एक अनुरोध में कई बार खोज सकता है; Phaseo URL, शीर्षक, स्निपेट, हाइलाइट और वैकल्पिक रूप से पेज टेक्स्ट लौटाता है, और मॉडल स्रोत-आधारित उत्तर लिखता है।

```bash
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [
      { "role": "user", "content": "What were the major AI announcements this week?" }
    ],
    "tools": [
      { "type": "phaseo:web_search" }
    ]
  }'
```

यही टूल एंट्री `/v1/responses` और `/v1/messages` पर `tools` में भी काम करती है।

<span id="parameters"></span>
## पैरामीटर

```json
{
  "type": "phaseo:web_search",
  "parameters": {
    "engine": "exa",
    "max_results": 5,
    "max_total_results": 15,
    "search_context_size": "medium",
    "max_characters": 2048,
    "allowed_domains": ["arxiv.org", "nature.com"],
    "include_highlights": true,
    "include_text": false
  }
}
```

| पैरामीटर | प्रकार | डिफ़ॉल्ट | विवरण |
| --- | --- | --- | --- |
| `engine` | string | `exa` | `auto`, `native`, `exa`, `parallel`, `firecrawl`, `perplexity` या `tinyfish`। देखें [इंजन चुनें](#choose-an-engine)। |
| `max_results` | integer | `5` | प्रति खोज कॉल परिणाम, अधिकतम `25`। |
| `max_total_results` | integer | `25` | अनुरोध की सभी खोजों में कुल परिणाम, अधिकतम `100`। कभी `max_results` से कम नहीं। |
| `max_uses` | integer | `10` | प्रति अनुरोध खोज कॉल, अधिकतम `100`। |
| `search_context_size` | string | `medium` | `low`, `medium` या `high`, उन इंजनों के लिए जो हाइलाइट का आकार तय करते हैं। |
| `max_characters` | integer | इंजन का डिफ़ॉल्ट | टेक्स्ट शामिल होने पर प्रति परिणाम टेक्स्ट के अक्षर। |
| `allowed_domains` | string[] | कोई नहीं | सिर्फ़ इन डोमेन में खोजें। उपनाम: `include_domains`। |
| `excluded_domains` | string[] | कोई नहीं | इन डोमेन को बाहर रखें। उपनाम: `exclude_domains`। |
| `include_highlights` | boolean | `true` | इंजन के हाइलाइट या स्निपेट शामिल करें। |
| `include_text` | boolean | `false` | जहां इंजन सपोर्ट करे, वहां पेज का ज़्यादा पूरा टेक्स्ट शामिल करें। |
| `user_location` | object | कोई नहीं | `engine` के `native` होने पर प्रदाता की अपनी खोज को भेजा जाने वाला स्थान संकेत। |

## मॉडल क्या भेजता है

हर कॉल में एक `query` होती है। मॉडल `max_results`, `engine`, `search_context_size`, डोमेन सूचियां, `include_text`, `include_highlights`, `max_characters` और ये स्थानीयकरण संकेत भी भेज सकता है:

| आर्गुमेंट | विवरण |
| --- | --- |
| `user_location` | अनुमानित स्थान। Perplexity क्षेत्रीय खोज के लिए `user_location.country` उपयोग करता है; TinyFish देश और भाषा उपयोग करता है। |
| `language` | परिणाम की भाषा का कोड, जैसे `en`, उन इंजनों के लिए जो स्थानीयकरण करते हैं। |
| `page` | परिणाम पेज `0` से `10`, TinyFish के लिए। |

मॉडल जो मान भेजता है, वे उस कॉल के लिए टूल के डिफ़ॉल्ट की जगह लेते हैं। `max_results` फिर भी `max_total_results` में बचे हिस्से तक सीमित रहता है; वह खत्म होने पर आगे की कॉल `max_total_results_reached` लौटाती हैं।

<span id="choose-an-engine"></span>
## इंजन चुनें

| इंजन | क्या चलता है |
| --- | --- |
| `exa` | प्रबंधित Exa खोज। डिफ़ॉल्ट। |
| `auto` | प्रबंधित डिफ़ॉल्ट, अभी Exa। |
| `parallel` | प्रबंधित Parallel खोज। |
| `firecrawl` | प्रबंधित Firecrawl खोज। |
| `perplexity` | Perplexity Search API: रैंक किए गए परिणाम, `search_context_size`, और `user_location.country` से क्षेत्रीय खोज। |
| `tinyfish` | TinyFish Search: स्थानीयकृत, पेज-वार रैंक किए गए परिणाम। यह स्निपेट लौटाता है, पूरा पेज टेक्स्ट नहीं; मॉडल को ज़्यादा चाहिए तो [`phaseo:web_fetch`](./web-fetch) उपयोग करें। |
| `native` | प्रदाता का अपना वेब खोज टूल, जैसे OpenAI का `web_search_preview` या Anthropic का `web_search_20250305`। |

अगर कोई प्रबंधित इंजन सक्षम नहीं है, तो कॉल मॉडल को `search_not_configured` लौटाती है।

`/v1/chat/completions` या `/v1/responses` पर `engine: "native"` के साथ अनुरोध सिर्फ़ उन प्रदाताओं को जाता है जो खुद वेब खोज चलाते हैं। अगर कोई भी प्रदाता मॉडल को सर्व नहीं करता, तो Phaseo अपना डिफ़ॉल्ट इंजन चलाता है और उसका बिल प्रबंधित खोज के रूप में बनाता है। `native` सिर्फ़ टूल परिभाषा में सेट करें: अगर मॉडल किसी कॉल में `native` मांगता है, तो कॉल `unsupported_search_engine` लौटाती है, क्योंकि प्रदाता का टूल अनुरोध भेजने से पहले चुनना होता है।

## डोमेन से फ़िल्टर करें

जब उत्तर स्रोतों के एक तय सेट से ही आना चाहिए, तब `allowed_domains` उपयोग करें, और खुली खोज से कुछ खास साइटें हटाने के लिए `excluded_domains`।

```json
{
  "type": "phaseo:web_search",
  "parameters": { "allowed_domains": ["phaseo.app", "github.com"] }
}
```

इंजन सूचियों को अलग-अलग तरह से संभालते हैं:

- **Perplexity** दोनों में से एक ही सूची लेता है, दोनों नहीं, और अधिकतम 20 डोमेन। बाहर रखे गए डोमेन उसके deny-list फ़ॉर्मेट में भेजे जाते हैं।
- **Firecrawl** दोनों में से एक ही सूची लेता है, दोनों नहीं।
- **TinyFish** दोनों लेता है और उन्हें query में `site:` और `-site:` ऑपरेटर में बदल देता है।

## टूल क्या लौटाता है

एक JSON परिणाम, जिसमें इंजन, query और एक `results` ऐरे होता है। हर परिणाम में `title`, `url`, `snippet` या `highlights` होते हैं, और `text` तब, जब पेज टेक्स्ट मांगा गया हो और इंजन उसे देता हो।

## उपयोग और मूल्य

हर खोज `usage.server_tool_use` में जुड़ती है:

```json
{
  "usage": {
    "server_tool_use": {
      "web_search_requests": 1,
      "web_search_results": 5,
      "web_search_extra_results": 0
    }
  }
}
```

Phaseo हर managed search के लिए $0.007 लेता है, और पहले 10 के बाद हर result के लिए $0.001, जब तक मॉडल का price card `server_tool_web_search_requests` और `server_tool_web_search_extra_results` के लिए अपनी कीमतें तय न करे। असफल searches का शुल्क नहीं लगता, और TinyFish Search अपने प्रकाशित प्लान पर मुफ़्त है, इसलिए `engine: "tinyfish"` कोई search शुल्क नहीं जोड़ता। सशुल्क engines पर searches के लिए क्रेडिट चाहिए, भले ही मॉडल मुफ़्त हो। Native search का बिल `native_web_search_requests` से बनता है, जहाँ मॉडल का price card इसे तय करता है।
