प्रीसेट किसी एक काम के लिए मॉडल, सिस्टम प्रॉम्प्ट, पैरामीटर और प्रदाता नियमों को `@support-triage` जैसे नाम के तहत सेव करता है। कॉलर `model` के रूप में वह नाम और सिर्फ़ इनपुट भेजते हैं; बाकी सब Gateway प्रदाता चुनने से पहले भर देता है।

अनुरोध फ़ील्ड को चालू-बंद करके देखें कि कौन-सा मान लागू होता है:

<PresetMergeExplorer locale="hi" />

नियम ये हैं:

- **पैरामीटर खाली जगह भरते हैं।** प्रीसेट के डिफ़ॉल्ट पैरामीटर सिर्फ़ उन फ़ील्ड पर लागू होते हैं जिन्हें अनुरोध छोड़ देता है। अनुरोध में दिया गया मान हमेशा लागू होता है।
- **सिस्टम प्रॉम्प्ट जुड़ते जाते हैं।** प्रीसेट का प्रॉम्प्ट पहले आता है। अगर अनुरोध में अपना सिस्टम प्रॉम्प्ट या `instructions` है, तो वह एक खाली पंक्ति के बाद आता है।
- **अनुरोध की प्रदाता सेटिंग लागू होती हैं।** अनुरोध में `provider.order` या `provider.max_price` जैसे फ़ील्ड उस फ़ील्ड के लिए प्रीसेट का मान बदल देते हैं।
- **अनुमति सूचियाँ दायरा घटाती हैं, कभी बढ़ाती नहीं।** प्रीसेट की प्रदाता अनुमति और अनदेखी सूचियाँ प्रदाता चुनने से पहले लागू होती हैं, इसलिए ये यह भी सीमित करती हैं कि फ़ॉलबैक किन प्रदाताओं का उपयोग कर सकता है। प्रीसेट के अनुमत मॉडलों से बाहर का मॉडल `validation_error` के साथ विफल होता है, जिसका विवरण कीवर्ड `preset_model_not_allowed` होता है; उसे दूसरी जगह रूट नहीं किया जाता।

## प्रीसेट बनाएँ और उपयोग करें

<Steps>
<Step title="प्रीसेट बनाएँ">

**डैशबोर्ड -> सेटिंग्स -> प्रीसेट** खोलें और `support-triage` जैसे slug के साथ प्रीसेट बनाएँ। सिर्फ़ वे डिफ़ॉल्ट जोड़ें जो हर कॉलर को साझा करने चाहिए।

CLI से: `phaseo presets create --name @support-triage --model <model-id>`।

</Step>

<Step title="इसे नाम से कॉल करें">

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "@support-triage",
    "input": "Customer says the invoice total is wrong."
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "@support-triage",
  input: "Customer says the invoice total is wrong.",
});
```

```python Python
from phaseo import Phaseo

client = Phaseo(api_key="YOUR_API_KEY")

response = client.generate_response({
    "model": "@support-triage",
    "input": "Customer says the invoice total is wrong.",
})
```
</CodeGroup>

</Step>

<Step title="देखें कि क्या लागू हुआ">

**Gateway -> उपयोग** में अनुरोध खोलें और देखें कि प्रीसेट के कौन-से डिफ़ॉल्ट लागू हुए और किस प्रदाता ने उसे संभाला।

</Step>
</Steps>

## प्रीसेट में क्या रखा जा सकता है

| सेटिंग | असर |
| --- | --- |
| मॉडल | जब अनुरोध प्रीसेट के नाम से भेजा जाता है, तब उपयोग होता है। |
| अनुमत मॉडल | मॉडल ID या `anthropic/*` जैसे पैटर्न। बाकी मॉडल अस्वीकार किए जाते हैं। |
| सिस्टम प्रॉम्प्ट | हर अनुरोध की शुरुआत में जोड़ा जाता है। |
| [प्रॉम्प्ट टेम्पलेट](./prompt-templates) | `{{variables}}` वाले संदेश, जिन्हें हर अनुरोध भरता है। |
| डिफ़ॉल्ट पैरामीटर | `temperature`, `top_p`, `max_tokens`, रीज़निंग सेटिंग और इसी तरह के अन्य। |
| प्रदाता नियम | अनुमति और अनदेखी सूचियाँ, प्रदाता क्रम, क्षेत्र, कीमत की ऊपरी सीमा। |

कॉलर-विशेष लॉजिक अपने ऐप्लिकेशन में रखें, और जब वर्कफ़्लो को अलग प्रॉम्प्ट, रूटिंग या कैशिंग चाहिए तो अलग प्रीसेट का उपयोग करें।

## प्रीसेट को नाम दें

प्रीसेट को `model` फ़ील्ड से भेजें, या जब उसमें [प्रॉम्प्ट टेम्पलेट](./prompt-templates) हो तो `prompt.id` से। कोई अलग `preset` फ़ील्ड नहीं है।

| रूप | कहाँ से रिज़ॉल्व होता है |
| --- | --- |
| `@support-triage` | API कुंजी का वर्कस्पेस (निजी और वर्कस्पेस प्रीसेट)। |
| `@octavia/support-triage` | कोई भी वर्कस्पेस (सार्वजनिक प्रीसेट, उपयोगकर्ता `octavia` द्वारा प्रकाशित)। |
| `@support-triage@v3` | वह प्रकाशित संस्करण। |
| `@support-triage@production` | वह संस्करण जिस पर `production` लेबल इशारा करता है। |

सार्वजनिक प्रीसेट प्रकाशित करने के लिए सक्षम सार्वजनिक प्रोफ़ाइल और उपयोगकर्ता नाम चाहिए। उपयोगकर्ता नाम पूरे Phaseo में अद्वितीय होते हैं; slug सिर्फ़ एक प्रकाशक के लिए अद्वितीय होने चाहिए। Slug छोटे अक्षरों में बदल दिए जाते हैं और उनमें अक्षर, अंक, `-`, `_`, `.` और `:` हो सकते हैं।

## संस्करण बनाएँ और वापस लौटें

सेव करने से एक निजी ड्राफ़्ट में बदलाव होता है। **नया संस्करण प्रकाशित करें** ड्राफ़्ट को एक अपरिवर्तनीय, क्रमांकित रिलीज़ में बदल देता है और हर पिछली रिलीज़ को बनाए रखता है।

चुनें कि रिलीज़ लेबल कैसे दिखें:

| फ़ॉर्मैट | उदाहरण |
| --- | --- |
| क्रमिक | `v1`, `v2`, `v3` |
| सिमैंटिक वर्ज़निंग | `1.2.0`, `2.0.0-beta.1`, `1.4.2+build.7` |
| तारीख | `2026.08.02`, फिर उसी दिन दूसरी रिलीज़ के लिए `2026.08.02.2` |

`production` जैसे नामित लेबल को किसी संस्करण पर इंगित करें, और वापस लौटने के लिए उसे किसी पिछले संस्करण पर ले जाएँ। [संस्करण और लेबल](/hi/v1/guides/prompt-templates#versions-and-labels) देखें।

CLI से: `phaseo presets versions create` और `phaseo presets labels set`, या `/v1/presets` API।

## मार्केटप्लेस प्रीसेट को फ़ोर्क करें

मार्केटप्लेस प्रीसेट की कॉपी उसी संस्करण पर पिन रहती है जिसे आपने कॉपी किया था। जब प्रकाशक कोई अपडेट रिलीज़ करता है, तो आपकी कॉपी पर एक सूचना दिखती है। उसे लागू करने से सिर्फ़ आपका ड्राफ़्ट बदलता है, इसलिए जब तक आप खुद प्रकाशित नहीं करते, प्रोडक्शन तक कुछ नहीं पहुँचता।

Phaseo हर फ़ोर्क का स्रोत और पूरी वंशावली दर्ज करता है, ताकि मार्केटप्लेस पेज सीधे फ़ोर्क को सभी वंशजों से अलग दिखा सके।

किसी प्रीसेट के जवाबों पर रेटिंग इकट्ठा करने के लिए [प्रीसेट के लिए फ़ीडबैक इकट्ठा करें](./preset-feedback) देखें।
