हर उपयोगकर्ता रेटिंग को अनुरोध ID और जवाब देने वाले [प्रीसेट](./presets.mdx) के साथ `POST /v1/feedback` पर भेजें, फिर प्रीसेट की तुलना सिर्फ़ लेटेंसी और लागत से नहीं, बल्कि इस बात से भी करें कि उनके जवाबों को कितनी बार अच्छी रेटिंग मिली।

<Note>
प्रीसेट फ़ीडबैक Alpha में है, और API व डैशबोर्ड अभी बदल सकते हैं। इसे और उपयोगी बनाने के लिए अपने सुझाव देने हेतु [प्रीसेट फ़ीडबैक पेज](https://phaseo.app/settings/presets/experiments) पर **फ़ीडबैक** बटन का उपयोग करें।
</Note>

## रेटिंग दर्ज करें

आपको `feedback:write` क्षमता वाली API कुंजी, Phaseo द्वारा लौटाई गई अनुरोध ID, और प्रीसेट का UUID चाहिए। प्रीसेट ID ही इवेंट को प्रीसेट तुलनाओं और कोहॉर्ट विश्लेषण में शामिल करती है।

```bash cURL
curl https://api.phaseo.app/v1/feedback \
  -X POST \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "requestId": "gen_01K...",
    "presetId": "8f54b2d9-9ba3-4ced-8a7f-9bb70a44dbea",
    "rating": "thumbs_up",
    "score": 1,
    "comment": "The answer resolved the customer question.",
    "metadataDimensions": {
      "plan": "pro",
      "surface": "support_chat"
    }
  }'
```

फ़ीडबैक इवेंट को कम से कम एक अनुरोध, सत्र, प्रीसेट या टेस्ट रन को लक्षित करना होगा। `score` वैकल्पिक है और `0` से `1` के बीच होना चाहिए।

प्लान, डिप्लॉयमेंट, लोकेल या ऐप्लिकेशन सरफ़ेस जैसे कम कार्डिनैलिटी वाले मान `metadataDimensions` में रखें, ताकि आप उनसे फ़िल्टर कर सकें। मनमाना या ज़्यादा कार्डिनैलिटी वाला संदर्भ इसके बजाय `metadata` में रखें।

## रेटिंग चुनें

| संकेत | `rating` |
| --- | --- |
| सामान्य उपयोगकर्ता प्रतिक्रिया | `thumbs_up`, `thumbs_down` |
| मूल्यांकित जवाब | `correct`, `partly_correct`, `incorrect` |
| ऑपरेशनल समस्या | `bad_format`, `too_slow`, `too_expensive` |
| सुरक्षा परिणाम | `unsafe`, `refused_incorrectly` |
| बाकी सब | `not_helpful`, `other` |

सिर्फ़ संख्यात्मक स्कोर के बजाय स्पष्ट रेटिंग को प्राथमिकता दें: प्रीसेट तुलनाएँ रेटिंग पर बनती हैं, और स्कोर सहायक जानकारी के रूप में दिखाए जाते हैं।

## प्रीसेट की तुलना करें

[सेटिंग्स → प्रीसेट → फ़ीडबैक](https://phaseo.app/settings/presets/experiments) खोलें और:

- सकारात्मक, आंशिक और नकारात्मक दरों की तुलना करें
- एक बेसलाइन प्रीसेट चुनें
- तारीख, रेटिंग और मेटाडेटा आयामों से फ़िल्टर करें
- किसी इवेंट के पीछे का अनुरोध, सत्र, टिप्पणियाँ और टैग देखें

डैशबोर्ड चुनी गई अवधि में मेल खाने वाली अधिकतम 10,000 सबसे हाल की फ़ीडबैक पंक्तियों का विश्लेषण करता है।

## API से फ़ीडबैक पढ़ें

पढ़ने के लिए `feedback:read` चाहिए। नतीजे प्रमाणित वर्कस्पेस और उन प्रीसेट तक सीमित रहते हैं जिन्हें कॉलर देख सकता है।

हाल के इवेंट की सूची:

```bash
curl "https://api.phaseo.app/v1/feedback?preset_id=PRESET_UUID&limit=100" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

सर्वर पर गणना किया गया सारांश:

```bash
curl "https://api.phaseo.app/v1/feedback/summary?group_by=preset&since=2026-08-01T00:00:00Z" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

टेस्ट रन और कस्टम परिणाम इवेंट के API उपलब्ध हैं, लेकिन उनके डैशबोर्ड व्यू अभी बदल रहे हैं। किसी प्रीसेट बदलाव को धीरे-धीरे रोल आउट करने के लिए [प्रीसेट रोल आउट करें और रूटिंग डीबग करें](../cookbook/preset-rollout-and-routing-debug) देखें।
