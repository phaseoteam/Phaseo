ऐसे किसी भी ऑटोमेशन प्लेटफ़ॉर्म से Phaseo को कॉल करें जो प्रमाणित HTTP अनुरोध भेज सकता हो: एक HTTP स्टेप जोड़ें जो आपकी कुंजी को bearer token के रूप में लेकर `https://api.phaseo.app/v1/responses` पर POST करे। Phaseo का कोई नेटिव Zapier, n8n या Pipedream ऐप नहीं है।

## अनुरोध बनाएँ

| सेटिंग | मान |
| --- | --- |
| मेथड | `POST` |
| URL | `https://api.phaseo.app/v1/responses` |
| हेडर | `Authorization: Bearer <PHASEO_API_KEY>` |
| हेडर | `Content-Type: application/json` |

```json
{
  "model": "openai/gpt-6-astra",
  "input": "Summarise the supplied workflow data in one paragraph."
}
```

कुंजी को प्लेटफ़ॉर्म के क्रेडेंशियल या सीक्रेट स्टोर में रखें, किसी साझा वर्कफ़्लो परिभाषा में नहीं। हर अनुरोध फ़ील्ड के लिए [Responses](../../api-reference/endpoint/responses.mdx) देखें।

## Zapier

**Webhooks by Zapier → Custom Request** इस्तेमाल करें:

1. `POST` चुनें और `https://api.phaseo.app/v1/responses` दर्ज करें।
2. bearer और content-type हेडर जोड़ें।
3. पिछले Zap स्टेप के फ़ील्ड `input` में मैप करें।
4. संवेदनशील न होने वाले डेटा से Zap टेस्ट करें।

## n8n

bearer ऑथेंटिकेशन और JSON बॉडी के साथ **HTTP Request** नोड इस्तेमाल करें। आने वाले आइटम को n8n एक्सप्रेशन से `input` में मैप करें।

## Pipedream

एक HTTP अनुरोध स्टेप या Node.js कोड स्टेप इस्तेमाल करें। `PHASEO_API_KEY` को Pipedream सीक्रेट के रूप में रखें और उसे स्टेप एनवायरनमेंट से पढ़ें।

## जाँचें कि यह काम करता है

स्टेप एक बार चलाएँ। `output` ऐरे वाली `200` प्रतिक्रिया का मतलब है कि कुंजी और URL काम करते हैं, और अनुरोध **सेटिंग्स → उपयोग → लॉग्स** में दिखता है।

## ऑटोमेशन सुरक्षित रूप से चलाएँ

- हर ऑटोमेशन को खर्च सीमा वाली उसकी अपनी कुंजी दें, ताकि आप उसे अलग से ट्रैक और रद्द कर सकें।
- जब बाद के स्टेप मशीन से पढ़े जाने लायक फ़ील्ड की उम्मीद करें, तो [संरचित आउटपुट](../structured-outputs.mdx) इस्तेमाल करें।
- `429` और ठीक हो सकने वाली `5xx` प्रतिक्रियाओं पर दोबारा कोशिश करें; [एरर](../../api-reference/errors.mdx) देखें।
- जो बाहरी कार्रवाइयाँ idempotent नहीं हैं, उन्हें सिर्फ़ इसलिए न दोहराएँ कि किसी मॉडल स्टेप की दोबारा कोशिश हुई।
