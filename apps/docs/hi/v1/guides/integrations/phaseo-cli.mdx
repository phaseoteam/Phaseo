कोडिंग एजेंट को Phaseo से जोड़ने और टर्मिनल से कुंजियाँ, वर्कस्पेस, प्रीसेट, सेटिंग्स और गार्डरेल प्रबंधित करने के लिए `@phaseo/cli` इंस्टॉल करें और `phaseo login` चलाएँ। CLI मॉडल, प्रदाता, कीमतें, क्रेडिट, गतिविधि, एनालिटिक्स और जनरेशन भी पढ़ता है।

## इंस्टॉल करें

<CodeGroup>

```bash npm
npm install -g @phaseo/cli
```

```bash pnpm
pnpm add -g @phaseo/cli
```

```bash yarn
yarn global add @phaseo/cli
```

```bash bun
bun add -g @phaseo/cli
```

</CodeGroup>

वर्ज़न जाँचें:

| कमांड | क्या प्रिंट करता है |
| --- | --- |
| `phaseo --version` | इंस्टॉल किया गया वर्ज़न। |
| `phaseo version` | वर्ज़न और आपके पैकेज मैनेजर के लिए अपडेट कमांड। संरचित आउटपुट के लिए `--json` जोड़ें। |

नया वर्ज़न प्रकाशित होने पर इंटरैक्टिव रन एक संकेत भी दिखाते हैं।

## साइन इन करें

```bash
phaseo login
```

| फ़्लो | फ़्लैग | किसके लिए इस्तेमाल करें |
| --- | --- | --- |
| Phaseo से साइन इन करें | `--browser` | ऑथराइज़ेशन कोड और PKCE के साथ ब्राउज़र OAuth। |
| डिवाइस कोड से साइन इन करें | `--device-code` | SSH, CI, हेडलेस शेल और एजेंट एनवायरनमेंट। |

रिमोट और गैर-इंटरैक्टिव एनवायरनमेंट अपने आप डिवाइस कोड इस्तेमाल करते हैं। आप किस खाते से साइन इन हैं, अपने स्कोप, सक्रिय वर्कस्पेस और दूसरे वर्कस्पेस के साथ देखें:

```bash
phaseo whoami
phaseo whoami --json
```

## कुंजियाँ बनाएँ और अपना वर्कस्पेस प्रबंधित करें

```bash
phaseo keys create --name "Local CLI Key"
phaseo keys create --name "Agent Sandbox Key" --json
phaseo keys current

phaseo workspaces list
phaseo workspaces members <workspace-id-or-slug>

phaseo guardrails list
phaseo guardrails create --name "Production Safety" --body-json '{"enabled":true}'
```

जब किसी एजेंट या स्क्रिप्ट को नई कुंजी चाहिए, तो `--json` इस्तेमाल करें; कुंजी सिर्फ़ एक बार दिखाई जाती है। CLI डैशबोर्ड के प्रबंधन कार्य कवर करता है, जिनमें बिलिंग, बजट, BYOK, रूटिंग और आइडेंटिटी शामिल हैं। हर कार्य की कमांड के लिए [एजेंट से Phaseo प्रबंधित करें](../../developers/manage-from-an-agent) देखें।

## कोडिंग एजेंट जोड़ें

एजेंट का नाम कमांड के रूप में इस्तेमाल करें। CLI एक समर्पित कुंजी बनाता है और एजेंट का कॉन्फ़िगरेशन लिखता है:

```bash
phaseo codex
phaseo claude-code
phaseo opencode
phaseo fx
phaseo deepseek-harness
phaseo pi
phaseo prime-agent
phaseo openclaw
phaseo hermes
phaseo aider
phaseo continue
phaseo zed
phaseo roo-code
phaseo kilo-code
phaseo cursor
```

ज़रूरत के अनुसार `--model`, `--catalog all|default` या `--dry-run` इस्तेमाल करें। `phaseo setup <agent>` और `phaseo integrations setup <agent>` भी काम करते हैं।

Cline, Kilo Code, oh-my-pi, Muse Code या MiniMax Code को ऐसी अस्थायी सेटिंग्स के साथ चलाने के लिए जो उनके बंद होने पर मिट जाएँ, सत्र रनर इस्तेमाल करें। Phaseo के फ़्लैग `--` से पहले, और एजेंट के अपने फ़्लैग उसके बाद लिखें:

```bash
phaseo cline --model openai/gpt-5.6-terra -- --tui
phaseo kilo --model openai/gpt-5.6-terra
phaseo omp --model openai/gpt-5.6-terra
phaseo muse --model meta/muse-spark-1.3
phaseo minimax --model openai/gpt-5.6-terra
```

`phaseo run <cline|kilo|omp|muse|minimax>` लंबा रूप है। हर सक्रिय Phaseo टेक्स्ट मॉडल दिखाने के लिए `--catalog all` जोड़ें, या कुंजी बनाए बिना पूर्वावलोकन के लिए `--dry-run --json`। इंटरैक्टिव टर्मिनल में रनर गायब एजेंट को इंस्टॉल करने का विकल्प देते हैं (Windows पर MiniMax Code अपना आधिकारिक PowerShell इंस्टॉलर इस्तेमाल करता है; Windows पर Muse Code हाथ से इंस्टॉल करना होता है)। जब आप एजेंट ख़ुद संभालते हैं, तो `--skip-install` इस्तेमाल करें।

[कोडिंग एजेंट](./coding-assistants.mdx) हर एजेंट, उसकी कमांड क्या करती है, और उसकी गाइड की सूची देता है।

## CLI से स्क्रिप्ट लिखें

`--json` वाली कमांड बिना रंग या स्पिनर के सादा संरचित आउटपुट प्रिंट करती हैं। बाकी जगहों पर स्पिनर `stderr` पर जाते हैं और काम पूरा होने पर अपनी लाइन साफ़ कर देते हैं।

| वेरिएबल | असर |
| --- | --- |
| `NO_COLOR` | रंग बंद करता है। |
| `TERM=dumb` | एनिमेशन बंद करता है। Non-TTY `stderr` भी यही करता है। |
| `FORCE_COLOR=1` | जब कोई टर्मिनल रैपर रंग सपोर्ट करता है लेकिन TTY रिपोर्ट नहीं करता, तब रंग ज़बरदस्ती चालू करता है। |

## CLI क्रेडेंशियल कैसे सुरक्षित रखता है

- सत्र OS क्रेडेंशियल स्टोर में रखे जाते हैं। `PHASEO_SESSION_BACKEND=file` सिर्फ़ तभी सेट करें जब कोई क्रेडेंशियल स्टोर उपलब्ध न हो; यह रिफ़्रेश टोकन को सीमित अनुमतियों वाली सादा-टेक्स्ट फ़ाइल में रखता है।
- `phaseo logout` लोकल स्थिति साफ़ करने से पहले सेव किया गया रिफ़्रेश टोकन रद्द करता है।
- प्रबंधन कुंजियों को स्पष्ट क्षमताएँ चाहिए। इनफ़रेंस कुंजियाँ स्कोप की जगह गार्डरेल, रूटिंग नीतियों और वर्कस्पेस सेटिंग्स से सीमित होती हैं।

## OAuth ऐप

Phaseo CLI, उपयोगकर्ताओं के बनाए ऐप और डायनामिक रूप से रजिस्टर किए गए MCP क्लाइंट के लिए एक ही OAuth ऑथराइज़ेशन सर्वर इस्तेमाल करता है। CLI रोटेट होने वाले रिफ़्रेश टोकन के साथ ब्राउज़र या डिवाइस लॉगिन इस्तेमाल करता है। तीसरे पक्ष के क्लाइंट PKCE के साथ ऑथराइज़ेशन कोड, स्पष्ट स्कोप और वर्कस्पेस सहमति, और वैकल्पिक protected-resource बाइंडिंग इस्तेमाल करते हैं। उन्हें 7 दिन चलने वाला रद्द करने योग्य एक्सेस टोकन और आख़िरी इस्तेमाल से 90 दिन चलने वाला रोटेट होने वाला रिफ़्रेश टोकन मिलता है; रिफ़्रेश कैसे काम करता है, इसके लिए [OAuth Next.js वर्कबेंच बनाएँ](../../cookbook/build-an-oauth-nextjs-workbench) देखें। उसी ऐप को फिर से मंज़ूरी देने पर दूसरी कुंजी जोड़ने की जगह उसकी कुंजी नवीनीकृत होती है।

होस्ट किए गए Phaseo API में तीसरे पक्ष का OAuth चालू है। सेल्फ़-होस्टेड और प्रीव्यू API डिप्लॉयमेंट में यह बंद रहता है, जब तक `PHASEO_THIRD_PARTY_OAUTH_ENABLED` सत्य मान न हो: `1`, `true`, `yes` या `on`, बड़े-छोटे अक्षरों का फ़र्क़ नहीं, और आसपास के स्पेस अनदेखे किए जाते हैं।

```bash .env
PHASEO_THIRD_PARTY_OAUTH_ENABLED=true
```

इसे चालू करने से उपयोगकर्ताओं के बनाए OAuth ऐप का प्रबंधन और डायनामिक क्लाइंट रजिस्ट्रेशन उपलब्ध हो जाते हैं, इसलिए पहले अपनी redirect URI, सहमति, client-secret, रेट-लिमिट और वर्कस्पेस ऑथराइज़ेशन सेटिंग्स की समीक्षा करें।

```bash
phaseo update
```

<CodeGroup>

```bash npm
npm install -g @phaseo/cli@latest
```

```bash pnpm
pnpm add -g @phaseo/cli@latest
```

```bash yarn
yarn global add @phaseo/cli@latest
```

```bash bun
bun add -g @phaseo/cli@latest
```

</CodeGroup>
