Harness web interface से Phaseo models और routing उपयोग करने के लिए DeepSeek Harness को Phaseo से जोड़ें। Custom adapter की ज़रूरत नहीं; Harness सीधे Phaseo को OpenAI-संगत Chat Completions requests भेज सकता है।

**नतीजा:** Harness के model picker में Phaseo provider दिखता है और नए Harness sessions Phaseo द्वारा दिए गए model का उपयोग कर सकते हैं।

## ज़रूरी चीज़ें

- Phaseo CLI, Phaseo खाता और DeepSeek Harness का स्थापित संस्करण

इस गाइड की live request provider credentials का उपयोग करती है और model usage charges लग सकते हैं।

## Phaseo CLI से सेट अप करें

एक कमांड से प्रदाता, Base URL, प्रोटोकॉल, मॉडल कैटलॉग और डिफ़ॉल्ट मॉडल सेट करें:

```bash
phaseo login
phaseo dsh
```

CLI `$DSH_HOME/cordis.patch.yml` में अन्य entries सुरक्षित रखती है और Phaseo block को mark करती है, ताकि केवल managed settings बदली या हटाई जाएँ। यह Chat Completions-संगत सभी active Phaseo text models sync करती है। ज़रूरत हो तो अलग default model दें:

```bash
phaseo dsh --model YOUR_PHASEO_MODEL_ID
```

Setup `Phaseo CLI: DeepSeek Harness API Key` नाम की बिना expiry वाली Gateway key बनाकर Harness के protected `$DSH_HOME/.credentials.yaml` store में लिखती है। केवल चुना model configure करने के लिए `--catalog default` उपयोग करें।

`phaseo integrations remove deepseek-harness` से integration हटाने पर केवल Phaseo-managed configuration हटती है और CLI की बनाई key revoke होती है।

## Harness UI में Phaseo को स्वयं जोड़ें

1. DeepSeek Harness में **Settings > Models** खोलें।
2. **Add a custom provider** चुनें।
3. ये values दर्ज करें:

| Field | मान |
| --- | --- |
| Provider ID | `phaseo` |
| Display name | `Phaseo` |
| Base URL | `https://api.phaseo.app/v1` |
| API protocol | `OpenAI Completions` |
| API key | आपकी Phaseo API कुंजी |

4. **Model catalog** में **Fetch available models** चुनें।
5. Tool सपोर्ट वाला Chat Completions model चुनें, जैसे `anthropic/claude-sonnet-4.6`, फिर provider save करें।
6. Composer पर लौटें, Phaseo model चुनें और नया session शुरू करें।

Harness saved sessions और credential references में provider ID रखता है, इसलिए `phaseo` को स्थायी मानें। Display name, URL, credential और model list बाद में बदली जा सकती है।

## YAML से Phaseo कॉन्फ़िगर करें

इसी provider को `$DSH_HOME/settings.yaml` में सीधे configure कर सकते हैं। API key इस file में न रखें; `apiKeyEnv` वह credential बताता है जिसे Harness resolve करे।

```yaml
llm-pi-ai:
  providers:
    phaseo:
      displayName: Phaseo
      apiKeyEnv: PHASEO_API_KEY
      api: openai-completions
      baseURL: https://api.phaseo.app/v1
      models:
        - id: YOUR_PHASEO_MODEL_ID
```

Harness लॉन्च करने वाले environment में `PHASEO_API_KEY` दें या Models page से वही credential सहेजें। `YOUR_PHASEO_MODEL_ID` को Phaseo model discovery के सटीक ID से बदलें। Coding-agent workflow के लिए `anthropic/claude-sonnet-4.6` से शुरू करें।

<Note>
  `settings.yaml` में `models` list saved catalog है, live query नहीं। Harness में और Phaseo models दिखाने हों तो इसे update करें।
</Note>

## कनेक्शन जाँचें

Harness जाँचने से पहले credential और model discovery route अलग-अलग confirm करें:

```bash
curl https://api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

फिर नए Harness session में Phaseo model चुनें और यह भेजें:

```text
Reply with exactly: Phaseo is connected.
```

सफल response से Harness से Phaseo होकर चुने गए model provider तक का पूरा path verify होता है।

## समस्या निवारण

- **Model fetch पर `401` मिलता है** - जाँचें कि Phaseo API key चालू है और Base URL में `/v1` है।
- **Picker में model नहीं है** - Catalog दोबारा fetch करें या `$DSH_HOME/settings.yaml` के `models` में Phaseo का exact model ID जोड़ें।
- **Harness `MISSING_CREDENTIAL` बताता है** - Models page में key सहेजें या Harness process को `PHASEO_API_KEY` उपलब्ध कराएँ।
- **Request गलत endpoint का उपयोग करता है** - `OpenAI Completions` / `openai-completions` चुनें। यह Harness integration Phaseo का `/v1/chat/completions` compatibility route उपयोग करता है।
- **Reasoning चालू होने पर model function tools अस्वीकार करता है** - Chat Completions पर tools सपोर्ट करने वाला model चुनें। Tools के साथ reasoning के लिए Responses API चाहने वाले models इस Harness provider protocol से संगत नहीं हैं।
- **मौजूदा session पुराना model रखता है** - नया session शुरू करें। Harness request भेज चुकी sessions में चुने provider और model को दर्ज करता है।
