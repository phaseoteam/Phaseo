अपने वर्कस्पेस के अलर्ट ईमेल, Slack, Discord, Microsoft Teams या अपने HTTPS वेबहुक पर भेजने के लिए **सेटिंग्स → सूचनाएँ** में एक गंतव्य जोड़ें। गंतव्य वर्कस्पेस के होते हैं, और किसी पर भरोसा करने से पहले आप एक टेस्ट भेज सकते हैं।

| गंतव्य | आप क्या देते हैं | मेंशन |
| --- | --- | --- |
| ईमेल | पते या वितरण सूचियाँ | कोई नहीं |
| Slack | एक इनकमिंग वेबहुक URL | यूज़र ID और यूज़र-ग्रुप ID |
| Discord | एक चैनल और बॉट टोकन, या एक वेबहुक URL | यूज़र ID और रोल ID |
| Microsoft Teams | एक वर्कफ़्लो URL | Microsoft 365 ईमेल पते या Entra ऑब्जेक्ट ID |
| कस्टम वेबहुक | एक HTTPS URL | कोई नहीं; डिलीवरी [साइन की जाती हैं](#verify-webhook-signatures) |

क्रेडेंशियल और वेबहुक URL स्टोर करने से पहले एन्क्रिप्ट किए जाते हैं। चैनल क्रेडेंशियल को सिर्फ़ सूचना डिलीवरी तक सीमित रखें, और उजागर होने पर उन्हें बदलें।

## गंतव्य जोड़ें

<Steps>
<Step title="इसे बनाएँ">
**सेटिंग्स → सूचनाएँ** खोलें, **गंतव्य जोड़ें** चुनें, एक नाम दर्ज करें, और एक या ज़्यादा चैनल चुनें। गंतव्य की जानकारी और कोई भी मेंशन जोड़ें।
</Step>
<Step title="हर चैनल को टेस्ट करें">
हर चैनल के लिए **परीक्षण भेजें** चुनें, फिर हर टेस्ट सफल होने के बाद गंतव्य बनाएँ।
</Step>
<Step title="साइनिंग सीक्रेट सहेजें">
कस्टम वेबहुक बनाते समय उसे एक साइनिंग सीक्रेट मिलता है। इसे खुलने वाले डायलॉग से कॉपी करें; यह सिर्फ़ एक बार दिखाया जाता है।
</Step>
</Steps>

CLI से, `phaseo notifications destinations create` चलाएँ, उसे `phaseo notifications destinations test <id>` से जाँचें, फिर `phaseo notifications routes set <event-kind> --destination-ids <id>` से चुनें कि उसे कौन-से अलर्ट मिलें।

मेंशन कम इस्तेमाल करें: बहुत ज़्यादा आने वाले अलर्ट किसी बड़े ग्रुप को पेज करने के बजाय ऐसे चैनल पर भेजें जिस पर नज़र रखी जाती हो।

<span id="enable-product-alerts"></span>
## उत्पाद अलर्ट चालू करें

सूचना पेज आपके वर्कस्पेस के लिए उपलब्ध अलर्ट प्रकारों की सूची देता है। गंतव्यों को अलर्ट डैशबोर्ड में दिखाए गए किसी भी बिल्ट-इन प्राप्तकर्ता के अलावा मिलता है।

**मॉडल अप्रचलन अलर्ट** वर्कस्पेस के इस्तेमाल किए जा रहे किसी मॉडल के रिटायर होने से पहले सूचना देते हैं।

**प्रतिस्थापन मॉडल सूचनाएँ** तब भेजी जाती हैं जब [रिटायर्ड मॉडल रूटिंग](./model-retirement.mdx#route-requests-to-a-replacement-automatically) चालू हो और कोई प्रतिस्थापन मॉडल वर्कस्पेस के ऐसे मॉडल के अनुरोधों का जवाब दे जिसे अब कोई प्रदाता नहीं चलाता। हर मॉडल और प्रतिस्थापन के लिए एक सूचना भेजी जाती है, पहली बार जब प्रतिस्थापन सफलतापूर्वक जवाब देता है। वर्कस्पेस मालिक को हमेशा ईमेल जाता है; अपनी टीम को भी सूचना भेजने के लिए गंतव्य चुनें।

<span id="spend-reports"></span>
## खर्च रिपोर्ट

वर्कस्पेस मालिकों को हर सोमवार 09:00 बजे, वर्कस्पेस के बिलिंग टाइम ज़ोन में, पिछले सोमवार-से-रविवार के सप्ताह की खर्च रिपोर्ट ईमेल मिलती है। इसे सूचना पेज पर **खर्च अलर्ट → वर्कस्पेस खर्च सेटिंग** में बदलें: दैनिक (09:00, पिछले दिन के लिए), साप्ताहिक, मासिक (1 तारीख को, पिछले महीने के लिए) या बंद, और यह भी कि एडमिन को भी मिले या नहीं। बिना खर्च वाली अवधियाँ छोड़ दी जाती हैं।

हर रिपोर्ट में खर्च और पिछली अवधि से बदलाव, सबसे ऊपर की कुंजियाँ, मॉडल, सदस्य और विभाग, इस महीने का पूर्वानुमान, बैलेंस रनवे, और अवधि के खर्च अलर्ट और ब्लॉक दिखते हैं। जिसे भी यह मिलती है, वह ईमेल के लिंक से सदस्यता खत्म कर सकता है; इससे उस वर्कस्पेस की रिपोर्ट की सिर्फ़ उसकी कॉपी बंद होती है। **खर्च रिपोर्ट** पर रूट किए गए गंतव्यों को हर रिपोर्ट का एक सारांश मिलता है।

यही सेटिंग [सूचना सेटिंग API](../api-reference/endpoint/notifications-settings-update.mdx) में `spend.report_cadence` और `spend.report_include_admins` हैं।

खर्च, बजट, पूर्वानुमान, उछाल और कम बैलेंस पर अलर्ट के लिए, और खर्च किसी सीमा को पार करने पर अनुरोध ब्लॉक करने के लिए, [खर्च अलर्ट](./spend-alerts.mdx) देखें।

<Note>खर्च रिपोर्ट ईमेल धीरे-धीरे शुरू किए जा रहे हैं। इन्हें चालू किए जाने तक आपकी पसंद सहेजी जाती है, लेकिन कोई रिपोर्ट नहीं भेजी जाती।</Note>

## गंतव्यों को काम करता रखें

क्रेडेंशियल बदलने या किसी गंतव्य का चैनल बदलने के बाद, उसके पास **परीक्षण भेजें** इस्तेमाल करें। जिन गंतव्यों पर कोई नज़र नहीं रखता, उन्हें हटा दें, ताकि छोड़े हुए चैनल में पहुँचने वाले अलर्ट डिलीवर हुए न लगें।

कस्टम वेबहुक रिसीवर को हर अनुरोध प्रोसेस करने से पहले सत्यापित करना चाहिए, जल्दी सफलता की प्रतिक्रिया लौटानी चाहिए, और धीमा काम बैकग्राउंड जॉब में भेजना चाहिए।

<span id="verify-webhook-signatures"></span>
## वेबहुक सिग्नेचर सत्यापित करें

Phaseo हर कस्टम वेबहुक डिलीवरी को, सहेजे गए गंतव्य से भेजे गए टेस्ट समेत, उसी तरीके से साइन करता है जैसे [वीडियो और बैच वेबहुक](./async-video-and-batch.mdx#receive-updates)। हर अनुरोध में ये हेडर होते हैं:

```http
POST /your/endpoint HTTP/1.1
content-type: application/json
user-agent: Phaseo-Notifications/1.0
x-phaseo-event-id: 6f1c0f5e-3f0b-4a39-9a51-2f4f2c1d9e10
x-phaseo-event-type: rate_limit_throttled
x-phaseo-timestamp: 1792569600
x-phaseo-signature: 5d2a…e41f
```

`x-phaseo-signature`, `x-phaseo-timestamp` के मान, एक शाब्दिक बिंदु (`.`) और **बिना बदली अनुरोध बॉडी** का हेक्साडेसिमल HMAC-SHA256 है, जिसकी कुंजी गंतव्य का साइनिंग सीक्रेट (`whsec_…`) है। `x-phaseo-timestamp` Unix सेकंड में होता है।

किसी डिलीवरी को सत्यापित करने के लिए:

1. JSON के रूप में पार्स करने से पहले कच्ची अनुरोध बॉडी पढ़ें।
2. सिग्नेचर फिर से गणना करें और उसकी तुलना कॉन्स्टेंट टाइम में करें।
3. आपकी घड़ी से पाँच मिनट से ज़्यादा अलग टाइमस्टैम्प अस्वीकार करें।
4. `x-phaseo-event-id` पर डुप्लिकेट हटाएँ। विफल डिलीवरी फिर से भेजी जाती हैं, और हर कोशिश नए टाइमस्टैम्प के साथ फिर से साइन होती है।

<CodeGroup>
```js Node.js
import crypto from "node:crypto";

// rawBody अनुरोध बॉडी है, ठीक वैसे ही जैसे मिली, स्ट्रिंग के रूप में।
export function verifyPhaseoSignature(rawBody, headers, secret, toleranceSeconds = 300) {
  const timestamp = headers["x-phaseo-timestamp"];
  const signature = headers["x-phaseo-signature"];
  if (!timestamp || !signature) return false;
  if (Math.abs(Date.now() / 1000 - Number(timestamp)) > toleranceSeconds) return false;
  const expected = crypto
    .createHmac("sha256", secret)
    .update(`${timestamp}.${rawBody}`)
    .digest("hex");
  const a = Buffer.from(expected, "hex");
  const b = Buffer.from(signature, "hex");
  return a.length === b.length && crypto.timingSafeEqual(a, b);
}
```

```python Python
import hashlib
import hmac
import time

# raw_body अनुरोध बॉडी है, ठीक वैसे ही जैसे मिली, bytes के रूप में।
def verify_phaseo_signature(raw_body: bytes, headers, secret: str, tolerance_seconds: int = 300) -> bool:
    timestamp = headers.get("x-phaseo-timestamp", "")
    signature = headers.get("x-phaseo-signature", "")
    if not timestamp.isdigit() or not signature:
        return False
    if abs(time.time() - int(timestamp)) > tolerance_seconds:
        return False
    expected = hmac.new(secret.encode(), timestamp.encode() + b"." + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)
```
</CodeGroup>

### सीक्रेट बनाएँ या बदलें

सीक्रेट सिर्फ़ एक बार, गंतव्य बनाते समय दिखाया जाता है। इसे बदलने के लिए, **सेटिंग्स → सूचनाएँ** में गंतव्य के पास **सीक्रेट बदलें** चुनें, या [`POST /v1/notifications/destinations/{id}/rotate-secret`](/hi/v1/api-reference/endpoint/notifications-destination-rotate-secret) कॉल करें। अगली डिलीवरी नए सीक्रेट से साइन होती है और पुराना काम करना बंद कर देता है, इसलिए अपना रिसीवर तुरंत अपडेट करें।

साइनिंग उपलब्ध होने से पहले बनाए गए कस्टम वेबहुक में कोई सीक्रेट नहीं होता और वे अब भी बिना साइन किए डिलीवर होते हैं। सेटिंग्स में उन पर **बिना साइन** दिखता है। **सीक्रेट बनाएँ** चुनें, सीक्रेट अपने रिसीवर में जोड़ें, फिर सत्यापन जाँचने के लिए एक टेस्ट भेजें। गंतव्य सहेजे जाने से पहले **गंतव्य जोड़ें** शीट से भेजे गए टेस्ट बिना साइन के होते हैं, क्योंकि तब तक कोई सीक्रेट मौजूद नहीं होता।

ईमेल, Slack, Discord और Microsoft Teams गंतव्य साइन नहीं किए जाते: ये सेवाएँ वेबहुक URL या बॉट टोकन को खुद प्रमाणित करती हैं।
