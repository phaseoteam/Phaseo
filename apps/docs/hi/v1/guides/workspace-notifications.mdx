सूचना गंतव्यों के ज़रिए वर्कस्पेस के चालू अलर्ट उन टूल पर भेजें जिनकी निगरानी आपकी टीम पहले से करती है। गंतव्य पूरे वर्कस्पेस में साझा होते हैं, और परिचालन अलर्ट के लिए उन पर निर्भर होने से पहले आप उनका परीक्षण कर सकते हैं।

## गंतव्य जोड़ें

1. **Gateway → सेटिंग्स → सूचनाएँ** खोलें।
2. **गंतव्य जोड़ें** चुनें।
3. नाम दर्ज करें और एक या अधिक चैनल चुनें।
4. गंतव्य की जानकारी और वैकल्पिक उल्लेख जोड़ें।
5. हर कॉन्फ़िगर किए गए चैनल के लिए **टेस्ट भेजें** चुनें।
6. सभी परीक्षण सफल होने के बाद गंतव्य बनाएँ।

CLI से `phaseo notifications destinations create` चलाएँ, `phaseo notifications destinations test <id>` से उसकी जाँच करें, फिर `phaseo notifications routes set <event-kind> --destination-ids <id>` से चुनें कि उसे कौन-से अलर्ट मिलें।

कस्टम वेबहुक बनाते समय उन्हें एक साइनिंग सीक्रेट मिलता है। खुलने वाले डायलॉग से इसे कॉपी करें; यह केवल एक बार दिखाया जाता है।

Phaseo इन विकल्पों का समर्थन करता है:

- ईमेल पते और वितरण सूचियाँ
- बॉट टोकन के ज़रिए Discord चैनल
- Discord वेबहुक
- Slack के इनकमिंग वेबहुक
- Microsoft Teams वर्कफ़्लो URL
- कस्टम HTTPS वेबहुक

क्रेडेंशियल और वेबहुक URL सहेजने से पहले एन्क्रिप्ट किए जाते हैं। चैनल क्रेडेंशियल को सूचना भेजने तक सीमित रखें और उजागर होने पर बदल दें।

## उत्पाद सूचनाएँ चालू करें

सूचनाएँ पेज पर आपके वर्कस्पेस के लिए उपलब्ध अलर्ट के प्रकार दिखते हैं। वर्कस्पेस में इस्तेमाल होने वाले किसी मॉडल के बंद होने से पहले सूचना पाने के लिए **मॉडल अप्रचलन अलर्ट** चालू करें।

**प्रतिस्थापन मॉडल सूचनाएँ** तब भेजी जाती हैं जब [सेवानिवृत्त मॉडल रूटिंग](./model-retirement.mdx#route-requests-to-a-replacement-automatically) चालू हो और कोई प्रतिस्थापन मॉडल वर्कस्पेस के ऐसे मॉडल के अनुरोधों का उत्तर दे जिसे अब कोई प्रदाता उपलब्ध नहीं कराता। हर मॉडल और प्रतिस्थापन के लिए एक सूचना भेजी जाती है, जब कोई प्रतिस्थापन पहली बार सफलतापूर्वक उत्तर देता है। वर्कस्पेस के मालिक को हमेशा ईमेल भेजा जाता है; सूचना अपनी टीम को भी भेजने के लिए गंतव्य चुनें।

अलर्ट, डैशबोर्ड में दिखाए गए बिल्ट-इन प्राप्तकर्ता व्यवहार के अलावा, कॉन्फ़िगर किए गए गंतव्यों पर भी भेजे जाते हैं।

## खर्च रिपोर्ट

वर्कस्पेस मालिकों को हर सोमवार 09:00 बजे (वर्कस्पेस के बिलिंग समय क्षेत्र में) पिछले सोमवार से रविवार के सप्ताह की खर्च रिपोर्ट ईमेल से मिलती है। इसे सूचनाएँ पेज पर **खर्च अलर्ट → वर्कस्पेस खर्च सेटिंग** में बदलें: दैनिक (09:00 बजे, पिछले दिन के लिए), साप्ताहिक, मासिक (1 तारीख को, पिछले महीने के लिए) या बंद, और क्या एडमिन को भी यह मिले। बिना खर्च वाली अवधियाँ छोड़ दी जाती हैं।

हर रिपोर्ट में खर्च और पिछली अवधि से बदलाव, शीर्ष कुंजियाँ, मॉडल, सदस्य और विभाग, इस महीने का पूर्वानुमान, बैलेंस की शेष अवधि, और अवधि के खर्च अलर्ट और ब्लॉक दिखते हैं। जिसे भी यह मिलता है, वह ईमेल के लिंक से सदस्यता छोड़ सकता है; इससे केवल उस वर्कस्पेस की उसकी अपनी रिपोर्ट बंद होती है। **Spend Reports** पर रूट किए गए गंतव्यों को हर रिपोर्ट का एक सारांश मिलता है।

यही सेटिंग्स [सूचना सेटिंग्स API](../api-reference/endpoint/notifications-settings-update.mdx) में `spend.report_cadence` और `spend.report_include_admins` हैं।

<Note>खर्च रिपोर्ट ईमेल धीरे-धीरे शुरू किए जा रहे हैं। चालू होने तक आपकी पसंद सहेजी जाती है, लेकिन कोई रिपोर्ट नहीं भेजी जाती।</Note>

## उल्लेख

वैकल्पिक उल्लेख फ़ील्ड की मदद से अलर्ट खास प्राप्तकर्ताओं को सूचित कर सकता है:

- Discord उपयोगकर्ता ID और रोल ID स्वीकार करता है।
- Slack उपयोगकर्ता ID और उपयोगकर्ता-समूह ID स्वीकार करता है।
- Microsoft Teams, Microsoft 365 ईमेल पते या Entra ऑब्जेक्ट ID स्वीकार करता है।

उल्लेखों का सीमित उपयोग करें। ज़्यादा संख्या में आने वाले वर्कस्पेस अलर्ट आम तौर पर किसी बड़े समूह को पेज करने के बजाय ऐसे चैनल पर जाने चाहिए जिसकी निगरानी होती हो।

## गंतव्यों की जाँच करें और हटाएँ

क्रेडेंशियल बदलने या चैनल का कॉन्फ़िगरेशन बदलने के बाद मौजूदा गंतव्य के पास **टेस्ट भेजें** इस्तेमाल करें। जिन गंतव्यों की अब निगरानी नहीं होती, उन्हें हटा दें, ताकि अलर्ट किसी छोड़े हुए चैनल पर डिलीवर हुए न दिखें।

कस्टम वेबहुक में HTTPS अनिवार्य है, और उन्हें अनुरोध को प्रोसेस करने से पहले सत्यापित करना चाहिए। तुरंत सफल प्रतिक्रिया लौटाएँ और धीमे काम को बैकग्राउंड जॉब में भेजें।

## वेबहुक सिग्नेचर सत्यापित करें

Phaseo हर कस्टम वेबहुक डिलीवरी को, सहेजे गए गंतव्य से भेजे गए परीक्षणों सहित, उसी तरीके से साइन करता है जैसे [वीडियो और बैच वेबहुक](./async-video-and-batch.mdx)। हर अनुरोध में ये हेडर होते हैं:

```http
POST /your/endpoint HTTP/1.1
content-type: application/json
user-agent: Phaseo-Notifications/1.0
x-phaseo-event-id: 6f1c0f5e-3f0b-4a39-9a51-2f4f2c1d9e10
x-phaseo-event-type: rate_limit_throttled
x-phaseo-timestamp: 1792569600
x-phaseo-signature: 5d2a…e41f
```

`x-phaseo-signature`, `x-phaseo-timestamp` के मान, एक बिंदु (`.`) और **बिना बदले अनुरोध बॉडी** का हेक्साडेसिमल HMAC-SHA256 है, जिसकी कुंजी गंतव्य का साइनिंग सीक्रेट (`whsec_…`) है। `x-phaseo-timestamp` Unix सेकंड में होता है।

डिलीवरी सत्यापित करने के लिए:

1. JSON के रूप में पार्स करने से पहले मूल बॉडी पढ़ें।
2. सिग्नेचर फिर से गणना करें और स्थिर समय में तुलना करें।
3. आपकी घड़ी से पाँच मिनट से अधिक अंतर वाले टाइमस्टैम्प अस्वीकार करें।
4. `x-phaseo-event-id` के आधार पर डुप्लिकेट हटाएँ। विफल डिलीवरी दोबारा भेजी जाती हैं, और हर प्रयास नए टाइमस्टैम्प के साथ फिर से साइन होता है।

<CodeGroup>
```js Node.js
import crypto from "node:crypto";

// rawBody, प्राप्त हुई अनुरोध बॉडी है, ठीक वैसी ही, स्ट्रिंग के रूप में।
export function verifyPhaseoSignature(rawBody, headers, secret, toleranceSeconds = 300) {
  const timestamp = headers["x-phaseo-timestamp"];
  const signature = headers["x-phaseo-signature"];
  if (!timestamp || !signature) return false;
  if (Math.abs(Date.now() / 1000 - Number(timestamp)) > toleranceSeconds) return false;
  const expected = crypto
    .createHmac("sha256", secret)
    .update(`${timestamp}.${rawBody}`)
    .digest("hex");
  const a = Buffer.from(expected, "hex");
  const b = Buffer.from(signature, "hex");
  return a.length === b.length && crypto.timingSafeEqual(a, b);
}
```

```python Python
import hashlib
import hmac
import time

# raw_body, प्राप्त हुई अनुरोध बॉडी है, ठीक वैसी ही, bytes के रूप में।
def verify_phaseo_signature(raw_body: bytes, headers, secret: str, tolerance_seconds: int = 300) -> bool:
    timestamp = headers.get("x-phaseo-timestamp", "")
    signature = headers.get("x-phaseo-signature", "")
    if not timestamp.isdigit() or not signature:
        return False
    if abs(time.time() - int(timestamp)) > tolerance_seconds:
        return False
    expected = hmac.new(secret.encode(), timestamp.encode() + b"." + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)
```

### सीक्रेट बनाएँ या बदलें

सीक्रेट केवल एक बार, गंतव्य बनाते समय दिखाया जाता है। इसे बदलने के लिए **Settings → Notifications** में गंतव्य के पास **सीक्रेट बदलें** चुनें, या [`POST /v1/notifications/destinations/{id}/rotate-secret`](/hi/v1/api-reference/endpoint/notifications-destination-rotate-secret) कॉल करें। अगली डिलीवरी नए सीक्रेट से साइन होती है और पुराना काम करना बंद कर देता है, इसलिए अपना रिसीवर तुरंत अपडेट करें।

साइनिंग उपलब्ध होने से पहले बने कस्टम वेबहुक के पास कोई सीक्रेट नहीं है और वे अब भी बिना साइन के भेजे जाते हैं। Settings में वे **बिना साइन** दिखते हैं। **सीक्रेट बनाएँ** चुनें, सीक्रेट को अपने रिसीवर में जोड़ें, फिर सत्यापन जाँचने के लिए परीक्षण भेजें। **गंतव्य जोड़ें** पैनल से, गंतव्य सहेजने से पहले भेजे गए परीक्षण साइन नहीं होते क्योंकि तब तक कोई सीक्रेट नहीं होता।

ईमेल, Slack, Discord और Microsoft Teams गंतव्य साइन नहीं होते: ये सेवाएँ वेबहुक URL या बॉट टोकन को स्वयं प्रमाणित करती हैं।
