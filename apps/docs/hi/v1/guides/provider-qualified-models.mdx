प्रदाता-योग्य मॉडल ID से आप `model` फ़ील्ड में सटीक प्रदाता और कैनोनिकल मॉडल चुन सकते हैं। इनका उपयोग तब करें जब प्रदाता का चुनाव रूटिंग की प्राथमिकता नहीं, बल्कि अनुरोध के अनुबंध का हिस्सा हो।

## वाक्यविन्यास

```text
<provider-id>:<canonical-model-id>
```

उदाहरण के लिए:

```text
baseten:thinking-machines/inkling-small
deepinfra:deepseek/deepseek-v3
```

पहला कोलन प्रदाता को कैनोनिकल मॉडल ID से अलग करता है। मॉडल नेमस्पेस के बाद आने वाले कोलन मॉडल सफ़िक्स ही बने रहते हैं, इसलिए यह पहचानकर्ता अस्पष्ट नहीं है:

```text
baseten:google/gemma-4-26b-a4b:free
```

इस उदाहरण में:

- `baseten` अनुरोधित प्रदाता है
- `google/gemma-4-26b-a4b:free` Phaseo का कैनोनिकल मॉडल ID है

## अनुरोध भेजें

जहाँ भी एंडपॉइंट मॉडल ID स्वीकार करता है, वहाँ योग्य पहचानकर्ता का उपयोग करें।

<CodeGroup>

```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "baseten:thinking-machines/inkling-small",
    "input": "Explain mixture-of-experts routing in two sentences."
  }'
```

```javascript JavaScript
const response = await fetch("https://api.phaseo.app/v1/responses", {
  method: "POST",
  headers: {
    Authorization: "Bearer YOUR_API_KEY",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "baseten:thinking-machines/inkling-small",
    input: "Explain mixture-of-experts routing in two sentences.",
  }),
});

const result = await response.json();
```

```python Python
import os
import requests

response = requests.post(
    "https://api.phaseo.app/v1/responses",
    headers={
        "Authorization": f"Bearer {os.environ['PHASEO_API_KEY']}",
        "Content-Type": "application/json",
    },
    json={
        "model": "baseten:thinking-machines/inkling-small",
        "input": "Explain mixture-of-experts routing in two sentences.",
    },
)

result = response.json()
```

</CodeGroup>

## सटीक रूटिंग का व्यवहार

प्रदाता क्वालिफ़ायर एक सटीक पाबंदी है। Phaseo पात्र प्रदाताओं के समूह को अनुरोधित प्रदाता तक सीमित कर देता है और उस अनुरोध के लिए किसी दूसरे प्रदाता पर फ़ॉलबैक नहीं करता।

क्वालिफ़ायर अन्य नियंत्रणों को बायपास नहीं करता। प्रदाता के लिए फिर भी ज़रूरी है कि वह:

- अनुरोधित एंडपॉइंट पर कैनोनिकल मॉडल उपलब्ध कराए
- एंडपॉइंट की क्षमता के लिए सक्षम हो
- वर्कस्पेस और API कुंजी की नीतियाँ पूरी करे
- प्रीसेट और गोपनीयता संबंधी पाबंदियाँ पूरी करे
- अनुरोधित सेवा स्तर और पैरामीटर का समर्थन करे
- मान्य मूल्य निर्धारण के साथ कॉन्फ़िगर हो

इनमें से कोई भी जाँच विफल हो, तो Phaseo चुपचाप दूसरा प्रदाता चुनने के बजाय अनुरोध अस्वीकार कर देता है।

## रूटिंग फ़ील्ड के साथ तालमेल

योग्य प्रदाता और स्पष्ट रूटिंग फ़ील्ड आपस में मेल खाने चाहिए।

```json
{
  "model": "baseten:thinking-machines/inkling-small",
  "provider": {
    "only": ["baseten"]
  }
}
```

मेल खाता `provider.only` या `routing.only` मान स्वीकार किया जाता है। परस्पर विरोधी अनुमति सूची, या योग्य प्रदाता को शामिल करने वाली अनदेखी सूची, सत्यापन त्रुटि लौटाती है।

उदाहरण के लिए, यह अनुरोध विरोधाभासी है और अस्वीकार कर दिया जाता है:

```json
{
  "model": "baseten:thinking-machines/inkling-small",
  "provider": {
    "only": ["deepinfra"]
  }
}
```

अगर प्रदाता का चुनाव केवल एक प्राथमिकता है और दूसरे प्रदाता पर फ़ॉलबैक वांछनीय है, तो सामान्य [रूटिंग और फ़ॉलबैक नियंत्रणों](./routing-and-fallbacks.mdx) के साथ बिना क्वालिफ़ायर वाले कैनोनिकल मॉडल ID का उपयोग जारी रखें।

## प्रदाता के नाम से निर्दिष्ट मुफ़्त मॉडल

योग्य `:free` अनुरोध केवल तभी स्वीकार होता है जब उसी सटीक प्रदाता के पास उस कैनोनिकल मॉडल और एंडपॉइंट के लिए पात्र मुफ़्त रूट हो।

```json
{
  "model": "baseten:google/gemma-4-26b-a4b:free",
  "input": "Hello"
}
```

Phaseo अनुरोध को तभी स्वीकार करता है जब चुने गए रूट में ऐसा मूल्य कार्ड हो जो खाली न हो और जिसका हर मौजूदा मूल्य नियम:

- स्पष्ट रूप से `free` लेबल किया गया हो
- बिल्कुल शून्य कीमत वाला हो

मूल्य निर्धारण न होना, सशुल्क मूल्य, मिश्रित मूल्य, ऋणात्मक मूल्य, या शून्य मूल्य वाला ऐसा नियम जिसे स्पष्ट रूप से `free` लेबल न किया गया हो—इनमें से किसी भी स्थिति में प्रदाता पर निष्पादन से पहले ही अनुरोध अस्वीकार कर दिया जाता है।

<Note>
कैनोनिकल `:free` मॉडल मौजूद होने का अर्थ यह नहीं है कि मूल मॉडल उपलब्ध कराने वाला हर प्रदाता मुफ़्त रूट भी देता है।
</Note>

## प्रदाता स्लग और उपनाम

Phaseo के प्रदाता कैटलॉग में उपलब्ध प्रदाता स्लग का उपयोग करें। स्लग छोटे अक्षरों में सामान्यीकृत किए जाते हैं, और समर्थित पुराने या ब्रांड उपनाम उनके कैनोनिकल प्रदाता ID से मैप किए जाते हैं।

उदाहरण के लिए, `NovitaAI` और `novita-ai` दोनों अभी `novita` में सामान्यीकृत होते हैं।

गलत प्रारूप वाले और अज्ञात स्लग प्रदाता चयन से पहले ही अस्वीकार कर दिए जाते हैं। Phaseo उन्हें मॉडल नाम के हिस्से के रूप में अपस्ट्रीम नहीं भेजता।

## सत्यापन त्रुटियाँ

प्रदाता-योग्य पहचानकर्ता की विफलताओं में HTTP `400` और शीर्ष-स्तरीय त्रुटि कोड `validation_error` लौटता है। सटीक कारण के लिए `reason` या `details[].keyword` देखें।

| कारण | अर्थ |
| --- | --- |
| `invalid_provider_slug` | प्रदाता वाला भाग खाली है या उसमें असमर्थित वर्ण हैं। |
| `unknown_provider_slug` | स्लग का प्रारूप सही है, लेकिन वह कोई पहचाना हुआ Phaseo प्रदाता नहीं है। |
| `invalid_provider_qualified_model` | संयुक्त पहचानकर्ता `<provider>:<publisher>/<model>` से मेल नहीं खाता। |
| `provider_qualified_model_conflict` | `provider.only`, `provider.ignore`, `routing.only` या `routing.ignore` क्वालिफ़ायर का विरोध करता है। |
| `qualified_provider_unavailable` | प्रदाता पहचाना गया है, लेकिन अनुरोधित एंडपॉइंट पर वह मॉडल उपलब्ध नहीं कराता। |
| `qualified_free_provider_unavailable` | सटीक प्रदाता रूट को सभी नियमों में शून्य मूल्य के साथ स्पष्ट रूप से मुफ़्त सत्यापित नहीं किया गया है। |

त्रुटि का उदाहरण:

```json
{
  "error": "validation_error",
  "status_code": 400,
  "reason": "unknown_provider_slug",
  "description": "Unknown provider slug \"not-a-provider\" in provider-qualified model \"not-a-provider:publisher/model\". Use a provider slug returned by Phaseo's provider catalogue.",
  "provider": "not-a-provider",
  "model": "publisher/model",
  "details": [
    {
      "path": ["model"],
      "keyword": "unknown_provider_slug"
    }
  ]
}
```
