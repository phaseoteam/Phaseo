अनुरोध को सिर्फ़ उसी प्रदाता पर, किसी दूसरे प्रदाता पर फ़ॉलबैक के बिना, चलाने के लिए मॉडल ID के आगे प्रदाता ID और कोलन लगाएँ, जैसे `baseten:thinking-machines/inkling-small`।

| आप चाहते हैं | `model` के रूप में भेजें |
| --- | --- |
| Phaseo प्रदाता चुने और प्रदाताओं के बीच फ़ॉलबैक करे | `thinking-machines/inkling-small` |
| सिर्फ़ Baseten, बिना क्रॉस-प्रदाता फ़ॉलबैक के | `baseten:thinking-machines/inkling-small` |
| एक प्रदाता पर एक सत्यापित मुफ़्त रूट | `google-ai-studio:google/gemma-4-26b-a4b:free` |

फ़ॉर्मैट `<provider-id>:<canonical-model-id>` है। पहला कोलन प्रदाता को अलग करता है; मॉडल नेमस्पेस के बाद के कोलन मॉडल ID का हिस्सा बने रहते हैं। `google-ai-studio:google/gemma-4-26b-a4b:free` में प्रदाता `google-ai-studio` है और मॉडल `google/gemma-4-26b-a4b:free` है।

अगर आप सिर्फ़ किसी प्रदाता को प्राथमिकता देना चाहते हैं और उसके विफल होने पर फ़ॉलबैक चाहते हैं, तो इसके बजाय सामान्य मॉडल ID के साथ [रूटिंग और फ़ॉलबैक नियंत्रणों](./routing-and-fallbacks.mdx) का उपयोग करें।

## अनुरोध भेजें

जहाँ भी एंडपॉइंट मॉडल ID स्वीकार करता है, वहाँ योग्य ID का उपयोग करें।

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "baseten:thinking-machines/inkling-small",
    "input": "Explain mixture-of-experts routing in two sentences."
  }'
```

```javascript JavaScript
const response = await fetch("https://api.phaseo.app/v1/responses", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "baseten:thinking-machines/inkling-small",
    input: "Explain mixture-of-experts routing in two sentences.",
  }),
});

const result = await response.json();
```

```python Python
import os
import requests

response = requests.post(
    "https://api.phaseo.app/v1/responses",
    headers={
        "Authorization": f"Bearer {os.environ['PHASEO_API_KEY']}",
        "Content-Type": "application/json",
    },
    json={
        "model": "baseten:thinking-machines/inkling-small",
        "input": "Explain mixture-of-experts routing in two sentences.",
    },
)

result = response.json()
```
</CodeGroup>

## प्रदाता को फिर भी क्या पूरा करना होगा

क्वालिफ़ायर रूटिंग को एक प्रदाता तक सीमित करता है; यह कोई और जाँच नहीं छोड़ता। प्रदाता को फिर भी:

- अनुरोधित एंडपॉइंट पर कैनोनिकल मॉडल सर्व करना होगा, और वह क्षमता सक्षम होनी चाहिए
- वर्कस्पेस, API कुंजी, प्रीसेट और गोपनीयता प्रतिबंधों को पूरा करना होगा
- अनुरोधित सेवा स्तर और पैरामीटर को सपोर्ट करना होगा
- कीमत कॉन्फ़िगर होनी चाहिए

अगर कोई भी जाँच विफल होती है, तो अनुरोध अस्वीकार कर दिया जाता है। Phaseo कभी चुपचाप कोई दूसरा प्रदाता नहीं चुनता।

## `provider` या `routing` फ़ील्ड के साथ जोड़ें

क्वालिफ़ायर और कोई भी स्पष्ट रूटिंग फ़ील्ड आपस में मेल खाने चाहिए। मेल खाता `provider.only` या `routing.only` स्वीकार किया जाता है:

```json
{
  "model": "baseten:thinking-machines/inkling-small",
  "provider": { "only": ["baseten"] }
}
```

दूसरे प्रदाताओं का नाम लेने वाली अनुमति सूची, या योग्य प्रदाता वाली अनदेखी सूची, `provider_qualified_model_conflict` के साथ अस्वीकार की जाती है:

```json
{
  "model": "baseten:thinking-machines/inkling-small",
  "provider": { "only": ["deepinfra"] }
}
```

## एक प्रदाता पर मुफ़्त रूट का अनुरोध करें

योग्य `:free` मॉडल सिर्फ़ तब स्वीकार होता है जब उस प्रदाता के पास उस मॉडल और एंडपॉइंट के लिए योग्य मुफ़्त रूट हो। कैनोनिकल `:free` मॉडल का मतलब यह नहीं कि मूल मॉडल का हर प्रदाता उसे मुफ़्त देता है।

```json
{
  "model": "google-ai-studio:google/gemma-4-26b-a4b:free",
  "input": "Hello"
}
```

रूट का प्राइसिंग कार्ड खाली नहीं होना चाहिए, और उस पर हर मौजूदा प्राइसिंग नियम `free` लेबल वाला और ठीक शून्य कीमत वाला होना चाहिए। गायब, सशुल्क, मिली-जुली या नकारात्मक कीमत, या `free` लेबल के बिना शून्य कीमत वाला नियम, अनुरोध को प्रदाता तक पहुँचने से पहले ही अस्वीकार कर देता है।

## प्रदाता ID और उपनाम

Phaseo के प्रदाता कैटलॉग से प्रदाता ID का उपयोग करें ([API प्रदाता](../exploring/api-providers) देखें)। ID छोटे अक्षरों में बदल दी जाती हैं, और ज्ञात पुराने या ब्रांड उपनाम कैनोनिकल ID से मैप होते हैं: `NovitaAI` और `novita-ai` दोनों `novita` बन जाते हैं। गलत बनी और अज्ञात ID प्रदाता चुनने से पहले अस्वीकार कर दी जाती हैं; उन्हें कभी मॉडल नाम के हिस्से के रूप में अपस्ट्रीम नहीं भेजा जाता।

## वैलिडेशन त्रुटियाँ

गलत योग्य ID HTTP `400` और त्रुटि कोड `validation_error` लौटाती है। `reason` और `details[].keyword` कारण बताते हैं:

| कारण | अर्थ |
| --- | --- |
| `invalid_provider_slug` | प्रदाता वाला हिस्सा खाली है या उसमें असमर्थित अक्षर हैं। |
| `unknown_provider_slug` | प्रदाता ID सही बनी है लेकिन वह Phaseo प्रदाता नहीं है। |
| `invalid_provider_qualified_model` | ID `<provider>:<publisher>/<model>` से मेल नहीं खाती। |
| `provider_qualified_model_conflict` | `provider.only`, `provider.ignore`, `routing.only` या `routing.ignore` क्वालिफ़ायर के विपरीत है। |
| `qualified_provider_unavailable` | प्रदाता मौजूद है लेकिन अनुरोधित एंडपॉइंट पर वह मॉडल सर्व नहीं करता। |
| `qualified_free_provider_unavailable` | प्रदाता का रूट पूरी तरह शून्य कीमत के साथ मुफ़्त के रूप में सत्यापित नहीं है। |

```json
{
  "error": "validation_error",
  "status_code": 400,
  "reason": "unknown_provider_slug",
  "description": "Unknown provider slug \"not-a-provider\" in provider-qualified model \"not-a-provider:publisher/model\". Use a provider slug returned by Phaseo's provider catalogue.",
  "provider": "not-a-provider",
  "model": "publisher/model",
  "details": [
    {
      "path": ["model"],
      "keyword": "unknown_provider_slug"
    }
  ]
}
```

त्रुटियों के अन्य रूपों के लिए [त्रुटियाँ और डीबगिंग](../api-reference/errors.mdx) देखें।
