वर्कस्पेस किसी टीम, उत्पाद या परिवेश की API कुंजियाँ, रूटिंग सेटिंग, प्रीसेट, सुरक्षा नियम और व्यवस्थापक पहुँच व्यवस्थित करते हैं।

वर्कस्पेस Phaseo की मानक उपयोग-अनुसार-भुगतान सेवा में शामिल हैं। इन्हें बनाने या इस्तेमाल करने के लिए अलग योजना की ज़रूरत नहीं है।

## कार्यक्षेत्र कब बनाएँ

अलग-अलग workspaces बनाएँ, अगर आप चाहते हैं:

- development, staging और production credentials अलग रखना
- अलग-अलग products या customer projects अलग रखना
- admin integrations को केवल ज़रूरी resources तक access देना
- अलग-अलग routing, preset या guardrail policies लागू करना

छोटे integration के लिए default workspace पर्याप्त हो सकता है।

## कार्यक्षेत्र प्रबंधित करें

Phaseo dashboard या management API से workspaces manage कर सकते हैं।

Workspace API में [प्रबंधन API कुंजियाँ](../developers/management-api-keys.mdx) उपयोग होती हैं। मानक Gateway API कुंजियाँ केवल इन्फ़रेंस अनुरोधों के लिए होती हैं; उनसे वर्कस्पेस प्रशासन के एंडपॉइंट नहीं बुलाए जा सकते।

| Task | Endpoint |
| --- | --- |
| Workspaces की सूची | [`GET /workspaces`](../api-reference/endpoint/workspaces-list.mdx) |
| Workspace बनाएँ | [`POST /workspaces`](../api-reference/endpoint/workspaces-create.mdx) |
| Workspace पढ़ें | [`GET /workspaces/{id}`](../api-reference/endpoint/workspaces-get.mdx) |
| Workspace update करें | [`PATCH /workspaces/{id}`](../api-reference/endpoint/workspaces-update.mdx) |
| Workspace delete करें | [`DELETE /workspaces/{id}`](../api-reference/endpoint/workspaces-delete.mdx) |

<Note>
Workspace management endpoints अभी Beta हैं। Admin automation को आसानी से retry करें और आगे के changes लागू करने से पहले API responses review करें।
</Note>

## सही access चुनें

Integration के लिए ज़रूरी workspace capabilities तक सीमित management key बनाएँ:

- Workspaces की सूची और जानकारी के लिए `workspaces:read`
- Workspaces बनाने या update करने के लिए `workspaces:write`
- Workspaces हटाने के लिए `workspaces:delete`

Phaseo workspace membership और roles भी check करता है। केवल capability से दूसरे workspace का access नहीं मिलता।

प्रबंधन कुंजियों को सर्वर-पक्ष के गुप्त भंडारण में रखें। उन्हें ब्राउज़र कोड, डेस्कटॉप लॉग, स्रोत नियंत्रण या चैट में उजागर न करें।

## कार्यक्षेत्र हटाएँ

Default workspace delete नहीं किया जा सकता। किसी अन्य को delete करने से पहले उसकी active API keys हटाएँ या move करें, ताकि requests ऐसे workspace को target न करें जो अब मौजूद नहीं है।

## बिलिंग

वर्कस्पेस अलग मूल्य निर्धारण स्तर नहीं बनाते। उपयोग पर [मूल्य निर्धारण और बिलिंग](../pricing/tiers.mdx) में बताए गए मानक उपयोग-आधारित मॉडल के अनुसार शुल्क लगता है।
