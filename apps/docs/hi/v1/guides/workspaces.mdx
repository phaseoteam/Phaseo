हर टीम, उत्पाद या एनवायरनमेंट के लिए एक वर्कस्पेस बनाएँ, ताकि उसकी API कुंजियाँ, रूटिंग सेटिंग, प्रीसेट, गार्डरेल और एडमिन पहुँच अलग रहें। हर खाता एक निजी वर्कस्पेस से शुरू होता है, जो एक छोटे इंटीग्रेशन के लिए काफ़ी है।

अलग वर्कस्पेस तब मदद करते हैं जब आप चाहते हैं:

- डेवलपमेंट, स्टेजिंग और प्रोडक्शन क्रेडेंशियल अलग रखना
- उत्पादों या ग्राहक प्रोजेक्ट को अलग रखना
- किसी एडमिन इंटीग्रेशन को सिर्फ़ उन्हीं संसाधनों तक पहुँच देना जिनकी उसे ज़रूरत है
- अलग-अलग रूटिंग, प्रीसेट या गार्डरेल नीतियाँ लागू करना

वर्कस्पेस आपकी कीमतें नहीं बदलते: सारा उपयोग सामान्य पे-एज़-यू-गो बिलिंग पर रहता है, जिसका वर्णन [कीमत और बिलिंग](../pricing/tiers) में है। अतिरिक्त वर्कस्पेस आपके पहले क्रेडिट जमा के बाद खुलते हैं; तब तक, कोई वर्कस्पेस बनाने पर `403 workspace_upgrade_required` के साथ विफलता मिलती है।

## API से वर्कस्पेस प्रबंधित करें

वर्कस्पेस को डैशबोर्ड में या प्रबंधन API से प्रबंधित करें। API के लिए एक [प्रबंधन कुंजी](../developers/management-api-keys) चाहिए; सामान्य Gateway API कुंजियाँ इनफ़रेंस के लिए हैं और इन एंडपॉइंट को कॉल नहीं कर सकतीं।

| काम | एंडपॉइंट | क्षमता |
| --- | --- | --- |
| वर्कस्पेस की सूची देखें | [`GET /workspaces`](../api-reference/endpoint/workspaces-list) | `workspaces:read` |
| एक वर्कस्पेस पढ़ें | [`GET /workspaces/{id}`](../api-reference/endpoint/workspaces-get) | `workspaces:read` |
| वर्कस्पेस बनाएँ | [`POST /workspaces`](../api-reference/endpoint/workspaces-create) | `workspaces:write` |
| वर्कस्पेस अपडेट करें | [`PATCH /workspaces/{id}`](../api-reference/endpoint/workspaces-update) | `workspaces:write` |
| वर्कस्पेस मिटाएँ | [`DELETE /workspaces/{id}`](../api-reference/endpoint/workspaces-delete) | `workspaces:delete` |

कुंजी को सिर्फ़ वही क्षमताएँ दें जिनकी उसे ज़रूरत है। Phaseo वर्कस्पेस की सदस्यता और भूमिका भी जाँचता है, इसलिए सिर्फ़ कोई क्षमता किसी दूसरे वर्कस्पेस तक पहुँच कभी नहीं देती। नए वर्कस्पेस का `slug` 1 से 50 छोटे अक्षरों, अंकों या डैश का होना चाहिए।

प्रबंधन कुंजियाँ सर्वर-साइड सीक्रेट स्टोरेज में रखें, ब्राउज़र कोड, डेस्कटॉप लॉग, सोर्स कंट्रोल या चैट में कभी नहीं।

<Note>
वर्कस्पेस एंडपॉइंट बीटा में हैं। ऑटोमेशन को दोबारा चलाने के लिए सुरक्षित बनाएँ, और अगला बदलाव करने से पहले हर प्रतिक्रिया जाँचें।
</Note>

## वर्कस्पेस का नाम बदलें या उसे मिटाएँ

निजी (डिफ़ॉल्ट) वर्कस्पेस का नाम न बदला जा सकता है, न उसे मिटाया जा सकता है; दोनों `400 bad_request` लौटाते हैं। कोई दूसरा वर्कस्पेस मिटाने से पहले, उसकी सक्रिय API कुंजियाँ हटा दें या दूसरी जगह ले जाएँ, ताकि कोई भी अनुरोध ऐसे वर्कस्पेस की ओर न जाए जो अब मौजूद नहीं है।
