जब प्रदाता समर्थन करता हो, तब सेवा स्तरों से आप अलग-अलग मूल्य निर्धारण और डिलीवरी मोड में से चुन सकते हैं।

उपलब्धता प्रदाता और मॉडल पर निर्भर करती है। अगर अनुरोधित मॉडल के लिए कोई स्तर समर्थित नहीं है, तो Gateway उस स्तर पर रूट नहीं करेगा।

<Note type="warning">
अभी सेवा स्तर केवल उन प्रदाताओं के समर्थित टेक्स्ट मॉडल पर उपलब्ध हैं जो यह सुविधा देते हैं।
</Note>

`service_tier` टेक्स्ट अनुरोध के तीनों इंटरफ़ेस पर समर्थित है:

- `/v1/messages` पर Anthropic के साथ संगत Messages API
- `/v1/chat/completions` पर OpenAI के साथ संगत Chat Completions API
- `/v1/responses` पर OpenAI के साथ संगत Responses API

## स्तरों का अवलोकन

| स्तर | माँगने का तरीका | सामान्य उपयोग |
| --- | --- | --- |
| `Standard` | डिफ़ॉल्ट व्यवहार। कोई अतिरिक्त फ़ील्ड ज़रूरी नहीं। | सामान्य प्रोडक्शन ट्रैफ़िक। |
| `Fast` | अनुरोध में `service_tier: "fast"` सेट करें। | समर्थन मिलने पर तेज़ या प्रीमियम रूटिंग। OpenAI `priority` भी स्वीकार करता है। |
| `Ultrafast` | अनुरोध में `service_tier: "ultrafast"` सेट करें। | समर्थन मिलने पर सबसे तेज़ रूटिंग। |
| `Flex` | अनुरोध में `service_tier: "flex"` सेट करें। | समर्थन मिलने पर कम लागत वाली रूटिंग। |
| `Batch` | `service_tier` के बजाय Batch API उपयोग करें। | बाद में चलाए जा सकने वाले बड़े वर्कलोड, जहाँ लेटेंसी कम महत्वपूर्ण हो। |

## API संगतता

किसी भी समर्थित सिंक्रोनस टेक्स्ट API को कॉल करते समय वही `service_tier` फ़ील्ड इस्तेमाल करें:

- [Anthropic Messages API का संदर्भ](../api-reference/endpoint/anthropic-messages.mdx)
- [Chat Completions API का संदर्भ](../api-reference/endpoint/chat-completions.mdx)
- [Responses API का संदर्भ](../api-reference/endpoint/responses.mdx)
- [साझा पैरामीटर का संदर्भ](../api-reference/parameters.mdx)

`service_tier` के स्वीकृत मान हैं: `standard`, `fast`, `ultrafast`, `priority`, `flex` और `batch`। `service_tier` छोड़ने पर डिफ़ॉल्ट व्यवहार `Standard` होता है। Phaseo प्रीमियम स्तर के मानक नाम के रूप में `Fast` इस्तेमाल करता है। OpenAI रूट पर `priority` को प्रदाता-संगत उपनाम के रूप में स्वीकार किया जाता है, और उस पर वही रूटिंग और मूल्य निर्धारण लागू होता है। `Batch` को सिंक्रोनस टेक्स्ट अनुरोधों के बजाय Batch API संभालता है।

<Note>
Phaseo सामान्यीकृत गेटवे मानों को आंतरिक रूप से प्रदाता के मूल नियंत्रणों से मैप करता है। उदाहरण के लिए, Anthropic रूट को अपस्ट्रीम में Anthropic के अपने स्तर फ़ील्ड मिल सकते हैं, लेकिन क्लाइंट की ओर से भेजे गए अनुरोध में यहाँ बताए गए गेटवे मान ही रहते हैं।
</Note>

## Standard

`Standard` डिफ़ॉल्ट रूटिंग मोड है। इसे इस्तेमाल करने के लिए `service_tier` सेट करना ज़रूरी नहीं है।

```json
{
  "model": "openai/gpt-5.5",
  "input": "Summarise this incident report."
}
```

## Fast

अगर आपको प्रदाता का प्रीमियम या उच्च-प्राथमिकता वाला ऑफ़र चाहिए, तो `Fast` इस्तेमाल करें। Phaseo प्रदाता-निरपेक्ष नाम के रूप में `fast` इस्तेमाल करता है। OpenAI इसे Fast मोड कहता है और समर्थित मॉडलों पर `fast` और `priority` दोनों स्वीकार करता है।

```json
{
  "model": "openai/gpt-5.5",
  "input": "Summarise this incident report.",
  "service_tier": "fast"
}
```

### Anthropic Messages का उदाहरण

```json
{
  "model": "anthropic/claude-sonnet-4",
  "max_tokens": 512,
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "fast"
}
```

Anthropic पर रूट करते समय Phaseo इसे प्रदाता के उपयुक्त मूल नियंत्रण से मैप करता है।

### Mistral Priority और EU रूटिंग

Mistral Priority Tier के लिए पात्र Mistral एंटरप्राइज़ खाता आवश्यक है। Phaseo
`priority` को Mistral के स्वचालित प्राथमिकता मोड से मैप करता है और Mistral द्वारा बताए गए स्तर के अनुसार बिल करता है;
अगर Mistral, Standard पर फ़ॉलबैक करता है, तो Standard मूल्य निर्धारण लागू होता है।

GLM 5.2 को `mistral-eu` प्रदाता ऑफ़र के ज़रिए Mistral के EU क्षेत्रीय एंडपॉइंट पर पिन किया जा सकता है:

```json
{
  "model": "z-ai/glm-5.2",
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "priority",
  "provider": {
    "only": ["mistral-eu"],
    "required_execution_region": "eu"
  }
}
```

Mistral क्षेत्रीय इन्फ़रेंस पर कीमत में 10% की बढ़ोतरी लागू होती है। वैश्विक Mistral ऑफ़र पर Batch मूल्य निर्धारण उपलब्ध है, लेकिन
Mistral क्षेत्रीय एंडपॉइंट पर Batch का समर्थन नहीं करता।

Phaseo, Mistral की प्रकाशित Batch और Priority संदर्भ दरों को रनटाइम उपलब्धता से अलग दर्ज करता है।
कैटलॉग में कीमत दिखने से वह स्तर रूट करने योग्य नहीं हो जाता:
जब तक कोई विशिष्ट Mistral रूट Priority समर्थन घोषित न करे, Priority बंद रहता है, और
Batch के लिए वैश्विक Mistral Batch API इस्तेमाल करना होता है। Priority की पात्रता
अब भी Mistral खाते और मॉडल पर निर्भर करती है।

## Ultrafast

मॉडल और प्रदाता समर्थन करें तो सबसे तेज़ सेवा स्तर के लिए `Ultrafast` इस्तेमाल करें। Phaseo केवल Ultrafast मूल्य वाले या Ultrafast-विशिष्ट रूट पर भेजता है; यह स्तर उपलब्ध न हो तो Fast या Standard पर नहीं लौटता।

```json
{
  "model": "<model-id-with-ultrafast-pricing>",
  "input": "Summarise this incident report.",
  "service_tier": "ultrafast"
}
```

## Flex

जब प्रदाता कम लागत वाला सेवा स्तर उपलब्ध कराता हो और आप उस मूल्य मोड के बदले कुछ समझौते स्वीकार करने को तैयार हों, तब `Flex` इस्तेमाल करें।

```json
{
  "model": "openai/gpt-5.5",
  "input": "Summarise this incident report.",
  "service_tier": "flex"
}
```

### Chat Completions का उदाहरण

```json
{
  "model": "openai/gpt-5.5",
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "flex"
}
```

### Responses का उदाहरण

```json
{
  "model": "openai/gpt-5.5",
  "input": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "flex"
}
```

## Batch

`batch` बैच निष्पादन के लिए मान्य स्तर मान है, लेकिन सिंक्रोनस टेक्स्ट API `service_tier: "batch"` को सत्यापन त्रुटि के साथ अस्वीकार करते हैं, जो Batch API की ओर इशारा करती है।

बैच मूल्य निर्धारण सामान्य सिंक्रोनस अनुरोधों पर नहीं, बल्कि बाद में चलने वाले बैच निष्पादन पर लागू होता है; इसलिए Batch API या बैच जॉब वर्कफ़्लो इस्तेमाल करें।

## ध्यान दें

- स्तरों का समर्थन प्रदाता और मॉडल के अनुसार अलग-अलग होता है।
- जब हमारे पास डेटा होता है, तब मॉडल पेजों के मूल्य कार्ड स्तर-विशिष्ट दरें दिखाते हैं।
- कुछ प्रदाता विशेष अपस्ट्रीम ऑफ़र देते हैं, जिन्हें Phaseo कैटलॉग में एकीकृत, स्तर-आधारित अनुभव में मैप करता है।
- समर्थित टेक्स्ट इंटरफ़ेस पर क्लाइंट को दिखने वाले `service_tier` मान सामान्यीकृत रहते हैं; प्रदाता के मूल नाम गेटवे के भीतर संभाले जाते हैं।
