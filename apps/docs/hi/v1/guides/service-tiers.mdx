तेज़ डिलीवरी के लिए भुगतान करने (`fast`, `ultrafast`) या सस्ता, कम प्राथमिकता वाला मोड (`flex`) स्वीकार करने के लिए टेक्स्ट अनुरोध पर `service_tier` सेट करें। फिर Phaseo सिर्फ़ उन प्रदाताओं पर रूट करता है जो उस मॉडल के लिए वह स्तर देते हैं। यह फ़ील्ड `/v1/chat/completions`, `/v1/responses` और `/v1/messages` पर एक जैसा काम करता है।

```json
{
  "model": "openai/gpt-5.5",
  "input": "Summarise this incident report.",
  "service_tier": "fast"
}
```

| स्तर | अनुरोध कैसे करें | किसके लिए |
| --- | --- | --- |
| Standard | कुछ नहीं, या `"standard"` / `"default"` | सामान्य प्रोडक्शन ट्रैफ़िक |
| Fast | `"fast"`, या इसका उपनाम `"priority"` | प्रदाता का प्रीमियम या ज़्यादा प्राथमिकता वाला ऑफ़र |
| Ultrafast | `"ultrafast"` | सबसे तेज़ गति वाला ऑफ़र |
| Flex | `"flex"` | कम लागत वाला ऑफ़र, जहाँ प्रदाता के पास हो |
| Batch | [Batch API](../api-reference/endpoint/batches-create.mdx), `service_tier` नहीं | बड़े विलंबित वर्कलोड |

स्तर सिर्फ़ टेक्स्ट मॉडल के लिए, और सिर्फ़ वहीं उपलब्ध हैं जहाँ मॉडल और प्रदाता उन्हें सपोर्ट करते हैं। जहाँ Phaseo के पास स्तर-विशेष कीमतें हैं, वहाँ मॉडल पेज उन्हें दिखाते हैं।

## जब कोई स्तर उपलब्ध न हो तो क्या होता है

Phaseo सिर्फ़ वे प्रदाता रूट रखता है जो अनुरोधित स्तर देते हैं; यह कभी किसी दूसरे स्तर पर फ़ॉलबैक नहीं करता। अगर कोई रूट उसे नहीं देता, तो अनुरोध `400 unsupported_model_or_endpoint`, कारण `service_tier_not_supported`, के साथ विफल होता है।

अन्य मान `400 validation_error` के साथ विफल होते हैं:

- सिंक्रोनस अनुरोध पर `service_tier: "batch"` (कीवर्ड `batch_service_tier_not_supported`)। इसके बजाय Batch API का उपयोग करें।
- `standard`, `default`, `fast`, `ultrafast`, `priority`, `flex` या `batch` के अलावा कोई भी मान (कीवर्ड `unsupported_service_tier`)।

आप हमेशा यही Gateway मान भेजते हैं। Phaseo इन्हें हर प्रदाता के अपने नियंत्रणों में बदल देता है, इसलिए उदाहरण के लिए Anthropic रूट को Anthropic के स्तर फ़ील्ड मिलते हैं।

## हर एंडपॉइंट पर स्तर का अनुरोध करें

<CodeGroup>
```json Responses
{
  "model": "openai/gpt-5.5",
  "input": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "flex"
}
```

```json Chat Completions
{
  "model": "openai/gpt-5.5",
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "flex"
}
```

```json Messages
{
  "model": "anthropic/claude-opus-5.5",
  "max_tokens": 512,
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "fast"
}
```
</CodeGroup>

`ultrafast` के लिए ऐसा मॉडल उपयोग करें जिसके पेज पर Ultrafast कीमत दी गई हो।

## Mistral Priority और EU रूटिंग

Mistral Priority Tier के लिए योग्य Mistral एंटरप्राइज़ खाता चाहिए। Phaseo `priority` को Mistral के स्वचालित प्राथमिकता मोड से मैप करता है और Mistral जो स्तर रिपोर्ट करता है उसी का बिल बनाता है: अगर Mistral Standard पर फ़ॉलबैक करता है, तो आप Standard कीमत देते हैं।

कैटलॉग में कीमत होने से कोई स्तर रूट करने योग्य नहीं बनता। Priority तब तक बंद रहता है जब तक वह खास Mistral रूट Priority सपोर्ट का विज्ञापन न करे, और योग्यता फिर भी Mistral खाते और मॉडल पर निर्भर करती है।

GLM 5.2 को `mistral-eu` प्रदाता ऑफ़र के साथ Mistral के EU क्षेत्रीय एंडपॉइंट पर पिन किया जा सकता है:

```json
{
  "model": "z-ai/glm-5.2",
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "priority",
  "provider": {
    "only": ["mistral-eu"],
    "required_execution_region": "eu"
  }
}
```

Mistral क्षेत्रीय इन्फ़रेंस की लागत 10% ज़्यादा है। Batch कीमत सिर्फ़ ग्लोबल Mistral ऑफ़र पर Batch API के ज़रिए उपलब्ध है; Mistral क्षेत्रीय एंडपॉइंट पर Batch सपोर्ट नहीं करता।

पूरा फ़ील्ड संदर्भ [पैरामीटर](../api-reference/parameters.mdx) में है; स्तर प्रदाता क्रम और फ़ॉलबैक के साथ कैसे मिलते हैं, यह जानने के लिए [रूटिंग और फ़ॉलबैक](./routing-and-fallbacks.mdx) देखें।
