जब आपके ऐप्लिकेशन को एक बार के टेक्स्ट जनरेशन से अधिक चाहिए, तब `@phaseo/agent-sdk` उपयोग करें:

- कई चरणों वाले टूल लूप
- स्थानीय रनटाइम टूल
- SDK द्वारा लौटाई गई स्थिति से फिर शुरू किए जा सकने वाले रन
- मानवीय अनुमोदन के लिए स्पष्ट विराम
- टाइप किए गए अंतिम आउटपुट
- मौजूदा TypeScript SDK के ज़रिए Gateway मॉडल टर्न

यह पैकेज इंस्टॉल किया जा सकने वाला SDK है, होस्ट किया गया एजेंट प्लेटफ़ॉर्म नहीं। ऐप्लिकेशन, डिप्लॉयमेंट मॉडल और लौटाई गई रन स्थिति को सहेजने की रणनीति आप स्वयं तय करते हैं।

## स्थिति मॉडल

Agent SDK रन को Phaseo द्वारा होस्ट की गई किसी भी सेवा में नहीं सहेजता।

- `run()` बाद में जारी रखने के लिए आवश्यक पूरी स्थिति लौटाता है।
- यदि आपके ऐप्लिकेशन को अनुरोधों के बीच या प्रोसेस के पुनरारंभ के बाद रन फिर से शुरू करना हो, तो लौटाई गई स्थिति को अपने ऐप्लिकेशन स्टोर में सहेजें।
- `continueRun()` उस पिछली रन स्थिति को सीधे स्वीकार करता है।

Phaseo आपके ऐप्लिकेशन के बाहर कुछ भी नहीं सहेजता।

## इंस्टॉल करें

```bash
pnpm add @phaseo/sdk @phaseo/agent-sdk
```

## SDK में शामिल सुविधाएँ

- `createAgent()`
- `defineTool()`
- `createGatewayAgentClient()`
- पहले लौटाई गई रन स्थिति से जारी रखने के लिए `continueRun()`
- क्रमिक और दोबारा चलाए जा सकने वाले परिणामों के लिए `stream()` और `continueStream()`
- `stepCountIs()`, `maxCost()` और `hasToolCall()` जैसे रोकने की शर्त वाले हेल्पर

## पहला एजेंट

```typescript
import {
  createAgent,
  createGatewayAgentClient,
  defineTool,
} from "@phaseo/agent-sdk";

const lookupDocs = defineTool({
  id: "lookup-docs",
  description: "Look up an internal docs page by slug.",
  parameters: {
    type: "object",
    properties: {
      slug: { type: "string" },
    },
    required: ["slug"],
    additionalProperties: false,
  },
  async execute(input: { slug: string }) {
    return {
      slug: input.slug,
      url: `https://phaseo.app/docs/v1/${input.slug}`,
    };
  },
});

const agent = createAgent({
  id: "support-docs-agent",
  model: "phaseo/free",
  instructions: "Use tools when helpful and finish with a concise answer.",
  tools: [lookupDocs],
});

const result = await agent.run({
  input: "Find the docs page for presets and explain when to use them.",
  client: createGatewayAgentClient({
    clientOptions: {
      apiKey: process.env.PHASEO_API_KEY!,
    },
  }),
});

console.log(result.output);
```

## मानसिक मॉडल

रनटाइम लूप चार काम करता है:

1. संदेशों की मौजूदा स्थिति को मॉडल क्लाइंट को भेजता है
2. लौटाई गई स्थानीय टूल कॉल को निष्पादित करता है
3. टूल परिणामों को अगले टर्न में जोड़ता है
4. हर चरण की सीमा पूरी होने के बाद अपडेट की गई रन स्थिति लौटाता है

इससे होस्ट किए गए ऑर्केस्ट्रेशन उत्पाद पर निर्भर हुए बिना आपके ऐप्लिकेशन को फिर से शुरू किया जा सकने वाला लूप मिलता है।

## मुख्य प्रिमिटिव

### `createAgent()`

`createAgent()` से ये परिभाषित करें:

- एक स्थिर `id`
- निर्देश
- एक मॉडल या प्रीसेट
- टूल की एक छोटी सूची
- वैकल्पिक आउटपुट पार्सिंग
- वैकल्पिक मानवीय समीक्षा नियम
- वैकल्पिक पुनः प्रयास और टूल निष्पादन नियंत्रण

पहले एजेंट का दायरा छोटा रखें। आम तौर पर एक वर्कफ़्लो और एक या दो टूल पर्याप्त होते हैं।

### `defineTool()`

स्थानीय रनटाइम टूल को इनसे परिभाषित करें:

- `id`
- `description`
- वैकल्पिक JSON `parameters`
- वैकल्पिक `timeoutMs`
- `inputSchema` और `outputSchema` रनटाइम वैलिडेटर
- `execute()`, `execute: false` या मानवीय समीक्षा के कॉलबैक
- `requireApproval`, `onError`, `nextTurnParams` और प्रगति इवेंट

```typescript
const fetchTicket = defineTool({
  id: "fetch-ticket",
  description: "Load one internal support ticket.",
  parameters: {
    type: "object",
    properties: {
      ticketId: { type: "string" },
    },
    required: ["ticketId"],
    additionalProperties: false,
  },
  timeoutMs: 3_000,
  async execute(input: { ticketId: string }, context) {
    const response = await fetch(`https://internal.example/tickets/${input.ticketId}`, {
      signal: context.signal,
    });

    return await response.json();
  },
});
```

टाइमआउट होने पर रनटाइम `context.signal` को निरस्त करता है, रन को `failed` चिह्नित करता है और टाइमआउट त्रुटि फिर से थ्रो करता है।

स्कीमा कोई फ़ंक्शन या `parse()`/`safeParse()` उपलब्ध कराने वाला कोई भी ऑब्जेक्ट हो सकता है। अमान्य मॉडल आर्ग्युमेंट और अमान्य टूल परिणाम, टूल की सीमा पार करने से पहले ही विफल हो जाते हैं।

## अनुमोदन, HITL और मैन्युअल टूल

साइड इफ़ेक्ट वाले टूल को हर कॉल के स्तर पर अनुमोदन से नियंत्रित करें:

```typescript
const deploy = defineTool({
  id: "deploy",
  requireApproval: ({ environment }) => environment === "production",
  async execute(input: { environment: string }) {
    return deployRelease(input.environment);
  },
});
```

रन `run.pause.pendingToolCalls` के साथ रुकता है। सटीक कॉल ID से फिर शुरू करें, ताकि समवर्ती कॉल आपस में न उलझें:

```typescript
const resumed = await agent.continueRun({
  run: paused,
  client,
  approvals: [{ toolCallId: "call_deploy_42" }],
  rejections: [{ toolCallId: "call_delete_17", reason: "Not authorized" }],
});
```

आपके ऐप्लिकेशन द्वारा किए जाने वाले काम के लिए `execute: false` रखें और उसका परिणाम `toolOutputs` के ज़रिए दें। इंटरैक्टिव टूल के लिए `onToolCalled` से `null` लौटाएँ; जारी रखने के बाद `onResponseReceived` दी गई मानवीय प्रतिक्रिया को सत्यापित या रूपांतरित कर सकता है।

## प्रगति देने वाले टूल

एक एसिंक्रोनस जनरेटर शुरुआती परिणाम प्रकाशित कर सकता है और एक अंतिम परिणाम लौटा सकता है:

```typescript
const indexRepository = defineTool({
  id: "index-repository",
  async *execute(input: { path: string }) {
    yield { phase: "scan" };
    yield { phase: "embed" };
    return { indexed: 248 };
  },
});
```

प्रगति `tool.preliminary_result` इवेंट के रूप में और चरण के `preliminaryResults` में दिखती है।

## स्ट्रीमिंग परिणाम

`stream()` स्ट्रीमिंग मॉडल क्लाइंट के साथ वही स्टेट मशीन शुरू करता है। इसके उपभोक्ता स्ट्रीम को दोबारा पढ़ सकते हैं, इसलिए UI, टेलीमेट्री और सहेजने वाला कोड एक साथ पढ़ सकते हैं:

```typescript
const result = agent.stream({ input, client });

for await (const delta of result.getTextStream()) {
  process.stdout.write(delta);
}

const [text, completed] = await Promise.all([result.getText(), result.getResult()]);
```

अधिक विशिष्ट उपभोक्ताओं के लिए `getReasoningStream()`, `getItemsStream()`, `getToolStream()` या `getFullStream()` उपयोग करें। `cancel()` रन को निरस्त करता है।

### टाइप किए गए रन आइटम रेंडर करें

`getItemsStream()` `AgentItem<TOutput>` देता है, जो एक डिस्क्रिमिनेटेड यूनियन है और जिसे `switch` में सुरक्षित रूप से उपयोग किया जा सकता है:

```typescript
for await (const item of result.getItemsStream()) {
  switch (item.type) {
    case "message":
      renderAssistantMessage(item.content);
      break;
    case "reasoning":
      renderReasoning(item.text);
      break;
    case "tool_call":
      renderToolCall(item.toolCallId, item.name, item.input);
      break;
    case "tool_result":
      renderToolResult(item.toolCallId, item.output);
      break;
    case "error":
      renderError(item.message);
      break;
    case "output":
      renderFinalOutput(item.value);
      break;
  }
}
```

`run()` या `stream()` के बाद वही क्रमबद्ध आइटम अनुबंध `completed.items` में मिलता है। प्रदाता का आउटपुट संदेश, तर्क-विचार, टूल-कॉल, टूल-परिणाम, त्रुटि और अंतिम-आउटपुट आइटम में सामान्यीकृत होता है। सामान्यीकृत प्रदाता आइटम के प्रदाता-विशिष्ट फ़ील्ड `rawProviderItem` से मिलते हैं।

## रोकने की शर्तें और डायनामिक टर्न

रोकने की शर्तें एक ऐरे के रूप में जुड़ती हैं; पहली मेल खाने वाली शर्त अपना कारण दर्ज करती है और `stopped` रन लौटाती है:

```typescript
import { maxCost, maxTokensUsed, stepCountIs } from "@phaseo/agent-sdk";

const agent = createAgent({
  id: "bounded-research",
  stopWhen: [stepCountIs(12), maxTokensUsed(40_000), maxCost(2)],
  model: ({ context }) => context.fast ? "phaseo/free" : "anthropic/claude-sonnet-4",
  instructions: ({ numberOfTurns }) => `Research turn ${numberOfTurns}`,
});
```

टूल `context.setContext()` से ऐप्लिकेशन संदर्भ सेट कर सकते हैं और `nextTurnParams` से ठीक अगले टर्न को ओवरराइड कर सकते हैं।

### `createGatewayAgentClient()`

जब मॉडल टर्न Phaseo Gateway के ज़रिए चलने चाहिए, तब Gateway-आधारित एडैप्टर उपयोग करें।

यह Gateway के अपने नियंत्रण भी साथ ले जा सकता है, जैसे:

- `responseFormat`
- `plugins`
- `gatewayTools`
- `toolChoice`
- `webSearchOptions`
- `providerOptions`
- `promptCacheKey`
- `includeMeta`

इससे आपका ऐप हर रन पर कच्चा अनुरोध पेलोड दोबारा बनाने के बजाय रूटिंग, खोज, संरचित आउटपुट और प्लगइन डिफ़ॉल्ट को मॉडल क्लाइंट के पास ही रख सकता है।

## एप्लिकेशन द्वारा प्रबंधित स्थायित्व

अगर आपके ऐप्लिकेशन को रन फिर से शुरू करने की क्षमता चाहिए, तो लौटाए गए `AgentRunResult` को सीधे सहेजें, या एसिंक्रोनस `load(runId)` और `save(result)` मेथड वाला `state` एक्सेसर दें। इसके बाद जारी रखा गया रन हर परत से सीरियलाइज़ किया गया रिकॉर्ड गुज़ारे बिना `runId` उपयोग कर सकता है।

SDK जानबूझकर स्थायित्व एडैप्टर या होस्ट किया गया स्टेट बैकएंड शामिल नहीं करता।

इसका मतलब है कि आप ये कर सकते हैं:

- एक बार चलने वाले रन को पूरी तरह प्रोसेस के भीतर रखना
- रोके गए या अधूरे रन को अपने ऐप्लिकेशन रिकॉर्ड में सीरियलाइज़ करना
- बाद में सहेजी गई रन स्थिति फिर से लोड करके `continueRun()` को देना

## मानवीय समीक्षा और आगे जारी रखना

जब रन को चेकपॉइंट बनाकर अनुमोदन की प्रतीक्षा करनी हो, तब `humanReview` उपयोग करें:

```typescript
const agent = createAgent({
  id: "support-agent",
  humanReview: ({ response }) =>
    response.message.content.includes("needs approval")
      ? {
          reason: "approval_required",
          payload: { draft: response.message.content },
        }
      : null,
});
```

स्पष्ट मानवीय इनपुट के साथ जारी रखें:

```typescript
const continued = await agent.continueRun({
  run: pausedResult,
  client,
  humanInput: "Approved. Continue and return the final answer.",
});
```

## टाइप किए गए आउटपुट

जब आपके ऐप को टाइप किया गया अंतिम मान चाहिए, तब `parseOutput` उपयोग करें:

```typescript
const agent = createAgent<string, { summary: string }>({
  id: "summary-agent",
  parseOutput(text) {
    return JSON.parse(text) as { summary: string };
  },
});
```

मॉडल के अधिक सख्त व्यवहार के लिए इसे Gateway एडैप्टर के संरचित आउटपुट के साथ जोड़ें:

```typescript
const client = createGatewayAgentClient({
  clientOptions: {
    apiKey: process.env.PHASEO_API_KEY!,
  },
  responseFormat: {
    type: "json_schema",
    name: "agent_answer",
    schema: {
      type: "object",
      properties: {
        summary: { type: "string" },
      },
      required: ["summary"],
      additionalProperties: false,
    },
  },
  plugins: [{ id: "response-healing" }],
});
```

## रनटाइम नियंत्रण

### मॉडल पुनः प्रयास

जब अस्थायी मॉडल विफलताओं पर रन को `failed` के रूप में सहेजने से पहले पुनः प्रयास होना चाहिए, तब `modelRetry` उपयोग करें:

```typescript
const agent = createAgent({
  id: "support-agent",
  modelRetry: {
    maxRetries: 2,
    backoffMs: 250,
  },
});
```

पहले मॉडल अनुरोध के बाद के अतिरिक्त प्रयास `maxRetries` में गिने जाते हैं।
सहेजे गए चरण रिकॉर्ड में पुनः प्रयासों की अंतिम संख्या `modelAttempts` के रूप में रखी जाती है।

### समवर्ती स्थानीय टूल

अगर एक मॉडल टर्न कई स्वतंत्र टूल को सुरक्षित रूप से कॉल कर सकता है, तो `toolExecution.toolConcurrency` सेट करें:

```typescript
const agent = createAgent({
  id: "research-agent",
  toolExecution: {
    toolConcurrency: 3,
  },
  tools: [fetchDocs, fetchStatus, fetchIncidents],
});
```

रनटाइम फिर भी टूल परिणाम संदेशों का क्रम बनाए रखता है।

### प्रीसेट-आधारित रूटिंग

जब रूटिंग, प्रॉम्प्ट या पैरामीटर डिफ़ॉल्ट को ऐप कोड में हार्ड-कोड करने के बजाय डैशबोर्ड में प्रबंधित रखना हो, तब `preset` उपयोग करें:

```typescript
const agent = createAgent({
  id: "support-triage-agent",
  preset: "support-triage",
});
```

## इवेंट हुक

जब आपके ऐप्लिकेशन को लॉग, टेलीमेट्री या आंतरिक वर्कफ़्लो के लिए लाइफ़साइकल हुक चाहिए, तब `onEvent` उपयोग करें।

मौजूदा इवेंट में शामिल हैं:

- `run.started`
- `run.resumed`
- `step.started`
- `step.completed`
- `step.failed`
- `step.cancelled`
- `model.requested`
- `model.completed`
- `model.failed`
- `tool.started`
- `tool.completed`
- `tool.failed`
- `checkpoint.saved`
- `run.waiting_for_human`
- `run.cancelled`
- `run.completed`
- `run.failed`

जब कोई चरण सफल होता है, तो चेकपॉइंट वाला चरण सहेजे जाने के बाद रनटाइम `step.completed` इवेंट भेजता है।

## त्रुटि प्रबंधन

Gateway विफलताओं को `AgentGatewayError` के रूप में फिर से थ्रो किया जाता है:

```typescript
import { AgentGatewayError } from "@phaseo/agent-sdk";

try {
  await agent.run({ input, client });
} catch (error) {
  if (error instanceof AgentGatewayError) {
    console.error(error.status, error.requestId, error.reason);
  }
  throw error;
}
```

अगर विफलता Gateway से आई हो, तो विफल रन और चरणों में `errorDetails` भी सहेजा जाता है।

## मौजूदा दायरा

SDK जानबूझकर ऐप्लिकेशन बनाने वाले प्रिमिटिव पर केंद्रित है:

- स्थानीय या ऐप-प्रबंधित चेकपॉइंट सहेजना
- Gateway के ज़रिए मॉडल टर्न
- स्थानीय टूल
- फिर से शुरू किए जा सकने वाले एजेंट लूप
- हर चरण का सामान्यीकृत टोकन उपयोग, लागत, चेतावनियाँ, समाप्ति कारण और टूल परिणाम

यह होस्टेड ऑर्केस्ट्रेशन प्लेटफ़ॉर्म बनने या कोई तयशुदा दूरस्थ डेटा-संग्रह बैकएंड देने का प्रयास नहीं करता।
