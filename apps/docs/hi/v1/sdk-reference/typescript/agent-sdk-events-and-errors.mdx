जब आपके ऐप्लिकेशन को तय करना हो कि पुनः प्रयास करना है, उपयोगकर्ता से अलग इनपुट माँगना है या ऑपरेटर को अनुरोध का विवरण दिखाना है, तब Agent SDK की संरचित त्रुटियों का उपयोग करें।

## गेटवे विफलताओं को संभालें

गेटवे की विफलताएँ `AgentGatewayError` के रूप में फिर से थ्रो की जाती हैं:

```typescript
import { AgentGatewayError } from "@phaseo/agent-sdk";

try {
  await agent.run({ input, client });
} catch (error) {
  if (error instanceof AgentGatewayError) {
    console.error(error.status, error.requestId, error.reason);
  }
  throw error;
}
```

उपलब्ध होने पर, विफल रन और चरणों में गेटवे त्रुटि का विवरण बना रहता है।

## स्कीमा विफलताओं को संभालें

`AgentSchemaValidationError` अमान्य टूल इनपुट, टूल आउटपुट, प्रगति इवेंट या अंतिम आउटपुट की पहचान करता है। इन्हें अस्थायी मॉडल विफलताओं के बजाय अनुबंध विफलताएँ मानें।

```typescript
import { AgentSchemaValidationError } from "@phaseo/agent-sdk";

try {
  await agent.run({ input, client });
} catch (error) {
  if (error instanceof AgentSchemaValidationError) {
    console.error(error.target, error.message);
  }
  throw error;
}
```

## विफल रन की जाँच करें

अगर रनटाइम विफलता का चेकपॉइंट बना सके, तो ये देखें:

- `result.run.status`
- `result.run.error`
- सबसे हाल के चरण का `status`, `error` और `modelAttempts`
- गेटवे लॉग से मिलान करने के लिए `requestId` और `nativeResponseId`

## सामान्य जाँचें

- पुष्टि करें कि सर्वर प्रोसेस के लिए `PHASEO_API_KEY` उपलब्ध है।
- हर टूल को अद्वितीय और स्थिर `id` दें।
- अनुमोदन, अस्वीकृति या मैन्युअल आउटपुट देते समय टूल कॉल की सटीक ID इस्तेमाल करें।
- मॉडल के पुनः प्रयास सीमित रखें; सत्यापन और अनुमोदन की विफलताओं पर आँख मूँदकर पुनः प्रयास नहीं होना चाहिए।
- ब्राउज़र या कतार वर्कर को नियंत्रण लौटाने से पहले रुके हुए रन की स्थिति सहेजें।
