ट्रांसपोर्ट और गेटवे की विफलताओं को अमान्य टूल या आउटपुट डेटा से अलग संभालें। विफल रन में उसकी स्थिति, सक्रिय चरण, पुनः प्रयास की संख्या, अनुरोध ID, मूल प्रतिक्रिया ID और गेटवे का उपलब्ध विवरण बना रहता है।

## आम जाँच

- पुष्टि करें कि `PHASEO_API_KEY` Java प्रोसेस के लिए उपलब्ध है।
- हर टूल को अद्वितीय और स्थिर ID दें।
- अनुमोदन, अस्वीकृति और मैन्युअल आउटपुट देते समय टूल कॉल की सटीक ID इस्तेमाल करें।
- किसी दूसरे अनुरोध या वर्कर को नियंत्रण लौटाने से पहले रुका हुआ `RunResult` सहेजें।
- वैलिडेटर को नियतात्मक और साइड इफ़ेक्ट से मुक्त रखें।
- जब तक ऐप्लिकेशन स्पष्ट रूप से नया रन शुरू न करे, रद्दीकरण और टाइमआउट एक्सेप्शन को अंतिम मानें।

ऐप्लिकेशन टेलीमेट्री के लिए लाइफ़साइकल हुक और स्थानीय रन रिकॉर्ड के लिए DevTools इस्तेमाल करें; केवल कंसोल आउटपुट पर निर्भर न रहें।
