## एजेंट बनाएँ

एक definition से एजेंट बनाता है। Definition की स्टेप सीमा हर run या continue कॉल पर लागू होती है।

| भाषा | नाम | डिफ़ॉल्ट स्टेप सीमा |
| --- | --- | --- |
| TypeScript | `createAgent(definition)` | 12 |
| Python | `create_agent(definition)`, किसी dict या `AgentDefinition` से | 12 |
| Go | `CreateAgent(AgentDefinition) *Agent` | 8 |
| C# | `AgentSdk.CreateAgent(AgentDefinition)` | 12 |
| PHP | `AgentSdk::createAgent(AgentDefinition)` | 12 |
| Ruby | `PhaseoAgentSdk.create_agent(definition)`, किसी `AgentDefinition` या keyword फ़ील्ड से | 12 |
| Java | `AgentSdk.createAgent(AgentDefinition)` | 12 (1 से कम `maxSteps` 12 हो जाता है) |
| Rust | `create_agent(AgentDefinition::new(id, model))` | 8 (मान कम से कम 1 तक सीमित किए जाते हैं) |

### Definition फ़ील्ड

Rust definition को फ़ील्ड के बजाय methods से बनाता है: `AgentDefinition::new(id, model)`, फिर `.instructions(text)`, `.tool(tool)` (हर टूल के लिए एक बार), `.max_steps(limit)`, `.model_retries(count, backoff)` और `.human_review(callback)`। Java का `AgentDefinition` 10-, 13- और 19-argument constructors वाला एक record है।

| --- | --- | --- | --- | --- |

| निर्देश | `instructions` | `instructions` | `Instructions` | |
| टूल | `tools` | `tools` | `Tools` | |

### Run विकल्प

PHP और Ruby इन्हें named या keyword arguments के रूप में लेते हैं; Java का `RunOptions` एक positional record है, इस क्रम में: `input, client, context, model, preset, maxSteps, modelRetry, toolExecution, onEvent, devtools`, फिर एक वैकल्पिक `state`।

| विकल्प | camelCase (TypeScript, PHP, Java) | snake_case (Python, Ruby, Rust) | PascalCase (Go, C#) | इनमें नहीं |
| --- | --- | --- | --- | --- |
| इनपुट | `input` | `input` | `Input` | |
| इनपुट की जगह पूरी बातचीत | `messages` | | | TypeScript को छोड़कर सभी |
| मॉडल क्लाइंट | `client` | `client` | `Client` | Rust इसे अलग argument के रूप में देता है |
| ऐप्लिकेशन संदर्भ | `context` | `context` | `Context` | |
| मॉडल, प्रीसेट और स्टेप सीमा overrides | `model`, `preset`, `maxSteps` | `model`, `preset`, `max_steps` | `Model`, `Preset`, `MaxSteps` | Rust में सिर्फ़ `model` और `max_steps` हैं |
| Retry और टूल concurrency overrides | `modelRetry`, `toolExecution` | `model_retry`, `tool_execution` | `ModelRetry`, `ToolExecution` | Rust |
| Sampling overrides | `temperature`, `maxOutputTokens`, `topP` (TypeScript) | | | TypeScript को छोड़कर सभी |
| रद्द करना | `signal` (TypeScript) | | `CancellationToken` (C#) | Go `ctx` का उपयोग करता है; बाकी स्ट्रीम के ज़रिए रद्द करते हैं |

| स्थानीय कैप्चर | `devtools` | `devtools` | `Devtools` | Rust |
| State accessor | `state` | `state` | `State` | Rust |
| अगले मॉडल अनुरोध से पहले मैसेज जोड़ें | `takeMessages` (TypeScript) | | | TypeScript को छोड़कर सभी |

Python का `run()` `stop_when` भी स्वीकार करता है लेकिन उसे अनदेखा करता है; रोकने की शर्तें definition पर सेट करें। PHP का `stream()` और Ruby का `stream` सिर्फ़ `input`, `client`, `context` और `state` लेते हैं। Rust `RunOptions::new(input)` से डिफ़ॉल्ट बनाता है।

Continue विकल्प ऊपर दिए run overrides लेते हैं, साथ में:

| पूरा अंतिम टेक्स्ट | `getText()` | | | | | | |
| टेक्स्ट deltas | `getTextStream()` | `text_stream()` | `Text()` | `TextStream()` | `textStream()` | `text_stream` | `textStream()` |

Consumers शुरुआत से replay करते हैं, इसलिए कई consumers एक ही रन पढ़ सकते हैं। उनका व्यवहार अलग-अलग है:

| भाषा | Stream result टाइप | व्यवहार |
| --- | --- | --- |
| TypeScript | `AgentStreamResult` | `getFullStream()` एक `result` इवेंट के साथ ख़त्म होता है |
| Python | `AgentStreamResult` | बैकग्राउंड थ्रेड में चलता है; `result()` पूरा होने तक ब्लॉक करता है |

| Ruby | `StreamResult` | वर्कर थ्रेड में चलता है; `result` उससे join करता है और `cancel` उसे ख़त्म करता है |
| Java | `StreamResult` | `textStream()` और `fullStream()` रन ख़त्म होने के बाद एक `List` लौटाते हैं; `cancel()` वर्कर थ्रेड को बाधित करता है |
| Rust | कोई नहीं | `0.2` में स्ट्रीमिंग नहीं है |

## रन नतीजा

| फ़ील्ड | camelCase (TypeScript, PHP, Java) | snake_case (Python, Ruby, Rust) | PascalCase (Go, C#) |
| --- | --- | --- | --- |
| रन रिकॉर्ड | `run` | `run` | `Run` |
| स्टेप रिकॉर्ड | `steps` | `steps` | `Steps` |
| अंतिम आउटपुट | `output` | `output` | `Output` |
| पूरी बातचीत | `messages` | `messages` | `Messages` |
| कुल उपयोग | `usage` | `usage` | `Usage` |

TypeScript और Python में टाइप `AgentRunResult` है और बाकी जगह `RunResult`। TypeScript में `stepResults` (normalized स्टेप नतीजे) और `items` (क्रमबद्ध मैसेज, reasoning, टूल गतिविधि, त्रुटियाँ और अंतिम आउटपुट; [आइटम](./items) देखें) भी हैं। Rust में, `output` एक `serde_json::Value` है, और `RunResult`, `RunRecord`, `RunStep`, `Message`, `ToolCall`, `HumanPause`, `PendingToolCall`, `ToolDecision`, `ToolOutput` और `UsageSummary` Serde से serialize होते हैं।

### रन रिकॉर्ड

## मॉडल क्लाइंट

मॉडल टर्न किसी दूसरे ट्रांसपोर्ट से भेजने के लिए, या gateway क्लाइंट को लपेटने के लिए, एक मॉडल क्लाइंट लागू करें।

| भाषा | Interface | Methods |
| --- | --- | --- |
| Go | `ModelClient`, `StreamingModelClient` | `Generate(ctx, ModelRequest)`; `Stream(ctx, ModelRequest)` |
| C# | `IModelClient`, `IStreamingModelClient` | `Generate(ModelRequest)`; `Stream(ModelRequest)` |
| PHP | `ModelClient`, `StreamingModelClient` (interfaces) | `generate(ModelRequest)`; `stream(ModelRequest)` |
| Java | `ModelClient`, `StreamingModelClient` | `generate(ModelRequest)`; `stream(ModelRequest)` |
| Rust | `ModelClient` (trait) | `fn generate(&mut self, request: &ModelRequest) -> Result<ModelResponse, AgentError>` |

Rust में, `ModelRequest` में एजेंट ID, प्रभावी मॉडल, निर्देश, मौजूदा मैसेज, टूल विनिर्देश (`ToolSpec`: `id`, `description`, JSON Schema `parameters`) और ऐप्लिकेशन संदर्भ होते हैं। `ModelResponse` में `message`, `usage`, `request_id`, `provider`, `model` और `finish_reason` होते हैं। `Message` में `role`, `content`, `tool_calls`, `tool_call_id`, `name` और `is_error` होते हैं, साथ में `Message::user(content)` और `Message::assistant(content)` constructors; `ToolCall` में `id`, `name` और JSON `input` होते हैं।
