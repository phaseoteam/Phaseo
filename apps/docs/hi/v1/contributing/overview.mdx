कैटलॉग सुधार और जोड़ने के लिए प्रभावित रिकॉर्ड तथा समर्थन स्रोतों के साथ issue खोलें। कोड या दस्तावेज़ बदलाव के लिए [Phaseo रिपॉज़िटरी](https://github.com/phaseoteam/Phaseo) में पुल अनुरोध भेजें।

## अपना योगदान चुनें

| बदलाव | यहाँ शुरू करें |
| --- | --- |
| मॉडल मेटाडेटा, क्षमताएँ, उपलब्धता या कीमत | [मॉडल अपडेट की रिपोर्ट दें](./editing-a-model.mdx) |
| कंपनी या शोध संगठन विवरण | [संगठन अपडेट की रिपोर्ट दें](./editing-an-organisation.mdx) |
| बेंचमार्क परिणाम | [स्कोर भेजें](../research/submitting-scores.mdx) |
| अन्य कैटलॉग सुधार | [गलत जानकारी की रिपोर्ट दें](https://github.com/phaseoteam/Phaseo/issues/new?template=incorrect-info.yml) |
| अनुपस्थित प्रदाता या अन्य कैटलॉग डेटा | [नया डेटा माँगें](https://github.com/phaseoteam/Phaseo/issues/new?template=data-request.yml) |
| दस्तावेज़ या कोड | [योगदान प्रक्रिया](./how-to-contribute.mdx) और [रिपॉज़िटरी संरचना](./repo-structure.mdx) |

## कैटलॉग रिपोर्ट कैसे प्रकाशित होती हैं

रखरखावकर्ता issue में प्रमाण जाँचते हैं और केवल एडमिन के [आंतरिक एडिटर](https://phaseo.app/internal/data) से स्वीकृत बदलाव लागू करते हैं। प्रदाता कीमत अपडेट प्रकाशित करने से पहले स्पष्ट समीक्षा चाहिए।

डेटाबेस कैटलॉग का प्रामाणिक स्रोत है। दैनिक सार्वजनिक JSON स्नैपशॉट उपलब्ध रहते हैं, लेकिन स्नैपशॉट संपादन या संग्रहीत JSON पुल अनुरोध लाइव कैटलॉग नहीं बदलते। पुराना JSON आयातक बंद हो चुका है।

## भेजने से पहले

- प्रभावित पेज या रिकॉर्ड ID शामिल करें और प्रस्तावित सुधार बताएँ।
- आधिकारिक स्रोत दें और बताए गए बेंचमार्क परिणाम स्वतंत्र मापों से अलग रखें।
- हर रिपोर्ट या पुल अनुरोध केंद्रित रखें।
- क्रेडेंशियल या निजी ग्राहक डेटा कभी शामिल न करें।
- [आचार संहिता](../community/code-of-conduct.mdx) मानें।

बड़े स्कीमा या सुविधा बदलाव लागू करने से पहले रखरखावकर्ताओं से चर्चा करें। बदलाव कहाँ होना चाहिए, यह स्पष्ट न हो तो [Discord](https://discord.gg/aQyywCvgZ5) में मदद माँगें।
