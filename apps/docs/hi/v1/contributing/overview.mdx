कैटलॉग में सुधार और नई जानकारी के लिए प्रभावित रिकॉर्ड और सहायक स्रोतों के साथ issue खोलें। कोड या दस्तावेज़ बदलाव के लिए [Phaseo रिपॉज़िटरी](https://github.com/phaseoteam/Phaseo) में pull request भेजें।

## अपना योगदान चुनें

| बदलाव | यहाँ से शुरू करें |
| --- | --- |
| मॉडल मेटाडेटा, क्षमताएँ, उपलब्धता या कीमतें | [मॉडल अपडेट की सूचना दें](./editing-a-model.mdx) |
| कंपनी या शोध संगठन की जानकारी | [संगठन अपडेट की सूचना दें](./editing-an-organisation.mdx) |
| बेंचमार्क परिणाम | [स्कोर सबमिट करें](../research/submitting-scores.mdx) |
| कैटलॉग के दूसरे सुधार | [गलत जानकारी की रिपोर्ट करें](https://github.com/phaseoteam/Phaseo/issues/new?template=incorrect-info.yml) |
| छूटे हुए प्रदाता या दूसरा कैटलॉग डेटा | [नए डेटा का अनुरोध करें](https://github.com/phaseoteam/Phaseo/issues/new?template=data-request.yml) |
| दस्तावेज़ या कोड | [योगदान प्रक्रिया](./how-to-contribute.mdx) और [रिपॉज़िटरी संरचना](./repo-structure.mdx) |

## कैटलॉग रिपोर्ट कैसे प्रकाशित होती हैं

मेंटेनर issue में दिए प्रमाणों की समीक्षा करते हैं और स्वीकृत बदलाव सिर्फ़ एडमिन के लिए उपलब्ध [आंतरिक संपादक](https://phaseo.app/internal/data) से लागू करते हैं। प्रदाता की कीमतों के अपडेट प्रकाशन से पहले स्पष्ट समीक्षा माँगते हैं।

कैटलॉग रिकॉर्ड का एकमात्र स्रोत डेटाबेस है। रिपॉज़िटरी में कोई कैटलॉग JSON नहीं है, इसलिए pull request से कैटलॉग रिकॉर्ड नहीं बदला जा सकता।

## सबमिट करने से पहले

- प्रभावित पेज या रिकॉर्ड ID शामिल करें और प्रस्तावित सुधार बताएँ।
- आधिकारिक स्रोतों का हवाला दें, और रिपोर्ट किए गए बेंचमार्क परिणामों को स्वतंत्र मापों से अलग बताएँ।
- हर रिपोर्ट या pull request को एक ही विषय पर केंद्रित रखें।
- कभी भी क्रेडेंशियल या निजी ग्राहक डेटा शामिल न करें।
- [आचार संहिता](../community/code-of-conduct.mdx) का पालन करें।

बड़े स्कीमा या फ़ीचर बदलावों को लागू करने से पहले मेंटेनर से चर्चा करें। अगर आपको पक्का नहीं है कि कोई बदलाव कहाँ जाना चाहिए, तो [Discord](https://discord.gg/aQyywCvgZ5) में मदद माँगें।
