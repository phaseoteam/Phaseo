बेस URL और कुंजी बदलें, अनुरोध पेलोड वैसे ही रखें, और हर मॉडल ID मैप करें: LLM Gateway का प्रीफ़िक्स सर्व करने वाले प्रदाता का नाम बताता है, जबकि Phaseo का प्रीफ़िक्स मॉडल बनाने वाले का।

| सेटिंग | LLM Gateway | Phaseo |
| --- | --- | --- |
| बेस URL | `https://api.llmgateway.io/v1` | `https://api.phaseo.app/v1` |
| Anthropic-शैली के क्लाइंट | `ANTHROPIC_BASE_URL=https://api.llmgateway.io` | `https://api.phaseo.app`, देखें [Anthropic SDK से माइग्रेट करना](./from-anthropic) |
| API कुंजी | `LLM_GATEWAY_API_KEY` (`llmgtwy_…`) | `PHASEO_API_KEY` |
| मॉडल ID | `gpt-4o`, `<provider>/<model>`, `auto` | `GET /v1/models?format=openai` से `<org>/<model>` |
| अनुरोध पेलोड | OpenAI-संगत | अपरिवर्तित |

## क्लाइंट बदलें

<CodeGroup>
```typescript TypeScript
import OpenAI from "openai";

// पहले:
// new OpenAI({ apiKey: process.env.LLM_GATEWAY_API_KEY, baseURL: "https://api.llmgateway.io/v1" });
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});
```

```python Python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
)
```

```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```
</CodeGroup>

हर `LLM_GATEWAY_*` वेरिएबल को मैप करें या हटाएं, CI और होस्टिंग सेटिंग में भी। अगर ऐप `@llmgateway/ai-sdk-provider` उपयोग करता है, तो [Vercel AI Gateway से माइग्रेट करना](./from-vercel) की तरह `@phaseo/ai-sdk-provider` पर जाएं।

## मॉडल ID मैप करें

Phaseo की ID सूचीबद्ध करें और हर प्रोडक्शन मॉडल को उनसे जांचें:

```bash
curl -s "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY" | jq -r '.data[].id'
```

LLM Gateway पर `alibaba/<model>` Phaseo ID नहीं है। हर ID को Phaseo के `<org>/<model>` से मैप करें, और प्रदाता पिन को `provider.only` या `provider:org/model` ID से बनाए रखें। `gpt-4o` जैसे बिना प्रीफ़िक्स वाले उपनामों का अनुवाद हर कॉल साइट पर नहीं, क्लाइंट सीमा पर एक फ़ंक्शन में करें।

## गेटवे सुविधाएं मैप करें

| LLM Gateway | Phaseo पर |
| --- | --- |
| `auto` राउटर | `phaseo/auto` ([ऑटो रूटिंग](../guides/auto-routing), अल्फ़ा); `models` के साथ नहीं मिलाया जा सकता। |
| फ़ॉलबैक चेन | `models` ऐरे या डायनामिक रूट, जो `429`, `500`, `502`, `503` और `504` पर आज़माए जाते हैं, अनुरोध त्रुटियों पर कभी नहीं। |
| `X-No-Fallback` | `provider.allow_fallbacks: false`, या `provider:org/model` ID। |
| प्रदाता अनुमति और अस्वीकृति तर्क | `provider.only`, `provider.ignore`, या [प्रीसेट](../guides/presets)। कम से कम एक योग्य प्रदाता रखें। |
| `X-LLMGateway-<Key>` हेडर | `X-Phaseo-Metadata` [लेबल](../guides/request-labels), अधिकतम 32। |
| सत्र हेडर (`x-session-id`) | `session_id` बॉडी फ़ील्ड; Phaseo सत्र हेडर को अनदेखा करता है। |
| `X-Source` | `HTTP-Referer` या `X-App-Name`। देखें [ऐप एट्रिब्यूशन](../guides/app-attribution)। |
| प्रतिक्रिया कैशिंग | कोई प्रतिक्रिया कैश नहीं। |
| प्रदाता कुंजियां | BYOK (`phaseo byok create` या `POST /v1/byok`), या Phaseo क्रेडिट। क्रेडिट पर फ़ॉलबैक `byok_fallback_enabled` वर्कस्पेस सेटिंग है। |
| अनुरोध लॉग | अनुरोध लॉग, ऑब्ज़र्वेबिलिटी गंतव्य, और `GET /v1/generations?id=<request_id>`। `replay_supported` के `true` होने पर, विफल अनुरोध को उसके `replay_request` पेलोड से रीप्ले करें। |

## टेस्ट करें और रोलआउट करें

अपने गोल्डन प्रॉम्प्ट दोनों गेटवे पर चलाएं और गुणवत्ता, लेटेंसी और लागत की तुलना करें। पहले एंडपॉइंट जांचें:

```bash
curl -s "https://api.phaseo.app/v1/health"
curl -s "https://api.phaseo.app/v1/models?format=openai" -H "Authorization: Bearer $PHASEO_API_KEY"
```

ट्रैफ़िक बदलने से पहले:

- `PHASEO_API_KEY` हर एनवायरनमेंट में सेट है;
- हर प्रोडक्शन मॉडल ID मैप की गई है और सूची में है;
- स्टेजिंग में एक नॉन-स्ट्रीमिंग और एक स्ट्रीमिंग अनुरोध पास होता है;
- अमान्य-कुंजी और अमान्य-मॉडल त्रुटियां संभाली जाती हैं; उनकी बॉडी LLM Gateway से अलग हो सकती है;
- स्टेजिंग का कोई विफल अनुरोध `GET /v1/generations` से वापस पाया जा सकता है;
- साझा प्रॉम्प्ट और रूटिंग डिफ़ॉल्ट वहीं प्रीसेट में हैं जहां उन्हें होना चाहिए।

कैनरी फ़्लैग के पीछे रिलीज़ करें, स्थिर होने पर ट्रैफ़िक के छोटे हिस्से से पूरे ट्रैफ़िक तक जाएं, और पुराना कॉन्फ़िगरेशन हटाने से पहले कम से कम एक रिलीज़ चक्र तक प्रोडक्शन मेट्रिक्स पर नज़र रखें।
