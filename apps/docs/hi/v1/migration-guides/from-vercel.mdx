AI SDK कोड में `@ai-sdk/gateway` की जगह `@phaseo/ai-sdk-provider` लगाएं और हर मॉडल ID को `phaseo(...)` में लपेटें। OpenAI-संगत क्लाइंट में बेस URL और कुंजी बदलें। आपका जेनरेशन तर्क वैसा ही रहता है।

| सेटिंग | Vercel AI Gateway | Phaseo |
| --- | --- | --- |
| बेस URL | `https://ai-gateway.vercel.sh/v1` | `https://api.phaseo.app/v1` |
| API कुंजी | `AI_GATEWAY_API_KEY` या Vercel OIDC | `PHASEO_API_KEY`, सर्वर-साइड सीक्रेट के रूप में |
| AI SDK प्रदाता | `@ai-sdk/gateway`, या सादे स्ट्रिंग मॉडल | `@phaseo/ai-sdk-provider` |
| रूटिंग विकल्प | `providerOptions.gateway` | `providerOptions.phaseo` |

## प्रदाता बदलें

<CodeGroup>
```typescript AI SDK
import { generateText } from "ai";
// पहले: import { gateway } from "@ai-sdk/gateway";
import { phaseo } from "@phaseo/ai-sdk-provider";

const { text } = await generateText({
  // पहले: model: gateway("openai/gpt-4.1-mini"),
  model: phaseo("openai/gpt-4.1-mini"),
  prompt: "Generate a migration checklist.",
});
```

```typescript OpenAI SDK
import OpenAI from "openai";

// पहले:
// new OpenAI({ apiKey: process.env.AI_GATEWAY_API_KEY, baseURL: "https://ai-gateway.vercel.sh/v1" });
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});
```

```bash cURL
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role":"user","content":"Hello"}]
  }'
```
</CodeGroup>

डिफ़ॉल्ट `phaseo` एक्सपोर्ट मॉड्यूल इम्पोर्ट होते समय एक बार `PHASEO_API_KEY` पढ़ता है और `https://api.phaseo.app/v1` उपयोग करता है। अगर वेरिएबल इम्पोर्ट के बाद सेट होता है, जैसा कुछ सर्वरलेस और टेस्ट सेटअप में होता है, तो हर कॉल कुंजी-गायब त्रुटि देती है; इसके बजाय हैंडलर के अंदर `createPhaseo({ apiKey, baseURL, headers })` कॉल करें।

अपने `ai` के मुख्य संस्करण से मेल खाती प्रदाता लाइन इंस्टॉल करें: AI SDK 7 के लिए `@phaseo/ai-sdk-provider`, AI SDK 6 के लिए `@phaseo/ai-sdk-provider@ai-sdk-v6`, और AI SDK 5 के लिए `@phaseo/ai-sdk-provider@ai-sdk-v5`।

AI SDK डिफ़ॉल्ट रूप से सादे स्ट्रिंग मॉडल (`model: "openai/gpt-4.1-mini"`) Vercel के गेटवे से भेजता है, इसलिए छूटा हुआ कोई सादा स्ट्रिंग मॉडल उसी को कॉल करता रहता है। साझा मॉडल फ़ैक्टरी एक बार बदलें, फिर AI SDK कॉल में `model: "` खोजें। `ai-gateway.vercel.sh` पर पॉइंट किए गए Anthropic SDK क्लाइंट [Anthropic SDK से माइग्रेट करना](./from-anthropic) वाले सेटअप पर जाते हैं।

## गेटवे विकल्प मैप करें

`providerOptions.phaseo` अनुरोध बॉडी में मर्ज होता है। बचा हुआ `providerOptions.gateway` बिना त्रुटि के अनदेखा हो जाता है।

| Vercel AI Gateway | Phaseo पर |
| --- | --- |
| `providerOptions.gateway.order`, `.only` | `providerOptions: { phaseo: { provider: { order, only } } }`, या `phaseo("@slug")` के रूप में कॉल किया गया [प्रीसेट](../guides/presets)। |
| `providerOptions.gateway.models` | `providerOptions: { phaseo: { models: [...] } }`, या डायनामिक रूट में फ़ॉलबैक। |
| `providerOptions.gateway.sort` (`cost`, `ttft`, `tps`) | `provider.sort` (`price`, `latency`, `throughput`)। |
| `providerOptions.gateway.zeroDataRetention` | `provider.require_zero_data_retention`, जो रूटिंग को ZDR प्रदाताओं तक सीमित करता है। |
| `providerOptions.gateway.user`, `.tags` | `user` और `X-Phaseo-Metadata` [लेबल](../guides/request-labels)। |
| अनुरोध-स्तर के `byok` क्रेडेंशियल | कोई समकक्ष नहीं। `phaseo byok create` से वर्कस्पेस में प्रदाता कुंजियां जोड़ें। |
| टेक्स्ट, स्ट्रीमिंग, टूल, संरचित आउटपुट, एम्बेडिंग, इमेज, ट्रांसक्रिप्शन, स्पीच | प्रदाता द्वारा समर्थित; क्षमताएं फिर भी मॉडल पर निर्भर करती हैं। |
| रीरैंकिंग | AI SDK 6 और 7 लाइन पर `phaseo.rerankingModel(id)`। |
| प्रबंधित फ़ाइल संदर्भ, प्रदाता द्वारा चलाए जाने वाले टूल | समर्थित नहीं। असमर्थित हिस्से हटाए नहीं जाते, त्रुटि के साथ विफल होते हैं। |
| गेटवे उपयोग डैशबोर्ड | Phaseo अनुरोध लॉग और `GET /v1/generations?id=<request_id>`। परिणामों के प्रदाता मेटाडेटा में अनुरोध ID शामिल होती है। |

## टेस्ट करें और रोलआउट करें

वही प्रॉम्प्ट सेट दोनों पथों से चलाएं और लेटेंसी, आउटपुट फ़ॉर्मेट और टोकन उपयोग की तुलना करें। ट्रैफ़िक बढ़ाने से पहले:

- `PHASEO_API_KEY` हर उस रनटाइम में सेट है जिसमें गेटवे कुंजी थी, जिसमें एज, सर्वर और प्रीव्यू डिप्लॉयमेंट शामिल हैं;
- मुख्य टेक्स्ट-जेनरेशन पथ और एक स्ट्रीमिंग टेस्ट स्टेजिंग में बिना बदलाव के पास होते हैं;
- ऐप उपयोग करता हो तो टूल कॉल और संरचित आउटपुट पास होते हैं;
- ऐप्लिकेशन-स्तर की त्रुटि मैपिंग अब भी काम करती है;
- स्टेजिंग का कोई विफल अनुरोध ढूंढा जा सकता है और, `replay_supported` के `true` होने पर, `GET /v1/generations?id=<request_id>` से रीप्ले किया जा सकता है।

फ़ीचर फ़्लैग या प्रतिशत रोलआउट के पीछे शिप करें, आंतरिक ट्रैफ़िक से शुरू करके। लेटेंसी, त्रुटि दर, और टोकन व लागत में बदलाव पर नज़र रखें, और कम से कम एक रिलीज़ तक पुराना प्रदाता उपलब्ध रखें, ताकि रोलबैक के लिए कोड बदलने की ज़रूरत न पड़े।

```bash
curl -s "https://api.phaseo.app/v1/health"
curl -s "https://api.phaseo.app/v1/models?format=openai" -H "Authorization: Bearer $PHASEO_API_KEY"
```

प्रदाता के बारे में और जानने के लिए [AI SDK](../guides/integrations/ai-sdk) देखें।
