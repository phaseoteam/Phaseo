बेस URL को `https://api.phaseo.app/v1` और कुंजी को `PHASEO_API_KEY` में बदलें। अनुरोध पेलोड, `Authorization: Bearer` हेडर, `provider` ऑब्जेक्ट और `models` फ़ॉलबैक ऐरे काम करते रहते हैं; मॉडल ID और नीचे की तालिका के कुछ फ़ील्ड जांचें।

| सेटिंग | OpenRouter | Phaseo |
| --- | --- | --- |
| बेस URL | `https://openrouter.ai/api/v1` | `https://api.phaseo.app/v1` |
| API कुंजी | `OPENROUTER_API_KEY` (`sk-or-v1-…`) | `PHASEO_API_KEY` |
| प्रमाणीकरण | `Authorization: Bearer <key>` | अपरिवर्तित |
| अनुरोध पेलोड | OpenAI-संगत | अपरिवर्तित |
| मॉडल ID | `<org>/<model>` | `<org>/<model>`; ज़्यादातर मेल खाती हैं, कुछ org अलग हैं |
| एट्रिब्यूशन हेडर | `HTTP-Referer`, `X-Title` | अपरिवर्तित; स्थिर समूहन के लिए `X-App-Id` जोड़ें |

## क्लाइंट बदलें

<CodeGroup>
```typescript पहले
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.OPENROUTER_API_KEY,
  baseURL: "https://openrouter.ai/api/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Summarize our migration plan." }],
});
```

```typescript बाद में
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Summarize our migration plan." }],
});
```

```bash cURL
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role":"user","content":"Say hello"}]
  }'
```
</CodeGroup>

पहले चरण में पेलोड अपरिवर्तित रखें और ऑप्टिमाइज़ करने से पहले समानता हासिल करें। कोड, CI और होस्टिंग सेटिंग से `OPENROUTER_BASE_URL` और पुरानी कुंजी हटाएं। `@openrouter/ai-sdk-provider` बन जाता है `@phaseo/ai-sdk-provider` (देखें [Vercel AI Gateway से माइग्रेट करना](./from-vercel)); OpenRouter के अपने SDK (`@openrouter/sdk`, PyPI पर `openrouter`) में सिर्फ़ नया बेस URL नहीं, क्लाइंट बदलना पड़ता है।

## मॉडल ID जांचें

ज़्यादातर ID मेल खाती हैं, लेकिन कुछ org अलग हैं: `x-ai/` है `spacex-ai/`, `meta-llama/` है `meta/`, और `mistralai/` है `mistral/`। Phaseo की ID सूचीबद्ध करें और हर प्रोडक्शन मॉडल को उनसे जांचें:

```bash
curl -s "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY" | jq -r '.data[].id'
```

डिफ़ॉल्ट सूची में सिर्फ़ वे मॉडल होते हैं जिन्हें आप अभी कॉल कर सकते हैं; निष्क्रिय या जल्द आने वाले मॉडल देखने के लिए `availability=all` जोड़ें। `format=openai` के बिना प्रतिक्रिया Phaseo की पेज-वार `models` सूची होती है, जिसमें कोई `data` ऐरे नहीं होता।

## अनुरोध फ़ील्ड मैप करें

| OpenRouter | Phaseo पर |
| --- | --- |
| `provider.order`, `only`, `ignore`, `allow_fallbacks`, `require_parameters`, `max_price` | वही फ़ील्ड। एंडपॉइंट स्लग नहीं, बेस प्रदाता ID उपयोग करें। |
| `provider.sort` | वही फ़ील्ड: `price`, `latency` या `throughput`। |
| `provider.zdr` | `provider.require_zero_data_retention` के उपनाम के रूप में स्वीकार है। |
| `provider.data_collection: "deny"` | `400` लौटाता है। इसके बजाय `zdr: true` उपयोग करें। |
| `models` फ़ॉलबैक ऐरे | वही, 1 से 25 एंट्री। `model` ज़रूरी है, इसलिए `models[0]` को उसमें ले जाएं। |
| `:nitro` प्रत्यय | वही (थ्रूपुट)। Phaseo में `:cheap` और `:fast` भी हैं; `:floor` बन जाता है `:cheap`। `:online` और `:thinking` हटाएं और उनकी जगह वेब खोज और `reasoning` उपयोग करें। |
| `openrouter/auto`, `openrouter/free` | `phaseo/auto` ([ऑटो रूटिंग](../guides/auto-routing), अल्फ़ा, `models` के साथ नहीं मिलाया जा सकता) और `phaseo/free`। |
| `plugins` `web`, `web-fetch`, `response-healing` | वही प्लगइन ID। दूसरे प्लगइन, जैसे `file-parser`, `400` लौटाते हैं। |
| `transforms`, `usage: { include: true }` | स्वीकार नहीं। इन्हें हटाएं; उपयोग और लागत हमेशा लौटाए जाते हैं। |
| `X-OpenRouter-Title` | नाम बदलकर `X-Title` करें। देखें [ऐप एट्रिब्यूशन](../guides/app-attribution)। |
| प्रीसेट `@preset/<slug>` | इन्हें [प्रीसेट](../guides/presets) के रूप में दोबारा बनाएं और `"model": "@slug"` से कॉल करें। |
| प्रतिक्रियाओं में `usage.cost`, `reasoning_details`, `provider` | लौटाए जाते हैं। `native_finish_reason` और `is_byok` नहीं; अगर कॉलर इन्हें पढ़ते हैं तो इन्हें एक परत में सामान्य करें। |

Phaseo में `provider.required_execution_region` और `provider.required_data_region` भी हैं, जिनका OpenRouter में कोई समकक्ष नहीं है। पूरे अनुरोधों के लिए [प्रदाताओं को पिन करें या अनदेखा करें](../cookbook/pin-or-ignore-providers-per-request) और [सिर्फ़ EU या ZDR-सक्षम प्रदाताओं पर रूट करें](../cookbook/route-only-to-eu-or-zdr-providers) देखें।

बचे हुए सिर्फ़-OpenRouter फ़ील्ड को हर कॉल साइट पर नहीं, एक एडैप्टर में रखें, ताकि रोलबैक बेस URL और कुंजी का बदलाव ही रहे।

## कटओवर से पहले सत्यापित करें

इन्हें Phaseo पर चलाएं, फिर यही जांच अपने ऐप के अपने क्लाइंट पथ से करें:

```bash
curl -s "https://api.phaseo.app/v1/health"

curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"openai/gpt-6-astra","messages":[{"role":"user","content":"Say hello"}]}'

# स्ट्रीमिंग
curl -N "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"openai/gpt-6-astra","stream":true,"messages":[{"role":"user","content":"Reply with: stream works"}]}'

# अमान्य मॉडल: ऐप को क्रेडेंशियल उजागर किए बिना त्रुटि संभालनी चाहिए
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"invalid/migration-test","messages":[{"role":"user","content":"test"}]}'
```

अर्थपूर्ण ट्रैफ़िक बदलने से पहले पुष्टि करें कि:

- हर एनवायरनमेंट में `OPENROUTER_API_KEY` की जगह `PHASEO_API_KEY` है;
- हर प्रोडक्शन मॉडल ID `GET /v1/models?format=openai` में है;
- प्रोडक्शन वाले ही क्लाइंट पथ से, `/v1/chat/completions` या `/v1/responses` पर एक नॉन-स्ट्रीमिंग और एक स्ट्रीमिंग अनुरोध पास होता है;
- असली प्रॉम्प्ट के साथ टूल कॉलिंग और संरचित आउटपुट फ़्लो पास होते हैं;
- अमान्य-कुंजी और अमान्य-मॉडल विफलताएं संभाली जाती हैं;
- विफल अनुरोध को `GET /v1/generations?id=<request_id>` से देखा जा सकता है और, `replay_supported` के `true` होने पर, `replay_request` से रीप्ले किया जा सकता है;
- सिर्फ़-OpenRouter हेडर और प्रतिक्रिया फ़ील्ड हटाए या सामान्य किए गए हैं, और साझा डिफ़ॉल्ट प्रीसेट में हैं।

## रोलआउट करें

1. आंतरिक ट्रैफ़िक से शुरू करें।
2. प्रोडक्शन ट्रैफ़िक का 5-10% बदलें और गुणवत्ता, लेटेंसी और लागत की तुलना करें।
3. समानता की पुष्टि होने पर 100% तक बढ़ाएं।
4. कटओवर स्थिर होने तक रोलबैक को बेस URL और कुंजी के स्विच के रूप में रखें।

## माइग्रेशन किसी कोडिंग एजेंट को सौंपें

एजेंट को यह सीमित क्रम दें, या [OpenRouter से Phaseo माइग्रेशन स्किल](https://github.com/phaseoteam/Phaseo/tree/main/.agents/skills/openrouter-to-phaseo-migration) इंस्टॉल करें, जिसमें यही सूची, मैपिंग, सत्यापन और रोलबैक चरण पैक हैं:

1. रनटाइम कोड और डिप्लॉयमेंट कॉन्फ़िग में `openrouter.ai`, `OPENROUTER_API_KEY`, `sk-or-v1`, `HTTP-Referer` और `X-Title` खोजें।
2. सोर्स कंट्रोल में कोई सीक्रेट मान जोड़े बिना क्लाइंट सीमा को `https://api.phaseo.app/v1` और `PHASEO_API_KEY` पर बदलें।
3. `GET /v1/models?format=openai` क्वेरी करें और हर पुरानी-से-नई मॉडल मैपिंग दर्ज करें।
4. सिर्फ़-OpenRouter रूटिंग विकल्पों या प्रतिक्रिया फ़ील्ड को एक संगतता मॉड्यूल में अनुकूलित करें।
5. ऊपर की हेल्थ, नॉन-स्ट्रीमिंग, स्ट्रीमिंग और विफलता-पथ जांच चलाएं।
6. बदली गई फ़ाइलें, सीक्रेट-नाम में बदलाव, मॉडल मैपिंग, टेस्ट के प्रमाण, समानता की कमियां और रोलबैक स्विच की रिपोर्ट दें।

निर्देशित संस्करण के लिए [इंटरैक्टिव OpenRouter माइग्रेशन गाइड](https://phaseo.app/migrate/openrouter) खोलें, देखें कि दोनों की [तुलना](https://phaseo.app/compare/openrouter) कैसी है, या [माइग्रेशन में मुफ़्त मदद लें](https://phaseo.app/contact)।
