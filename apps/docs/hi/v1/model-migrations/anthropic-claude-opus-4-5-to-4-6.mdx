मॉडल को `anthropic/claude-opus-4.6` में बदलें, असिस्टेंट प्रीफ़िल हटाएं, और संरचित आउटपुट को `output_config.format` पर ले जाएं। ये अनुरोध-आकार के बदलाव हैं: पुराने Opus 4.5 पैटर्न छोड़ दिए जाएं तो `400` के साथ विफल होते हैं।

| | Claude Opus 4.5 | Claude Opus 4.6 |
| --- | --- | --- |
| Phaseo मॉडल ID | `anthropic/claude-opus-4.5` | `anthropic/claude-opus-4.6` |
| कॉन्टेक्स्ट विंडो | 200K टोकन | 1M टोकन |
| अधिकतम आउटपुट | 64K टोकन | 128K टोकन |
| असिस्टेंट प्रीफ़िल | समर्थित | `400` लौटाता है |
| संरचित आउटपुट | `output_format` | `output_config.format` |
| थिंकिंग | `budget_tokens` | एडैप्टिव, `output_config.effort` से नियंत्रित |
| `interleaved-thinking-2025-05-14` बीटा | ज़रूरी | ज़रूरी नहीं |

## अनुरोध अपडेट करें

**1. असिस्टेंट प्रीफ़िल हटाएं।** अगर आप JSON या कोई प्रीफ़िक्स ज़बरदस्ती लाने के लिए असिस्टेंट टर्न पहले से भरते हैं, तो Opus 4.6 `400` लौटाता है। इसके बजाय ज़्यादा स्पष्ट सिस्टम निर्देश, प्रॉम्प्ट में उदाहरण, या संरचित आउटपुट उपयोग करें।

**2. संरचित आउटपुट ले जाएं** `output_format` से `output_config.format` पर, और अपने स्कीमा और पार्सर टेस्ट दोबारा चलाएं:

```json
{
  "model": "anthropic/claude-opus-4.6",
  "max_tokens": 1024,
  "messages": [{ "role": "user", "content": "Extract the invoice fields." }],
  "output_config": {
    "format": { "type": "json_schema", "schema": { "type": "object", "properties": { "total": { "type": "number" } } } }
  }
}
```

`/v1/chat/completions` और `/v1/responses` पर `response_format` ही उपयोग करते रहें।

**3. थिंकिंग को एडैप्टिव पर बदलें।** जब तक अनुरोध न मांगे, Opus 4.6 थिंक नहीं करता। Phaseo पर, टोकन बजट के बिना `reasoning.effort` या `reasoning.enabled: true` एडैप्टिव थिंकिंग चालू करता है, और effort `output_config.effort` बन जाता है। Opus 4.6 `xhigh` को छोड़कर हर effort लेवल लेता है; `xhigh` को Phaseo `max` के रूप में भेजता है। थिंकिंग चालू रहने पर Phaseo `temperature` और `top_k` को, और 0.95 से कम `top_p` को छोड़ देता है।

**4. पुराने बीटा हेडर हटाएं** SDK रैपर, मिडलवेयर और प्रीसेट से। Phaseo `anthropic-beta` हेडर आगे नहीं भेजता, इसलिए अब इनका कोई असर नहीं होता।

## क्या टेस्ट करें

- **प्रॉम्प्ट:** लंबे कोडिंग और रीफ़ैक्टर प्रॉम्प्ट, बहु-चरणीय रिसर्च और दस्तावेज़ वर्कफ़्लो, प्रीफ़िल पर निर्भर प्रॉम्प्ट, और अगर आप 1M विंडो उपयोग करेंगे तो लंबे कॉन्टेक्स्ट वाले कार्य।
- **अनुबंध और टूल:** `output_config.format` पर जाने के बाद स्कीमा पास दर, बहु-चरणीय एजेंट कार्यों पर टूल-कॉल आर्गुमेंट, मॉडल के मना करने या आउटपुट का फ़ॉर्मेट बदलने पर पुनः प्रयास, और कोड-रिव्यू व डीबगिंग वर्कफ़्लो।
- **संचालन:** थिंकिंग चालू होने पर माध्य और p95 लेटेंसी, लंबे रन पर टोकन उपयोग, बड़े कॉन्टेक्स्ट वाले कार्यों पर टाइमआउट दर, और आपके मूल्यांकन सेट पर Opus 4.5 के मुकाबले सफलता दर।

## रोलआउट करें

1. कोई भी ट्रैफ़िक बदलने से पहले प्रीफ़िल हटाएं और संरचित आउटपुट माइग्रेट करें।
2. आपके लिए अहम प्रोडक्शन प्रॉम्प्ट पर Opus 4.6 को शैडो करें।
3. Opus 4.5 को `models` में फ़ॉलबैक रखकर कैनरी चलाएं।
4. स्कीमा पास दर, लेटेंसी और कार्य-पूर्णता बनी रहने पर प्रमोट करें।
