Claude Opus 4.1 ट्रैफ़िक को `anthropic/claude-opus-4.8` पर ले जाएं: मॉडल ID बदलें, सैंपलिंग पैरामीटर हटाएं, और थिंकिंग बजट की जगह effort लेवल दें।

Anthropic ने Opus 4.1 को 5 जून, 2026 को डेप्रिकेट किया और 5 अगस्त, 2026 को रिटायर किया। जब तक कोई प्रदाता `anthropic/claude-opus-4.1` सर्व करता है, Phaseo उसे सर्व करता रहता है, और जब कोई नहीं करता, तो वह उन अनुरोधों को Opus 4.8 पर रूट करता है (देखें [मॉडल डेप्रिकेशन और रिटायरमेंट](../guides/model-retirement))। ऐसा होने से पहले माइग्रेट करें, ताकि बदलाव अपने आप होने के बजाय टेस्ट किया हुआ हो।

Anthropic का मार्गदर्शन संचयी है: Opus 4.7 के अनुरोध-आकार बदलाव लागू करें, फिर Opus 4.8 के व्यवहार बदलावों की समीक्षा करें।

| | Claude Opus 4.1 | Claude Opus 4.8 |
| --- | --- | --- |
| Phaseo मॉडल ID | `anthropic/claude-opus-4.1` | `anthropic/claude-opus-4.8` |
| कॉन्टेक्स्ट विंडो | 200K टोकन | 1M टोकन |
| अधिकतम आउटपुट | 32K टोकन | 128K टोकन |
| `temperature`, `top_p`, `top_k` | भेजे जाते हैं | Phaseo इन्हें छोड़ देता है |
| थिंकिंग | `budget_tokens` | एडैप्टिव, effort से नियंत्रित (डिफ़ॉल्ट `high`) |
| बातचीत के बीच सिस्टम संदेश | नहीं | हां |

## अनुरोध अपडेट करें

**1. मॉडल ID बदलें** `anthropic/claude-opus-4.8` पर।

**2. सैंपलिंग पैरामीटर हटाएं।** Anthropic, Opus 4.7 और बाद के मॉडल पर गैर-डिफ़ॉल्ट `temperature`, `top_p` और `top_k` को `400` के साथ अस्वीकार करता है। Phaseo विफल होने के बजाय इन्हें छोड़ देता है, इसलिए अब इनका कोई असर नहीं होता; इसके बजाय निर्देशों से ट्यून करें।

**3. थिंकिंग बजट की जगह effort लेवल दें।** Phaseo, Opus 4.8 को `budget_tokens` आगे नहीं भेजता। कोई भी रीज़निंग सेटिंग `thinking: {"type": "adaptive", "display": "summarized"}` के रूप में भेजी जाती है, और `reasoning.effort` (या `/v1/messages` पर `output_config.effort`) गहराई तय करता है:

```json
{
  "model": "anthropic/claude-opus-4.8",
  "max_tokens": 4096,
  "thinking": { "type": "adaptive" },
  "output_config": { "effort": "high" },
  "messages": [{ "role": "user", "content": "Plan the schema migration." }]
}
```

कोई रीज़निंग सेटिंग न हो, तो Opus 4.8 थिंक नहीं करता। `reasoning.effort: "none"` `thinking: {"type": "disabled"}` भेजता है।

**4. effort और लंबे कॉन्टेक्स्ट की नई बेसलाइन बनाएं।** Opus 4.8 का डिफ़ॉल्ट effort `high` है और इसकी कॉन्टेक्स्ट विंडो Opus 4.1 से बहुत बड़ी है। लेटेंसी बजट, टोकन उपयोग, प्रॉम्प्ट कैशिंग, और लंबे दस्तावेज़ों व लंबे एजेंट ट्रेस दोबारा टेस्ट करें। Microsoft Foundry पर, Anthropic ने लॉन्च के समय Opus 4.8 के लिए 200K कॉन्टेक्स्ट विंडो दर्ज की है।

**5. लंबी बातचीत में निर्देश अपडेट सरल बनाएं।** Opus 4.8 बातचीत के बीच `role: "system"` संदेश स्वीकार करता है। अगर आपका एजेंट लूप हर टर्न पर पूरा सिस्टम प्रॉम्प्ट दोबारा लिखता है, तो इसके बजाय एक सिस्टम संदेश जोड़ें और ज़्यादा कैश हिट पाएं।

## क्या टेस्ट करें

- वे अनुरोध जो अब भी `temperature`, `top_p` या `top_k` भेजते हैं, क्योंकि अब इनका असर खत्म हो गया है;
- वे थिंकिंग रूट जो `budget_tokens` पर निर्भर थे;
- लंबी अवधि के एजेंट और टूल वर्कफ़्लो;
- हर `effort` लेवल पर स्कीमा-संवेदनशील आउटपुट;
- आपकी सबसे ज़्यादा मात्रा वाली Opus 4.1 प्रॉम्प्ट श्रेणियों पर टोकन लागत और लेटेंसी।

## रोलआउट करें

1. ट्रैफ़िक बदलने से पहले सैंपलिंग पैरामीटर और थिंकिंग बजट हटाएं।
2. प्रोडक्शन जैसे प्रॉम्प्ट और टूल फ़्लो पर Opus 4.8 को शैडो करें।
3. जब तक प्रदाता Opus 4.1 सर्व करते हैं, उसे `models` में फ़ॉलबैक रखकर कैनरी चलाएं।
4. लेटेंसी, लागत और कार्य-पूर्णता में बदलाव लक्ष्य के भीतर होने पर प्रमोट करें।
