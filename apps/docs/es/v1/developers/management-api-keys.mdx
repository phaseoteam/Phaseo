Crea una clave de administración para llamar a las API de administración de Phaseo desde tus propios servidores: créditos, actividad, espacios de trabajo, claves, preajustes, ajustes y guardrails. Las claves de administración no pueden enviar solicitudes de inferencia.

```bash
phaseo management-keys create --name <name> --template read-only --json
```

También puedes crearla en el panel, en **Ajustes → Claves de administración**. El secreto solo se muestra una vez, así que guárdalo en tu gestor de secretos. Envíalo solo desde código del lado del servidor, a la misma URL base que el Gateway (`https://api.phaseo.app/v1`):

```http
Authorization: Bearer phaseo_v1_mk_<kid>_<secret>
```

## Claves de administración, claves de API y tokens OAuth

| Credencial | Formato | Úsala para | Limitada por |
| --- | --- | --- | --- |
| Clave de API de Gateway | `phaseo_v1_sk_<kid>_<secret>` | Solicitudes de modelos y generación | Política de enrutamiento, presupuestos, límites y guardrails asociados |
| Clave de API de administración | `phaseo_v1_mk_<kid>_<secret>` | Solicitudes de administración | Sus capacidades y tu rol en el espacio de trabajo |
| Token de acceso OAuth | | Administración en nombre de un usuario | Los ámbitos OAuth aprobados y el rol del usuario en el espacio de trabajo |

Las rutas de administración solo aceptan claves de administración (o tokens OAuth); una clave de API de Gateway no puede llamarlas.

Los [guardrails](../cookbook/guardrails-for-api-keys.mdx) son un control distinto: se aplican a las claves de API de Gateway y gobiernan el tráfico de inferencia, como las restricciones de enrutamiento, los presupuestos, la gestión de la inyección de instrucciones y las reglas sobre información sensible. Las capacidades de una clave de administración determinan a qué API de administración puede llamar.

## Elige un nivel de acceso

Cada plantilla se expande a una lista explícita de capacidades al crear la clave. Phaseo nunca almacena un comodín como `all`, así que una clave nunca obtiene un permiso que se añada más adelante.

| Plantilla | `--template` | Concede |
| --- | --- | --- |
| **Read** | `read-only` | Todas las capacidades `*:read` actuales |
| **Write** | `read-write` | Todas las capacidades `*:read` y `*:write` actuales, sin eliminación |
| **All** | `full-control` | Todas las capacidades actuales de lectura, escritura y eliminación |

Ninguna plantilla incluye `billing:write`, que inicia recargas de créditos; solicítala explícitamente con `--scopes`. Usa **All** solo para automatizaciones administrativas de confianza.

Para conceder menos, pasa las capacidades que necesites con `--scopes scope_a,scope_b`:

| Área | Lectura | Escritura | Eliminación |
| --- | --- | --- | --- |
| Identidad y catálogo | `me:read`, `models:read`, `providers:read`, `pricing:read` | | |
| Uso y observabilidad | `credits:read`, `activity:read`, `analytics:read`, `generations:read`, `feedback:read` | `feedback:write` | |
| Facturación | | `billing:write` (opcional) | |
| Espacios de trabajo | `workspaces:read` | `workspaces:write` | `workspaces:delete` |
| Claves de API de Gateway | `keys:read` | `keys:write` | `keys:delete` |
| Claves de API de administración | `management_keys:read` | `management_keys:write` | `management_keys:delete` |
| Preajustes | `presets:read` | `presets:write` | `presets:delete` |
| Ajustes | `settings:read` | `settings:write` | |
| Credenciales de proveedor | `provider_credentials:read` | `provider_credentials:write` | `provider_credentials:delete` |
| Modelos privados | `private_models:read` | `private_models:write` | `private_models:delete` |
| Guardrails | `guardrails:read` | `guardrails:write` | `guardrails:delete` |
| Presupuestos | `budgets:read` | `budgets:write` | `budgets:delete` |
| Límites de frecuencia | `rate_limits:read` | `rate_limits:write` | `rate_limits:delete` |
| Clasificadores | `classifiers:read` | `classifiers:write` | `classifiers:delete` |
| Reglas de gasto | `spend_rules:read` | `spend_rules:write` | `spend_rules:delete` |
| Clientes OAuth | `oauth_clients:read` | `oauth_clients:write` | `oauth_clients:delete` |

## Las capacidades no sustituyen a los roles del espacio de trabajo

Phaseo comprueba dos cosas en cada llamada: que la clave tenga la capacidad y que la clave o el usuario OAuth pertenezca al espacio de trabajo con el rol que exige la acción. Por ejemplo, `keys:write` permite gestionar claves, pero la comprobación del rol sigue decidiendo si quien llama puede gestionar claves en ese espacio de trabajo. Una clave no puede usar una capacidad para acceder a otro espacio de trabajo ni para saltarse las comprobaciones de propietario y administrador.

## Mantén las claves seguras

- Mantén las claves de administración fuera de los navegadores, los registros de escritorio, el control de versiones y los chats.
- Usa una clave por integración, con la plantilla más restrictiva que funcione.
- Define una caducidad cuando la integración no necesite acceso indefinido.
- Pausa o elimina de inmediato las claves que no uses.
- Rota una clave filtrada antes de seguir investigando.
