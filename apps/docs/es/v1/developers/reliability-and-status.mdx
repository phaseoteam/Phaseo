Consulta la [página de estado](https://status.phaseo.app) y `GET /v1/health` para saber si Phaseo funciona correctamente, `GET /v1/models` para saber si un modelo se puede enrutar ahora y tu propia prueba para saber si una ruta cumple tu objetivo de fiabilidad.

## Comprueba el estado actual del servicio

1. Abre la [página de estado de Phaseo](https://status.phaseo.app) para ver los incidentes actuales y su historial.
2. Llama a `GET /v1/health` para hacer una comprobación mínima del estado del Gateway.
3. Si falla una sola solicitud, guarda su ID y revisa su registro de actividad o de generación antes de suponer que todo el servicio está caído.

```bash
curl https://api.phaseo.app/v1/health
```

```json
{
  "status": "ok"
}
```

<Note>
La página pública de estado informa sobre el estado del servicio. Actualmente, Phaseo no ofrece un SLA público contractual de disponibilidad.
</Note>

## Confirma que un modelo se puede enrutar

El catálogo de Phaseo incluye más modelos de los que el Gateway puede enrutar: que un modelo aparezca en el catálogo significa que Phaseo lo sigue, no que exista una ruta pública. `GET /v1/models` devuelve por defecto solo los modelos que se pueden enrutar en este momento:

```bash
curl https://api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

Añade `availability=all` para ver también las asignaciones próximas e inactivas. Envía tráfico de producción a una fila de proveedor solo cuando su `availability_status` sea `active` e `is_active_gateway` sea `true`. Consulta [Estados del proveedor y de Phaseo](../guides/provider-statuses.mdx) para saber qué significan los iconos de estado en las páginas de modelos.

| Estado | Significado |
| --- | --- |
| `active` | Hay al menos una ruta pública de Gateway disponible ahora. |
| `coming_soon` | Phaseo sigue una ruta planificada o en versión preliminar, pero no se puede enrutar públicamente. |
| `inactive` | Una ruta conocida está desactivada, no disponible, caducada o no se puede enrutar por otro motivo. |
| `not_listed` | Actualmente no hay ninguna asignación de proveedor de Gateway para el modelo. |

`active` no garantiza la disponibilidad, el acceso en todas las regiones ni las mismas condiciones comerciales para cada espacio de trabajo.

## Interpreta las métricas de rendimiento

Los datos de rendimiento de Phaseo resumen solicitudes reales enrutadas a través del Gateway; no son una prueba de laboratorio controlada.

| Métrica | Definición |
| --- | --- |
| TTFT del Gateway | Desde el inicio de la solicitud en el Gateway hasta la primera salida generada con contenido. |
| TTFT del proveedor | Desde el envío al proveedor hasta la primera salida generada con contenido. |
| Duración del proveedor | Desde el envío al proveedor hasta la respuesta final. |
| E2E del Gateway | Desde el inicio de la solicitud en el Gateway hasta su finalización. |
| Sobrecoste de Phaseo | La diferencia no negativa entre el E2E del Gateway y la duración del proveedor. |
| Rendimiento efectivo | Todos los tokens de salida divididos entre la duración total del proveedor. |
| Velocidad de salida | Los tokens de salida posteriores al primero divididos entre el tiempo del proveedor después del TTFT. |

El TTFT y la velocidad de salida requieren una respuesta en streaming cuya primera salida tenga contenido. Una solicitud sin streaming sigue aportando la duración y el rendimiento efectivo, pero no el TTFT.

Interpreta cada métrica junto con su intervalo de tiempo, ruta, región, modo de streaming y percentil. La carga del proveedor, la longitud del prompt, la longitud de la salida, los reintentos y las condiciones de red cambian el resultado.

Para ver las definiciones completas, consulta [Precios y rendimiento](../exploring/pricing-performance) y [Cómo mide Phaseo la latencia y el rendimiento](https://phaseo.app/how-phaseo-measures-latency-throughput).

## Valida con tu carga de trabajo

Las métricas públicas indican una tendencia; no demuestran que una ruta cumpla tu objetivo de producción. Antes de un despliegue, ejecuta una prueba pequeña y reproducible:

1. Elimina los datos sensibles de producción y conserva una mezcla representativa de prompts.
2. Registra el ID del modelo, el endpoint, las restricciones del proveedor, la región, el modo de streaming y la concurrencia.
3. Ejecuta suficientes repeticiones para comparar distribuciones en lugar de una sola solicitud.
4. Registra la tasa de éxito, el TTFT del Gateway, la duración del proveedor, el E2E del Gateway, los tokens de salida y el coste final.
5. Prueba claves no válidas, modelos no válidos, límites de frecuencia y errores de proveedores no disponibles.
6. Guarda los ID de solicitud y el intervalo de tiempo exacto para que otra persona del equipo pueda reproducir el resultado.

No publiques el nombre de un cliente, una cita, un resultado de carga de trabajo ni un porcentaje de fiabilidad sin permiso y sin un método documentado.

## Investiga una solicitud fallida

1. Consulta el [estado del servicio](https://status.phaseo.app).
2. Confirma que el modelo sigue apareciendo en la respuesta predeterminada de [`GET /v1/models`](../api-reference/endpoint/models) y revisa sus [endpoints](../api-reference/endpoint/model-endpoints).
3. Busca el estado HTTP y el código de error en [Errores y depuración](../api-reference/errors).
4. Reintenta las respuestas transitorias `429` y `5xx` con un retroceso exponencial limitado; consulta [Límites de frecuencia](../api-reference/limits.mdx).
5. Guarda el ID de la solicitud cuando contactes con [soporte](https://phaseo.app/help).

Para que las solicitudes sigan funcionando cuando falla un proveedor, configura el [enrutamiento y las alternativas](../guides/routing-and-fallbacks).
