Para correcciones e incorporaciones al catálogo, abre una incidencia con el registro afectado y las fuentes que lo respaldan. Para cambios de código o documentación, envía una solicitud de incorporación al [repositorio de Phaseo](https://github.com/phaseoteam/Phaseo).

## Elige tu contribución

| Cambio | Empieza aquí |
| --- | --- |
| Metadatos, capacidades, disponibilidad o precios de modelos | [Comunicar una actualización de modelo](./editing-a-model.mdx) |
| Datos de empresas u organizaciones de investigación | [Comunicar una actualización de organización](./editing-an-organisation.mdx) |
| Resultados de benchmarks | [Enviar puntuaciones](../research/submitting-scores.mdx) |
| Otras correcciones del catálogo | [Comunicar información incorrecta](https://github.com/phaseoteam/Phaseo/issues/new?template=incorrect-info.yml) |
| Proveedores u otros datos del catálogo que faltan | [Solicitar datos nuevos](https://github.com/phaseoteam/Phaseo/issues/new?template=data-request.yml) |
| Documentación o código | [Flujo de contribución](./how-to-contribute.mdx) y [estructura del repositorio](./repo-structure.mdx) |

## Cómo se publican los informes del catálogo

Los responsables revisan las pruebas de la incidencia y aplican los cambios aprobados mediante el [editor interno](https://phaseo.app/internal/data), exclusivo de administradores. Las actualizaciones de precios de proveedores requieren una revisión explícita antes de publicarse.

La base de datos es la única fuente de los registros del catálogo. El repositorio no contiene JSON del catálogo, así que una solicitud de incorporación no puede cambiar un registro del catálogo.

## Antes de enviar

- Incluye la página o el ID del registro afectado y describe la corrección propuesta.
- Cita fuentes oficiales y distingue los resultados de benchmarks publicados de las mediciones independientes.
- Mantén cada informe o solicitud de incorporación centrado en un solo tema.
- Nunca incluyas credenciales ni datos privados de clientes.
- Sigue el [Código de conducta](../community/code-of-conduct.mdx).

Habla con los responsables antes de implementar cambios grandes de esquema o de funciones. Pide ayuda en [Discord](https://discord.gg/aQyywCvgZ5) si no sabes dónde encaja un cambio.
