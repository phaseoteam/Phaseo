## Crea un agente

Crea un agente a partir de una definición. El límite de pasos de la definición se aplica a cada llamada de ejecución o de continuación.

| Lenguaje | Nombre | Límite de pasos predeterminado |
| --- | --- | --- |
| TypeScript | `createAgent(definition)` | 12 |
| Python | `create_agent(definition)`, a partir de un dict o de un `AgentDefinition` | 12 |
| Go | `CreateAgent(AgentDefinition) *Agent` | 8 |
| C# | `AgentSdk.CreateAgent(AgentDefinition)` | 12 |
| PHP | `AgentSdk::createAgent(AgentDefinition)` | 12 |
| Ruby | `PhaseoAgentSdk.create_agent(definition)`, a partir de un `AgentDefinition` o de campos con palabra clave | 12 |
| Java | `AgentSdk.createAgent(AgentDefinition)` | 12 (un `maxSteps` menor que 1 pasa a ser 12) |
| Rust | `create_agent(AgentDefinition::new(id, model))` | 8 (los valores se ajustan a un mínimo de 1) |

### Campos de la definición

Rust construye la definición con métodos en lugar de campos: `AgentDefinition::new(id, model)` y después `.instructions(text)`, `.tool(tool)` (una vez por herramienta), `.max_steps(limit)`, `.model_retries(count, backoff)` y `.human_review(callback)`. El `AgentDefinition` de Java es un record con constructores de 10, 13 y 19 argumentos.

| Campo | camelCase (TypeScript, PHP, Java) | snake_case (Python, Ruby) | PascalCase (Go, C#) | No disponible en |
| --- | --- | --- | --- | --- |
| ID del agente (obligatorio) | `id` | `id` | `ID` (Go), `Id` (C#) | |
| Modelo o preset | `model`, `preset` | `model`, `preset` | `Model`, `Preset` | Rust no tiene `preset` |
| Lista de modelos (solo se usa el primero, cuando no se establece `model`; sin fallback) | `models` | | | Todos menos TypeScript |
| Instrucciones | `instructions` | `instructions` | `Instructions` | |
| Herramientas | `tools` | `tools` | `Tools` | |
| Herramientas ofrecidas en un paso | `activeTools` | | | Todos menos TypeScript |
| Reescribir el historial antes de cada solicitud al modelo | `prepareMessages` | | | Todos menos TypeScript |
| Límite de pasos y condiciones de parada | `maxSteps`, `stopWhen` | `max_steps`, `stop_when` | `MaxSteps`, `StopWhen` | Rust no tiene `stop_when` |
| Reintento del modelo y concurrencia de herramientas | `modelRetry`, `toolExecution` | `model_retry`, `tool_execution` | `ModelRetry`, `ToolExecution` | Rust no tiene concurrencia de herramientas |

## Ejecuta y continúa

| Propósito | TypeScript | Python | Go | C# | PHP | Ruby | Java | Rust |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Ejecutar | `run(options)` | `run(...)` | `Run(ctx, RunOptions)` | `Run(RunOptions)` | `run(...)` | `run(...)` | `run(RunOptions)` | `run(&mut client, options)`, `run_with_events(&mut client, options, callback)` |
| Ejecutar con streaming | `stream(options)` | `stream(...)` | `Stream(ctx, RunOptions)` | `Stream(RunOptions)` | `stream(...)` | `stream(...)` | `stream(RunOptions)` | Ninguno |
| Continuar | `continueRun(options)` | `continue_run(...)` | `Continue(ctx, ContinueOptions)` | `ContinueRun(ContinueOptions)` | `continueRun(...)`, `continueRunById(...)` | `continue_run(...)` | `continueRun(ContinueOptions)` | `continue_run(&mut client, options)`, `continue_with_events(...)` |
| Continuar con streaming | `continueStream(options)` | `continue_stream(...)` | `ContinueStream(ctx, ContinueOptions)` | `ContinueStream(ContinueOptions)` | `continueStream(...)` | `continue_stream(...)` | `continueStream(ContinueOptions)` | Ninguno |

Ejecutar y continuar devuelven un resultado de ejecución: un `Promise<AgentRunResult>` en TypeScript, `(RunResult, error)` en Go, `Task<RunResult>` en C#, `Result<RunResult, AgentError>` en Rust y el resultado de ejecución directamente en los demás. Los métodos de streaming devuelven un resultado de stream de inmediato.

### Opciones de ejecución

PHP y Ruby las reciben como argumentos con nombre o con palabra clave; el `RunOptions` de Java es un record posicional en el orden `input, client, context, model, preset, maxSteps, modelRetry, toolExecution, onEvent, devtools`, seguido de un `state` opcional.

| Opción | camelCase (TypeScript, PHP, Java) | snake_case (Python, Ruby, Rust) | PascalCase (Go, C#) | No disponible en |
| --- | --- | --- | --- | --- |
| Entrada | `input` | `input` | `Input` | |
| Conversación completa en lugar de la entrada | `messages` | | | Todos menos TypeScript |
| Cliente del modelo | `client` | `client` | `Client` | Rust lo pasa como argumento aparte |
| Contexto de la aplicación | `context` | `context` | `Context` | |
| Sustituciones de modelo, preset y límite de pasos | `model`, `preset`, `maxSteps` | `model`, `preset`, `max_steps` | `Model`, `Preset`, `MaxSteps` | Rust solo tiene `model` y `max_steps` |
| Sustituciones de reintentos y concurrencia de herramientas | `modelRetry`, `toolExecution` | `model_retry`, `tool_execution` | `ModelRetry`, `ToolExecution` | Rust |
| Sustituciones de muestreo | `temperature`, `maxOutputTokens`, `topP` (TypeScript) | | | Todos menos TypeScript |
| Cancelación | `signal` (TypeScript) | | `CancellationToken` (C#) | Go usa `ctx`; los demás cancelan a través del stream |
| Manejador de eventos | `onEvent` | `on_event` | `OnEvent` | Rust usa `run_with_events` |
| Captura local | `devtools` | `devtools` | `Devtools` | Rust |
| Accesor de estado | `state` | `state` | `State` | Rust |
| Añadir mensajes antes de la siguiente solicitud al modelo | `takeMessages` (TypeScript) | | | Todos menos TypeScript |

El `run()` de Python también acepta `stop_when`, pero lo ignora; establece las condiciones de parada en la definición. El `stream()` de PHP y el `stream` de Ruby solo reciben `input`, `client`, `context` y `state`. Rust crea los valores predeterminados con `RunOptions::new(input)`.

### Opciones de continuación

Las opciones de continuación aceptan las sustituciones de ejecución anteriores, más:

| Opción | camelCase (TypeScript, PHP, Java) | snake_case (Python, Ruby, Rust) | PascalCase (Go, C#) | No disponible en |
| --- | --- | --- | --- | --- |
| La ejecución guardada | `run` | `run` (Rust: `result`) | `Run` | |
| Cargar la ejecución por ID mediante `state` | `runId` | `run_id` | `RunID` (Go), `RunId` (C#) | Rust; PHP usa `continueRunById($runId, $state, $client, ...)` |
| Entrada humana | `humanInput` | `human_input` | `HumanInput` | |
| Mensajes humanos estructurados | `humanMessages` (TypeScript) | | | Todos menos TypeScript |
| Aprobaciones | `approvals` (alias de TypeScript `approveToolCalls`) | `approvals` | `Approvals` | |
| Rechazos | `rejections` (alias de TypeScript `rejectToolCalls`) | `rejections` | `Rejections` | Rust |
| Salidas de herramientas | `toolOutputs` | `tool_outputs` | `ToolOutputs` | |

El orden del `ContinueOptions` de Java es `run, client, context, model, preset, maxSteps, humanInput, modelRetry, toolExecution, onEvent, devtools`, después `approvals, rejections, toolOutputs` y después `runId, state`. Además de esta forma de 16 argumentos, tiene constructores que reciben solo los 11 primeros o los 14 primeros; el resto toma listas vacías o `null` por defecto. Rust crea los valores predeterminados con `ContinueOptions::new(result)`.

| --- | --- | --- | --- | --- | --- | --- | --- |

Los consumidores reproducen desde el principio, así que varios pueden leer la misma ejecución. Su comportamiento varía:

| Lenguaje | Tipo de resultado del stream | Comportamiento |
| --- | --- | --- |
| TypeScript | `AgentStreamResult` | `getFullStream()` termina con un evento `result` |
| Python | `AgentStreamResult` | Se ejecuta en un hilo en segundo plano; `result()` bloquea hasta que termina |
| Go | `*StreamResult` | `Text()` y `Events()` son canales; `Cancel()` cancela el contexto de la ejecución |
| C# | `AgentStreamResult` | Consumidores `IAsyncEnumerable`; `Cancel()` cancela el token vinculado de la ejecución |
| PHP | `AgentStreamResult` | Se ejecuta en una Fiber; `$result` contiene el `RunResult` cuando el stream se ha consumido por completo y, si no, `null` |
| Ruby | `StreamResult` | Se ejecuta en un hilo de trabajo; `result` espera a que termine y `cancel` lo mata |
| Java | `StreamResult` | `textStream()` y `fullStream()` devuelven una `List` cuando termina la ejecución; `cancel()` interrumpe el hilo de trabajo |
| Rust | Ninguno | Sin streaming en `0.2` |

## Resultado de la ejecución

| Campo | camelCase (TypeScript, PHP, Java) | snake_case (Python, Ruby, Rust) | PascalCase (Go, C#) |
| --- | --- | --- | --- |
| Registro de la ejecución | `run` | `run` | `Run` |
| Registros de pasos | `steps` | `steps` | `Steps` |
| Salida final | `output` | `output` | `Output` |
| Conversación completa | `messages` | `messages` | `Messages` |
| Uso acumulado | `usage` | `usage` | `Usage` |

El tipo es `AgentRunResult` en TypeScript y Python y `RunResult` en los demás. TypeScript añade `stepResults` (resultados de pasos normalizados) e `items` (mensajes, razonamiento, actividad de herramientas, errores y salida final, en orden; consulta [Elementos](./items)). En Rust, `output` es un `serde_json::Value`, y `RunResult`, `RunRecord`, `RunStep`, `Message`, `ToolCall`, `HumanPause`, `PendingToolCall`, `ToolDecision`, `ToolOutput` y `UsageSummary` se serializan con Serde.

### Resumen de uso

`inputTokens`, `outputTokens`, `cachedTokens`, `totalTokens`, `cost` (TypeScript, Java); `input_tokens`, `output_tokens`, `cached_tokens`, `total_tokens`, `cost` (claves de Python, PHP y Ruby, Rust); `InputTokens`, `OutputTokens`, `CachedTokens`, `TotalTokens`, `Cost` (Go, C#). El tipo es `AgentUsageSummary` en TypeScript y Python y `UsageSummary` en Go, C#, Java y Rust. PHP y Ruby usan un array o un Hash. Consulta [Observabilidad](./observability) para ver las salvedades sobre `cost`.

## Clientes del modelo

Implementa un cliente del modelo para enviar los turnos del modelo por otro transporte o para envolver el cliente de gateway.

| Lenguaje | Interfaz | Métodos |
| --- | --- | --- |
| Go | `ModelClient`, `StreamingModelClient` | `Generate(ctx, ModelRequest)`; `Stream(ctx, ModelRequest)` |
| C# | `IModelClient`, `IStreamingModelClient` | `Generate(ModelRequest)`; `Stream(ModelRequest)` |
| PHP | `ModelClient`, `StreamingModelClient` (interfaces) | `generate(ModelRequest)`; `stream(ModelRequest)` |
| Java | `ModelClient`, `StreamingModelClient` | `generate(ModelRequest)`; `stream(ModelRequest)` |
| Rust | `ModelClient` (trait) | `fn generate(&mut self, request: &ModelRequest) -> Result<ModelResponse, AgentError>` |

En Rust, `ModelRequest` contiene el ID del agente, el modelo efectivo, las instrucciones, los mensajes actuales, las especificaciones de las herramientas (`ToolSpec`: `id`, `description`, `parameters` en JSON Schema) y el contexto de la aplicación. `ModelResponse` contiene `message`, `usage`, `request_id`, `provider`, `model` y `finish_reason`. `Message` tiene `role`, `content`, `tool_calls`, `tool_call_id`, `name` e `is_error`, con los constructores `Message::user(content)` y `Message::assistant(content)`; `ToolCall` tiene `id`, `name` e `input` en JSON.

TypeScript también exporta `agentErrorIsRetryable()`, `agentRetryAfterMs()` y `agentErrorIsContextOverflow()` para clasificar errores, `repairToolHistory(messages)` para responder a las llamadas a herramientas que quedaron sin resultado y descartar los resultados que no responden a ninguna llamada, y `truncateToolOutput(text, limit)` para conservar el principio y el final de un texto largo con un aviso de lo que se ha recortado.
