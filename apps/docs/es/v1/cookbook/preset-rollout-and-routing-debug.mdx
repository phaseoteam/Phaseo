Pasa varios servicios a un mismo preajuste para que compartan prompt, modelo y reglas de proveedor, y después usa los registros de solicitudes para explicar adónde fue cada solicitud. Al terminar, tus llamantes enviarán `"model": "@release-summary"` y su entrada, y podrás desplegar un cambio de política llamante por llamante.

La forma de la solicitud está lista para producción. [Preajustes](../guides/presets) explica cómo se combinan los ajustes de un preajuste con la solicitud; esta receta trata del despliegue.

## Pasa un llamante a un preajuste

<Steps>
<Step title="Crea el preajuste">

En **Configuración → Preajustes**, crea `release-summary` con un prompt de sistema, los modelos aprobados, las preferencias de proveedor y parámetros predeterminados como `temperature`. O con una clave de administración:

```bash
curl https://api.phaseo.app/v1/presets \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name":"@release-summary","config":{"model":"anthropic/claude-sonnet-5.5"}}'
```

</Step>
<Step title="Llámalo por su nombre">

Envía el preajuste como `model`. No hay un campo `preset` aparte.

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "@release-summary",
    "input": "Generate a release summary for the last 24 hours.",
    "meta": true
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "@release-summary",
  input: "Generate a release summary for the last 24 hours.",
  meta: true,
});

console.log(response.model, response.meta?.routing);
```

```python Python
import os

from phaseo import Phaseo

client = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

response = client.generate_response(
    {
        "model": "@release-summary",
        "input": "Generate a release summary for the last 24 hours.",
        "meta": True,
    }
)

print(response.get("model"), response["meta"]["routing"]["selected_provider"])
```
</CodeGroup>

En la respuesta, `model` es el modelo que contestó y `meta.routing.selected_provider`, el proveedor.

</Step>
<Step title="Comprueba qué aplicó el preajuste">

Abre la solicitud en **Configuración → Uso → Registros**. Muestra qué valores predeterminados del preajuste se aplicaron. Un modelo que no está entre los permitidos del preajuste falla con `validation_error` (palabra clave `preset_model_not_allowed`) en lugar de enrutarse a otro.

</Step>
</Steps>

## Explica una decisión de enrutamiento

Cuando una solicitud no se enrutó como esperabas, despliega **Observabilidad de enrutamiento** en la solicitud dentro de **Configuración → Uso → Registros**. Responde a tres preguntas:

| Pregunta | Dónde mirar |
| --- | --- |
| ¿Por qué se omitió un proveedor? | Los proveedores excluidos antes de la clasificación, con el motivo, y los proveedores relegados por su estado de despliegue o de enrutamiento |
| ¿Por qué se bloqueó la solicitud? | Los bloqueos de la política del espacio de trabajo o de guardrails sobre la solicitud |
| ¿Por qué ganó este proveedor? | La puntuación final de cada proveedor clasificado y los factores que la explican |

[Explica una decisión de enrutamiento](../guides/routing-and-fallbacks#explain-a-routing-decision) describe cada campo.

## Despliega un cambio de política

1. Publica el cambio como una nueva versión del preajuste, o crea un slug nuevo para una política muy distinta.
2. Pasa a ella un llamante de bajo riesgo, por ejemplo apuntándolo a `@release-summary@v4` o a una etiqueta `canary`.
3. Compara sus detalles de solicitud y sus tendencias de uso con los de los demás llamantes.
4. Pasa el resto de los llamantes cuando el enrutamiento coincida con lo que esperas. Para revertir, apunta la etiqueta a la versión anterior.

[Versiona y revierte](../guides/presets#version-and-roll-back) explica las versiones y las etiquetas. Para cambios a nivel de solicitud que no deberían vivir en un preajuste, consulta [Fija o ignora proveedores](./pin-or-ignore-providers-per-request).
