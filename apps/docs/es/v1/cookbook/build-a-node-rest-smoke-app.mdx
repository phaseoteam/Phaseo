Ejecuta un script de Node.js sin dependencias que llama a Phaseo con `fetch` sin más, para que veas cada solicitud y cada respuesta. Al terminar tendrás una prueba rápida que puedes ejecutar antes de un despliegue: comprueba que la API responde, lista los modelos y envía una solicitud a Responses, otra a Chat Completions y otra a Embeddings.

El script es ilustrativo: imprime el estado HTTP de cada llamada, pero siempre termina con `0`, así que añade la comprobación del código de salida de [Úsalo como comprobación de despliegue](#use-it-as-a-deploy-check) antes de confiar en él en CI.

Para que un agente de programación cree el mismo script desde cero, pega este prompt:

## Qué llama el script

El ejemplo es [examples/gateway-node-quickstart](https://github.com/phaseoteam/Phaseo/tree/main/examples/gateway-node-quickstart): un solo archivo, `index.mjs`, sin dependencias.

| Modo | Llamadas | Consume créditos |
| --- | --- | --- |
| `npm run smoke` | `GET /v1/health`, `GET /v1/models` | No |
| `npm run start` | Las dos anteriores y después `POST /v1/responses`, `POST /v1/chat/completions`, `POST /v1/embeddings` | Sí |

Las llamadas de texto envían `Return exactly: integration_ok` a `PHASEO_MODEL` (por defecto, `openai/gpt-5.6-sol`). La llamada de embeddings usa `google/gemini-embedding-2`.

## Ejecútalo

Necesitas Node.js 18 o posterior, por el `fetch` integrado, y una clave de API de Phaseo.

<Steps>
<Step title="Crea .env.local">

El script carga `.env.local` desde la carpeta en la que lo ejecutas, sin ningún paquete. El ejemplo no incluye `.env.example`, así que crea el archivo:

```bash .env.local
PHASEO_API_KEY=phaseo_v1_sk_...
# Optional
PHASEO_MODEL=openai/gpt-6-astra
PHASEO_BASE_URL=https://api.phaseo.app/v1
PHASEO_APP_TITLE=My smoke test
PHASEO_HTTP_REFERER=https://myapp.example
```

Las variables que ya están definidas en tu shell tienen prioridad sobre el archivo.

</Step>
<Step title="Ejecuta el modo de prueba rápida">

```bash
cd examples/gateway-node-quickstart
npm run smoke
```

</Step>
<Step title="Ejecuta el modo completo">

```bash
npm run start
```

</Step>
</Steps>

## Comprueba que ha funcionado

Cada llamada imprime un bloque como este:

```text
=== Health ===
HTTP 200
{ ... }
```

- `Health` y `Models` muestran `HTTP 200`, y `Models` lista al menos un modelo.
- En la ejecución completa, los bloques de Responses y Chat Completions contienen `integration_ok`.
- Con una clave incorrecta, los bloques de generación muestran `HTTP 401` y el cuerpo del error, en lugar de ocultarlo.
- Las solicitudes aparecen en **Configuración → Uso → Registros**.

## Úsalo como comprobación de despliegue

`request()` devuelve `{ status, ok, payload }`, pero nada comprueba `ok`. Añade una línea al principio de `print()` para que el script termine con `1` cuando falle alguna llamada:

```js index.mjs
function print(title, result) {
  if (!result.ok) process.exitCode = 1;
  console.log(`\n=== ${title} ===`);
  // ...rest unchanged
}
```

Reduce el script a las rutas que usa tu servicio y pasa al [SDK de TypeScript](../sdk-reference/client/overview) cuando prefieras no construir los payloads a mano.
