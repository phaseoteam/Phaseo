Usa esta página para crear una integración Node mínima y ver con claridad cada solicitud HTTP.

**Objetivo:** Verificar el estado de Phaseo, descubrir modelos y enviar una solicitud de generación mediante HTTP sin procesar.

**Resultado:** Un script con pocas dependencias que puedes conservar como prueba rápida de despliegue o integración.

## Proyecto de ejemplo

- GitHub: [examples/gateway-node-quickstart](https://github.com/phaseoteam/Phaseo/tree/main/examples/gateway-node-quickstart)
- Ruta del repositorio local: `examples/gateway-node-quickstart`

## Qué hace esta aplicación

- llama a `GET /v1/health`
- llama a `GET /v1/models`
- prueba rutas de generación como `POST /v1/responses`
- te ofrece una referencia HTTP directa para pruebas rápidas, scripts y comprobaciones del backend

## Cuándo conviene usar este ejemplo

Empieza aquí cuando:

- quieras depurar directamente las llamadas HTTP a la API
- todavía no quieras usar abstracciones de SDK
- estés creando un script, un worker o una CLI en lugar de una interfaz web

## Requisitos previos

- Node.js con compatibilidad integrada para `fetch`
- una clave de API de Phaseo

## Ejecuta el ejemplo

```bash
cd examples/gateway-node-quickstart
cp .env.example .env.local
```

Configura:

- `PHASEO_API_KEY`

Después, ejecuta uno de estos comandos:

```bash
npm run smoke
```

or:

```bash
npm run start
```

## Comprueba el resultado

- El modo de prueba rápida confirma que se puede acceder a la API.
- La búsqueda de modelos devuelve al menos un modelo.
- La ejecución completa muestra una respuesta de generación correcta.
- Los errores de autenticación y las respuestas que no sean 200 generan mensajes claros en la terminal.

## Qué revisar en el código

- cómo carga el script `.env.local`
- cómo se añade el encabezado de autorización
- cómo se construye cada solicitud de forma explícita
- cómo se muestran las respuestas distintas de 200 en lugar de ocultarlas

## Cómo adaptarlo

- reduce el script a las rutas que realmente necesita tu servicio
- si varios scripts van a usar el mismo código de solicitud, muévelo a una función auxiliar
- si las solicitudes HTTP directas se vuelven repetitivas, cambia más adelante al SDK de TypeScript
