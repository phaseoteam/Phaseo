---

Añade requisitos de residencia y de <Tooltip tip="Retención cero de datos: el proveedor no guarda los prompts ni las salidas.">ZDR</Tooltip> al objeto `provider` de una solicitud, y Phaseo quitará todas las ofertas de proveedores que no los cumplan antes de clasificar el resto. Al terminar, un flujo de trabajo se ejecutará solo en proveedores de la UE o con ZDR, sin cambiar la política de todo el espacio de trabajo.

La solicitud está lista para producción. Si ningún proveedor del modelo cumple todos los requisitos, la solicitud falla antes de llamar a ningún proveedor, así que comprueba antes la disponibilidad.

| Campo | Solo conserva los proveedores que |
| --- | --- |
| `required_execution_region: "eu"` | Ejecutan el modelo en la UE |
| `required_data_region: "eu"` | Tratan los datos del prompt y de la respuesta en la UE |
| `require_zero_data_retention: true` | Cumplen los requisitos de retención cero de datos |

## Envía una solicitud restringida

<Steps>
<Step title="Comprueba que un proveedor cumple los requisitos">

En la página del modelo, las tarjetas de proveedor muestran ofertas regionales como **OpenAI EU** o **Google Vertex EU**, la compatibilidad con ZDR y las notas y fuentes de la política de datos de cada proveedor. Para la UE, también puedes listar lo que sirve el gateway de la UE:

```bash
curl https://eu.api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

</Step>
<Step title="Añade solo los requisitos que necesitas">

Cada requisito reduce el grupo, así que puede enrutar a una oferta regional más cara o dejarte sin ningún proveedor. Envía solo lo que exige tu política:

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5.6-luna",
    "input": "Summarize the ticket in one line.",
    "provider": {
      "required_execution_region": "eu",
      "required_data_region": "eu"
    },
    "meta": true
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "openai/gpt-5.6-luna",
  input: "Summarize the ticket in one line.",
  provider: {
    required_execution_region: "eu",
    required_data_region: "eu",
  },
  meta: true,
});

console.log(response.meta?.routing);
```

```python Python
import os

from phaseo import Phaseo

client = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

response = client.generate_response(
    {
        "model": "openai/gpt-5.6-luna",
        "input": "Summarize the ticket in one line.",
        "provider": {
            "required_execution_region": "eu",
            "required_data_region": "eu",
        },
        "meta": True,
    }
)

print(response["meta"]["routing"]["selected_provider"])
```
</CodeGroup>

Para exigir también ZDR, añade `"require_zero_data_retention": true`. Con los tres, un modelo necesita al menos un proveedor de la UE que además cumpla ZDR.

</Step>
<Step title="Comprueba dónde se ejecutó">

`meta.routing.selected_provider` indica el proveedor que la atendió, por ejemplo `openai-eu`. La solicitud en **Configuración → Uso → Registros** guarda las regiones exigidas y el proveedor seleccionado.

</Step>
</Steps>

## Elige entre campos de solicitud, el gateway de la UE o los ajustes del espacio de trabajo

| Usa | Cuándo |
| --- | --- |
| Estos campos de solicitud en `api.phaseo.app` | La regla se aplica a un flujo de trabajo, un cliente o una solicitud. Todos los endpoints y funciones siguen disponibles. |
| [`eu.api.phaseo.app`](../guides/regional-routing) | Todas las solicitudes de texto de un servicio deben quedarse en la UE. El nombre de host impone la región y además rechaza la entrada multimedia, las herramientas de servidor de Phaseo y las herramientas alojadas por el proveedor. Enviar allí un `required_execution_region` o `required_data_region` de otra región devuelve `400 validation_error` con el motivo `deployment_region_conflict`. |
| **Configuración → Privacidad** | La regla se aplica a todas las solicitudes del espacio de trabajo. |

El enrutamiento regional restringe qué proveedores atienden la llamada al modelo. Todavía no es una garantía de residencia de datos de extremo a extremo; [Qué queda fuera de la región](../guides/regional-routing#what-stays-outside-the-region) lista los sistemas compartidos. Para restringir proveedores sin una regla de residencia, consulta [Fija o ignora proveedores](./pin-or-ignore-providers-per-request).
