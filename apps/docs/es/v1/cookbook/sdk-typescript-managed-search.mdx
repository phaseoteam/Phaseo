Dale a una solicitud de TypeScript la herramienta `phaseo:web_search` y un JSON Schema, para que el modelo busque antes de responder y devuelva un informe con sus fuentes. Al terminar tendrás un script que imprime un objeto `{ summary, sources }` validado, además de los IDs y los contadores de búsqueda que necesitas para depurarlo.

El script está listo para producción en cuanto sustituyas el preajuste y el dominio por los tuyos. Los resultados de búsqueda son contenido web no fiable: valida la salida y no sigas las instrucciones que aparezcan en ella.

## Créalo

<Steps>
<Step title="Crea un preajuste">

Crea `research-brief` en **Configuración → Preajustes** con el modelo, las preferencias de proveedor, los ajustes de razonamiento y el prompt de sistema que deben compartir todos los llamantes. El modelo tiene que admitir herramientas y salida con JSON Schema.

</Step>
<Step title="Instala el SDK">

```bash
npm install @phaseo/sdk zod
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="Escribe el script">

```ts research-brief.ts
import Phaseo from "@phaseo/sdk";
import { z } from "zod";

const gateway = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const Brief = z
  .object({
    summary: z.string().min(1),
    sources: z
      .array(z.object({ title: z.string(), url: z.string().url() }).strict())
      .min(1),
  })
  .strict();

const response = await gateway.generateResponse({
  model: "@research-brief",
  input: "Find the latest public changes to Phaseo webhook delivery behavior and summarize them.",
  tools: [
    {
      type: "phaseo:web_search",
      parameters: {
        allowed_domains: ["phaseo.app"],
        max_results: 5,
        include_highlights: true,
      },
    },
  ],
  tool_choice: "phaseo:web_search",
  text: {
    format: {
      type: "json_schema",
      name: "research_brief",
      strict: true,
      schema: {
        type: "object",
        required: ["summary", "sources"],
        properties: {
          summary: { type: "string" },
          sources: {
            type: "array",
            minItems: 1,
            items: {
              type: "object",
              required: ["title", "url"],
              properties: {
                title: { type: "string" },
                url: { type: "string", format: "uri" },
              },
              additionalProperties: false,
            },
          },
        },
        additionalProperties: false,
      },
    },
  },
  plugins: [{ id: "response-healing" }],
  meta: true,
});

const text = (response.output ?? [])
  .filter((item) => item.type === "message")
  .flatMap((item) => item.content ?? [])
  .filter((part) => part.type === "output_text")
  .map((part) => part.text ?? "")
  .join("");

const brief = Brief.parse(JSON.parse(text));

console.log({
  responseId: response.id,
  model: response.model,
  routing: response.meta?.routing,
  pluginExecutions: response.meta?.plugin_executions,
  serverToolUse: response.usage?.server_tool_use,
});
console.log(brief);
```

| Campo | Qué hace |
| --- | --- |
| `tools` con `phaseo:web_search` | Phaseo ejecuta la búsqueda, tenga o no el proveedor su propia búsqueda. El modelo escribe la consulta. |
| `allowed_domains` | Limita los resultados a tus propias fuentes. Todos los parámetros están en la [guía de búsqueda web](../guides/server-tools/web-search#parameters). |
| `tool_choice: "phaseo:web_search"` | Obliga al modelo a buscar en lugar de responder de memoria. |
| `text.format` | El JSON Schema de la respuesta. |
| `plugins` | Repara el JSON casi válido; consulta [reparación de respuestas](./response-healing-for-structured-json). |
| `meta: true` | Añade `meta.routing` y `meta.plugin_executions`. |

</Step>
<Step title="Ejecútalo">

```bash
npx tsx research-brief.ts
```

</Step>
</Steps>

## Comprueba que ha funcionado

- `serverToolUse.web_search_requests` es al menos `1`, así que la búsqueda se ejecutó.
- `brief.sources` lista URLs de `phaseo.app`.
- `routing.selected_provider` indica el proveedor, y `pluginExecutions` muestra si la reparación cambió algo.
- En **Configuración → Uso → Registros**, la sección **Supervisión de la búsqueda web** de la solicitud muestra las búsquedas gestionadas, los resultados y las citas.

Si los resultados no parecen correctos, corrige el preajuste o los parámetros de la herramienta según lo que muestren los registros en lugar de añadir sustituciones. [Depura la búsqueda web](./web-search-debugging) lista los casos habituales. Mantén la investigación exploratoria y con temperatura más alta en un preajuste distinto de este, que es determinista, para que su enrutamiento siga siendo fácil de comparar.
