Crea un agente de clasificación en TypeScript cuyo modelo, prompt y reglas de proveedor vienen de un preset del panel, de modo que el código solo gestiona el flujo de trabajo. Al terminar devuelve una decisión de clasificación en JSON estricto, detiene los casos que necesitan a una persona, reintenta las llamadas al modelo un número limitado de veces y registra los fallos del gateway con los ID que necesitas para encontrarlos.

El script está listo para producción en cuanto exista el preset y guardes las ejecuciones en pausa, como en el [bucle duradero](./agent-sdk-durable-loop). Hay una versión empaquetada en `packages/sdk/agent-sdk-ts/examples/support-triage-agent.ts`.

## Créalo

<Steps>
<Step title="Crea el preset">

En **Ajustes → Preajustes**, crea `support-triage` con el modelo enrutado, las preferencias de proveedor, el prompt de sistema de soporte y parámetros de decodificación estables. El modelo debe admitir salida con JSON Schema. [Presets](../guides/presets) explica cómo se combina un preset con cada solicitud.

</Step>
<Step title="Instala">

```bash
npm install @phaseo/agent-sdk zod
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="Escribe el agente">

```ts triage-agent.ts
import { z } from "zod";
import { AgentGatewayError, createAgent, createGatewayAgentClient } from "@phaseo/agent-sdk";

const SupportTriageDecision = z
  .object({
    queue: z.enum(["billing", "reliability", "product", "security"]),
    severity: z.enum(["low", "medium", "high"]),
    needsHumanReview: z.boolean(),
    summary: z.string().min(1),
  })
  .strict();
type SupportTriageDecision = z.infer<typeof SupportTriageDecision>;

// `preset` se convierte en el modelo `@support-triage` en cada turno.
const supportTriageAgent = createAgent<string, SupportTriageDecision>({
  id: "support-triage-agent",
  preset: "support-triage",
  maxSteps: 3,
  parseOutput: (text) => JSON.parse(text),
  outputSchema: SupportTriageDecision,
  humanReview: ({ parsedOutput }) =>
    parsedOutput?.needsHumanReview
      ? { reason: "support_triage_review_required", payload: parsedOutput }
      : null,
});

const client = createGatewayAgentClient({
  clientOptions: { apiKey: process.env.PHASEO_API_KEY! },
  responseFormat: {
    type: "json_schema",
    name: "support_triage_decision",
    schema: {
      type: "object",
      properties: {
        queue: { type: "string", enum: ["billing", "reliability", "product", "security"] },
        severity: { type: "string", enum: ["low", "medium", "high"] },
        needsHumanReview: { type: "boolean" },
        summary: { type: "string" },
      },
      required: ["queue", "severity", "needsHumanReview", "summary"],
      additionalProperties: false,
    },
  },
  plugins: [{ id: "response-healing", mode: "strict" }],
});

try {
  const result = await supportTriageAgent.run({
    input: "Customer says webhook deliveries failed overnight and asks whether data was lost.",
    client,
    modelRetry: { maxRetries: 2, backoffMs: 250 },
    onEvent(event) {
      if (event.type === "model.retrying") console.log("retrying", event.attempt, event.error);
    },
  });

  if (result.run.status === "waiting_for_human") {
    // Guarda `result` y continúa cuando un agente de soporte lo haya revisado.
    console.log("Needs review:", result.run.pause?.payload);
  } else {
    console.log(result.output);
  }
} catch (error) {
  if (error instanceof AgentGatewayError) {
    console.error("Gateway request failed", {
      status: error.status,
      requestId: error.requestId,
      generationId: error.generationId,
      reason: error.reason,
      providerFailureDiagnostics: error.providerFailureDiagnostics,
      routingDiagnostics: error.routingDiagnostics,
    });
  }
  throw error;
}
```

</Step>

## Comprueba que funciona

Ejecuta un ticket rutinario y uno de riesgo, y después comprueba que:

- En **Ajustes → Uso → Registros**, el modelo de la solicitud muestra que se usó el preset.
- El caso de riesgo termina en `waiting_for_human` con la decisión en `pause.payload`.
- Una llamada al modelo reintentada queda registrada en el paso como `modelAttempts`, y cada reintento registra `model.retrying`.
- Una solicitud bloqueada se registra con su `requestId` y su `reason`, y la misma solicitud en los registros muestra el motivo.

## Mantén visibles los fallos del gateway

No silencies los errores dentro de los callbacks del agente. Captura `AgentGatewayError` en el borde, registra sus ID y vuelve a lanzarlo. Cuando una ejecución falla, su estado guardado conserva los mismos detalles en `run.errorDetails` y `steps[n].errorDetails`, para que un trabajo de recuperación posterior pueda leerlos cuando la excepción ya no exista.

Estos fallos vienen de la política del Gateway, no del agente, así que hay que mirar la solicitud en los registros:

| Fallo | Dónde aparece |
| --- | --- |
| Un guardrail bloquea la solicitud | La sección **Aplicación de guardrails** de la solicitud |
| Los modelos permitidos del preset rechazan el modelo | `validation_error` con la palabra clave `preset_model_not_allowed` |
| Las credenciales o la habilitación de proveedores no dejan ningún proveedor | `providerFailureDiagnostics` y **Observabilidad de enrutamiento** |
| La reparación no consigue JSON válido según el esquema | El registro de plugins y, después, `AgentSchemaValidationError` de `outputSchema` |
