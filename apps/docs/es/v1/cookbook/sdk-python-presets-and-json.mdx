Llama desde Python a un preajuste del panel con un JSON Schema, y después valida la respuesta y registra los IDs que necesitas para depurarla. Al terminar tendrás un script que envía `"model": "@release-summary"`, recibe `{"summary": ..., "risk_level": ...}` e imprime los detalles del proveedor y de los plugins de esa solicitud.

El script está listo para producción en cuanto sustituyas el preajuste y el esquema por los tuyos. Mantén el paso de validación: la reparación corrige la sintaxis, no el contenido.

## Créalo

<Steps>
<Step title="Crea el preajuste">

En **Configuración → Preajustes**, crea `release-summary` con el prompt de sistema, el modelo o los modelos permitidos, las preferencias de proveedor, los ajustes de razonamiento y la `temperature` que deben compartir todos los llamantes. Así el código de Python solo envía lo que cambia. [Preajustes](../guides/presets) explica cómo se combina el preajuste con la solicitud.

</Step>
<Step title="Instala el SDK">

```bash
pip install phaseo
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="Escribe el script">

```python release_summary.py
import json
import os

from phaseo import Phaseo

# Crea un solo cliente y reutilízalo.
gateway = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

SCHEMA = {
    "type": "object",
    "properties": {
        "summary": {"type": "string"},
        "risk_level": {"type": "string", "enum": ["low", "medium", "high"]},
    },
    "required": ["summary", "risk_level"],
    "additionalProperties": False,
}


def output_text(response: dict) -> str:
    return "".join(
        part.get("text", "")
        for item in response.get("output", [])
        if item.get("type") == "message"
        for part in item.get("content", [])
        if part.get("type") == "output_text"
    )


def validate(payload: dict) -> dict:
    if set(payload) != {"summary", "risk_level"}:
        raise ValueError(f"unexpected keys: {sorted(payload)}")
    if not isinstance(payload["summary"], str) or not payload["summary"]:
        raise ValueError("summary must be a non-empty string")
    if payload["risk_level"] not in ("low", "medium", "high"):
        raise ValueError("risk_level must be low, medium or high")
    return payload


response = gateway.generate_response(
    {
        "model": "@release-summary",
        "input": "Summarize the last 24 hours of deployment activity.",
        "text": {
            "format": {
                "type": "json_schema",
                "name": "release_summary",
                "strict": True,
                "schema": SCHEMA,
            }
        },
        "plugins": [{"id": "response-healing"}],
        "meta": True,
    }
)

if response.get("status") != "completed":
    raise RuntimeError(f"response {response.get('id')} ended as {response.get('status')}")

payload = validate(json.loads(output_text(response)))
meta = response.get("meta", {})

print("response_id:", response.get("id"))
print("model:", response.get("model"))
print("selected_provider:", meta.get("routing", {}).get("selected_provider"))
print("plugin_executions:", meta.get("plugin_executions"))
print(payload)
```

| Campo | Qué hace |
| --- | --- |
| `"model": "@release-summary"` | Usa el preajuste. No hay un campo `preset` aparte. |
| `text.format` | Pide este JSON Schema. En Chat Completions va en `response_format`; consulta [Salidas estructuradas](../guides/structured-outputs). |
| `plugins` | Repara el JSON casi válido; consulta [reparación de respuestas](./response-healing-for-structured-json). |
| `meta: true` | Añade `meta.routing` y `meta.plugin_executions` a la respuesta. |

</Step>
<Step title="Ejecútalo">

```bash
python release_summary.py
```

</Step>
</Steps>

## Comprueba que ha funcionado

El script imprime el ID de la respuesta, el modelo y el proveedor que contestaron, el registro del plugin y un dict con `summary` y uno de los valores `low`, `medium` o `high`. Busca el ID de la respuesta en **Configuración → Uso → Registros** para ver la misma solicitud con sus detalles de enrutamiento.

Un modelo que no está entre los permitidos del preajuste falla con `validation_error` (palabra clave `preset_model_not_allowed`). Un `ValueError` de `validate()` significa que el JSON se analizó, pero el contenido era incorrecto: ajusta el esquema o el prompt en lugar de añadir reintentos.

## Depura antes de sustituir ajustes

Si una solicitud se enruta de forma distinta a la que esperabas, ábrela en los registros, lee **Observabilidad de enrutamiento** y el registro del plugin, y cambia el preajuste solo cuando los registros muestren qué pasó. Acumular sustituciones en línea en una solicitud anula el sentido del preajuste; si un llamante necesita de verdad otro comportamiento, dale su propio preajuste.
