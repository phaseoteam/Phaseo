title: "Registro de auditoría del espacio de trabajo"
description: "Consulta los cambios administrativos del espacio de trabajo relacionados con la seguridad."
---

Abre **Ajustes → Espacio de trabajo → Actividad** para ver quién cambió una clave, un miembro u otro control administrativo en el espacio de trabajo activo, y cuándo. Los eventos se muestran del más reciente al más antiguo. Solo los propietarios y administradores del espacio de trabajo pueden leer el registro.

Los registros de solicitudes y generaciones muestran qué tráfico se ejecutó. El registro de auditoría muestra quién cambió los controles que lo rodean.

## Qué se registra

| Área | Acciones de ejemplo |
| --- | --- |
| Claves de API | `api_key.created`, `api_key.updated`, `api_key.paused`, `api_key.resumed`, `api_key.rotated`, `api_key.deleted` |
| Claves de gestión | `management_key.created`, `management_key.updated`, `management_key.deleted` |
| Miembros e invitaciones | `workspace.member.added`, `workspace.member.role_updated`, `workspace.member.removed`, `workspace.invite.created` |
| Claves de proveedor (BYOK) | `provider_credential.created`, `provider_credential.updated`, `provider_credential.reordered`, `provider_credential.deleted` |
| Enrutamiento y presets | `routing.policy.updated`, `routing.dynamic_route.deployed`, `preset.version.published` |
| Presupuestos y gasto | `workspace_budget.updated`, `spend_block.lifted`, `rate_limit_raise.requested` |
| Guardrails | `guardrail.created`, `guardrail.updated`, `guardrail.keys.added` |
| Identidad | `identity.sso.updated`, `identity.scim_token.created`, `identity.group_mapping.updated` |
| Integraciones | `observability.destination.created`, `notifications.destination.created`, `webhook_endpoint.secret_rotated`, `oauth_authorization.revoked` |

Cada evento incluye el actor, la acción, el tipo de destino, el ID y el nombre del destino, la marca de tiempo, el ID de solicitud y un pequeño conjunto de metadatos sobre el cambio. Los eventos son de solo anexado.

El registro nunca guarda claves en texto plano, hashes de credenciales, encabezados de autorización, listas completas de permisos ni cuerpos de solicitudes. Los campos de metadatos cuyo nombre menciona un secreto, token, hash, credencial, permiso o valor se eliminan antes de escribir el evento.

## Leer eventos desde la API

Llama a `GET /v1/audit-events` con una [clave de gestión](../developers/management-api-keys.mdx) que tenga `activity:read`. Un token OAuth también necesita `activity:read`, y su usuario debe ser propietario o administrador del espacio de trabajo.

```bash
curl "https://api.phaseo.app/v1/audit-events?limit=50" \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY"
```

| Parámetro de consulta | Significado |
| --- | --- |
| `limit` | Eventos por página, de 1 a 100. Valor predeterminado: `50`. |
| `cursor` | El `next_cursor` de la página anterior. Al paginar por cursor nunca se saltan eventos que comparten marca de tiempo. |
| `action` | Devuelve solo una acción, como `api_key.rotated`. |
| `target_type` | Devuelve solo un tipo de destino, como `api_key`. |

La respuesta incluye `data`, `has_more` y `next_cursor`. Cada evento incluye un objeto `actor` con el `display_name` y el `email` del miembro.
