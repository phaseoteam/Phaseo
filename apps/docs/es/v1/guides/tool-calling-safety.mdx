Trata cada llamada a herramienta como una entrada no confiable: comprueba el nombre de la herramienta con una lista de permitidas y valida los argumentos antes de ejecutar nada.

```typescript
import { z } from "zod";

const WeatherArgs = z.object({
  city: z.string().min(1),
});

function executeToolCall(name: string, rawArgs: string) {
  if (name !== "get_weather") {
    throw new Error(`Unsupported tool: ${name}`);
  }

  const parsed = WeatherArgs.parse(JSON.parse(rawArgs));
  return getWeather(parsed.city);
}
```

## Lista de comprobación

- **Mantén los esquemas pequeños y explícitos.** Menos campos, y con tipo, dejan al modelo menos margen para enviar algo inesperado.
- **Valida los argumentos analizados** antes de ejecutar, como arriba.
- **Rechaza los nombres de herramientas desconocidos** en lugar de adivinar qué quería decir el modelo.
- **Añade tiempos de espera y reintentos** a las llamadas que acceden a sistemas externos.
- **Registra** el ID de la llamada, el nombre de la herramienta y cualquier fallo de validación.

## Cuando la validación falla

No ejecutes la herramienta. Envía un error breve y controlado como resultado de la herramienta en el siguiente turno, y pide al modelo que vuelva a intentarlo con los argumentos corregidos.

## Streaming

Con `stream: true`, los argumentos llegan por partes. Acumula todos los deltas de argumentos de una llamada antes de analizarla, validarla o ejecutarla. Que las llamadas a herramientas se transmitan depende del modelo y del proveedor. Consulta [Transmisión](./streaming.mdx).
