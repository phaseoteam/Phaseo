Establece `service_tier` en una solicitud de texto para pagar por una entrega más rápida (`fast`, `ultrafast`) o aceptar un modo más barato y de menor prioridad (`flex`). Phaseo enruta entonces solo a los proveedores que ofrecen ese nivel para el modelo. El campo funciona igual en `/v1/chat/completions`, `/v1/responses` y `/v1/messages`.

```json
{
  "model": "openai/gpt-5.5",
  "input": "Summarise this incident report.",
  "service_tier": "fast"
}
```

| Nivel | Cómo solicitarlo | Para qué usarlo |
| --- | --- | --- |
| Standard | Nada, o `"standard"` / `"default"` | Tráfico de producción general |
| Fast | `"fast"`, o su alias `"priority"` | La oferta premium o de mayor prioridad del proveedor |
| Ultrafast | `"ultrafast"` | La oferta de mayor velocidad |
| Flex | `"flex"` | Una oferta de menor coste, cuando el proveedor la tiene |
| Batch | La [Batch API](../api-reference/endpoint/batches-create.mdx), no `service_tier` | Cargas de trabajo grandes y diferidas |

Los niveles solo están disponibles para modelos de texto, y solo cuando el modelo y el proveedor los admiten. Las páginas de los modelos muestran los precios de cada nivel cuando Phaseo los tiene.

## Qué pasa cuando no se ofrece un nivel

Phaseo conserva solo las rutas de proveedor que ofrecen el nivel solicitado; nunca recurre a otro nivel. Si ninguna ruta lo ofrece, la solicitud falla con `400 unsupported_model_or_endpoint`, motivo `service_tier_not_supported`.

Otros valores fallan con `400 validation_error`:

- `service_tier: "batch"` en una solicitud síncrona (palabra clave `batch_service_tier_not_supported`). Usa la Batch API en su lugar.
- Cualquier valor distinto de `standard`, `default`, `fast`, `ultrafast`, `priority`, `flex` o `batch` (palabra clave `unsupported_service_tier`).

Siempre envías estos valores del Gateway. Phaseo los traduce a los controles propios de cada proveedor; por ejemplo, una ruta de Anthropic recibe los campos de nivel de Anthropic.

## Solicita un nivel en cada endpoint

<CodeGroup>
```json Responses
{
  "model": "openai/gpt-5.5",
  "input": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "flex"
}
```

```json Chat Completions
{
  "model": "openai/gpt-5.5",
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "flex"
}
```

```json Messages
{
  "model": "anthropic/claude-opus-5.5",
  "max_tokens": 512,
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "fast"
}
```
</CodeGroup>

Para `ultrafast`, usa un modelo cuya página muestre precios de Ultrafast.

## Mistral Priority y enrutamiento en la UE

El nivel Priority de Mistral necesita una cuenta empresarial de Mistral apta. Phaseo asigna `priority` al modo de prioridad automática de Mistral y factura el nivel que indica Mistral: si Mistral recurre a Standard, pagas precios de Standard.

Que haya un precio en el catálogo no hace que un nivel sea enrutable. Priority sigue desactivado salvo que la ruta concreta de Mistral anuncie compatibilidad con Priority, y la aptitud sigue dependiendo de la cuenta y el modelo de Mistral.

GLM 5.2 se puede fijar al endpoint regional de Mistral en la UE con la oferta de proveedor `mistral-eu`:

```json
{
  "model": "z-ai/glm-5.2",
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "priority",
  "provider": {
    "only": ["mistral-eu"],
    "required_execution_region": "eu"
  }
}
```

La inferencia regional de Mistral cuesta un 10% más. Los precios de Batch solo están disponibles en la oferta global de Mistral a través de la Batch API; Mistral no admite Batch en los endpoints regionales.

La referencia completa del campo está en [Parámetros](../api-reference/parameters.mdx); para ver cómo se combinan los niveles con el orden de proveedores y las alternativas, consulta [Enrutamiento y alternativas](./routing-and-fallbacks.mdx).
