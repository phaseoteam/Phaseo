title: "Enrutar solicitudes de texto por región"
description: "Limita la generación de texto de Phaseo a rutas de proveedor de la UE o de EE. UU."
---

Envía las solicitudes de texto a `eu.api.phaseo.app` o a `us.api.phaseo.app` para usar solo las rutas de proveedor que ejecutan el modelo y tratan los datos de prompts y respuestas en esa región. Los ID de modelo y las claves de API no cambian. Se admiten Chat Completions, Responses y Messages.

| Región | URL base | Rutas de proveedor que se usan |
| --- | --- | --- |
| Unión Europea | `https://eu.api.phaseo.app/v1` | Solo las rutas que declaran ejecución en la UE y tratamiento de datos en la UE |
| Estados Unidos | `https://us.api.phaseo.app/v1` | Solo las rutas que declaran ejecución en EE. UU. y tratamiento de datos en EE. UU. |
| Global | `https://api.phaseo.app/v1` | La política de enrutamiento global estándar |

<Warning>
El enrutamiento regional todavía no es una garantía de residencia de datos de extremo a extremo. Phaseo limita la selección de proveedores y sitúa el Gateway cerca de la región, pero los sistemas compartidos de cuentas, facturación, caché y operaciones pueden procesar datos fuera de ella. Consulta [Qué queda fuera de la región](#what-stays-outside-the-region).
</Warning>

## Envía una solicitud regional

<CodeGroup>
```ts TypeScript
import { Phaseo } from "@phaseo/sdk";

const phaseo = new Phaseo({
  apiKey: process.env.PHASEO_API_KEY!,
  region: "eu",
});

const response = await phaseo.responses.create({
  model: "openai/gpt-5.6-luna",
  input: "Summarize this note in one sentence.",
});

console.log(response.output_text);
```

```python Python
import os
from phaseo import Phaseo

phaseo = Phaseo(
    api_key=os.environ["PHASEO_API_KEY"],
    region="eu",
)

response = phaseo.responses.create({
    "model": "openai/gpt-5.6-luna",
    "input": "Summarize this note in one sentence.",
})

print(response.get("output_text"))
```

```bash Chat Completions
curl https://eu.api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5.6-luna",
    "messages": [
      {"role": "user", "content": "Write a two-line status update."}
    ]
  }'
```

```bash Responses
curl https://eu.api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5.6-luna",
    "input": "Extract the three most important actions from this note."
  }'
```

```bash Messages
curl https://us.api.phaseo.app/v1/messages \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -H "anthropic-version: 2023-06-01" \
  -d '{
    "model": "anthropic/claude-sonnet-5.5",
    "max_tokens": 256,
    "messages": [
      {"role": "user", "content": "Summarize this incident report."}
    ]
  }'
```
</CodeGroup>

En los SDK, establece `region` en `"eu"` o `"us"`; omítelo, o usa `"global"`, para el enrutamiento global. El SDK lanza un error si estableces a la vez `region` y una `baseUrl` personalizada (`base_url` en Python), porque eligen hosts distintos.

El nombre de host es la política. Un `required_execution_region` o `required_data_region` en la solicitud o en un preajuste que nombre otra región falla con `400 validation_error`, motivo `deployment_region_conflict`. Los preajustes y las reglas de enrutamiento dinámico se aplican primero y la regla regional al final, así que no pueden debilitarla. Phaseo nunca reintenta a través de un proveedor fuera de la región.

## Qué puede contener una solicitud regional

| Se admite | Se rechaza |
| --- | --- |
| Entrada de texto y salida de texto | Imágenes, audio, vídeo, documentos, archivos y adjuntos |
| Con y sin streaming | Modalidades de salida que no son texto |
| Instrucciones de sistema y de desarrollador | Herramientas alojadas por el proveedor, como búsqueda web, búsqueda de archivos, ejecución de código, uso del ordenador y generación de imágenes, y `web_search_options` |
| Tus propias herramientas `function` y `custom`, y resultados de herramientas en texto | [Herramientas de servidor](./server-tools) de Phaseo (tipos `phaseo:`) |
| Salida de texto estructurado y JSON, cuando el modelo lo admite | Endpoints de imagen, audio, vídeo, embeddings, moderación, lotes, archivos, webhooks y tiempo real |
| Preajustes, orden de proveedores, alternativas y límites de precio que no entren en conflicto con la región | |

Tus propias herramientas están permitidas porque se ejecutan en tu aplicación. Las herramientas alojadas y de servidor se ejecutan en lugares que la regla regional no puede controlar.

## Busca los modelos disponibles en una región

Llama a `/v1/models` en el mismo nombre de host al que envías las solicitudes. La disponibilidad varía entre los endpoints de la UE, de EE. UU. y global.

```bash
curl https://eu.api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

La lista solo contiene modelos con una ruta de proveedor activa cuyas regiones declaradas de ejecución y de datos incluyen ambas la región, y solo anuncia Chat Completions, Responses y Messages con entrada y salida de texto. Cada oferta muestra sus regiones:

```json
{
  "provider": { "id": "example-eu", "name": "Example EU" },
  "residency": {
    "execution_regions": ["eu"],
    "data_regions": ["eu"]
  }
}
```

## Comprueba qué Gateway gestionó una solicitud

Las respuestas regionales llevan `X-Phaseo-Gateway-Region: eu` (o `us`). El encabezado nombra la política regional que gestionó la solicitud; no demuestra dónde la ejecutó Cloudflare. Los detalles de la solicitud también registran las regiones de ejecución y de datos requeridas, el proveedor seleccionado y las regiones que declara ese proveedor.

## Errores

Las infracciones de la regla regional devuelven `400 not_supported` con uno de estos valores de `reason`:

| `reason` | Causa | Solución |
| --- | --- | --- |
| `regional_endpoint_not_supported` | La ruta no está disponible de forma regional | Usa Chat Completions, Responses o Messages, o la API global |
| `regional_non_text_content` | Hay contenido multimedia, un archivo o un adjunto en la solicitud | Quítalo o usa la API global |
| `regional_non_text_output` | Se pidió una modalidad de salida que no es texto | Pide texto o usa la API global |
| `regional_hosted_tool_not_supported` | Una herramienta que no es `function` ni `custom` | Usa tu propia herramienta de función o la API global |

`400 validation_error` con el motivo `deployment_region_conflict` significa que la solicitud o un preajuste nombra otra región; quita ese ajuste. Si ninguna ruta de proveedor en buen estado cumple a la vez con el modelo y con la región, la solicitud se detiene antes de llamar a ningún proveedor; elige un modelo de los que muestra el `/v1/models` regional.

## Qué queda fuera de la región

La regla regional abarca qué proveedor ejecuta el modelo y trata los datos de prompts y respuestas. Todavía no abarca todo el ciclo de vida de la solicitud:

- La ubicación de Cloudflare sitúa el Gateway cerca de la región, pero no es un límite de cumplimiento normativo.
- Los datos de cuenta, autenticación, facturación y metadatos de solicitudes residen en una infraestructura compartida de Supabase.
- Cloudflare KV y los registros de invocación de Workers no están ligados a una región.
- Las llamadas al proveedor van al endpoint regional de ese proveedor, independientemente de dónde haya situado Cloudflare el Gateway.
- El personal de soporte y operaciones no está restringido a la región.

Phaseo solo llamará a esto residencia de datos de extremo a extremo cuando el Gateway, el almacenamiento, los registros, el proveedor y las rutas operativas tengan todos controles regionales aplicables.
