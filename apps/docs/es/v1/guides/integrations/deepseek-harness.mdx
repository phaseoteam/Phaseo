Ejecuta `phaseo deepseek-harness` para añadir Phaseo al selector de modelos de DeepSeek Harness, o añade un proveedor personalizado en la interfaz de Harness o en `settings.yaml`. Harness envía solicitudes de Chat Completions compatibles con OpenAI directamente a Phaseo, así que no hace falta ningún adaptador.

## Configura con la CLI de Phaseo

```bash
phaseo login
phaseo deepseek-harness
```

Si falta Harness, la CLI muestra el comando de instalación oficial y pide confirmación antes de ejecutarlo. Después, la configuración:

- escribe el proveedor, la URL base, el protocolo, el catálogo de modelos y el modelo predeterminado en `$DSH_HOME/cordis.patch.yml` (`DSH_HOME` es `~/.dsh` por defecto), dentro de un bloque marcado para poder actualizar o quitar más adelante solo sus propios ajustes;
- añade todos los modelos de texto activos de Phaseo que funcionan con Chat Completions. Usa `--catalog default` para añadir solo el modelo predeterminado;
- crea una `Phaseo CLI: DeepSeek Harness API Key` que caduca a los 90 días y tiene un límite de gasto mensual de $100, y la escribe en el archivo protegido `$DSH_HOME/.credentials.yaml` de Harness. Vuelve a ejecutar `phaseo deepseek-harness` para sustituir una clave caducada.

El modelo predeterminado es `anthropic/claude-sonnet-4.6`. Para elegir otro:

```bash
phaseo deepseek-harness --model YOUR_PHASEO_MODEL_ID
```

## Añade Phaseo en la interfaz de Harness

1. Abre **Settings > Models** y elige **Add a custom provider**.
2. Introduce:

| Campo | Valor |
| --- | --- |
| Provider ID | `phaseo` |
| Display name | `Phaseo` |
| Base URL | `https://api.phaseo.app/v1` |
| API protocol | `OpenAI Completions` |
| API key | Una clave de API de Phaseo |

3. En **Model catalog**, elige **Fetch available models**.
4. Selecciona un modelo de Chat Completions compatible con herramientas, como `anthropic/claude-sonnet-5.5`, y guarda el proveedor.
5. En el compositor, elige el modelo de Phaseo e inicia una sesión nueva.

Las sesiones guardadas y las referencias a credenciales conservan el ID del proveedor, así que considera `phaseo` como permanente. Más adelante puedes editar el nombre visible, la URL, la clave y la lista de modelos.

## Configura Phaseo en settings.yaml

Puedes configurar el mismo proveedor en `$DSH_HOME/settings.yaml`. No pongas la clave en este archivo: `apiKeyEnv` indica la variable de la que Harness la lee.

```yaml $DSH_HOME/settings.yaml
llm-pi-ai:
  providers:
    phaseo:
      displayName: Phaseo
      apiKeyEnv: PHASEO_API_KEY
      api: openai-completions
      baseURL: https://api.phaseo.app/v1
      models:
        - id: YOUR_PHASEO_MODEL_ID
```

Establece `PHASEO_API_KEY` en el entorno que inicia Harness, o guarda la clave en la página Models. Sustituye `YOUR_PHASEO_MODEL_ID` por un ID exacto de Phaseo; para agentes de programación, empieza con `anthropic/claude-sonnet-5.5`. La lista `models` es un catálogo guardado, no una consulta en directo, así que actualízala cuando quieras más modelos de Phaseo en Harness.

## Comprueba que funciona

Comprueba primero la clave y el descubrimiento de modelos:

```bash
curl https://api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

Después selecciona un modelo de Phaseo en una sesión nueva de Harness y envía `Reply with exactly: Phaseo is connected.` Una respuesta confirma todo el recorrido desde Harness, a través de Phaseo, hasta el proveedor del modelo. La solicitud también aparece en **Ajustes → Uso → Registros**. Las solicitudes reales se facturan como uso normal.

## Quita Phaseo

```bash
phaseo integrations remove deepseek-harness
```

Esto quita solo la configuración que pertenece a Phaseo y revoca la clave.

## Soluciona problemas habituales

| Problema | Solución |
| --- | --- |
| Obtener los modelos devuelve `401` | Comprueba que la clave está vigente y que la URL base incluye `/v1`. |
| El modelo no aparece en el selector | Vuelve a obtener el catálogo, o añade el ID exacto del modelo en `models` dentro de `settings.yaml`. |
| Harness indica `MISSING_CREDENTIAL` | Guarda la clave en la página Models, o haz que `PHASEO_API_KEY` esté disponible para el proceso de Harness. |
| Las solicitudes van al endpoint equivocado | Selecciona `OpenAI Completions` (`openai-completions`). Este proveedor usa `/v1/chat/completions` de Phaseo. |
| Un modelo rechaza las herramientas de función con el razonamiento activado | Elige un modelo que admita herramientas en Chat Completions. Los modelos que necesitan la API de Responses para razonar con herramientas no funcionan con este protocolo. |
| Una sesión conserva su modelo anterior | Inicia una sesión nueva. Harness guarda el proveedor y el modelo en las sesiones que ya han enviado una solicitud. |
