Instala `@phaseo/cli` y ejecuta `phaseo login` para conectar agentes de programación a Phaseo y gestionar claves, espacios de trabajo, preajustes, ajustes y guardrails desde la terminal. La CLI también consulta modelos, proveedores, precios, créditos, actividad, analíticas y generaciones.

## Instala

<CodeGroup>

```bash npm
npm install -g @phaseo/cli
```

```bash pnpm
pnpm add -g @phaseo/cli
```

```bash yarn
yarn global add @phaseo/cli
```

```bash bun
bun add -g @phaseo/cli
```

</CodeGroup>

Comprueba la versión:

| Comando | Muestra |
| --- | --- |
| `phaseo --version` | La versión instalada. |
| `phaseo version` | La versión y el comando de actualización para tu gestor de paquetes. Añade `--json` para obtener una salida estructurada. |

Las ejecuciones interactivas también muestran un aviso cuando se publica una versión más reciente.

## Inicia sesión

```bash
phaseo login
```

| Flujo | Flag | Úsalo para |
| --- | --- | --- |
| Iniciar sesión con Phaseo | `--browser` | OAuth en el navegador con código de autorización y PKCE. |
| Iniciar sesión con código de dispositivo | `--device-code` | SSH, CI, shells sin interfaz gráfica y entornos de agentes. |

Los entornos remotos y no interactivos usan el código de dispositivo automáticamente. Comprueba con qué cuenta has iniciado sesión, junto con tus permisos, el espacio de trabajo activo y los demás espacios de trabajo:

```bash
phaseo whoami
phaseo whoami --json
```

## Gestiona tu espacio de trabajo

```bash
phaseo keys list
phaseo keys current

phaseo workspaces list
phaseo workspaces members <workspace-id-or-slug>

phaseo guardrails list
```

Usa `--json` cuando un agente o un script lea la salida. La CLI cubre las tareas habituales de la cuenta; los límites de las claves, los presupuestos, BYOK, las reglas de enrutamiento, los preajustes y la identidad se cambian en el panel o con una clave de administración. Consulta [Gestiona Phaseo desde un agente](../../developers/manage-from-an-agent) para ver qué tareas cubre la CLI.

## Conecta un agente de programación

Usa el nombre del agente como comando. La CLI pide una clave propia, que apruebas en el navegador, y escribe la configuración del agente:

```bash
phaseo codex
phaseo claude-code
phaseo opencode
phaseo fx
phaseo deepseek-harness
phaseo pi
phaseo prime-agent
phaseo openclaw
phaseo hermes
phaseo aider
phaseo continue
phaseo zed
phaseo roo-code
phaseo kilo-code
phaseo cursor
```

Usa `--model`, `--catalog all|default` o `--dry-run` según lo necesites. `phaseo setup <agent>` y `phaseo integrations setup <agent>` también funcionan.

### Aprueba la clave en el navegador

La primera vez que configuras un agente, la CLI abre una página del panel de Phaseo y muestra su enlace. La página indica el espacio de trabajo, el nombre de la clave, su límite de gasto mensual de $100 y su caducidad a los 90 días, y que la pidió la CLI de Phaseo. Elige **Aprobar y crear clave** y la CLI recoge la clave una sola vez y termina la configuración. Si eliges **Rechazar**, o dejas la solicitud 10 minutos hasta que caduque, no se crea nada.

Aprueba con la sesión iniciada en el panel con la cuenta que usaste en la CLI, como propietario o administrador del espacio de trabajo y con tu segundo factor si lo has configurado. Por SSH o en CI, abre el enlace mostrado en cualquier dispositivo en el que hayas iniciado sesión.

Para usar en su lugar una clave que creaste en el panel, pásala con `--key <key>`, o con `--key-stdin` para que no quede en el historial de la shell. La CLI comprueba la clave y la guarda, y no la revoca cuando quitas el agente.

Para ejecutar Cline, Kilo Code, oh-my-pi, Muse Code o MiniMax Code con ajustes temporales que se borran al cerrarse, usa el ejecutor de sesiones. Los flags de Phaseo van antes de `--`, y los del propio agente, después:

```bash
phaseo cline --model openai/gpt-5.6-terra -- --tui
phaseo kilo --model openai/gpt-5.6-terra
phaseo omp --model openai/gpt-5.6-terra
phaseo muse --model meta/muse-spark-1.3
phaseo minimax --model openai/gpt-5.6-terra
```

`phaseo run <cline|kilo|omp|muse|minimax>` es la forma larga. Añade `--catalog all` para mostrar todos los modelos de texto activos de Phaseo, o `--dry-run --json` para previsualizar sin crear una clave. En una terminal interactiva, los ejecutores ofrecen instalar el agente si falta (MiniMax Code usa su instalador oficial de PowerShell en Windows; Muse Code se tiene que instalar a mano en Windows). Usa `--skip-install` cuando gestiones tú el agente.

[Agentes de programación](./coding-assistants.mdx) muestra todos los agentes, qué hace su comando y su guía.

## Usa la CLI en scripts

Los comandos con `--json` muestran una salida estructurada simple, sin colores ni indicadores de progreso. En el resto de casos, los indicadores de progreso van a `stderr` y borran su línea al terminar.

| Variable | Efecto |
| --- | --- |
| `NO_COLOR` | Desactiva los colores. |
| `TERM=dumb` | Desactiva la animación. Un `stderr` que no es TTY tiene el mismo efecto. |
| `FORCE_COLOR=1` | Fuerza los colores cuando un wrapper de terminal los admite pero no indica que es un TTY. |

## Cómo protege la CLI las credenciales

- Las sesiones se guardan en el almacén de credenciales del sistema operativo. Establece `PHASEO_SESSION_BACKEND=file` solo si no hay ningún almacén de credenciales disponible; guarda los tokens de actualización en un archivo de texto plano con permisos restringidos.
- `phaseo logout` revoca el token de actualización guardado antes de borrar el estado local.
- Las claves de administración necesitan capacidades explícitas. Las claves de inferencia se limitan con guardrails, políticas de enrutamiento y ajustes del espacio de trabajo, no con permisos.

## Aplicaciones OAuth

Phaseo usa un único servidor de autorización OAuth para la CLI, las aplicaciones creadas por los usuarios y los clientes MCP registrados dinámicamente. La CLI usa el inicio de sesión en el navegador o con código de dispositivo, con tokens de actualización rotatorios. Los clientes de terceros usan el código de autorización con PKCE, permisos explícitos y consentimiento por espacio de trabajo, y la vinculación opcional a un recurso protegido. Reciben un token de acceso revocable que dura 7 días y un token de actualización rotatorio que dura 90 días desde su último uso; consulta [Crea un Workbench OAuth con Next.js](../../cookbook/build-an-oauth-nextjs-workbench) para ver cómo funciona la actualización. Aprobar de nuevo la misma aplicación renueva su clave en lugar de añadir otra.

La API de Phaseo alojada tiene OAuth de terceros activado. Los despliegues de la API autoalojados y de vista previa lo mantienen desactivado salvo que `PHASEO_THIRD_PARTY_OAUTH_ENABLED` tenga un valor verdadero: `1`, `true`, `yes` u `on`, sin distinguir mayúsculas y minúsculas, e ignorando los espacios alrededor.

```bash .env
PHASEO_THIRD_PARTY_OAUTH_ENABLED=true
```

Activarlo expone la gestión de aplicaciones OAuth creadas por los usuarios y el registro dinámico de clientes, así que revisa primero tus ajustes de URI de redirección, consentimiento, secretos de cliente, límites de velocidad y autorización del espacio de trabajo.

## Actualiza

```bash
phaseo update
```

Esto ejecuta la actualización con el gestor de paquetes con el que instalaste la CLI. Para actualizar a mano:

<CodeGroup>

```bash npm
npm install -g @phaseo/cli@latest
```

```bash pnpm
pnpm add -g @phaseo/cli@latest
```

```bash yarn
yarn global add @phaseo/cli@latest
```

```bash bun
bun add -g @phaseo/cli@latest
```

</CodeGroup>
