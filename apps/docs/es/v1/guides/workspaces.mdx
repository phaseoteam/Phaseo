Crea un espacio de trabajo para cada equipo, producto o entorno para mantener separados sus claves de API, ajustes de enrutamiento, presets, guardrails y acceso administrativo. Cada cuenta empieza con un espacio de trabajo personal, que basta para una integración pequeña.

Los espacios de trabajo separados ayudan cuando quieres:

- aislar las credenciales de desarrollo, staging y producción
- mantener separados distintos productos o proyectos de clientes
- dar a una integración administrativa acceso solo a los recursos que necesita
- aplicar distintas políticas de enrutamiento, presets o guardrails

Los espacios de trabajo no cambian tus precios: todo el uso sigue en la facturación estándar de pago por uso, descrita en [Precios y facturación](../pricing/tiers). Los espacios de trabajo adicionales se desbloquean después de tu primer depósito de créditos; hasta entonces, crear uno falla con `403 workspace_upgrade_required`.

## Gestionar espacios de trabajo desde la API

Gestiona los espacios de trabajo en el panel o con la API de gestión. La API necesita una [clave de gestión](../developers/management-api-keys); las claves de API normales del Gateway son para inferencia y no pueden llamar a estos endpoints.

| Tarea | Endpoint | Capacidad |
| --- | --- | --- |
| Listar espacios de trabajo | [`GET /workspaces`](../api-reference/endpoint/workspaces-list) | `workspaces:read` |
| Leer un espacio de trabajo | [`GET /workspaces/{id}`](../api-reference/endpoint/workspaces-get) | `workspaces:read` |
| Crear un espacio de trabajo | [`POST /workspaces`](../api-reference/endpoint/workspaces-create) | `workspaces:write` |
| Actualizar un espacio de trabajo | [`PATCH /workspaces/{id}`](../api-reference/endpoint/workspaces-update) | `workspaces:write` |
| Eliminar un espacio de trabajo | [`DELETE /workspaces/{id}`](../api-reference/endpoint/workspaces-delete) | `workspaces:delete` |

Da a la clave solo las capacidades que necesita. Phaseo también comprueba la pertenencia al espacio de trabajo y el rol, así que una capacidad por sí sola nunca da acceso a otro espacio de trabajo. El `slug` de un espacio de trabajo nuevo debe tener de 1 a 50 letras minúsculas, números o guiones.

Guarda las claves de gestión en un almacén de secretos del servidor, nunca en código del navegador, registros de escritorio, control de código fuente ni chats.

<Note>
Los endpoints de espacios de trabajo están en beta. Haz que la automatización se pueda reintentar con seguridad y comprueba cada respuesta antes de hacer un cambio posterior.
</Note>

## Cambiar el nombre de un espacio de trabajo o eliminarlo

El espacio de trabajo personal (predeterminado) no se puede renombrar ni eliminar; ambas operaciones devuelven `400 bad_request`. Antes de eliminar otro espacio de trabajo, elimina o traslada sus claves de API activas para que ninguna solicitud apunte a un espacio de trabajo que ya no existe.
