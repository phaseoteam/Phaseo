Un preajuste guarda el modelo, el prompt de sistema, los parámetros y las reglas de proveedor de una tarea con un nombre como `@support-triage`. Quien hace la llamada envía ese nombre como `model` y solo la entrada; el Gateway completa el resto antes de elegir un proveedor.

Activa y desactiva los campos de la solicitud para ver qué valor prevalece:

<PresetMergeExplorer locale="es" />

Las reglas son:

- **Los parámetros rellenan huecos.** Los parámetros predeterminados de un preajuste solo se aplican a los campos que la solicitud omite. Un valor de la solicitud siempre prevalece.
- **Los prompts de sistema se acumulan.** El prompt del preajuste va primero. Si la solicitud tiene su propio prompt de sistema o `instructions`, va a continuación, tras una línea en blanco.
- **Los ajustes de proveedor de la solicitud prevalecen.** Campos como `provider.order` o `provider.max_price` en la solicitud sustituyen el valor del preajuste para ese campo.
- **Las listas de permitidos restringen, nunca amplían.** Las listas de proveedores permitidos e ignorados del preajuste se aplican antes de seleccionar el proveedor, así que también limitan qué proveedores puede usar una alternativa. Un modelo que no está entre los modelos permitidos del preajuste falla con un `validation_error` cuya palabra clave de detalle es `preset_model_not_allowed`; no se redirige.

## Crea y usa un preajuste

<Steps>
<Step title="Crea el preajuste">

Abre **Panel -> Ajustes -> Presets** y crea un preajuste con un slug como `support-triage`. Añade solo los valores predeterminados que deban compartir todos los que hacen llamadas.

Desde la CLI: `phaseo presets create --name @support-triage --model <model-id>`.

</Step>

<Step title="Llámalo por su nombre">

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "@support-triage",
    "input": "Customer says the invoice total is wrong."
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "@support-triage",
  input: "Customer says the invoice total is wrong.",
});
```

```python Python
from phaseo import Phaseo

client = Phaseo(api_key="YOUR_API_KEY")

response = client.generate_response({
    "model": "@support-triage",
    "input": "Customer says the invoice total is wrong.",
})
```
</CodeGroup>

</Step>

<Step title="Comprueba qué se aplicó">

Abre la solicitud en **Gateway -> Uso** para ver qué valores predeterminados del preajuste se aplicaron y qué proveedor la atendió.

</Step>

## Qué puede incluir un preajuste

| Ajuste | Efecto |
| --- | --- |
| Modelo | Se usa cuando la solicitud se envía con el nombre del preajuste. |
| Modelos permitidos | ID de modelo o patrones como `anthropic/*`. Los demás modelos se rechazan. |
| Prompt de sistema | Se antepone a cada solicitud. |
| [Plantilla de prompt](./prompt-templates) | Mensajes con `{{variables}}` que cada solicitud completa. |
| Parámetros predeterminados | `temperature`, `top_p`, `max_tokens`, ajustes de razonamiento y similares. |
| Reglas de proveedor | Listas de permitidos e ignorados, orden de proveedores, regiones, precios máximos. |

Mantén la lógica específica de cada llamada en tu aplicación y usa preajustes distintos cuando los flujos de trabajo necesiten prompts, enrutamiento o almacenamiento en caché diferentes.

## Nombra un preajuste

Envía un preajuste mediante el campo `model`, o mediante `prompt.id` cuando tiene una [plantilla de prompt](./prompt-templates). No existe un campo `preset` independiente.

| Forma | Se resuelve en |
| --- | --- |
| `@support-triage` | El espacio de trabajo de la clave de API (preajustes privados y del espacio de trabajo). |
| `@octavia/support-triage` | Cualquier espacio de trabajo (preajustes públicos, publicados por el usuario `octavia`). |
| `@support-triage@v3` | Esa versión publicada. |
| `@support-triage@production` | La versión a la que apunte la etiqueta `production`. |

Para publicar un preajuste público se necesitan un perfil público habilitado y un nombre de usuario. Los nombres de usuario son únicos en todo Phaseo; los slugs solo tienen que ser únicos para cada autor. Los slugs se convierten a minúsculas y pueden contener letras, números, `-`, `_`, `.` y `:`.

## Versiona y revierte

Al guardar se edita un borrador privado. **Publicar nueva versión** convierte el borrador en una versión numerada e inmutable y conserva todas las anteriores.

Elige el formato de las etiquetas de versión:

| Formato | Ejemplo |
| --- | --- |
| Secuencial | `v1`, `v2`, `v3` |
| Versionado semántico | `1.2.0`, `2.0.0-beta.1`, `1.4.2+build.7` |
| Fecha | `2026.08.02`, y después `2026.08.02.2` para una segunda versión ese mismo día |

Apunta una etiqueta con nombre, como `production`, a una versión, y devuélvela a una versión anterior para revertir. Consulta [Versiones y etiquetas](/es/v1/guides/prompt-templates#versions-and-labels).

Desde la CLI: `phaseo presets versions create` y `phaseo presets labels set`, o la API `/v1/presets`.

## Bifurca un preajuste del marketplace

Una copia de un preajuste del marketplace queda fijada en la versión que copiaste. Cuando el autor publica una actualización, tu copia muestra un aviso. Aplicarla solo cambia tu borrador, así que nada llega a producción hasta que lo publiques tú.

Phaseo registra el origen y la genealogía completa de cada bifurcación, de modo que una página del marketplace puede mostrar las bifurcaciones directas por separado de todos los descendientes.

Para recopilar valoraciones de las respuestas de un preajuste, consulta [Recopilar comentarios sobre preajustes](./preset-feedback).
