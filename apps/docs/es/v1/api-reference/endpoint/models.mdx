De forma predeterminada, este endpoint solo devuelve los modelos que se pueden enrutar actualmente. Define `availability=all` para incluir modelos conocidos que todavía no están disponibles.

`GET /models/me` está reservado para filtrar en el futuro los modelos según los guardrails del usuario actual. Ahora devuelve `501 not implemented`, así que por el momento usa `GET /models` para consultar el catálogo compartido de Gateway.

## Filtros útiles

- `endpoints` usa nombres públicos como `chat.completions`, `responses` y `messages`
- `status` filtra por ciclo de vida del modelo, por ejemplo `active`, `deprecated` o `retired`
- `provider` filtra por ID público del proveedor, por ejemplo `openai`, `anthropic` o `google_vertex`
- `provider_status` filtra por nivel de despliegue del proveedor, por ejemplo `active`, `beta`, `alpha` o `not_ready`
- `provider_routing_status` filtra por estado de enrutamiento del proveedor
- `model_routing_status` filtra por estado de enrutamiento del modelo
- `capability_status` filtra por estado de capacidad del proveedor para la asignación de endpoint solicitada
- `provider_availability_status` filtra por disponibilidad del proveedor, por ejemplo `active`, `coming_soon` o `inactive`
- `provider_availability_reason` filtra por motivo de disponibilidad del proveedor, por ejemplo `preview_only`, `provider_not_ready`, `gated`, `access_limited` o `region_limited`
- `organisation` filtra por el prefijo del ID público del modelo; por ejemplo, `anthropic` en `anthropic/claude-3-haiku`
- `availability=active` es el valor predeterminado
- `availability=all` incluye modelos o proveedores que están `coming_soon`, `inactive` o aún no se pueden enrutar públicamente
- `input_modalities` es un alias de `input_types`
- `output_modalities` es un alias de `output_types`
- `supported_parameters` es un alias de `params`

Para consultar el contrato de endpoint de un modelo, llama a `GET /models/{author}/{slug}/endpoints`. La respuesta separa las rutas por proveedor e incluye, en cada fila, la ruta pública, las modalidades, los detalles de los parámetros compatibles, la disponibilidad, el estado de enrutamiento, el slug del modelo del proveedor y un resumen de precios.

Las entradas de proveedores también pueden incluir:

- `availability_status`
- `availability_reason`
- `provider_status`
- `provider_routing_status`
- `model_routing_status`
- `capability_status`
