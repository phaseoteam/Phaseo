Llama a `GET /v1/models` para listar los modelos a los que puedes enrutar ahora mismo. Configura `availability=all` para incluir los modelos conocidos que no están disponibles en este momento.

```bash
curl "https://api.phaseo.app/v1/models?limit=50" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

Cada modelo incluye una entrada en `offers` por cada ruta de proveedor (resumido, valores ilustrativos):

```json
{
  "ok": true,
  "availability_mode": "active",
  "limit": 50,
  "offset": 0,
  "total": 412,
  "models": [
    {
      "id": "anthropic/claude-sonnet-5.5",
      "name": "Claude Sonnet 5.5",
      "organization": { "id": "anthropic", "name": "Anthropic", "color": "#d97757" },
      "lifecycle": { "status": "active", "released_at": "2026-09-28", "replacement_id": null },
      "modalities": { "input": ["text", "image"], "output": ["text"] },
      "capabilities": { "endpoints": ["chat.completions", "messages", "responses"] },
      "availability": { "status": "active", "provider_count": 3, "active_provider_count": 3 },
      "offers": [
        {
          "provider": { "id": "anthropic", "name": "Anthropic" },
          "model": "claude-sonnet-5-5",
          "status": "active",
          "status_reason": null,
          "routable": true,
          "service_tiers": ["standard"],
          "routing": { "provider": "active", "model": "active", "capability": "active" }
        }
      ]
    }
  ]
}
```

Enruta tráfico de producción solo a una oferta cuyo `routable` sea `true`. `status_reason` explica por qué una oferta está solo en vista previa o inactiva. El esquema completo aparece más abajo.

`GET /models/me` devuelve la misma lista con los guardrails de tu clave aplicados: las reglas de privacidad y de proveedores de tu espacio de trabajo, y los guardrails de los departamentos de la clave, de su miembro y de la propia clave. Se omiten los modelos que bloquea una regla de modelos y los que no tienen ningún proveedor permitido, y cada modelo conserva solo las ofertas a las que se pueden enviar sus solicitudes. Acepta los mismos filtros que `GET /models`.

## Filtra la lista

Los filtros que aceptan varios valores admiten parámetros repetidos o una lista separada por comas.

| Parámetro | Filtra por |
| --- | --- |
| `availability` | `active` (predeterminado) para los modelos enrutables públicamente, o `all` para añadir modelos y proveedores `coming_soon`, `inactive` y aún no enrutables |
| `endpoints` | Nombres de endpoints públicos, como `chat.completions`, `responses` y `messages` |
| `status` | Ciclo de vida del modelo, como `active`, `deprecated` o `retired` |
| `organisation` | Prefijo del ID del modelo, como `anthropic` en `anthropic/claude-3-haiku` |
| `provider` | ID público del proveedor, como `openai`, `anthropic` o `google_vertex` |
| `provider_status` | Nivel de despliegue del proveedor, como `active`, `beta`, `alpha` o `not_ready` |
| `provider_routing_status` | Estado de enrutamiento a nivel de proveedor |
| `model_routing_status` | Estado de enrutamiento a nivel de modelo |
| `capability_status` | Estado de la capacidad del proveedor para la asignación de endpoint solicitada |
| `provider_availability_status` | Disponibilidad en el proveedor, como `active`, `coming_soon` o `inactive` |
| `provider_availability_reason` | Por qué un proveedor no está disponible, como `preview_only`, `provider_not_ready`, `gated`, `access_limited` o `region_limited` |
| `input_types` (alias `input_modalities`) | Modalidades de entrada |
| `output_types` (alias `output_modalities`) | Modalidades de salida |
| `params` (alias `supported_parameters`) | Parámetros de solicitud admitidos |

Para consultar las rutas de proveedores, el detalle de parámetros y los precios de un modelo, llama a [`GET /models/{author}/{slug}/endpoints`](./model-endpoints.mdx).

## Comprueba los niveles de servicio de cada oferta

Cada entrada de `offers` incluye `service_tiers`, los [niveles de servicio](../../guides/service-tiers.mdx) que acepta esa oferta del proveedor. Es un subconjunto ordenado alfabéticamente de `flex`, `priority`, `standard` y `ultrafast`, donde `priority` es el nivel Fast. Un nivel aparece cuando la ruta del proveedor tiene precios activos y vigentes para él, y una ruta que atiende un solo nivel enumera solo ese nivel. Algunos niveles también están disponibles mediante rutas de proveedor específicas de cada nivel que no aparecen en la lista. Los precios de `pricing` siguen siendo los del nivel estándar.

## Obtén la lista en formato OpenAI

Usa `GET /v1/models?format=openai` para los clientes que esperan la respuesta de lista de modelos de OpenAI. El valor predeterminado `format=json` devuelve los metadatos de modelo más completos de Phaseo.

```bash
curl "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

```json
{
  "object": "list",
  "data": [
    { "id": "openai/gpt-6-astra", "object": "model", "created": 1788393600, "owned_by": "openai" }
  ]
}
```

El formato OpenAI usa la misma autenticación, disponibilidad regional, modelos privados del espacio de trabajo y filtros que el JSON nativo. Devuelve todos los modelos que coinciden salvo que indiques `limit`; `offset` se sigue aplicando. Los IDs se mantienen en la forma canónica de Phaseo para la inferencia. `created` usa la fecha de lanzamiento del catálogo, o `0` si se desconoce; `owned_by` usa la organización del catálogo, `private` para los modelos del espacio de trabajo, o `phaseo` si se desconoce.

## Guarda en caché la lista de modelos

Las respuestas del catálogo se guardan en caché durante cinco minutos y pueden servirse otros cinco minutos mientras la caché se revalida. Esto se aplica a las representaciones JSON, RSS y Atom del catálogo actual; el feed de lanzamientos tiene su propia caché de consulta, más corta.

Las respuestas JSON y en formato OpenAI incluyen un encabezado `ETag` débil (`W/"…"`). Cambia cuando cambian los modelos de la página, `limit`, `offset`, `total` o el formato. Ignora `gateway_region`, así que el mismo catálogo servido desde otra región tiene el mismo `ETag`. Por eso es débil: las respuestas que lo comparten son equivalentes, pero sus bytes pueden diferir. Las respuestas RSS, Atom y de error no lo incluyen.

Devuelve el valor guardado sin cambios en `If-None-Match`. Si el catálogo no ha cambiado, la respuesta es `304 Not Modified` sin cuerpo y repite los encabezados `ETag`, `Cache-Control` y `Vary`. Si no, recibes un `200` normal con la nueva lista y un `ETag` nuevo. `If-None-Match` también acepta una lista separada por comas y `*`, y la comparación es débil, así que el valor coincide con o sin su prefijo `W/`.

```ts
let etag: string | null = null;
let models: unknown[] = [];

async function refreshModels() {
  const response = await fetch("https://api.phaseo.app/v1/models?limit=250", {
    headers: {
      Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
      ...(etag ? { "If-None-Match": etag } : {}),
    },
  });
  if (response.status === 304) return models; // Sin cambios; un 304 no tiene cuerpo.
  if (!response.ok) throw new Error(`Model list request failed: ${response.status}`);
  etag = response.headers.get("ETag");
  models = (await response.json()).models;
  return models;
}
```

Un `304` ahorra transferencia y análisis. El servidor sigue evaluando la solicitud: carga el catálogo y vuelve a calcular el `ETag`. Basta con consultar aproximadamente cada 15 minutos y descargar la lista de nuevo solo cuando cambia el catálogo. Guarda un `ETag` por URL de solicitud, porque cada página, conjunto de filtros y formato tiene su propio valor.
