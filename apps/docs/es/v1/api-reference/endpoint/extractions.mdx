<Warning>La extracción está en vista previa. La disponibilidad de modelos depende de las rutas de proveedores configuradas.</Warning>

Indica los `fields` que quieres y envíalos con tu texto de origen a `POST /v1/extractions` para recibir valores tipados, como un número de factura, una fecha o un total. Para elegir entre opciones conocidas, usa [Decisions](./decisions.mdx).

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/extractions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "cloudflare/clairic",
    "input": "Invoice INV-2291: 4 pallets at $250 each, shipping $80.",
    "fields": {
      "invoice_number": { "type": "text" },
      "total": { "type": "number", "decimals": 2, "instructions": "Total including shipping" }
    }
  }'
```

```typescript TypeScript SDK
import { Phaseo } from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY });
const result = await client.extractions.create({
  model: "cloudflare/clairic",
  input: "Invoice INV-2291: 4 pallets at $250 each, shipping $80.",
  fields: {
    invoice_number: { type: "text" },
    total: { type: "number", decimals: 2, instructions: "Total including shipping" },
  },
});
console.log(result.answers.total.value);
```

```python Python SDK
import os
from phaseo import Phaseo

client = Phaseo(api_key=os.environ["PHASEO_API_KEY"])
result = client.extractions.create({
    "model": "cloudflare/clairic",
    "input": "Invoice INV-2291: 4 pallets at $250 each, shipping $80.",
    "fields": {"total": {"type": "number", "decimals": 2,
                         "instructions": "Total including shipping"}},
})
print(result["answers"]["total"]["value"])
```
</CodeGroup>

Los ejemplos necesitan una ruta de modelo de extracción activa, así que comprueba
la disponibilidad del modelo antes de enviar solicitudes. `AsyncPhaseo` de Python
también expone `await client.extractions.create(...)`.

## Tipos de campo

Los tipos admitidos son `text`, `number`, `date`, `time`, `datetime`, `duration` y
`list`. Las listas requieren `items: "text"`, `"number"` o `"date"`. Proporciona de 1 a 64 campos
y como máximo 16.384 caracteres de origen. Los nombres de campo empiezan por una letra o un guion bajo
y contienen hasta 64 letras, dígitos, guiones bajos, puntos o guiones.

Los números y las duraciones admiten `integer` y `decimals` (0–6). Las duraciones aceptan
`seconds`, `minutes`, `hours`, `days`, `weeks`, `months` o `years`. Configura
`reference_date` cuando la interpretación de fechas incompletas dependa de un año concreto.

Las entradas de imagen usan objetos `{ content_type, base64 }`: como máximo cuatro imágenes
PNG/JPEG/WebP, de 4 MiB cada una y 8 MiB en total tras la decodificación. El límite de la solicitud es de 16 MiB.
No se admiten URLs remotas, PDFs, audio, vídeo, estimaciones, previsiones ni streaming.

## Lee las respuestas

Lee `answers[field_name].value`. Un valor escalar puede ser `null` cuando el origen
no lo determina. `p_null` es la probabilidad, según el modelo, de que el valor esté indeterminado;
`confidence` es una puntuación aparte que informa el modelo. Las listas proporcionan confianza sin
`p_null`. Estas puntuaciones no garantizan que el resultado sea correcto: elige umbrales de revisión para
tu carga de trabajo. Una lista vacía válida es distinta de una solicitud fallida.

`truncated: true` significa que el proveedor no procesó toda la entrada de origen. Revisa o
vuelve a enviar una entrada más corta antes de confiar en que esté completa. No se exponen los desplazamientos de texto ni las conjeturas sin procesar.
Los cálculos aritméticos complejos deben hacerse en el código de la aplicación.

Los informes de uso agregan `input_tokens` de todas las pasadas del proveedor. Los tokens de salida son
cero. Usa los precios que devuelve el gateway en lugar de estimar el coste a partir de la longitud del origen
o de multiplicar el uso por el número de campos.
