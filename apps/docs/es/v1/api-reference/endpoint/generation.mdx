Llama a `GET /v1/generations?id=<request_id>` para obtener el registro de auditoría guardado de una solicitud de tu espacio de trabajo. Necesita el scope `generations:read`; si falta `id`, devuelve `400` `missing_id`.

Las solicitudes nuevas reciben un ID de generación `G-` generado por el servidor, que se devuelve en el encabezado de respuesta `x-request-id` y en la respuesta de la generación. Usa ese ID para los registros de solicitudes, la consulta de generaciones y el soporte. Un `x-request-id` enviado por quien llama no sustituye el ID de generación. Los IDs de registro UUID antiguos siguen funcionando para las consultas.

## Repite una solicitud

Todas las respuestas incluyen `replay_supported`. Cuando el registro de E/S guardó el cuerpo de la solicitud y tienes permiso para leer el contenido guardado, `replay_supported` es `true` y `replay_request` contiene el cuerpo que debes reenviar para una repetición controlada:

<Steps>
  <Step title="Lee la generación">
    Llama a `GET /v1/generations?id=<request_id>`.
  </Step>
  <Step title="Comprueba que se puede repetir">
    Continúa solo si `replay_supported` es `true`.
  </Step>
  <Step title="Envíala de nuevo">
    Envía `replay_request` al endpoint indicado en `endpoint`, como `/v1/chat/completions` o `/v1/responses`.
  </Step>
</Steps>

Un espacio de trabajo puede limitar el contenido guardado a propietarios y administradores. Los demás, incluidas las claves de API creadas por miembros, reciben entonces `replay_request: null` y los detalles de la solicitud sin su contenido.
