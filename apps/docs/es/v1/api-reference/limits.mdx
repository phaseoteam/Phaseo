Actualmente, el Gateway no aplica un límite de solicitudes independiente a nivel de plataforma. La mayoría de las limitaciones provienen de los proveedores upstream.

## Cómo funcionan los límites

- El proveedor seleccionado para el modelo puede limitar la frecuencia de las solicitudes.
- El tráfico BYOK está sujeto a los límites de tu cuenta con el proveedor.
- El enrutamiento y los fallbacks del Gateway pueden reducir los fallos, pero aun así pueden aparecer errores `429`.

## Gestionar respuestas `429`

- Respeta `Retry-After` cuando esté presente.
- Aplica retroceso exponencial con variación aleatoria (jitter).
- Establece un número máximo de reintentos y gestiona el fallo de forma controlada.

Phaseo reenvía el valor validado de `Retry-After` cuando el proveedor seleccionado lo proporciona. En las solicitudes BYOK, también pueden devolverse detalles de cuota del proveedor mediante encabezados `X-Phaseo-Upstream-RateLimit-*`. Estos encabezados de cuota se omiten intencionalmente para solicitudes con proveedores administrados, ya que describen la capacidad compartida de Phaseo y no el límite de cada cliente. No se reenvían otros encabezados upstream.

```ts
async function retryWithBackoff(run: () => Promise<Response>, maxRetries = 4) {
  for (let attempt = 0; attempt <= maxRetries; attempt += 1) {
    const response = await run();
    if (response.status !== 429) return response;

    const retryAfterHeader = response.headers.get("retry-after");
    const retryAfterMs = retryAfterHeader
      ? Number(retryAfterHeader) * 1000
      : Math.min(1000 * 2 ** attempt, 8000);

    await new Promise((resolve) => setTimeout(resolve, retryAfterMs));
  }

  throw new Error("Rate limit retries exhausted");
}
```

## Supervisión

- Registra la tasa de errores `429` por endpoint y modelo.
- Observa la frecuencia de los fallbacks para detectar presión en los proveedores.
- Usa las métricas del panel junto con los registros de tu aplicación para investigar incidentes.
