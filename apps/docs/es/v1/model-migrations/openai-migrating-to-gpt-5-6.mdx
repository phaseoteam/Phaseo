Elige el nivel de GPT-5.6 que se ajuste a la carga de trabajo, cambia solo el ID de modelo y vuelve a probar el esfuerzo de razonamiento, las herramientas, la latencia y el coste. Mantén tu modelo GPT-5 anterior como respaldo hasta que pasen tus evaluaciones.

## Elige un nivel

| Modelo | Úsalo para | Esfuerzo de razonamiento |
| --- | --- | --- |
| `openai/gpt-5.6-sol` | Razonamiento de máxima capacidad, programación con agentes, análisis científico y trabajo profesional complejo | `none`, `low`, `medium`, `high`, `xhigh`, `max` |
| `openai/gpt-5.6-terra` | Razonamiento equilibrado para el día a día, programación y trabajo de asistente | `none`, `low`, `medium`, `high`, `xhigh`, `max` |
| `openai/gpt-5.6-luna` | Trabajo de menor latencia y sensible al coste | `none`, `low`, `medium`, `high`, `xhigh`, `max` |

Los tres tienen una ventana de contexto de 1.050.000 tokens y 128K tokens de salida. Cada uno tiene además un ID Pro (`openai/gpt-5.6-sol-pro`, `-terra-pro`, `-luna-pro`), que envía `reasoning.mode: "pro"` por ti.

El alias propio de OpenAI `gpt-5.6` apunta a `gpt-5.6-sol`; en Phaseo, llama directamente a los ID de nivel. Los alias de nivel `openai/gpt-sol-latest`, `openai/gpt-terra-latest` y `openai/gpt-luna-latest` siguen al modelo más reciente de cada nivel, y `openai/gpt-sol-latest` ya apunta más allá de GPT-5.6. Úsalos solo cuando quieras que las versiones futuras se adopten automáticamente.

## Actualiza la solicitud

GPT-5.6 añade `max`, el mayor presupuesto de razonamiento, en todos los niveles. Úsalo solo donde la latencia y el coste adicionales compensen.

<CodeGroup>
```json Responses
{
  "model": "openai/gpt-5.6-sol",
  "input": "Review this multi-service incident report and propose a rollback plan.",
  "reasoning": { "effort": "max" }
}
```

```json Chat Completions
{
  "model": "openai/gpt-5.6-terra",
  "messages": [
    { "role": "user", "content": "Design a test plan for this agent workflow." }
  ],
  "reasoning_effort": "medium"
}
```
</CodeGroup>

GPT-5.6 también añade:

- **`reasoning.mode: "pro"`** para tareas más difíciles, sin cambiar de modelo;
- **`reasoning.context`** (`auto`, `current_turn` o `all_turns`) para controlar qué razonamiento se conserva;
- compatibilidad multiagente en beta y Programmatic Tool Calling para flujos con mucho uso de herramientas;
- almacenamiento explícito en caché de prompts con `prompt_cache_options` y puntos de corte de caché. En GPT-5.6, `prompt_cache_options.ttl` sustituye a `prompt_cache_retention`, que Phaseo no envía a los modelos GPT-5.6.

## Revisa los precios

Precios por 1M de tokens en el nivel estándar de OpenAI, para solicitudes de hasta 272K tokens de entrada:

| Modelo | Entrada | Lectura de caché | Escritura de caché (30 min) | Escritura de caché (12 h) | Salida |
| --- | ---: | ---: | ---: | ---: | ---: |
| Sol | $5.00 | $0.50 | $6.25 | $12.50 | $30.00 |
| Terra | $2.00 | $0.20 | $2.50 | $5.00 | $12.00 |
| Luna | $0.20 | $0.02 | $0.25 | $0.50 | $1.20 |

Las solicitudes de más de 272K tokens de entrada cuestan más: Sol $10.00 de entrada y $45.00 de salida, Terra $4.00 y $18.00, Luna $0.40 y $1.80, con los precios de caché escalados de la misma forma. Hasta el 30 de noviembre de 2026 se aplica el precio promocional de Sol de OpenAI: $4.00 de entrada y $20.00 de salida hasta 272K tokens. Consulta la página del modelo para ver los precios actuales de otros niveles y proveedores.

Una lectura de caché cuesta el 10 % de la tarifa de entrada, una escritura de 30 minutos 1.25× y una escritura de 12 horas 2.5×. Cada token de entrada se factura exactamente a una de estas tarifas. El uso cuenta las lecturas y escrituras de caché dentro de `input_tokens` (`prompt_tokens` en Chat Completions) e indica las escrituras en `cache_write_tokens`; consulta los [campos de uso y precios](../guides/prompt-caching.mdx#usage-and-pricing-fields).

## Almacena en caché el contexto repetido

Pon la parte estable del prompt en un bloque que se pueda almacenar en caché y deja después el texto específico de la solicitud:

```json
{
  "model": "openai/gpt-5.6-sol",
  "input": [
    {
      "role": "user",
      "content": [
        {
          "type": "input_text",
          "text": "Stable policy document...",
          "prompt_cache_breakpoint": { "mode": "explicit" }
        },
        {
          "type": "input_text",
          "text": "Apply the policy to this new customer request."
        }
      ]
    }
  ],
  "prompt_cache_options": { "mode": "explicit", "ttl": "30m" }
}
```

- `prompt_cache_breakpoint` almacena en caché todo hasta su bloque, incluido. En el modo `explicit`, OpenAI solo almacena en caché los puntos de corte que colocas.
- Un `cache_control` de bloque como `{"type": "ephemeral"}` también funciona; Phaseo lo envía a GPT-5.6 como `prompt_cache_breakpoint`. Cualquiera de las dos marcas llega a Claude como punto de corte de caché, así que un respaldo a Claude también usa la caché.
- `ttl` es `30m` (el predeterminado) o `12h`. Consulta [Caché de 12 horas en OpenAI](../guides/prompt-caching.mdx#12-hour-cache-on-openai) para saber qué rutas lo admiten, y [Retención y opciones de OpenAI](../guides/prompt-caching.mdx#openai-retention-and-options) para los demás campos.

## Qué probar

- **Razonamiento y calidad de la salida:** cada nivel con los esfuerzos que vayas a exponer, incluido `max` donde la calidad es lo primero; modo estándar frente a `reasoning.mode: "pro"` en tareas difíciles; tasa de validación del esquema y calidad de las llamadas a herramientas en cada nivel.
- **Coste y latencia:** latencia en cada esfuerzo, aumento de los tokens de salida frente a tu referencia actual, la proporción de lecturas y escrituras de caché en prompts repetidos y el coste por tarea completada con éxito en lugar del precio por token.

## Despliega

1. Mantén tu modelo GPT-5 anterior como respaldo en `models`.
2. Mantén `max` detrás de una marca de configuración o de un [preset](../guides/presets) hasta que se demuestre con prompts similares a producción.
3. Supervisa el volumen de escrituras de caché por separado de las lecturas.
4. Haz de GPT-5.6 el modelo predeterminado solo cuando tus evaluaciones confirmen el éxito de las tareas, el coste y la latencia.
