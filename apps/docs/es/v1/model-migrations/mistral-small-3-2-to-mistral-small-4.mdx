Cambia el modelo a `mistral/mistral-small-4` y decide en cada ruta si el razonamiento está activado. Mistral Small 4 tiene dos modos de razonamiento, desactivado y alto, y Phaseo asigna cada valor de esfuerzo a uno de ellos.

```json
{
  "model": "mistral/mistral-small-4",
  "messages": [
    { "role": "user", "content": "Why is fast inference important?" }
  ],
  "reasoning": { "effort": "high" }
}
```

## Activa o desactiva el razonamiento

El razonamiento está desactivado salvo que la solicitud lo pida. En la API propia de Mistral, Phaseo envía `reasoning_effort` así:

| Solicitud | Se envía a Mistral |
| --- | --- |
| Sin ajuste de razonamiento | `reasoning_effort: "none"` |
| `reasoning.effort: "none"` o `reasoning.enabled: false` | `reasoning_effort: "none"` |
| Cualquier otro `reasoning.effort`, o `reasoning.enabled: true` | `reasoning_effort: "high"` |

Un `reasoning_effort` plano en la solicitud tiene prioridad sobre `reasoning.effort`. Usa `none` para las rutas ligeras y `high` para el razonamiento profundo; `low` y `medium` se comportan exactamente igual que `high`.

## Lee la respuesta y el razonamiento

Mistral puede devolver bloques de contenido mixtos, como `thinking` seguido de `text`. Phaseo los separa en campos de estilo OpenAI, así que el código posterior que lee Chat Completions sigue funcionando:

- la respuesta está en `choices[0].message.content`;
- el texto del razonamiento está en `choices[0].message.reasoning_content` y `reasoning_details`.

## Despliega

1. Cambia el ID de modelo de Mistral Small 3.2 a `mistral/mistral-small-4`.
2. Prueba el razonamiento solo con `none` y `high`.
3. Vuelve a ejecutar las pruebas de calidad de la salida y de esquema en las rutas que usan `high`.
4. Compara la latencia y el coste de `none` y `high` antes del cambio completo.
