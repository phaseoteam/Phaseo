Cambia el modelo a `anthropic/claude-opus-4.7`, quita los parámetros de muestreo y los presupuestos de pensamiento, y fija la profundidad con un nivel de esfuerzo. Las solicitudes que todavía llevan campos de Opus 4.6 no fallan en Phaseo; el gateway las reescribe como se muestra a continuación.

| Solicitud de Opus 4.6 | Qué envía Phaseo a Opus 4.7 |
| --- | --- |
| `temperature`, `top_p`, `top_k` | Se omiten. Anthropic devolvería `400` con valores no predeterminados. |
| `thinking: {"type": "enabled", "budget_tokens": …}` | `thinking: {"type": "adaptive", "display": "summarized"}`; el presupuesto no se reenvía. |
| `reasoning.effort` | `output_config.effort`, incluido `xhigh`. |
| `reasoning.effort: "none"` o `reasoning.enabled: false` | `thinking: {"type": "disabled"}`. |
| Sin ajuste de razonamiento | Sin campo `thinking`, así que Opus 4.7 no piensa. |

Opus 4.7 también oculta el contenido del pensamiento salvo que lo actives; Phaseo pide la visualización resumida siempre que activa el pensamiento. Su tokenizador puede producir más tokens que Opus 4.6 para el mismo texto.

## Actualiza la solicitud

1. Cambia el ID de modelo a `anthropic/claude-opus-4.7`.
2. Elimina `temperature`, `top_p` y `top_k`, y ajusta el comportamiento con instrucciones.
3. Sustituye los presupuestos de pensamiento por pensamiento adaptativo y un nivel de esfuerzo:

```json
{
  "model": "anthropic/claude-opus-4.7",
  "messages": [{ "role": "user", "content": "Refactor this module and explain the risks." }],
  "reasoning": { "effort": "xhigh" }
}
```

Empieza con `high` y usa `xhigh` para las rutas de programación y de agentes más difíciles. En `/v1/messages`, envía en su lugar `thinking: {"type": "adaptive"}` con `output_config.effort`.

4. Como el tokenizador ha cambiado, revisa `max_tokens` y `max_output_tokens`, los presupuestos de tiempo de espera y las alertas de coste.

## Qué probar

- tasa de validación del esquema en tus prompts de producción;
- flujos de herramientas de larga duración: número de llamadas a herramientas, tasa de finalización y latencia;
- calidad con `high` frente a `xhigh`;
- coste de tokens en las clases de prompts con más volumen.

## Despliega

1. Despliega los cambios en la estructura de la solicitud antes de mover tráfico.
2. Ejecuta Opus 4.7 en modo sombra con tu conjunto de evaluación de producción.
3. Haz un canary con Opus 4.6 como respaldo en `models`.
4. Promuévelo cuando los cambios de calidad, latencia y coste estén dentro del objetivo.
