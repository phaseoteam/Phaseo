sidebarTitle: "Vercel AI Gateway"

---

En el código de AI SDK, sustituye `@ai-sdk/gateway` por `@phaseo/ai-sdk-provider` y envuelve cada ID de modelo con `phaseo(...)`. En los clientes compatibles con OpenAI, cambia la URL base y la clave. Tu lógica de generación no cambia.

| Ajuste | Vercel AI Gateway | Phaseo |
| --- | --- | --- |
| URL base | `https://ai-gateway.vercel.sh/v1` | `https://api.phaseo.app/v1` |
| Clave de API | `AI_GATEWAY_API_KEY` u OIDC de Vercel | `PHASEO_API_KEY`, como secreto del lado del servidor |
| Proveedor de AI SDK | `@ai-sdk/gateway`, o modelos como cadenas simples | `@phaseo/ai-sdk-provider` |
| Opciones de enrutamiento | `providerOptions.gateway` | `providerOptions.phaseo` |

## Cambia el proveedor

<CodeGroup>
```typescript AI SDK
import { generateText } from "ai";
// Antes: import { gateway } from "@ai-sdk/gateway";
import { phaseo } from "@phaseo/ai-sdk-provider";

const { text } = await generateText({
  // Antes: model: gateway("openai/gpt-4.1-mini"),
  model: phaseo("openai/gpt-4.1-mini"),
  prompt: "Generate a migration checklist.",
});
```

```typescript OpenAI SDK
import OpenAI from "openai";

// Antes:
// new OpenAI({ apiKey: process.env.AI_GATEWAY_API_KEY, baseURL: "https://ai-gateway.vercel.sh/v1" });
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});
```

```bash cURL
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role":"user","content":"Hello"}]
  }'
```
</CodeGroup>

La exportación predeterminada `phaseo` lee `PHASEO_API_KEY` una sola vez, al importar el módulo, y usa `https://api.phaseo.app/v1`. Si la variable se define después de las importaciones, como ocurre en algunas configuraciones serverless y de pruebas, cada llamada lanza un error de clave ausente; en ese caso, llama a `createPhaseo({ apiKey, baseURL, headers })` dentro del manejador.

Instala la línea del proveedor que corresponda a tu versión principal de `ai`: `@phaseo/ai-sdk-provider` para AI SDK 7, `@phaseo/ai-sdk-provider@ai-sdk-v6` para AI SDK 6 y `@phaseo/ai-sdk-provider@ai-sdk-v5` para AI SDK 5.

AI SDK envía de forma predeterminada los modelos indicados como cadenas simples (`model: "openai/gpt-4.1-mini"`) a través del gateway de Vercel, así que una cadena simple olvidada sigue llamándolo. Cambia una vez la fábrica de modelos compartida y después busca `model: "` en las llamadas de AI SDK. Los clientes del SDK de Anthropic que apuntan a `ai-gateway.vercel.sh` pasan a la configuración de [Migrar desde el SDK de Anthropic](./from-anthropic).

## Asigna las opciones del gateway

`providerOptions.phaseo` se combina con el cuerpo de la solicitud. Un `providerOptions.gateway` que quede se ignora sin error.

| Vercel AI Gateway | En Phaseo |
| --- | --- |
| `providerOptions.gateway.order`, `.only` | `providerOptions: { phaseo: { provider: { order, only } } }`, o un [preset](../guides/presets) llamado como `phaseo("@slug")`. |
| `providerOptions.gateway.models` | `providerOptions: { phaseo: { models: [...] } }`, o respaldos en una ruta dinámica. |
| `providerOptions.gateway.sort` (`cost`, `ttft`, `tps`) | `provider.sort` (`price`, `latency`, `throughput`). |
| `providerOptions.gateway.zeroDataRetention` | `provider.require_zero_data_retention`, que limita el enrutamiento a proveedores con ZDR. |
| `providerOptions.gateway.user`, `.tags` | `user` y [etiquetas](../guides/request-labels) `X-Phaseo-Metadata`. |
| Credenciales `byok` por solicitud | Sin equivalente. Añade las claves de proveedor al espacio de trabajo con `phaseo byok create`. |
| Texto, streaming, herramientas, salida estructurada, embeddings, imágenes, transcripción, voz | Compatibles con el proveedor; las capacidades siguen dependiendo del modelo. |
| Reordenación | `phaseo.rerankingModel(id)` en las líneas de AI SDK 6 y 7. |
| Referencias a archivos gestionados, herramientas ejecutadas por el proveedor | No compatibles. Las partes no compatibles fallan con un error en lugar de descartarse. |
| Panel de uso del gateway | Registros de solicitudes de Phaseo y `GET /v1/generations?id=<request_id>`. Los metadatos del proveedor en los resultados incluyen el ID de solicitud. |

## Prueba y despliega

Ejecuta el mismo conjunto de prompts por ambas rutas y compara latencia, formato de salida y uso de tokens. Antes de promover el tráfico, comprueba que:

- `PHASEO_API_KEY` está definida en cada entorno de ejecución que tenía la clave del gateway, incluidos los despliegues de edge, de servidor y de vista previa;
- la ruta principal de generación de texto y una prueba de streaming funcionan sin cambios en staging;
- las llamadas a herramientas y las salidas estructuradas funcionan si la aplicación las usa;
- la asignación de errores a nivel de aplicación sigue funcionando;
- una solicitud fallida en staging se puede encontrar y, cuando `replay_supported` es `true`, repetir desde `GET /v1/generations?id=<request_id>`.

Publica detrás de una marca de función o de un despliegue por porcentaje, empezando por el tráfico interno. Vigila la latencia, la tasa de errores y las desviaciones de tokens y coste, y mantén disponible el proveedor anterior durante al menos una publicación para que la reversión no requiera cambios de código.

```bash
curl -s "https://api.phaseo.app/v1/health"
curl -s "https://api.phaseo.app/v1/models?format=openai" -H "Authorization: Bearer $PHASEO_API_KEY"
```

Para saber más sobre el proveedor, consulta [AI SDK](../guides/integrations/ai-sdk).
