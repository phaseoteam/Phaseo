sidebarTitle: "Helicone"

---

Apunta el cliente a `https://api.phaseo.app/v1` con una clave de Phaseo, elimina `Helicone-Auth` y pasa cada encabezado `Helicone-*` que todavía necesites a su equivalente en Phaseo. El cambio en la solicitud es pequeño; planifica el cambio de observabilidad con el mismo cuidado.

| Ajuste | Helicone | Phaseo |
| --- | --- | --- |
| URL base | `oai.helicone.ai/v1`, `anthropic.helicone.ai`, `ai-gateway.helicone.ai`, o `gateway.helicone.ai` con `Helicone-Target-URL` | `https://api.phaseo.app/v1` |
| Autenticación | Clave del proveedor más `Helicone-Auth`, o `HELICONE_API_KEY` en el AI Gateway | Solo `PHASEO_API_KEY` |
| Propiedades personalizadas | `Helicone-Property-<Name>` | Etiquetas `X-Phaseo-Metadata` |
| Visibilidad de las solicitudes | Panel de Helicone | Registros y detalles de solicitudes de Phaseo |

## Cambia el cliente

<CodeGroup>
```typescript TypeScript
import OpenAI from "openai";

// Antes:
// new OpenAI({
//   apiKey: process.env.OPENAI_API_KEY,
//   baseURL: "https://oai.helicone.ai/v1",
//   defaultHeaders: {
//     "Helicone-Auth": `Bearer ${process.env.HELICONE_API_KEY}`,
//     "Helicone-Property-Team": "support",
//   },
// });
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
  defaultHeaders: {
    "X-Phaseo-Metadata": JSON.stringify({ labels: [{ key: "team", value: "support" }] }),
  },
});

const response = await client.chat.completions.create(
  {
    model: "openai/gpt-6-astra",
    messages: [{ role: "user", content: "Reply with: migration ready" }],
  },
  { headers: { "X-Phaseo-User-Id": "user_123" } },
);
```

```python Python
import json
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
    default_headers={
        "X-Phaseo-Metadata": json.dumps({"labels": [{"key": "team", "value": "support"}]}),
    },
)
```

```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role": "user", "content": "Reply with: migration ready"}]
  }'
```
</CodeGroup>

Los valores por solicitud, como los ID de usuario, van en la solicitud, no en el cliente. Las rutas `anthropic.helicone.ai` pasan a la configuración de [Migrar desde el SDK de Anthropic](./from-anthropic).

En el Helicone AI Gateway, el enrutamiento está en la cadena `model`. Divídela: la primera entrada separada por comas pasa a ser `model` y el resto forma la matriz `models`; una fijación `<model>/<provider>` pasa a ser `provider.only` o un ID `provider:org/model`; una exclusión `!provider` pasa a ser `provider.ignore`.

## Asigna los encabezados de Helicone

| Helicone | En Phaseo |
| --- | --- |
| `Helicone-Auth` | Elimínalo. |
| `Helicone-Property-<Name>` | [Etiquetas](../guides/request-labels) `X-Phaseo-Metadata`: hasta 32, y las claves cumplen `[A-Za-z0-9_.:-]` (64 caracteres), así que renombra las propiedades con espacios. Un JSON mal formado o las claves duplicadas devuelven `400`. No pongas datos personales en las etiquetas. |
| `Helicone-User-Id` | Campo del cuerpo `user` o `X-Phaseo-User-Id`. También sirve de clave para las políticas de límites de velocidad por usuario final. |
| `Helicone-Session-Id` | Campo del cuerpo `session_id`. Determina la afinidad de caché y de proveedor, no un árbol de trazas. |
| `Helicone-Session-Path`, `Helicone-Session-Name` | `metadata.trace_id`, `parent_span_id`, `trace_name`, `span_name` en el cuerpo, o un encabezado W3C `traceparent`. Dan forma a los spans que se envían a los destinos de observabilidad; los registros propios de Phaseo no tienen árbol de trazas. |
| `Helicone-Cache-Enabled` | No hay caché de respuestas. Usa caché en la aplicación si la necesitas. |
| `Helicone-Fallbacks`, `Helicone-Retry-Enabled` | Matriz `models`, que se prueba con `429`, `500`, `502`, `503` y `504`, más el respaldo de proveedores integrado. Mantén la espera exponencial en el cliente. |
| `Helicone-RateLimit-Policy` | Políticas de límites de velocidad y límites de clave. Consulta [Límites](../api-reference/limits). |
| `Helicone-LLM-Security-Enabled` | Detección de inyección de prompts de los guardrails, solo en las solicitudes. |
| `Helicone-Moderations-Enabled` | Sin equivalente dentro del gateway. Llama a `/v1/moderations` desde la aplicación. |
| `Helicone-Omit-Request`, `Helicone-Omit-Response` | Política de registro del espacio de trabajo o retención de datos cero. |
| `Helicone-Posthog-*` | [Destino de observabilidad](../guides/integrations/observability) de PostHog. |
| Gestión de prompts | [Plantillas de prompts de presets](../guides/prompt-templates): `"prompt": {"id": "@slug", "version": "production", "variables": {...}}`. |

## Traslada la visibilidad de las solicitudes

Usa los registros de solicitudes, los ID de solicitud, los intentos de proveedores y los detalles de precios para depurar. Si el equipo exporta telemetría, conecta el [destino de observabilidad](../guides/integrations/observability) correspondiente antes del cambio para que no haya huecos. El registro asíncrono de Helicone, que no hace de proxy del tráfico, es una decisión aparte del cambio de gateway.

## Prueba y despliega

Verifica que las solicitudes funcionan sin los encabezados de Helicone y que el equipo sigue pudiendo responder a las preguntas que se plantea durante los incidentes. Antes de mover tráfico, comprueba que:

- cada URL de Helicone y cada encabezado `Helicone-*` se ha eliminado o asignado;
- los ID de modelo de producción están en `GET /v1/models?format=openai`;
- las alertas y los paneles tienen un sustituto donde el equipo lo necesita;
- la reversión sigue siendo solo un cambio de URL base y clave.
