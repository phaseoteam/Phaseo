Elige la guía según lo que cambies: la plataforma a la que llama tu aplicación (abajo) o el modelo que usa ([migraciones de modelos](../model-migrations)). Si cambias ambas cosas, migra primero la plataforma y mantén el mismo modelo hasta verificar la nueva ruta.

Para obtener una lista de comprobación a medida, usa el [Asistente de migración](https://phaseo.app/migrate).

<span id="platform-migrations"></span>
## Migraciones de plataforma

Todas las guías de plataforma siguen el mismo orden: cambia la URL base y la clave, asigna los ID de modelos, asigna las funciones de la plataforma y después prueba y despliega, manteniendo la reversión como un cambio de URL base y clave.

| A qué llamas | Señales en el código | Guía |
| --- | --- | --- |
| OpenAI directamente | `api.openai.com`, `OPENAI_API_KEY`, `AzureOpenAI` | [SDK de OpenAI](./from-openai) |
| Anthropic directamente | `api.anthropic.com`, `ANTHROPIC_API_KEY`, `@anthropic-ai/sdk` | [SDK de Anthropic](./from-anthropic) |
| OpenRouter | `openrouter.ai`, `OPENROUTER_API_KEY`, claves `sk-or-v1` | [OpenRouter](./from-openrouter) |
| Vercel AI Gateway | `ai-gateway.vercel.sh`, `@ai-sdk/gateway`, modelos como cadenas simples en las llamadas de AI SDK | [Vercel AI Gateway](./from-vercel) |
| LLM Gateway | `api.llmgateway.io`, `LLM_GATEWAY_API_KEY` | [LLM Gateway](./from-llmgateway) |
| Un proxy de LiteLLM | `config.yaml` con `model_list`, variables `LITELLM_*`, puerto 4000 | [LiteLLM](./from-litellm) |
| Cloudflare AI Gateway | `gateway.ai.cloudflare.com`, encabezados `cf-aig-*` | [Cloudflare AI Gateway](./from-cloudflare) |
| Helicone | `*.helicone.ai`, `Helicone-Auth` | [Helicone](./from-helicone) |

Para planificar y comprobar el despliegue, usa la [Lista de comprobación de funciones para la migración](./feature-parity-matrix).

## Migra con un agente de programación

<Prompt description="Pide a un agente de programación que planifique y lleve a cabo la migración contigo." icon="arrow-right-left" actions={["copy", "cursor"]}>
{`Migrate this project's AI requests to Phaseo Gateway.

1. Install the Phaseo skills: npx skills add https://phaseo.app/docs
   Use phaseo-migration, which has a guide for each source platform (and openrouter-to-phaseo-migration for a detailed OpenRouter move).
2. Find every place the project calls its current provider or gateway (OpenAI, Anthropic, OpenRouter, Vercel AI Gateway, LiteLLM or another), including environment variables, SDK clients, base URLs and model IDs.
3. Read the matching guide at https://phaseo.app/docs/es/v1/migration-guides and map each call to its Phaseo equivalent at https://api.phaseo.app/v1 with a server-side PHASEO_API_KEY.
4. Check every model ID against data[].id from GET /v1/models?format=openai. Do not assume IDs carry over unchanged.
5. List the changes and a rollback plan before editing. After editing, verify one normal request and one streaming request if the project streams.
6. Never print or commit API keys, and do not switch production traffic without my approval.`}
</Prompt>

## Migraciones de modelos

Usa una [guía de migración de modelos](../model-migrations) cuando la integración no cambia pero el modelo sí. Cada una explica los cambios en los parámetros de la solicitud, las variaciones en el comportamiento de los prompts y del razonamiento, las diferencias en la salida estructurada y las llamadas a herramientas, y cómo desplegar con un respaldo.

En cualquiera de los dos tipos de migración, comprueba los parámetros de la solicitud y el comportamiento del endpoint antes de comparar la calidad de la salida, y ejecuta evaluaciones en condiciones similares a producción antes de mover el tráfico real.
