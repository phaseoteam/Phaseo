Sustituye la URL del gateway de Cloudflare y la clave del proveedor por `https://api.phaseo.app/v1` y una clave de Phaseo, y elimina los encabezados `cf-aig-*`. La carga útil de la solicitud no cambia.

| Ajuste | Cloudflare AI Gateway | Phaseo |
| --- | --- | --- |
| URL base | `gateway.ai.cloudflare.com/v1/<account_id>/<gateway_id>/<provider>`, o `api.cloudflare.com/client/v4/accounts/<account_id>/ai/v1` | `https://api.phaseo.app/v1` |
| Autenticación | Clave del proveedor, más `cf-aig-authorization` o un token de API de Cloudflare | `PHASEO_API_KEY` como `Authorization: Bearer` |
| Elección de proveedor | Una ruta por proveedor | Una sola URL base; el ID de modelo elige el modelo y el enrutamiento elige el proveedor |
| Encabezados del gateway | `cf-aig-*` | Se eliminan o se asignan como en la tabla siguiente |
| Visibilidad de las solicitudes | Analíticas de Cloudflare | Registros y detalles de solicitudes de Phaseo |

## Cambia el cliente

<CodeGroup>
```typescript TypeScript
import OpenAI from "openai";

// Antes:
// new OpenAI({
//   apiKey: process.env.OPENAI_API_KEY,
//   baseURL: `https://gateway.ai.cloudflare.com/v1/${accountId}/${gatewayId}/openai`,
//   defaultHeaders: { "cf-aig-authorization": `Bearer ${process.env.CF_AIG_TOKEN}` },
// });
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-6-astra",
  messages: [{ role: "user", content: "Reply with: migration ready" }],
});
```

```python Python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
)
```

```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role": "user", "content": "Reply with: migration ready"}]
  }'
```
</CodeGroup>

Una ruta `/anthropic` pasa a la configuración del SDK de Anthropic de [Migrar desde el SDK de Anthropic](./from-anthropic). Las llamadas mediante el binding de Workers AI (`env.AI.run(model, input, { gateway })`) no son clientes HTTP: sustitúyelas por `fetch` o por el SDK de OpenAI apuntando a Phaseo, y solo para los modelos que aparecen en `GET /v1/models?format=openai`. Guarda `PHASEO_API_KEY` como secreto del Worker, no en la configuración de `wrangler`.

## Asigna las funciones del gateway

Los ajustes de Cloudflare no se transfieren automáticamente. Decide para cada uno si corresponde a Phaseo, a la aplicación o a la capa de edge.

| Cloudflare AI Gateway | En Phaseo |
| --- | --- |
| Cadenas de respaldo | Matriz `models`, respaldo de proveedores o [rutas dinámicas](../guides/routing-and-fallbacks). Los respaldos de modelo se activan con `429`, `500`, `502`, `503` y `504`, nunca con errores de la solicitud. |
| Cadenas de modelo `dynamic/<route>` | Rutas dinámicas asociadas a claves de API; envía un ID de modelo real. |
| `cloudflare/auto` | `phaseo/auto` ([Enrutamiento automático](../guides/auto-routing), alfa); no se puede combinar con `models`. |
| Caché (`cf-aig-cache-ttl`, `cf-aig-skip-cache`, `cf-aig-cache-key`) | No hay caché de respuestas. Usa caché en la aplicación si la necesitas; el [almacenamiento en caché de prompts](../guides/prompt-caching) sigue reduciendo el coste de entrada. |
| `cf-aig-metadata` | [Etiquetas](../guides/request-labels) `X-Phaseo-Metadata`: hasta 32, las claves cumplen `[A-Za-z0-9_.:-]` (64 caracteres) y los valores son cadenas de hasta 256. Convierte los números y los booleanos. |
| `cf-aig-collect-log` | Política de registro del espacio de trabajo, o `provider.require_zero_data_retention`, que además limita el enrutamiento a proveedores con ZDR. |
| `cf-aig-request-timeout`, `cf-aig-max-attempts` | No hay control por solicitud. Respaldo de proveedores integrado más espera exponencial en el cliente. |
| `cf-aig-session-id` | Campo del cuerpo `session_id`. |
| `cf-aig-custom-cost` | Sin equivalente. |
| Limitación de velocidad, límites de gasto | Políticas de límites de velocidad, límites de clave y presupuestos de espacio de trabajo, clave y departamento. Consulta [Límites](../api-reference/limits). |
| Guardrails y DLP | Los guardrails de claves y de miembros analizan las solicitudes en busca de inyección de prompts y PII. Las respuestas no se analizan; llama a `/v1/moderations` para la seguridad del contenido. |
| Registros y analíticas | Registros de solicitudes, detalles de solicitudes con los intentos de proveedores y los precios, y [destinos de observabilidad](../guides/integrations/observability). |
| Modelos `@cf/...` de Workers AI | Solo si aparecen en `GET /v1/models?format=openai`; si no, mantén esas llamadas en Workers AI. |

## Prueba y despliega

Prueba solicitudes sin streaming y con streaming, errores, herramientas y salidas estructuradas tal como las usa la aplicación, y compara latencia, salida, uso de tokens y coste antes de mover el tráfico de forma gradual. Antes del cambio, comprueba que:

- no queda ninguna URL `gateway.ai.cloudflare.com` ni `api.cloudflare.com/.../ai/v1` ni ningún encabezado `cf-aig-*`; una ruta olvidada mantiene tráfico en la ruta anterior;
- los ID de modelo de producción están en `GET /v1/models?format=openai`;
- cada comportamiento de caché se ha recreado en la aplicación o se ha descartado a propósito;
- los registros de solicitudes dan al equipo la visibilidad que necesita;
- la reversión sigue siendo solo un cambio de URL base y clave.
