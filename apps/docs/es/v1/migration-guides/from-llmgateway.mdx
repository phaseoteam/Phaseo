Cambia la URL base y la clave, conserva las cargas útiles de las solicitudes y asigna cada ID de modelo: el prefijo de LLM Gateway indica el proveedor que sirve el modelo, mientras que el de Phaseo indica quién creó el modelo.

| Ajuste | LLM Gateway | Phaseo |
| --- | --- | --- |
| URL base | `https://api.llmgateway.io/v1` | `https://api.phaseo.app/v1` |
| Clientes de estilo Anthropic | `ANTHROPIC_BASE_URL=https://api.llmgateway.io` | `https://api.phaseo.app`; consulta [Migrar desde el SDK de Anthropic](./from-anthropic) |
| Clave de API | `LLM_GATEWAY_API_KEY` (`llmgtwy_…`) | `PHASEO_API_KEY` |
| ID de modelos | `gpt-4o`, `<provider>/<model>`, `auto` | `<org>/<model>` de `GET /v1/models?format=openai` |
| Carga útil de la solicitud | Compatible con OpenAI | Sin cambios |

## Cambia el cliente

<CodeGroup>
```typescript TypeScript
import OpenAI from "openai";

// Antes:
// new OpenAI({ apiKey: process.env.LLM_GATEWAY_API_KEY, baseURL: "https://api.llmgateway.io/v1" });
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});
```

```python Python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
)
```

```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```
</CodeGroup>

Asigna o elimina cada variable `LLM_GATEWAY_*`, también en los ajustes de CI y de hosting. Si la aplicación usa `@llmgateway/ai-sdk-provider`, cambia a `@phaseo/ai-sdk-provider` como en [Migrar desde Vercel AI Gateway](./from-vercel).

## Asigna los ID de modelos

Lista los ID de Phaseo y comprueba cada modelo de producción con ellos:

```bash
curl -s "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY" | jq -r '.data[].id'
```

`alibaba/<model>` en LLM Gateway no es un ID de Phaseo. Asigna cada ID al formato `<org>/<model>` de Phaseo y conserva la fijación de proveedor con `provider.only` o con un ID `provider:org/model`. Traduce los alias sin prefijo, como `gpt-4o`, en una sola función en el límite del cliente en lugar de en cada punto de llamada.

## Asigna las funciones del gateway

| LLM Gateway | En Phaseo |
| --- | --- |
| Enrutador `auto` | `phaseo/auto` ([Enrutamiento automático](../guides/auto-routing), alfa); no se puede combinar con `models`. |
| Cadenas de respaldo | Matriz `models` o rutas dinámicas, que se prueban con `429`, `500`, `502`, `503` y `504`, nunca con errores de la solicitud. |
| `X-No-Fallback` | `provider.allow_fallbacks: false`, o un ID `provider:org/model`. |
| Lógica de proveedores permitidos y denegados | `provider.only`, `provider.ignore` o [Presets](../guides/presets). Mantén al menos un proveedor apto. |
| Encabezados `X-LLMGateway-<Key>` | [Etiquetas](../guides/request-labels) `X-Phaseo-Metadata`, hasta 32. |
| Encabezados de sesión (`x-session-id`) | Campo del cuerpo `session_id`; Phaseo ignora los encabezados de sesión. |
| `X-Source` | `HTTP-Referer` o `X-App-Name`. Consulta [Atribución de aplicaciones](../guides/app-attribution). |
| Caché de respuestas | No hay caché de respuestas. |
| Claves de proveedores | BYOK (`phaseo byok create` o `POST /v1/byok`), o créditos de Phaseo. Recurrir a los créditos se controla con el ajuste del espacio de trabajo `byok_fallback_enabled`. |
| Registros de solicitudes | Registros de solicitudes, destinos de observabilidad y `GET /v1/generations?id=<request_id>`. Cuando `replay_supported` es `true`, repite una solicitud fallida a partir de su carga útil `replay_request`. |

## Prueba y despliega

Ejecuta tus prompts de referencia en ambos gateways y compara calidad, latencia y coste. Comprueba primero los endpoints:

```bash
curl -s "https://api.phaseo.app/v1/health"
curl -s "https://api.phaseo.app/v1/models?format=openai" -H "Authorization: Bearer $PHASEO_API_KEY"
```

Antes de mover tráfico, comprueba que:

- `PHASEO_API_KEY` está definida en todos los entornos;
- cada ID de modelo de producción está asignado y aparece en la lista;
- una solicitud sin streaming y otra con streaming funcionan en staging;
- se gestionan los errores de clave no válida y de modelo no válido; sus cuerpos pueden ser distintos de los de LLM Gateway;
- una solicitud fallida en staging se puede recuperar con `GET /v1/generations`;
- los valores predeterminados compartidos de prompts y enrutamiento están en presets cuando corresponde.

Publica detrás de una marca canary, pasa de una pequeña parte del tráfico a todo él cuando sea estable y vigila las métricas de producción durante al menos un ciclo de publicación antes de eliminar la configuración anterior.
