Cambia la URL base a `https://api.phaseo.app/v1` y la clave a `PHASEO_API_KEY`. Las cargas útiles de las solicitudes, el encabezado `Authorization: Bearer`, el objeto `provider` y la matriz de respaldo `models` siguen funcionando; comprueba los ID de modelo y los pocos campos de la tabla siguiente.

| Ajuste | OpenRouter | Phaseo |
| --- | --- | --- |
| URL base | `https://openrouter.ai/api/v1` | `https://api.phaseo.app/v1` |
| Clave de API | `OPENROUTER_API_KEY` (`sk-or-v1-…`) | `PHASEO_API_KEY` |
| Autenticación | `Authorization: Bearer <key>` | Sin cambios |
| Carga útil de la solicitud | Compatible con OpenAI | Sin cambios |
| ID de modelos | `<org>/<model>` | `<org>/<model>`; la mayoría coinciden, algunas organizaciones difieren |
| Encabezados de atribución | `HTTP-Referer`, `X-Title` | Sin cambios; añade `X-App-Id` para una agrupación estable |

## Cambia el cliente

<CodeGroup>
```typescript Antes
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.OPENROUTER_API_KEY,
  baseURL: "https://openrouter.ai/api/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Summarize our migration plan." }],
});
```

```typescript Después
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Summarize our migration plan." }],
});
```

```bash cURL
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role":"user","content":"Say hello"}]
  }'
```
</CodeGroup>

En la primera pasada, deja la carga útil sin cambios y consigue paridad antes de optimizar. Elimina `OPENROUTER_BASE_URL` y la clave antigua del código, de CI y de los ajustes de hosting. `@openrouter/ai-sdk-provider` pasa a ser `@phaseo/ai-sdk-provider` (consulta [Migrar desde Vercel AI Gateway](./from-vercel)); los SDK propios de OpenRouter (`@openrouter/sdk`, `openrouter` en PyPI) necesitan un cambio de cliente, no solo una URL base nueva.

## Comprueba los ID de modelos

La mayoría de los ID coinciden, pero algunas organizaciones difieren: `x-ai/` es `spacex-ai/`, `meta-llama/` es `meta/` y `mistralai/` es `mistral/`. Lista los ID de Phaseo y comprueba cada modelo de producción con ellos:

```bash
curl -s "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY" | jq -r '.data[].id'
```

La lista predeterminada solo contiene los modelos que puedes llamar ahora; añade `availability=all` para ver los inactivos o los que llegarán pronto. Sin `format=openai`, la respuesta es la lista paginada `models` de Phaseo, que no tiene matriz `data`.

## Asigna los campos de la solicitud

| OpenRouter | En Phaseo |
| --- | --- |
| `provider.order`, `only`, `ignore`, `allow_fallbacks`, `require_parameters`, `max_price` | Los mismos campos. Usa los ID base de proveedor, no los slugs de endpoint. |
| `provider.sort` | El mismo campo: `price`, `latency` o `throughput`. |
| `provider.zdr` | Se acepta como alias de `provider.require_zero_data_retention`. |
| `provider.data_collection: "deny"` | Devuelve `400`. Usa `zdr: true` en su lugar. |
| Matriz de respaldo `models` | Igual, de 1 a 25 entradas. `model` es obligatorio, así que mueve `models[0]` a ese campo. |
| Sufijo `:nitro` | Igual (rendimiento). Phaseo también tiene `:cheap` y `:fast`; `:floor` pasa a ser `:cheap`. Elimina `:online` y `:thinking` y usa en su lugar la búsqueda web y `reasoning`. |
| `openrouter/auto`, `openrouter/free` | `phaseo/auto` ([Enrutamiento automático](../guides/auto-routing), alfa, no se puede combinar con `models`) y `phaseo/free`. |
| `plugins` `web`, `web-fetch`, `response-healing` | Los mismos ID de plugin. Otros plugins, como `file-parser`, devuelven `400`. |
| `transforms`, `usage: { include: true }` | No se aceptan. Elimínalos; el uso y el coste se devuelven siempre. |
| `X-OpenRouter-Title` | Renómbralo a `X-Title`. Consulta [Atribución de aplicaciones](../guides/app-attribution). |
| Presets `@preset/<slug>` | Recréalos como [Presets](../guides/presets) y llámalos como `"model": "@slug"`. |
| `usage.cost`, `reasoning_details`, `provider` en las respuestas | Se devuelven. `native_finish_reason` e `is_byok` no; normalízalos en una sola capa si los llamadores los leen. |

Phaseo también tiene `provider.required_execution_region` y `provider.required_data_region`, que no tienen equivalente en OpenRouter. Consulta [Fijar o ignorar proveedores](../cookbook/pin-or-ignore-providers-per-request) y [Enrutar solo a proveedores de la UE o con ZDR](../cookbook/route-only-to-eu-or-zdr-providers) para ver solicitudes completas.

Mantén los campos exclusivos de OpenRouter que queden en un único adaptador en lugar de en cada punto de llamada, para que la reversión siga siendo un cambio de URL base y clave.

## Valida antes del cambio

Ejecuta estas comprobaciones contra Phaseo y después las mismas a través de la ruta de cliente de tu aplicación:

```bash
curl -s "https://api.phaseo.app/v1/health"

curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"openai/gpt-6-astra","messages":[{"role":"user","content":"Say hello"}]}'

# Streaming
curl -N "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"openai/gpt-6-astra","stream":true,"messages":[{"role":"user","content":"Reply with: stream works"}]}'

# Modelo no válido: la aplicación debe gestionar el error sin exponer credenciales
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"invalid/migration-test","messages":[{"role":"user","content":"test"}]}'
```

Antes de mover una parte significativa del tráfico, confirma que:

- `OPENROUTER_API_KEY` se ha sustituido por `PHASEO_API_KEY` en todos los entornos;
- cada ID de modelo de producción está en `GET /v1/models?format=openai`;
- una solicitud sin streaming y otra con streaming funcionan a través de `/v1/chat/completions` o `/v1/responses`, usando la misma ruta de cliente que en producción;
- los flujos de llamadas a herramientas y de salida estructurada funcionan con prompts reales;
- se gestionan los fallos por clave no válida y por modelo no válido;
- una solicitud fallida se puede consultar con `GET /v1/generations?id=<request_id>` y, cuando `replay_supported` es `true`, repetir a partir de `replay_request`;
- los encabezados y campos de respuesta exclusivos de OpenRouter se han eliminado o normalizado, y los valores predeterminados compartidos están en presets.

## Despliega

1. Empieza con el tráfico interno.
2. Mueve entre el 5 y el 10 % del tráfico de producción y compara calidad, latencia y coste.
3. Pasa al 100 % cuando se confirme la paridad.
4. Mantén la reversión como un cambio de URL base y clave hasta que el cambio sea estable.

## Encarga la migración a un agente de programación

Da al agente esta secuencia acotada, o instala la [skill de migración de OpenRouter a Phaseo](https://github.com/phaseoteam/Phaseo/tree/main/.agents/skills/openrouter-to-phaseo-migration), que incluye los mismos pasos de inventario, asignación, validación y reversión:

1. Busca en el código de ejecución y en la configuración de despliegue `openrouter.ai`, `OPENROUTER_API_KEY`, `sk-or-v1`, `HTTP-Referer` y `X-Title`.
2. Cambia el límite del cliente a `https://api.phaseo.app/v1` y `PHASEO_API_KEY` sin añadir ningún valor secreto al control de versiones.
3. Consulta `GET /v1/models?format=openai` y anota cada correspondencia de modelo antiguo a nuevo.
4. Adapta las opciones de enrutamiento o los campos de respuesta exclusivos de OpenRouter en un único módulo de compatibilidad.
5. Ejecuta las comprobaciones de estado, sin streaming, con streaming y de rutas de fallo anteriores.
6. Informa de los archivos cambiados, los cambios de nombre de secretos, las correspondencias de modelos, las pruebas realizadas, las diferencias de paridad y el interruptor de reversión.

Para una versión guiada, abre la [guía interactiva de migración desde OpenRouter](https://phaseo.app/migrate/openrouter), consulta cómo se [comparan](https://phaseo.app/compare/openrouter) ambos o [recibe ayuda gratuita con la migración](https://phaseo.app/contact).
