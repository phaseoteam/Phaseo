Install the Phaseo package for your language, create a client with your API key, and call one method per Gateway endpoint. Every SDK reads `PHASEO_API_KEY` when you don't pass a key.

| Language | Package | Registry | Published version |
| --- | --- | --- | --- |
| TypeScript | [`@phaseo/sdk`](https://www.npmjs.com/package/@phaseo/sdk) | npm | `3.0.0` |
| Python | [`phaseo`](https://pypi.org/project/phaseo/) | PyPI | `3.0.0` |
| Go | [`github.com/phaseoteam/Phaseo/packages/sdk/sdk-go/v4`](https://pkg.go.dev/github.com/phaseoteam/Phaseo/packages/sdk/sdk-go/v4) | Go modules | `v3.0.0` |
| C# | [`Phaseo.Sdk`](https://www.nuget.org/packages/Phaseo.Sdk) | NuGet | `3.0.0` |
| PHP | [`phaseo/sdk`](https://packagist.org/packages/phaseo/sdk) | Packagist | `v3.0.0` |
| Ruby | [`phaseo_sdk`](https://rubygems.org/gems/phaseo_sdk) | RubyGems | `3.0.0` |
| Java | `app.phaseo:phaseo-sdk` | Maven Central (older API); build the current source instead | `3.0.0` |
| Rust | [`phaseo`](https://crates.io/crates/phaseo) | crates.io | `0.2.0` |

## What you send and get back

Request bodies use the API's JSON field names in every SDK. [Usage](./usage) has one example per endpoint.

| Language | Request body | Returns |
| --- | --- | --- |
| TypeScript | Typed objects generated from the OpenAPI spec | Typed objects |
| Python | Dicts; types live in `phaseo.models` | `APIResponse` dicts with `output_text`, `request_id` and `trace_url` |
| Go | `map[string]interface{}`, or the typed `phaseo.ChatCompletionsRequest` and `phaseo.ResponsesRequest` (PascalCase struct fields such as `Model`, `Messages`, `Input`) | Decoded JSON |
| C# | `Dictionary<string, object>` | `Dictionary<string, object>?` |
| PHP | Arrays | Arrays |
| Ruby | Hashes (keyword arguments) | Hashes |
| Java | A `Map` or Jackson `JsonNode`; parse JSON strings first | `JsonNode` |
| Rust | `&serde_json::Value` | `PhaseoResponse` with `status`, `body` and `request_id` |

A missing key fails when you create the client. Python raises `ValueError`, Go's `NewFromEnv()` returns an error, C# and PHP throw `Missing API key. Pass apiKey or set PHASEO_API_KEY.`, Ruby raises `ArgumentError: Missing API key. Pass api_key or set PHASEO_API_KEY.`, and Rust's `Phaseo::from_env()` returns a `PhaseoError`.

## Configure the client

<Tabs>
<Tab title="TypeScript">

| Option | What it does |
| --- | --- |
| `apiKey` | A key string, or a function that returns a credential for each request (for example a [trusted workload](/v1/developers/trusted-workloads) token). Defaults to `PHASEO_API_KEY`. |
| `baseUrl` / `region` | `region` is `global`, `eu` or `us`. You can't set both. |
| `timeoutMs`, `maxRetries`, `signal` | Request controls; see [Request controls and errors](#request-controls-and-errors). |
| `app` | Your app's `id`, `name`, `url` and up to three `categories`, sent as attribution headers. |
| `modelLifecycleChecks` | Default `true`: the client looks up each model once (`GET /models`) and refuses models that aren't active. Set `false` to skip the lookup. |
| `enableDeprecationWarnings`, `warningsAsErrors`, `logger` | Control deprecation warnings for models. |
| `devtools` | Local DevTools capture. |
| `headers`, `fetchImpl` | Extra headers and a custom `fetch`. |

</Tab>
<Tab title="Python">

| Option | What it does |
| --- | --- |
| `api_key` | A key string, or a callable that returns a credential for each request (for example a [trusted workload](/v1/developers/trusted-workloads) token). Defaults to `PHASEO_API_KEY`. |
| `base_url` / `region` | `region` is `global`, `eu` or `us`. You can't set both. |
| `timeout`, `max_retries` | Request controls; see [Request controls and errors](#request-controls-and-errors). |
| `app` | A dict with your app's `id`, `name` and `url`, sent as attribution headers. |
| `enable_deprecation_warnings`, `warnings_as_errors`, `logger` | Control deprecation warnings for models. On `Phaseo` only. |
| `devtools` | Local DevTools capture. On `Phaseo` only. |
| `http_client` | An `httpx.Client` (`httpx.AsyncClient` for `AsyncPhaseo`) to send requests through. A client you inject stays yours to close. |
| `on_request`, `on_response`, `on_retry` | Hooks called for each attempt. |

Use `AsyncPhaseo` for asyncio:

```python Python
import asyncio
from phaseo import AsyncPhaseo

async def main():
    async with AsyncPhaseo() as client:
        response = await client.responses.create({"model": "openai/gpt-6-astra", "input": "Hello"})
        print(response.output_text, response.request_id, response.trace_url)

asyncio.run(main())
```

Use `async for event in client.responses.stream(request)` for parsed text events. Cancelling the asyncio task stops the HTTP request and any polling. `AsyncPhaseo` has resource namespaces for text, images, audio, realtime, music, video, batches, files, models, embeddings, OCR, rerank, parse, moderations, decisions and extractions; use `await client.request(...)` for any other HTTP operation.

## Wait for music, video, or batches

The wait helpers are in TypeScript and Python. The other SDKs return the job from the create call; poll it with the get method or open its [job WebSocket URL](#find-the-method-for-each-endpoint).

<CodeGroup>

```typescript TypeScript
const music = await client.music.generateAndWait(
  { model: process.env.PHASEO_MUSIC_MODEL!, prompt: "Gentle instrumental piano" },
  { timeoutMs: 600_000, onPoll: (job) => console.log(job.id, job.status) },
);
```

```python Python
import os

music = client.music.generate_and_wait(
    {"model": os.environ["PHASEO_MUSIC_MODEL"], "prompt": "Gentle instrumental piano"},
    timeout=600,
    on_poll=lambda job: print(job["id"], job["status"]),
)
```

</CodeGroup>

Use `videos.generateAndWait` / `videos.generate_and_wait` for video and `batches.createAndWait` / `batches.create_and_wait` for batches. Each helper submits once. If the first response is already complete it returns it without polling; otherwise it polls the same job until it finishes and returns the full response. Failed, cancelled, or expired jobs raise `JobFailedError`, whose `response` holds the details. A completed batch can still contain failed individual requests.

`wait(id, options)` on each resource resumes an existing job and returns any terminal response, including failures. In Python, music also has `create(request)` and `retrieve(id)`.

| TypeScript | Python | Default | Notes |
| --- | --- | --- | --- |
| `intervalMs` | `interval` | `5000` ms / `5` seconds | Minimum `250` ms / `0.25` seconds. |
| `timeoutMs` | `timeout` | `1800000` ms / `1800` seconds (30 minutes) | Starts after the submission returns; the submission request keeps its own timeout. |
| `signal` | `cancel_event` | none | Stops waiting. In Python, a `threading.Event`. |
| `onPoll` | `on_poll` | none | Receives the first response and each poll. |

`JobTimeoutError` and `JobCancelledError` keep the job ID and last response (`jobId`/`lastResponse` in TypeScript, `job_id`/`last_response` in Python), so you can resume with `.wait(error.jobId)` or `.wait(error.job_id)`. Stopping a wait doesn't cancel the remote job. In TypeScript it cancels the in-flight poll; the synchronous Python client checks cancellation and the deadline between requests and callbacks, so it can't interrupt an HTTP call that is already in progress. HTTP failures are raised as they are, and submissions are never retried. These helpers poll from your process; they don't add background execution to the gateway.

### Keep a handle across processes

`music.start`, `videos.start` and `batches.start` return a handle with `result()`, `events()` and `cancel()`, plus `toJSON()` (TypeScript) or `to_dict()` (Python). Store the kind and ID it returns and rebuild the handle later with `resume(id)`. `result()` throws on terminal failures. Only video and batch jobs support `cancel()`. On `AsyncPhaseo`, await the methods and iterate events with `async for`.

| Task | TypeScript | Python |
| --- | --- | --- |
| Stream video content | `videos.streamContent(id)`, written with `downloadTo(stream, writable)` | `videos.stream_content(id)`, written with the synchronous `download_to(chunks, binary_file)`, which doesn't hold the whole download in memory |
| Stream batch results | `batchResults(await client.batches.streamResults(id))` parses JSONL one row at a time; `matchBatchResult(row, inputsByCustomId)` pairs each row with its input and keeps per-row errors | `batches.results(id)` |
| Prepare uploads | `toFile(bytes, filename, contentType)` | Pass bytes, `Path` objects, file objects or HTTPX file tuples |

## Request controls and errors

Retries default to `0` in TypeScript, Python and Java, and apply only to `GET` and `HEAD` requests. Paid submissions, writes and streaming requests are never retried.

<CodeGroup>

```typescript TypeScript
const fast = client.withOptions({ timeoutMs: 30_000, signal, maxRetries: 2 });
```

```python Python
fast = client.with_options(timeout=30, max_retries=2)
```

```java Java
Phaseo client = new Phaseo(System.getenv("PHASEO_API_KEY"))
    .setTimeout(Duration.ofSeconds(30))
    .setMaxRetries(2);
```

</CodeGroup>

<Tabs>
<Tab title="TypeScript">

`withOptions(...)` returns a new client with those controls applied to every resource, stream and media call; the original client is unchanged. Retries honour `Retry-After`. `timeoutMs` includes reading the response body.

`responseMetadata(result)` returns the gateway request ID and the dashboard trace URL. HTTP errors are `PhaseoHttpError`, with the HTTP `status`, the API error `code`, `requestId`, `traceUrl`, the retry delay, the body and `headers`.

</Tab>
<Tab title="Python">

`with_options(...)` returns a new client and also takes `headers=...`; it works on both `Phaseo` and `AsyncPhaseo`. Retries happen before the response is read, up to a maximum of `10`. Timeouts are HTTPX timeouts in seconds, so they bound network inactivity rather than total duration.

JSON responses are `APIResponse` dicts with `output_text`, `request_id` and `trace_url`. HTTP errors are `PhaseoHTTPError`, with `status`, `code`, `request_id`, `trace_url`, the retry delay and the body.

When upgrading from an older release, replace catches of `urllib.error.HTTPError` with `PhaseoHTTPError` (or `httpx.HTTPStatusError`), and connection-error catches with `httpx.TransportError`.

</Tab>
<Tab title="Java">

HTTP errors are `Client.ApiException` (`app.phaseo.gen.Client`), with `getStatusCode()`, `getRequestId()`, `getResponseBody()` and the headers. `requestWithResponse(...)` returns the data with its `requestId()`.

</Tab>
<Tab title="Rust">

Every call returns `Result<PhaseoResponse, PhaseoError>`. `PhaseoError` implements `std::error::Error` and `Display`; transport and configuration failures have no `status`.

| Type | Field | Meaning |
| --- | --- | --- |
| `PhaseoResponse` | `status: u16` | HTTP status code. |
| `PhaseoResponse` | `body: serde_json::Value` | Parsed JSON response, or a JSON string when the response wasn't valid JSON. |
| `PhaseoResponse` | `request_id: Option<String>` | The `x-request-id` response header, when present. |
| `PhaseoError` | `message: String` | Configuration, transport, or Gateway error message. |
| `PhaseoError` | `status: Option<u16>` | Gateway HTTP status, when a response was received. |
| `PhaseoError` | `body: Option<serde_json::Value>` | Parsed Gateway error body, when available. |

## Call an endpoint without a wrapper

Each SDK also ships the client generated from the Phaseo OpenAPI spec:

| Language | Generated client |
| --- | --- |
| TypeScript | `client.rawClient()`; the generated operations are exported as `operations`. |
| Python | `client.raw_client()`; the generated operations live in `phaseo.ops`. |
| Go | `client.RawClient()`, from `src/gen`. `client.Request(ctx, method, path, query, headers, body)` sends any request. |
| Java | `client.rawClient()`, with `requestLines` for streams and `requestBytes` for binary responses. |
| Rust | `phaseo::gen` holds the generated client, models and operations, re-exported as `phaseo::client`, `phaseo::models` and `phaseo::operations`. `phaseo::model_ids` has the generated model IDs. `client.post(path, body)` sends JSON to any path under the base URL. See [docs.rs](https://docs.rs/phaseo). |

The generated operations are lower-level than the wrapper methods; prefer the wrapper where one exists.

## Parse output and collect streams

These helpers are in TypeScript and Python. `responses.parse(request, schema)` validates a completed JSON response. In TypeScript, `schema` is a Zod-compatible parser; in Python, a Pydantic model. Set the structured-output format in the request as well; the parser only validates.

`collectStream(client.streamResponses(request))` (TypeScript), or `collect_stream` and `collect_async_stream` (Python), gather the streamed text and usage.

## Check a model before you call it

`checkModelCapabilities` / `check_model_capabilities` (TypeScript and Python) checks advertised capabilities and scalar constraints (`inputTypes`, `outputTypes`, `endpoints`, `parameters`, `parameterValues`, or the snake_case names in Python) on one active provider offer. It never changes the model or drops parameters, and it can't guarantee a live provider will accept the request. Missing metadata is handled differently: TypeScript reports it as unknown, and Python fails the check.

For model pickers and parameter editors, use live endpoint metadata:

<CodeGroup>

```typescript TypeScript
const support = await client.models.checkParameters(
  "anthropic/claude-haiku-4.5",
  { temperature: 0.7, top_p: 0.9 },
  { endpoint: "responses" },
);
```

```python Python
support = client.models.check_parameters(
    "anthropic/claude-haiku-4.5",
    {"temperature": 0.7, "top_p": 0.9},
    endpoint="responses",
)
```

</CodeGroup>

Each parameter comes back as `supported`, `partial`, `unsupported`, or `unknown`, with matching provider routes and constraint issues you can highlight inline. These checks are explicit calls; they don't add a lookup to generation requests. [Models](./models#check-one-model) lists the method in each SDK.

## Test without the network

<Tabs>
<Tab title="TypeScript">

Import `createMockTransport` and `jobFixtures` from `@phaseo/sdk/testing` and pass the mock's `fetchImpl` to the client. Fixtures are strict and ordered: an unexpected call fails locally and never reaches the network. Call `mock.assertDone()` to check every expected request happened.

</Tab>
<Tab title="Python">

Pass `phaseo.testing.MockTransport(fixtures)` to an `httpx.Client` or `httpx.AsyncClient` and give that to the Phaseo client as `http_client`. An unexpected request fails locally; call `assert_done()` to check every fixture was used. `phaseo.testing.job_fixtures(path, job_id)` builds the submit-and-poll fixtures for a job. Fixtures don't verify live provider behaviour.

</Tab>
</Tabs>

## Export code from a room

After you send a request in a Phaseo room, **Get code** exports its model and settings as TypeScript or Python, and **View request** opens its dashboard trace when a request ID is available. Run exported code on your server with `PHASEO_API_KEY` set.
