| Language | Method | Multi-value filters |
| --- | --- | --- |
| TypeScript | `client.getModels(filters)` or `client.models.list(filters)` | Arrays |
| Python | `client.get_models(filters)` or `client.models.list(filters)` | Lists |
| Go | `client.GetModels(ctx, query)` with a `map[string]string` | Comma-separated strings |

| Ruby | `client.list_models(...)` | Comma-separated strings |
| Java | `client.listModels(query)` with a `Map<String, String>` | Comma-separated strings |
| Rust | No helper; call `client.request("GET", "/models?<filters>", None, &RequestOptions::default())` | Comma-separated strings in the query string |

## Filter the list

All filters are optional and have the same names in every SDK: they're the query parameters.

| Filter | Filters by |
| --- | --- |
| `provider`, `organisation` | Provider or model organisation |
| `endpoints`, `input_types`, `output_types`, `params` | Supported endpoints, modalities, and request parameters |
| `status`, `provider_status`, `provider_routing_status`, `model_routing_status`, `capability_status`, `provider_availability_status`, `provider_availability_reason` | Lifecycle and routing state |
| `availability` | Set `all` to include models that can't be routed |
| `limit`, `offset` | Paging |

By default the list holds only routable models. Set `availability` to `all` to include the rest, then narrow it:

- `provider_availability_reason` selects rollout states such as `preview_only`, `provider_not_ready`, `gated`, `access_limited`, `region_limited`, `project_limited`, `paused` or `soft_blocked`.
- `capability_status` selects endpoint mappings that aren't routable yet, such as `coming_soon` or `internal_testing`.

## Check one model

`checkParameters` and its equivalents read live provider-route metadata, mark each parameter `supported`, `partial`, `unsupported` or `unknown`, check advertised values and ranges, and return the provider routes that accept the whole set. `preflight` does the same for a whole request body and adds the model's lifecycle check, with an overall `ok`.

| Language | Capabilities | Check parameters | Preflight | Lifecycle |
| --- | --- | --- | --- | --- |
| TypeScript | `models.capabilities(modelId)` | `models.checkParameters(modelId, values, { endpoint, provider })` | `models.preflight(request, { endpoint, provider })` | `models.validate(modelId)` returns `{ ok, info, reason }`; `models.getDeprecationInfo(modelId)` |
| Python | `models.capabilities(model_id)` | `models.check_parameters(model_id, values, endpoint=..., provider=...)` | `models.preflight(request, endpoint=..., provider=...)` | `models.validate(model_id)`, `models.get_deprecation_info(model_id)` |
| Go (next release) | `GetModelEndpointCapabilities` | `CheckModelParameters` | `PreflightRequest` | `ValidateModel`, `GetModelDeprecationInfo` (published) |
| C# (next release) | `GetModelEndpointCapabilities(modelId)` | `CheckModelParameters(modelId, values)` | `PreflightRequest` | `ValidateModel`, `GetModelDeprecationInfo` (published) |
| PHP (next release) | `getModelEndpointCapabilities` | `checkModelParameters(...)` | `preflightRequest` | `validateModel`, `getModelDeprecationInfo` (published) |
| Ruby (next release) | `model_endpoint_capabilities` | `check_model_parameters(model_id, values)` | `preflight_request` | `validate_model`, `get_model_deprecation_info` (published) |
| Java (source build) | `getModelEndpointCapabilities(modelId, query)` | `checkModelParameters(modelId, values, options)` | `preflightRequest(request, options)` | `validateModel`, `getModelDeprecationInfo` |
| Rust (not in `0.2.0`) | `Phaseo::model_endpoint_capabilities(...)` | `Phaseo::check_model_parameters(...)` | None | None |

"Next release" means the method is in the SDK source but not in the published package; see [Check what each package ships](./overview#check-what-each-package-ships). The deprecation-info methods return the model's status (`active`, `deprecated` or `retired`), deprecation and retirement dates, and replacement model ID.
