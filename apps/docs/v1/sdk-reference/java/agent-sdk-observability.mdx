Handle transport and gateway failures separately from invalid tool or output data. A failed run retains its status, active step, retry count, request ID, native response ID, and available gateway details.

## Common checks

- Confirm `PHASEO_API_KEY` is available to the Java process.
- Give every tool a unique stable ID.
- Supply approvals, rejections, and manual output using exact tool-call IDs.
- Persist a paused `RunResult` before returning control to another request or worker.
- Keep validators deterministic and free of side effects.
- Treat cancellation and timeout exceptions as terminal unless the application explicitly starts a new run.

Use lifecycle hooks for application telemetry and DevTools for a local run record rather than relying on console output alone.
