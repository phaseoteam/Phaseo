In AI SDK code, swap `@ai-sdk/gateway` for `@phaseo/ai-sdk-provider` and wrap each model ID with `phaseo(...)`. In OpenAI-compatible clients, change the base URL and key. Your generation logic stays the same.

| Setting | Vercel AI Gateway | Phaseo |
| --- | --- | --- |
| Base URL | `https://ai-gateway.vercel.sh/v1` | `https://api.phaseo.app/v1` |
| API key | `AI_GATEWAY_API_KEY` or Vercel OIDC | `PHASEO_API_KEY`, as a server-side secret |
| AI SDK provider | `@ai-sdk/gateway`, or bare string models | `@phaseo/ai-sdk-provider` |
| Routing options | `providerOptions.gateway` | `providerOptions.phaseo` |

## Switch the provider

<CodeGroup>
```typescript AI SDK
import { generateText } from "ai";
// Before: import { gateway } from "@ai-sdk/gateway";
import { phaseo } from "@phaseo/ai-sdk-provider";

const { text } = await generateText({
  // Before: model: gateway("openai/gpt-4.1-mini"),
  model: phaseo("openai/gpt-4.1-mini"),
  prompt: "Generate a migration checklist.",
});
```

```typescript OpenAI SDK
import OpenAI from "openai";

// Before:
// new OpenAI({ apiKey: process.env.AI_GATEWAY_API_KEY, baseURL: "https://ai-gateway.vercel.sh/v1" });
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});
```

```bash cURL
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role":"user","content":"Hello"}]
  }'
```
</CodeGroup>

The default `phaseo` export reads `PHASEO_API_KEY` once, when the module is imported, and uses `https://api.phaseo.app/v1`. If the variable is set after imports, as in some serverless and test setups, every call throws a missing-key error; call `createPhaseo({ apiKey, baseURL, headers })` inside the handler instead.

Install the provider line that matches your `ai` major: `@phaseo/ai-sdk-provider` for AI SDK 7, `@phaseo/ai-sdk-provider@ai-sdk-v6` for AI SDK 6, and `@phaseo/ai-sdk-provider@ai-sdk-v5` for AI SDK 5.

The AI SDK sends bare string models (`model: "openai/gpt-4.1-mini"`) through Vercel's gateway by default, so a bare string left behind keeps calling it. Change the shared model factory once, then search for `model: "` in AI SDK calls. Anthropic SDK clients pointed at `ai-gateway.vercel.sh` move to the setup in [Migrating from Anthropic SDK](./from-anthropic).

## Map gateway options

`providerOptions.phaseo` is merged into the request body. A leftover `providerOptions.gateway` is ignored without an error.

| Vercel AI Gateway | On Phaseo |
| --- | --- |
| `providerOptions.gateway.order`, `.only` | `providerOptions: { phaseo: { provider: { order, only } } }`, or a [preset](../guides/presets) called as `phaseo("@slug")`. |
| `providerOptions.gateway.models` | `providerOptions: { phaseo: { models: [...] } }`, or fallbacks in a dynamic route. |
| `providerOptions.gateway.sort` (`cost`, `ttft`, `tps`) | `provider.sort` (`price`, `latency`, `throughput`). |
| `providerOptions.gateway.zeroDataRetention` | `provider.require_zero_data_retention`, which limits routing to ZDR providers. |
| `providerOptions.gateway.user`, `.tags` | `user` and `X-Phaseo-Metadata` [labels](../guides/request-labels). |
| Request-scoped `byok` credentials | No equivalent. Add provider keys to the workspace with `phaseo byok create`. |
| Text, streaming, tools, structured output, embeddings, images, transcription, speech | Supported by the provider; capabilities still depend on the model. |
| Reranking | `phaseo.rerankingModel(id)` on the AI SDK 6 and 7 lines. |
| Managed file references, provider-executed tools | Not supported. Unsupported parts fail with an error instead of being dropped. |
| Gateway usage dashboard | Phaseo request logs and `GET /v1/generations?id=<request_id>`. Provider metadata on results includes the request ID. |

## Test and roll out

Run the same prompt set through both paths and compare latency, output format, and token usage. Before promoting traffic:

- `PHASEO_API_KEY` is set in every runtime that had the gateway key, including edge, server, and preview deployments;
- the main text-generation path and one streaming test pass unchanged in staging;
- tool calls and structured outputs pass if the app uses them;
- application-level error mapping still works;
- a failed staging request can be found and, when `replay_supported` is `true`, replayed from `GET /v1/generations?id=<request_id>`.

Ship behind a feature flag or a percentage rollout, starting with internal traffic. Watch latency, error rate, and token and cost drift, and keep the old provider available for at least one release so rollback needs no code change.

```bash
curl -s "https://api.phaseo.app/v1/health"
curl -s "https://api.phaseo.app/v1/models?format=openai" -H "Authorization: Bearer $PHASEO_API_KEY"
```

For more on the provider, see [AI SDK](../guides/integrations/ai-sdk).
