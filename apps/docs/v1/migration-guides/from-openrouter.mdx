Change the base URL to `https://api.phaseo.app/v1` and the key to `PHASEO_API_KEY`. Request payloads, the `Authorization: Bearer` header, the `provider` object, and the `models` fallback array keep working; check model IDs and the few fields in the table below.

| Setting | OpenRouter | Phaseo |
| --- | --- | --- |
| Base URL | `https://openrouter.ai/api/v1` | `https://api.phaseo.app/v1` |
| API key | `OPENROUTER_API_KEY` (`sk-or-v1-…`) | `PHASEO_API_KEY` |
| Authentication | `Authorization: Bearer <key>` | Unchanged |
| Request payload | OpenAI-compatible | Unchanged |
| Model IDs | `<org>/<model>` | `<org>/<model>`; most match, some orgs differ |
| Attribution headers | `HTTP-Referer`, `X-Title` | Unchanged; add `X-App-Id` for stable grouping |

## Switch the client

<CodeGroup>
```typescript Before
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.OPENROUTER_API_KEY,
  baseURL: "https://openrouter.ai/api/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Summarize our migration plan." }],
});
```

```typescript After
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Summarize our migration plan." }],
});
```

```bash cURL
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role":"user","content":"Say hello"}]
  }'
```
</CodeGroup>

Keep the payload unchanged for the first pass and get parity before optimizing. Remove `OPENROUTER_BASE_URL` and the old key from code, CI, and hosting settings. `@openrouter/ai-sdk-provider` becomes `@phaseo/ai-sdk-provider` (see [Migrating from Vercel AI Gateway](./from-vercel)); OpenRouter's own SDKs (`@openrouter/sdk`, `openrouter` on PyPI) need a client change, not just a new base URL.

## Check model IDs

Most IDs match, but some orgs differ: `x-ai/` is `spacex-ai/`, `meta-llama/` is `meta/`, and `mistralai/` is `mistral/`. List Phaseo's IDs and check each production model against them:

```bash
curl -s "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY" | jq -r '.data[].id'
```

The default list contains only models you can call now; add `availability=all` to see inactive or coming-soon ones. Without `format=openai` the response is Phaseo's paged `models` list, which has no `data` array.

## Map request fields

| OpenRouter | On Phaseo |
| --- | --- |
| `provider.order`, `only`, `ignore`, `allow_fallbacks`, `require_parameters`, `max_price` | Same fields. Use base provider IDs, not endpoint slugs. |
| `provider.sort` | Same field: `price`, `latency`, or `throughput`. |
| `provider.zdr` | Accepted as an alias of `provider.require_zero_data_retention`. |
| `provider.data_collection: "deny"` | Returns `400`. Use `zdr: true` instead. |
| `models` fallback array | Same, 1 to 25 entries. `model` is required, so move `models[0]` into it. |
| `:nitro` suffix | Same (throughput). Phaseo also has `:cheap` and `:fast`; `:floor` becomes `:cheap`. Remove `:online` and `:thinking` and use web search and `reasoning` instead. |
| `openrouter/auto`, `openrouter/free` | `phaseo/auto` ([Auto Routing](../guides/auto-routing), alpha, can't be combined with `models`) and `phaseo/free`. |
| `plugins` `web`, `web-fetch`, `response-healing` | Same plugin IDs. Other plugins, such as `file-parser`, return `400`. |
| `transforms`, `usage: { include: true }` | Not accepted. Remove them; usage and cost are always returned. |
| `X-OpenRouter-Title` | Rename to `X-Title`. See [App Attribution](../guides/app-attribution). |
| Presets `@preset/<slug>` | Recreate them as [Presets](../guides/presets) and call them as `"model": "@slug"`. |
| `usage.cost`, `reasoning_details`, `provider` in responses | Returned. `native_finish_reason` and `is_byok` aren't; normalize them in one layer if callers read them. |

Phaseo also has `provider.required_execution_region` and `provider.required_data_region`, which have no OpenRouter counterpart. See [Pin or ignore providers](../cookbook/pin-or-ignore-providers-per-request) and [Route only to EU or ZDR-capable providers](../cookbook/route-only-to-eu-or-zdr-providers) for complete requests.

Keep any remaining OpenRouter-only fields in one adapter rather than at every call site, so rollback stays a base URL and key change.

## Validate before cutover

Run these against Phaseo, then the same checks through your app's own client path:

```bash
curl -s "https://api.phaseo.app/v1/health"

curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"openai/gpt-6-astra","messages":[{"role":"user","content":"Say hello"}]}'

# Streaming
curl -N "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"openai/gpt-6-astra","stream":true,"messages":[{"role":"user","content":"Reply with: stream works"}]}'

# Invalid model: the app should handle the error without exposing credentials
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"invalid/migration-test","messages":[{"role":"user","content":"test"}]}'
```

Before shifting meaningful traffic, confirm that:

- `OPENROUTER_API_KEY` is replaced with `PHASEO_API_KEY` in every environment;
- every production model ID is in `GET /v1/models?format=openai`;
- a non-streaming and a streaming request pass through `/v1/chat/completions` or `/v1/responses`, using the same client path as production;
- tool-calling and structured-output flows pass with real prompts;
- invalid-key and invalid-model failures are handled;
- a failed request can be looked up with `GET /v1/generations?id=<request_id>` and, when `replay_supported` is `true`, replayed from `replay_request`;
- OpenRouter-only headers and response fields are removed or normalized, and shared defaults live in presets.

## Roll out

1. Start with internal traffic.
2. Move 5-10% of production traffic and compare quality, latency, and cost.
3. Promote to 100% once parity is confirmed.
4. Keep rollback as a base URL and key switch until the cutover is stable.

## Hand the migration to a coding agent

Give the agent this bounded sequence, or install the [OpenRouter to Phaseo migration skill](https://github.com/phaseoteam/Phaseo/tree/main/.agents/skills/openrouter-to-phaseo-migration), which packages the same inventory, mapping, validation, and rollback steps:

1. Search runtime code and deployment config for `openrouter.ai`, `OPENROUTER_API_KEY`, `sk-or-v1`, `HTTP-Referer`, and `X-Title`.
2. Change the client boundary to `https://api.phaseo.app/v1` and `PHASEO_API_KEY` without adding a secret value to source control.
3. Query `GET /v1/models?format=openai` and record every old-to-new model mapping.
4. Adapt OpenRouter-only routing options or response fields in one compatibility module.
5. Run the health, non-streaming, streaming, and failure-path checks above.
6. Report changed files, secret-name changes, model mappings, test evidence, parity gaps, and the rollback switch.
