Swap the base URL and key, keep the request payloads, and map each model ID: LLM Gateway's prefix names the serving provider, while Phaseo's names the model's maker.

| Setting | LLM Gateway | Phaseo |
| --- | --- | --- |
| Base URL | `https://api.llmgateway.io/v1` | `https://api.phaseo.app/v1` |
| Anthropic-style clients | `ANTHROPIC_BASE_URL=https://api.llmgateway.io` | `https://api.phaseo.app`, see [Migrating from Anthropic SDK](./from-anthropic) |
| API key | `LLM_GATEWAY_API_KEY` (`llmgtwy_…`) | `PHASEO_API_KEY` |
| Model IDs | `gpt-4o`, `<provider>/<model>`, `auto` | `<org>/<model>` from `GET /v1/models?format=openai` |
| Request payload | OpenAI-compatible | Unchanged |

## Switch the client

<CodeGroup>
```typescript TypeScript
import OpenAI from "openai";

// Before:
// new OpenAI({ apiKey: process.env.LLM_GATEWAY_API_KEY, baseURL: "https://api.llmgateway.io/v1" });
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});
```

```python Python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
)
```

```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```
</CodeGroup>

Map or remove every `LLM_GATEWAY_*` variable, including in CI and hosting settings. If the app uses `@llmgateway/ai-sdk-provider`, switch to `@phaseo/ai-sdk-provider` as in [Migrating from Vercel AI Gateway](./from-vercel).

## Map model IDs

List Phaseo's IDs and check each production model against them:

```bash
curl -s "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY" | jq -r '.data[].id'
```

`alibaba/<model>` on LLM Gateway is not a Phaseo ID. Map each ID to Phaseo's `<org>/<model>`, and keep a provider pin with `provider.only` or a `provider:org/model` ID. Translate unprefixed aliases such as `gpt-4o` in one function at the client boundary rather than at every call site.

## Map gateway features

| LLM Gateway | On Phaseo |
| --- | --- |
| `auto` router | `phaseo/auto` ([Auto Routing](../guides/auto-routing), alpha); can't be combined with `models`. |
| Fallback chains | `models` array or dynamic routes, tried on `429`, `500`, `502`, `503` and `504`, never on request errors. |
| `X-No-Fallback` | `provider.allow_fallbacks: false`, or a `provider:org/model` ID. |
| Provider allow and deny logic | `provider.only`, `provider.ignore`, or [Presets](../guides/presets). Keep at least one eligible provider. |
| `X-LLMGateway-<Key>` headers | `X-Phaseo-Metadata` [labels](../guides/request-labels), up to 32. |
| Session headers (`x-session-id`) | `session_id` body field; Phaseo ignores session headers. |
| `X-Source` | `HTTP-Referer` or `X-App-Name`. See [App Attribution](../guides/app-attribution). |
| Response caching | No response cache. |
| Provider keys | BYOK (`phaseo byok create` or `POST /v1/byok`), or Phaseo credits. Fallback to credits is the `byok_fallback_enabled` workspace setting. |
| Request logs | Request logs, observability destinations, and `GET /v1/generations?id=<request_id>`. When `replay_supported` is `true`, replay a failed request from its `replay_request` payload. |

## Test and roll out

Run your golden prompts against both gateways and compare quality, latency, and cost. Check the endpoints first:

```bash
curl -s "https://api.phaseo.app/v1/health"
curl -s "https://api.phaseo.app/v1/models?format=openai" -H "Authorization: Bearer $PHASEO_API_KEY"
```

Before moving traffic:

- `PHASEO_API_KEY` is set in every environment;
- every production model ID is mapped and listed;
- a non-streaming and a streaming request pass in staging;
- invalid-key and invalid-model errors are handled; their bodies may differ from LLM Gateway's;
- a failed staging request can be recovered from `GET /v1/generations`;
- shared prompt and routing defaults live in presets where they belong.

Release behind a canary flag, move from a small share of traffic to all of it once stable, and watch production metrics for at least one release cycle before removing the old configuration.
