## Model migrations

For a tailored starting checklist, use the [Migration Assistant](https://phaseo.app/migrate).

Use model migrations when the integration stays broadly the same but the model changes underneath it.

These guides focus on:

- request parameter changes
- prompt and reasoning behavior shifts
- structured output and tool-calling differences
- rollout, fallback, and rollback strategy

## Platform migrations

Use platform migrations when you are changing SDKs, providers, or gateways and need to map your current integration onto Phaseo.

<Card title="Build a migration checklist" icon="list-checks" href="https://phaseo.app/migrate">
	Choose your current integration and open the interactive migration assistant.
</Card>

<Prompt description="Ask a coding agent to plan and carry out the migration with you." icon="arrow-right-left" actions={["copy", "cursor"]}>
{`Migrate this project's AI requests to Phaseo Gateway.

1. Install the Phaseo skills: npx skills add https://phaseo.app/docs
   Use phaseo-migration, which has a guide for each source platform (and openrouter-to-phaseo-migration for a detailed OpenRouter move).
2. Find every place the project calls its current provider or gateway (OpenAI, Anthropic, OpenRouter, Vercel AI Gateway, LiteLLM or another), including environment variables, SDK clients, base URLs and model IDs.
3. Read the matching guide at https://phaseo.app/docs/v1/migration-guides and map each call to its Phaseo equivalent at https://api.phaseo.app/v1 with a server-side PHASEO_API_KEY.
4. Check every model ID with GET /v1/models. Do not assume IDs carry over unchanged.
5. List the changes and a rollback plan before editing. After editing, verify one normal request and one streaming request if the project streams.
6. Never print or commit API keys, and do not switch production traffic without my approval.`}
</Prompt>

## How to use these guides

1. Identify whether you are changing the platform, the model, or both.
2. Start with the guide that matches the riskiest part of the migration.
3. Verify request parameters and endpoint behavior before comparing output quality.
4. Run production-like evals before shifting live traffic.
