Point the clients that call your LiteLLM proxy at `https://api.phaseo.app/v1` with a Phaseo key, then map each `model_name` alias and each proxy setting deliberately. To keep LiteLLM and use Phaseo as its upstream instead, see [LiteLLM integration](../guides/integrations/litellm).

| Setting | LiteLLM proxy | Phaseo |
| --- | --- | --- |
| Base URL | Your proxy, often `http://localhost:4000` | `https://api.phaseo.app/v1` |
| API key | `LITELLM_MASTER_KEY` or a virtual key | `PHASEO_API_KEY` |
| Model | `model_name` alias from `config.yaml` | Phaseo model ID, a preset (`"model": "@slug"`), or one mapping function |
| Routing and defaults | `router_settings`, `litellm_settings` | [Presets](../guides/presets) and [Routing and Fallbacks](../guides/routing-and-fallbacks) |

## Switch the client

<CodeGroup>
```typescript TypeScript
import OpenAI from "openai";

// Before:
// new OpenAI({ apiKey: process.env.LITELLM_API_KEY, baseURL: process.env.LITELLM_BASE_URL });
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-6-astra",
  messages: [{ role: "user", content: "Reply with: migration ready" }],
});
```

```python Python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
)
```

```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role": "user", "content": "Reply with: migration ready"}]
  }'
```
</CodeGroup>

Every alias needs an explicit mapping to an ID in `GET /v1/models?format=openai`. If callers use internal aliases, translate them in one function at the client boundary instead of editing every request.

## Map the proxy configuration

Inventory callbacks, budgets, and retries before removing the proxy: they stop silently when it goes away.

| LiteLLM | On Phaseo |
| --- | --- |
| `fallbacks` | `models` array or dynamic route fallbacks, tried on `429`, `500`, `502`, `503` and `504`, never on request errors. |
| `context_window_fallbacks`, `content_policy_fallbacks` | No equivalent: Phaseo never falls back on a `400`. Handle these in the app. |
| `routing_strategy` | Workspace routing mode or `provider.sort` (`price`, `latency`, `throughput`). |
| Per-deployment provider choice | `provider.order`, `provider.only`, `provider.ignore`, or a [provider-qualified ID](../guides/provider-qualified-models) such as `provider:org/model`, which doesn't fall back across providers. |
| Self-hosted deployments (vLLM and similar) | [Private Models](../guides/private-models), which need a public HTTPS OpenAI-compatible `/chat/completions` endpoint with bearer auth. |
| Response cache (`litellm_settings.cache`) | No response cache. Cache in the app if needed; [prompt caching](../guides/prompt-caching) still cuts input cost. |
| Virtual keys (`max_budget`, `rpm_limit`, `tpm_limit`, `max_parallel_requests`, `models`) | API keys with spend limits and allowed models, budgets, and rate limit policies for requests per minute, tokens per minute, and concurrent requests. See [Limits](../api-reference/limits). |
| Team budgets, `metadata.tags` | Department budgets and `X-Phaseo-Metadata` [labels](../guides/request-labels). End-user budgets map only to an end-user rate limit policy; there's no end-user spend cap. |
| `guardrails` (Presidio, Lakera and similar) | Key guardrails scan requests for prompt injection and PII. Responses aren't scanned. |
| Callbacks (`success_callback`, Langfuse, Datadog, OpenTelemetry) | [Observability destinations](../guides/integrations/observability) or client-side tracing. Body `metadata` exports as `phaseo.metadata.<key>`. |
| Provider API keys in config | BYOK (**Settings → BYOK** or `POST /v1/byok`), or Phaseo credits. Set `byok_fallback_enabled` with **Settings → BYOK** to fall back to credits. |

A proxy sends a whole team's traffic through one key owner, so it shares that user's requests-per-minute allowance, which is 10 for a new workspace. Check [Gateway limits](../api-reference/limits#gateway-limits) and arrange a higher limit before cutover.

## Test and roll out

Test streaming, tools, structured outputs, retries, error mapping, and any callback-driven telemetry the proxy handled. Compare latency, output, token usage, and cost before moving traffic gradually. Before cutover:

- every LiteLLM URL, key, and `LITELLM_*` variable is identified;
- every production alias has an explicit Phaseo mapping;
- shared defaults live in presets or one boundary function;
- required callbacks and telemetry have a replacement;
- you've decided whether LiteLLM, Phaseo, or both is the record for spend;
- rollback is still only a base URL and key change.
