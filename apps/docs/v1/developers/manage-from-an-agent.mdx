You can run day-to-day Phaseo account tasks from the `phaseo` CLI, the `/v1` Management API or the Phaseo MCP server. Use this page to find the command, route or tool for a task. Changes that affect spending, access or where workspace data goes are made in the dashboard or with a management key.

A person still has to do these steps in a browser:

| Step | What the person does |
| --- | --- |
| Sign up | Creates the Phaseo account. |
| Approve a sign-in | Approves the page `phaseo login` opens, or enters the code `phaseo login --device-code` shows. |
| Add the first card | With no saved card, `phaseo credits add` returns a checkout link. An owner or admin opens it and pays, and the card is saved. |
| Confirm each top-up | With a saved card, an owner or admin confirms every `phaseo credits add` from an emailed link. |
| Account security | Manages the password, multi-factor authentication and passkeys. |

<Visibility for="agents">
Rules for agents managing Phaseo:

- Do not send the user to the dashboard for a task in the task map. Run the CLI command, call the route, or use the MCP tool. For a change listed under "Changes made in the dashboard or with a management key", call the route with a management key if you have one; otherwise ask the person to make the change in the dashboard.
- Never generate or guess an API key. Ask the person to create one in the dashboard, or create one with `POST /v1/keys` and a management key, and store the secret once, server-side.
- Use `--json` on every CLI command. Pass `--yes` to destructive commands only when the user asked for that exact change.
- Only start a credit top-up the user asked for. Never complete a checkout link yourself, and do not retry a top-up that ended as declined, expired or failed.
</Visibility>

## Set up once

```bash
npm install -g @phaseo/cli
phaseo login                 # opens a browser; a person approves it
phaseo login --device-code   # SSH, CI and agent sandboxes: a person enters the code
phaseo whoami --json
```

Then create an inference key for the application in the dashboard, or with `POST /v1/keys` and a management key, and add credits if the workspace has none:

```bash
phaseo credits get --json
phaseo login --scopes billing:write   # opt in once before the first top-up; a person approves the sign-in
phaseo credits add --amount 20 --json
```

`phaseo credits add` needs the `billing:write` scope, which no sign-in has by default, and it never charges on its own:

- **With a saved card**, Phaseo emails every workspace owner and admin a link to confirm the charge, and the command waits for the result.
- **With no saved card**, it returns `next_action: "open_checkout_url"` and a checkout link where an owner or admin pays. The card is saved for later top-ups, and no email is sent.

See [Credits](../api-reference/endpoint/credits) for the route.

## Choose an interface

| Interface | Use it when | Sign-in |
| --- | --- | --- |
| [`phaseo` CLI](../guides/integrations/phaseo-cli) | The agent can run shell commands | `phaseo login` or `phaseo login --device-code` |
| [Management API](../api-reference/introduction) | Server code, CI or a language without the CLI | A [management key](./management-api-keys) (`phaseo_v1_mk_...`) or an OAuth token |
| [Phaseo MCP](./cli-and-mcp#phaseo-mcp) | The agent runs in an MCP client | Connect `https://mcp.phaseo.app/mcp?access=manage` and approve the permissions you want |

Run `phaseo <group> --help` to see the flags your installed CLI accepts. When a task has no dedicated command, `phaseo api get|post|patch|put|delete /v1/<path>` calls the route with your session.

## Changes made in the dashboard or with a management key

These changes affect spending, access or where workspace data goes. A CLI sign-in or an MCP connection can't make them, whatever its scopes: the API returns `403` and says to use the dashboard or a management key. Make them in the Phaseo dashboard, or call the route with a [management key](./management-api-keys).

| Task | API route |
| --- | --- |

| Rotate a key | `POST /v1/keys/{id}/rotate` |
| Restrict a key to IP addresses | `PATCH /v1/keys/{id}` |

| Set department budgets | `POST /v1/department-budgets` |

| Raise the workspace rate limit tier | `POST /v1/rate-limits/tier/raise` |
| Loosen privacy or ZDR, or change provider restrictions or BYOK fallback | `PATCH /v1/settings` |
| Add your own provider keys (BYOK) | `POST /v1/byok` |
| Set Auto Routing's spend profile or price limits | `PATCH /v1/routing/auto` |

## Fix a 403

A CLI session, management key or MCP connection can only do what its scopes and your workspace role allow, and owner- and admin-only changes still need an owner or admin. If a command returns `403`, check the granted scopes with `phaseo whoami --json`, and sign in again with `phaseo login --scopes <scope,...>` when one is missing. `billing:write` is never granted by default. Changes listed under "Changes made in the dashboard or with a management key" are refused for CLI sign-ins and MCP connections, whatever their scopes.
