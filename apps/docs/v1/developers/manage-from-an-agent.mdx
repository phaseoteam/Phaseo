You can run a Phaseo account from the `phaseo` CLI, the `/v1` Management API or the Phaseo MCP server, without opening the dashboard. Use this page to find the command, route or tool for a task.

Only three steps need a person in a browser:

- **Signing up** for a Phaseo account.
- **Approving the first sign-in**: the browser page that `phaseo login` opens, or the code that `phaseo login --device-code` shows.
- **Entering a card the first time** credits are bought. Later top-ups use the saved card, and a workspace owner or admin approves each one from an emailed link.

<Visibility for="agents">
Rules for agents managing Phaseo:

- Do not send the user to the dashboard for a task in the table below. Run the CLI command, call the route, or use the MCP tool.
- Never generate or guess an API key. Create one with `phaseo keys create --name <name> --json` and store the secret once, server-side.
- Use `--json` on every CLI command. Pass `--yes` to destructive commands only when the user asked for that exact change.
- Only start a credit top-up the user asked for. Never complete a checkout link yourself, and do not retry a top-up that ended as declined, expired or failed.
</Visibility>

## Set up once

```bash
npm install -g @phaseo/cli
phaseo login                 # opens a browser; a person approves it
phaseo login --device-code   # SSH, CI and agent sandboxes: a person enters the code
phaseo whoami --json
```

Then create an inference key for the application and add credits if the workspace has none:

```bash
phaseo keys create --name "Production app" --json
phaseo credits get --json
phaseo login --scopes billing:write   # one-time opt-in before the first top-up
phaseo credits add --amount 20 --json
```

`phaseo credits add` never charges on its own. With a saved card, Phaseo emails every workspace owner and admin a link to confirm the charge, and the command waits for the result. With no saved card, it returns a link where an owner or admin enters a card. See [Credits](../api-reference/endpoint/credits) for the route.

## Choose an interface

| Interface | Use it when | Sign-in |
| --- | --- | --- |
| [`phaseo` CLI](../guides/integrations/phaseo-cli) | The agent can run shell commands | `phaseo login` or `phaseo login --device-code` |
| [Management API](../api-reference/introduction) | Server code, CI or a language without the CLI | A [management key](./management-api-keys) (`phaseo_v1_mk_...`) or an OAuth token |
| [Phaseo MCP](./cli-and-mcp#phaseo-mcp) | The agent runs in an MCP client | Connect `https://mcp.phaseo.app/mcp?access=manage` and approve the permissions you want |

Run `phaseo <group> --help` to see the flags your installed CLI accepts. When a task has no dedicated command, `phaseo api get|post|patch|put|delete /v1/<path>` calls the route with your session.

## Task map

### Keys and access

| Task | CLI | API route | MCP tool |
| --- | --- | --- | --- |
| Create an API key | `phaseo keys create --name <name>` | `POST /v1/keys` | `api_key_create` |
| List, update or delete keys | `phaseo keys list`, `keys update <id>`, `keys delete <id>` | `GET`, `PATCH`, `DELETE /v1/keys/{id}` | `api_keys_list`, `api_key_update`, `api_key_delete` |
| Rotate a key | `phaseo keys rotate <id>` | `POST /v1/keys/{id}/rotate` | `api_key_rotate` |
| Restrict a key to IP addresses | `phaseo keys update <id> --ip-allowlist <label=address,...>` | `PATCH /v1/keys/{id}` | — |
| Create a management key | `phaseo management-keys create --name <name>` | `POST /v1/management-keys` | — |
| Review or revoke apps you authorized | `phaseo authorized-apps list`, `authorized-apps revoke <id>` | `GET`, `DELETE /v1/me/authorized-apps/{id}` | — |
| Update your profile | `phaseo profile update` | `PATCH /v1/me/profile` | — |

## Permissions

A CLI session, management key or MCP connection can only do what its scopes and your workspace role allow. Owner- and admin-only changes still need an owner or admin. If a command returns `403`, check `phaseo whoami --json` for the granted scopes, and sign in again with `phaseo login --scopes <scope,...>` when a scope is missing. `billing:write` is never granted by default.
