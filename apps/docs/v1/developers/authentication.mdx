Create a key with `phaseo keys create --name <name> --json` in the [Phaseo CLI](../guides/integrations/phaseo-cli) or in the [dashboard](https://phaseo.app/settings/keys), store it on your server, and send it as a bearer token with every Gateway request. Agents should use the CLI; see [Manage Phaseo from an agent](./manage-from-an-agent).

```http
Authorization: Bearer phaseo_v1_sk_<kid>_<secret>
```

Set the header once on your client. For example, with `fetch`:

```ts
const response = await fetch("https://api.phaseo.app/v1/chat/completions", {
	method: "POST",
	headers: {
		Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
		"Content-Type": "application/json",
	},
	body: JSON.stringify({
		model: "openai/gpt-6-astra",
		messages: [
			{ role: "system", content: "You are a helpful assistant." },
			{ role: "user", content: "Summarize the drawbacks to AI." },
		],
	}),
});
```

<Note>
You can call `:free` models without depositing credits. Paid models need available wallet balance.
</Note>

## Choose a credential

| Credential | Format | Use it for |
| --- | --- | --- |
| Gateway API key | `phaseo_v1_sk_<kid>_<secret>` | Model, provider and generation endpoints available to your workspace. |
| [Management API key](./management-api-keys.mdx) | `phaseo_v1_mk_<kid>_<secret>` | Administration APIs. |
| [Trusted workload](./trusted-workloads.mdx) (beta) | A short-lived OIDC token from the platform | Deployments and CI jobs on Vercel, GitHub Actions, GitLab, Google Cloud, Buildkite, CircleCI, AWS or your own OIDC issuer, with no stored key. |

Treat keys like passwords: keep them out of client-side code and public repositories.

## Handle keys safely

- **One key per app and environment**, so you can rotate one without affecting other services.
- **Store keys in a secrets manager**, which keeps them out of logs and error tracking.
- **Watch per-key usage** in the dashboard to spot anomalies.
- **Delete keys you no longer use.**

To rotate a key, move your application to the replacement before you invalidate the old one. See the [key rotation endpoint](../api-reference/endpoint/keys-rotate.mdx).

## Fix authentication errors

| Status | Cause | What to do |
| --- | --- | --- |
| `401` | The key is missing, invalid, or belongs to a disabled workspace. The body's `reason` says which. | Check the header and the key. |
| `403` | The key is valid but can't use the requested provider or model. | Check the key's guardrails and the workspace's provider settings. |
| `429` | The key or workspace reached a limit. | See [Rate Limits](../api-reference/limits.mdx). |
| `5xx` | Phaseo or the provider failed. | Retry with exponential backoff, and contact [support](https://phaseo.app/help) if it persists. |

See [Errors and Debugging](../api-reference/errors.mdx) for every error code.
