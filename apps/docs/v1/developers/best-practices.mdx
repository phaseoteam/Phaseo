Put Gateway calls behind one service on your backend, keep keys out of clients and logs, retry only what is safe to retry, and watch latency, cost and errors per model. Each section below links to the page with the details.

## Structure the integration

- **Wrap Gateway calls in one service or SDK client**, so a model or provider change stays in one place. See [Integrating with the Gateway](./integrating-with-the-gateway.mdx).
- **Stream responses to chat UIs**, so users see tokens as they arrive. See [Streaming](../guides/streaming.mdx).
- **Queue work that isn't urgent**, such as background generations and evaluations, to smooth out traffic spikes. The [Batch API](../guides/async-video-and-batch.mdx) runs large jobs asynchronously.

## Keep keys secret

- Store API keys in a secrets manager (AWS Secrets Manager, Doppler, 1Password) rather than `.env` files in production.
- Call the Gateway from your backend, and authenticate your own client apps to it, so clients never hold a Gateway key.
- Log only a key's prefix, such as `phaseo_v1_sk_<kid>`, never the secret.

See [Authentication](./authentication.mdx).

## Retry safely

- Retry `429` and `5xx` responses with exponential backoff and jitter.
- Wait for [`Retry-After`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Retry-After) before retrying a rate-limited request.
- Check which provider served each request in request logs, so you notice when traffic fails over to another provider.

See [Errors and Debugging](../api-reference/errors.mdx) and [Rate Limits](../api-reference/limits.mdx).

## Watch the right signals

| Signal | What to do |
| --- | --- |
| Latency | Track p95 and p99 to catch regressions. |
| Token usage | Compare cost with the business metric it supports. |
| Error rate | Alert when failures stay above 1%. |
| Provider mix | Check traffic is split across providers as you expect. |

See [Request logs and observability](../guides/integrations/observability.mdx). Keep your prompt templates, parameters and output handling documented where your team can review them; [presets](../guides/presets.mdx) keep shared prompts and defaults in one place.
