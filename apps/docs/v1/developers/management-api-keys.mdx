Create a management key to call Phaseo's administration APIs from your own servers: credits, activity, workspaces, keys, presets, settings and guardrails. Management keys can't send inference requests.

```bash
phaseo management-keys create --name <name> --template read-only --json
```

Or create one in the dashboard under **Settings → Management Keys**. The secret is shown once, so store it in your secrets manager. Send it from server-side code only, to the same base URL as the Gateway (`https://api.phaseo.app/v1`):

```http
Authorization: Bearer phaseo_v1_mk_<kid>_<secret>
```

## Management keys, API keys and OAuth tokens

| Credential | Format | Use it for | Limited by |
| --- | --- | --- | --- |
| Gateway API key | `phaseo_v1_sk_<kid>_<secret>` | Model and generation requests | Routing policy, budgets, limits and attached guardrails |
| Management API key | `phaseo_v1_mk_<kid>_<secret>` | Administration requests | Its capabilities and your workspace role |
| OAuth access token | | Administration on a user's behalf | The approved OAuth scopes and the user's workspace role |

Management routes accept only management keys (or OAuth tokens); a Gateway API key can't call them.

[Guardrails](../cookbook/guardrails-for-api-keys.mdx) are a separate control: they apply to Gateway API keys and govern inference traffic, such as routing restrictions, budgets, prompt-injection handling and sensitive-information rules. A management key's capabilities govern which administration APIs it can call.

## Choose an access level

Each template expands to an explicit list of capabilities when the key is created. Phaseo never stores a wildcard such as `all`, so a key never gains a permission added later.

| Template | `--template` | Grants |
| --- | --- | --- |
| **Read** | `read-only` | Every current `*:read` capability |
| **Write** | `read-write` | Every current `*:read` and `*:write` capability, no delete |
| **All** | `full-control` | Every current read, write and delete capability |

No template includes `billing:write`, which starts credit top-ups; ask for it explicitly with `--scopes`. Use **All** only for trusted administrative automation.

For a smaller grant, pass the capabilities you need with `--scopes scope_a,scope_b`:

| Area | Read | Write | Delete |
| --- | --- | --- | --- |
| Identity and catalogue | `me:read`, `models:read`, `providers:read`, `pricing:read` | | |
| Usage and observability | `credits:read`, `activity:read`, `analytics:read`, `generations:read`, `feedback:read` | `feedback:write` | |
| Billing | | `billing:write` (opt-in) | |
| Workspaces | `workspaces:read` | `workspaces:write` | `workspaces:delete` |
| Gateway API keys | `keys:read` | `keys:write` | `keys:delete` |
| Management API keys | `management_keys:read` | `management_keys:write` | `management_keys:delete` |
| Presets | `presets:read` | `presets:write` | `presets:delete` |
| Settings | `settings:read` | `settings:write` | |
| Provider credentials | `provider_credentials:read` | `provider_credentials:write` | `provider_credentials:delete` |
| Private models | `private_models:read` | `private_models:write` | `private_models:delete` |
| Guardrails | `guardrails:read` | `guardrails:write` | `guardrails:delete` |
| Budgets | `budgets:read` | `budgets:write` | `budgets:delete` |
| Rate limits | `rate_limits:read` | `rate_limits:write` | `rate_limits:delete` |
| Classifiers | `classifiers:read` | `classifiers:write` | `classifiers:delete` |
| Spend rules | `spend_rules:read` | `spend_rules:write` | `spend_rules:delete` |
| OAuth clients | `oauth_clients:read` | `oauth_clients:write` | `oauth_clients:delete` |

## Capabilities don't override workspace roles

Phaseo checks two things on every call: that the key has the capability, and that the key or OAuth user belongs to the workspace with the role the action needs. For example, `keys:write` allows key management, but the role check still decides whether the caller may manage keys in that workspace. A key can't use a capability to reach another workspace or skip owner and admin checks.

## Keep keys safe

- Keep management keys out of browsers, desktop logs, source control and chat.
- Use one key per integration, with the narrowest template that works.
- Set an expiry when the integration doesn't need indefinite access.
- Pause or delete unused keys straight away.
- Rotate a leaked key before you investigate further.
