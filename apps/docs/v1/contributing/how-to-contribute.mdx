Use this workflow for code and documentation changes. For model, provider, pricing, organisation, or benchmark records, [submit a catalog issue](./overview.mdx) instead; no local setup is needed.

## Set up your fork

Install Git, Node.js 22.12 or newer, and pnpm. Fork the [Phaseo repository](https://github.com/phaseoteam/Phaseo), then clone your fork and create a new branch:

```bash
git clone https://github.com/yourusername/Phaseo.git
cd Phaseo
git switch -c docs/improve-quickstart
pnpm install
```

## Make and preview the change

See [Repository structure](./repo-structure.mdx) for the relevant application or package. For Markdown-only edits, you can also use GitHub's file editor and open a pull request there.

```bash
# Web app at http://localhost:3100
pnpm --filter @phaseo/web dev

# Documentation at http://localhost:3101
pnpm --filter @phaseo/docs dev
```

Follow the relevant `AGENTS.md` instructions. Keep secrets in local environment files and out of commits. Local app previews may require configured backend services and normal sign-in.

## Validate your changes

Run the checks relevant to the files you changed. For documentation:

```bash
pnpm docs:links
pnpm docs:build
```

For web changes:

```bash
pnpm --filter @phaseo/web lint
pnpm --filter @phaseo/web typecheck
pnpm --filter @phaseo/web test
```

Run a production build for rendering or routing changes. API, SDK, and schema changes need their corresponding tests and generation steps. See the root [contribution guide](https://github.com/phaseoteam/Phaseo/blob/main/CONTRIBUTING.md).

## Open a pull request

Stage only the files you changed, use a descriptive commit message, and push your branch:

```bash
git add apps/docs/v1/quickstart.mdx
git commit -m "docs: clarify the quickstart"
git push -u origin docs/improve-quickstart
```

Open a pull request from your fork. Explain the problem, what changed, and which checks passed. Link related issues and include screenshots for visible UI changes. Address review feedback before merge; changes become live after the relevant deployment completes.

Follow the [Code of Conduct](../community/code-of-conduct.mdx). For large or uncertain changes, discuss the proposal before writing code.
