Open **Settings → Workspace → Activity** to see who changed a key, member, or other administrative control in the active workspace, and when. Events are listed newest first. Only workspace owners and admins can read the log.

Request and generation logs show what traffic ran. The audit log shows who changed the controls around it.

## What is recorded

| Area | Example actions |
| --- | --- |
| API keys | `api_key.created`, `api_key.updated`, `api_key.paused`, `api_key.resumed`, `api_key.rotated`, `api_key.deleted` |
| Management keys | `management_key.created`, `management_key.updated`, `management_key.deleted` |
| Members and invites | `workspace.member.added`, `workspace.member.role_updated`, `workspace.member.removed`, `workspace.invite.created` |
| Provider keys (BYOK) | `provider_credential.created`, `provider_credential.updated`, `provider_credential.reordered`, `provider_credential.deleted` |
| Routing and presets | `routing.policy.updated`, `routing.dynamic_route.deployed`, `preset.version.published` |
| Budgets and spend | `workspace_budget.updated`, `spend_block.lifted`, `rate_limit_raise.requested` |
| Guardrails | `guardrail.created`, `guardrail.updated`, `guardrail.keys.added` |
| Identity | `identity.sso.updated`, `identity.scim_token.created`, `identity.group_mapping.updated` |
| Integrations | `observability.destination.created`, `notifications.destination.created`, `webhook_endpoint.secret_rotated`, `oauth_authorization.revoked` |

Each event has the actor, action, target type, target ID and name, timestamp, request ID, and a small set of change metadata. Events are append-only.

The log never stores plaintext keys, credential hashes, authorization headers, full scope lists, or request bodies. Metadata fields whose names mention a secret, token, hash, credential, scope, or value are stripped before the event is written.

## Read events from the API

Call `GET /v1/audit-events` with a [management key](../developers/management-api-keys.mdx) that has `activity:read`. An OAuth token also needs `activity:read`, and its user must be a workspace owner or admin.

```bash
curl "https://api.phaseo.app/v1/audit-events?limit=50" \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY"
```

| Query parameter | Meaning |
| --- | --- |
| `limit` | Events per page, 1 to 100. Default `50`. |
| `cursor` | The `next_cursor` from the previous page. Paging by cursor never skips events that share a timestamp. |
| `action` | Return only one action, such as `api_key.rotated`. |
| `target_type` | Return only one target type, such as `api_key`. |

The response has `data`, `has_more`, and `next_cursor`. Each event includes an `actor` object with the member's `display_name` and `email`.
