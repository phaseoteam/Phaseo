Set `stream: true` and the Gateway sends output as server-sent events (SSE) while the model writes it. A stream is finished only when its successful end event arrives. Press **Play** to watch one, then switch to **Fails partway** to see how a broken stream ends.

## Send a streaming request

```bash
curl --no-buffer https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "input": "Say hello in one sentence.",
    "stream": true
  }'
```

Check the HTTP status before you read the body. A request that fails before streaming starts gets the normal [JSON error response](../api-reference/errors.mdx), not a stream. Keep your Phaseo API key on your server and forward the text to your UI from there.

## Read the events

Each endpoint uses its own event format:

| Endpoint | Text arrives in | Successful end | Failure end |
| --- | --- | --- | --- |
| [Responses](../api-reference/endpoint/responses.mdx) | `response.output_text.delta` | `response.completed` | `response.failed` or `error` |
| [Chat Completions](../api-reference/endpoint/chat-completions.mdx) | `choices[].delta` | a `finish_reason`, then `[DONE]` | an `error` frame with no `finish_reason` |
| [Messages](../api-reference/endpoint/anthropic-messages.mdx) | `content_block_delta` | `message_stop` | an `error` event with no `message_stop` |

Events are separated by blank lines, but a network chunk can hold half an event or several. Buffer until each event is complete before you parse it as JSON, or use an SDK helper, which does this for you:

- TypeScript: `streamResponses()`, `streamChat()`, `streamMessages()`; Python: `stream_responses()`, `stream_chat()`, `stream_message()` ([usage guide](../sdk-reference/client/usage.mdx))
- Vercel AI SDK: `streamText()` with `@phaseo/ai-sdk-provider`

Only Chat Completions sends `[DONE]`. Don't wait for it on the other endpoints.

## Stream tool calls

Tool calls arrive as argument deltas, the same way text does. Whether a model streams them depends on the model and provider. Collect the deltas until the call is complete, then parse, validate, and authorise the arguments. Never run a tool on partial arguments.

See [tool-calling patterns](./tool-calling-patterns.mdx) for sending results back and [tool safety](./tool-calling-safety.mdx) for validation and approval.

## Cancel a stream

Pass an `AbortSignal` (or your HTTP client's equivalent) and abort when the user stops or disconnects. Set a deadline that fits the workload. Cancelling doesn't guarantee the provider stops at once, or that output it already generated is free.

## Recover from an interrupted stream

If a stream fails after text has started, it ends with the failure event from the table above instead of the successful one. A closed connection on its own doesn't mean the answer is complete. Phaseo doesn't charge for the partial output of a stream that fails.

When it happens:

1. Keep the partial text on screen, marked as interrupted.
2. Log the request or generation ID, endpoint, and model.
3. Offer a retry. A new request can produce different text and is charged again.
4. Don't replay tools that already ran, and don't append the retried answer to the partial one.

For failures before any text arrives, retry with backoff and respect the [rate-limit headers](../api-reference/limits.mdx). If you must validate the whole answer before anyone sees it, use a non-streaming request or buffer the stream on your server.
