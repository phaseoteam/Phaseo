Put a provider ID and a colon in front of the model ID, such as `baseten:thinking-machines/inkling-small`, to run the request on that provider only, with no fallback to another provider.

| You want | Send as `model` |
| --- | --- |
| Phaseo to choose a provider and fall back between providers | `thinking-machines/inkling-small` |
| Baseten only, with no cross-provider fallback | `baseten:thinking-machines/inkling-small` |
| One verified free route on one provider | `google-ai-studio:google/gemma-4-26b-a4b:free` |

The format is `<provider-id>:<canonical-model-id>`. The first colon separates the provider; colons after the model namespace stay part of the model ID. In `google-ai-studio:google/gemma-4-26b-a4b:free`, the provider is `google-ai-studio` and the model is `google/gemma-4-26b-a4b:free`.

If you only prefer a provider and want fallback when it fails, use the plain model ID with the [routing and fallback controls](./routing-and-fallbacks.mdx) instead.

## Send a request

Use the qualified ID anywhere the endpoint accepts a model ID.

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "baseten:thinking-machines/inkling-small",
    "input": "Explain mixture-of-experts routing in two sentences."
  }'
```

```javascript JavaScript
const response = await fetch("https://api.phaseo.app/v1/responses", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "baseten:thinking-machines/inkling-small",
    input: "Explain mixture-of-experts routing in two sentences.",
  }),
});

const result = await response.json();
```

```python Python
import os
import requests

response = requests.post(
    "https://api.phaseo.app/v1/responses",
    headers={
        "Authorization": f"Bearer {os.environ['PHASEO_API_KEY']}",
        "Content-Type": "application/json",
    },
    json={
        "model": "baseten:thinking-machines/inkling-small",
        "input": "Explain mixture-of-experts routing in two sentences.",
    },
)

result = response.json()
```
</CodeGroup>

## What the provider must still pass

The qualifier narrows routing to one provider; it doesn't skip any other check. The provider must still:

- serve the canonical model on the requested endpoint, with that capability enabled
- satisfy workspace, API key, preset and privacy restrictions
- support the requested service tier and parameters
- have pricing configured

If any check fails, the request is rejected. Phaseo never quietly picks another provider.

## Combine with `provider` or `routing` fields

The qualifier and any explicit routing fields must agree. A matching `provider.only` or `routing.only` is accepted:

```json
{
  "model": "baseten:thinking-machines/inkling-small",
  "provider": { "only": ["baseten"] }
}
```

An allowlist that names other providers, or an ignore list that contains the qualified provider, is rejected with `provider_qualified_model_conflict`:

```json
{
  "model": "baseten:thinking-machines/inkling-small",
  "provider": { "only": ["deepinfra"] }
}
```

## Request a free route on one provider

A qualified `:free` model is accepted only when that provider has an eligible free route for the model and endpoint. A canonical `:free` model doesn't mean every provider of the underlying model offers it free.

```json
{
  "model": "google-ai-studio:google/gemma-4-26b-a4b:free",
  "input": "Hello"
}
```

The route's pricing card must be non-empty, and every current pricing rule on it must be labelled `free` and priced at exactly zero. Missing, paid, mixed or negative pricing, or a zero-priced rule not labelled `free`, rejects the request before it reaches the provider.

## Provider IDs and aliases

Use a provider ID from Phaseo's provider catalogue (see [API Providers](../exploring/api-providers)). IDs are lower-cased, and known legacy or brand aliases map to the canonical ID: `NovitaAI` and `novita-ai` both become `novita`. Malformed and unknown IDs are rejected before provider selection; they are never sent upstream as part of the model name.

## Validation errors

A bad qualified ID returns HTTP `400` with the error code `validation_error`. `reason` and `details[].keyword` give the cause:

| Reason | Meaning |
| --- | --- |
| `invalid_provider_slug` | The provider part is empty or contains unsupported characters. |
| `unknown_provider_slug` | The provider ID is well formed but isn't a Phaseo provider. |
| `invalid_provider_qualified_model` | The ID doesn't match `<provider>:<publisher>/<model>`. |
| `provider_qualified_model_conflict` | `provider.only`, `provider.ignore`, `routing.only`, or `routing.ignore` contradicts the qualifier. |
| `qualified_provider_unavailable` | The provider exists but doesn't serve that model on the requested endpoint. |
| `qualified_free_provider_unavailable` | The provider's route isn't verified as free with all-zero pricing. |

```json
{
  "error": "validation_error",
  "status_code": 400,
  "reason": "unknown_provider_slug",
  "description": "Unknown provider slug \"not-a-provider\" in provider-qualified model \"not-a-provider:publisher/model\". Use a provider slug returned by Phaseo's provider catalogue.",
  "provider": "not-a-provider",
  "model": "publisher/model",
  "details": [
    {
      "path": ["model"],
      "keyword": "unknown_provider_slug"
    }
  ]
}
```

For other error shapes, see [Errors and Debugging](../api-reference/errors.mdx).
