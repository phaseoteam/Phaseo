Give each kind of request an input target and an output limit, then check real usage against them. Every token you send or receive adds latency and cost, and an output limit that is too small cuts answers off.

## What counts towards a request

| Part | Counts as | Watch for |
| --- | --- | --- |
| System and developer instructions | Input | Long instructions repeated on every request. Cache them with [prompt caching](./prompt-caching.mdx). |
| User input | Input | Unbounded pastes and uploads. |
| Retrieved context (documents, search results, tool output) | Input | Low-relevance passages that add tokens and dilute the answer. |
| Tool schemas and function definitions | Input | Declared tools count as input whether or not the model calls them. |
| Reasoning | Output | Reasoning models spend part of the output limit before they answer. |
| The answer | Output | Limits that truncate answers or structured output. |

## When reasoning uses up the output limit

A reasoning model can spend the whole output limit before it produces an answer. The response is still HTTP `200` and contains the reasoning that was produced, with no invented answer:

| Endpoint | What you get |
| --- | --- |
| Chat Completions | `reasoning_content`, with `finish_reason: "length"` |
| Responses | The reasoning output item, with `status: "incomplete"` |

A normal stop is still `stop` (Chat Completions) or `completed` (Responses). Raise the output limit or lower the reasoning effort if you see these often.

## Set a budget per route

1. Set a maximum input size for each kind of request, such as a search answer or a long-form draft. Don't copy one limit across every endpoint.
2. Leave output room for the longest answer that kind of request should produce.
3. Trim or summarise large context before sending it, starting with the passages least likely to matter.
4. Check outputs for truncation, such as `finish_reason: "length"` or partial JSON, and retry with more room when it happens.
5. Track the token counts in each response's `usage` over time, and adjust the limits as your prompts change.

For how output limits and sampling interact, see [Inference Parameters](./inference-parameters.mdx).
