Add `phaseo:web_search` so the model can search the web when it needs current or sourced information. The model writes the query and can search several times in one request; Phaseo returns URLs, titles, snippets, highlights, and optionally page text, and the model writes a grounded answer.

```bash
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [
      { "role": "user", "content": "What were the major AI announcements this week?" }
    ],
    "tools": [
      { "type": "phaseo:web_search" }
    ]
  }'
```

The same tool entry works in `tools` on `/v1/responses` and `/v1/messages`.

## Parameters

```json
{
  "type": "phaseo:web_search",
  "parameters": {
    "engine": "exa",
    "max_results": 5,
    "max_total_results": 15,
    "search_context_size": "medium",
    "max_characters": 2048,
    "allowed_domains": ["arxiv.org", "nature.com"],
    "include_highlights": true,
    "include_text": false
  }
}
```

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `engine` | string | `exa` | `auto`, `native`, `exa`, `parallel`, `firecrawl`, `perplexity`, or `tinyfish`. See [Choose an engine](#choose-an-engine). |
| `max_results` | integer | `5` | Results per search call, up to `25`. |
| `max_total_results` | integer | `25` | Results across all searches in the request, up to `100`. Never lower than `max_results`. |
| `max_uses` | integer | `10` | Search calls per request, up to `100`. |
| `search_context_size` | string | `medium` | `low`, `medium`, or `high`, for engines that size highlights. |
| `max_characters` | integer | Engine default | Text characters per result when text is included. |
| `allowed_domains` | string[] | None | Search only these domains. Alias: `include_domains`. |
| `excluded_domains` | string[] | None | Leave these domains out. Alias: `exclude_domains`. |
| `include_highlights` | boolean | `true` | Include the engine's highlights or snippets. |
| `include_text` | boolean | `false` | Include fuller page text where the engine supports it. |
| `user_location` | object | None | Location hint passed to the provider's own search when `engine` is `native`. |

## What the model sends

Each call has a `query`. The model can also send `max_results`, `engine`, `search_context_size`, the domain lists, `include_text`, `include_highlights`, `max_characters`, and these localization hints:

| Argument | Description |
| --- | --- |
| `user_location` | Approximate location. Perplexity uses `user_location.country` for regional search; TinyFish uses the country and language. |
| `language` | Result language code, such as `en`, for engines that localize. |
| `page` | Result page `0` to `10`, for TinyFish. |

Values the model sends replace the tool's defaults for that call. `max_results` is still capped by what's left of `max_total_results`; once that runs out, further calls return `max_total_results_reached`.

## Choose an engine

| Engine | What runs |
| --- | --- |
| `exa` | Managed Exa search. The default. |
| `auto` | The managed default, currently Exa. |
| `parallel` | Managed Parallel search. |
| `firecrawl` | Managed Firecrawl search. |
| `perplexity` | The Perplexity Search API: ranked results, `search_context_size`, and regional search from `user_location.country`. |
| `tinyfish` | TinyFish Search: localized, paginated ranked results. It returns snippets, not full page text; use [`phaseo:web_fetch`](./web-fetch) when the model needs more. |
| `native` | The provider's own web search tool, such as OpenAI's `web_search_preview` or Anthropic's `web_search_20250305`. |

If a managed engine isn't enabled, the call returns `search_not_configured` to the model.

With `engine: "native"` on `/v1/chat/completions` or `/v1/responses`, the request goes only to providers that run web search themselves. If none serve the model, Phaseo runs its default engine instead and bills it as managed search. Set `native` in the tool definition only: if the model asks for `native` in a call, the call returns `unsupported_search_engine`, because the provider's tool has to be chosen before the request is sent.

## Filter by domain

Use `allowed_domains` when the answer must come from a fixed set of sources, and `excluded_domains` to drop specific sites from an otherwise open search.

```json
{
  "type": "phaseo:web_search",
  "parameters": { "allowed_domains": ["phaseo.app", "github.com"] }
}
```

Engines handle the lists differently:

- **Perplexity** takes either list, not both, and up to 20 domains. Excluded domains are sent as its deny-list format.
- **Firecrawl** takes either list, not both.
- **TinyFish** takes both and turns them into `site:` and `-site:` operators in the query.

## What the tool returns

A JSON result with the engine, the query, and a `results` array. Each result has a `title`, `url`, `snippet` or `highlights`, and `text` when page text was requested and the engine supplies it.

## Usage and pricing

Each search adds to `usage.server_tool_use`:

```json
{
  "usage": {
    "server_tool_use": {
      "web_search_requests": 1,
      "web_search_results": 5,
      "web_search_extra_results": 0
    }
  }
}
```

Managed search is billed with `server_tool_web_search_requests` and `server_tool_web_search_extra_results`. Native search is billed with `native_web_search_requests` where the model's price card defines it. TinyFish Search is free on its published plans, so Phaseo adds no search charge for `engine: "tinyfish"`; the request's normal token pricing still applies.
