Add `phaseo:web_search` so the model can search the web when it needs current or sourced information. The model writes the query and can search several times in one request; Phaseo returns URLs, titles, snippets, highlights, and optionally page text, and the model writes a grounded answer.

```bash
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [
      { "role": "user", "content": "What were the major AI announcements this week?" }
    ],
    "tools": [
      { "type": "phaseo:web_search" }
    ]
  }'
```

The same tool entry works in `tools` on `/v1/responses` and `/v1/messages`.

## Parameters

```json
{
  "type": "phaseo:web_search",
  "parameters": {
    "engine": "exa",
    "max_results": 5,
    "max_total_results": 15,
    "search_context_size": "medium",
    "max_characters": 2048,
    "allowed_domains": ["arxiv.org", "nature.com"],
    "include_highlights": true,
    "include_text": false
  }
}
```

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `engine` | string | `exa` | `auto`, `native`, `exa`, `parallel`, `firecrawl`, `perplexity`, `tinyfish`, or `deepseek`. See [Choose an engine](#choose-an-engine). |
| `mode` | string | Engine default | How the engine searches: faster, deeper, or a research run. See [Choose a mode](#choose-a-mode). |
| `max_results` | integer | `5` | Results per search call, up to `25`. |
| `max_total_results` | integer | `25` | Results across all searches in the request, up to `100`. Never lower than `max_results`. |
| `max_uses` | integer | `10` | Search calls per request, up to `100`. |
| `search_context_size` | string | `medium` | `low`, `medium`, or `high`, for engines that size highlights. |
| `max_characters` | integer | Engine default | Text characters per result when text is included. |
| `allowed_domains` | string[] | None | Search only these domains. Alias: `include_domains`. |
| `excluded_domains` | string[] | None | Leave these domains out. Alias: `exclude_domains`. |
| `include_highlights` | boolean | `true` | Include the engine's highlights or snippets. |
| `include_text` | boolean | `false` | Include fuller page text where the engine supports it. |
| `user_location` | object | None | Location hint. With `engine: "native"` it goes to the provider's own search; otherwise Phaseo's search uses it whenever the model's call gives no location. |

## What the model sends

Each call has a `query`. The model can also send `max_results`, `engine`, `search_context_size`, the domain lists, `include_text`, `include_highlights`, `max_characters`, and these localization hints:

| Argument | Description |
| --- | --- |
| `user_location` | Approximate location. Exa and Perplexity use `user_location.country` (a two-letter code such as `GB`) for regional search; TinyFish uses the country and language. |
| `language` | Result language code, such as `en`, for engines that localize. DeepSeek adds it to the query as a `lang:` filter. |
| `page` | Result page `0` to `10`, for TinyFish. |

Values the model sends replace the tool's defaults for that call. `max_results` is still capped by what's left of `max_total_results`; once that runs out, further calls return `max_total_results_reached`.

## Choose an engine

| Engine | What runs |
| --- | --- |
| `exa` | Managed Exa search. The default. |
| `auto` | The managed default, currently Exa. |
| `parallel` | Managed Parallel search. |
| `firecrawl` | Managed Firecrawl search. |
| `perplexity` | The Perplexity Search API: ranked results, `search_context_size`, and regional search from `user_location.country`. |
| `tinyfish` | TinyFish Search: localized, paginated ranked results. It returns snippets, not full page text; use [`phaseo:web_fetch`](./web-fetch) when the model needs more. |
| `deepseek` | DeepSeek Search: ranked results with a summary of each page, written for the model to read. |
| `native` | The provider's own web search tool, such as OpenAI's `web_search_preview`, Anthropic's `web_search_20250305`, or DeepSeek's `deepseek_web_search`. |

If a managed engine isn't enabled, the call returns `search_not_configured` to the model.

With `engine: "native"` on `/v1/chat/completions` or `/v1/responses`, the request goes only to providers that run web search themselves. If none serve the model, Phaseo runs its default engine instead and bills it as managed search.

The providers that run web search themselves on these endpoints are OpenAI, Azure OpenAI deployments on `/v1/responses`, xAI, and DeepSeek on `deepseek/deepseek-v4.1-flash-1017`. DeepSeek searches on its own only when web search is the request's only tool, with no domain lists or user location, no JSON output and no forced `tool_choice`. Its API rejects domain lists, a location and JSON output, turns its web search off when the request has other tools, and cannot force a search. Other requests to that model use Phaseo's search instead, which works alongside your own tools. With reasoning on, DeepSeek runs a deeper search that opens and reads pages over several steps.

The providers' own search tools can't enforce `max_results` or `max_total_results`, and only Claude's enforces `max_uses`. A native search that sets a limit its provider can't enforce runs on Phaseo's default engine instead and is billed as managed search.

Sending OpenAI's own `{ "type": "web_search" }` tool works the same way as `engine: "native"`. Set `native` in the tool definition only: if the model asks for `native` in a call, the call returns `unsupported_search_engine`, because the provider's tool has to be chosen before the request is sent.

## Choose a mode

Set `mode` on the tool to choose how its engine searches. The model can't change it, so a call never costs more than the mode you chose. If the model switches to another engine, that engine runs in its default mode. A mode the engine doesn't have returns a 400.

| Engine | `mode` | What runs | Price per call |
| --- | --- | --- | --- |
| `exa` | `lite` | Low-latency search for chat and voice | $0.004 |
| `exa` | `auto` (default) | Balanced search | $0.007 |
| `exa` | `deep-lite` | Light multi-step research, about 4 seconds | $0.012 |
| `exa` | `deep` | Multi-step research with a synthesized `answer`, 4 to 15 seconds | $0.012 |
| `exa` | `agent-minimal` | An Exa Agent research run at minimal effort | $0.012 |
| `exa` | `agent-low` | An Exa Agent research run at low effort | $0.025 |
| `parallel` | `turbo`, `fast` | Parallel's fastest search | $0.001 |
| `parallel` | `basic`, `advanced` (default) | Parallel's higher-quality search | $0.005 |
| `parallel` | `task-lite` | A Parallel Task research run, 10 to 60 seconds | $0.005 |
| `parallel` | `task-base` | A Parallel Task research run, 15 to 100 seconds | $0.010 |
| `perplexity` | `standard` (default) | Perplexity Search | $0.005 |
| `perplexity` | `fast` | Perplexity Fast Search | $0.001 |

Exa and Parallel searches also cost $0.001 for each result past the first 10, and Exa charges $0.001 per page for each content type it returns, so highlights and text on 5 results add $0.010. `firecrawl`, `tinyfish` and `deepseek` have no modes.

Research modes return an `answer` and the pages it cites as `results`. A research run that hasn't finished after 120 seconds returns `research_timeout`. Runs that time out, fail, or lose their client aren't charged. Research modes can't be limited to domains, so a research tool with `allowed_domains` or `excluded_domains` returns a 400. The `native` engine takes no mode.

## Filter by domain

Use `allowed_domains` when the answer must come from a fixed set of sources, and `excluded_domains` to drop specific sites from an otherwise open search.

```json
{
  "type": "phaseo:web_search",
  "parameters": { "allowed_domains": ["phaseo.app", "github.com"] }
}
```

Engines handle the lists differently:

- **Perplexity** takes either list, not both, and up to 20 domains. Excluded domains are sent as its deny-list format.
- **Firecrawl** takes either list, not both.
- **TinyFish** takes both and turns them into `site:` and `-site:` operators in the query.
- **DeepSeek** takes both and turns them into `site:` and `-site:` operators. Its queries are limited to 128 characters, so the query is shortened to make room for the operators. If the domain lists alone exceed the limit, the call returns `search_query_too_long`.

## What the tool returns

A JSON result with the engine, the query, and a `results` array. Each result has a `title`, `url`, `snippet` or `highlights`, and `text` when page text was requested and the engine supplies it.

## Usage and pricing

Each search adds to `usage.server_tool_use`:

```json
{
  "usage": {
    "server_tool_use": {
      "web_search_requests": 1,
      "web_search_results": 5,
      "web_search_extra_results": 0
    }
  }
}
```

Phaseo bills searches on Exa, Parallel, Perplexity and DeepSeek at what each engine charges Phaseo: the prices in [Choose a mode](#choose-a-mode), and $0.00075 for a DeepSeek search, billed only when it returns results. For Exa, the charge is the cost Exa reports for the call, or its list price when Exa reports none. Each charge is a line in the request's `pricing_lines` with its `engine`, `mode` and `price_source`. Firecrawl searches are billed at $0.007, plus $0.001 for each result past the first 10. Failed searches are not billed, and TinyFish Search is free on its published plans, so `engine: "tinyfish"` adds no search charge. Searches on paid engines need credits even when the model is free. Native search is billed with `native_web_search_requests` at the provider's published price: for example $10 per 1,000 searches on OpenAI and Anthropic, and $0.75 per 1,000 on DeepSeek, where only searches that return results count. DeepSeek also bills each page fetch, where it reads a URL with its read-link tool, at $0.75 per 1,000, as `native_web_fetch_requests`. With reasoning on, one DeepSeek answer can run a dozen or more searches, and the results it reads add to the input tokens.
