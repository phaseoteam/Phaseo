Add `phaseo:advisor` so the main model can ask a second model for a review, plan, sanity check, or specialist opinion before it answers. The main model calls the Advisor like any tool; Phaseo runs the Advisor model and returns its advice as the tool result.

```bash
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [
      { "role": "user", "content": "Design a rate limiter for a distributed API gateway." }
    ],
    "tools": [
      {
        "type": "phaseo:advisor",
        "parameters": {
          "model": "anthropic/claude-opus-5",
          "max_uses": 1,
          "max_completion_tokens": 1400
        }
      }
    ]
  }'
```

Advisor works with any supported text model. Phaseo runs it itself; it is converted to Anthropic's native Advisor tool only if you send Anthropic's native tool shape.

## Parameters

```json
{
  "type": "phaseo:advisor",
  "parameters": {
    "name": "reviewer",
    "model": "anthropic/claude-opus-5",
    "instructions": "Review plans for correctness, missing edge cases, and implementation risk.",
    "forward_transcript": true,
    "max_uses": 2,
    "max_completion_tokens": 1400,
    "reasoning": { "effort": "high" },
    "temperature": 0.2
  }
}
```

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `name` | string | None | 1 to 64 letters, numbers, spaces, underscores, or dashes. Needed when you add more than one Advisor. |
| `model` | string | See below | The Advisor model. |
| `instructions` | string | Built-in advisor instructions | Extra instructions for the Advisor. |
| `forward_transcript` | boolean | `false` | Send the current conversation to the Advisor. |
| `max_uses` | integer | `1` | Calls to this Advisor per request. |
| `max_completion_tokens` | integer | `1400` | Output tokens for each Advisor reply. Values below `1024` are raised to `1024`. `max_tokens` is accepted as an older alias. |
| `reasoning` | object | Provider default | Reasoning settings, passed on where the Advisor model supports them. |
| `temperature` | number | Provider default | Sampling temperature for the Advisor call. |

The Advisor model is `parameters.model` if set; otherwise the `model` the main model sends in its call; otherwise the request's own model.

## What the model sends

Usually a `prompt`. If the tool doesn't pin a model, the call can also choose one:

```json
{
  "model": "anthropic/claude-opus-5",
  "prompt": "Check this security design for missing controls."
}
```

With `forward_transcript: true`, the model can call the Advisor without a prompt, and the Advisor reviews the forwarded conversation.

## Add several advisors

Add one `phaseo:advisor` entry per advisor. Each named Advisor becomes its own tool for the model, such as `phaseo_advisor_security_reviewer`.

```json
{
  "tools": [
    {
      "type": "phaseo:advisor",
      "parameters": {
        "name": "security-reviewer",
        "model": "anthropic/claude-opus-5",
        "instructions": "Review for vulnerabilities, abuse cases, and missing mitigations."
      }
    },
    {
      "type": "phaseo:advisor",
      "parameters": {
        "name": "architect",
        "model": "openai/gpt-5",
        "instructions": "Review system design tradeoffs and operational risks."
      }
    }
  ]
}
```

Names must be unique after trimming, ignoring case, and at most one entry can leave `name` out; otherwise the request is rejected. `tool_choice: "phaseo:advisor"` with several Advisors forces the first one.

## What the tool returns

```json
{
  "status": "ok",
  "name": "reviewer",
  "model": "anthropic/claude-opus-5",
  "advice": "Start with a smaller migration slice and define rollback criteria before changing traffic routing."
}
```

If the call can't run, the model gets an error result instead: `advisor_invalid_request` (no prompt or no model), `advisor_max_uses_exceeded`, or `advisor_request_failed`.

The Advisor keeps no state between requests. If you replay earlier messages and tool results, the main model sees the earlier advice; the Advisor sees the conversation only when `forward_transcript` is on. Advice isn't streamed, and the Advisor can't call tools itself.

## Usage and pricing

Each call adds 1 to `usage.server_tool_use.advisor_requests` and can be billed with `server_tool_advisor_requests`. The Advisor's tokens are billed at the Advisor model's own rates, as a separate line on the request's bill; they are not added to the calling model's token counts. A paid Advisor model needs credits even when the calling model is free.
