Add `phaseo:apply_patch` on `/v1/responses` to get file changes back as structured patch operations. Phaseo checks each operation's shape and returns it; it never touches your files. Your app decides whether to apply the patch, show it to a user, reject it, or ask for a revision.

```bash
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "input": "Create a small README patch for this project.",
    "tools": [
      { "type": "phaseo:apply_patch" }
    ]
  }'
```

On `/v1/chat/completions` or `/v1/messages`, the request is rejected.

## Parameters

None. Add `{ "type": "phaseo:apply_patch" }` as it is.

## What the model sends

An `operation` object:

```json
{
  "operation": {
    "type": "update_file",
    "path": "/README.md",
    "diff": "@@ ...\n-Old text\n+New text\n"
  }
}
```

| `type` | Required fields | Diff rules |
| --- | --- | --- |
| `create_file` | `path`, `diff` | Every non-empty line starts with `+` |
| `update_file` | `path`, `diff` | Every non-empty line starts with `@@`, a space, `+`, or `-` |
| `delete_file` | `path` | None |

`path` can't contain null bytes.

## What the tool returns

```json
{
  "status": "completed",
  "operation": {
    "type": "update_file",
    "path": "/README.md",
    "diff": "@@ ...\n-Old text\n+New text\n"
  },
  "message": "Patch operation validated. The client must apply or reject this patch and report the result."
}
```

An operation that breaks the rules above returns `apply_patch_invalid_operation` with the reason, so the model can try again.

## Usage and pricing

Each call adds 1 to `usage.server_tool_use.apply_patch_requests` and can be billed with `server_tool_apply_patch_requests`.
