Add `phaseo:datetime` so the model can look up the current date and time when a prompt depends on it, such as "what day is it in Tokyo?". The model decides when to call it; Phaseo returns the time in each timezone you listed.

```bash
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [
      { "role": "user", "content": "What day of the week is it in Tokyo?" }
    ],
    "tools": [
      {
        "type": "phaseo:datetime",
        "parameters": { "timezones": ["Asia/Tokyo", "UTC"] }
      }
    ]
  }'
```

## Parameters

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `timezones` | string[] | `["UTC"]` | Up to 5 IANA timezone names, such as `["Europe/London", "UTC"]`. |

More than 5 timezones, or a name that isn't a valid IANA timezone, rejects the request before the model runs. The older type name `gateway:datetime` is still accepted.

## What the tool returns

One entry per timezone:

```json
{
  "timezones": [
    { "timezone": "Europe/London", "datetime": "2026-07-03T10:00:00.123+01:00" },
    { "timezone": "UTC", "datetime": "2026-07-03T09:00:00.123+00:00" }
  ]
}
```

## Usage and pricing

Each call adds 1 to `usage.server_tool_use.datetime_requests`. Datetime has no price meter of its own.
