Send an `X-Phaseo-Metadata` header to tag a request with key/value labels such as `team=support`, then filter spend and logs by those labels. Use labels when you need a cost dimension finer than an API key or app. They don't change the model request and are not forwarded to providers.

```bash
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -H 'X-Phaseo-Metadata: {"labels":[{"key":"team","value":"support"},{"key":"environment","value":"production"}]}' \
  -d '{
    "model": "openai/gpt-6-astra",
    "input": "Summarize this ticket."
  }'
```

The TypeScript and Python SDKs accept custom headers, so you can set the same header once on the client.

To label requests automatically from their content, use [request classifiers](/v1/guides/request-classifiers). Their answers are stored as request labels and filter the same way.

## Label rules

| Rule | Limit |
| --- | --- |
| Labels per request | Up to 32, each with a unique key |
| Key | 1 to 64 characters: letters, numbers, `_`, `.`, `:`, `-` |
| Value | String, 1 to 256 characters, no control characters |
| Header size | Up to 8 KiB |
| Reserved key | `phaseo.classifier` is set only by Phaseo's classifier calls |

Keys and values are trimmed. A malformed header, a duplicate key, or a label that breaks these rules fails the request with `400 validation_error`, reason `invalid_request_metadata`, before any model is called.

Don't put prompts, secrets, email addresses, or other personal data in labels.

## Filter spend by label

Pass both `label_key` and `label_value` to the analytics endpoint:

```text
GET /v1/analytics?label_key=team&label_value=support
```

The response has the same grouped spend format as unfiltered analytics, but counts only requests carrying that exact label pair. Sending only one of the two parameters returns `400 invalid_request`.
