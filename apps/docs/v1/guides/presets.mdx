A preset stores the model, system prompt, parameters, and provider rules for one job under a name such as `@support-triage`. Callers send that name as the `model` and only the input; the Gateway fills in the rest before it picks a provider.

Toggle the request fields to see which value wins:

<PresetMergeExplorer />

The rules are:

- **Parameters fill gaps.** A preset's default parameters apply only to fields the request leaves out. A value in the request always wins.
- **System prompts stack.** The preset's prompt goes first. If the request has its own system prompt or `instructions`, it follows after a blank line.
- **Provider settings in the request win.** Fields such as `provider.order` or `provider.max_price` in the request replace the preset's value for that field.
- **Allow lists narrow, never widen.** The preset's provider allow and ignore lists are applied before provider selection, so they also limit which providers a fallback can use. A model outside the preset's allowed models fails with a `validation_error` whose detail keyword is `preset_model_not_allowed`; it isn't rerouted.

## Create and use a preset

<Steps>
<Step title="Create the preset">

Open **Dashboard -> Settings -> Presets** and create a preset with a slug such as `support-triage`. Add only the defaults every caller should share.

To create one from a script, call `POST /v1/presets` with a management key.

</Step>

<Step title="Call it by name">

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "@support-triage",
    "input": "Customer says the invoice total is wrong."
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "@support-triage",
  input: "Customer says the invoice total is wrong.",
});
```

```python Python
from phaseo import Phaseo

client = Phaseo(api_key="YOUR_API_KEY")

response = client.generate_response({
    "model": "@support-triage",
    "input": "Customer says the invoice total is wrong.",
})
```
</CodeGroup>

</Step>

## What a preset can hold

| Setting | Effect |
| --- | --- |
| Model | Used when the request is sent with the preset's name. |
| Allowed models | Model IDs or patterns such as `anthropic/*`. Other models are rejected. |
| System prompt | Prepended to every request. |
| [Prompt template](./prompt-templates) | Messages with `{{variables}}` that each request fills in. |
| Default parameters | `temperature`, `top_p`, `max_tokens`, reasoning settings and similar. |
| Provider rules | Allow and ignore lists, provider order, regions, price ceilings. |

Keep caller-specific logic in your application and use separate presets when workflows need different prompts, routing, or caching.

## Name a preset

Send a preset through the `model` field, or through `prompt.id` when it has a [prompt template](./prompt-templates). There is no separate `preset` field.

| Form | Resolves in |
| --- | --- |
| `@support-triage` | The API key's workspace (private and workspace presets). |
| `@octavia/support-triage` | Any workspace (public presets, published by user `octavia`). |
| `@support-triage@v3` | That published version. |
| `@support-triage@production` | Whichever version the `production` label points at. |

Publishing a public preset needs an enabled public profile and a username. Usernames are unique across Phaseo; slugs only need to be unique for one publisher. Slugs are lower-cased and may contain letters, numbers, `-`, `_`, `.`, and `:`.

## Version and roll back

Saving edits a private draft. **Publish new version** turns the draft into an immutable, numbered release and keeps every earlier one.

Choose how release labels look:

| Format | Example |
| --- | --- |
| Sequential | `v1`, `v2`, `v3` |
| Semantic Versioning | `1.2.0`, `2.0.0-beta.1`, `1.4.2+build.7` |
| Date | `2026.08.02`, then `2026.08.02.2` for a second release that day |

Point a named label such as `production` at a version, and move it back to an earlier version to roll back. See [Versions and labels](/v1/guides/prompt-templates#versions-and-labels).

From a script, publish with `POST /v1/presets/{id}/versions` and move labels with `PUT /v1/presets/{id}/labels/{label}`, using a management key. A CLI sign-in or an app that uses Sign in with Phaseo can read presets but can't change them.

## Fork a marketplace preset

A copy of a marketplace preset stays pinned to the version you copied. When the publisher releases an update, your copy shows a notice. Applying it changes only your draft, so nothing reaches production until you publish it yourself.

Phaseo records each fork's source and full ancestry, so a marketplace page can show direct forks separately from all descendants.
