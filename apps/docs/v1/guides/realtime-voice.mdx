A realtime session is a voice call between your client and a provider's realtime model, relayed by Phaseo so it can be metered and billed. The relay forwards the provider's own events unchanged and adds three of its own: `session.end`, `session.warning` and `session.ended`.

## Start a session

Create the session from your server:

```bash
curl https://api.phaseo.app/v1/audio/realtime/sessions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "openai/gpt-realtime-2", "voice": "marin"}'
```

The response includes `client_secret`, `connect.url`, `max_duration_seconds` and `idle_timeout_seconds` (always `null` for API sessions). Open a WebSocket to `connect.url` on `api.phaseo.app` with the WebSocket subprotocol `rtsec.<client_secret>`. The relay sends `relay.connected` once the provider is ready, then accepts microphone audio as `{"type": "client.audio", "audio": "<base64 PCM16>"}`: 24 kHz for OpenAI, xAI and ElevenLabs, 16 kHz for Google.

Phaseo holds $5 of credit when the session starts and extends the hold as the call runs.

### Google Live connections

Keep streaming microphone audio for the whole call, including silence. Google closes a connection that receives no audio for about 150 seconds (close code `1008`), and the call then ends with `provider_closed`. The relay sends a `provider_closing` warning with `threshold: "input_idle"` after 2 minutes without audio. Silence between turns is not part of any turn, so it isn't billed.

Google also replaces each connection after about 10 minutes. The relay moves the call to a new connection with Google's session resumption, keeps your socket open and sends `{"type": "relay.provider_reconnected", "reconnects": 1}` when the switch is done. Audio you send during the switch (usually under a second) is held and passed on. The resumed connection reprocesses the conversation so far, and Google bills that again as input tokens on the next turn, so a long call costs a little more per turn after each switch. All of it is included in `usage` and the bill. The relay only warns with `provider_closing` if it can't resume, and the call then ends when Google closes the connection.

### GPT Live sessions

GPT Live (`openai/gpt-live-1`) handles the voice and hands reasoning to a Responses backend model. Create it with `POST /v1/live/sessions`:

```bash
curl https://api.phaseo.app/v1/live/sessions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-live-1",
    "provider": "openai",
    "voice": "marin",
    "backend_model": "openai/gpt-5.6-luna",
    "backend_settings": {
      "tools": [{ "type": "function", "name": "get_time", "description": "Returns the current UTC time.", "parameters": { "type": "object", "properties": {} } }]
    }
  }'
```

`voice` is one of `alloy`, `ash`, `ballad`, `beacon`, `bossa`, `cedar`, `cinder`, `coral`, `delta`, `echo`, `gleam`, `marin`, `meridian`, `quartz`, `ripple`, `sage`, `shimmer`, `stone`, `tempo`, `verse`, `vesper` or `willow`. `backend_model` is `openai/gpt-5.6-luna` (default) or `openai/gpt-5.6-terra`. Connect and stream 24 kHz audio the same way as other sessions.

Function tools run on your client. The backend's call arrives as a `response.event` whose `event.item.type` is `function_call`. Run the tool, then send the result and ask for the follow-up reply:

```json
{ "type": "response.item.create", "item": { "type": "function_call_output", "call_id": "call_63hZ...", "output": "{\"utc\":\"2026-10-22T09:42:48Z\"}" } }
{ "type": "response.create" }
```

The relay accepts a `function_call_output` only for a call the backend made, once per call and up to 64 KB, and `response.create` only after at least one output. Anything else gets `{"type": "relay.client_event_rejected", "reason": "..."}` and the call continues. Phaseo never runs function tools itself.

A GPT Live call is billed per second of voice ($0.05 per minute, from GPT Live's own `usage.seconds`) plus the backend model's tokens for every response, including the replies after tool results. GPT Live expires a session that receives no audio for about 30 seconds, which ends the call with `provider_idle_timeout`. Keep streaming microphone audio, silence included.

### ElevenLabs Realtime sessions

ElevenLabs Realtime comes in two models: `eleven-labs/eleven-realtime-v1-mini`, the faster and cheaper default, and `eleven-labs/eleven-realtime-v1-max`, which reasons before it answers and suits complex instructions and multi-step tool use. Both use the same create request and relay as OpenAI, with 24 kHz audio. Phaseo connects to ElevenLabs with its own key; your client only ever sees the relay.

ElevenLabs bills a call for every second it's connected, plus the language-model tokens it uses, and it doesn't report usage during the call. The relay meters connected time while the call runs, so holds and the overdraft cap work as for other providers. When the call ends, Phaseo reads ElevenLabs' bill for the conversation and charges the larger of that and its own list-price total. That usually takes a few seconds. If it takes longer, `session.ended` arrives with `billing_status: "pending"` and a `final_bill` request, and the bill is settled within 10 minutes.

## End a session

Send `session.end` when the caller hangs up:

```json
{ "type": "session.end", "reason": "caller hung up" }
```

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `reason` | string | none | Your own note, up to 120 printable characters, echoed back as `client_reason`. |
| `cancel_response` | boolean | `true` | `true` cancels a reply that is still playing. `false` lets it finish, for up to 20 seconds. |

The relay then:

1. stops accepting audio;
2. discards microphone audio the provider has not committed to a turn;
3. cancels the reply in progress, or lets it finish, and waits up to 10 seconds for its usage;
4. for GPT Live, sends the provider `session.close` and waits for `session.closed`;
5. settles the bill;
6. sends `session.ended`;
7. closes the socket with code `1000`.

Closing the socket without `session.end` also ends the call and bills it the same way, but your client won't receive `session.ended`.

## session.ended

The relay sends `session.ended` on every ending: one you requested, one the provider started and one the gateway started. It's sent while your socket is still open, just before the relay closes it.

```json
{
  "type": "session.ended",
  "session_id": "rt_01k8...",
  "reason": "client_requested",
  "initiated_by": "client",
  "client_reason": "caller hung up",
  "duration_seconds": 184.2,
  "usage": { "input_audio_tokens": 1840, "output_audio_tokens": 3120, "input_text_tokens": 412 },
  "cost": {
    "total_usd": 0.231,
    "total_nanos": 231000000,
    "estimated": false,
    "estimate_basis": null,
    "debt_nanos": 0,
    "uncollected_nanos": 0,
    "currency": "USD"
  },
  "billing_status": "settled"
}
```

| Field | Meaning |
| --- | --- |
| `reason` | A stable reason code. See [reason codes](#reason-codes). |
| `initiated_by` | `client`, `gateway` or `provider`. |
| `duration_seconds` | Time since the relay connected. |
| `usage` | The billed meters: token counts by modality and, for xAI and GPT Live, `audio_seconds`. |
| `cost.estimated` | `true` when part of the usage was estimated from metered audio because the provider's usage for an interrupted turn never arrived. `estimate_basis` says why. |
| `cost.debt_nanos` | The part of the cost charged as overdraft beyond your holds and free balance. |
| `cost.uncollected_nanos` | Cost beyond the overdraft cap that wasn't charged. |
| `provider_close_code` | The provider's WebSocket close code, when the provider ended the call. |
| `billing_status` | `settled`, `pending` or `unresolved`. |

If settlement is still being retried, `billing_status` is `pending` and `cost` shows the running estimate. If the session needs a billing review, it's `unresolved`. In both cases `final_bill` gives the request to fetch the final cost once it's settled:

```json
"final_bill": { "method": "GET", "path": "/v1/generations?id=realtime%3Art_01k8..." }
```

### Reason codes

| `reason` | `initiated_by` | When |
| --- | --- | --- |
| `client_requested` | client | You sent `session.end`. |
| `client_disconnected` | client | Your socket closed without `session.end`. |
| `provider_closed` | provider | The provider closed its connection, for example Google after about 150 seconds without audio (code `1008`), or after a `goAway` the relay couldn't resume from. |
| `provider_idle_timeout` | provider | GPT Live expired the session because it received no audio for about 30 seconds. |
| `provider_error` | provider | The provider connection failed or reported an error. |
| `max_duration_reached` | gateway | The provider's session limit was reached. |
| `insufficient_funds` | gateway | The overdraft cap was reached. |
| `key_revoked` | gateway | The API key was revoked or deleted during the call. |
| `key_expired` | gateway | The API key expired during the call. |
| `key_blocked` | gateway | The API key was paused during the call. |
| `workspace_disabled` | gateway | The workspace no longer exists. |
| `policy_blocked` | gateway | A workspace policy change blocked the model, or removed the provider from the allowed list, and was still in place 30 seconds after the `policy_blocked` warning. |
| `input_rejected` | gateway | The relay rejected client audio: too large, faster than real time, or the provider fell behind. |
| `session_reconciled` | gateway | The relay lost its state and the session was closed by reconciliation. |
| `gateway_error` | gateway | Phaseo couldn't process provider events or record usage. |
| `idle_timeout` | gateway | Playground only: five minutes without audio. |
| `spend_limit_reached` | gateway | Playground only: a key spend limit or workspace budget was reached. |

New codes may be added, so treat an unknown `reason` like `gateway_error`.

## session.warning

Warnings tell you what's coming without ending the call. Each code is sent at most once per threshold.

```json
{ "type": "session.warning", "code": "max_duration_approaching", "message": "...", "seconds_remaining": 120, "expires_at": "2026-10-22T11:00:00.000Z" }
```

| `code` | Extra fields | When |
| --- | --- | --- |
| `max_duration_approaching` | `seconds_remaining`, `expires_at` | 2 minutes and 30 seconds before the provider's session limit. |
| `provider_closing` | `seconds_remaining`, and `threshold: "input_idle"` for the idle case | Google will close the connection: after a `goAway` the relay couldn't resume from, or (`input_idle`) because no audio has arrived for 2 minutes. |
| `funds_low` | `remaining_usd` | The credit hold couldn't be extended. The call continues on your free balance. |
| `overdraft_in_use` | `remaining_usd`, `overdraft_used_usd` | Your free balance is used up and the call is running on overdraft. Sent again when less than $0.25 of the cap is left. |
| `spend_limit_exceeded` | `limit` (`key` or `workspace_budget`) | A key spend limit or workspace budget was reached. The call continues; new requests are refused. |
| `policy_blocked` | `status`, plus `seconds_remaining` and `ends_at` when `status` is `ending` | A workspace policy now blocks the call, or its provider was removed from the allowed list. The call ends after 30 seconds unless the change is undone, in which case a second warning arrives with `status: "cleared"`. |

`remaining_usd` is what the call can still spend before it ends, including the overdraft.

## Limits

API sessions are never ended for being idle, and spend limits only warn. A call ends on its own only when one of these happens:

| Limit | Value |
| --- | --- |
| OpenAI Realtime | 60 minutes |
| xAI | 120 minutes |
| Google Live | 60 minutes, across the connections the relay resumes. The call also ends if your client stops sending audio for about 150 seconds. |
| GPT Live | 25 minutes |
| ElevenLabs Realtime | 30 minutes |
| Overdraft cap | $1 beyond your holds and free balance |
| Lost access | The key is revoked, expired or paused, or the workspace is removed. Detected within about a minute, then the call ends without a grace period. |
| Policy change | 30 seconds after a `policy_blocked` warning, if the policy still blocks the call |

Session limits count from when the relay connects, not from when the session was created.
