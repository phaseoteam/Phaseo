Create a workspace for each team, product, or environment to keep its API keys, routing settings, presets, guardrails, and admin access separate. Every account starts with a personal workspace, which is enough for a small integration.

Separate workspaces help when you want to:

- isolate development, staging, and production credentials
- keep products or customer projects apart
- give an admin integration access to only the resources it needs
- apply different routing, preset, or guardrail policies

Workspaces don't change your pricing: all usage stays on standard pay-as-you-go billing, described in [Pricing & Billing](../pricing/tiers). Additional workspaces unlock after your first credit deposit; until then, creating one fails with `403 workspace_upgrade_required`.

## Manage workspaces from the API

Manage workspaces in the dashboard or with the management API. The API needs a [management key](../developers/management-api-keys); ordinary Gateway API keys are for inference and can't call these endpoints.

| Task | Endpoint | Capability |
| --- | --- | --- |
| List workspaces | [`GET /workspaces`](../api-reference/endpoint/workspaces-list) | `workspaces:read` |
| Read a workspace | [`GET /workspaces/{id}`](../api-reference/endpoint/workspaces-get) | `workspaces:read` |
| Create a workspace | [`POST /workspaces`](../api-reference/endpoint/workspaces-create) | `workspaces:write` |
| Update a workspace | [`PATCH /workspaces/{id}`](../api-reference/endpoint/workspaces-update) | `workspaces:write` |
| Delete a workspace | [`DELETE /workspaces/{id}`](../api-reference/endpoint/workspaces-delete) | `workspaces:delete` |

Give the key only the capabilities it needs. Phaseo also checks workspace membership and role, so a capability alone never grants access to another workspace. A new workspace's `slug` must be 1 to 50 lowercase letters, numbers, or dashes.

Keep management keys in server-side secret storage, never in browser code, desktop logs, source control, or chat.

<Note>
The workspace endpoints are in beta. Make automation safe to retry, and check each response before you make a follow-up change.
</Note>

## Rename or delete a workspace

The personal (default) workspace can't be renamed or deleted; both return `400 bad_request`. Before you delete another workspace, remove or move its active API keys so no requests point at a workspace that no longer exists.
