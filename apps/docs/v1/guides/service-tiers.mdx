Set `service_tier` on a text request to pay for faster delivery (`fast`, `ultrafast`) or accept a cheaper, lower-priority mode (`flex`). Phaseo then routes only to providers that offer that tier for the model. The field works the same on `/v1/chat/completions`, `/v1/responses`, and `/v1/messages`.

```json
{
  "model": "openai/gpt-5.5",
  "input": "Summarise this incident report.",
  "service_tier": "fast"
}
```

| Tier | Request it with | Use it for |
| --- | --- | --- |
| Standard | Nothing, or `"standard"` / `"default"` | General production traffic |
| Fast | `"fast"`, or its alias `"priority"` | The provider's premium or higher-priority offer |
| Ultrafast | `"ultrafast"` | The highest-speed offer |
| Flex | `"flex"` | A lower-cost offer, where the provider has one |
| Batch | The [Batch API](../api-reference/endpoint/batches-create.mdx), not `service_tier` | Large deferred workloads |

Tiers are available only for text models, and only where the model and provider support them. Model pages show tier-specific prices where Phaseo has them.

## What happens when a tier isn't offered

Phaseo keeps only the provider routes that offer the requested tier; it never falls back to another tier. If no route offers it, the request fails with `400 unsupported_model_or_endpoint`, reason `service_tier_not_supported`.

Other values fail with `400 validation_error`:

- `service_tier: "batch"` on a synchronous request (keyword `batch_service_tier_not_supported`). Use the Batch API instead.
- Any value other than `standard`, `default`, `fast`, `ultrafast`, `priority`, `flex`, or `batch` (keyword `unsupported_service_tier`).

You always send these gateway values. Phaseo translates them into each provider's own controls, so an Anthropic route, for example, receives Anthropic's tier fields.

## Request a tier on each endpoint

<CodeGroup>
```json Responses
{
  "model": "openai/gpt-5.5",
  "input": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "flex"
}
```

```json Chat Completions
{
  "model": "openai/gpt-5.5",
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "flex"
}
```

```json Messages
{
  "model": "anthropic/claude-opus-5.5",
  "max_tokens": 512,
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "fast"
}
```
</CodeGroup>

For `ultrafast`, use a model whose page lists Ultrafast pricing.

## Mistral Priority and EU routing

Mistral Priority Tier needs an eligible Mistral enterprise account. Phaseo maps `priority` to Mistral's automatic priority mode and bills the tier Mistral reports: if Mistral falls back to Standard, you pay Standard prices.

A price in the catalogue doesn't make a tier routable. Priority stays off unless the specific Mistral route advertises Priority support, and eligibility still depends on the Mistral account and model.

GLM 5.2 can be pinned to Mistral's EU regional endpoint with the `mistral-eu` provider offer:

```json
{
  "model": "z-ai/glm-5.2",
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "priority",
  "provider": {
    "only": ["mistral-eu"],
    "required_execution_region": "eu"
  }
}
```

Mistral regional inference costs 10% more. Batch pricing is available only on the global Mistral offer through the Batch API; Mistral doesn't support Batch on regional endpoints.

The full field reference is in [Parameters](../api-reference/parameters.mdx); for how tiers combine with provider order and fallbacks, see [Routing and Fallbacks](./routing-and-fallbacks.mdx).
