Run `phaseo deepseek-harness` to add Phaseo to the DeepSeek Harness model picker, or add a custom provider in the Harness UI or `settings.yaml`. Harness sends OpenAI-compatible Chat Completions requests straight to Phaseo, so no adapter is needed.

## Set up with the Phaseo CLI

```bash
phaseo login
phaseo deepseek-harness
```

If Harness is missing, the CLI shows the official install command and asks before running it. Setup then:

- writes the provider, base URL, protocol, model catalog, and default model to `$DSH_HOME/cordis.patch.yml` (`DSH_HOME` defaults to `~/.dsh`), inside a marked block so it can later update or remove only its own settings;
- adds every active Phaseo text model that works with Chat Completions. Use `--catalog default` to add only the default model;
- creates a `Phaseo CLI: DeepSeek Harness API Key` that expires after 90 days and has a $100 monthly spend limit, and writes it to Harness's protected `$DSH_HOME/.credentials.yaml`. Run `phaseo deepseek-harness` again to replace an expired key.

The default model is `anthropic/claude-sonnet-4.6`. To pick another:

```bash
phaseo deepseek-harness --model YOUR_PHASEO_MODEL_ID
```

## Add Phaseo in the Harness UI

1. Open **Settings > Models** and choose **Add a custom provider**.
2. Enter:

| Field | Value |
| --- | --- |
| Provider ID | `phaseo` |
| Display name | `Phaseo` |
| Base URL | `https://api.phaseo.app/v1` |
| API protocol | `OpenAI Completions` |
| API key | A Phaseo API key |

3. Under **Model catalog**, choose **Fetch available models**.
4. Select a Chat Completions model with tool support, such as `anthropic/claude-sonnet-5.5`, and save the provider.
5. In the composer, choose the Phaseo model and start a new session.

Saved sessions and credential references keep the provider ID, so treat `phaseo` as permanent. You can edit the display name, URL, key, and model list later.

## Configure Phaseo in settings.yaml

You can set up the same provider in `$DSH_HOME/settings.yaml`. Keep the key out of this file: `apiKeyEnv` names the variable Harness reads it from.

```yaml $DSH_HOME/settings.yaml
llm-pi-ai:
  providers:
    phaseo:
      displayName: Phaseo
      apiKeyEnv: PHASEO_API_KEY
      api: openai-completions
      baseURL: https://api.phaseo.app/v1
      models:
        - id: YOUR_PHASEO_MODEL_ID
```

Set `PHASEO_API_KEY` in the environment that launches Harness, or store the key on the Models page. Replace `YOUR_PHASEO_MODEL_ID` with an exact ID from Phaseo; for coding agents, start with `anthropic/claude-sonnet-5.5`. The `models` list is a saved catalog, not a live query, so update it when you want more Phaseo models in Harness.

## Check it works

Check the key and model discovery first:

```bash
curl https://api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

Then select a Phaseo model in a new Harness session and send `Reply with exactly: Phaseo is connected.` A reply confirms the whole path from Harness through Phaseo to the model provider. The request also appears in **Settings → Usage → Logs**. Live requests are billed as normal usage.

## Remove Phaseo

```bash
phaseo integrations remove deepseek-harness
```

This removes only the Phaseo-owned configuration and revokes the key.

## Fix common problems

| Problem | Fix |
| --- | --- |
| Fetching models returns `401` | Check that the key is current and the base URL includes `/v1`. |
| The model is missing from the picker | Fetch the catalog again, or add the exact model ID under `models` in `settings.yaml`. |
| Harness reports `MISSING_CREDENTIAL` | Store the key on the Models page, or make `PHASEO_API_KEY` available to the Harness process. |
| Requests go to the wrong endpoint | Select `OpenAI Completions` (`openai-completions`). This provider uses Phaseo's `/v1/chat/completions`. |
| A model rejects function tools with reasoning on | Choose a model that supports tools on Chat Completions. Models that need the Responses API for reasoning with tools don't work with this protocol. |
| A session keeps its old model | Start a new session. Harness saves the provider and model in sessions that have sent a request. |
