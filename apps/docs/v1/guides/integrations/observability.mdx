Trace Phaseo requests in two ways: turn on [Broadcast](../broadcast.mdx) to have Phaseo send a trace of every request to Langfuse, LangSmith, or any OpenTelemetry tool with no code change, or keep your tracing library in your app and point its model client at Phaseo.

| | Broadcast | Tracing in your app |
| --- | --- | --- |
| Where traces come from | Phaseo, for every request | Your app's model client |
| Code change | None; set up in **Settings → Broadcast** | Wrap the client, then change its base URL |
| What's in the trace | Model, provider, each provider attempt, tokens, cost, timing, and (optionally) prompt and output | Whatever your library records, plus your own app context |

## Langfuse with the OpenAI SDK

Keep Langfuse's OpenAI wrapper and give the wrapped client Phaseo's base URL:

```bash
pip install langfuse openai
```

```python
import os
from langfuse.openai import openai

client = openai.OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
)

response = client.responses.create(
    model="openai/gpt-6-astra",
    input="Reply with only: ok",
)
```

## LangSmith with LangChain

Use the [LangChain](./langchain.mdx) `ChatOpenAI` setup and turn on LangSmith with LangChain's usual environment variables:

```bash
export LANGSMITH_TRACING=true
export LANGSMITH_API_KEY="your_langsmith_key"
export PHASEO_API_KEY="your_phaseo_key"
```

## OpenTelemetry

If your framework already emits OpenTelemetry spans, you don't need a special exporter. Add this request context to your spans yourself:

- model ID;
- endpoint, such as `responses` or `chat.completions`;
- the Phaseo request ID, from response metadata or [logs](../../api-reference/endpoint/activity.mdx);
- the provider that served the request, when response metadata is on.

Never record Phaseo API keys as span attributes.
