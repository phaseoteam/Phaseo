Give LiteLLM the model `openai/<Phaseo model ID>`, your Phaseo key, and `api_base="https://api.phaseo.app/v1"`. This works for direct LiteLLM calls and for models behind a LiteLLM proxy.

## Install

```bash
pip install litellm
```

## Call Phaseo from LiteLLM

```python
import os
from litellm import completion

response = completion(
    model="openai/openai/gpt-6-astra",
    api_key=os.environ["PHASEO_API_KEY"],
    api_base="https://api.phaseo.app/v1",
    messages=[{"role": "user", "content": "Reply with only: ok"}],
)

print(response.choices[0].message.content)
```

A printed `ok` means the setup works. LiteLLM uses the `openai/` prefix for OpenAI-compatible endpoints. The Phaseo model ID is still `openai/gpt-6-astra`, so the LiteLLM model string becomes `openai/openai/gpt-6-astra`.

## Add Phaseo models to a LiteLLM proxy

Give each model an alias so application code doesn't need the LiteLLM prefix:

```yaml
model_list:
  - model_name: phaseo-gpt-6-astra
    litellm_params:
      model: openai/openai/gpt-6-astra
      api_key: os.environ/PHASEO_API_KEY
      api_base: https://api.phaseo.app/v1
```

Then call the proxy with `model: "phaseo-gpt-6-astra"`. Aliases keep model names readable in production.

## Known limits

- Some proxy layers change or drop tool types they don't know. If you use Phaseo [server tools](../server-tools/index.mdx), test the exact LiteLLM route.
- Both LiteLLM and Phaseo track spend. Decide which one is your record for cost; Phaseo's prices are in the [pricing calculator](../../api-reference/endpoint/pricing-calculate.mdx).
