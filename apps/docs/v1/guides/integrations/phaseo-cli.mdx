Install `@phaseo/cli` and run `phaseo login` to connect coding agents to Phaseo and manage keys, workspaces, presets, settings, and guardrails from the terminal. The CLI also reads models, providers, pricing, credits, activity, analytics, and generations.

## Install

<CodeGroup>

```bash npm
npm install -g @phaseo/cli
```

```bash pnpm
pnpm add -g @phaseo/cli
```

```bash yarn
yarn global add @phaseo/cli
```

```bash bun
bun add -g @phaseo/cli
```

</CodeGroup>

Check the version:

| Command | Prints |
| --- | --- |
| `phaseo --version` | The installed version. |
| `phaseo version` | The version and the update command for your package manager. Add `--json` for structured output. |

Interactive runs also show a hint when a newer version is published.

## Sign in

```bash
phaseo login
```

| Flow | Flag | Use it for |
| --- | --- | --- |
| Sign in with Phaseo | `--browser` | Browser OAuth with authorization code and PKCE. |
| Sign in with Device Code | `--device-code` | SSH, CI, headless shells, and agent environments. |

Remote and non-interactive environments use device code automatically. Check who you're signed in as, with your scopes, active workspace, and other workspaces:

```bash
phaseo whoami
phaseo whoami --json
```

## Manage your workspace

```bash
phaseo keys list
phaseo keys current

phaseo workspaces list
phaseo workspaces members <workspace-id-or-slug>

phaseo guardrails list
```

Use `--json` when an agent or script reads the output. The CLI covers everyday account tasks; changes to key limits, budgets, BYOK, routing rules, presets and identity are made in the dashboard or with a management key. See [Manage Phaseo from an agent](../../developers/manage-from-an-agent) for which tasks the CLI covers.

## Connect a coding agent

Use the agent's name as the command. The CLI asks for a dedicated key, which you approve in your browser, and writes the agent's configuration:

```bash
phaseo codex
phaseo claude-code
phaseo opencode
phaseo fx
phaseo deepseek-harness
phaseo pi
phaseo prime-agent
phaseo openclaw
phaseo hermes
phaseo aider
phaseo continue
phaseo zed
phaseo roo-code
phaseo kilo-code
phaseo cursor
```

Use `--model`, `--catalog all|default`, or `--dry-run` as needed. `phaseo setup <agent>` and `phaseo integrations setup <agent>` also work.

### Approve the key in your browser

The first time you set up an agent, the CLI opens a Phaseo dashboard page and prints its link. The page shows the workspace, the key's name, its $100 monthly spend limit and 90-day expiry, and that the Phaseo CLI asked for it. Choose **Approve and create key**, and the CLI picks up the key once and finishes setup. Choose **Deny**, or leave the request for 10 minutes until it expires, and nothing is created.

Approve while signed in to the dashboard with the account you used in the CLI, as a workspace owner or admin, and with your second factor if you've set one up. Over SSH or in CI, open the printed link on any device where you're signed in.

To use a key you made in the dashboard instead, pass it with `--key <key>`, or with `--key-stdin` to keep it out of your shell history. The CLI checks the key and stores it, and doesn't revoke it when you remove the agent.

To run Cline, Kilo Code, oh-my-pi, Muse Code, or MiniMax Code with temporary settings that are deleted when it exits, use the session runner. Phaseo flags go before `--`, the agent's own flags after it:

```bash
phaseo cline --model openai/gpt-5.6-terra -- --tui
phaseo kilo --model openai/gpt-5.6-terra
phaseo omp --model openai/gpt-5.6-terra
phaseo muse --model meta/muse-spark-1.3
phaseo minimax --model openai/gpt-5.6-terra
```

`phaseo run <cline|kilo|omp|muse|minimax>` is the long form. Add `--catalog all` to list every active Phaseo text model, or `--dry-run --json` to preview without creating a key. The runners offer to install a missing agent in an interactive terminal (MiniMax Code uses its official PowerShell installer on Windows; Muse Code must be installed by hand on Windows). Use `--skip-install` when you manage the agent yourself.

[Coding Agents](./coding-assistants.mdx) lists every agent, what its command does, and its guide.

## Script with the CLI

Commands with `--json` print plain structured output with no colour or spinners. Elsewhere, spinners go to `stderr` and clear their line when done.

| Variable | Effect |
| --- | --- |
| `NO_COLOR` | Turns off colour. |
| `TERM=dumb` | Turns off animation. Non-TTY `stderr` does the same. |
| `FORCE_COLOR=1` | Forces colour when a terminal wrapper supports it but doesn't report a TTY. |

## How the CLI keeps credentials safe

- Sessions are stored in the OS credential store. Set `PHASEO_SESSION_BACKEND=file` only if no credential store is available; it keeps refresh tokens in a permission-restricted plaintext file.
- `phaseo logout` revokes the stored refresh token before clearing local state.
- Management keys need explicit capabilities. Inference keys are limited by guardrails, routing policies, and workspace settings rather than scopes.

## OAuth apps

Phaseo uses one OAuth authorization server for the CLI, user-created apps, and dynamically registered MCP clients. The CLI uses browser or device login with rotating refresh tokens. Third-party clients use authorization code with PKCE, explicit scopes and workspace consent, and optional protected-resource binding. They get a revocable access token that lasts 7 days and a rotating refresh token that lasts 90 days from its last use; see [Build an OAuth Next.js Workbench](../../cookbook/build-an-oauth-nextjs-workbench) for how refresh works. Approving the same app again renews its key instead of adding a second one.

The hosted Phaseo API has third-party OAuth turned on. Self-hosted and preview API deployments keep it off unless `PHASEO_THIRD_PARTY_OAUTH_ENABLED` is truthy: `1`, `true`, `yes`, or `on`, case-insensitive, with surrounding spaces ignored.

```bash .env
PHASEO_THIRD_PARTY_OAUTH_ENABLED=true
```

Turning it on exposes user-created OAuth app management and dynamic client registration, so review your redirect URI, consent, client-secret, rate-limit, and workspace authorization settings first.

## Update

```bash
phaseo update
```

This runs the update with the package manager you installed the CLI with. To update by hand:

<CodeGroup>

```bash npm
npm install -g @phaseo/cli@latest
```

```bash pnpm
pnpm add -g @phaseo/cli@latest
```

```bash yarn
yarn global add @phaseo/cli@latest
```

```bash bun
bun add -g @phaseo/cli@latest
```

</CodeGroup>
