Call Phaseo from any automation platform that can send an authenticated HTTP request: add an HTTP step that posts to `https://api.phaseo.app/v1/responses` with your key as a bearer token. Phaseo has no native Zapier, n8n, or Pipedream app.

## Build the request

| Setting | Value |
| --- | --- |
| Method | `POST` |
| URL | `https://api.phaseo.app/v1/responses` |
| Header | `Authorization: Bearer <PHASEO_API_KEY>` |
| Header | `Content-Type: application/json` |

```json
{
  "model": "openai/gpt-6-astra",
  "input": "Summarise the supplied workflow data in one paragraph."
}
```

Store the key in the platform's credential or secret store, not in a shared workflow definition. See [Responses](../../api-reference/endpoint/responses.mdx) for every request field.

## Zapier

Use **Webhooks by Zapier → Custom Request**:

1. Select `POST` and enter `https://api.phaseo.app/v1/responses`.
2. Add the bearer and content-type headers.
3. Map fields from earlier Zap steps into `input`.
4. Test the Zap with non-sensitive data.

## n8n

Use the **HTTP Request** node with bearer authentication and a JSON body. Map the incoming item into `input` with an n8n expression.

## Pipedream

Use an HTTP request step or a Node.js code step. Store `PHASEO_API_KEY` as a Pipedream secret and read it from the step environment.

## Check it works

Run the step once. A `200` response with an `output` array means the key and URL work, and the request appears in **Settings → Usage → Logs**.

## Run automations safely

- Give each automation its own key with a spending limit, so you can track and revoke it on its own.
- Use [structured outputs](../structured-outputs.mdx) when later steps expect machine-readable fields.
- Retry on `429` and recoverable `5xx` responses; see [Errors](../../api-reference/errors.mdx).
- Don't repeat external actions that aren't idempotent just because a model step was retried.
