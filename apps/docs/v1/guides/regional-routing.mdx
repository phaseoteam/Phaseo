Send text requests to `eu.api.phaseo.app` or `us.api.phaseo.app` to use only provider routes that run the model and handle prompt and completion data in that region. Model IDs and API keys stay the same. Chat Completions, Responses, and Messages are supported.

| Region | Base URL | Provider routes used |
| --- | --- | --- |
| European Union | `https://eu.api.phaseo.app/v1` | Only routes that declare EU execution and EU data handling |
| United States | `https://us.api.phaseo.app/v1` | Only routes that declare US execution and US data handling |
| Global | `https://api.phaseo.app/v1` | The standard global routing policy |

<Warning>
Regional routing is not yet an end-to-end data residency guarantee. Phaseo restricts provider selection and places the gateway near the region, but shared account, billing, cache, and operational systems can process data outside it. See [What stays outside the region](#what-stays-outside-the-region).
</Warning>

## Send a regional request

<CodeGroup>
```ts TypeScript
import { Phaseo } from "@phaseo/sdk";

const phaseo = new Phaseo({
  apiKey: process.env.PHASEO_API_KEY!,
  region: "eu",
});

const response = await phaseo.responses.create({
  model: "openai/gpt-5.6-luna",
  input: "Summarize this note in one sentence.",
});

console.log(response.output_text);
```

```python Python
import os
from phaseo import Phaseo

phaseo = Phaseo(
    api_key=os.environ["PHASEO_API_KEY"],
    region="eu",
)

response = phaseo.responses.create({
    "model": "openai/gpt-5.6-luna",
    "input": "Summarize this note in one sentence.",
})

print(response.get("output_text"))
```

```bash Chat Completions
curl https://eu.api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5.6-luna",
    "messages": [
      {"role": "user", "content": "Write a two-line status update."}
    ]
  }'
```

```bash Responses
curl https://eu.api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5.6-luna",
    "input": "Extract the three most important actions from this note."
  }'
```

```bash Messages
curl https://us.api.phaseo.app/v1/messages \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -H "anthropic-version: 2023-06-01" \
  -d '{
    "model": "anthropic/claude-sonnet-5.5",
    "max_tokens": 256,
    "messages": [
      {"role": "user", "content": "Summarize this incident report."}
    ]
  }'
```
</CodeGroup>

In the SDKs, set `region` to `"eu"` or `"us"`; leave it out, or use `"global"`, for global routing. The SDK throws if you set both `region` and a custom `baseUrl` (`base_url` in Python), because they pick different hosts.

The hostname is the policy. A `required_execution_region` or `required_data_region` in the request or a preset that names another region fails with `400 validation_error`, reason `deployment_region_conflict`. Presets and dynamic routing rules are applied first and the regional rule last, so they can't weaken it. Phaseo never retries through a provider outside the region.

## What a regional request can contain

| Supported | Rejected |
| --- | --- |
| Text input and text output | Images, audio, video, documents, files, and attachments |
| Streaming and non-streaming | Non-text output modalities |
| System and developer instructions | Provider-hosted tools such as web search, file search, code execution, computer use, and image generation, and `web_search_options` |
| Your own `function` and `custom` tools, and text tool results | Phaseo [server tools](./server-tools) (`phaseo:` types) |
| Structured text and JSON output, where the model supports it | Image, audio, video, embedding, moderation, batch, file, webhook, and realtime endpoints |
| Presets, provider ordering, fallbacks, and price limits that don't conflict with the region | |

Your own tools are allowed because they run in your application. Hosted and server tools run somewhere the regional rule can't control.

## Find models available in a region

Call `/v1/models` on the same hostname you send requests to. Availability differs between the EU, US, and global endpoints.

```bash
curl https://eu.api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

The list contains only models with an active provider route whose declared execution and data regions both include the region, and advertises only Chat Completions, Responses, and Messages with text input and output. Each offer shows its regions:

```json
{
  "provider": { "id": "example-eu", "name": "Example EU" },
  "residency": {
    "execution_regions": ["eu"],
    "data_regions": ["eu"]
  }
}
```

## Check which gateway handled a request

Regional responses carry `X-Phaseo-Gateway-Region: eu` (or `us`). The header names the regional policy that handled the request; it isn't proof of where Cloudflare ran it. Request details also record the required execution and data regions, the selected provider, and that provider's declared regions.

## Errors

Regional rule violations return `400 not_supported` with one of these `reason` values:

| `reason` | Cause | Fix |
| --- | --- | --- |
| `regional_endpoint_not_supported` | The path isn't available regionally | Use Chat Completions, Responses, or Messages, or the global API |
| `regional_non_text_content` | Media, a file, or an attachment in the request | Remove it, or use the global API |
| `regional_non_text_output` | A non-text output modality was requested | Ask for text, or use the global API |
| `regional_hosted_tool_not_supported` | A tool other than `function` or `custom` | Use your own function tool, or the global API |

`400 validation_error` with reason `deployment_region_conflict` means the request or a preset names another region; remove that setting. If no healthy provider route meets both the model and the region, the request stops before any provider is called; pick a model listed by the regional `/v1/models`.

## What stays outside the region

The region rule covers which provider runs the model and handles prompt and completion data. It doesn't yet cover the whole request lifecycle:

- Cloudflare placement puts the gateway near the region, but it isn't a compliance boundary.
- Account, authentication, billing, and request metadata live on shared Supabase infrastructure.
- Cloudflare KV and Worker invocation logs aren't region-bound.
- Calls to the provider go to that provider's regional endpoint, regardless of where Cloudflare placed the gateway.
- Support and operations staff aren't restricted to the region.

Phaseo will call this end-to-end data residency only once the gateway, storage, logging, provider, and operational paths all have enforceable regional controls.
