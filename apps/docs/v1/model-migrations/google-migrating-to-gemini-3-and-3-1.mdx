Set reasoning depth with `reasoning.effort`, which Phaseo sends to Gemini 3 as `thinking_level`, and send assistant tool-call turns back as Phaseo returned them so thought signatures survive. Treat Gemini 3 and Gemini 3.1 Pro as two separate migrations.

| Phaseo model ID | Status |
| --- | --- |
| `google/gemini-3.1-pro-preview` | Available |
| `google/gemini-3-flash-preview` | Available |
| `google/gemini-3.1-flash-lite` | Deprecated; retires May 7, 2027 |
| `google/gemini-3-pro-preview` | Retired March 9, 2026; requests route to `google/gemini-3.1-pro-preview` |
| `google/gemini-3.1-flash-lite-preview` | Retired May 25, 2026; requests route to `google/gemini-3.1-flash-lite` |

Retired IDs keep working only through automatic replacement; see [Model Deprecation and Retirement](../guides/model-retirement). Call the current ID directly.

## Set reasoning depth

Gemini 3 replaced thinking budgets with `thinking_level`. Phaseo maps `reasoning.effort` (or the flat `reasoning_effort`) to it:

| `reasoning.effort` | Gemini 3 Flash | Gemini 3.1 Pro |
| --- | --- | --- |
| `minimal` | `MINIMAL` | `LOW` (3.1 Pro has no `MINIMAL`) |
| `low` | `LOW` | `LOW` |
| `medium` | `MEDIUM` | `MEDIUM` |
| `high`, `xhigh`, `max` | `HIGH` | `HIGH` |

```json
{
  "model": "google/gemini-3.1-pro-preview",
  "messages": [{ "role": "user", "content": "Compare these three architecture options." }],
  "reasoning": { "effort": "medium" }
}
```

The levels don't behave like other providers' effort settings one for one, so re-test latency and quality at each level you expose.

## Keep thought signatures

Gemini 3 returns thought signatures that carry reasoning context across calls, and in function calling a missing signature can lower quality or return `400`. Send each assistant turn, including its tool calls, back exactly as Phaseo returned it. Phaseo replays a signature to the model that issued it; when one is missing or came from a different model, it sends Google's skip placeholder so the request doesn't fail.

## Revisit prompts and media

Google's Gemini 3 guidance favors direct prompts and parameter-driven control over long prompt scaffolding. If your prompts compensate for older model behavior, simplify them and re-evaluate.

Gemini 3 also added `media_resolution` for images and documents. Phaseo doesn't expose it, so Google's default applies; re-test image, document, and mixed-media routes rather than assuming older results hold.

## What to test

- **Reasoning:** concise versus scaffolded prompts, step-by-step tasks, long-context synthesis, and agent workflows that depend on reasoning continuity.
- **Responses:** signatures across turns, function-calling success rate, schema pass rate, and empty, partial, or malformed outputs after changing effort.
- **Production metrics:** latency at each level, token use and cost, multimodal routes, and task success on Gemini 3 versus Gemini 3.1 Pro.

## Roll out

1. Migrate the request shape and signature handling first.
2. Re-run prompt and schema evaluations on Gemini 3.
3. Promote Gemini 3.1 Pro separately for the routes that need deeper reasoning.
4. Keep a cheaper fallback for high-volume workloads.
