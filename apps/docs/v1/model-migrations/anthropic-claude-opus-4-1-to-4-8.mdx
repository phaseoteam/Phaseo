Move Claude Opus 4.1 traffic to `anthropic/claude-opus-4.8`: change the model ID, remove sampling parameters, and replace thinking budgets with an effort level.

Anthropic deprecated Opus 4.1 on June 5, 2026 and retired it on August 5, 2026. Phaseo keeps serving `anthropic/claude-opus-4.1` while any provider does, and once none does it routes those requests to Opus 4.8 (see [Model Deprecation and Retirement](../guides/model-retirement)). Migrate before that happens so the change is tested rather than automatic.

Anthropic's guidance is cumulative: apply the Opus 4.7 request-shape changes, then review the Opus 4.8 behavior changes.

| | Claude Opus 4.1 | Claude Opus 4.8 |
| --- | --- | --- |
| Phaseo model ID | `anthropic/claude-opus-4.1` | `anthropic/claude-opus-4.8` |
| Context window | 200K tokens | 1M tokens |
| Max output | 32K tokens | 128K tokens |
| `temperature`, `top_p`, `top_k` | Sent | Left out by Phaseo |
| Thinking | `budget_tokens` | Adaptive, steered by effort (default `high`) |
| Mid-conversation system messages | No | Yes |

## Update the request

**1. Change the model ID** to `anthropic/claude-opus-4.8`.

**2. Remove sampling parameters.** Anthropic rejects non-default `temperature`, `top_p`, and `top_k` on Opus 4.7 and later with `400`. Phaseo leaves them out instead of failing, so they no longer have any effect; tune with instructions instead.

**3. Replace thinking budgets with an effort level.** Phaseo doesn't forward `budget_tokens` to Opus 4.8. Any reasoning setting is sent as `thinking: {"type": "adaptive", "display": "summarized"}`, and `reasoning.effort` (or `output_config.effort` on `/v1/messages`) sets the depth:

```json
{
  "model": "anthropic/claude-opus-4.8",
  "max_tokens": 4096,
  "thinking": { "type": "adaptive" },
  "output_config": { "effort": "high" },
  "messages": [{ "role": "user", "content": "Plan the schema migration." }]
}
```

Without any reasoning setting, Opus 4.8 doesn't think. `reasoning.effort: "none"` sends `thinking: {"type": "disabled"}`.

**4. Rebaseline effort and long context.** Opus 4.8 defaults effort to `high` and has a much larger context window than Opus 4.1. Re-test latency budgets, token use, prompt caching, and long-document and long-agent traces. On Microsoft Foundry, Anthropic documents a 200K context window for Opus 4.8 at launch.

**5. Simplify instruction updates in long conversations.** Opus 4.8 accepts `role: "system"` messages mid-conversation. If your agent loop rewrites the whole system prompt each turn, add a system message instead and keep more cache hits.

## What to test

- requests that still send `temperature`, `top_p`, or `top_k`, since their effect is now gone;
- thinking routes that relied on `budget_tokens`;
- long-horizon agent and tool workflows;
- schema-sensitive outputs at each `effort` level;
- token cost and latency on your highest-volume Opus 4.1 prompt classes.

## Roll out

1. Remove sampling parameters and thinking budgets before switching traffic.
2. Shadow Opus 4.8 on production-like prompts and tool flows.
3. Canary with Opus 4.1 as a fallback in `models` while providers still serve it.
4. Promote once latency, cost, and task-completion changes are within target.
