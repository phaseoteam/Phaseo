Change the model to `anthropic/claude-opus-5` and keep Claude Opus 4.8 as a fallback while you evaluate it. The price is the same as Opus 4.8, so the cost difference comes from token use.

```json
{
  "model": "anthropic/claude-opus-5",
  "models": ["anthropic/claude-opus-4.8"],
  "messages": [
    {
      "role": "user",
      "content": "Review this implementation plan and identify the highest-risk assumptions."
    }
  ]
}
```

| | Claude Opus 4.8 | Claude Opus 5 |
| --- | --- | --- |
| Phaseo model ID | `anthropic/claude-opus-4.8` | `anthropic/claude-opus-5` |
| Context window | 1M tokens | 1M tokens |
| Max output | 128K tokens | 128K tokens |
| Price per 1M tokens (input / output) | $5.00 / $25.00 | $5.00 / $25.00 |
| Thinking when the request sets no reasoning | Off | Adaptive |

Prices are Anthropic's standard tier from the catalogue; check the model page for other tiers and providers.

## How Phaseo sends the request

Opus 5 takes the same request shape as Opus 4.7 and 4.8:

- **Sampling parameters are left out.** `temperature`, `top_p`, and `top_k` aren't sent to the model.
- **Any reasoning setting turns on adaptive thinking.** Phaseo sends `thinking: {"type": "adaptive", "display": "summarized"}`, and `reasoning.effort` becomes `output_config.effort`. Thinking budgets aren't forwarded.
- **`reasoning.effort: "none"` or `reasoning.enabled: false` turns thinking off** (`thinking: {"type": "disabled"}`).
- **With no reasoning setting, Phaseo sends no `thinking` field,** so Opus 5's default, adaptive thinking, applies. Opus 4.8 thinks only when asked, so the same request can use more output tokens on Opus 5.

## What to test

- **Prompts and outputs:** instruction following on your longest system prompts, schema pass rates, response length and stopping, and prompts tuned for Opus 4.8.
- **Tools and agents:** tool selection and arguments, recovery after tool errors or partial results, long-horizon completion rate, and permission boundaries in high-autonomy workflows.
- **Operations:** latency and token use at each effort level you expose, context use on long documents and agent traces, cost per successful task, and fallback when the primary route times out or fails.

## Roll out

1. Shadow representative production traffic before serving users.
2. Canary by workload rather than moving every Opus route at once.
3. Promote only after quality, latency, cost, and tool-safety checks meet your targets.
