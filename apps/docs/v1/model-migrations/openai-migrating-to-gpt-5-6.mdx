Pick the GPT-5.6 tier that fits the workload, swap only the model ID, and re-test reasoning effort, tools, latency, and cost. Keep your previous GPT-5 model as a fallback until your evaluations pass.

## Choose a tier

| Model | Use it for | Reasoning effort |
| --- | --- | --- |
| `openai/gpt-5.6-sol` | Highest-capability reasoning, agentic coding, scientific analysis, and complex professional work | `none`, `low`, `medium`, `high`, `xhigh`, `max` |
| `openai/gpt-5.6-terra` | Balanced everyday reasoning, coding, and assistant work | `none`, `low`, `medium`, `high`, `xhigh`, `max` |
| `openai/gpt-5.6-luna` | Lower-latency, cost-sensitive work | `none`, `low`, `medium`, `high`, `xhigh`, `max` |

All three have a 1,050,000-token context window and 128K output tokens. Each also has a Pro ID (`openai/gpt-5.6-sol-pro`, `-terra-pro`, `-luna-pro`), which sends `reasoning.mode: "pro"` for you.

OpenAI's own `gpt-5.6` alias points to `gpt-5.6-sol`; on Phaseo, call the tier IDs directly. The tier aliases `openai/gpt-sol-latest`, `openai/gpt-terra-latest`, and `openai/gpt-luna-latest` follow the newest model in each tier, and `openai/gpt-sol-latest` already points past GPT-5.6. Use them only when you want future releases to roll forward automatically.

## Update your request

GPT-5.6 adds `max`, the highest reasoning budget, on every tier. Use it only where the extra latency and cost pay off.

<CodeGroup>
```json Responses
{
  "model": "openai/gpt-5.6-sol",
  "input": "Review this multi-service incident report and propose a rollback plan.",
  "reasoning": { "effort": "max" }
}
```

```json Chat Completions
{
  "model": "openai/gpt-5.6-terra",
  "messages": [
    { "role": "user", "content": "Design a test plan for this agent workflow." }
  ],
  "reasoning_effort": "medium"
}
```
</CodeGroup>

GPT-5.6 also adds:

- **`reasoning.mode: "pro"`** for harder tasks, without switching model;
- **`reasoning.context`** (`auto`, `current_turn`, or `all_turns`) to control which reasoning persists;
- beta multi-agent support and Programmatic Tool Calling for tool-heavy workflows;
- explicit prompt caching with `prompt_cache_options` and cache breakpoints. On GPT-5.6, `prompt_cache_options.ttl` replaces `prompt_cache_retention`, which Phaseo doesn't send to GPT-5.6 models.

## Review pricing

Prices per 1M tokens on OpenAI's standard tier, for requests up to 272K input tokens:

| Model | Input | Cache read | Cache write (30 min) | Cache write (12 h) | Output |
| --- | ---: | ---: | ---: | ---: | ---: |
| Sol | $5.00 | $0.50 | $6.25 | $12.50 | $30.00 |
| Terra | $2.00 | $0.20 | $2.50 | $5.00 | $12.00 |
| Luna | $0.20 | $0.02 | $0.25 | $0.50 | $1.20 |

Requests above 272K input tokens cost more: Sol $10.00 input and $45.00 output, Terra $4.00 and $18.00, Luna $0.40 and $1.80, with cache prices scaled the same way. Until November 30, 2026, OpenAI's promotional Sol price applies: $4.00 input and $20.00 output up to 272K tokens. Check the model page for current prices on other tiers and providers.

A cache read costs 10% of the input rate, a 30-minute write 1.25×, and a 12-hour write 2.5×. Each input token is billed at exactly one of these rates. Usage counts cache reads and writes inside `input_tokens` (`prompt_tokens` on Chat Completions) and reports writes in `cache_write_tokens`; see [usage and pricing fields](../guides/prompt-caching.mdx#usage-and-pricing-fields).

## Cache repeated context

Put the stable part of the prompt in a cacheable block and leave request-specific text after it:

```json
{
  "model": "openai/gpt-5.6-sol",
  "input": [
    {
      "role": "user",
      "content": [
        {
          "type": "input_text",
          "text": "Stable policy document...",
          "prompt_cache_breakpoint": { "mode": "explicit" }
        },
        {
          "type": "input_text",
          "text": "Apply the policy to this new customer request."
        }
      ]
    }
  ],
  "prompt_cache_options": { "mode": "explicit", "ttl": "30m" }
}
```

- `prompt_cache_breakpoint` caches everything up to and including its block. In `explicit` mode OpenAI caches only the breakpoints you place.
- A block `cache_control` such as `{"type": "ephemeral"}` works too; Phaseo sends it to GPT-5.6 as `prompt_cache_breakpoint`. Either mark reaches Claude as a cache breakpoint, so a fallback to Claude still caches.
- `ttl` is `30m` (the default) or `12h`. See [12-hour cache on OpenAI](../guides/prompt-caching.mdx#12-hour-cache-on-openai) for which routes take it, and [OpenAI retention and options](../guides/prompt-caching.mdx#openai-retention-and-options) for the other fields.

## What to test

- **Reasoning and output quality:** each tier at the effort levels you'll expose, including `max` where quality comes first; standard versus `reasoning.mode: "pro"` on hard tasks; schema pass rate and tool-call quality at each level.
- **Cost and latency:** latency at each effort, output-token growth against your current baseline, the cache read and write mix on repeated prompts, and cost per successful task rather than price per token.

## Roll out

1. Keep your previous GPT-5 model as a fallback in `models`.
2. Keep `max` behind a config flag or [preset](../guides/presets) until it's proven on production-like prompts.
3. Monitor cache write volume separately from cache reads.
4. Make GPT-5.6 the default only after your evaluations confirm task success, cost, and latency.
