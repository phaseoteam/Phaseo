Add a `SKILL.md` to your repository so coding agents call Phaseo the way your project expects: the same base URL, key variable, endpoint, approved models and logging. When you're done you have the public Phaseo skills installed, one project skill on top of them, and one shared client module the skill points at.

The skill and module below are production-ready once you replace the model IDs and preset names with your own.

<Steps>
<Step title="Install the public Phaseo skills">

<Visibility for="humans">
The public skills cover the Gateway, SDKs, presets, routing and migrations. Install them from [`phaseo.app/docs`](https://phaseo.app/docs/.well-known/agent-skills/index.json):
</Visibility>

<Visibility for="agents">
Install the public Phaseo skills from [`phaseo.app/docs`](https://phaseo.app/docs/.well-known/agent-skills/index.json) before writing project-local instructions:
</Visibility>

```bash
npx skills add https://phaseo.app/docs --agent codex --skill '*'
```

Change `--agent` to the agent your team uses. Keep only project-specific rules in your own `SKILL.md`.

</Step>
<Step title="Install the SDK">

<CodeGroup>
```bash npm
npm install @phaseo/sdk
```

```bash pnpm
pnpm add @phaseo/sdk
```

```bash yarn
yarn add @phaseo/sdk
```

```bash bun
bun add @phaseo/sdk
```

```bash Python
pip install phaseo
```
</CodeGroup>

</Step>
<Step title="Add one shared client">

Agents reuse a small, obvious helper more reliably than a large wrapper. Put the client in one module and import it everywhere:

```ts src/lib/phaseo.ts
import Phaseo from "@phaseo/sdk";

export const gateway = new Phaseo({
  apiKey: process.env.PHASEO_API_KEY!,
});
```

Keep one call path per surface you use, such as text generation, embeddings, image generation or async video.

</Step>
<Step title="Write the project skill">

Create `SKILL.md` at the repository root or in the skills folder your agent reads (for example `.agents/skills/phaseo-project/SKILL.md`). The `name` and `description` frontmatter is what the agent reads to decide when to load the skill:

```md SKILL.md
---
name: phaseo-project
description: "How this repository calls Phaseo Gateway: client module, endpoint, approved models and presets, logging and async jobs. Use when adding or changing any Phaseo call in this repo."
---

# Phaseo in this repository

- Import the client from `src/lib/phaseo.ts`. Never create another one.
- The base URL is `https://api.phaseo.app/v1`. The key is in `PHASEO_API_KEY`; never hard-code it or send it to the browser.
- Use the Responses API (`POST /v1/responses`) for new text features.
- Approved models: `openai/gpt-6-astra` for drafts, `anthropic/claude-sonnet-5.5` for reviews. Ask before adding another.
- Prefer the `@support-triage` preset for support features; pass it as `model`.
- Log the response `id` and `model` on every call, and `generation_id` from error bodies.
- For async video jobs, store the returned ID and poll status until it is terminal.
- Validate any model-generated tool arguments before acting on them.
```

</Step>
</Steps>

## Check it worked

Ask your agent to add a small Phaseo feature, such as "summarise a ticket with Phaseo". The change should import `src/lib/phaseo.ts`, read `PHASEO_API_KEY`, use an approved model or preset, and log the response ID. If it doesn't, the skill's `description` probably doesn't match the request: name the task words your team uses.

## What to put in the skill

Answer the questions that cost an agent the most time, and nothing else:

| Question | Example answer |
| --- | --- |
| Which endpoint family? | Responses for text, Embeddings for search |
| Where are credentials? | `PHASEO_API_KEY`, server-side only |
| Which model IDs or presets are approved? | A short list, in `org/model` form |
| What gets logged? | The response `id`, `model`, and `generation_id` on errors |
| How are async jobs tracked? | Store the ID, poll until terminal |

[Codex](../guides/integrations/codex), the [Vercel AI SDK](../guides/integrations/ai-sdk) and [Examples](../guides/examples) show the same conventions in each tool.
