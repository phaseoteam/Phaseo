Add a `provider` object to one request to change which providers serve it, without touching workspace defaults or presets. When you're done you can prefer an order, keep a request inside an allow list, or skip one provider, and see in the response which provider answered.

These request shapes are production-ready. The provider slugs are real examples; check the model's page for the providers that serve your model.

| Field | Does | Example |
| --- | --- | --- |
| `order` | Tries these providers first, then the rest of the eligible pool | `["anthropic-us", "anthropic"]` |
| `only` | Keeps the request inside this list | `["openai", "openai-eu"]` |
| `ignore` | Removes these providers for this request | `["novita"]` |
| `sort` | Ranks what's left by `price`, `latency` or `throughput` | `"price"` |

To use exactly one provider and turn off cross-provider fallback, put it in front of the model ID instead: see [Pin one provider](../guides/routing-and-fallbacks#pin-one-provider).

## Try providers in a set order

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-sonnet-5.5",
    "input": "Write a concise launch summary.",
    "provider": {
      "order": ["anthropic-us", "anthropic"]
    },
    "meta": true
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "anthropic/claude-sonnet-5.5",
  input: "Write a concise launch summary.",
  provider: {
    order: ["anthropic-us", "anthropic"],
  },
  meta: true,
});

console.log(response.meta?.routing); // { selected_provider: "anthropic-us", ... }
```

```python Python
import os

from phaseo import Phaseo

client = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

response = client.generate_response(
    {
        "model": "anthropic/claude-sonnet-5.5",
        "input": "Write a concise launch summary.",
        "provider": {
            "order": ["anthropic-us", "anthropic"],
        },
        "meta": True,
    }
)

print(response["meta"]["routing"]["selected_provider"])
```
</CodeGroup>

`meta: true` adds `meta.routing.selected_provider` to the response, so you can check the result without opening the logs.

## Keep a request inside an allow list

Send `only`, and optionally `sort` to rank inside that list:

```json
{
  "model": "openai/gpt-5.6-luna",
  "input": "Extract the action items.",
  "provider": {
    "only": ["openai", "openai-eu"],
    "sort": "price"
  }
}
```

If none of the listed providers serves the model, the request fails instead of leaving the list.

## Skip one provider

Send `ignore` when a provider is degraded, or while you test another path:

```json
{
  "model": "meta/llama-4-maverick",
  "input": "Summarize the transcript.",
  "provider": {
    "ignore": ["novita"]
  }
}
```

## Combine them

Use `only` for the pool, `order` for the preference inside it, and `sort` for the rest. This keeps a request on Google Vertex, tries the EU region first, then ranks by latency:

```json
{
  "model": "anthropic/claude-sonnet-5.5",
  "input": "Summarize the incident in one sentence.",
  "provider": {
    "only": ["google-vertex", "google-vertex-eu"],
    "order": ["google-vertex-eu"],
    "sort": "latency"
  }
}
```

## Check where it went

Open the request in **Settings → Usage → Logs** and expand **Routing observability**. It lists the providers that were excluded before ranking and why, and the ranked candidates with their scores; [Explain a routing decision](../guides/routing-and-fallbacks#explain-a-routing-decision) describes each field.

Use request-level rules for overrides that are temporary, specific to one caller, or tied to one user flow. Once the same rules appear in several services, move them into a [preset](../guides/presets), where they also limit which providers a fallback can use. To compare rankings, see [Sort providers](./sort-providers-by-price-latency-or-throughput).
