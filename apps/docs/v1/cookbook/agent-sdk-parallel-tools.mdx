Set `toolExecution.toolConcurrency` so the TypeScript Agent SDK runs several independent tool calls from one model turn at the same time instead of one after another. When you're done you have an agent that gathers docs, status and incident context in parallel and still records the results in the order the model asked for them.

The tools return fixed sample data, so the script is illustrative; replace them with your own read-only lookups. A packaged version is in `packages/sdk/agent-sdk-ts/examples/parallel-tool-agent.ts`.

## Build it

<Steps>
<Step title="Install">

```bash
npm install @phaseo/agent-sdk zod
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="Write the agent">

```ts parallel-agent.ts
import { z } from "zod";
import { createAgent, createGatewayAgentClient, defineTool } from "@phaseo/agent-sdk";

const fetchDocs = defineTool({
  id: "fetch-docs",
  description: "Return a short summary of one Phaseo docs page by slug.",
  parameters: {
    type: "object",
    properties: { slug: { type: "string" } },
    required: ["slug"],
    additionalProperties: false,
  },
  inputSchema: z.object({ slug: z.string().regex(/^[a-z0-9/-]{1,80}$/) }).strict(),
  parallelSafe: true,
  timeoutMs: 5_000,
  async execute({ slug }) {
    return { slug, summary: `Docs summary for ${slug}` };
  },
});

const fetchStatus = defineTool({
  id: "fetch-status",
  description: "Return the status of one Phaseo component.",
  parameters: {
    type: "object",
    properties: { component: { type: "string", enum: ["gateway", "dashboard", "async-jobs"] } },
    required: ["component"],
    additionalProperties: false,
  },
  inputSchema: z.object({ component: z.enum(["gateway", "dashboard", "async-jobs"]) }).strict(),
  parallelSafe: true,
  timeoutMs: 5_000,
  async execute({ component }) {
    return { component, status: "operational" };
  },
});

const fetchIncidents = defineTool({
  id: "fetch-incidents",
  description: "Return the open incident count for one service.",
  parameters: {
    type: "object",
    properties: { service: { type: "string", enum: ["gateway", "dashboard", "async-jobs"] } },
    required: ["service"],
    additionalProperties: false,
  },
  inputSchema: z.object({ service: z.enum(["gateway", "dashboard", "async-jobs"]) }).strict(),
  parallelSafe: true,
  timeoutMs: 5_000,
  async execute({ service }) {
    return { service, openIncidents: 0 };
  },
});

const agent = createAgent({
  id: "parallel-tool-agent",
  model: "openai/gpt-6-astra",
  instructions:
    "Use the available tools to gather context, then return one concise operational summary.",
  tools: [fetchDocs, fetchStatus, fetchIncidents],
  toolExecution: { toolConcurrency: 3 },
  maxSteps: 4,
});

const result = await agent.run({
  input:
    "Fetch the presets docs, the gateway status, and the async-jobs incident digest, then summarize the current state.",
  client: createGatewayAgentClient({
    clientOptions: { apiKey: process.env.PHASEO_API_KEY! },
    parallelToolCalls: true,
  }),
  onEvent(event) {
    if (event.type === "tool.started" || event.type === "tool.completed") {
      console.log(event.type, event.toolName, event.timestamp);
    }
  },
});

console.log(result.output);
```

</Step>
<Step title="Run it">

```bash
npx tsx parallel-agent.ts
```

</Step>
</Steps>

## Check it worked

- The three `tool.started` lines print before the matching `tool.completed` lines, with close timestamps, when the model asks for all three in one turn.
- `result.messages` lists the tool results in the order of the model's tool calls, whatever order they finished in.
- The run ends with one summary in `result.output`.

## What runs together

| Setting | Effect |
| --- | --- |
| `toolExecution.toolConcurrency` | Up to this many tool calls from one turn run at once. Default `1`. |
| `parallelSafe: true` on every tool in the turn | Up to 8 run at once, or `toolConcurrency` if that's higher. Use it only for read-only tools. |
| `timeoutMs` on a tool | That call fails after this long, so one stuck dependency can't hold every slot. |
| `parallelToolCalls` on the gateway client | Lets the model ask for several tool calls in one turn; whether it does depends on the model. |

`tool.started` and `tool.completed` still fire for each call, and the run checkpoints once the tool phase finishes.

## Keep it safe

Use concurrency only for tools that don't depend on each other's output and don't change shared state. Start at `2` or `3`, keep tools idempotent with few side effects, and validate every argument with `inputSchema` as above. Add a `state` accessor, as in the [durable loop](./agent-sdk-durable-loop), only when you need to resume runs. Before relying on it, run your tests that cover multi-tool turns and check the result order.
