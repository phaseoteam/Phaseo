Set `provider.sort` on one request to rank the same model's providers by `price`, `latency` or `throughput` instead of the default balanced ranking. When you're done you have the request in your language, and you can see in the response and logs which provider the sort picked.

The request shapes are production-ready. [Choose how providers are ranked](../guides/routing-and-fallbacks#choose-how-providers-are-ranked) covers the workspace default, `routing.mode`, and the `:cheap`, `:fast` and `:nitro` model suffixes.

| `sort` | Use it for |
| --- | --- |
| `price` | Batch and background work, when cost matters more than tail latency |
| `latency` | Chat, copilots and human-in-the-loop tools |
| `throughput` | High-volume generation and backfills with long outputs |

`meta: true` adds `meta.routing.selected_provider`, the provider the sort picked.

## What each sort weighs

A sort changes the weights of the provider score; it doesn't drop the other signals, so an unreliable cheap provider can still lose:

| Sort | Price | Success rate | Median latency | Tail latency | Throughput |
| --- | --- | --- | --- | --- | --- |
| `price` | 0.40 | 0.25 | 0.15 | 0.10 | 0.05 |
| `latency` | 0 | 0.25 | 0.55 | 0.15 | 0.02 |
| `throughput` | 0 | 0.20 | 0.20 | 0.10 | 0.40 |

Latency and throughput come from Phaseo's latest measurements for each provider.

## Sort inside an approved set

Sorting works best once the pool only holds providers you'd accept. Add `only`, and the sort ranks inside it:

```json
{
  "model": "anthropic/claude-sonnet-5.5",
  "input": "Summarize the incident in one sentence.",
  "provider": {
    "only": ["anthropic", "google-vertex"],
    "sort": "latency"
  }
}
```

[Pin or ignore providers](./pin-or-ignore-providers-per-request) covers `only`, `order` and `ignore`.

## Check the ranking

Open the request in **Settings → Usage → Logs** and expand **Routing observability**. It lists the providers considered, their rank, and each score's factors and weights, so you can confirm the sort did what you expected. To apply the same sort to many callers, put it in a [preset](./preset-rollout-and-routing-debug).
