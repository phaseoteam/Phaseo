Build a TypeScript agent that searches the web through Phaseo before it answers, and returns a research brief as strict JSON with its sources. When you're done you have one script that prints a validated `{ topic, summary, sources }` object for any topic you give it.

The script is production-ready for one-shot research. Search results are untrusted web content: the schema check below stops malformed output, but review the sources before you act on them. A packaged version is in `packages/sdk/agent-sdk-ts/examples/research-brief-agent.ts`.

<Step title="Write the agent">

```ts research-agent.ts
import { z } from "zod";
import { createAgent, createGatewayAgentClient } from "@phaseo/agent-sdk";

// Small enough to read in a log line.
const ResearchBrief = z
  .object({
    topic: z.string(),
    summary: z.string().min(1),
    sources: z.array(z.object({ title: z.string(), url: z.string().url() }).strict()).min(1),
  })
  .strict();
type ResearchBrief = z.infer<typeof ResearchBrief>;

const researchBriefAgent = createAgent<string, ResearchBrief>({
  id: "research-brief-agent",
  model: "openai/gpt-6-astra",
  instructions:
    "Research the user's topic with web search and return a concise JSON brief with cited sources.",
  maxSteps: 4,
  parseOutput: (text) => JSON.parse(text),
  outputSchema: ResearchBrief,
});

const client = createGatewayAgentClient({
  clientOptions: { apiKey: process.env.PHASEO_API_KEY! },
  // The JSON Schema the Gateway asks the model for.
  responseFormat: {
    type: "json_schema",
    name: "research_brief",
    schema: {
      type: "object",
      properties: {
        topic: { type: "string" },
        summary: { type: "string" },
        sources: {
          type: "array",
          items: {
            type: "object",
            properties: { title: { type: "string" }, url: { type: "string" } },
            required: ["title", "url"],
            additionalProperties: false,
          },
          minItems: 1,
        },
      },
      required: ["topic", "summary", "sources"],
      additionalProperties: false,
    },
  },
  // Repair near-valid JSON.
  plugins: [{ id: "response-healing" }],
  // Phaseo runs the search; the model writes the queries.
  gatewayTools: [{ type: "phaseo:web_search", parameters: { max_results: 5 } }],
  // Always search before answering.
  toolChoice: "phaseo:web_search",
  webSearchOptions: { search_context_size: "high" },
});

const result = await researchBriefAgent.run({
  input: "Summarize the latest browser automation support patterns for coding agents.",
  client,
  onEvent(event) {
    console.log(event.type, event.runId);
  },
});

console.log(result.output);
```

| Client option | Does |
| --- | --- |
| `responseFormat` | Keeps the output schema explicit |
| `plugins` | [Response healing](./response-healing-for-structured-json) for near-valid JSON |
| `gatewayTools` | Adds `phaseo:web_search`; the [web search guide](../guides/server-tools/web-search) lists its parameters |
| `toolChoice` | Forces the search for a workflow that must always ground itself |
| `webSearchOptions` | Search settings for engines that size their results |

</Step>

## Check it worked

The script prints a brief with at least one source URL. Then open the request in **Settings → Usage → Logs** and check:

- **Web search observability** shows managed searches, results and citations.
- The plugin record shows `response-healing` as `applied` only when the JSON needed repair.
- The response matched the schema; a mismatch would have failed the run with an `AgentSchemaValidationError`.

[Debug web search](./web-search-debugging) covers the cases where no search ran.

## When to use something else

This pattern suits one-shot research where the model should ground itself and callers want typed JSON. Use [`phaseo:web_fetch`](./tool-grounding-with-web-fetch) when you already know the URLs, a [local-tool agent](./agent-sdk-durable-loop) when the work needs your own data more than the web, and plain text output when the contract is loose enough that a schema adds more work than it saves.
