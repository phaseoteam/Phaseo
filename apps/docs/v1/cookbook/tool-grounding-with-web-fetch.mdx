Give the model `phaseo:web_fetch` and a URL you already know, and Phaseo fetches the page, trims it to a size limit and hands the text back before the model extracts, summarises or classifies it. When you're done you have one request that reads a single page and returns fields from it, and you can confirm in the log which page it actually read.

The request is production-ready with the domain limit shown. Fetched pages are untrusted input: the model may see instructions in them, so validate what it returns. Use [web search](../guides/server-tools/web-search) instead when you don't know the URL.

## Send a grounded request

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "input": "Fetch https://phaseo.app/docs/v1/guides/tool-calling and list the section headings. Use only the fetched text.",
    "tools": [
      {
        "type": "phaseo:web_fetch",
        "parameters": {
          "allowed_domains": ["phaseo.app"],
          "max_chars": 8000,
          "max_uses": 1
        }
      }
    ],
    "tool_choice": "phaseo:web_fetch"
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "openai/gpt-6-astra",
  input:
    "Fetch https://phaseo.app/docs/v1/guides/tool-calling and list the section headings. Use only the fetched text.",
  tools: [
    {
      type: "phaseo:web_fetch",
      parameters: {
        allowed_domains: ["phaseo.app"],
        max_chars: 8000,
        max_uses: 1,
      },
    },
  ],
  tool_choice: "phaseo:web_fetch",
});

console.log(JSON.stringify(response.output, null, 2));
console.log(response.usage?.server_tool_use);
```
</CodeGroup>

Keep the prompt explicit about the job after the fetch: extract these fields, summarise this section, classify the document, or check one claim.

| Parameter | Default | Use |
| --- | --- | --- |
| `allowed_domains` | None | Fetch only from these domains. The model can narrow the list, never widen it. |
| `max_chars` | `12000` | Characters of page text returned, up to `100000`. Lower for a title or summary, higher for field extraction. |
| `max_uses` | `10` | Fetch calls per request, up to `100`. |

The [web fetch guide](../guides/server-tools/web-fetch#parameters) lists the rest, including `blocked_domains` and the engines.

## Check what it read

The tool result, which the request log shows, says exactly which page the model grounded on:

```json
{
  "url": "https://phaseo.app/docs/v1/guides/tool-calling",
  "final_url": "https://phaseo.app/docs/v1/guides/tool-calling",
  "status": 200,
  "content_type": "text/html",
  "title": "Tool Calling",
  "truncated": false,
  "returned_chars": 8000
}
```

Check `final_url` after redirects and `truncated` before you trust that the model saw the whole page. Each fetch adds 1 to `usage.server_tool_use.web_fetch_requests`.

## Know the limits

With the default `direct` engine, Phaseo fetches the page itself and reduces HTML to plain text. It refuses `localhost` and private addresses, follows at most 5 redirects, and checks each redirect against your domain lists; a redirect outside them returns `redirect_blocked_by_domain_policy` to the model.

Web fetch suits HTML pages, plain text, and small JSON or XML responses. It isn't for binary files, crawling many pages, or checking how a page renders with JavaScript; use a browser workflow for that. If the page is very large, narrow the extraction task rather than raising `max_chars`.

Start with one preset or endpoint, read the fetch details and truncation in the logs, and tighten the prompt if the fetched text is too broad before you widen use.
