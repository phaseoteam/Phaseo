Run a Go agent that answers an operational question by calling a local status tool, inside one service and without a job system. When you're done you have one `main.go` that prints a short answer about current provider latency.

The tool returns fixed sample data, so the program is illustrative; replace it with your own status or metrics call. It suits a Go service whose context already exists as local or internal calls.

## Build it

<Steps>
<Step title="Install">

```bash
go mod init ops-runbook
go get github.com/phaseoteam/Phaseo/packages/sdk/agent-sdk-go@latest
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

The core `sdk-go/v4` module comes with it. See [Go Agent SDK installation](../sdk-reference/agent/installation) for requirements.

</Step>
<Step title="Write the agent">

```go main.go
package main

import (
  "context"
  "fmt"

  phaseoagent "github.com/phaseoteam/Phaseo/packages/sdk/agent-sdk-go"
)

func main() {
  statusTool := phaseoagent.DefineTool(phaseoagent.Tool{
    ID:          "read-status",
    Description: "Read the current service status page summary.",
    Parameters: map[string]any{
      "type":                 "object",
      "properties":           map[string]any{},
      "additionalProperties": false,
    },
    Execute: func(input any, ctx phaseoagent.RuntimeContext) (any, error) {
      return map[string]any{
        "status":  "degraded",
        "summary": "Latency is elevated on one provider route.",
      }, nil
    },
  })

  agent := phaseoagent.CreateAgent(phaseoagent.AgentDefinition{
    ID:           "ops-runbook-agent",
    Model:        "openai/gpt-6-astra",
    Instructions: "Use tools when helpful and answer briefly.",
    Tools:        []phaseoagent.Tool{statusTool},
    MaxSteps:     4,
  })

  // Reads PHASEO_API_KEY (and PHASEO_BASE_URL if set).
  client, err := phaseoagent.CreateGatewayAgentClient(phaseoagent.GatewayAgentClientOptions{})
  if err != nil {
    panic(err)
  }

  result, err := agent.Run(context.Background(), phaseoagent.RunOptions{
    Input:  "What is happening with provider latency right now?",
    Client: client,
  })
  if err != nil {
    panic(err)
  }

  fmt.Println(result.Run.Status)
  fmt.Println(result.Output)
}
```

</Step>
<Step title="Run it">

```bash
go run .
```

</Step>
</Steps>

## Check it worked

- The program prints `completed`, then an answer that mentions degraded latency on one provider route.
- In **Settings → Usage → Logs**, the first model turn shows a `read-status` tool call.
- Without `PHASEO_API_KEY`, `CreateGatewayAgentClient` returns `PHASEO_API_KEY is required`.

## Before production

`MaxSteps` defaults to `8` in the Go SDK; set it to the smallest number that finishes the job. When a tool takes arguments, give it a `Parameters` schema and an `InputSchema` validator that returns an error for anything unexpected, because the arguments come from the model. Keep tools read-only unless a person approves the call (`RequireApproval: true`). The [Go Agent SDK reference](../sdk-reference/agent/usage) covers approvals, state and streaming, and [web fetch grounding](./tool-grounding-with-web-fetch) shows how to read a known page instead of a local tool.
