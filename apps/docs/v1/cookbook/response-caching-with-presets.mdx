<Warning>
Response caching isn't available yet. A preset accepts `response_caching.enabled` and `response_caching.ttl_seconds`, but the Gateway doesn't store or replay any response today, so every request goes to a provider and is billed normally.
</Warning>

To cut the cost and latency of repeated requests now, use [prompt caching](../guides/prompt-caching): providers reuse a long, stable prompt prefix and bill the cached part at a lower rate. Phaseo keeps a conversation on the provider that holds its cache; see [Provider affinity](../guides/prompt-caching#provider-affinity).

## Prepare a preset for caching

These habits help prompt caching today and will matter for response caching when it ships, because both depend on requests staying identical:

| Keep stable | Why |
| --- | --- |
| System prompt wording | Any change starts a new cache entry |
| Model, provider options and reasoning settings | Part of what makes two requests the same |
| `temperature` and other parameters | Same |
| Response format, tools and tool choice | Same |

Put these in one [preset](../guides/presets) so every caller sends the same request, and give exploratory or high-temperature callers their own preset so they don't mix with cacheable traffic.

## When not to cache

Don't plan to cache prompts that depend on live external state, user-specific answers whose context changes quickly, requests with volatile tool output, or generations where you want a fresh answer each time.
