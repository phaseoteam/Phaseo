Build a TypeScript triage agent whose model, prompt and provider rules come from a dashboard preset, so the code only handles the workflow. When you're done it returns a strict JSON triage decision, pauses cases that need a person, retries model calls a bounded number of times, and logs gateway failures with the IDs you need to find them.

The script is production-ready once the preset exists and you store paused runs, as in the [durable loop](./agent-sdk-durable-loop). A packaged version is in `packages/sdk/agent-sdk-ts/examples/support-triage-agent.ts`.

## Build it

<Steps>
<Step title="Create the preset">

In **Settings → Presets**, create `support-triage` with the routed model, provider preferences, the support system prompt, and stable decoding parameters. The model must support JSON Schema output. [Presets](../guides/presets) explains how a preset merges with each request.

</Step>
<Step title="Install">

```bash
npm install @phaseo/agent-sdk zod
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="Write the agent">

```ts triage-agent.ts
import { z } from "zod";
import { AgentGatewayError, createAgent, createGatewayAgentClient } from "@phaseo/agent-sdk";

const SupportTriageDecision = z
  .object({
    queue: z.enum(["billing", "reliability", "product", "security"]),
    severity: z.enum(["low", "medium", "high"]),
    needsHumanReview: z.boolean(),
    summary: z.string().min(1),
  })
  .strict();
type SupportTriageDecision = z.infer<typeof SupportTriageDecision>;

// `preset` becomes the model `@support-triage` on every turn.
const supportTriageAgent = createAgent<string, SupportTriageDecision>({
  id: "support-triage-agent",
  preset: "support-triage",
  maxSteps: 3,
  parseOutput: (text) => JSON.parse(text),
  outputSchema: SupportTriageDecision,
  humanReview: ({ parsedOutput }) =>
    parsedOutput?.needsHumanReview
      ? { reason: "support_triage_review_required", payload: parsedOutput }
      : null,
});

const client = createGatewayAgentClient({
  clientOptions: { apiKey: process.env.PHASEO_API_KEY! },
  responseFormat: {
    type: "json_schema",
    name: "support_triage_decision",
    schema: {
      type: "object",
      properties: {
        queue: { type: "string", enum: ["billing", "reliability", "product", "security"] },
        severity: { type: "string", enum: ["low", "medium", "high"] },
        needsHumanReview: { type: "boolean" },
        summary: { type: "string" },
      },
      required: ["queue", "severity", "needsHumanReview", "summary"],
      additionalProperties: false,
    },
  },
  plugins: [{ id: "response-healing", mode: "strict" }],
});

try {
  const result = await supportTriageAgent.run({
    input: "Customer says webhook deliveries failed overnight and asks whether data was lost.",
    client,
    modelRetry: { maxRetries: 2, backoffMs: 250 },
    onEvent(event) {
      if (event.type === "model.retrying") console.log("retrying", event.attempt, event.error);
    },
  });

  if (result.run.status === "waiting_for_human") {
    // Store `result`, then continue once an agent has reviewed it.
    console.log("Needs review:", result.run.pause?.payload);
  } else {
    console.log(result.output);
  }
} catch (error) {
  if (error instanceof AgentGatewayError) {
    console.error("Gateway request failed", {
      status: error.status,
      requestId: error.requestId,
      generationId: error.generationId,
      reason: error.reason,
      providerFailureDiagnostics: error.providerFailureDiagnostics,
      routingDiagnostics: error.routingDiagnostics,
    });
  }
  throw error;
}
```

</Step>
<Step title="Run it">

```bash
npx tsx triage-agent.ts
```

</Step>
</Steps>

To finish a paused case, continue it with the reviewer's decision:

```ts
const continued = await supportTriageAgent.continueRun({
  run: storedResult,
  client,
  humanInput: "Approved. Finalize the triage decision.",
});
```

## Check it worked

Run one routine ticket and one risky one, then check:

- In **Settings → Usage → Logs**, the request's model shows the preset was used.
- The risky case ends at `waiting_for_human` with the decision in `pause.payload`.
- A retried model call is recorded on the step as `modelAttempts`, and each retry logs `model.retrying`.
- A blocked request is logged with its `requestId` and `reason`, and the same request in the logs shows why.

## Keep gateway failures visible

Don't swallow errors inside agent callbacks. Catch `AgentGatewayError` at the edge, log its IDs, and rethrow. Once a run fails, its saved state keeps the same details in `run.errorDetails` and `steps[n].errorDetails`, so a later recovery job can read them after the exception is gone.

These failures come from Gateway policy, not the agent, so the request in the logs is where to look:

| Failure | Where it shows |
| --- | --- |
| A guardrail blocks the request | The request's **Guardrail enforcement** section |
| The preset's allowed models reject the model | `validation_error` with keyword `preset_model_not_allowed` |
| Provider credentials or enablement leave no provider | `providerFailureDiagnostics` and **Routing observability** |
| Healing can't produce schema-valid JSON | The plugin record, then `AgentSchemaValidationError` from `outputSchema` |
