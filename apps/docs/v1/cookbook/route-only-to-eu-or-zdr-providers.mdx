Add residency and <Tooltip tip="Zero data retention: the provider doesn't keep prompts or outputs.">ZDR</Tooltip> requirements to the `provider` object of one request, and Phaseo removes every provider offer that doesn't meet them before it ranks the rest. When you're done one workflow runs only on EU or ZDR-capable providers, without changing the policy for the whole workspace.

The request is production-ready. If no provider for the model meets every requirement, the request fails before any provider is called, so check availability first.

| Field | Keeps only providers that |
| --- | --- |
| `required_execution_region: "eu"` | Run the model in the EU |
| `required_data_region: "eu"` | Handle prompt and completion data in the EU |
| `require_zero_data_retention: true` | Meet zero-data-retention requirements |

## Send a restricted request

<Steps>
<Step title="Check a provider qualifies">

On the model's page, the provider cards show regional offers such as **OpenAI EU** or **Google Vertex EU**, ZDR support, and each provider's data-policy notes and sources. For EU, you can also list what the EU gateway serves:

```bash
curl https://eu.api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

</Step>
<Step title="Add only the requirements you need">

Each requirement shrinks the pool, so it can route to a pricier regional offer or leave no provider at all. Send only what your policy demands:

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5.6-luna",
    "input": "Summarize the ticket in one line.",
    "provider": {
      "required_execution_region": "eu",
      "required_data_region": "eu"
    },
    "meta": true
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "openai/gpt-5.6-luna",
  input: "Summarize the ticket in one line.",
  provider: {
    required_execution_region: "eu",
    required_data_region: "eu",
  },
  meta: true,
});

console.log(response.meta?.routing);
```

```python Python
import os

from phaseo import Phaseo

client = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

response = client.generate_response(
    {
        "model": "openai/gpt-5.6-luna",
        "input": "Summarize the ticket in one line.",
        "provider": {
            "required_execution_region": "eu",
            "required_data_region": "eu",
        },
        "meta": True,
    }
)

print(response["meta"]["routing"]["selected_provider"])
```
</CodeGroup>

To also require ZDR, add `"require_zero_data_retention": true`. With all three, a model needs at least one EU provider that also meets ZDR.

</Step>
<Step title="Check where it ran">

`meta.routing.selected_provider` names the provider that served it, for example `openai-eu`. The request in **Settings → Usage → Logs** records the required regions and the selected provider.

</Step>
</Steps>

## Choose request fields, the EU gateway, or workspace settings

| Use | When |
| --- | --- |
| These request fields on `api.phaseo.app` | The rule applies to one workflow, customer or request. Every endpoint and feature stays available. |
| [`eu.api.phaseo.app`](../guides/regional-routing) | Every text request from a service must stay in the EU. The hostname enforces the region and also rejects media input, Phaseo server tools and provider-hosted tools. Sending a `required_execution_region` or `required_data_region` for another region there returns `400 validation_error` with reason `deployment_region_conflict`. |
| **Settings → Privacy** | The rule applies to every request in the workspace. |

Regional routing restricts which providers handle the model call. It isn't yet an end-to-end data residency guarantee; [What stays outside the region](../guides/regional-routing#what-stays-outside-the-region) lists the shared systems. To restrict providers without a residency rule, see [Pin or ignore providers](./pin-or-ignore-providers-per-request).
