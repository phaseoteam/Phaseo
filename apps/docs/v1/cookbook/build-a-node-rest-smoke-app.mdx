Run a zero-dependency Node.js script that calls Phaseo with plain `fetch`, so you can see every request and response. When you're done you have a smoke test you can run before a deploy: it checks the API is reachable, lists models, and sends one request each to Responses, Chat Completions and Embeddings.

The script is illustrative: it prints each HTTP status but always exits `0`, so add the exit-code check in [Use it as a deploy check](#use-it-as-a-deploy-check) before you rely on it in CI.

## What the script calls

The sample is [examples/gateway-node-quickstart](https://github.com/phaseoteam/Phaseo/tree/main/examples/gateway-node-quickstart): one file, `index.mjs`, with no dependencies.

| Mode | Calls | Costs credits |
| --- | --- | --- |
| `npm run smoke` | `GET /v1/health`, `GET /v1/models` | No |
| `npm run start` | Both of the above, then `POST /v1/responses`, `POST /v1/chat/completions`, `POST /v1/embeddings` | Yes |

The text calls send `Return exactly: integration_ok` to `PHASEO_MODEL` (default `openai/gpt-5.6-sol`). The embeddings call uses `google/gemini-embedding-2`.

## Run it

You need Node.js 18 or newer, for the built-in `fetch`, and a Phaseo API key.

<Steps>
<Step title="Create .env.local">

The script loads `.env.local` from the folder you run it in, without any package. The sample has no `.env.example`, so create the file:

```bash .env.local
PHASEO_API_KEY=phaseo_v1_sk_...
# Optional
PHASEO_MODEL=openai/gpt-6-astra
PHASEO_BASE_URL=https://api.phaseo.app/v1
PHASEO_APP_TITLE=My smoke test
PHASEO_HTTP_REFERER=https://myapp.example
```

Variables already set in your shell win over the file.

</Step>
<Step title="Run the smoke mode">

```bash
cd examples/gateway-node-quickstart
npm run smoke
```

</Step>
<Step title="Run the full mode">

```bash
npm run start
```

</Step>
</Steps>

## Check it worked

Each call prints a block like this:

```text
=== Health ===
HTTP 200
{ ... }
```

- `Health` and `Models` show `HTTP 200`, and `Models` lists at least one model.
- In the full run, the Responses and Chat Completions blocks contain `integration_ok`.
- With a wrong key, the generation blocks show `HTTP 401` and the error body instead of being swallowed.
- The requests appear in **Settings → Usage → Logs**.

## Use it as a deploy check

`request()` returns `{ status, ok, payload }`, but nothing checks `ok`. Add one line at the top of `print()` so the script exits `1` when any call failed:

```js index.mjs
function print(title, result) {
  if (!result.ok) process.exitCode = 1;
  console.log(`\n=== ${title} ===`);
  // ...rest unchanged
}
```

Trim the script to the routes your service uses, and move to the [TypeScript SDK](../sdk-reference/client/overview) when you'd rather not build payloads by hand.
