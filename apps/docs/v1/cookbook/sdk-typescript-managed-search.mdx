Give one TypeScript request the `phaseo:web_search` tool and a JSON Schema, so the model searches before it answers and returns a brief with its sources. When you're done you have a script that prints a validated `{ summary, sources }` object plus the IDs and search counters you need to debug it.

The script is production-ready once you replace the preset and domain with your own. Search results are untrusted web content: validate the output and don't follow instructions found in it.

## Build it

<Steps>
<Step title="Create a preset">

Create `research-brief` in **Settings → Presets** with the model, provider preferences, reasoning settings and system prompt every caller should share. The model must support tools and JSON Schema output.

</Step>
<Step title="Install the SDK">

```bash
npm install @phaseo/sdk zod
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="Write the script">

```ts research-brief.ts
import Phaseo from "@phaseo/sdk";
import { z } from "zod";

const gateway = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const Brief = z
  .object({
    summary: z.string().min(1),
    sources: z
      .array(z.object({ title: z.string(), url: z.string().url() }).strict())
      .min(1),
  })
  .strict();

const response = await gateway.generateResponse({
  model: "@research-brief",
  input: "Find the latest public changes to Phaseo webhook delivery behavior and summarize them.",
  tools: [
    {
      type: "phaseo:web_search",
      parameters: {
        allowed_domains: ["phaseo.app"],
        max_results: 5,
        include_highlights: true,
      },
    },
  ],
  tool_choice: "phaseo:web_search",
  text: {
    format: {
      type: "json_schema",
      name: "research_brief",
      strict: true,
      schema: {
        type: "object",
        required: ["summary", "sources"],
        properties: {
          summary: { type: "string" },
          sources: {
            type: "array",
            minItems: 1,
            items: {
              type: "object",
              required: ["title", "url"],
              properties: {
                title: { type: "string" },
                url: { type: "string", format: "uri" },
              },
              additionalProperties: false,
            },
          },
        },
        additionalProperties: false,
      },
    },
  },
  plugins: [{ id: "response-healing" }],
  meta: true,
});

const text = (response.output ?? [])
  .filter((item) => item.type === "message")
  .flatMap((item) => item.content ?? [])
  .filter((part) => part.type === "output_text")
  .map((part) => part.text ?? "")
  .join("");

const brief = Brief.parse(JSON.parse(text));

console.log({
  responseId: response.id,
  model: response.model,
  routing: response.meta?.routing,
  pluginExecutions: response.meta?.plugin_executions,
  serverToolUse: response.usage?.server_tool_use,
});
console.log(brief);
```

| Field | Does |
| --- | --- |
| `tools` with `phaseo:web_search` | Phaseo runs the search, whether or not the provider has its own search. The model writes the query. |
| `allowed_domains` | Limits results to your own sources. Every parameter is in the [web search guide](../guides/server-tools/web-search#parameters). |
| `tool_choice: "phaseo:web_search"` | Makes the model search instead of answering from memory. |
| `text.format` | The JSON Schema for the answer. |
| `plugins` | Repairs near-valid JSON; see [response healing](./response-healing-for-structured-json). |
| `meta: true` | Adds `meta.routing` and `meta.plugin_executions`. |

</Step>
<Step title="Run it">

```bash
npx tsx research-brief.ts
```

</Step>
</Steps>

## Check it worked

- `serverToolUse.web_search_requests` is at least `1`, so the search ran.
- `brief.sources` lists `phaseo.app` URLs.
- `routing.selected_provider` names the provider, and `pluginExecutions` shows whether healing changed anything.
- In **Settings → Usage → Logs**, the request's **Web search observability** section shows the managed searches, results and citations.

If results look wrong, fix the preset or tool parameters from what the logs show rather than adding overrides. [Debug web search](./web-search-debugging) lists the common cases. Keep exploratory, higher-temperature research in a separate preset from this deterministic one, so their routing stays easy to compare.
