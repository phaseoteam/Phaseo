Call a dashboard preset from Python with a JSON Schema, then validate the answer and log the IDs you need to debug it. When you're done you have one script that sends `"model": "@release-summary"`, gets back `{"summary": ..., "risk_level": ...}`, and prints the provider and plugin details for that request.

The script is production-ready once you replace the preset and schema with your own. Keep the validation step: healing fixes syntax, not content.

## Build it

<Steps>
<Step title="Create the preset">

In **Settings → Presets**, create `release-summary` with the system prompt, model or allowed models, provider preferences, reasoning settings and `temperature` every caller should share. The Python code then only sends what varies. [Presets](../guides/presets) explains how the preset merges with the request.

</Step>
<Step title="Install the SDK">

```bash
pip install phaseo
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="Write the script">

```python release_summary.py
import json
import os

from phaseo import Phaseo

# Create one client and reuse it.
gateway = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

SCHEMA = {
    "type": "object",
    "properties": {
        "summary": {"type": "string"},
        "risk_level": {"type": "string", "enum": ["low", "medium", "high"]},
    },
    "required": ["summary", "risk_level"],
    "additionalProperties": False,
}


def output_text(response: dict) -> str:
    return "".join(
        part.get("text", "")
        for item in response.get("output", [])
        if item.get("type") == "message"
        for part in item.get("content", [])
        if part.get("type") == "output_text"
    )


def validate(payload: dict) -> dict:
    if set(payload) != {"summary", "risk_level"}:
        raise ValueError(f"unexpected keys: {sorted(payload)}")
    if not isinstance(payload["summary"], str) or not payload["summary"]:
        raise ValueError("summary must be a non-empty string")
    if payload["risk_level"] not in ("low", "medium", "high"):
        raise ValueError("risk_level must be low, medium or high")
    return payload


response = gateway.generate_response(
    {
        "model": "@release-summary",
        "input": "Summarize the last 24 hours of deployment activity.",
        "text": {
            "format": {
                "type": "json_schema",
                "name": "release_summary",
                "strict": True,
                "schema": SCHEMA,
            }
        },
        "plugins": [{"id": "response-healing"}],
        "meta": True,
    }
)

if response.get("status") != "completed":
    raise RuntimeError(f"response {response.get('id')} ended as {response.get('status')}")

payload = validate(json.loads(output_text(response)))
meta = response.get("meta", {})

print("response_id:", response.get("id"))
print("model:", response.get("model"))
print("selected_provider:", meta.get("routing", {}).get("selected_provider"))
print("plugin_executions:", meta.get("plugin_executions"))
print(payload)
```

| Field | Does |
| --- | --- |
| `"model": "@release-summary"` | Uses the preset. There is no separate `preset` field. |
| `text.format` | Asks for this JSON Schema. On Chat Completions it goes in `response_format`; see [Structured outputs](../guides/structured-outputs). |
| `plugins` | Repairs near-valid JSON; see [response healing](./response-healing-for-structured-json). |
| `meta: true` | Adds `meta.routing` and `meta.plugin_executions` to the response. |

</Step>
<Step title="Run it">

```bash
python release_summary.py
```

</Step>
</Steps>

## Check it worked

The script prints the response ID, the model and provider that answered, the plugin record, and a dict with `summary` and one of `low`, `medium` or `high`. Search for the response ID in **Settings → Usage → Logs** to see the same request with its routing details.

A model outside the preset's allowed models fails with `validation_error` (keyword `preset_model_not_allowed`). A `ValueError` from `validate()` means the JSON parsed but the content was wrong: tighten the schema or prompt rather than adding retries.

## Debug before you override

If a request routes differently from what you expected, open it in the logs, read **Routing observability** and the plugin record, and change the preset only once the logs show what happened. Piling inline overrides onto one request defeats the point of the preset; if one caller really needs different behaviour, give it its own preset.
