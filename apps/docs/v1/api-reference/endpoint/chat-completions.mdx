## Use server tools

Add a `phaseo:` tool to `tools` next to your own function tools, and Phaseo runs it when the model calls it. `/v1/chat/completions` accepts every server tool except `phaseo:apply_patch`; the [Server Tools](../../guides/server-tools) guide lists them.

```bash
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [
      { "role": "user", "content": "What is the current datetime in Europe/London?" }
    ],
    "tools": [
      { "type": "phaseo:datetime", "parameters": { "timezones": ["Europe/London"] } }
    ],
    "tool_choice": "auto"
  }'
```

Each server tool call is counted in `usage.server_tool_use`:

```json
{
  "usage": {
    "prompt_tokens": 12,
    "completion_tokens": 34,
    "total_tokens": 46,
    "server_tool_use": {
      "datetime_requests": 1
    }
  }
}
```

`phaseo:web_search` adds `web_search_requests`, `web_search_results` and `web_search_extra_results`; `phaseo:web_fetch` adds `web_fetch_requests`. The older `gateway:datetime` type still works.

With `stream: true`, Phaseo runs the tool turns itself, then streams the continued answer to you as a single stream.

## Reasoning in tool loops

Reasoning models return their reasoning on the assistant message in two fields:

- `reasoning_content`: the reasoning text, where the provider returns any.
- `reasoning_details`: an array of reasoning blocks. Each entry has a `type` of `reasoning.text`, `reasoning.summary` or `reasoning.encrypted`, an `index`, and a `format` naming the provider family, for example `anthropic-claude-v1` or `google-gemini-v1`.

Entries can carry provider state that the model needs on the next step of a tool loop:

| Provider state | Where it is |
| --- | --- |
| Claude thinking signatures | `signature` on `reasoning.text` entries |
| Claude redacted thinking, OpenAI encrypted reasoning | `data` on `reasoning.encrypted` entries |
| Gemini thought signatures | `data` on `reasoning.encrypted` entries whose `id` is the tool call they belong to |

When streaming, a `reasoning_details` delta arrives once each reasoning block is complete.

To keep the model's reasoning between steps, send the assistant message back with its `reasoning_details` unchanged. `signature` and `data` values are opaque and record the provider and model that produced them. Phaseo sends them only to that provider family and model, so a fallback to another provider drops them rather than failing. Claude models in manual thinking mode need their thinking back to keep thinking during a tool loop; if it is missing, that step runs without thinking.
