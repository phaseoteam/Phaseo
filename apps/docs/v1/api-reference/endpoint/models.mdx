Call `GET /v1/models` to list the models you can route to right now. Set `availability=all` to include models that are known but not currently available.

```bash
curl "https://api.phaseo.app/v1/models?limit=50" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

Each model lists one entry in `offers` per provider route (abridged, values illustrative):

```json
{
  "ok": true,
  "availability_mode": "active",
  "limit": 50,
  "offset": 0,
  "total": 412,
  "models": [
    {
      "id": "anthropic/claude-sonnet-5.5",
      "name": "Claude Sonnet 5.5",
      "organization": { "id": "anthropic", "name": "Anthropic", "color": "#d97757" },
      "lifecycle": { "status": "active", "released_at": "2026-09-28", "replacement_id": null },
      "modalities": { "input": ["text", "image"], "output": ["text"] },
      "capabilities": { "endpoints": ["chat.completions", "messages", "responses"] },
      "availability": { "status": "active", "provider_count": 3, "active_provider_count": 3 },
      "offers": [
        {
          "provider": { "id": "anthropic", "name": "Anthropic" },
          "model": "claude-sonnet-5-5",
          "status": "active",
          "status_reason": null,
          "routable": true,
          "service_tiers": ["standard"],
          "routing": { "provider": "active", "model": "active", "capability": "active" }
        }
      ]
    }
  ]
}
```

Only route production traffic to an offer whose `routable` is `true`. `status_reason` explains why an offer is preview-only or inactive. The full schema is below.

`GET /models/me` returns the same list with your key's guardrails applied: your workspace's privacy and provider rules, and the guardrails on the key's departments, its member and the key itself. Models a model rule blocks, and models with no provider you allow, are left out, and each model keeps only the offers its requests may be routed to. It takes the same filters as `GET /models`. The response also has `access`: whether any rule applies (`restricted`), the models they leave out (`hidden_model_count` and `hidden_models`, with ids and names) and how many listed models lost some providers (`limited_model_count`), so you can tell people why a model is missing.

## Filter the list

Filters that take several values accept repeated parameters or a comma-separated list.

| Parameter | Filters by |
| --- | --- |
| `availability` | `active` (default) for publicly routable models, or `all` to add `coming_soon`, `inactive` and not-yet-routable models and providers |
| `endpoints` | Public endpoint names, such as `chat.completions`, `responses` and `messages` |
| `status` | Model lifecycle, such as `active`, `deprecated` or `retired` |
| `organisation` | Model ID prefix, such as `anthropic` in `anthropic/claude-3-haiku` |
| `provider` | Public provider ID, such as `openai`, `anthropic` or `google_vertex` |
| `provider_status` | Provider rollout tier, such as `active`, `beta`, `alpha` or `not_ready` |
| `provider_routing_status` | Provider-level routing state |
| `model_routing_status` | Model-level routing state |
| `capability_status` | Provider capability state for the requested endpoint mapping |
| `provider_availability_status` | Provider-side availability, such as `active`, `coming_soon` or `inactive` |
| `provider_availability_reason` | Why a provider is unavailable, such as `preview_only`, `provider_not_ready`, `gated`, `access_limited` or `region_limited` |
| `input_types` (alias `input_modalities`) | Input modalities |
| `output_types` (alias `output_modalities`) | Output modalities |
| `params` (alias `supported_parameters`) | Supported request parameters |

To inspect one model's provider routes, parameter detail and pricing, call [`GET /models/{author}/{slug}/endpoints`](./model-endpoints.mdx).

## Check service tiers per offer

Each entry in `offers` includes `service_tiers`, the [service tiers](../../guides/service-tiers.mdx) that provider offer accepts. It is an alphabetically sorted subset of `flex`, `priority`, `standard` and `ultrafast`, where `priority` is the Fast tier. A tier is listed when the provider route has active, currently effective pricing for it, and a route that serves one tier lists just that tier. Some tiers are also available through separate tier-specific provider routes that are not listed. Prices under `pricing` remain standard-tier prices.

## Get the list in OpenAI format

Use `GET /v1/models?format=openai` for clients that expect OpenAI's model-list response. The default `format=json` returns Phaseo's richer model metadata.

```bash
curl "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

```json
{
  "object": "list",
  "data": [
    { "id": "openai/gpt-6-astra", "object": "model", "created": 1788393600, "owned_by": "openai" }
  ]
}
```

OpenAI format uses the same authentication, regional availability, workspace private models and filters as native JSON. It returns all matching models unless you supply `limit`; `offset` still applies. IDs stay in Phaseo's canonical form for inference. `created` uses the catalogue release date, or `0` when unknown; `owned_by` uses the catalogue organization, `private` for workspace models, or `phaseo` when unknown.

## Cache the model list

Catalogue responses are cached for five minutes and may be served for another five minutes while the cache revalidates. This applies to the JSON, RSS and Atom representations of the current catalogue; the release feed has its own shorter polling cache.

JSON and OpenAI-format responses include a weak `ETag` header (`W/"…"`). It changes when the models on the page, `limit`, `offset`, `total` or the format change. It ignores `gateway_region`, so the same catalogue served from another region has the same `ETag`. That is why it is weak: responses that share it are equivalent, but their bytes can differ. RSS, Atom and error responses don't include one.

Send the saved value back unchanged in `If-None-Match`. If the catalogue has not changed, the response is `304 Not Modified` with no body and repeats the `ETag`, `Cache-Control` and `Vary` headers. Otherwise you get a normal `200` with the new list and a new `ETag`. `If-None-Match` also accepts a comma-separated list and `*`, and the comparison is weak, so the value matches with or without its `W/` prefix.

```ts
let etag: string | null = null;
let models: unknown[] = [];

async function refreshModels() {
  const response = await fetch("https://api.phaseo.app/v1/models?limit=250", {
    headers: {
      Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
      ...(etag ? { "If-None-Match": etag } : {}),
    },
  });
  if (response.status === 304) return models; // Unchanged; a 304 has no body.
  if (!response.ok) throw new Error(`Model list request failed: ${response.status}`);
  etag = response.headers.get("ETag");
  models = (await response.json()).models;
  return models;
}
```

A `304` saves transfer and parsing. The server still evaluates the request: it loads the catalogue and recomputes the `ETag`. Polling about every 15 minutes is enough, downloading the list again only when the catalogue changes. Keep one `ETag` per request URL, because each page, filter set and format has its own value.
