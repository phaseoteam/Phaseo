By default, this endpoint only returns models that are currently routable. Set `availability=all` to include models that are known but not currently available.

Catalogue responses are cached for five minutes and may be served for another five minutes while the cache revalidates. This applies to the JSON, RSS, and Atom representations of the current catalogue; the release feed has its own shorter polling cache.

`GET /models/me` is reserved for future guardrail-aware filtering of models for the current caller. It currently returns `501 not implemented`, so use `GET /models` for the shared gateway catalogue today.

## OpenAI format

Use `GET /v1/models?format=openai` for clients that expect OpenAI's model-list response. The default `format=json` returns Phaseo's richer model metadata.

```bash
curl 'https://api.phaseo.app/v1/models?format=openai' \
  -H 'Authorization: Bearer YOUR_PHASEO_API_KEY'
```

```json
{
  "object": "list",
  "data": [
    { "id": "openai/gpt-4o-mini", "object": "model", "created": 1721260800, "owned_by": "openai" }
  ]
}
```

OpenAI format uses the same authentication, regional availability, workspace private models, and filters as native JSON. It returns all matching models unless you supply `limit`; `offset` still applies. IDs stay in Phaseo's canonical form for inference. `created` uses the catalogue release date, or `0` when unknown; `owned_by` uses the catalogue organization, `private` for workspace models, or `phaseo` when unknown.

## Caching the model list

JSON and OpenAI-format responses include a weak `ETag` header (`W/"…"`). It changes when the models on the page, `limit`, `offset`, `total`, or the format change. It ignores `gateway_region`, so the same catalogue served from another region has the same `ETag`. That is why it is weak: responses that share it are equivalent, but their bytes can differ. RSS, Atom, and error responses do not include one.

Send the saved value back unchanged in `If-None-Match`. If the catalogue has not changed, the response is `304 Not Modified` with no body and repeats the `ETag`, `Cache-Control`, and `Vary` headers. Otherwise you get a normal `200` with the new list and a new `ETag`. `If-None-Match` also accepts a comma-separated list and `*`, and the comparison is weak, so the value matches with or without its `W/` prefix.

```ts
let etag: string | null = null;
let models: unknown[] = [];

async function refreshModels() {
  const response = await fetch("https://api.phaseo.app/v1/models?limit=250", {
    headers: {
      Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
      ...(etag ? { "If-None-Match": etag } : {}),
    },
  });
  if (response.status === 304) return models; // Unchanged; a 304 has no body.
  if (!response.ok) throw new Error(`Model list request failed: ${response.status}`);
  etag = response.headers.get("ETag");
  models = (await response.json()).models;
  return models;
}
```

A `304` saves transfer and parsing, because it has no body. The server still evaluates the request: it loads the catalogue and recomputes the `ETag`. Polling about every 15 minutes is therefore appropriate, downloading the list again only when the catalogue changes. Keep one `ETag` per request URL, because each page, filter set, and format has its own value.

### Service tiers per offer

Each entry in `offers` includes `service_tiers`, the [service tiers](../../guides/service-tiers.mdx) that provider offer accepts. It is an alphabetically sorted subset of `flex`, `priority`, `standard`, and `ultrafast`, where `priority` is the Fast tier. A tier is listed when the provider route has active, currently effective pricing for it, and a route that serves one tier only lists just that tier. Some tiers may also be available through separate tier-specific provider routes that are not listed. Prices under `pricing` remain standard-tier prices.

## Useful filters

- `endpoints` uses public names like `chat.completions`, `responses`, and `messages`
- `status` filters by model lifecycle, for example `active`, `deprecated`, or `retired`
- `provider` filters by public provider ID, for example `openai`, `anthropic`, or `google_vertex`
- `provider_status` filters the provider rollout tier, for example `active`, `beta`, `alpha`, or `not_ready`
- `provider_routing_status` filters provider-level routing state
- `model_routing_status` filters model-level routing state
- `capability_status` filters provider capability state for the requested endpoint mapping
- `provider_availability_status` filters provider-side availability, for example `active`, `coming_soon`, or `inactive`
- `provider_availability_reason` filters provider-side availability reason, for example `preview_only`, `provider_not_ready`, `gated`, `access_limited`, or `region_limited`
- `organisation` filters by the public model ID prefix, for example `anthropic` in `anthropic/claude-3-haiku`
- `availability=active` is the default
- `availability=all` includes models or providers that are `coming_soon`, `inactive`, or not yet publicly routable
- `input_modalities` is an alias for `input_types`
- `output_modalities` is an alias for `output_types`
- `supported_parameters` is an alias for `params`

To inspect the endpoint contract for one model, call `GET /models/{author}/{slug}/endpoints`. The response separates provider routes and includes the public path, modalities, supported parameter detail, availability, routing state, provider model slug, and pricing summary for each row.

Provider entries can also include:

- `availability_status`
- `availability_reason`
- `provider_status`
- `provider_routing_status`
- `model_routing_status`
- `capability_status`
