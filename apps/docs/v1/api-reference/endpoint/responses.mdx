## Use server tools

Add a `phaseo:` tool to `tools` next to your own function tools, and Phaseo runs it when the model calls it. `/v1/responses` accepts every server tool, including `phaseo:apply_patch`, which only this endpoint supports; the [Server Tools](../../guides/server-tools) guide lists them.

```bash
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "input": [
      { "role": "user", "content": "Give me the current datetime in Asia/Tokyo." }
    ],
    "tools": [
      { "type": "phaseo:datetime", "parameters": { "timezones": ["Asia/Tokyo"] } }
    ],
    "tool_choice": "auto"
  }'
```

Each server tool call is counted in `usage.server_tool_use`:

| Tool | Counters |
| --- | --- |
| `phaseo:datetime` | `datetime_requests` |
| `phaseo:web_search` | `web_search_requests`, `web_search_results`, `web_search_extra_results` |
| `phaseo:web_fetch` | `web_fetch_requests` |
| `phaseo:advisor` | `advisor_requests` |
| `phaseo:subagent` | `subagent_requests` |
| `phaseo:fusion` | `fusion_requests` |
| `phaseo:search_models` | `search_models_requests` |
| `phaseo:image_generation` | `image_generation_requests` |
| `phaseo:apply_patch` | `apply_patch_requests` |

The older `gateway:datetime` type still works. With `stream: true`, Phaseo runs the tool turns itself, then streams the continued answer to you as a single stream.

## Reasoning in tool loops

On OpenAI, Azure OpenAI and xAI, Phaseo sends Responses requests upstream with `store: false`, so a model's reasoning continues between tool-loop steps only through the `reasoning` output items.

Each `reasoning` item has an `id`, `summary` and `content`. When the provider returns reasoning state, the item also has `encrypted_content`, which holds one of:

- OpenAI, Azure OpenAI and xAI encrypted reasoning. Phaseo requests it with `include: ["reasoning.encrypted_content"]` for reasoning models.
- Claude thinking signatures and redacted thinking.
- Gemini thought signatures, including a separate `reasoning` item placed just before the function call a signature belongs to.
- The effort level a Claude reply ran at, in the last `reasoning` item of the output, which has no text.

Streaming responses carry the same items on `response.output_item.done` and `response.completed`.

<Warning>
Send every output item back in `input` unchanged on every request, not only in tool loops. Never drop, edit or reorder `reasoning` items, with or without `encrypted_content`, including items with no text.
</Warning>

`encrypted_content` is opaque and records the provider and model that produced it. Phaseo sends it only to that provider family and model, so a fallback to another provider drops it rather than failing. Without it, Claude loses its reasoning between tool-loop steps, and a change of `reasoning.effort` restarts Claude's prompt cache; see [Change reasoning effort mid-conversation](../../guides/prompt-caching#change-reasoning-effort-mid-conversation).
