Call `GET /v1/generations?id=<request_id>` to fetch the stored audit record for a request in your workspace. It needs the `generations:read` scope; a missing `id` returns `400` `missing_id`.

New requests receive a server-generated `G-` generation ID, returned in the `x-request-id` response header and in the generation response. Use that ID for request logs, generation lookup and support. A caller-supplied `x-request-id` does not replace the generation ID. Older UUID log IDs still work for lookup.

## Replay a request

Every response includes `replay_supported`. When I/O logging stored the request body and you may read stored contents, `replay_supported` is `true` and `replay_request` holds the body to send back for a controlled rerun:

<Steps>
  <Step title="Read the generation">
    Call `GET /v1/generations?id=<request_id>`.
  </Step>
  <Step title="Check it can be replayed">
    Continue only if `replay_supported` is `true`.
  </Step>
  <Step title="Send it again">
    Send `replay_request` to the endpoint named in `endpoint`, such as `/v1/chat/completions` or `/v1/responses`.
  </Step>
</Steps>

A workspace can limit stored contents to owners and admins. Other callers, including API keys created by members, then get `replay_request: null` and request details without their contents.
