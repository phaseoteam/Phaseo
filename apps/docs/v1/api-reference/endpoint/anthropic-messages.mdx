Send an Anthropic Messages API payload to `/v1/messages` and get an Anthropic-formatted response back, for any model Phaseo routes. Anthropic tool-use fields are supported, and the `X-Phaseo-Strictness` header controls how unsupported parameters are handled.

Set `stream: true` to receive server-sent events in Anthropic format (`message_start`, `content_block_*`, `message_delta`, `message_stop`). Streaming also works in tool loops.

## Mid-conversation system messages

Add a `role: "system"` message to `messages` for an instruction that applies from that point in the conversation. The top-level `system` field stays the same, so a cached prefix still hits.

```bash
curl https://api.phaseo.app/v1/messages \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-opus-5.5",
    "max_tokens": 512,
    "system": "You are a code review assistant.",
    "messages": [
      { "role": "user", "content": "Review process() in utils.py." },
      { "role": "assistant", "content": "The loop is fine; the regex is compiled on every call." },
      { "role": "user", "content": "Now review the code that calls it." },
      { "role": "system", "content": "From now on, include type annotations in every suggestion." }
    ]
  }'
```

A system message takes a string or text blocks. It must come straight after a user turn (or an assistant turn ending in a server tool result) and be the last message or be followed by an assistant turn. Other positions return a `400`. `clear_at`, `output_config`, and `tool_addition` or `tool_removal` blocks are not supported.

| Model | How it receives the system message |
| --- | --- |
| Claude Fable 5 and 5.1, Mythos 5 and 5.1, Opus 4.8, Opus 5 and 5.5, Sonnet 5.5, Haiku 5.5 | In place |
| Other Claude models, including Sonnet 5, and every Claude model on Microsoft Foundry | Merged into the top-level system prompt |
| Models from other providers | As a system message, the same as one sent to Chat Completions |

## Use server tools

Add a `phaseo:` tool to `tools` and Phaseo runs it when the model calls it, rewriting it to Anthropic's tool format upstream and continuing the tool loop server-side. `/v1/messages` accepts every server tool except `phaseo:apply_patch`; the [Server Tools](../../guides/server-tools) guide lists them.

```bash
curl https://api.phaseo.app/v1/messages \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-sonnet-5.5",
    "max_tokens": 512,
    "messages": [
      { "role": "user", "content": "What time is it in America/New_York right now?" }
    ],
    "tools": [
      { "type": "phaseo:datetime", "parameters": { "timezones": ["America/New_York"] } }
    ],
    "tool_choice": { "type": "auto" }
  }'
```

Server tool calls are counted in `usage.server_tool_use`. The older `gateway:datetime` type still works. With `stream: true`, Phaseo runs the tool turns itself, then streams the continued answer to you as a single stream.

## Use Anthropic's native web search

When the routed Anthropic model and provider support native web search, pass Anthropic's tool definition directly, for example `type: "web_search_20250305"`. Provider routing still filters for `web_search_options` support before execution.

```bash
curl https://api.phaseo.app/v1/messages \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-sonnet-5.5",
    "max_tokens": 512,
    "messages": [
      { "role": "user", "content": "Find the latest Anthropic web search guidance." }
    ],
    "tools": [
      {
        "type": "web_search_20250305",
        "name": "web_search",
        "max_uses": 3,
        "allowed_domains": ["docs.anthropic.com"]
      }
    ],
    "tool_choice": { "type": "auto" }
  }'
```
