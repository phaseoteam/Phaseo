## Unsupported parameters

If the provider serving a request doesn't support one of its optional sampling parameters, Phaseo drops that parameter: it isn't sent upstream and the request isn't rejected, so clients that always send OpenAI defaults keep working.

Phaseo decides per provider, from its provider profile first and then the route's catalogue parameters. If a route declares no parameters, only the catalogue check is skipped; parameters the provider profile marks unsupported are still dropped, such as `top_k` on Cohere or `stop` on Reflection.

| Can be dropped | Never dropped |
| --- | --- |
| `temperature`, `top_p`, `top_k`, `min_p`, `repetition_penalty`, `frequency_penalty`, `presence_penalty`, `logit_bias`, `logprobs`, `top_logprobs`, `seed`, `stop` (`stop_sequences` on `/v1/messages`), `parallel_tool_calls`, `max_tool_calls`, `image_config`, and `context_management` from `/v1/messages` on non-Anthropic providers | Messages, `tools`, `tool_choice`, `response_format`, reasoning settings, output limits |

A prompt-cache `ttl` of `12h` is also removed on routes that can't take OpenAI's 12-hour cache, and reported as `prompt_cache_options.ttl` or `prompt_cache_breakpoint.ttl`; see [Prompt Caching](../guides/prompt-caching.mdx#12-hour-cache-on-openai).

Successful responses list the dropped parameters that the request body sent:

- in the `X-Phaseo-Dropped-Params` header, such as `X-Phaseo-Dropped-Params: top_k, min_p`;
- in `meta.routing.dropped_params` when the request sets `meta: true`, such as `[{"param": "top_k", "reason": "unsupported_by_provider"}]`.

A parameter that came from a preset or a default rather than the request body can be dropped without appearing in either place. It is still recorded in the routing diagnostics stored with the request.

## Choose the model

<span id="model"></span>
<h3 id="parameter-model"><code>model</code></h3>

The Phaseo model ID to run, such as `openai/gpt-6-astra`. Required. Use the ID shown in the quickstart on the model page; it is the safest choice for automation and long-lived integrations. A [preset](../guides/presets.mdx) name such as `@support-triage` also works here.

<span id="models"></span>
<h3 id="parameter-models"><code>models</code></h3>

Fallback models, tried in order after `model`. `model` is still required and always runs first. The next entry is tried only when an attempt fails with `429`, `500`, `502`, `503` or `504`.

**Type** `string[]` · **Entries** 1 to 25; duplicates and entries equal to `model` are ignored · **Example** `["anthropic/claude-sonnet-5.5", "google/gemini-4-argon"]`

- Each attempt is validated, logged and billed as its own request. The response `model` field and the routing trace show the model that answered.
- Streaming requests fall back only before the first byte; video and music jobs only at submission.
- Fallbacks on an attached dynamic route take precedence. Presets are accepted as entries. `phaseo/auto` can't be combined with `models`.
- Batch, realtime and council requests reject `models` with `400`.
- Multipart endpoints accept repeated `models` fields, `models[]` fields or one JSON array.

See [Request-level model fallbacks](../guides/routing-and-fallbacks#request-level-model-fallbacks).

<span id="stream"></span>
<h3 id="parameter-stream"><code>stream</code></h3>

Returns output over Server-Sent Events as it is generated, instead of one response body.

**Type** `boolean` · **Default** `false`

Use it for chat UIs and long responses. Leave it off when you want one JSON response that is simpler to retry and parse. Tool calls and structured output can stream differently by provider. See [Streaming](../guides/streaming.mdx).

## Sampling

<span id="temperature"></span>
<h3 id="parameter-temperature"><code>temperature</code></h3>

How random token selection is. Lower values give more conservative, repeatable output; higher values give more variety but less consistency and schema adherence.

**Type** `number` · **Range** `0`–`2` on Chat Completions and Responses, `0`–`1` on Messages · **Default** the provider's (Phaseo sends nothing when unset)

Start at `0.2`–`0.7`, and low for extraction, classification and JSON. Tune `temperature` or `top_p`, not both at once. A high temperature on a heavily quantized model can make output unstable.

<span id="top_p"></span>
<h3 id="parameter-top_p"><code>top_p</code></h3>

Nucleus sampling: the model picks from the smallest set of tokens whose combined probability reaches `top_p`. Lower values give narrower, more focused output.

**Type** `number` · **Range** `0`–`1` · **Default** the provider's

`0.9`–`1.0` with a moderate `temperature` is a reasonable baseline.

<span id="top_k"></span>
<h3 id="parameter-top_k"><code>top_k</code></h3>

Limits sampling to the k most likely tokens at each step. Lower values make output more predictable. Not every provider supports it.

**Type** `integer` · **Range** `-1` or more on Chat Completions, `0` or more on Messages · **Default** the provider's

<span id="min_p"></span>
<h3 id="parameter-min_p"><code>min_p</code></h3>

Narrows sampling by discarding tokens below a minimum probability threshold.

**Type** `number` · **Range** `0`–`1` · **Default** the provider's

<span id="frequency_penalty"></span>
<h3 id="parameter-frequency_penalty"><code>frequency_penalty</code></h3>

Penalises tokens in proportion to how often they have already appeared. Raise it when the model loops or repeats phrases.

**Type** `number` · **Range** `-2`–`2` · **Default** the provider's, usually `0`

<span id="presence_penalty"></span>
<h3 id="parameter-presence_penalty"><code>presence_penalty</code></h3>

Penalises any token that has already appeared, which pushes the model toward new topics and wording.

**Type** `number` · **Range** `-2`–`2` · **Default** the provider's, usually `0`

<span id="repetition_penalty"></span>
<h3 id="parameter-repetition_penalty"><code>repetition_penalty</code></h3>

A provider-specific anti-repetition control, separate from the two penalties above. Its exact effect varies more by provider.

**Type** `number` · **Range** more than `0`; providers often take up to `2` · **Default** the provider's

<span id="logit_bias"></span>
<h3 id="parameter-logit_bias"><code>logit_bias</code></h3>

Makes specific tokens more or less likely. Keys are token IDs for the model's tokenizer; values are the bias to add.

**Type** `object` (token ID to number) · **Default** unset

<span id="seed"></span>
<h3 id="parameter-seed"><code>seed</code></h3>

Requests seeded sampling, for debugging and regression tests. Identical output isn't guaranteed across providers or provider infrastructure changes.

**Type** `integer` · **Default** unset

## Output length and stopping

<span id="max_tokens"></span>
<h3 id="parameter-max_tokens"><code>max_tokens</code></h3>

Caps output tokens on Chat Completions, and is required on Messages. Use it to control cost and latency; too small a value cuts the output off.

**Type** `integer` · **Range** `1` or more (`0` or more on Messages) · **Default** the provider's on Chat Completions

<span id="max_output_tokens"></span>
<h3 id="parameter-max_output_tokens"><code>max_output_tokens</code></h3>

Caps output tokens on Responses. Same purpose as `max_tokens`; send the name your endpoint uses.

**Type** `integer` · **Range** `1` or more · **Default** the provider's

<span id="max_completion_tokens"></span>
<h3 id="parameter-max_completion_tokens"><code>max_completion_tokens</code></h3>

Caps output tokens on Chat Completions, the newer OpenAI name for `max_tokens`. Don't mix the two in one request.

**Type** `integer` · **Range** `1` or more · **Default** the provider's

<span id="stop"></span>
<h3 id="parameter-stop"><code>stop</code></h3>

One or more sequences that end generation, such as a template ending or a protocol marker. On Messages the field is `stop_sequences` and takes an array.

**Type** `string` or `string[]` · **Default** unset

## Token probabilities

<span id="logprobs"></span>
<h3 id="parameter-logprobs"><code>logprobs</code></h3>

Returns the log probability of each output token, for evaluation, ranking and confidence scoring.

**Type** `boolean` · **Default** `false`

<span id="top_logprobs"></span>
<h3 id="parameter-top_logprobs"><code>top_logprobs</code></h3>

Returns the most likely alternative tokens at each position, with their log probabilities. Needs `logprobs: true`.

**Type** `integer` · **Range** `0`–`20`

## Tools

<span id="tools"></span>
<h3 id="parameter-tools"><code>tools</code></h3>

The tools the model may call. Use the OpenAI tool schema unless the endpoint's reference says otherwise; Messages takes Anthropic's. Declaring a tool doesn't force the model to call it.

**Type** `array` · **Default** unset

<span id="tool_choice"></span>
<h3 id="parameter-tool_choice"><code>tool_choice</code></h3>

Whether the model may call tools: `none` for text only, `auto` to let the model decide, `required` to force a call, or an object naming one tool.

**Type** `string` or `object`

<span id="parallel_tool_calls"></span>
<h3 id="parameter-parallel_tool_calls"><code>parallel_tool_calls</code></h3>

Allows several tool calls in one turn. Set it to `false` when your tools must run one at a time, for example when they have ordered side effects.

**Type** `boolean` · **Default** the provider's (Phaseo sends nothing when unset)

<span id="max_tool_calls"></span>
<h3 id="parameter-max_tool_calls"><code>max_tool_calls</code></h3>

Caps how many tool calls the model makes for the request.

**Type** `integer` · **Range** `1` or more · **Default** unset

## Structured output

<span id="response_format"></span>
<h3 id="parameter-response_format"><code>response_format</code></h3>

Asks for plain text, JSON, or output that matches a JSON schema. The accepted shapes depend on the endpoint and provider.

**Type** `string` or `object` · **Default** the endpoint's and provider's

<span id="json_schema"></span>
<h3 id="parameter-json_schema"><code>json_schema</code></h3>

The JSON schema the output must match, set inside `response_format` (`{"type": "json_schema", "json_schema": {...}}`). Keep schemas narrow and task-specific for better adherence.

**Type** `object`

<span id="structured_outputs"></span>
<h3 id="parameter-structured_outputs"><code>structured_outputs</code></h3>

Not a request field. On a model page, it marks endpoints whose active providers support schema-constrained output. Request it with [`response_format`](#parameter-response_format).

## Reasoning

<span id="reasoning"></span>
<h3 id="parameter-reasoning"><code>reasoning</code></h3>

Configures reasoning on models that support it.

| Field | Values |
| --- | --- |
| `effort` | `none`, `instant`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max` (no `instant` on Messages) |
| `enabled` | `true` or `false` |
| `max_tokens` | Reasoning token budget, `0` or more |
| `summary` | `auto`, `concise`, `detailed` |
| `mode` | `standard`, `pro` (Chat Completions and Responses) |
| `context` | `auto`, `current_turn`, `all_turns` (Responses) |

Unset fields leave the model's default in place. Higher effort helps on hard problems and costs more latency and tokens.

<span id="reasoning_effort"></span>
<h3 id="parameter-reasoning_effort"><code>reasoning_effort</code></h3>

The Chat Completions shorthand for `reasoning.effort`.

**Type** `string` · **Values** `none`, `instant`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max` · **Default** the model's

<span id="reasoning_tokens"></span>
<h3 id="parameter-reasoning_tokens"><code>reasoning_tokens</code></h3>

Not a request field. On a model page it marks routes that report reasoning tokens or accept a reasoning budget. Set the budget with `reasoning.max_tokens`.

<span id="include_reasoning"></span>
<h3 id="parameter-include_reasoning"><code>include_reasoning</code></h3>

Accepted on Chat Completions for compatibility, and has no effect: reasoning content and summaries are returned whenever the model produces them. Reasoning output can be large and not every model returns it. To reduce it, lower `reasoning.effort` or set `reasoning.enabled` to `false`.

**Type** `boolean`

## Service tier and prompt caching

<span id="service_tier"></span>
<h3 id="parameter-service_tier"><code>service_tier</code></h3>

Chooses a speed and price tier on Chat Completions, Responses and Messages, when the model and provider support it. Phaseo maps each value to the provider's own control.

**Type** `string` · **Default** `standard`

| Value | Tier |
| --- | --- |
| `standard` (or omitted) | Standard. |
| `fast`, `priority` | Fast routing and pricing; the two are the same. |
| `ultrafast` | The fastest supported tier. |
| `flex` | Flex. |
| `auto` or `null` | No particular tier; treated as omitted. |
| `default`, `scale` | OpenAI's values, treated as `standard`. |
| `standard_only` | Anthropic's value on `/v1/messages`, treated as `standard`. |

`batch` isn't a tier and is rejected; use the [Batch API](./endpoint/batches-create.mdx). With an official Anthropic SDK pointed at Phaseo, prefer Anthropic's `auto` and `standard_only` on `/v1/messages`; for `ultrafast`, `priority`, `flex` or `fast`, use raw HTTP or Chat Completions and Responses. See [Service Tiers](../guides/service-tiers.mdx).

<span id="prompt_cache_key"></span>
<h3 id="parameter-prompt_cache_key"><code>prompt_cache_key</code></h3>

Keeps requests that share a prompt prefix, such as the steps of an agent loop, on the provider that holds their cache.

**Type** `string` · **Default** unset · **Endpoints** Chat Completions, Responses, Messages

Phaseo pins the key to the provider and route (deployment or region) that served the first successful request, and keeps later requests with the same key there until that provider fails, Phaseo's managed quota on it runs out, or your routing policy stops allowing it. Pins are per workspace and last as long as the provider's cache retention. See [Provider affinity](../guides/prompt-caching.mdx#provider-affinity).

Phaseo sends a hash of your workspace ID and key upstream, never the raw key, so two workspaces that choose the same key don't share a provider cache. Responses echo the key you sent. Providers whose API rejects the field don't receive it, and sending it never excludes a provider from routing. Without a key Phaseo derives affinity from the request, but an explicit key works better for long conversations and agent sessions.

<span id="prompt_cache_options"></span>
<h3 id="parameter-prompt_cache_options"><code>prompt_cache_options</code></h3>

Prompt-cache mode and lifetime for OpenAI and Azure OpenAI GPT-5.6 and later (including GPT-6 Astra), DeepInfra and Moonshot AI.

**Type** `object` · **Fields** `mode` (`implicit` or `explicit`), `ttl`

| Provider | `ttl` |
| --- | --- |
| OpenAI | `30m` (default) or `12h` on the Responses API. See [12-hour cache on OpenAI](../guides/prompt-caching.mdx#12-hour-cache-on-openai). |
| Azure OpenAI | `30m` |
| DeepInfra | `5m` or `1h`. Needs `prompt_cache_key` on every request in the session. |
| Moonshot AI | `5m`, or `1h` on Kimi K3. Takes `mode: "implicit"`. |

Use `{"mode": "explicit", "ttl": "30m"}` to have OpenAI cache only the breakpoints you place. A lifetime the route can't take, such as `12h` on Azure OpenAI or `1h` on a Moonshot AI model without a 1-hour price, is removed and listed in `X-Phaseo-Dropped-Params`. Every other provider, and OpenAI models before GPT-5.6, get no `prompt_cache_options`; those OpenAI models use [`prompt_cache_retention`](#parameter-prompt_cache_retention). `provider_options.openai.prompt_cache_options` is also accepted; the top-level value wins.

<span id="cache_control"></span>
<h3 id="parameter-cache_control"><code>cache_control</code></h3>

At the top level, sets a Claude prompt-cache policy. On a content block, tool definition or tool result, marks a cache breakpoint.

**Type** `object` · **Fields** `type`, `ttl`, `scope`

**Top level.** Accepted on Chat Completions, Responses and Messages. It applies to Claude on Anthropic, Claude on AWS, Amazon Bedrock and Google Vertex AI: Phaseo places up to four breakpoints according to `scope` (`all_text`, `last_user_message`, `agent` or `none`). Other providers ignore it. `provider_options.anthropic.cache_control` is the same setting and wins when both are sent.

**On a block.** Phaseo sends the breakpoint to Claude routes, Alibaba Model Studio and Venice, converts it to `prompt_cache_breakpoint` for OpenAI and Azure OpenAI GPT-5.6 and later, and removes it for other providers. OpenAI's own `prompt_cache_breakpoint: {"mode": "explicit"}` is accepted on the same blocks and wins when a block has both.

Use `type: "ephemeral"` with a `ttl` of `5m` (default) or `1h`. Anthropic accepts at most four breakpoints per request; when you mark more, Phaseo keeps the first and the latest three. See [Prompt Caching](../guides/prompt-caching.mdx#cache-controls).

<span id="prompt_cache_retention"></span>
<h3 id="parameter-prompt_cache_retention"><code>prompt_cache_retention</code></h3>

Prompt-cache retention on OpenAI and Azure OpenAI models before GPT-5.6.

**Type** `string` · **Values** `in_memory`, `24h`

Phaseo sends it only to those models, and only the models OpenAI lists accept `24h`. GPT-5.6 and later use [`prompt_cache_options.ttl`](#parameter-prompt_cache_options), and other providers don't receive the field. `provider_options.openai.prompt_cache_retention` is also accepted; the top-level value wins.

## Routing and provider settings

<span id="provider"></span>
<h3 id="parameter-provider"><code>provider</code></h3>

Restricts which providers can serve the request and how they are ranked. `routing` is accepted as an alias. See [Routing and Fallbacks](../guides/routing-and-fallbacks.mdx).

| Field | Type | Effect |
| --- | --- | --- |
| `order` | `string[]` | Preferred provider order. |
| `only` | `string[]` | Only these providers. |
| `ignore` | `string[]` | Never these providers. |
| `include_alpha` | `boolean` | Allow alpha providers. |
| `sort` | `string` or `object` | Rank providers, such as by `price`, `latency` or `throughput`. |
| `required_execution_region` | `string` | Run only in this region. |
| `required_data_region` | `string` | Handle data only in this region. |
| `require_zero_data_retention` | `boolean` | Only providers that meet zero data retention. |
| `max_price` | `object` | Ceilings for `prompt`, `completion`, `image`, `audio` or `request` cost. |
| `quantizations` | `string[]` | Only offers whose catalogue quantization matches one of these. |

`quantizations` matching ignores case, spaces, hyphens and underscores, and treats unambiguous names as aliases, such as `float8` and `FP8`, or `bfloat16` and `BF16`. Offers without quantization data are excluded whenever the filter is set. If no offer matches, the request fails with an error listing the requested and available quantizations rather than routing to a different variant.

<span id="provider_options"></span>
<h3 id="parameter-provider_options"><code>provider_options</code></h3>

Provider-native settings that Phaseo passes through, keyed by provider, while the rest of the request stays on the common schema.

**Type** `object`

| Key | Effect |
| --- | --- |
| `openai.context_management` | OpenAI compaction (`type: "compaction"`, optional `compact_threshold`). |
| `openai.prompt_cache_retention`, `openai.prompt_cache_options` | Same as the top-level fields; the top-level value wins. |
| `anthropic.cache_control` | Same as top-level `cache_control`; this one wins. |
| `google.cached_content` | An explicit Gemini cache (see below). |
| `xai.conversation_id` | xAI conversation ID. |

`google.cached_content` names an explicit Gemini cache and works only with your own credential: a Google API key on Google AI Studio, or a Vertex AI credential on Vertex AI. On Vertex AI, Phaseo sends the request to the project and location in the cache's full name (`projects/{project}/locations/{location}/cachedContents/{id}`); a short name uses the `project_id` and `region` in your service-account JSON. With Phaseo's credentials the request returns `400`. `google.cache_control` and `google.cache_ttl` are accepted but not sent to Google.

Prefer top-level `cache_control` for Claude, `prompt_cache_options` for OpenAI GPT-5.6 and later, and `prompt_cache_retention` for earlier OpenAI models. See [Prompt Caching](../guides/prompt-caching.mdx).

## Response extras and debugging

<span id="meta"></span>
<h3 id="parameter-meta"><code>meta</code></h3>

Adds a `meta` object to the response with routing details, such as `meta.routing.dropped_params`.

**Type** `boolean` · **Default** `false`

<span id="usage"></span>
<h3 id="parameter-usage"><code>usage</code></h3>

Requests usage accounting in the response body, rather than relying on headers or the dashboard.

**Type** `boolean` · **Default** unset

<span id="debug"></span>
<h3 id="parameter-debug"><code>debug</code></h3>

Returns routing traces and upstream payloads. Debug output can contain your request content, so use it only in development or tightly controlled environments. See [Debug a request](./errors.mdx#debug-a-request).

| Field | Type | Effect |
| --- | --- | --- |
| `enabled` | `boolean` | Turns debug mode on. |
| `return_upstream_request` | `boolean` | Includes the request Phaseo sent upstream. |
| `return_upstream_response` | `boolean` | Includes the upstream response, where available. |
| `trace` | `boolean` | Returns routing traces. |
| `trace_level` | `summary` or `full` | Trace detail. |

## Example request

```json
{
  "model": "openai/gpt-5.6-luna",
  "input": "Summarize this changelog.",
  "stream": false,
```
