Branch on `error.code` and the HTTP status, not on the message text. Every Phaseo error has the same JSON body on every endpoint, and its `error` object (`code`, `message`, `type`, `param`) is the shape OpenAI-compatible SDKs read, so their exceptions carry Phaseo's message.

```json
{
  "error": {
    "code": "upstream_error",
    "message": "Provider \"google-ai-studio\" failed with HTTP 403 for endpoint \"responses\" on model \"google/gemini-2.5-pro\".",
    "type": "server_error",
    "param": null,
    "metadata": {
      "reason": "all_candidates_failed",
      "attempt_count": 1,
      "failed_providers": ["google-ai-studio"],
      "failed_statuses": [403],
      "upstream_error": {
        "code": "PERMISSION_DENIED",
        "message": "The caller does not have permission.",
        "description": null,
        "param": null
      }
    }
  },
  "code": "upstream_error",
  "message": "Provider \"google-ai-studio\" failed with HTTP 403 for endpoint \"responses\" on model \"google/gemini-2.5-pro\".",
  "generation_id": "G-abc123",
  "status_code": 502,
  "error_type": "system",
  "error_origin": "upstream",
  "reason": "all_candidates_failed",
  "description": "Provider \"google-ai-studio\" failed with HTTP 403 for endpoint \"responses\" on model \"google/gemini-2.5-pro\".",
  "attempt_count": 1,
  "failed_providers": ["google-ai-studio"],
  "failed_statuses": [403],
  "provider_failure_diagnostics": {
    "category": "provider_access_missing",
    "hint": "The provider account appears not to have access to this model or feature yet. Verify account entitlements and provider-side access.",
    "provider": "google-ai-studio"
  },
  "upstream_error": {
    "code": "PERMISSION_DENIED",
    "message": "The caller does not have permission.",
    "description": null,
    "param": null
  },
  "failure_sample": [
    {
      "provider": "google-ai-studio",
      "type": "upstream_non_2xx",
      "status": 403,
      "upstream_error_code": "PERMISSION_DENIED",
      "upstream_error_message": "The caller does not have permission.",
      "upstream_error_description": null,
      "upstream_error_param": null,
      "upstream_payload_preview": "{\"error\":{\"status\":\"PERMISSION_DENIED\"}}",
      "retryable": false
    }
  ]
}
```

## Fields in every error

| Field | Contents |
| --- | --- |
| `error.code` | Machine-readable code, such as `validation_error`. See [Error codes](#error-codes). |
| `error.message` | Plain-language explanation. |
| `error.type` | Error class, set from the HTTP status. See [Error types](#error-types). |
| `error.param` | The request field that caused the error, when Phaseo knows it; otherwise `null`. |
| `error.metadata` | Optional. Structured detail such as `reason`, `failed_providers`, `failed_statuses` or `retry_after_seconds`. The same values are also at the top level. |
| `code` | Same as `error.code`. Older responses returned this string as `error`; read `code` if your client expects a string there. |
| `message`, `description` | Same text as `error.message`. |
| `generation_id` | Request ID to log and to share with support. |
| `status_code` | The HTTP status. |
| `error_type` | `user` or `system`. |
| `error_origin` | Where the problem came from: the caller (`user`), Phaseo (`gateway`) or a provider (`upstream`). |
| `details` | Optional. Validation details when the request body is invalid. |

Some errors add more context:

| Field | When it appears |
| --- | --- |
| `reason` | A specific subreason, such as `all_candidates_failed` or `no_provider_pricing`. |
| `provider_failure_diagnostics` | A provider was reached and failed. See [When a provider fails](#when-a-provider-fails). |
| `upstream_error`, `failure_sample` | A best-effort summary of the first provider failure. |
| `failed_providers`, `failed_statuses`, `attempt_count` | Which providers were tried and what they returned. |
| `provider_candidate_diagnostics`, `provider_enablement`, `routing_diagnostics` | No provider could serve the model on this endpoint. See [When a model or endpoint is not available](#when-a-model-or-endpoint-is-not-available). |

## Error types

`error.type` follows OpenAI's [documented error types](https://platform.openai.com/docs/guides/error-codes) and is set from the HTTP status:

| Status | `error.type` |
| --- | --- |
| `401` | `authentication_error` |
| `402` | `insufficient_quota` |
| `403` | `permission_error` |
| `404` | `not_found_error` |
| `429` | `rate_limit_error` |
| `408`, `500`, `502` and other 5xx | `server_error` |
| `503` | `service_unavailable` |
| `529` | `overloaded` |
| `400`, `409`, `410`, `413`, `422` and other 4xx | `invalid_request_error` |

Errors on `/v1/messages` use the same body, so Anthropic SDKs also find `error.type` and `error.message`.

## Error codes

| `error.code` | Status | Meaning | What to do |
| --- | --- | --- | --- |
| `validation_error` | `400` | A parameter or the request body is invalid. `error.param` names the first invalid field. | Fix the request. |
| `invalid_json` | `400` | The body is not valid JSON. | Fix the request. |
| `model_required` | `400` | The request has no `model`. | Add `model`. |
| `unsupported_model_or_endpoint` | `400` | No provider can serve this model on this endpoint. | See [below](#when-a-model-or-endpoint-is-not-available). |
| `unsupported_modalities` | `400` | No route accepts the input or output types in the request. | Change the model or the inputs. |
| `byok_credentials_required` | `400` | The route only runs with your own provider key. | Add an eligible [provider key](./endpoint/provider-credentials-create.mdx). |
| `upstream_error` | `400`, `413` or `422` | Every provider rejected the request with the same status (reason `upstream_rejected_request`). | Fix the request; retrying won't help. |
| `unauthorised` | `401` | The key is missing or invalid. `reason` says why. | Check the `Authorization` header. |
| `insufficient_funds` | `402` | The workspace doesn't have enough credits. | Add credits. |
| `pricing_not_configured` | `402` | No provider for this model has pricing (reason `no_provider_pricing`). | Choose another model. |
| `guardrail_blocked` | `403` | A guardrail or access policy blocked the request. | Change the request or the guardrail. |
| `model_region_unavailable` | `403` | No provider serves the model in the required region, or from the caller's location. | Relax the region requirement or choose another model. |
| `not_found` | `404` | The endpoint or resource doesn't exist. | Check the path and ID. |
| `not_ready` | `409` | A job's results aren't ready yet. | Poll the job's status. |
| `model_retired` | `410` | The model is retired and no provider serves it. | Switch to `replacement_model`. See [below](#when-a-model-is-retired). |
| `payload_too_large` | `413` | The body is larger than the endpoint accepts. `max_bytes` gives the limit. | Send a smaller body or upload a file. |
| `key_limit_exceeded` | `429` | A key limit, budget or the per-minute gateway limit was reached. | See [Rate Limits](./limits.mdx#key-limits-and-budgets). |
| `phaseo_free_model_limit_exceeded` | `429` | The daily free-model allowance (1,500 requests by default) is used up. | Honor `Retry-After`, wait for the 00:00 UTC reset, or use a paid model. |
| `rate_limit_exceeded` | `429` | A workspace [rate limit policy](./limits.mdx#rate-limit-policies) is exhausted. `policy_id` and `limit_scope` identify it. | Honor `Retry-After`, or ask an admin to change the policy. |
| `spend_rule_blocked` | `429` | A [spend rule](../guides/spend-alerts.mdx) set to block is active. | Honor `Retry-After`, or ask an owner or admin to lift the block. |
| `upstream_error` | `429` | Every provider tried rate limited the request. | Honor `Retry-After`. BYOK requests also carry `X-Phaseo-Upstream-RateLimit-*` headers. |
| `provider_capacity_exhausted` | `429` | Every eligible provider is at capacity (reason `all_candidates_rate_limited`). | Honor `Retry-After` when present, otherwise back off. |
| `gateway_error` | `500` | Something failed inside Phaseo. | Retry with backoff. |
| `not_implemented_yet` | `501` | The operation isn't available yet. | Don't retry. |
| `upstream_error` | `502` | The provider failed to respond correctly. | Retry with backoff. |
| `upstream_stream_failure` | `502` | A non-streaming request whose provider failed after it started generating. No partial output is returned and the request isn't charged. | Retry. |
| `provider_payment_required` | `502` | Phaseo's account with the provider needs attention. | Retry later or report it. |

## Retry the right errors

| Status | Retry? |
| --- | --- |
| `400`–`499` except `429` | No. Fix the request, key or access first. |
| `429` | Yes. Wait for `Retry-After` (seconds or an HTTP date), otherwise use exponential backoff with jitter. A `key_limit_exceeded` error without `Retry-After` doesn't reset by itself, so don't retry it. |
| `500`–`599` | Only when repeating the operation is safe. An ambiguous submission may already have created a job or a charge; look up an accepted job instead of submitting it again. |

Set an attempt limit and an overall deadline. See [Rate Limits](./limits.mdx) for the rate limit headers.

## When a provider fails

When Phaseo reached a provider and the request still failed, `provider_failure_diagnostics` has a `category`, a `hint` and the `provider`. Categories:

| `category` | Meaning |
| --- | --- |
| `credentials_not_configured` | No credential is set up for this route. |
| `credentials_invalid_or_forbidden` | The credential was rejected. |
| `provider_access_missing` | The provider account doesn't have access to the model or feature. |
| `region_or_project_restriction` | The provider refused because of the region or project. |
| `model_unavailable_for_endpoint` | The provider doesn't expose the model on this endpoint. |
| `rate_limited` | The provider rate limited the request. |
| `server_error` | The provider failed or timed out. |

## When a model or endpoint is not available

`unsupported_model_or_endpoint` errors can include `provider_candidate_diagnostics`, `provider_enablement`, `missing_pricing_providers` and `routing_diagnostics`. Together they tell apart a model that isn't active yet, a model that doesn't support the endpoint, missing pricing, and rollout restrictions.

| Field | Meaning |
| --- | --- |
| `provider_candidate_diagnostics.totalProviders` | Providers known for the model before endpoint filtering. |
| `provider_candidate_diagnostics.supportsEndpointCount` | Providers that support the requested endpoint. |
| `provider_candidate_diagnostics.candidateCount` | Providers left after adapter checks. |
| `provider_candidate_diagnostics.droppedUnsupportedEndpoint` | Providers dropped because they don't support the endpoint. |
| `provider_candidate_diagnostics.droppedMissingAdapter` | Provider and endpoint pairs dropped because Phaseo has no adapter for that endpoint yet. |
| `provider_enablement.capability` | The capability being enforced, such as `video_generation`. |
| `provider_enablement.providersBefore`, `providersAfter` | Providers before and after capability filtering. |
| `provider_enablement.dropped[].reason` | Why a provider was dropped, such as `pricing_missing`. |
| `routing_diagnostics.filterStages[].stage` | A routing stage, such as capability, rollout or routing-status filtering. |
| `routing_diagnostics.filterStages[].beforeCount`, `afterCount` | Providers before and after that stage. |
| `routing_diagnostics.filterStages[].droppedProviders[].reason` | Why a provider was dropped at that stage. |

```json
{
  "error": {
    "code": "unsupported_model_or_endpoint",
    "message": "No provider is currently routable for endpoint \"responses\" on model \"example/model\".",
    "type": "invalid_request_error",
    "param": null
  },
  "code": "unsupported_model_or_endpoint",
  "generation_id": "G-unsupported123",
  "status_code": 400,
  "description": "No provider is currently routable for endpoint \"responses\" on model \"example/model\".",
  "provider_candidate_diagnostics": {
    "totalProviders": 3,
    "supportsEndpointCount": 2,
    "candidateCount": 1,
    "droppedUnsupportedEndpoint": ["provider-a"],
    "droppedMissingAdapter": [
      {
        "providerId": "provider-b",
        "endpoint": "responses"
      }
    ]
  },
  "provider_enablement": {
    "capability": "responses",
    "providersBefore": ["provider-b", "provider-c"],
    "providersAfter": ["provider-c"],
    "dropped": [
      {
        "providerId": "provider-b",
        "reason": "pricing_missing"
      }
    ]
  },
  "routing_diagnostics": {
    "filterStages": [
      {
        "stage": "provider_routing_status",
        "beforeCount": 1,
        "afterCount": 0,
        "droppedProviders": [
          {
            "providerId": "provider-c",
            "reason": "provider_status_not_ready"
          }
        ]
      }
    ]
  }
}
```

## When a model is retired

A retired model is still served while any provider serves it. Once none does, requests fail with `410` and `model_retired`:

```json
{
  "error": {
    "code": "model_retired",
    "message": "Model \"lab/old-model\" was retired on 2026-09-30 and no provider serves it any more. Use \"lab/new-model\" instead.",
    "type": "invalid_request_error",
    "param": null,
    "metadata": {
      "retired_at": "2026-09-30T00:00:00Z",
      "replacement_model": "lab/new-model"
    }
  },
  "code": "model_retired",
  "generation_id": "G-retired123",
  "status_code": 410,
  "reason": "model_retired_without_providers",
  "description": "Model \"lab/old-model\" was retired on 2026-09-30 and no provider serves it any more. Use \"lab/new-model\" instead.",
  "model": "lab/old-model",
  "retired_at": "2026-09-30T00:00:00Z",
  "replacement_model": "lab/new-model"
}
```

`model` is the model you asked for, `retired_at` is when it was retired (or `null`), and `replacement_model` is the suggested replacement (or `null`).

Retrying doesn't help; change the model ID. To keep these requests working while you migrate, add the replacement to the request's `models` list or turn on retired model routing for the workspace. See [Model Deprecation and Retirement](../guides/model-retirement.mdx).

## Errors during a stream

If a request fails before streaming starts, you get the JSON error body above. If it fails mid-stream, the stream ends with the endpoint's failure event instead of a normal finish:

| Endpoint | Failure event |
| --- | --- |
| Chat Completions | An `error` frame |
| Responses | `response.failed` (or `error`) |
| Messages | An `error` event |

Treat the partial output as incomplete and offer a retry. The Chat Completions `error` frame carries the same error object, with `error.type` set from the code:

```json
{
  "object": "error",
  "message": "The upstream stream ended before the response completed.",
  "code": "upstream_stream_failure",
  "error": {
    "code": "upstream_stream_failure",
    "message": "The upstream stream ended before the response completed.",
    "type": "server_error",
    "param": null
  }
}
```

A non-streaming request whose provider fails part-way returns `502` with `upstream_stream_failure`, not a partial response. See [Streaming](../guides/streaming.mdx).

## Debug a request

Send a `debug` object to get routing traces and the upstream payloads:

```json
{
  "debug": {
    "enabled": true,
    "return_upstream_request": true,
    "return_upstream_response": false,
    "trace": true,
    "trace_level": "summary"
  }
}
```

`trace_level` is `summary` or `full`. Debug payloads can contain your request content, so use them only in development or tightly controlled environments. See [`debug`](./parameters.mdx#parameter-debug).

When a request fails, check the [status page](https://status.phaseo.app) for incidents, compare your payload with the endpoint's reference page, and log `generation_id` with the endpoint and model. Include `generation_id` when you contact [support](https://phaseo.app/help).

<Visibility for="agents">
Error-handling rules for agents, summarising this page:

- Branch on `error.code` (also returned as top-level `code`), `error.type` and `status_code`, not on the message text. Log `generation_id` with every failure.
- `400`, `401`, `403` and `404`: fix the request, key or access first. Do not retry the same request unchanged.
- `410` with `model_retired`: switch to `replacement_model` when it is not `null`; otherwise choose a new model from `GET /v1/models`.
- `429`: when `Retry-After` is present (seconds or an HTTP date), wait that long before retrying; otherwise use jittered exponential backoff. A `key_limit_exceeded` error without `Retry-After` does not reset by itself, so do not retry it.
- `500` to `599`: retry only when repeating the call is safe, with an attempt limit, an overall deadline and jittered exponential backoff. For async jobs, look up the accepted job instead of submitting it again.
- Treat debug payloads as sensitive and redact them before writing persistent logs.
- For tested retry and error-parsing patterns, install the `phaseo-gateway` skill: `npx skills add https://phaseo.app/docs --skill phaseo-gateway`.
</Visibility>
