---
title: 管理 API キー
description: Phaseo コントロールプレーン API 用に、権限を絞った管理キーを作成します。
icon: "key-round"
---

管理キーを作成すると、自社サーバーから Phaseo の管理 API（クレジット、アクティビティ、ワークスペース、キー、プリセット、設定、ガードレール）を呼び出せます。管理キーで推論リクエストを送ることはできません。

```bash
phaseo management-keys create --name <name> --template read-only --json
```

ダッシュボードの **設定 → 管理用キー** でも作成できます。シークレットは一度しか表示されないため、シークレットマネージャーに保存してください。送信はサーバー側のコードからのみ行い、送信先は Gateway と同じベース URL（`https://api.phaseo.app/v1`）です。

```http
Authorization: Bearer phaseo_v1_mk_<kid>_<secret>
```

## 管理キー、API キー、OAuth トークン

| 認証情報 | 形式 | 用途 | 制限するもの |
| --- | --- | --- | --- |
| Gateway API キー | `phaseo_v1_sk_<kid>_<secret>` | モデルおよび生成リクエスト | ルーティングポリシー、予算、制限、適用済みのガードレール |
| 管理 API キー | `phaseo_v1_mk_<kid>_<secret>` | 管理リクエスト | キーの機能とワークスペースでのロール |
| OAuth アクセストークン | | ユーザーに代わって行う管理操作 | 承認済みの OAuth スコープとユーザーのワークスペースでのロール |

管理ルートが受け付けるのは管理キー（または OAuth トークン）のみです。Gateway API キーでは呼び出せません。

[ガードレール](../cookbook/guardrails-for-api-keys.mdx)は別の制御です。Gateway API キーに適用され、ルーティング制限、予算、プロンプトインジェクションへの対処、機密情報のルールなど、推論トラフィックを管理します。管理キーの機能は、そのキーが呼び出せる管理 API を決めます。

## アクセスレベルを選ぶ

各テンプレートは、キーの作成時に明示的な機能のリストに展開されます。Phaseo は `all` のようなワイルドカードを保存しないため、後から追加された権限をキーが得ることはありません。

| テンプレート | `--template` | 付与される機能 |
| --- | --- | --- |
| **読み取り** | `read-only` | 現在のすべての `*:read` 機能 |
| **書き込み** | `read-write` | 現在のすべての `*:read` と `*:write` 機能（削除なし） |
| **すべて** | `full-control` | 現在のすべての読み取り、書き込み、削除機能 |

クレジットのチャージを開始する `billing:write` はどのテンプレートにも含まれません。必要な場合は `--scopes` で明示的に指定してください。**すべて** は信頼できる管理用の自動化にのみ使ってください。

付与範囲をさらに絞るには、必要な機能を `--scopes scope_a,scope_b` で指定します。

| 領域 | 読み取り | 書き込み | 削除 |
| --- | --- | --- | --- |
| アイデンティティとカタログ | `me:read`, `models:read`, `providers:read`, `pricing:read` | | |
| 使用量とオブザーバビリティ | `credits:read`, `activity:read`, `analytics:read`, `generations:read`, `feedback:read` | `feedback:write` | |
| 請求 | | `billing:write`（オプトイン） | |
| ワークスペース | `workspaces:read` | `workspaces:write` | `workspaces:delete` |
| Gateway API キー | `keys:read` | `keys:write` | `keys:delete` |
| 管理 API キー | `management_keys:read` | `management_keys:write` | `management_keys:delete` |
| プリセット | `presets:read` | `presets:write` | `presets:delete` |
| 設定 | `settings:read` | `settings:write` | |
| プロバイダーの認証情報 | `provider_credentials:read` | `provider_credentials:write` | `provider_credentials:delete` |
| プライベートモデル | `private_models:read` | `private_models:write` | `private_models:delete` |
| ガードレール | `guardrails:read` | `guardrails:write` | `guardrails:delete` |
| 予算 | `budgets:read` | `budgets:write` | `budgets:delete` |
| レート制限 | `rate_limits:read` | `rate_limits:write` | `rate_limits:delete` |
| 分類器 | `classifiers:read` | `classifiers:write` | `classifiers:delete` |
| 支出ルール | `spend_rules:read` | `spend_rules:write` | `spend_rules:delete` |
| OAuth クライアント | `oauth_clients:read` | `oauth_clients:write` | `oauth_clients:delete` |

## 機能はワークスペースのロールに優先しない

Phaseo は呼び出しのたびに 2 つの点を確認します。キーがその機能を持っていること、そしてキーまたは OAuth ユーザーが、その操作に必要なロールでワークスペースに所属していることです。たとえば `keys:write` があればキー管理が許可されますが、呼び出し元がそのワークスペースでキーを管理できるかどうかは、引き続きロールのチェックで決まります。機能を使って別のワークスペースにアクセスしたり、オーナーや管理者のチェックを回避したりすることはできません。

## キーを安全に保つ

- 管理キーをブラウザー、デスクトップのログ、ソース管理、チャットに含めないでください。
- 連携ごとに 1 つのキーを使い、動作する範囲で最も狭いテンプレートを選んでください。
- 無期限のアクセスが不要な連携には有効期限を設定してください。
- 使っていないキーはすぐに一時停止するか削除してください。
- キーが漏えいした場合は、調査を進める前にローテーションしてください。
