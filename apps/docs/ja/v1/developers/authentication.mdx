認証済みリクエストの送信方法や、キーの保管・ローテーション方法を確認できます。

Phaseo Gateway は Bearer トークンを使用します。すべての API リクエストに、ワークスペースの有効なキーを含めてください。

---

## キーの種類

- **Gateway API キー**は、ワークスペースで利用可能なモデル、プロバイダー、生成エンドポイントを呼び出します。
- **管理 API キー**は、管理用 API を呼び出します。[管理 API キー](./management-api-keys.mdx)を参照してください。
- **ローテーションしたキー**はいつでも作成できます。古いキーを削除する前に、アプリで新しいキーに切り替えてください。

キーの形式は `phaseo_v1_sk_<kid>_<secret>` です。 パスワードと同じように扱い、クライアント側のコードや公開リポジトリに保存しないでください。

<Note>
クレジットを入金せずに `:free` モデルを呼び出せます。有料モデルにはウォレット残高が必要です。
</Note>

---

## ヘッダー形式

すべてのリクエストの `Authorization` ヘッダーにキーを含めます。

```http
Authorization: Bearer phaseo_v1_sk_<kid>_<secret>
```

ほとんどの HTTP クライアントでは、この設定を一度だけ行えます。`fetch` の例：

```ts
const response = await fetch("https://api.phaseo.app/v1/chat/completions", {
	method: "POST",
	headers: {
		Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
		"Content-Type": "application/json",
	},
	body: JSON.stringify({
		model: "gpt-5-nano-2025-08-07",
		messages: [
			{ role: "system", content: "You are a helpful assistant." },
			{
				role: "user",
				content: "Summarize the drawbacks to AI.",
			},
		],
	}),
});
```

## キー管理のチェックリスト

| 実践方法            | 理由                                                           |
| ------------------- | ------------------------------------------------------------------------ |
| アプリごとにキーを分ける | ほかのサービスに影響を与えずにキーをローテーションできます。                |
| キーを安全に保管する | シークレットマネージャーを使えば、ログやエラー追跡ツールへの誤った流出を防げます。  |
| 使用状況を監視する       | ダッシュボードではキーごとの指標を確認できるため、異常をすばやく検知できます。 |
| 使っていないキーを削除する  | 古いキーを削除すると、悪用される可能性のある範囲を小さくできます。        |

---

## よくある認証エラー

- **401 認証されていません**：キーがないか無効であるか、無効化されたワークスペースに属しています。
- **403 禁止されています**：キーは存在しますが、要求されたプロバイダーまたはモデルにアクセスできません。
- **429 リクエストが多すぎます**：キーまたはワークスペースが上限を超えました。[レート制限](./rate-limits.mdx)を参照してください。
- **5xx エラー**：指数バックオフで再試行し、問題が続く場合は[サポート](https://phaseo.app/help)にお問い合わせください。
