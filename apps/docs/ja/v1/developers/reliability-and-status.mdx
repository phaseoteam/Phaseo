Phaseoが正常か、モデルを今ルーティングできるか、ルートがアプリケーションの信頼性目標を満たすかを確認する際に、このガイドを使います。

## 現在のサービス状態を確認する

1. [Phaseoのステータスページ](https://status.phaseo.app)を開き、現在のインシデントと過去の履歴を確認します。
2. 次を呼び出します: `GET /v1/health` Gatewayの簡易ヘルスチェックを行います。
3. リクエストが1件失敗した場合は、サービス全体が停止したと判断する前に、request IDを控えてアクティビティまたは生成レコードを確認します。

```bash
curl https://api.phaseo.app/v1/health
```

```json
{
  "status": "ok"
}
```

<Note>
公開ステータスページではサービスの稼働状況を確認できます。Phaseoは現在、契約上の公開稼働率SLAを提示していません。
</Note>

## モデルがルーティング可能か確認する

PhaseoのカタログはGatewayから利用できるモデルより広い範囲を扱います。カタログにあることはPhaseoがモデルを追跡していることを示すだけで、公開ルートが存在するとは限りません。

`GET /v1/models` デフォルトでは、現在ルーティング可能なモデルのみを返します。

```bash
curl https://api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

`availability=all` は、近日公開または無効なマッピングを意図的に確認する場合にのみ使用します。`availability_status` が `active` かつ `is_active_gateway` が `true` でない限り、プロバイダー行に本番トラフィックを送信しないでください。

| 状態 | 意味 |
| --- | --- |
| `active` | 現在、少なくとも1つの公開Gatewayルートを利用できます。 |
| `coming_soon` | Phaseoが予定中またはプレビュー中のルートとして追跡していますが、公開ルーティングには対応していません。 |
| `inactive` | 既知のルートが無効、利用不可、期限切れ、またはその他の理由でルーティングできません。 |
| `not_listed` | このモデルに対応するGatewayプロバイダーマッピングは現在登録されていません。 |

利用可能であることは、継続的な稼働、すべてのリージョンからのアクセス、全ワークスペースで同一の商用条件を保証するものではありません。

## パフォーマンス指標を読み解く

Phaseoのパフォーマンスデータは観測データです。管理されたラボのベンチマークではなく、Gatewayを経由したリクエストを集計しています。

| 指標 | 定義 |
| --- | --- |
| Gateway TTFT | Gatewayリクエストの開始から、内容を含む最初の生成出力までの時間。 |
| Provider TTFT | プロバイダーへの送信から、内容を含む最初の生成出力までの時間。 |
| プロバイダー所要時間 | プロバイダーへの送信から最終レスポンスまでの時間。 |
| Gateway E2E | Gatewayリクエストの開始から完了までの時間。 |
| Phaseoのオーバーヘッド | Gateway E2Eとプロバイダー所要時間の差（0以上）。 |
| 実効スループット | すべての出力トークン数をプロバイダーの全所要時間で割った値。 |
| 出力速度 | 最初のトークン以降の出力トークン数をTTFT後のプロバイダー時間で割った値。 |

TTFTと出力速度の測定には、最初の出力が内容を含むストリーミングレスポンスが必要です。非ストリーミングのリクエストでも、TTFTを作り出さずに所要時間と実効スループットの測定に利用できます。

指標は必ず時間範囲、ルート、リージョン、ストリーミングモード、パーセンタイルと合わせて確認します。プロバイダーの負荷、プロンプトや出力の長さ、再試行、転送条件によって結果が変わります。

詳しい定義は次を参照してください: [料金とパフォーマンス](../exploring/pricing-performance.mdx) と[Phaseoによるレイテンシとスループットの測定方法](https://phaseo.app/how-phaseo-measures-latency-throughput).

## 実際のワークロードで検証する

公開テレメトリーは傾向を示す参考情報であり、ルートが本番目標を満たす証明ではありません。展開前に、小規模で再現可能な調査を行います。

1. 機密性の高い本番データを取り除き、代表的なプロンプト構成を残します。
2. モデルID、エンドポイント、プロバイダー制約、リージョン、ストリーミングモード、並行数を記録します。
3. 1回のリクエストではなく分布を比較できる回数だけ実行します。
4. 成功率、Gateway TTFT、プロバイダー所要時間、Gateway E2E、出力トークン数、最終コストを記録します。
5. 無効なキーやモデル、レート制限、プロバイダー利用不可時の失敗をテストします。
6. 他のエンジニアが結果を再現できるよう、リクエストIDと正確な時間範囲を保存します。

許可と文書化された方法がない限り、顧客名、引用、ワークロード結果、信頼性の割合を公開しないでください。

## 失敗したリクエストを調査する

- [サービスのステータス](https://status.phaseo.app)を確認します。
- `GET /v1/models` のデフォルトレスポンスにモデルが引き続き表示されることを確認します。
- HTTPステータスとエラーコードを確認します: [エラー処理](../api-reference/errors.mdx).
- 一時的な `429` と `5xx` エラーは、上限付きの指数バックオフで再試行します。
- [サポート](https://phaseo.app/help)に問い合わせる際は、リクエストIDを控えてください。
