SDK の一覧メソッドを呼び出すと、`GET /v1/models` からモデルカタログを読み取れます。フィルターは省略可能です。

<CodeGroup>

```typescript TypeScript

  provider: ["anthropic"],
  provider_status: ["beta", "not_ready"],
  provider_availability_reason: ["preview_only", "provider_not_ready"],
  capability_status: ["coming_soon", "internal_testing"],
  availability: "all",
});
```

## 一覧を絞り込む

フィルターはすべて省略可能で、どの SDK でも同じ名前です。これらはクエリパラメーターです。

| フィルター | 絞り込みの対象 |
| --- | --- |
| `provider`、`organisation` | プロバイダーまたはモデルの組織 |
| `endpoints`、`input_types`、`output_types`、`params` | 対応するエンドポイント、モダリティ、リクエストパラメーター |
| `status`、`provider_status`、`provider_routing_status`、`model_routing_status`、`capability_status`、`provider_availability_status`、`provider_availability_reason` | ライフサイクルとルーティングの状態 |
| `availability` | `all` に設定すると、ルーティングできないモデルも含めます |
| `limit`、`offset` | ページング |

デフォルトでは、一覧にはルーティング可能なモデルだけが含まれます。`availability` を `all` に設定して残りも含め、そのうえで絞り込みます。

- `provider_availability_reason` は、`preview_only`、`provider_not_ready`、`gated`、`access_limited`、`region_limited`、`project_limited`、`paused`、`soft_blocked` などの展開状態を選びます。
- `capability_status` は、`coming_soon` や `internal_testing` など、まだルーティングできないエンドポイントの対応付けを選びます。

## 1 つのモデルを確認する

`checkParameters` とそれに相当するメソッドは、ライブのプロバイダールートのメタデータを読み取り、各パラメーターを `supported`、`partial`、`unsupported`、`unknown` のいずれかに分類し、公表されている値と範囲を確認して、パラメーター全体を受け付けるプロバイダールートを返します。`preflight` はリクエスト本文全体について同じことを行い、モデルのライフサイクルの確認を加えて、全体の `ok` を返します。

| 言語 | 機能 | パラメーターの確認 | プリフライト | ライフサイクル |
| --- | --- | --- | --- | --- |
| TypeScript | `models.capabilities(modelId)` | `models.checkParameters(modelId, values, { endpoint, provider })` | `models.preflight(request, { endpoint, provider })` | `models.validate(modelId)` は `{ ok, info, reason }` を返します。`models.getDeprecationInfo(modelId)` |
| Python | `models.capabilities(model_id)` | `models.check_parameters(model_id, values, endpoint=..., provider=...)` | `models.preflight(request, endpoint=..., provider=...)` | `models.validate(model_id)`、`models.get_deprecation_info(model_id)` |
| Go（次のリリース） | `GetModelEndpointCapabilities` | `CheckModelParameters` | `PreflightRequest` | `ValidateModel`、`GetModelDeprecationInfo`（公開済み） |
| C#（次のリリース） | `GetModelEndpointCapabilities(modelId)` | `CheckModelParameters(modelId, values)` | `PreflightRequest` | `ValidateModel`、`GetModelDeprecationInfo`（公開済み） |
| PHP（次のリリース） | `getModelEndpointCapabilities` | `checkModelParameters(...)` | `preflightRequest` | `validateModel`、`getModelDeprecationInfo`（公開済み） |
| Ruby（次のリリース） | `model_endpoint_capabilities` | `check_model_parameters(model_id, values)` | `preflight_request` | `validate_model`、`get_model_deprecation_info`（公開済み） |
| Java（ソースビルド） | `getModelEndpointCapabilities(modelId, query)` | `checkModelParameters(modelId, values, options)` | `preflightRequest(request, options)` | `validateModel`、`getModelDeprecationInfo` |
| Rust（`0.2.0` にはありません） | `Phaseo::model_endpoint_capabilities(...)` | `Phaseo::check_model_parameters(...)` | なし | なし |

「次のリリース」は、メソッドが SDK のソースにはあるものの、公開済みのパッケージにはないことを意味します。[各パッケージに含まれるものを確認する](./overview#check-what-each-package-ships)を参照してください。非推奨情報のメソッドは、モデルのステータス（`active`、`deprecated`、`retired`）、非推奨日と廃止日、後継モデルの ID を返します。
