使う言語の Phaseo パッケージをインストールし、API キーでクライアントを作成すれば、Gateway のエンドポイントごとに 1 つのメソッドを呼び出せます。キーを渡さない場合、どの SDK も `PHASEO_API_KEY` を読み込みます。

| 言語 | パッケージ | レジストリ | 公開バージョン |
| --- | --- | --- | --- |
| TypeScript | [`@phaseo/sdk`](https://www.npmjs.com/package/@phaseo/sdk) | npm | `3.0.0` |
| Python | [`phaseo`](https://pypi.org/project/phaseo/) | PyPI | `3.0.0` |
| Go | [`github.com/phaseoteam/Phaseo/packages/sdk/sdk-go/v4`](https://pkg.go.dev/github.com/phaseoteam/Phaseo/packages/sdk/sdk-go/v4) | Go modules | `v3.0.0` |
| C# | [`Phaseo.Sdk`](https://www.nuget.org/packages/Phaseo.Sdk) | NuGet | `3.0.0` |
| PHP | [`phaseo/sdk`](https://packagist.org/packages/phaseo/sdk) | Packagist | `v3.0.0` |
| Ruby | [`phaseo_sdk`](https://rubygems.org/gems/phaseo_sdk) | RubyGems | `3.0.0` |
| Java | `app.phaseo:phaseo-sdk` | Maven Central（古い API）。代わりに現在のソースをビルドしてください | `3.0.0` |
| Rust | [`phaseo`](https://crates.io/crates/phaseo) | crates.io | `0.2.0` |

各言語のインストールコマンドと要件は[インストール](./installation)にあります。C++ SDK はまだリリースされていません。

## 送るものと返ってくるもの

どの SDK でも、リクエスト本文には API の JSON フィールド名を使います。エンドポイントごとの例は[使い方](./usage)にあります。

| 言語 | リクエスト本文 | 戻り値 |
| --- | --- | --- |
| TypeScript | OpenAPI 仕様から生成された型付きオブジェクト | 型付きオブジェクト |
| Python | dict。型は `phaseo.models` にあります | `output_text`、`request_id`、`trace_url` を持つ `APIResponse` の dict |
| Go | `map[string]interface{}`、または型付きの `phaseo.ChatCompletionsRequest` と `phaseo.ResponsesRequest`（`Model`、`Messages`、`Input` などのパスカルケースの構造体フィールド） | デコード済みの JSON |
| C# | `Dictionary<string, object>` | `Dictionary<string, object>?` |
| PHP | 配列 | 配列 |
| Ruby | ハッシュ（キーワード引数） | ハッシュ |
| Java | `Map` または Jackson の `JsonNode`。JSON 文字列は先に解析します | `JsonNode` |
| Rust | `&serde_json::Value` | `status`、`body`、`request_id` を持つ `PhaseoResponse` |

キーがない場合は、クライアントの作成時に失敗します。Python は `ValueError` を送出し、Go の `NewFromEnv()` はエラーを返し、C# と PHP は `Missing API key. Pass apiKey or set PHASEO_API_KEY.` をスローし、Ruby は `ArgumentError: Missing API key. Pass api_key or set PHASEO_API_KEY.` を送出し、Rust の `Phaseo::from_env()` は `PhaseoError` を返します。

## 各パッケージに含まれるものを確認する

公開済みのパッケージは、SDK のソースにある一部の機能より前のものです。

| 言語 | 公開済みパッケージにまだないもの |
| --- | --- |
| Go | `GetModelEndpointCapabilities`、`CheckModelParameters`、`PreflightRequest` は `v3.0.0` にありません。次のリリースに含まれます。 |
| C# | `GetModelEndpointCapabilities`、`CheckModelParameters`、`PreflightRequest` は `3.0.0` にありません。次のリリースに含まれます。 |
| PHP | `getModelEndpointCapabilities`、`checkModelParameters`、`preflightRequest` は `v3.0.0` にありません。次のリリースに含まれます。 |
| Ruby | `model_endpoint_capabilities`、`check_model_parameters`、`preflight_request` は `3.0.0` の gem にありません。次のリリースに含まれます。 |
| Java | Maven Central にある `3.0.0` のアーティファクトには、再試行の制御、レスポンスのメタデータ、パラメーターの確認がありません。これらを使うには、[インストール](./installation)にある固定版のソースをビルドしてください。 |
| Rust | `Phaseo::model_endpoint_capabilities(...)` と `Phaseo::check_model_parameters(...)` は `0.2.0` の crate にありません。crate は `1.0` より前のため、本番環境では互換性のあるマイナーバージョンに固定してください。 |

<Tabs>
<Tab title="TypeScript">

| オプション | 役割 |
| --- | --- |

| `modelLifecycleChecks` | デフォルトは `true` で、クライアントは各モデルを 1 回だけ照会し（`GET /models`）、有効でないモデルを拒否します。照会を省くには `false` に設定します。 |
| `enableDeprecationWarnings`、`warningsAsErrors`、`logger` | モデルの非推奨警告を制御します。 |
| `devtools` | ローカルの DevTools キャプチャ。 |
| `headers`、`fetchImpl` | 追加のヘッダーと独自の `fetch`。 |

</Tab>
<Tab title="Python">

| オプション | 役割 |
| --- | --- |
| `api_key` | キーの文字列、またはリクエストごとに認証情報を返す呼び出し可能オブジェクト（たとえば[信頼済みワークロード](/ja/v1/developers/trusted-workloads)のトークン）。デフォルトは `PHASEO_API_KEY` です。 |

| `app` | アプリの `id`、`name`、`url` を含む dict。アトリビューションヘッダーとして送信されます。 |
| `enable_deprecation_warnings`、`warnings_as_errors`、`logger` | モデルの非推奨警告を制御します。`Phaseo` でのみ使えます。 |
| `devtools` | ローカルの DevTools キャプチャ。`Phaseo` でのみ使えます。 |
| `http_client` | リクエストの送信に使う `httpx.Client`（`AsyncPhaseo` では `httpx.AsyncClient`）。注入したクライアントは、あなたが閉じる必要があります。 |
| `on_request`、`on_response`、`on_retry` | 試行ごとに呼び出されるフック。 |

asyncio では `AsyncPhaseo` を使います。

```python Python
import asyncio
from phaseo import AsyncPhaseo

async def main():
    async with AsyncPhaseo() as client:
        response = await client.responses.create({"model": "openai/gpt-6-astra", "input": "Hello"})
        print(response.output_text, response.request_id, response.trace_url)

asyncio.run(main())
```

解析済みのテキストイベントには `async for event in client.responses.stream(request)` を使います。asyncio のタスクをキャンセルすると、HTTP リクエストとポーリングが停止します。`AsyncPhaseo` には、テキスト、画像、音声、リアルタイム、音楽、動画、バッチ、ファイル、モデル、埋め込み、OCR、リランク、解析、モデレーション、判断、抽出のリソース名前空間があります。それ以外の HTTP 操作には `await client.request(...)` を使ってください。

| `.with_header(name, value)` | `Phaseo` | 以降のすべてのリクエストにヘッダーを追加します。 |

## 音楽、動画、バッチの完了を待つ

待機用のヘルパーは TypeScript と Python にあります。その他の SDK は作成の呼び出しでジョブを返すので、取得メソッドでポーリングするか、その[ジョブの WebSocket URL](#find-the-method-for-each-endpoint) を開いてください。

<CodeGroup>

```typescript TypeScript
const music = await client.music.generateAndWait(
  { model: process.env.PHASEO_MUSIC_MODEL!, prompt: "Gentle instrumental piano" },
  { timeoutMs: 600_000, onPoll: (job) => console.log(job.id, job.status) },
);
```

```python Python
import os

music = client.music.generate_and_wait(
    {"model": os.environ["PHASEO_MUSIC_MODEL"], "prompt": "Gentle instrumental piano"},
    timeout=600,
    on_poll=lambda job: print(job["id"], job["status"]),
)
```

</CodeGroup>

動画には `videos.generateAndWait` / `videos.generate_and_wait` を、バッチには `batches.createAndWait` / `batches.create_and_wait` を使います。各ヘルパーは 1 回だけ送信します。最初のレスポンスがすでに完了していればポーリングせずにそれを返し、そうでなければ同じジョブを完了までポーリングして完全なレスポンスを返します。失敗、キャンセル、期限切れになったジョブは `JobFailedError` を送出し、その `response` に詳細が含まれます。完了したバッチにも、個々のリクエストの失敗が含まれている場合があります。

各リソースの `wait(id, options)` は既存のジョブを再開し、失敗を含む終了時のレスポンスを返します。Python では、音楽に `create(request)` と `retrieve(id)` もあります。

| TypeScript | Python | デフォルト | 注記 |
| --- | --- | --- | --- |
| `intervalMs` | `interval` | `5000` ミリ秒 / `5` 秒 | 最小 `250` ミリ秒 / `0.25` 秒。 |
| `timeoutMs` | `timeout` | `1800000` ミリ秒 / `1800` 秒（30 分） | 送信が戻った後に開始します。送信リクエストには独自のタイムアウトがあります。 |
| `signal` | `cancel_event` | なし | 待機を停止します。Python では `threading.Event` です。 |
| `onPoll` | `on_poll` | なし | 最初のレスポンスと各ポーリングの結果を受け取ります。 |

`JobTimeoutError` と `JobCancelledError` はジョブ ID と最後のレスポンス（TypeScript では `jobId`/`lastResponse`、Python では `job_id`/`last_response`）を保持するため、`.wait(error.jobId)` または `.wait(error.job_id)` で再開できます。待機を停止しても、リモートのジョブはキャンセルされません。TypeScript では実行中のポーリングがキャンセルされます。同期の Python クライアントはリクエストとコールバックの間でキャンセルと期限を確認するため、すでに進行中の HTTP 呼び出しは中断できません。HTTP の失敗はそのまま送出され、送信は再試行されません。これらのヘルパーはあなたのプロセスからポーリングするもので、Gateway にバックグラウンド実行を追加するものではありません。

### プロセスをまたいでハンドルを保持する

`music.start`、`videos.start`、`batches.start` は、`result()`、`events()`、`cancel()`、さらに `toJSON()`（TypeScript）または `to_dict()`（Python）を持つハンドルを返します。返される種類と ID を保存しておき、後で `resume(id)` でハンドルを再構築します。`result()` は終了時の失敗で例外を送出します。`cancel()` に対応しているのは動画とバッチのジョブだけです。`AsyncPhaseo` では、メソッドを await し、`async for` でイベントを反復処理します。

| 作業 | TypeScript | Python |
| --- | --- | --- |
| 動画コンテンツをストリーミングする | `videos.streamContent(id)` を `downloadTo(stream, writable)` で書き込む | `videos.stream_content(id)` を同期の `download_to(chunks, binary_file)` で書き込む。ダウンロード全体をメモリに保持しません |
| バッチの結果をストリーミングする | `batchResults(await client.batches.streamResults(id))` が JSONL を 1 行ずつ解析し、`matchBatchResult(row, inputsByCustomId)` が各行を入力と対応付け、行ごとのエラーを保持します | `batches.results(id)` |
| アップロードを準備する | `toFile(bytes, filename, contentType)` | バイト列、`Path` オブジェクト、ファイルオブジェクト、または HTTPX のファイルタプルを渡します |

<span id="request-controls-and-errors"></span>
## リクエストの制御とエラー

TypeScript、Python、Java では、再試行のデフォルトは `0` で、`GET` と `HEAD` のリクエストにのみ適用されます。有料の送信、書き込み、ストリーミングのリクエストは再試行されません。

<CodeGroup>

```typescript TypeScript
const fast = client.withOptions({ timeoutMs: 30_000, signal, maxRetries: 2 });
```

```python Python
fast = client.with_options(timeout=30, max_retries=2)
```

```java Java
Phaseo client = new Phaseo(System.getenv("PHASEO_API_KEY"))
    .setTimeout(Duration.ofSeconds(30))
    .setMaxRetries(2);
```

</CodeGroup>

<Tabs>
<Tab title="TypeScript">

`withOptions(...)` は、それらの制御をすべてのリソース、ストリーム、メディアの呼び出しに適用した新しいクライアントを返します。元のクライアントは変更されません。再試行は `Retry-After` に従います。`timeoutMs` にはレスポンス本文の読み込みも含まれます。

`responseMetadata(result)` は、Gateway のリクエスト ID とダッシュボードのトレース URL を返します。HTTP エラーは `PhaseoHttpError` で、HTTP の `status`、API エラーの `code`、`requestId`、`traceUrl`、再試行までの待ち時間、本文、`headers` を含みます。

</Tab>
<Tab title="Python">

`with_options(...)` は新しいクライアントを返し、`headers=...` も受け付けます。`Phaseo` と `AsyncPhaseo` の両方で動作します。再試行はレスポンスを読み込む前に行われ、最大 `10` 回です。タイムアウトは秒単位の HTTPX タイムアウトのため、合計時間ではなくネットワークの無通信時間を制限します。

JSON レスポンスは、`output_text`、`request_id`、`trace_url` を持つ `APIResponse` の dict です。HTTP エラーは `PhaseoHTTPError` で、`status`、`code`、`request_id`、`trace_url`、再試行までの待ち時間、本文を含みます。

古いリリースからアップグレードする場合は、`urllib.error.HTTPError` の catch を `PhaseoHTTPError`（または `httpx.HTTPStatusError`）に、接続エラーの catch を `httpx.TransportError` に置き換えてください。

</Tab>
<Tab title="Java">

HTTP エラーは `Client.ApiException`（`app.phaseo.gen.Client`）で、`getStatusCode()`、`getRequestId()`、`getResponseBody()` とヘッダーを持ちます。`requestWithResponse(...)` は、データとその `requestId()` を返します。

</Tab>
<Tab title="Rust">

どの呼び出しも `Result<PhaseoResponse, PhaseoError>` を返します。`PhaseoError` は `std::error::Error` と `Display` を実装しています。通信と設定の失敗には `status` がありません。

| 型 | フィールド | 意味 |
| --- | --- | --- |
| `PhaseoResponse` | `status: u16` | HTTP ステータスコード。 |
| `PhaseoResponse` | `body: serde_json::Value` | 解析済みの JSON レスポンス。レスポンスが有効な JSON でなかった場合は JSON 文字列。 |
| `PhaseoResponse` | `request_id: Option<String>` | `x-request-id` レスポンスヘッダー（ある場合）。 |
| `PhaseoError` | `message: String` | 設定、通信、または Gateway のエラーメッセージ。 |
| `PhaseoError` | `status: Option<u16>` | レスポンスを受け取った場合の Gateway の HTTP ステータス。 |
| `PhaseoError` | `body: Option<serde_json::Value>` | 解析済みの Gateway エラー本文（ある場合）。 |

</Tab>
</Tabs>

各言語の完全なエラーハンドラーは[使い方](./usage#handle-errors)にあります。

## ラッパーのないエンドポイントを呼び出す

各 SDK には、Phaseo の OpenAPI 仕様から生成されたクライアントも含まれています。

| 言語 | 生成されたクライアント |
| --- | --- |
| TypeScript | `client.rawClient()`。生成された操作は `operations` としてエクスポートされます。 |
| Python | `client.raw_client()`。生成された操作は `phaseo.ops` にあります。 |
| Go | `src/gen` の `client.RawClient()`。`client.Request(ctx, method, path, query, headers, body)` は任意のリクエストを送信します。 |
| Java | `client.rawClient()`。ストリームには `requestLines`、バイナリのレスポンスには `requestBytes` を使います。 |
| Rust | `phaseo::gen` に生成されたクライアント、モデル、操作があり、`phaseo::client`、`phaseo::models`、`phaseo::operations` として再エクスポートされます。`phaseo::model_ids` には生成されたモデル ID があります。`client.post(path, body)` は、ベース URL 配下の任意のパスに JSON を送信します。[docs.rs](https://docs.rs/phaseo) を参照してください。 |

生成された操作はラッパーメソッドより低レベルです。ラッパーがある場合はそちらを使ってください。

## 出力を解析し、ストリームを集める

これらのヘルパーは TypeScript と Python にあります。`responses.parse(request, schema)` は、完了した JSON レスポンスを検証します。`schema` は、TypeScript では Zod 互換のパーサー、Python では Pydantic モデルです。リクエストにも構造化出力の形式を設定してください。パーサーは検証しか行いません。

`collectStream(client.streamResponses(request))`（TypeScript）、または `collect_stream` と `collect_async_stream`（Python）は、ストリーミングされたテキストと使用量を集めます。

## 呼び出す前にモデルを確認する

`checkModelCapabilities` / `check_model_capabilities`（TypeScript と Python）は、有効なプロバイダーのオファー 1 つについて、公表されている機能とスカラーの制約（`inputTypes`、`outputTypes`、`endpoints`、`parameters`、`parameterValues`、Python ではスネークケースの名前）を確認します。モデルを変更したりパラメーターを削除したりすることはなく、実際のプロバイダーがリクエストを受け付けることを保証するものでもありません。メタデータがない場合の扱いは異なり、TypeScript は不明として報告し、Python はチェックを失敗させます。

モデルの選択画面やパラメーターのエディターには、ライブのエンドポイントのメタデータを使います。

<CodeGroup>

```typescript TypeScript
const support = await client.models.checkParameters(
  "anthropic/claude-haiku-4.5",
  { temperature: 0.7, top_p: 0.9 },
  { endpoint: "responses" },
);
```

```python Python
support = client.models.check_parameters(
    "anthropic/claude-haiku-4.5",
    {"temperature": 0.7, "top_p": 0.9},
    endpoint="responses",
)
```

</CodeGroup>

各パラメーターは `supported`、`partial`、`unsupported`、`unknown` のいずれかとして返され、該当するプロバイダーのルートと、インラインで強調表示できる制約の問題も含まれます。これらのチェックは明示的な呼び出しで、生成リクエストに照会を追加するものではありません。各 SDK のメソッドは[モデル](./models#check-one-model)にあります。

## ネットワークなしでテストする

<Tabs>
<Tab title="TypeScript">

`@phaseo/sdk/testing` から `createMockTransport` と `jobFixtures` をインポートし、モックの `fetchImpl` をクライアントに渡します。フィクスチャは厳密で順序付きです。予期しない呼び出しはローカルで失敗し、ネットワークには届きません。期待したリクエストがすべて行われたかを確認するには `mock.assertDone()` を呼び出します。

</Tab>
<Tab title="Python">

`phaseo.testing.MockTransport(fixtures)` を `httpx.Client` または `httpx.AsyncClient` に渡し、それを `http_client` として Phaseo クライアントに渡します。予期しないリクエストはローカルで失敗します。すべてのフィクスチャが使われたかを確認するには `assert_done()` を呼び出します。`phaseo.testing.job_fixtures(path, job_id)` は、ジョブの送信とポーリングのフィクスチャを組み立てます。フィクスチャは実際のプロバイダーの動作を検証しません。

</Tab>
</Tabs>

## ルームからコードをエクスポートする

Phaseo のルームでリクエストを送信した後、**コードを取得** でそのモデルと設定を TypeScript または Python としてエクスポートできます。リクエスト ID がある場合は、**リクエストを表示** でダッシュボードのトレースを開けます。エクスポートしたコードは、`PHASEO_API_KEY` を設定したサーバーで実行してください。
