## エージェントを作成する

定義からエージェントを作成します。定義のステップ上限は、各 run または continue の呼び出しに適用されます。

| 言語 | 名前 | デフォルトのステップ上限 |
| --- | --- | --- |
| TypeScript | `createAgent(definition)` | 12 |
| Python | `create_agent(definition)`。dict または `AgentDefinition` から | 12 |
| Go | `CreateAgent(AgentDefinition) *Agent` | 8 |
| C# | `AgentSdk.CreateAgent(AgentDefinition)` | 12 |
| PHP | `AgentSdk::createAgent(AgentDefinition)` | 12 |
| Ruby | `PhaseoAgentSdk.create_agent(definition)`。`AgentDefinition` またはキーワードのフィールドから | 12 |
| Java | `AgentSdk.createAgent(AgentDefinition)` | 12（1未満の `maxSteps` は12になります） |
| Rust | `create_agent(AgentDefinition::new(id, model))` | 8（値は最低1に切り上げられます） |

### 定義のフィールド

Rust は、フィールドではなくメソッドで定義を組み立てます。`AgentDefinition::new(id, model)` の後に、`.instructions(text)`、`.tool(tool)`（ツールごとに1回）、`.max_steps(limit)`、`.model_retries(count, backoff)`、`.human_review(callback)` を続けます。Java の `AgentDefinition` は、10引数、13引数、19引数のコンストラクターを持つレコードです。

| フィールド | camelCase（TypeScript、PHP、Java） | snake_case（Python、Ruby） | PascalCase（Go、C#） | ない言語 |
| --- | --- | --- | --- | --- |
| エージェント ID（必須） | `id` | `id` | `ID`（Go）、`Id`（C#） | |
| モデルまたはプリセット | `model`、`preset` | `model`、`preset` | `Model`、`Preset` | Rust には `preset` がない |
| モデルのリスト（`model` が未設定の場合に先頭だけを使用。フォールバックなし） | `models` | | | TypeScript 以外すべて |
| 指示 | `instructions` | `instructions` | `Instructions` | |
| ツール | `tools` | `tools` | `Tools` | |
| ステップで提供するツール | `activeTools` | | | TypeScript 以外すべて |
| 各モデルリクエストの前に履歴を書き換える | `prepareMessages` | | | TypeScript 以外すべて |
| ステップ上限と停止条件 | `maxSteps`、`stopWhen` | `max_steps`、`stop_when` | `MaxSteps`、`StopWhen` | Rust には `stop_when` がない |
| モデルの再試行とツールの同時実行数 | `modelRetry`、`toolExecution` | `model_retry`、`tool_execution` | `ModelRetry`、`ToolExecution` | Rust にはツールの同時実行数がない |

TypeScript では、`model`、`instructions`、サンプリングの値を固定にも動的にもできます。

## 実行と続行

| 目的 | TypeScript | Python | Go | C# | PHP | Ruby | Java | Rust |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 実行 | `run(options)` | `run(...)` | `Run(ctx, RunOptions)` | `Run(RunOptions)` | `run(...)` | `run(...)` | `run(RunOptions)` | `run(&mut client, options)`、`run_with_events(&mut client, options, callback)` |
| 実行してストリーミング | `stream(options)` | `stream(...)` | `Stream(ctx, RunOptions)` | `Stream(RunOptions)` | `stream(...)` | `stream(...)` | `stream(RunOptions)` | なし |
| 続行 | `continueRun(options)` | `continue_run(...)` | `Continue(ctx, ContinueOptions)` | `ContinueRun(ContinueOptions)` | `continueRun(...)`、`continueRunById(...)` | `continue_run(...)` | `continueRun(ContinueOptions)` | `continue_run(&mut client, options)`、`continue_with_events(...)` |
| 続行してストリーミング | `continueStream(options)` | `continue_stream(...)` | `ContinueStream(ctx, ContinueOptions)` | `ContinueStream(ContinueOptions)` | `continueStream(...)` | `continue_stream(...)` | `continueStream(ContinueOptions)` | なし |

実行と続行は実行結果を返します。TypeScript では `Promise<AgentRunResult>`、Go では `(RunResult, error)`、C# では `Task<RunResult>`、Rust では `Result<RunResult, AgentError>`、その他の言語では実行結果を直接返します。ストリームのメソッドは、すぐにストリーム結果を返します。

### 実行オプション

PHP と Ruby は、これらを名前付き引数またはキーワード引数として受け取ります。Java の `RunOptions` は位置引数のレコードで、順序は `input, client, context, model, preset, maxSteps, modelRetry, toolExecution, onEvent, devtools`、その後に省略可能な `state` が続きます。

| オプション | camelCase（TypeScript、PHP、Java） | snake_case（Python、Ruby、Rust） | PascalCase（Go、C#） | ない言語 |
| --- | --- | --- | --- | --- |
| 入力 | `input` | `input` | `Input` | |
| 入力の代わりに会話全体を渡す | `messages` | | | TypeScript 以外すべて |
| モデルクライアント | `client` | `client` | `Client` | Rust は別の引数として渡す |
| アプリケーションのコンテキスト | `context` | `context` | `Context` | |
| モデル、プリセット、ステップ上限の上書き | `model`、`preset`、`maxSteps` | `model`、`preset`、`max_steps` | `Model`、`Preset`、`MaxSteps` | Rust には `model` と `max_steps` のみ |
| 再試行とツールの同時実行数の上書き | `modelRetry`、`toolExecution` | `model_retry`、`tool_execution` | `ModelRetry`、`ToolExecution` | Rust |
| サンプリングの上書き | `temperature`、`maxOutputTokens`、`topP`（TypeScript） | | | TypeScript 以外すべて |
| キャンセル | `signal`（TypeScript） | | `CancellationToken`（C#） | Go は `ctx` を使い、その他はストリームでキャンセル |
| イベントハンドラー | `onEvent` | `on_event` | `OnEvent` | Rust は `run_with_events` を使う |
| ローカルへの記録 | `devtools` | `devtools` | `Devtools` | Rust |
| 状態アクセサー | `state` | `state` | `State` | Rust |
| 次のモデルリクエストの前にメッセージを追加する | `takeMessages`（TypeScript） | | | TypeScript 以外すべて |

Python の `run()` は `stop_when` も受け付けますが無視します。停止条件は定義に設定してください。PHP の `stream()` と Ruby の `stream` が受け取るのは `input`、`client`、`context`、`state` だけです。Rust は `RunOptions::new(input)` でデフォルトを作成します。

### 続行オプション

続行オプションは、上記の実行の上書きに加えて、次のものを受け取ります。

| オプション | camelCase（TypeScript、PHP、Java） | snake_case（Python、Ruby、Rust） | PascalCase（Go、C#） | ない言語 |
| --- | --- | --- | --- | --- |
| 保存した実行 | `run` | `run`（Rust：`result`） | `Run` | |
| `state` を通じて ID で実行を読み込む | `runId` | `run_id` | `RunID`（Go）、`RunId`（C#） | Rust。PHP は `continueRunById($runId, $state, $client, ...)` を使う |
| 人の入力 | `humanInput` | `human_input` | `HumanInput` | |
| 構造化された人のメッセージ | `humanMessages`（TypeScript） | | | TypeScript 以外すべて |
| 承認 | `approvals`（TypeScript の別名 `approveToolCalls`） | `approvals` | `Approvals` | |
| 拒否 | `rejections`（TypeScript の別名 `rejectToolCalls`） | `rejections` | `Rejections` | Rust |
| ツール出力 | `toolOutputs` | `tool_outputs` | `ToolOutputs` | |

Java の `ContinueOptions` の順序は `run, client, context, model, preset, maxSteps, humanInput, modelRetry, toolExecution, onEvent, devtools`、次に `approvals, rejections, toolOutputs`、最後に `runId, state` です。この 16 引数の形式のほかに、最初の 11 引数だけ、または最初の 14 引数だけを受け取るコンストラクターもあり、残りは空のリストまたは `null` になります。Rust は `ContinueOptions::new(result)` でデフォルトを作成します。

| 目的 | TypeScript | Python | Go | C# | PHP | Ruby | Java |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 完了した結果 | `getResult()`、またはストリームを `await` | `result()` | `Result()` | `GetResult()` | `getResult()` | `result` | `getResult()` |
| 最終テキスト全体 | `getText()` | | | | | | |
| テキストの差分 | `getTextStream()` | `text_stream()` | `Text()` | `TextStream()` | `textStream()` | `text_stream` | `textStream()` |
| 推論の差分 | `getReasoningStream()` | `reasoning_stream()` | | | `reasoningStream()` | `reasoning_stream` | |
| アイテム | `getItemsStream()` | `item_stream()` | | | `itemStream()` | `item_stream` | |
| ツールのイベント | `getToolStream()` | `tool_stream()` | | | | | |
| すべてのイベント | `getFullStream()` | `full_stream()` | `Events()` | `FullStream()` | `fullStream()` | `full_stream` | `fullStream()` |
| キャンセル | `cancel(reason?)` | `cancel()` | `Cancel()` | `Cancel()` | `cancel()` | `cancel` | `cancel()` |

コンシューマーは最初から再生するため、複数のコンシューマーが同じ実行を読み取れます。動作は言語によって異なります。

| 言語 | ストリーム結果の型 | 動作 |
| --- | --- | --- |
| TypeScript | `AgentStreamResult` | `getFullStream()` は `result` イベントで終わります |
| Python | `AgentStreamResult` | バックグラウンドスレッドで実行します。`result()` は完了までブロックします |
| Go | `*StreamResult` | `Text()` と `Events()` はチャネルです。`Cancel()` は実行の context をキャンセルします |
| C# | `AgentStreamResult` | `IAsyncEnumerable` のコンシューマーです。`Cancel()` は実行のリンクされたトークンをキャンセルします |
| PHP | `AgentStreamResult` | Fiber で実行します。ストリームを消費し終えると `$result` に `RunResult` が入り、それまでは `null` です |
| Ruby | `StreamResult` | ワーカースレッドで実行します。`result` はその終了を待ち、`cancel` はそれを終了させます |
| Java | `StreamResult` | `textStream()` と `fullStream()` は実行が終わった後に `List` を返します。`cancel()` はワーカースレッドを中断します |
| Rust | なし | `0.2` にはストリーミングがありません |

## 実行結果

| フィールド | camelCase（TypeScript、PHP、Java） | snake_case（Python、Ruby、Rust） | PascalCase（Go、C#） |
| --- | --- | --- | --- |
| 実行レコード | `run` | `run` | `Run` |
| ステップのレコード | `steps` | `steps` | `Steps` |
| 最終出力 | `output` | `output` | `Output` |
| 会話全体 | `messages` | `messages` | `Messages` |
| 累計の使用量 | `usage` | `usage` | `Usage` |

型は、TypeScript と Python では `AgentRunResult`、その他では `RunResult` です。TypeScript には、`stepResults`（正規化されたステップ結果）と `items`（順序付きのメッセージ、推論、ツールの動き、エラー、最終出力。[アイテム](./items)を参照）も加わります。Rust では、`output` は `serde_json::Value` で、`RunResult`、`RunRecord`、`RunStep`、`Message`、`ToolCall`、`HumanPause`、`PendingToolCall`、`ToolDecision`、`ToolOutput`、`UsageSummary` は Serde でシリアライズできます。

## 一時停止と判断

| 型 | TypeScript | Python | Go、C#、PHP、Ruby、Java、Rust | フィールド |
| --- | --- | --- | --- | --- |
| 呼び出しを承認または拒否する | `{ toolCallId, reason? }` | `AgentToolDecision` | `ToolDecision` | ツール呼び出し ID と、任意の理由 |
| ツールの結果を渡す | `{ toolCallId, output }` | `AgentToolOutput` | `ToolOutput` | ツール呼び出し ID と出力 |
| レビューを求める | `{ reason, payload }` | `AgentHumanReviewRequest` | `HumanReviewRequest` | `reason`、任意の `payload` |
| レビューのコールバックの入力 | | `AgentHumanReviewContext` | `HumanReviewContext` | 実行 ID とエージェント ID、ステップ番号、メッセージ、モデルのレスポンス、パース済みの出力（Rust：パース済みの出力の代わりにアプリケーションのコンテキスト） |
| 一時停止 | `run.pause` | `AgentHumanPause` | `HumanPause` | `reason`、`payload`、`kind`、保留中のツール呼び出し |
| 保留中の呼び出し | | | `PendingToolCall` | `call` と `kind`（`approval`、`manual`、`hitl` のいずれか）。Rust には人が読める `reason` が加わります |

フィールド名は各言語の命名規則に従います。`toolCallId`（TypeScript、PHP、Java）、`tool_call_id`（Python、Ruby、Rust）、`ToolCallID`（Go）、`ToolCallId`（C#）です。Rust の `ToolDecision` は承認専用です。[状態と承認](./state-and-approval)を参照してください。

## モデルクライアント

モデルターンを別の通信手段で送る場合や、Gateway クライアントをラップする場合は、モデルクライアントを実装します。

| 言語 | インターフェース | メソッド |
| --- | --- | --- |
| Go | `ModelClient`、`StreamingModelClient` | `Generate(ctx, ModelRequest)`、`Stream(ctx, ModelRequest)` |
| C# | `IModelClient`、`IStreamingModelClient` | `Generate(ModelRequest)`、`Stream(ModelRequest)` |
| PHP | `ModelClient`、`StreamingModelClient`（インターフェース） | `generate(ModelRequest)`、`stream(ModelRequest)` |
| Java | `ModelClient`、`StreamingModelClient` | `generate(ModelRequest)`、`stream(ModelRequest)` |
| Rust | `ModelClient`（トレイト） | `fn generate(&mut self, request: &ModelRequest) -> Result<ModelResponse, AgentError>` |

Rust では、`ModelRequest` はエージェント ID、実際に使われるモデル、指示、現在のメッセージ、ツールの仕様（`ToolSpec`：`id`、`description`、JSON Schema の `parameters`）、アプリケーションのコンテキストを保持します。`ModelResponse` は `message`、`usage`、`request_id`、`provider`、`model`、`finish_reason` を保持します。`Message` は `role`、`content`、`tool_calls`、`tool_call_id`、`name`、`is_error` を持ち、コンストラクター `Message::user(content)` と `Message::assistant(content)` があります。`ToolCall` は `id`、`name`、JSON の `input` を持ちます。

## イベントとエラー

| 言語 | イベントの型 | エラーの型 |
| --- | --- | --- |
| TypeScript | `type` を持つイベントオブジェクト | `AgentGatewayError`（`isAgentGatewayError()`）、`AgentStreamError`、`AgentSchemaValidationError` |
| Python | `"type"` を持つ dict | 組み込みの例外と `phaseo.PhaseoHTTPError` |
| Go | `AgentEvent` | `error` の値 |
| C# | `AgentEvent` | 例外 |
| PHP | `"type"` を持つ配列 | `RuntimeException` |
| Ruby | `:type` を持つハッシュ | 例外 |
| Java | `AgentEvent` | 例外 |
| Rust | `AgentEvent`（`event_type`、`run_id`、`agent_id`、`timestamp_ms`、`details`） | `AgentError`（`AgentError::new(...)`、`message()`。`std::error::Error` と `Display` を実装） |

TypeScript は、エラーを分類する `agentErrorIsRetryable()`、`agentRetryAfterMs()`、`agentErrorIsContextOverflow()`、結果のないまま残ったツール呼び出しに応答し、どの呼び出しにも対応しない結果を取り除く `repairToolHistory(messages)`、長いテキストの先頭と末尾を残して切り詰めた内容の通知を入れる `truncateToolOutput(text, limit)` もエクスポートします。[ライフサイクルフック](./lifecycle-hooks)と[イベントとエラー](./events-and-errors)を参照してください。
