---

通信やゲートウェイの失敗と、無効なツールデータや出力データを分けて扱います。実行に失敗しても、ステータス、アクティブなステップ、再試行回数、リクエストID、ネイティブレスポンスID、利用可能なゲートウェイ情報は保持されます。

## よくある確認事項

- Javaプロセスから`PHASEO_API_KEY`を参照できることを確認します。
- 各ツールに一意で安定したIDを付けます。
- 承認、却下、手動出力には、正確なツール呼び出しIDを指定します。
- 別のリクエストやワーカーに制御を戻す前に、一時停止中の`RunResult`を保存します。
- バリデーターは決定論的にし、副作用を起こさないようにします。
- アプリケーションが明示的に新しい実行を開始しない限り、キャンセルやタイムアウトの例外は終端として扱います。

アプリケーションのテレメトリーにはライフサイクルフックを、ローカルの実行記録にはDevToolsを使い、コンソール出力だけに依存しないでください。
