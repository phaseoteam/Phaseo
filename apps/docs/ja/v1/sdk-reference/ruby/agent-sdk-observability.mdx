エージェントの失敗は通常、モデルリクエスト、ローカルツール、スキーマ検証、タイムアウト、または未完了の人間による判断が原因です。

## ツールエラーからの回復

モデルがツールエラーから回復できる場合は、`on_error: "return-to-model"`を設定します。エラーはツール結果として返され、エージェントは別の操作を選べます。危険または回復不能な操作ではfail-runの動作を維持してください。

## Rubyの実行方式

Rubyは通常の同期イテレーションでモデルのストリームを読み取ります。ネットワークやプロセスを扱うツールには明示的なタイムアウトを設定し、遅い永続化処理でライフサイクルコールバックをブロックしないでください。

## 続行処理のエラーを診断する

保留中の各呼び出しには、ツール呼び出しIDで識別される承認、却下、または外部から提供された出力が必要です。承認UIを表示する前に、返された実行状態全体を保存してください。

## 有用なフィールドを記録する

実行ID、ステップ番号、リクエストID、プロバイダー、モデル、終了理由、ツール呼び出しID、停止理由を記録します。プロンプトを直接記録するより、ライフサイクルフックまたはDevToolsを使ってください。
