---
title: "SKILL.md でコーディングエージェントを設定する"
icon: "file-code"
description: "SDK と SKILL.md ファイルを組み合わせて、ローカルのコーディングエージェントが Phaseo 連携を一貫して利用できるようにします。"
---

リポジトリに `SKILL.md` を追加して、コーディングエージェントがプロジェクトの想定どおりに Phaseo を呼び出すようにします。ベース URL、キーの変数、エンドポイント、承認済みモデル、ログ記録がそろいます。完成すると、公開されている Phaseo スキル、その上に重ねるプロジェクトスキル 1 つ、スキルが参照する共有クライアントモジュール 1 つがそろいます。

以下のスキルとモジュールは、モデル ID とプリセット名を自分のものに置き換えれば本番環境でそのまま使えます。

<Steps>
<Step title="公開されている Phaseo スキルをインストールする">

<Visibility for="humans">
公開スキルは Gateway、SDK、プリセット、ルーティング、移行を扱います。[`phaseo.app/docs`](https://phaseo.app/docs/.well-known/agent-skills/index.json) からインストールします。
</Visibility>

<Visibility for="agents">
プロジェクト固有の指示を書く前に、[`phaseo.app/docs`](https://phaseo.app/docs/.well-known/agent-skills/index.json) から公開されている Phaseo スキルをインストールしてください。
</Visibility>

```bash
npx skills add https://phaseo.app/docs --agent codex --skill '*'
```

`--agent` はチームが使うエージェントに変更します。自分の `SKILL.md` にはプロジェクト固有のルールだけを書いてください。

</Step>
<Step title="SDK をインストールする">

<CodeGroup>
```bash npm
npm install @phaseo/sdk
```

```bash pnpm
pnpm add @phaseo/sdk
```

```bash yarn
yarn add @phaseo/sdk
```

```bash bun
bun add @phaseo/sdk
```

```bash Python
pip install phaseo
```
</CodeGroup>

</Step>
<Step title="共有クライアントを 1 つ追加する">

エージェントは、大きなラッパーよりも小さく分かりやすいヘルパーのほうを確実に再利用します。クライアントを 1 つのモジュールに置き、どこからでもそれをインポートします。

```ts src/lib/phaseo.ts
import Phaseo from "@phaseo/sdk";

export const gateway = new Phaseo({
  apiKey: process.env.PHASEO_API_KEY!,
});
```

テキスト生成、埋め込み、画像生成、非同期の動画など、使う機能ごとに呼び出し経路を 1 つにしてください。

</Step>
<Step title="プロジェクトスキルを書く">

リポジトリのルート、またはエージェントが読み込むスキルフォルダー（例: `.agents/skills/phaseo-project/SKILL.md`）に `SKILL.md` を作成します。エージェントは frontmatter の `name` と `description` を読んで、いつスキルを読み込むかを判断します。

```md SKILL.md
---
name: phaseo-project
description: "How this repository calls Phaseo Gateway: client module, endpoint, approved models and presets, logging and async jobs. Use when adding or changing any Phaseo call in this repo."
---

# Phaseo in this repository

- Import the client from `src/lib/phaseo.ts`. Never create another one.
- The base URL is `https://api.phaseo.app/v1`. The key is in `PHASEO_API_KEY`; never hard-code it or send it to the browser.
- Use the Responses API (`POST /v1/responses`) for new text features.
- Approved models: `openai/gpt-6-astra` for drafts, `anthropic/claude-sonnet-5.5` for reviews. Ask before adding another.
- Prefer the `@support-triage` preset for support features; pass it as `model`.
- Log the response `id` and `model` on every call, and `generation_id` from error bodies.
- For async video jobs, store the returned ID and poll status until it is terminal.
- Validate any model-generated tool arguments before acting on them.
```

</Step>
</Steps>

## 動作を確認する

「Phaseo でチケットを要約する」のような小さな Phaseo 機能の追加をエージェントに依頼します。変更が `src/lib/phaseo.ts` をインポートし、`PHASEO_API_KEY` を読み取り、承認済みのモデルまたはプリセットを使い、レスポンス ID をログに記録していれば成功です。そうでない場合は、スキルの `description` が依頼内容と一致していない可能性があります。チームが使うタスクの言葉を書き込んでください。

## スキルに書く内容

エージェントが最も時間を費やす質問にだけ答え、それ以外は書きません。

| 質問 | 回答の例 |
| --- | --- |
| どのエンドポイント群を使うか | テキストには Responses、検索には Embeddings |
| 認証情報はどこにあるか | `PHASEO_API_KEY`、サーバー側のみ |
| 承認済みのモデル ID やプリセットは何か | `org/model` 形式の短い一覧 |
| 何をログに記録するか | レスポンスの `id`、`model`、エラー時の `generation_id` |
| 非同期ジョブをどう追跡するか | ID を保存し、終了状態になるまでポーリングする |

[Codex](../guides/integrations/codex)、[Vercel AI SDK](../guides/integrations/ai-sdk)、[サンプル](../guides/examples)では、各ツールで同じ規約を使う方法を紹介しています。
