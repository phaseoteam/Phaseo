モデル、プロンプト、プロバイダーのルールをダッシュボードのプリセットから取得し、コードではワークフローだけを扱う TypeScript のトリアージエージェントを作成します。完成すると、厳密な JSON のトリアージ判定を返し、人の判断が必要なケースを一時停止し、モデル呼び出しを決まった回数まで再試行し、Gateway の失敗を調査に必要な ID とともにログに記録するエージェントができます。

プリセットが作成済みで、[永続化可能なループ](./agent-sdk-durable-loop)のように一時停止した実行を保存していれば、このスクリプトは本番環境で使えます。パッケージ化した版は `packages/sdk/agent-sdk-ts/examples/support-triage-agent.ts` にあります。

## 作成する

<Steps>
<Step title="プリセットを作成する">

**設定 → プリセット** で、ルーティング先のモデル、プロバイダーの設定、サポート用のシステムプロンプト、安定したデコードパラメーターを指定して `support-triage` を作成します。モデルは JSON Schema 出力に対応している必要があります。プリセットが各リクエストとどのようにマージされるかは[プリセット](../guides/presets)で説明しています。

</Step>
<Step title="インストールする">

```bash
npm install @phaseo/agent-sdk zod
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="エージェントを書く">

```ts triage-agent.ts
import { z } from "zod";
import { AgentGatewayError, createAgent, createGatewayAgentClient } from "@phaseo/agent-sdk";

const SupportTriageDecision = z
  .object({
    queue: z.enum(["billing", "reliability", "product", "security"]),
    severity: z.enum(["low", "medium", "high"]),
    needsHumanReview: z.boolean(),
    summary: z.string().min(1),
  })
  .strict();
type SupportTriageDecision = z.infer<typeof SupportTriageDecision>;

// `preset` は毎ターン、モデル `@support-triage` になります。
const supportTriageAgent = createAgent<string, SupportTriageDecision>({
  id: "support-triage-agent",
  preset: "support-triage",
  maxSteps: 3,
  parseOutput: (text) => JSON.parse(text),
  outputSchema: SupportTriageDecision,
  humanReview: ({ parsedOutput }) =>
    parsedOutput?.needsHumanReview
      ? { reason: "support_triage_review_required", payload: parsedOutput }
      : null,
});

const client = createGatewayAgentClient({
  clientOptions: { apiKey: process.env.PHASEO_API_KEY! },
  responseFormat: {
    type: "json_schema",
    name: "support_triage_decision",
    schema: {
      type: "object",
      properties: {
        queue: { type: "string", enum: ["billing", "reliability", "product", "security"] },
        severity: { type: "string", enum: ["low", "medium", "high"] },
        needsHumanReview: { type: "boolean" },
        summary: { type: "string" },
      },
      required: ["queue", "severity", "needsHumanReview", "summary"],
      additionalProperties: false,
    },
  },
  plugins: [{ id: "response-healing", mode: "strict" }],
});

try {
  const result = await supportTriageAgent.run({
    input: "Customer says webhook deliveries failed overnight and asks whether data was lost.",
    client,
    modelRetry: { maxRetries: 2, backoffMs: 250 },
    onEvent(event) {
      if (event.type === "model.retrying") console.log("retrying", event.attempt, event.error);
    },
  });

  if (result.run.status === "waiting_for_human") {
    // `result` を保存し、担当者がレビューしたら続行します。
    console.log("Needs review:", result.run.pause?.payload);
  } else {
    console.log(result.output);
  }
} catch (error) {
  if (error instanceof AgentGatewayError) {
    console.error("Gateway request failed", {
      status: error.status,
      requestId: error.requestId,
      generationId: error.generationId,
      reason: error.reason,
      providerFailureDiagnostics: error.providerFailureDiagnostics,
      routingDiagnostics: error.routingDiagnostics,
    });
  }
  throw error;
}
```

</Step>
<Step title="実行する">

```bash
npx tsx triage-agent.ts
```

</Step>
</Steps>

一時停止したケースを完了するには、レビュー担当者の判断を付けて続行します。

```ts
const continued = await supportTriageAgent.continueRun({
  run: storedResult,
  client,
  humanInput: "Approved. Finalize the triage decision.",
});
```

## 動作を確認する

通常のチケットとリスクの高いチケットを 1 件ずつ実行し、次の点を確認します。

- **設定 → 利用状況 → ログ** で、リクエストのモデルにプリセットが使われたことが表示されます。
- リスクの高いケースは `waiting_for_human` で終わり、判定は `pause.payload` に入ります。
- 再試行されたモデル呼び出しはステップに `modelAttempts` として記録され、再試行のたびに `model.retrying` がログに出力されます。
- ブロックされたリクエストは `requestId` と `reason` とともにログに記録され、ログ内の同じリクエストでその理由を確認できます。

## Gateway の失敗を見える状態に保つ

エージェントのコールバック内でエラーを握りつぶさないでください。`AgentGatewayError` は境界で捕捉し、その ID をログに記録してから再スローします。実行が失敗すると、保存された状態の `run.errorDetails` と `steps[n].errorDetails` に同じ詳細が残るため、例外が消えた後でも、後続の復旧ジョブがそれを読み取れます。

これらの失敗はエージェントではなく Gateway のポリシーから発生するため、ログ内のリクエストを確認してください。

| 失敗 | 表示される場所 |
| --- | --- |
| ガードレールがリクエストをブロックした | リクエストの **ガードレールの適用** セクション |
| プリセットの許可モデルがそのモデルを拒否した | キーワード `preset_model_not_allowed` を含む `validation_error` |
| プロバイダーの認証情報や有効化の設定により、使えるプロバイダーがない | `providerFailureDiagnostics` と **ルーティングの可観測性** |
| 修復でスキーマに合った JSON を生成できない | プラグイン記録、続いて `outputSchema` からの `AgentSchemaValidationError` |
