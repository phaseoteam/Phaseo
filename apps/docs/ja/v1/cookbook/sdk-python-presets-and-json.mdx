Python から JSON Schema 付きでダッシュボードのプリセットを呼び出し、回答を検証して、デバッグに必要な ID をログに記録します。完成すると、`"model": "@release-summary"` を送り、`{"summary": ..., "risk_level": ...}` を受け取り、そのリクエストのプロバイダーとプラグインの詳細を表示するスクリプトが 1 つできます。

このスクリプトは、プリセットとスキーマを自分のものに置き換えれば本番環境で使えます。検証の手順は残してください。修復が直すのは構文であり、内容ではありません。

## 作成する

<Steps>
<Step title="プリセットを作成する">

**設定 → プリセット** で、すべての呼び出し元が共有するシステムプロンプト、モデルまたは許可するモデル、プロバイダーの優先設定、推論の設定、`temperature` を持つ `release-summary` を作成します。こうすると、Python のコードは変化する部分だけを送ればよくなります。プリセットがリクエストとどう統合されるかは[プリセット](../guides/presets)で説明しています。

</Step>
<Step title="SDK をインストールする">

```bash
pip install phaseo
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="スクリプトを書く">

```python release_summary.py
import json
import os

from phaseo import Phaseo

# クライアントを 1 つ作成して再利用します。
gateway = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

SCHEMA = {
    "type": "object",
    "properties": {
        "summary": {"type": "string"},
        "risk_level": {"type": "string", "enum": ["low", "medium", "high"]},
    },
    "required": ["summary", "risk_level"],
    "additionalProperties": False,
}


def output_text(response: dict) -> str:
    return "".join(
        part.get("text", "")
        for item in response.get("output", [])
        if item.get("type") == "message"
        for part in item.get("content", [])
        if part.get("type") == "output_text"
    )


def validate(payload: dict) -> dict:
    if set(payload) != {"summary", "risk_level"}:
        raise ValueError(f"unexpected keys: {sorted(payload)}")
    if not isinstance(payload["summary"], str) or not payload["summary"]:
        raise ValueError("summary must be a non-empty string")
    if payload["risk_level"] not in ("low", "medium", "high"):
        raise ValueError("risk_level must be low, medium or high")
    return payload


response = gateway.generate_response(
    {
        "model": "@release-summary",
        "input": "Summarize the last 24 hours of deployment activity.",
        "text": {
            "format": {
                "type": "json_schema",
                "name": "release_summary",
                "strict": True,
                "schema": SCHEMA,
            }
        },
        "plugins": [{"id": "response-healing"}],
        "meta": True,
    }
)

if response.get("status") != "completed":
    raise RuntimeError(f"response {response.get('id')} ended as {response.get('status')}")

payload = validate(json.loads(output_text(response)))
meta = response.get("meta", {})

print("response_id:", response.get("id"))
print("model:", response.get("model"))
print("selected_provider:", meta.get("routing", {}).get("selected_provider"))
print("plugin_executions:", meta.get("plugin_executions"))
print(payload)
```

| フィールド | 動作 |
| --- | --- |
| `"model": "@release-summary"` | プリセットを使います。別の `preset` フィールドはありません。 |
| `text.format` | この JSON Schema を要求します。Chat Completions では `response_format` に入れます。[構造化出力](../guides/structured-outputs)を参照してください。 |
| `plugins` | ほぼ有効な JSON を修復します。[応答の修復](./response-healing-for-structured-json)を参照してください。 |
| `meta: true` | レスポンスに `meta.routing` と `meta.plugin_executions` を追加します。 |

</Step>
<Step title="実行する">

```bash
python release_summary.py
```

</Step>
</Steps>

## 動作を確認する

スクリプトは、レスポンス ID、応答したモデルとプロバイダー、プラグインの記録、そして `summary` と `low`・`medium`・`high` のいずれかを持つ dict を表示します。**設定 → 使用量 → ログ** でレスポンス ID を検索すると、同じリクエストをルーティングの詳細とともに確認できます。

プリセットで許可されていないモデルは、`validation_error`（キーワード `preset_model_not_allowed`）で失敗します。`validate()` からの `ValueError` は、JSON は解析できたものの内容が誤っていたことを意味します。再試行を追加するのではなく、スキーマやプロンプトを厳しくしてください。

## 上書きする前にデバッグする

リクエストが想定と異なるルーティングをした場合は、ログでリクエストを開き、**ルーティングの可観測性** とプラグインの記録を読み、何が起きたかがログで分かってからプリセットを変更してください。1 件のリクエストにインラインの上書きを重ねると、プリセットを使う意味がなくなります。ある呼び出し元に本当に別の動作が必要なら、その呼び出し元専用のプリセットを用意してください。
