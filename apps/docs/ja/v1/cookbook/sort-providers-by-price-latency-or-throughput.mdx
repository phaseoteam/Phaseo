1 件のリクエストに `provider.sort` を設定すると、既定のバランス型の順位付けではなく、`price`、`latency`、`throughput` のいずれかで同じモデルのプロバイダーを順位付けします。完成すると、使う言語でのリクエストができ、並べ替えでどのプロバイダーが選ばれたかをレスポンスとログで確認できます。

これらのリクエストの形は本番環境で使えます。ワークスペースの既定値、`routing.mode`、モデルのサフィックス `:cheap`・`:fast`・`:nitro` については、[プロバイダーの順位付け方法を選ぶ](../guides/routing-and-fallbacks#choose-how-providers-are-ranked)で説明しています。

| `sort` | 用途 |
| --- | --- |
| `price` | テールレイテンシよりコストが重要なバッチ処理やバックグラウンド処理 |
| `latency` | チャット、コパイロット、人が介在するツール |
| `throughput` | 出力の長い大量生成やバックフィル |

`meta: true` を指定すると、並べ替えで選ばれたプロバイダーである `meta.routing.selected_provider` が追加されます。

## 各並べ替えの重み付け

並べ替えはプロバイダーのスコアの重みを変えるだけで、他の指標を外すわけではありません。そのため、安くても信頼性の低いプロバイダーが選ばれないこともあります。

| 並べ替え | 価格 | 成功率 | レイテンシの中央値 | テールレイテンシ | スループット |
| --- | --- | --- | --- | --- | --- |
| `price` | 0.40 | 0.25 | 0.15 | 0.10 | 0.05 |
| `latency` | 0 | 0.25 | 0.55 | 0.15 | 0.02 |
| `throughput` | 0 | 0.20 | 0.20 | 0.10 | 0.40 |

レイテンシとスループットは、各プロバイダーについて Phaseo が最新に計測した値です。

## 承認済みの範囲内で並べ替える

並べ替えは、候補が受け入れられるプロバイダーだけになっているときに最も効果を発揮します。`only` を追加すると、その範囲内で並べ替えが行われます。

```json
{
  "model": "anthropic/claude-sonnet-5.5",
  "input": "Summarize the incident in one sentence.",
  "provider": {
    "only": ["anthropic", "google-vertex"],
    "sort": "latency"
  }
}
```

`only`、`order`、`ignore` については[プロバイダーを固定または除外する](./pin-or-ignore-providers-per-request)で説明しています。

## 順位付けを確認する

**設定 → 使用量 → ログ** でリクエストを開き、**ルーティングの可観測性** を展開します。検討されたプロバイダー、その順位、各スコアの要素と重みが一覧表示されるため、並べ替えが想定どおりに動いたかを確認できます。同じ並べ替えを多くの呼び出し元に適用するには、[プリセット](./preset-rollout-and-routing-debug)にまとめてください。
