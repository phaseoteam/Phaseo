回答する前に Phaseo 経由でウェブを検索し、情報源付きのリサーチブリーフを厳密な JSON で返す TypeScript エージェントを作成します。完成すると、指定した任意のトピックについて検証済みの `{ topic, summary, sources }` オブジェクトを出力するスクリプトが 1 つできます。

このスクリプトは 1 回だけのリサーチであれば本番環境でそのまま使えます。検索結果は信頼できないウェブコンテンツです。以下のスキーマチェックで不正な形式の出力は止められますが、情報源に基づいて行動する前に内容を確認してください。パッケージ化した版は `packages/sdk/agent-sdk-ts/examples/research-brief-agent.ts` にあります。

## 作成する

<Steps>
<Step title="インストールする">



```bash yarn

```

```bash bun

```
</CodeGroup>

```bash
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="エージェントを書く">

```ts research-agent.ts
import { z } from "zod";
import { createAgent, createGatewayAgentClient } from "@phaseo/agent-sdk";

// ログの 1 行で読めるくらいの小ささにします。
const ResearchBrief = z
  .object({
    topic: z.string(),
    summary: z.string().min(1),
    sources: z.array(z.object({ title: z.string(), url: z.string().url() }).strict()).min(1),
  })
  .strict();
type ResearchBrief = z.infer<typeof ResearchBrief>;

const researchBriefAgent = createAgent<string, ResearchBrief>({
  id: "research-brief-agent",
  model: "openai/gpt-6-astra",
  instructions:
    "Research the user's topic with web search and return a concise JSON brief with cited sources.",
  maxSteps: 4,
  parseOutput: (text) => JSON.parse(text),
  outputSchema: ResearchBrief,
});

const client = createGatewayAgentClient({
  clientOptions: { apiKey: process.env.PHASEO_API_KEY! },
  // Gateway がモデルに要求する JSON Schema です。
  responseFormat: {
    type: "json_schema",
    name: "research_brief",
    schema: {
      type: "object",
      properties: {
        topic: { type: "string" },
        summary: { type: "string" },
        sources: {
          type: "array",
          items: {
            type: "object",
            properties: { title: { type: "string" }, url: { type: "string" } },
            required: ["title", "url"],
            additionalProperties: false,
          },
          minItems: 1,
        },
      },
      required: ["topic", "summary", "sources"],
      additionalProperties: false,
    },
  },
  // ほぼ正しい JSON を修復します。
  plugins: [{ id: "response-healing" }],
  // 検索は Phaseo が実行し、クエリはモデルが書きます。
  gatewayTools: [{ type: "phaseo:web_search", parameters: { max_results: 5 } }],
  // 回答する前に必ず検索します。
  toolChoice: "phaseo:web_search",
  webSearchOptions: { search_context_size: "high" },
});

const result = await researchBriefAgent.run({
  input: "Summarize the latest browser automation support patterns for coding agents.",
  client,
  onEvent(event) {
    console.log(event.type, event.runId);
  },
});

console.log(result.output);
```

| クライアントオプション | 役割 |
| --- | --- |
| `responseFormat` | 出力スキーマを明示的に保ちます |
| `plugins` | ほぼ正しい JSON のための[レスポンス修復](./response-healing-for-structured-json) |
| `gatewayTools` | `phaseo:web_search` を追加します。パラメーターは[ウェブ検索ガイド](../guides/server-tools/web-search)に記載されています |
| `toolChoice` | 常に根拠に基づく必要があるワークフローで、検索を強制します |
| `webSearchOptions` | 結果の量を調整する検索エンジン向けの検索設定 |

</Step>
<Step title="実行する">

```bash
npx tsx research-agent.ts
```

## 動作を確認する

スクリプトは、少なくとも 1 つの情報源 URL を含むブリーフを出力します。次に **設定 → 利用状況 → ログ** でリクエストを開き、以下を確認します。

- **ウェブ検索の可観測性** に、マネージド検索、結果、引用が表示されます。
- プラグイン記録では、JSON の修復が必要だった場合にだけ `response-healing` が `applied` と表示されます。
- レスポンスはスキーマに一致しています。一致しない場合、実行は `AgentSchemaValidationError` で失敗します。

検索が実行されなかった場合については、[ウェブ検索をデバッグする](./web-search-debugging)で説明しています。

## 別の方法を使う場合

このパターンは、モデルが自ら根拠を集め、呼び出し側が型付きの JSON を必要とする 1 回だけのリサーチに適しています。URL がすでにわかっている場合は [`phaseo:web_fetch`](./tool-grounding-with-web-fetch) を、ウェブよりも自社のデータが必要な場合は[ローカルツールのエージェント](./agent-sdk-durable-loop)を使ってください。契約が緩く、スキーマを使うと省ける手間よりも増える手間のほうが大きい場合は、プレーンテキストの出力を使ってください。
