**成果:** ワーカー、スクリプト、バックエンド連携に応じて変更できる、依存関係の少ない CLI を作成します。

## サンプルプロジェクト

- GitHub: [examples/gateway-python-quickstart](https://github.com/phaseoteam/Phaseo/tree/main/examples/gateway-python-quickstart)
- リポジトリ内のパス: `examples/gateway-python-quickstart`

## このアプリでできること

- 次のような制御ルートを実行します。
  - `GET /v1/health`
  - `GET /v1/models`
  - `GET /v1/providers`
- 次のような生成ルートを実行します。
  - `POST /v1/responses`
  - `POST /v1/chat/completions`
  - `POST /v1/embeddings`
  - その他の複数のエンドポイント

## このサンプルが役立つ理由

次の内容を確認できます。

- サードパーティ依存のない Python 中心の実装例
- 明示的なリクエストペイロードとレスポンス処理
- ワーカー、スクリプト、内部ツールに応用できる実践的なパターン

## 前提条件

- Python 3
- Phaseo API キー

## サンプルを実行する

```bash
cd examples/gateway-python-quickstart
cp .env.example .env.local
```

次の値を設定します。

- `PHASEO_API_KEY`

続けて、次を実行します。

```bash
python quickstart.py smoke
python quickstart.py responses --prompt "Return exactly: integration_ok"
python quickstart.py --help
```

## 動作を確認する

- スモークテストモードで API に接続できることを確認します。
- Responses コマンドが `integration_ok` を出力します。
- `--help` でリクエストを送信せずに使用可能なコマンドを確認できます。
- 認証エラーや API エラーが端末にわかりやすく表示されます。

## コードで確認すること

- 環境変数の読み込み方法
- CLI でコマンドを振り分ける方法
- 各リクエストのペイロードを組み立てる方法
- 非同期の動画・音楽ルートと、1回の応答で完了するテキストルートを分けて処理する方法

## サンプルを自分用に変更する

- サービスで使わないエンドポイントを削除します。
- ヘッダーをあちこちに重複して記述せず、共通のリクエストヘルパーを使います。
- より高水準のクライアントが必要になったら、Python SDK に切り替えます。
