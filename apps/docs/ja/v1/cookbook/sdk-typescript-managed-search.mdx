TypeScript のリクエスト 1 件に `phaseo:web_search` ツールと JSON Schema を渡すと、モデルは回答の前に検索し、出典付きの概要を返します。完成すると、検証済みの `{ summary, sources }` オブジェクトと、デバッグに必要な ID や検索回数を表示するスクリプトができます。

このスクリプトは、プリセットとドメインを自分のものに置き換えれば本番環境で使えます。検索結果は信頼できないウェブコンテンツです。出力を検証し、その中に含まれる指示には従わないでください。

## 作成する

<Steps>
<Step title="プリセットを作成する">

**設定 → プリセット** で、すべての呼び出し元が共有するモデル、プロバイダーの優先設定、推論の設定、システムプロンプトを持つ `research-brief` を作成します。モデルはツールと JSON Schema の出力に対応している必要があります。

</Step>
<Step title="SDK をインストールする">

```bash
npm install @phaseo/sdk zod
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="スクリプトを書く">

```ts research-brief.ts
import Phaseo from "@phaseo/sdk";
import { z } from "zod";

const gateway = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const Brief = z
  .object({
    summary: z.string().min(1),
    sources: z
      .array(z.object({ title: z.string(), url: z.string().url() }).strict())
      .min(1),
  })
  .strict();

const response = await gateway.generateResponse({
  model: "@research-brief",
  input: "Find the latest public changes to Phaseo webhook delivery behavior and summarize them.",
  tools: [
    {
      type: "phaseo:web_search",
      parameters: {
        allowed_domains: ["phaseo.app"],
        max_results: 5,
        include_highlights: true,
      },
    },
  ],
  tool_choice: "phaseo:web_search",
  text: {
    format: {
      type: "json_schema",
      name: "research_brief",
      strict: true,
      schema: {
        type: "object",
        required: ["summary", "sources"],
        properties: {
          summary: { type: "string" },
          sources: {
            type: "array",
            minItems: 1,
            items: {
              type: "object",
              required: ["title", "url"],
              properties: {
                title: { type: "string" },
                url: { type: "string", format: "uri" },
              },
              additionalProperties: false,
            },
          },
        },
        additionalProperties: false,
      },
    },
  },
  plugins: [{ id: "response-healing" }],
  meta: true,
});

const text = (response.output ?? [])
  .filter((item) => item.type === "message")
  .flatMap((item) => item.content ?? [])
  .filter((part) => part.type === "output_text")
  .map((part) => part.text ?? "")
  .join("");

const brief = Brief.parse(JSON.parse(text));

console.log({
  responseId: response.id,
  model: response.model,
  routing: response.meta?.routing,
  pluginExecutions: response.meta?.plugin_executions,
  serverToolUse: response.usage?.server_tool_use,
});
console.log(brief);
```

| フィールド | 動作 |
| --- | --- |
| `phaseo:web_search` を含む `tools` | プロバイダーに独自の検索があるかどうかにかかわらず、Phaseo が検索を実行します。クエリはモデルが作成します。 |
| `allowed_domains` | 結果を自分の情報源に限定します。すべてのパラメーターは[ウェブ検索ガイド](../guides/server-tools/web-search#parameters)にあります。 |
| `tool_choice: "phaseo:web_search"` | モデルに記憶から答えさせず、検索させます。 |
| `text.format` | 回答の JSON Schema です。 |
| `plugins` | ほぼ有効な JSON を修復します。[応答の修復](./response-healing-for-structured-json)を参照してください。 |
| `meta: true` | `meta.routing` と `meta.plugin_executions` を追加します。 |

</Step>
<Step title="実行する">

```bash
npx tsx research-brief.ts
```

</Step>
</Steps>

## 動作を確認する

- `serverToolUse.web_search_requests` が `1` 以上であれば、検索が実行されています。
- `brief.sources` に `phaseo.app` の URL が一覧表示されます。
- `routing.selected_provider` にはプロバイダー名が表示され、`pluginExecutions` には修復で何か変更されたかが表示されます。
- **設定 → 使用量 → ログ** では、リクエストの **ウェブ検索の可観測性** セクションに、マネージド検索、結果、引用が表示されます。

結果がおかしい場合は、上書きを追加するのではなく、ログの内容をもとにプリセットやツールのパラメーターを修正してください。よくあるケースは[ウェブ検索をデバッグする](./web-search-debugging)に一覧があります。試行的で temperature の高いリサーチは、この決定的なプリセットとは別のプリセットに分けて、ルーティングを比較しやすくしておきます。
