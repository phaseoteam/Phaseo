1 つのローカルツールで情報を調べ、その回答を厳密な JSON で返す Python エージェントを実行します。完成すると、`result.output` が自由形式の文章ではなく、`summary` と `recommendation` を持つ検証済みの `PolicySummary` オブジェクトになるスクリプトが 1 つできます。

ツールは固定のサンプルデータを返すため、このスクリプトは例示用です。実際には独自の検索に置き換えてください。オーケストレーションを自分で管理し、小さく決定的なツールのセットを持つ Python worker に適しています。

## 作成する

<Steps>
<Step title="インストールする">

<CodeGroup>
```bash pip
pip install phaseo-agent-sdk
```

```bash uv
uv add phaseo-agent-sdk
```
</CodeGroup>

`phaseo-agent-sdk` をインストールすると、`phaseo` クライアントと Pydantic も一緒にインストールされます。

```bash
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="エージェントを書く">

```python extract.py
import json
import os

from pydantic import BaseModel, ConfigDict

from phaseo_agent import AgentTool, create_agent, create_gateway_agent_client, define_tool

POLICY_SLUGS = {"presets", "routing", "guardrails"}


class PolicySummary(BaseModel):
    model_config = ConfigDict(extra="forbid")
    summary: str
    recommendation: str


def check_lookup_input(value):
    # モデルが生成した引数です。既知のスラッグ以外は拒否します。
    if not isinstance(value, dict) or set(value) != {"slug"} or value["slug"] not in POLICY_SLUGS:
        raise ValueError(f"slug must be one of {sorted(POLICY_SLUGS)}")
    return value


lookup_policy = define_tool(
    AgentTool(
        id="lookup-policy",
        description="Look up one internal policy by slug.",
        parameters={
            "type": "object",
            "properties": {"slug": {"type": "string", "enum": sorted(POLICY_SLUGS)}},
            "required": ["slug"],
            "additionalProperties": False,
        },
        input_schema=check_lookup_input,
        execute=lambda input, ctx: {
            "slug": input["slug"],
            "summary": "Presets centralize routing, prompts, and caching defaults.",
        },
    )
)

agent = create_agent(
    {
        "id": "policy-extractor",
        "model": "openai/gpt-6-astra",
        "instructions": "Use tools when needed and return JSON with summary and recommendation.",
        "tools": [lookup_policy],
        "max_steps": 4,
        "parse_output": json.loads,
        "output_schema": PolicySummary,
    }
)

# Python クライアントは PHASEO_API_KEY を自動では読み取りません。明示的に渡してください。
client = create_gateway_agent_client(
    client_options={"api_key": os.environ["PHASEO_API_KEY"]},
    response_format={
        "type": "json_schema",
        "name": "policy_summary",
        "schema": {
            "type": "object",
            "properties": {
                "summary": {"type": "string"},
                "recommendation": {"type": "string"},
            },
            "required": ["summary", "recommendation"],
            "additionalProperties": False,
        },
    },
    plugins=[{"id": "response-healing"}],
)

result = agent.run(input="Look up our presets policy and recommend when to use it.", client=client)

print(result.run.status)
print(result.output)
```

| 要素 | 役割 |
| --- | --- |
| `parameters` | ツールの引数としてモデルに見える JSON Schema |
| `input_schema` | `execute` の実行前に引数を確認します。不正な呼び出しは実行を失敗させます |
| `response_format` | 毎ターン、この JSON Schema を Gateway に要求します |
| `parse_output` と `output_schema` | 最終テキストをパースし、`PolicySummary` として検証します |

</Step>
<Step title="実行する">

```bash
python extract.py
```

</Step>
</Steps>

## 動作を確認する

- スクリプトは `completed` を出力し、続いて両方のフィールドが埋まった `PolicySummary` を出力します。
- **設定 → 利用状況 → ログ** では、最初のモデルターンに `{"slug": "presets"}` を指定した `lookup-policy` の呼び出しが表示されます。
- モデルに一致しない出力は、半分だけ埋まったオブジェクトを返す代わりに `Invalid agent output` で失敗します。

ツールを使わない 1 回だけの構造化出力には、[Python SDK を直接](./sdk-python-presets-and-json)呼び出してください。状態、承認、ストリーミングについては [Python Agent SDK リファレンス](../sdk-reference/agent/usage)で説明しています。
