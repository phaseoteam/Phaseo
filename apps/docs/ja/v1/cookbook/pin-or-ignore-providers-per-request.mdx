title: "リクエストごとにプロバイダーを固定または除外する"
icon: "pin"
description: "リクエスト単位のプロバイダー設定を使って、優先順を指定したり、候補を絞ったり、プロバイダーを候補から外したりします。"
---

1 件のリクエストに `provider` オブジェクトを追加すると、ワークスペースの既定値やプリセットを変えずに、そのリクエストを処理するプロバイダーを変更できます。完成すると、優先順を指定する、リクエストを許可リストの中に収める、特定のプロバイダーをスキップする、といったことができ、どのプロバイダーが応答したかをレスポンスで確認できます。

これらのリクエストの形は本番環境で使えます。プロバイダーのスラッグは実在する例です。使うモデルを提供しているプロバイダーは、そのモデルのページで確認してください。

| フィールド | 動作 | 例 |
| --- | --- | --- |
| `order` | これらのプロバイダーを先に試し、その後に対象となる残りの候補を試します | `["anthropic-us", "anthropic"]` |
| `only` | リクエストをこの一覧の中に収めます | `["openai", "openai-eu"]` |
| `ignore` | このリクエストからこれらのプロバイダーを外します | `["novita"]` |
| `sort` | 残った候補を `price`、`latency`、`throughput` で順位付けします | `"price"` |

プロバイダーを 1 つだけに限定し、プロバイダー間のフォールバックを無効にするには、代わりにモデル ID の前にプロバイダーを付けます。[1 つのプロバイダーに固定する](../guides/routing-and-fallbacks#pin-one-provider)を参照してください。

## 決まった順序でプロバイダーを試す

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-sonnet-5.5",
    "input": "Write a concise launch summary.",
    "provider": {
      "order": ["anthropic-us", "anthropic"]
    },
    "meta": true
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "anthropic/claude-sonnet-5.5",
  input: "Write a concise launch summary.",
  provider: {
    order: ["anthropic-us", "anthropic"],
  },
  meta: true,
});

console.log(response.meta?.routing); // { selected_provider: "anthropic-us", ... }
```

```python Python
import os

from phaseo import Phaseo

client = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

response = client.generate_response(
    {
        "model": "anthropic/claude-sonnet-5.5",
        "input": "Write a concise launch summary.",
        "provider": {
            "order": ["anthropic-us", "anthropic"],
        },
        "meta": True,
    }
)

print(response["meta"]["routing"]["selected_provider"])
```
</CodeGroup>

`meta: true` を指定するとレスポンスに `meta.routing.selected_provider` が追加されるため、ログを開かずに結果を確認できます。

## リクエストを許可リストの中に収める

`only` を送り、必要に応じて `sort` も送ると、その一覧の中で順位付けされます。

```json
{
  "model": "openai/gpt-5.6-luna",
  "input": "Extract the action items.",
  "provider": {
    "only": ["openai", "openai-eu"],
    "sort": "price"
  }
}
```

一覧のどのプロバイダーもモデルを提供していない場合、リクエストは一覧の外に出ずに失敗します。

## 特定のプロバイダーをスキップする

プロバイダーの品質が低下しているときや、別の経路をテストしている間は `ignore` を送ります。

```json
{
  "model": "meta/llama-4-maverick",
  "input": "Summarize the transcript.",
  "provider": {
    "ignore": ["novita"]
  }
}
```

## 組み合わせる

候補の範囲には `only`、その中での優先順には `order`、残りには `sort` を使います。次の例はリクエストを Google Vertex に限定し、EU リージョンを最初に試し、その後はレイテンシで順位付けします。

```json
{
  "model": "anthropic/claude-sonnet-5.5",
  "input": "Summarize the incident in one sentence.",
  "provider": {
    "only": ["google-vertex", "google-vertex-eu"],
    "order": ["google-vertex-eu"],
    "sort": "latency"
  }
}
```

## 送信先を確認する

**設定 → 使用量 → ログ** でリクエストを開き、**ルーティングの可観測性** を展開します。順位付けの前に除外されたプロバイダーとその理由、およびスコア付きの順位付けされた候補が一覧表示されます。各フィールドの説明は[ルーティングの判断を説明する](../guides/routing-and-fallbacks#explain-a-routing-decision)を参照してください。

リクエスト単位のルールは、一時的な上書き、1 つの呼び出し元に固有の上書き、1 つのユーザーフローに結びついた上書きに使います。同じルールが複数のサービスに現れたら、[プリセット](../guides/presets)に移します。プリセットでは、フォールバックが使えるプロバイダーも制限されます。順位付けを比較するには、[プロバイダーを並べ替える](./sort-providers-by-price-latency-or-throughput)を参照してください。
