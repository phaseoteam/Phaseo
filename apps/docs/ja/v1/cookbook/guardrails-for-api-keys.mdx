title: "API キーにガードレールを適用する"
icon: "shield-check"
description: "API キーにガードレールを適用し、展開前に動作をテストして、アクティビティ画面でブロック、マスキング、フラグを確認します。"
---

**設定 → ガードレール** でガードレールを 1 つ作成し、リスクの低い API キーに適用して、ログで想定どおりに動いていることを確認してから適用範囲を広げます。完成すると、そのキーは許可したプロバイダーとモデルにだけ到達でき、プロンプトはモデルに届く前にプロンプトインジェクションと機微情報のスキャンを受けます。

これはダッシュボードでの手順です。同じポリシーは[ガードレール API](../api-reference/endpoint/guardrails-create) でスクリプト化することもできます。

```mermaid
flowchart LR
  ws["ワークスペースのプライバシールール"] --> gr["ガードレール: データ処理"]
  gr --> prov["プロバイダーの許可リストまたはブロックリスト"]
  prov --> mdl["モデルの許可リスト"]
  mdl --> scan["プロンプトインジェクションと機微情報のスキャン"]
  scan -->|"フラグ、マスキング、またはブロック"| route["リクエストをルーティング"]
```

ワークスペースのプライバシールールが最初に適用され、ガードレールはそれをさらに絞り込むことしかできません。ガードレールは支出を制限しません。支出を制限するには、キーに上限を設定するか、[ワークスペースの予算](../api-reference/limits#key-limits-and-budgets)を使ってください。

## 展開する

<Steps>
<Step title="ガードレールを作成する">

**設定 → ガードレール → 新規ガードレール** を開きます。複数のキーで再利用できるように、チーム名ではなく `eu-models-pii-redact` のように適用する内容に合わせて名前を付けます。

内容のチェックより先に、ルートへのアクセスを設定します。

| 設定 | 選択肢 |
| --- | --- |
| **プロバイダーモード** | すべてのプロバイダーを許可、選択したプロバイダーのみ許可、または選択したプロバイダー以外をすべて許可 |
| **モデルモード** | すべてのモデルを許可、または選択したモデルのみ許可（プロバイダーの絞り込み後に適用） |
| **データ処理** | ZDRのみ、および入力を学習に使う可能性がある無料または有料のエンドポイントを対象に残すかどうか |

よくある最初のポリシーは、信頼性の低いプロバイダーをブロックし、キーが到達すべき本番用のモデルだけを正確に許可するものです。プレビューで、どのプロバイダーとモデルがルーティング可能なまま残るか、そして **のみ許可** が意図より狭くなっていないかを確認してください。

</Step>
<Step title="内容のチェックを追加する">

**プロンプトインジェクション** は、ユーザーが提供した内容をよくあるインジェクションのパターンについてスキャンします。**機微情報** は、リクエストが Phaseo を出る前にデータを検出します。

| 検出対象 | マスキング後の表記 | レイテンシの増加 |
| --- | --- | --- |
| メールアドレス | `[EMAIL]` | なし |
| 電話番号 | `[PHONE]` | なし |
| 米国社会保障番号 | `[SSN]` | なし |
| クレジットカード番号 | `[CREDIT_CARD]` | なし |
| IP アドレス（IPv4） | `[IP_ADDRESS]` | なし |
| 人名 | `[PERSON_NAME]` | あり |
| 住所 | `[ADDRESS]` | あり |

各チェックには **フラグ**、**マスキング**、**ブロック** のいずれかのアクションがあります。プロンプトインジェクションは **フラグ** または **マスキング** から始め、誤検知を確認してから **ブロック** に切り替えてください。まずは高速な検出器を使います。独自のパターンは明示的な正規表現ルールとして追加します。

</Step>
<Step title="プレビューでテストする">

保存する前に、3 つの入力をプレビューで試します。無害なもの、明らかに止めるべきもの、本番の現実的なプロンプトの 3 つです。マスキング後のテキスト、ブロックか許可かの結果、そして無関係なものが一致していないことを確認します。

</Step>
<Step title="1 つのキーに適用する">

**キーに適用** で、ステージング用またはリスクの低いキーを選びます。ガードレールは作成中に適用することもできます。**メンバーに適用** を使うと、代わりにそのメンバーが作成する API キーに適用されます。ワークスペースのオーナーまたは管理者が割り当てたガードレールを、メンバーが編集したり外したりすることはできません。

</Step>
<Step title="適用状況を確認する">

キーを通して実際のリクエストを送り、次を確認します。

- **設定 → 使用量 → ガードレール** で、ブロック、マスキング、フラグの件数。
- **設定 → 使用量 → ログ** のリクエストの **ガードレールの適用** セクションで、作動したガードレールと検出器。
- **設定 → APIキー** の **ガードレール** 列で、ガードレールが適用されているキー。

</Step>
<Step title="適用範囲を広げる">

同じガードレールをより多くのキーに適用し、アクションを **フラグ** から **マスキング** や **ブロック** に強め、人名と住所の検出器はレイテンシが許容できる場合にだけ追加します。

</Step>
</Steps>

無効にしたガードレールは設定を保持しますが、適用はされません。キーに強制するのではなく呼び出し元の間でルーティングのルールを共有したい場合は、[プリセット](../guides/presets)を使ってください。
