---

リクエストの種類ごとに入力の目標値と出力の上限を決め、実際の使用量をそれと照らし合わせます。送受信するトークンはすべてレイテンシーとコストを増やし、出力の上限が小さすぎると回答が途中で切れます。

## リクエストに含まれるもの

| 部分 | 扱い | 注意点 |
| --- | --- | --- |
| システムと開発者の指示 | 入力 | 毎回のリクエストで繰り返される長い指示。[プロンプトキャッシュ](./prompt-caching.mdx)でキャッシュしてください。 |
| ユーザーの入力 | 入力 | 際限のない貼り付けやアップロード。 |
| 取得したコンテキスト（ドキュメント、検索結果、ツールの出力） | 入力 | トークンを増やし、回答を薄めてしまう関連性の低い文章。 |
| ツールのスキーマと関数の定義 | 入力 | 宣言したツールは、モデルが呼び出すかどうかにかかわらず入力としてカウントされます。 |
| 推論 | 出力 | 推論モデルは、回答する前に出力の上限の一部を使います。 |
| 回答 | 出力 | 回答や構造化出力を途中で切ってしまう上限。 |

## 推論が出力の上限を使い切った場合

推論モデルは、回答を生成する前に出力の上限をすべて使ってしまうことがあります。その場合もレスポンスは HTTP `200` で、生成された推論が含まれ、作り出された回答は含まれません。

| エンドポイント | 返される内容 |
| --- | --- |
| Chat Completions | `finish_reason: "length"` 付きの `reasoning_content` |
| Responses | `status: "incomplete"` 付きの推論出力アイテム |

通常の終了は、引き続き `stop`（Chat Completions）または `completed`（Responses）です。これらが頻繁に見られる場合は、出力の上限を引き上げるか、推論の強度を下げてください。

## ルートごとに予算を設定する

1. 検索の回答や長文の下書きなど、リクエストの種類ごとに入力の最大サイズを設定します。1 つの上限をすべてのエンドポイントにそのまま使い回さないでください。
2. その種類のリクエストが生成すべき最も長い回答に足りるだけの出力の余地を残します。
3. 大きなコンテキストは、重要度が最も低い文章から順に、送信前に削るか要約します。
4. `finish_reason: "length"` や不完全な JSON など、出力が途中で切れていないか確認し、切れていた場合は余地を増やしてリトライします。
5. 各レスポンスの `usage` にあるトークン数を継続的に追跡し、プロンプトの変化に合わせて上限を調整します。

出力の上限とサンプリングの関係については、[推論パラメーター](./inference-parameters.mdx)を参照してください。
