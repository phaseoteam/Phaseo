チーム、製品、環境ごとにワークスペースを作成すると、API キー、ルーティング設定、プリセット、ガードレール、管理アクセスを分けて管理できます。どのアカウントにも最初から個人用ワークスペースがあり、小規模なインテグレーションならそれで十分です。

ワークスペースを分けると、次のような場合に役立ちます。

- 開発、ステージング、本番環境の認証情報を分離する
- 製品や顧客プロジェクトを分ける
- 管理用インテグレーションが必要なリソースだけにアクセスできるようにする
- 異なるルーティング、プリセット、ガードレールのポリシーを適用する

ワークスペースによって料金が変わることはありません。使用量はすべて、[料金と請求](../pricing/tiers)に記載された標準の従量課金で請求されます。追加のワークスペースは、最初にクレジットを入金した後に使えるようになります。それまでは、作成しようとすると `403 workspace_upgrade_required` で失敗します。

## API でワークスペースを管理する

ワークスペースはダッシュボードまたは管理 API で管理します。API には[管理キー](../developers/management-api-keys)が必要です。通常の Gateway API キーは推論用で、これらのエンドポイントは呼び出せません。

| 操作 | エンドポイント | 権限 |
| --- | --- | --- |
| ワークスペースを一覧表示する | [`GET /workspaces`](../api-reference/endpoint/workspaces-list) | `workspaces:read` |
| ワークスペースを取得する | [`GET /workspaces/{id}`](../api-reference/endpoint/workspaces-get) | `workspaces:read` |
| ワークスペースを作成する | [`POST /workspaces`](../api-reference/endpoint/workspaces-create) | `workspaces:write` |
| ワークスペースを更新する | [`PATCH /workspaces/{id}`](../api-reference/endpoint/workspaces-update) | `workspaces:write` |
| ワークスペースを削除する | [`DELETE /workspaces/{id}`](../api-reference/endpoint/workspaces-delete) | `workspaces:delete` |

キーには必要な権限だけを付与してください。Phaseo はワークスペースのメンバーシップとロールも確認するため、権限だけで別のワークスペースにアクセスできることはありません。新しいワークスペースの `slug` は、小文字、数字、ハイフンで 1〜50 文字にする必要があります。

管理キーはサーバー側のシークレットストアに保存してください。ブラウザーのコード、デスクトップのログ、ソース管理、チャットには含めないでください。

<Note>
ワークスペースのエンドポイントはベータ版です。自動化は再試行しても安全なように作り、後続の変更を行う前に各レスポンスを確認してください。
</Note>

## ワークスペースの名前を変更する、または削除する

個人用（デフォルト）ワークスペースは、名前の変更も削除もできません。どちらも `400 bad_request` を返します。ほかのワークスペースを削除する前に、そのアクティブな API キーを削除するか移動し、存在しないワークスペースにリクエストが向かわないようにしてください。
