`stream: true` を設定すると、Gateway はモデルが書いている間、出力を Server-Sent Events（SSE）として送ります。ストリームが完了したといえるのは、正常な終了イベントが届いたときだけです。**再生** を押してストリームを見てから、**途中で失敗** に切り替えると、壊れたストリームがどう終わるかを確認できます。

## ストリーミングリクエストを送る

```bash
curl --no-buffer https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "input": "Say hello in one sentence.",
    "stream": true
  }'
```

本文を読む前に HTTP ステータスを確認してください。ストリーミングが始まる前に失敗したリクエストには、ストリームではなく通常の [JSON エラーレスポンス](../api-reference/errors.mdx)が返されます。Phaseo API キーはサーバーに保持し、そこからテキストを UI に転送してください。

## イベントを読む

エンドポイントごとにイベントの形式が異なります。

| エンドポイント | テキストが届く場所 | 正常な終了 | 失敗による終了 |
| --- | --- | --- | --- |
| [Responses](../api-reference/endpoint/responses.mdx) | `response.output_text.delta` | `response.completed` | `response.failed` または `error` |
| [Chat Completions](../api-reference/endpoint/chat-completions.mdx) | `choices[].delta` | `finish_reason` の後に `[DONE]` | `finish_reason` のない `error` フレーム |
| [Messages](../api-reference/endpoint/anthropic-messages.mdx) | `content_block_delta` | `message_stop` | `message_stop` のない `error` イベント |

イベントは空行で区切られますが、1 つのネットワークチャンクにはイベントの半分や複数のイベントが含まれることがあります。各イベントが揃うまでバッファリングしてから JSON として解析するか、これを自動で行う SDK のヘルパーを使ってください。

- TypeScript：`streamResponses()`、`streamChat()`、`streamMessages()`；Python：`stream_responses()`、`stream_chat()`、`stream_message()`（[使用ガイド](../sdk-reference/client/usage.mdx)）
- Vercel AI SDK：`@phaseo/ai-sdk-provider` と `streamText()`

`[DONE]` を送るのは Chat Completions だけです。ほかのエンドポイントではこれを待たないでください。

## ツール呼び出しをストリーミングする

ツール呼び出しは、テキストと同じように引数の差分として届きます。モデルがそれをストリーミングするかどうかは、モデルとプロバイダーによって異なります。呼び出しが完了するまで差分を集めてから、引数を解析、検証、認可してください。部分的な引数でツールを実行してはいけません。

結果を返す方法は[ツール呼び出しのパターン](./tool-calling-patterns.mdx)を、検証と承認は[ツールの安全性](./tool-calling-safety.mdx)を参照してください。

## ストリームをキャンセルする

`AbortSignal`（または HTTP クライアントの同等の仕組み）を渡し、ユーザーが停止したり切断したりしたときに中止します。処理に合った期限を設定してください。キャンセルしても、プロバイダーがすぐに止まることや、すでに生成された出力が無料になることは保証されません。

## 中断したストリームから復旧する

テキストが始まった後にストリームが失敗すると、正常な終了イベントではなく、上の表にある失敗のイベントで終わります。接続が閉じただけでは、回答が完了したことにはなりません。失敗したストリームの部分的な出力は、Phaseo では課金されません。

その場合は次のようにします。

1. 部分的なテキストは画面に残し、中断されたことを示します。
2. リクエスト ID または生成 ID、エンドポイント、モデルをログに残します。
3. 再試行を提示します。新しいリクエストは異なるテキストを返すことがあり、改めて課金されます。
4. すでに実行したツールを再実行したり、再試行した回答を部分的な回答に付け足したりしないでください。

テキストが届く前の失敗は、バックオフを入れて再試行し、[レート制限ヘッダー](../api-reference/limits.mdx)に従ってください。誰かが見る前に回答全体を検証する必要がある場合は、ストリーミングしないリクエストを使うか、サーバーでストリームをバッファリングしてください。
