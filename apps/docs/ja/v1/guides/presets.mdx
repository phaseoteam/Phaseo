プリセットは、1 つの用途に使うモデル、システムプロンプト、パラメーター、プロバイダールールを `@support-triage` のような名前で保存したものです。呼び出し元はその名前を `model` として送り、入力だけを渡します。Gateway はプロバイダーを選ぶ前に残りの設定を補います。

リクエストのフィールドを切り替えて、どちらの値が優先されるかを確認してください。

<PresetMergeExplorer locale="ja" />

ルールは次のとおりです。

- **パラメーターは不足分を補います。** プリセットの既定パラメーターは、リクエストが省略したフィールドにのみ適用されます。リクエストに値があれば、常にそちらが優先されます。
- **システムプロンプトは重ねられます。** プリセットのプロンプトが先に来ます。リクエストに独自のシステムプロンプトや `instructions` がある場合は、空行を挟んでその後に続きます。
- **リクエストのプロバイダー設定が優先されます。** リクエスト内の `provider.order` や `provider.max_price` などのフィールドは、そのフィールドについてプリセットの値を置き換えます。
- **許可リストは絞り込むだけで、広げることはありません。** プリセットのプロバイダー許可リストと除外リストはプロバイダー選択の前に適用されるため、フォールバックで使えるプロバイダーも制限されます。プリセットの許可モデル以外のモデルは、詳細キーワード `preset_model_not_allowed` を含む `validation_error` で失敗し、別のルートには回されません。

## プリセットを作成して使う

<Steps>
<Step title="プリセットを作成する">

**ダッシュボード -> 設定 -> プリセット** を開き、`support-triage` のようなスラッグでプリセットを作成します。すべての呼び出し元で共有する既定値だけを追加してください。

スクリプトから作成するには、管理キーを使って `POST /v1/presets` を呼び出します。

</Step>

<Step title="名前で呼び出す">

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "@support-triage",
    "input": "Customer says the invoice total is wrong."
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "@support-triage",
  input: "Customer says the invoice total is wrong.",
});
```

```python Python
from phaseo import Phaseo

client = Phaseo(api_key="YOUR_API_KEY")

response = client.generate_response({
    "model": "@support-triage",
    "input": "Customer says the invoice total is wrong.",
})
```
</CodeGroup>

</Step>

<Step title="適用された内容を確認する">

**Gateway -> 使用量** でリクエストを開くと、どのプリセットの既定値が適用され、どのプロバイダーが処理したかを確認できます。

</Step>

## プリセットに保存できる設定

| 設定 | 効果 |
| --- | --- |
| モデル | リクエストがプリセット名で送信されたときに使われます。 |
| 許可モデル | モデル ID、または `anthropic/*` のようなパターン。それ以外のモデルは拒否されます。 |
| システムプロンプト | すべてのリクエストの先頭に追加されます。 |
| [プロンプトテンプレート](./prompt-templates) | 各リクエストが値を埋める `{{variables}}` を含むメッセージ。 |
| 既定パラメーター | `temperature`、`top_p`、`max_tokens`、推論設定など。 |
| プロバイダールール | 許可リストと除外リスト、プロバイダーの順序、リージョン、価格の上限。 |

呼び出し元ごとのロジックはアプリケーション側に置き、ワークフローごとにプロンプト、ルーティング、キャッシュが異なる場合は別々のプリセットを使ってください。

## プリセットを名前で指定する

プリセットは `model` フィールドで送ります。[プロンプトテンプレート](./prompt-templates)がある場合は `prompt.id` でも送れます。`preset` という専用のフィールドはありません。

| 形式 | 解決される範囲 |
| --- | --- |
| `@support-triage` | API キーのワークスペース（非公開プリセットとワークスペースプリセット）。 |
| `@octavia/support-triage` | すべてのワークスペース（ユーザー `octavia` が公開した公開プリセット）。 |
| `@support-triage@v3` | その公開バージョン。 |
| `@support-triage@production` | `production` ラベルが指しているバージョン。 |

公開プリセットを公開するには、公開プロフィールを有効にし、ユーザー名を設定する必要があります。ユーザー名は Phaseo 全体で一意です。スラッグは 1 人の公開者の中で一意であれば十分です。スラッグは小文字に変換され、英字、数字、`-`、`_`、`.`、`:` を使えます。

## バージョンを管理してロールバックする

保存すると非公開の下書きが更新されます。**新しいバージョンを公開** を押すと、下書きが変更不可の番号付きリリースになり、以前のリリースもすべて残ります。

リリースラベルの形式を選びます。

| 形式 | 例 |
| --- | --- |
| 連番 | `v1`、`v2`、`v3` |
| セマンティックバージョニング | `1.2.0`、`2.0.0-beta.1`、`1.4.2+build.7` |
| 日付 | `2026.08.02`。同じ日の 2 回目のリリースは `2026.08.02.2` |

`production` のような名前付きラベルをバージョンに割り当て、ロールバックするときは以前のバージョンに戻します。[バージョンとラベル](/ja/v1/guides/prompt-templates#versions-and-labels)を参照してください。

スクリプトからは、管理キーを使って `POST /v1/presets/{id}/versions` で公開し、`PUT /v1/presets/{id}/labels/{label}` でラベルを移動します。CLI のサインインや Phaseo でサインインを使うアプリは、プリセットを読み取れますが変更はできません。

## マーケットプレイスのプリセットをフォークする

マーケットプレイスのプリセットのコピーは、コピーしたバージョンに固定されたままです。公開者が更新をリリースすると、コピーに通知が表示されます。適用しても変わるのは自分の下書きだけなので、自分で公開するまで本番には何も反映されません。

Phaseo は各フォークの元と系譜全体を記録するため、マーケットプレイスのページでは直接のフォークとすべての派生を分けて表示できます。

プリセットの回答に対する評価を集めるには、[プリセットのフィードバックを収集する](./preset-feedback)を参照してください。
