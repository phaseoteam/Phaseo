リクエストごとに `temperature`、`top_p`、出力の上限を設定して、多様性と再現性、長さとコストのバランスを調整します。モデルの[量子化](./quantization.mdx)が品質の上限を決め、これらのパラメーターは、その範囲内でモデルが次のトークンをどう選ぶかを決めます。

```json
{
  "model": "openai/gpt-6-astra",
  "messages": [{ "role": "user", "content": "Extract the invoice total as JSON." }],
  "temperature": 0.1,
  "top_p": 1,
  "max_tokens": 200
}
```

このページでは、各コントロールの役割と最初に設定する値を説明します。各エンドポイントでのフィールドの型、受け付ける値、既定値については、[パラメーターリファレンス](../api-reference/parameters.mdx)を参照してください。

## ランダム性を制御する

| パラメーター | 役割 | 備考 |
| --- | --- | --- |
| `temperature` | 全体のランダム性を調整します。高いほど多様になり、低いほど決定的になります。 | 通常、最初に調整するパラメーターです。 |
| `top_p` | 確率の合計が `top_p` になるまでの、最も可能性の高いトークンだけからサンプリングします。低いほど安全で焦点の絞られた出力になります。 | 中程度の temperature と組み合わせることがよくあります。 |
| `top_k` | 最も可能性の高い `k` 個のトークンだけからサンプリングします。低いほど引き締まった予測しやすい出力になります。 | すべてのプロバイダーで使えるわけではありません。 |
| `seed` | 乱数のシードを固定し、デバッグやテストで実行結果の再現性を高めます。 | プロバイダーがサポートしている場合のみ。 |

`temperature` と `top_p` はどちらもランダム性を変えるため、一度に 1 つずつ調整してください。低ビットに量子化されたモデルでランダム性を高くすると、出力が目に見えて不安定になることがあります。

## 繰り返しを減らす

| パラメーター | 役割 | 備考 |
| --- | --- | --- |
| `frequency_penalty` | トークンやフレーズの繰り返しを抑えます。 | 繰り返しのループを減らします。 |
| `presence_penalty` | 新しいトークンや話題を促します。 | より幅広い探索に役立ちます。 |
| `repetition_penalty` | 繰り返されたテキストにペナルティを与えます。 | 上記のペナルティと同じ目的です。正確な効果はプロバイダーとモデルによって異なります。 |

## 出力を制限して停止する

出力の上限は、Chat Completions と Anthropic Messages では `max_tokens`、Responses では `max_output_tokens` です。コストとレイテンシーに上限を設けますが、低すぎると回答が途中で切れます。`finish_reason: "length"` で早く停止したレスポンスは出力の上限に達したもので、モデルの失敗ではありません。

`stop` には出力を終了させるシーケンスを指定し、出力の区切りや解析を容易にします。各エンドポイントのフィールドについては、[出力の長さと停止](../api-reference/parameters.mdx#output-length-and-stopping)を参照してください。

## プロバイダーがパラメーターをサポートしていない場合

`top_k`、`seed`、`stop`、ペナルティをすべてのプロバイダーがサポートしているわけではありません。リクエストを処理するプロバイダーがサポートしていない場合、Phaseo はリクエストを拒否せずにそのパラメーターを削除し、`X-Phaseo-Dropped-Params` レスポンスヘッダーに記載します。出力の上限が削除されることはありません。完全なリストは[サポートされていないパラメーター](../api-reference/parameters.mdx#unsupported-parameters)を参照してください。

## 次の値から始める

| タスク | 最初の値 |
| --- | --- |
| 抽出、分類、JSON | `temperature` を `0.0`〜`0.2`、狭いサンプリング |
| 一般的なアシスタントの応答 | `temperature` を `0.3`〜`0.7`、`top_p` を `0.9`〜`1.0` |
| 創作 | 高めの `temperature` と広いサンプリング。より入念に評価します |

`max_tokens` は、すべてに 1 つの大きな値を使うのではなく、タスクごとに想定される出力に合わせて設定してください。すべてに 1 つのプロファイルを使うのではなく、タスクごとに個別に調整してください。創作のタスクでは、ランダム性を徐々に上げ、出力を目で確認してください。

## 不適切な設定を見分ける

| 症状 | 考えられる原因 |
| --- | --- |
| 事実の一貫性がない、構造化出力が不安定 | ランダム性が高すぎる |
| 繰り返しが多い、または味気ない応答 | 決定的すぎる |
| 不自然な言い回し、話題のずれ | ペナルティが高すぎる |
| 回答が途中で切れる、`finish_reason: "length"` | 出力の上限が低すぎる |

## パラメーターを調整する

<Steps>
<Step title="先にモデルと量子化を選ぶ">
[量子化](./quantization.mdx#pick-a-precision)を参照してください。
</Step>
<Step title="評価セットを固定する">
結果を比較できるよう、毎回同じプロンプトを使います。
</Step>
<Step title="一度に 1 つのパラメーターだけを変える">
値ごとに、品質、レイテンシー、トークン使用量を比較します。
</Step>
<Step title="タスクごとに結果を保存する">
エンドポイントやユースケースごとに別々の[プリセット](./presets.mdx)を用意し、呼び出し元が調整済みの既定値を引き継げるようにします。
</Step>
</Steps>
