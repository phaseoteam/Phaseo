`X-Phaseo-Metadata` ヘッダーを送信して、`team=support` のようなキーと値のラベルをリクエストに付け、そのラベルで支出とログを絞り込みます。API キーやアプリよりも細かいコストの切り口が必要なときにラベルを使います。ラベルはモデルへのリクエストを変更せず、プロバイダーにも転送されません。

```bash
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -H 'X-Phaseo-Metadata: {"labels":[{"key":"team","value":"support"},{"key":"environment","value":"production"}]}' \
  -d '{
    "model": "openai/gpt-6-astra",
    "input": "Summarize this ticket."
  }'
```

TypeScript SDK と Python SDK はカスタムヘッダーを受け付けるため、同じヘッダーをクライアントで一度設定できます。

内容に基づいてリクエストに自動でラベルを付けるには、[リクエスト分類器](/ja/v1/guides/request-classifiers)を使います。その回答はリクエストラベルとして保存され、同じ方法で絞り込めます。

## ラベルのルール

| ルール | 制限 |
| --- | --- |
| リクエストあたりのラベル数 | 最大 32 個、キーはそれぞれ一意 |
| キー | 1〜64 文字。英字、数字、`_`、`.`、`:`、`-` |
| 値 | 文字列、1〜256 文字、制御文字は不可 |
| ヘッダーサイズ | 最大 8 KiB |
| 予約済みキー | `phaseo.classifier` は Phaseo の分類器呼び出しだけが設定します |

キーと値の前後の空白は取り除かれます。ヘッダーの形式が不正な場合、キーが重複している場合、またはこれらのルールに違反するラベルがある場合、モデルが呼び出される前に、リクエストは `400 validation_error`（理由 `invalid_request_metadata`）で失敗します。

プロンプト、シークレット、メールアドレス、その他の個人データをラベルに入れないでください。

## ラベルで支出を絞り込む

分析エンドポイントに `label_key` と `label_value` の両方を渡します。

```text
GET /v1/analytics?label_key=team&label_value=support
```

レスポンスはフィルターなしの分析と同じグループ化された支出形式ですが、そのラベルの組み合わせと完全に一致するリクエストだけを集計します。2 つのパラメーターの一方だけを送ると `400 invalid_request` が返ります。
