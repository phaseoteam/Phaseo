テキストリクエストに `service_tier` を設定すると、より速い配信（`fast`、`ultrafast`）に料金を払うか、安価で優先度の低いモード（`flex`）を選べます。Phaseo は、そのモデルでそのティアを提供しているプロバイダーにだけルーティングします。このフィールドは `/v1/chat/completions`、`/v1/responses`、`/v1/messages` で同じように機能します。

```json
{
  "model": "openai/gpt-5.5",
  "input": "Summarise this incident report.",
  "service_tier": "fast"
}
```

| ティア | 指定方法 | 用途 |
| --- | --- | --- |
| Standard | 指定なし、または `"standard"` / `"default"` | 一般的な本番トラフィック |
| Fast | `"fast"`、またはそのエイリアス `"priority"` | プロバイダーのプレミアムまたは優先度の高いオファー |
| Ultrafast | `"ultrafast"` | 最も高速なオファー |
| Flex | `"flex"` | プロバイダーにある場合の低コストのオファー |
| Batch | `service_tier` ではなく [Batch API](../api-reference/endpoint/batches-create.mdx) | 大規模な後回しのワークロード |

ティアを使えるのはテキストモデルだけで、モデルとプロバイダーが対応している場合に限られます。Phaseo がティア別の料金を把握している場合は、モデルページに表示されます。

## ティアが提供されていない場合

Phaseo は、要求されたティアを提供しているプロバイダールートだけを残し、別のティアにフォールバックすることはありません。提供しているルートがない場合、リクエストは `400 unsupported_model_or_endpoint`（理由 `service_tier_not_supported`）で失敗します。

次の値は `400 validation_error` で失敗します。

- 同期リクエストでの `service_tier: "batch"`（キーワード `batch_service_tier_not_supported`）。代わりに Batch API を使ってください。
- `standard`、`default`、`fast`、`ultrafast`、`priority`、`flex`、`batch` 以外の値（キーワード `unsupported_service_tier`）。

送るのは常にこれらの Gateway の値です。Phaseo はそれを各プロバイダー独自の設定に変換するため、たとえば Anthropic のルートは Anthropic のティアのフィールドを受け取ります。

## 各エンドポイントでティアを指定する

<CodeGroup>
```json Responses
{
  "model": "openai/gpt-5.5",
  "input": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "flex"
}
```

```json Chat Completions
{
  "model": "openai/gpt-5.5",
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "flex"
}
```

```json Messages
{
  "model": "anthropic/claude-opus-5.5",
  "max_tokens": 512,
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "fast"
}
```
</CodeGroup>

`ultrafast` には、モデルページに Ultrafast の料金が表示されているモデルを使ってください。

## Mistral Priority と EU ルーティング

Mistral Priority Tier には、対象となる Mistral のエンタープライズアカウントが必要です。Phaseo は `priority` を Mistral の自動優先モードに対応付け、Mistral が報告したティアで課金します。Mistral が Standard にフォールバックした場合は、Standard の料金を支払います。

カタログに料金があっても、そのティアにルーティングできるとは限りません。特定の Mistral ルートが Priority への対応を公表していない限り Priority は無効のままで、利用資格は Mistral のアカウントとモデルにも左右されます。

GLM 5.2 は、`mistral-eu` プロバイダーオファーで Mistral の EU リージョンのエンドポイントに固定できます。

```json
{
  "model": "z-ai/glm-5.2",
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "priority",
  "provider": {
    "only": ["mistral-eu"],
    "required_execution_region": "eu"
  }
}
```

Mistral のリージョン推論は 10% 高くなります。Batch の料金は、Batch API 経由のグローバルな Mistral のオファーでのみ利用できます。Mistral はリージョンのエンドポイントで Batch に対応していません。

フィールドの完全なリファレンスは[パラメーター](../api-reference/parameters.mdx)にあります。ティアとプロバイダーの順序やフォールバックの組み合わせについては、[ルーティングとフォールバック](./routing-and-fallbacks.mdx)を参照してください。
