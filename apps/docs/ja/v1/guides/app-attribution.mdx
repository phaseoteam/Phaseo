すべてのリクエストで `X-App-Id` ヘッダーを送ると、その使用状況がアプリ分析とリクエスト監査で 1 つのアプリケーションにまとめられます。別々に集計したい製品、環境、顧客向け体験ごとに異なる ID を使ってください。帰属情報によって推論の応答が変わることはありません。

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -H "X-App-Id: acme-support" \
  -H "X-App-Name: Acme Support" \
  -H "HTTP-Referer: https://acme.example/support" \
  -H "X-App-Categories: chat,productivity" \
  -d '{
    "model": "openai/gpt-6-astra",
    "input": "Summarize this ticket."
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const phaseo = new Phaseo({
  apiKey: process.env.PHASEO_API_KEY,
  app: {
    id: "acme-support",
    name: "Acme Support",
    url: "https://acme.example/support",
    categories: ["chat", "productivity"],
  },
});

const response = await phaseo.generateResponse({
  model: "openai/gpt-6-astra",
  input: "Summarize this ticket.",
});
```
</CodeGroup>

TypeScript SDK の `app` オプションは、すべてのリクエストで同じヘッダーを送ります。Phaseo が帰属情報を自動で設定することはありません。

## ヘッダー

| ヘッダー | 目的 |
| --- | --- |
| `X-App-Id` | アプリケーションが選ぶ安定した識別子。 |
| `X-App-Name` | アプリと使用状況の画面に表示される、人が読める名前。 |
| `HTTP-Referer` | アプリに関連付ける公開ページまたはデプロイの URL。 |
| `X-App-Categories` | 最大 3 つのカテゴリーをカンマで区切ったリスト。 |
| `X-Title` | 人が読めるアプリ名の互換用エイリアス。 |

Phaseo は、`HTTP-Referer` の URL を送った場合はそれでアプリを識別し、送らない場合は `X-App-Id` で識別します。どちらも変えないようにしてください。新しい URL や ID を使うと、分析では新しいアプリとして扱われます。

`HTTP-Referer` は、ブラウザーが自動で付ける `Referer` ヘッダーと一致している必要はありません。正規のアプリ URL を 1 つにしたい場合は、サーバー側の連携で明示的に設定してください。

## カテゴリー

`chat`、`developer-tools`、`research`、`productivity`、`education`、`commerce`、`media`、`finance`、`other` から最大 3 つを選びます。

値は大文字と小文字を区別しません。Phaseo は不明な値を無視し、重複を取り除き、有効な最初の 3 つのカテゴリーを保持します。後のリクエストで送ったカテゴリーは、そのアプリにすでに保存されているカテゴリーに追加されます。ダッシュボードで選んだカテゴリーが削除されることはありません。

アプリケーションのコードではなく一か所でカテゴリーを管理するには、**設定 → アプリ** で編集します。

## 共有しても安全な帰属情報にする

- 帰属情報のヘッダーに、顧客 ID、メールアドレス、その他の個人データを含めないでください。
- URL と名前は公開されるものとして扱ってください。共有または公開のアプリ画面に表示されることがあります。
