description: "使用中のモデルが提供終了になる前に通知を受け取り、代替モデルへ移行し、必要に応じてそのリクエストを自動でルーティングします。"

---

ラボが新しいバージョンをリリースし、プロバイダーが古いモデルの提供をやめるにつれて、モデルは非推奨になり、提供終了になります。Phaseo は、ワークスペースで使用中のモデルが廃止に向かっているときに通知し、プロバイダーが提供している限りそのモデルを提供し続け、どのプロバイダーも提供しなくなった後はそのリクエストを代替モデルへルーティングできます。

<span id="how-a-model-is-retired"></span>

## モデルが提供終了になるまで

| 段階 | 意味 | リクエストへの影響 |
| --- | --- | --- |
| 非推奨 | ラボまたはプロバイダーが、モデルの提供終了を発表しています。提供終了日がわかっている場合は表示されます。 | 通常どおり処理されます。 |
| 提供終了 | 提供終了日を過ぎています。 | いずれかのプロバイダーがモデルを提供している間は、引き続き処理されます。 |
| 提供なし | どのプロバイダーもモデルを提供していません。 | [自動の代替](#route-requests-to-a-replacement-automatically)が有効でない限り、`410 model_retired` で拒否されます。 |

モデルのページには、そのステータス、非推奨日と提供終了日、そして推奨される代替モデルがある場合はそのモデルが表示されます。

<span id="get-notice-before-a-model-is-retired"></span>

## モデルが提供終了になる前に通知を受け取る

Phaseo はワークスペースがリクエストで送信したモデル ID を確認するため、フォールバックモデルが最終的にリクエストを処理した場合でも、そのモデルは使用中として扱われます。

- **ダッシュボードの通知。** 過去 90 日間にワークスペースがリクエストしたモデルが今後 90 日以内に提供終了になる場合、サインインしたメンバーにはダッシュボード上部に通知が表示されます。提供終了日のないモデルでは、代わりに非推奨日が使われます。提供終了まで 7 日以内になると、通知は赤色になります。通知のリンク先は **設定 -> 使用量 -> アラート** で、影響を受けるすべてのモデルが、日付、最終使用日時、推奨される代替モデルとともに一覧表示されます。通知を閉じると、モデルの日付が変わるまで表示されなくなります。
- **メールと通知先。** **設定 -> 通知** で **モデル非推奨アラート** を有効にします。過去 30 日間にワークスペースがリクエストしたモデルが非推奨になると、そのモデルについてワークスペースのオーナーにメールが 1 回送信されます。管理者にもメールを送るには **管理者にもメールで通知** を有効にし、Slack、Discord、Teams、または Webhook にアラートを送るには [通知先](./workspace-notifications.mdx) を選択します。

アラートはカウントダウン形式ではなくモデルごとに 1 回だけ送信されるため、最初のアラートが届いた時点で移行を計画してください。

<span id="what-happens-when-no-provider-serves-a-model"></span>

## どのプロバイダーもモデルを提供しなくなった場合

提供終了したモデルは、少なくとも 1 つのプロバイダーが提供している間は引き続き動作します。どのプロバイダーも提供しなくなると、リクエストは `410` で失敗します。

```json
{
  "error": "model_retired",
  "reason": "model_retired_without_providers",
  "description": "Model \"lab/old-model\" was retired on 2026-09-30 and no provider serves it any more. Use \"lab/new-model\" instead.",
  "retired_at": "2026-09-30T00:00:00Z",
  "replacement_model": "lab/new-model"
}
```

`replacement_model` は推奨される代替モデルで、ない場合は `null` です。同じモデルで再試行しても成功しません。エラー形式の詳細は [エラーとデバッグ](../api-reference/errors.mdx#when-a-model-is-retired) を参照してください。

<span id="move-to-a-replacement"></span>

## 代替モデルに移行する

1. **設定 -> 使用量 -> アラート** を開き、影響を受けるモデルとその最終使用日時を確認します。
2. モデルのページで推奨される代替モデルを確認します。価格、コンテキストウィンドウ、対応するエンドポイントとパラメーターを、現在使用しているモデルと比較します。
3. 代表的なリクエストで代替モデルをテストします。新しいモデルは、同じプロンプトに対して異なる応答を返すことがあります。
4. コード、プリセット、動的ルートのモデル ID を変更します。

移行中は、古いモデルを先頭に置いたまま、代替モデルを [リクエスト単位のフォールバック](./routing-and-fallbacks.mdx#request-level-model-fallbacks) として指定できます。古いモデルを提供するプロバイダーがない場合、Phaseo はすぐに `models` の次のモデルに進みます。

```bash
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "lab/old-model",
    "models": ["lab/new-model"],
    "messages": [{ "role": "user", "content": "Hello" }]
  }'
```

レスポンスの `model` フィールドに、リクエストを処理したモデルが表示されます。

<span id="route-requests-to-a-replacement-automatically"></span>

## 代替モデルにリクエストを自動でルーティングする

ワークスペースでは、提供されなくなったモデルへのリクエストを失敗させる代わりに、代替モデルへ送るよう選択できます。この機能は既定ではオフです。オーナーと管理者は、**設定 -> ルーティング -> 提供終了モデルのルーティング** で、または [ワークスペース設定 API](../api-reference/endpoint/workspace-settings-update.mdx) の `model_successor_redirect_enabled` で有効にできます。

有効にすると、次の条件をすべて満たす場合にのみ、リクエストが代替モデルに送られます。

- 要求されたモデルを 72 時間どのプロバイダーも提供していないこと。それまでは、リクエストは通常どおり失敗します。
- 代替モデルが Phaseo によって承認されているか、ワークスペースで選択されたものであること。Phaseo は承認済みの代替モデルを連続して最大 3 つまでたどります。
- 要求されたモデルが無料で、代替モデルが有料という組み合わせではないこと。無料モデルが有料モデルに置き換えられることはありません。
- 代替モデルが、通常のリクエストと同じチェック（ワークスペースのモデル制限、キーの制限、ガードレール、エンドポイントの対応状況）を通過すること。代替モデルが自動的に許可リストに追加されることはありません。
- リクエストでモデルが直接指定されていること。`phaseo/auto` やプロバイダー指定付きのモデル ID へのリクエストはリダイレクトされません。

<span id="choose-a-price-policy"></span>

### 価格ポリシーを選択する

より高価な代替モデルがリクエストを処理できるかどうかは、ワークスペースの価格ポリシーで決まります。価格は、両方のモデルが課金する料金で比較されます。

| `model_successor_price_policy` | 動作 |
| --- | --- |
| `never`（既定） | 代替モデルの価格が高くならない場合にのみ使用します。 |
| `limit` | `model_successor_max_price_increase_percent`（0〜1000）の割合まで高くなることを許可します。 |
| `any` | 価格を比較できない代替モデルを含め、どの価格でも許可します。 |

このリクエストには `settings:write` を持つ[管理APIキー](../developers/management-api-keys.mdx)が必要です。標準のGateway APIキーは推論リクエスト用であり、ワークスペースの設定は変更できません。

たとえば、最大 20% 高い代替モデルを許可するには、次のようにします。

```bash
curl https://api.phaseo.app/v1/settings \
  -X PATCH \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model_successor_redirect_enabled": true,
    "model_successor_price_policy": "limit",
    "model_successor_max_price_increase_percent": 20
  }'
```

<span id="set-your-own-replacements"></span>

### 独自の代替モデルを設定する

同じ設定セクションの **独自の代替モデル** で、オーナーと管理者は特定のモデルの代替モデルを選択することも、**リダイレクトしない** を選択してそのモデルへのリクエストを失敗のままにすることもできます。独自の代替モデルは価格に関係なく使用されますが、その場合も無料モデルが有料モデルに置き換えられることはありません。独自の代替モデルはダッシュボードでのみ設定できます。

これらの設定の変更は約 1 分以内に反映されます。

<span id="replacements-and-request-level-fallbacks"></span>

### 代替モデルとリクエスト単位のフォールバック

独自の `models` リストが優先されます。プライマリモデルを提供するプロバイダーがない場合、Phaseo は代替モデルではなく `models` の次のエントリを試します。代替モデルが検討されるのは、リストの最後のモデルに対してだけです。動的ルートのフォールバックモデルでも、置き換えの対象になるのは最後のモデルだけです。

<span id="tell-when-a-request-was-redirected"></span>

## リクエストがリダイレクトされたかどうかを確認する

レスポンスの `model` フィールドとリクエストログには、リクエストを処理したモデルが表示され、リクエストはそのモデルの価格で課金されます。リダイレクトされたレスポンスには、次の 2 つのヘッダーも含まれます。

| ヘッダー | 例 |
| --- | --- |
| `X-Phaseo-Requested-Model` | `lab/old-model` |
| `X-Phaseo-Model-Substitution` | `reason=unserved; from=lab/old-model; to=lab/new-model` |

あるモデルに対するワークスペースのリクエストに代替モデルが初めて正常に応答すると、ワークスペースのオーナーにメールが 1 回送信されます。この通知をチームにも送るには、[ワークスペース通知](./workspace-notifications.mdx#enable-product-alerts) で **代替モデルの通知** の通知先を選択します。

<span id="troubleshooting"></span>

## トラブルシューティング

**自動の代替を有効にした後も、リクエストが `410` で失敗する。**
次の点を確認してください。

- モデルが少なくとも 72 時間提供されていないこと。
- モデルに承認済みの代替モデルがあるか、独自の代替モデルを設定していること。
- 代替モデルの価格が、価格ポリシーで許可される範囲を超えていないこと。
- 無料モデルに有料の代替モデルを組み合わせていないこと。
- 代替モデルが、ワークスペースとキーのモデル制限で許可されていること。
- リクエストでプロバイダー指定付きのモデル ID や `phaseo/auto` を使用していないこと。

**リクエストしたものとは異なるモデルが応答した。** `X-Phaseo-Model-Substitution` ヘッダーを確認してください。モデルが置き換えられないようにするには、**独自の代替モデル** でそのモデルに **リダイレクトしない** を設定するか、自動の代替をオフにします。
