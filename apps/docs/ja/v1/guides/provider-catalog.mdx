承認済みプロバイダーは、公開済みの正規モデルに対する提供内容を更新できます。新しいモデルには承認が必要です。カタログは完全なスナップショットです。削除した提供内容は無効になり、料金履歴は保持されます。

## 形式の選択

バージョン指定のない V1 フィードはそのまま利用できます。`"schema_version": "1.0"` も V1 を表します。V1.1 は `"schema_version": "1.1"` を指定し、各モデルに `service_tiers` 配列を追加します。バージョンは URL パラメーターではなく、文書から判断されます。

各モデルには `standard` が必須です。追加できる階層は `fast`、`ultrafast`、`flex`、`batch` です。各階層に `service_tier`、`provider_model_slug`、`availability`、`pricing` を指定します。機能、制限、公開日はモデルで共有されます。

Fast、Ultrafast、Flex はテキスト生成で利用できます。異なるモデル ID または `upstream_service_tier` で実際の階層を選択してください。Fast は `fast` または `priority`、Standard は `default` または `standard` を受け付けます。Batch は別の Batch API を使用し、プロバイダーの Batch 連携と対応機能が必要です。

## 料金と更新

各階層には、課金するすべての単位の明示的な料金が必要です。`price_nanos` は割引後の実効料金です。ゼロは有効ですが、負の料金、不明な単位、重複した階層、条件付き料金は拒否されます。料金変更時には新しいスナップショットを公開します。過去の料金は保持されます。

ポーリングと署名付き Webhook は両形式に対応します。設定画面では、編集前に階層を選択してください。モデルの対応付けエラーは個別に表示され、有効なモデルの取り込みは継続します。

完全な例と JSON スキーマは[英語の契約ガイド](/v1/guides/provider-catalog)を参照してください。

API カタログの画面での編集は保持されます。取り込みは、手動変更のない項目を更新します。**フィード値を使用**で変更を解除できます。画面にはフィード値、適用中の値、編集者、日時が表示され、履歴に編集と復元が記録されます。手動追加したモデルはローカルの提供内容として保持されます。フィードから削除したモデルは、編集した項目があっても無効になります。手動専用カタログも引き続き利用できます。

## レート制限

プラットフォームが Phaseo のアカウントに適用するリクエスト数とトークン数の上限は、V1 と V1.1 のどちらでも、最上位の任意配列 `rate_limits` で宣言します。すべてのモデルに対する制限では `model` を省略し、特定のモデルには同じドキュメント内のモデルまたは階層の `provider_model_slug` を指定します。各エントリは `requests_per_minute`、`requests_per_day`、`tokens_per_minute`、`tokens_per_day` を正の整数または `null` で受け付け、少なくとも 1 つの値が必要です。モデルの制限は、すべてのモデルの制限に加えて適用されます。

```json
{
  "rate_limits": [
    { "requests_per_minute": 600, "tokens_per_minute": 2000000 },
    { "model": "example-model", "requests_per_day": 100000 }
  ]
}
```

制限によってリクエストがブロックされることはありません。上限に達すると、Phaseo はオファーの順位を下げ、他のプロバイダーを優先してトラフィックを送ります。そのため、申請が承認されると審査なしで適用され、通常は 1 分以内に反映されます。配列がある場合、変更されたフィードの取り込みが成功するたびに制限が置き換えられます。`[]` で削除され、配列を省略するとプロバイダー設定で定めた制限が維持されます。エントリが存在しないモデルを指定した場合、スコープが重複した場合、または値が無効な場合は、スナップショット全体が拒否されます。**プロバイダー設定 → モデル → レート制限** でも編集できます。
