<Note>
リクエスト分類器はベータ版です。オーナーと管理者は **設定 → 分類器** で管理するか、`classifiers:*` スコープを持つ[管理キー](../developers/management-api-keys.mdx)で管理API `/v1/classifiers` を使って管理できます。
</Note>

分類器は、部門、対象読者、タスクの種類などの分類体系と、それを適用するモデルを定義します。対象となる各リクエストが完了すると、Phaseo はそのリクエストをこのモデルに送り、モデルが各ディメンションの値を選びます。各回答は[リクエストラベル](./request-labels.mdx)としてリクエストに追加されるため、コードから送るラベルと同じようにログ、使用量、分析を絞り込んだりグループ化したりできます。

プロンプトが誰に向けて書かれたか、エージェントがどんな作業をしているか、リクエストが規制対象のテーマに関わるかなど、コード側でカテゴリが分からない場合に分類器を使います。

## リクエストが分類される流れ

1. リクエストが完了し、レスポンスがアプリケーションに返されます。分類によってレイテンシが増えることはありません。
2. Phaseo はリクエストのトランスクリプトを作成します。内容はシステム指示、メッセージ、ツール名（スキーマは含みません）、ツールの結果です。各ターンは4,000文字までに制限され、APIキーなどの秘密情報は伏せられます。分類器がレスポンスを含める設定の場合は、生成された出力も追加されます。
3. 分類器モデルは、指定した値だけを許可する構造化出力で回答します。
4. 回答は各回答の信頼度とともにリクエストのラベルとして保存され、その後でリクエストがログに表示されます。

分類器は `chat/completions`、`responses`、`messages` への成功したリクエストで実行されます。分類が失敗またはタイムアウトした場合も、リクエストはそれらのラベルなしで記録されます。

## 分類器を作成する

ダッシュボードのプリセットから始めるか、分類体系を直接送信します。

```bash
curl https://api.phaseo.app/v1/classifiers \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Department",
    "model": "google/gemini-2.5-flash-lite",
    "dimensions": [{
      "key": "department",
      "name": "Department",
      "allow_other": true,
      "values": [
        { "value": "engineering", "description": "Writing, reviewing, or debugging code" },
        { "value": "legal", "description": "Contracts, policies, and compliance" },
        { "value": "sales" },
        { "value": "support" }
      ]
    }],
    "sample_rate": 0.25,
    "monthly_budget_usd": 20
  }'
```

| フィールド | 意味 |
| --- | --- |
| `dimensions` | 1〜12個の質問です。各 `key` がラベルのキーになり、各ディメンションには2〜50個の値（`allow_other` の場合は1個から）を指定します。 |
| `multiple` | 1つのディメンションに複数の値を許可します。各値は同じキーを持つ個別のラベルになります。 |
| `allow_other` | どの値も当てはまらない場合に、モデルが `other` と回答できるようにします。 |
| `instructions` | 分類プロンプトに追加する補足の指示です。 |
| `sample_rate` | 対象リクエストのうち分類する割合で、`0.0001` から `1` までです。 |
| `sample_by` | `request` はリクエストごとにサンプリングします。`session` はセッション単位でまとめて対象に含めるか外し、回答を1時間再利用するため、長いエージェントの実行も1回だけ分類されます。 |
| `input_scope` | `prompt` はリクエストを分類します。`prompt_and_response` はレスポンスもモデルに見せます。 |
| `scope` | 指定した `key_ids`、`app_ids`、`models` からのリクエストだけを分類します。 |
| `monthly_budget_usd` | この金額を使い切ると、UTCの月末まで分類器を一時停止します。 |

1つのワークスペースには最大5個の分類器を作成できます。変更は約1分以内にゲートウェイへ反映されます。

## 結果で絞り込み、グループ化する

分類器の回答は通常のリクエストラベルです。

- **ログ** と **使用量** で、`department` = `legal` のようなラベルで絞り込みます。
- APIでは `label_key` と `label_value` を使います。

```text
GET /v1/analytics?label_key=department&label_value=legal
```

- [Broadcast](./integrations/observability.mdx) の送信先は、ラベルをスパン属性 `phaseo.label.<key>` として受け取ります。

コードがすでにディメンションのキーと同じラベルを送っている場合、Phaseo はその値を残し、そのディメンションをスキップします。2つの分類器が同じキーを使う場合は、先に作成された分類器が優先されます。

## コストとプライバシー

- 各分類は分類器モデルへの個別のリクエストで、元のリクエストと同じAPIキーまたはOAuthトークンで送信されます。そのモデルの通常料金で課金され、ワークスペースのプロバイダー、データ保持、BYOKの設定に従います。
- 分類器のリクエストには分類器IDを値とするラベル `phaseo.classifier` が付くため、**使用量** でその支出を確認できます。分類器のリクエスト自体は分類されず、レート制限ポリシーにも計上されません。
- 小さく高速なモデル、サンプリング率、セッション単位のサンプリング、適用範囲、月間予算でコストを抑えられます。
- トランスクリプトが送られるのは分類器モデルだけです。分類器のリクエストはほかのリクエストと同じように記録されるため、その入力が保存されるかどうかはワークスペースのログ設定に従います。
