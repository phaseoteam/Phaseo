部署、対象読者、タスクの種類などの分類体系と、それを適用するモデルを定義すると、Phaseo は完了した各リクエストにそのモデルの回答でラベルを付けます。各回答は[リクエストラベル](/ja/v1/guides/request-labels)として保存されるため、コードが送るラベルとまったく同じように、ログ、使用量、分析を絞り込んだりグループ化したりできます。プロンプトが誰に向けて書かれたか、エージェントがどんな作業をしているか、リクエストが規制対象のトピックに触れているかなど、コードがカテゴリを把握していない場合に分類器を使います。

<Note>
リクエスト分類器はベータ版です。オーナーと管理者は、**設定 → 分類器**、または `classifiers:*` スコープを持つ[管理キー](/ja/v1/developers/management-api-keys)による `/v1/classifiers` 管理 API で管理します。
</Note>

## リクエストが分類される仕組み

1. リクエストが完了し、レスポンスがアプリケーションに返されます。分類によってレイテンシが増えることはありません。
2. Phaseo はリクエストのトランスクリプトを作成します。システム指示、メッセージ、ツール名（スキーマは含まない）、ツール結果です。各ターンは 4,000 文字に制限され、API キーなどのシークレットは伏せ字になります。分類器がレスポンスを含める設定の場合は、生成された出力も追加されます。
3. 分類器のモデルが、指定した値の中から選びます。それ以外の回答は除かれます（[モデルを選ぶ](#choose-a-model)を参照）。
4. 回答は、各回答の信頼度とともに、リクエストがログに表示される前にリクエストのラベルとして保存されます。

分類器は、成功した `chat/completions`、`responses`、`messages` のリクエストで実行されます。分類が失敗するかタイムアウトしても、リクエストはそのラベルなしで記録されます。

## 分類器を作成する

ダッシュボードのプリセットから始めるか、分類体系を自分で送ります。

```bash
curl https://api.phaseo.app/v1/classifiers \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Department",
    "model": "google/gemini-2.5-flash-lite",
    "dimensions": [{
      "key": "department",
      "name": "Department",
      "allow_other": true,
      "values": [
        { "value": "engineering", "description": "Writing, reviewing, or debugging code" },
        { "value": "legal", "description": "Contracts, policies, and compliance" },
        { "value": "sales" },
        { "value": "support" }
      ]
    }],
    "sample_rate": 0.25,
    "monthly_budget_usd": 20
  }'
```

| フィールド | 意味 |
| --- | --- |
| `dimensions` | 1〜12 個の質問。各 `key` がラベルのキーになります。各ディメンションには 2〜50 個の値を列挙します（`allow_other` の場合は 1 個から）。 |
| `multiple` | 1 つのディメンションに複数の値を許可します。各値は同じキーを持つ別々のラベルになります。 |
| `allow_other` | 該当するものがない場合に、モデルが `other` と答えることを許可します。 |
| `instructions` | 分類のプロンプトに追加する補足の指示。最大 8,000 文字です。 |
| `sample_rate` | 対象となるリクエストのうち分類する割合。`0.0001` から `1` までです。 |
| `sample_by` | `request` はリクエストごとにサンプリングします。`session` はセッション単位でまとめて対象にするかを決め、その回答を 1 時間再利用するため、長いエージェントの実行は 1 回だけ分類されます。 |
| `input_scope` | `prompt` はリクエストを分類します。`prompt_and_response` はモデルにレスポンスも見せます。 |
| `scope` | これらの `key_ids`、`app_ids`、`models` からのリクエストだけを分類します。それぞれ最大 50 個です。 |
| `monthly_budget_usd` | この金額を使った時点で、UTC の月末まで分類器を一時停止します。 |

1 つのワークスペースで作成できる分類器は最大 5 つです。変更は約 1 分以内に Gateway に反映されます。

## モデルを選ぶ

テキストモデルや[判断モデル](/ja/v1/api-reference/endpoint/decisions)ならどれでも分類に使えます。Phaseo は、モデルのプロバイダーが対応している内容に応じて問い合わせ方を選びます。

| モデル | 問い合わせ方 |
| --- | --- |
| 構造化出力に対応したテキストモデル | 厳密な JSON スキーマを使った `responses` リクエスト。すべての回答が指定した値のいずれかになります。 |
| 判断モデル | ディメンションごとに選択式の質問を 1 つ持つ `decisions` リクエスト。`multiple` のディメンションは値ごとに yes/no の質問をし、確率が 0.5 以上の値をすべて残します（分類器に 128 を超える質問が必要になる場合、そのディメンションには最も良い値が 1 つだけ付きます）。信頼度はモデル自身の確率です。 |
| その他のテキストモデル | 同じ JSON をプロンプトで求める `responses` リクエスト。指定した値以外の回答は除かれるため、ディメンションにラベルが付かないことが多くなります。プロバイダーがスキーマを拒否した場合のフォールバックでもあります。 |

通常は小さく高速なモデルで十分です。保存する前に、分類器エディターの **サンプルで試す** でモデルを確認してください。

## 結果で絞り込んでグループ化する

分類器の回答は通常のリクエストラベルです。

- **ログ** と **使用量** では、`department` = `legal` のようなラベルで絞り込みます。
- API では `label_key` と `label_value` を使います。

```text
GET /v1/analytics?label_key=department&label_value=legal
```

- [ブロードキャスト](/ja/v1/guides/integrations/observability)の送信先は、ラベルを `phaseo.label.<key>` のスパン属性として受け取ります。

コードがすでにディメンションのキーと同じラベルを送っている場合、Phaseo はその値を残し、そのディメンションをスキップします。2 つの分類器が同じキーを使う場合は、先に作成した方が優先されます。

## コストとプライバシー

- 各分類は、元のリクエストと同じ API キーまたは OAuth トークンを使った、分類器モデルへの別のリクエストです。そのモデルの通常の料金で課金され、ワークスペースのプロバイダー、データ保持、BYOK の設定に従います。
- 分類器のリクエストには、分類器 ID を値とするラベル `phaseo.classifier` が付くため、**使用量** でその支出を確認できます。分類器のリクエスト自体は分類されず、レート制限のポリシーにも数えられません。
- 小さく高速なモデル、サンプリング率、セッション単位のサンプリング、範囲の指定、月の予算を使ってコストを抑えてください。
- トランスクリプトは分類器のモデルにだけ送られます。分類器のリクエストは他のリクエストと同じように記録されるため、その入力が保存されるかどうかはワークスペースのログ設定に従います。
