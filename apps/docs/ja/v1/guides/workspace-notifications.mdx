通知先を設定すると、ワークスペースで有効にしたアラートを、チームが普段監視しているツールに送信できます。通知先はワークスペースで共有され、運用アラートに使う前にテストできます。

## 通知先を追加する

1. **Gateway → 設定 → 通知**を開きます。
2. **通知先を追加**を選択します。
3. 名前を入力し、1つ以上のチャンネルを選びます。
4. 通知先の詳細と、必要に応じてメンションを追加します。
5. 設定した各チャンネルで**テストを送信**します。
6. すべてのテストが成功したら通知先を作成します。

CLI からは `phaseo notifications destinations create` で送信先を作成し、`phaseo notifications destinations test <id>` でテストしてから、`phaseo notifications routes set <event-kind> --destination-ids <id>` で受け取るアラートを選びます。

カスタム Webhook には作成時に署名シークレットが発行されます。表示されるダイアログからコピーしてください。表示されるのは一度だけです。

Phaseoで利用できる通知先:

- メールアドレスと配布リスト
- ボットトークンを使ったDiscordチャンネル
- Discord Webhook
- Slackの受信Webhook
- Microsoft TeamsのワークフローURL
- カスタムHTTPS Webhook

認証情報とWebhook URLは保存前に暗号化されます。チャンネルの認証情報は通知配信に限定し、漏えいした場合はローテーションしてください。

<span id="enable-product-alerts"></span>

## 製品アラートを有効にする

通知ページには、ワークスペースで利用できるアラートの種類が表示されます。**モデル非推奨アラート**を有効にすると、ワークスペースで使用中のモデルが提供終了になる前に通知を受け取れます。

**代替モデルの通知**は、[提供終了モデルのルーティング](./model-retirement.mdx#route-requests-to-a-replacement-automatically)が有効で、どのプロバイダーも提供しなくなったモデルへのワークスペースのリクエストに代替モデルが応答したときに送信されます。通知はモデルと代替モデルの組み合わせごとに 1 回、代替モデルが初めて正常に応答したときに送信されます。ワークスペースのオーナーには常にメールが届きます。チームにも通知を送るには、通知先を選択してください。

アラートは、ダッシュボードに表示される組み込みの宛先に加えて、設定した通知先にも送信されます。

<span id="spend-reports"></span>

## 支出レポート

ワークスペースのオーナーには、毎週月曜 09:00（ワークスペースの請求タイムゾーン）に、前週の月曜〜日曜の支出レポートがメールで届きます。通知ページの **支出アラート → ワークスペースの支出設定** で、毎日（09:00 に前日分）、毎週、毎月（1 日に前月分）、オフを選べます。管理者にも送るかどうかも設定できます。支出のない期間は送信されません。

各レポートには、支出と前期間からの変化、上位のキー・モデル・メンバー・部署、今月の予測、残高の持続日数、期間中の支出アラートとブロックが含まれます。受信者はメール内のリンクから配信を停止できます。停止されるのは、そのワークスペースのレポートのうち本人宛てのものだけです。**Spend Reports** にルーティングされた通知先には、レポートごとに 1 件の要約が届きます。

同じ設定は [通知設定 API](../api-reference/endpoint/notifications-settings-update.mdx) の `spend.report_cadence` と `spend.report_include_admins` です。

支出、予算、予測、急増、残高不足のアラートと、支出が上限を超えたときのリクエストのブロックについては、[支出アラート](./spend-alerts.mdx)を参照してください。

<Note>支出レポートのメールは段階的に提供を開始しています。有効になるまでは、選択内容は保存されますがレポートは送信されません。</Note>

## メンション

メンション欄を任意で設定すると、アラートで特定の宛先に通知できます。

- DiscordではユーザーIDとロールIDを指定できます。
- SlackではユーザーIDとユーザーグループIDを指定できます。
- Microsoft TeamsではMicrosoft 365のメールアドレスまたはEntraオブジェクトIDを指定できます。

メンションは必要な場合に限って使ってください。頻繁に届くワークスペースのアラートは、広範囲に通知するより、監視されているチャンネルに送るのが適切です。

## 通知先をテストして削除する

認証情報をローテーションした後やチャンネル設定を変更した後は、既存の通知先の横にある**テストを送信**を使います。監視されなくなった通知先は削除し、放置されたチャンネルにアラートが届いているように見える状態を避けます。

カスタムWebhookではHTTPSを使用し、リクエストを処理する前に検証してください。速やかに成功応答を返し、時間のかかる処理はバックグラウンドジョブに移します。

## Webhook 署名を検証する

Phaseo は、保存済みの通知先から送信するテストを含め、すべてのカスタム Webhook 配信に [動画とバッチの Webhook](./async-video-and-batch.mdx) と同じ方式で署名します。各リクエストには次のヘッダーが含まれます。

```http
POST /your/endpoint HTTP/1.1
content-type: application/json
user-agent: Phaseo-Notifications/1.0
x-phaseo-event-id: 6f1c0f5e-3f0b-4a39-9a51-2f4f2c1d9e10
x-phaseo-event-type: rate_limit_throttled
x-phaseo-timestamp: 1792569600
x-phaseo-signature: 5d2a…e41f
```

`x-phaseo-signature` は、`x-phaseo-timestamp` の値、ドット（`.`）、**変更されていないリクエストボディ**を連結し、通知先の署名シークレット（`whsec_…`）をキーにして計算した HMAC-SHA256 の 16 進文字列です。`x-phaseo-timestamp` は Unix 秒です。

配信を検証するには:

1. JSON として解析する前に、生のボディを読み取ります。
2. 署名を再計算し、定数時間で比較します。
3. 自分の時計と 5 分以上ずれたタイムスタンプは拒否します。
4. `x-phaseo-event-id` で重複を除外します。失敗した配信は再試行され、試行ごとに新しいタイムスタンプで署名し直されます。

<CodeGroup>
```js Node.js
import crypto from "node:crypto";

// rawBody は受信したままのリクエストボディ（文字列）です。
export function verifyPhaseoSignature(rawBody, headers, secret, toleranceSeconds = 300) {
  const timestamp = headers["x-phaseo-timestamp"];
  const signature = headers["x-phaseo-signature"];
  if (!timestamp || !signature) return false;
  if (Math.abs(Date.now() / 1000 - Number(timestamp)) > toleranceSeconds) return false;
  const expected = crypto
    .createHmac("sha256", secret)
    .update(`${timestamp}.${rawBody}`)
    .digest("hex");
  const a = Buffer.from(expected, "hex");
  const b = Buffer.from(signature, "hex");
  return a.length === b.length && crypto.timingSafeEqual(a, b);
}
```

```python Python
import hashlib
import hmac
import time

# raw_body は受信したままのリクエストボディ（bytes）です。
def verify_phaseo_signature(raw_body: bytes, headers, secret: str, tolerance_seconds: int = 300) -> bool:
    timestamp = headers.get("x-phaseo-timestamp", "")
    signature = headers.get("x-phaseo-signature", "")
    if not timestamp.isdigit() or not signature:
        return False
    if abs(time.time() - int(timestamp)) > tolerance_seconds:
        return False
    expected = hmac.new(secret.encode(), timestamp.encode() + b"." + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)
```
</CodeGroup>

### シークレットを生成またはローテーションする

シークレットは通知先の作成時に一度だけ表示されます。置き換えるには、**設定 → 通知** で通知先の横にある **シークレットをローテーション** を選ぶか、[`POST /v1/notifications/destinations/{id}/rotate-secret`](/ja/v1/api-reference/endpoint/notifications-destination-rotate-secret) を呼び出します。次の配信から新しいシークレットで署名され、古いシークレットは使えなくなるため、すぐに受信側を更新してください。

署名機能の導入前に作成されたカスタム Webhook にはシークレットがなく、引き続き署名なしで配信されます。設定では **署名なし** と表示されます。**シークレットを生成** を選び、受信側にシークレットを設定してから、テストを送信して検証を確認してください。**通知先を追加** パネルから保存前に送信したテストは、まだシークレットがないため署名されません。

メール、Slack、Discord、Microsoft Teams の通知先は署名されません。これらのサービスは Webhook URL やボットトークンを自ら認証します。
