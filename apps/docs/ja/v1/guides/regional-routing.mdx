title: "テキストリクエストをリージョンでルーティングする"
description: "Phaseo のテキスト生成を EU または US のプロバイダールートに限定します。"
---

テキストリクエストを `eu.api.phaseo.app` または `us.api.phaseo.app` に送ると、そのリージョンでモデルを実行し、プロンプトと補完のデータを処理するプロバイダールートだけが使われます。モデル ID と API キーは変わりません。Chat Completions、Responses、Messages に対応しています。

| リージョン | ベース URL | 使われるプロバイダールート |
| --- | --- | --- |
| 欧州連合 | `https://eu.api.phaseo.app/v1` | EU での実行と EU でのデータ処理を宣言したルートのみ |
| 米国 | `https://us.api.phaseo.app/v1` | US での実行と US でのデータ処理を宣言したルートのみ |
| グローバル | `https://api.phaseo.app/v1` | 標準のグローバルなルーティングポリシー |

<Warning>
リージョンルーティングは、まだエンドツーエンドのデータ所在地の保証ではありません。Phaseo はプロバイダーの選択を制限し、Gateway をリージョンの近くに配置しますが、共有のアカウント、請求、キャッシュ、運用のシステムがリージョン外でデータを処理することがあります。[リージョン外に残るもの](#what-stays-outside-the-region)を参照してください。
</Warning>

## リージョン指定のリクエストを送る

<CodeGroup>
```ts TypeScript
import { Phaseo } from "@phaseo/sdk";

const phaseo = new Phaseo({
  apiKey: process.env.PHASEO_API_KEY!,
  region: "eu",
});

const response = await phaseo.responses.create({
  model: "openai/gpt-5.6-luna",
  input: "Summarize this note in one sentence.",
});

console.log(response.output_text);
```

```python Python
import os
from phaseo import Phaseo

phaseo = Phaseo(
    api_key=os.environ["PHASEO_API_KEY"],
    region="eu",
)

response = phaseo.responses.create({
    "model": "openai/gpt-5.6-luna",
    "input": "Summarize this note in one sentence.",
})

print(response.get("output_text"))
```

```bash Chat Completions
curl https://eu.api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5.6-luna",
    "messages": [
      {"role": "user", "content": "Write a two-line status update."}
    ]
  }'
```

```bash Responses
curl https://eu.api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5.6-luna",
    "input": "Extract the three most important actions from this note."
  }'
```

```bash Messages
curl https://us.api.phaseo.app/v1/messages \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -H "anthropic-version: 2023-06-01" \
  -d '{
    "model": "anthropic/claude-sonnet-5.5",
    "max_tokens": 256,
    "messages": [
      {"role": "user", "content": "Summarize this incident report."}
    ]
  }'
```
</CodeGroup>

SDK では `region` を `"eu"` または `"us"` に設定します。グローバルなルーティングを使う場合は省略するか `"global"` を使います。`region` とカスタムの `baseUrl`（Python では `base_url`）の両方を設定すると、それぞれ別のホストを選ぶため、SDK は例外を投げます。

ホスト名がそのままポリシーになります。リクエストやプリセット内の `required_execution_region` または `required_data_region` が別のリージョンを指定している場合は、`400 validation_error`（理由 `deployment_region_conflict`）で失敗します。プリセットと動的ルーティングのルールが先に適用され、リージョンのルールは最後に適用されるため、それらがリージョンのルールを弱めることはできません。Phaseo がリージョン外のプロバイダーで再試行することはありません。

## リージョン指定のリクエストに含められるもの

| 対応 | 拒否 |
| --- | --- |
| テキストの入力とテキストの出力 | 画像、音声、動画、ドキュメント、ファイル、添付 |
| ストリーミングと非ストリーミング | テキスト以外の出力モダリティ |
| system と developer の指示 | Web 検索、ファイル検索、コード実行、コンピューター操作、画像生成などのプロバイダーがホストするツール、および `web_search_options` |
| 自分の `function` と `custom` のツール、テキストのツール結果 | Phaseo の[サーバーツール](./server-tools)（`phaseo:` の型） |
| モデルが対応している場合の構造化テキストと JSON の出力 | 画像、音声、動画、埋め込み、モデレーション、バッチ、ファイル、Webhook、リアルタイムのエンドポイント |
| リージョンと矛盾しないプリセット、プロバイダーの順序、フォールバック、価格の上限 | |

自分のツールはアプリケーション内で実行されるため許可されます。ホスト型ツールとサーバーツールは、リージョンのルールが制御できない場所で実行されます。

## リージョンで利用できるモデルを調べる

リクエストを送るのと同じホスト名で `/v1/models` を呼び出します。利用できるモデルは EU、US、グローバルのエンドポイントで異なります。

```bash
curl https://eu.api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

一覧には、宣言された実行リージョンとデータリージョンの両方にそのリージョンが含まれる、有効なプロバイダールートを持つモデルだけが含まれ、テキストの入出力による Chat Completions、Responses、Messages だけが示されます。各オファーにはリージョンが表示されます。

```json
{
  "provider": { "id": "example-eu", "name": "Example EU" },
  "residency": {
    "execution_regions": ["eu"],
    "data_regions": ["eu"]
  }
}
```

## どの Gateway がリクエストを処理したか確認する

リージョン指定のレスポンスには `X-Phaseo-Gateway-Region: eu`（または `us`）が付きます。このヘッダーはリクエストを処理したリージョンのポリシーを示すもので、Cloudflare がどこで実行したかの証明ではありません。リクエスト詳細には、必要な実行リージョンとデータリージョン、選択されたプロバイダー、そのプロバイダーが宣言したリージョンも記録されます。

## エラー

リージョンのルールに違反すると、次のいずれかの `reason` とともに `400 not_supported` が返ります。

| `reason` | 原因 | 対処 |
| --- | --- | --- |
| `regional_endpoint_not_supported` | そのパスはリージョン指定で利用できません | Chat Completions、Responses、Messages、またはグローバル API を使います |
| `regional_non_text_content` | リクエストにメディア、ファイル、添付があります | それを取り除くか、グローバル API を使います |
| `regional_non_text_output` | テキスト以外の出力モダリティが要求されました | テキストを要求するか、グローバル API を使います |
| `regional_hosted_tool_not_supported` | `function` と `custom` 以外のツールがあります | 自分の関数ツールか、グローバル API を使います |

理由 `deployment_region_conflict` の `400 validation_error` は、リクエストまたはプリセットが別のリージョンを指定していることを意味します。その設定を取り除いてください。モデルとリージョンの両方を満たす正常なプロバイダールートがない場合、リクエストはプロバイダーを呼び出す前に停止します。リージョンの `/v1/models` に表示されるモデルを選んでください。

## リージョン外に残るもの

リージョンのルールが対象とするのは、どのプロバイダーがモデルを実行し、プロンプトと補完のデータを処理するかです。リクエストのライフサイクル全体はまだ対象になっていません。

- Cloudflare の配置によって Gateway はリージョンの近くに置かれますが、それはコンプライアンス上の境界ではありません。
- アカウント、認証、請求、リクエストのメタデータは、共有の Supabase インフラにあります。
- Cloudflare KV と Worker の呼び出しログは、リージョンに限定されません。
- プロバイダーへの呼び出しは、Cloudflare が Gateway をどこに配置したかにかかわらず、そのプロバイダーのリージョンのエンドポイントに送られます。
- サポートと運用のスタッフはリージョン内に限定されていません。

Phaseo がこれをエンドツーエンドのデータ所在地と呼ぶのは、Gateway、ストレージ、ログ、プロバイダー、運用のすべての経路に、強制力のあるリージョンの制御が備わってからです。
