`phaseo cursor` を実行してキーを作成し、Cursor の OpenAI API キーと **Override OpenAI Base URL** の設定をオンにします。これにより Cursor のチャットモデルが Phaseo 経由でルーティングされます。タブ補完など、Cursor 独自のモデルを使う機能は、引き続き Cursor のインフラを使う場合があります。

## Phaseo CLI で設定する

```bash
phaseo login
phaseo cursor --model openai/gpt-5.6-terra
```

CLI は、有効期限が 90 日で月額 $100 の利用上限が付いた `Phaseo CLI: Cursor API Key` を作成し、以下の設定値を表示します。期限が切れたら、`phaseo cursor` を再実行して新しいキーを取得します。CLI は Cursor の資格情報ストアを編集しません。

## Cursor を設定する

1. **Cursor Settings → Models** を開きます。
2. **OpenAI API Key** のセクションを見つけて有効にします。
3. `phaseo integrations credential cursor` で取得したキー、または任意の Phaseo API キーを貼り付けます。
4. **Override OpenAI Base URL** を有効にし、末尾のスラッシュなしで `https://api.phaseo.app/v1` を入力します。
5. 使いたい Phaseo のモデルを追加するか有効にします。

| Cursor の項目 | 値 |
| --- | --- |
| OpenAI API Key | `phaseo integrations credential cursor` の出力 |
| Override OpenAI Base URL | `https://api.phaseo.app/v1` |
| Model | Cursor が受け付ける Phaseo のモデル ID |

Cursor のキーと Base URL の設定はプロバイダーごとではなく全体に適用されます。有効にしたキーと Base URL によって OpenAI 系のすべてのリクエストの送信先が決まり、モデル名はそのまま転送されます。**Verify** ボタンがなくキーを保存するだけのリリースもあるため、その場合は新しいチャットで確認してください。Cursor の [API キーのドキュメント](https://docs.cursor.com/settings/api-keys)を参照してください。

## 動作を確認する

1. キーと Base URL の上書きを有効にしたままにします。
2. Cursor のモデル選択でモデルを選び、新しいチャットを開始します。
3. `PHASEO_CURSOR_OK` と返答するよう依頼します。
4. **設定 → 利用状況 → ログ**にリクエストが表示されることを確認します。

## Phaseo を削除する

**Cursor Settings → Models** で OpenAI API キーと Base URL の上書きを無効にしてから、キーを失効させます。

```bash
phaseo integrations remove cursor
```

CLI は Cursor の資格情報ストレージを消去できません。キーがまだ設定済みと表示される場合は、Cursor の Models 設定で削除します。

## よくある問題を解決する

### Cursor がホストするモデルが動かなくなる

Cursor は Base URL の上書きを OpenAI 系のすべてのモデルに適用します。Cursor がホストするモデルに戻す前に、**Override OpenAI Base URL** をオフにします。

### モデルが拒否される

Cursor は、組み込みカタログと重複する ID や、OpenAI 系のルーティングに合わない ID を拒否することがあり、プロバイダーのプレフィックスが付いた ID を拒否するリリースもあります。Cursor が OpenAI 系のカスタムモデルとして受け付ける別の Phaseo モデルを試してください。

### 認証に失敗する

`phaseo integrations credential cursor` を再実行して Cursor のキーを置き換え、Base URL が正確に `https://api.phaseo.app/v1` であることを確認します。
