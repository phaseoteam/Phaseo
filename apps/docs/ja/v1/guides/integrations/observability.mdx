Phaseo のリクエストをトレースする方法は 2 つあります。[Broadcast](../broadcast.mdx) をオンにして、コードを変更せずに Phaseo からすべてのリクエストのトレースを Langfuse、LangSmith、または任意の OpenTelemetry ツールに送信する方法と、アプリ内のトレースライブラリはそのままにして、そのモデルクライアントを Phaseo に向ける方法です。

| | Broadcast | アプリ内でのトレース |
| --- | --- | --- |
| トレースの送信元 | Phaseo（すべてのリクエスト） | アプリのモデルクライアント |
| コードの変更 | 不要。**設定 → イベント配信**で設定します | クライアントをラップし、Base URL を変更します |
| トレースの内容 | モデル、プロバイダー、プロバイダーへの各試行、トークン、コスト、時間、（任意で）プロンプトと出力 | ライブラリが記録する内容と、アプリ独自のコンテキスト |

## OpenAI SDK で Langfuse を使う

Langfuse の OpenAI ラッパーはそのまま使い、ラップしたクライアントに Phaseo の Base URL を渡します。

```bash
pip install langfuse openai
```

```python
import os
from langfuse.openai import openai

client = openai.OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
)

response = client.responses.create(
    model="openai/gpt-6-astra",
    input="Reply with only: ok",
)
```

## LangChain で LangSmith を使う

[LangChain](./langchain.mdx) の `ChatOpenAI` の設定を使い、LangChain の通常の環境変数で LangSmith をオンにします。

```bash
export LANGSMITH_TRACING=true
export LANGSMITH_API_KEY="your_langsmith_key"
export PHASEO_API_KEY="your_phaseo_key"
```

## OpenTelemetry

フレームワークがすでに OpenTelemetry のスパンを出力している場合、特別なエクスポーターは不要です。次のリクエストのコンテキストを自分でスパンに追加します。

- モデル ID
- エンドポイント（`responses` や `chat.completions` など）
- Phaseo のリクエスト ID（レスポンスのメタデータまたは[ログ](../../api-reference/endpoint/activity.mdx)から取得）
- リクエストを処理したプロバイダー（レスポンスのメタデータがオンの場合）

Phaseo の API キーは、決してスパンの属性として記録しないでください。
