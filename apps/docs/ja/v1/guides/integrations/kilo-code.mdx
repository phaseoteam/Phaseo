`phaseo kilo` を実行すると、Phaseo 経由で Kilo Code CLI のセッションを開始できます。または `phaseo kilo-code` でキーを作成し、Kilo Code 拡張機能にカスタムプロバイダーを追加します。

## Phaseo 経由で Kilo Code CLI を実行する

```bash
phaseo login
phaseo kilo --model openai/gpt-5.6-terra
```

ランナーは一時的な `KILO_CONFIG` ファイルを書き込んで `kilo` を起動し、Kilo の終了時にそのファイルを削除します。そのため、既存の Kilo Code や VS Code の設定には影響しません。Kilo がインストールされていない場合、対話型の実行ではインストールを提案します。Kilo 自体のフラグは `--` の後に指定します。

| フラグ | 効果 |
| --- | --- |
| `--model <id>` | 使用するモデル。デフォルトは `openai/gpt-5.6-terra` です。 |
| `--catalog all` | 選択したモデルだけでなく、Phaseo の有効なテキストモデルをすべて Kilo に表示します。 |
| `--dry-run --json` | キーの作成や Kilo の起動を行わずに、インストールと起動の計画を表示します。 |
| `--skip-install` | インストールの確認をスキップします。 |

`phaseo run kilo ...` は同じコマンドの完全な形式です。

## Kilo Code 拡張機能を設定する

拡張機能用のキーを作成します。

```bash
phaseo login
phaseo kilo-code --model anthropic/claude-sonnet-5.5
```

次に、VS Code で以下を行います。

1. Kilo Code を開き、設定アイコンを選択して **Providers** を開き、**Add custom provider** を選択します。
2. 次の値を入力します。

| Kilo Code の項目 | 値 |
| --- | --- |
| Provider ID | `phaseo` |
| Display name | `Phaseo` |
| Provider API | **OpenAI Compatible** |
| Base URL | `https://api.phaseo.app/v1` |
| API key | `phaseo integrations credential kilo-code` の出力 |

3. モデルが検出されない場合は、ID `anthropic/claude-sonnet-5.5` を手動で追加します。
4. **Submit** を選択し、Phaseo のモデルを選びます。

Kilo では選択したモデルが `phaseo/anthropic/claude-sonnet-5.5` と表示されます。`phaseo` はローカルのプロバイダー ID で、残りの部分が Phaseo に送信されるモデル ID です。完全な形式については、Kilo の[カスタムモデル](https://kilo.ai/docs/code-with-ai/agents/custom-models)のドキュメントを参照してください。

## 動作を確認する

Kilo Code に `PHASEO_KILO_OK` と返答するよう依頼し、**設定 → 利用状況 → ログ**にリクエストが表示されることを確認します。

## Phaseo を削除する

Kilo Code でカスタムプロバイダーを削除してから、次を実行します。

```bash
phaseo integrations remove kilo-code
```

これによりキーが失効します。CLI は拡張機能のストレージを消去できません。

## よくある問題を解決する

### モデルが検出されない

モデルを手動で追加します。Kilo は `/models` による検出を必要としません。

### 認証に失敗する

保存済みのキーを `phaseo integrations credential kilo-code` の出力に置き換え、Base URL は表示どおりに入力します。

### モデル名の表示が異なる

Kilo では `phaseo/<Phaseo model ID>` を選択しますが、モデル ID の項目には `phaseo/` を付けないでください。
