認証付きの HTTP リクエストを送れる自動化プラットフォームなら、どこからでも Phaseo を呼び出せます。キーをベアラートークンにして `https://api.phaseo.app/v1/responses` に POST する HTTP ステップを追加してください。Zapier、n8n、Pipedream 用のネイティブアプリはありません。

## リクエストを組み立てる

| 設定 | 値 |
| --- | --- |
| メソッド | `POST` |
| URL | `https://api.phaseo.app/v1/responses` |
| ヘッダー | `Authorization: Bearer <PHASEO_API_KEY>` |
| ヘッダー | `Content-Type: application/json` |

```json
{
  "model": "openai/gpt-6-astra",
  "input": "Summarise the supplied workflow data in one paragraph."
}
```

キーは共有のワークフロー定義ではなく、プラットフォームの認証情報ストアやシークレットストアに保存してください。リクエストのすべてのフィールドは [Responses](../../api-reference/endpoint/responses.mdx) を参照してください。

## Zapier

**Webhooks by Zapier → Custom Request** を使います。

1. `POST` を選び、`https://api.phaseo.app/v1/responses` を入力します。
2. ベアラーと Content-Type のヘッダーを追加します。
3. 前の Zap ステップのフィールドを `input` にマッピングします。
4. 機密でないデータで Zap をテストします。

## n8n

ベアラー認証と JSON ボディを設定した **HTTP Request** ノードを使います。n8n の式で、受け取ったアイテムを `input` にマッピングします。

## Pipedream

HTTP リクエストのステップか Node.js のコードステップを使います。`PHASEO_API_KEY` を Pipedream のシークレットとして保存し、ステップの環境から読み取ります。

## 動作を確認する

ステップを 1 回実行します。`output` 配列を含む `200` レスポンスが返れば、キーと URL は機能しており、リクエストは **設定 → 使用量 → ログ** に表示されます。

## 自動化を安全に実行する

- 自動化ごとに支出上限付きの専用キーを用意し、個別に追跡して取り消せるようにします。
- 後続のステップが機械可読なフィールドを想定している場合は、[構造化出力](../structured-outputs.mdx)を使います。
- `429` と復旧可能な `5xx` レスポンスでは再試行します。[エラー](../../api-reference/errors.mdx)を参照してください。
- モデルのステップが再試行されたからといって、冪等でない外部操作を繰り返さないでください。
