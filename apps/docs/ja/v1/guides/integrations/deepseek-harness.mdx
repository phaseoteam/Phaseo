`phaseo deepseek-harness` を実行して DeepSeek Harness のモデル選択に Phaseo を追加するか、Harness の画面または `settings.yaml` でカスタムプロバイダーを追加します。Harness は OpenAI 互換の Chat Completions リクエストを Phaseo に直接送信するため、アダプターは不要です。

## Phaseo CLI で設定する

```bash
phaseo login
phaseo deepseek-harness
```

Harness がインストールされていない場合、CLI は公式のインストールコマンドを表示し、実行する前に確認します。その後、セットアップは次の処理を行います。

- プロバイダー、Base URL、プロトコル、モデルカタログ、デフォルトのモデルを `$DSH_HOME/cordis.patch.yml`（`DSH_HOME` のデフォルトは `~/.dsh`）のマーク付きブロック内に書き込みます。これにより、後から自分の設定だけを更新または削除できます。
- Chat Completions で動作する Phaseo の有効なテキストモデルをすべて追加します。デフォルトのモデルだけを追加するには `--catalog default` を使います。
- 有効期限が 90 日で月額 $100 の利用上限が付いた `Phaseo CLI: DeepSeek Harness API Key` を作成し、Harness の保護された `$DSH_HOME/.credentials.yaml` に書き込みます。期限切れのキーを置き換えるには、`phaseo deepseek-harness` を再実行します。

デフォルトのモデルは `anthropic/claude-sonnet-4.6` です。別のモデルを選ぶには、次を実行します。

```bash
phaseo deepseek-harness --model YOUR_PHASEO_MODEL_ID
```

## Harness の画面で Phaseo を追加する

1. **Settings > Models** を開き、**Add a custom provider** を選びます。
2. 次の値を入力します。

| 項目 | 値 |
| --- | --- |
| Provider ID | `phaseo` |
| Display name | `Phaseo` |
| Base URL | `https://api.phaseo.app/v1` |
| API protocol | `OpenAI Completions` |
| API key | Phaseo の API キー |

3. **Model catalog** で **Fetch available models** を選びます。
4. `anthropic/claude-sonnet-5.5` など、ツールに対応した Chat Completions モデルを選び、プロバイダーを保存します。
5. コンポーザーで Phaseo のモデルを選び、新しいセッションを開始します。

保存済みのセッションと資格情報の参照にはプロバイダー ID が保持されるため、`phaseo` は変更しないものとして扱ってください。表示名、URL、キー、モデル一覧は後から編集できます。

## settings.yaml で Phaseo を設定する

同じプロバイダーを `$DSH_HOME/settings.yaml` で設定することもできます。このファイルにはキーを書かないでください。`apiKeyEnv` には、Harness がキーを読み込む変数の名前を指定します。

```yaml $DSH_HOME/settings.yaml
llm-pi-ai:
  providers:
    phaseo:
      displayName: Phaseo
      apiKeyEnv: PHASEO_API_KEY
      api: openai-completions
      baseURL: https://api.phaseo.app/v1
      models:
        - id: YOUR_PHASEO_MODEL_ID
```

Harness を起動する環境で `PHASEO_API_KEY` を設定するか、Models ページにキーを保存します。`YOUR_PHASEO_MODEL_ID` は Phaseo の正確な ID に置き換えます。コーディングエージェントには、まず `anthropic/claude-sonnet-5.5` から始めてください。`models` の一覧はライブで照会されるものではなく保存済みのカタログなので、Harness で使う Phaseo のモデルを増やしたいときは更新します。

## 動作を確認する

まず、キーとモデルの検出を確認します。

```bash
curl https://api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

次に、新しい Harness セッションで Phaseo のモデルを選び、`Reply with exactly: Phaseo is connected.` を送信します。返答があれば、Harness から Phaseo を経由してモデルプロバイダーまでの経路全体が確認できます。リクエストは**設定 → 利用状況 → ログ**にも表示されます。ライブリクエストは通常の利用として課金されます。

## Phaseo を削除する

```bash
phaseo integrations remove deepseek-harness
```

これにより、Phaseo が管理する設定だけが削除され、キーが失効します。

## よくある問題を解決する

| 問題 | 対処 |
| --- | --- |
| モデルの取得で `401` が返る | キーが有効であり、Base URL に `/v1` が含まれていることを確認します。 |
| モデル選択にモデルが表示されない | カタログを再取得するか、`settings.yaml` の `models` に正確なモデル ID を追加します。 |
| Harness が `MISSING_CREDENTIAL` を報告する | Models ページにキーを保存するか、Harness のプロセスから `PHASEO_API_KEY` を参照できるようにします。 |
| リクエストが誤ったエンドポイントに送られる | `OpenAI Completions`（`openai-completions`）を選びます。このプロバイダーは Phaseo の `/v1/chat/completions` を使います。 |
| 推論をオンにするとモデルが関数ツールを拒否する | Chat Completions でツールに対応したモデルを選びます。ツールを使った推論に Responses API が必要なモデルは、このプロトコルでは動作しません。 |
| セッションが古いモデルを使い続ける | 新しいセッションを開始します。Harness は、リクエストを送信したセッションにプロバイダーとモデルを保存します。 |
