`phaseo muse` を実行すると、Phaseo 経由で Muse Code のセッションを開始できます。Muse Code で Phaseo を使うためにサポートされている方法は、このランナーだけです。

## Phaseo CLI で Muse Code を実行する

```bash
phaseo login
phaseo muse --model meta/muse-spark-1.3
```

ランナーは専用のキーを作成し、一時的な `XDG_CONFIG_HOME` の下に Muse の設定を書き込んで `muse` を起動し、Muse Code の終了時に設定を削除します。Muse Code 自体のフラグは `--` の後に指定します。

| フラグ | 効果 |
| --- | --- |
| `--model <id>` | 使用するモデル。デフォルトは `openai/gpt-5.6-terra` です。 |
| `--catalog all` | 選択したモデルだけでなく、Phaseo の有効なテキストモデルをすべて表示します。 |
| `--dry-run --json` | キーの作成や Muse Code の起動を行わずに、起動の計画を表示します。 |
| `--skip-install` | インストールの確認をスキップします。 |

`phaseo run muse ...` は同じコマンドの完全な形式です。

macOS と Linux では、初回の対話型の実行で Meta のインストーラーによる Muse Code のインストールを提案します。Windows では、Muse Code を自分でインストールして `muse --version` を確認し、`--skip-install` を使います。

## 手動での設定がない理由

Muse Code は Meta 独自の [Model API](https://ai.meta.com/llama) とサインインを前提に作られています。Meta は別の OpenAI 互換エンドポイントに向けるための安定した設定を公開していないため、ランナーを使ってください。ランナーの一時的な設定を通常の Muse のプロファイルにコピーしないでください。これは内部の詳細であり、ランナーの終了時に削除されます。

代わりに自分のコードから Phaseo のモデルを呼び出すには、`https://api.phaseo.app/v1` と Phaseo の API キーで [OpenAI SDK](./openai-sdk.mdx) を使います。

## 動作を確認する

短いプロンプトを送信し、**設定 → 利用状況 → ログ**にリクエストが表示されることを確認します。

## よくある問題を解決する

### Muse Code がインストールされていない

Muse Code を自分でインストールして `muse --version` を確認し、`--skip-install` を付けて再実行します。

### モデルが一覧に表示されない

`--catalog all` を使うか、`--model` でモデル ID を渡します。Phaseo はモデルの自動検出を必要としません。
