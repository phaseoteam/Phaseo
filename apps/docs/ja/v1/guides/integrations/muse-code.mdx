Phaseo CLI は、専用のゲートウェイキーと一時的なプロバイダー設定を使って Muse Code を起動できます。

## Phaseo CLI でセットアップ

```bash
phaseo login
phaseo muse --model meta/muse-spark-1.3 --
```

`--catalog all` で Phaseo のすべての有効なテキスト・チャットモデルを利用可能にできます。`--dry-run --json` では、キーを作成したり Muse Code を起動したりせずに起動計画を確認できます。

```bash
phaseo muse --catalog all --dry-run --json
```

明示的なコマンド形式は `phaseo run muse ...` です。Phaseo が自身のオプションを先に処理できるよう、Muse Code のオプションは `--` の後に指定してください。

Unix 系システムでは、初回の対話実行時に Meta のインストーラーで Muse Code をインストールすることを提案します。Windows では Muse Code を別途インストールし、`muse --version` を確認して `--skip-install` を使ってください。

## 手動設定

Muse Code の公開セットアップは、Meta 独自の Model API と認証フローを前提としています。Meta は現在、このエンドポイントをサードパーティーの OpenAI 互換ゲートウェイに置き換えるための安定した永続設定を公開していません。そのため、Muse Code を Phaseo 経由でルーティングする際は Phaseo CLI ランナーを使用する方法がサポートされています。

別のクライアントから Phaseo モデルを手動で使用する場合は、`https://api.phaseo.app/v1` と Phaseo API キーを使って [OpenAI 互換の連携](./openai-sdk)を設定してください。ランナーが作成する一時的な Muse 設定を通常の Muse プロファイルにコピーしないでください。これらのファイルは内部実装用であり、ランナーの終了時に削除されます。

## 確認

起動した環境から短いプロンプトを送信し、Phaseo のアクティビティにリクエストが表示されることを確認します。ランナーは一時的な `XDG_CONFIG_HOME` 内に `settings.json` を作成し、Muse Code の終了時に削除します。

## トラブルシューティング

### Muse Code がインストールされていない

Muse Code を別途インストールし、`muse --version` を確認して、`--skip-install` を指定して再実行してください。

### モデルが表示されない

`--catalog all` を使うか、`--model` でモデル ID を指定してください。Phaseo ゲートウェイではモデルの自動検出は必須ではありません。
