`phaseo minimax` を実行すると、Phaseo 経由で MiniMax Code（`mcode`）のセッションを開始できます。すべてのセッションで Phaseo を使い続けるには、`mcode provider add` で Phaseo を追加します。

## Phaseo CLI で MiniMax Code を実行する

```bash
phaseo login
phaseo minimax --model openai/gpt-5.6-terra
```

ランナーは専用のキーを作成し、`MINIMAX_DATA_DIR` を一時ディレクトリに設定し、`mcode provider add` でそこに Phaseo プロバイダーを追加してから `mcode` を起動し、`mcode` の終了時にそのディレクトリを削除します。通常の `~/.minimax` の設定は変更されず、キーはプロバイダーの設定プロセスにのみ渡されます。MiniMax Code 自体のフラグは `--` の後に指定します。

| フラグ | 効果 |
| --- | --- |
| `--model <id>` | 使用するモデル。デフォルトは `openai/gpt-5.6-terra` です。 |
| `--catalog all` | Chat Completions で動作する Phaseo の有効なテキストモデルをすべて登録します。 |
| `--dry-run --json` | キーを作成せずに、インストールと起動の計画を表示します。 |
| `--skip-install` | インストールの確認をスキップします。 |

`phaseo run minimax ...` は同じコマンドの完全な形式です。

`mcode` がインストールされていない場合、初回の対話型の実行では MiniMax の公式インストーラー（Windows では PowerShell のインストーラー）によるインストールを提案します。MiniMax Code を自分で管理している場合は、インストールして `mcode --version` を確認し、`--skip-install` を付けて再実行します。

## MiniMax Code を手動で設定する

Phaseo プロバイダーを保持するには、MiniMax Code 自体のコマンドで追加します。

```bash
export MCODE_PROVIDER_API_KEY="your_phaseo_api_key"
mcode provider add \
  --name "Phaseo" \
  --base-url "https://api.phaseo.app/v1" \
  --api-format openai-completions \
  --model "openai/gpt-5.6-terra" \
  --use
```

MiniMax Code はプロバイダーをデータディレクトリに保存します。

## 動作を確認する

短いプロンプトを送信し、**設定 → 利用状況 → ログ**にリクエストが表示されることを確認します。

## よくある問題を解決する

### MiniMax Code がインストールされていない

対話型ターミナルでコマンドを実行して公式インストーラーを承認するか、MiniMax Code を自分でインストールして `--skip-install` を付けて再実行します。

### プロバイダーまたはモデルが一覧に表示されない

`phaseo minimax --catalog all` を使うか、`--model` でモデル ID を渡します。

### 対話型 CLI ではなく ACP が必要な場合

`phaseo minimax` は対話型 CLI を実行します。MiniMax Code は `mcode acp` で ACP プロセスとしても動作します。エディターやホストが ACP を直接扱う場合は、MiniMax Code の ACP の設定を使ってください。
