`@phaseo/cli` をインストールして `phaseo login` を実行すると、コーディングエージェントを Phaseo に接続し、キー、ワークスペース、プリセット、設定、ガードレールをターミナルから管理できます。CLI では、モデル、プロバイダー、料金、クレジット、アクティビティ、分析、生成の情報も参照できます。

## インストール

<CodeGroup>

```bash npm
npm install -g @phaseo/cli
```

```bash pnpm
pnpm add -g @phaseo/cli
```

```bash yarn
yarn global add @phaseo/cli
```

```bash bun
bun add -g @phaseo/cli
```

</CodeGroup>

バージョンを確認します。

| コマンド | 出力内容 |
| --- | --- |
| `phaseo --version` | インストールされているバージョン。 |
| `phaseo version` | バージョンと、お使いのパッケージマネージャー用の更新コマンド。構造化された出力には `--json` を付けます。 |

対話型の実行では、新しいバージョンが公開されたときにヒントも表示されます。

## サインインする

```bash
phaseo login
```

| フロー | フラグ | 用途 |
| --- | --- | --- |
| Phaseo でサインイン | `--browser` | 認可コードと PKCE を使うブラウザーの OAuth。 |
| デバイスコードでサインイン | `--device-code` | SSH、CI、ヘッドレスシェル、エージェント環境。 |

リモート環境と非対話型の環境では、自動的にデバイスコードが使われます。サインインしているユーザーを、スコープ、有効なワークスペース、その他のワークスペースとともに確認します。

```bash
phaseo whoami
phaseo whoami --json
```

## キーを作成してワークスペースを管理する

```bash
phaseo keys create --name "Local CLI Key"
phaseo keys create --name "Agent Sandbox Key" --json
phaseo keys current

phaseo workspaces list
phaseo workspaces members <workspace-id-or-slug>

phaseo guardrails list
phaseo guardrails create --name "Production Safety" --body-json '{"enabled":true}'
```

エージェントやスクリプトが新しいキーを必要とする場合は `--json` を使います。キーは 1 回しか表示されません。CLI は、請求、予算、BYOK、ルーティング、ID など、ダッシュボードの管理作業に対応しています。各作業のコマンドについては、[エージェントから Phaseo を管理する](../../developers/manage-from-an-agent)を参照してください。

## コーディングエージェントを接続する

エージェントの名前をコマンドとして使います。CLI は専用のキーを要求し、ブラウザーで承認されるとエージェントの設定を書き込みます。

```bash
phaseo codex
phaseo claude-code
phaseo opencode
phaseo fx
phaseo deepseek-harness
phaseo pi
phaseo prime-agent
phaseo openclaw
phaseo hermes
phaseo aider
phaseo continue
phaseo zed
phaseo roo-code
phaseo kilo-code
phaseo cursor
```

必要に応じて `--model`、`--catalog all|default`、`--dry-run` を使います。`phaseo setup <agent>` と `phaseo integrations setup <agent>` も使えます。

### ブラウザーでキーを承認する

エージェントを初めてセットアップすると、CLI は Phaseo ダッシュボードのページを開き、そのリンクを表示します。ページには、ワークスペース、キー名、月額 $100 の利用上限と 90 日の有効期限、そして Phaseo CLI からの要求であることが表示されます。**承認してキーを作成** を選ぶと、CLI がキーを一度だけ受け取り、セットアップを完了します。**拒否** を選ぶか、10 分経って要求の期限が切れた場合は、何も作成されません。

CLI で使ったアカウントでダッシュボードにサインインし、ワークスペースのオーナーまたは管理者として承認してください。2 要素認証を設定している場合は、その確認も必要です。CLI のサインインだけではキーを作成できません。SSH や CI では、表示されたリンクをサインイン済みの任意のデバイスで開いてください。

代わりにダッシュボードで作成したキーを使うには、`--key <key>` で渡します。シェルの履歴に残したくない場合は `--key-stdin` を使います。CLI はキーを確認して保存しますが、エージェントを削除してもそのキーは取り消しません。

終了時に削除される一時的な設定で Cline、Kilo Code、oh-my-pi、Muse Code、MiniMax Code を実行するには、セッションランナーを使います。Phaseo のフラグは `--` の前に、エージェント自体のフラグは `--` の後に指定します。

```bash
phaseo cline --model openai/gpt-5.6-terra -- --tui
phaseo kilo --model openai/gpt-5.6-terra
phaseo omp --model openai/gpt-5.6-terra
phaseo muse --model meta/muse-spark-1.3
phaseo minimax --model openai/gpt-5.6-terra
```

`phaseo run <cline|kilo|omp|muse|minimax>` は完全な形式です。Phaseo の有効なテキストモデルをすべて表示するには `--catalog all` を、キーを作成せずにプレビューするには `--dry-run --json` を付けます。対話型ターミナルでは、ランナーはインストールされていないエージェントのインストールを提案します（Windows では、MiniMax Code は公式の PowerShell インストーラーを使い、Muse Code は手動でインストールする必要があります）。エージェントを自分で管理している場合は `--skip-install` を使います。

すべてのエージェント、各コマンドの動作、ガイドの一覧は[コーディングエージェント](./coding-assistants.mdx)にあります。

## CLI でスクリプトを書く

`--json` を付けたコマンドは、色やスピナーのないプレーンな構造化出力を表示します。それ以外の場合、スピナーは `stderr` に出力され、完了すると行が消去されます。

| 変数 | 効果 |
| --- | --- |
| `NO_COLOR` | 色をオフにします。 |
| `TERM=dumb` | アニメーションをオフにします。TTY ではない `stderr` でも同様です。 |
| `FORCE_COLOR=1` | ターミナルのラッパーが色に対応しているのに TTY を報告しない場合に、色を強制します。 |

## CLI が資格情報を安全に保つ仕組み

- セッションは OS の資格情報ストアに保存されます。`PHASEO_SESSION_BACKEND=file` は、資格情報ストアが使えない場合にのみ設定してください。この設定では、リフレッシュトークンがアクセス権を制限した平文のファイルに保存されます。
- `phaseo logout` は、ローカルの状態を消去する前に、保存されたリフレッシュトークンを失効させます。
- 管理用キーには明示的な権限が必要です。推論用のキーは、スコープではなく、ガードレール、ルーティングポリシー、ワークスペースの設定によって制限されます。

## OAuth アプリ

Phaseo は、CLI、ユーザーが作成したアプリ、動的に登録された MCP クライアントで 1 つの OAuth 認可サーバーを使います。CLI は、ローテーションするリフレッシュトークンとともに、ブラウザーまたはデバイスによるログインを使います。サードパーティのクライアントは、PKCE 付きの認可コード、明示的なスコープとワークスペースの同意、任意の保護リソースのバインディングを使います。クライアントには、7 日間有効な失効可能なアクセストークンと、最後の使用から 90 日間有効なローテーションするリフレッシュトークンが発行されます。リフレッシュの仕組みについては、[OAuth Next.js ワークベンチを構築する](../../cookbook/build-an-oauth-nextjs-workbench)を参照してください。同じアプリを再度承認すると、2 つ目のキーが追加されるのではなく、既存のキーが更新されます。

ホストされている Phaseo API では、サードパーティの OAuth がオンになっています。セルフホストおよびプレビューの API デプロイでは、`PHASEO_THIRD_PARTY_OAUTH_ENABLED` が真の値（`1`、`true`、`yes`、`on`。大文字と小文字は区別せず、前後の空白は無視）でない限りオフのままです。

```bash .env
PHASEO_THIRD_PARTY_OAUTH_ENABLED=true
```

オンにすると、ユーザーが作成した OAuth アプリの管理と動的クライアント登録が公開されるため、先にリダイレクト URI、同意、クライアントシークレット、レート制限、ワークスペースの認可の設定を見直してください。

## 更新する

```bash
phaseo update
```

これにより、CLI のインストールに使ったパッケージマネージャーで更新が実行されます。手動で更新するには、次を実行します。

<CodeGroup>

```bash npm
npm install -g @phaseo/cli@latest
```

```bash pnpm
pnpm add -g @phaseo/cli@latest
```

```bash yarn
yarn global add @phaseo/cli@latest
```

```bash bun
bun add -g @phaseo/cli@latest
```

</CodeGroup>
