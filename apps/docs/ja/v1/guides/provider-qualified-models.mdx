`baseten:thinking-machines/inkling-small` のように、モデル ID の前にプロバイダー ID とコロンを付けると、リクエストはそのプロバイダーだけで実行され、他のプロバイダーへのフォールバックは行われません。

| 目的 | `model` に送る値 |
| --- | --- |
| Phaseo にプロバイダーを選ばせ、プロバイダー間でフォールバックさせる | `thinking-machines/inkling-small` |
| Baseten のみを使い、プロバイダー間のフォールバックはしない | `baseten:thinking-machines/inkling-small` |
| 1 つのプロバイダーにある検証済みの無料ルートを 1 つ使う | `google-ai-studio:google/gemma-4-26b-a4b:free` |

形式は `<provider-id>:<canonical-model-id>` です。最初のコロンがプロバイダーを区切り、モデル名前空間より後のコロンはモデル ID の一部として残ります。`google-ai-studio:google/gemma-4-26b-a4b:free` では、プロバイダーは `google-ai-studio`、モデルは `google/gemma-4-26b-a4b:free` です。

プロバイダーを優先したいだけで、失敗時にはフォールバックさせたい場合は、通常のモデル ID と[ルーティングとフォールバックの設定](./routing-and-fallbacks.mdx)を使ってください。

## リクエストを送信する

エンドポイントがモデル ID を受け付ける場所ならどこでも、プロバイダー指定の ID を使えます。

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "baseten:thinking-machines/inkling-small",
    "input": "Explain mixture-of-experts routing in two sentences."
  }'
```

```javascript JavaScript
const response = await fetch("https://api.phaseo.app/v1/responses", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "baseten:thinking-machines/inkling-small",
    input: "Explain mixture-of-experts routing in two sentences.",
  }),
});

const result = await response.json();
```

```python Python
import os
import requests

response = requests.post(
    "https://api.phaseo.app/v1/responses",
    headers={
        "Authorization": f"Bearer {os.environ['PHASEO_API_KEY']}",
        "Content-Type": "application/json",
    },
    json={
        "model": "baseten:thinking-machines/inkling-small",
        "input": "Explain mixture-of-experts routing in two sentences.",
    },
)

result = response.json()
```
</CodeGroup>

## プロバイダーが満たす必要がある条件

プロバイダー指定はルーティングを 1 つのプロバイダーに絞るだけで、他のチェックを省略するものではありません。プロバイダーは引き続き次の条件を満たす必要があります。

- 要求されたエンドポイントで正規モデルを提供し、その機能が有効になっている
- ワークスペース、API キー、プリセット、プライバシーの制限を満たす
- 要求されたサービスティアとパラメーターに対応している
- 料金が設定されている

いずれかのチェックに失敗すると、リクエストは拒否されます。Phaseo が黙って別のプロバイダーを選ぶことはありません。

## `provider` や `routing` フィールドと組み合わせる

プロバイダー指定と明示的なルーティングフィールドは一致している必要があります。一致する `provider.only` または `routing.only` は受け付けられます。

```json
{
  "model": "baseten:thinking-machines/inkling-small",
  "provider": { "only": ["baseten"] }
}
```

他のプロバイダーを指定した許可リストや、指定したプロバイダーを含む除外リストは、`provider_qualified_model_conflict` で拒否されます。

```json
{
  "model": "baseten:thinking-machines/inkling-small",
  "provider": { "only": ["deepinfra"] }
}
```

## 1 つのプロバイダーの無料ルートをリクエストする

プロバイダー指定の `:free` モデルは、そのプロバイダーにそのモデルとエンドポイントで利用できる無料ルートがある場合にのみ受け付けられます。正規の `:free` モデルがあっても、元のモデルのすべてのプロバイダーが無料で提供しているわけではありません。

```json
{
  "model": "google-ai-studio:google/gemma-4-26b-a4b:free",
  "input": "Hello"
}
```

ルートの料金カードが空でなく、現在のすべての料金ルールに `free` のラベルが付いていて、価格がちょうどゼロである必要があります。料金がない、有料、混在、または負の値の場合や、`free` のラベルがないゼロ円のルールがある場合は、プロバイダーに届く前にリクエストが拒否されます。

## プロバイダー ID とエイリアス

Phaseo のプロバイダーカタログにあるプロバイダー ID を使います（[API プロバイダー](../exploring/api-providers)を参照）。ID は小文字に変換され、既知の旧名やブランド名のエイリアスは正規の ID に対応付けられます。たとえば `NovitaAI` と `novita-ai` はどちらも `novita` になります。形式が不正な ID や不明な ID はプロバイダー選択の前に拒否され、モデル名の一部として上流に送られることはありません。

## 検証エラー

不正なプロバイダー指定の ID は、エラーコード `validation_error` とともに HTTP `400` を返します。原因は `reason` と `details[].keyword` で示されます。

| 理由 | 意味 |
| --- | --- |
| `invalid_provider_slug` | プロバイダー部分が空か、使用できない文字を含んでいます。 |
| `unknown_provider_slug` | プロバイダー ID の形式は正しいものの、Phaseo のプロバイダーではありません。 |
| `invalid_provider_qualified_model` | ID が `<provider>:<publisher>/<model>` に一致しません。 |
| `provider_qualified_model_conflict` | `provider.only`、`provider.ignore`、`routing.only`、`routing.ignore` のいずれかがプロバイダー指定と矛盾しています。 |
| `qualified_provider_unavailable` | プロバイダーは存在しますが、要求されたエンドポイントでそのモデルを提供していません。 |
| `qualified_free_provider_unavailable` | プロバイダーのルートが、すべてゼロの料金を持つ無料ルートとして検証されていません。 |

```json
{
  "error": "validation_error",
  "status_code": 400,
  "reason": "unknown_provider_slug",
  "description": "Unknown provider slug \"not-a-provider\" in provider-qualified model \"not-a-provider:publisher/model\". Use a provider slug returned by Phaseo's provider catalogue.",
  "provider": "not-a-provider",
  "model": "publisher/model",
  "details": [
    {
      "path": ["model"],
      "keyword": "unknown_provider_slug"
    }
  ]
}
```

その他のエラーの形式については、[エラーとデバッグ](../api-reference/errors.mdx)を参照してください。
