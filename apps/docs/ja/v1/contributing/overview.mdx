カタログの修正や追加は、対象のレコードと根拠となる情報源を添えて Issue を作成してください。コードやドキュメントの変更は、[Phaseo リポジトリ](https://github.com/phaseoteam/Phaseo)にプルリクエストを提出してください。

## 貢献の種類を選ぶ

| 変更 | 開始場所 |
| --- | --- |
| モデルのメタデータ、機能、提供状況、料金 | [モデルの更新を報告](./editing-a-model.mdx) |
| 企業や研究組織の詳細 | [組織の更新を報告](./editing-an-organisation.mdx) |
| ベンチマーク結果 | [スコアを提出](../research/submitting-scores.mdx) |
| その他のカタログの修正 | [誤った情報を報告](https://github.com/phaseoteam/Phaseo/issues/new?template=incorrect-info.yml) |
| 未掲載のプロバイダーやその他のカタログデータ | [新しいデータを依頼](https://github.com/phaseoteam/Phaseo/issues/new?template=data-request.yml) |
| ドキュメントまたはコード | [貢献の手順](./how-to-contribute.mdx)と[リポジトリ構成](./repo-structure.mdx) |

## カタログの報告が公開される流れ

メンテナーは Issue の根拠を確認し、管理者専用の[内部エディター](https://phaseo.app/internal/data)で承認済みの変更を適用します。プロバイダー料金の更新は、公開前に明示的なレビューが必要です。

カタログのレコードの唯一の情報源はデータベースです。リポジトリにはカタログ JSON がないため、プルリクエストでカタログのレコードを変更することはできません。

## 提出前に

- 対象のページまたはレコード ID を添え、提案する修正を説明してください。
- 公式の情報源を引用し、公表されたベンチマーク結果と独立した測定を区別してください。
- 各報告やプルリクエストは対象を絞ってください。
- 認証情報や顧客の非公開データは含めないでください。
- [行動規範](../community/code-of-conduct.mdx)に従ってください。

大きなスキーマ変更や機能変更は、実装前にメンテナーと相談してください。変更先がわからない場合は [Discord](https://discord.gg/aQyywCvgZ5) で質問してください。
