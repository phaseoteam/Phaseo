PhaseoはpnpmとTurborepoのモノレポです。コードやドキュメントの変更に必要なファイルを探すときに使ってください。カタログレコードの変更は[Issueを開いて](./overview.mdx)ください。

## アプリケーションとパッケージ

| パス | 用途 |
| --- | --- |
| `apps/web` | Next.js 16のWebサイト、ダッシュボード、内部カタログエディター。 |
| `apps/web-api` | 公開カタログの読み取りと、認証付きアカウント・管理API。 |
| `apps/api` | Cloudflare Workersでのゲートウェイルーティングとプロバイダー実行。 |
| `apps/docs` | Mintlifyドキュメント。MDXページは`v1`、ナビゲーションは`docs.json`。 |
| `packages/data/catalog` | カタログスキーマ、互換性フィクスチャ、生成された公開スナップショット。 |
| `packages/sdk` | TypeScript、Python、Go、C#、PHP、Ruby、Java、Rust、C++のSDK。 |
| `supabase/migrations` | データベーススキーマと権限のマイグレーション。 |
| `scripts` | 検証、SDK生成、自動化のユーティリティ。 |
| `.github/workflows` | CI、デプロイ、カタログ同期、スナップショットのスケジュール。 |
| `.changeset` | バージョン管理されたパッケージのリリースメタデータ。 |

## カタログデータ

モデル、プロバイダー、組織、料金、ベンチマーク、関連するカタログ設定の正本はデータベースです。管理者は[内部データ](https://phaseo.app/internal/data)でレコードを管理します。公開の貢献はGitHubのIssueでレビューされます。

- `packages/data/catalog/generated/database-v2`には毎日の公開スナップショットと、OpenAPI・SDKツールが使う生成済みモデル列挙インデックスがあります。
- `packages/data/catalog/src/data`にはアーカイブ済みの互換性フィクスチャがあります。
- どちらのディレクトリを編集しても本番カタログのレコードは更新されません。従来のJSONからデータベースへのインポーターは廃止されました。

スキーマとアプリケーションの変更には引き続きマイグレーションとプルリクエストを使います。生成されたスナップショットとSDK成果物は、それぞれの生成コマンドで更新してください。

## カタログの自動化

プロバイダー同期は、提案された料金を[プロバイダー更新](https://phaseo.app/internal/data/imports)でのレビュー待ちにします。ベンチマークとモデルのライフサイクルジョブはデータベースを使います。毎日の公開エクスポートは、レビュー可能なスナップショットのプルリクエストを作成します。

カタログだけのレコードはゲートウェイルーティングを自動で有効にしません。ルートと料金の変更には適切な管理者レビューが必要です。
