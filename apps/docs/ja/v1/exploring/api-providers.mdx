API プロバイダーは、モデル API をホストして提供するプラットフォームです。

モデル開発組織はモデルをトレーニングします。プロバイダーは本番エンドポイント、認証、使用量の制御、運用ツールを通じてモデルを利用可能にします。

## API プロバイダーが通常担うこと

- 認証とキー管理
- リクエストのルーティングと可用性の管理
- 使用量の計測と請求
- API と SDK の使いやすさ
- リージョン別ホスティングとコンプライアンス制御

## プロバイダーと組織の違い

| 項目 | 組織 | API プロバイダー |
| --- | --- | --- |
| 主な役割 | モデルを開発・学習する | モデル API をホストして提供する |
| 注力点 | 研究とモデル品質 | 信頼性、アクセス、運用 |
| 提供範囲 | 通常は自社のモデルファミリー | 複数組織のモデルを提供する場合がある |

製品によっては、1社が両方の役割を担います。

## Phaseo のプロバイダーページで確認できること

| セクション | 内容 |
| --- | --- |
| 概要 | プロバイダー情報、ドキュメントへのリンク、対応機能 |
| モデル | 利用可能なモデルとバリエーション |
| 価格 | プロバイダー価格の統一表記と課金単位 |
| 制限 | 利用可能な場合のリクエスト数とスループットの制限 |
| 機能 | ストリーミング、ツール、構造化出力、モダリティ対応 |

## プロバイダーレイヤーとしての Phaseo Gateway

Phaseo Gateway は多数のバックエンドへのアクセスを統一します。

利点:

- プロバイダー間で統一されたリクエストとレスポンスの形式
- プロバイダーを考慮したルーティングとフォールバック
- 複数プロバイダーの連携でも統一された SDK の使い方
- 使用量とコストを一元的に可視化
- プロバイダー独自キーを使う BYOK のオプション対応

## プロバイダーを選ぶ

プロバイダーを比較するときは、次の点を確認します。

- 用途に合ったモデルを利用できるか
- 対象リージョンでの信頼性とレイテンシ
- 想定トラフィックにおけるコスト
- ツール、ストリーミング、構造化出力への対応
- コンプライアンスとデータ取り扱いの要件

## 比較するときの質問

- 必要なモデルファミリーを提供しているプロバイダーはどれか
- 自分のリージョンでレイテンシが低いのはどのプロバイダーか
- 想定するトークン量で最も低コストなのはどれか
- 必要なエンドポイント機能に対応しているのはどのプロバイダーか
