変更する対象に合わせてガイドを選びます。アプリが呼び出すプラットフォーム(下記)か、アプリが使うモデル([モデルの移行](../model-migrations))です。両方を変更する場合は、まずプラットフォームを移行し、新しい経路を検証するまでモデルは変えないでください。

自分に合わせたチェックリストが必要な場合は、[移行アシスタント](https://phaseo.app/migrate)を使ってください。

<span id="platform-migrations"></span>
## プラットフォームの移行

どのプラットフォームのガイドも同じ順序で進みます。ベース URL とキーを切り替え、モデル ID を対応付け、プラットフォームの機能を対応付けてから、切り戻しをベース URL とキーの変更だけにしたままテストして展開します。

| 呼び出している対象 | コード上の目印 | ガイド |
| --- | --- | --- |
| OpenAI を直接 | `api.openai.com`、`OPENAI_API_KEY`、`AzureOpenAI` | [OpenAI SDK](./from-openai) |
| Anthropic を直接 | `api.anthropic.com`、`ANTHROPIC_API_KEY`、`@anthropic-ai/sdk` | [Anthropic SDK](./from-anthropic) |
| OpenRouter | `openrouter.ai`、`OPENROUTER_API_KEY`、`sk-or-v1` キー | [OpenRouter](./from-openrouter) |
| Vercel AI Gateway | `ai-gateway.vercel.sh`、`@ai-sdk/gateway`、AI SDK 呼び出しでの文字列のみのモデル指定 | [Vercel AI Gateway](./from-vercel) |
| LLM Gateway | `api.llmgateway.io`、`LLM_GATEWAY_API_KEY` | [LLM Gateway](./from-llmgateway) |
| LiteLLM プロキシ | `model_list` を含む `config.yaml`、`LITELLM_*` 変数、ポート 4000 | [LiteLLM](./from-litellm) |
| Cloudflare AI Gateway | `gateway.ai.cloudflare.com`、`cf-aig-*` ヘッダー | [Cloudflare AI Gateway](./from-cloudflare) |
| Helicone | `*.helicone.ai`、`Helicone-Auth` | [Helicone](./from-helicone) |

展開の計画と確認には、[移行機能チェックリスト](./feature-parity-matrix)を使ってください。

## モデルの移行

連携はそのままでモデルだけが変わる場合は、[モデル移行ガイド](../model-migrations)を使います。各ガイドでは、リクエストパラメーターの変更、プロンプトと推論の動作の変化、構造化出力とツール呼び出しの違い、フォールバックを用意した展開の方法を扱います。

どちらの移行でも、出力の品質を比べる前にリクエストパラメーターとエンドポイントの動作を確認し、本番のトラフィックを移す前に本番相当の評価を実行してください。
