OpenAI SDK はそのまま使い、ベース URL と API キーの 2 つだけを変更します。次に、各モデルに Phaseo の ID を指定します。Phaseo の ID には `openai/` プレフィックスが付きます。

| 設定 | OpenAI | Phaseo |
| --- | --- | --- |
| ベース URL | SDK の既定値(`https://api.openai.com/v1`) | `https://api.phaseo.app/v1` |
| API キー | `OPENAI_API_KEY` | `PHASEO_API_KEY`。`Authorization: Bearer` として送信 |
| モデル | `gpt-4.1-mini` | `openai/gpt-4.1-mini`、または `GET /v1/models` の任意の ID |
| リクエストのコード | `chat.completions.create`、`responses.create` | 変更なし |

## クライアントを切り替える

[Phaseo CLI](../guides/integrations/phaseo-cli) の `phaseo keys create` または [APIキー](https://phaseo.app/settings/keys)でキーを作成し、アプリを実行するすべての環境に追加します。次に、そのキーとベース URL を既存のクライアントに渡します。

<CodeGroup>
```typescript TypeScript
import OpenAI from "openai";

// Before: const client = new OpenAI();
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Reply with: migration ready" }],
});
```

```python Python
import os
from openai import OpenAI

# Before: client = OpenAI()
client = OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
)

response = client.chat.completions.create(
    model="openai/gpt-4.1-mini",
    messages=[{"role": "user", "content": "Reply with: migration ready"}],
)
```

```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-4.1-mini",
    "messages": [{"role": "user", "content": "Reply with: migration ready"}]
  }'
```
</CodeGroup>

Phaseo キーを `OPENAI_API_KEY` に入れるのではなく新しい変数名を使い、古い `OPENAI_BASE_URL` の値を削除して、リポジトリ内の他のクライアントが OpenAI を呼び出し続けないようにしてください。`AzureOpenAI` クライアントは通常の `OpenAI` クライアントに移行します。Azure のデプロイ名も同じ方法で Phaseo のモデル ID に対応付けます。

## モデル ID を対応付ける

Phaseo が提供する ID を OpenAI の一覧形式で表示し、本番のすべてのモデルを `data[].id` と照合します。

```bash
curl "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

`format=openai` を付けない場合、レスポンスは Phaseo のページ分割された `models` 一覧になり、`data` 配列はありません。`client.models.list()` でも同様で、Node では `{ query: { format: "openai" } }`、Python では `extra_query={"format": "openai"}` を渡してください。既定の一覧には現在呼び出せるモデルのみが含まれます。非アクティブなモデルや近日公開のモデルも含めるには `availability=all` を追加します。

## 動作が異なる点

| OpenAI の機能 | Phaseo での扱い |
| --- | --- |
| Chat Completions、Responses | `/v1/chat/completions` と `/v1/responses` で同じリクエスト形式。未知のトップレベルフィールドは `400` `unknown_param` を返します。 |
| `previous_response_id`、`conversation` | `400` を返します。Phaseo はレスポンスを保存しないため、毎回のリクエストで `input` に履歴全体を送ってください。 |
| 埋め込み、モデレーション、画像、音声合成、文字起こし | `/v1/embeddings`、`/v1/moderations`、`/v1/images/*`、`/v1/audio/*`。モデルがその操作に対応していることを確認してください。 |
| Batch API | `/v1/files` と `/v1/batches`。`/v1/files` が保持するのはバッチ入力のみで、他のリクエストに `file_id` 入力として渡すことはできません。 |
| Realtime | `POST /v1/audio/realtime/sessions` の後、返された `connect.url` に WebSocket で接続します。[リアルタイム音声](../guides/realtime-voice)を参照してください。 |
| 保存されたプロンプト(`prompt: { id: "pmpt_…" }`) | プロンプトをプリセットとして作り直し、`prompt: { id: "@slug", version, variables }` で呼び出します。[プロンプトテンプレート](../guides/prompt-templates)を参照してください。 |
| `organization`、`project`、`OpenAI-Organization` ヘッダー | 代替はありません。削除して、Phaseo のワークスペースとキーを使ってください。 |
| Assistants、Threads、ベクトルストア、ファインチューニング、旧来の `/v1/completions` | Phaseo のエンドポイントはありません。OpenAI に残すか、`/v1/responses` に移植してください。 |

## テストして展開する

同じ代表的なプロンプトを旧構成と新構成で実行し、出力の形式、レイテンシー、トークン使用量、エラー、コストを比較します。トラフィックを移す前に、次を確認してください。

- 開発、ステージング、本番に Phaseo キーが設定されている
- 本番のすべてのモデル ID が `GET /v1/models?format=openai` に表示される
- ステージングで非ストリーミングとストリーミングのリクエストが通り、アプリが使う場合はツール呼び出しと構造化出力も通る
- 切り戻しが引き続きベース URL とキーの変更だけで済む

その後、段階的にトラフィックを移します。フォールバックモデルについては[ルーティングとフォールバック](../guides/routing-and-fallbacks)を、アプリが受け取る可能性のあるエラーのボディについては[エラー処理](../api-reference/errors.mdx)を参照してください。
