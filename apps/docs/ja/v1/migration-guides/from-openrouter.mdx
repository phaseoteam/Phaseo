ベース URL を `https://api.phaseo.app/v1` に、キーを `PHASEO_API_KEY` に変更します。リクエストのペイロード、`Authorization: Bearer` ヘッダー、`provider` オブジェクト、`models` フォールバック配列はそのまま動作します。モデル ID と、下の表にあるいくつかのフィールドを確認してください。

| 設定 | OpenRouter | Phaseo |
| --- | --- | --- |
| ベース URL | `https://openrouter.ai/api/v1` | `https://api.phaseo.app/v1` |
| API キー | `OPENROUTER_API_KEY`(`sk-or-v1-…`) | `PHASEO_API_KEY` |
| 認証 | `Authorization: Bearer <key>` | 変更なし |
| リクエストのペイロード | OpenAI 互換 | 変更なし |
| モデル ID | `<org>/<model>` | `<org>/<model>`。ほとんどは一致しますが、一部の org は異なります |
| 帰属ヘッダー | `HTTP-Referer`、`X-Title` | 変更なし。安定したグループ分けのために `X-App-Id` を追加します |

## クライアントを切り替える

<CodeGroup>
```typescript Before
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.OPENROUTER_API_KEY,
  baseURL: "https://openrouter.ai/api/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Summarize our migration plan." }],
});
```

```typescript After
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Summarize our migration plan." }],
});
```

```bash cURL
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role":"user","content":"Say hello"}]
  }'
```
</CodeGroup>

最初の段階ではペイロードを変えず、最適化の前に同等の動作を確認してください。コード、CI、ホスティングの設定から `OPENROUTER_BASE_URL` と古いキーを削除します。`@openrouter/ai-sdk-provider` は `@phaseo/ai-sdk-provider` に置き換えます([Vercel AI Gateway からの移行](./from-vercel)を参照)。OpenRouter 独自の SDK(`@openrouter/sdk`、PyPI の `openrouter`)は、ベース URL の変更だけでなくクライアントの変更が必要です。

## モデル ID を確認する

ほとんどの ID は一致しますが、一部の org は異なります。`x-ai/` は `spacex-ai/`、`meta-llama/` は `meta/`、`mistralai/` は `mistral/` です。Phaseo の ID を一覧表示し、本番の各モデルと照合します。

```bash
curl -s "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY" | jq -r '.data[].id'
```

既定の一覧には現在呼び出せるモデルのみが含まれます。非アクティブなモデルや近日公開のモデルを表示するには `availability=all` を追加します。`format=openai` を付けない場合、レスポンスは Phaseo のページ分割された `models` 一覧になり、`data` 配列はありません。

## リクエストフィールドを対応付ける

| OpenRouter | Phaseo での扱い |
| --- | --- |
| `provider.order`、`only`、`ignore`、`allow_fallbacks`、`require_parameters`、`max_price` | 同じフィールドです。エンドポイントのスラッグではなく、基本のプロバイダー ID を使ってください。 |
| `provider.sort` | 同じフィールドです: `price`、`latency`、`throughput`。 |
| `provider.zdr` | `provider.require_zero_data_retention` の別名として受け付けます。 |
| `provider.data_collection: "deny"` | `400` を返します。代わりに `zdr: true` を使ってください。 |
| `models` フォールバック配列 | 同じです。1〜25 件。`model` は必須なので、`models[0]` をそこに移してください。 |
| `:nitro` サフィックス | 同じです(スループット)。Phaseo には `:cheap` と `:fast` もあり、`:floor` は `:cheap` になります。`:online` と `:thinking` は削除し、代わりに Web 検索と `reasoning` を使ってください。 |
| `openrouter/auto`、`openrouter/free` | `phaseo/auto`([自動ルーティング](../guides/auto-routing)、アルファ版、`models` とは併用不可)と `phaseo/free`。 |
| `plugins` の `web`、`web-fetch`、`response-healing` | 同じプラグイン ID です。`file-parser` などのその他のプラグインは `400` を返します。 |
| `transforms`、`usage: { include: true }` | 受け付けません。削除してください。使用量とコストは常に返されます。 |
| `X-OpenRouter-Title` | `X-Title` に名前を変えてください。[アプリの帰属](../guides/app-attribution)を参照してください。 |
| プリセット `@preset/<slug>` | [プリセット](../guides/presets)として作り直し、`"model": "@slug"` として呼び出します。 |
| レスポンスの `usage.cost`、`reasoning_details`、`provider` | 返されます。`native_finish_reason` と `is_byok` は返されないため、呼び出し元が読んでいる場合は 1 つの層で正規化してください。 |

Phaseo には `provider.required_execution_region` と `provider.required_data_region` もあり、これらに相当するものは OpenRouter にはありません。完全なリクエスト例は、[プロバイダーを固定または除外する](../cookbook/pin-or-ignore-providers-per-request)と[EU または ZDR 対応のプロバイダーにのみルーティングする](../cookbook/route-only-to-eu-or-zdr-providers)を参照してください。

切り戻しがベース URL とキーの変更で済むよう、残った OpenRouter 専用のフィールドは呼び出し箇所ごとではなく、1 つのアダプターにまとめてください。

## 切り替え前に検証する

次のコマンドを Phaseo に対して実行し、続いて同じ確認をアプリ自身のクライアント経路で行います。

```bash
curl -s "https://api.phaseo.app/v1/health"

curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"openai/gpt-6-astra","messages":[{"role":"user","content":"Say hello"}]}'

# ストリーミング
curl -N "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"openai/gpt-6-astra","stream":true,"messages":[{"role":"user","content":"Reply with: stream works"}]}'

# 無効なモデル: アプリは認証情報を露出せずにエラーを処理する必要があります
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"invalid/migration-test","messages":[{"role":"user","content":"test"}]}'
```

まとまった量のトラフィックを移す前に、次を確認してください。

- すべての環境で `OPENROUTER_API_KEY` が `PHASEO_API_KEY` に置き換えられている
- 本番のすべてのモデル ID が `GET /v1/models?format=openai` にある
- 本番と同じクライアント経路を使い、`/v1/chat/completions` または `/v1/responses` で非ストリーミングとストリーミングのリクエストが通る
- 実際のプロンプトでツール呼び出しと構造化出力のフローが通る
- 無効なキーと無効なモデルの失敗を処理している
- 失敗したリクエストを `GET /v1/generations?id=<request_id>` で調べられ、`replay_supported` が `true` の場合は `replay_request` からリプレイできる
- OpenRouter 専用のヘッダーとレスポンスフィールドが削除または正規化され、共有の既定値がプリセットにまとまっている

## 展開する

1. 社内のトラフィックから始めます。
2. 本番トラフィックの 5〜10% を移し、品質、レイテンシー、コストを比較します。
3. 同等であることを確認したら 100% に引き上げます。
4. 切り替えが安定するまで、切り戻しはベース URL とキーの切り替えで済むようにしておきます。

## 移行をコーディングエージェントに任せる

エージェントには次の範囲を限定した手順を渡すか、同じ棚卸し、対応付け、検証、切り戻しの手順をまとめた [OpenRouter から Phaseo への移行スキル](https://github.com/phaseoteam/Phaseo/tree/main/.agents/skills/openrouter-to-phaseo-migration)をインストールしてください。

1. ランタイムのコードとデプロイ設定から `openrouter.ai`、`OPENROUTER_API_KEY`、`sk-or-v1`、`HTTP-Referer`、`X-Title` を検索します。
2. ソース管理にシークレットの値を追加せずに、クライアントの境界を `https://api.phaseo.app/v1` と `PHASEO_API_KEY` に変更します。
3. `GET /v1/models?format=openai` を照会し、旧モデルから新モデルへの対応付けをすべて記録します。
4. OpenRouter 専用のルーティングオプションやレスポンスフィールドを、1 つの互換モジュールで変換します。
5. 上記のヘルスチェック、非ストリーミング、ストリーミング、失敗経路の確認を実行します。
6. 変更したファイル、シークレット名の変更、モデルの対応付け、テストの証跡、同等性のギャップ、切り戻しのスイッチを報告します。

手順を追って進めたい場合は、[インタラクティブな OpenRouter 移行ガイド](https://phaseo.app/migrate/openrouter)を開くか、両者の[比較](https://phaseo.app/compare/openrouter)を確認するか、[移行の無料サポート](https://phaseo.app/contact)を依頼してください。
