ベース URL とキーを切り替え、リクエストのペイロードはそのままにして、各モデル ID を対応付けます。LLM Gateway のプレフィックスは提供元のプロバイダーを表し、Phaseo のプレフィックスはモデルの開発元を表します。

| 設定 | LLM Gateway | Phaseo |
| --- | --- | --- |
| ベース URL | `https://api.llmgateway.io/v1` | `https://api.phaseo.app/v1` |
| Anthropic 形式のクライアント | `ANTHROPIC_BASE_URL=https://api.llmgateway.io` | `https://api.phaseo.app`。[Anthropic SDK からの移行](./from-anthropic)を参照してください |
| API キー | `LLM_GATEWAY_API_KEY`(`llmgtwy_…`) | `PHASEO_API_KEY` |
| モデル ID | `gpt-4o`、`<provider>/<model>`、`auto` | `GET /v1/models?format=openai` の `<org>/<model>` |
| リクエストのペイロード | OpenAI 互換 | 変更なし |

## クライアントを切り替える

<CodeGroup>
```typescript TypeScript
import OpenAI from "openai";

// Before:
// new OpenAI({ apiKey: process.env.LLM_GATEWAY_API_KEY, baseURL: "https://api.llmgateway.io/v1" });
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});
```

```python Python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
)
```

```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```
</CodeGroup>

CI やホスティングの設定も含め、すべての `LLM_GATEWAY_*` 変数を対応付けるか削除してください。アプリが `@llmgateway/ai-sdk-provider` を使っている場合は、[Vercel AI Gateway からの移行](./from-vercel)のとおり `@phaseo/ai-sdk-provider` に切り替えます。

## モデル ID を対応付ける

Phaseo の ID を一覧表示し、本番の各モデルと照合します。

```bash
curl -s "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY" | jq -r '.data[].id'
```

LLM Gateway の `alibaba/<model>` は Phaseo の ID ではありません。各 ID を Phaseo の `<org>/<model>` に対応付け、プロバイダーの固定は `provider.only` または `provider:org/model` 形式の ID で維持します。`gpt-4o` のようなプレフィックスのないエイリアスは、呼び出し箇所ごとではなく、クライアントの境界にある 1 つの関数で変換してください。

## Gateway の機能を対応付ける

| LLM Gateway | Phaseo での扱い |
| --- | --- |
| `auto` ルーター | `phaseo/auto`([自動ルーティング](../guides/auto-routing)、アルファ版)。`models` とは併用できません。 |
| フォールバックチェーン | `models` 配列または動的ルート。`429`、`500`、`502`、`503`、`504` で試され、リクエストエラーでは試されません。 |
| `X-No-Fallback` | `provider.allow_fallbacks: false`、または `provider:org/model` 形式の ID。 |
| プロバイダーの許可・拒否ロジック | `provider.only`、`provider.ignore`、または[プリセット](../guides/presets)。対象となるプロバイダーを少なくとも 1 つ残してください。 |
| `X-LLMGateway-<Key>` ヘッダー | `X-Phaseo-Metadata` の[ラベル](../guides/request-labels)。最大 32 個です。 |
| セッションヘッダー(`x-session-id`) | ボディの `session_id` フィールド。Phaseo はセッションヘッダーを無視します。 |
| `X-Source` | `HTTP-Referer` または `X-App-Name`。[アプリの帰属](../guides/app-attribution)を参照してください。 |
| レスポンスキャッシュ | レスポンスキャッシュはありません。 |
| プロバイダーキー | BYOK(`phaseo byok create` または `POST /v1/byok`)、または Phaseo のクレジット。クレジットへのフォールバックはワークスペース設定の `byok_fallback_enabled` です。 |
| リクエストログ | リクエストログ、オブザーバビリティの送信先、`GET /v1/generations?id=<request_id>`。`replay_supported` が `true` の場合は、失敗したリクエストを `replay_request` のペイロードからリプレイできます。 |

## テストして展開する

基準となるプロンプトを両方の Gateway で実行し、品質、レイテンシー、コストを比較します。まずエンドポイントを確認してください。

```bash
curl -s "https://api.phaseo.app/v1/health"
curl -s "https://api.phaseo.app/v1/models?format=openai" -H "Authorization: Bearer $PHASEO_API_KEY"
```

トラフィックを移す前に、次を確認してください。

- すべての環境に `PHASEO_API_KEY` が設定されている
- 本番のすべてのモデル ID が対応付けられ、一覧に載っている
- ステージングで非ストリーミングとストリーミングのリクエストが通る
- 無効なキーと無効なモデルのエラーを処理している。エラーのボディは LLM Gateway と異なる場合があります
- ステージングで失敗したリクエストを `GET /v1/generations` から復元できる
- 共有のプロンプトとルーティングの既定値が、本来あるべきプリセットにまとまっている

カナリアフラグの背後でリリースし、安定したら少量のトラフィックから全量へ移します。旧設定を削除する前に、少なくとも 1 リリースサイクルは本番のメトリクスを監視してください。
