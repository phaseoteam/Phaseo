モデルを `openai/gpt-5.4` に変更し、リクエストの残りはそのままにして、ルートごとに推論の effort を選びます。リクエスト形式は以前の GPT-5 モデルと同じで、変わるのは effort の範囲、画像の詳細度、computer ツールです。OpenAI のドキュメントには、GPT-5.4 固有の `phase` パラメーターの説明はありません。

| 変更点 | 行うこと |
| --- | --- |
| `reasoning.effort` が `none`、`low`、`medium`、`high`、`xhigh` を受け付ける | 各ルートを、そのレイテンシーの予算に合った effort で再テストします。 |
| 完全な忠実度で認識するための画像入力 `detail: "original"` | 品質とコストが変わるため、別途テストします。 |
| 更新された `computer` ツールがコンピューター操作の手段になる | ブラウザーとデスクトップの自動化をこれに移し、エンドツーエンドで再テストします。 |
| 長期のツール使用、大きなコンテキストの作業、ドキュメントのワークフローが向上 | エージェントとドキュメントの評価を再実行します。 |

```json
{
  "model": "openai/gpt-5.4",
  "input": "Summarize the open risks in this design review.",
  "reasoning": { "effort": "medium" }
}
```

## 推論の effort を選ぶ

GPT-4.1 または以前の GPT-5 モデルから移行する場合は、以前の既定値がそのまま合うとは考えないでください。

| ルート | 最初に試す値 |
| --- | --- |
| 低レイテンシー | `none` または `low` |
| ほとんどの構造化タスク | `medium` または `high` |
| 深い推論とエージェントのワークフロー | `xhigh` |

## 画像を完全な詳細度で送る

情報量の多いスクリーンショット、ドキュメント、UI のローカライズでは、画像入力に `detail: "original"` を設定します。Phaseo は、OpenAI や Azure などこれに対応するプロバイダーにはそのまま渡し、対応しないプロバイダーには最も近いレベルの `high` を送ります。

## コンピューター操作を `computer` ツールに移す

ブラウザーとデスクトップの自動化を `computer` ツールに更新し、タスク全体を通してステップの完了を再テストします。ホスト型のツールは、それを実行するプロバイダーにのみルーティングされます。

## テストする内容

- **プロンプト:** 長いシステムプロンプト、抽出と分類、書式に敏感な出力、タスクから外れないためにリトライが必要だったプロンプト。
- **ツールと構造化出力:** 各 effort レベルでのスキーマへの準拠、ツールの選択、引数の完全性、複数ステップのコンピューター操作の安定性。
- **ビジョンと運用:** `high` と `original` の詳細度でのスクリーンショットとドキュメント、負荷時のレイテンシーとトークン使用量、リトライとタイムアウトの率、置き換えるモデルと比べた成功したタスクあたりのコスト。

## 展開する

1. 実際に使う effort レベルそのもので GPT-5.4 をベンチマークします。
2. 既定のルートを切り替える前に、本番のプロンプトでシャドー実行します。
3. 古い OpenAI モデルまたは別のプロバイダーを `models` のフォールバックとして、段階的に昇格させます。
