# OpenAI GPT-5.4

`openai/gpt-5.4` を本番環境に安全に導入するには、このガイドを使います。

GPT-5.4 の主な変更点は、まったく新しいリクエスト形式ではなく、推論制御、画像処理、ツール利用の更新です。2026 年 3 月 10 日時点で、OpenAI の公式ドキュメントは `reasoning.effort`、改善されたコンピューター操作、高忠実度の画像入力を紹介しています。GPT-5.4 固有の `phase` パラメーターは記載されていません。

## 移行クイックスタート

1. ほかのリクエスト部分は変更せず、モデル ID を `openai/gpt-5.4` にします。
2. ルートのレイテンシ予算に合う推論 effort を選び、テストします。
3. 必要に応じてビジョン、構造化出力、コンピューター操作のワークフローを再テストします。
4. 以前の経路をフォールバックとして残し、GPT-5.4 を段階的に試します。

## 新機能

- `reasoning.effort` は `none`、`low`、`medium`、`high`、`xhigh` に対応します。
- GPT-5.4 は高忠実度の視覚認識向けに `original` 画像詳細度を追加します。
- 更新された `computer` ツールが GPT-5.4 のコンピューター操作ワークフローで推奨される公式経路です。
- 長時間のツール利用、大きなコンテキスト、業務文書のワークフローが改善されています。

## 連携で変更する内容

### 1. 推論設定を確認する

GPT-4.1 や以前の GPT-5 から移行する場合、以前のデフォルトが最適とは限りません。レイテンシ予算に合う effort で各経路を再テストします。

- 低レイテンシの経路には `none` または `low`。
- 多くの構造化タスクには `medium` または `high`。
- 深い推論やエージェント処理には `xhigh`。

### 2. ビジョンのパイプラインを見直す

詳細なスクリーンショット、文書、UI ローカライズを扱う場合は、新しい画像詳細度 `original` をテストします。忠実度とコストの両方が変わります。

### 3. コンピューター操作の経路を確認する

ブラウザーやデスクトップの自動化タスクを移行する場合は、`computer` ツールの現行経路に更新し、各ステップの完了まで通して再テストします。

## テスト項目

### プロンプトとの互換性

- 長いシステムプロンプト
- 抽出と分類のプロンプト
- 書式に敏感な出力
- 以前は指示から逸れないよう再試行が必要だったプロンプト

### ツールと構造化出力

- 各 effort レベルでのスキーマ遵守
- ツール選択の品質
- 引数の完全性
- 複数ステップのコンピューター操作の安定性

### ビジョンと運用

- `high` と `original` によるスクリーンショットや文書の理解
- 現実的な負荷でのレイテンシとトークン使用量
- 再試行率とタイムアウト率
- 移行元モデルと比較したタスク成功あたりのコスト

## 安全なロールアウト

1. 実際に使う effort レベルで GPT-5.4 を評価します。
2. 画像を使う場合は、品質とコストが変わるため `original` を個別にテストします。
3. デフォルト経路を変更する前に、本番プロンプトをシャドー実行します。
4. 古い OpenAI モデルまたは別のプロバイダーをフォールバックに残して、段階的に拡大します。
