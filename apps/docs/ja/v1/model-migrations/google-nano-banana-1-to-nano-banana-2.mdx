画像リクエストを `google/gemini-3.1-flash-image`(Nano Banana 2)に切り替え、`image_config` でアスペクト比と出力サイズを選びます。最初に壊れるのは、画像サイズが 1 つだけだと想定している下流のコードです。

| | Nano Banana | Nano Banana 2 |
| --- | --- | --- |
| Phaseo のモデル ID | `google/gemini-2.5-flash-image` | `google/gemini-3.1-flash-image` |
| ステータス | 非推奨。2027 年 3 月 15 日に提供終了 | 利用可能 |

Nano Banana 2 では、アスペクト比(`image_config.aspect_ratio`。`16:9` や `9:16` など)と、512px から 4K までの出力サイズ(`image_config.image_size`: `0.5K`、`1K`、`2K`、`4K`)を明示的に制御できます。Google は、生成と編集をまたいだ被写体の一貫性の向上、指示への追従性の強化、画像内のテキストの描画と翻訳の改善、同程度の速度でのより高い忠実度も報告しています。後継の `google/gemini-nano-banana-2.1` も利用できます。

```json
{
  "model": "google/gemini-3.1-flash-image",
  "messages": [{ "role": "user", "content": "A product photo of a ceramic mug on a walnut desk." }],
  "modalities": ["image", "text"],
  "image_config": { "aspect_ratio": "16:9", "image_size": "2K" }
}
```

`image_config` を受け付けないプロバイダーはこれを除外し、`X-Phaseo-Dropped-Params` レスポンスヘッダーに記載します。[パラメーター](../api-reference/parameters)を参照してください。

## プロダクトを更新する

1. **出力に関する前提を確認します。** 下流のコードが固定のサイズ、アスペクト比、切り抜きを前提としている場合は、まずそこを更新します。
2. **プリセットを見直します:** SNS 向けのアスペクト比、既定のサイズ、編集とインペイントのワークフロー、画像サイズを表す UI のラベル。
3. **編集用のプロンプトを短くします。** 古いモデルを補うために構図、テキスト、スタイルを細かく指定しすぎたプロンプトは、今では硬直しすぎている可能性があります。短いバージョンで再テストしてください。

## テストする内容

- **出力の品質:** 縦長、正方形、横長の比率、小さいサイズと大きいサイズ、編集をまたいだ被写体の一貫性、画像内のテキスト・看板・キャプション・翻訳されたテキスト。
- **ワークフロー:** 大きいサイズでのファイルの扱い、高忠実度の生成でのタイムアウト、モデレーションや人によるレビューの合格率、下流でのリサイズ。
- **プロダクトのメトリクス:** エンドツーエンドのレイテンシー、使える出力の割合、リトライ率、承認されたアセットあたりのコスト。

## 展開する

1. 1 つの移行としてではなく、アスペクト比とサイズごとにテストします。
2. サポートする最大のサイズで、アセットのパイプラインを検証します。
3. 実際の本番プロンプト、特に編集と画像内テキストのリクエストを抽出してテストします。
4. UI で画像のオプションを公開している場合は、既定のプリセットの変更をモデルの切り替えとは別に出荷します。
