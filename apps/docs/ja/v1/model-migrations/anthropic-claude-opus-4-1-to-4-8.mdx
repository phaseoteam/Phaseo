Claude Opus 4.1 のトラフィックを `anthropic/claude-opus-4.8` に移します。モデル ID を変更し、サンプリングパラメーターを削除し、思考の予算を effort レベルに置き換えます。

Anthropic は 2026 年 6 月 5 日に Opus 4.1 を非推奨とし、2026 年 8 月 5 日に提供を終了しました。Phaseo は、いずれかのプロバイダーが提供している間は `anthropic/claude-opus-4.1` の提供を続け、提供するプロバイダーがなくなると、それらのリクエストを Opus 4.8 にルーティングします([モデルの非推奨化と提供終了](../guides/model-retirement)を参照)。変更が自動で行われるのではなくテスト済みの状態になるよう、その前に移行してください。

Anthropic のガイダンスは累積的です。Opus 4.7 のリクエスト形式の変更を適用してから、Opus 4.8 の動作の変更を確認してください。

| | Claude Opus 4.1 | Claude Opus 4.8 |
| --- | --- | --- |
| Phaseo のモデル ID | `anthropic/claude-opus-4.1` | `anthropic/claude-opus-4.8` |
| コンテキストウィンドウ | 200K トークン | 1M トークン |
| 最大出力 | 32K トークン | 128K トークン |
| `temperature`、`top_p`、`top_k` | 送信される | Phaseo が除外する |
| 思考 | `budget_tokens` | 適応型。effort で調整(既定は `high`) |
| 会話途中のシステムメッセージ | 不可 | 可 |

## リクエストを更新する

**1. モデル ID を変更します。** `anthropic/claude-opus-4.8` にします。

**2. サンプリングパラメーターを削除します。** Anthropic は、Opus 4.7 以降で既定以外の `temperature`、`top_p`、`top_k` を `400` で拒否します。Phaseo は失敗させる代わりにこれらを除外するため、もう何の効果もありません。代わりに指示で調整してください。

**3. 思考の予算を effort レベルに置き換えます。** Phaseo は `budget_tokens` を Opus 4.8 に転送しません。推論の設定はすべて `thinking: {"type": "adaptive", "display": "summarized"}` として送られ、`reasoning.effort`(`/v1/messages` では `output_config.effort`)で深さを設定します。

```json
{
  "model": "anthropic/claude-opus-4.8",
  "max_tokens": 4096,
  "thinking": { "type": "adaptive" },
  "output_config": { "effort": "high" },
  "messages": [{ "role": "user", "content": "Plan the schema migration." }]
}
```

推論の設定がない場合、Opus 4.8 は思考しません。`reasoning.effort: "none"` は `thinking: {"type": "disabled"}` を送ります。

**4. effort と長いコンテキストの基準を取り直します。** Opus 4.8 は effort の既定値が `high` で、コンテキストウィンドウも Opus 4.1 よりはるかに大きくなっています。レイテンシーの予算、トークン使用量、プロンプトキャッシュ、長いドキュメントや長時間のエージェントのトレースを再テストしてください。Microsoft Foundry では、Anthropic はリリース時点での Opus 4.8 のコンテキストウィンドウを 200K と記載しています。

**5. 長い会話での指示の更新を簡素化します。** Opus 4.8 は会話の途中で `role: "system"` メッセージを受け付けます。エージェントのループが毎ターンシステムプロンプト全体を書き換えている場合は、代わりにシステムメッセージを追加すると、キャッシュヒットを多く保てます。

## テストする内容

- まだ `temperature`、`top_p`、`top_k` を送っているリクエスト。これらの効果はなくなっています
- `budget_tokens` に依存していた思考のルート
- 長期にわたるエージェントとツールのワークフロー
- 各 `effort` レベルでの、スキーマに敏感な出力
- Opus 4.1 で最も量の多いプロンプト分類でのトークンコストとレイテンシー

## 展開する

1. トラフィックを切り替える前に、サンプリングパラメーターと思考の予算を削除します。
2. 本番相当のプロンプトとツールフローで Opus 4.8 をシャドー実行します。
3. プロバイダーがまだ提供している間は、`models` に Opus 4.1 をフォールバックとして入れてカナリアリリースします。
4. レイテンシー、コスト、タスク完了の変化が目標内に収まったら昇格させます。
