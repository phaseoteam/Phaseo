モデルを `anthropic/claude-opus-4.7` に変更し、サンプリングパラメーターと思考の予算を外して、深さを effort レベルで設定します。Opus 4.6 のフィールドを含んだままのリクエストも Phaseo では失敗せず、Gateway が次のように書き換えます。

| Opus 4.6 のリクエスト | Phaseo が Opus 4.7 に送る内容 |
| --- | --- |
| `temperature`、`top_p`、`top_k` | 除外されます。既定以外の値には Anthropic が `400` を返すためです。 |
| `thinking: {"type": "enabled", "budget_tokens": …}` | `thinking: {"type": "adaptive", "display": "summarized"}`。予算は転送されません。 |
| `reasoning.effort` | `output_config.effort`。`xhigh` も含みます。 |
| `reasoning.effort: "none"` または `reasoning.enabled: false` | `thinking: {"type": "disabled"}`。 |
| 推論の設定なし | `thinking` フィールドなし。Opus 4.7 は思考しません。 |

また、Opus 4.7 はオプトインしない限り思考の内容を表示しません。Phaseo は思考を有効にするときは常に要約表示を要求します。Opus 4.7 のトークナイザーは、同じテキストに対して Opus 4.6 より多くのトークンを生成することがあります。

## リクエストを更新する

1. モデル ID を `anthropic/claude-opus-4.7` に設定します。
2. `temperature`、`top_p`、`top_k` を削除し、代わりに指示で調整します。
3. 思考の予算を、適応型思考と effort レベルに置き換えます。

```json
{
  "model": "anthropic/claude-opus-4.7",
  "messages": [{ "role": "user", "content": "Refactor this module and explain the risks." }],
  "reasoning": { "effort": "xhigh" }
}
```

まず `high` から始め、最も難しいコーディングやエージェントのルートには `xhigh` を使います。`/v1/messages` では、代わりに `thinking: {"type": "adaptive"}` と `output_config.effort` を送ります。

4. トークナイザーが変わったため、`max_tokens` と `max_output_tokens`、タイムアウトの予算、コストアラートを見直します。

## テストする内容

- 本番プロンプトでのスキーマ合格率
- 長時間実行するツールワークフロー: ツール呼び出しの回数、完了率、レイテンシー
- `high` と `xhigh` での品質の比較
- 最も量の多いプロンプト分類でのトークンコスト

## 展開する

1. トラフィックを移す前に、リクエスト形式の変更をデプロイします。
2. 本番の評価スイートで Opus 4.7 をシャドー実行します。
3. `models` に Opus 4.6 をフォールバックとして入れてカナリアリリースします。
4. 品質、レイテンシー、コストの変化が目標内に収まったら昇格させます。
