# Mistral Small 4

Phaseo Gateway で Mistral Small 4 を安全に導入するには、このガイドを使います。

- `mistral/mistral-small-4-2026-03-16`

## 新機能

- `reasoning_effort` で推論モードを制御できます。
- Gateway がこのモデル経路で上流に送る値は次の 2 つだけです。
  - `none`（推論オフ）
  - `high`（推論オン）
- Gateway は Mistral の思考ブロックを標準の応答フィールドに変換します。
  - `message.content`：アシスタントがユーザーに表示するテキスト
  - `message.reasoning_content` と `message.reasoning_details`：推論テキスト

## 移行クイックスタート

この経路では、推論はデフォルトでオフです。

Gateway のマッピング規則：

- 推論制御を省略すると `reasoning_effort: "none"` を送信します。
- `reasoning.enabled: true` を指定すると `reasoning_effort: "high"` を送信します。
- `reasoning.effort: "none"` を指定すると `reasoning_effort: "none"` を送信します。
- `reasoning.effort` にそれ以外の値を指定すると `reasoning_effort: "high"` を送信します。

推奨設定：

- 軽い処理には `reasoning.effort: "none"` を使います。
- 深い推論には `reasoning.effort: "high"` を使います。

例：

```json
{
  "model": "mistral/mistral-small-4-2026-03-16",
  "messages": [
    { "role": "user", "content": "Why is fast inference important?" }
  ],
  "reasoning": {
    "effort": "high"
  }
}
```

## 応答の処理に関する注意

Mistral は `thinking` と `text` のような異なるアシスタントコンテンツブロックを返すことがあります。Gateway は次の安定した形式に変換します。

- ユーザーに表示する最終回答：`choices[0].message.content`
- 推論テキスト：`choices[0].message.reasoning_content`

これにより、OpenAI 形式のチャット補完フィールドを期待する後続処理を維持できます。

## ロールアウトのチェックリスト

1. モデル ID を `mistral/mistral-small-4-2026-03-16` に更新します。
2. 推論制御が `none` と `high` だけで動作することを確認します。
3. 高負荷の経路で出力品質とスキーマのテストを再実行します。
4. 全面移行の前に、`none` と `high` のレイテンシとコストを比較します。
