モデルを `mistral/mistral-small-4` に変更し、ルートごとに推論をオンにするかどうかを決めます。Mistral Small 4 にはオフと high の 2 つの推論モードがあり、Phaseo はすべての effort の値をそのどちらかに対応付けます。

```json
{
  "model": "mistral/mistral-small-4",
  "messages": [
    { "role": "user", "content": "Why is fast inference important?" }
  ],
  "reasoning": { "effort": "high" }
}
```

## 推論をオンまたはオフにする

リクエストで求めない限り、推論はオフです。Mistral 自身の API に対して、Phaseo は `reasoning_effort` を次のように送ります。

| リクエスト | Mistral に送られる値 |
| --- | --- |
| 推論の設定なし | `reasoning_effort: "none"` |
| `reasoning.effort: "none"` または `reasoning.enabled: false` | `reasoning_effort: "none"` |
| その他の `reasoning.effort`、または `reasoning.enabled: true` | `reasoning_effort: "high"` |

リクエスト内のフラットな `reasoning_effort` は `reasoning.effort` より優先されます。軽量なルートには `none` を、深い推論には `high` を使います。`low` と `medium` は `high` とまったく同じ動作です。

## 回答と推論を読み取る

Mistral は、`thinking` の後に `text` が続くような混在したコンテンツブロックを返すことがあります。Phaseo はこれらを OpenAI 形式のフィールドに分割するため、Chat Completions を読む下流のコードはそのまま動作します。

- 回答は `choices[0].message.content` にあります。
- 推論のテキストは `choices[0].message.reasoning_content` と `reasoning_details` にあります。

## 展開する

1. モデル ID を Mistral Small 3.2 から `mistral/mistral-small-4` に変更します。
2. `none` と `high` のみで推論をテストします。
3. `high` を使うルートで、出力の品質とスキーマのテストを再実行します。
4. 完全に切り替える前に、`none` と `high` のレイテンシーとコストを比較します。
