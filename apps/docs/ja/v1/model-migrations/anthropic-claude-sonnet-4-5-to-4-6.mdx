モデルを `anthropic/claude-sonnet-4.6` に変更し、assistant のプリフィルを削除し、構造化出力を `output_config.format` に移します。Sonnet 4.6 のこれらのリクエストの変更は [Claude Opus 4.6](./anthropic-claude-opus-4-5-to-4-6) と共通です。さらに、コーディング、コンピューター操作、エージェントの計画での性能が大きく異なるため、プロンプトとルーティングの前提を再テストする必要があります。

| | Claude Sonnet 4.5 | Claude Sonnet 4.6 |
| --- | --- | --- |
| Phaseo のモデル ID | `anthropic/claude-sonnet-4.5` | `anthropic/claude-sonnet-4.6` |
| ステータス | 非推奨。2026 年 11 月 30 日に提供終了 | 利用可能 |
| コンテキストウィンドウ | 200K トークン | 1M トークン |
| 最大出力 | 64K トークン | 64K トークン |
| assistant のプリフィル | サポート | `400` を返す |
| 構造化出力 | `output_format` | `output_config.format` |
| 思考 | `budget_tokens` | 適応型。`output_config.effort` で調整 |

## リクエストを更新する

**1. assistant のプリフィルをやめます。** Sonnet 4.5 のプロンプトで、assistant のターンを JSON の書き出し、XML タグ、書式のひな形で始めている場合は、展開前に削除してください。Sonnet 4.6 は `400` を返します。

**2. 構造化出力を移します。** `/v1/messages` では `output_format` から `output_config.format` に移し、スキーマとパーサーのテストを再実行します。`/v1/chat/completions` と `/v1/responses` では、引き続き `response_format` を使います。

**3. レイテンシーに合わせて effort を調整し直します。** Sonnet 4.6 は求められたときだけ思考します。Phaseo では、`reasoning.effort` または `reasoning.enabled: true` で適応型思考が有効になり、`output_config.effort` が設定されます。`xhigh` 以外のすべてのレベルを受け付け、`xhigh` は `max` として送られます。対話的なルートで 4.6 を既定にする前に、レイテンシーの予算に対して各レベルをベンチマークしてください。

**4. 古いベータヘッダーを削除します。** Phaseo は `anthropic-beta` ヘッダーを転送しません。

## テストする内容

- **出力の動作:** 書式に敏感なプロンプト、複数ステップのエージェントの計画、コーディング・リファクタリング・レビューのプロンプト、長いコンテキストでの検索と要約。
- **契約の安定性:** JSON とスキーマの合格率、ツール引数の完全性、終了理由と空の出力、プリフィルに依存していたルート。
- **本番のメトリクス:** effort レベルごとのレイテンシー、Sonnet 4.5 と比べたタスク成功率、タイムアウトとリトライの率、成功したタスクあたりのコスト。

## 展開する

1. まずプリフィルを削除し、構造化出力を更新します。
2. 現在の本番プロンプトで Sonnet 4.6 を評価します。
3. `models` に Sonnet 4.5 または別の安定したモデルをフォールバックとして入れてカナリアリリースし、Sonnet 4.5 の提供終了前に完了させます。
4. 品質と契約の安定性が維持されたら、トラフィックを増やします。
