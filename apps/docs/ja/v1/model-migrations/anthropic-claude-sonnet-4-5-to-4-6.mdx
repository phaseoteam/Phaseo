# Anthropic Claude Sonnet 4.6

`anthropic/claude-sonnet-4.6` を本番環境に安全に導入するには、このガイドを使います。

Sonnet 4.6 の移行手順は Claude 4.6 系と共通ですが、性能特性が十分に変わるため、プロンプトとルーティングの前提を再検証する必要があります。

## 新機能

- Claude 4.6 モデルでは assistant prefill が使えなくなり、`400` が返されます。
- 構造化出力の設定は `output_format` から `output_config.format` に移りました。
- 適応型思考は `output_config.effort` で設定します。
- 古いベータヘッダーを削除します。
- Sonnet 4.6 はコーディング、コンピューター操作、長いコンテキストの推論、エージェント計画、指示追従を総合的に改善します。
- Sonnet 4.6 はベータ版で 100 万トークンのコンテキストウィンドウを追加します。

## 移行クイックスタート

### 1. assistant prefill を使わない

既存の Sonnet 4.5 プロンプトが JSON プレフィックス、XML タグ、書式テンプレートで assistant ターンを始めている場合、ロールアウト前にその方法を削除します。

### 2. 構造化出力設定を移す

`output_format` を `output_config.format` に置き換え、スキーマやパーサーのテストを再実行します。

### 3. effort とレイテンシの想定を調整する

対話型の経路で使う場合は、4.6 をデフォルトにする前に複数の `effort` レベルを比較します。モデルの性能は向上していますが、最適な設定はレイテンシ予算によって異なります。

## テスト項目

### 出力の動作

- 書式に厳しいプロンプトでの指示追従。
- 複数ステップのタスクにおけるエージェント計画の品質。
- コーディング、リファクタリング、レビューのプロンプト。
- 長いコンテキストからの検索と要約。

### 契約の安定性

- JSON およびスキーマの検証成功率。
- ツール引数の完全性。
- 終了理由と空の出力の処理。
- 安定した書式のために prefill に依存していた経路。

### 本番メトリクス

- effort レベルごとのレイテンシ。
- Sonnet 4.5 に対するタスク成功率。
- タイムアウトとリトライの割合。
- タスク成功あたりのコスト。

## 安全なロールアウト

1. prefill を削除し、構造化出力設定を先に更新します。
2. 現在の本番プロンプトセットで Sonnet 4.6 を評価します。
3. Sonnet 4.5 または別の安定した経路をフォールバックに残して段階的に試します。
4. 品質と契約の安定性が保たれてからトラフィックを増やします。
