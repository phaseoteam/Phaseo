推論の深さは `reasoning.effort` で設定します。Phaseo はこれを Gemini 3 に `thinking_level` として送ります。また、思考シグネチャが保たれるよう、assistant のツール呼び出しのターンは Phaseo が返したとおりに送り返してください。Gemini 3 と Gemini 3.1 Pro は、別々の移行として扱います。

| Phaseo のモデル ID | ステータス |
| --- | --- |
| `google/gemini-3.1-pro-preview` | 利用可能 |
| `google/gemini-3-flash-preview` | 利用可能 |
| `google/gemini-3.1-flash-lite` | 非推奨。2027 年 5 月 7 日に提供終了 |
| `google/gemini-3-pro-preview` | 2026 年 3 月 9 日に提供終了。リクエストは `google/gemini-3.1-pro-preview` にルーティングされます |
| `google/gemini-3.1-flash-lite-preview` | 2026 年 5 月 25 日に提供終了。リクエストは `google/gemini-3.1-flash-lite` にルーティングされます |

提供終了した ID は、自動の置き換えによってのみ引き続き動作します。[モデルの非推奨化と提供終了](../guides/model-retirement)を参照してください。現在の ID を直接呼び出してください。

## 推論の深さを設定する

Gemini 3 では、思考の予算が `thinking_level` に置き換わりました。Phaseo は `reasoning.effort`(またはフラットな `reasoning_effort`)をこれに対応付けます。

| `reasoning.effort` | Gemini 3 Flash | Gemini 3.1 Pro |
| --- | --- | --- |
| `minimal` | `MINIMAL` | `LOW`(3.1 Pro には `MINIMAL` がありません) |
| `low` | `LOW` | `LOW` |
| `medium` | `MEDIUM` | `MEDIUM` |
| `high`、`xhigh`、`max` | `HIGH` | `HIGH` |

```json
{
  "model": "google/gemini-3.1-pro-preview",
  "messages": [{ "role": "user", "content": "Compare these three architecture options." }],
  "reasoning": { "effort": "medium" }
}
```

これらのレベルは、他のプロバイダーの effort 設定と一対一では対応しません。公開する各レベルで、レイテンシーと品質を再テストしてください。

## 思考シグネチャを保持する

Gemini 3 は、呼び出しをまたいで推論のコンテキストを運ぶ思考シグネチャを返します。関数呼び出しでシグネチャが欠けていると、品質が下がったり `400` が返ったりすることがあります。各 assistant のターンは、ツール呼び出しも含めて Phaseo が返したとおりに送り返してください。Phaseo はシグネチャを発行したモデルにそれを再送します。シグネチャが欠けている場合や別のモデルから来た場合は、リクエストが失敗しないよう、Google のスキップ用プレースホルダーを送ります。

## プロンプトとメディアを見直す

Google の Gemini 3 向けガイダンスは、長いプロンプトの足場よりも、直接的なプロンプトとパラメーターによる制御を推奨しています。プロンプトが古いモデルの動作を補うためのものになっている場合は、簡素化して再評価してください。

Gemini 3 では、画像とドキュメント向けに `media_resolution` も追加されました。Phaseo はこれを公開していないため、Google の既定値が適用されます。以前の結果がそのまま当てはまると考えず、画像、ドキュメント、混在メディアのルートを再テストしてください。

## テストする内容

- **推論:** 簡潔なプロンプトと足場を組んだプロンプトの比較、段階的なタスク、長いコンテキストの統合、推論の連続性に依存するエージェントのワークフロー。
- **レスポンス:** ターンをまたいだシグネチャ、関数呼び出しの成功率、スキーマ合格率、effort を変えた後の空・部分的・不正な出力。
- **本番のメトリクス:** 各レベルでのレイテンシー、トークン使用量とコスト、マルチモーダルのルート、Gemini 3 と Gemini 3.1 Pro でのタスク成功率。

## 展開する

1. まずリクエスト形式とシグネチャの扱いを移行します。
2. Gemini 3 でプロンプトとスキーマの評価を再実行します。
3. より深い推論が必要なルートには、Gemini 3.1 Pro を別途昇格させます。
4. 量の多いワークロード向けに、より安価なフォールバックを残しておきます。
