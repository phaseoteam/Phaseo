Gateway へのすべてのリクエストには Bearer API キーが必要です。

キーは Phaseo ダッシュボードで作成・管理します。

<Note>
`:free` モデルへの呼び出しは、入金済みクレジットがなくても実行できます。有料モデルへの呼び出しには、利用可能なウォレット残高が必要です。
</Note>

## API キーを使う

API キーを `Bearer` スキームで `Authorization` ヘッダーに含めます。

```bash
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5-nano",
    "input": "Hello!"
  }'
```

## キーの形式と取り扱い

- キーの形式: `phaseo_v1_sk_<kid>_<secret>`
- キーはシークレットマネージャーに保存し、ブラウザーで実行するコードには含めないでください。
- 安全にローテーションできるよう、アプリと環境ごとに別のキーを使用してください。

## 管理キー

管理 API キーは公開 API ではなく、Phaseo ダッシュボードで作成・管理します。

[クレジット](./endpoint/credits.mdx)や[アクティビティ](./endpoint/activity.mdx)などの高い権限を要する管理エンドポイントや、今後提供されるガードレール、キー管理、ワークスペース管理などのコントロールプレーン API に使用します。

## 認証エラー

- `401`: API キーがない、形式が正しくない、または無効です。
- `403`: キーは有効ですが、要求された機能へのアクセス権がありません。

<Visibility for="agents">
エージェントとして認証フローを実装する場合:

- シークレットの取り扱いと環境設定には、リポジトリのスキルを使用してください。
- Gateway API キーをクライアントに配信するコードへ決して含めないでください。
- フロントエンドとバックエンド間では有効期間の短い内部トークンを優先し、Gateway キーはサーバー側だけに置いてください。
</Visibility>
