Chat Completions（`/v1/chat/completions`）、Responses（`/v1/responses`）、Anthropic Messages（`/v1/messages`）のリクエストフィールドについて、型、受け付ける値、デフォルトを確認できます。対応状況はモデルとプロバイダーによって異なります。各モデルページのクイックスタートの表で、有効なプロバイダーがエンドポイントごとにどのパラメーターに対応しているかを確認できます。調整のヒントについては[推論パラメーター](/ja/v1/guides/inference-parameters)を参照してください。

| パラメーター | 型 | 値 | 用途 |
| --- | --- | --- | --- |
| [`model`](#parameter-model) | `string` | モデル ID、エイリアス、またはプリセット | 実行するモデル。必須。 |
| [`models`](#parameter-models) | `string[]` | 1〜25 個のモデル ID | `model` の後に試すフォールバックモデル。 |
| [`stream`](#parameter-stream) | `boolean` | デフォルト `false` | 1 つのレスポンス本文の代わりに Server-Sent Events を使う。 |
| [`temperature`](#parameter-temperature) | `number` | `0`–`2`（Messages では `0`–`1`） | ランダム性。 |
| [`top_p`](#parameter-top_p) | `number` | `0`–`1` | Nucleus サンプリング。 |
| [`top_k`](#parameter-top_k) | `integer` | `-1` 以上 | 上位 k 個のトークンからのサンプリング。 |
| [`min_p`](#parameter-min_p) | `number` | `0`–`1` | 可能性の低いトークンの除外。 |
| [`max_tokens`](#parameter-max_tokens) | `integer` | `1` 以上 | Chat Completions と Messages の出力長。 |
| [`max_output_tokens`](#parameter-max_output_tokens) | `integer` | `1` 以上 | Responses の出力長。 |
| [`max_completion_tokens`](#parameter-max_completion_tokens) | `integer` | `1` 以上 | Chat Completions の出力長。 |
| [`frequency_penalty`](#parameter-frequency_penalty) | `number` | `-2`–`2` | 出現回数に応じたトークンへのペナルティ。 |
| [`presence_penalty`](#parameter-presence_penalty) | `number` | `-2`–`2` | 一度でも出現したトークンへのペナルティ。 |
| [`repetition_penalty`](#parameter-repetition_penalty) | `number` | `0` より大きい値 | プロバイダー固有の繰り返し抑制。 |
| [`logit_bias`](#parameter-logit_bias) | `object` | トークン ID からバイアスへの対応 | 特定のトークンを出やすく、または出にくくする。 |
| [`seed`](#parameter-seed) | `integer` | 任意の整数 | 再現可能なサンプリング。 |
| [`stop`](#parameter-stop) | `string` または `string[]` | | 停止シーケンス。 |
| [`logprobs`](#parameter-logprobs) / [`top_logprobs`](#parameter-top_logprobs) | `boolean` / `integer` | `top_logprobs`: `0`–`20` | トークンの確率。 |
| [`tools`](#parameter-tools)、[`tool_choice`](#parameter-tool_choice) | `array`、`string`、または `object` | `none`、`auto`、`required` | ツール呼び出し。 |
| [`parallel_tool_calls`](#parameter-parallel_tool_calls) | `boolean` | | 1 ターンでの複数のツール呼び出しを許可する。 |
| [`max_tool_calls`](#parameter-max_tool_calls) | `integer` | `1` 以上 | ツール呼び出し数の上限。 |
| [`response_format`](#parameter-response_format) | `string` または `object` | | テキスト、JSON、またはスキーマに沿った出力。 |
| [`json_schema`](#parameter-json_schema) | `object` | | 構造化出力のスキーマ。 |
| [`structured_outputs`](#parameter-structured_outputs) | `boolean` | | モデルページの機能フラグで、リクエストフィールドではありません。 |
| [`reasoning`](#parameter-reasoning) | `object` | | 推論の労力、予算、要約。 |
| [`reasoning_effort`](#parameter-reasoning_effort) | `string` | `none` から `max` | Chat Completions での推論の労力。 |
| [`reasoning_tokens`](#parameter-reasoning_tokens) | `integer` | | モデルページの機能フラグで、リクエストフィールドではありません。 |
| [`include_reasoning`](#parameter-include_reasoning) | `boolean` | | 互換性のために受け付けますが、効果はありません。 |
| [`service_tier`](#parameter-service_tier) | `string` | `standard`、`fast`、`ultrafast`、`priority`、`flex` | 速度と料金のティア。 |
| [`prompt_cache_key`](#parameter-prompt_cache_key) | `string` | | 関連するリクエストを、キャッシュを保持するプロバイダーに留める。 |
| [`prompt_cache_options`](#parameter-prompt_cache_options) | `object` | `mode`、`ttl` | OpenAI GPT-5.6 以降でのプロンプトキャッシュのモードと有効期間。 |
| [`cache_control`](#parameter-cache_control) | `object` | `type`、`ttl`、`scope` | Claude のキャッシュポリシーとキャッシュブレークポイント。 |
| [`prompt_cache_retention`](#parameter-prompt_cache_retention) | `string` | `in_memory`、`24h` | GPT-5.6 より前の OpenAI モデルでのプロンプトキャッシュの保持期間。 |
| [`provider`](#parameter-provider) | `object` | | ルーティングルールとプロバイダーの選択。 |
| [`provider_options`](#parameter-provider_options) | `object` | | プロバイダー固有の設定。 |
| [`meta`](#parameter-meta) / [`usage`](#parameter-usage) | `boolean` | | レスポンスに含める追加のメタデータまたは使用量の集計。 |
| [`debug`](#parameter-debug) | `object` | | ルーティングのトレースと上流のペイロード。 |

<span id="unsupported-parameters"></span>
## サポートされていないパラメーター

リクエストを処理するプロバイダーが任意のサンプリングパラメーターのいずれかに対応していない場合、Phaseo はそのパラメーターを除外します。上流には送信されず、リクエストも拒否されないため、常に OpenAI のデフォルト値を送信するクライアントもそのまま動作します。

Phaseo はプロバイダーごとに判断し、まずプロバイダープロファイルを、次にルートのカタログのパラメーターを確認します。ルートがパラメーターを宣言していない場合はカタログの確認だけが省略され、プロバイダープロファイルが非対応としているパラメーター（Cohere の `top_k` や Reflection の `stop` など）は引き続き除外されます。

| 除外されることがあるもの | 除外されないもの |
| --- | --- |
| `temperature`、`top_p`、`top_k`、`min_p`、`repetition_penalty`、`frequency_penalty`、`presence_penalty`、`logit_bias`、`logprobs`、`top_logprobs`、`seed`、`stop`（`/v1/messages` では `stop_sequences`）、`parallel_tool_calls`、`max_tool_calls`、`image_config`、および Anthropic 以外のプロバイダーでの `/v1/messages` の `context_management` | メッセージ、`tools`、`tool_choice`、`response_format`、推論の設定、出力の上限 |

OpenAI の 12 時間キャッシュを使えないルートでは、プロンプトキャッシュの `ttl` が `12h` の場合も除外され、`prompt_cache_options.ttl` または `prompt_cache_breakpoint.ttl` として報告されます。[プロンプトキャッシュ](../guides/prompt-caching.mdx#12-hour-cache-on-openai)を参照してください。

成功したレスポンスには、リクエスト本文で送信されたうち除外されたパラメーターが示されます。

- `X-Phaseo-Dropped-Params` ヘッダー（例: `X-Phaseo-Dropped-Params: top_k, min_p`）
- リクエストで `meta: true` を設定した場合は `meta.routing.dropped_params`（例: `[{"param": "top_k", "reason": "unsupported_by_provider"}]`）

リクエスト本文ではなくプリセットやデフォルトから来たパラメーターは、どちらにも表示されずに除外されることがあります。その場合も、リクエストと一緒に保存されるルーティング診断には記録されます。

## モデルを選ぶ

<span id="model"></span>
<h3 id="parameter-model"><code>model</code></h3>

実行する Phaseo のモデル ID（例: `openai/gpt-6-astra`）。必須です。モデルページのクイックスタートに表示される ID を使ってください。自動化や長期間使う連携では、これが最も安全です。`@support-triage` のような[プリセット](../guides/presets.mdx)名も指定できます。

<span id="models"></span>
<h3 id="parameter-models"><code>models</code></h3>

`model` の後に順番に試すフォールバックモデルです。`model` は引き続き必須で、常に最初に実行されます。次のエントリーは、試行が `429`、`500`、`502`、`503`、`504` で失敗した場合にのみ試されます。

**型** `string[]` · **エントリー** 1〜25 個。重複と `model` と同じエントリーは無視されます · **例** `["anthropic/claude-sonnet-5.5", "google/gemini-4-argon"]`

- 各試行は、それぞれ独立したリクエストとして検証、記録、課金されます。レスポンスの `model` フィールドとルーティングのトレースに、応答したモデルが表示されます。
- ストリーミングリクエストは最初のバイトの前にのみフォールバックし、動画と音楽のジョブは送信時にのみフォールバックします。
- 付加された動的ルートのフォールバックが優先されます。エントリーにはプリセットも指定できます。`phaseo/auto` は `models` と組み合わせられません。
- バッチ、リアルタイム、カウンシルのリクエストは、`models` を `400` で拒否します。
- マルチパートのエンドポイントは、繰り返しの `models` フィールド、`models[]` フィールド、または 1 つの JSON 配列を受け付けます。

[リクエスト単位のモデルフォールバック](../guides/routing-and-fallbacks#request-level-model-fallbacks)を参照してください。

<span id="stream"></span>
<h3 id="parameter-stream"><code>stream</code></h3>

1 つのレスポンス本文の代わりに、生成された出力を Server-Sent Events で順次返します。

**型** `boolean` · **デフォルト** `false`

チャット UI や長いレスポンスに使います。再試行や解析がしやすい 1 つの JSON レスポンスが必要な場合はオフのままにしてください。ツール呼び出しと構造化出力のストリーミング方法はプロバイダーによって異なります。[ストリーミング](../guides/streaming.mdx)を参照してください。

## サンプリング

<span id="temperature"></span>
<h3 id="parameter-temperature"><code>temperature</code></h3>

トークン選択のランダムさです。値を低くすると控えめで再現性の高い出力に、高くすると多様性は増しますが、一貫性とスキーマへの準拠は下がります。

**型** `number` · **範囲** Chat Completions と Responses では `0`–`2`、Messages では `0`–`1` · **デフォルト** プロバイダーの値（未設定の場合、Phaseo は何も送信しません）

まずは `0.2`–`0.7` から始め、抽出、分類、JSON では低くしてください。`temperature` と `top_p` は同時にではなく、どちらか一方を調整します。量子化の強いモデルで temperature を高くすると、出力が不安定になることがあります。

<span id="top_p"></span>
<h3 id="parameter-top_p"><code>top_p</code></h3>

Nucleus サンプリングです。モデルは、合計確率が `top_p` に達する最小のトークン集合から選びます。値を低くすると、より狭く焦点の絞られた出力になります。

**型** `number` · **範囲** `0`–`1` · **デフォルト** プロバイダーの値

`0.9`–`1.0` と中程度の `temperature` の組み合わせが、妥当な基準です。

<span id="top_k"></span>
<h3 id="parameter-top_k"><code>top_k</code></h3>

各ステップで、最も可能性の高い k 個のトークンにサンプリングを限定します。値を低くすると出力が予測しやすくなります。すべてのプロバイダーが対応しているわけではありません。

**型** `integer` · **範囲** Chat Completions では `-1` 以上、Messages では `0` 以上 · **デフォルト** プロバイダーの値

<span id="min_p"></span>
<h3 id="parameter-min_p"><code>min_p</code></h3>

最小確率のしきい値を下回るトークンを除外して、サンプリングを絞り込みます。

**型** `number` · **範囲** `0`–`1` · **デフォルト** プロバイダーの値

<span id="frequency_penalty"></span>
<h3 id="parameter-frequency_penalty"><code>frequency_penalty</code></h3>

すでに出現した回数に比例して、トークンにペナルティを課します。モデルがループしたり、同じ表現を繰り返したりする場合は値を上げてください。

**型** `number` · **範囲** `-2`–`2` · **デフォルト** プロバイダーの値（通常は `0`）

<span id="presence_penalty"></span>
<h3 id="parameter-presence_penalty"><code>presence_penalty</code></h3>

すでに出現したトークンすべてにペナルティを課し、モデルを新しい話題や言い回しへ促します。

**型** `number` · **範囲** `-2`–`2` · **デフォルト** プロバイダーの値（通常は `0`）

<span id="repetition_penalty"></span>
<h3 id="parameter-repetition_penalty"><code>repetition_penalty</code></h3>

上記の 2 つのペナルティとは別の、プロバイダー固有の繰り返し抑制の制御です。正確な効果はプロバイダーによって大きく異なります。

**型** `number` · **範囲** `0` より大きい値。プロバイダーは多くの場合 `2` まで受け付けます · **デフォルト** プロバイダーの値

<span id="logit_bias"></span>
<h3 id="parameter-logit_bias"><code>logit_bias</code></h3>

特定のトークンを出やすく、または出にくくします。キーはモデルのトークナイザーのトークン ID、値は加算するバイアスです。

**型** `object`（トークン ID から数値への対応） · **デフォルト** 未設定

<span id="seed"></span>
<h3 id="parameter-seed"><code>seed</code></h3>

デバッグや回帰テストのために、シード付きのサンプリングを要求します。プロバイダー間や、プロバイダーのインフラ変更をまたいで同一の出力が得られる保証はありません。

**型** `integer` · **デフォルト** 未設定

<span id="output-length-and-stopping"></span>
## 出力の長さと停止

<span id="max_tokens"></span>
<h3 id="parameter-max_tokens"><code>max_tokens</code></h3>

Chat Completions の出力トークン数の上限で、Messages では必須です。コストとレイテンシーの制御に使います。値が小さすぎると出力が途中で切れます。

**型** `integer` · **範囲** `1` 以上（Messages では `0` 以上） · **デフォルト** Chat Completions ではプロバイダーの値

<span id="max_output_tokens"></span>
<h3 id="parameter-max_output_tokens"><code>max_output_tokens</code></h3>

Responses の出力トークン数の上限です。目的は `max_tokens` と同じなので、使用するエンドポイントの名前で送信してください。

**型** `integer` · **範囲** `1` 以上 · **デフォルト** プロバイダーの値

<span id="max_completion_tokens"></span>
<h3 id="parameter-max_completion_tokens"><code>max_completion_tokens</code></h3>

Chat Completions の出力トークン数の上限で、`max_tokens` の新しい OpenAI での名前です。1 つのリクエストで両方を混在させないでください。

**型** `integer` · **範囲** `1` 以上 · **デフォルト** プロバイダーの値

<span id="stop"></span>
<h3 id="parameter-stop"><code>stop</code></h3>

テンプレートの終わりやプロトコルのマーカーなど、生成を終了させる 1 つ以上のシーケンスです。Messages ではフィールド名が `stop_sequences` で、配列を受け付けます。

**型** `string` または `string[]` · **デフォルト** 未設定

## トークンの確率

<span id="logprobs"></span>
<h3 id="parameter-logprobs"><code>logprobs</code></h3>

評価、ランキング、信頼度スコアリングのために、各出力トークンの対数確率を返します。

**型** `boolean` · **デフォルト** `false`

<span id="top_logprobs"></span>
<h3 id="parameter-top_logprobs"><code>top_logprobs</code></h3>

各位置で最も可能性の高い代替トークンを、その対数確率とともに返します。`logprobs: true` が必要です。

**型** `integer` · **範囲** `0`–`20`

## ツール

<span id="tools"></span>
<h3 id="parameter-tools"><code>tools</code></h3>

モデルが呼び出せるツールです。エンドポイントのリファレンスに別の記載がない限り、OpenAI のツールスキーマを使います。Messages は Anthropic のスキーマを受け付けます。ツールを宣言しても、モデルにその呼び出しが強制されるわけではありません。

**型** `array` · **デフォルト** 未設定

<span id="tool_choice"></span>
<h3 id="parameter-tool_choice"><code>tool_choice</code></h3>

モデルがツールを呼び出せるかどうかを指定します。テキストのみなら `none`、モデルに判断させるなら `auto`、呼び出しを強制するなら `required`、または 1 つのツールを指定するオブジェクトを使います。

**型** `string` または `object`

<span id="parallel_tool_calls"></span>
<h3 id="parameter-parallel_tool_calls"><code>parallel_tool_calls</code></h3>

1 ターンで複数のツール呼び出しを許可します。順序のある副作用を持つツールなど、ツールを 1 つずつ実行する必要がある場合は `false` に設定します。

**型** `boolean` · **デフォルト** プロバイダーの値（未設定の場合、Phaseo は何も送信しません）

<span id="max_tool_calls"></span>
<h3 id="parameter-max_tool_calls"><code>max_tool_calls</code></h3>

そのリクエストでモデルが行うツール呼び出しの回数の上限です。

**型** `integer` · **範囲** `1` 以上 · **デフォルト** 未設定

## 構造化出力

<span id="response_format"></span>
<h3 id="parameter-response_format"><code>response_format</code></h3>

プレーンテキスト、JSON、または JSON スキーマに一致する出力を要求します。受け付ける形式はエンドポイントとプロバイダーによって異なります。

**型** `string` または `object` · **デフォルト** エンドポイントとプロバイダーの値

<span id="json_schema"></span>
<h3 id="parameter-json_schema"><code>json_schema</code></h3>

出力が一致すべき JSON スキーマで、`response_format` の中に設定します（`{"type": "json_schema", "json_schema": {...}}`）。準拠しやすくするため、スキーマは狭くタスクに特化したものにしてください。

**型** `object`

<span id="structured_outputs"></span>
<h3 id="parameter-structured_outputs"><code>structured_outputs</code></h3>

リクエストフィールドではありません。モデルページでは、有効なプロバイダーがスキーマに沿った出力に対応しているエンドポイントを示します。要求するには [`response_format`](#parameter-response_format) を使ってください。

## 推論

<span id="reasoning"></span>
<h3 id="parameter-reasoning"><code>reasoning</code></h3>

推論に対応したモデルで推論を設定します。

| フィールド | 値 |
| --- | --- |
| `effort` | `none`、`instant`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`（Messages には `instant` はありません） |
| `enabled` | `true` または `false` |
| `max_tokens` | 推論トークンの予算。`0` 以上 |
| `summary` | `auto`、`concise`、`detailed` |
| `mode` | `standard`、`pro`（Chat Completions と Responses） |
| `context` | `auto`、`current_turn`、`all_turns`（Responses） |

未設定のフィールドでは、モデルのデフォルトがそのまま使われます。労力を高くすると難しい問題に効果がありますが、レイテンシーとトークンが増えます。

<span id="reasoning_effort"></span>
<h3 id="parameter-reasoning_effort"><code>reasoning_effort</code></h3>

`reasoning.effort` の Chat Completions での短縮形です。

**型** `string` · **値** `none`、`instant`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max` · **デフォルト** モデルの値

<span id="reasoning_tokens"></span>
<h3 id="parameter-reasoning_tokens"><code>reasoning_tokens</code></h3>

リクエストフィールドではありません。モデルページでは、推論トークンを報告するルート、または推論の予算を受け付けるルートを示します。予算は `reasoning.max_tokens` で設定します。

<span id="include_reasoning"></span>
<h3 id="parameter-include_reasoning"><code>include_reasoning</code></h3>

互換性のために Chat Completions で受け付けますが、効果はありません。推論の内容と要約は、モデルが生成した場合は常に返されます。推論の出力は大きくなることがあり、すべてのモデルが返すわけではありません。減らすには、`reasoning.effort` を下げるか、`reasoning.enabled` を `false` に設定します。

**型** `boolean`

## サービスティアとプロンプトキャッシュ

<span id="service_tier"></span>
<h3 id="parameter-service_tier"><code>service_tier</code></h3>

モデルとプロバイダーが対応している場合に、Chat Completions、Responses、Messages で速度と料金のティアを選びます。Phaseo は各値をプロバイダー独自の制御に対応付けます。

**型** `string` · **デフォルト** `standard`

| 値 | ティア |
| --- | --- |
| `standard`（または省略） | 標準。 |
| `fast`、`priority` | 高速なルーティングと料金。両者は同じです。 |
| `ultrafast` | 対応している最速のティア。 |
| `flex` | Flex。 |
| `auto` または `null` | 特定のティアなし。省略として扱われます。 |
| `default`、`scale` | OpenAI の値で、`standard` として扱われます。 |
| `standard_only` | `/v1/messages` での Anthropic の値で、`standard` として扱われます。 |

`batch` はティアではないため拒否されます。[Batch API](./endpoint/batches-create.mdx) を使ってください。公式の Anthropic SDK を Phaseo に向けて使う場合、`/v1/messages` では Anthropic の `auto` と `standard_only` を使うことをお勧めします。`ultrafast`、`priority`、`flex`、`fast` を使うには、生の HTTP、または Chat Completions と Responses を使ってください。[サービスティア](../guides/service-tiers.mdx)を参照してください。

<span id="prompt_cache_key"></span>
<h3 id="parameter-prompt_cache_key"><code>prompt_cache_key</code></h3>

エージェントループの各ステップなど、プロンプトのプレフィックスを共有するリクエストを、そのキャッシュを保持するプロバイダーに留めます。

**型** `string` · **デフォルト** 未設定 · **エンドポイント** Chat Completions、Responses、Messages

Phaseo は、最初に成功したリクエストを処理したプロバイダーとルート（デプロイメントまたはリージョン）にキーを固定し、同じキーを持つ後続のリクエストを、そのプロバイダーが失敗するか、そのプロバイダーでの Phaseo のマネージドクォータがなくなるか、ルーティングポリシーで許可されなくなるまで、そこに留めます。固定はワークスペースごとで、プロバイダーのキャッシュ保持期間と同じだけ続きます。[プロバイダーアフィニティ](../guides/prompt-caching.mdx#provider-affinity)を参照してください。

Phaseo は生のキーではなく、ワークスペース ID とキーのハッシュを上流に送信するため、同じキーを選んだ 2 つのワークスペースがプロバイダーのキャッシュを共有することはありません。レスポンスには送信したキーがそのまま返されます。API がこのフィールドを拒否するプロバイダーには送信されず、このフィールドを送信してもプロバイダーがルーティングから除外されることはありません。キーがない場合、Phaseo はリクエストからアフィニティを導き出しますが、長い会話やエージェントのセッションでは明示的なキーのほうが効果的です。

<span id="prompt_cache_options"></span>
<h3 id="parameter-prompt_cache_options"><code>prompt_cache_options</code></h3>

OpenAI と Azure OpenAI の GPT-5.6 以降（GPT-6 Astra を含む）、DeepInfra、Moonshot AI でのプロンプトキャッシュのモードと有効期間です。

**型** `object` · **フィールド** `mode`（`implicit` または `explicit`）、`ttl`

| プロバイダー | `ttl` |
| --- | --- |
| OpenAI | `30m`（デフォルト）、または Responses API では `12h`。[OpenAI の 12 時間キャッシュ](../guides/prompt-caching.mdx#12-hour-cache-on-openai)を参照してください。 |
| Azure OpenAI | `30m` |
| DeepInfra | `5m` または `1h`。セッション内のすべてのリクエストに `prompt_cache_key` が必要です。 |
| Moonshot AI | `5m`、または Kimi K3 では `1h`。`mode: "implicit"` を受け付けます。 |

OpenAI に、配置したブレークポイントのみをキャッシュさせるには `{"mode": "explicit", "ttl": "30m"}` を使います。Azure OpenAI での `12h` や、1 時間の料金がない Moonshot AI モデルでの `1h` など、ルートが受け付けない有効期間は除外され、`X-Phaseo-Dropped-Params` に示されます。その他のプロバイダーと GPT-5.6 より前の OpenAI モデルには `prompt_cache_options` は送信されません。これらの OpenAI モデルは [`prompt_cache_retention`](#parameter-prompt_cache_retention) を使います。`provider_options.openai.prompt_cache_options` も受け付けますが、トップレベルの値が優先されます。

<span id="cache_control"></span>
<h3 id="parameter-cache_control"><code>cache_control</code></h3>

トップレベルでは、Claude のプロンプトキャッシュのポリシーを設定します。コンテンツブロック、ツール定義、ツール結果では、キャッシュブレークポイントを示します。

**型** `object` · **フィールド** `type`、`ttl`、`scope`

**トップレベル。** Chat Completions、Responses、Messages で受け付けます。Anthropic の Claude、AWS の Claude、Amazon Bedrock、Google Vertex AI に適用され、Phaseo は `scope`（`all_text`、`last_user_message`、`agent`、`none`）に従って最大 4 つのブレークポイントを配置します。その他のプロバイダーは無視します。`provider_options.anthropic.cache_control` は同じ設定で、両方が送信された場合はこちらが優先されます。

**ブロック上。** Phaseo はブレークポイントを Claude のルート、Alibaba Model Studio、Venice に送信し、OpenAI と Azure OpenAI の GPT-5.6 以降では `prompt_cache_breakpoint` に変換し、その他のプロバイダーでは除外します。OpenAI 独自の `prompt_cache_breakpoint: {"mode": "explicit"}` も同じブロックで受け付け、ブロックに両方がある場合はこちらが優先されます。

`type: "ephemeral"` と、`5m`（デフォルト）または `1h` の `ttl` を使います。Anthropic が受け付けるブレークポイントは 1 リクエストあたり最大 4 つです。それより多く指定した場合、Phaseo は最初の 1 つと最新の 3 つを残します。[プロンプトキャッシュ](../guides/prompt-caching.mdx#cache-controls)を参照してください。

<span id="prompt_cache_retention"></span>
<h3 id="parameter-prompt_cache_retention"><code>prompt_cache_retention</code></h3>

GPT-5.6 より前の OpenAI と Azure OpenAI のモデルでの、プロンプトキャッシュの保持期間です。

**型** `string` · **値** `in_memory`、`24h`

Phaseo はこれらのモデルにのみ送信し、`24h` を受け付けるのは OpenAI が掲載しているモデルだけです。GPT-5.6 以降は [`prompt_cache_options.ttl`](#parameter-prompt_cache_options) を使い、その他のプロバイダーにはこのフィールドは送信されません。`provider_options.openai.prompt_cache_retention` も受け付けますが、トップレベルの値が優先されます。

## ルーティングとプロバイダーの設定

<span id="provider"></span>
<h3 id="parameter-provider"><code>provider</code></h3>

リクエストを処理できるプロバイダーと、その順位付けの方法を制限します。エイリアスとして `routing` も受け付けます。[ルーティングとフォールバック](../guides/routing-and-fallbacks.mdx)を参照してください。

| フィールド | 型 | 効果 |
| --- | --- | --- |
| `order` | `string[]` | 優先するプロバイダーの順序。 |
| `only` | `string[]` | これらのプロバイダーのみ。 |
| `ignore` | `string[]` | これらのプロバイダーは使わない。 |
| `include_alpha` | `boolean` | アルファ版のプロバイダーを許可する。 |
| `sort` | `string` または `object` | `price`、`latency`、`throughput` などでプロバイダーを順位付けする。 |
| `required_execution_region` | `string` | このリージョンでのみ実行する。 |
| `required_data_region` | `string` | このリージョンでのみデータを扱う。 |
| `require_zero_data_retention` | `boolean` | データ保持ゼロを満たすプロバイダーのみ。 |
| `max_price` | `object` | `prompt`、`completion`、`image`、`audio`、`request` のコストの上限。 |
| `quantizations` | `string[]` | カタログの量子化がこれらのいずれかに一致する提供内容のみ。 |

`quantizations` の照合では、大文字と小文字、スペース、ハイフン、アンダースコアは区別されず、`float8` と `FP8`、`bfloat16` と `BF16` のように曖昧さのない名前はエイリアスとして扱われます。このフィルターを設定すると、量子化データのない提供内容は除外されます。一致する提供内容がない場合、リクエストは別のバリアントにルーティングされるのではなく、要求された量子化と利用可能な量子化を示すエラーで失敗します。

<span id="provider_options"></span>
<h3 id="parameter-provider_options"><code>provider_options</code></h3>

Phaseo がそのまま渡すプロバイダー固有の設定で、プロバイダーごとにキーを指定します。リクエストの残りの部分は共通スキーマのままです。

**型** `object`

| キー | 効果 |
| --- | --- |
| `openai.context_management` | OpenAI のコンパクション（`type: "compaction"`、任意の `compact_threshold`）。 |
| `openai.prompt_cache_retention`、`openai.prompt_cache_options` | トップレベルのフィールドと同じ。トップレベルの値が優先されます。 |
| `anthropic.cache_control` | トップレベルの `cache_control` と同じ。こちらが優先されます。 |
| `google.cached_content` | 明示的な Gemini キャッシュ（下記を参照）。 |
| `xai.conversation_id` | xAI の会話 ID。 |

`google.cached_content` は明示的な Gemini キャッシュを指定し、自分の認証情報（Google AI Studio では Google API キー、Vertex AI では Vertex AI の認証情報）でのみ動作します。Vertex AI では、Phaseo はキャッシュの完全な名前（`projects/{project}/locations/{location}/cachedContents/{id}`）に含まれるプロジェクトとロケーションにリクエストを送信します。短い名前の場合は、サービスアカウント JSON の `project_id` と `region` を使います。Phaseo の認証情報を使うと、リクエストは `400` を返します。`google.cache_control` と `google.cache_ttl` は受け付けますが、Google には送信されません。

Claude ではトップレベルの `cache_control`、OpenAI GPT-5.6 以降では `prompt_cache_options`、それより前の OpenAI モデルでは `prompt_cache_retention` を使うことをお勧めします。[プロンプトキャッシュ](../guides/prompt-caching.mdx)を参照してください。

## レスポンスの追加情報とデバッグ

<span id="meta"></span>
<h3 id="parameter-meta"><code>meta</code></h3>

`meta.routing.dropped_params` などのルーティングの詳細を含む `meta` オブジェクトをレスポンスに追加します。

**型** `boolean` · **デフォルト** `false`

<span id="usage"></span>
<h3 id="parameter-usage"><code>usage</code></h3>

ヘッダーやダッシュボードに頼らず、レスポンス本文で使用量の集計を要求します。

**型** `boolean` · **デフォルト** 未設定

<span id="debug"></span>
<h3 id="parameter-debug"><code>debug</code></h3>

ルーティングのトレースと上流のペイロードを返します。デバッグ出力にはリクエストの内容が含まれることがあるため、開発環境か、厳密に管理された環境でのみ使ってください。[リクエストをデバッグする](./errors.mdx#debug-a-request)を参照してください。

| フィールド | 型 | 効果 |
| --- | --- | --- |
| `enabled` | `boolean` | デバッグモードを有効にします。 |
| `return_upstream_request` | `boolean` | Phaseo が上流に送信したリクエストを含めます。 |
| `return_upstream_response` | `boolean` | 利用可能な場合、上流のレスポンスを含めます。 |
| `trace` | `boolean` | ルーティングのトレースを返します。 |
| `trace_level` | `summary` または `full` | トレースの詳細度。 |

## リクエストの例

```json
{
  "model": "openai/gpt-5.6-luna",
  "input": "Summarize this changelog.",
  "stream": false,
  "max_output_tokens": 300,
  "provider": {
    "order": ["openai", "azure"],
    "sort": "latency",
    "required_execution_region": "eu",
    "require_zero_data_retention": true
  },
  "debug": {
    "enabled": true,
    "trace": true,
    "trace_level": "summary"
  }
}
```

<Visibility for="agents">
エージェント向けのパラメーター処理ルール:

- フィールド名を推測せず、https://phaseo.app/docs/openapi/v1/openapi.yaml の API コントラクトに照らしてリクエスト本文を検証します。
- ツール、ストリーミング、デバッグオプションなどの高度なフィールドを組み合わせる前に、エンドポイントの API リファレンスページを確認します。
- エンドポイントが許可している場合、パススルーのフローでは未知のプロバイダー固有のキーを保持します。
- 検証済みのリクエスト形式のパターンを使うには、`phaseo-gateway` スキルをインストールします: `npx skills add https://phaseo.app/docs --skill phaseo-gateway`。
</Visibility>
