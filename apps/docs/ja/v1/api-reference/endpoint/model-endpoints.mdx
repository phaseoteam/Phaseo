リクエストを送信する前にこのエンドポイントを呼び出すと、モデル、プロバイダー、エンドポイント、パラメーターの組み合わせが利用できるかを確認できます。`openai/gpt-6-astra` の場合:

```bash
curl "https://api.phaseo.app/v1/models/openai/gpt-6-astra/endpoints" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

`endpoints` の各エントリーは、1 つのエンドポイントに対する 1 つのプロバイダールートです。

| フィールド | 内容 |
| --- | --- |
| `endpoint`、`capability_id`、`public_path`、`collection` | 正規のエンドポイント ID と機能 ID、および公開 API パス |
| `provider`、`model` | プロバイダー ID と名前、およびプロバイダーのモデルスラッグ |
| `routable`、`status`、`status_reason` | ルートが現在トラフィックを受け付けるか、その提供状況、およびプレビュー限定または無効である理由 |
| `modalities` | 入力と出力のモダリティ |
| `capabilities` | 対応しているパラメーター名と、パラメーターの構造化された詳細 |
| `routing` | プロバイダー、モデル、機能のルーティング状態 |
| `effective` | ルートが予定されている、または期間限定である場合の `from` と `to` の日付 |
| `pricing` | エンドポイントの料金の概要 |

先にモデルを比較するには [モデルを一覧表示](./models.mdx)を、API が公開しているすべてのエンドポイントを確認するには[エンドポイントを一覧表示](./endpoints.mdx)を使ってください。

## 予定中と無効のルートを含める

デフォルトの `availability=active` は、公開でルーティング可能な行のみを返します。近日提供予定や無効のルートを確認するには `availability=all` を使います。

```bash
curl "https://api.phaseo.app/v1/models/openai/gpt-6-astra/endpoints?availability=all" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

本番トラフィックは、`routable` が `true` で `status` が `active` の行にのみルーティングしてください。

## ルートを絞り込む

次のフィルターは、繰り返しのパラメーターまたはカンマ区切りのリストを受け付けます: `provider`、`provider_status`、`provider_routing_status`、`model_routing_status`、`capability_status`、`provider_availability_status`、`provider_availability_reason`、`status`、`supported_parameters`（エイリアス `params`）。値については[モデルを一覧表示](./models.mdx#filter-the-list)で説明しています。

次の例は、`reasoning_effort` に対応する OpenAI のルートを返します。

```bash
curl "https://api.phaseo.app/v1/models/openai/gpt-6-astra/endpoints?provider=openai&supported_parameters=reasoning_effort" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```
