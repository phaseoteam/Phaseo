チームに属する`request_id`の保存済み監査レコードを取得します。

新しいリクエストにはサーバーが生成した `G-` 生成 ID が割り当てられ、レスポンスヘッダー `x-request-id` と生成レスポンスで返されます。ログ、生成の検索、サポートにはこの ID を使用してください。クライアントが指定した `x-request-id` では置き換えられません。過去の UUID 形式のログ ID も引き続き検索に使用できます。

次を使用します。
- `GET /v1/generations?id=<request_id>`

ゲートウェイがその生成のリクエスト詳細をすべて記録している場合、レスポンスには次も含まれます。

- `replay_supported`: 再実行可能なペイロードがあるかどうか
- `replay_request`: 保存されたリクエスト本文。元のエンドポイントに送信して制御された再実行を行えます

一般的な再実行手順:

1. `GET /v1/generations?id=<request_id>`で生成レコードを読み取ります。
2. `replay_supported === true`であることを確認します。
3. `endpoint`が示す元のエンドポイント（例: `/v1/chat/completions`や`/v1/responses`）に`replay_request`を再送信します。
