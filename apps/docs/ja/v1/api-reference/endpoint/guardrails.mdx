<Info>
ガードレールの管理には管理APIキーが必要です。読み取り操作には`guardrails:read`、変更操作には`guardrails:write`または`guardrails:delete`が必要です。
</Info>

ガードレールを使って、プライバシー制御、プロバイダーやモデルの制限、プロンプトインジェクション対策、機密情報ポリシーを適用できます。ガードレールはAPIキー、ワークスペースメンバー、またはその両方に割り当てられます。

ガードレールはリクエスト数や支出を制限しません。代わりに [API キーの上限](./keys-update.mdx)、[ワークスペースの予算](./budgets-list.mdx)、または[支出アラート](../../guides/spend-alerts.mdx)を使用してください。ガードレールの `budgets` 入力と `*_limit_requests`・`*_limit_cost_nanos` フィールドは削除されました。これらをまだ送信するクライアントも拒否されず、値は無視されます。

変更が成功するとワークスペースのポリシー状態が更新され、監査ログに記録されます。
