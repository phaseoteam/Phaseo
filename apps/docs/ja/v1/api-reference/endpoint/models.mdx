`GET /v1/models` を呼び出すと、現在ルーティングできるモデルが一覧表示されます。把握されているものの現在は利用できないモデルも含めるには、`availability=all` を設定します。

```bash
curl "https://api.phaseo.app/v1/models?limit=50" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

各モデルの `offers` には、プロバイダールートごとに 1 つのエントリーがあります（抜粋。値は説明用です）。

```json
{
  "ok": true,
  "availability_mode": "active",
  "limit": 50,
  "offset": 0,
  "total": 412,
  "models": [
    {
      "id": "anthropic/claude-sonnet-5.5",
      "name": "Claude Sonnet 5.5",
      "organization": { "id": "anthropic", "name": "Anthropic", "color": "#d97757" },
      "lifecycle": { "status": "active", "released_at": "2026-09-28", "replacement_id": null },
      "modalities": { "input": ["text", "image"], "output": ["text"] },
      "capabilities": { "endpoints": ["chat.completions", "messages", "responses"] },
      "availability": { "status": "active", "provider_count": 3, "active_provider_count": 3 },
      "offers": [
        {
          "provider": { "id": "anthropic", "name": "Anthropic" },
          "model": "claude-sonnet-5-5",
          "status": "active",
          "status_reason": null,
          "routable": true,
          "service_tiers": ["standard"],
          "routing": { "provider": "active", "model": "active", "capability": "active" }
        }
      ]
    }
  ]
}
```

本番トラフィックは、`routable` が `true` の提供内容にのみルーティングしてください。`status_reason` は、提供内容がプレビュー限定または無効である理由を示します。完全なスキーマは下にあります。

`GET /models/me` は、現在の呼び出し元向けにガードレールを考慮してモデルを絞り込む将来の機能のために予約されています。現在は `501 not implemented` を返すため、`GET /models` を使ってください。

## 一覧を絞り込む

複数の値を取るフィルターは、繰り返しのパラメーターまたはカンマ区切りのリストを受け付けます。

| パラメーター | 絞り込みの対象 |
| --- | --- |
| `availability` | 公開でルーティング可能なモデルなら `active`（デフォルト）、`coming_soon`、`inactive`、まだルーティングできないモデルとプロバイダーも加えるなら `all` |
| `endpoints` | `chat.completions`、`responses`、`messages` などの公開エンドポイント名 |
| `status` | `active`、`deprecated`、`retired` などのモデルのライフサイクル |
| `organisation` | `anthropic/claude-3-haiku` の `anthropic` のような、モデル ID のプレフィックス |
| `provider` | `openai`、`anthropic`、`google_vertex` などの公開プロバイダー ID |
| `provider_status` | `active`、`beta`、`alpha`、`not_ready` などのプロバイダーのロールアウト段階 |
| `provider_routing_status` | プロバイダー単位のルーティング状態 |
| `model_routing_status` | モデル単位のルーティング状態 |
| `capability_status` | リクエストされたエンドポイントの対応付けに対するプロバイダーの機能の状態 |
| `provider_availability_status` | `active`、`coming_soon`、`inactive` などのプロバイダー側の提供状況 |
| `provider_availability_reason` | `preview_only`、`provider_not_ready`、`gated`、`access_limited`、`region_limited` などの、プロバイダーが利用できない理由 |
| `input_types`（エイリアス `input_modalities`） | 入力のモダリティ |
| `output_types`（エイリアス `output_modalities`） | 出力のモダリティ |
| `params`（エイリアス `supported_parameters`） | 対応しているリクエストパラメーター |

1 つのモデルのプロバイダールート、パラメーターの詳細、料金を確認するには、[`GET /models/{author}/{slug}/endpoints`](./model-endpoints.mdx) を呼び出します。

## 提供内容ごとのサービスティアを確認する

`offers` の各エントリーには `service_tiers` が含まれます。これは、そのプロバイダーの提供内容が受け付ける[サービスティア](../../guides/service-tiers.mdx)です。`flex`、`priority`、`standard`、`ultrafast` のうちの一部をアルファベット順に並べたもので、`priority` は Fast ティアです。プロバイダールートに、そのティアについて有効で現在適用中の料金がある場合にティアが表示され、1 つのティアのみを提供するルートにはそのティアだけが表示されます。一部のティアは、表示されていない別のティア専用のプロバイダールートでも利用できます。`pricing` の料金は引き続き標準ティアの料金です。

## OpenAI 形式で一覧を取得する

OpenAI のモデル一覧のレスポンスを期待するクライアントには、`GET /v1/models?format=openai` を使います。デフォルトの `format=json` は、Phaseo のより詳しいモデルのメタデータを返します。

```bash
curl "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

```json
{
  "object": "list",
  "data": [
    { "id": "openai/gpt-6-astra", "object": "model", "created": 1788393600, "owned_by": "openai" }
  ]
}
```

OpenAI 形式では、ネイティブの JSON と同じ認証、リージョンごとの提供状況、ワークスペースのプライベートモデル、フィルターが使われます。`limit` を指定しない限り一致するすべてのモデルが返され、`offset` は引き続き適用されます。ID は推論用の Phaseo の正規の形式のままです。`created` にはカタログのリリース日（不明な場合は `0`）が、`owned_by` にはカタログの組織、ワークスペースのモデルでは `private`、不明な場合は `phaseo` が入ります。

## モデル一覧をキャッシュする

カタログのレスポンスは 5 分間キャッシュされ、キャッシュの再検証中はさらに 5 分間提供されることがあります。これは現在のカタログの JSON、RSS、Atom の表現に適用されます。リリースフィードには、より短い独自のポーリング用キャッシュがあります。

JSON と OpenAI 形式のレスポンスには、弱い `ETag` ヘッダー（`W/"…"`）が含まれます。これは、ページ上のモデル、`limit`、`offset`、`total`、または形式が変わると変化します。`gateway_region` は無視されるため、別のリージョンから提供された同じカタログには同じ `ETag` が付きます。弱い ETag であるのはこのためで、同じ値を持つレスポンスは同等ですが、バイト列は異なることがあります。RSS、Atom、エラーのレスポンスには含まれません。

保存した値を、そのまま `If-None-Match` で送り返してください。カタログが変わっていない場合、レスポンスは本文のない `304 Not Modified` で、`ETag`、`Cache-Control`、`Vary` ヘッダーが繰り返されます。変わっている場合は、新しい一覧と新しい `ETag` を含む通常の `200` が返されます。`If-None-Match` はカンマ区切りのリストと `*` も受け付け、比較は弱い比較なので、値は `W/` プレフィックスの有無にかかわらず一致します。

```ts
let etag: string | null = null;
let models: unknown[] = [];

async function refreshModels() {
  const response = await fetch("https://api.phaseo.app/v1/models?limit=250", {
    headers: {
      Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
      ...(etag ? { "If-None-Match": etag } : {}),
    },
  });
  if (response.status === 304) return models; // 変更なし。304 には本文がありません。
  if (!response.ok) throw new Error(`Model list request failed: ${response.status}`);
  etag = response.headers.get("ETag");
  models = (await response.json()).models;
  return models;
}
```

`304` により転送と解析の手間が省けます。それでもサーバーはリクエストを評価し、カタログを読み込んで `ETag` を再計算します。約 15 分ごとのポーリングで十分で、カタログが変わったときにだけ一覧を再ダウンロードすれば済みます。ページ、フィルターの組み合わせ、形式ごとに値が異なるため、`ETag` はリクエスト URL ごとに 1 つ保持してください。
