デフォルトでは、このエンドポイントは現在ルーティング可能なモデルのみを返します。`availability=all` を設定すると、既知だが現在利用できないモデルも含まれます。

カタログのレスポンスは 5 分間キャッシュされ、キャッシュの再検証中はさらに 5 分間提供される場合があります。これは現在のカタログの JSON、RSS、Atom 表現に適用されます。リリースフィードには、より短い独自のポーリングキャッシュがあります。

`GET /models/me` は、現在の呼び出し元に適用されるガードレールに基づくモデルの絞り込みに将来使用するための予約パスです。現在は `501 not implemented` を返すため、共通の Gateway カタログには `GET /models` を使用してください。

## 便利なフィルター

- `endpoints` では `chat.completions`、`responses`、`messages` などの公開名を指定します
- `status` は `active`、`deprecated`、`retired` などのモデルのライフサイクルで絞り込みます
- `provider` は `openai`、`anthropic`、`google_vertex` などの公開プロバイダー ID で絞り込みます
- `provider_status` は `active`、`beta`、`alpha`、`not_ready` などのプロバイダーの展開段階で絞り込みます
- `provider_routing_status` はプロバイダー単位のルーティング状態で絞り込みます
- `model_routing_status` はモデル単位のルーティング状態で絞り込みます
- `capability_status` は要求されたエンドポイントの対応付けに対するプロバイダー機能の状態で絞り込みます
- `provider_availability_status` は `active`、`coming_soon`、`inactive` などのプロバイダー可用性で絞り込みます
- `provider_availability_reason` は `preview_only`、`provider_not_ready`、`gated`、`access_limited`、`region_limited` などのプロバイダー可用性の理由で絞り込みます
- `organisation` は公開モデル ID のプレフィックスで絞り込みます。たとえば `anthropic/claude-3-haiku` の `anthropic` を指定します
- `availability=active` がデフォルトです
- `availability=all` は `coming_soon`、`inactive`、または一般公開のルーティング対象になっていないモデルやプロバイダーを含みます
- `input_modalities` は `input_types` の別名です
- `output_modalities` は `output_types` の別名です
- `supported_parameters` は `params` の別名です

モデルのエンドポイント契約を確認するには `GET /models/{author}/{slug}/endpoints` を呼び出します。レスポンスではプロバイダーのルートが分けられ、各行に公開パス、モダリティ、対応パラメーターの詳細、可用性、ルーティング状態、プロバイダー側モデルのスラッグ、料金の概要が含まれます。

プロバイダーの各項目には、次の情報も含まれる場合があります。

- `availability_status`
- `availability_reason`
- `provider_status`
- `provider_routing_status`
- `model_routing_status`
- `capability_status`
