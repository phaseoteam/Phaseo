デフォルトでは、このエンドポイントは現在ルーティング可能なモデルのみを返します。`availability=all` を設定すると、既知だが現在利用できないモデルも含まれます。

カタログのレスポンスは 5 分間キャッシュされ、キャッシュの再検証中はさらに 5 分間提供される場合があります。これは現在のカタログの JSON、RSS、Atom 表現に適用されます。リリースフィードには、より短い独自のポーリングキャッシュがあります。

`GET /models/me` は、現在の呼び出し元に適用されるガードレールに基づくモデルの絞り込みに将来使用するための予約パスです。現在は `501 not implemented` を返すため、共通の Gateway カタログには `GET /models` を使用してください。

## OpenAI 形式

OpenAI のモデル一覧レスポンスを想定しているクライアントには、`GET /v1/models?format=openai` を使用します。既定の `format=json` は、より詳細な Phaseo のモデルメタデータを返します。

```bash
curl 'https://api.phaseo.app/v1/models?format=openai' \
  -H 'Authorization: Bearer YOUR_PHASEO_API_KEY'
```

```json
{
  "object": "list",
  "data": [
    { "id": "openai/gpt-4o-mini", "object": "model", "created": 1721260800, "owned_by": "openai" }
  ]
}
```

OpenAI 形式では、ネイティブの JSON 形式と同じ認証、地域別の利用可否、ワークスペースのプライベートモデル、フィルターが使用されます。`limit` を指定しない限り一致するすべてのモデルを返し、`offset` は引き続き適用されます。ID は推論に使用する Phaseo の正規形式のままです。`created` にはカタログのリリース日が入り、不明な場合は `0` になります。`owned_by` にはカタログの組織が入り、ワークスペースのモデルでは `private`、不明な場合は `phaseo` になります。

## モデル一覧のキャッシュ

JSON 形式と OpenAI 形式のレスポンスには、弱い `ETag` ヘッダー（`W/"…"`）が含まれます。ページ上のモデル、`limit`、`offset`、`total`、形式のいずれかが変わると値も変わります。`gateway_region` は無視されるため、別のリージョンから提供された同じカタログでも `ETag` は同じです。そのため弱いバリデーターになっています。同じ値を持つレスポンスは同等ですが、バイト列は異なる場合があります。RSS、Atom、エラーのレスポンスには含まれません。

保存した値をそのまま `If-None-Match` で送り返してください。カタログが変わっていなければ、レスポンスは本文なしの `304 Not Modified` になり、`ETag`、`Cache-Control`、`Vary` ヘッダーを同じように返します。変わっている場合は、新しい一覧と新しい `ETag` を含む通常の `200` が返ります。`If-None-Match` には、カンマ区切りのリストと `*` も指定できます。比較は弱い比較のため、`W/` プレフィックスの有無にかかわらず値は一致します。

```ts
let etag: string | null = null;
let models: unknown[] = [];

async function refreshModels() {
  const response = await fetch("https://api.phaseo.app/v1/models?limit=250", {
    headers: {
      Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
      ...(etag ? { "If-None-Match": etag } : {}),
    },
  });
  if (response.status === 304) return models; // Unchanged; a 304 has no body.
  if (!response.ok) throw new Error(`Model list request failed: ${response.status}`);
  etag = response.headers.get("ETag");
  models = (await response.json()).models;
  return models;
}
```

`304` レスポンスには本文がないため、転送量とパース処理を節約できます。ただし、サーバーは引き続きリクエストを評価し、カタログを読み込んで `ETag` を再計算します。そのため、確認はおよそ 15 分ごとが適切です。カタログが変わったときだけ一覧を再ダウンロードしてください。ページ、フィルターの組み合わせ、形式ごとに値が異なるため、`ETag` はリクエスト URL ごとに保持してください。

### オファーごとのサービス階層

`offers` の各エントリには `service_tiers` が含まれます。これは、そのプロバイダーのオファーが受け付ける[サービス階層](../../guides/service-tiers.mdx)です。値は `flex`、`priority`、`standard`、`ultrafast` のうち該当するものをアルファベット順に並べたもので、`priority` は Fast 階層を表します。プロバイダールートにその階層の有効かつ現在適用中の料金がある場合に記載され、1 つの階層だけを提供するルートにはその階層のみが記載されます。一部の階層は、ここに記載されない階層専用の別のプロバイダールートを通じて利用できる場合もあります。`pricing` の料金は引き続き標準階層の料金です。

## 便利なフィルター

- `endpoints` では `chat.completions`、`responses`、`messages` などの公開名を指定します
- `status` は `active`、`deprecated`、`retired` などのモデルのライフサイクルで絞り込みます
- `provider` は `openai`、`anthropic`、`google_vertex` などの公開プロバイダー ID で絞り込みます
- `provider_status` は `active`、`beta`、`alpha`、`not_ready` などのプロバイダーの展開段階で絞り込みます
- `provider_routing_status` はプロバイダー単位のルーティング状態で絞り込みます
- `model_routing_status` はモデル単位のルーティング状態で絞り込みます
- `capability_status` は要求されたエンドポイントの対応付けに対するプロバイダー機能の状態で絞り込みます
- `provider_availability_status` は `active`、`coming_soon`、`inactive` などのプロバイダー可用性で絞り込みます
- `provider_availability_reason` は `preview_only`、`provider_not_ready`、`gated`、`access_limited`、`region_limited` などのプロバイダー可用性の理由で絞り込みます
- `organisation` は公開モデル ID のプレフィックスで絞り込みます。たとえば `anthropic/claude-3-haiku` の `anthropic` を指定します
- `availability=active` がデフォルトです
- `availability=all` は `coming_soon`、`inactive`、または一般公開のルーティング対象になっていないモデルやプロバイダーを含みます
- `input_modalities` は `input_types` の別名です
- `output_modalities` は `output_types` の別名です
- `supported_parameters` は `params` の別名です

モデルのエンドポイント契約を確認するには `GET /models/{author}/{slug}/endpoints` を呼び出します。レスポンスではプロバイダーのルートが分けられ、各行に公開パス、モダリティ、対応パラメーターの詳細、可用性、ルーティング状態、プロバイダー側モデルのスラッグ、料金の概要が含まれます。

プロバイダーの各項目には、次の情報も含まれる場合があります。

- `availability_status`
- `availability_reason`
- `provider_status`
- `provider_routing_status`
- `model_routing_status`
- `capability_status`
