请使用本页了解 Phaseo 错误代表什么，以及接下来应该采取什么操作。

所有错误响应都使用相同的 JSON 格式，因此应用可以在不同模型和提供商之间一致地处理失败。 `error` 字段是一个包含 `code`、`message` 和 `type` 的对象，即 OpenAI 兼容 SDK 读取的格式，因此这些 SDK 的异常会带上网关的消息。

## 错误响应示例

```json
{
  "error": {
    "code": "upstream_error",
    "message": "Provider \"google-ai-studio\" failed with HTTP 403 for endpoint \"responses\" on model \"google/gemini-2.5-pro\".",
    "type": "server_error",
    "param": null,
    "metadata": {
      "reason": "all_candidates_failed",
      "attempt_count": 1,
      "failed_providers": ["google-ai-studio"],
      "failed_statuses": [403],
      "upstream_error": {
        "code": "PERMISSION_DENIED",
        "message": "The caller does not have permission.",
        "description": null,
        "param": null
      }
    }
  },
  "code": "upstream_error",
  "message": "Provider \"google-ai-studio\" failed with HTTP 403 for endpoint \"responses\" on model \"google/gemini-2.5-pro\".",
  "generation_id": "G-abc123",
  "status_code": 502,
  "error_type": "system",
  "error_origin": "upstream",
  "reason": "all_candidates_failed",
  "description": "Provider \"google-ai-studio\" failed with HTTP 403 for endpoint \"responses\" on model \"google/gemini-2.5-pro\".",
  "attempt_count": 1,
  "failed_providers": ["google-ai-studio"],
  "failed_statuses": [403],
  "provider_failure_diagnostics": {
    "category": "provider_access_missing",
    "hint": "The provider account appears not to have access to this model or feature yet. Verify account entitlements and provider-side access.",
    "provider": "google-ai-studio"
  },
  "upstream_error": {
    "code": "PERMISSION_DENIED",
    "message": "The caller does not have permission.",
    "description": null,
    "param": null
  },
  "failure_sample": [
    {
      "provider": "google-ai-studio",
      "type": "upstream_non_2xx",
      "status": 403,
      "upstream_error_code": "PERMISSION_DENIED",
      "upstream_error_message": "The caller does not have permission.",
      "upstream_error_description": null,
      "upstream_error_param": null,
      "upstream_payload_preview": "{\"error\":{\"status\":\"PERMISSION_DENIED\"}}",
      "retryable": false
    }
  ]
}
```

## 始终会返回的字段

- `generation_id`：稳定的请求 ID，可提供给支持团队。
- `status_code`：与 HTTP 状态代码一致。
- `error`：描述失败情况的对象：
  - `error.code`：机器可读的错误代码，例如 `validation_error`。
  - `error.message`：用通俗语言说明发生了什么。
  - `error.type`：错误类型（见下方的“错误类型”一节）。
  - `error.param`：导致错误的请求参数；网关无法确定时为 `null`。
  - `error.metadata`（可选）：结构化详情，例如失败的提供商、子原因、失败的状态码或 `retry_after_seconds`。相同的值也会在顶层返回。
- `code`：与 `error.code` 相同的代码。以前的响应把此代码作为字符串放在 `error` 中；如果你的客户端在那里期望字符串，请改读 `code`。
- `message`：与 `error.message` 相同的文本。
- `error_type`：较高层级的分类，通常为 `user` 或 `system`。
- `error_origin`：指出问题主要由调用方、Phaseo 还是上游提供商导致。
- `description`：对问题的通俗说明。
- `details`（可选）：请求验证失败时提供结构化的验证详情。

## 可能出现的其他字段

部分错误会包含更多详情，帮助你更快解决问题：

- `reason`：更具体的原因，例如 `all_candidates_failed` 或 `pricing_not_configured`。
- `provider_candidate_diagnostics` 和 `provider_enablement`：解释为何无法使用模型处理所请求的端点。
- `routing_diagnostics`：说明路由或可用性检查如何缩小请求范围。
- `provider_failure_diagnostics`：关于凭证缺失、访问权限不足、区域限制、速率限制及其他提供商侧失败的提示。
- `upstream_error` 和 `failure_sample`：如果请求到达了提供商，则尽可能总结首次提供商故障。
- `failed_providers`、`failed_statuses` 和 `attempt_count`：重试和故障转移的补充信息。

## 错误类型

`error.type` 遵循 OpenAI [文档中的错误类型](https://platform.openai.com/docs/guides/error-codes)，并由 HTTP 状态决定：

| 状态 | `error.type` |
| --- | --- |
| `400`, `409`, `410`, `413`, `422` 及其他 4xx | `invalid_request_error` |
| `401` | `authentication_error` |
| `402` | `insufficient_quota` |
| `403` | `permission_error` |
| `404` | `not_found_error` |
| `429` | `rate_limit_error` |
| `503` | `service_unavailable` |
| `529` | `overloaded` |
| `500`, `502` 及其他 5xx | `server_error` |

`/v1/messages` 的错误使用相同的响应体，因此 Anthropic SDK 也能读到 `error.type` 和 `error.message`。

## 状态码类别指南

| 状态 | 含义 | 建议操作 |
| --- | --- | --- |
| `400-499` | 请求、身份验证或权限问题 | 重试前修正请求或凭证。 |
| `429` | 提供商或路由级限流 | 采用退避重试并遵守 `Retry-After`。 |
| `500-599` | Phaseo 或上游提供商故障 | 采用带抖动的退避重试，并记录请求 ID。 |

## 常见错误代码

| `error.code` | HTTP 状态 | `error.type` | 说明 |
| --- | --- | --- | --- |
| `unauthorised` | `401` | `authentication_error` | API 密钥缺失或无效。 |
| `guardrail_blocked` | `403` | `permission_error` | 工作区的护栏或访问策略阻止了该请求。 |
| `not_found` | `404` | `not_found_error` | 找不到端点或资源。 |
| `model_retired` | `410` | `invalid_request_error` | 该模型已停用，且不再有任何提供商提供。请改用 `replacement_model`。 |
| `insufficient_funds` | `402` | `insufficient_quota` | 工作区的额度不足以完成该请求。 |
| `key_limit_exceeded` | `429` | `rate_limit_error` | API 密钥已达到其某项限制。 |
| `phaseo_free_model_limit_exceeded` | `429` | `rate_limit_error` | Phaseo 免费模型的共享每日配额已用尽（默认 1,500 次请求）。请遵循 `Retry-After`，等待 00:00 UTC 重置，或选择付费模型。 |
| `rate_limit_exceeded` | `429` | `rate_limit_error` | 工作区的某个[速率限制策略](./limits.mdx)已耗尽。可通过 `policy_id` 和 `limit_scope` 确定是哪一个。请遵循 `Retry-After`，或请工作区管理员修改该策略。 |
| `validation_error` | `400` | `invalid_request_error` | 参数或请求正文无效。 `error.param` 指出第一个无效字段。 |
| `upstream_error` | `429` | `rate_limit_error` | 为该请求尝试的所有提供商都对其进行了速率限制。请遵循 `Retry-After`；BYOK 请求还会带有 `X-Phaseo-Upstream-RateLimit-*` 标头。 |
| `upstream_error` | `502` | `server_error` | 上游模型提供商未能正确响应。 |
| `upstream_stream_failure` | `502` | `server_error` | 非流式请求的提供商在开始生成后失败。不会返回部分输出，也不会对该请求计费。 |
| `gateway_error` | `500` | `server_error` | Phaseo 内部发生意外问题。 |

## 提供商故障时

如果 Phaseo 已连接到提供商，但请求仍然失败，你可能会看到：

- `provider_failure_diagnostics.category`
- `provider_failure_diagnostics.hint`
- `provider_failure_diagnostics.provider`

当前类别包括：

- `credentials_not_configured`
- `credentials_invalid_or_forbidden`
- `provider_access_missing`
- `region_or_project_restriction`
- `model_unavailable_for_endpoint`
- `rate_limited`
- `server_error`

这些字段旨在帮助解决问题，无需开启完整调试模式。

## 模型或端点不可用时

对于 `unsupported_model_or_endpoint` 响应，Phaseo 可能会返回：

- `provider_candidate_diagnostics`
- `provider_enablement`
- `missing_pricing_providers`
- `routing_diagnostics`

这有助于区分：

- 已知但尚未启用的模型
- 不支持所请求端点的模型
- 缺少价格数据
- 发布阶段或内部可用性限制

常用字段：

- `provider_candidate_diagnostics.totalProviders`：按端点筛选之前，该模型已知的提供商数量。
- `provider_candidate_diagnostics.supportsEndpointCount`：其中支持所请求端点的提供商数量。
- `provider_candidate_diagnostics.candidateCount`：适配器检查后剩余的提供商数量。
- `provider_candidate_diagnostics.droppedUnsupportedEndpoint`：因不支持该端点而移除的提供商。
- `provider_candidate_diagnostics.droppedMissingAdapter`：因 Gateway 尚无该端点适配器而移除的提供商/端点组合。
- `provider_enablement.capability`：正在执行的能力门控，例如 `video_generation`。
- `provider_enablement.providersBefore` / `provider_enablement.providersAfter`：能力或启用筛选前后的提供商。
- `provider_enablement.dropped[].reason`：机器可读原因，例如 `pricing_missing`。
- `routing_diagnostics.filterStages[].stage`：路由阶段，例如能力、发布或路由状态筛选。
- `routing_diagnostics.filterStages[].beforeCount` / `routing_diagnostics.filterStages[].afterCount`：每个阶段前后的提供商数量。
- `routing_diagnostics.filterStages[].droppedProviders[].reason`：机器可读原因，例如发布或路由限制。

### 示例

```json
{
  "error": {
    "code": "unsupported_model_or_endpoint",
    "message": "No provider is currently routable for endpoint \"responses\" on model \"example/model\".",
    "type": "invalid_request_error",
    "param": null
  },
  "code": "unsupported_model_or_endpoint",
  "generation_id": "G-unsupported123",
  "status_code": 400,
  "description": "No provider is currently routable for endpoint \"responses\" on model \"example/model\".",
  "provider_candidate_diagnostics": {
    "totalProviders": 3,
    "supportsEndpointCount": 2,
    "candidateCount": 1,
    "droppedUnsupportedEndpoint": ["provider-a"],
    "droppedMissingAdapter": [
      {
        "providerId": "provider-b",
        "endpoint": "responses"
      }
    ]
  },
  "provider_enablement": {
    "capability": "responses",
    "providersBefore": ["provider-b", "provider-c"],
    "providersAfter": ["provider-c"],
    "dropped": [
      {
        "providerId": "provider-b",
        "reason": "pricing_missing"
      }
    ]
  },
  "routing_diagnostics": {
    "filterStages": [
      {
        "stage": "provider_routing_status",
        "beforeCount": 1,
        "afterCount": 0,
        "droppedProviders": [
          {
            "providerId": "provider-c",
            "reason": "provider_status_not_ready"
          }
        ]
      }
    ]
  }
}
```

## 模型停用时

已停用的模型只要仍有任何提供商提供，就会继续提供服务。一旦没有任何提供商提供，对它的请求就会失败，并返回 `410` 和 `model_retired` 错误：

```json
{
  "error": {
    "code": "model_retired",
    "message": "Model \"lab/old-model\" was retired on 2026-09-30 and no provider serves it any more. Use \"lab/new-model\" instead.",
    "type": "invalid_request_error",
    "param": null,
    "metadata": {
      "retired_at": "2026-09-30T00:00:00Z",
      "replacement_model": "lab/new-model"
    }
  },
  "code": "model_retired",
  "generation_id": "G-retired123",
  "status_code": 410,
  "reason": "model_retired_without_providers",
  "description": "Model \"lab/old-model\" was retired on 2026-09-30 and no provider serves it any more. Use \"lab/new-model\" instead.",
  "model": "lab/old-model",
  "retired_at": "2026-09-30T00:00:00Z",
  "replacement_model": "lab/new-model"
}
```

- `model`：你请求的模型。
- `retired_at`：模型的停用时间；如果未记录日期，则为 `null`。
- `replacement_model`：建议的替代模型；如果没有，则为 `null`。

重试无济于事。请更新请求中的模型 ID。如需在迁移期间继续处理这些请求，请将替代模型添加到请求的 `models` 列表中，或为工作区开启已停用模型的路由。请参阅[模型弃用与停用](../guides/model-retirement.mdx)。

## 可选调试模式

大多数请求架构都支持 `debug` 对象，用于受控的问题排查：

```json
{
  "debug": {
    "enabled": true,
    "return_upstream_request": true,
    "return_upstream_response": false,
    "trace": true,
    "trace_level": "summary"
  }
}
```

可用字段：

- `enabled`
- `return_upstream_request`
- `return_upstream_response`
- `trace`
- `trace_level`（`summary` 或 `full`）

仅在开发环境或严格受控的环境中使用调试模式。

## 重试策略

- **429 以外的 400 系列错误：**重试前请修正请求、凭据或访问策略。
- **429：**实施指数退避并遵循 `Retry-After` 标头。
- **500 系列错误：**仅在重复操作安全时进行有限重试。结果不明确的提交可能已经创建了任务或产生了费用；请获取已受理的任务，而不要重新提交。

设置重试次数上限和总体截止时间，并在退避延迟中加入随机抖动。有关响应标头和重试处理，请参阅[速率限制](./limits.mdx)。

## 流式传输注意事项

- 如果请求在流式传输开始前失败，会收到标准 JSON 错误负载。
- 如果请求在流式传输期间失败，流会以端点的失败事件结束，而不是正常完成：Chat Completions 为 `error` 帧，Responses 为 `response.failed`（或 `error`），Messages 为 `error` 事件。请将不完整的部分流视为未完成，并提供重试选项。
- Chat Completions 的 `error` 帧同样带有该错误对象，`error.type` 由代码决定：

  ```json
  {
    "object": "error",
    "message": "The upstream stream ended before the response completed.",
    "code": "upstream_stream_failure",
    "error": {
      "code": "upstream_stream_failure",
      "message": "The upstream stream ended before the response completed.",
      "type": "server_error",
      "param": null
    }
  }
  ```
- 非流式请求的提供商中途失败时，会返回带有 `upstream_stream_failure` 的 `502`，而不是部分响应。
- 请始终记录 `generation_id` 以及端点和模型元数据。

## 故障排查提示

- 查看 [Gateway 状态页](https://status.phaseo.app)了解正在发生的事故。
- 对照端点文档检查请求负载。
- 联系支持团队时，请提供 `generation_id`。

面向智能体的错误处理规则（本页摘要）：

- 根据 `error.code`（也会作为顶层 `code` 返回）、`error.type` 和 `status_code` 做判断，而不是根据消息文本。每次失败都记录 `generation_id`。
- `400`、`401`、`403` 和 `404`：先修正请求、密钥或访问权限。不要原样重试同一请求。
- 带有 `model_retired` 的 `410`：`replacement_model` 不为 `null` 时改用它；否则通过 `GET /v1/models` 选择新模型。
- `429`：如果有 `Retry-After`（秒数或 HTTP 日期），先等待该时长再重试；否则使用带抖动的指数退避。没有 `Retry-After` 的 `key_limit_exceeded` 错误不会自动重置，因此不要重试。
- `500` 到 `599`：仅在重复调用安全时重试，并设置尝试次数上限、总截止时间和带抖动的指数退避。对于异步任务，应查询已接受的任务，而不是重新提交。
- 将调试载荷视为敏感信息，写入持久日志前先脱敏。
- 如需经过验证的重试和错误解析模式，请安装 `phaseo-gateway` 技能：`npx skills add https://phaseo.app/docs --skill phaseo-gateway`。
</Visibility>
