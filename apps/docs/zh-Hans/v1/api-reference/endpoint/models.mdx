默认情况下，此端点仅返回当前可路由的模型。设置 `availability=all` 可同时包含已知但当前不可用的模型。

目录响应会缓存五分钟，并可能在缓存重新验证期间继续提供五分钟。这适用于当前目录的 JSON、RSS 和 Atom 表示；发布动态有自己时长更短的轮询缓存。

`GET /models/me` 为未来根据当前调用方的护栏筛选模型而保留。目前该接口会返回 `501 not implemented`，因此现在请使用 `GET /models` 查询共享的 Gateway 目录。

## 常用筛选条件

- `endpoints` 使用公开名称，例如 `chat.completions`、`responses` 和 `messages`
- `status` 按模型生命周期筛选，例如 `active`、`deprecated` 或 `retired`
- `provider` 按提供商公开 ID 筛选，例如 `openai`、`anthropic` 或 `google_vertex`
- `provider_status` 按提供商发布阶段筛选，例如 `active`、`beta`、`alpha` 或 `not_ready`
- `provider_routing_status` 按提供商级路由状态筛选
- `model_routing_status` 按模型级路由状态筛选
- `capability_status` 按提供商对所请求端点映射的能力状态筛选
- `provider_availability_status` 按提供商可用性筛选，例如 `active`、`coming_soon` 或 `inactive`
- `provider_availability_reason` 按提供商可用性原因筛选，例如 `preview_only`、`provider_not_ready`、`gated`、`access_limited` 或 `region_limited`
- `organisation` 按公开模型 ID 前缀筛选，例如 `anthropic/claude-3-haiku` 中的 `anthropic`
- `availability=active` 是默认值
- `availability=all` 包含状态为 `coming_soon`、`inactive` 或尚未公开路由的模型或提供商
- `input_modalities` 是 `input_types` 的别名
- `output_modalities` 是 `output_types` 的别名
- `supported_parameters` 是 `params` 的别名

如需查看某个模型的端点契约，请调用 `GET /models/{author}/{slug}/endpoints`。响应会按提供商区分路由，并在每一行中列出公开路径、模态、受支持参数详情、可用性、路由状态、提供商模型标识和价格摘要。

提供商条目还可能包括：

- `availability_status`
- `availability_reason`
- `provider_status`
- `provider_routing_status`
- `model_routing_status`
- `capability_status`
