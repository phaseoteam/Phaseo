调用 `GET /v1/models` 列出你当前可以路由到的模型。设置 `availability=all` 可包含已知但当前不可用的模型。

```bash
curl "https://api.phaseo.app/v1/models?limit=50" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

每个模型在 `offers` 中为每条提供商路由列出一个条目（已节选，数值仅作示意）：

```json
{
  "ok": true,
  "availability_mode": "active",
  "limit": 50,
  "offset": 0,
  "total": 412,
  "models": [
    {
      "id": "anthropic/claude-sonnet-5.5",
      "name": "Claude Sonnet 5.5",
      "organization": { "id": "anthropic", "name": "Anthropic", "color": "#d97757" },
      "lifecycle": { "status": "active", "released_at": "2026-09-28", "replacement_id": null },
      "modalities": { "input": ["text", "image"], "output": ["text"] },
      "capabilities": { "endpoints": ["chat.completions", "messages", "responses"] },
      "availability": { "status": "active", "provider_count": 3, "active_provider_count": 3 },
      "offers": [
        {
          "provider": { "id": "anthropic", "name": "Anthropic" },
          "model": "claude-sonnet-5-5",
          "status": "active",
          "status_reason": null,
          "routable": true,
          "service_tiers": ["standard"],
          "routing": { "provider": "active", "model": "active", "capability": "active" }
        }
      ]
    }
  ]
}
```

只能将生产流量路由到 `routable` 为 `true` 的 offer。`status_reason` 说明 offer 为何仅为预览或处于非活动状态。完整的架构见下文。

`GET /models/me` 返回同一列表，但会应用你的密钥的护栏规则：工作区的隐私和提供商规则，以及密钥所属部门、其成员和密钥本身的护栏。被模型规则屏蔽的模型，以及没有任何允许的提供商的模型都不会列出，每个模型只保留其请求可以路由到的服务。它接受与 `GET /models` 相同的筛选参数。 响应中还包含 `access`：是否有规则生效（`restricted`）、被规则排除的模型（`hidden_model_count` 和 `hidden_models`，含 ID 和名称），以及有多少列出的模型失去了部分提供商（`limited_model_count`），方便你说明某个模型为何不见了。

## 筛选列表

接受多个值的筛选条件可以使用重复的参数或逗号分隔的列表。

| 参数 | 筛选依据 |
| --- | --- |
| `availability` | `active`（默认）表示可公开路由的模型；`all` 会额外加入 `coming_soon`、`inactive` 以及尚不可路由的模型和提供商 |
| `endpoints` | 公共端点名称，例如 `chat.completions`、`responses` 和 `messages` |
| `status` | 模型生命周期，例如 `active`、`deprecated` 或 `retired` |
| `organisation` | 模型 ID 前缀，例如 `anthropic/claude-3-haiku` 中的 `anthropic` |
| `provider` | 公共提供商 ID，例如 `openai`、`anthropic` 或 `google_vertex` |
| `provider_status` | 提供商上线阶段，例如 `active`、`beta`、`alpha` 或 `not_ready` |
| `provider_routing_status` | 提供商级别的路由状态 |
| `model_routing_status` | 模型级别的路由状态 |
| `capability_status` | 所请求端点映射的提供商能力状态 |
| `provider_availability_status` | 提供商侧的可用性，例如 `active`、`coming_soon` 或 `inactive` |
| `provider_availability_reason` | 提供商不可用的原因，例如 `preview_only`、`provider_not_ready`、`gated`、`access_limited` 或 `region_limited` |
| `input_types`（别名 `input_modalities`） | 输入模态 |
| `output_types`（别名 `output_modalities`） | 输出模态 |
| `params`（别名 `supported_parameters`） | 支持的请求参数 |

如需查看某个模型的提供商路由、参数详情和价格，请调用 [`GET /models/{author}/{slug}/endpoints`](./model-endpoints.mdx)。

## 查看每个 offer 的服务层级

`offers` 中的每个条目都包含 `service_tiers`，即该提供商 offer 接受的[服务层级](../../guides/service-tiers.mdx)。它是 `flex`、`priority`、`standard` 和 `ultrafast` 的一个按字母排序的子集，其中 `priority` 就是 Fast 层级。当提供商路由对某个层级有已启用且当前生效的定价时，才会列出该层级；只服务一个层级的路由只列出该层级。有些层级还可以通过未列出的、针对特定层级的单独提供商路由使用。`pricing` 下的价格仍是标准层级的价格。

## 以 OpenAI 格式获取列表

对于需要 OpenAI 模型列表响应格式的客户端，请使用 `GET /v1/models?format=openai`。默认的 `format=json` 返回 Phaseo 更丰富的模型元数据。

```bash
curl "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

```json
{
  "object": "list",
  "data": [
    { "id": "openai/gpt-6-astra", "object": "model", "created": 1788393600, "owned_by": "openai" }
  ]
}
```

OpenAI 格式与原生 JSON 使用相同的身份验证、区域可用性、工作区私有模型和筛选条件。除非你提供 `limit`，否则它会返回所有匹配的模型；`offset` 仍然有效。ID 保持 Phaseo 用于推理的规范形式。`created` 使用目录中的发布日期，未知时为 `0`；`owned_by` 使用目录中的组织，工作区模型为 `private`，未知时为 `phaseo`。

## 缓存模型列表

目录响应会缓存五分钟，在缓存重新验证期间还可能再提供五分钟。这适用于当前目录的 JSON、RSS 和 Atom 表示形式；发布动态有自己更短的轮询缓存。

JSON 和 OpenAI 格式的响应包含一个弱 `ETag` 标头（`W/"…"`）。当页面上的模型、`limit`、`offset`、`total` 或格式发生变化时，它会改变。它忽略 `gateway_region`，因此从其他区域提供的同一目录具有相同的 `ETag`。这就是它是弱 ETag 的原因：共享同一个值的响应是等价的，但字节可能不同。RSS、Atom 和错误响应不包含它。

在 `If-None-Match` 中原样发回保存的值。如果目录没有变化，响应为 `304 Not Modified`，没有正文，并重复 `ETag`、`Cache-Control` 和 `Vary` 标头。否则你会收到一个正常的 `200`，其中包含新列表和新的 `ETag`。`If-None-Match` 也接受逗号分隔的列表和 `*`，并且使用弱比较，因此无论值是否带有 `W/` 前缀都能匹配。

```ts
let etag: string | null = null;
let models: unknown[] = [];

async function refreshModels() {
  const response = await fetch("https://api.phaseo.app/v1/models?limit=250", {
    headers: {
      Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
      ...(etag ? { "If-None-Match": etag } : {}),
    },
  });
  if (response.status === 304) return models; // 未变化；304 没有正文。
  if (!response.ok) throw new Error(`Model list request failed: ${response.status}`);
  etag = response.headers.get("ETag");
  models = (await response.json()).models;
  return models;
}
```

`304` 可以节省传输和解析开销。服务器仍会处理该请求：它会加载目录并重新计算 `ETag`。大约每 15 分钟轮询一次就足够了，只有在目录发生变化时才会重新下载列表。为每个请求 URL 保留一个 `ETag`，因为每个页面、筛选条件组合和格式都有各自的值。
