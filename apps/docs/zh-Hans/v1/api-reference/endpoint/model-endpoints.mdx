在发送请求之前调用此端点，确认某个模型、提供商、端点和参数组合是否可用。以 `openai/gpt-6-astra` 为例：

```bash
curl "https://api.phaseo.app/v1/models/openai/gpt-6-astra/endpoints" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

`endpoints` 中的每个条目是一个端点的一条提供商路由：

| 字段 | 内容 |
| --- | --- |
| `endpoint`、`capability_id`、`public_path`、`collection` | 规范的端点 ID 和能力 ID，以及公共 API 路径 |
| `provider`、`model` | 提供商 ID 和名称，以及提供商的模型 slug |
| `routable`、`status`、`status_reason` | 该路由当前是否接收流量、它的可用性，以及它仅为预览或处于非活动状态的原因 |
| `modalities` | 输入和输出模态 |
| `capabilities` | 支持的参数名称和结构化参数详情 |
| `routing` | 提供商、模型和能力的路由状态 |
| `effective` | 路由已排期或有时间限制时的 `from` 和 `to` 日期 |
| `pricing` | 端点定价摘要 |

如需先比较模型，请使用[列出模型](./models.mdx)；如需查看 API 公开的所有端点，请使用[列出端点](./endpoints.mdx)。

## 包含计划中和非活动的路由

默认的 `availability=active` 只返回可公开路由的行。使用 `availability=all` 可查看即将推出和非活动的路由：

```bash
curl "https://api.phaseo.app/v1/models/openai/gpt-6-astra/endpoints?availability=all" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

只能将生产流量路由到 `routable` 为 `true` 且 `status` 为 `active` 的行。

## 筛选路由

以下筛选条件接受重复的参数或逗号分隔的列表：`provider`、`provider_status`、`provider_routing_status`、`model_routing_status`、`capability_status`、`provider_availability_status`、`provider_availability_reason`、`status`，以及 `supported_parameters`（别名 `params`）。[列出模型](./models.mdx#filter-the-list)说明了它们的取值。

以下请求返回支持 `reasoning_effort` 的 OpenAI 路由：

```bash
curl "https://api.phaseo.app/v1/models/openai/gpt-6-astra/endpoints?provider=openai&supported_parameters=reasoning_effort" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```
