把模型改为 `anthropic/claude-sonnet-4.6`，删除 assistant 预填充，并把结构化输出移到 `output_config.format`。Sonnet 4.6 与 [Claude Opus 4.6](./anthropic-claude-opus-4-5-to-4-6) 有相同的请求变更；它在编码、计算机使用和智能体规划上的表现也有明显差异，因此需要重新测试提示词和路由方面的假设。

| | Claude Sonnet 4.5 | Claude Sonnet 4.6 |
| --- | --- | --- |
| Phaseo 模型 ID | `anthropic/claude-sonnet-4.5` | `anthropic/claude-sonnet-4.6` |
| 状态 | 已弃用；2026 年 11 月 30 日停用 | 可用 |
| 上下文窗口 | 200K token | 1M token |
| 最大输出 | 64K token | 64K token |
| Assistant 预填充 | 支持 | 返回 `400` |
| 结构化输出 | `output_format` | `output_config.format` |
| 思考 | `budget_tokens` | 自适应，由 `output_config.effort` 调节 |

## 更新请求

**1. 停止使用 assistant 预填充。** 如果你的 Sonnet 4.5 提示词用 JSON 前缀、XML 标签或格式占位开启 assistant 轮次，请在上线前删除；Sonnet 4.6 会返回 `400`。

**2. 在 `/v1/messages` 上把结构化输出**从 `output_format` 移到 `output_config.format`，并重新运行 schema 和解析器测试。在 `/v1/chat/completions` 和 `/v1/responses` 上，继续使用 `response_format`。

**3. 针对延迟重新调整 effort。** Sonnet 4.6 只在被要求时才思考。在 Phaseo 上，`reasoning.effort` 或 `reasoning.enabled: true` 会开启自适应思考并设置 `output_config.effort`；除 `xhigh` 外的所有级别都被接受，`xhigh` 会作为 `max` 发送。在把 4.6 设为交互式路由的默认模型之前，先按你的延迟预算对各级别做基准测试。

**4. 删除过时的 beta 请求头。** Phaseo 不会转发 `anthropic-beta` 请求头。

## 要测试的内容

- **输出行为：** 对格式敏感的提示词、多步骤智能体规划、编码、重构和审查提示词，以及长上下文检索和摘要。
- **契约稳定性：** JSON 和 schema 通过率、工具参数的完整性、结束原因和空输出，以及依赖预填充的路由。
- **生产指标：** 各 effort 级别的延迟、相对 Sonnet 4.5 的任务成功率、超时和重试率，以及每个成功任务的成本。

## 上线

1. 先删除预填充并更新结构化输出。
2. 在当前的生产提示词上评估 Sonnet 4.6。
3. 金丝雀发布，把 Sonnet 4.5 或其他稳定模型作为 `models` 中的回退，并在 Sonnet 4.5 停用之前完成。
4. 当质量和契约稳定性保持稳定后再增加流量。
