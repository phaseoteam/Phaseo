把模型改为 `anthropic/claude-opus-4.7`，去掉采样参数和思考预算，并用 effort 级别设定深度。仍带有 Opus 4.6 字段的请求在 Phaseo 上不会失败；网关会按下表改写它们。

| Opus 4.6 请求 | Phaseo 发送给 Opus 4.7 的内容 |
| --- | --- |
| `temperature`、`top_p`、`top_k` | 省略。对于非默认值，Anthropic 会返回 `400`。 |
| `thinking: {"type": "enabled", "budget_tokens": …}` | `thinking: {"type": "adaptive", "display": "summarized"}`；预算不会被转发。 |
| `reasoning.effort` | `output_config.effort`，包括 `xhigh`。 |
| `reasoning.effort: "none"` 或 `reasoning.enabled: false` | `thinking: {"type": "disabled"}`。 |
| 没有推理设置 | 没有 `thinking` 字段，因此 Opus 4.7 不会思考。 |

除非你主动选择，Opus 4.7 还会隐藏思考内容；Phaseo 每次开启思考时都会请求摘要显示。对于相同的文本，它的分词器可能比 Opus 4.6 产生更多 token。

## 更新请求

1. 把模型 ID 设为 `anthropic/claude-opus-4.7`。
2. 删除 `temperature`、`top_p` 和 `top_k`，改用指令进行调整。
3. 用自适应思考和 effort 级别替换思考预算：

```json
{
  "model": "anthropic/claude-opus-4.7",
  "messages": [{ "role": "user", "content": "Refactor this module and explain the risks." }],
  "reasoning": { "effort": "xhigh" }
}
```

从 `high` 开始，在最难的编码和智能体路由上使用 `xhigh`。在 `/v1/messages` 上，改为发送 `thinking: {"type": "adaptive"}` 和 `output_config.effort`。

4. 由于分词器发生了变化，请检查 `max_tokens` 和 `max_output_tokens`、超时预算以及成本告警。

## 要测试的内容

- 生产提示词上的 schema 通过率；
- 长时间运行的工具工作流：工具调用次数、完成率和延迟；
- `high` 与 `xhigh` 下的质量对比；
- 你调用量最大的几类提示词的 token 成本。

## 上线

1. 迁移流量之前先部署请求结构的变更。
2. 在你的生产评估套件上影子运行 Opus 4.7。
3. 金丝雀发布，把 Opus 4.6 作为 `models` 中的回退。
4. 当质量、延迟和成本的变化都在目标范围内时再全面推广。
