选择适合工作负载的 GPT-5.6 层级，只替换模型 ID，然后重新测试推理 effort、工具、延迟和成本。在评估通过之前，保留之前的 GPT-5 模型作为回退。

## 选择层级

| 模型 | 适用于 | 推理 effort |
| --- | --- | --- |
| `openai/gpt-5.6-sol` | 能力最强的推理、智能体编码、科学分析和复杂的专业工作 | `none`、`low`、`medium`、`high`、`xhigh`、`max` |
| `openai/gpt-5.6-terra` | 均衡的日常推理、编码和助手工作 | `none`、`low`、`medium`、`high`、`xhigh`、`max` |
| `openai/gpt-5.6-luna` | 延迟更低、对成本敏感的工作 | `none`、`low`、`medium`、`high`、`xhigh`、`max` |

三者的上下文窗口都是 1,050,000 token，输出上限为 128K token。每个层级还有一个 Pro ID（`openai/gpt-5.6-sol-pro`、`-terra-pro`、`-luna-pro`），它会替你发送 `reasoning.mode: "pro"`。

OpenAI 自己的 `gpt-5.6` 别名指向 `gpt-5.6-sol`；在 Phaseo 上，请直接调用各层级的 ID。层级别名 `openai/gpt-sol-latest`、`openai/gpt-terra-latest` 和 `openai/gpt-luna-latest` 会跟随各层级的最新模型，而 `openai/gpt-sol-latest` 已经指向比 GPT-5.6 更新的模型。只有在你希望未来版本自动前滚时才使用它们。

## 更新请求

GPT-5.6 在每个层级都新增了最高推理预算 `max`。只在额外的延迟和成本值得时使用它。

<CodeGroup>
```json Responses
{
  "model": "openai/gpt-5.6-sol",
  "input": "Review this multi-service incident report and propose a rollback plan.",
  "reasoning": { "effort": "max" }
}
```

```json Chat Completions
{
  "model": "openai/gpt-5.6-terra",
  "messages": [
    { "role": "user", "content": "Design a test plan for this agent workflow." }
  ],
  "reasoning_effort": "medium"
}
```
</CodeGroup>

GPT-5.6 还新增了：

- **`reasoning.mode: "pro"`**，用于更难的任务，无需更换模型；
- **`reasoning.context`**（`auto`、`current_turn` 或 `all_turns`），用于控制保留哪些推理内容；
- 面向大量使用工具的工作流的 beta 多智能体支持和 Programmatic Tool Calling；
- 通过 `prompt_cache_options` 和缓存断点实现的显式提示词缓存。在 GPT-5.6 上，`prompt_cache_options.ttl` 取代了 `prompt_cache_retention`，Phaseo 不会把后者发送给 GPT-5.6 模型。

## 查看价格

OpenAI 标准层级的每 1M token 价格，适用于输入不超过 272K token 的请求：

| 模型 | 输入 | 缓存读取 | 缓存写入（30 分钟） | 缓存写入（12 小时） | 输出 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Sol | $5.00 | $0.50 | $6.25 | $12.50 | $30.00 |
| Terra | $2.00 | $0.20 | $2.50 | $5.00 | $12.00 |
| Luna | $0.20 | $0.02 | $0.25 | $0.50 | $1.20 |

输入超过 272K token 的请求价格更高：Sol 输入 $10.00、输出 $45.00，Terra 为 $4.00 和 $18.00，Luna 为 $0.40 和 $1.80，缓存价格按相同比例调整。在 2026 年 11 月 30 日之前，适用 OpenAI 的 Sol 促销价：272K token 以内输入 $4.00、输出 $20.00。其他层级和提供商的当前价格请查看模型页面。

缓存读取按输入价格的 10% 计费，30 分钟写入按 1.25 倍，12 小时写入按 2.5 倍。每个输入 token 只按其中一种价格计费。用量把缓存读取和写入计入 `input_tokens`（在 Chat Completions 上为 `prompt_tokens`），并在 `cache_write_tokens` 中报告写入；参见[用量和价格字段](../guides/prompt-caching.mdx#usage-and-pricing-fields)。

## 缓存重复的上下文

把提示词中稳定的部分放进可缓存的块，并把请求特有的文本放在它后面：

```json
{
  "model": "openai/gpt-5.6-sol",
  "input": [
    {
      "role": "user",
      "content": [
        {
          "type": "input_text",
          "text": "Stable policy document...",
          "prompt_cache_breakpoint": { "mode": "explicit" }
        },
        {
          "type": "input_text",
          "text": "Apply the policy to this new customer request."
        }
      ]
    }
  ],
  "prompt_cache_options": { "mode": "explicit", "ttl": "30m" }
}
```

- `prompt_cache_breakpoint` 会缓存到其所在块为止（含该块）的全部内容。在 `explicit` 模式下，OpenAI 只缓存你设置的断点。
- 块级 `cache_control`（例如 `{"type": "ephemeral"}`）同样有效；Phaseo 会把它作为 `prompt_cache_breakpoint` 发送给 GPT-5.6。两种标记都会作为缓存断点传给 Claude，因此回退到 Claude 时仍然会缓存。
- `ttl` 为 `30m`（默认）或 `12h`。哪些路由接受它，请参见 [OpenAI 上的 12 小时缓存](../guides/prompt-caching.mdx#12-hour-cache-on-openai)；其他字段请参见 [OpenAI 保留时长和选项](../guides/prompt-caching.mdx#openai-retention-and-options)。

## 要测试的内容

- **推理和输出质量：** 每个层级在你将开放的 effort 级别下的表现，包括质量优先场景下的 `max`；困难任务上标准模式与 `reasoning.mode: "pro"` 的对比；各级别下的 schema 通过率和工具调用质量。
- **成本和延迟：** 各 effort 下的延迟、相对当前基线的输出 token 增长、重复提示词的缓存读写比例，以及每个成功任务的成本，而不是每 token 价格。

## 上线

1. 保留之前的 GPT-5 模型作为 `models` 中的回退。
2. 在 `max` 于类似生产的提示词上得到验证之前，把它放在配置开关或[预设](../guides/presets)之后。
3. 把缓存写入量与缓存读取分开监控。
4. 只有在评估确认了任务成功率、成本和延迟之后，才把 GPT-5.6 设为默认模型。
