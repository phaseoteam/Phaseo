把模型改为 `mistral/mistral-small-4`，并按路由决定是否开启推理。Mistral Small 4 有两种推理模式：关闭和 high，Phaseo 会把每个 effort 值映射到其中之一。

```json
{
  "model": "mistral/mistral-small-4",
  "messages": [
    { "role": "user", "content": "Why is fast inference important?" }
  ],
  "reasoning": { "effort": "high" }
}
```

## 开启或关闭推理

除非请求要求，否则推理处于关闭状态。在 Mistral 自己的 API 上，Phaseo 按如下方式发送 `reasoning_effort`：

| 请求 | 发送给 Mistral 的内容 |
| --- | --- |
| 没有推理设置 | `reasoning_effort: "none"` |
| `reasoning.effort: "none"` 或 `reasoning.enabled: false` | `reasoning_effort: "none"` |
| 任何其他 `reasoning.effort`，或 `reasoning.enabled: true` | `reasoning_effort: "high"` |

请求中扁平的 `reasoning_effort` 优先于 `reasoning.effort`。轻量路由使用 `none`，深度推理使用 `high`；`low` 和 `medium` 的行为与 `high` 完全相同。

## 读取答案和推理内容

Mistral 可能返回混合的内容块，例如先是 `thinking` 再是 `text`。Phaseo 会把它们拆分为 OpenAI 风格的字段，因此读取 Chat Completions 的下游代码可以继续工作：

- 答案在 `choices[0].message.content` 中；
- 推理文本在 `choices[0].message.reasoning_content` 和 `reasoning_details` 中。

## 上线

1. 把模型 ID 从 Mistral Small 3.2 改为 `mistral/mistral-small-4`。
2. 只用 `none` 和 `high` 测试推理。
3. 在使用 `high` 的路由上重新运行输出质量和 schema 测试。
4. 全面切换之前，比较 `none` 和 `high` 的延迟和成本。
