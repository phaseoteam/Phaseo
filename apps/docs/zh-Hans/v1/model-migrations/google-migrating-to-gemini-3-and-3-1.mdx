用 `reasoning.effort` 设定推理深度，Phaseo 会把它作为 `thinking_level` 发送给 Gemini 3；并把 assistant 的工具调用轮次按 Phaseo 返回的原样发回，以保留思维签名。把 Gemini 3 和 Gemini 3.1 Pro 当作两次独立的迁移。

| Phaseo 模型 ID | 状态 |
| --- | --- |
| `google/gemini-3.1-pro-preview` | 可用 |
| `google/gemini-3-flash-preview` | 可用 |
| `google/gemini-3.1-flash-lite` | 已弃用；2027 年 5 月 7 日停用 |
| `google/gemini-3-pro-preview` | 已于 2026 年 3 月 9 日停用；请求会路由到 `google/gemini-3.1-pro-preview` |
| `google/gemini-3.1-flash-lite-preview` | 已于 2026 年 5 月 25 日停用；请求会路由到 `google/gemini-3.1-flash-lite` |

已停用的 ID 只能通过自动替换继续使用；参见[模型弃用和停用](../guides/model-retirement)。请直接调用当前的 ID。

## 设定推理深度

Gemini 3 用 `thinking_level` 取代了思考预算。Phaseo 会把 `reasoning.effort`（或扁平的 `reasoning_effort`）映射到它：

| `reasoning.effort` | Gemini 3 Flash | Gemini 3.1 Pro |
| --- | --- | --- |
| `minimal` | `MINIMAL` | `LOW`（3.1 Pro 没有 `MINIMAL`） |
| `low` | `LOW` | `LOW` |
| `medium` | `MEDIUM` | `MEDIUM` |
| `high`、`xhigh`、`max` | `HIGH` | `HIGH` |

```json
{
  "model": "google/gemini-3.1-pro-preview",
  "messages": [{ "role": "user", "content": "Compare these three architecture options." }],
  "reasoning": { "effort": "medium" }
}
```

这些级别与其他提供商的 effort 设置并不一一对应，因此请在你开放的每个级别上重新测试延迟和质量。

## 保留思维签名

Gemini 3 会返回在多次调用之间传递推理上下文的思维签名；在函数调用中，缺少签名可能会降低质量或返回 `400`。把每个 assistant 轮次（包括其工具调用）按 Phaseo 返回的原样发回。Phaseo 会把签名重放给生成它的模型；如果签名缺失或来自另一个模型，Phaseo 会发送 Google 的跳过占位符，让请求不会失败。

## 重新审视提示词和媒体

Google 对 Gemini 3 的指南倾向于直接的提示词和由参数驱动的控制，而不是冗长的提示词脚手架。如果你的提示词是为弥补旧模型的行为而写的，请简化它们并重新评估。

Gemini 3 还为图像和文档新增了 `media_resolution`。Phaseo 没有开放它，因此适用 Google 的默认值；请重新测试图像、文档和混合媒体路由，而不是假定旧的结果依然成立。

## 要测试的内容

- **推理：** 简洁提示词与带脚手架的提示词、分步骤任务、长上下文综合，以及依赖推理连续性的智能体工作流。
- **响应：** 跨轮次的签名、函数调用成功率、schema 通过率，以及更改 effort 后出现的空输出、不完整输出或格式错误的输出。
- **生产指标：** 各级别的延迟、token 用量和成本、多模态路由，以及 Gemini 3 与 Gemini 3.1 Pro 的任务成功率。

## 上线

1. 先迁移请求结构和签名处理。
2. 在 Gemini 3 上重新运行提示词和 schema 评估。
3. 为需要更深推理的路由单独推广 Gemini 3.1 Pro。
4. 为高调用量的工作负载保留一个更便宜的回退。
