把模型改为 `anthropic/claude-opus-4.6`，删除 assistant 预填充，并把结构化输出移到 `output_config.format`。这些都是请求结构的变更：如果保留旧的 Opus 4.5 写法，请求会以 `400` 失败。

| | Claude Opus 4.5 | Claude Opus 4.6 |
| --- | --- | --- |
| Phaseo 模型 ID | `anthropic/claude-opus-4.5` | `anthropic/claude-opus-4.6` |
| 上下文窗口 | 200K token | 1M token |
| 最大输出 | 64K token | 128K token |
| Assistant 预填充 | 支持 | 返回 `400` |
| 结构化输出 | `output_format` | `output_config.format` |
| 思考 | `budget_tokens` | 自适应，由 `output_config.effort` 调节 |
| `interleaved-thinking-2025-05-14` beta | 需要 | 不需要 |

## 更新请求

**1. 删除 assistant 预填充。** 如果你预先填充 assistant 轮次来强制输出 JSON 或某个前缀，Opus 4.6 会返回 `400`。请改用更清晰的系统指令、提示词中的示例或结构化输出。

**2. 把结构化输出**从 `output_format` 移到 `output_config.format`，并重新运行 schema 和解析器测试：

```json
{
  "model": "anthropic/claude-opus-4.6",
  "max_tokens": 1024,
  "messages": [{ "role": "user", "content": "Extract the invoice fields." }],
  "output_config": {
    "format": { "type": "json_schema", "schema": { "type": "object", "properties": { "total": { "type": "number" } } } }
  }
}
```

在 `/v1/chat/completions` 和 `/v1/responses` 上，继续使用 `response_format`。

**3. 把思考切换为自适应。** 除非请求要求，否则 Opus 4.6 不会思考。在 Phaseo 上，`reasoning.effort` 或不带 token 预算的 `reasoning.enabled: true` 会开启自适应思考，effort 会转为 `output_config.effort`。Opus 4.6 接受除 `xhigh` 以外的所有 effort 级别，Phaseo 会把 `xhigh` 作为 `max` 发送。思考开启时，Phaseo 会省略 `temperature` 和 `top_k`，以及低于 0.95 的 `top_p`。

**4. 从 SDK 封装、中间件和预设中删除过时的 beta 请求头。** Phaseo 不会转发 `anthropic-beta` 请求头，因此它们不再起任何作用。

## 要测试的内容

- **提示词：** 长的编码和重构提示词、多步骤研究和文档工作流、依赖预填充的提示词，以及（如果你会用到 1M 窗口）长上下文任务。
- **契约和工具：** 迁移到 `output_config.format` 后的 schema 通过率、多步骤智能体任务中的工具调用参数、模型拒绝或重新格式化输出时的重试，以及代码审查和调试工作流。
- **运营：** 开启思考时的中位数和 p95 延迟、较长运行中的 token 用量、大上下文任务的超时率，以及在你的评估集上相对 Opus 4.5 的成功率。

## 上线

1. 迁移任何流量之前，先删除预填充并迁移结构化输出。
2. 在对你重要的生产提示词上影子运行 Opus 4.6。
3. 金丝雀发布，把 Opus 4.5 作为 `models` 中的回退。
4. 当 schema 通过率、延迟和任务完成率保持稳定时再全面推广。
