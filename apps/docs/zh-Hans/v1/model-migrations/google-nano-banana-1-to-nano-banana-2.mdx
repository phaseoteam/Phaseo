把图像请求切换到 `google/gemini-3.1-flash-image`（Nano Banana 2），并用 `image_config` 选择宽高比和输出尺寸。最先出问题的，往往是假定只有一种图像尺寸的下游代码。

| | Nano Banana | Nano Banana 2 |
| --- | --- | --- |
| Phaseo 模型 ID | `google/gemini-2.5-flash-image` | `google/gemini-3.1-flash-image` |
| 状态 | 已弃用；2027 年 3 月 15 日停用 | 可用 |

Nano Banana 2 新增了对宽高比（`image_config.aspect_ratio`，例如 `16:9` 或 `9:16`）和输出尺寸（从 512px 到 4K，`image_config.image_size`：`0.5K`、`1K`、`2K` 或 `4K`）的显式控制。Google 还表示，它在多次生成和编辑之间的主体一致性更好，指令遵循更强，图像内文字的渲染和翻译更好，并且在相近速度下保真度更高。它的后继模型 `google/gemini-nano-banana-2.1` 也已可用。

```json
{
  "model": "google/gemini-3.1-flash-image",
  "messages": [{ "role": "user", "content": "A product photo of a ceramic mug on a walnut desk." }],
  "modalities": ["image", "text"],
  "image_config": { "aspect_ratio": "16:9", "image_size": "2K" }
}
```

不支持 `image_config` 的提供商会丢弃它，并在 `X-Phaseo-Dropped-Params` 响应头中列出；参见[参数](../api-reference/parameters)。

## 更新你的产品

1. **检查对输出的假设。** 如果下游代码预期固定的尺寸、宽高比或裁剪方式，请先更新它。
2. **重新审视预设：** 社交平台的宽高比、默认尺寸、编辑和局部重绘工作流，以及描述图像尺寸的 UI 标签。
3. **缩短编辑提示词。** 为弥补旧模型而对构图、文字或风格过度规定的提示词，现在可能显得过于死板。请重新测试更短的版本。

## 要测试的内容

- **输出质量：** 竖屏、方形和宽屏比例；小尺寸与大尺寸；多次编辑之间的主体一致性；图像中的文字、标识、说明文字和翻译后的文字。
- **工作流：** 大尺寸下的文件处理、高保真生成的超时、内容审核或人工审核的通过率，以及下游的尺寸调整。
- **产品指标：** 端到端延迟、可用输出率、重试率，以及每个获批素材的成本。

## 上线

1. 按宽高比和尺寸分别测试，而不是当作一次迁移。
2. 在你将支持的最大尺寸下验证素材处理流程。
3. 抽样真实的生产提示词，尤其是编辑请求和图中带文字的请求。
4. 如果你的 UI 开放了图像选项，请把默认预设的变更与模型切换分开发布。
