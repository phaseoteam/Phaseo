把模型改为 `openai/gpt-5.4`，保留请求的其余部分，并按路由选择推理 effort。请求结构与早期 GPT-5 模型相同；变化在于 effort 范围、图像细节和 computer 工具。OpenAI 的文档没有描述 GPT-5.4 专用的 `phase` 参数。

| 变化 | 你需要做的 |
| --- | --- |
| `reasoning.effort` 接受 `none`、`low`、`medium`、`high` 和 `xhigh` | 在符合各路由延迟预算的 effort 下重新测试每个路由。 |
| 图像输入 `detail: "original"`，用于全保真感知 | 单独测试：它会改变质量和成本。 |
| 更新后的 `computer` 工具是计算机使用的途径 | 把浏览器和桌面自动化迁移到它，并端到端重新测试。 |
| 更好的长周期工具使用、大上下文工作和文档工作流 | 重新运行你的智能体和文档评估。 |

```json
{
  "model": "openai/gpt-5.4",
  "input": "Summarize the open risks in this design review.",
  "reasoning": { "effort": "medium" }
}
```

## 选择推理 effort

如果你是从 GPT-4.1 或更早的 GPT-5 模型迁移过来，不要假定之前的默认值仍然合适：

| 路由 | 起始值 |
| --- | --- |
| 低延迟 | `none` 或 `low` |
| 大多数结构化任务 | `medium` 或 `high` |
| 深度推理和智能体工作流 | `xhigh` |

## 以完整细节发送图像

对于密集的截图、文档或 UI 本地化，请在图像输入上设置 `detail: "original"`。Phaseo 会把它传给支持它的提供商（包括 OpenAI 和 Azure），对不支持的提供商则发送最接近的级别 `high`。

## 把计算机使用迁移到 `computer` 工具

把浏览器和桌面自动化更新为 `computer` 工具，并在完整任务上重新测试步骤完成情况。托管工具只会路由到运行它们的提供商。

## 要测试的内容

- **提示词：** 长系统提示词、提取和分类、对格式敏感的输出，以及之前需要重试才能不跑题的提示词。
- **工具和结构化输出：** 各 effort 级别下的 schema 遵循情况、工具选择、参数完整性，以及多步骤计算机使用的稳定性。
- **视觉和运营：** `high` 与 `original` 细节下的截图和文档、负载下的延迟和 token 用量、重试和超时率，以及相对被替换模型的每个成功任务成本。

## 上线

1. 在你将使用的具体 effort 级别上对 GPT-5.4 做基准测试。
2. 在切换默认路由之前，先影子运行生产提示词。
3. 逐步推广，把较旧的 OpenAI 模型或其他提供商作为 `models` 中的回退。
