为整个工作区或某个预设一次性开启[响应修复](./response-healing-for-structured-json)，而不必在每个请求中开启。完成后，每个使用结构化输出的调用方都会采用相同的修复策略，你还可以锁定它，让任何预设或请求都无法将其关闭。

这是一个仪表板操作流程；末尾的请求示例可直接用于生产环境。

## 各层如何组合

Phaseo 从三层构建每个请求的插件列表。对于同一个插件，后面的层会替换前面层的设置，除非前面的层已被锁定：

```mermaid
flowchart LR
  ws["工作区默认值"] --> pr["预设插件"]
  pr --> rq["请求插件"]
  rq --> eff["实际运行的插件"]
  lock["工作区锁定已开启"] -.->|"后面的层无法更改 response-healing"| pr
```

| 层 | 设置位置 | 覆盖 |
| --- | --- | --- |
| 工作区 | **设置 → 路由 → 响应修复** | 无 |
| 预设 | **设置 → 预设 →（预设）→ 响应修复** | 工作区设置，除非已锁定 |
| 请求 | 请求体中的 `plugins` | 预设和工作区设置，除非工作区已锁定 |

## 进行设置

<Steps>
<Step title="开启工作区默认值">

在**设置 → 路由 → 响应修复**中，开启**默认启用**并选择一种**修复模式**：`safe` 用于有限度的语法修复，`strict` 只解包本来就有效的 JSON。工作区内所有 API 密钥共享的通用默认值就在这里设置。

</Step>
<Step title="如果不容更改，就锁定它">

开启**锁定工作区策略**。之后预设和请求既不能关闭修复，也不能更改其模式。日志仍会显示它是已应用还是已跳过。

</Step>
<Step title="为某个工作流设置预设默认值">

当某一类请求需要同时带上结构化输出格式和修复时，在预设编辑器中开启**响应修复**并选择其模式。之后该预设的调用方只需发送输入。

</Step>
</Steps>

## 为单个请求覆盖设置

当工作区未锁定时，请求可以自行设置该插件。`"enabled": false` 会为该请求关闭它：

```json
{
  "model": "openai/gpt-6-astra",
  "input": "Return the summary as JSON.",
  "text": {
    "format": {
      "type": "json_schema",
      "name": "answer",
      "schema": {
        "type": "object",
        "properties": { "summary": { "type": "string" } },
        "required": ["summary"],
        "additionalProperties": false
      }
    }
  },
  "plugins": [{ "id": "response-healing", "enabled": true, "mode": "strict" }],
  "meta": true
}
```

## 查看实际运行的策略

在**设置 → 用量 → 日志**中打开该请求；如果你发送了 `meta: true`，也可以读取 `meta.plugin_executions`。其中显示状态（`applied`、`skipped` 或 `failed`）、实际运行的模式，以及修复后的候选结果不符合 schema 时的 `validation_errors`。

如果两个服务的表现不同，在把它当作模型问题之前，先比较工作区设置及其锁定状态、预设的插件，以及每个请求的 `plugins`。
