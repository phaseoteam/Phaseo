为一个 TypeScript 请求提供 `phaseo:web_search` 工具和 JSON Schema，让模型先搜索再回答，并返回附带来源的简报。完成后，你会得到一个脚本，它打印经过验证的 `{ summary, sources }` 对象，以及调试所需的 ID 和搜索计数。

把预设和域名换成你自己的之后，该脚本即可用于生产环境。搜索结果是不可信的网页内容：请验证输出，不要执行其中出现的指令。

## 构建

<Steps>
<Step title="创建预设">

在**设置 → 预设**中创建 `research-brief`，包含所有调用方应共享的模型、提供商偏好、推理设置和系统提示。模型必须支持工具和 JSON Schema 输出。

</Step>
<Step title="安装 SDK">

```bash
npm install @phaseo/sdk zod
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="编写脚本">

```ts research-brief.ts
import Phaseo from "@phaseo/sdk";
import { z } from "zod";

const gateway = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const Brief = z
  .object({
    summary: z.string().min(1),
    sources: z
      .array(z.object({ title: z.string(), url: z.string().url() }).strict())
      .min(1),
  })
  .strict();

const response = await gateway.generateResponse({
  model: "@research-brief",
  input: "Find the latest public changes to Phaseo webhook delivery behavior and summarize them.",
  tools: [
    {
      type: "phaseo:web_search",
      parameters: {
        allowed_domains: ["phaseo.app"],
        max_results: 5,
        include_highlights: true,
      },
    },
  ],
  tool_choice: "phaseo:web_search",
  text: {
    format: {
      type: "json_schema",
      name: "research_brief",
      strict: true,
      schema: {
        type: "object",
        required: ["summary", "sources"],
        properties: {
          summary: { type: "string" },
          sources: {
            type: "array",
            minItems: 1,
            items: {
              type: "object",
              required: ["title", "url"],
              properties: {
                title: { type: "string" },
                url: { type: "string", format: "uri" },
              },
              additionalProperties: false,
            },
          },
        },
        additionalProperties: false,
      },
    },
  },
  plugins: [{ id: "response-healing" }],
  meta: true,
});

const text = (response.output ?? [])
  .filter((item) => item.type === "message")
  .flatMap((item) => item.content ?? [])
  .filter((part) => part.type === "output_text")
  .map((part) => part.text ?? "")
  .join("");

const brief = Brief.parse(JSON.parse(text));

console.log({
  responseId: response.id,
  model: response.model,
  routing: response.meta?.routing,
  pluginExecutions: response.meta?.plugin_executions,
  serverToolUse: response.usage?.server_tool_use,
});
console.log(brief);
```

| 字段 | 作用 |
| --- | --- |
| 带 `phaseo:web_search` 的 `tools` | 由 Phaseo 执行搜索，无论提供商是否有自己的搜索。查询由模型编写。 |
| `allowed_domains` | 把结果限制在你自己的来源中。所有参数都在[网页搜索指南](../guides/server-tools/web-search#parameters)中。 |
| `tool_choice: "phaseo:web_search"` | 让模型去搜索，而不是凭记忆回答。 |
| `text.format` | 回答的 JSON Schema。 |
| `plugins` | 修复接近有效的 JSON；参见[响应修复](./response-healing-for-structured-json)。 |
| `meta: true` | 添加 `meta.routing` 和 `meta.plugin_executions`。 |

</Step>
<Step title="运行">

```bash
npx tsx research-brief.ts
```

</Step>
</Steps>

## 检查是否成功

- `serverToolUse.web_search_requests` 至少为 `1`，说明搜索已运行。
- `brief.sources` 列出 `phaseo.app` 的 URL。
- `routing.selected_provider` 给出提供商，`pluginExecutions` 显示修复是否改动了内容。
- 在**设置 → 用量 → 日志**中，该请求的**网络搜索可观测性**部分会显示托管搜索、结果和引用。

如果结果看起来不对，请根据日志显示的情况修改预设或工具参数，而不是添加覆盖。[调试网页搜索](./web-search-debugging)列出了常见情况。把探索性、temperature 较高的研究放在另一个预设中，与这个确定性的预设分开，这样两者的路由就容易比较。
