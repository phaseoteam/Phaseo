<Warning>
响应缓存尚未推出。预设接受 `response_caching.enabled` 和 `response_caching.ttl_seconds`，但 Gateway 目前不会存储或重放任何响应，因此每个请求都会发送到提供商并正常计费。
</Warning>

要立即降低重复请求的成本和延迟，请使用[提示缓存](../guides/prompt-caching)：提供商会复用较长且稳定的提示前缀，并以较低的费率对缓存部分计费。Phaseo 会让对话留在持有其缓存的提供商上；参见[提供商亲和性](../guides/prompt-caching#provider-affinity)。

## 为缓存准备预设

这些习惯现在有助于提示缓存，将来响应缓存上线时也同样重要，因为两者都依赖请求保持一致：

| 保持稳定 | 原因 |
| --- | --- |
| 系统提示的措辞 | 任何改动都会产生新的缓存条目 |
| 模型、提供商选项和推理设置 | 决定两个请求是否相同的因素之一 |
| `temperature` 和其他参数 | 同上 |
| 响应格式、工具和工具选择 | 同上 |

把这些设置放进同一个[预设](../guides/presets)，让每个调用方都发送相同的请求；为探索性或高 temperature 的调用方单独设置预设，避免它们与可缓存的流量混在一起。

## 何时不该缓存

不要打算缓存以下内容：依赖实时外部状态的提示、上下文变化很快的用户特定回答、工具输出易变的请求，或你希望每次都得到新回答的生成。
