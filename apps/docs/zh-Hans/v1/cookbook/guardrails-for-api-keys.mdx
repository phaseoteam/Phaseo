---
title: "在 API 密钥上推行护栏"
icon: "shield-check"
description: "将护栏应用到 API 密钥，在推行前测试其执行效果，并通过活动视图核实拦截、脱敏和标记。"
---

在**设置 → 护栏**中创建一个护栏，把它挂到一个低风险的 API 密钥上，等日志显示它运行正常后再扩大范围。完成后，该密钥只能访问你允许的提供商和模型，并且它的提示在到达模型之前会被扫描，检查提示词注入和敏感数据。

这是一个仪表板操作流程；同样的策略也可以通过[护栏 API](../api-reference/endpoint/guardrails-create) 用脚本完成。

```mermaid
flowchart LR
  ws["工作区隐私规则"] --> gr["护栏：数据处理"]
  gr --> prov["提供商允许或屏蔽列表"]
  prov --> mdl["模型允许列表"]
  mdl --> scan["提示词注入和敏感信息扫描"]
  scan -->|"标记、脱敏或拦截"| route["路由请求"]
```

工作区隐私规则最先生效；护栏只能在其基础上进一步收紧。护栏不限制支出：请改为在密钥上设置上限，或设置[工作区预算](../api-reference/limits#key-limits-and-budgets)。

## 推行步骤

<Steps>
<Step title="创建护栏">

打开**设置 → 护栏 → 新护栏**。按它执行的规则命名，例如 `eu-models-pii-redact`，而不是按团队命名，这样它就能在多个密钥之间复用。

先设置路由访问，再设置内容检查：

| 设置 | 选项 |
| --- | --- |
| **提供商模式** | 允许所有提供商、仅允许选定的提供商，或允许除选定提供商之外的所有提供商 |
| **模型模式** | 允许所有模型，或仅允许选定的模型（在提供商筛选之后应用） |
| **数据处理** | 仅 ZDR，以及可能使用输入进行训练的免费或付费端点是否仍然可用 |

常见的第一个策略是屏蔽低可信度的提供商，并只允许该密钥应当访问的那些确切的生产模型。用预览检查哪些提供商和模型仍可路由，以及**仅允许**是否比你预想的更窄。

</Step>
<Step title="添加内容检查">

**提示词注入**会扫描用户提供的内容，查找常见的注入模式。**敏感信息**会在请求离开 Phaseo 之前检测数据：

| 检测器 | 脱敏为 | 是否增加延迟 |
| --- | --- | --- |
| 电子邮件地址 | `[EMAIL]` | 否 |
| 电话号码 | `[PHONE]` | 否 |
| 美国社会安全号码 | `[SSN]` | 否 |
| 信用卡号 | `[CREDIT_CARD]` | 否 |
| IP 地址（IPv4） | `[IP_ADDRESS]` | 否 |
| 人名 | `[PERSON_NAME]` | 是 |
| 实际地址 | `[ADDRESS]` | 是 |

每项检查都有一个操作：**标记**、**脱敏**或**拦截**。提示词注入先从**标记**或**脱敏**开始，在审查过误报之后再改为**拦截**。先使用快速检测器。自定义模式以显式正则规则添加。

</Step>
<Step title="在预览中测试">

保存之前，在预览中运行三个输入：一个无害的、一个显然应被拦下的，以及一个真实的生产提示。检查脱敏文本、拦截或放行结果，并确认没有误匹配无关内容。

</Step>
<Step title="挂到一个密钥上">

在**应用于密钥**下，选择一个预发布或低风险的密钥。你可以在创建护栏时就挂上它。**应用于成员**则会对这些成员创建的 API 密钥强制执行该护栏。成员无法编辑或移除由工作区所有者或管理员分配的护栏。

</Step>
<Step title="检查执行情况">

通过该密钥发送真实请求，然后检查：

- **设置 → 用量 → 护栏**，查看被拦截、脱敏和标记的数量。
- **设置 → 用量 → 日志**中某个请求的**护栏执行**部分，查看触发的护栏和检测器。
- **设置 → API 密钥**中的**护栏**列，确认它挂在了哪些密钥上。

</Step>
<Step title="扩大推行范围">

把同一个护栏挂到更多密钥上，把操作从**标记**收紧为**脱敏**或**拦截**，并且只在延迟可以接受的地方添加人名和地址检测器。

</Step>
</Steps>

已关闭的护栏会保留配置，但不会被执行。如果想在调用方之间共享路由规则，而不是在密钥上强制执行，请使用[预设](../guides/presets)。
