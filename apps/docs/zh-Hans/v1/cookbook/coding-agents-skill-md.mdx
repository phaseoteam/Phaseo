---
title: "使用 SKILL.md 设置编程智能体"
icon: "file-code"
description: "将 SDK 与 SKILL.md 文件搭配使用，让本地编程智能体以一致的方式使用你的 Phaseo 集成。"
---

在仓库中添加一个 `SKILL.md`，让编程智能体按项目期望的方式调用 Phaseo：相同的基础 URL、密钥变量、端点、批准的模型和日志记录。完成后，你会安装好公开的 Phaseo 技能，在其之上有一个项目技能，以及一个该技能指向的共享客户端模块。

把下面的模型 ID 和预设名称换成你自己的之后，这个技能和模块即可用于生产环境。

<Steps>
<Step title="安装公开的 Phaseo 技能">

<Visibility for="humans">
公开技能涵盖 Gateway、SDK、预设、路由和迁移。从 [`phaseo.app/docs`](https://phaseo.app/docs/.well-known/agent-skills/index.json) 安装它们：
</Visibility>

<Visibility for="agents">
在编写项目本地说明之前，先从 [`phaseo.app/docs`](https://phaseo.app/docs/.well-known/agent-skills/index.json) 安装公开的 Phaseo 技能：
</Visibility>

```bash
npx skills add https://phaseo.app/docs --agent codex --skill '*'
```

把 `--agent` 改成你的团队使用的智能体。你自己的 `SKILL.md` 中只保留项目特有的规则。

</Step>
<Step title="安装 SDK">

<CodeGroup>
```bash npm
npm install @phaseo/sdk
```

```bash pnpm
pnpm add @phaseo/sdk
```

```bash yarn
yarn add @phaseo/sdk
```

```bash bun
bun add @phaseo/sdk
```

```bash Python
pip install phaseo
```
</CodeGroup>

</Step>
<Step title="添加一个共享客户端">

相比庞大的封装，智能体更能稳定地复用一个小而直观的辅助模块。把客户端放在一个模块里，并在各处导入它：

```ts src/lib/phaseo.ts
import Phaseo from "@phaseo/sdk";

export const gateway = new Phaseo({
  apiKey: process.env.PHASEO_API_KEY!,
});
```

你使用的每个接口（例如文本生成、embeddings、图像生成或异步视频）只保留一条调用路径。

</Step>
<Step title="编写项目技能">

在仓库根目录或你的智能体读取的技能文件夹中创建 `SKILL.md`（例如 `.agents/skills/phaseo-project/SKILL.md`）。智能体通过 frontmatter 中的 `name` 和 `description` 来决定何时加载该技能：

```md SKILL.md
---
name: phaseo-project
description: "How this repository calls Phaseo Gateway: client module, endpoint, approved models and presets, logging and async jobs. Use when adding or changing any Phaseo call in this repo."
---

# Phaseo in this repository

- Import the client from `src/lib/phaseo.ts`. Never create another one.
- The base URL is `https://api.phaseo.app/v1`. The key is in `PHASEO_API_KEY`; never hard-code it or send it to the browser.
- Use the Responses API (`POST /v1/responses`) for new text features.
- Approved models: `openai/gpt-6-astra` for drafts, `anthropic/claude-sonnet-5.5` for reviews. Ask before adding another.
- Prefer the `@support-triage` preset for support features; pass it as `model`.
- Log the response `id` and `model` on every call, and `generation_id` from error bodies.
- For async video jobs, store the returned ID and poll status until it is terminal.
- Validate any model-generated tool arguments before acting on them.
```

</Step>
</Steps>

## 检查是否成功

让你的智能体添加一个小的 Phaseo 功能，例如“用 Phaseo 总结一个工单”。改动应当导入 `src/lib/phaseo.ts`、读取 `PHASEO_API_KEY`、使用批准的模型或预设，并记录响应 ID。如果没有做到，可能是技能的 `description` 与请求不匹配：请写上你的团队常用的任务用词。

## 技能里该写什么

只回答最耗费智能体时间的问题，其他一概不写：

| 问题 | 示例回答 |
| --- | --- |
| 使用哪类端点？ | 文本用 Responses，搜索用 Embeddings |
| 凭据在哪里？ | `PHASEO_API_KEY`，仅限服务器端 |
| 批准了哪些模型 ID 或预设？ | 一个简短列表，采用 `org/model` 格式 |
| 记录哪些日志？ | 响应的 `id`、`model`，出错时记录 `generation_id` |
| 如何跟踪异步任务？ | 保存 ID，轮询直到进入终态 |

[Codex](../guides/integrations/codex)、[Vercel AI SDK](../guides/integrations/ai-sdk) 和[示例](../guides/examples)展示了这些约定在各个工具中的用法。
