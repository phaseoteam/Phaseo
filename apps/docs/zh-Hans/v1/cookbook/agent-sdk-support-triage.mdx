构建一个 TypeScript 分类智能体，其模型、提示词和提供商规则来自控制台中的预设，因此代码只需处理工作流。完成后，它会返回严格的 JSON 分类决定，暂停需要人工处理的案例，以有限次数重试模型调用，并记录 Gateway 失败及查找它们所需的 ID。

一旦预设已创建，并且你像[持久化循环](./agent-sdk-durable-loop)中那样存储已暂停的运行，该脚本即可用于生产环境。打包好的版本位于 `packages/sdk/agent-sdk-ts/examples/support-triage-agent.ts`。

## 构建

<Steps>
<Step title="创建预设">

在 **设置 → 预设** 中创建 `support-triage`，包含路由模型、提供商偏好、支持系统提示词和稳定的解码参数。该模型必须支持 JSON Schema 输出。[预设](../guides/presets)介绍了预设如何与每个请求合并。

</Step>
<Step title="安装">

```bash
npm install @phaseo/agent-sdk zod
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="编写智能体">

```ts triage-agent.ts
import { z } from "zod";
import { AgentGatewayError, createAgent, createGatewayAgentClient } from "@phaseo/agent-sdk";

const SupportTriageDecision = z
  .object({
    queue: z.enum(["billing", "reliability", "product", "security"]),
    severity: z.enum(["low", "medium", "high"]),
    needsHumanReview: z.boolean(),
    summary: z.string().min(1),
  })
  .strict();
type SupportTriageDecision = z.infer<typeof SupportTriageDecision>;

// 在每个轮次中，`preset` 都会变成模型 `@support-triage`。
const supportTriageAgent = createAgent<string, SupportTriageDecision>({
  id: "support-triage-agent",
  preset: "support-triage",
  maxSteps: 3,
  parseOutput: (text) => JSON.parse(text),
  outputSchema: SupportTriageDecision,
  humanReview: ({ parsedOutput }) =>
    parsedOutput?.needsHumanReview
      ? { reason: "support_triage_review_required", payload: parsedOutput }
      : null,
});

const client = createGatewayAgentClient({
  clientOptions: { apiKey: process.env.PHASEO_API_KEY! },
  responseFormat: {
    type: "json_schema",
    name: "support_triage_decision",
    schema: {
      type: "object",
      properties: {
        queue: { type: "string", enum: ["billing", "reliability", "product", "security"] },
        severity: { type: "string", enum: ["low", "medium", "high"] },
        needsHumanReview: { type: "boolean" },
        summary: { type: "string" },
      },
      required: ["queue", "severity", "needsHumanReview", "summary"],
      additionalProperties: false,
    },
  },
  plugins: [{ id: "response-healing", mode: "strict" }],
});

try {
  const result = await supportTriageAgent.run({
    input: "Customer says webhook deliveries failed overnight and asks whether data was lost.",
    client,
    modelRetry: { maxRetries: 2, backoffMs: 250 },
    onEvent(event) {
      if (event.type === "model.retrying") console.log("retrying", event.attempt, event.error);
    },
  });

  if (result.run.status === "waiting_for_human") {
    // 保存 `result`，然后在客服人员审查后继续。
    console.log("Needs review:", result.run.pause?.payload);
  } else {
    console.log(result.output);
  }
} catch (error) {
  if (error instanceof AgentGatewayError) {
    console.error("Gateway request failed", {
      status: error.status,
      requestId: error.requestId,
      generationId: error.generationId,
      reason: error.reason,
      providerFailureDiagnostics: error.providerFailureDiagnostics,
      routingDiagnostics: error.routingDiagnostics,
    });
  }
  throw error;
}
```

</Step>
<Step title="运行">

```bash
npx tsx triage-agent.ts
```

</Step>
</Steps>

要完成一个已暂停的案例，请带上审查者的决定继续运行：

```ts
const continued = await supportTriageAgent.continueRun({
  run: storedResult,
  client,
  humanInput: "Approved. Finalize the triage decision.",
});
```

## 检查是否成功

运行一个常规工单和一个高风险工单，然后检查：

- 在 **设置 → 使用情况 → 日志** 中，请求的模型显示使用了该预设。
- 高风险案例停在 `waiting_for_human`，决定位于 `pause.payload` 中。
- 重试过的模型调用会作为 `modelAttempts` 记录在该步骤上，每次重试都会记录 `model.retrying`。
- 被拦截的请求会连同其 `requestId` 和 `reason` 一起记录，日志中的同一请求会显示原因。

## 让 Gateway 失败保持可见

不要在智能体回调中吞掉错误。在边界处捕获 `AgentGatewayError`，记录其 ID，然后重新抛出。运行失败后，其保存的状态会在 `run.errorDetails` 和 `steps[n].errorDetails` 中保留相同的详细信息，因此即使异常已经消失，之后的恢复任务也能读取它们。

这些失败来自 Gateway 策略，而不是智能体，因此应在日志中的请求里查找：

| 失败 | 显示位置 |
| --- | --- |
| 护栏拦截了请求 | 请求的 **护栏执行** 部分 |
| 预设允许的模型拒绝了该模型 | `validation_error`，关键字为 `preset_model_not_allowed` |
| 提供商凭据或启用状态导致没有可用提供商 | `providerFailureDiagnostics` 和 **路由可观测性** |
| 修复无法生成符合 schema 的 JSON | 插件记录，然后是 `outputSchema` 抛出的 `AgentSchemaValidationError` |
