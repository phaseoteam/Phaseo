把 Gateway 调用放在后端的一个服务之后，让密钥远离客户端和日志，只重试可以安全重试的请求，并按模型监控延迟、成本和错误。下面每一节都链接到包含详细内容的页面。

## 组织集成结构

- **把 Gateway 调用封装在一个服务或 SDK 客户端中**，这样更换模型或提供商时只需改动一处。参见[集成 Gateway](./integrating-with-the-gateway.mdx)。
- **向聊天界面流式传输响应**，让用户在 token 到达时就能看到。参见[流式传输](../guides/streaming.mdx)。
- **把不紧急的工作放入队列**，例如后台生成和评估，以平滑流量高峰。[Batch API](../guides/async-video-and-batch.mdx) 以异步方式运行大型任务。

## 保护密钥

- 在生产环境中，把 API 密钥存放在密钥管理器（AWS Secrets Manager、Doppler、1Password）中，而不是 `.env` 文件中。
- 从后端调用 Gateway，并让你自己的客户端应用向后端进行身份验证，这样客户端永远不会持有 Gateway 密钥。
- 只记录密钥的前缀，例如 `phaseo_v1_sk_<kid>`，绝不记录密钥本身。

参见[身份验证](./authentication.mdx)。

## 安全地重试

- 对 `429` 和 `5xx` 响应使用带抖动的指数退避重试。
- 重试受速率限制的请求之前，等待 [`Retry-After`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Retry-After) 指定的时间。
- 在请求日志中查看每个请求由哪个提供商处理，以便发现流量何时故障转移到另一个提供商。

参见[错误与调试](../api-reference/errors.mdx)和[速率限制](../api-reference/limits.mdx)。

## 关注正确的信号

| 信号 | 做法 |
| --- | --- |
| 延迟 | 跟踪 p95 和 p99，以发现性能退化。 |
| Token 用量 | 将成本与它所支撑的业务指标进行比较。 |
| 错误率 | 当失败率持续高于 1% 时发出告警。 |
| 提供商分布 | 检查流量是否按你的预期分配到各提供商。 |

参见[请求日志与可观测性](../guides/integrations/observability.mdx)。把提示模板、参数和输出处理方式记录在团队可以审阅的地方；[预设](../guides/presets.mdx)可以把共享的提示和默认值集中在一处。
