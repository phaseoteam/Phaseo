创建管理密钥后，你就可以从自己的服务器调用 Phaseo 的管理 API：额度、活动、工作区、密钥、预设、设置和护栏。管理密钥不能发送推理请求。

请在控制台的**设置 → 管理密钥**中创建。密钥只显示一次，请将其保存到你的密钥管理器中。只能从服务器端代码发送它，基础 URL 与 Gateway 相同（`https://api.phaseo.app/v1`）：

```http
Authorization: Bearer phaseo_v1_mk_<kid>_<secret>
```

## 管理密钥、API 密钥和 OAuth 令牌

| 凭证 | 格式 | 用途 | 受以下内容限制 |
| --- | --- | --- | --- |
| Gateway API 密钥 | `phaseo_v1_sk_<kid>_<secret>` | 模型和生成请求 | 路由策略、预算、限制和已关联的护栏 |
| 管理 API 密钥 | `phaseo_v1_mk_<kid>_<secret>` | 管理请求 | 密钥的能力和你的工作区角色 |
| OAuth 访问令牌 | | 代表用户执行管理操作 | 已批准的 OAuth 范围和该用户的工作区角色 |

管理路由只接受管理密钥（或 OAuth 令牌）；Gateway API 密钥无法调用它们。

[护栏](../cookbook/guardrails-for-api-keys.mdx)是另一种独立的控制：它们作用于 Gateway API 密钥，管控推理流量，例如路由限制、预算、提示注入处理和敏感信息规则。管理密钥的能力决定它可以调用哪些管理 API。

## 选择访问级别

创建密钥时，每个模板都会展开为一份明确的能力列表。Phaseo 从不存储 `all` 之类的通配符，因此密钥永远不会获得之后新增的权限。

| 模板 | `--template` | 授予 |
| --- | --- | --- |
| **Read** | `read-only` | 当前所有 `*:read` 能力 |
| **Write** | `read-write` | 当前所有 `*:read` 和 `*:write` 能力，不含删除 |
| **All** | `full-control` | 当前所有读取、写入和删除能力 |

所有模板都不包含 `billing:write`（用于发起额度充值）；需要时请通过 `--scopes` 明确申请。**All** 仅用于可信的管理自动化。

如需更小的授权，请用 `--scopes scope_a,scope_b` 传入你需要的能力：

| 领域 | 读取 | 写入 | 删除 |
| --- | --- | --- | --- |
| 身份和目录 | `me:read`、`models:read`、`providers:read`、`pricing:read` | | |
| 使用情况和可观测性 | `credits:read`、`activity:read`、`analytics:read`、`generations:read`、`feedback:read` | `feedback:write` | |
| 账单 | | `billing:write`（需主动启用） | |
| 工作区 | `workspaces:read` | `workspaces:write` | `workspaces:delete` |
| Gateway API 密钥 | `keys:read` | `keys:write` | `keys:delete` |
| 管理 API 密钥 | `management_keys:read` | `management_keys:write` | `management_keys:delete` |
| 预设 | `presets:read` | `presets:write` | `presets:delete` |
| 设置 | `settings:read` | `settings:write` | |
| 提供商凭证 | `provider_credentials:read` | `provider_credentials:write` | `provider_credentials:delete` |
| 私有模型 | `private_models:read` | `private_models:write` | `private_models:delete` |
| 护栏 | `guardrails:read` | `guardrails:write` | `guardrails:delete` |
| 预算 | `budgets:read` | `budgets:write` | `budgets:delete` |
| 速率限制 | `rate_limits:read` | `rate_limits:write` | `rate_limits:delete` |
| 分类器 | `classifiers:read` | `classifiers:write` | `classifiers:delete` |
| 支出规则 | `spend_rules:read` | `spend_rules:write` | `spend_rules:delete` |
| OAuth 客户端 | `oauth_clients:read` | `oauth_clients:write` | `oauth_clients:delete` |

## 能力不会覆盖工作区角色

每次调用时，Phaseo 都会检查两件事：密钥是否具有该能力，以及密钥或 OAuth 用户是否属于该工作区并拥有操作所需的角色。例如，`keys:write` 允许管理密钥，但仍由角色检查决定调用方能否管理该工作区中的密钥。密钥不能借助某项能力访问其他工作区，也不能跳过所有者和管理员检查。

## 保护好密钥

- 不要让管理密钥出现在浏览器、桌面日志、源代码管理或聊天中。
- 每个集成使用一个密钥，并选择能满足需求的最小权限模板。
- 如果集成不需要永久访问，请设置过期时间。
- 立即暂停或删除不再使用的密钥。
- 密钥泄露时，先轮换密钥，再进一步调查。
