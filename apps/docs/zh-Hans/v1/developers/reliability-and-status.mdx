查看[状态页](https://status.phaseo.app)和 `GET /v1/health` 可以了解 Phaseo 是否正常，`GET /v1/models` 可以了解模型现在是否可路由，而你自己的测试运行可以告诉你某条路由是否达到你的可靠性目标。

## 检查当前服务状态

1. 打开 [Phaseo 状态页](https://status.phaseo.app)，查看当前事故和历史事故。
2. 调用 `GET /v1/health` 执行最基本的 Gateway 健康检查。
3. 如果某个请求失败，请保留其 request ID，并先检查它的活动记录或生成记录，再判断是否整个服务都不可用。

```bash
curl https://api.phaseo.app/v1/health
```

```json
{
  "status": "ok"
}
```

<Note>
公共状态页报告的是服务健康状况。Phaseo 目前不承诺具有合同约束力的公共正常运行时间 SLA。
</Note>

## 确认模型是否可路由

Phaseo 目录收录的模型多于 Gateway 能路由的模型：目录中有某个条目，只表示 Phaseo 在跟踪该模型，并不代表存在公共路由。`GET /v1/models` 默认只返回当前可路由的模型：

```bash
curl https://api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

添加 `availability=all` 可同时看到即将推出和已停用的映射。只有当提供商行的 `availability_status` 为 `active` 且 `is_active_gateway` 为 `true` 时，才向它发送生产流量。模型页面上各状态图标的含义，请参阅[提供商和 Phaseo 状态](../guides/provider-statuses.mdx)。

| 状态 | 含义 |
| --- | --- |
| `active` | 目前至少有一条公共 Gateway 路由可用。 |
| `coming_soon` | Phaseo 在跟踪一条计划中或预览阶段的路由，但它尚不可公开路由。 |
| `inactive` | 已知路由已停用、不可用、已过期，或因其他原因无法路由。 |
| `not_listed` | 目前没有列出该模型的 Gateway 提供商映射。 |

`active` 并不保证正常运行时间、在所有地区都能访问，也不保证每个工作区的商业条款都相同。

## 解读性能指标

Phaseo 的性能数据汇总的是经由 Gateway 路由的真实请求，而不是受控的实验室基准测试。

| 指标 | 定义 |
| --- | --- |
| Gateway TTFT | 从 Gateway 请求开始到首个包含内容的生成输出。 |
| Provider TTFT | 从发送到提供商到首个包含内容的生成输出。 |
| 提供商耗时 | 从发送到提供商到最终响应。 |
| Gateway E2E | 从 Gateway 请求开始到完成。 |
| Phaseo 开销 | Gateway E2E 与提供商耗时之间的非负差值。 |
| 有效吞吐量 | 全部输出 token 数除以提供商总耗时。 |
| 输出速度 | 首个输出之后的输出 token 数除以 TTFT 之后的提供商耗时。 |

TTFT 和输出速度需要流式响应，且首个输出必须包含内容。非流式请求仍会计入耗时和有效吞吐量，但不计入 TTFT。

查看每个指标时，都要结合它的时间范围、路由、地区、流式模式和百分位数。提供商负载、提示词长度、输出长度、重试和网络状况都会改变结果。

完整定义请参阅[价格与性能](../exploring/pricing-performance)和 [Phaseo 如何衡量延迟和吞吐量](https://phaseo.app/how-phaseo-measures-latency-throughput)。

## 使用你的工作负载进行验证

公共指标只能指示大致方向，不能证明某条路由满足你的生产目标。上线前请运行一次小规模、可复现的测试：

1. 移除敏感的生产数据，并保留有代表性的提示词组合。
2. 记录模型 ID、端点、提供商限制、地区、流式模式和并发数。
3. 运行足够多次，以便比较分布，而不是只看单个请求。
4. 记录成功率、Gateway TTFT、提供商耗时、Gateway E2E、输出 token 数和最终成本。
5. 测试无效密钥、无效模型、速率限制和提供商不可用导致的失败。
6. 保存 request ID 和准确的时间范围，以便其他工程师复现结果。

未经许可且没有记录在案的方法时，不要公开客户名称、引述、工作负载结果或可靠性百分比。

## 排查失败的请求

1. 查看[服务状态](https://status.phaseo.app)。
2. 确认该模型仍出现在默认的 [`GET /v1/models`](../api-reference/endpoint/models) 响应中，并检查它的[端点](../api-reference/endpoint/model-endpoints)。
3. 在[错误与调试](../api-reference/errors)中查找 HTTP 状态和错误代码。
4. 对暂时性的 `429` 和 `5xx` 响应，采用有上限的指数退避重试；请参阅[速率限制](../api-reference/limits.mdx)。
5. 联系[支持团队](https://phaseo.app/help)时，请提供 request ID。

如需在某个提供商故障时保持请求正常，请设置[路由与回退](../guides/routing-and-fallbacks)。
