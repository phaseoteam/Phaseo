---
title: "身份验证"
description: "使用 API 密钥对发送到 Phaseo Gateway 的每个请求进行身份验证。"
icon: "key-round"
---

在[仪表板](https://phaseo.app/settings/keys)中创建密钥，或使用管理密钥调用 `POST /v1/keys`，把它保存在你的服务器上，并在每个 Gateway 请求中作为 bearer 令牌发送。智能体应使用 CLI；参见[通过智能体管理 Phaseo](./manage-from-an-agent)。

```http
Authorization: Bearer phaseo_v1_sk_<kid>_<secret>
```

在客户端上设置一次该请求头即可。例如使用 `fetch`：

```ts
const response = await fetch("https://api.phaseo.app/v1/chat/completions", {
	method: "POST",
	headers: {
		Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
		"Content-Type": "application/json",
	},
	body: JSON.stringify({
		model: "openai/gpt-6-astra",
		messages: [
			{ role: "system", content: "You are a helpful assistant." },
			{ role: "user", content: "Summarize the drawbacks to AI." },
		],
	}),
});
```

<Note>
无需充值额度即可调用 `:free` 模型。付费模型需要钱包中有可用余额。
</Note>

## 选择凭据

| 凭据 | 格式 | 用途 |
| --- | --- | --- |
| Gateway API 密钥 | `phaseo_v1_sk_<kid>_<secret>` | 你的工作区可用的模型、提供商和生成端点。 |
| [管理 API 密钥](./management-api-keys.mdx) | `phaseo_v1_mk_<kid>_<secret>` | 管理类 API。 |
| [受信任的工作负载](./trusted-workloads.mdx)（测试版） | 平台签发的短期 OIDC 令牌 | 在 Vercel、GitHub Actions、GitLab、Google Cloud、Buildkite、CircleCI、AWS 或你自己的 OIDC 签发方上运行的部署和 CI 任务，无需存储密钥。 |

像对待密码一样对待密钥：不要把它们放进客户端代码和公开仓库。

## 安全地处理密钥

- **每个应用和环境使用一个密钥**，这样轮换一个密钥时不会影响其他服务。
- **把密钥存放在密钥管理器中**，避免它们出现在日志和错误跟踪中。
- **在仪表板中监控每个密钥的用量**，及时发现异常。
- **删除不再使用的密钥。**

轮换密钥时，先把应用切换到新密钥，再让旧密钥失效。参见[密钥轮换端点](../api-reference/endpoint/keys-rotate.mdx)。

## 修复身份验证错误

| 状态 | 原因 | 处理方法 |
| --- | --- | --- |
| `401` | 密钥缺失、无效，或属于已停用的工作区。响应体中的 `reason` 会说明是哪一种。 | 检查请求头和密钥。 |
| `403` | 密钥有效，但不能使用所请求的提供商或模型。 | 检查密钥的护栏和工作区的提供商设置。 |
| `429` | 密钥或工作区达到了某个限制。 | 参见[速率限制](../api-reference/limits.mdx)。 |
| `5xx` | Phaseo 或提供商出错。 | 使用指数退避重试；如果问题持续，请联系[支持](https://phaseo.app/help)。 |

所有错误码参见[错误与调试](../api-reference/errors.mdx)。
