## 创建智能体

根据定义创建一个智能体。定义中的步数上限作用于每次运行或继续调用。

| 语言 | 名称 | 默认步数上限 |
| --- | --- | --- |
| TypeScript | `createAgent(definition)` | 12 |
| Python | `create_agent(definition)`，接受字典或 `AgentDefinition` | 12 |
| Go | `CreateAgent(AgentDefinition) *Agent` | 8 |
| C# | `AgentSdk.CreateAgent(AgentDefinition)` | 12 |
| PHP | `AgentSdk::createAgent(AgentDefinition)` | 12 |
| Ruby | `PhaseoAgentSdk.create_agent(definition)`，接受 `AgentDefinition` 或关键字字段 | 12 |
| Java | `AgentSdk.createAgent(AgentDefinition)` | 12（小于 1 的 `maxSteps` 会变为 12） |
| Rust | `create_agent(AgentDefinition::new(id, model))` | 8（值至少会被限制为 1） |

### 定义字段

Rust 用方法而不是字段构建定义：先 `AgentDefinition::new(id, model)`，再调用 `.instructions(text)`、`.tool(tool)`（每个工具调用一次）、`.max_steps(limit)`、`.model_retries(count, backoff)` 和 `.human_review(callback)`。Java 的 `AgentDefinition` 是一个 record，有 10 个、13 个和 19 个参数的构造函数。

| 字段 | camelCase（TypeScript、PHP、Java） | snake_case（Python、Ruby） | PascalCase（Go、C#） | 不支持的语言 |
| --- | --- | --- | --- | --- |
| 智能体 ID（必填） | `id` | `id` | `ID`（Go）、`Id`（C#） | |
| 模型或预设 | `model`、`preset` | `model`、`preset` | `Model`、`Preset` | Rust 没有 `preset` |
| 模型列表（未设置 `model` 时只使用第一个；没有回退） | `models` | | | 除 TypeScript 外的所有语言 |
| 指令 | `instructions` | `instructions` | `Instructions` | |
| 工具 | `tools` | `tools` | `Tools` | |
| 某一步提供的工具 | `activeTools` | | | 除 TypeScript 外的所有语言 |
| 在每次模型请求前改写历史 | `prepareMessages` | | | 除 TypeScript 外的所有语言 |
| 步数上限和停止条件 | `maxSteps`、`stopWhen` | `max_steps`、`stop_when` | `MaxSteps`、`StopWhen` | Rust 没有 `stop_when` |
| 模型重试和工具并发 | `modelRetry`、`toolExecution` | `model_retry`、`tool_execution` | `ModelRetry`、`ToolExecution` | Rust 没有工具并发 |
| 采样和长度 | `temperature`、`maxOutputTokens`、`topP` | `temperature`、`max_output_tokens`、`top_p` | | Go、C#、Java、Rust |

| 每个模型响应后的审核 | `humanReview` | `human_review` | `HumanReview` | |

在 TypeScript 中，`model`、`instructions` 和采样参数既可以是固定值，也可以是动态的。

## 停止条件

| 条件 | camelCase（TypeScript、PHP、Java） | snake_case（Python、Ruby） | PascalCase（Go、C#） |
| --- | --- | --- | --- |
| 步数 | `stepCountIs` | `step_count_is` | `StepCountIs` |
| 已用 token 数 | `maxTokensUsed` | `max_tokens_used` | `MaxTokensUsed` |
| 费用 | `maxCost` | `max_cost` | `MaxCost` |
| 已用时间 | `maxDuration`（TypeScript 和 PHP 中为毫秒；Java 中为 `Duration`） | `max_duration`（毫秒） | `MaxDuration`（Go 中为 `time.Duration`；C# 中为 `TimeSpan`） |
| 调用了某个工具 | `hasToolCall` | `has_tool_call` | `HasToolCall` |

Go 和 Java 返回 `StopCondition`；C# 返回 `Func<StopState, (bool Stop, string Reason)>`；PHP 返回 `callable`；Ruby 返回 lambda。Rust 没有停止条件，只有步数上限。参见[停止条件](./stop-conditions)。

## 运行与继续

| 用途 | TypeScript | Python | Go | C# | PHP | Ruby | Java | Rust |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 运行 | `run(options)` | `run(...)` | `Run(ctx, RunOptions)` | `Run(RunOptions)` | `run(...)` | `run(...)` | `run(RunOptions)` | `run(&mut client, options)`、`run_with_events(&mut client, options, callback)` |
| 运行并流式传输 | `stream(options)` | `stream(...)` | `Stream(ctx, RunOptions)` | `Stream(RunOptions)` | `stream(...)` | `stream(...)` | `stream(RunOptions)` | 无 |
| 继续 | `continueRun(options)` | `continue_run(...)` | `Continue(ctx, ContinueOptions)` | `ContinueRun(ContinueOptions)` | `continueRun(...)`、`continueRunById(...)` | `continue_run(...)` | `continueRun(ContinueOptions)` | `continue_run(&mut client, options)`、`continue_with_events(...)` |
| 继续并流式传输 | `continueStream(options)` | `continue_stream(...)` | `ContinueStream(ctx, ContinueOptions)` | `ContinueStream(ContinueOptions)` | `continueStream(...)` | `continue_stream(...)` | `continueStream(ContinueOptions)` | 无 |

运行和继续都返回运行结果：TypeScript 中为 `Promise<AgentRunResult>`，Go 中为 `(RunResult, error)`，C# 中为 `Task<RunResult>`，Rust 中为 `Result<RunResult, AgentError>`，其他语言直接返回运行结果。流式方法会立即返回一个流结果。

### 运行选项

PHP 和 Ruby 以命名参数或关键字参数接收这些选项；Java 的 `RunOptions` 是按位置传参的 record，顺序为 `input, client, context, model, preset, maxSteps, modelRetry, toolExecution, onEvent, devtools`，之后是可选的 `state`。

| 选项 | camelCase（TypeScript、PHP、Java） | snake_case（Python、Ruby、Rust） | PascalCase（Go、C#） | 不支持的语言 |
| --- | --- | --- | --- | --- |
| 输入 | `input` | `input` | `Input` | |
| 用完整对话代替输入 | `messages` | | | 除 TypeScript 外的所有语言 |
| 模型客户端 | `client` | `client` | `Client` | Rust 把它作为单独的参数传入 |
| 应用上下文 | `context` | `context` | `Context` | |
| 覆盖模型、预设和步数上限 | `model`、`preset`、`maxSteps` | `model`、`preset`、`max_steps` | `Model`、`Preset`、`MaxSteps` | Rust 只有 `model` 和 `max_steps` |
| 覆盖重试和工具并发 | `modelRetry`、`toolExecution` | `model_retry`、`tool_execution` | `ModelRetry`、`ToolExecution` | Rust |
| 覆盖采样参数 | `temperature`、`maxOutputTokens`、`topP`（TypeScript） | | | 除 TypeScript 外的所有语言 |
| 取消 | `signal`（TypeScript） | | `CancellationToken`（C#） | Go 使用 `ctx`；其他语言通过流取消 |
| 事件处理函数 | `onEvent` | `on_event` | `OnEvent` | Rust 使用 `run_with_events` |
| 本地捕获 | `devtools` | `devtools` | `Devtools` | Rust |
| 状态访问器 | `state` | `state` | `State` | Rust |
| 在下一次模型请求前添加消息 | `takeMessages`（TypeScript） | | | 除 TypeScript 外的所有语言 |

Python 的 `run()` 也接受 `stop_when`，但会忽略它；请在定义上设置停止条件。PHP 的 `stream()` 和 Ruby 的 `stream` 只接收 `input`、`client`、`context` 和 `state`。Rust 用 `RunOptions::new(input)` 创建默认值。

### 继续选项

继续选项接收上面的运行覆盖项，另外还有：

| 选项 | camelCase（TypeScript、PHP、Java） | snake_case（Python、Ruby、Rust） | PascalCase（Go、C#） | 不支持的语言 |
| --- | --- | --- | --- | --- |
| 已保存的运行 | `run` | `run`（Rust：`result`） | `Run` | |
| 通过 `state` 按 ID 加载运行 | `runId` | `run_id` | `RunID`（Go）、`RunId`（C#） | Rust；PHP 使用 `continueRunById($runId, $state, $client, ...)` |
| 人工输入 | `humanInput` | `human_input` | `HumanInput` | |
| 结构化的人工消息 | `humanMessages`（TypeScript） | | | 除 TypeScript 外的所有语言 |
| 批准 | `approvals`（TypeScript 别名 `approveToolCalls`） | `approvals` | `Approvals` | |
| 拒绝 | `rejections`（TypeScript 别名 `rejectToolCalls`） | `rejections` | `Rejections` | Rust |
| 工具输出 | `toolOutputs` | `tool_outputs` | `ToolOutputs` | |

Java 的 `ContinueOptions` 顺序为 `run, client, context, model, preset, maxSteps, humanInput, modelRetry, toolExecution, onEvent, devtools`，然后是 `approvals, rejections, toolOutputs`，最后是 `runId, state`。除了这个 16 参数的形式，还有只接收前 11 个或前 14 个参数的构造函数，其余参数默认为空列表或 `null`。Rust 用 `ContinueOptions::new(result)` 创建默认值。

## 流结果

| 用途 | TypeScript | Python | Go | C# | PHP | Ruby | Java |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 完成后的结果 | `getResult()`，或对流使用 `await` | `result()` | `Result()` | `GetResult()` | `getResult()` | `result` | `getResult()` |
| 完整的最终文本 | `getText()` | | | | | | |
| 文本增量 | `getTextStream()` | `text_stream()` | `Text()` | `TextStream()` | `textStream()` | `text_stream` | `textStream()` |
| 推理增量 | `getReasoningStream()` | `reasoning_stream()` | | | `reasoningStream()` | `reasoning_stream` | |
| 条目 | `getItemsStream()` | `item_stream()` | | | `itemStream()` | `item_stream` | |
| 工具事件 | `getToolStream()` | `tool_stream()` | | | | | |
| 所有事件 | `getFullStream()` | `full_stream()` | `Events()` | `FullStream()` | `fullStream()` | `full_stream` | `fullStream()` |
| 取消 | `cancel(reason?)` | `cancel()` | `Cancel()` | `Cancel()` | `cancel()` | `cancel` | `cancel()` |

消费者会从头重放，所以多个消费者可以读取同一个运行。它们的行为有所不同：

| 语言 | 流结果类型 | 行为 |
| --- | --- | --- |
| TypeScript | `AgentStreamResult` | `getFullStream()` 以一个 `result` 事件结束 |
| Python | `AgentStreamResult` | 在后台线程中运行；`result()` 会阻塞直到完成 |
| Go | `*StreamResult` | `Text()` 和 `Events()` 是 channel；`Cancel()` 会取消运行的 context |
| C# | `AgentStreamResult` | `IAsyncEnumerable` 消费者；`Cancel()` 会取消运行的关联令牌 |
| PHP | `AgentStreamResult` | 在 Fiber 中运行；流被读完后 `$result` 保存 `RunResult`，否则为 `null` |
| Ruby | `StreamResult` | 在工作线程中运行；`result` 会 join 该线程，`cancel` 会终止它 |
| Java | `StreamResult` | `textStream()` 和 `fullStream()` 在运行结束后返回一个 `List`；`cancel()` 会中断工作线程 |
| Rust | 无 | `0.2` 中没有流式传输 |

## 运行结果

| 字段 | camelCase（TypeScript、PHP、Java） | snake_case（Python、Ruby、Rust） | PascalCase（Go、C#） |
| --- | --- | --- | --- |
| 运行记录 | `run` | `run` | `Run` |
| 步骤记录 | `steps` | `steps` | `Steps` |
| 最终输出 | `output` | `output` | `Output` |
| 完整对话 | `messages` | `messages` | `Messages` |

该类型在 TypeScript 和 Python 中为 `AgentRunResult`，在其他语言中为 `RunResult`。TypeScript 还增加了 `stepResults`（规范化的步骤结果）和 `items`（按顺序排列的消息、推理、工具活动、错误和最终输出；参见[条目](./items)）。在 Rust 中，`output` 是 `serde_json::Value`，`RunResult`、`RunRecord`、`RunStep`、`Message`、`ToolCall`、`HumanPause`、`PendingToolCall`、`ToolDecision`、`ToolOutput` 和 `UsageSummary` 都可以用 Serde 序列化。

### 用量汇总

`inputTokens`、`outputTokens`、`cachedTokens`、`totalTokens`、`cost`（TypeScript、Java）；`input_tokens`、`output_tokens`、`cached_tokens`、`total_tokens`、`cost`（Python、PHP 和 Ruby 的键，Rust）；`InputTokens`、`OutputTokens`、`CachedTokens`、`TotalTokens`、`Cost`（Go、C#）。该类型在 TypeScript 和 Python 中为 `AgentUsageSummary`，在 Go、C#、Java 和 Rust 中为 `UsageSummary`。PHP 和 Ruby 使用数组或 Hash。关于 `cost` 的注意事项，参见[可观测性](./observability)。

## 暂停与决定

| 类型 | TypeScript | Python | Go、C#、PHP、Ruby、Java、Rust | 字段 |
| --- | --- | --- | --- | --- |
| 批准或拒绝调用 | `{ toolCallId, reason? }` | `AgentToolDecision` | `ToolDecision` | 工具调用 ID 和可选的原因 |
| 提供工具结果 | `{ toolCallId, output }` | `AgentToolOutput` | `ToolOutput` | 工具调用 ID 和输出 |
| 请求审核 | `{ reason, payload }` | `AgentHumanReviewRequest` | `HumanReviewRequest` | `reason`，可选的 `payload` |

字段名遵循各语言的风格：`toolCallId`（TypeScript、PHP、Java）、`tool_call_id`（Python、Ruby、Rust）、`ToolCallID`（Go）和 `ToolCallId`（C#）。Rust 的 `ToolDecision` 只用于批准。参见[状态与审批](./state-and-approval)。

## 模型客户端

实现一个模型客户端，即可通过其他传输方式发送模型轮次，或包装网关客户端。

| 语言 | 接口 | 方法 |
| --- | --- | --- |
| Go | `ModelClient`、`StreamingModelClient` | `Generate(ctx, ModelRequest)`；`Stream(ctx, ModelRequest)` |
| C# | `IModelClient`、`IStreamingModelClient` | `Generate(ModelRequest)`；`Stream(ModelRequest)` |
| PHP | `ModelClient`、`StreamingModelClient`（接口） | `generate(ModelRequest)`；`stream(ModelRequest)` |
| Java | `ModelClient`、`StreamingModelClient` | `generate(ModelRequest)`；`stream(ModelRequest)` |
| Rust | `ModelClient`（trait） | `fn generate(&mut self, request: &ModelRequest) -> Result<ModelResponse, AgentError>` |

在 Rust 中，`ModelRequest` 包含智能体 ID、实际使用的模型、指令、当前消息、工具规范（`ToolSpec`：`id`、`description`、JSON Schema `parameters`）和应用上下文。`ModelResponse` 包含 `message`、`usage`、`request_id`、`provider`、`model` 和 `finish_reason`。`Message` 有 `role`、`content`、`tool_calls`、`tool_call_id`、`name` 和 `is_error`，并提供 `Message::user(content)` 和 `Message::assistant(content)` 构造函数；`ToolCall` 有 `id`、`name` 和 JSON 格式的 `input`。
