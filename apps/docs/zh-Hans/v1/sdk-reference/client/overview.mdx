## 你发送什么，拿回什么

在每个 SDK 中，请求正文都使用 API 的 JSON 字段名。[用法](./usage)为每个端点提供了一个示例。

| 语言 | 请求正文 | 返回值 |
| --- | --- | --- |
| TypeScript | 由 OpenAPI 规范生成的带类型对象 | 带类型对象 |
| Python | dict；类型位于 `phaseo.models` | 带有 `output_text`、`request_id` 和 `trace_url` 的 `APIResponse` dict |
| Go | `map[string]interface{}`，或带类型的 `phaseo.ChatCompletionsRequest` 和 `phaseo.ResponsesRequest`（PascalCase 结构体字段，例如 `Model`、`Messages`、`Input`） | 解码后的 JSON |
| C# | `Dictionary<string, object>` | `Dictionary<string, object>?` |
| PHP | 数组 | 数组 |
| Ruby | Hash（关键字参数） | Hash |
| Java | `Map` 或 Jackson `JsonNode`；JSON 字符串需先解析 | `JsonNode` |
| Rust | `&serde_json::Value` | 带有 `status`、`body` 和 `request_id` 的 `PhaseoResponse` |

缺少密钥时，创建客户端就会失败。Python 抛出 `ValueError`，Go 的 `NewFromEnv()` 返回错误，C# 和 PHP 抛出 `Missing API key. Pass apiKey or set PHASEO_API_KEY.`，Ruby 抛出 `ArgumentError: Missing API key. Pass api_key or set PHASEO_API_KEY.`，Rust 的 `Phaseo::from_env()` 返回 `PhaseoError`。

在 asyncio 下使用 `AsyncPhaseo`：

```python Python
import asyncio
from phaseo import AsyncPhaseo

async def main():
    async with AsyncPhaseo() as client:
        response = await client.responses.create({"model": "openai/gpt-6-astra", "input": "Hello"})
        print(response.output_text, response.request_id, response.trace_url)

asyncio.run(main())
```

使用 `async for event in client.responses.stream(request)` 获取解析后的文本事件。取消 asyncio 任务会停止 HTTP 请求以及任何轮询。`AsyncPhaseo` 为文本、图片、音频、实时、音乐、视频、批处理、文件、模型、嵌入、OCR、重排序、解析、审核、决策和提取提供资源命名空间；其他 HTTP 操作请使用 `await client.request(...)`。

<span id="wait-for-music-video-or-batches"></span>
## 等待音乐、视频或批处理完成

等待辅助方法仅在 TypeScript 和 Python 中提供。其他 SDK 从创建调用中返回任务；请用 get 方法轮询它，或打开它的[任务 WebSocket URL](#find-the-method-for-each-endpoint)。

<CodeGroup>

```typescript TypeScript
const music = await client.music.generateAndWait(
  { model: process.env.PHASEO_MUSIC_MODEL!, prompt: "Gentle instrumental piano" },
  { timeoutMs: 600_000, onPoll: (job) => console.log(job.id, job.status) },
);
```

```python Python
import os

music = client.music.generate_and_wait(
    {"model": os.environ["PHASEO_MUSIC_MODEL"], "prompt": "Gentle instrumental piano"},
    timeout=600,
    on_poll=lambda job: print(job["id"], job["status"]),
)
```

</CodeGroup>

视频使用 `videos.generateAndWait` / `videos.generate_and_wait`，批处理使用 `batches.createAndWait` / `batches.create_and_wait`。每个辅助方法只提交一次。如果第一个响应已经完成，它会直接返回而不轮询；否则它会轮询同一个任务直到结束，并返回完整响应。失败、取消或过期的任务会抛出 `JobFailedError`，其 `response` 包含详细信息。已完成的批处理中仍可能包含失败的单个请求。

每个资源上的 `wait(id, options)` 会接续一个已有任务，并返回任何终态响应，包括失败。在 Python 中，音乐还提供 `create(request)` 和 `retrieve(id)`。

| TypeScript | Python | 默认值 | 说明 |
| --- | --- | --- | --- |
| `intervalMs` | `interval` | `5000` 毫秒 / `5` 秒 | 最小 `250` 毫秒 / `0.25` 秒。 |
| `timeoutMs` | `timeout` | `1800000` 毫秒 / `1800` 秒（30 分钟） | 从提交返回后开始计时；提交请求本身保留自己的超时。 |
| `signal` | `cancel_event` | 无 | 停止等待。在 Python 中是一个 `threading.Event`。 |
| `onPoll` | `on_poll` | 无 | 接收第一个响应以及每次轮询结果。 |

`JobTimeoutError` 和 `JobCancelledError` 会保留任务 ID 和最后一个响应（TypeScript 中为 `jobId`/`lastResponse`，Python 中为 `job_id`/`last_response`），因此你可以用 `.wait(error.jobId)` 或 `.wait(error.job_id)` 接续。停止等待不会取消远程任务。在 TypeScript 中，它会取消正在进行的轮询；同步 Python 客户端在请求和回调之间检查取消和截止时间，因此无法中断已经在进行的 HTTP 调用。HTTP 失败会原样抛出，提交永远不会重试。这些辅助方法从你的进程中轮询；它们不会给网关增加后台执行。

### 跨进程保留句柄

`music.start`、`videos.start` 和 `batches.start` 返回一个带有 `result()`、`events()` 和 `cancel()` 的句柄，以及 `toJSON()`（TypeScript）或 `to_dict()`（Python）。保存它返回的类型和 ID，之后用 `resume(id)` 重建句柄。`result()` 遇到终态失败时会抛出异常。只有视频和批处理任务支持 `cancel()`。在 `AsyncPhaseo` 上，请 await 这些方法，并用 `async for` 迭代事件。

| 任务 | TypeScript | Python |
| --- | --- | --- |
| 流式获取视频内容 | `videos.streamContent(id)`，用 `downloadTo(stream, writable)` 写入 | `videos.stream_content(id)`，用同步的 `download_to(chunks, binary_file)` 写入，不会把整个下载内容保存在内存中 |
| 流式获取批处理结果 | `batchResults(await client.batches.streamResults(id))` 逐行解析 JSONL；`matchBatchResult(row, inputsByCustomId)` 把每一行与其输入配对，并保留每行的错误 | `batches.results(id)` |
| 准备上传 | `toFile(bytes, filename, contentType)` | 传入 bytes、`Path` 对象、文件对象或 HTTPX 文件元组 |

## 请求控制和错误

在 TypeScript、Python 和 Java 中，重试默认为 `0`，并且只适用于 `GET` 和 `HEAD` 请求。付费提交、写入和流式请求永远不会重试。

<CodeGroup>

```typescript TypeScript
const fast = client.withOptions({ timeoutMs: 30_000, signal, maxRetries: 2 });
```

```python Python
fast = client.with_options(timeout=30, max_retries=2)
```

```java Java
Phaseo client = new Phaseo(System.getenv("PHASEO_API_KEY"))
    .setTimeout(Duration.ofSeconds(30))
    .setMaxRetries(2);
```

</CodeGroup>

<Tabs>
<Tab title="TypeScript">

`withOptions(...)` 返回一个新客户端，这些控制会应用到它的每个资源、流和媒体调用；原客户端保持不变。重试遵循 `Retry-After`。`timeoutMs` 包括读取响应正文的时间。

`responseMetadata(result)` 返回网关请求 ID 和控制台追踪 URL。HTTP 错误为 `PhaseoHttpError`，包含 HTTP `status`、API 错误 `code`、`requestId`、`traceUrl`、重试延迟、正文和 `headers`。

</Tab>
<Tab title="Python">

`with_options(...)` 返回一个新客户端，还接受 `headers=...`；它在 `Phaseo` 和 `AsyncPhaseo` 上都可用。重试发生在读取响应之前，最多 `10` 次。超时是以秒为单位的 HTTPX 超时，因此它限制的是网络无活动时间，而不是总时长。

JSON 响应是带有 `output_text`、`request_id` 和 `trace_url` 的 `APIResponse` dict。HTTP 错误为 `PhaseoHTTPError`，包含 `status`、`code`、`request_id`、`trace_url`、重试延迟和正文。

从旧版本升级时，把捕获 `urllib.error.HTTPError` 的地方换成 `PhaseoHTTPError`（或 `httpx.HTTPStatusError`），把捕获连接错误的地方换成 `httpx.TransportError`。

</Tab>
<Tab title="Java">

HTTP 错误为 `Client.ApiException`（`app.phaseo.gen.Client`），提供 `getStatusCode()`、`getRequestId()`、`getResponseBody()` 和请求头。`requestWithResponse(...)` 返回数据及其 `requestId()`。

</Tab>
<Tab title="Rust">

每次调用都返回 `Result<PhaseoResponse, PhaseoError>`。`PhaseoError` 实现了 `std::error::Error` 和 `Display`；传输和配置失败没有 `status`。

| 类型 | 字段 | 含义 |
| --- | --- | --- |
| `PhaseoResponse` | `status: u16` | HTTP 状态码。 |
| `PhaseoResponse` | `body: serde_json::Value` | 解析后的 JSON 响应；响应不是有效 JSON 时为一个 JSON 字符串。 |
| `PhaseoResponse` | `request_id: Option<String>` | 响应头 `x-request-id`（存在时）。 |
| `PhaseoError` | `message: String` | 配置、传输或 Gateway 错误消息。 |
| `PhaseoError` | `status: Option<u16>` | 收到响应时的 Gateway HTTP 状态。 |
| `PhaseoError` | `body: Option<serde_json::Value>` | 解析后的 Gateway 错误正文（可用时）。 |

</Tab>
</Tabs>

[用法](./usage#handle-errors)展示了每种语言的完整错误处理程序。

## 调用没有封装的端点

每个 SDK 还附带由 Phaseo OpenAPI 规范生成的客户端：

| 语言 | 生成的客户端 |
| --- | --- |
| TypeScript | `client.rawClient()`；生成的操作导出为 `operations`。 |
| Python | `client.raw_client()`；生成的操作位于 `phaseo.ops`。 |
| Go | `client.RawClient()`，来自 `src/gen`。`client.Request(ctx, method, path, query, headers, body)` 可发送任意请求。 |
| Java | `client.rawClient()`，用 `requestLines` 处理流，用 `requestBytes` 处理二进制响应。 |
| Rust | `phaseo::gen` 包含生成的客户端、模型和操作，并重新导出为 `phaseo::client`、`phaseo::models` 和 `phaseo::operations`。`phaseo::model_ids` 包含生成的模型 ID。`client.post(path, body)` 向基础 URL 下的任意路径发送 JSON。参见 [docs.rs](https://docs.rs/phaseo)。 |

生成的操作比封装方法更底层；有封装方法时请优先使用封装方法。

## 解析输出并收集流

这些辅助方法仅在 TypeScript 和 Python 中提供。`responses.parse(request, schema)` 验证已完成的 JSON 响应。在 TypeScript 中，`schema` 是兼容 Zod 的解析器；在 Python 中，是一个 Pydantic 模型。同时还要在请求中设置结构化输出格式；解析器只负责验证。

`collectStream(client.streamResponses(request))`（TypeScript），或 `collect_stream` 和 `collect_async_stream`（Python），会汇总流式输出的文本和用量。

## 调用前检查模型

`checkModelCapabilities` / `check_model_capabilities`（TypeScript 和 Python）会针对一个活跃的提供商报价，检查其公布的能力和标量约束（`inputTypes`、`outputTypes`、`endpoints`、`parameters`、`parameterValues`，Python 中为对应的 snake_case 名称）。它从不更换模型或丢弃参数，也无法保证实时提供商一定会接受请求。缺少元数据时处理方式不同：TypeScript 将其报告为未知，Python 则判定检查失败。

对于模型选择器和参数编辑器，请使用实时端点元数据：

<CodeGroup>

```typescript TypeScript
const support = await client.models.checkParameters(
  "anthropic/claude-haiku-4.5",
  { temperature: 0.7, top_p: 0.9 },
  { endpoint: "responses" },
);
```

```python Python
support = client.models.check_parameters(
    "anthropic/claude-haiku-4.5",
    {"temperature": 0.7, "top_p": 0.9},
    endpoint="responses",
)
```

</CodeGroup>

每个参数都会返回 `supported`、`partial`、`unsupported` 或 `unknown`，并附带匹配的提供商路由和约束问题，你可以在界面中就地高亮显示。这些检查需要显式调用；它们不会给生成请求增加查询。[模型](./models#check-one-model)列出了每个 SDK 中的对应方法。

## 不联网进行测试

<Tabs>
<Tab title="TypeScript">

从 `@phaseo/sdk/testing` 导入 `createMockTransport` 和 `jobFixtures`，并把 mock 的 `fetchImpl` 传给客户端。fixture 是严格且有序的：意外的调用会在本地失败，永远不会到达网络。调用 `mock.assertDone()` 检查每个预期请求是否都已发生。

</Tab>
<Tab title="Python">

把 `phaseo.testing.MockTransport(fixtures)` 传给 `httpx.Client` 或 `httpx.AsyncClient`，再把它作为 `http_client` 交给 Phaseo 客户端。意外的请求会在本地失败；调用 `assert_done()` 检查每个 fixture 是否都已被使用。`phaseo.testing.job_fixtures(path, job_id)` 为一个任务构建提交和轮询的 fixture。fixture 不会验证实时提供商的行为。

</Tab>
</Tabs>

## 从房间导出代码
