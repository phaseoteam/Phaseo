保留 Anthropic SDK 和 Messages 调用。把客户端指向 `https://api.phaseo.app`，将 Phaseo 密钥作为 `authToken` 传入，并为每个模型使用其 Phaseo ID。

| 设置 | Anthropic | Phaseo |
| --- | --- | --- |
| Base URL | SDK 默认值（`https://api.anthropic.com`） | `https://api.phaseo.app`（SDK 会追加 `/v1/messages`） |
| API 密钥 | `ANTHROPIC_API_KEY`，以 `x-api-key` 发送 | `PHASEO_API_KEY` 作为 `authToken` / `auth_token`，以 `Authorization: Bearer` 发送 |
| 模型 | `claude-sonnet-5-5` | `anthropic/claude-sonnet-5.5`，或 `GET /v1/models` 返回的任意 ID |
| Messages 调用 | `messages.create` | 不变 |

## 切换客户端

在 [API 密钥](https://phaseo.app/settings/keys)中创建密钥，并将其作为 `PHASEO_API_KEY` 提供给应用。

<CodeGroup>
```typescript TypeScript
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic({
  apiKey: null,
  authToken: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app",
});

const response = await client.messages.create({
  model: "anthropic/claude-sonnet-5.5",
  max_tokens: 256,
  messages: [{ role: "user", content: "Reply with: migration ready" }],
});
```

```python Python
import os
import anthropic

client = anthropic.Anthropic(
    auth_token=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app",
)

response = client.messages.create(
    model="anthropic/claude-sonnet-5.5",
    max_tokens=256,
    messages=[{"role": "user", "content": "Reply with: migration ready"}],
)
```

```bash cURL
curl https://api.phaseo.app/v1/messages \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-sonnet-5.5",
    "max_tokens": 256,
    "messages": [{"role": "user", "content": "Reply with: migration ready"}]
  }'
```
</CodeGroup>

这一步最常因以下三个细节出错：

- **使用根主机。** `baseURL: "https://api.phaseo.app/v1"` 会生成 `/v1/v1/messages`。同一仓库中的 OpenAI 兼容客户端仍然使用 `/v1`。
- **以 bearer 令牌发送密钥。** 网关只读取 `Authorization: Bearer`；`x-api-key` 请求头会得到 `401` `missing_or_invalid_authorization_header`。`authToken` 在所有 SDK 版本中都发送 Bearer。`apiKey` 只有从 `@anthropic-ai/sdk` 1.0 和 `anthropic` 2.0 起才会这样做。
- **从现在调用 Phaseo 的环境中删除 `ANTHROPIC_API_KEY`。** `apiKey: null` 可以阻止旧版 TypeScript SDK 读取它，而 0.98 之前的 Python SDK 即使设置了 `auth_token` 也会读取它。

通过环境变量配置的工具（例如 Claude Code）使用 `ANTHROPIC_BASE_URL=https://api.phaseo.app`、设为 Phaseo 密钥的 `ANTHROPIC_AUTH_TOKEN`，以及为空的 `ANTHROPIC_API_KEY`。

## 映射模型 ID

用 `GET /v1/models?format=openai` 返回的 `data[].id` 核对每个生产模型。Phaseo ID 的版本号使用点号：`claude-sonnet-5-5` 变为 `anthropic/claude-sonnet-5.5`。如果模型也要更换，请阅读对应的[模型迁移指南](../model-migrations)。

## 有哪些不同

| Anthropic 功能 | 在 Phaseo 上 |
| --- | --- |
| `anthropic-version` 请求头 | 接受任何值；Phaseo 使用自己的版本调用 Claude。 |
| `anthropic-beta` 请求头 | 不转发。Phaseo 会添加其支持的功能所需的 beta；仅限 beta 的请求体字段（例如 `mcp_servers`）会返回 `400`。 |
| `temperature`、`top_p`、`top_k` | 在模型或路由不接受时会被丢弃，并列在 `X-Phaseo-Dropped-Params` 中。 |
| `speed: "fast"` | 返回 `400`。请使用 `service_tier: "fast"`。 |
| 原生网页搜索和 web fetch 工具 | 在提供商运行它们时接受，也可以使用 Phaseo 的 `phaseo:web_search` 服务器工具。 |
| `cache_control` | 支持在顶层或按块设置。参见[提示词缓存](../guides/prompt-caching)。 |
| `metadata.user_id` | 不作为终端用户 ID 使用。如需终端用户速率限制策略，请发送 `user` 或 `X-Phaseo-User-Id` 请求头。 |
| Message Batches（`/v1/messages/batches`） | 没有这个路径。`/v1/batches` 接受形状不同的 `/v1/messages` 行。 |
| token 计数（`/v1/messages/count_tokens`） | 没有对应项。保留在 Anthropic 上，或在客户端估算。 |
| Files API（`client.beta.files`） | 没有对应项。以内联方式发送文档。 |
| `AnthropicBedrock`、`AnthropicVertex` 客户端 | 替换为普通的 `Anthropic` 客户端；云身份验证和区域设置不再适用。 |

## 测试并上线

用应用实际使用的模型 ID 测试系统提示词、流式传输、工具使用、思考和结构化输出。然后用一组有代表性的提示词比较两种配置的输出形状、延迟、token 用量、错误和成本。迁移流量之前确认：

- 每个部署环境都设置了 Phaseo 密钥；
- 每个生产模型 ID 都出现在 `GET /v1/models?format=openai` 中；
- 流式传输和工具使用流程在预发布环境中通过；
- 每个 `anthropic-beta` 请求头和仅限 beta 的字段都已删除或替换；
- 回退仍然只需更改 base URL 和密钥。
