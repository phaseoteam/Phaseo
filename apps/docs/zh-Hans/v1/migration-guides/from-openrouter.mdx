把 base URL 改为 `https://api.phaseo.app/v1`，把密钥改为 `PHASEO_API_KEY`。请求载荷、`Authorization: Bearer` 请求头、`provider` 对象和 `models` 回退数组都能继续使用；只需核对模型 ID 和下表中的少数字段。

| 设置 | OpenRouter | Phaseo |
| --- | --- | --- |
| Base URL | `https://openrouter.ai/api/v1` | `https://api.phaseo.app/v1` |
| API 密钥 | `OPENROUTER_API_KEY`（`sk-or-v1-…`） | `PHASEO_API_KEY` |
| 身份验证 | `Authorization: Bearer <key>` | 不变 |
| 请求载荷 | OpenAI 兼容 | 不变 |
| 模型 ID | `<org>/<model>` | `<org>/<model>`；大多数相同，部分 org 不同 |
| 归因请求头 | `HTTP-Referer`、`X-Title` | 不变；添加 `X-App-Id` 以获得稳定的分组 |

## 切换客户端

<CodeGroup>
```typescript 之前
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.OPENROUTER_API_KEY,
  baseURL: "https://openrouter.ai/api/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Summarize our migration plan." }],
});
```

```typescript 之后
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Summarize our migration plan." }],
});
```

```bash cURL
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role":"user","content":"Say hello"}]
  }'
```
</CodeGroup>

第一轮保持载荷不变，先做到行为一致，再做优化。从代码、CI 和托管设置中删除 `OPENROUTER_BASE_URL` 和旧密钥。`@openrouter/ai-sdk-provider` 改为 `@phaseo/ai-sdk-provider`（参见[从 Vercel AI Gateway 迁移](./from-vercel)）；OpenRouter 自己的 SDK（`@openrouter/sdk`、PyPI 上的 `openrouter`）需要更换客户端，而不只是换一个 base URL。

## 核对模型 ID

大多数 ID 相同，但部分 org 不同：`x-ai/` 对应 `spacex-ai/`，`meta-llama/` 对应 `meta/`，`mistralai/` 对应 `mistral/`。列出 Phaseo 的 ID，并用它们核对每个生产模型：

```bash
curl -s "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY" | jq -r '.data[].id'
```

默认列表只包含现在可以调用的模型；添加 `availability=all` 可以查看未激活或即将推出的模型。不带 `format=openai` 时，响应是 Phaseo 的分页 `models` 列表，没有 `data` 数组。

## 映射请求字段

| OpenRouter | 在 Phaseo 上 |
| --- | --- |
| `provider.order`、`only`、`ignore`、`allow_fallbacks`、`require_parameters`、`max_price` | 字段相同。使用基础提供商 ID，而不是接口 slug。 |
| `provider.sort` | 字段相同：`price`、`latency` 或 `throughput`。 |
| `provider.zdr` | 作为 `provider.require_zero_data_retention` 的别名接受。 |
| `provider.data_collection: "deny"` | 返回 `400`。请改用 `zdr: true`。 |
| `models` 回退数组 | 相同，1 到 25 项。`model` 是必填项，因此请把 `models[0]` 移到其中。 |
| `:nitro` 后缀 | 相同（吞吐量）。Phaseo 还有 `:cheap` 和 `:fast`；`:floor` 改为 `:cheap`。删除 `:online` 和 `:thinking`，改用网页搜索和 `reasoning`。 |
| `openrouter/auto`、`openrouter/free` | `phaseo/auto`（[自动路由](../guides/auto-routing)，alpha，不能与 `models` 一起使用）和 `phaseo/free`。 |
| `plugins` `web`、`web-fetch`、`response-healing` | 插件 ID 相同。其他插件（例如 `file-parser`）会返回 `400`。 |
| `transforms`、`usage: { include: true }` | 不接受。请删除；用量和成本总会返回。 |
| `X-OpenRouter-Title` | 重命名为 `X-Title`。参见[应用归因](../guides/app-attribution)。 |
| 预设 `@preset/<slug>` | 重建为[预设](../guides/presets)，并以 `"model": "@slug"` 调用。 |
| 响应中的 `usage.cost`、`reasoning_details`、`provider` | 会返回。`native_finish_reason` 和 `is_byok` 不会返回；如果调用方读取它们，请在一个层中统一处理。 |

Phaseo 还有 `provider.required_execution_region` 和 `provider.required_data_region`，OpenRouter 中没有对应项。完整请求示例请参见[按请求固定或忽略提供商](../cookbook/pin-or-ignore-providers-per-request)和[只路由到欧盟或支持 ZDR 的提供商](../cookbook/route-only-to-eu-or-zdr-providers)。

把剩余的 OpenRouter 专属字段集中在一个适配器中，而不是分散在每个调用处，这样回退仍然只需更改 base URL 和密钥。

## 切换前验证

先对 Phaseo 运行以下检查，再通过应用自己的客户端路径运行同样的检查：

```bash
curl -s "https://api.phaseo.app/v1/health"

curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"openai/gpt-6-astra","messages":[{"role":"user","content":"Say hello"}]}'

# 流式传输
curl -N "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"openai/gpt-6-astra","stream":true,"messages":[{"role":"user","content":"Reply with: stream works"}]}'

# 无效模型：应用应处理该错误，且不暴露凭据
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"invalid/migration-test","messages":[{"role":"user","content":"test"}]}'
```

在迁移较大比例的流量之前，确认：

- 每个环境中的 `OPENROUTER_API_KEY` 都已替换为 `PHASEO_API_KEY`；
- 每个生产模型 ID 都出现在 `GET /v1/models?format=openai` 中；
- 使用与生产相同的客户端路径，一个非流式请求和一个流式请求通过 `/v1/chat/completions` 或 `/v1/responses`；
- 工具调用和结构化输出流程在真实提示词下通过；
- 已处理无效密钥和无效模型的失败；
- 失败的请求可以用 `GET /v1/generations?id=<request_id>` 查到，并且在 `replay_supported` 为 `true` 时可以用 `replay_request` 重放；
- OpenRouter 专属的请求头和响应字段已删除或统一处理，共享的默认设置放在预设中。

## 上线

1. 从内部流量开始。
2. 迁移 5-10% 的生产流量，比较质量、延迟和成本。
3. 确认行为一致后提升到 100%。
4. 在切换稳定之前，让回退保持为更换 base URL 和密钥。

## 把迁移交给编程智能体

把下面这组有边界的步骤交给智能体，或安装 [OpenRouter 到 Phaseo 迁移技能](https://github.com/phaseoteam/Phaseo/tree/main/.agents/skills/openrouter-to-phaseo-migration)，它打包了同样的清点、映射、验证和回退步骤：

1. 在运行时代码和部署配置中搜索 `openrouter.ai`、`OPENROUTER_API_KEY`、`sk-or-v1`、`HTTP-Referer` 和 `X-Title`。
2. 把客户端边界改为 `https://api.phaseo.app/v1` 和 `PHASEO_API_KEY`，不要把任何密钥值加入源代码管理。
3. 查询 `GET /v1/models?format=openai`，记录每个从旧到新的模型映射。
4. 在一个兼容模块中适配 OpenRouter 专属的路由选项或响应字段。
5. 运行上面的健康检查、非流式、流式和失败路径检查。
6. 报告已修改的文件、密钥名称的变更、模型映射、测试证据、一致性差距和回退开关。

如需引导式迁移，请打开[交互式 OpenRouter 迁移指南](https://phaseo.app/migrate/openrouter)，查看两者的[对比](https://phaseo.app/compare/openrouter)，或[获取免费的迁移帮助](https://phaseo.app/contact)。
