---

把客户端指向 `https://api.phaseo.app/v1` 并使用 Phaseo 密钥，删除 `Helicone-Auth`，然后把仍需要的每个 `Helicone-*` 请求头迁移到对应的 Phaseo 设置。请求本身的改动很小；可观测性的切换同样需要仔细规划。

| 设置 | Helicone | Phaseo |
| --- | --- | --- |
| Base URL | `oai.helicone.ai/v1`、`anthropic.helicone.ai`、`ai-gateway.helicone.ai`，或带 `Helicone-Target-URL` 的 `gateway.helicone.ai` | `https://api.phaseo.app/v1` |
| 身份验证 | 提供商密钥加 `Helicone-Auth`，或 AI Gateway 上的 `HELICONE_API_KEY` | 只需 `PHASEO_API_KEY` |
| 自定义属性 | `Helicone-Property-<Name>` | `X-Phaseo-Metadata` 标签 |
| 请求可见性 | Helicone 控制台 | Phaseo 请求日志和请求详情 |

## 切换客户端

<CodeGroup>
```typescript TypeScript
import OpenAI from "openai";

// 之前：
// new OpenAI({
//   apiKey: process.env.OPENAI_API_KEY,
//   baseURL: "https://oai.helicone.ai/v1",
//   defaultHeaders: {
//     "Helicone-Auth": `Bearer ${process.env.HELICONE_API_KEY}`,
//     "Helicone-Property-Team": "support",
//   },
// });
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
  defaultHeaders: {
    "X-Phaseo-Metadata": JSON.stringify({ labels: [{ key: "team", value: "support" }] }),
  },
});

const response = await client.chat.completions.create(
  {
    model: "openai/gpt-6-astra",
    messages: [{ role: "user", content: "Reply with: migration ready" }],
  },
  { headers: { "X-Phaseo-User-Id": "user_123" } },
);
```

```python Python
import json
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
    default_headers={
        "X-Phaseo-Metadata": json.dumps({"labels": [{"key": "team", "value": "support"}]}),
    },
)
```

```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role": "user", "content": "Reply with: migration ready"}]
  }'
```
</CodeGroup>

用户 ID 这类按请求变化的值放在请求上，而不是客户端上。`anthropic.helicone.ai` 路由改用[从 Anthropic SDK 迁移](./from-anthropic)中的配置。

在 Helicone AI Gateway 上，路由写在 `model` 字符串里。把它拆开：逗号分隔的第一项成为 `model`，其余项成为 `models` 数组；`<model>/<provider>` 固定写法改为 `provider.only` 或 `provider:org/model` ID；`!provider` 排除写法改为 `provider.ignore`。

## 映射 Helicone 请求头

| Helicone | 在 Phaseo 上 |
| --- | --- |
| `Helicone-Auth` | 删除。 |
| `Helicone-Property-<Name>` | `X-Phaseo-Metadata` [标签](../guides/request-labels)：最多 32 个，键匹配 `[A-Za-z0-9_.:-]`（64 个字符），因此需要重命名含空格的属性。格式错误的 JSON 或重复的键会返回 `400`。不要在标签中放个人数据。 |
| `Helicone-User-Id` | 请求体字段 `user` 或 `X-Phaseo-User-Id`。它也是终端用户速率限制策略的键。 |
| `Helicone-Session-Id` | 请求体字段 `session_id`。它决定缓存和提供商亲和性，而不是追踪树。 |
| `Helicone-Session-Path`、`Helicone-Session-Name` | 请求体中的 `metadata.trace_id`、`parent_span_id`、`trace_name`、`span_name`，或 W3C `traceparent` 请求头。它们决定发送到可观测性目标的 span 结构；Phaseo 自己的日志没有追踪树。 |
| `Helicone-Cache-Enabled` | 没有响应缓存。如有需要请在应用中缓存。 |
| `Helicone-Fallbacks`、`Helicone-Retry-Enabled` | `models` 数组（在 `429`、`500`、`502`、`503` 和 `504` 时尝试），加上内置的提供商回退。保留客户端退避。 |
| `Helicone-RateLimit-Policy` | 速率限制策略和密钥限制。参见[限制](../api-reference/limits)。 |
| `Helicone-LLM-Security-Enabled` | 护栏的提示词注入检测，仅作用于请求。 |
| `Helicone-Moderations-Enabled` | 网关内没有对应项。请在应用中调用 `/v1/moderations`。 |
| `Helicone-Omit-Request`、`Helicone-Omit-Response` | 工作区日志策略或零数据保留。 |
| `Helicone-Posthog-*` | PostHog [可观测性目标](../guides/integrations/observability)。 |
| 提示词管理 | [预设提示词模板](../guides/prompt-templates)：`"prompt": {"id": "@slug", "version": "production", "variables": {...}}`。 |

## 迁移请求可见性

使用请求日志、请求 ID、提供商尝试和价格详情进行调试。如果团队导出遥测数据，请在切换前连接相应的[可观测性目标](../guides/integrations/observability)，避免出现空档。Helicone 的异步日志不代理流量，是否保留它与替换网关是两个独立的决定。

## 测试并上线

确认去掉 Helicone 请求头后请求仍然成功，并且团队在事故期间仍能回答常问的问题。迁移流量之前确认：

- 每个 Helicone URL 和 `Helicone-*` 请求头都已删除或映射；
- 生产模型 ID 都出现在 `GET /v1/models?format=openai` 中；
- 团队需要的告警和仪表板都有替代方案；
- 回退仍然只需更改 base URL 和密钥。
