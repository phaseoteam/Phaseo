在 AI SDK 代码中，把 `@ai-sdk/gateway` 换成 `@phaseo/ai-sdk-provider`，并用 `phaseo(...)` 包裹每个模型 ID。在 OpenAI 兼容客户端中，更改 base URL 和密钥。生成逻辑保持不变。

| 设置 | Vercel AI Gateway | Phaseo |
| --- | --- | --- |
| Base URL | `https://ai-gateway.vercel.sh/v1` | `https://api.phaseo.app/v1` |
| API 密钥 | `AI_GATEWAY_API_KEY` 或 Vercel OIDC | `PHASEO_API_KEY`，作为服务器端 secret |
| AI SDK provider | `@ai-sdk/gateway`，或裸字符串模型 | `@phaseo/ai-sdk-provider` |
| 路由选项 | `providerOptions.gateway` | `providerOptions.phaseo` |

## 切换 provider

<CodeGroup>
```typescript AI SDK
import { generateText } from "ai";
// 之前：import { gateway } from "@ai-sdk/gateway";
import { phaseo } from "@phaseo/ai-sdk-provider";

const { text } = await generateText({
  // 之前：model: gateway("openai/gpt-4.1-mini"),
  model: phaseo("openai/gpt-4.1-mini"),
  prompt: "Generate a migration checklist.",
});
```

```typescript OpenAI SDK
import OpenAI from "openai";

// 之前：
// new OpenAI({ apiKey: process.env.AI_GATEWAY_API_KEY, baseURL: "https://ai-gateway.vercel.sh/v1" });
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});
```

```bash cURL
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role":"user","content":"Hello"}]
  }'
```
</CodeGroup>

默认导出的 `phaseo` 会在模块被导入时读取一次 `PHASEO_API_KEY`，并使用 `https://api.phaseo.app/v1`。如果该变量在导入之后才设置（某些 serverless 和测试环境就是这样），每次调用都会抛出缺少密钥的错误；这时请在处理函数内部调用 `createPhaseo({ apiKey, baseURL, headers })`。

安装与你的 `ai` 主版本匹配的 provider 版本线：AI SDK 7 用 `@phaseo/ai-sdk-provider`，AI SDK 6 用 `@phaseo/ai-sdk-provider@ai-sdk-v6`，AI SDK 5 用 `@phaseo/ai-sdk-provider@ai-sdk-v5`。

AI SDK 默认会通过 Vercel 的网关发送裸字符串模型（`model: "openai/gpt-4.1-mini"`），所以遗留的裸字符串会继续调用它。先修改共享的模型工厂，再在 AI SDK 调用中搜索 `model: "`。指向 `ai-gateway.vercel.sh` 的 Anthropic SDK 客户端改用[从 Anthropic SDK 迁移](./from-anthropic)中的配置。

## 映射网关选项

`providerOptions.phaseo` 会合并到请求体中。遗留的 `providerOptions.gateway` 会被忽略，不会报错。

| Vercel AI Gateway | 在 Phaseo 上 |
| --- | --- |
| `providerOptions.gateway.order`、`.only` | `providerOptions: { phaseo: { provider: { order, only } } }`，或以 `phaseo("@slug")` 调用的[预设](../guides/presets)。 |
| `providerOptions.gateway.models` | `providerOptions: { phaseo: { models: [...] } }`，或动态路由中的回退。 |
| `providerOptions.gateway.sort`（`cost`、`ttft`、`tps`） | `provider.sort`（`price`、`latency`、`throughput`）。 |
| `providerOptions.gateway.zeroDataRetention` | `provider.require_zero_data_retention`，它会把路由限制为 ZDR 提供商。 |
| `providerOptions.gateway.user`、`.tags` | `user` 和 `X-Phaseo-Metadata` [标签](../guides/request-labels)。 |
| 请求级 `byok` 凭据 | 没有对应项。用 `phaseo byok create` 把提供商密钥添加到工作区。 |
| 文本、流式传输、工具、结构化输出、嵌入、图像、转录、语音 | provider 支持；具体能力仍取决于模型。 |
| 重排序 | AI SDK 6 和 7 版本线上的 `phaseo.rerankingModel(id)`。 |
| 托管文件引用、由提供商执行的工具 | 不支持。不支持的部分会报错，而不是被丢弃。 |
| 网关用量仪表板 | Phaseo 请求日志和 `GET /v1/generations?id=<request_id>`。结果中的提供商元数据包含请求 ID。 |

## 测试并上线

用同一组提示词分别走两条路径，比较延迟、输出格式和 token 用量。提升流量之前确认：

- 每个原先有网关密钥的运行时都设置了 `PHASEO_API_KEY`，包括 edge、服务器和预览部署；
- 主要的文本生成路径和一个流式测试在预发布环境中无需改动即可通过；
- 如果应用用到工具调用和结构化输出，它们也要通过；
- 应用层的错误映射仍然有效；
- 预发布环境中的失败请求可以通过 `GET /v1/generations?id=<request_id>` 找到，并在 `replay_supported` 为 `true` 时重放。

在功能开关或按百分比发布之后上线，先从内部流量开始。观察延迟、错误率以及 token 和成本的偏移，并至少在一个发布周期内保留旧 provider，这样回退时无需修改代码。

```bash
curl -s "https://api.phaseo.app/v1/health"
curl -s "https://api.phaseo.app/v1/models?format=openai" -H "Authorization: Bearer $PHASEO_API_KEY"
```

关于该 provider 的更多信息，请参见 [AI SDK](../guides/integrations/ai-sdk)。
