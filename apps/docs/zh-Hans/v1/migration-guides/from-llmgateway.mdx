替换 base URL 和密钥，保留请求载荷，并映射每个模型 ID：LLM Gateway 的前缀表示提供服务的提供商，而 Phaseo 的前缀表示模型的开发方。

| 设置 | LLM Gateway | Phaseo |
| --- | --- | --- |
| Base URL | `https://api.llmgateway.io/v1` | `https://api.phaseo.app/v1` |
| Anthropic 风格的客户端 | `ANTHROPIC_BASE_URL=https://api.llmgateway.io` | `https://api.phaseo.app`，参见[从 Anthropic SDK 迁移](./from-anthropic) |
| API 密钥 | `LLM_GATEWAY_API_KEY`（`llmgtwy_…`） | `PHASEO_API_KEY` |
| 模型 ID | `gpt-4o`、`<provider>/<model>`、`auto` | `GET /v1/models?format=openai` 中的 `<org>/<model>` |
| 请求载荷 | OpenAI 兼容 | 不变 |

## 切换客户端

<CodeGroup>
```typescript TypeScript
import OpenAI from "openai";

// 之前：
// new OpenAI({ apiKey: process.env.LLM_GATEWAY_API_KEY, baseURL: "https://api.llmgateway.io/v1" });
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});
```

```python Python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
)
```

```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```
</CodeGroup>

映射或删除每个 `LLM_GATEWAY_*` 变量，包括 CI 和托管设置中的变量。如果应用使用 `@llmgateway/ai-sdk-provider`，请按[从 Vercel AI Gateway 迁移](./from-vercel)中的说明切换到 `@phaseo/ai-sdk-provider`。

## 映射模型 ID

列出 Phaseo 的 ID，并用它们核对每个生产模型：

```bash
curl -s "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY" | jq -r '.data[].id'
```

LLM Gateway 上的 `alibaba/<model>` 不是 Phaseo ID。把每个 ID 映射到 Phaseo 的 `<org>/<model>`，并用 `provider.only` 或 `provider:org/model` ID 保留提供商固定。像 `gpt-4o` 这样不带前缀的别名，请在客户端边界用一个函数统一转换，而不是在每个调用处转换。

## 映射网关功能

| LLM Gateway | 在 Phaseo 上 |
| --- | --- |
| `auto` 路由器 | `phaseo/auto`（[自动路由](../guides/auto-routing)，alpha）；不能与 `models` 一起使用。 |
| 回退链 | `models` 数组或动态路由，在 `429`、`500`、`502`、`503` 和 `504` 时尝试，请求错误时从不触发。 |
| `X-No-Fallback` | `provider.allow_fallbacks: false`，或 `provider:org/model` ID。 |
| 提供商允许和拒绝逻辑 | `provider.only`、`provider.ignore` 或[预设](../guides/presets)。至少保留一个符合条件的提供商。 |
| `X-LLMGateway-<Key>` 请求头 | `X-Phaseo-Metadata` [标签](../guides/request-labels)，最多 32 个。 |
| 会话请求头（`x-session-id`） | 请求体字段 `session_id`；Phaseo 会忽略会话请求头。 |
| `X-Source` | `HTTP-Referer` 或 `X-App-Name`。参见[应用归因](../guides/app-attribution)。 |
| 响应缓存 | 没有响应缓存。 |
| 提供商密钥 | BYOK（`phaseo byok create` 或 `POST /v1/byok`），或 Phaseo 额度。是否回退到额度由工作区设置 `byok_fallback_enabled` 决定。 |
| 请求日志 | 请求日志、可观测性目标和 `GET /v1/generations?id=<request_id>`。当 `replay_supported` 为 `true` 时，可以用失败请求的 `replay_request` 载荷重放它。 |

## 测试并上线

用你的黄金提示词集分别调用两个网关，比较质量、延迟和成本。先检查接口：

```bash
curl -s "https://api.phaseo.app/v1/health"
curl -s "https://api.phaseo.app/v1/models?format=openai" -H "Authorization: Bearer $PHASEO_API_KEY"
```

迁移流量之前确认：

- 每个环境都设置了 `PHASEO_API_KEY`；
- 每个生产模型 ID 都已映射并出现在列表中；
- 一个非流式请求和一个流式请求在预发布环境中通过；
- 已处理无效密钥和无效模型错误；它们的响应体可能与 LLM Gateway 不同；
- 预发布环境中的失败请求可以通过 `GET /v1/generations` 找回；
- 共享的提示词和路由默认设置放在了预设中。

在金丝雀开关后发布，稳定后从一小部分流量扩大到全部流量，并在删除旧配置之前至少观察一个发布周期的生产指标。
