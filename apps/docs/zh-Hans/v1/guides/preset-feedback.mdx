把每条用户评分连同请求 ID 和给出回答的[预设](./presets.mdx)一起发送到 `POST /v1/feedback`，然后按回答获得好评的频率来比较预设，而不只是比较延迟和成本。

<Note>
Preset Feedback 目前处于 Alpha 阶段，API 和控制台仍可能变化。请使用 [Preset Feedback 页面](https://phaseo.app/settings/presets/experiments)上的 **反馈** 按钮告诉我们怎样让它更有用。
</Note>

## 记录一条评分

你需要一个具有 `feedback:write` 能力的 API 密钥、Phaseo 返回的请求 ID，以及预设的 UUID。有了预设 ID，事件才会进入预设比较和群组分析。

```bash cURL
curl https://api.phaseo.app/v1/feedback \
  -X POST \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "requestId": "gen_01K...",
    "presetId": "8f54b2d9-9ba3-4ced-8a7f-9bb70a44dbea",
    "rating": "thumbs_up",
    "score": 1,
    "comment": "The answer resolved the customer question.",
    "metadataDimensions": {
      "plan": "pro",
      "surface": "support_chat"
    }
  }'
```

一个反馈事件必须至少指向一个请求、会话、预设或测试运行。`score` 是可选的，取值必须在 `0` 到 `1` 之间。

把套餐、部署、语言区域或应用界面这类基数较低的值放在 `metadataDimensions` 中，这样就可以按它们筛选。任意的或基数较高的上下文则放在 `metadata` 中。

## 选择评分

| 信号 | `rating` |
| --- | --- |
| 简单的用户反应 | `thumbs_up`、`thumbs_down` |
| 经过评估的回答 | `correct`、`partly_correct`、`incorrect` |
| 运行问题 | `bad_format`、`too_slow`、`too_expensive` |
| 安全结果 | `unsafe`、`refused_incorrectly` |
| 其他情况 | `not_helpful`、`other` |

优先使用明确的评分，而不是只给一个数值分数：预设比较基于评分构建，分数只作为辅助信息显示。

## 比较预设

打开[设置 → 预设 → 反馈](https://phaseo.app/settings/presets/experiments)，你可以：

- 比较正面、部分正确和负面的比例
- 选择一个基准预设
- 按日期、评分和元数据维度筛选
- 查看某个事件背后的请求、会话、评论和标签

控制台在所选时间范围内最多分析最近 10,000 条匹配的反馈记录。

## 通过 API 读取反馈

读取需要 `feedback:read`。结果仅限于已认证的工作区以及调用方可见的预设。

列出最近的事件：

```bash
curl "https://api.phaseo.app/v1/feedback?preset_id=PRESET_UUID&limit=100" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

获取在服务器端计算的汇总：

```bash
curl "https://api.phaseo.app/v1/feedback/summary?group_by=preset&since=2026-08-01T00:00:00Z" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

测试运行和自定义结果事件的 API 已经可用，但它们的控制台视图仍在调整。要逐步发布预设变更，请参见[发布预设并调试路由](../cookbook/preset-rollout-and-routing-debug)。
