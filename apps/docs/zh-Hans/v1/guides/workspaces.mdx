为每个团队、产品或环境创建一个工作区，让它的 API 密钥、路由设置、预设、护栏和管理访问权限相互独立。每个账户一开始都有一个个人工作区，对于小型集成来说已经足够。

在以下情况下，单独的工作区会很有帮助：

- 隔离开发、预发布和生产环境的凭据
- 让不同产品或客户项目相互分开
- 只给管理集成授予它所需资源的访问权限
- 应用不同的路由、预设或护栏策略

工作区不会改变你的定价：所有用量都按标准的按量付费计费，详见[定价与计费](../pricing/tiers)。首次充值额度之后才能创建更多工作区；在此之前，创建会以 `403 workspace_upgrade_required` 失败。

## 通过 API 管理工作区

可以在控制台中或通过管理 API 管理工作区。该 API 需要[管理密钥](../developers/management-api-keys)；普通的 Gateway API 密钥用于推理，无法调用这些端点。

| 任务 | 端点 | 权限 |
| --- | --- | --- |
| 列出工作区 | [`GET /workspaces`](../api-reference/endpoint/workspaces-list) | `workspaces:read` |
| 读取工作区 | [`GET /workspaces/{id}`](../api-reference/endpoint/workspaces-get) | `workspaces:read` |
| 创建工作区 | [`POST /workspaces`](../api-reference/endpoint/workspaces-create) | `workspaces:write` |
| 更新工作区 | [`PATCH /workspaces/{id}`](../api-reference/endpoint/workspaces-update) | `workspaces:write` |
| 删除工作区 | [`DELETE /workspaces/{id}`](../api-reference/endpoint/workspaces-delete) | `workspaces:delete` |

只给密钥授予它所需的权限。Phaseo 还会检查工作区成员身份和角色，因此仅凭某项权限永远无法访问另一个工作区。新工作区的 `slug` 必须由 1 到 50 个小写字母、数字或短横线组成。

把管理密钥保存在服务器端的密钥存储中，绝不要放在浏览器代码、桌面日志、源代码管理或聊天中。

<Note>
工作区端点目前处于 Beta 阶段。请确保自动化可以安全重试，并在进行后续更改之前检查每个响应。
</Note>

## 重命名或删除工作区

个人（默认）工作区无法重命名或删除；这两种操作都会返回 `400 bad_request`。删除其他工作区之前，请移除或迁移其有效的 API 密钥，以免有请求指向已不存在的工作区。
