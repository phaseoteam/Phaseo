开启 Gateway I/O 日志后，Phaseo 会存储每个请求的提示词和响应。你可以在聊天中打开任何已存储的 Chat Completions、Responses 或 Messages 请求，查看它的呈现效果，并从那里使用同一模型或其他模型继续对话。

## 开始之前

- 在**设置 → 隐私**中开启**存储请求和响应负载**。只有在开启期间发出的请求才能打开。
- 开启**要求零数据保留**后，工作区从不存储提示词或响应；使用其护栏要求零数据保留的 API 密钥发出的请求也不会存储。这些请求无法打开。
- 发送到[区域端点](./regional-routing.mdx)（`eu.api.phaseo.app` 和 `us.api.phaseo.app`）的请求不会存储，因此无法打开。
- 你需要是该请求所属工作区的成员。如果**谁可以查看内容**设为**所有者和管理员**，则只有所有者和管理员可以打开其请求。

## 打开请求

| 位置 | 方法 |
| --- | --- |
| 请求详情 | 选择详情顶部的**在聊天中打开**。 |
| 请求日志 | 右键点击某个请求，然后选择**在聊天中打开**。 |
| 会话详情 | 选择**在聊天中打开**以从最新轮次继续，或选择某一行上的聊天图标以从该轮次继续。 |

会话的每个轮次都已包含截至该点的对话，因此打开某个轮次时也会打开它之前的所有内容。

聊天打开的链接只包含请求 ID，因此你可以把它分享给工作区的其他成员。聊天会为每位打开链接的人重新加载该请求，并使用其本人的访问权限。

## 选择要沿用的内容

在创建聊天之前，聊天会显示请求包含哪些内容以及哪些内容会被保留。

| 选项 | 作用 |
| --- | --- |
| 固定提供商 | 将后续轮次发送给处理该请求的提供商。默认关闭，因此路由会照常选择提供商。 |
| 参数 | 保留 temperature、最大 token 数、top-p 和 top-k、seed、惩罚项、推理和服务层级。 |
| 系统提示 | 保留请求的系统指令或开发者指令。 |
| 服务器工具 | 保留请求使用过的 Phaseo 服务端工具，例如网页搜索。 |
| 函数工具 | 声明请求自身的函数工具，使之前的工具调用保持有效。聊天无法运行这些工具。如果不包含它们，之前的工具调用和结果会以文本形式发送。 |
| 已记录的回复 | 包含该请求收到的响应。不包含时，会为同一对话生成新的响应。 |

如果请求所用的模型在聊天中不可用，聊天会改用你当前的模型。聊天打开后，你可以更换模型。

## 聊天如何继续

- 请求会作为一个新聊天打开，拥有自己的会话 ID，并像其他聊天一样保存在你的浏览器中。后续轮次不会加入日志中的原始会话。
- 你未编辑的消息会以原始形式发送，因此工具调用、工具结果、图片、音频和文件会在下一轮中保留。编辑过的消息和新消息会以文本形式发送，与任何聊天相同。
- 与任何聊天一样，你可以切换模型、并排比较多个模型、创建分支或编辑。
- 后续轮次在你当前的工作区中运行，并像其他聊天请求一样计费。

## 无法沿用的内容

在你继续之前，聊天会列出所有无法沿用的内容：

- 由提供商通过 `previous_response_id` 或对话 ID 保存的轮次。只有请求本身中的轮次会被存储。
- 通过文件 ID 或远程引用而非内联方式发送的附件。
- 失败、被截断或提供了多个选项的响应（只保留第一个）。
- 从未收到结果的工具调用。这些会以文本形式发送。
- 聊天无法显示的内容类型，例如提供商特定的块。

过大而无法存储的请求，以及存储内容已过期或已被删除的请求，都无法打开。聊天中只能打开文本请求，无法打开图片、音频、视频和嵌入请求。
