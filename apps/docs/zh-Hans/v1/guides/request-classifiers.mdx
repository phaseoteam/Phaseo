定义一套分类体系（例如部门、受众或任务类型）以及执行分类的模型，Phaseo 就会用该模型的回答为每个已完成的请求打标签。每个回答都会作为[请求标签](/zh-Hans/v1/guides/request-labels)保存，因此你可以像使用代码发送的标签一样，按它筛选和分组日志、用量和分析数据。当你的代码不知道类别时，就使用分类器：例如提示词是为谁写的、智能体正在做哪类工作，或者请求是否涉及受监管的主题。

<Note>
请求分类器目前处于 Beta 阶段。所有者和管理员可以在 **设置 → 分类器** 中管理它们，或使用 `/v1/classifiers` 管理 API，并配合具有 `classifiers:*` 权限范围的[管理密钥](/zh-Hans/v1/developers/management-api-keys)。
</Note>

## 请求如何被分类

1. 请求完成，响应返回给你的应用。分类永远不会增加延迟。
2. Phaseo 为请求构建一份记录：系统指令、消息、工具名称（不含其 schema）和工具结果。每一轮最多 4,000 个字符，API 密钥等机密信息会被脱敏。如果分类器包含响应，生成的输出也会被加入。
3. 分类器模型从你的取值中进行选择。超出这些取值的任何回答都会被丢弃（参见[选择模型](#choose-a-model)）。
4. 在请求出现在你的日志中之前，这些回答会连同各自的置信度一起作为标签保存到请求上。

分类器在成功的 `chat/completions`、`responses` 和 `messages` 请求上运行。如果分类失败或超时，请求仍会被记录，只是不带这些标签。

## 创建分类器

可以在控制台中从预设开始，也可以自己发送分类体系：

```bash
curl https://api.phaseo.app/v1/classifiers \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Department",
    "model": "google/gemini-2.5-flash-lite",
    "dimensions": [{
      "key": "department",
      "name": "Department",
      "allow_other": true,
      "values": [
        { "value": "engineering", "description": "Writing, reviewing, or debugging code" },
        { "value": "legal", "description": "Contracts, policies, and compliance" },
        { "value": "sales" },
        { "value": "support" }
      ]
    }],
    "sample_rate": 0.25,
    "monthly_budget_usd": 20
  }'
```

| 字段 | 含义 |
| --- | --- |
| `dimensions` | 1 到 12 个问题。每个 `key` 成为标签键；每个维度列出 2 到 50 个取值（设置 `allow_other` 时可以只有 1 个）。 |
| `multiple` | 允许一个维度有多个取值。每个取值成为一个使用相同键的独立标签。 |
| `allow_other` | 当没有合适的取值时，允许模型回答 `other`。 |
| `instructions` | 添加到分类提示词中的额外指引，最多 8,000 个字符。 |
| `sample_rate` | 要分类的符合条件请求的比例，从 `0.0001` 到 `1`。 |
| `sample_by` | `request` 对每个请求单独采样。`session` 让一个会话整体被选中或不被选中，并在一小时内复用其回答，因此一次较长的智能体运行只会被分类一次。 |
| `input_scope` | `prompt` 只对请求进行分类。`prompt_and_response` 还会把响应提供给模型。 |
| `scope` | 只对来自这些 `key_ids`、`app_ids` 或 `models` 的请求进行分类，每类最多 50 个。 |
| `monthly_budget_usd` | 一旦花费达到该金额，就在该 UTC 月份的剩余时间内暂停分类器。 |

一个工作区最多可以有五个分类器。更改大约一分钟内会生效到 Gateway。

## 选择模型

任何文本模型或[决策模型](/zh-Hans/v1/api-reference/endpoint/decisions)都可以用于分类。Phaseo 会根据模型的提供商支持什么来决定如何向它提问：

| 模型 | 提问方式 |
| --- | --- |
| 支持结构化输出的文本模型 | 一个使用严格 JSON schema 的 `responses` 请求，因此每个回答都是你的取值之一。 |
| 决策模型 | 一个 `decisions` 请求，每个维度一个选择题。设置了 `multiple` 的维度会对每个取值问一个是/否问题，并保留概率至少为 0.5 的所有取值（如果一个分类器需要超过 128 个问题，这类维度只取其最佳的单个取值）。置信度就是模型自己给出的概率。 |
| 其他文本模型 | 一个在提示词中要求相同 JSON 的 `responses` 请求。超出你取值范围的回答会被丢弃，因此某个维度更可能没有标签。当提供商拒绝 schema 时，这也是回退方式。 |

通常一个小而快的模型就足够了。保存前，可以在分类器编辑器中使用 **用示例试一试** 来检验模型。

## 按结果筛选和分组

分类器的回答就是普通的请求标签：

- 在 **日志** 和 **用量** 中，按 `department` = `legal` 这样的标签筛选。
- 通过 API，使用 `label_key` 和 `label_value`：

```text
GET /v1/analytics?label_key=department&label_value=legal
```

- [Broadcast](/zh-Hans/v1/guides/integrations/observability) 目标会以 `phaseo.label.<key>` span 属性的形式收到标签。

如果你的代码已经发送了与某个维度键相同的标签，Phaseo 会保留你的值并跳过该维度。当两个分类器使用相同的键时，以先创建的那个为准。

## 成本与隐私

- 每次分类都是对分类器模型的一个独立请求，使用与原始请求相同的 API 密钥或 OAuth 令牌。它按该模型的正常价格计费，并遵循你工作区的提供商、数据保留和 BYOK 设置。
- 分类器请求带有标签 `phaseo.classifier`，其值为分类器 ID，因此你可以在 **用量** 中看到它们的花费。它们本身不会被分类，也不计入你的速率限制策略。
- 使用小而快的模型、采样率、会话采样、范围或月度预算来控制成本。
- 记录只会发送给分类器模型。分类器请求会像其他请求一样被记录，因此其输入是否被保存取决于你工作区的日志设置。
