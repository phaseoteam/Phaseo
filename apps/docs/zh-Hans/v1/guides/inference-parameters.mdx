在每个请求上设置 `temperature`、`top_p` 和输出上限，以在多样性与可重复性、长度与成本之间进行取舍。模型的[量化](./quantization.mdx)决定质量上限；这些参数决定模型在该上限内如何选择下一个 token。

```json
{
  "model": "openai/gpt-6-astra",
  "messages": [{ "role": "user", "content": "Extract the invoice total as JSON." }],
  "temperature": 0.1,
  "top_p": 1,
  "max_tokens": 200
}
```

本页说明每个控制项的作用以及从哪里开始调整。各端点上每个字段的类型、可接受的值和默认值，请参阅[参数参考](../api-reference/parameters.mdx)。

## 控制随机性

| 参数 | 作用 | 说明 |
| --- | --- | --- |
| `temperature` | 调整整体随机性。越高越多样，越低越确定。 | 通常是第一个要调整的参数。 |
| `top_p` | 只从概率累加达到 `top_p` 的最可能 token 中采样。越低输出越稳妥、越集中。 | 常与适中的 temperature 搭配使用。 |
| `top_k` | 只从最可能的 `k` 个 token 中采样。越低输出越收敛、越可预测。 | 并非所有提供商都支持。 |
| `seed` | 固定随机种子，使调试和测试时的运行结果更可重复。 | 仅在提供商支持时有效。 |

`temperature` 和 `top_p` 都会改变随机性，因此一次只调整其中一个。低比特量化模型如果随机性很高，输出可能明显不稳定。

## 减少重复

| 参数 | 作用 | 说明 |
| --- | --- | --- |
| `frequency_penalty` | 抑制重复的 token 和短语。 | 减少重复循环。 |
| `presence_penalty` | 鼓励出现新的 token 和话题。 | 适合更广泛的探索。 |
| `repetition_penalty` | 惩罚重复的文本。 | 目标与上述惩罚项相同；具体效果取决于提供商和模型。 |

## 限制和停止输出

输出上限在 Chat Completions 和 Anthropic Messages 中为 `max_tokens`，在 Responses 中为 `max_output_tokens`。它会限制成本和延迟；设置得太低，回答就会被截断。以 `finish_reason: "length"` 提前结束的响应是触及了输出上限，而不是模型故障。

`stop` 接受会结束输出的序列，便于为输出划定边界并进行解析。各端点的字段请参阅[输出长度与停止](../api-reference/parameters.mdx#output-length-and-stopping)。

## 提供商不支持某个参数时

并非每个提供商都支持 `top_k`、`seed`、`stop` 或各惩罚项。如果处理请求的提供商不支持，Phaseo 会丢弃该参数而不是拒绝请求，并在 `X-Phaseo-Dropped-Params` 响应头中列出它。输出上限永远不会被丢弃。完整列表请参阅[不支持的参数](../api-reference/parameters.mdx#unsupported-parameters)。

## 从这些值开始

| 任务 | 起始设置 |
| --- | --- |
| 提取、分类、JSON | `temperature` `0.0` 到 `0.2`，较窄的采样 |
| 通用助手回复 | `temperature` `0.3` 到 `0.7`，`top_p` `0.9` 到 `1.0` |
| 创意写作 | 更高的 `temperature` 和更宽的采样，并更仔细地评估 |

根据每个任务预期的输出大小设置 `max_tokens`，而不是为所有任务使用同一个大值。分别调整每个任务，而不是用一套配置应对所有情况。对于创意任务，请逐步提高随机性，并人工审阅输出。

## 识别不合适的设置

| 症状 | 可能的原因 |
| --- | --- |
| 事实前后不一致、结构化输出不稳定 | 随机性过高 |
| 回复重复或平淡 | 确定性过高 |
| 措辞别扭、话题偏离 | 惩罚项过高 |
| 回答被截断，`finish_reason: "length"` | 输出上限过低 |

## 调整参数

<Steps>
<Step title="先选择模型和量化">
请参阅[量化](./quantization.mdx#pick-a-precision)。
</Step>
<Step title="固定一套评估集">
每次运行都使用相同的提示词，使结果具有可比性。
</Step>
<Step title="一次只改一个参数">
比较每个取值下的质量、延迟和 token 用量。
</Step>
<Step title="按任务保存结果">
为每个端点或用例保留单独的[预设](./presets.mdx)，让调用方继承调好的默认值。
</Step>
</Steps>
