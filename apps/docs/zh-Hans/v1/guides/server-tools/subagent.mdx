description: "让主模型把专注的工作委派给工作模型。"
---

添加 `phaseo:subagent`，主模型就能在同一个请求中把一个独立任务交给工作模型（通常是更小或更快的模型）。主模型描述任务；Phaseo 运行工作模型并返回其结果，再由主模型完成回答。

```bash
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-opus-5",
    "messages": [
      { "role": "user", "content": "Compare these release notes and summarize the breaking changes." }
    ],
    "tools": [
      {
        "type": "phaseo:subagent",
        "parameters": {
          "model": "openai/gpt-6-astra",
          "instructions": "Return concise findings for the main model. Do not address the end user directly.",
          "max_uses": 3,
          "max_completion_tokens": 1200
        }
      }
    ]
  }'
```

## 参数

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `model` | string | 请求的模型 | 工作模型。 |
| `instructions` | string | 内置的工作模型指令 | 给工作模型的额外指令。 |
| `max_uses` | integer | `1` | 每个请求中的 Subagent 调用次数。 |
| `max_completion_tokens` | integer | `1400` | 每次工作模型回复的输出 token 数。低于 `1024` 的值会被提高到 `1024`。`max_tokens` 作为旧别名仍被接受。 |
| `reasoning` | object | 提供商默认值 | 推理设置，在工作模型支持时传递。 |
| `temperature` | number | 提供商默认值 | 工作模型调用的采样温度。 |

工作模型永远不会收到对话内容：请把它需要的一切都写进任务中。

## 模型发送的内容

一个 `task_description`，包含完整的任务、上下文和预期输出，另外还可以带一个简短的 `task_name`：

```json
{
  "task_description": "Extract the three highest-risk migration steps from the supplied plan."
}
```

`task`、`prompt` 或 `input` 也可以代替 `task_description`。

## 工具返回的内容

```json
{
  "status": "ok",
  "model": "openai/gpt-6-astra",
  "outcome": "The highest-risk steps are schema migration, traffic cutover, and rollback verification."
}
```

如果调用无法执行，模型会收到 `subagent_invalid_request`（没有任务）、`subagent_max_uses_exceeded` 或 `subagent_request_failed`。

## 用量和价格

每次调用会使 `usage.server_tool_use.subagent_requests` 加 1，并可通过 `server_tool_subagent_requests` 计费。工作模型的 token 按该模型自身的费率计费，作为请求账单中的单独一项，不会计入调用模型的 token 数。即使调用模型免费，使用付费工作模型也需要账户有余额。如需审阅而非委派工作，请使用 [Advisor](./advisor)。
