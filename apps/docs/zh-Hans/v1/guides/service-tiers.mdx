在文本请求上设置 `service_tier`，即可付费获得更快的交付（`fast`、`ultrafast`），或接受更便宜、优先级更低的模式（`flex`）。Phaseo 随后只会路由到为该模型提供此层级的提供商。该字段在 `/v1/chat/completions`、`/v1/responses` 和 `/v1/messages` 上的用法相同。

```json
{
  "model": "openai/gpt-5.5",
  "input": "Summarise this incident report.",
  "service_tier": "fast"
}
```

| 层级 | 请求方式 | 适用场景 |
| --- | --- | --- |
| Standard | 不设置，或 `"standard"` / `"default"` | 一般的生产流量 |
| Fast | `"fast"`，或其别名 `"priority"` | 提供商的高级或更高优先级报价 |
| Ultrafast | `"ultrafast"` | 速度最快的报价 |
| Flex | `"flex"` | 成本更低的报价（如果提供商有的话） |
| Batch | [Batch API](../api-reference/endpoint/batches-create.mdx)，而不是 `service_tier` | 大型延后处理的工作负载 |

层级仅适用于文本模型，并且只在模型和提供商支持时可用。在 Phaseo 有相关数据时，模型页面会显示各层级的价格。

## 没有提供该层级时会怎样

Phaseo 只保留提供所请求层级的提供商路由；它永远不会回退到其他层级。如果没有路由提供该层级，请求会失败并返回 `400 unsupported_model_or_endpoint`，原因为 `service_tier_not_supported`。

其他取值会以 `400 validation_error` 失败：

- 在同步请求上设置 `service_tier: "batch"`（关键字 `batch_service_tier_not_supported`）。请改用 Batch API。
- 除 `standard`、`default`、`fast`、`ultrafast`、`priority`、`flex` 或 `batch` 以外的任何值（关键字 `unsupported_service_tier`）。

你始终发送这些 Gateway 取值。Phaseo 会把它们转换成各个提供商自己的控制项，例如 Anthropic 路由会收到 Anthropic 的层级字段。

## 在各个端点上请求层级

<CodeGroup>
```json Responses
{
  "model": "openai/gpt-5.5",
  "input": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "flex"
}
```

```json Chat Completions
{
  "model": "openai/gpt-5.5",
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "flex"
}
```

```json Messages
{
  "model": "anthropic/claude-opus-5.5",
  "max_tokens": 512,
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "fast"
}
```
</CodeGroup>

使用 `ultrafast` 时，请选择页面上列出了 Ultrafast 价格的模型。

## Mistral Priority 与欧盟路由

Mistral Priority Tier 需要符合条件的 Mistral 企业账户。Phaseo 会把 `priority` 映射到 Mistral 的自动优先模式，并按 Mistral 报告的层级计费：如果 Mistral 回退到 Standard，你就按 Standard 价格付费。

目录中有价格并不意味着该层级可以路由。除非具体的 Mistral 路由声明支持 Priority，否则 Priority 保持关闭；是否符合条件仍取决于 Mistral 账户和模型。

使用 `mistral-eu` 提供商报价，可以把 GLM 5.2 固定到 Mistral 的欧盟区域端点：

```json
{
  "model": "z-ai/glm-5.2",
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "priority",
  "provider": {
    "only": ["mistral-eu"],
    "required_execution_region": "eu"
  }
}
```

Mistral 区域推理的费用高 10%。Batch 价格只在通过 Batch API 使用的全球 Mistral 报价上提供；Mistral 不支持在区域端点上使用 Batch。

完整的字段参考见[参数](../api-reference/parameters.mdx)；关于层级如何与提供商顺序和回退结合，请参见[路由与回退](./routing-and-fallbacks.mdx)。
