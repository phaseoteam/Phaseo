获批提供商可以自行更新公开规范模型的报价。新模型需要审批。每份目录都是完整快照：删除的报价会停用，历史价格仍然保留。

## 选择格式

没有版本字段的 V1 数据源继续有效。`"schema_version": "1.0"` 也表示 V1。V1.1 声明 `"schema_version": "1.1"`，并为每个模型提供 `service_tiers` 数组。版本由文档决定，而不是 URL 查询参数。

每个模型必须提供 `standard`。其他允许的层级是 `fast`、`ultrafast`、`flex` 和 `batch`。每个层级包含 `service_tier`、`provider_model_slug`、`availability` 和 `pricing`。功能、限制和发布日期由模型共享。

Fast、Ultrafast 和 Flex 支持文本生成。使用不同的上游模型 ID 或 `upstream_service_tier` 来选择实际层级。Fast 接受 `fast` 或 `priority`；Standard 接受 `default` 或 `standard`。Batch 使用独立的 Batch API，仍然需要提供商 Batch 集成和对应功能。

## 价格与更新

每个层级必须明确列出所有计费单位的价格。`price_nanos` 是优惠后的实际价格。零价格有效；负数价格、未知单位、重复层级和条件价格会被拒绝。价格变化时发布新快照，历史价格会保留。

轮询和签名 Webhook 支持两种版本。在提供商设置中，先选择层级再编辑。模型映射错误会单独显示，不会阻止有效模型导入。

完整示例和 JSON Schema 请参阅[英文契约指南](/v1/guides/provider-catalog)。

API 目录中的手动编辑会持续保留。导入只更新没有手动覆盖的字段。选择**使用数据源值**可取消覆盖。页面显示数据源值、生效值、编辑者和时间；活动记录编辑与恢复。手动添加的模型保留为本地报价。模型从数据源删除后，其报价会停用，即使部分字段曾被编辑。纯手动目录仍受支持。

## 速率限制

在可选的顶层数组 `rate_limits` 中声明你的平台对 Phaseo 账户施加的请求数和令牌数上限，V1 和 V1.1 均适用。省略 `model` 表示适用于所有模型的限制，或填写同一文档中某个模型或层级的 `provider_model_slug`。每个条目接受 `requests_per_minute`、`requests_per_day`、`tokens_per_minute` 和 `tokens_per_day`，取值为正整数或 `null`，且至少有一个值。模型限制与所有模型的限制同时生效。

```json
{
  "rate_limits": [
    { "requests_per_minute": 600, "tokens_per_minute": 2000000 },
    { "model": "example-model", "requests_per_day": 100000 }
  ]
}
```

限制绝不会阻止请求：达到上限时，Phaseo 会降低你的报价排名，并优先将流量发送给其他提供商。因此，在你的申请获批后，限制无需审核即可生效，通常在一分钟内。数组存在时，每次成功导入已更改的数据源都会替换你的限制；`[]` 会移除限制，省略该数组则保留在提供商设置中定义的限制。如果某个条目引用了不存在的模型、重复了范围或使用了无效值，整个快照都会被拒绝。你也可以在 **提供商设置 → 你的模型 → 速率限制** 中编辑。
