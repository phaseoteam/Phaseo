获批提供商可以通过目录数据源或提供商设置，更新现有公开规范模型的报价。新的规范模型需要审批。每份目录都是完整快照：删除某个报价会停用这个由数据源管理的报价，并保留其价格历史。

## 选择格式

现有 V1 数据源无需更改即可继续使用。未声明版本的 `{"data": [...]}` 文档，或声明了 `"schema_version": "1.0"` 的文档，使用现有的标准层级格式。

V1.1 声明 `"schema_version": "1.1"`，并在每个模型中发布 `service_tiers`。导入程序根据文档本身选择格式。`?format=phaseo-v1.1` 等 URL 查询参数只是你的端点可选采用的约定；Phaseo 不会根据 URL 推断版本。

下载 [V1 Schema](https://phaseo.app/api/internal/provider-catalog/schema) 或 [V1.1 Schema](https://phaseo.app/api/internal/provider-catalog/schema?version=1.1)。不受支持的版本会被明确拒绝。

### V1.2 数据政策（预览）

V1.2 为每个服务层级添加按能力划分的训练和保留声明。发布这些字段前，请与 Phaseo 协调启用时间；旧版导入器会拒绝这些字段。V1 和 V1.1 数据源仍受支持。

V1.2 还接受模型级或层级级的可选 `declarations`，用于描述模型标识、类型化输入/输出限制、参数说明、按范围划分的价格和容量、折扣及部署详情。这些声明会经过验证并保留以供审核，不会自动启用参数，也不会更改计费价格、容量限制的执行方式或数据驻留保证。验证结果会标识已存储的声明；请继续通过现有字段发布实际生效的价格和能力。

将 `schema_version` 设为 `"1.2"`，并为每个适用层级添加 `data_policy` 对象：

```json
{
  "capabilities": [{
    "id": "text.generate",
    "training_policy": "no_train",
    "retention_mode": "none",
    "retention_days": 0,
    "zero_data_retention": true,
    "zdr_eligibility": "eligible",
    "requirements": { "contract_mode": "none", "account_settings": [] },
    "privacy_policy_url": "https://provider.example/privacy",
    "terms_of_service_url": "https://provider.example/terms"
  }]
}
```

此示例是层级的 `data_policy` 值，并非完整数据源。能力 ID 使用规范标识：即使模型声明了 `responses` 或 `chat.completions`，也应使用 `text.generate`。

声明涵盖整个上游处理链中的提示和输出，不描述计费元数据。训练值包括 `unknown`、`may_train`、`no_train`、`opt_out_available` 和 `enterprise_no_train`。保留模式包括 `unknown`、`none`、`transient`、`fixed` 和 `until_deleted`。none 使用零天，transient/fixed 使用正数的最长保留时长，unknown/until-deleted 使用 null。

通过 `contract_mode` 声明所需协议：`none`、`customer_agreement` 或 `enterprise_agreement`。所需账户设置以对象形式放入 `account_settings` 数组，对象包含 `id`、`description` 和 HTTPS `documentation_url`。有条件的计划使用 `zdr_eligibility: "conditional"`，不能将有效保证声明为 true。在 Phaseo 能验证条件已满足之前，这些信息仅供参考。

Phaseo 独立审批政策来源。数据源不能将声明标记为已验证。本版本仅对不进行训练、不保留内容且无附加条件的非批处理文本生成提供有效 ZDR。自行托管模型本身并不构成 ZDR 声明。

某个服务方案采用数据源管理的政策后，设为 false、发送 null、省略声明或降低数据源版本都会撤回该保证。Phaseo 的手动覆盖单独管理。如果连续 24 小时未成功验证目录，肯定性声明就会失效；撤销审批不需要重新抓取提供商数据。

## 发布标准化层级

| 层级 | 含义 |
| --- | --- |
| `standard` | 常规同步执行；每个模型都必须提供。 |
| `fast` | 更快或优先级更高的报价。HighSpeed 等提供商自有名称保留在上游模型 ID 中。 |
| `ultrafast` | 在支持时提供的独立、更高速报价。 |
| `flex` | 灵活、优先级较低的同步报价。 |
| `batch` | 通过 Batch API 异步执行。需要具备批处理能力。 |

不要将提供商特定的层级名称用作标准化 ID。`priority` 仍是调用方可用的 Fast 别名；目录中应发布 `fast`。

文本生成请求支持选择 Fast、Ultrafast 和 Flex。Batch 通过独立的 Batch API 运行，仍需要已安装的提供商 Batch 集成；发布层级并不会安装该集成。对于上传的提供商原生文件，请使用声明的 Batch 模型 ID，或以内联方式提交请求，以便 Phaseo 进行转换。

同一模型的各个服务层级使用相同的规范模型 ID。不同的模型需要各自独立的规范标识。层级会继承模型的能力、限制和发布时间表。每个层级各自声明上游模型 ID、可用性和生效价格。

```json
{
  "schema_version": "1.1",
  "data": [{
    "id": "your-provider/example-model",
    "name": "Example model",
    "capabilities": ["chat.completions"],
    "service_tiers": [{
      "service_tier": "standard",
      "provider_model_slug": "example-model",
      "availability": "ready",
      "pricing": [{
        "meter_key": "input_text_tokens",
        "modality": "text",
        "direction": "input",
        "unit": "token",
        "unit_quantity": 1000000,
        "price_nanos": 100000000,
        "display_label": "Input",
        "display_unit": "1M tokens"
      }, {
        "meter_key": "output_text_tokens",
        "modality": "text",
        "direction": "output",
        "unit": "token",
        "unit_quantity": 1000000,
        "price_nanos": 200000000,
        "display_label": "Output",
        "display_unit": "1M tokens"
      }]
    }]
  }]
}
```

要添加 Fast，请再添加一个层级对象，其中包含 `"service_tier": "fast"`、该层级的生效价格，以及该报价独有的上游模型 ID。如果提供商改用原生参数选择通道，请使用相同的上游模型 ID，并声明 `"upstream_service_tier": "priority"` 或 `"fast"`。如果由模型 ID 选择通道，请省略该字段。Standard 接受 `default` 或 `standard`；Flex 和 Ultrafast 接受各自对应的值。如果非标准同步层级既没有独立的模型 ID，也没有原生选择器，Phaseo 会拒绝该层级。

每个层级都需要明确的价格，包括输出以及你计费的所有缓存/媒体计量项。零价格有效；负数价格、未知计量项、重复层级和条件费率会被拒绝。`price_nanos` 仍表示优惠后的生效价格。费率变化时请发布新快照；Phaseo 会保留以前的生效价格。

## 声明速率限制

在可选的顶层数组 `rate_limits` 中声明你的平台对 Phaseo 账户施加的请求数和 token 数上限。该数组在 V1 和 V1.1 文档中的用法相同。省略 `model` 表示该限制适用于你的所有模型，也可以将其设为同一文档中任一模型或层级的上游 `provider_model_slug`。

```json
{
  "schema_version": "1.1",
  "data": [{ "id": "your-provider/example-model", "...": "..." }],
  "rate_limits": [
    { "requests_per_minute": 600, "tokens_per_minute": 2000000 },
    { "model": "example-model", "requests_per_day": 100000, "tokens_per_day": 500000000 }
  ]
}
```

每个条目接受 `requests_per_minute`、`requests_per_day`、`tokens_per_minute` 和 `tokens_per_day`。每个值为正整数或 `null`，且每个条目至少需要一个值。Phaseo 会对发送给你的全部流量在全局范围内统计每项限制。模型限制与适用于所有模型的限制同时生效。

限制绝不会阻止请求。当某个报价的流量接近上限时，Phaseo 会逐步减少分配给它的流量份额。达到上限后，在限制重置之前，Phaseo 会将该报价排在其他提供商之后。设置过低的值只会减少你自己的流量份额。因此，在你的提供商申请获批后，限制无需审核即可生效，通常在一分钟内。

数组存在时，每次成功导入已更改的数据源，都会替换你声明的限制。空数组会移除这些限制。省略 `rate_limits` 可保留你在提供商设置中管理的限制。如果某个条目引用了文档中不存在的模型、重复了某个范围，或使用了不是正整数的值，Phaseo 会拒绝整个快照，并保留你当前的目录和限制。拒绝结果会显示为**需要修改**。

你也可以在**提供商设置 → 你的模型 → 速率限制**中编辑限制。这些编辑与目录更改分开保存。目录编辑器不接受 `rate_limits`。

## 更新与验证

轮询和签名的目录变更 Webhook 通过相同的接入和刷新流程支持这两种版本。在提供商设置中，先选择层级，再编辑其上游 ID、可用性或价格。添加另一个层级会将已保存的目录改为 V1.1。

目录不会添加推理适配器或凭证。必须先集成提供商及其宣称的能力，才能启用路由。Batch 定价不会让 Batch 在同步聊天端点上可用。

不可用的规范模型或未知的发布方映射会显示为**需要修改**，但不会阻止有效模型导入。请在提供商控制台中查看各模型的具体原因。

对于通过 API 提供的目录，控制台中的编辑会作为持久覆盖保留。导入只更新没有覆盖的字段。选择**使用数据源值**可移除覆盖，并恢复跟随数据源更新该字段。控制台会显示最新的数据源值、生效值、编辑者和时间；目录活动会记录编辑和恢复操作。手动添加的模型仍是本地报价。从数据源中删除某个模型后，即使其部分字段曾被编辑，该数据源报价也会停用。现有的纯手动目录仍受支持。
