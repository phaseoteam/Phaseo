任何能发送带身份验证的 HTTP 请求的自动化平台都可以调用 Phaseo：添加一个 HTTP 步骤，向 `https://api.phaseo.app/v1/responses` 发送 POST 请求，并把你的密钥作为 Bearer 令牌。Phaseo 没有原生的 Zapier、n8n 或 Pipedream 应用。

## 构建请求

| 设置 | 值 |
| --- | --- |
| 方法 | `POST` |
| URL | `https://api.phaseo.app/v1/responses` |
| 请求头 | `Authorization: Bearer <PHASEO_API_KEY>` |
| 请求头 | `Content-Type: application/json` |

```json
{
  "model": "openai/gpt-6-astra",
  "input": "Summarise the supplied workflow data in one paragraph."
}
```

把密钥保存在平台的凭据或密钥存储中，不要放在共享的工作流定义里。所有请求字段请参阅 [Responses](../../api-reference/endpoint/responses.mdx)。

## Zapier

使用 **Webhooks by Zapier → Custom Request**：

1. 选择 `POST`，并输入 `https://api.phaseo.app/v1/responses`。
2. 添加 Bearer 和 Content-Type 请求头。
3. 把前面 Zap 步骤中的字段映射到 `input`。
4. 用不敏感的数据测试 Zap。

## n8n

使用 **HTTP Request** 节点，配置 Bearer 身份验证和 JSON 请求体。用 n8n 表达式把传入的项映射到 `input`。

## Pipedream

使用 HTTP 请求步骤或 Node.js 代码步骤。把 `PHASEO_API_KEY` 保存为 Pipedream 密钥，并从步骤环境中读取它。

## 检查是否可用

运行一次该步骤。返回带有 `output` 数组的 `200` 响应，就说明密钥和 URL 可用，请求也会出现在 **设置 → 使用情况 → 日志** 中。

## 安全地运行自动化

- 为每个自动化提供单独的、带支出上限的密钥，以便单独跟踪和撤销。
- 当后续步骤需要机器可读的字段时，请使用[结构化输出](../structured-outputs.mdx)。
- 遇到 `429` 和可恢复的 `5xx` 响应时重试；请参阅[错误](../../api-reference/errors.mdx)。
- 不要仅仅因为模型步骤重试了，就重复执行不具备幂等性的外部操作。
