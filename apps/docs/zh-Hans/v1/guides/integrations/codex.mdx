运行 `phaseo codex` 为 Codex 添加一个 Phaseo 配置档案，或者自己在 `config.toml` 中添加 `phaseo` 提供商。同一份配置适用于 Codex CLI、Codex App 和 Codex IDE 扩展。

## 使用 Phaseo CLI 设置

```bash
phaseo login
phaseo codex --model openai/gpt-5.6-terra
codex --profile phaseo
```

如果没有安装 Codex，CLI 会显示官方安装命令，并在运行前征求你的确认。随后 setup 会打开一个控制台页面，由你批准一个 `Phaseo CLI: Codex API Key`，它 90 天后过期，每月支出上限为 $100。CLI 把密钥保存在操作系统凭据存储中，并把配置档案写入 `~/.codex/phaseo.config.toml`（或 `CODEX_HOME` 下）。Codex 从 CLI 获取密钥，所以配置中不会写入明文密钥。密钥过期后，再次运行 `phaseo codex` 批准新密钥。不指定 `--model` 时，配置档案使用 `openai/gpt-5.6-terra`。

## 手动配置 Codex

将以下内容添加到 `~/.codex/config.toml`，或受信任项目中的 `.codex/config.toml`：

```toml
model = "openai/gpt-6-astra"
model_provider = "phaseo"

[model_providers.phaseo]
name = "Phaseo"
base_url = "https://api.phaseo.app/v1"
env_key = "PHASEO_API_KEY"
wire_api = "responses"
```

然后导出 `PHASEO_API_KEY` 并启动 Codex。Codex 自定义提供商使用 Responses 线路协议，这也是默认值，所以你也可以省略 `wire_api`。在 IDE 扩展中，通过 **Codex Settings → Open config.toml** 打开该文件。

## 确认可以正常使用

发送一条简短的提示词，并确认该请求出现在 **设置 → 用量 → 日志** 中。Codex 调用的是 [Responses](../../api-reference/endpoint/responses.mdx)，因此模型必须支持该端点。

## 移除 Phaseo

```bash
phaseo integrations remove codex
```

如果 `phaseo.config.toml` 是 Phaseo 创建的，此命令会删除它，并吊销密钥。对于手动设置，请从 `config.toml` 中删除 `phaseo` 提供商。

## 解决常见问题

| 错误 | 解决方法 |
| --- | --- |
| `401 Unauthorized` | 运行 `phaseo whoami`，然后重新运行 `phaseo codex`。 |
| `model_not_found` | 从 [Models](../../api-reference/endpoint/models.mdx) 获取当前 ID 并更新 `model`。 |
| 某个提供商失败 | 故障转移请参阅[路由和回退](../routing-and-fallbacks.mdx)。 |

## 添加 Phaseo 技能和文档

要让 Codex 在工作时读取最新的 Phaseo 文档，请添加 [Docs MCP](./docs-mcp.mdx) 服务器。要为 Codex 安装公开的 [Phaseo 技能](https://phaseo.app/docs/.well-known/agent-skills/index.json)：

```bash
npx skills add https://phaseo.app/docs --agent codex --skill '*'
```

同样的 CLI 工作流也可以用临时设置启动 [Cline](./cline.mdx)、[Kilo Code](./kilo-code.mdx)、[oh-my-pi](./oh-my-pi.mdx)、[Muse Code](./muse-code.mdx) 和 [MiniMax Code](./minimax-code.mdx)。
