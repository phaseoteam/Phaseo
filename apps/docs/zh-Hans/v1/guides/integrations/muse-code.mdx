运行 `phaseo muse` 通过 Phaseo 启动 Muse Code 会话。这个运行器是将 Phaseo 与 Muse Code 搭配使用的唯一受支持方式。

## 通过 Phaseo CLI 运行 Muse Code

```bash
phaseo login
phaseo muse --model meta/muse-spark-1.3
```

运行器会创建一个专用密钥，把 Muse 设置写入一个临时的 `XDG_CONFIG_HOME`，启动 `muse`，并在 Muse Code 退出时删除这些设置。Muse Code 自己的参数放在 `--` 之后。

| 参数 | 作用 |
| --- | --- |
| `--model <id>` | 要使用的模型。默认为 `openai/gpt-5.6-terra`。 |
| `--catalog all` | 列出所有活跃的 Phaseo 文本模型，而不只是所选模型。 |
| `--dry-run --json` | 显示启动计划，但不创建密钥，也不启动 Muse Code。 |
| `--skip-install` | 跳过安装检查。 |

`phaseo run muse ...` 是同一命令的完整形式。

在 macOS 和 Linux 上，首次交互式运行会提示你用 Meta 的安装程序安装 Muse Code。在 Windows 上，请自己安装 Muse Code，检查 `muse --version`，并使用 `--skip-install`。

## 为什么没有手动设置

Muse Code 是围绕 Meta 自己的 [Model API](https://ai.meta.com/llama) 和登录构建的。Meta 没有提供有文档说明的稳定设置来把它指向其他 OpenAI 兼容端点，所以请使用运行器。不要把运行器的临时设置复制到你平时的 Muse 配置档案中；它们属于内部细节，运行器退出时就会被删除。

如果想在自己的代码中调用 Phaseo 模型，请使用 [OpenAI SDK](./openai-sdk.mdx)，配合 `https://api.phaseo.app/v1` 和一个 Phaseo API 密钥。

## 确认可以正常使用

发送一条简短的提示词，并确认该请求出现在 **设置 → 用量 → 日志** 中。

## 解决常见问题

### 未安装 Muse Code

自己安装 Muse Code，检查 `muse --version`，再加上 `--skip-install` 重新运行。

### 模型没有列出

使用 `--catalog all`，或用 `--model` 传入模型 ID。Phaseo 不需要模型发现功能。
