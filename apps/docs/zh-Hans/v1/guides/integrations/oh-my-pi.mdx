运行 `phaseo omp` 通过 Phaseo 启动 oh-my-pi 会话，或者在 `~/.omp/agent/models.yml` 中添加 `phaseo` 提供商，让 Phaseo 在每个会话中都可用。

## 通过 Phaseo CLI 运行 oh-my-pi

```bash
phaseo login
phaseo omp --model openai/gpt-5.6-terra
```

运行器会创建一个专用密钥，把 `models.yml` 写入一个临时的 `PI_CODING_AGENT_DIR`，用 `--model phaseo/<model>` 启动 `omp`，并在 oh-my-pi 退出时删除该目录。如果没有安装 `omp`，首次交互式运行会提示你安装。oh-my-pi 自己的参数放在 `--` 之后。

| 参数 | 作用 |
| --- | --- |
| `--model <id>` | 要使用的模型。默认为 `openai/gpt-5.6-terra`。 |
| `--catalog all` | 列出所有活跃的 Phaseo 文本模型，而不只是所选模型。 |
| `--dry-run --json` | 显示安装和启动计划，但不创建密钥，也不启动 oh-my-pi。 |
| `--skip-install` | 跳过安装检查。 |

`phaseo run omp ...` 是同一命令的完整形式。

## 手动配置 oh-my-pi

在控制台的**设置 → API 密钥**中创建一个密钥，在启动 oh-my-pi 的 shell 中导出它，并创建配置目录：

```bash
export PHASEO_OMP_API_KEY="<your Phaseo API key>"
mkdir -p ~/.omp/agent
```

添加提供商：

```yaml ~/.omp/agent/models.yml
providers:
  phaseo:
    baseUrl: https://api.phaseo.app/v1
    api: openai-completions
    apiKey: PHASEO_OMP_API_KEY
    authHeader: true
    models:
      - id: openai/gpt-5.6-terra
        name: GPT-5.6 Terra via Phaseo
        contextWindow: 32768
        maxTokens: 8192
```

`apiKey` 指定的是环境变量名，因此密钥不会写入 `models.yml`。按需在 `models` 下添加更多条目；上面的限制只是示例。用带提供商前缀的模型 ID 启动 oh-my-pi：

```bash
omp --model phaseo/openai/gpt-5.6-terra
```

其他字段请参阅 oh-my-pi 的[提供商配置](https://github.com/can1357/oh-my-pi/blob/main/docs/providers.md)文档。

## 确认可以正常使用

发送一条简短的提示词，并确认该请求出现在 **设置 → 用量 → 日志** 中。

## 解决常见问题

### 未安装 oh-my-pi

在交互式终端中运行该命令以批准安装，或者自己安装 oh-my-pi，再加上 `--skip-install` 重新运行。

### 模型没有列出

使用 `--catalog all`，或用 `--model` 传入模型 ID。Phaseo 不需要模型发现功能。
