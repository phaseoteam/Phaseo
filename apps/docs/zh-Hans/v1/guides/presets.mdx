预设会把某项任务的模型、系统提示词、参数和提供商规则保存在一个名称下，例如 `@support-triage`。调用方把这个名称作为 `model` 发送，只需提供输入；Gateway 会在选择提供商之前补全其余部分。

切换下面的请求字段，看看哪个值会生效：

<PresetMergeExplorer locale="zh-Hans" />

规则如下：

- **参数只填补空缺。** 预设的默认参数只作用于请求中没有提供的字段。请求中的值总是优先。
- **系统提示词会叠加。** 预设的提示词排在前面。如果请求带有自己的系统提示词或 `instructions`，它会在一个空行之后接上。
- **请求中的提供商设置优先。** 请求中的 `provider.order` 或 `provider.max_price` 等字段会替换预设中该字段的值。
- **允许列表只会收窄，不会放宽。** 预设的提供商允许列表和忽略列表在选择提供商之前应用，因此也会限制回退可以使用哪些提供商。如果模型不在预设允许的模型范围内，请求会失败并返回 `validation_error`，其详情关键字为 `preset_model_not_allowed`；请求不会被改道。

## 创建并使用预设

<Steps>
<Step title="创建预设">

打开**控制台 -> 设置 -> 预设**，创建一个标识符为 `support-triage` 之类的预设。只添加所有调用方都应共享的默认值。

如需通过脚本创建，请使用管理密钥调用 `POST /v1/presets`。

</Step>

<Step title="按名称调用">

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "@support-triage",
    "input": "Customer says the invoice total is wrong."
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "@support-triage",
  input: "Customer says the invoice total is wrong.",
});
```

```python Python
from phaseo import Phaseo

client = Phaseo(api_key="YOUR_API_KEY")

response = client.generate_response({
    "model": "@support-triage",
    "input": "Customer says the invoice total is wrong.",
})
```
</CodeGroup>

</Step>

<Step title="检查实际应用了什么">

在 **Gateway -> 用量** 中打开该请求，查看应用了哪些预设默认值，以及由哪个提供商处理了它。

</Step>

## 预设可以包含什么

| 设置 | 作用 |
| --- | --- |
| 模型 | 当请求使用预设名称发送时使用。 |
| 允许的模型 | 模型 ID 或 `anthropic/*` 这样的模式。其他模型会被拒绝。 |
| 系统提示词 | 添加到每个请求的开头。 |
| [提示词模板](./prompt-templates) | 带有 `{{variables}}` 的消息，由每个请求填入。 |
| 默认参数 | `temperature`、`top_p`、`max_tokens`、推理设置等。 |
| 提供商规则 | 允许列表和忽略列表、提供商顺序、区域、价格上限。 |

把特定于调用方的逻辑留在你的应用中；当不同工作流需要不同的提示词、路由或缓存时，使用不同的预设。

## 为预设命名

通过 `model` 字段发送预设；如果预设带有[提示词模板](./prompt-templates)，也可以通过 `prompt.id` 发送。没有单独的 `preset` 字段。

| 形式 | 解析范围 |
| --- | --- |
| `@support-triage` | API 密钥所属的工作区（私有预设和工作区预设）。 |
| `@octavia/support-triage` | 任意工作区（公开预设，由用户 `octavia` 发布）。 |
| `@support-triage@v3` | 该已发布版本。 |
| `@support-triage@production` | `production` 标签当前指向的版本。 |

发布公开预设需要已启用的公开资料和用户名。用户名在整个 Phaseo 中唯一；标识符只需在同一发布者下唯一。标识符会被转为小写，可以包含字母、数字、`-`、`_`、`.` 和 `:`。

## 管理版本与回滚

保存只会编辑私有草稿。**发布新版本** 会把草稿变成一个不可更改、带编号的发布版本，并保留之前的所有版本。

选择发布标签的格式：

| 格式 | 示例 |
| --- | --- |
| 顺序编号 | `v1`、`v2`、`v3` |
| 语义化版本 | `1.2.0`、`2.0.0-beta.1`、`1.4.2+build.7` |
| 日期 | `2026.08.02`，同一天的第二次发布为 `2026.08.02.2` |

把 `production` 这样的命名标签指向某个版本；要回滚，就把它移回较早的版本。参见[版本和标签](/zh-Hans/v1/guides/prompt-templates#versions-and-labels)。

通过脚本时，请使用管理密钥，以 `POST /v1/presets/{id}/versions` 发布版本，并以 `PUT /v1/presets/{id}/labels/{label}` 移动标签。CLI 登录或采用“使用 Phaseo 登录”的应用可以读取预设，但不能更改。

## 复刻市场中的预设

市场预设的副本会固定在你复制时的版本上。发布者发布更新时，你的副本会显示提示。应用更新只会修改你的草稿，因此在你自己发布之前，任何变更都不会进入生产环境。

Phaseo 会记录每个复刻的来源和完整的派生链，因此市场页面可以把直接复刻与所有后代分开显示。

要收集对预设回答的评分，请参见[收集预设反馈](./preset-feedback)。
