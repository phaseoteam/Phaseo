当多个提供商提供同一个模型时，默认路由会按每次成功回答的预期成本为它们排名，并按该排名分配流量：成本最低的提供商获得最大份额。本页面向希望了解这一排名、并从中获得更多流量的提供商。

## 排名衡量什么

对于每个端点，Phaseo 会衡量：

- **实际价格。** 根据该模型真实的提示和输出规模，以及你实际从缓存提供的提示 Token 比例，计算该模型的典型请求在你的端点上的费用。如果输出或缓存读取更贵，较低的输入价格也无济于事。
- **首个 Token 时间**，从 Phaseo 发送请求时开始计算。
- **输出速度**，按包括首个 Token 在内的完整响应计算。
- **由你造成的错误**，例如 `5xx` 响应和中途失败的流式响应。这类错误惩罚较重。
- **速率限制拒绝**（`429`）。惩罚较轻。

等待时间会按该模型每秒的典型价格折算为美元，因此更快的端点即使价格更高也能排在首位。

## 流量如何分配

- 每次回答成本不高于最低值约 30% 的提供商分担大部分流量。稍微落后只会带来很小的影响。
- 超出这个范围后，份额会迅速下降。
- 每个可路由的端点都会保留少量流量，因此无需你做任何操作，恢复和改进也会被发现。
- 正在读取你的提示缓存的对话，只要你的端点保持正常，通常会继续留在你的端点上。

指定提供商顺序，或要求按价格、延迟或吞吐量排序的请求不使用这一排名。请参阅[路由与回退](./routing-and-fallbacks.mdx)。

## 如何获得更多流量

- 降低典型请求的费用，包括输出和缓存读取。
- 从缓存提供重复的提示。
- 更早返回首个 Token，并加快流式输出。
- 避免错误和速率限制拒绝，并在需求达到上限之前扩充容量。
