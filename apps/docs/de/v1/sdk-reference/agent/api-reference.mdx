## Einen Agenten erstellen

Erstellt einen Agenten aus einer Definition. Das Schrittlimit der Definition gilt für jeden Run- oder Continue-Aufruf.

| Sprache | Name | Standard-Schrittlimit |
| --- | --- | --- |
| TypeScript | `createAgent(definition)` | 12 |
| Python | `create_agent(definition)`, aus einem Dict oder einer `AgentDefinition` | 12 |
| Go | `CreateAgent(AgentDefinition) *Agent` | 8 |
| C# | `AgentSdk.CreateAgent(AgentDefinition)` | 12 |
| PHP | `AgentSdk::createAgent(AgentDefinition)` | 12 |
| Ruby | `PhaseoAgentSdk.create_agent(definition)`, aus einer `AgentDefinition` oder aus Keyword-Feldern | 12 |
| Java | `AgentSdk.createAgent(AgentDefinition)` | 12 (ein `maxSteps` unter 1 wird zu 12) |
| Rust | `create_agent(AgentDefinition::new(id, model))` | 8 (Werte werden auf mindestens 1 begrenzt) |

### Felder der Definition

Rust baut die Definition mit Methoden statt Feldern: `AgentDefinition::new(id, model)`, dann `.instructions(text)`, `.tool(tool)` (einmal pro Tool), `.max_steps(limit)`, `.model_retries(count, backoff)` und `.human_review(callback)`. `AgentDefinition` in Java ist ein Record mit Konstruktoren für 10, 13 und 19 Argumente.

| Feld | camelCase (TypeScript, PHP, Java) | snake_case (Python, Ruby) | PascalCase (Go, C#) | Nicht in |
| --- | --- | --- | --- | --- |
| Agenten-ID (erforderlich) | `id` | `id` | `ID` (Go), `Id` (C#) | |
| Modell oder Preset | `model`, `preset` | `model`, `preset` | `Model`, `Preset` | Rust hat kein `preset` |
| Modellliste (nur das erste wird verwendet, wenn `model` nicht gesetzt ist; kein Fallback) | `models` | | | Alle außer TypeScript |
| Anweisungen | `instructions` | `instructions` | `Instructions` | |
| Tools | `tools` | `tools` | `Tools` | |
| In einem Schritt angebotene Tools | `activeTools` | | | Alle außer TypeScript |
| Verlauf vor jeder Modellanfrage umschreiben | `prepareMessages` | | | Alle außer TypeScript |
| Schrittlimit und Stoppbedingungen | `maxSteps`, `stopWhen` | `max_steps`, `stop_when` | `MaxSteps`, `StopWhen` | Rust hat kein `stop_when` |
| Modellwiederholung und Tool-Parallelität | `modelRetry`, `toolExecution` | `model_retry`, `tool_execution` | `ModelRetry`, `ToolExecution` | Rust hat keine Tool-Parallelität |
| Sampling und Länge | `temperature`, `maxOutputTokens`, `topP` | `temperature`, `max_output_tokens`, `top_p` | | Go, C#, Java, Rust |

## Modell-Clients

Implementiere einen Modell-Client, um Modell-Turns über einen anderen Transport zu senden oder den Gateway-Client zu umhüllen.

| Sprache | Interface | Methoden |

| Java | `ModelClient`, `StreamingModelClient` | `generate(ModelRequest)`; `stream(ModelRequest)` |
| Rust | `ModelClient` (Trait) | `fn generate(&mut self, request: &ModelRequest) -> Result<ModelResponse, AgentError>` |

In Rust enthält `ModelRequest` die Agenten-ID, das effektive Modell, die Anweisungen, die aktuellen Nachrichten, die Tool-Spezifikationen (`ToolSpec`: `id`, `description`, JSON-Schema `parameters`) und den Anwendungskontext. `ModelResponse` enthält `message`, `usage`, `request_id`, `provider`, `model` und `finish_reason`. `Message` hat `role`, `content`, `tool_calls`, `tool_call_id`, `name` und `is_error`, mit den Konstruktoren `Message::user(content)` und `Message::assistant(content)`; `ToolCall` hat `id`, `name` und JSON-`input`.
