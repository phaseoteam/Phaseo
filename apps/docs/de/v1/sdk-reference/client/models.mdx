Rufe die Listenmethode des SDK auf, um den Modellkatalog von `GET /v1/models` zu lesen, optional mit Filtern.

<CodeGroup>

  provider_status: ["beta", "not_ready"],
  provider_availability_reason: ["preview_only", "provider_not_ready"],
  capability_status: ["coming_soon", "internal_testing"],
  availability: "all",
});

| Sprache | Methode | Filter mit mehreren Werten |
| --- | --- | --- |
| TypeScript | `client.getModels(filters)` oder `client.models.list(filters)` | Arrays |
| Python | `client.get_models(filters)` oder `client.models.list(filters)` | Listen |
| Go | `client.GetModels(ctx, query)` mit einer `map[string]string` | Kommagetrennte Strings |
| C# | `client.ListModels(query)` mit einem `Dictionary<string, string>` | Kommagetrennte Strings |
| PHP | `$client->listModels($params)` | Kommagetrennte Strings |
| Ruby | `client.list_models(...)` | Kommagetrennte Strings |
| Java | `client.listModels(query)` mit einer `Map<String, String>` | Kommagetrennte Strings |
| Rust | Kein Helfer; rufe `client.request("GET", "/models?<filters>", None, &RequestOptions::default())` auf | Kommagetrennte Strings im Query-String |

## Liste filtern

Alle Filter sind optional und heißen in jedem SDK gleich: Es sind die Query-Parameter.

| Filter | Filtert nach |
| --- | --- |
| `provider`, `organisation` | Anbieter oder Modellorganisation |
| `endpoints`, `input_types`, `output_types`, `params` | Unterstützten Endpunkten, Modalitäten und Anfrageparametern |
| `status`, `provider_status`, `provider_routing_status`, `model_routing_status`, `capability_status`, `provider_availability_status`, `provider_availability_reason` | Lebenszyklus- und Routing-Zustand |
| `availability` | Setze `all`, um Modelle einzuschließen, die nicht geroutet werden können |
| `limit`, `offset` | Seitenweise Abfrage |

Standardmäßig enthält die Liste nur routbare Modelle. Setze `availability` auf `all`, um auch die übrigen einzuschließen, und grenze die Liste dann ein:

- `provider_availability_reason` wählt Rollout-Zustände wie `preview_only`, `provider_not_ready`, `gated`, `access_limited`, `region_limited`, `project_limited`, `paused` oder `soft_blocked`.
- `capability_status` wählt Endpunkt-Zuordnungen, die noch nicht routbar sind, etwa `coming_soon` oder `internal_testing`.

## Ein einzelnes Modell prüfen

`checkParameters` und seine Entsprechungen lesen die Live-Metadaten der Anbieter-Routen, markieren jeden Parameter als `supported`, `partial`, `unsupported` oder `unknown`, prüfen angegebene Werte und Wertebereiche und geben die Anbieter-Routen zurück, die den gesamten Satz akzeptieren. `preflight` macht dasselbe für einen ganzen Anfrage-Body, ergänzt die Lebenszyklusprüfung des Modells und liefert einen Gesamtwert `ok`.

| Sprache | Fähigkeiten | Parameter prüfen | Preflight | Lebenszyklus |
| --- | --- | --- | --- | --- |
| TypeScript | `models.capabilities(modelId)` | `models.checkParameters(modelId, values, { endpoint, provider })` | `models.preflight(request, { endpoint, provider })` | `models.validate(modelId)` gibt `{ ok, info, reason }` zurück; `models.getDeprecationInfo(modelId)` |
| Python | `models.capabilities(model_id)` | `models.check_parameters(model_id, values, endpoint=..., provider=...)` | `models.preflight(request, endpoint=..., provider=...)` | `models.validate(model_id)`, `models.get_deprecation_info(model_id)` |
| Go (nächstes Release) | `GetModelEndpointCapabilities` | `CheckModelParameters` | `PreflightRequest` | `ValidateModel`, `GetModelDeprecationInfo` (veröffentlicht) |
| C# (nächstes Release) | `GetModelEndpointCapabilities(modelId)` | `CheckModelParameters(modelId, values)` | `PreflightRequest` | `ValidateModel`, `GetModelDeprecationInfo` (veröffentlicht) |
| PHP (nächstes Release) | `getModelEndpointCapabilities` | `checkModelParameters(...)` | `preflightRequest` | `validateModel`, `getModelDeprecationInfo` (veröffentlicht) |
| Ruby (nächstes Release) | `model_endpoint_capabilities` | `check_model_parameters(model_id, values)` | `preflight_request` | `validate_model`, `get_model_deprecation_info` (veröffentlicht) |
| Java (Build aus dem Quellcode) | `getModelEndpointCapabilities(modelId, query)` | `checkModelParameters(modelId, values, options)` | `preflightRequest(request, options)` | `validateModel`, `getModelDeprecationInfo` |
| Rust (nicht in `0.2.0`) | `Phaseo::model_endpoint_capabilities(...)` | `Phaseo::check_model_parameters(...)` | Keine | Keine |

„Nächstes Release“ bedeutet, dass die Methode im Quellcode des SDK steht, aber nicht im veröffentlichten Paket; siehe [Prüfen, was jedes Paket enthält](./overview#check-what-each-package-ships). Die Methoden für Abkündigungsinformationen geben den Status des Modells (`active`, `deprecated` oder `retired`), das Abkündigungs- und Einstellungsdatum sowie die ID des Nachfolgemodells zurück.
