## Was du sendest und zurückbekommst

Anfrage-Bodys verwenden in jedem SDK die JSON-Feldnamen der API. [Verwendung](./usage) enthält ein Beispiel pro Endpunkt.

| Sprache | Anfrage-Body | Rückgabe |
| --- | --- | --- |
| TypeScript | Typisierte Objekte, generiert aus der OpenAPI-Spezifikation | Typisierte Objekte |
| Python | Dicts; die Typen liegen in `phaseo.models` | `APIResponse`-Dicts mit `output_text`, `request_id` und `trace_url` |
| Go | `map[string]interface{}` oder die typisierten `phaseo.ChatCompletionsRequest` und `phaseo.ResponsesRequest` (Struct-Felder in PascalCase wie `Model`, `Messages`, `Input`) | Dekodiertes JSON |
| C# | `Dictionary<string, object>` | `Dictionary<string, object>?` |
| PHP | Arrays | Arrays |
| Ruby | Hashes (Keyword-Argumente) | Hashes |
| Java | Eine `Map` oder ein Jackson-`JsonNode`; JSON-Strings vorher parsen | `JsonNode` |
| Rust | `&serde_json::Value` | `PhaseoResponse` mit `status`, `body` und `request_id` |

Ein fehlender Schlüssel führt schon beim Erstellen des Clients zu einem Fehler. Python löst `ValueError` aus, `NewFromEnv()` in Go gibt einen Fehler zurück, C# und PHP werfen `Missing API key. Pass apiKey or set PHASEO_API_KEY.`, Ruby löst `ArgumentError: Missing API key. Pass api_key or set PHASEO_API_KEY.` aus, und `Phaseo::from_env()` in Rust gibt einen `PhaseoError` zurück.

<span id="wait-for-music-video-or-batches"></span>
## Auf Musik, Video oder Batches warten

Die Warte-Helfer gibt es in TypeScript und Python. Die anderen SDKs geben den Job aus dem Erstellungsaufruf zurück; frage ihn mit der Get-Methode ab oder öffne seine [WebSocket-URL des Jobs](#find-the-method-for-each-endpoint).

<CodeGroup>

```typescript TypeScript
const music = await client.music.generateAndWait(
  { model: process.env.PHASEO_MUSIC_MODEL!, prompt: "Gentle instrumental piano" },
  { timeoutMs: 600_000, onPoll: (job) => console.log(job.id, job.status) },
);
```

```python Python
import os

music = client.music.generate_and_wait(
    {"model": os.environ["PHASEO_MUSIC_MODEL"], "prompt": "Gentle instrumental piano"},
    timeout=600,
    on_poll=lambda job: print(job["id"], job["status"]),
)
```

</CodeGroup>

Verwende `videos.generateAndWait` / `videos.generate_and_wait` für Video und `batches.createAndWait` / `batches.create_and_wait` für Batches. Jeder Helfer sendet genau einmal. Ist die erste Antwort bereits fertig, gibt er sie ohne Abfrage zurück; andernfalls fragt er denselben Job ab, bis er fertig ist, und gibt die vollständige Antwort zurück. Fehlgeschlagene, abgebrochene oder abgelaufene Jobs lösen `JobFailedError` aus, dessen `response` die Details enthält. Ein abgeschlossener Batch kann trotzdem fehlgeschlagene einzelne Anfragen enthalten.

`wait(id, options)` auf jeder Ressource setzt einen bestehenden Job fort und gibt jede Endantwort zurück, auch Fehlschläge. In Python hat Musik außerdem `create(request)` und `retrieve(id)`.

| TypeScript | Python | Standard | Hinweise |
| --- | --- | --- | --- |
| `intervalMs` | `interval` | `5000` ms / `5` Sekunden | Minimum `250` ms / `0.25` Sekunden. |
| `timeoutMs` | `timeout` | `1800000` ms / `1800` Sekunden (30 Minuten) | Beginnt, nachdem das Absenden zurückkehrt; die Absende-Anfrage behält ihr eigenes Timeout. |
| `signal` | `cancel_event` | keiner | Beendet das Warten. In Python ein `threading.Event`. |
| `onPoll` | `on_poll` | keiner | Erhält die erste Antwort und jede Abfrage. |

`JobTimeoutError` und `JobCancelledError` behalten die Job-ID und die letzte Antwort (`jobId`/`lastResponse` in TypeScript, `job_id`/`last_response` in Python), sodass du mit `.wait(error.jobId)` bzw. `.wait(error.job_id)` fortsetzen kannst. Das Beenden des Wartens bricht den entfernten Job nicht ab. In TypeScript bricht es die laufende Abfrage ab; der synchrone Python-Client prüft Abbruch und Frist zwischen Anfragen und Callbacks und kann daher einen bereits laufenden HTTP-Aufruf nicht unterbrechen. HTTP-Fehler werden unverändert ausgelöst, und das Absenden wird nie wiederholt. Diese Helfer fragen aus deinem Prozess ab; sie fügen dem Gateway keine Hintergrundausführung hinzu.

### Ein Handle über Prozesse hinweg behalten

`music.start`, `videos.start` und `batches.start` geben ein Handle mit `result()`, `events()` und `cancel()` zurück, dazu `toJSON()` (TypeScript) oder `to_dict()` (Python). Speichere die zurückgegebene Art und ID und baue das Handle später mit `resume(id)` wieder auf. `result()` löst bei endgültigen Fehlschlägen einen Fehler aus. Nur Video- und Batch-Jobs unterstützen `cancel()`. Auf `AsyncPhaseo` verwendest du `await` für die Methoden und iterierst Events mit `async for`.

| Aufgabe | TypeScript | Python |
| --- | --- | --- |
| Videoinhalt streamen | `videos.streamContent(id)`, geschrieben mit `downloadTo(stream, writable)` | `videos.stream_content(id)`, geschrieben mit dem synchronen `download_to(chunks, binary_file)`, das nicht den ganzen Download im Speicher hält |
| Batch-Ergebnisse streamen | `batchResults(await client.batches.streamResults(id))` parst JSONL Zeile für Zeile; `matchBatchResult(row, inputsByCustomId)` ordnet jeder Zeile ihre Eingabe zu und behält Fehler pro Zeile | `batches.results(id)` |
| Uploads vorbereiten | `toFile(bytes, filename, contentType)` | Bytes, `Path`-Objekte, Dateiobjekte oder HTTPX-Datei-Tupel übergeben |

## Anfragesteuerung und Fehler

Wiederholungen stehen in TypeScript, Python und Java standardmäßig auf `0` und gelten nur für `GET`- und `HEAD`-Anfragen. Kostenpflichtige Absendungen, Schreibvorgänge und Streaming-Anfragen werden nie wiederholt.

<CodeGroup>

```typescript TypeScript
const fast = client.withOptions({ timeoutMs: 30_000, signal, maxRetries: 2 });
```

```python Python
fast = client.with_options(timeout=30, max_retries=2)
```

```java Java
Phaseo client = new Phaseo(System.getenv("PHASEO_API_KEY"))
    .setTimeout(Duration.ofSeconds(30))
    .setMaxRetries(2);
```

</CodeGroup>

<Tabs>
<Tab title="TypeScript">

`withOptions(...)` gibt einen neuen Client zurück, der diese Einstellungen auf jede Ressource, jeden Stream und jeden Medienaufruf anwendet; der ursprüngliche Client bleibt unverändert. Wiederholungen beachten `Retry-After`. `timeoutMs` schließt das Lesen des Antwort-Bodys ein.

`responseMetadata(result)` gibt die Anfrage-ID des Gateways und die Trace-URL im Dashboard zurück. HTTP-Fehler sind `PhaseoHttpError`, mit HTTP-`status`, dem API-Fehler-`code`, `requestId`, `traceUrl`, der Wartezeit bis zur Wiederholung, dem Body und `headers`.

</Tab>
<Tab title="Python">

`with_options(...)` gibt einen neuen Client zurück und nimmt außerdem `headers=...` an; es funktioniert sowohl auf `Phaseo` als auch auf `AsyncPhaseo`. Wiederholungen erfolgen, bevor die Antwort gelesen wird, höchstens `10`-mal. Timeouts sind HTTPX-Timeouts in Sekunden und begrenzen daher die Netzwerkinaktivität, nicht die Gesamtdauer.

JSON-Antworten sind `APIResponse`-Dicts mit `output_text`, `request_id` und `trace_url`. HTTP-Fehler sind `PhaseoHTTPError`, mit `status`, `code`, `request_id`, `trace_url`, der Wartezeit bis zur Wiederholung und dem Body.

Wenn du von einer älteren Version aktualisierst, ersetze das Abfangen von `urllib.error.HTTPError` durch `PhaseoHTTPError` (oder `httpx.HTTPStatusError`) und das Abfangen von Verbindungsfehlern durch `httpx.TransportError`.

</Tab>
<Tab title="Java">

HTTP-Fehler sind `Client.ApiException` (`app.phaseo.gen.Client`), mit `getStatusCode()`, `getRequestId()`, `getResponseBody()` und den Headern. `requestWithResponse(...)` gibt die Daten mit ihrer `requestId()` zurück.

</Tab>
<Tab title="Rust">

Jeder Aufruf gibt `Result<PhaseoResponse, PhaseoError>` zurück. `PhaseoError` implementiert `std::error::Error` und `Display`; Transport- und Konfigurationsfehler haben keinen `status`.

| Typ | Feld | Bedeutung |
| --- | --- | --- |
| `PhaseoResponse` | `status: u16` | HTTP-Statuscode. |
| `PhaseoResponse` | `body: serde_json::Value` | Geparste JSON-Antwort oder ein JSON-String, wenn die Antwort kein gültiges JSON war. |
| `PhaseoResponse` | `request_id: Option<String>` | Der Antwort-Header `x-request-id`, sofern vorhanden. |
| `PhaseoError` | `message: String` | Fehlermeldung zu Konfiguration, Transport oder Gateway. |
| `PhaseoError` | `status: Option<u16>` | HTTP-Status des Gateways, wenn eine Antwort empfangen wurde. |
| `PhaseoError` | `body: Option<serde_json::Value>` | Geparster Fehler-Body des Gateways, sofern verfügbar. |

</Tab>
</Tabs>

[Verwendung](./usage#handle-errors) zeigt in jeder Sprache eine vollständige Fehlerbehandlung.

## Endpunkt ohne Wrapper aufrufen

Jedes SDK liefert außerdem den Client mit, der aus der Phaseo-OpenAPI-Spezifikation generiert wird:

| Sprache | Generierter Client |
| --- | --- |
| TypeScript | `client.rawClient()`; die generierten Operationen werden als `operations` exportiert. |
| Python | `client.raw_client()`; die generierten Operationen liegen in `phaseo.ops`. |
| Go | `client.RawClient()`, aus `src/gen`. `client.Request(ctx, method, path, query, headers, body)` sendet jede beliebige Anfrage. |
| Java | `client.rawClient()`, mit `requestLines` für Streams und `requestBytes` für binäre Antworten. |
| Rust | `phaseo::gen` enthält den generierten Client, die Modelle und Operationen, re-exportiert als `phaseo::client`, `phaseo::models` und `phaseo::operations`. `phaseo::model_ids` enthält die generierten Modell-IDs. `client.post(path, body)` sendet JSON an jeden Pfad unter der Basis-URL. Siehe [docs.rs](https://docs.rs/phaseo). |

Die generierten Operationen liegen auf einer tieferen Ebene als die Wrapper-Methoden; nutze den Wrapper, wo es einen gibt.

## Ausgabe parsen und Streams sammeln

Diese Helfer gibt es in TypeScript und Python. `responses.parse(request, schema)` validiert eine abgeschlossene JSON-Antwort. In TypeScript ist `schema` ein Zod-kompatibler Parser, in Python ein Pydantic-Modell. Lege das Format für strukturierte Ausgabe zusätzlich in der Anfrage fest; der Parser validiert nur.

`collectStream(client.streamResponses(request))` (TypeScript) bzw. `collect_stream` und `collect_async_stream` (Python) sammeln den gestreamten Text und die Nutzung.

## Ein Modell vor dem Aufruf prüfen

`checkModelCapabilities` / `check_model_capabilities` (TypeScript und Python) prüft beworbene Fähigkeiten und skalare Einschränkungen (`inputTypes`, `outputTypes`, `endpoints`, `parameters`, `parameterValues` bzw. die snake_case-Namen in Python) an einem aktiven Anbieterangebot. Es ändert nie das Modell oder entfernt Parameter und kann nicht garantieren, dass ein Live-Anbieter die Anfrage akzeptiert. Fehlende Metadaten werden unterschiedlich behandelt: TypeScript meldet sie als unbekannt, Python lässt die Prüfung fehlschlagen.

Für Modellauswahl und Parameter-Editoren verwendest du Live-Metadaten der Endpunkte:

<CodeGroup>

```typescript TypeScript
const support = await client.models.checkParameters(
  "anthropic/claude-haiku-4.5",
  { temperature: 0.7, top_p: 0.9 },
  { endpoint: "responses" },
);
```

```python Python
support = client.models.check_parameters(
    "anthropic/claude-haiku-4.5",
    {"temperature": 0.7, "top_p": 0.9},
    endpoint="responses",
)
```

</CodeGroup>

Jeder Parameter kommt als `supported`, `partial`, `unsupported` oder `unknown` zurück, mit passenden Anbieter-Routen und Einschränkungsproblemen, die du direkt hervorheben kannst. Diese Prüfungen sind explizite Aufrufe; sie fügen Generierungsanfragen keinen Abruf hinzu. [Modelle](./models#check-one-model) listet die Methode in jedem SDK auf.

## Ohne Netzwerk testen

<Tabs>
<Tab title="TypeScript">

Importiere `createMockTransport` und `jobFixtures` aus `@phaseo/sdk/testing` und übergib das `fetchImpl` des Mocks an den Client. Fixtures sind strikt und geordnet: Ein unerwarteter Aufruf schlägt lokal fehl und erreicht nie das Netzwerk. Rufe `mock.assertDone()` auf, um zu prüfen, dass jede erwartete Anfrage stattgefunden hat.

</Tab>
<Tab title="Python">

Übergib `phaseo.testing.MockTransport(fixtures)` an einen `httpx.Client` oder `httpx.AsyncClient` und gib diesen dem Phaseo-Client als `http_client`. Eine unerwartete Anfrage schlägt lokal fehl; rufe `assert_done()` auf, um zu prüfen, dass jede Fixture verwendet wurde. `phaseo.testing.job_fixtures(path, job_id)` baut die Fixtures zum Absenden und Abfragen eines Jobs. Fixtures prüfen nicht das Verhalten von Live-Anbietern.

</Tab>
</Tabs>
