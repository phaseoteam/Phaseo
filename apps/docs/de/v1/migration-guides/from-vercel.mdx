Tausche in AI-SDK-Code `@ai-sdk/gateway` gegen `@phaseo/ai-sdk-provider` aus und umschließe jede Modell-ID mit `phaseo(...)`. Ändere in OpenAI-kompatiblen Clients die Basis-URL und den Schlüssel. Deine Generierungslogik bleibt gleich.

| Einstellung | Vercel AI Gateway | Phaseo |
| --- | --- | --- |
| Basis-URL | `https://ai-gateway.vercel.sh/v1` | `https://api.phaseo.app/v1` |
| API-Schlüssel | `AI_GATEWAY_API_KEY` oder Vercel OIDC | `PHASEO_API_KEY`, als serverseitiges Secret |
| AI-SDK-Provider | `@ai-sdk/gateway` oder Modelle als einfache Strings | `@phaseo/ai-sdk-provider` |
| Routing-Optionen | `providerOptions.gateway` | `providerOptions.phaseo` |

## Provider umstellen

<CodeGroup>
```typescript AI SDK
import { generateText } from "ai";
// Vorher: import { gateway } from "@ai-sdk/gateway";
import { phaseo } from "@phaseo/ai-sdk-provider";

const { text } = await generateText({
  // Vorher: model: gateway("openai/gpt-4.1-mini"),
  model: phaseo("openai/gpt-4.1-mini"),
  prompt: "Generate a migration checklist.",
});
```

```typescript OpenAI SDK
import OpenAI from "openai";

// Vorher:
// new OpenAI({ apiKey: process.env.AI_GATEWAY_API_KEY, baseURL: "https://ai-gateway.vercel.sh/v1" });
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});
```

```bash cURL
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role":"user","content":"Hello"}]
  }'
```
</CodeGroup>

Der Standardexport `phaseo` liest `PHASEO_API_KEY` einmal beim Import des Moduls und verwendet `https://api.phaseo.app/v1`. Wird die Variable erst nach den Imports gesetzt, wie in manchen Serverless- und Test-Setups, wirft jeder Aufruf einen Fehler wegen fehlendem Schlüssel; rufe stattdessen `createPhaseo({ apiKey, baseURL, headers })` innerhalb des Handlers auf.

Installiere die Provider-Linie, die zu deiner `ai`-Hauptversion passt: `@phaseo/ai-sdk-provider` für AI SDK 7, `@phaseo/ai-sdk-provider@ai-sdk-v6` für AI SDK 6 und `@phaseo/ai-sdk-provider@ai-sdk-v5` für AI SDK 5.

Das AI SDK schickt Modelle als einfache Strings (`model: "openai/gpt-4.1-mini"`) standardmäßig über das Gateway von Vercel, ein zurückgelassener String ruft es also weiter auf. Ändere die gemeinsame Modell-Factory einmal und suche dann in AI-SDK-Aufrufen nach `model: "`. Anthropic-SDK-Clients, die auf `ai-gateway.vercel.sh` zeigen, wechseln zur Einrichtung aus [Vom Anthropic-SDK migrieren](./from-anthropic).

## Gateway-Optionen zuordnen

`providerOptions.phaseo` wird in den Anfrage-Body übernommen. Ein übrig gebliebenes `providerOptions.gateway` wird ohne Fehler ignoriert.

| Vercel AI Gateway | Bei Phaseo |
| --- | --- |
| `providerOptions.gateway.order`, `.only` | `providerOptions: { phaseo: { provider: { order, only } } }` oder ein [Preset](../guides/presets), aufgerufen als `phaseo("@slug")`. |
| `providerOptions.gateway.models` | `providerOptions: { phaseo: { models: [...] } }` oder Fallbacks in einer dynamischen Route. |
| `providerOptions.gateway.sort` (`cost`, `ttft`, `tps`) | `provider.sort` (`price`, `latency`, `throughput`). |
| `providerOptions.gateway.zeroDataRetention` | `provider.require_zero_data_retention`, das das Routing auf ZDR-Anbieter beschränkt. |
| `providerOptions.gateway.user`, `.tags` | `user` und `X-Phaseo-Metadata`-[Labels](../guides/request-labels). |
| Anfragebezogene `byok`-Zugangsdaten | Keine Entsprechung. Füge Anbieterschlüssel mit `phaseo byok create` zum Workspace hinzu. |
| Text, Streaming, Tools, strukturierte Ausgaben, Embeddings, Bilder, Transkription, Sprachausgabe | Vom Provider unterstützt; die Fähigkeiten hängen weiterhin vom Modell ab. |
| Reranking | `phaseo.rerankingModel(id)` in den Linien für AI SDK 6 und 7. |
| Verwaltete Dateireferenzen, vom Anbieter ausgeführte Tools | Nicht unterstützt. Nicht unterstützte Teile schlagen mit einem Fehler fehl, statt verworfen zu werden. |
| Nutzungs-Dashboard des Gateways | Phaseo-Anfrage-Logs und `GET /v1/generations?id=<request_id>`. Die Provider-Metadaten in den Ergebnissen enthalten die Anfrage-ID. |

## Testen und umstellen

Schicke denselben Prompt-Satz über beide Wege und vergleiche Latenz, Ausgabeformat und Tokennutzung. Bevor du Traffic hochstufst:

- `PHASEO_API_KEY` ist in jeder Laufzeit gesetzt, die den Gateway-Schlüssel hatte, einschließlich Edge-, Server- und Preview-Deployments;
- der Haupt-Textgenerierungspfad und ein Streaming-Test bestehen in Staging unverändert;
- Tool-Aufrufe und strukturierte Ausgaben bestehen, falls die App sie nutzt;
- die Fehlerzuordnung auf Anwendungsebene funktioniert weiterhin;
- eine fehlgeschlagene Staging-Anfrage lässt sich finden und, wenn `replay_supported` `true` ist, über `GET /v1/generations?id=<request_id>` wiederholen.

Liefere hinter einem Feature-Flag oder einer prozentualen Umstellung aus, beginnend mit internem Traffic. Beobachte Latenz, Fehlerrate sowie Abweichungen bei Tokens und Kosten und halte den alten Provider mindestens ein Release lang verfügbar, damit das Zurückrollen keine Codeänderung braucht.

```bash
curl -s "https://api.phaseo.app/v1/health"
curl -s "https://api.phaseo.app/v1/models?format=openai" -H "Authorization: Bearer $PHASEO_API_KEY"
```
