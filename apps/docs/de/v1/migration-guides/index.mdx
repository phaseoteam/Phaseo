Die Phaseo-Migrationsleitfäden behandeln zwei Arten von Änderungen:

- den Wechsel von einer anderen Plattform oder einem anderen Gateway zu Phaseo
- die Einführung einer Modellversion auf derselben Plattform

## Modellmigrationen

Verwende den [Migrationsassistenten](https://phaseo.app/migrate) für eine individuelle Startcheckliste.

Nutze diese Leitfäden, wenn die Integration weitgehend gleich bleibt, sich aber das verwendete Modell ändert.

Sie behandeln:

- Änderungen an Anfrageparametern
- Unterschiede im Verhalten von Prompts und Reasoning
- Unterschiede bei strukturierten Ausgaben und Tool-Aufrufen
- Strategien für schrittweise Einführung, Fallbacks und Rollback

## Plattformmigrationen

Nutze diese Leitfäden, wenn du SDK, Anbieter oder Gateway wechselst und deine bisherige Integration auf Phaseo umstellen möchtest.

<Card title="Migrationscheckliste erstellen" icon="list-checks" href="https://phaseo.app/migrate">
	Wähle deine aktuelle Integration und öffne den interaktiven Assistenten.
</Card>

<Prompt description="Lass einen Coding-Agenten die Migration mit dir planen und durchführen." icon="arrow-right-left" actions={["copy", "cursor"]}>
{`Migrate this project's AI requests to Phaseo Gateway.

1. Install the Phaseo skills: npx skills add https://phaseo.app/docs
   They include phaseo-gateway, and openrouter-to-phaseo-migration for OpenRouter projects.
2. Find every place the project calls its current provider or gateway (OpenAI, Anthropic, OpenRouter, Vercel AI Gateway, LiteLLM or another), including environment variables, SDK clients, base URLs and model IDs.
3. Read the matching guide at https://phaseo.app/docs/v1/migration-guides and map each call to its Phaseo equivalent at https://api.phaseo.app/v1 with a server-side PHASEO_API_KEY.
4. Check every model ID with GET /v1/models. Do not assume IDs carry over unchanged.
5. List the changes and a rollback plan before editing. After editing, verify one normal request and one streaming request if the project streams.
6. Never print or commit API keys, and do not switch production traffic without my approval.`}
</Prompt>

## Diese Leitfäden verwenden

1. Ermittle, ob du die Plattform, das Modell oder beides wechselst.
2. Beginne mit dem Leitfaden für den riskantesten Teil der Migration.
3. Prüfe Anfrageparameter und Endpoint-Verhalten, bevor du die Antwortqualität vergleichst.
4. Führe produktionsnahe Auswertungen durch, bevor du Live-Traffic umstellst.
