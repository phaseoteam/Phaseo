Wähle den Leitfaden für das, was du änderst: die Plattform, die deine App aufruft (unten), oder das Modell, das sie verwendet ([Modellmigrationen](../model-migrations)). Wenn du beides änderst, wechsle zuerst die Plattform und behalte das Modell bei, bis der neue Weg geprüft ist.

Eine auf dich zugeschnittene Checkliste bekommst du im [Migrationsassistenten](https://phaseo.app/migrate).

<span id="platform-migrations"></span>
## Plattformmigrationen

Jeder Plattformleitfaden folgt derselben Reihenfolge: Basis-URL und Schlüssel austauschen, Modell-IDs zuordnen, die Funktionen der Plattform zuordnen, dann testen und umstellen, wobei das Zurückrollen eine Änderung von Basis-URL und Schlüssel bleibt.

| Du rufst auf | Hinweise im Code | Leitfaden |
| --- | --- | --- |
| OpenAI direkt | `api.openai.com`, `OPENAI_API_KEY`, `AzureOpenAI` | [OpenAI-SDK](./from-openai) |
| Anthropic direkt | `api.anthropic.com`, `ANTHROPIC_API_KEY`, `@anthropic-ai/sdk` | [Anthropic-SDK](./from-anthropic) |
| OpenRouter | `openrouter.ai`, `OPENROUTER_API_KEY`, Schlüssel `sk-or-v1` | [OpenRouter](./from-openrouter) |
| Vercel AI Gateway | `ai-gateway.vercel.sh`, `@ai-sdk/gateway`, Modelle als einfache Strings in AI-SDK-Aufrufen | [Vercel AI Gateway](./from-vercel) |
| LLM Gateway | `api.llmgateway.io`, `LLM_GATEWAY_API_KEY` | [LLM Gateway](./from-llmgateway) |
| Einen LiteLLM-Proxy | `config.yaml` mit `model_list`, `LITELLM_*`-Variablen, Port 4000 | [LiteLLM](./from-litellm) |
| Cloudflare AI Gateway | `gateway.ai.cloudflare.com`, `cf-aig-*`-Header | [Cloudflare AI Gateway](./from-cloudflare) |
| Helicone | `*.helicone.ai`, `Helicone-Auth` | [Helicone](./from-helicone) |

Zum Planen und Prüfen der Umstellung verwende die [Funktions-Checkliste für die Migration](./feature-parity-matrix).

## Modellmigrationen

Verwende einen [Leitfaden zur Modellmigration](../model-migrations), wenn die Integration gleich bleibt, sich aber das Modell ändert. Jeder Leitfaden behandelt Änderungen an Anfrageparametern, Verschiebungen im Prompt- und Reasoning-Verhalten, Unterschiede bei strukturierten Ausgaben und Tool-Aufrufen sowie die Umstellung mit einem Fallback.

Prüfe bei beiden Arten von Migration zuerst Anfrageparameter und Endpunktverhalten, bevor du die Ausgabequalität vergleichst, und führe produktionsnahe Evaluierungen durch, bevor du Live-Traffic verschiebst.
