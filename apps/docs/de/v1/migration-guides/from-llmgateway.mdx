Tausche Basis-URL und Schlüssel aus, behalte die Anfrage-Payloads und ordne jede Modell-ID zu: Bei LLM Gateway nennt das Präfix den ausführenden Anbieter, bei Phaseo den Hersteller des Modells.

| Einstellung | LLM Gateway | Phaseo |
| --- | --- | --- |
| Basis-URL | `https://api.llmgateway.io/v1` | `https://api.phaseo.app/v1` |
| Clients im Anthropic-Stil | `ANTHROPIC_BASE_URL=https://api.llmgateway.io` | `https://api.phaseo.app`, siehe [Vom Anthropic-SDK migrieren](./from-anthropic) |
| API-Schlüssel | `LLM_GATEWAY_API_KEY` (`llmgtwy_…`) | `PHASEO_API_KEY` |
| Modell-IDs | `gpt-4o`, `<provider>/<model>`, `auto` | `<org>/<model>` aus `GET /v1/models?format=openai` |
| Anfrage-Payload | OpenAI-kompatibel | Unverändert |

## Client umstellen

<CodeGroup>
```typescript TypeScript
import OpenAI from "openai";

// Vorher:
// new OpenAI({ apiKey: process.env.LLM_GATEWAY_API_KEY, baseURL: "https://api.llmgateway.io/v1" });
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});
```

```python Python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
)
```

```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```
</CodeGroup>

Ordne jede `LLM_GATEWAY_*`-Variable zu oder entferne sie, auch in CI- und Hosting-Einstellungen. Wenn die App `@llmgateway/ai-sdk-provider` nutzt, wechsle zu `@phaseo/ai-sdk-provider` wie in [Von Vercel AI Gateway migrieren](./from-vercel).

## Modell-IDs zuordnen

Liste die IDs von Phaseo auf und prüfe jedes Produktionsmodell dagegen:

```bash
curl -s "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY" | jq -r '.data[].id'
```

`alibaba/<model>` bei LLM Gateway ist keine Phaseo-ID. Ordne jede ID dem Phaseo-Format `<org>/<model>` zu und behalte eine Anbieterfestlegung mit `provider.only` oder einer ID `provider:org/model` bei. Übersetze Aliase ohne Präfix wie `gpt-4o` in einer einzigen Funktion an der Client-Grenze statt an jeder Aufrufstelle.

## Gateway-Funktionen zuordnen

| LLM Gateway | Bei Phaseo |
| --- | --- |
| `auto`-Router | `phaseo/auto` ([Auto-Routing](../guides/auto-routing), Alpha); nicht mit `models` kombinierbar. |
| Fallback-Ketten | `models`-Array oder dynamische Routen, versucht bei `429`, `500`, `502`, `503` und `504`, nie bei Anfragefehlern. |
| `X-No-Fallback` | `provider.allow_fallbacks: false` oder eine ID `provider:org/model`. |
| Logik zum Zulassen und Ausschließen von Anbietern | `provider.only`, `provider.ignore` oder [Presets](../guides/presets). Behalte mindestens einen zulässigen Anbieter. |
| Header `X-LLMGateway-<Key>` | `X-Phaseo-Metadata`-[Labels](../guides/request-labels), bis zu 32. |
| Sitzungs-Header (`x-session-id`) | Body-Feld `session_id`; Phaseo ignoriert Sitzungs-Header. |
| `X-Source` | `HTTP-Referer` oder `X-App-Name`. Siehe [App-Zuordnung](../guides/app-attribution). |
| Antwort-Caching | Kein Antwort-Cache. |
| Anbieterschlüssel | BYOK (`phaseo byok create` oder `POST /v1/byok`) oder Phaseo-Guthaben. Der Fallback auf Guthaben ist die Workspace-Einstellung `byok_fallback_enabled`. |
| Anfrage-Logs | Anfrage-Logs, Observability-Ziele und `GET /v1/generations?id=<request_id>`. Wenn `replay_supported` `true` ist, wiederhole eine fehlgeschlagene Anfrage mit ihrer `replay_request`-Payload. |

## Testen und umstellen

Führe deine Referenz-Prompts gegen beide Gateways aus und vergleiche Qualität, Latenz und Kosten. Prüfe zuerst die Endpunkte:

```bash
curl -s "https://api.phaseo.app/v1/health"
curl -s "https://api.phaseo.app/v1/models?format=openai" -H "Authorization: Bearer $PHASEO_API_KEY"
```

Bevor du Traffic verschiebst:

- `PHASEO_API_KEY` ist in jeder Umgebung gesetzt;
- jede Produktions-Modell-ID ist zugeordnet und aufgelistet;
- eine Anfrage ohne und eine mit Streaming bestehen in Staging;
- Fehler bei ungültigem Schlüssel und ungültigem Modell werden behandelt; ihre Bodies können von denen von LLM Gateway abweichen;
- eine fehlgeschlagene Staging-Anfrage lässt sich über `GET /v1/generations` wiederherstellen;
- gemeinsame Prompt- und Routing-Standards liegen dort in Presets, wo sie hingehören.

Veröffentliche hinter einem Canary-Flag, gehe nach stabilen Ergebnissen von einem kleinen Teil des Traffics zum gesamten Traffic über und beobachte die Produktionsmetriken mindestens einen Release-Zyklus lang, bevor du die alte Konfiguration entfernst.
