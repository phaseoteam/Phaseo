Behalte das OpenAI-SDK und ändere zwei Dinge: die Basis-URL und den API-Schlüssel. Gib dann jedem Modell seine Phaseo-ID, die das Präfix `openai/` ergänzt.

| Einstellung | OpenAI | Phaseo |
| --- | --- | --- |
| Basis-URL | SDK-Standard (`https://api.openai.com/v1`) | `https://api.phaseo.app/v1` |
| API-Schlüssel | `OPENAI_API_KEY` | `PHASEO_API_KEY`, gesendet als `Authorization: Bearer` |
| Modell | `gpt-4.1-mini` | `openai/gpt-4.1-mini` oder eine beliebige ID aus `GET /v1/models` |
| Anfragecode | `chat.completions.create`, `responses.create` | Unverändert |

## Client umstellen

Erstelle einen Schlüssel mit `phaseo keys create` in der [Phaseo CLI](../guides/integrations/phaseo-cli) oder unter [API-Schlüssel](https://phaseo.app/settings/keys) und füge ihn jeder Umgebung hinzu, in der die App läuft. Übergib ihn dann zusammen mit der Basis-URL an den bestehenden Client:

<CodeGroup>
```typescript TypeScript
import OpenAI from "openai";

// Vorher: const client = new OpenAI();
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Reply with: migration ready" }],
});
```

```python Python
import os
from openai import OpenAI

# Vorher: client = OpenAI()
client = OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
)

response = client.chat.completions.create(
    model="openai/gpt-4.1-mini",
    messages=[{"role": "user", "content": "Reply with: migration ready"}],
)
```

```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-4.1-mini",
    "messages": [{"role": "user", "content": "Reply with: migration ready"}]
  }'
```
</CodeGroup>

Verwende einen neuen Variablennamen, statt den Phaseo-Schlüssel in `OPENAI_API_KEY` abzulegen, und entferne veraltete `OPENAI_BASE_URL`-Werte, damit kein anderer Client im Repository weiter OpenAI aufruft. `AzureOpenAI`-Clients wechseln zum normalen `OpenAI`-Client; Azure-Deployment-Namen werden auf dieselbe Weise Phaseo-Modell-IDs zugeordnet.

## Modell-IDs zuordnen

Liste die IDs, die Phaseo bereitstellt, im Listenformat von OpenAI auf und prüfe jedes Produktionsmodell gegen `data[].id`:

```bash
curl "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

Ohne `format=openai` ist die Antwort die seitenweise `models`-Liste von Phaseo und hat kein `data`-Array. Dasselbe gilt für `client.models.list()`: Übergib `{ query: { format: "openai" } }` in Node oder `extra_query={"format": "openai"}` in Python. Die Standardliste enthält nur Modelle, die du jetzt aufrufen kannst; füge `availability=all` hinzu, um inaktive und demnächst verfügbare Modelle einzuschließen.

## Was anders funktioniert

| OpenAI-Funktion | Bei Phaseo |
| --- | --- |
| Chat Completions, Responses | Gleiche Anfrageformen unter `/v1/chat/completions` und `/v1/responses`. Ein unbekanntes Feld auf oberster Ebene gibt `400` `unknown_param` zurück. |
| `previous_response_id`, `conversation` | Geben `400` zurück: Phaseo speichert keine Antworten. Sende bei jeder Anfrage den vollständigen Verlauf in `input`. |
| Embeddings, Moderation, Bilder, Sprachausgabe, Transkription | `/v1/embeddings`, `/v1/moderations`, `/v1/images/*`, `/v1/audio/*`. Prüfe, ob das Modell die Operation unterstützt. |
| Batch-API | `/v1/files` und `/v1/batches`. `/v1/files` enthält nur Batch-Eingaben; es kann keine `file_id`-Eingaben für andere Anfragen liefern. |
| Realtime | `POST /v1/audio/realtime/sessions`, dann eine WebSocket-Verbindung zur zurückgegebenen `connect.url`. Siehe [Realtime Voice](../guides/realtime-voice). |
| Gespeicherte Prompts (`prompt: { id: "pmpt_…" }`) | Lege den Prompt als Preset neu an und rufe ihn mit `prompt: { id: "@slug", version, variables }` auf. Siehe [Prompt-Vorlagen](../guides/prompt-templates). |
| `organization`, `project`, Header `OpenAI-Organization` | Keine Entsprechung. Entferne sie; verwende Phaseo-Workspaces und -Schlüssel. |
| Assistants, Threads, Vektorspeicher, Fine-Tuning, altes `/v1/completions` | Kein Phaseo-Endpunkt. Belasse diese bei OpenAI oder portiere sie auf `/v1/responses`. |

## Testen und umstellen

Führe dieselben repräsentativen Prompts gegen die alte und die neue Konfiguration aus und vergleiche Ausgabeform, Latenz, Tokennutzung, Fehler und Kosten. Bevor du Traffic verschiebst:

- der Phaseo-Schlüssel ist in Entwicklung, Staging und Produktion gesetzt;
- jede Produktions-Modell-ID erscheint in `GET /v1/models?format=openai`;
- eine Anfrage ohne und eine mit Streaming bestehen in Staging, dazu Tool-Aufrufe und strukturierte Ausgaben, falls die App sie nutzt;
- das Zurückrollen ist weiterhin nur eine Änderung von Basis-URL und Schlüssel.

Verschiebe den Traffic dann schrittweise. [Routing und Fallbacks](../guides/routing-and-fallbacks) behandelt Fallback-Modelle, und [Fehlerbehandlung](../api-reference/errors.mdx) listet die Fehler-Bodies auf, die deine App jetzt sehen kann.
