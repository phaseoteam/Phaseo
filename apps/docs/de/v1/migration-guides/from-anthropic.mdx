Behalte das Anthropic-SDK und den Messages-Aufruf. Richte den Client auf `https://api.phaseo.app` aus, übergib deinen Phaseo-Schlüssel als `authToken` und gib jedem Modell seine Phaseo-ID.

| Einstellung | Anthropic | Phaseo |
| --- | --- | --- |
| Basis-URL | SDK-Standard (`https://api.anthropic.com`) | `https://api.phaseo.app` (das SDK hängt `/v1/messages` an) |
| API-Schlüssel | `ANTHROPIC_API_KEY`, gesendet als `x-api-key` | `PHASEO_API_KEY` als `authToken` / `auth_token`, gesendet als `Authorization: Bearer` |
| Modell | `claude-sonnet-5-5` | `anthropic/claude-sonnet-5.5` oder eine beliebige ID aus `GET /v1/models` |
| Messages-Aufruf | `messages.create` | Unverändert |

## Client umstellen

Erstelle einen Schlüssel unter [API-Schlüssel](https://phaseo.app/settings/keys) und stelle ihn der App als `PHASEO_API_KEY` bereit.

<CodeGroup>
```typescript TypeScript
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic({
  apiKey: null,
  authToken: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app",
});

const response = await client.messages.create({
  model: "anthropic/claude-sonnet-5.5",
  max_tokens: 256,
  messages: [{ role: "user", content: "Reply with: migration ready" }],
});
```

```python Python
import os
import anthropic

client = anthropic.Anthropic(
    auth_token=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app",
)

response = client.messages.create(
    model="anthropic/claude-sonnet-5.5",
    max_tokens=256,
    messages=[{"role": "user", "content": "Reply with: migration ready"}],
)
```

```bash cURL
curl https://api.phaseo.app/v1/messages \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-sonnet-5.5",
    "max_tokens": 256,
    "messages": [{"role": "user", "content": "Reply with: migration ready"}]
  }'
```
</CodeGroup>

Drei Details lassen diesen Schritt am häufigsten scheitern:

- **Verwende den Root-Host.** `baseURL: "https://api.phaseo.app/v1"` ergibt `/v1/v1/messages`. OpenAI-kompatible Clients im selben Repository verwenden weiterhin `/v1`.
- **Sende den Schlüssel als Bearer-Token.** Das Gateway liest nur `Authorization: Bearer`; ein `x-api-key`-Header erhält `401` `missing_or_invalid_authorization_header`. `authToken` sendet in jeder SDK-Version Bearer. `apiKey` tut das erst ab `@anthropic-ai/sdk` 1.0 und `anthropic` 2.0.
- **Entferne `ANTHROPIC_API_KEY`** aus Umgebungen, die jetzt Phaseo aufrufen. `apiKey: null` verhindert, dass ältere TypeScript-SDKs ihn lesen, und Python-SDKs vor 0.98 lesen ihn selbst dann, wenn `auth_token` gesetzt ist.

Tools, die über Umgebungsvariablen konfiguriert werden, etwa Claude Code, verwenden `ANTHROPIC_BASE_URL=https://api.phaseo.app`, `ANTHROPIC_AUTH_TOKEN` mit dem Phaseo-Schlüssel und ein leeres `ANTHROPIC_API_KEY`.

## Modell-IDs zuordnen

Prüfe jedes Produktionsmodell gegen `data[].id` aus `GET /v1/models?format=openai`. Phaseo-IDs verwenden Punkte in der Version: Aus `claude-sonnet-5-5` wird `anthropic/claude-sonnet-5.5`. Wenn sich auch das Modell ändert, lies die passende [Anleitung zur Modellmigration](../model-migrations).

## Was anders funktioniert

| Anthropic-Funktion | Bei Phaseo |
| --- | --- |
| `anthropic-version`-Header | Jeder Wert wird akzeptiert; Phaseo ruft Claude mit seiner eigenen Version auf. |
| `anthropic-beta`-Header | Werden nicht weitergeleitet. Phaseo fügt die Betas hinzu, die seine unterstützten Funktionen brauchen; reine Beta-Felder im Body wie `mcp_servers` geben `400` zurück. |
| `temperature`, `top_p`, `top_k` | Werden verworfen, wo Modell oder Route sie nicht annehmen, und in `X-Phaseo-Dropped-Params` aufgeführt. |
| `speed: "fast"` | Gibt `400` zurück. Verwende `service_tier: "fast"`. |
| Native Tools für Websuche und Web Fetch | Werden akzeptiert, wo der Anbieter sie ausführt; alternativ das Server-Tool `phaseo:web_search` von Phaseo. |
| `cache_control` | Auf oberster Ebene oder pro Block unterstützt. Siehe [Prompt-Caching](../guides/prompt-caching). |
| `metadata.user_id` | Wird nicht als Endbenutzer-ID verwendet. Sende `user` oder den Header `X-Phaseo-User-Id` für Ratenlimit-Richtlinien pro Endbenutzer. |
| Message Batches (`/v1/messages/batches`) | Diesen Pfad gibt es nicht. `/v1/batches` akzeptiert `/v1/messages`-Zeilen in einer anderen Form. |
| Tokenzählung (`/v1/messages/count_tokens`) | Keine Entsprechung. Belasse sie bei Anthropic oder schätze clientseitig. |
| Files API (`client.beta.files`) | Keine Entsprechung. Sende Dokumente inline. |
| Clients `AnthropicBedrock`, `AnthropicVertex` | Ersetze sie durch den normalen `Anthropic`-Client; Cloud-Authentifizierung und Regionseinstellungen entfallen. |

## Testen und umstellen

Teste System-Prompts, Streaming, Tool-Nutzung, Thinking und strukturierte Ausgaben mit genau den Modell-IDs, die die App verwendet. Vergleiche dann einen repräsentativen Prompt-Satz in beiden Konfigurationen hinsichtlich Ausgabeform, Latenz, Tokennutzung, Fehlern und Kosten. Bevor du Traffic verschiebst:

- der Phaseo-Schlüssel ist in jeder Deployment-Umgebung gesetzt;
- jede Produktions-Modell-ID steht in `GET /v1/models?format=openai`;
- Streaming- und Tool-Abläufe bestehen in Staging;
- jeder `anthropic-beta`-Header und jedes reine Beta-Feld wurde entfernt oder ersetzt;
- das Zurückrollen ist weiterhin nur eine Änderung von Basis-URL und Schlüssel.
