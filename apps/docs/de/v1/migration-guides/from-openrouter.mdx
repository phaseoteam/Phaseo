Ändere die Basis-URL in `https://api.phaseo.app/v1` und den Schlüssel in `PHASEO_API_KEY`. Anfrage-Payloads, der Header `Authorization: Bearer`, das `provider`-Objekt und das Fallback-Array `models` funktionieren weiter; prüfe die Modell-IDs und die wenigen Felder in der Tabelle unten.

| Einstellung | OpenRouter | Phaseo |
| --- | --- | --- |
| Basis-URL | `https://openrouter.ai/api/v1` | `https://api.phaseo.app/v1` |
| API-Schlüssel | `OPENROUTER_API_KEY` (`sk-or-v1-…`) | `PHASEO_API_KEY` |
| Authentifizierung | `Authorization: Bearer <key>` | Unverändert |
| Anfrage-Payload | OpenAI-kompatibel | Unverändert |
| Modell-IDs | `<org>/<model>` | `<org>/<model>`; die meisten stimmen überein, einige Organisationen weichen ab |
| Zuordnungs-Header | `HTTP-Referer`, `X-Title` | Unverändert; ergänze `X-App-Id` für eine stabile Gruppierung |

## Client umstellen

<CodeGroup>
```typescript Vorher
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.OPENROUTER_API_KEY,
  baseURL: "https://openrouter.ai/api/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Summarize our migration plan." }],
});
```

```typescript Nachher
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Summarize our migration plan." }],
});
```

```bash cURL
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role":"user","content":"Say hello"}]
  }'
```
</CodeGroup>

Lass die Payload im ersten Durchgang unverändert und stelle Gleichwertigkeit her, bevor du optimierst. Entferne `OPENROUTER_BASE_URL` und den alten Schlüssel aus Code, CI und Hosting-Einstellungen. Aus `@openrouter/ai-sdk-provider` wird `@phaseo/ai-sdk-provider` (siehe [Von Vercel AI Gateway migrieren](./from-vercel)); die eigenen SDKs von OpenRouter (`@openrouter/sdk`, `openrouter` auf PyPI) brauchen einen Client-Wechsel, nicht nur eine neue Basis-URL.

## Modell-IDs prüfen

Die meisten IDs stimmen überein, einige Organisationen weichen aber ab: `x-ai/` heißt `spacex-ai/`, `meta-llama/` heißt `meta/` und `mistralai/` heißt `mistral/`. Liste die IDs von Phaseo auf und prüfe jedes Produktionsmodell dagegen:

```bash
curl -s "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY" | jq -r '.data[].id'
```

Die Standardliste enthält nur Modelle, die du jetzt aufrufen kannst; füge `availability=all` hinzu, um inaktive oder demnächst verfügbare Modelle zu sehen. Ohne `format=openai` ist die Antwort die seitenweise `models`-Liste von Phaseo, die kein `data`-Array hat.

## Anfragefelder zuordnen

| OpenRouter | Bei Phaseo |
| --- | --- |
| `provider.order`, `only`, `ignore`, `allow_fallbacks`, `require_parameters`, `max_price` | Dieselben Felder. Verwende Basis-Anbieter-IDs, keine Endpunkt-Slugs. |
| `provider.sort` | Dasselbe Feld: `price`, `latency` oder `throughput`. |
| `provider.zdr` | Wird als Alias von `provider.require_zero_data_retention` akzeptiert. |
| `provider.data_collection: "deny"` | Gibt `400` zurück. Verwende stattdessen `zdr: true`. |
| Fallback-Array `models` | Gleich, 1 bis 25 Einträge. `model` ist Pflicht, verschiebe also `models[0]` dorthin. |
| Suffix `:nitro` | Gleich (Durchsatz). Phaseo hat außerdem `:cheap` und `:fast`; aus `:floor` wird `:cheap`. Entferne `:online` und `:thinking` und verwende stattdessen Websuche und `reasoning`. |
| `openrouter/auto`, `openrouter/free` | `phaseo/auto` ([Auto-Routing](../guides/auto-routing), Alpha, nicht mit `models` kombinierbar) und `phaseo/free`. |
| `plugins` `web`, `web-fetch`, `response-healing` | Dieselben Plugin-IDs. Andere Plugins wie `file-parser` geben `400` zurück. |
| `transforms`, `usage: { include: true }` | Werden nicht akzeptiert. Entferne sie; Nutzung und Kosten werden immer zurückgegeben. |
| `X-OpenRouter-Title` | Benenne ihn in `X-Title` um. Siehe [App-Zuordnung](../guides/app-attribution). |
| Presets `@preset/<slug>` | Lege sie als [Presets](../guides/presets) neu an und rufe sie als `"model": "@slug"` auf. |
| `usage.cost`, `reasoning_details`, `provider` in Antworten | Werden zurückgegeben. `native_finish_reason` und `is_byok` nicht; normalisiere sie in einer Schicht, falls Aufrufer sie lesen. |

Phaseo hat außerdem `provider.required_execution_region` und `provider.required_data_region`, für die es bei OpenRouter keine Entsprechung gibt. Vollständige Anfragen findest du unter [Anbieter pro Anfrage festlegen oder ignorieren](../cookbook/pin-or-ignore-providers-per-request) und [Nur an EU- oder ZDR-fähige Anbieter routen](../cookbook/route-only-to-eu-or-zdr-providers).

Behalte verbleibende OpenRouter-spezifische Felder in einem einzigen Adapter statt an jeder Aufrufstelle, damit das Zurückrollen eine Änderung von Basis-URL und Schlüssel bleibt.

## Vor der Umstellung prüfen

Führe diese Prüfungen gegen Phaseo aus und dann dieselben Prüfungen über den eigenen Client-Pfad deiner App:

```bash
curl -s "https://api.phaseo.app/v1/health"

curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"openai/gpt-6-astra","messages":[{"role":"user","content":"Say hello"}]}'

# Streaming
curl -N "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"openai/gpt-6-astra","stream":true,"messages":[{"role":"user","content":"Reply with: stream works"}]}'

# Ungültiges Modell: Die App sollte den Fehler behandeln, ohne Zugangsdaten preiszugeben
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"invalid/migration-test","messages":[{"role":"user","content":"test"}]}'
```

Bevor du nennenswerten Traffic verschiebst, prüfe, dass:

- `OPENROUTER_API_KEY` in jeder Umgebung durch `PHASEO_API_KEY` ersetzt ist;
- jede Produktions-Modell-ID in `GET /v1/models?format=openai` steht;
- eine Anfrage ohne und eine mit Streaming über `/v1/chat/completions` oder `/v1/responses` bestehen, über denselben Client-Pfad wie in der Produktion;
- Abläufe mit Tool-Aufrufen und strukturierten Ausgaben mit echten Prompts bestehen;
- Fehler durch ungültige Schlüssel und ungültige Modelle behandelt werden;
- sich eine fehlgeschlagene Anfrage mit `GET /v1/generations?id=<request_id>` nachschlagen und, wenn `replay_supported` `true` ist, aus `replay_request` wiederholen lässt;
- OpenRouter-spezifische Header und Antwortfelder entfernt oder normalisiert sind und gemeinsame Standards in Presets liegen.

## Umstellen

1. Beginne mit internem Traffic.
2. Verschiebe 5-10 % des Produktions-Traffics und vergleiche Qualität, Latenz und Kosten.
3. Gehe auf 100 %, sobald die Gleichwertigkeit bestätigt ist.
4. Halte das Zurückrollen als Wechsel von Basis-URL und Schlüssel bereit, bis die Umstellung stabil ist.

## Die Migration an einen Coding-Agenten übergeben

Gib dem Agenten diese klar begrenzte Abfolge oder installiere den [Skill für die Migration von OpenRouter zu Phaseo](https://github.com/phaseoteam/Phaseo/tree/main/.agents/skills/openrouter-to-phaseo-migration), der dieselben Schritte für Bestandsaufnahme, Zuordnung, Prüfung und Zurückrollen bündelt:

1. Durchsuche Laufzeitcode und Deployment-Konfiguration nach `openrouter.ai`, `OPENROUTER_API_KEY`, `sk-or-v1`, `HTTP-Referer` und `X-Title`.
2. Stelle die Client-Grenze auf `https://api.phaseo.app/v1` und `PHASEO_API_KEY` um, ohne einen geheimen Wert in die Versionskontrolle aufzunehmen.
3. Frage `GET /v1/models?format=openai` ab und notiere jede Zuordnung von alter zu neuer Modell-ID.
4. Passe OpenRouter-spezifische Routing-Optionen oder Antwortfelder in einem einzigen Kompatibilitätsmodul an.
5. Führe die oben genannten Prüfungen für Health, Anfragen ohne und mit Streaming sowie Fehlerpfade aus.
6. Berichte über geänderte Dateien, geänderte Secret-Namen, Modellzuordnungen, Testnachweise, Lücken in der Gleichwertigkeit und den Schalter zum Zurückrollen.

Für eine geführte Version öffne den [interaktiven OpenRouter-Migrationsleitfaden](https://phaseo.app/migrate/openrouter), sieh dir an, wie sich die beiden [im Vergleich](https://phaseo.app/compare/openrouter) schlagen, oder [hol dir kostenlose Hilfe bei der Migration](https://phaseo.app/contact).
