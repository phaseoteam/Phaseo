Wähle die GPT-5.6-Stufe, die zur Workload passt, tausche nur die Modell-ID aus und teste Reasoning-Effort, Tools, Latenz und Kosten neu. Behalte dein bisheriges GPT-5-Modell als Fallback, bis deine Evaluierungen bestanden sind.

## Stufe wählen

| Modell | Einsatzzweck | Reasoning-Effort |
| --- | --- | --- |
| `openai/gpt-5.6-sol` | Reasoning mit höchster Leistungsfähigkeit, agentisches Programmieren, wissenschaftliche Analysen und komplexe professionelle Arbeit | `none`, `low`, `medium`, `high`, `xhigh`, `max` |
| `openai/gpt-5.6-terra` | Ausgewogenes alltägliches Reasoning, Programmieren und Assistenzaufgaben | `none`, `low`, `medium`, `high`, `xhigh`, `max` |
| `openai/gpt-5.6-luna` | Aufgaben mit niedrigerer Latenz und Kostensensibilität | `none`, `low`, `medium`, `high`, `xhigh`, `max` |

Alle drei haben ein Kontextfenster von 1.050.000 Tokens und 128K Ausgabetokens. Jede Stufe hat außerdem eine Pro-ID (`openai/gpt-5.6-sol-pro`, `-terra-pro`, `-luna-pro`), die `reasoning.mode: "pro"` für dich sendet.

Der eigene Alias `gpt-5.6` von OpenAI zeigt auf `gpt-5.6-sol`; bei Phaseo rufst du die Stufen-IDs direkt auf. Die Stufen-Aliase `openai/gpt-sol-latest`, `openai/gpt-terra-latest` und `openai/gpt-luna-latest` folgen dem neuesten Modell jeder Stufe, und `openai/gpt-sol-latest` zeigt bereits über GPT-5.6 hinaus. Verwende sie nur, wenn künftige Versionen automatisch übernommen werden sollen.

## Anfrage anpassen

GPT-5.6 ergänzt auf jeder Stufe `max`, das höchste Reasoning-Budget. Verwende es nur dort, wo sich die zusätzliche Latenz und die Kosten lohnen.

<CodeGroup>
```json Responses
{
  "model": "openai/gpt-5.6-sol",
  "input": "Review this multi-service incident report and propose a rollback plan.",
  "reasoning": { "effort": "max" }
}
```

```json Chat Completions
{
  "model": "openai/gpt-5.6-terra",
  "messages": [
    { "role": "user", "content": "Design a test plan for this agent workflow." }
  ],
  "reasoning_effort": "medium"
}
```
</CodeGroup>

GPT-5.6 ergänzt außerdem:

- **`reasoning.mode: "pro"`** für schwierigere Aufgaben, ohne das Modell zu wechseln;
- **`reasoning.context`** (`auto`, `current_turn` oder `all_turns`), um zu steuern, welches Reasoning erhalten bleibt;
- Multi-Agent-Unterstützung als Beta und Programmatic Tool Calling für Tool-lastige Workflows;
- explizites Prompt-Caching mit `prompt_cache_options` und Cache-Breakpoints. Bei GPT-5.6 ersetzt `prompt_cache_options.ttl` das Feld `prompt_cache_retention`, das Phaseo nicht an GPT-5.6-Modelle sendet.

## Preise prüfen

Preise pro 1M Tokens in der Standardstufe von OpenAI, für Anfragen mit bis zu 272K Eingabetokens:

| Modell | Eingabe | Cache-Lesen | Cache-Schreiben (30 Min.) | Cache-Schreiben (12 Std.) | Ausgabe |
| --- | ---: | ---: | ---: | ---: | ---: |
| Sol | $5.00 | $0.50 | $6.25 | $12.50 | $30.00 |
| Terra | $2.00 | $0.20 | $2.50 | $5.00 | $12.00 |
| Luna | $0.20 | $0.02 | $0.25 | $0.50 | $1.20 |

Anfragen mit mehr als 272K Eingabetokens kosten mehr: Sol $10.00 Eingabe und $45.00 Ausgabe, Terra $4.00 und $18.00, Luna $0.40 und $1.80, wobei die Cache-Preise im selben Verhältnis steigen. Bis zum 30. November 2026 gilt der Aktionspreis von OpenAI für Sol: $4.00 Eingabe und $20.00 Ausgabe bis 272K Tokens. Aktuelle Preise für andere Stufen und Anbieter findest du auf der Modellseite.

Ein Cache-Lesevorgang kostet 10 % des Eingabepreises, ein 30-Minuten-Schreibvorgang 1.25× und ein 12-Stunden-Schreibvorgang 2.5×. Jedes Eingabetoken wird zu genau einem dieser Preise abgerechnet. Die Nutzung zählt Cache-Lese- und -Schreibvorgänge in `input_tokens` (`prompt_tokens` bei Chat Completions) und weist Schreibvorgänge in `cache_write_tokens` aus; siehe [Felder für Nutzung und Preise](../guides/prompt-caching.mdx#usage-and-pricing-fields).

## Wiederholten Kontext cachen

Lege den stabilen Teil des Prompts in einen cachebaren Block und setze anfragespezifischen Text dahinter:

```json
{
  "model": "openai/gpt-5.6-sol",
  "input": [
    {
      "role": "user",
      "content": [
        {
          "type": "input_text",
          "text": "Stable policy document...",
          "prompt_cache_breakpoint": { "mode": "explicit" }
        },
        {
          "type": "input_text",
          "text": "Apply the policy to this new customer request."
        }
      ]
    }
  ],
  "prompt_cache_options": { "mode": "explicit", "ttl": "30m" }
}
```

- `prompt_cache_breakpoint` cacht alles bis einschließlich seines Blocks. Im Modus `explicit` cacht OpenAI nur die Breakpoints, die du setzt.
- Ein Block-`cache_control` wie `{"type": "ephemeral"}` funktioniert ebenfalls; Phaseo sendet es an GPT-5.6 als `prompt_cache_breakpoint`. Beide Markierungen kommen bei Claude als Cache-Breakpoint an, sodass auch ein Fallback auf Claude cacht.
- `ttl` ist `30m` (Standard) oder `12h`. Welche Routen es annehmen, steht unter [12-Stunden-Cache bei OpenAI](../guides/prompt-caching.mdx#12-hour-cache-on-openai), die übrigen Felder unter [Aufbewahrung und Optionen bei OpenAI](../guides/prompt-caching.mdx#openai-retention-and-options).

## Was du testen solltest

- **Reasoning und Ausgabequalität:** jede Stufe mit den Effort-Werten, die du anbietest, einschließlich `max`, wo Qualität Vorrang hat; Standard im Vergleich zu `reasoning.mode: "pro"` bei schwierigen Aufgaben; Schema-Erfolgsquote und Qualität der Tool-Aufrufe auf jeder Stufe.
- **Kosten und Latenz:** Latenz pro Effort, Zuwachs an Ausgabetokens gegenüber deiner aktuellen Basis, das Verhältnis von Cache-Lese- und -Schreibvorgängen bei wiederholten Prompts und Kosten pro erfolgreicher Aufgabe statt Preis pro Token.

## Umstellen

1. Behalte dein bisheriges GPT-5-Modell als Fallback in `models`.
2. Halte `max` hinter einem Konfigurations-Flag oder [Preset](../guides/presets), bis es sich mit produktionsnahen Prompts bewährt hat.
3. Überwache das Volumen der Cache-Schreibvorgänge getrennt von den Cache-Lesevorgängen.
4. Mach GPT-5.6 erst zum Standard, wenn deine Evaluierungen Aufgabenerfolg, Kosten und Latenz bestätigen.
