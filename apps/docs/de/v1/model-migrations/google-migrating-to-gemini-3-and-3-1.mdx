Lege die Reasoning-Tiefe mit `reasoning.effort` fest, das Phaseo als `thinking_level` an Gemini 3 sendet, und schicke Assistant-Züge mit Tool-Aufrufen genau so zurück, wie Phaseo sie geliefert hat, damit die Thought Signatures erhalten bleiben. Behandle Gemini 3 und Gemini 3.1 Pro als zwei getrennte Migrationen.

| Phaseo-Modell-ID | Status |
| --- | --- |
| `google/gemini-3.1-pro-preview` | Verfügbar |
| `google/gemini-3-flash-preview` | Verfügbar |
| `google/gemini-3.1-flash-lite` | Veraltet; wird am 7. Mai 2027 eingestellt |
| `google/gemini-3-pro-preview` | Am 9. März 2026 eingestellt; Anfragen werden zu `google/gemini-3.1-pro-preview` geleitet |
| `google/gemini-3.1-flash-lite-preview` | Am 25. Mai 2026 eingestellt; Anfragen werden zu `google/gemini-3.1-flash-lite` geleitet |

Eingestellte IDs funktionieren nur noch über den automatischen Ersatz weiter; siehe [Veraltung und Einstellung von Modellen](../guides/model-retirement). Rufe direkt die aktuelle ID auf.

## Reasoning-Tiefe festlegen

Gemini 3 hat Thinking-Budgets durch `thinking_level` ersetzt. Phaseo ordnet `reasoning.effort` (oder das flache `reasoning_effort`) diesem Wert zu:

| `reasoning.effort` | Gemini 3 Flash | Gemini 3.1 Pro |
| --- | --- | --- |
| `minimal` | `MINIMAL` | `LOW` (3.1 Pro hat kein `MINIMAL`) |
| `low` | `LOW` | `LOW` |
| `medium` | `MEDIUM` | `MEDIUM` |
| `high`, `xhigh`, `max` | `HIGH` | `HIGH` |

```json
{
  "model": "google/gemini-3.1-pro-preview",
  "messages": [{ "role": "user", "content": "Compare these three architecture options." }],
  "reasoning": { "effort": "medium" }
}
```

Die Stufen verhalten sich nicht eins zu eins wie die Effort-Einstellungen anderer Anbieter, teste Latenz und Qualität also auf jeder Stufe neu, die du anbietest.

## Thought Signatures erhalten

Gemini 3 gibt Thought Signatures zurück, die Reasoning-Kontext über Aufrufe hinweg mitführen; beim Function Calling kann eine fehlende Signatur die Qualität senken oder `400` zurückgeben. Schicke jeden Assistant-Zug einschließlich seiner Tool-Aufrufe genau so zurück, wie Phaseo ihn geliefert hat. Phaseo spielt eine Signatur an das Modell zurück, das sie ausgestellt hat; fehlt eine oder stammt sie von einem anderen Modell, sendet Phaseo den Skip-Platzhalter von Google, damit die Anfrage nicht fehlschlägt.

## Prompts und Medien überarbeiten

Googles Hinweise zu Gemini 3 bevorzugen direkte Prompts und Steuerung über Parameter statt langer Prompt-Gerüste. Wenn deine Prompts das Verhalten älterer Modelle ausgleichen, vereinfache sie und evaluiere neu.

Gemini 3 hat außerdem `media_resolution` für Bilder und Dokumente eingeführt. Phaseo stellt diesen Parameter nicht bereit, daher gilt der Standard von Google; teste Routen mit Bildern, Dokumenten und gemischten Medien neu, statt anzunehmen, dass ältere Ergebnisse weiter gelten.

## Was du testen solltest

- **Reasoning:** knappe gegenüber gerüstartigen Prompts, schrittweise Aufgaben, Synthese mit langem Kontext und Agenten-Workflows, die von durchgehendem Reasoning abhängen.
- **Antworten:** Signaturen über mehrere Züge, Erfolgsquote beim Function Calling, Schema-Erfolgsquote sowie leere, unvollständige oder fehlerhafte Ausgaben nach einer Effort-Änderung.
- **Produktionsmetriken:** Latenz pro Stufe, Tokenverbrauch und Kosten, multimodale Routen und Aufgabenerfolg bei Gemini 3 im Vergleich zu Gemini 3.1 Pro.

## Umstellen

1. Migriere zuerst die Anfrageform und den Umgang mit Signaturen.
2. Führe Prompt- und Schema-Evaluierungen auf Gemini 3 erneut aus.
3. Stufe Gemini 3.1 Pro getrennt für die Routen hoch, die tieferes Reasoning brauchen.
4. Behalte für Workloads mit hohem Volumen einen günstigeren Fallback.
