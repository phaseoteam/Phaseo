Ändere das Modell in `mistral/mistral-small-4` und entscheide pro Route, ob Reasoning aktiv ist. Mistral Small 4 hat zwei Reasoning-Modi, aus und hoch, und Phaseo ordnet jeden Effort-Wert einem davon zu.

```json
{
  "model": "mistral/mistral-small-4",
  "messages": [
    { "role": "user", "content": "Why is fast inference important?" }
  ],
  "reasoning": { "effort": "high" }
}
```

## Reasoning ein- oder ausschalten

Reasoning ist aus, solange die Anfrage es nicht verlangt. Über die eigene API von Mistral sendet Phaseo `reasoning_effort` wie folgt:

| Anfrage | An Mistral gesendet |
| --- | --- |
| Keine Reasoning-Einstellung | `reasoning_effort: "none"` |
| `reasoning.effort: "none"` oder `reasoning.enabled: false` | `reasoning_effort: "none"` |
| Jeder andere `reasoning.effort` oder `reasoning.enabled: true` | `reasoning_effort: "high"` |

Ein flaches `reasoning_effort` in der Anfrage hat Vorrang vor `reasoning.effort`. Verwende `none` für leichte Routen und `high` für tiefes Reasoning; `low` und `medium` verhalten sich genau wie `high`.

## Antwort und Reasoning lesen

Mistral kann gemischte Inhaltsblöcke zurückgeben, etwa `thinking` gefolgt von `text`. Phaseo teilt sie in Felder im OpenAI-Stil auf, sodass nachgelagerter Code, der Chat Completions liest, weiter funktioniert:

- die Antwort steht in `choices[0].message.content`;
- der Reasoning-Text steht in `choices[0].message.reasoning_content` und `reasoning_details`.

## Umstellen

1. Ändere die Modell-ID von Mistral Small 3.2 in `mistral/mistral-small-4`.
2. Teste Reasoning nur mit `none` und `high`.
3. Führe Tests zu Ausgabequalität und Schema auf den Routen, die `high` verwenden, erneut aus.
4. Vergleiche Latenz und Kosten für `none` und `high` vor der vollständigen Umstellung.
