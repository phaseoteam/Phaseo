Behandle jeden Tool-Aufruf als nicht vertrauenswürdige Eingabe: Prüfe den Tool-Namen gegen eine Zulassungsliste und validiere die Argumente, bevor irgendetwas ausgeführt wird.

```typescript
import { z } from "zod";

const WeatherArgs = z.object({
  city: z.string().min(1),
});

function executeToolCall(name: string, rawArgs: string) {
  if (name !== "get_weather") {
    throw new Error(`Unsupported tool: ${name}`);
  }

  const parsed = WeatherArgs.parse(JSON.parse(rawArgs));
  return getWeather(parsed.city);
}
```

## Checkliste

- **Halte Schemas klein und eindeutig.** Weniger, typisierte Felder lassen dem Modell weniger Raum, etwas Unerwartetes zu senden.
- **Validiere geparste Argumente** vor der Ausführung, wie oben.
- **Lehne unbekannte Tool-Namen ab**, statt zu raten, was das Modell gemeint hat.
- **Füge Timeouts und Wiederholungsversuche** zu Aufrufen hinzu, die externe Systeme erreichen.
- **Protokolliere** die Aufruf-ID, den Tool-Namen und jeden Validierungsfehler.

## Wenn die Validierung fehlschlägt

Führe das Tool nicht aus. Sende im nächsten Durchgang einen kurzen, kontrollierten Fehler als Tool-Ergebnis und bitte das Modell, es mit korrigierten Argumenten erneut zu versuchen.

## Streaming

Mit `stream: true` kommen die Argumente in Teilen an. Sammle alle Argument-Deltas eines Aufrufs, bevor du ihn parst, validierst oder ausführst. Ob Tool-Aufrufe überhaupt gestreamt werden, hängt vom Modell und vom Anbieter ab. Siehe [Streaming](./streaming.mdx).
