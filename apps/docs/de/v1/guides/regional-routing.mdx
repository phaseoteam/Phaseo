Sende Textanfragen an `eu.api.phaseo.app` oder `us.api.phaseo.app`, um nur Anbieterrouten zu nutzen, die das Modell in dieser Region ausführen und Prompt- und Antwortdaten dort verarbeiten. Modell-IDs und API-Schlüssel bleiben gleich. Chat Completions, Responses und Messages werden unterstützt.

| Region | Basis-URL | Genutzte Anbieterrouten |
| --- | --- | --- |
| Europäische Union | `https://eu.api.phaseo.app/v1` | Nur Routen, die Ausführung und Datenverarbeitung in der EU deklarieren |
| Vereinigte Staaten | `https://us.api.phaseo.app/v1` | Nur Routen, die Ausführung und Datenverarbeitung in den USA deklarieren |
| Global | `https://api.phaseo.app/v1` | Die standardmäßige globale Routing-Richtlinie |

<Warning>
Regionales Routing ist noch keine durchgängige Garantie für Datenresidenz. Phaseo beschränkt die Anbieterauswahl und platziert das Gateway nahe der Region, aber gemeinsame Konto-, Abrechnungs-, Cache- und Betriebssysteme können Daten außerhalb davon verarbeiten. Siehe [Was außerhalb der Region bleibt](#what-stays-outside-the-region).
</Warning>

## Eine regionale Anfrage senden

<CodeGroup>
```ts TypeScript
import { Phaseo } from "@phaseo/sdk";

const phaseo = new Phaseo({
  apiKey: process.env.PHASEO_API_KEY!,
  region: "eu",
});

const response = await phaseo.responses.create({
  model: "openai/gpt-5.6-luna",
  input: "Summarize this note in one sentence.",
});

console.log(response.output_text);
```

```python Python
import os
from phaseo import Phaseo

phaseo = Phaseo(
    api_key=os.environ["PHASEO_API_KEY"],
    region="eu",
)

response = phaseo.responses.create({
    "model": "openai/gpt-5.6-luna",
    "input": "Summarize this note in one sentence.",
})

print(response.get("output_text"))
```

```bash Chat Completions
curl https://eu.api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5.6-luna",
    "messages": [
      {"role": "user", "content": "Write a two-line status update."}
    ]
  }'
```

```bash Responses
curl https://eu.api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5.6-luna",
    "input": "Extract the three most important actions from this note."
  }'
```

```bash Messages
curl https://us.api.phaseo.app/v1/messages \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -H "anthropic-version: 2023-06-01" \
  -d '{
    "model": "anthropic/claude-sonnet-5.5",
    "max_tokens": 256,
    "messages": [
      {"role": "user", "content": "Summarize this incident report."}
    ]
  }'
```
</CodeGroup>

Setze in den SDKs `region` auf `"eu"` oder `"us"`; lass es weg oder verwende `"global"` für globales Routing. Das SDK wirft einen Fehler, wenn du sowohl `region` als auch eine benutzerdefinierte `baseUrl` (`base_url` in Python) setzt, weil beide unterschiedliche Hosts auswählen.

Der Hostname ist die Richtlinie. Ein `required_execution_region` oder `required_data_region` in der Anfrage oder einer Voreinstellung, das eine andere Region nennt, schlägt mit `400 validation_error` und dem Grund `deployment_region_conflict` fehl. Voreinstellungen und dynamische Routing-Regeln werden zuerst angewendet und die regionale Regel zuletzt, sodass sie diese nicht abschwächen können. Phaseo wiederholt nie über einen Anbieter außerhalb der Region.

## Was eine regionale Anfrage enthalten kann

| Unterstützt | Abgelehnt |
| --- | --- |
| Texteingabe und Textausgabe | Bilder, Audio, Video, Dokumente, Dateien und Anhänge |
| Mit und ohne Streaming | Nichttextuelle Ausgabemodalitäten |
| System- und Developer-Anweisungen | Beim Anbieter gehostete Tools wie Websuche, Dateisuche, Codeausführung, Computerbedienung und Bilderzeugung sowie `web_search_options` |
| Deine eigenen `function`- und `custom`-Tools sowie Tool-Ergebnisse als Text | Phaseo-[Server-Tools](./server-tools) (`phaseo:`-Typen) |
| Strukturierter Text und JSON-Ausgabe, sofern das Modell sie unterstützt | Endpunkte für Bilder, Audio, Video, Embeddings, Moderation, Batch, Dateien, Webhooks und Echtzeit |
| Voreinstellungen, Anbieterreihenfolge, Fallbacks und Preisgrenzen, die der Region nicht widersprechen | |

Deine eigenen Tools sind erlaubt, weil sie in deiner Anwendung laufen. Gehostete Tools und Server-Tools laufen an einem Ort, den die regionale Regel nicht kontrollieren kann.

## In einer Region verfügbare Modelle finden

Rufe `/v1/models` auf demselben Hostnamen auf, an den du Anfragen sendest. Die Verfügbarkeit unterscheidet sich zwischen EU-, US- und globalen Endpunkten.

```bash
curl https://eu.api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

Die Liste enthält nur Modelle mit einer aktiven Anbieterroute, deren deklarierte Ausführungs- und Datenregionen beide die Region einschließen, und führt nur Chat Completions, Responses und Messages mit Texteingabe und -ausgabe auf. Jedes Angebot zeigt seine Regionen:

```json
{
  "provider": { "id": "example-eu", "name": "Example EU" },
  "residency": {
    "execution_regions": ["eu"],
    "data_regions": ["eu"]
  }
}
```

## Prüfen, welches Gateway eine Anfrage verarbeitet hat

Regionale Antworten tragen `X-Phaseo-Gateway-Region: eu` (oder `us`). Der Header nennt die regionale Richtlinie, die die Anfrage verarbeitet hat; er belegt nicht, wo Cloudflare sie ausgeführt hat. Die Anfragedetails erfassen außerdem die geforderten Ausführungs- und Datenregionen, den ausgewählten Anbieter und dessen deklarierte Regionen.

## Fehler

Verstöße gegen die regionale Regel geben `400 not_supported` mit einem dieser `reason`-Werte zurück:

| `reason` | Ursache | Lösung |
| --- | --- | --- |
| `regional_endpoint_not_supported` | Der Pfad ist regional nicht verfügbar | Verwende Chat Completions, Responses oder Messages oder die globale API |
| `regional_non_text_content` | Medien, eine Datei oder ein Anhang in der Anfrage | Entferne sie oder verwende die globale API |
| `regional_non_text_output` | Eine nichttextuelle Ausgabemodalität wurde angefordert | Fordere Text an oder verwende die globale API |
| `regional_hosted_tool_not_supported` | Ein anderes Tool als `function` oder `custom` | Verwende dein eigenes Funktions-Tool oder die globale API |

`400 validation_error` mit dem Grund `deployment_region_conflict` bedeutet, dass die Anfrage oder eine Voreinstellung eine andere Region nennt; entferne diese Einstellung. Erfüllt keine funktionsfähige Anbieterroute sowohl das Modell als auch die Region, stoppt die Anfrage, bevor ein Anbieter aufgerufen wird; wähle ein Modell, das der regionale Endpunkt `/v1/models` auflistet.

## Was außerhalb der Region bleibt

Die regionale Regel deckt ab, welcher Anbieter das Modell ausführt und Prompt- und Antwortdaten verarbeitet. Den gesamten Lebenszyklus einer Anfrage deckt sie noch nicht ab:

- Die Cloudflare-Platzierung bringt das Gateway nahe an die Region, ist aber keine Compliance-Grenze.
- Konto, Authentifizierung, Abrechnung und Anfragemetadaten liegen auf gemeinsamer Supabase-Infrastruktur.
- Cloudflare KV und Worker-Aufrufprotokolle sind nicht an eine Region gebunden.
- Aufrufe an den Anbieter gehen an dessen regionalen Endpunkt, unabhängig davon, wo Cloudflare das Gateway platziert hat.
- Support- und Betriebspersonal ist nicht auf die Region beschränkt.

Phaseo wird dies erst dann durchgängige Datenresidenz nennen, wenn Gateway, Speicherung, Protokollierung, Anbieter und Betriebsabläufe alle durchsetzbare regionale Kontrollen haben.
