Sende jede Nutzerbewertung an `POST /v1/feedback`, zusammen mit der Anfrage-ID und der [Voreinstellung](./presets.mdx), die geantwortet hat. Vergleiche Voreinstellungen dann danach, wie oft ihre Antworten gut bewertet wurden, und nicht nur nach Latenz und Kosten.

<Note>
Voreinstellungsfeedback befindet sich in der Alpha-Phase, API und Dashboard können sich noch ändern. Über die Schaltfläche **Feedback** auf der [Seite für Voreinstellungsfeedback](https://phaseo.app/settings/presets/experiments) kannst du uns mitteilen, was die Funktion nützlicher machen würde.
</Note>

## Eine Bewertung erfassen

Du brauchst einen API-Schlüssel mit der Fähigkeit `feedback:write`, die von Phaseo zurückgegebene Anfrage-ID und die UUID der Voreinstellung. Erst die ID der Voreinstellung bringt das Ereignis in Vergleiche von Voreinstellungen und in Kohortenanalysen.

```bash cURL
curl https://api.phaseo.app/v1/feedback \
  -X POST \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "requestId": "gen_01K...",
    "presetId": "8f54b2d9-9ba3-4ced-8a7f-9bb70a44dbea",
    "rating": "thumbs_up",
    "score": 1,
    "comment": "The answer resolved the customer question.",
    "metadataDimensions": {
      "plan": "pro",
      "surface": "support_chat"
    }
  }'
```

Ein Feedback-Ereignis muss sich auf mindestens eine Anfrage, Sitzung, Voreinstellung oder einen Testlauf beziehen. `score` ist optional und muss zwischen `0` und `1` liegen.

Lege Werte mit niedriger Kardinalität wie Tarif, Deployment, Sprache oder Anwendungsoberfläche in `metadataDimensions` ab, damit du danach filtern kannst. Beliebigen oder hochkardinalen Kontext legst du stattdessen in `metadata` ab.

## Eine Bewertung wählen

| Signal | `rating` |
| --- | --- |
| Eine einfache Nutzerreaktion | `thumbs_up`, `thumbs_down` |
| Eine bewertete Antwort | `correct`, `partly_correct`, `incorrect` |
| Ein Betriebsproblem | `bad_format`, `too_slow`, `too_expensive` |
| Ein Sicherheitsergebnis | `unsafe`, `refused_incorrectly` |
| Alles andere | `not_helpful`, `other` |

Ziehe eine explizite Bewertung einem reinen numerischen Score vor: Vergleiche von Voreinstellungen beruhen auf Bewertungen, Scores werden als ergänzendes Detail angezeigt.

## Voreinstellungen vergleichen

Öffne [Einstellungen → Voreinstellungen → Feedback](https://phaseo.app/settings/presets/experiments), um:

- positive, teilweise und negative Raten zu vergleichen
- eine Baseline-Voreinstellung auszuwählen
- nach Datum, Bewertung und Metadaten-Dimensionen zu filtern
- die Anfrage, Sitzung, Kommentare und Tags hinter einem Ereignis zu untersuchen

Das Dashboard analysiert im ausgewählten Zeitraum höchstens die 10.000 neuesten passenden Feedback-Zeilen.

## Feedback über die API lesen

Zum Lesen brauchst du `feedback:read`. Die Ergebnisse sind auf den authentifizierten Arbeitsbereich und die für den Aufrufer sichtbaren Voreinstellungen beschränkt.

Aktuelle Ereignisse auflisten:

```bash
curl "https://api.phaseo.app/v1/feedback?preset_id=PRESET_UUID&limit=100" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

Eine auf dem Server berechnete Zusammenfassung abrufen:

```bash
curl "https://api.phaseo.app/v1/feedback/summary?group_by=preset&since=2026-08-01T00:00:00Z" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

APIs für Testläufe und benutzerdefinierte Ergebnisereignisse sind verfügbar, ihre Dashboard-Ansichten ändern sich aber noch. Wie du eine Änderung an einer Voreinstellung schrittweise ausrollst, steht unter [Voreinstellungen ausrollen und Routing untersuchen](../cookbook/preset-rollout-and-routing-debug).
