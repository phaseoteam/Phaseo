Installiere `@phaseo/cli` und führe `phaseo login` aus, um Coding-Agents mit Phaseo zu verbinden und Schlüssel, Workspaces, Presets, Einstellungen und Guardrails im Terminal zu verwalten. Die CLI liest außerdem Modelle, Anbieter, Preise, Guthaben, Aktivität, Analysen und Generierungen.

## Installieren

<CodeGroup>

```bash npm
npm install -g @phaseo/cli
```

```bash pnpm
pnpm add -g @phaseo/cli
```

```bash yarn
yarn global add @phaseo/cli
```

```bash bun
bun add -g @phaseo/cli
```

</CodeGroup>

Prüfe die Version:

| Befehl | Gibt aus |
| --- | --- |
| `phaseo --version` | Die installierte Version. |
| `phaseo version` | Die Version und den Update-Befehl für deinen Paketmanager. Ergänze `--json` für strukturierte Ausgabe. |

Interaktive Läufe zeigen außerdem einen Hinweis, wenn eine neuere Version veröffentlicht wurde.

## Anmelden

```bash
phaseo login
```

| Ablauf | Flag | Wofür |
| --- | --- | --- |
| Mit Phaseo anmelden | `--browser` | Browser-OAuth mit Autorisierungscode und PKCE. |
| Mit Gerätecode anmelden | `--device-code` | SSH, CI, Shells ohne Oberfläche und Agent-Umgebungen. |

Entfernte und nicht interaktive Umgebungen nutzen automatisch den Gerätecode. So prüfst du, als wer du angemeldet bist, mit deinen Scopes, dem aktiven Workspace und deinen anderen Workspaces:

```bash
phaseo whoami
phaseo whoami --json
```

## Deinen Workspace verwalten

```bash
phaseo keys list
phaseo keys current

phaseo workspaces list
phaseo workspaces members <workspace-id-or-slug>

phaseo guardrails list
```

Nutze `--json`, wenn ein Agent oder Skript die Ausgabe liest. Die CLI deckt alltägliche Kontoaufgaben ab; Limits von Schlüsseln, Budgets, BYOK, Routing-Regeln, Voreinstellungen und Identität änderst du im Dashboard oder mit einem Management-Schlüssel. Welche Aufgaben die CLI abdeckt, steht unter [Phaseo aus einem Agent verwalten](../../developers/manage-from-an-agent).

## Einen Coding-Agent verbinden

Verwende den Namen des Agents als Befehl. Die CLI fordert einen eigenen Schlüssel an, den du im Browser genehmigst, und schreibt die Konfiguration des Agents:

```bash
phaseo codex
phaseo claude-code
phaseo opencode
phaseo fx
phaseo deepseek-harness
phaseo pi
phaseo prime-agent
phaseo openclaw
phaseo hermes
phaseo aider
phaseo continue
phaseo zed
phaseo roo-code
phaseo kilo-code
phaseo cursor
```

Nutze bei Bedarf `--model`, `--catalog all|default` oder `--dry-run`. `phaseo setup <agent>` und `phaseo integrations setup <agent>` funktionieren ebenfalls.

### Den Schlüssel im Browser genehmigen

Wenn du einen Agent zum ersten Mal einrichtest, öffnet die CLI eine Seite im Phaseo-Dashboard und gibt ihren Link aus. Die Seite zeigt den Workspace, den Namen des Schlüssels, sein monatliches Ausgabenlimit von $100 und den Ablauf nach 90 Tagen sowie, dass die Phaseo CLI ihn angefordert hat. Wähle **Genehmigen und Schlüssel erstellen**, dann holt die CLI den Schlüssel einmal ab und schließt die Einrichtung ab. Wählst du **Ablehnen** oder lässt die Anfrage 10 Minuten liegen, bis sie abläuft, wird nichts erstellt.

Genehmige im Dashboard mit dem Konto, das du in der CLI verwendet hast, als Inhaber oder Admin des Workspace und mit deinem zweiten Faktor, falls du einen eingerichtet hast. Über SSH oder in CI öffnest du den ausgegebenen Link auf einem beliebigen Gerät, auf dem du angemeldet bist.

Um stattdessen einen Schlüssel zu verwenden, den du im Dashboard erstellt hast, übergib ihn mit `--key <key>` oder mit `--key-stdin`, damit er nicht in deinem Shell-Verlauf landet. Die CLI prüft den Schlüssel und speichert ihn, widerruft ihn aber nicht, wenn du den Agent entfernst.

Um Cline, Kilo Code, oh-my-pi, Muse Code oder MiniMax Code mit temporären Einstellungen auszuführen, die beim Beenden gelöscht werden, nutze den Sitzungs-Runner. Phaseo-Flags stehen vor `--`, die eigenen Flags des Agents dahinter:

```bash
phaseo cline --model openai/gpt-5.6-terra -- --tui
phaseo kilo --model openai/gpt-5.6-terra
phaseo omp --model openai/gpt-5.6-terra
phaseo muse --model meta/muse-spark-1.3
phaseo minimax --model openai/gpt-5.6-terra
```

`phaseo run <cline|kilo|omp|muse|minimax>` ist die Langform. Ergänze `--catalog all`, um jedes aktive Phaseo-Textmodell aufzulisten, oder `--dry-run --json` für eine Vorschau, ohne einen Schlüssel zu erstellen. Die Runner bieten in einem interaktiven Terminal an, einen fehlenden Agent zu installieren (MiniMax Code nutzt unter Windows seinen offiziellen PowerShell-Installer; Muse Code muss unter Windows von Hand installiert werden). Nutze `--skip-install`, wenn du den Agent selbst verwaltest.

[Coding-Agents](./coding-assistants.mdx) listet jeden Agent auf, was sein Befehl tut und seine Anleitung.

## Skripte mit der CLI schreiben

Befehle mit `--json` geben schlichte strukturierte Ausgabe ohne Farbe oder Spinner aus. Sonst gehen Spinner nach `stderr` und leeren ihre Zeile, wenn sie fertig sind.

| Variable | Wirkung |
| --- | --- |
| `NO_COLOR` | Schaltet Farbe aus. |
| `TERM=dumb` | Schaltet Animationen aus. Ein `stderr` ohne TTY bewirkt dasselbe. |
| `FORCE_COLOR=1` | Erzwingt Farbe, wenn ein Terminal-Wrapper sie unterstützt, aber kein TTY meldet. |

## So schützt die CLI Anmeldeinformationen

- Sitzungen werden im Anmeldeinformationsspeicher des Betriebssystems abgelegt. Setze `PHASEO_SESSION_BACKEND=file` nur, wenn kein Anmeldeinformationsspeicher verfügbar ist. Dann liegen Refresh-Tokens in einer Klartextdatei mit eingeschränkten Berechtigungen.
- `phaseo logout` widerruft das gespeicherte Refresh-Token, bevor der lokale Zustand gelöscht wird.
- Verwaltungsschlüssel brauchen ausdrückliche Berechtigungen. Inferenzschlüssel werden durch Guardrails, Routing-Richtlinien und Workspace-Einstellungen begrenzt statt durch Scopes.

## OAuth-Apps

Phaseo nutzt einen einzigen OAuth-Autorisierungsserver für die CLI, von Nutzern erstellte Apps und dynamisch registrierte MCP-Clients. Die CLI nutzt Browser- oder Geräteanmeldung mit rotierenden Refresh-Tokens. Drittanbieter-Clients nutzen den Autorisierungscode mit PKCE, ausdrückliche Scopes und Workspace-Zustimmung sowie optional eine Bindung an eine geschützte Ressource. Sie erhalten ein widerrufbares Zugriffstoken, das 7 Tage gilt, und ein rotierendes Refresh-Token, das 90 Tage ab seiner letzten Nutzung gilt. Wie die Erneuerung funktioniert, zeigt [Eine OAuth-Next.js-Workbench bauen](../../cookbook/build-an-oauth-nextjs-workbench). Wird dieselbe App erneut genehmigt, wird ihr Schlüssel erneuert, statt einen zweiten hinzuzufügen.

Bei der gehosteten Phaseo API ist Drittanbieter-OAuth aktiviert. Selbst gehostete und Vorschau-Deployments der API lassen es deaktiviert, sofern `PHASEO_THIRD_PARTY_OAUTH_ENABLED` nicht wahr ist: `1`, `true`, `yes` oder `on`, ohne Beachtung der Groß- und Kleinschreibung und umgebender Leerzeichen.

```bash .env
PHASEO_THIRD_PARTY_OAUTH_ENABLED=true
```

Das Aktivieren macht die Verwaltung nutzererstellter OAuth-Apps und die dynamische Client-Registrierung verfügbar. Prüfe also vorher deine Einstellungen für Weiterleitungs-URIs, Zustimmung, Client-Secrets, Ratenlimits und Workspace-Autorisierung.

## Aktualisieren

```bash
phaseo update
```

Damit wird das Update mit dem Paketmanager ausgeführt, mit dem du die CLI installiert hast. So aktualisierst du von Hand:

<CodeGroup>

```bash npm
npm install -g @phaseo/cli@latest
```

```bash pnpm
pnpm add -g @phaseo/cli@latest
```

```bash yarn
yarn global add @phaseo/cli@latest
```

```bash bun
bun add -g @phaseo/cli@latest
```

</CodeGroup>
