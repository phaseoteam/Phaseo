Rotiere Phaseo-API-Schlüssel ohne Ausfallzeit: Erstelle mit einem [Verwaltungsschlüssel](../../developers/management-api-keys.mdx) einen Ersatzschlüssel, stelle deine App darauf um und lösche dann den alten. Diese Seite nennt die Werte, die eine Infisical-Verbindung für diese Rotation verwendet.

<Warning>
Phaseo ist in Infisical noch keine auswählbare App Connection. Connector, Tests und UI-Eintrag müssen erst noch in Infisical aufgenommen werden. Bis dahin nutzt du die unten stehenden Anfragen aus deinem eigenen Rotationsjob.
</Warning>

## So funktioniert die Rotation

```mermaid
flowchart LR
  mk["Verwaltungsschlüssel"] -->|"POST /v1/keys"| newkey["Neuer API-Schlüssel"]
  newkey -->|"Im Secret speichern"| app["App nutzt den neuen Schlüssel"]
  app -->|"DELETE /v1/keys/{id}"| old["Alter Schlüssel widerrufen"]
```

Phaseo zeigt den Wert eines API-Schlüssels nur einmal an, bei seiner Erstellung. Alter und neuer Schlüssel funktionieren beide, bis du den alten löschst. So kann deine App umstellen, während das Secret aktualisiert wird.

## Einen eingeschränkten Verwaltungsschlüssel erstellen

Erstelle unter **Einstellungen → Verwaltungsschlüssel** einen Schlüssel mit diesen Berechtigungen:

| Berechtigung | Wofür |
| --- | --- |
| `keys:read` | Die Verbindung prüfen und verwaltete Schlüssel auflisten. |
| `keys:write` | Ersatzschlüssel erstellen. |
| `keys:delete` | Alte Schlüssel widerrufen. |

Speichere den Wert `phaseo_v1_mk_...` in Infisical. Verwaltungsschlüssel steuern dein Konto und können nicht für Inferenz verwendet werden.

## Verbindungsdetails

| Feld | Wert |
| --- | --- |
| Base URL | `https://api.phaseo.app/v1` |
| Authentifizierung | `Authorization: Bearer <PHASEO_MANAGEMENT_KEY>` |
| Verbindung prüfen | `GET /keys` |
| API-Schlüssel auflisten | `GET /keys` |
| API-Schlüssel erstellen | [`POST /keys`](../../api-reference/endpoint/keys-create.mdx) |
| API-Schlüssel widerrufen | [`DELETE /keys/{id}`](../../api-reference/endpoint/keys-delete.mdx) |

## Den Ersatzschlüssel erstellen

```bash
curl https://api.phaseo.app/v1/keys \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "infisical-production",
    "limit": 100,
    "limit_reset": "monthly",
    "include_byok_in_limit": false
  }'
```

Die Antwort enthält den neuen Schlüssel einmalig in `data.key` und seine ID in `data.id`.

| Feld | Werte |
| --- | --- |
| `limit` | Ausgabenlimit in US-Dollar. |
| `limit_reset` | `daily`, `weekly` oder `monthly`. |
| `include_byok_in_limit` | Wird nur aus Kompatibilitätsgründen akzeptiert. BYOK-Nutzung zählt nie zu diesem Limit. |

## Den alten Schlüssel widerrufen

```bash
curl -X DELETE https://api.phaseo.app/v1/keys/$PREVIOUS_KEY_ID \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY"
```

Das Löschen ist idempotent: Wird ein bereits gelöschter Schlüssel erneut gelöscht, kommt `200` mit `{"deleted": true}` zurück. Eine wiederholte Rotation ist also sicher.
