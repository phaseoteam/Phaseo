Führe `phaseo codex` aus, um Codex ein Phaseo-Profil hinzuzufügen, oder trage selbst einen `phaseo`-Anbieter in `config.toml` ein. Dieselbe Konfiguration funktioniert in Codex CLI, der Codex App und der Codex-IDE-Erweiterung.

## Mit der Phaseo CLI einrichten

```bash
phaseo login
phaseo codex --model openai/gpt-5.6-terra
codex --profile phaseo
```

Fehlt Codex, zeigt die CLI den offiziellen Installationsbefehl an und fragt nach, bevor sie ihn ausführt. Danach erstellt die Einrichtung einen `Phaseo CLI: Codex API Key`, der nach 90 Tagen abläuft und ein monatliches Ausgabenlimit von $100 hat, legt ihn im Anmeldeinformationsspeicher des Betriebssystems ab und schreibt das Profil nach `~/.codex/phaseo.config.toml` (oder unter `CODEX_HOME`). Codex holt den Schlüssel von der CLI, die einen neuen erstellt, wenn der alte abläuft. So landet kein Klartextschlüssel in der Konfiguration. Ohne `--model` verwendet das Profil `openai/gpt-5.6-terra`.

## Codex manuell konfigurieren

Füge Folgendes zu `~/.codex/config.toml` hinzu oder zu `.codex/config.toml` in einem vertrauenswürdigen Projekt:

```toml
model = "openai/gpt-6-astra"
model_provider = "phaseo"

[model_providers.phaseo]
name = "Phaseo"
base_url = "https://api.phaseo.app/v1"
env_key = "PHASEO_API_KEY"
wire_api = "responses"
```

Exportiere dann `PHASEO_API_KEY` und starte Codex. Benutzerdefinierte Codex-Anbieter verwenden das Responses-Wire-Protokoll, das ohnehin der Standard ist, du kannst `wire_api` also auch weglassen. In der IDE-Erweiterung öffnest du die Datei über **Codex Settings → Open config.toml**.

## Prüfen, ob es funktioniert

Sende einen kurzen Prompt und prüfe, ob die Anfrage unter **Einstellungen → Nutzung → Protokolle** erscheint. Codex ruft [Responses](../../api-reference/endpoint/responses.mdx) auf, daher muss das Modell diesen Endpunkt unterstützen.

## Phaseo entfernen

```bash
phaseo integrations remove codex
```

Damit wird `phaseo.config.toml` gelöscht, sofern Phaseo die Datei erstellt hat, und der Schlüssel widerrufen. Bei einer manuellen Einrichtung entfernst du den `phaseo`-Anbieter aus `config.toml`.

## Häufige Probleme beheben

| Fehler | Lösung |
| --- | --- |
| `401 Unauthorized` | Führe `phaseo whoami` und dann erneut `phaseo codex` aus. |
| `model_not_found` | Hol dir eine aktuelle ID unter [Modelle](../../api-reference/endpoint/models.mdx) und aktualisiere `model`. |
| Ein Anbieter schlägt fehl | Unter [Routing und Fallbacks](../routing-and-fallbacks.mdx) findest du das Failover. |

## Phaseo-Skills und -Dokumentation hinzufügen

Damit Codex während der Arbeit die aktuelle Phaseo-Dokumentation lesen kann, füge den [Docs MCP](./docs-mcp.mdx)-Server hinzu. So installierst du die öffentlichen [Phaseo-Skills](https://phaseo.app/docs/.well-known/agent-skills/index.json) für Codex:

```bash
npx skills add https://phaseo.app/docs --agent codex --skill '*'
```

Derselbe CLI-Ablauf startet [Cline](./cline.mdx), [Kilo Code](./kilo-code.mdx), [oh-my-pi](./oh-my-pi.mdx), [Muse Code](./muse-code.mdx) und [MiniMax Code](./minimax-code.mdx) mit temporären Einstellungen.
