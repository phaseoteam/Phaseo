Du kannst Phaseo-Anfragen auf zwei Arten verfolgen: Aktiviere [Broadcast](../broadcast.mdx), dann sendet Phaseo ohne Codeänderung einen Trace jeder Anfrage an Langfuse, LangSmith oder ein beliebiges OpenTelemetry-Tool. Oder du behältst deine Tracing-Bibliothek in deiner App und richtest ihren Modell-Client auf Phaseo.

| | Broadcast | Tracing in deiner App |
| --- | --- | --- |
| Woher die Traces kommen | Von Phaseo, für jede Anfrage | Vom Modell-Client deiner App |
| Codeänderung | Keine. Einrichtung unter **Einstellungen → Broadcast** | Client kapseln, dann seine Base URL ändern |
| Was der Trace enthält | Modell, Anbieter, jeden Anbieterversuch, Tokens, Kosten, Zeitmessung und (optional) Prompt und Ausgabe | Was deine Bibliothek aufzeichnet, plus deinen eigenen App-Kontext |

## Langfuse mit dem OpenAI SDK

Behalte den OpenAI-Wrapper von Langfuse und gib dem gekapselten Client die Base URL von Phaseo:

```bash
pip install langfuse openai
```

```python
import os
from langfuse.openai import openai

client = openai.OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
)

response = client.responses.create(
    model="openai/gpt-6-astra",
    input="Reply with only: ok",
)
```

## LangSmith mit LangChain

Nutze die `ChatOpenAI`-Einrichtung aus [LangChain](./langchain.mdx) und aktiviere LangSmith mit den üblichen Umgebungsvariablen von LangChain:

```bash
export LANGSMITH_TRACING=true
export LANGSMITH_API_KEY="your_langsmith_key"
export PHASEO_API_KEY="your_phaseo_key"
```

## OpenTelemetry

Wenn dein Framework bereits OpenTelemetry-Spans ausgibt, brauchst du keinen speziellen Exporter. Füge diesen Anfragekontext selbst zu deinen Spans hinzu:

- Modell-ID;
- Endpunkt, etwa `responses` oder `chat.completions`;
- die Phaseo-Anfrage-ID, aus den Antwortmetadaten oder den [Protokollen](../../api-reference/endpoint/activity.mdx);
- den Anbieter, der die Anfrage bedient hat, wenn Antwortmetadaten aktiviert sind.

Erfasse Phaseo-API-Schlüssel niemals als Span-Attribute.
