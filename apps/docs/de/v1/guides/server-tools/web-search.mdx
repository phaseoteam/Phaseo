Füge `phaseo:web_search` hinzu, damit das Modell im Web suchen kann, wenn es aktuelle oder durch Quellen belegte Informationen braucht. Das Modell formuliert die Suchanfrage und kann innerhalb einer Anfrage mehrmals suchen; Phaseo gibt URLs, Titel, Snippets, Hervorhebungen und optional Seitentext zurück, und das Modell schreibt eine fundierte Antwort.

```bash
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [
      { "role": "user", "content": "What were the major AI announcements this week?" }
    ],
    "tools": [
      { "type": "phaseo:web_search" }
    ]
  }'
```

Derselbe Tool-Eintrag funktioniert in `tools` unter `/v1/responses` und `/v1/messages`.

<span id="parameters"></span>
## Parameter

```json
{
  "type": "phaseo:web_search",
  "parameters": {
    "engine": "exa",
    "max_results": 5,
    "max_total_results": 15,
    "search_context_size": "medium",
    "max_characters": 2048,
    "allowed_domains": ["arxiv.org", "nature.com"],
    "include_highlights": true,
    "include_text": false
  }
}
```

| Parameter | Typ | Standardwert | Beschreibung |
| --- | --- | --- | --- |
| `engine` | string | `exa` | `auto`, `native`, `exa`, `parallel`, `firecrawl`, `perplexity`, `tinyfish` oder `deepseek`. Siehe [Engine auswählen](#choose-an-engine). |
| `mode` | string | Standard der Engine | Wie die Engine sucht: schneller, gründlicher oder als Recherchelauf. Siehe [Modus wählen](#choose-a-mode). |
| `max_results` | integer | `5` | Ergebnisse pro Suchaufruf, bis `25`. |
| `max_total_results` | integer | `25` | Ergebnisse über alle Suchen der Anfrage, bis `100`. Nie niedriger als `max_results`. |
| `max_uses` | integer | `10` | Suchaufrufe pro Anfrage, bis `100`. |
| `search_context_size` | string | `medium` | `low`, `medium` oder `high`, für Engines, die den Umfang der Hervorhebungen anpassen. |
| `max_characters` | integer | Standard der Engine | Textzeichen pro Ergebnis, wenn Text enthalten ist. |
| `allowed_domains` | string[] | Keiner | Sucht nur in diesen Domains. Alias: `include_domains`. |
| `excluded_domains` | string[] | Keiner | Lässt diese Domains aus. Alias: `exclude_domains`. |
| `include_highlights` | boolean | `true` | Bezieht die Hervorhebungen oder Snippets der Engine ein. |
| `include_text` | boolean | `false` | Bezieht ausführlicheren Seitentext ein, wenn die Engine das unterstützt. |
| `user_location` | object | Keiner | Standorthinweis. Bei `engine` `native` geht er an die eigene Suche des Anbieters, sonst nutzt die Suche von Phaseo ihn, wenn der Aufruf des Modells keinen Standort angibt. |

## Was das Modell sendet

Jeder Aufruf enthält eine `query`. Das Modell kann außerdem `max_results`, `engine`, `search_context_size`, die Domainlisten, `include_text`, `include_highlights`, `max_characters` und diese Lokalisierungshinweise senden:

| Argument | Beschreibung |
| --- | --- |
| `user_location` | Ungefährer Standort. Exa und Perplexity nutzen `user_location.country` (ein zweistelliger Code wie `GB`) für regionale Suche; TinyFish nutzt Land und Sprache. |
| `language` | Sprachcode der Ergebnisse, etwa `en`, für Engines, die lokalisieren. DeepSeek fügt ihn der Suchanfrage als `lang:`-Filter hinzu. |
| `page` | Ergebnisseite `0` bis `10`, für TinyFish. |

Werte, die das Modell sendet, ersetzen für diesen Aufruf die Standardwerte des Tools. `max_results` bleibt durch den Rest von `max_total_results` begrenzt; ist dieser aufgebraucht, geben weitere Aufrufe `max_total_results_reached` zurück.

<span id="choose-an-engine"></span>
## Engine auswählen

| Engine | Was ausgeführt wird |
| --- | --- |
| `exa` | Verwaltete Exa-Suche. Der Standard. |
| `auto` | Der verwaltete Standard, derzeit Exa. |
| `parallel` | Verwaltete Parallel-Suche. |
| `firecrawl` | Verwaltete Firecrawl-Suche. |
| `perplexity` | Die Perplexity Search API: sortierte Ergebnisse, `search_context_size` und regionale Suche anhand von `user_location.country`. |
| `tinyfish` | TinyFish Search: lokalisierte, paginierte und sortierte Ergebnisse. Liefert Snippets, keinen vollständigen Seitentext; verwende [`phaseo:web_fetch`](./web-fetch), wenn das Modell mehr braucht. |
| `deepseek` | DeepSeek Search: sortierte Ergebnisse mit einer Zusammenfassung jeder Seite, für das Modell zum Lesen geschrieben. |
| `native` | Das eigene Websuche-Tool des Anbieters, etwa OpenAIs `web_search_preview`, Anthropics `web_search_20250305` oder DeepSeeks `deepseek_web_search`. |

Ist eine verwaltete Engine nicht aktiviert, gibt der Aufruf `search_not_configured` an das Modell zurück.

Mit `engine: "native"` unter `/v1/chat/completions` oder `/v1/responses` geht die Anfrage nur an Anbieter, die die Websuche selbst ausführen. Bedient keiner von ihnen das Modell, führt Phaseo stattdessen seine Standard-Engine aus und rechnet sie als verwaltete Suche ab.

Die Anbieter, die die Websuche an diesen Endpunkten selbst ausführen, sind OpenAI, Azure OpenAI-Deployments unter `/v1/responses`, xAI und DeepSeek bei `deepseek/deepseek-v4.1-flash-1017`. DeepSeek sucht nur dann selbst, wenn die Websuche das einzige Tool der Anfrage ist, ohne Domain-Listen oder Nutzerstandort, ohne JSON-Ausgabe und ohne erzwungenes `tool_choice`. Seine API lehnt Domain-Listen, einen Standort und JSON-Ausgabe ab, schaltet die Websuche ab, wenn die Anfrage weitere Tools enthält, und kann keine Suche erzwingen. Andere Anfragen an dieses Modell nutzen stattdessen die Suche von Phaseo, die neben deinen eigenen Tools funktioniert. Bei aktiviertem Reasoning führt DeepSeek eine tiefere Suche aus, die Seiten über mehrere Schritte öffnet und liest.

Die eigenen Suchtools der Anbieter können `max_results` und `max_total_results` nicht durchsetzen, und nur das von Claude setzt `max_uses` durch. Eine native Suche mit einem Limit, das ihr Anbieter nicht durchsetzen kann, läuft stattdessen über die Standard-Engine von Phaseo und wird als verwaltete Suche abgerechnet.

Das Senden von OpenAIs eigenem Tool `{ "type": "web_search" }` funktioniert genauso wie `engine: "native"`. Setze `native` nur in der Tool-Definition: Fordert das Modell `native` in einem Aufruf an, gibt der Aufruf `unsupported_search_engine` zurück, weil das Tool des Anbieters vor dem Senden der Anfrage gewählt werden muss.

<span id="choose-a-mode"></span>
## Modus wählen

Setze `mode` im Tool, um festzulegen, wie seine Engine sucht. Das Modell kann den Modus nicht ändern, daher kostet ein Aufruf nie mehr als der gewählte Modus. Wechselt das Modell zu einer anderen Engine, läuft diese in ihrem Standardmodus. Ein Modus, den die Engine nicht hat, liefert einen 400.

| Engine | `mode` | Was läuft | Preis pro Aufruf |
| --- | --- | --- | --- |
| `exa` | `lite` | Suche mit niedriger Latenz für Chat und Sprache | $0.004 |
| `exa` | `auto` (Standard) | Ausgewogene Suche | $0.007 |
| `exa` | `deep-lite` | Leichte mehrstufige Recherche, etwa 4 Sekunden | $0.012 |
| `exa` | `deep` | Mehrstufige Recherche mit zusammengefasster `answer`, 4 bis 15 Sekunden | $0.012 |
| `exa` | `agent-minimal` | Ein Recherchelauf von Exa Agent mit minimalem Aufwand | $0.012 |
| `exa` | `agent-low` | Ein Recherchelauf von Exa Agent mit niedrigem Aufwand | $0.025 |
| `parallel` | `turbo`, `fast` | Die schnellste Suche von Parallel | $0.001 |
| `parallel` | `basic`, `advanced` (Standard) | Die hochwertigere Suche von Parallel | $0.005 |
| `parallel` | `task-lite` | Ein Recherchelauf von Parallel Task, 10 bis 60 Sekunden | $0.005 |
| `parallel` | `task-base` | Ein Recherchelauf von Parallel Task, 15 bis 100 Sekunden | $0.010 |
| `perplexity` | `standard` (Standard) | Perplexity Search | $0.005 |
| `perplexity` | `fast` | Perplexity Fast Search | $0.001 |

Suchen über Exa und Parallel kosten außerdem $0.001 für jedes Ergebnis nach den ersten 10, und Exa berechnet $0.001 pro Seite für jeden zurückgegebenen Inhaltstyp, sodass Highlights und Text bei 5 Ergebnissen $0.010 hinzufügen. `firecrawl`, `tinyfish` und `deepseek` haben keine Modi.

Recherchemodi liefern eine `answer` und die zitierten Seiten als `results`. Ein Recherchelauf, der nach 120 Sekunden nicht fertig ist, liefert `research_timeout`. Läufe, die ablaufen, fehlschlagen oder ihren Client verlieren, werden nicht berechnet. Recherchemodi lassen sich nicht auf Domains beschränken; ein Recherche-Tool mit `allowed_domains` oder `excluded_domains` liefert daher 400. Die Engine `native` hat keinen Modus.

## Nach Domain filtern

Verwende `allowed_domains`, wenn die Antwort aus einer festen Quellenauswahl stammen muss, und `excluded_domains`, um bestimmte Websites aus einer sonst offenen Suche auszuschließen.

```json
{
  "type": "phaseo:web_search",
  "parameters": { "allowed_domains": ["phaseo.app", "github.com"] }
}
```

Die Engines behandeln die Listen unterschiedlich:

- **Perplexity** nimmt eine der beiden Listen, nicht beide, und bis zu 20 Domains. Ausgeschlossene Domains werden in seinem Sperrlistenformat gesendet.
- **Firecrawl** nimmt eine der beiden Listen, nicht beide.
- **TinyFish** nimmt beide und wandelt sie in der Suchanfrage in die Operatoren `site:` und `-site:` um.
- **DeepSeek** nimmt beide und wandelt sie in `site:`- und `-site:`-Operatoren um. Seine Anfragen sind auf 128 Zeichen begrenzt, daher wird die Suchanfrage gekürzt, um Platz für die Operatoren zu schaffen. Überschreiten allein die Domain-Listen das Limit, gibt der Aufruf `search_query_too_long` zurück.

## Was das Tool zurückgibt

Ein JSON-Ergebnis mit der Engine, der Suchanfrage und einem `results`-Array. Jedes Ergebnis hat `title`, `url`, `snippet` oder `highlights` sowie `text`, wenn Seitentext angefordert wurde und die Engine ihn liefert.

## Nutzung und Preise

Jede Suche erhöht die Werte in `usage.server_tool_use`:

```json
{
  "usage": {
    "server_tool_use": {
      "web_search_requests": 1,
      "web_search_results": 5,
      "web_search_extra_results": 0
    }
  }
}
```

Phaseo berechnet Suchen über Exa, Parallel, Perplexity und DeepSeek mit dem, was jede Engine Phaseo berechnet: den Preisen unter [Modus wählen](#choose-a-mode) und $0.00075 für eine DeepSeek-Suche, die nur berechnet wird, wenn sie Ergebnisse liefert. Bei Exa sind es die Kosten, die Exa für den Aufruf meldet, oder sein Listenpreis, wenn Exa keine meldet. Jede Gebühr ist eine Zeile in den `pricing_lines` der Anfrage mit `engine`, `mode` und `price_source`. Firecrawl-Suchen werden mit $0.007 plus $0.001 für jedes Ergebnis nach den ersten 10 berechnet. Fehlgeschlagene Suchen werden nicht berechnet, und TinyFish Search ist in seinen veröffentlichten Tarifen kostenlos, daher fügt `engine: "tinyfish"` keine Suchkosten hinzu. Suchen mit kostenpflichtigen Engines erfordern Guthaben, auch wenn das Modell kostenlos ist. Native Suche wird über `native_web_search_requests` zum veröffentlichten Preis des Anbieters abgerechnet: zum Beispiel $10 pro 1,000 Suchen bei OpenAI und Anthropic und $0.75 pro 1,000 bei DeepSeek, wo nur Suchen mit Ergebnissen zählen. DeepSeek berechnet außerdem jeden Seitenabruf, bei dem es eine URL mit seinem Link-Lese-Tool liest, mit $0.75 pro 1,000, als `native_web_fetch_requests`. Bei aktiviertem Reasoning kann eine einzige DeepSeek-Antwort ein Dutzend oder mehr Suchen ausführen, und die gelesenen Ergebnisse erhöhen die Eingabe-Tokens.
