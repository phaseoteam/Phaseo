Füge `phaseo:web_search` hinzu, damit das Modell im Web suchen kann, wenn es aktuelle oder durch Quellen belegte Informationen braucht. Das Modell formuliert die Suchanfrage und kann innerhalb einer Anfrage mehrmals suchen; Phaseo gibt URLs, Titel, Snippets, Hervorhebungen und optional Seitentext zurück, und das Modell schreibt eine fundierte Antwort.

```bash
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [
      { "role": "user", "content": "What were the major AI announcements this week?" }
    ],
    "tools": [
      { "type": "phaseo:web_search" }
    ]
  }'
```

Derselbe Tool-Eintrag funktioniert in `tools` unter `/v1/responses` und `/v1/messages`.

<span id="parameters"></span>
## Parameter

```json
{
  "type": "phaseo:web_search",
  "parameters": {
    "engine": "exa",
    "max_results": 5,
    "max_total_results": 15,
    "search_context_size": "medium",
    "max_characters": 2048,
    "allowed_domains": ["arxiv.org", "nature.com"],
    "include_highlights": true,
    "include_text": false
  }
}
```

| Parameter | Typ | Standardwert | Beschreibung |
| --- | --- | --- | --- |
| `engine` | string | `exa` | `auto`, `native`, `exa`, `parallel`, `firecrawl`, `perplexity` oder `tinyfish`. Siehe [Engine auswählen](#choose-an-engine). |
| `max_results` | integer | `5` | Ergebnisse pro Suchaufruf, bis `25`. |
| `max_total_results` | integer | `25` | Ergebnisse über alle Suchen der Anfrage, bis `100`. Nie niedriger als `max_results`. |
| `max_uses` | integer | `10` | Suchaufrufe pro Anfrage, bis `100`. |
| `search_context_size` | string | `medium` | `low`, `medium` oder `high`, für Engines, die den Umfang der Hervorhebungen anpassen. |
| `max_characters` | integer | Standard der Engine | Textzeichen pro Ergebnis, wenn Text enthalten ist. |
| `allowed_domains` | string[] | Keiner | Sucht nur in diesen Domains. Alias: `include_domains`. |
| `excluded_domains` | string[] | Keiner | Lässt diese Domains aus. Alias: `exclude_domains`. |
| `include_highlights` | boolean | `true` | Bezieht die Hervorhebungen oder Snippets der Engine ein. |
| `include_text` | boolean | `false` | Bezieht ausführlicheren Seitentext ein, wenn die Engine das unterstützt. |
| `user_location` | object | Keiner | Standorthinweis, der an die eigene Suche des Anbieters geht, wenn `engine` `native` ist. |

## Was das Modell sendet

Jeder Aufruf enthält eine `query`. Das Modell kann außerdem `max_results`, `engine`, `search_context_size`, die Domainlisten, `include_text`, `include_highlights`, `max_characters` und diese Lokalisierungshinweise senden:

| Argument | Beschreibung |
| --- | --- |
| `user_location` | Ungefährer Standort. Perplexity nutzt `user_location.country` für regionale Suche; TinyFish nutzt Land und Sprache. |
| `language` | Sprachcode der Ergebnisse, etwa `en`, für Engines, die lokalisieren. |
| `page` | Ergebnisseite `0` bis `10`, für TinyFish. |

Werte, die das Modell sendet, ersetzen für diesen Aufruf die Standardwerte des Tools. `max_results` bleibt durch den Rest von `max_total_results` begrenzt; ist dieser aufgebraucht, geben weitere Aufrufe `max_total_results_reached` zurück.

<span id="choose-an-engine"></span>
## Engine auswählen

| Engine | Was ausgeführt wird |
| --- | --- |
| `exa` | Verwaltete Exa-Suche. Der Standard. |
| `auto` | Der verwaltete Standard, derzeit Exa. |
| `parallel` | Verwaltete Parallel-Suche. |
| `firecrawl` | Verwaltete Firecrawl-Suche. |
| `perplexity` | Die Perplexity Search API: sortierte Ergebnisse, `search_context_size` und regionale Suche anhand von `user_location.country`. |
| `tinyfish` | TinyFish Search: lokalisierte, paginierte und sortierte Ergebnisse. Liefert Snippets, keinen vollständigen Seitentext; verwende [`phaseo:web_fetch`](./web-fetch), wenn das Modell mehr braucht. |
| `native` | Das eigene Websuche-Tool des Anbieters, etwa OpenAIs `web_search_preview` oder Anthropics `web_search_20250305`. |

Ist eine verwaltete Engine nicht aktiviert, gibt der Aufruf `search_not_configured` an das Modell zurück.

Mit `engine: "native"` unter `/v1/chat/completions` oder `/v1/responses` geht die Anfrage nur an Anbieter, die die Websuche selbst ausführen. Bedient keiner von ihnen das Modell, führt Phaseo stattdessen seine Standard-Engine aus und rechnet sie als verwaltete Suche ab. Setze `native` nur in der Tool-Definition: Fordert das Modell `native` in einem Aufruf an, gibt der Aufruf `unsupported_search_engine` zurück, weil das Tool des Anbieters vor dem Senden der Anfrage gewählt werden muss.

## Nach Domain filtern

Verwende `allowed_domains`, wenn die Antwort aus einer festen Quellenauswahl stammen muss, und `excluded_domains`, um bestimmte Websites aus einer sonst offenen Suche auszuschließen.

```json
{
  "type": "phaseo:web_search",
  "parameters": { "allowed_domains": ["phaseo.app", "github.com"] }
}
```

Die Engines behandeln die Listen unterschiedlich:

- **Perplexity** nimmt eine der beiden Listen, nicht beide, und bis zu 20 Domains. Ausgeschlossene Domains werden in seinem Sperrlistenformat gesendet.
- **Firecrawl** nimmt eine der beiden Listen, nicht beide.
- **TinyFish** nimmt beide und wandelt sie in der Suchanfrage in die Operatoren `site:` und `-site:` um.

## Was das Tool zurückgibt

Ein JSON-Ergebnis mit der Engine, der Suchanfrage und einem `results`-Array. Jedes Ergebnis hat `title`, `url`, `snippet` oder `highlights` sowie `text`, wenn Seitentext angefordert wurde und die Engine ihn liefert.

## Nutzung und Preise

Jede Suche erhöht die Werte in `usage.server_tool_use`:

```json
{
  "usage": {
    "server_tool_use": {
      "web_search_requests": 1,
      "web_search_results": 5,
      "web_search_extra_results": 0
    }
  }
}
```

Phaseo berechnet jede verwaltete Suche mit $0.007 plus $0.001 für jedes Ergebnis nach den ersten 10, sofern die Preiskarte des Modells keine eigenen Preise für `server_tool_web_search_requests` und `server_tool_web_search_extra_results` festlegt. Fehlgeschlagene Suchen werden nicht berechnet, und TinyFish Search ist in seinen veröffentlichten Tarifen kostenlos, daher fügt `engine: "tinyfish"` keine Suchkosten hinzu. Suchen mit kostenpflichtigen Engines erfordern Guthaben, auch wenn das Modell kostenlos ist. Native Suche wird über `native_web_search_requests` abgerechnet, wenn die Preiskarte des Modells dies festlegt.
