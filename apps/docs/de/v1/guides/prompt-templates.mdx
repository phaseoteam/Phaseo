Speichere deine Nachrichten mit `{{variables}}` in einer [Voreinstellung](/de/v1/guides/presets), dann sendet deine Anwendung nur noch den Verweis auf die Voreinstellung und die Werte der Variablen. Phaseo prüft die Werte, füllt die Nachrichten aus und sendet die Anfrage an das Modell der Voreinstellung. Eine Änderung am Prompt im Dashboard braucht kein Deployment, und alle Aufrufer erhalten denselben Wortlaut, dieselben Tools und dasselbe Antwortformat.

Vorlagen funktionieren mit `POST /v1/chat/completions`, `POST /v1/responses` und `POST /v1/messages`.

## Eine Vorlage erstellen und aufrufen

<Steps>
<Step title="Die Vorlage schreiben">

Öffne **Einstellungen -> Voreinstellungen**, erstelle oder öffne eine Voreinstellung, wähle ihr Modell und öffne den Tab **Prompt-Vorlage**. Füge Nachrichten hinzu und schreibe Variablen in doppelte geschweifte Klammern:

```text
System: You triage support tickets for {{company}}. Reply in a {{tone}} tone.
User:   Ticket: {{ticket}}
```

Der Editor listet jede gefundene Variable auf. Lege ihren Typ fest, ob sie erforderlich ist, einen Standardwert und eine Beschreibung. Fülle das Panel **Ausprobieren** aus, um genau die Nachrichten zu sehen, die das Gateway senden wird, und speichere dann.

Sobald die Voreinstellung gespeichert ist, sendet **Gespeichertes Preset ausführen** eine echte Anfrage mit deinen Testwerten und zeigt die Antwort, das Modell und die Token-Zahlen an. Dabei werden die Credits deines Arbeitsbereichs verbraucht. Dasselbe Panel enthält cURL-, TypeScript- und Python-Code für die Anfrage, ausgefüllt mit deinen Testwerten.

</Step>

<Step title="Die Variablen senden">

Gib die Voreinstellung in `prompt.id` an und lege die Werte in `prompt.variables` ab. Lass `model` weg oder setze es auf denselben Verweis.

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "prompt": {
      "id": "@support-triage",
      "variables": {
        "company": "Acme",
        "tone": "friendly",
        "ticket": "I was charged twice this month."
      }
    }
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const completion = await client.generateText({
	model: "@support-triage",
	messages: [],
	prompt: {
		id: "@support-triage",
		variables: {
			company: "Acme",
			tone: "friendly",
			ticket: "I was charged twice this month.",
		},
	},
});
```

```python Python
from phaseo import Phaseo

client = Phaseo(api_key="YOUR_API_KEY")

completion = client.generate_text({
    "prompt": {
        "id": "@support-triage",
        "variables": {
            "company": "Acme",
            "tone": "friendly",
            "ticket": "I was charged twice this month.",
        },
    },
})
```
</CodeGroup>

</Step>

<Step title="Die Anfrage prüfen">

Öffne **Gateway -> Protokolle**, um die Anfrage, das Modell, das sie bedient hat, und ihre Kosten zu sehen. Die Metadaten der Anfrage erfassen die Voreinstellung, die Variablennamen und die Zahl der gerenderten Nachrichten, aber nicht die Werte der Variablen.

</Step>
</Steps>

## Vorlagen von jedem Endpunkt aus nutzen

Dasselbe `prompt`-Objekt funktioniert auf allen drei Endpunkten. Die System- und Developer-Nachrichten der Vorlage werden zu den Systemanweisungen des Endpunkts, und ihre übrigen Nachrichten stehen vor jeder Unterhaltung, die deine Anfrage sendet.

| Endpunkt | System-Nachrichten der Vorlage landen in | Unterhaltung der Vorlage steht vor |
| --- | --- | --- |
| `/v1/chat/completions` | `messages` (bleiben System-Nachrichten) | deinen `messages` |
| `/v1/responses` | `instructions` | deinem `input` |
| `/v1/messages` | `system` | deinen `messages` |

Du kannst mit der Vorlage eine Unterhaltung senden. Eine Chat-Anfrage kann zum Beispiel die Folgebeiträge des Nutzers nach den Nachrichten der Vorlage anhängen:

```json
{
  "prompt": { "id": "@support-triage", "variables": { "company": "Acme", "ticket": "Refund request" } },
  "messages": [
    { "role": "assistant", "content": "Can you share the order number?" },
    { "role": "user", "content": "It is 10482." }
  ]
}
```

## Vorlagensyntax

Vorlagen nutzen eine kleine, logikfreie Teilmenge von Mustache. Nichts in einer Vorlage wird je als Code ausgeführt.

| Syntax | Wirkung |
| --- | --- |
| `{{name}}` | Fügt einen Wert ein. Text wird unverändert eingefügt, Zahlen und Booleans als Text, Listen und Objekte als JSON. Ein fehlender optionaler Wert fügt nichts ein. |
| `{{customer.name}}` | Fügt ein Feld einer Objektvariable ein. |
| `{{#name}}...{{/name}}` | Rendert den Block einmal, wenn der Wert gesetzt und nicht `false` ist, oder einmal pro Element einer Liste. Darin ist `{{.}}` das aktuelle Element, und seine Felder lassen sich über ihren Namen nutzen. |
| `{{^name}}...{{/name}}` | Rendert den Block, wenn der Wert fehlt, `false`, leerer Text oder eine leere Liste ist. |
| `{{! note }}` | Ein Kommentar. Er wird entfernt. |
| `\{{` | Ein wörtliches `{{`. |

Werte werden als reiner Text ohne HTML-Escaping eingefügt. Ein Wert kann den Text einer Nachricht ändern, aber nie die Struktur der Anfrage.

Rendert eine Nachricht zu nichts als Leerraum, wird sie verworfen. So machst du eine ganze Nachricht optional:

```text
{{#notes}}Notes from the account manager: {{notes}}{{/notes}}
```

Um Text für jedes Element einer Liste zu wiederholen, öffne einen Abschnitt auf der Liste und verwende `{{.}}` für das aktuelle Element:

```text
Examples of good replies:
{{#examples}}- {{.}}
{{/examples}}
```

Partials (`{{> name}}`), nicht maskierte Tags (`{{{name}}}` und `{{& name}}`), Änderungen der Trennzeichen und Lambdas werden nicht unterstützt; Editor und API lehnen Vorlagen ab, die sie verwenden.

## Variablen

Jede Variable hat einen Typ. Du musst eine Variable nur deklarieren, um ihre Standardwerte zu ändern; Variablen, die in den Nachrichten vorkommen, aber nicht deklariert sind, sind erforderlicher Text.

| Typ | Akzeptiert |
| --- | --- |
| `string` | Text. Setze `max_length`, um seine Länge zu begrenzen. |
| `number` | Eine Zahl. |
| `boolean` | `true` oder `false`. |
| `enum` | Einen der in `enum` aufgeführten Strings. |
| `array` | Eine Liste. |
| `object` | Ein JSON-Objekt. |
| `any` | Einen beliebigen JSON-Wert. |
| `image` | Ein Bild für eine Nutzernachricht. Siehe [Bildvariablen](#image-variables). |

Jede Variable kann außerdem Folgendes haben:

- `required`: Die Anfrage schlägt fehl, wenn der Wert fehlt. Eine erforderliche Variable kann keinen Standardwert haben.
- `default`: Wird verwendet, wenn die Anfrage den Wert weglässt. Er muss zum Typ passen.
- `description`: Wird im Editor und in Fehlermeldungen angezeigt, bis zu 500 Zeichen.

Ein Name, der nur zum Öffnen von Abschnitten dient, wie `notes` und `examples` oben, ist optional und akzeptiert jeden Wert.

Anfragen werden streng geprüft. Ein fehlender erforderlicher Wert, ein Wert vom falschen Typ oder ein Name, den die Vorlage nicht hat, ergibt einen `400`, der alle Probleme auf einmal auflistet, damit ein Tippfehler nicht unbemerkt einen Teil des Prompts weglässt.

<span id="image-variables"></span>
## Bildvariablen

Eine Bildvariable füllt einen ganzen Inhaltsteil einer Nutzernachricht, sodass die Vorlage bestimmt, wo das Bild steht. Wähle im Editor **Bild hinzufügen** innerhalb einer Nutzernachricht. In der API verwendest du einen `variable`-Teil:

```json
{
  "role": "user",
  "content": [
    { "type": "text", "text": "Before:" },
    { "type": "variable", "name": "before" },
    { "type": "text", "text": "After:" },
    { "type": "variable", "name": "after" },
    { "type": "text", "text": "What changed?" }
  ]
}
```

Die Anfrage kann jedes Bild als `https`-URL, als `data:image/...`-URL oder als Bildteil im Format von Chat Completions, Responses oder Messages senden. Phaseo wandelt es in das Format des aufgerufenen Endpunkts um. Das ausgewählte Modell muss Bildeingaben akzeptieren.

## Tools und Antwortformat

Eine Vorlage kann `tools`, `tool_choice` und `response_format` enthalten, geschrieben im Chat-Completions-Format (siehe [Tool Calling](./tool-calling.mdx) und [Strukturierte Ausgaben](./structured-outputs.mdx)). Phaseo wandelt sie für die Endpunkte Responses und Messages um.

Setzen beide dasselbe, gewinnt immer die Anfrage:

- Tools werden über den Funktionsnamen zusammengeführt. Definiert die Anfrage ein Tool mit demselben Namen, wird die Definition der Anfrage verwendet.
- `tool_choice` und das Antwortformat der Anfrage (`response_format`, `text.format` oder `output_config.format`) ersetzen die der Vorlage.

Anfrageparameter wie `temperature` und `max_tokens` funktionieren wie gewohnt. Die eigenen Standardwerte der Voreinstellung füllen nur die Felder, die die Anfrage weglässt.

## Eine Vorlage mit der API erstellen

Vorlagen werden in `config.prompt` der Voreinstellung gespeichert. Erstelle oder aktualisiere die Voreinstellung mit einem [Verwaltungs-API-Schlüssel](/de/v1/developers/management-api-keys), der `presets:write` besitzt:

```bash
curl https://api.phaseo.app/v1/presets \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "@support-triage",
    "visibility": "team",
    "config": {
      "models": ["anthropic/claude-haiku-5.5"],
      "prompt": {
        "messages": [
          { "role": "system", "content": "You triage support tickets for {{company}}. Reply in a {{tone}} tone." },
          { "role": "user", "content": "Ticket: {{ticket}}" }
        ],
        "variables": {
          "company": { "type": "string", "required": true },
          "tone": { "type": "enum", "enum": ["formal", "friendly"], "default": "formal" },
          "ticket": { "type": "string", "required": true, "max_length": 4000 }
        }
      }
    }
  }'
```

Phaseo prüft die Vorlage beim Speichern. Eine Vorlage mit einem Syntaxfehler, einem unbekannten Typ oder einem Standardwert, der nicht zu seinem Typ passt, wird mit `400 invalid_prompt_template` und der Stelle jedes Problems abgelehnt, hier wie im Editor.

Gespeicherte Änderungen erreichen Anfragen innerhalb von etwa zwei Minuten.

<span id="versions-and-labels"></span>
## Versionen und Labels

Jedes Mal, wenn du eine Voreinstellung veröffentlichst, speichert Phaseo eine unveränderliche Version (siehe [Voreinstellungen](/de/v1/guides/presets#version-and-roll-back)). Anfragen führen die neueste veröffentlichte Version aus, sofern sie keine festlegen. Eine festgelegte Anfrage verwendet Modelle, Parameter und Vorlage dieser Version gemeinsam.

Lege eine Version mit `prompt.version` fest:

```json
{
  "prompt": {
    "id": "@support-triage",
    "version": "production",
    "variables": { "company": "Acme", "ticket": "My invoice is wrong" }
  }
}
```

`prompt.version` akzeptiert eine Versionsbezeichnung wie `v3`, `1.2.0` oder `2026.10.27` oder ein Label wie `production`. Du kannst die Version auch in die Modell-ID schreiben, mit oder ohne Vorlage:

```json
{
  "model": "@support-triage@production",
  "messages": [{ "role": "user", "content": "My invoice is wrong" }]
}
```

Öffentliche Voreinstellungen verwenden `@publisher/support-triage@production`. Legen sowohl `model` als auch `prompt.version` eine Version fest, müssen beide dieselbe nennen.

### Labels

Ein Label ist ein Name wie `production` oder `staging`, der auf eine veröffentlichte Version zeigt. Labels bestehen aus 1 bis 32 Kleinbuchstaben, Ziffern, Bindestrichen oder Unterstrichen, beginnen mit einem Buchstaben und dürfen nicht wie eine Versionsbezeichnung aussehen (`v1`, `v2`).

Öffne die Voreinstellung unter **Einstellungen -> Voreinstellungen**. **Veröffentlichen** neben **Entwurf speichern** speichert deine Änderungen und veröffentlicht sie als nächste Version. Öffne **Versionen und Labels**, um Labels zu verwalten: Jedes Label hat eine Versionsauswahl; die Wahl einer anderen Version verschiebt das Label, die Wahl einer früheren rollt zurück. Mit **Label hinzufügen** legst du ein neues an. Öffne eine Version, um ihre Modelle und Vorlagennachrichten zu sehen und wie sie sich von der Standardversion unterscheiden (der Version, die Anfragen ausführen, wenn sie keine festlegen), und nutze **Ausführen**, um diese Version mit den Testwerten aus **Prompt-Vorlage** auszuprobieren. Der Ersteller der Voreinstellung kann ihre Labels ändern, ebenso Eigentümer und Administratoren des Arbeitsbereichs, wenn die Voreinstellung geteilt ist. Mit einem [Verwaltungs-API-Schlüssel](/de/v1/developers/management-api-keys), der `presets:write` besitzt:

```bash
curl -X PUT https://api.phaseo.app/v1/presets/support-triage/labels/production \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "version": "v3" }'
```

Der Body akzeptiert `version` (eine Versionsbezeichnung oder ein anderes Label, dessen Ziel übernommen wird) oder `version_id`. `GET /v1/presets/{id}/labels` listet Labels auf, und `DELETE /v1/presets/{id}/labels/{label}` entfernt eines. Anfragen, die ein entferntes Label festlegen, schlagen fehl, bis es wieder hinzugefügt wird.

### Zurückrollen

Um zurückzurollen, verschiebe das Label auf die frühere Version: Wähle diese Version in der Versionsauswahl des Labels unter **Versionen und Labels** oder sende dieselbe Anfrage mit `"version": "v2"`. Anfragen, die `production` festlegen, führen dann wieder v2 aus, ohne dass sich an deiner Anwendung etwas ändert.

Verschobene Labels erreichen Anfragen innerhalb von etwa zwei Minuten, genau wie andere Änderungen an Voreinstellungen.

## Fehler

Vorlagenprobleme in einer Anfrage geben `400` mit dem Code `validation_error` zurück. `reason` enthält den Code des ersten Problems, und `details` listet alle mit ihrem Pfad auf:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Template \"@support-triage\" needs variable \"ticket\" (string)",
    "type": "invalid_request_error"
  },
  "code": "validation_error",
  "reason": "template_variable_required",
  "description": "Template \"@support-triage\" needs variable \"ticket\" (string)",
  "details": [
    {
      "message": "Template \"@support-triage\" needs variable \"ticket\" (string)",
      "path": ["prompt", "variables", "ticket"],
      "keyword": "template_variable_required"
    }
  ]
}
```

| Grund | Ursache |
| --- | --- |
| `template_variable_required` | Eine erforderliche Variable fehlt. |
| `template_variable_type` | Ein Wert passt nicht zu seinem Typ, seiner Enum-Liste oder `max_length`. |
| `template_variable_unknown` | Die Anfrage hat eine Variable gesendet, die die Vorlage nicht hat, oder die Voreinstellung hat keine Vorlage. |
| `template_variables_invalid` | `prompt.variables` ist kein Objekt. |
| `template_limit_exceeded` | Die Variablen oder der gerenderte Text überschreiten die Grenzen unten. |
| `template_rendered_empty` | Die Vorlage hat keine Nutzer- oder Assistentennachricht gerendert, und die Anfrage hat keine gesendet. |
| `template_endpoint_unsupported` | Die Voreinstellung hat eine Vorlage und wurde von einem anderen Endpunkt als den drei oben aufgerufen. |
| `prompt_model_conflict` | `model` nennt eine andere Voreinstellung oder ein anderes Modell als `prompt.id` oder legt eine andere Version fest als `prompt.version`. |
| `prompt_version_invalid` | `prompt.version` ist leer, länger als 64 Zeichen oder enthält andere Zeichen als Buchstaben, Ziffern, `.`, `_`, `+` und `-`. |
| `prompt_model_fallbacks_unsupported` | Die Anfrage hat `models`-Fallbacks gesetzt. Liste Fallback-Modelle stattdessen in der Voreinstellung auf. |

Eine `prompt.id`, die keine Voreinstellung in deinem Arbeitsbereich nennt, gibt `404` zurück.

Eine festgelegte Version oder ein Label, das nicht existiert oder das der Schlüssel nicht nutzen darf, gibt `404` mit dem Grund `preset_version_not_found` zurück.

## Grenzen

| Grenze | Wert |
| --- | --- |
| Nachrichten pro Vorlage | 64 |
| Variablen pro Vorlage | 64 |
| Länge eines Variablennamens | 64 Zeichen |
| Vorlagentext über alle Nachrichten | 48.000 Zeichen |
| Verschachtelungstiefe von Abschnitten | 8 |
| Abschnittswiederholungen pro Anfrage | 1.000 |
| Gerenderter Text pro Anfrage | 1.000.000 Zeichen |
| Größe von `prompt.variables` | 256 KB |
| Werte pro `enum` | 100 |

## Guardrails und Protokolle

[Guardrails](/de/v1/cookbook/guardrails-for-api-keys) prüfen Variablenwerte als Nutzerinhalt, auch wenn die Vorlage sie in eine System-Nachricht einsetzt. Eine Guardrail, die einen Wert schwärzt, schwärzt ihn überall dort, wo die Vorlage ihn eingefügt hat, und eine, die einen Wert blockiert, blockiert die Anfrage.

Die Metadaten der Anfrage erfassen die Voreinstellung, die Variablennamen und die Zahl der gerenderten Nachrichten. Die Werte selbst werden nur dort gespeichert, wo auch der Anfrage-Body gespeichert wird, gemäß den normalen Protokollierungseinstellungen deines Arbeitsbereichs.
