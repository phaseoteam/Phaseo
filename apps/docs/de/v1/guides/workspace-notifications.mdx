Nutze Benachrichtigungsziele, um aktivierte Workspace-Alarme an die Tools zu senden, die dein Team bereits überwacht. Die Ziele werden im gesamten Workspace gemeinsam genutzt und können getestet werden, bevor du ihnen wichtige Betriebsalarme anvertraust.

## Ziel hinzufügen

1. Öffne **Gateway → Einstellungen → Benachrichtigungen**.
2. Wähle **Ziel hinzufügen** aus.
3. Gib einen Namen ein und wähle einen oder mehrere Kanäle aus.
4. Füge die Zieldetails und bei Bedarf Erwähnungen hinzu.
5. Wähle für jeden eingerichteten Kanal **Test senden** aus.
6. Erstelle die Ziele, sobald alle Tests erfolgreich waren.

Eigene Webhooks erhalten beim Anlegen ein Signaturgeheimnis. Kopiere es aus dem Dialog, der sich öffnet; es wird nur einmal angezeigt.

Phaseo unterstützt:

- E-Mail-Adressen und Verteilerlisten
- Discord-Kanäle über ein Bot-Token
- Discord-Webhooks
- eingehende Slack-Webhooks
- URLs von Microsoft-Teams-Workflows
- eigene HTTPS-Webhooks

Zugangsdaten und Webhook-URLs werden vor dem Speichern verschlüsselt. Beschränke Kanalzugangsdaten auf den Benachrichtigungsversand und rotiere sie, falls sie offengelegt wurden.

## Produktalarme aktivieren

Auf der Benachrichtigungsseite werden die für deinen Workspace verfügbaren Alarmtypen angezeigt. Aktiviere **Warnungen zur Modellablösung**, um vor der Abschaltung eines im Workspace verwendeten Modells benachrichtigt zu werden.

**Hinweise zu Ersatzmodellen** werden gesendet, wenn das [Routing für eingestellte Modelle](./model-retirement.mdx#route-requests-to-a-replacement-automatically) aktiviert ist und ein Ersatzmodell die Anfragen des Workspace für ein Modell beantwortet, das kein Anbieter mehr bereitstellt. Pro Modell und Ersatzmodell wird ein Hinweis gesendet, wenn ein Ersatzmodell zum ersten Mal erfolgreich antwortet. Der Workspace-Inhaber erhält immer eine E-Mail; wähle Ziele aus, um den Hinweis auch an dein Team zu senden.

Zusätzlich zu den im Dashboard angezeigten integrierten Empfängern werden Alarme auch an die eingerichteten Ziele gesendet.

## Erwähnungen

Mit optionalen Erwähnungsfeldern kann ein Alarm bestimmte Empfänger benachrichtigen:

- Discord unterstützt Benutzer- und Rollen-IDs.
- Slack unterstützt Benutzer- und Benutzergruppen-IDs.
- Microsoft Teams unterstützt Microsoft-365-E-Mail-Adressen oder Entra-Objekt-IDs.

Verwende Erwähnungen sparsam. Häufige Workspace-Alarme sollten normalerweise an einen überwachten Kanal gehen, statt eine große Gruppe direkt zu alarmieren.

## Ziele testen und entfernen

Wähle neben einem vorhandenen Ziel **Test senden**, nachdem du Zugangsdaten rotiert oder die Kanaleinstellungen geändert hast. Entferne nicht mehr überwachte Ziele, damit Alarme nicht scheinbar an einen aufgegebenen Kanal gesendet werden.

Eigene Webhooks müssen HTTPS verwenden und die Anfrage vor der Verarbeitung prüfen. Gib zeitnah eine erfolgreiche Antwort zurück und verlagere langsamere Aufgaben in einen Hintergrundprozess.

## Webhook-Signaturen prüfen

Phaseo signiert jede Zustellung an eigene Webhooks, auch Tests von einem gespeicherten Ziel, nach demselben Schema wie [Video- und Batch-Webhooks](./async-video-and-batch.mdx). Jede Anfrage enthält diese Header:

```http
POST /your/endpoint HTTP/1.1
content-type: application/json
user-agent: Phaseo-Notifications/1.0
x-phaseo-event-id: 6f1c0f5e-3f0b-4a39-9a51-2f4f2c1d9e10
x-phaseo-event-type: rate_limit_throttled
x-phaseo-timestamp: 1792569600
x-phaseo-signature: 5d2a…e41f
```

`x-phaseo-signature` ist der hexadezimale HMAC-SHA256 aus dem Wert von `x-phaseo-timestamp`, einem Punkt (`.`) und dem **unveränderten Request-Body**, berechnet mit dem Signaturgeheimnis des Ziels (`whsec_…`). `x-phaseo-timestamp` ist in Unix-Sekunden angegeben.

So prüfst du eine Zustellung:

1. Lies den unveränderten Body, bevor du ihn als JSON parst.
2. Berechne die Signatur neu und vergleiche sie in konstanter Zeit.
3. Lehne Zeitstempel ab, die mehr als fünf Minuten von deiner Uhr abweichen.
4. Dedupliziere anhand von `x-phaseo-event-id`. Fehlgeschlagene Zustellungen werden wiederholt, und jeder Versuch wird mit einem neuen Zeitstempel erneut signiert.

<CodeGroup>
```js Node.js
import crypto from "node:crypto";

// rawBody ist der Request-Body genau wie empfangen, als String.
export function verifyPhaseoSignature(rawBody, headers, secret, toleranceSeconds = 300) {
  const timestamp = headers["x-phaseo-timestamp"];
  const signature = headers["x-phaseo-signature"];
  if (!timestamp || !signature) return false;
  if (Math.abs(Date.now() / 1000 - Number(timestamp)) > toleranceSeconds) return false;
  const expected = crypto
    .createHmac("sha256", secret)
    .update(`${timestamp}.${rawBody}`)
    .digest("hex");
  const a = Buffer.from(expected, "hex");
  const b = Buffer.from(signature, "hex");
  return a.length === b.length && crypto.timingSafeEqual(a, b);
}
```

```python Python
import hashlib
import hmac
import time

# raw_body ist der Request-Body genau wie empfangen, als Bytes.
def verify_phaseo_signature(raw_body: bytes, headers, secret: str, tolerance_seconds: int = 300) -> bool:
    timestamp = headers.get("x-phaseo-timestamp", "")
    signature = headers.get("x-phaseo-signature", "")
    if not timestamp.isdigit() or not signature:
        return False
    if abs(time.time() - int(timestamp)) > tolerance_seconds:
        return False
    expected = hmac.new(secret.encode(), timestamp.encode() + b"." + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)
```
</CodeGroup>

### Geheimnis erzeugen oder rotieren

Das Geheimnis wird nur einmal angezeigt, beim Anlegen des Ziels. Um es zu ersetzen, wähle **Geheimnis rotieren** neben dem Ziel unter **Einstellungen → Benachrichtigungen** oder rufe [`POST /v1/notifications/destinations/{id}/rotate-secret`](/de/v1/api-reference/endpoint/notifications-destination-rotate-secret) auf. Die nächste Zustellung wird mit dem neuen Geheimnis signiert und das alte funktioniert nicht mehr; aktualisiere deinen Empfänger also sofort.

Eigene Webhooks, die vor Einführung der Signierung angelegt wurden, haben kein Geheimnis und werden weiterhin unsigniert zugestellt. In den Einstellungen sind sie als **Unsigniert** markiert. Wähle **Geheimnis erzeugen**, hinterlege das Geheimnis in deinem Empfänger und sende dann einen Test, um die Prüfung zu kontrollieren. Tests aus dem Bereich **Ziel hinzufügen** vor dem Speichern sind unsigniert, weil noch kein Geheimnis existiert.

E-Mail-, Slack-, Discord- und Microsoft-Teams-Ziele werden nicht signiert: Diese Dienste authentifizieren die Webhook-URL oder das Bot-Token selbst.
