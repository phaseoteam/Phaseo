Eine Voreinstellung speichert Modell, System-Prompt, Parameter und Anbieterregeln für eine Aufgabe unter einem Namen wie `@support-triage`. Aufrufer senden diesen Namen als `model` und nur die Eingabe; das Gateway ergänzt den Rest, bevor es einen Anbieter auswählt.

Schalte die Anfragefelder um, um zu sehen, welcher Wert gewinnt:

<PresetMergeExplorer locale="de" />

Es gelten diese Regeln:

- **Parameter füllen Lücken.** Die Standardparameter einer Voreinstellung gelten nur für Felder, die in der Anfrage fehlen. Ein Wert in der Anfrage gewinnt immer.
- **System-Prompts werden gestapelt.** Der Prompt der Voreinstellung steht zuerst. Hat die Anfrage einen eigenen System-Prompt oder `instructions`, folgt dieser nach einer Leerzeile.
- **Anbietereinstellungen in der Anfrage gewinnen.** Felder wie `provider.order` oder `provider.max_price` in der Anfrage ersetzen den Wert der Voreinstellung für dieses Feld.
- **Zulassungslisten schränken ein, erweitern aber nie.** Die Zulassungs- und Ignorierlisten der Voreinstellung für Anbieter werden vor der Anbieterauswahl angewendet und begrenzen daher auch, welche Anbieter ein Fallback nutzen kann. Ein Modell außerhalb der erlaubten Modelle der Voreinstellung schlägt mit einem `validation_error` fehl, dessen Detail-Schlüsselwort `preset_model_not_allowed` lautet; es wird nicht umgeleitet.

## Eine Voreinstellung erstellen und nutzen

<Steps>
<Step title="Die Voreinstellung erstellen">

Öffne **Dashboard -> Einstellungen -> Voreinstellungen** und erstelle eine Voreinstellung mit einem Slug wie `support-triage`. Füge nur die Standards hinzu, die alle Aufrufer teilen sollen.

Für Skripte rufst du `POST /v1/presets` mit einem Management-Schlüssel auf.

</Step>

<Step title="Über ihren Namen aufrufen">

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "@support-triage",
    "input": "Customer says the invoice total is wrong."
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "@support-triage",
  input: "Customer says the invoice total is wrong.",
});
```

```python Python
from phaseo import Phaseo

client = Phaseo(api_key="YOUR_API_KEY")

response = client.generate_response({
    "model": "@support-triage",
    "input": "Customer says the invoice total is wrong.",
})
```
</CodeGroup>

</Step>

<Step title="Prüfen, was angewendet wurde">

Öffne die Anfrage unter **Gateway -> Nutzung**, um zu sehen, welche Standards der Voreinstellung angewendet wurden und welcher Anbieter sie bedient hat.

</Step>

## Was eine Voreinstellung enthalten kann

| Einstellung | Wirkung |
| --- | --- |
| Modell | Wird verwendet, wenn die Anfrage mit dem Namen der Voreinstellung gesendet wird. |
| Erlaubte Modelle | Modell-IDs oder Muster wie `anthropic/*`. Andere Modelle werden abgelehnt. |
| System-Prompt | Wird jeder Anfrage vorangestellt. |
| [Prompt-Vorlage](./prompt-templates) | Nachrichten mit `{{variables}}`, die jede Anfrage ausfüllt. |
| Standardparameter | `temperature`, `top_p`, `max_tokens`, Reasoning-Einstellungen und Ähnliches. |
| Anbieterregeln | Zulassungs- und Ignorierlisten, Anbieterreihenfolge, Regionen, Preisobergrenzen. |

Halte aufruferspezifische Logik in deiner Anwendung und nutze getrennte Voreinstellungen, wenn Workflows unterschiedliche Prompts, Routing oder Caching brauchen.

## Eine Voreinstellung benennen

Sende eine Voreinstellung über das Feld `model` oder, wenn sie eine [Prompt-Vorlage](./prompt-templates) hat, über `prompt.id`. Ein separates Feld `preset` gibt es nicht.

| Form | Wird aufgelöst in |
| --- | --- |
| `@support-triage` | Dem Arbeitsbereich des API-Schlüssels (private und Arbeitsbereichs-Voreinstellungen). |
| `@octavia/support-triage` | Jedem Arbeitsbereich (öffentliche Voreinstellungen, veröffentlicht vom Benutzer `octavia`). |
| `@support-triage@v3` | Dieser veröffentlichten Version. |
| `@support-triage@production` | Der Version, auf die das Label `production` gerade zeigt. |

Zum Veröffentlichen einer öffentlichen Voreinstellung brauchst du ein aktiviertes öffentliches Profil und einen Benutzernamen. Benutzernamen sind in ganz Phaseo eindeutig; Slugs müssen nur pro Herausgeber eindeutig sein. Slugs werden in Kleinbuchstaben umgewandelt und dürfen Buchstaben, Ziffern, `-`, `_`, `.` und `:` enthalten.

## Versionieren und zurückrollen

Speichern ändert einen privaten Entwurf. **Neue Version veröffentlichen** macht aus dem Entwurf eine unveränderliche, nummerierte Version und behält alle früheren.

Lege fest, wie Versionsbezeichnungen aussehen:

| Format | Beispiel |
| --- | --- |
| Fortlaufend | `v1`, `v2`, `v3` |
| Semantische Versionierung | `1.2.0`, `2.0.0-beta.1`, `1.4.2+build.7` |
| Datum | `2026.08.02`, dann `2026.08.02.2` für eine zweite Version am selben Tag |

Richte ein benanntes Label wie `production` auf eine Version, und schiebe es auf eine frühere Version zurück, um zurückzurollen. Siehe [Versionen und Labels](/de/v1/guides/prompt-templates#versions-and-labels).

In Skripten veröffentlichst du mit `POST /v1/presets/{id}/versions` und verschiebst Labels mit `PUT /v1/presets/{id}/labels/{label}`, jeweils mit einem Management-Schlüssel. Eine CLI-Anmeldung oder eine App, die Mit Phaseo anmelden nutzt, kann Voreinstellungen lesen, aber nicht ändern.

## Eine Marketplace-Voreinstellung forken

Eine Kopie einer Marketplace-Voreinstellung bleibt an die Version gebunden, die du kopiert hast. Veröffentlicht der Herausgeber ein Update, zeigt deine Kopie einen Hinweis. Das Anwenden ändert nur deinen Entwurf, sodass nichts in die Produktion gelangt, bevor du selbst veröffentlichst.

Phaseo speichert die Quelle und die vollständige Abstammung jedes Forks, sodass eine Marketplace-Seite direkte Forks getrennt von allen Nachkommen anzeigen kann.

Wie du Bewertungen zu den Antworten einer Voreinstellung sammelst, steht unter [Feedback zu Voreinstellungen erfassen](./preset-feedback).
