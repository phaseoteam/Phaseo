Erstelle für jedes Team, jedes Produkt oder jede Umgebung einen Workspace, um API-Schlüssel, Routing-Einstellungen, Presets, Guardrails und Administratorzugriff getrennt zu halten. Jedes Konto beginnt mit einem persönlichen Workspace, der für eine kleine Integration ausreicht.

Separate Workspaces helfen, wenn du:

- Entwicklungs-, Staging- und Produktionszugangsdaten trennen willst
- Produkte oder Kundenprojekte auseinanderhalten willst
- einer administrativen Integration nur Zugriff auf die Ressourcen geben willst, die sie braucht
- unterschiedliche Routing-, Preset- oder Guardrail-Richtlinien anwenden willst

Workspaces ändern deine Preise nicht: Die gesamte Nutzung bleibt bei der normalen nutzungsbasierten Abrechnung, die unter [Preise und Abrechnung](../pricing/tiers) beschrieben ist. Weitere Workspaces werden nach deiner ersten Guthabeneinzahlung freigeschaltet; bis dahin schlägt das Erstellen mit `403 workspace_upgrade_required` fehl.

## Workspaces über die API verwalten

Verwalte Workspaces im Dashboard oder mit der Verwaltungs-API. Die API braucht einen [Verwaltungsschlüssel](../developers/management-api-keys); normale Gateway-API-Schlüssel sind für Inferenz gedacht und können diese Endpunkte nicht aufrufen.

| Aufgabe | Endpunkt | Berechtigung |
| --- | --- | --- |
| Workspaces auflisten | [`GET /workspaces`](../api-reference/endpoint/workspaces-list) | `workspaces:read` |
| Einen Workspace abrufen | [`GET /workspaces/{id}`](../api-reference/endpoint/workspaces-get) | `workspaces:read` |
| Einen Workspace erstellen | [`POST /workspaces`](../api-reference/endpoint/workspaces-create) | `workspaces:write` |
| Einen Workspace aktualisieren | [`PATCH /workspaces/{id}`](../api-reference/endpoint/workspaces-update) | `workspaces:write` |
| Einen Workspace löschen | [`DELETE /workspaces/{id}`](../api-reference/endpoint/workspaces-delete) | `workspaces:delete` |

Gib dem Schlüssel nur die Berechtigungen, die er braucht. Phaseo prüft außerdem Workspace-Mitgliedschaft und Rolle, eine Berechtigung allein gewährt also nie Zugriff auf einen anderen Workspace. Der `slug` eines neuen Workspace muss aus 1 bis 50 Kleinbuchstaben, Ziffern oder Bindestrichen bestehen.

Bewahre Verwaltungsschlüssel in einem serverseitigen Secret-Speicher auf, nie in Browser-Code, Desktop-Protokollen, der Versionsverwaltung oder Chats.

<Note>
Die Workspace-Endpunkte sind in der Beta. Gestalte Automatisierungen so, dass sie sicher wiederholt werden können, und prüfe jede Antwort, bevor du eine Folgeänderung vornimmst.
</Note>

## Einen Workspace umbenennen oder löschen

Der persönliche (Standard-)Workspace kann weder umbenannt noch gelöscht werden; beides gibt `400 bad_request` zurück. Bevor du einen anderen Workspace löschst, entferne oder verschiebe seine aktiven API-Schlüssel, damit keine Anfragen auf einen Workspace verweisen, den es nicht mehr gibt.
