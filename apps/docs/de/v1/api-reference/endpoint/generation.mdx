Rufe `GET /v1/generations?id=<request_id>` auf, um den gespeicherten Auditdatensatz einer Anfrage in deinem Workspace abzurufen. Dafür ist der Scope `generations:read` nötig; eine fehlende `id` gibt `400` `missing_id` zurück.

Neue Anfragen erhalten eine vom Server erzeugte Generierungs-ID mit dem Präfix `G-`, die im Antwort-Header `x-request-id` und in der Generierungsantwort zurückgegeben wird. Verwende diese ID für Anfrageprotokolle, das Nachschlagen von Generierungen und den Support. Ein vom Aufrufer gesendeter `x-request-id` ersetzt die Generierungs-ID nicht. Ältere UUID-Protokoll-IDs funktionieren zum Nachschlagen weiterhin.

## Eine Anfrage erneut ausführen

Jede Antwort enthält `replay_supported`. Wenn die I/O-Protokollierung den Anfrage-Body gespeichert hat und du gespeicherte Inhalte lesen darfst, ist `replay_supported` gleich `true`, und `replay_request` enthält den Body, den du für eine kontrollierte erneute Ausführung zurücksendest:

<Steps>
  <Step title="Generierung lesen">
    Rufe `GET /v1/generations?id=<request_id>` auf.
  </Step>
  <Step title="Prüfen, ob sie erneut ausgeführt werden kann">
    Fahre nur fort, wenn `replay_supported` gleich `true` ist.
  </Step>
  <Step title="Erneut senden">
    Sende `replay_request` an den in `endpoint` genannten Endpunkt, zum Beispiel `/v1/chat/completions` oder `/v1/responses`.
  </Step>
</Steps>

Ein Workspace kann gespeicherte Inhalte auf Owner und Admins beschränken. Andere Aufrufer, einschließlich API-Schlüsseln, die von Mitgliedern erstellt wurden, erhalten dann `replay_request: null` und Anfragedetails ohne deren Inhalte.
