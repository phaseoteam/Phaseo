Rufe `GET /v1/models` auf, um die Modelle aufzulisten, an die du gerade routen kannst. Setze `availability=all`, um auch Modelle einzubeziehen, die bekannt, aber derzeit nicht verfügbar sind.

```bash
curl "https://api.phaseo.app/v1/models?limit=50" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

Jedes Modell führt in `offers` einen Eintrag pro Anbieter-Route (gekürzt, Werte zur Veranschaulichung):

```json
{
  "ok": true,
  "availability_mode": "active",
  "limit": 50,
  "offset": 0,
  "total": 412,
  "models": [
    {
      "id": "anthropic/claude-sonnet-5.5",
      "name": "Claude Sonnet 5.5",
      "organization": { "id": "anthropic", "name": "Anthropic", "color": "#d97757" },
      "lifecycle": { "status": "active", "released_at": "2026-09-28", "replacement_id": null },
      "modalities": { "input": ["text", "image"], "output": ["text"] },
      "capabilities": { "endpoints": ["chat.completions", "messages", "responses"] },
      "availability": { "status": "active", "provider_count": 3, "active_provider_count": 3 },
      "offers": [
        {
          "provider": { "id": "anthropic", "name": "Anthropic" },
          "model": "claude-sonnet-5-5",
          "status": "active",
          "status_reason": null,
          "routable": true,
          "service_tiers": ["standard"],
          "routing": { "provider": "active", "model": "active", "capability": "active" }
        }
      ]
    }
  ]
}
```

Route Produktions-Traffic nur an ein Angebot, dessen `routable` gleich `true` ist. `status_reason` erklärt, warum ein Angebot nur Vorschau oder inaktiv ist. Das vollständige Schema steht unten.

`GET /models/me` gibt dieselbe Liste mit den Guardrails deines Schlüssels zurück: den Datenschutz- und Anbieterregeln deines Workspace sowie den Guardrails der Abteilungen des Schlüssels, seines Mitglieds und des Schlüssels selbst. Modelle, die eine Modellregel sperrt, und Modelle ohne erlaubten Anbieter fehlen, und jedes Modell behält nur die Angebote, an die seine Anfragen geleitet werden dürfen. Es nimmt dieselben Filter wie `GET /models` an. Die Antwort enthält außerdem `access`: ob eine Regel greift (`restricted`), welche Modelle die Regeln ausschließen (`hidden_model_count` und `hidden_models`, mit IDs und Namen) und wie viele gelistete Modelle Anbieter verloren haben (`limited_model_count`), damit du erklären kannst, warum ein Modell fehlt.

## Die Liste filtern

Filter, die mehrere Werte annehmen, akzeptieren wiederholte Parameter oder eine kommagetrennte Liste.

| Parameter | Filtert nach |
| --- | --- |
| `availability` | `active` (Standard) für öffentlich routbare Modelle oder `all`, um `coming_soon`-, `inactive`- und noch nicht routbare Modelle und Anbieter hinzuzufügen |
| `endpoints` | Öffentliche Endpunktnamen, zum Beispiel `chat.completions`, `responses` und `messages` |
| `status` | Modell-Lebenszyklus, zum Beispiel `active`, `deprecated` oder `retired` |
| `organisation` | Präfix der Modell-ID, zum Beispiel `anthropic` in `anthropic/claude-3-haiku` |
| `provider` | Öffentliche Anbieter-ID, zum Beispiel `openai`, `anthropic` oder `google_vertex` |
| `provider_status` | Rollout-Stufe des Anbieters, zum Beispiel `active`, `beta`, `alpha` oder `not_ready` |
| `provider_routing_status` | Routing-Status auf Anbieterebene |
| `model_routing_status` | Routing-Status auf Modellebene |
| `capability_status` | Fähigkeitsstatus des Anbieters für die angefragte Endpunktzuordnung |
| `provider_availability_status` | Verfügbarkeit beim Anbieter, zum Beispiel `active`, `coming_soon` oder `inactive` |
| `provider_availability_reason` | Warum ein Anbieter nicht verfügbar ist, zum Beispiel `preview_only`, `provider_not_ready`, `gated`, `access_limited` oder `region_limited` |
| `input_types` (Alias `input_modalities`) | Eingabemodalitäten |
| `output_types` (Alias `output_modalities`) | Ausgabemodalitäten |
| `params` (Alias `supported_parameters`) | Unterstützte Anfrageparameter |

Um die Anbieter-Routen, Parameterdetails und Preise eines einzelnen Modells zu prüfen, rufe [`GET /models/{author}/{slug}/endpoints`](./model-endpoints.mdx) auf.

## Service-Tiers pro Angebot prüfen

Jeder Eintrag in `offers` enthält `service_tiers`, die [Service-Tiers](../../guides/service-tiers.mdx), die dieses Anbieterangebot akzeptiert. Es ist eine alphabetisch sortierte Teilmenge von `flex`, `priority`, `standard` und `ultrafast`, wobei `priority` die Fast-Stufe ist. Eine Stufe wird aufgeführt, wenn die Anbieter-Route aktive, derzeit gültige Preise für sie hat, und eine Route, die nur eine Stufe bedient, führt nur diese Stufe auf. Einige Stufen sind auch über separate, stufenspezifische Anbieter-Routen verfügbar, die nicht aufgeführt werden. Die Preise unter `pricing` bleiben Preise der Standardstufe.

## Die Liste im OpenAI-Format abrufen

Verwende `GET /v1/models?format=openai` für Clients, die die Modelllisten-Antwort von OpenAI erwarten. Der Standard `format=json` gibt die umfangreicheren Modellmetadaten von Phaseo zurück.

```bash
curl "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

```json
{
  "object": "list",
  "data": [
    { "id": "openai/gpt-6-astra", "object": "model", "created": 1788393600, "owned_by": "openai" }
  ]
}
```

Das OpenAI-Format verwendet dieselbe Authentifizierung, regionale Verfügbarkeit, privaten Workspace-Modelle und Filter wie natives JSON. Es gibt alle passenden Modelle zurück, sofern du kein `limit` angibst; `offset` gilt weiterhin. IDs bleiben für die Inferenz in der kanonischen Form von Phaseo. `created` verwendet das Veröffentlichungsdatum aus dem Katalog oder `0`, wenn es unbekannt ist; `owned_by` verwendet die Organisation aus dem Katalog, `private` für Workspace-Modelle oder `phaseo`, wenn sie unbekannt ist.

## Die Modellliste zwischenspeichern

Katalogantworten werden fünf Minuten lang zwischengespeichert und können weitere fünf Minuten ausgeliefert werden, während der Cache neu validiert wird. Das gilt für die JSON-, RSS- und Atom-Darstellungen des aktuellen Katalogs; der Release-Feed hat einen eigenen, kürzeren Polling-Cache.

JSON-Antworten und Antworten im OpenAI-Format enthalten einen schwachen `ETag`-Header (`W/"…"`). Er ändert sich, wenn sich die Modelle auf der Seite, `limit`, `offset`, `total` oder das Format ändern. Er ignoriert `gateway_region`, sodass derselbe Katalog aus einer anderen Region denselben `ETag` hat. Deshalb ist er schwach: Antworten mit demselben Wert sind gleichwertig, ihre Bytes können sich aber unterscheiden. RSS-, Atom- und Fehlerantworten enthalten keinen.

Sende den gespeicherten Wert unverändert in `If-None-Match` zurück. Hat sich der Katalog nicht geändert, lautet die Antwort `304 Not Modified` ohne Body und wiederholt die Header `ETag`, `Cache-Control` und `Vary`. Andernfalls erhältst du ein normales `200` mit der neuen Liste und einem neuen `ETag`. `If-None-Match` akzeptiert auch eine kommagetrennte Liste und `*`, und der Vergleich ist schwach, sodass der Wert mit oder ohne sein Präfix `W/` passt.

```ts
let etag: string | null = null;
let models: unknown[] = [];

async function refreshModels() {
  const response = await fetch("https://api.phaseo.app/v1/models?limit=250", {
    headers: {
      Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
      ...(etag ? { "If-None-Match": etag } : {}),
    },
  });
  if (response.status === 304) return models; // Unverändert; ein 304 hat keinen Body.
  if (!response.ok) throw new Error(`Model list request failed: ${response.status}`);
  etag = response.headers.get("ETag");
  models = (await response.json()).models;
  return models;
}
```

Ein `304` spart Übertragung und Parsing. Der Server wertet die Anfrage trotzdem aus: Er lädt den Katalog und berechnet den `ETag` neu. Ein Abruf etwa alle 15 Minuten reicht; die Liste wird nur dann erneut heruntergeladen, wenn sich der Katalog ändert. Speichere einen `ETag` pro Anfrage-URL, weil jede Seite, jede Filterkombination und jedes Format einen eigenen Wert hat.
