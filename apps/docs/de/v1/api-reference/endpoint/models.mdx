Standardmäßig gibt dieser Endpunkt nur Modelle zurück, die aktuell geroutet werden können. Setze `availability=all`, um bekannte, derzeit aber nicht verfügbare Modelle einzuschließen.

Katalogantworten werden fünf Minuten zwischengespeichert und können während der Cache-Revalidierung weitere fünf Minuten ausgeliefert werden. Dies gilt für die JSON-, RSS- und Atom-Darstellungen des aktuellen Katalogs; der Veröffentlichungsfeed hat einen eigenen, kürzeren Abfrage-Cache.

`GET /models/me` ist für eine künftige Filterung nach den Guardrails des aktuellen Aufrufers vorgesehen. Der Endpunkt gibt derzeit `501 not implemented` zurück. Verwende deshalb vorerst `GET /models` für den gemeinsamen Gateway-Katalog.

## OpenAI-Format

Verwende `GET /v1/models?format=openai` für Clients, die die Modelllisten-Antwort von OpenAI erwarten. Der Standardwert `format=json` liefert die ausführlicheren Modellmetadaten von Phaseo.

```bash
curl 'https://api.phaseo.app/v1/models?format=openai' \
  -H 'Authorization: Bearer YOUR_PHASEO_API_KEY'
```

```json
{
  "object": "list",
  "data": [
    { "id": "openai/gpt-4o-mini", "object": "model", "created": 1721260800, "owned_by": "openai" }
  ]
}
```

Das OpenAI-Format verwendet dieselbe Authentifizierung, regionale Verfügbarkeit, privaten Workspace-Modelle und Filter wie das native JSON. Es gibt alle passenden Modelle zurück, sofern du kein `limit` angibst; `offset` gilt weiterhin. IDs bleiben für die Inferenz in der kanonischen Form von Phaseo. `created` verwendet das Veröffentlichungsdatum aus dem Katalog oder `0`, wenn es unbekannt ist; `owned_by` verwendet die Katalogorganisation, `private` für Workspace-Modelle oder `phaseo`, wenn sie unbekannt ist.

## Modellliste zwischenspeichern

Antworten im JSON- und OpenAI-Format enthalten einen schwachen `ETag`-Header (`W/"…"`). Er ändert sich, wenn sich die Modelle auf der Seite, `limit`, `offset`, `total` oder das Format ändern. `gateway_region` wird ignoriert, sodass derselbe Katalog aus einer anderen Region denselben `ETag` hat. Deshalb ist er schwach: Antworten mit demselben Wert sind gleichwertig, ihre Bytes können sich aber unterscheiden. RSS-, Atom- und Fehlerantworten enthalten keinen.

Sende den gespeicherten Wert unverändert in `If-None-Match` zurück. Hat sich der Katalog nicht geändert, lautet die Antwort `304 Not Modified` ohne Antworttext und wiederholt die Header `ETag`, `Cache-Control` und `Vary`. Andernfalls erhältst du eine normale `200`-Antwort mit der neuen Liste und einem neuen `ETag`. `If-None-Match` akzeptiert außerdem eine durch Kommas getrennte Liste und `*`. Der Vergleich ist schwach, daher passt der Wert mit oder ohne sein `W/`-Präfix.

```ts
let etag: string | null = null;
let models: unknown[] = [];

async function refreshModels() {
  const response = await fetch("https://api.phaseo.app/v1/models?limit=250", {
    headers: {
      Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
      ...(etag ? { "If-None-Match": etag } : {}),
    },
  });
  if (response.status === 304) return models; // Unchanged; a 304 has no body.
  if (!response.ok) throw new Error(`Model list request failed: ${response.status}`);
  etag = response.headers.get("ETag");
  models = (await response.json()).models;
  return models;
}
```

Eine `304`-Antwort spart Übertragung und Parsing, weil sie keinen Antworttext hat. Der Server wertet die Anfrage trotzdem aus: Er lädt den Katalog und berechnet den `ETag` neu. Polling etwa alle 15 Minuten ist daher angemessen; lade die Liste nur dann erneut herunter, wenn sich der Katalog ändert. Speichere einen `ETag` pro Anfrage-URL, denn jede Seite, jede Filterkombination und jedes Format hat einen eigenen Wert.

### Service-Stufen pro Angebot

Jeder Eintrag in `offers` enthält `service_tiers`, die [Service-Stufen](../../guides/service-tiers.mdx), die dieses Anbieterangebot akzeptiert. Das Feld ist eine alphabetisch sortierte Teilmenge von `flex`, `priority`, `standard` und `ultrafast`, wobei `priority` die Fast-Stufe ist. Eine Stufe wird aufgeführt, wenn die Anbieterroute dafür aktive, derzeit gültige Preise hat; eine Route, die nur eine Stufe bedient, führt nur diese Stufe auf. Manche Stufen können auch über separate, stufenspezifische Anbieterrouten verfügbar sein, die hier nicht aufgeführt werden. Die Preise unter `pricing` bleiben Preise der Standard-Stufe.

## Nützliche Filter

- `endpoints` verwendet öffentliche Namen wie `chat.completions`, `responses` und `messages`
- `status` filtert nach dem Lebenszyklus eines Modells, etwa `active`, `deprecated` oder `retired`
- `provider` filtert nach der öffentlichen Anbieter-ID, etwa `openai`, `anthropic` oder `google_vertex`
- `provider_status` filtert nach der Rollout-Stufe eines Anbieters, etwa `active`, `beta`, `alpha` oder `not_ready`
- `provider_routing_status` filtert nach dem Routing-Status eines Anbieters
- `model_routing_status` filtert nach dem Routing-Status eines Modells
- `capability_status` filtert nach dem Status der Anbieterfunktion für die angeforderte Endpunktzuordnung
- `provider_availability_status` filtert nach der Verfügbarkeit des Anbieters, etwa `active`, `coming_soon` oder `inactive`
- `provider_availability_reason` filtert nach dem Verfügbarkeitsgrund des Anbieters, etwa `preview_only`, `provider_not_ready`, `gated`, `access_limited` oder `region_limited`
- `organisation` filtert nach dem Präfix der öffentlichen Modell-ID, etwa `anthropic` in `anthropic/claude-3-haiku`
- `availability=active` ist der Standardwert
- `availability=all` umfasst Modelle oder Anbieter mit `coming_soon`, `inactive` oder ohne öffentliche Routing-Freigabe
- `input_modalities` ist ein Alias für `input_types`
- `output_modalities` ist ein Alias für `output_types`
- `supported_parameters` ist ein Alias für `params`

Rufe `GET /models/{author}/{slug}/endpoints` auf, um den Endpunktvertrag für ein Modell abzurufen. Die Antwort trennt die Anbieter-Routen und enthält für jede Zeile den öffentlichen Pfad, Modalitäten, Details zu unterstützten Parametern, Verfügbarkeit, Routing-Status, den Modell-Slug des Anbieters und eine Preisübersicht.

Anbietereinträge können außerdem Folgendes enthalten:

- `availability_status`
- `availability_reason`
- `provider_status`
- `provider_routing_status`
- `model_routing_status`
- `capability_status`
