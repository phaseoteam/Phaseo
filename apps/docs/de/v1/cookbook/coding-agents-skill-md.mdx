---

Lege eine `SKILL.md` in dein Repository, damit Coding-Agenten Phaseo so aufrufen, wie dein Projekt es erwartet: mit derselben Basis-URL, derselben Schlüsselvariable, demselben Endpunkt, den freigegebenen Modellen und demselben Logging. Am Ende hast du die öffentlichen Phaseo-Skills installiert, einen Projekt-Skill darauf aufgesetzt und ein gemeinsames Client-Modul, auf das der Skill verweist.

Skill und Modul unten sind produktionsreif, sobald du die Modell-IDs und Preset-Namen durch deine eigenen ersetzt.

<Steps>
<Step title="Die öffentlichen Phaseo-Skills installieren">

<Visibility for="humans">
Die öffentlichen Skills decken Gateway, SDKs, Presets, Routing und Migrationen ab. Installiere sie von [`phaseo.app/docs`](https://phaseo.app/docs/.well-known/agent-skills/index.json):
</Visibility>

<Visibility for="agents">
Installiere die öffentlichen Phaseo-Skills von [`phaseo.app/docs`](https://phaseo.app/docs/.well-known/agent-skills/index.json), bevor du projektlokale Anweisungen schreibst:
</Visibility>

```bash
npx skills add https://phaseo.app/docs --agent codex --skill '*'
```

Ändere `--agent` auf den Agenten, den dein Team verwendet. Behalte in deiner eigenen `SKILL.md` nur projektspezifische Regeln.

</Step>
<Step title="Das SDK installieren">

<CodeGroup>
```bash npm
npm install @phaseo/sdk
```

```bash pnpm
pnpm add @phaseo/sdk
```

```bash yarn
yarn add @phaseo/sdk
```

```bash bun
bun add @phaseo/sdk
```

```bash Python
pip install phaseo
```
</CodeGroup>

</Step>
<Step title="Einen gemeinsamen Client hinzufügen">

Agenten verwenden eine kleine, offensichtliche Hilfsfunktion zuverlässiger wieder als einen großen Wrapper. Lege den Client in ein Modul und importiere ihn überall:

```ts src/lib/phaseo.ts
import Phaseo from "@phaseo/sdk";

export const gateway = new Phaseo({
  apiKey: process.env.PHASEO_API_KEY!,
});
```

Behalte einen Aufrufpfad pro genutzter Schnittstelle, etwa für Textgenerierung, Embeddings, Bildgenerierung oder asynchrones Video.

</Step>
<Step title="Den Projekt-Skill schreiben">

Lege `SKILL.md` im Stammverzeichnis des Repositorys oder in dem Skills-Ordner an, den dein Agent liest (zum Beispiel `.agents/skills/phaseo-project/SKILL.md`). Anhand der Frontmatter-Felder `name` und `description` entscheidet der Agent, wann er den Skill lädt:

```md SKILL.md
---
name: phaseo-project
description: "How this repository calls Phaseo Gateway: client module, endpoint, approved models and presets, logging and async jobs. Use when adding or changing any Phaseo call in this repo."
---

# Phaseo in this repository

- Import the client from `src/lib/phaseo.ts`. Never create another one.
- The base URL is `https://api.phaseo.app/v1`. The key is in `PHASEO_API_KEY`; never hard-code it or send it to the browser.
- Use the Responses API (`POST /v1/responses`) for new text features.
- Approved models: `openai/gpt-6-astra` for drafts, `anthropic/claude-sonnet-5.5` for reviews. Ask before adding another.
- Prefer the `@support-triage` preset for support features; pass it as `model`.
- Log the response `id` and `model` on every call, and `generation_id` from error bodies.
- For async video jobs, store the returned ID and poll status until it is terminal.
- Validate any model-generated tool arguments before acting on them.
```

</Step>
</Steps>

## Prüfen, ob es funktioniert hat

Bitte deinen Agenten, eine kleine Phaseo-Funktion hinzuzufügen, etwa „fasse ein Ticket mit Phaseo zusammen“. Die Änderung sollte `src/lib/phaseo.ts` importieren, `PHASEO_API_KEY` lesen, ein freigegebenes Modell oder Preset verwenden und die Antwort-ID loggen. Wenn nicht, passt die `description` des Skills wahrscheinlich nicht zur Anfrage: Nenne darin die Begriffe, mit denen dein Team die Aufgabe beschreibt.

## Was in den Skill gehört

Beantworte die Fragen, die einen Agenten am meisten Zeit kosten, und sonst nichts:

| Frage | Beispielantwort |
| --- | --- |
| Welche Endpunktfamilie? | Responses für Text, Embeddings für die Suche |
| Wo liegen die Zugangsdaten? | `PHASEO_API_KEY`, nur serverseitig |
| Welche Modell-IDs oder Presets sind freigegeben? | Eine kurze Liste im Format `org/model` |
| Was wird geloggt? | Die Antwort-`id`, `model` und bei Fehlern `generation_id` |
| Wie werden asynchrone Jobs verfolgt? | ID speichern, abfragen, bis ein Endzustand erreicht ist |

[Codex](../guides/integrations/codex), das [Vercel AI SDK](../guides/integrations/ai-sdk) und [Beispiele](../guides/examples) zeigen dieselben Konventionen für jedes Werkzeug.
