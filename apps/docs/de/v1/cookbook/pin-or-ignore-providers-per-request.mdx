---

Füge einer Anfrage ein `provider`-Objekt hinzu, um zu ändern, welche Anbieter sie bedienen, ohne die Workspace-Standards oder Presets anzufassen. Am Ende kannst du eine Reihenfolge bevorzugen, eine Anfrage innerhalb einer Zulassungsliste halten oder einen Anbieter überspringen und in der Antwort sehen, welcher Anbieter geantwortet hat.

Diese Anfrageformen sind produktionsreif. Die Anbieter-Slugs sind echte Beispiele; prüfe auf der Seite des Modells, welche Anbieter dein Modell bedienen.

| Feld | Wirkung | Beispiel |
| --- | --- | --- |
| `order` | Versucht zuerst diese Anbieter, danach den Rest der zulässigen Auswahl | `["anthropic-us", "anthropic"]` |
| `only` | Hält die Anfrage innerhalb dieser Liste | `["openai", "openai-eu"]` |
| `ignore` | Entfernt diese Anbieter für diese Anfrage | `["novita"]` |
| `sort` | Ordnet die verbleibenden nach `price`, `latency` oder `throughput` | `"price"` |

Um genau einen Anbieter zu verwenden und den anbieterübergreifenden Fallback abzuschalten, stelle ihn stattdessen der Modell-ID voran: siehe [Einen Anbieter festlegen](../guides/routing-and-fallbacks#pin-one-provider).

## Anbieter in einer festen Reihenfolge versuchen

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-sonnet-5.5",
    "input": "Write a concise launch summary.",
    "provider": {
      "order": ["anthropic-us", "anthropic"]
    },
    "meta": true
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "anthropic/claude-sonnet-5.5",
  input: "Write a concise launch summary.",
  provider: {
    order: ["anthropic-us", "anthropic"],
  },
  meta: true,
});

console.log(response.meta?.routing); // { selected_provider: "anthropic-us", ... }
```

```python Python
import os

from phaseo import Phaseo

client = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

response = client.generate_response(
    {
        "model": "anthropic/claude-sonnet-5.5",
        "input": "Write a concise launch summary.",
        "provider": {
            "order": ["anthropic-us", "anthropic"],
        },
        "meta": True,
    }
)

print(response["meta"]["routing"]["selected_provider"])
```
</CodeGroup>

`meta: true` fügt der Antwort `meta.routing.selected_provider` hinzu, sodass du das Ergebnis prüfen kannst, ohne die Protokolle zu öffnen.

## Eine Anfrage innerhalb einer Zulassungsliste halten

Sende `only` und optional `sort`, um innerhalb dieser Liste zu ordnen:

```json
{
  "model": "openai/gpt-5.6-luna",
  "input": "Extract the action items.",
  "provider": {
    "only": ["openai", "openai-eu"],
    "sort": "price"
  }
}
```

Bedient keiner der aufgeführten Anbieter das Modell, schlägt die Anfrage fehl, statt die Liste zu verlassen.

## Einen Anbieter überspringen

Sende `ignore`, wenn ein Anbieter beeinträchtigt ist oder während du einen anderen Pfad testest:

```json
{
  "model": "meta/llama-4-maverick",
  "input": "Summarize the transcript.",
  "provider": {
    "ignore": ["novita"]
  }
}
```

## Kombinieren

Verwende `only` für die Auswahl, `order` für die Bevorzugung darin und `sort` für den Rest. Dieses Beispiel hält eine Anfrage bei Google Vertex, versucht zuerst die EU-Region und ordnet dann nach Latenz:

```json
{
  "model": "anthropic/claude-sonnet-5.5",
  "input": "Summarize the incident in one sentence.",
  "provider": {
    "only": ["google-vertex", "google-vertex-eu"],
    "order": ["google-vertex-eu"],
    "sort": "latency"
  }
}
```

## Prüfen, wohin sie ging

Öffne die Anfrage unter **Einstellungen → Nutzung → Protokolle** und klappe **Beobachtbarkeit des Routings** auf. Dort stehen die Anbieter, die vor der Rangfolge ausgeschlossen wurden, samt Grund, und die gereihten Kandidaten mit ihren Bewertungen; [Eine Routing-Entscheidung erklären](../guides/routing-and-fallbacks#explain-a-routing-decision) beschreibt jedes Feld.

Verwende Regeln auf Anfrageebene für Überschreibungen, die vorübergehend sind, nur für einen Aufrufer gelten oder an einen Nutzerablauf gebunden sind. Sobald dieselben Regeln in mehreren Diensten auftauchen, verschiebe sie in ein [Preset](../guides/presets), wo sie auch begrenzen, welche Anbieter ein Fallback nutzen darf. Um Rangfolgen zu vergleichen, siehe [Anbieter sortieren](./sort-providers-by-price-latency-or-throughput).
