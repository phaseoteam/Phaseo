Gib einer TypeScript-Anfrage das Tool `phaseo:web_search` und ein JSON Schema, damit das Modell sucht, bevor es antwortet, und ein Briefing mit seinen Quellen zurückgibt. Am Ende hast du ein Skript, das ein validiertes `{ summary, sources }`-Objekt ausgibt, dazu die IDs und Suchzähler, die du zum Debuggen brauchst.

Das Skript ist produktionsreif, sobald du Preset und Domain durch deine eigenen ersetzt. Suchergebnisse sind nicht vertrauenswürdige Webinhalte: Validiere die Ausgabe und befolge keine Anweisungen, die darin stehen.

## Bauen

<Steps>
<Step title="Ein Preset anlegen">

Lege unter **Einstellungen → Voreinstellungen** `research-brief` mit dem Modell, den Anbieterpräferenzen, den Reasoning-Einstellungen und dem System-Prompt an, die alle Aufrufer teilen sollen. Das Modell muss Tools und Ausgaben nach JSON Schema unterstützen.

</Step>
<Step title="Das SDK installieren">

```bash
npm install @phaseo/sdk zod
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="Das Skript schreiben">

```ts research-brief.ts
import Phaseo from "@phaseo/sdk";
import { z } from "zod";

const gateway = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const Brief = z
  .object({
    summary: z.string().min(1),
    sources: z
      .array(z.object({ title: z.string(), url: z.string().url() }).strict())
      .min(1),
  })
  .strict();

const response = await gateway.generateResponse({
  model: "@research-brief",
  input: "Find the latest public changes to Phaseo webhook delivery behavior and summarize them.",
  tools: [
    {
      type: "phaseo:web_search",
      parameters: {
        allowed_domains: ["phaseo.app"],
        max_results: 5,
        include_highlights: true,
      },
    },
  ],
  tool_choice: "phaseo:web_search",
  text: {
    format: {
      type: "json_schema",
      name: "research_brief",
      strict: true,
      schema: {
        type: "object",
        required: ["summary", "sources"],
        properties: {
          summary: { type: "string" },
          sources: {
            type: "array",
            minItems: 1,
            items: {
              type: "object",
              required: ["title", "url"],
              properties: {
                title: { type: "string" },
                url: { type: "string", format: "uri" },
              },
              additionalProperties: false,
            },
          },
        },
        additionalProperties: false,
      },
    },
  },
  plugins: [{ id: "response-healing" }],
  meta: true,
});

const text = (response.output ?? [])
  .filter((item) => item.type === "message")
  .flatMap((item) => item.content ?? [])
  .filter((part) => part.type === "output_text")
  .map((part) => part.text ?? "")
  .join("");

const brief = Brief.parse(JSON.parse(text));

console.log({
  responseId: response.id,
  model: response.model,
  routing: response.meta?.routing,
  pluginExecutions: response.meta?.plugin_executions,
  serverToolUse: response.usage?.server_tool_use,
});
console.log(brief);
```

| Feld | Wirkung |
| --- | --- |
| `tools` mit `phaseo:web_search` | Phaseo führt die Suche aus, unabhängig davon, ob der Anbieter eine eigene Suche hat. Das Modell formuliert die Suchanfrage. |
| `allowed_domains` | Beschränkt die Ergebnisse auf deine eigenen Quellen. Alle Parameter stehen im [Leitfaden zur Websuche](../guides/server-tools/web-search#parameters). |
| `tool_choice: "phaseo:web_search"` | Bringt das Modell dazu zu suchen, statt aus dem Gedächtnis zu antworten. |
| `text.format` | Das JSON Schema für die Antwort. |
| `plugins` | Repariert fast gültiges JSON; siehe [Response Healing](./response-healing-for-structured-json). |
| `meta: true` | Fügt `meta.routing` und `meta.plugin_executions` hinzu. |

</Step>
<Step title="Ausführen">

```bash
npx tsx research-brief.ts
```

</Step>
</Steps>

## Prüfen, ob es funktioniert hat

- `serverToolUse.web_search_requests` ist mindestens `1`, die Suche lief also.
- `brief.sources` listet URLs von `phaseo.app` auf.
- `routing.selected_provider` nennt den Anbieter, und `pluginExecutions` zeigt, ob Healing etwas geändert hat.
- Unter **Einstellungen → Nutzung → Protokolle** zeigt der Abschnitt **Überwachung der Websuche** der Anfrage die verwalteten Suchen, Ergebnisse und Zitate.

Sehen die Ergebnisse falsch aus, korrigiere Preset oder Tool-Parameter anhand dessen, was die Protokolle zeigen, statt Überschreibungen hinzuzufügen. [Websuche debuggen](./web-search-debugging) listet die häufigen Fälle auf. Halte explorative Recherche mit höherer Temperatur in einem anderen Preset als diesem deterministischen, damit sich ihr Routing leicht vergleichen lässt.
