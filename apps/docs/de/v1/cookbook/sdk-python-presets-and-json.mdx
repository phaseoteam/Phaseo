Rufe aus Python ein Dashboard-Preset mit einem JSON Schema auf, validiere dann die Antwort und logge die IDs, die du zum Debuggen brauchst. Am Ende hast du ein Skript, das `"model": "@release-summary"` sendet, `{"summary": ..., "risk_level": ...}` zurückbekommt und die Anbieter- und Plugin-Details dieser Anfrage ausgibt.

Das Skript ist produktionsreif, sobald du Preset und Schema durch deine eigenen ersetzt. Behalte den Validierungsschritt: Healing behebt die Syntax, nicht den Inhalt.

## Bauen

<Steps>
<Step title="Das Preset anlegen">

Lege unter **Einstellungen → Voreinstellungen** `release-summary` mit dem System-Prompt, dem Modell oder den erlaubten Modellen, den Anbieterpräferenzen, den Reasoning-Einstellungen und der `temperature` an, die alle Aufrufer teilen sollen. Der Python-Code sendet dann nur noch, was sich ändert. [Presets](../guides/presets) erklärt, wie das Preset mit der Anfrage zusammengeführt wird.

</Step>
<Step title="Das SDK installieren">

```bash
pip install phaseo
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="Das Skript schreiben">

```python release_summary.py
import json
import os

from phaseo import Phaseo

# Einen Client erstellen und wiederverwenden.
gateway = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

SCHEMA = {
    "type": "object",
    "properties": {
        "summary": {"type": "string"},
        "risk_level": {"type": "string", "enum": ["low", "medium", "high"]},
    },
    "required": ["summary", "risk_level"],
    "additionalProperties": False,
}


def output_text(response: dict) -> str:
    return "".join(
        part.get("text", "")
        for item in response.get("output", [])
        if item.get("type") == "message"
        for part in item.get("content", [])
        if part.get("type") == "output_text"
    )


def validate(payload: dict) -> dict:
    if set(payload) != {"summary", "risk_level"}:
        raise ValueError(f"unexpected keys: {sorted(payload)}")
    if not isinstance(payload["summary"], str) or not payload["summary"]:
        raise ValueError("summary must be a non-empty string")
    if payload["risk_level"] not in ("low", "medium", "high"):
        raise ValueError("risk_level must be low, medium or high")
    return payload


response = gateway.generate_response(
    {
        "model": "@release-summary",
        "input": "Summarize the last 24 hours of deployment activity.",
        "text": {
            "format": {
                "type": "json_schema",
                "name": "release_summary",
                "strict": True,
                "schema": SCHEMA,
            }
        },
        "plugins": [{"id": "response-healing"}],
        "meta": True,
    }
)

if response.get("status") != "completed":
    raise RuntimeError(f"response {response.get('id')} ended as {response.get('status')}")

payload = validate(json.loads(output_text(response)))
meta = response.get("meta", {})

print("response_id:", response.get("id"))
print("model:", response.get("model"))
print("selected_provider:", meta.get("routing", {}).get("selected_provider"))
print("plugin_executions:", meta.get("plugin_executions"))
print(payload)
```

| Feld | Wirkung |
| --- | --- |
| `"model": "@release-summary"` | Verwendet das Preset. Ein eigenes `preset`-Feld gibt es nicht. |
| `text.format` | Fordert dieses JSON Schema an. Bei Chat Completions gehört es in `response_format`; siehe [Strukturierte Ausgaben](../guides/structured-outputs). |
| `plugins` | Repariert fast gültiges JSON; siehe [Response Healing](./response-healing-for-structured-json). |
| `meta: true` | Fügt der Antwort `meta.routing` und `meta.plugin_executions` hinzu. |

</Step>
<Step title="Ausführen">

```bash
python release_summary.py
```

</Step>
</Steps>

## Prüfen, ob es funktioniert hat

Das Skript gibt die Antwort-ID, das Modell und den Anbieter, die geantwortet haben, den Plugin-Eintrag und ein Dict mit `summary` und einem der Werte `low`, `medium` oder `high` aus. Suche die Antwort-ID unter **Einstellungen → Nutzung → Protokolle**, um dieselbe Anfrage mit ihren Routing-Details zu sehen.

Ein Modell außerhalb der erlaubten Modelle des Presets schlägt mit `validation_error` (Schlüsselwort `preset_model_not_allowed`) fehl. Ein `ValueError` aus `validate()` bedeutet, dass sich das JSON parsen ließ, der Inhalt aber falsch war: Verschärfe Schema oder Prompt, statt Wiederholungen hinzuzufügen.

## Debuggen, bevor du überschreibst

Wenn eine Anfrage anders geroutet wird als erwartet, öffne sie in den Protokollen, lies **Beobachtbarkeit des Routings** und den Plugin-Eintrag und ändere das Preset erst, wenn die Protokolle zeigen, was passiert ist. Inline-Überschreibungen in einer Anfrage anzuhäufen, untergräbt den Zweck des Presets; braucht ein Aufrufer wirklich ein anderes Verhalten, gib ihm ein eigenes Preset.
