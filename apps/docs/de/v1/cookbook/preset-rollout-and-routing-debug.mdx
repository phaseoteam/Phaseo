Stelle mehrere Dienste auf ein Preset um, damit sie sich Prompt, Modell und Anbieterregeln teilen, und erkläre dann anhand der Anfrageprotokolle, wohin jede Anfrage ging. Am Ende senden deine Aufrufer `"model": "@release-summary"` und ihre Eingabe, und du kannst eine Richtlinienänderung Aufrufer für Aufrufer ausrollen.

Die Anfrageform ist produktionsreif. [Presets](../guides/presets) erklärt, wie die Einstellungen eines Presets mit der Anfrage zusammengeführt werden; dieses Rezept beschreibt den Rollout.

## Einen Aufrufer auf ein Preset umstellen

<Steps>
<Step title="Das Preset anlegen">

Lege unter **Einstellungen → Voreinstellungen** `release-summary` mit einem System-Prompt, den freigegebenen Modellen, Anbieterpräferenzen und Standardparametern wie `temperature` an. Oder mit einem Management-Schlüssel:

```bash
curl https://api.phaseo.app/v1/presets \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name":"@release-summary","config":{"model":"anthropic/claude-sonnet-5.5"}}'
```

</Step>
<Step title="Es über den Namen aufrufen">

Sende das Preset als `model`. Ein eigenes `preset`-Feld gibt es nicht.

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "@release-summary",
    "input": "Generate a release summary for the last 24 hours.",
    "meta": true
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "@release-summary",
  input: "Generate a release summary for the last 24 hours.",
  meta: true,
});

console.log(response.model, response.meta?.routing);
```

```python Python
import os

from phaseo import Phaseo

client = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

response = client.generate_response(
    {
        "model": "@release-summary",
        "input": "Generate a release summary for the last 24 hours.",
        "meta": True,
    }
)

print(response.get("model"), response["meta"]["routing"]["selected_provider"])
```
</CodeGroup>

`model` in der Antwort ist das Modell, das geantwortet hat, und `meta.routing.selected_provider` der Anbieter.

</Step>
<Step title="Prüfen, was das Preset angewendet hat">

Öffne die Anfrage unter **Einstellungen → Nutzung → Protokolle**. Dort steht, welche Preset-Standards angewendet wurden. Ein Modell außerhalb der erlaubten Modelle des Presets schlägt mit `validation_error` (Schlüsselwort `preset_model_not_allowed`) fehl, statt umgeleitet zu werden.

</Step>
</Steps>

## Eine Routing-Entscheidung erklären

Wenn eine Anfrage nicht wie erwartet geroutet wurde, klappe bei der Anfrage unter **Einstellungen → Nutzung → Protokolle** **Beobachtbarkeit des Routings** auf. Dort findest du Antworten auf drei Fragen:

| Frage | Wo du nachsiehst |
| --- | --- |
| Warum wurde ein Anbieter übersprungen? | Anbieter, die vor der Rangfolge ausgeschlossen wurden, samt Grund, und Anbieter, die wegen ihres Rollout- oder Routing-Status herabgestuft wurden |
| Warum wurde die Anfrage blockiert? | Blockierungen durch Workspace-Richtlinien oder Guardrails bei der Anfrage |
| Warum hat dieser Anbieter gewonnen? | Die Endbewertung jedes gereihten Anbieters und die Faktoren dahinter |

[Eine Routing-Entscheidung erklären](../guides/routing-and-fallbacks#explain-a-routing-decision) beschreibt jedes Feld.

## Eine Richtlinienänderung ausrollen

1. Veröffentliche die Änderung als neue Preset-Version oder lege für eine sehr andere Richtlinie einen neuen Slug an.
2. Stelle einen Aufrufer mit geringem Risiko darauf um, zum Beispiel indem du ihn auf `@release-summary@v4` oder ein `canary`-Label zeigen lässt.
3. Vergleiche seine Anfragedetails und Nutzungstrends mit denen der anderen Aufrufer.
4. Stelle die übrigen Aufrufer um, sobald das Routing deinen Erwartungen entspricht. Für einen Rollback lässt du das Label auf die frühere Version zeigen.

[Versionieren und zurückrollen](../guides/presets#version-and-roll-back) behandelt Versionen und Labels. Für Überschreibungen auf Anfrageebene, die nicht in ein Preset gehören, siehe [Anbieter festlegen oder ignorieren](./pin-or-ignore-providers-per-request).
