Führe ein Node.js-Skript ohne Abhängigkeiten aus, das Phaseo mit einfachem `fetch` aufruft, damit du jede Anfrage und jede Antwort siehst. Am Ende hast du einen Smoke-Test, den du vor einem Deploy ausführen kannst: Er prüft, ob die API erreichbar ist, listet Modelle auf und sendet je eine Anfrage an Responses, Chat Completions und Embeddings.

Das Skript ist ein Beispiel: Es gibt jeden HTTP-Status aus, beendet sich aber immer mit `0`. Ergänze deshalb die Exit-Code-Prüfung aus [Als Deploy-Check verwenden](#use-it-as-a-deploy-check), bevor du dich in CI darauf verlässt.

Damit ein Coding-Agent dasselbe Skript von Grund auf baut, füge diesen Prompt ein:

## Was das Skript aufruft

Das Beispiel ist [examples/gateway-node-quickstart](https://github.com/phaseoteam/Phaseo/tree/main/examples/gateway-node-quickstart): eine einzige Datei, `index.mjs`, ohne Abhängigkeiten.

| Modus | Aufrufe | Kostet Credits |
| --- | --- | --- |
| `npm run smoke` | `GET /v1/health`, `GET /v1/models` | Nein |
| `npm run start` | Beide oben genannten, danach `POST /v1/responses`, `POST /v1/chat/completions`, `POST /v1/embeddings` | Ja |

Die Textaufrufe senden `Return exactly: integration_ok` an `PHASEO_MODEL` (Standard `openai/gpt-5.6-sol`). Der Embeddings-Aufruf verwendet `google/gemini-embedding-2`.

## Ausführen

Du brauchst Node.js 18 oder neuer, wegen des eingebauten `fetch`, und einen Phaseo-API-Schlüssel.

<Steps>
<Step title=".env.local anlegen">

Das Skript lädt `.env.local` aus dem Ordner, in dem du es ausführst, ganz ohne Paket. Das Beispiel enthält keine `.env.example`, also lege die Datei selbst an:

```bash .env.local
PHASEO_API_KEY=phaseo_v1_sk_...
# Optional
PHASEO_MODEL=openai/gpt-6-astra
PHASEO_BASE_URL=https://api.phaseo.app/v1
PHASEO_APP_TITLE=My smoke test
PHASEO_HTTP_REFERER=https://myapp.example
```

Variablen, die in deiner Shell bereits gesetzt sind, haben Vorrang vor der Datei.

</Step>
<Step title="Smoke-Modus ausführen">

```bash
cd examples/gateway-node-quickstart
npm run smoke
```

</Step>
<Step title="Vollständigen Modus ausführen">

```bash
npm run start
```

</Step>
</Steps>

## Prüfen, ob es funktioniert hat

Jeder Aufruf gibt einen Block wie diesen aus:

```text
=== Health ===
HTTP 200
{ ... }
```

- `Health` und `Models` zeigen `HTTP 200`, und `Models` listet mindestens ein Modell auf.
- Im vollständigen Lauf enthalten die Blöcke für Responses und Chat Completions `integration_ok`.
- Mit einem falschen Schlüssel zeigen die Generierungsblöcke `HTTP 401` und den Fehlertext, statt ihn zu verschlucken.
- Die Anfragen erscheinen unter **Einstellungen → Nutzung → Protokolle**.

## Als Deploy-Check verwenden

`request()` gibt `{ status, ok, payload }` zurück, aber nichts prüft `ok`. Füge oben in `print()` eine Zeile ein, damit das Skript mit `1` endet, sobald ein Aufruf fehlgeschlagen ist:

```js index.mjs
function print(title, result) {
  if (!result.ok) process.exitCode = 1;
  console.log(`\n=== ${title} ===`);
  // ...rest unchanged
}
```

Kürze das Skript auf die Routen, die dein Dienst nutzt, und wechsle zum [TypeScript-SDK](../sdk-reference/client/overview), wenn du Payloads nicht von Hand bauen möchtest.
