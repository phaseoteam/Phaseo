Baue einen TypeScript-Triage-Agenten, dessen Modell, Prompt und Anbieterregeln aus einem Preset im Dashboard stammen, sodass der Code nur den Workflow behandelt. Am Ende gibt er eine streng strukturierte JSON-Triage-Entscheidung zurück, hält Fälle an, die eine Person brauchen, wiederholt Modellaufrufe eine begrenzte Anzahl von Malen und protokolliert Gateway-Fehler mit den IDs, die du brauchst, um sie zu finden.

Das Skript ist produktionsreif, sobald das Preset existiert und du angehaltene Läufe speicherst, wie in der [robusten Agent-Schleife](./agent-sdk-durable-loop). Eine fertig verpackte Version liegt in `packages/sdk/agent-sdk-ts/examples/support-triage-agent.ts`.

## Agenten bauen

<Steps>
<Step title="Preset anlegen">

Lege unter **Einstellungen → Voreinstellungen** das Preset `support-triage` mit dem gerouteten Modell, den Anbieterpräferenzen, dem Support-Systemprompt und stabilen Decoding-Parametern an. Das Modell muss JSON-Schema-Ausgabe unterstützen. [Presets](../guides/presets) erklärt, wie ein Preset mit jeder Anfrage zusammengeführt wird.

</Step>
<Step title="Installieren">

```bash
npm install @phaseo/agent-sdk zod
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="Agenten schreiben">

```ts triage-agent.ts
import { z } from "zod";
import { AgentGatewayError, createAgent, createGatewayAgentClient } from "@phaseo/agent-sdk";

const SupportTriageDecision = z
  .object({
    queue: z.enum(["billing", "reliability", "product", "security"]),
    severity: z.enum(["low", "medium", "high"]),
    needsHumanReview: z.boolean(),
    summary: z.string().min(1),
  })
  .strict();
type SupportTriageDecision = z.infer<typeof SupportTriageDecision>;

// `preset` wird in jedem Zug zum Modell `@support-triage`.
const supportTriageAgent = createAgent<string, SupportTriageDecision>({
  id: "support-triage-agent",
  preset: "support-triage",
  maxSteps: 3,
  parseOutput: (text) => JSON.parse(text),
  outputSchema: SupportTriageDecision,
  humanReview: ({ parsedOutput }) =>
    parsedOutput?.needsHumanReview
      ? { reason: "support_triage_review_required", payload: parsedOutput }
      : null,
});

const client = createGatewayAgentClient({
  clientOptions: { apiKey: process.env.PHASEO_API_KEY! },
  responseFormat: {
    type: "json_schema",
    name: "support_triage_decision",
    schema: {
      type: "object",
      properties: {
        queue: { type: "string", enum: ["billing", "reliability", "product", "security"] },
        severity: { type: "string", enum: ["low", "medium", "high"] },
        needsHumanReview: { type: "boolean" },
        summary: { type: "string" },
      },
      required: ["queue", "severity", "needsHumanReview", "summary"],
      additionalProperties: false,
    },
  },
  plugins: [{ id: "response-healing", mode: "strict" }],
});

try {
  const result = await supportTriageAgent.run({
    input: "Customer says webhook deliveries failed overnight and asks whether data was lost.",
    client,
    modelRetry: { maxRetries: 2, backoffMs: 250 },
    onEvent(event) {
      if (event.type === "model.retrying") console.log("retrying", event.attempt, event.error);
    },
  });

  if (result.run.status === "waiting_for_human") {
    // `result` speichern und fortsetzen, sobald ein Support-Mitarbeiter es geprüft hat.
    console.log("Needs review:", result.run.pause?.payload);
  } else {
    console.log(result.output);
  }
} catch (error) {
  if (error instanceof AgentGatewayError) {
    console.error("Gateway request failed", {
      status: error.status,
      requestId: error.requestId,
      generationId: error.generationId,
      reason: error.reason,
      providerFailureDiagnostics: error.providerFailureDiagnostics,
      routingDiagnostics: error.routingDiagnostics,
    });
  }
  throw error;
}
```

</Step>
<Step title="Ausführen">

```bash
npx tsx triage-agent.ts
```

</Step>
</Steps>

Um einen angehaltenen Fall abzuschließen, setze ihn mit der Entscheidung der prüfenden Person fort:

```ts
const continued = await supportTriageAgent.continueRun({
  run: storedResult,
  client,
  humanInput: "Approved. Finalize the triage decision.",
});
```

## Prüfen, ob es funktioniert hat

Führe ein Routineticket und ein riskantes Ticket aus und prüfe dann:

- Unter **Einstellungen → Nutzung → Protokolle** zeigt das Modell der Anfrage, dass das Preset verwendet wurde.
- Der riskante Fall endet bei `waiting_for_human`, mit der Entscheidung in `pause.payload`.
- Ein wiederholter Modellaufruf wird im Schritt als `modelAttempts` erfasst, und jede Wiederholung protokolliert `model.retrying`.
- Eine blockierte Anfrage wird mit ihrer `requestId` und ihrem `reason` protokolliert, und dieselbe Anfrage in den Protokollen zeigt den Grund.

## Gateway-Fehler sichtbar halten

Verschlucke keine Fehler in Agent-Callbacks. Fange `AgentGatewayError` am Rand ab, protokolliere seine IDs und wirf ihn erneut. Sobald ein Lauf fehlschlägt, behält sein gespeicherter Zustand dieselben Details in `run.errorDetails` und `steps[n].errorDetails`, sodass ein späterer Wiederherstellungsjob sie lesen kann, nachdem die Ausnahme verschwunden ist.

Diese Fehler stammen aus Gateway-Richtlinien, nicht vom Agenten, deshalb ist die Anfrage in den Protokollen der richtige Ort zum Nachsehen:

| Fehler | Wo er erscheint |
| --- | --- |
| Eine Guardrail blockiert die Anfrage | Der Abschnitt **Durchsetzung der Leitplanken** der Anfrage |
| Die erlaubten Modelle des Presets lehnen das Modell ab | `validation_error` mit dem Schlüsselwort `preset_model_not_allowed` |
| Anbieter-Zugangsdaten oder -Aktivierung lassen keinen Anbieter übrig | `providerFailureDiagnostics` und **Beobachtbarkeit des Routings** |
| Die Reparatur kann kein schemagültiges JSON erzeugen | Der Plugin-Eintrag, danach `AgentSchemaValidationError` aus `outputSchema` |
