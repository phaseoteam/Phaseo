Phaseo ist ein pnpm- und Turborepo-Monorepo. Finde mit dieser Referenz die Dateien für Code- oder Dokumentationsänderungen. Für Katalogdatensatzänderungen [öffne ein Issue](./overview.mdx).

## Anwendungen und Pakete

| Pfad | Zweck |
| --- | --- |
| `apps/web` | Next.js-16-Website, Dashboard und interner Katalogeditor. |
| `apps/web-api` | Öffentliche Katalogabfragen und authentifizierte Konto- und Admin-APIs. |
| `apps/api` | Gateway-Routing und Anbieterausführung auf Cloudflare Workers. |
| `apps/docs` | Mintlify-Dokumentation; MDX-Seiten in `v1`, Navigation in `docs.json`. |
| `packages/sdk` | SDKs für TypeScript, Python, Go, C#, PHP, Ruby, Java, Rust und C++. |
| `supabase/migrations` | Migrationen für Datenbankschema und Berechtigungen. |
| `scripts` | Hilfsprogramme für Validierung, SDK-Generierung und Automatisierung. |
| `.github/workflows` | CI, Bereitstellung und Katalogsynchronisierung. |
| `.changeset` | Releasemetadaten versionierter Pakete. |

## Katalogdaten

Die Datenbank ist die maßgebliche Quelle für Modelle, Anbieter, Organisationen, Preise, Benchmarks und unterstützende Katalogeinstellungen. Administratoren verwalten Datensätze über [Interne Daten](https://phaseo.app/internal/data). Öffentliche Beiträge werden über GitHub-Issues geprüft.

- Das Repository enthält keine Katalog-JSON-Dateien. Der alte JSON-zu-Datenbank-Importer wurde eingestellt.

Schema- und Anwendungsänderungen verwenden weiterhin Migrationen und Pull Requests. Generierte SDK-Artefakte sollten mit den jeweiligen Generierungsbefehlen aktualisiert werden.

## Katalogautomatisierung

Die Anbietersynchronisierung stellt vorgeschlagene Preise unter [Anbieteraktualisierungen](https://phaseo.app/internal/data/imports) zur Prüfung in die Warteschlange. Benchmark- und Modelllebenszyklusaufträge verwenden die Datenbank.

Reine Katalogdatensätze aktivieren Gateway-Routing nicht automatisch. Routen- und Preisänderungen erfordern die entsprechende Adminprüfung.
