Zu **Phaseo** beizutragen ist einfach, transparent und für alle offen.
Diese Anleitung führt dich durch den gesamten Ablauf – ob du einen Modelleinsatz bearbeitest, Benchmarkdaten aktualisierst, die Dokumentation verbesserst oder neue Ideen einbringst.

---

## Vor dem Start

Du benötigst einige grundlegende installierte Werkzeuge:

| Werkzeug | Zweck | Installation |
| ------------------ | ---------------------------------------------- | -------------------------------------------------- |
| **Git**            | Versionsverwaltung zum Klonen und Übertragen von Änderungen.     | [Git installieren](https://git-scm.com/downloads)       |
| **Node.js (v20+)** | Führt die Phaseo-Website lokal aus (Next.js).      | [Node.js herunterladen](https://nodejs.org/en/download) |
| **pnpm**           | Paketmanager für dieses Projekt.          | `npm install -g pnpm`                              |
| **GitHub-Konto** | Wird für Forks, Issues und Pull Requests benötigt. | [Hier registrieren](https://github.com/signup)          |

Wenn du nur **Daten** oder die **Markdown-Dokumentation** bearbeiten möchtest, kannst du Änderungen direkt auf GitHub vornehmen, ohne eine lokale Umgebung einzurichten.

---

## 1. Repository forken

Öffne das [Phaseo-GitHub-Repository](https://github.com/phaseoteam/Phaseo) und klicke oben rechts auf **Fork**.
Dadurch erhältst du eine eigene Kopie des Projekts, die du frei bearbeiten kannst.

---

## 2. Fork klonen

```bash
git clone https://github.com/yourusername/Phaseo.git
cd Phaseo
```

Dadurch wird dein Fork auf deinen lokalen Rechner geladen.

---

## 3. Neuen Branch erstellen

Erstelle am besten für jede Änderung einen neuen Branch:

```bash
git checkout -b update-benchmark-data
```

Wähle einen aussagekräftigen Branch-Namen, der deine Änderung beschreibt und die Prüfung erleichtert.

Beispiele:

-   `fix-{model-name}`
-   `add-new-organisation`
-   `improve-docs`
-   `update-pricing-for-{model-name}`

---

## 4. Änderungen vornehmen

Je nachdem, was du bearbeiten möchtest:

| Bereich | Dateien | Beschreibung |
| --------------------- | --------------------------------------------- | ----------------------------------------------------- |
| **Modelldaten**        | `/packages/data/catalog/src/data/models/**/model.json`     | Modellmetadaten, Preise oder Benchmarks ergänzen oder aktualisieren. |
| **Organisationsdaten** | `/packages/data/catalog/src/data/organisations/*.json`     | Angaben zu Unternehmen oder Forschungsgruppen aktualisieren.    |
| **Benchmarkdaten**    | `/packages/data/catalog/src/data/benchmarks/**/*.json`     | Neue Bewertungsergebnisse oder Korrekturen einreichen.         |
| **Dokumentation**     | `/apps/docs/v1/**/*.mdx`                      | Leitfäden, Referenzen und Dokumentationsseiten verbessern oder erweitern. |
| **Gateway**           | `/apps/api/*`                                 | Änderungen am API-Gateway vornehmen.                      |

Wenn du Daten bearbeitest, halte dich an die Schemas und Feldformate in der [Repositorystruktur](./repo-structure.mdx).

---

## 5. Änderungen in der Vorschau ansehen (optional)

Wenn du deine Änderungen lokal in der Vorschau ansehen möchtest:

```bash
pnpm install
pnpm dev
```

Verwende [http://localhost:3100](http://localhost:3100) für Änderungen an der Website und [http://localhost:3101](http://localhost:3101) für Änderungen an der Dokumentation. Datenänderungen lassen sich erst nach dem Erstellen einer PR in der Web-App ansehen, da diese ihre Daten aus der Datenbank bezieht.

---

## 6. Änderungen committen

Wenn du mit deinen Änderungen zufrieden bist, committe sie:

```bash
git add .
git commit -m "Updated benchmark data for Claude 3.5 Sonnet"
```

Achte auf eine aussagekräftige Commit-Nachricht, damit Reviewer deinen Beitrag nachvollziehen können.

---

## 7. Branch pushen

```bash
git push origin update-benchmark-data
```

---

## 8. Pull Request (PR) erstellen

1. Öffne deinen Fork auf GitHub.
2. GitHub bietet dir an, eine PR zu erstellen. Klicke auf **Compare & Pull Request**.
3. Fülle die PR-Vorlage mit den passenden Informationen zu deinen Änderungen aus.
4. Reiche die PR ein.

Nach Prüfung und Freigabe wird deine PR in das Phaseo-Hauptrepository übernommen.

---

## 9. Feiern

Dein Beitrag wird nach dem Merge veröffentlicht. Vielen Dank für deinen Einsatz und deine Unterstützung.

## Tipps für Beiträge

-   Halte PRs **klein und fokussiert** – eine zusammenhängende Änderung pro PR.
-   Verwende nach Möglichkeit [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/) und **eindeutige Präfixe** wie `fix:`, `add:` oder `chore:`.
-   Wenn deine Änderung die Datenrichtigkeit betrifft, füge **Quellen oder Belege** hinzu.
-   Besprich größere oder noch unklare Ideen vor dem Programmieren in einer **GitHub-Diskussion** oder auf Discord.
-   Bleib stets respektvoll und halte dich an unseren [Verhaltenskodex](../community/code-of-conduct.mdx).

---

## Beispielhafter Ablauf

```bash
# 1. Fork and clone

git clone https://github.com/yourusername/Phaseo.git
cd Phaseo

# 2. Create branch
git checkout -b add-openai-new-model

# 3. Make changes
# e.g., update packages/data/catalog/src/data/models/openai/new-model/model.json

# 4. Commit and push
git add .
git commit -m "Add new OpenAI model entry"
git push origin add-new-openai-model

# 5. Create a Pull Request on GitHub
```
