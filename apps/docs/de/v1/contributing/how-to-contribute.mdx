Verwende diesen Ablauf für Code- und Dokumentationsänderungen. Für Modell-, Anbieter-, Preis-, Organisations- oder Benchmark-Datensätze [erstelle stattdessen ein Katalog-Issue](./overview.mdx); eine lokale Einrichtung ist nicht erforderlich.

## Deinen Fork einrichten

Installiere Git, Node.js ab 22.12 und pnpm. Erstelle einen Fork des [Phaseo-Repositorys](https://github.com/phaseoteam/Phaseo), klone ihn und erstelle eine neue Branch:

```bash
git clone https://github.com/yourusername/Phaseo.git
cd Phaseo
git switch -c docs/improve-quickstart
pnpm install
```

## Die Änderung umsetzen und ansehen

Die [Repositorystruktur](./repo-structure.mdx) zeigt die passende Anwendung oder das Paket. Bei reinen Markdown-Änderungen kannst du auch den GitHub-Dateieditor verwenden und dort einen Pull Request öffnen.

```bash
# Web app at http://localhost:3100
pnpm --filter @phaseo/web dev

# Documentation at http://localhost:3101
pnpm --filter @phaseo/docs dev
```

Befolge die zutreffenden `AGENTS.md`-Anweisungen. Bewahre Geheimnisse in lokalen Umgebungsdateien auf und nimm sie nicht in Commits auf. Lokale App-Vorschauen können konfigurierte Backenddienste und eine normale Anmeldung erfordern.

## Deine Änderungen prüfen

Führe die für die geänderten Dateien passenden Prüfungen aus. Für Dokumentation:

```bash
pnpm docs:links
pnpm docs:build
```

Für Webänderungen:

```bash
pnpm --filter @phaseo/web lint
pnpm --filter @phaseo/web typecheck
pnpm --filter @phaseo/web test
```

Führe bei Rendering- oder Routingänderungen einen Produktionsbuild aus. API-, SDK- und Schemaänderungen erfordern die entsprechenden Tests und Generierungsschritte. Siehe den [Beitragsleitfaden](https://github.com/phaseoteam/Phaseo/blob/main/CONTRIBUTING.md) im Stammverzeichnis.

## Einen Pull Request öffnen

Stage nur die geänderten Dateien, verwende eine aussagekräftige Commitnachricht und pushe deine Branch:

```bash
git add apps/docs/v1/quickstart.mdx
git commit -m "docs: clarify the quickstart"
git push -u origin docs/improve-quickstart
```

Öffne einen Pull Request aus deinem Fork. Beschreibe das Problem, die Änderungen und bestandene Prüfungen. Verlinke zugehörige Issues und füge bei sichtbaren UI-Änderungen Screenshots hinzu. Bearbeite Reviewfeedback vor dem Merge; Änderungen sind nach Abschluss der entsprechenden Bereitstellung verfügbar.

Befolge den [Verhaltenskodex](../community/code-of-conduct.mdx). Besprich größere oder unklare Änderungen vor dem Schreiben von Code.
