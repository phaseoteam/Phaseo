---
title: "Authentifizierung"
description: "Verwende API-Schlüssel, um jede Anfrage an Phaseo Gateway zu authentifizieren."
icon: "key-round"
---

Erstelle einen Schlüssel im [Dashboard](https://phaseo.app/settings/keys) oder mit `POST /v1/keys` und einem Management-Schlüssel, speichere ihn auf deinem Server und sende ihn bei jeder Gateway-Anfrage als Bearer-Token. Agenten sollten die CLI verwenden; siehe [Phaseo mit einem Agenten verwalten](./manage-from-an-agent).

```http
Authorization: Bearer phaseo_v1_sk_<kid>_<secret>
```

Setze den Header einmal in deinem Client. Zum Beispiel mit `fetch`:

```ts
const response = await fetch("https://api.phaseo.app/v1/chat/completions", {
	method: "POST",
	headers: {
		Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
		"Content-Type": "application/json",
	},
	body: JSON.stringify({
		model: "openai/gpt-6-astra",
		messages: [
			{ role: "system", content: "You are a helpful assistant." },
			{ role: "user", content: "Summarize the drawbacks to AI." },
		],
	}),
});
```

<Note>
Du kannst `:free`-Modelle aufrufen, ohne Credits einzuzahlen. Kostenpflichtige Modelle brauchen ein verfügbares Guthaben in der Wallet.
</Note>

## Zugangsdaten wählen

| Zugangsdaten | Format | Verwendung |
| --- | --- | --- |
| Gateway-API-Schlüssel | `phaseo_v1_sk_<kid>_<secret>` | Modell-, Anbieter- und Generierungsendpunkte, die deinem Workspace zur Verfügung stehen. |
| [Management-API-Schlüssel](./management-api-keys.mdx) | `phaseo_v1_mk_<kid>_<secret>` | Verwaltungs-APIs. |
| [Vertrauenswürdiger Workload](./trusted-workloads.mdx) (Beta) | Ein kurzlebiges OIDC-Token der Plattform | Deployments und CI-Jobs auf Vercel, GitHub Actions, GitLab, Google Cloud, Buildkite, CircleCI, AWS oder deinem eigenen OIDC-Aussteller, ohne gespeicherten Schlüssel. |

Behandle Schlüssel wie Passwörter: Halte sie aus clientseitigem Code und öffentlichen Repositorys heraus.

## Sicher mit Schlüsseln umgehen

- **Ein Schlüssel pro App und Umgebung**, damit du einen rotieren kannst, ohne andere Dienste zu beeinträchtigen.
- **Schlüssel in einem Secrets-Manager speichern**, der sie aus Logs und Fehlertracking heraushält.
- **Die Nutzung pro Schlüssel** im Dashboard beobachten, um Auffälligkeiten zu erkennen.
- **Schlüssel löschen, die du nicht mehr verwendest.**

Um einen Schlüssel zu rotieren, stelle deine Anwendung auf den Ersatz um, bevor du den alten ungültig machst. Siehe den [Endpunkt zur Schlüsselrotation](../api-reference/endpoint/keys-rotate.mdx).

## Authentifizierungsfehler beheben

| Status | Ursache | Was zu tun ist |
| --- | --- | --- |
| `401` | Der Schlüssel fehlt, ist ungültig oder gehört zu einem deaktivierten Workspace. Das Feld `reason` im Body sagt, was zutrifft. | Header und Schlüssel prüfen. |
| `403` | Der Schlüssel ist gültig, darf aber den angeforderten Anbieter oder das Modell nicht verwenden. | Die Guardrails des Schlüssels und die Anbietereinstellungen des Workspace prüfen. |
| `429` | Der Schlüssel oder der Workspace hat ein Limit erreicht. | Siehe [Ratenlimits](../api-reference/limits.mdx). |
| `5xx` | Phaseo oder der Anbieter ist fehlgeschlagen. | Mit exponentiellem Backoff wiederholen und den [Support](https://phaseo.app/help) kontaktieren, wenn es anhält. |

Unter [Fehler und Debugging](../api-reference/errors.mdx) findest du alle Fehlercodes.
