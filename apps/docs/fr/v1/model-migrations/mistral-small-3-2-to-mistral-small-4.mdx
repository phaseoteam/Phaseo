Changez le modèle pour `mistral/mistral-small-4` et décidez, route par route, si le raisonnement est activé. Mistral Small 4 a deux modes de raisonnement, désactivé et élevé, et Phaseo fait correspondre chaque valeur d’effort à l’un d’eux.

```json
{
  "model": "mistral/mistral-small-4",
  "messages": [
    { "role": "user", "content": "Why is fast inference important?" }
  ],
  "reasoning": { "effort": "high" }
}
```

## Activer ou désactiver le raisonnement

Le raisonnement est désactivé sauf si la requête le demande. Sur l’API propre à Mistral, Phaseo envoie `reasoning_effort` comme suit :

| Requête | Envoyé à Mistral |
| --- | --- |
| Aucun paramètre de raisonnement | `reasoning_effort: "none"` |
| `reasoning.effort: "none"` ou `reasoning.enabled: false` | `reasoning_effort: "none"` |
| Toute autre valeur de `reasoning.effort`, ou `reasoning.enabled: true` | `reasoning_effort: "high"` |

Un champ à plat `reasoning_effort` dans la requête a priorité sur `reasoning.effort`. Utilisez `none` pour les routes légères et `high` pour un raisonnement approfondi ; `low` et `medium` se comportent exactement comme `high`.

## Lire la réponse et le raisonnement

Mistral peut renvoyer des blocs de contenu mixtes, par exemple `thinking` suivi de `text`. Phaseo les sépare en champs de style OpenAI, pour que le code en aval qui lit Chat Completions continue de fonctionner :

- la réponse se trouve dans `choices[0].message.content` ;
- le texte du raisonnement se trouve dans `choices[0].message.reasoning_content` et `reasoning_details`.

## Déployer

1. Changez l’identifiant de modèle de Mistral Small 3.2 pour `mistral/mistral-small-4`.
2. Testez le raisonnement uniquement avec `none` et `high`.
3. Relancez les tests de qualité des sorties et de schéma sur les routes qui utilisent `high`.
4. Comparez la latence et le coût de `none` et `high` avant la bascule complète.
