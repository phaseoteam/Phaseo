Changez le modèle pour `anthropic/claude-opus-4.6`, supprimez les préremplissages de l’assistant et déplacez les sorties structurées vers `output_config.format`. Ce sont des changements de format de requête : les anciens schémas d’Opus 4.5 échouent avec `400` s’ils restent en place.

| | Claude Opus 4.5 | Claude Opus 4.6 |
| --- | --- | --- |
| Identifiant de modèle Phaseo | `anthropic/claude-opus-4.5` | `anthropic/claude-opus-4.6` |
| Fenêtre de contexte | 200K jetons | 1M jetons |
| Sortie maximale | 64K jetons | 128K jetons |
| Préremplissage de l’assistant | Pris en charge | Renvoie `400` |
| Sorties structurées | `output_format` | `output_config.format` |
| Réflexion | `budget_tokens` | Adaptative, pilotée par `output_config.effort` |
| Bêta `interleaved-thinking-2025-05-14` | Nécessaire | Inutile |

## Mettre à jour la requête

**1. Supprimez les préremplissages de l’assistant.** Si vous pré-remplissez le tour de l’assistant pour imposer du JSON ou un préfixe, Opus 4.6 renvoie `400`. Utilisez plutôt des instructions système plus claires, des exemples dans le prompt ou les sorties structurées.

**2. Déplacez les sorties structurées** de `output_format` vers `output_config.format`, puis relancez vos tests de schéma et d’analyse :

```json
{
  "model": "anthropic/claude-opus-4.6",
  "max_tokens": 1024,
  "messages": [{ "role": "user", "content": "Extract the invoice fields." }],
  "output_config": {
    "format": { "type": "json_schema", "schema": { "type": "object", "properties": { "total": { "type": "number" } } } }
  }
}
```

Sur `/v1/chat/completions` et `/v1/responses`, continuez d’utiliser `response_format`.

**3. Passez à la réflexion adaptative.** Opus 4.6 ne réfléchit pas sauf si la requête le demande. Sur Phaseo, `reasoning.effort` ou `reasoning.enabled: true` sans budget de jetons active la réflexion adaptative, et l’effort devient `output_config.effort`. Opus 4.6 accepte tous les niveaux d’effort sauf `xhigh`, que Phaseo envoie sous la forme `max`. Lorsque la réflexion est active, Phaseo omet `temperature` et `top_k`, ainsi que `top_p` inférieur à 0.95.

**4. Supprimez les en-têtes bêta obsolètes** des wrappers de SDK, des middlewares et des préréglages. Phaseo ne transmet pas les en-têtes `anthropic-beta` ; ils n’ont donc plus aucun effet.

## Ce qu’il faut tester

- **Prompts :** longs prompts de code et de refactorisation, workflows de recherche et de documents en plusieurs étapes, prompts qui s’appuyaient sur des préremplissages, et tâches à long contexte si vous utiliserez la fenêtre de 1M.
- **Contrats et outils :** taux de conformité au schéma après le passage à `output_config.format`, arguments des appels d’outils sur les tâches d’agent en plusieurs étapes, nouvelles tentatives lorsque le modèle refuse ou reformate la sortie, et workflows de revue de code et de débogage.
- **Exploitation :** latence médiane et p95 avec la réflexion active, utilisation des jetons sur les exécutions plus longues, taux d’expiration sur les tâches à grand contexte et taux de réussite par rapport à Opus 4.5 sur votre jeu d’évaluation.

## Déployer

1. Supprimez les préremplissages et migrez les sorties structurées avant de déplacer le moindre trafic.
2. Exécutez Opus 4.6 en mode fantôme sur les prompts de production qui comptent pour vous.
3. Lancez un canary avec Opus 4.5 comme secours dans `models`.
4. Généralisez une fois que le taux de conformité au schéma, la latence et la réussite des tâches se maintiennent.
