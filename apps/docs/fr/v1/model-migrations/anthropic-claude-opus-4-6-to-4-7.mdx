Changez le modèle pour `anthropic/claude-opus-4.7`, supprimez les paramètres d’échantillonnage et les budgets de réflexion, et définissez la profondeur avec un niveau d’effort. Les requêtes qui contiennent encore des champs d’Opus 4.6 n’échouent pas sur Phaseo ; la passerelle les réécrit comme indiqué ci-dessous.

| Requête Opus 4.6 | Ce que Phaseo envoie à Opus 4.7 |
| --- | --- |
| `temperature`, `top_p`, `top_k` | Omis. Anthropic renverrait `400` pour des valeurs non par défaut. |
| `thinking: {"type": "enabled", "budget_tokens": …}` | `thinking: {"type": "adaptive", "display": "summarized"}` ; le budget n’est pas transmis. |
| `reasoning.effort` | `output_config.effort`, y compris `xhigh`. |
| `reasoning.effort: "none"` ou `reasoning.enabled: false` | `thinking: {"type": "disabled"}`. |
| Aucun paramètre de raisonnement | Aucun champ `thinking` ; Opus 4.7 ne réfléchit donc pas. |

Opus 4.7 masque aussi le contenu de la réflexion, sauf si vous l’activez explicitement ; Phaseo demande l’affichage résumé chaque fois qu’il active la réflexion. Son tokenizer peut produire plus de jetons qu’Opus 4.6 pour un même texte.

## Mettre à jour la requête

1. Définissez l’identifiant de modèle sur `anthropic/claude-opus-4.7`.
2. Supprimez `temperature`, `top_p` et `top_k`, et ajustez plutôt le comportement par des instructions.
3. Remplacez les budgets de réflexion par la réflexion adaptative et un niveau d’effort :

```json
{
  "model": "anthropic/claude-opus-4.7",
  "messages": [{ "role": "user", "content": "Refactor this module and explain the risks." }],
  "reasoning": { "effort": "xhigh" }
}
```

Commencez à `high` et utilisez `xhigh` pour les routes de code et d’agent les plus difficiles. Sur `/v1/messages`, envoyez plutôt `thinking: {"type": "adaptive"}` avec `output_config.effort`.

4. Comme le tokenizer a changé, vérifiez `max_tokens` et `max_output_tokens`, les budgets de délai d’expiration et les alertes de coût.

## Ce qu’il faut tester

- le taux de conformité au schéma sur vos prompts de production ;
- les workflows d’outils de longue durée : nombre d’appels d’outils, taux de réussite et latence ;
- la qualité à `high` par rapport à `xhigh` ;
- le coût en jetons sur vos catégories de prompts les plus volumineuses.

## Déployer

1. Déployez les changements de format de requête avant de déplacer le trafic.
2. Exécutez Opus 4.7 en mode fantôme sur votre suite d’évaluation de production.
3. Lancez un canary avec Opus 4.6 comme secours dans `models`.
4. Généralisez une fois que les changements de qualité, de latence et de coût sont dans les objectifs.
