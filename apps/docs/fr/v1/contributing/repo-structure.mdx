Phaseo est un monorepo pnpm et Turborepo. Trouvez ci-dessous le dossier de votre changement de code ou de documentation. Les enregistrements du catalogue ne sont pas dans le dépôt ; pour en modifier un, [ouvrez une issue](./overview.mdx).

## Applications

| Chemin | Rôle |
| --- | --- |
| `apps/web` | Site Next.js 16, tableau de bord et éditeur interne du catalogue. |
| `apps/web-api` | Lectures publiques du catalogue et API authentifiées de compte et d’administration. |
| `apps/api` | Routage du Gateway et exécution des fournisseurs sur Cloudflare Workers. |
| `apps/docs` | Documentation Mintlify ; pages MDX dans `v1`, navigation dans `docs.json`. |
| `apps/mcp` | Serveur MCP Phaseo pour la découverte des modèles, les tarifs et l’utilisation. |
| `apps/desktop` | Application Phaseo Desktop. |
| `apps/mobile` | Application mobile Phaseo (Expo, Android d’abord). |
| `apps/slack` | Worker derrière l’agent Slack de Phaseo. |

## Packages et outils

| Chemin | Rôle |
| --- | --- |
| `packages/sdk` | SDK TypeScript, Python, Go, C#, PHP, Ruby, Java, Rust et C++, ainsi que les Agent SDK (`agent-sdk-*`). |
| `packages/cli/phaseo` | L’outil en ligne de commande `@phaseo/cli`. |
| `packages/integrations` | Le fournisseur Vercel AI SDK et le fournisseur Terraform. |
| `packages/shared` | Code partagé entre les applications, comme l’interface, les règles de dépenses et les paramètres de routage. |
| `supabase/schemas` | Définitions déclaratives de la base de données. |
| `supabase/migrations` | Migrations SQL incrémentales qui déploient les changements de schéma et d’autorisations. |
| `scripts` | Utilitaires de validation, de génération des SDK et d’automatisation. |
| `.github/workflows` | CI, déploiement et synchronisation du catalogue. |
| `.changeset` | Métadonnées de publication des packages versionnés. |

## Données du catalogue

La base de données est la seule source des modèles, fournisseurs, organisations, tarifs, benchmarks et paramètres du catalogue. Le dépôt ne contient aucun JSON de catalogue. Les administrateurs gèrent les enregistrements dans [Données internes](https://phaseo.app/internal/data) ; les contributions publiques arrivent sous forme d’issues GitHub.

Les changements de schéma et d’application passent toujours par des migrations et des pull requests. Mettez à jour les fichiers SDK générés avec leurs commandes de génération, pas à la main.

## Automatisation du catalogue

La synchronisation des fournisseurs met les prix proposés en attente de revue dans [Mises à jour des fournisseurs](https://phaseo.app/internal/data/imports). Les tâches de benchmarks et de cycle de vie des modèles lisent et écrivent dans la base de données.

Un enregistrement du catalogue n’active pas à lui seul le routage du Gateway. Les changements de routes et de prix nécessitent une revue par un administrateur.

Pour commencer un changement, consultez [Contribuer au code ou à la documentation](./how-to-contribute.mdx).
