Pointez le client vers `https://api.phaseo.app/v1` avec une clé Phaseo, supprimez `Helicone-Auth` et remplacez chaque en-tête `Helicone-*` encore nécessaire par son équivalent Phaseo. Le changement de requête est minime ; planifiez le transfert de l’observabilité avec autant de soin.

| Paramètre | Helicone | Phaseo |
| --- | --- | --- |
| URL de base | `oai.helicone.ai/v1`, `anthropic.helicone.ai`, `ai-gateway.helicone.ai`, ou `gateway.helicone.ai` avec `Helicone-Target-URL` | `https://api.phaseo.app/v1` |
| Authentification | Clé du fournisseur plus `Helicone-Auth`, ou `HELICONE_API_KEY` sur l’AI Gateway | `PHASEO_API_KEY` seule |
| Propriétés personnalisées | `Helicone-Property-<Name>` | Étiquettes `X-Phaseo-Metadata` |
| Visibilité des requêtes | Tableau de bord Helicone | Journaux des requêtes et détails des requêtes Phaseo |

## Changer de client

<CodeGroup>
```typescript TypeScript
import OpenAI from "openai";

// Avant :
// new OpenAI({
//   apiKey: process.env.OPENAI_API_KEY,
//   baseURL: "https://oai.helicone.ai/v1",
//   defaultHeaders: {
//     "Helicone-Auth": `Bearer ${process.env.HELICONE_API_KEY}`,
//     "Helicone-Property-Team": "support",
//   },
// });
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
  defaultHeaders: {
    "X-Phaseo-Metadata": JSON.stringify({ labels: [{ key: "team", value: "support" }] }),
  },
});

const response = await client.chat.completions.create(
  {
    model: "openai/gpt-6-astra",
    messages: [{ role: "user", content: "Reply with: migration ready" }],
  },
  { headers: { "X-Phaseo-User-Id": "user_123" } },
);
```

```python Python
import json
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
    default_headers={
        "X-Phaseo-Metadata": json.dumps({"labels": [{"key": "team", "value": "support"}]}),
    },
)
```

```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role": "user", "content": "Reply with: migration ready"}]
  }'
```
</CodeGroup>

Les valeurs propres à chaque requête, comme les identifiants d’utilisateur, se placent sur la requête, pas sur le client. Les routes `anthropic.helicone.ai` passent à la configuration décrite dans [Migrer depuis le SDK Anthropic](./from-anthropic).

Sur l’AI Gateway de Helicone, le routage se trouve dans la chaîne `model`. Découpez-la : la première entrée séparée par une virgule devient `model` et les autres forment le tableau `models` ; un épinglage `<model>/<provider>` devient `provider.only` ou un identifiant `provider:org/model` ; une exclusion `!provider` devient `provider.ignore`.

## Faire correspondre les en-têtes Helicone

| Helicone | Sur Phaseo |
| --- | --- |
| `Helicone-Auth` | Supprimez-le. |
| `Helicone-Property-<Name>` | [Étiquettes](../guides/request-labels) `X-Phaseo-Metadata` : jusqu’à 32, les clés respectent `[A-Za-z0-9_.:-]` (64 caractères), donc renommez les propriétés qui contiennent des espaces. Un JSON mal formé ou des clés en double renvoient `400`. Ne mettez pas de données personnelles dans les étiquettes. |
| `Helicone-User-Id` | Champ de corps `user` ou `X-Phaseo-User-Id`. Il sert aussi de clé aux règles de limite de débit par utilisateur final. |
| `Helicone-Session-Id` | Champ de corps `session_id`. Il pilote l’affinité de cache et de fournisseur, pas une arborescence de traces. |
| `Helicone-Session-Path`, `Helicone-Session-Name` | Champs de corps `metadata.trace_id`, `parent_span_id`, `trace_name`, `span_name`, ou un en-tête W3C `traceparent`. Ils structurent les spans envoyés aux destinations d’observabilité ; les journaux propres à Phaseo n’ont pas d’arborescence de traces. |
| `Helicone-Cache-Enabled` | Pas de cache de réponses. Mettez en cache dans l’application si nécessaire. |
| `Helicone-Fallbacks`, `Helicone-Retry-Enabled` | Tableau `models`, essayé sur `429`, `500`, `502`, `503` et `504`, plus le secours intégré entre fournisseurs. Gardez la temporisation progressive côté client. |
| `Helicone-RateLimit-Policy` | Règles de limite de débit et limites de clé. Consultez [Limites](../api-reference/limits). |
| `Helicone-LLM-Security-Enabled` | Détection de l’injection de prompt par les garde-fous, sur les requêtes uniquement. |
| `Helicone-Moderations-Enabled` | Pas d’équivalent dans la passerelle. Appelez `/v1/moderations` depuis l’application. |
| `Helicone-Omit-Request`, `Helicone-Omit-Response` | Règle de journalisation de l’espace de travail ou conservation zéro des données. |
| `Helicone-Posthog-*` | [Destination d’observabilité](../guides/integrations/observability) PostHog. |
| Gestion des prompts | [Modèles de prompt des préréglages](../guides/prompt-templates) : `"prompt": {"id": "@slug", "version": "production", "variables": {...}}`. |

## Transférer la visibilité des requêtes

Utilisez les journaux des requêtes, les identifiants de requête, les tentatives de fournisseur et les détails de tarification pour le débogage. Si l’équipe exporte de la télémétrie, connectez la [destination d’observabilité](../guides/integrations/observability) correspondante avant la bascule pour éviter toute interruption. La journalisation asynchrone de Helicone, qui ne fait pas transiter le trafic, est une décision distincte du changement de passerelle.

## Tester et déployer

Vérifiez que les requêtes réussissent sans les en-têtes Helicone et que l’équipe peut toujours répondre aux questions qu’elle se pose pendant les incidents. Avant de déplacer le trafic, vérifiez que :

- chaque URL Helicone et chaque en-tête `Helicone-*` est supprimé ou mis en correspondance ;
- les identifiants de modèle de production figurent dans `GET /v1/models?format=openai` ;
- les alertes et les tableaux de bord ont un remplaçant là où l’équipe en a besoin ;
- le retour arrière se limite toujours à un changement d’URL de base et de clé.
