Changez l’URL de base et la clé, conservez les charges utiles des requêtes et faites correspondre chaque identifiant de modèle : le préfixe de LLM Gateway désigne le fournisseur qui sert le modèle, tandis que celui de Phaseo désigne le créateur du modèle.

| Paramètre | LLM Gateway | Phaseo |
| --- | --- | --- |
| URL de base | `https://api.llmgateway.io/v1` | `https://api.phaseo.app/v1` |
| Clients de style Anthropic | `ANTHROPIC_BASE_URL=https://api.llmgateway.io` | `https://api.phaseo.app`, voir [Migrer depuis le SDK Anthropic](./from-anthropic) |
| Clé API | `LLM_GATEWAY_API_KEY` (`llmgtwy_…`) | `PHASEO_API_KEY` |
| Identifiants de modèle | `gpt-4o`, `<provider>/<model>`, `auto` | `<org>/<model>` depuis `GET /v1/models?format=openai` |
| Charge utile de la requête | Compatible OpenAI | Inchangée |

## Changer de client

<CodeGroup>
```typescript TypeScript
import OpenAI from "openai";

// Avant :
// new OpenAI({ apiKey: process.env.LLM_GATEWAY_API_KEY, baseURL: "https://api.llmgateway.io/v1" });
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});
```

```python Python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
)
```

```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```
</CodeGroup>

Faites correspondre ou supprimez chaque variable `LLM_GATEWAY_*`, y compris dans la CI et les paramètres d’hébergement. Si l’application utilise `@llmgateway/ai-sdk-provider`, passez à `@phaseo/ai-sdk-provider` comme dans [Migrer depuis Vercel AI Gateway](./from-vercel).

## Faire correspondre les identifiants de modèle

Listez les identifiants Phaseo et vérifiez chaque modèle de production par rapport à cette liste :

```bash
curl -s "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY" | jq -r '.data[].id'
```

`alibaba/<model>` sur LLM Gateway n’est pas un identifiant Phaseo. Faites correspondre chaque identifiant au format `<org>/<model>` de Phaseo, et conservez un épinglage de fournisseur avec `provider.only` ou un identifiant `provider:org/model`. Traduisez les alias sans préfixe comme `gpt-4o` dans une seule fonction à la frontière du client plutôt qu’à chaque point d’appel.

## Faire correspondre les fonctionnalités de la passerelle

| LLM Gateway | Sur Phaseo |
| --- | --- |
| Routeur `auto` | `phaseo/auto` ([Routage automatique](../guides/auto-routing), alpha) ; ne peut pas être combiné avec `models`. |
| Chaînes de secours | Tableau `models` ou routes dynamiques, essayés sur `429`, `500`, `502`, `503` et `504`, jamais sur les erreurs de requête. |
| `X-No-Fallback` | `provider.allow_fallbacks: false`, ou un identifiant `provider:org/model`. |
| Logique d’autorisation et de refus des fournisseurs | `provider.only`, `provider.ignore` ou [Préréglages](../guides/presets). Gardez au moins un fournisseur éligible. |
| En-têtes `X-LLMGateway-<Key>` | [Étiquettes](../guides/request-labels) `X-Phaseo-Metadata`, jusqu’à 32. |
| En-têtes de session (`x-session-id`) | Champ de corps `session_id` ; Phaseo ignore les en-têtes de session. |
| `X-Source` | `HTTP-Referer` ou `X-App-Name`. Consultez [Attribution des applications](../guides/app-attribution). |
| Mise en cache des réponses | Pas de cache de réponses. |
| Clés de fournisseur | BYOK (`phaseo byok create` ou `POST /v1/byok`), ou crédits Phaseo. Le basculement sur les crédits correspond au paramètre d’espace de travail `byok_fallback_enabled`. |
| Journaux des requêtes | Journaux des requêtes, destinations d’observabilité et `GET /v1/generations?id=<request_id>`. Lorsque `replay_supported` vaut `true`, relancez une requête en échec à partir de sa charge utile `replay_request`. |

## Tester et déployer

Exécutez vos prompts de référence sur les deux passerelles et comparez la qualité, la latence et le coût. Vérifiez d’abord les endpoints :

```bash
curl -s "https://api.phaseo.app/v1/health"
curl -s "https://api.phaseo.app/v1/models?format=openai" -H "Authorization: Bearer $PHASEO_API_KEY"
```

Avant de déplacer le trafic, vérifiez que :

- `PHASEO_API_KEY` est défini dans chaque environnement ;
- chaque identifiant de modèle de production est mis en correspondance et listé ;
- une requête sans streaming et une requête en streaming passent en préproduction ;
- les erreurs de clé invalide et de modèle invalide sont gérées ; leurs corps peuvent différer de ceux de LLM Gateway ;
- une requête de préproduction en échec peut être récupérée depuis `GET /v1/generations` ;
- les valeurs par défaut partagées de prompt et de routage se trouvent dans des préréglages, là où elles ont leur place.

Publiez derrière un drapeau canary, passez d’une petite part du trafic à la totalité une fois la situation stable, et surveillez les métriques de production pendant au moins un cycle de publication avant de supprimer l’ancienne configuration.
