Conservez le SDK Anthropic et l’appel Messages. Pointez le client vers `https://api.phaseo.app`, passez votre clé Phaseo comme `authToken` et donnez à chaque modèle son identifiant Phaseo.

| Paramètre | Anthropic | Phaseo |
| --- | --- | --- |
| URL de base | Valeur par défaut du SDK (`https://api.anthropic.com`) | `https://api.phaseo.app` (le SDK ajoute `/v1/messages`) |
| Clé API | `ANTHROPIC_API_KEY`, envoyée comme `x-api-key` | `PHASEO_API_KEY` comme `authToken` / `auth_token`, envoyée comme `Authorization: Bearer` |
| Modèle | `claude-sonnet-5-5` | `anthropic/claude-sonnet-5.5`, ou tout identifiant de `GET /v1/models` |
| Appel Messages | `messages.create` | Inchangé |

## Changer de client

Créez une clé dans [Clés API](https://phaseo.app/settings/keys), puis rendez-la disponible pour l’application sous le nom `PHASEO_API_KEY`.

<CodeGroup>
```typescript TypeScript
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic({
  apiKey: null,
  authToken: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app",
});

const response = await client.messages.create({
  model: "anthropic/claude-sonnet-5.5",
  max_tokens: 256,
  messages: [{ role: "user", content: "Reply with: migration ready" }],
});
```

```python Python
import os
import anthropic

client = anthropic.Anthropic(
    auth_token=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app",
)

response = client.messages.create(
    model="anthropic/claude-sonnet-5.5",
    max_tokens=256,
    messages=[{"role": "user", "content": "Reply with: migration ready"}],
)
```

```bash cURL
curl https://api.phaseo.app/v1/messages \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-sonnet-5.5",
    "max_tokens": 256,
    "messages": [{"role": "user", "content": "Reply with: migration ready"}]
  }'
```
</CodeGroup>

Trois détails font le plus souvent échouer cette étape :

- **Utilisez l’hôte racine.** `baseURL: "https://api.phaseo.app/v1"` produit `/v1/v1/messages`. Les clients compatibles OpenAI du même dépôt continuent d’utiliser `/v1`.
- **Envoyez la clé comme jeton bearer.** La passerelle lit uniquement `Authorization: Bearer` ; un en-tête `x-api-key` reçoit `401` `missing_or_invalid_authorization_header`. `authToken` envoie Bearer avec toutes les versions du SDK. `apiKey` ne le fait qu’à partir de `@anthropic-ai/sdk` 1.0 et `anthropic` 2.0.
- **Supprimez `ANTHROPIC_API_KEY`** des environnements qui appellent désormais Phaseo. `apiKey: null` empêche les anciens SDK TypeScript de la lire, et les SDK Python antérieurs à 0.98 la lisent même lorsque `auth_token` est défini.

Les outils configurés par variables d’environnement, comme Claude Code, utilisent `ANTHROPIC_BASE_URL=https://api.phaseo.app`, `ANTHROPIC_AUTH_TOKEN` défini sur la clé Phaseo et un `ANTHROPIC_API_KEY` vide.

## Faire correspondre les identifiants de modèle

Vérifiez chaque modèle de production dans `data[].id` de `GET /v1/models?format=openai`. Les identifiants Phaseo utilisent des points dans la version : `claude-sonnet-5-5` devient `anthropic/claude-sonnet-5.5`. Si le modèle change aussi, lisez le [guide de migration de modèle](../model-migrations) correspondant.

## Ce qui fonctionne différemment

| Fonctionnalité Anthropic | Sur Phaseo |
| --- | --- |
| En-tête `anthropic-version` | Toute valeur est acceptée ; Phaseo appelle Claude avec sa propre version. |
| En-têtes `anthropic-beta` | Non transmis. Phaseo ajoute les bêtas dont ses fonctionnalités prises en charge ont besoin ; les champs de corps réservés aux bêtas, comme `mcp_servers`, renvoient `400`. |
| `temperature`, `top_p`, `top_k` | Supprimés lorsque le modèle ou la route ne les accepte pas, et listés dans `X-Phaseo-Dropped-Params`. |
| `speed: "fast"` | Renvoie `400`. Utilisez `service_tier: "fast"`. |
| Outils natifs de recherche Web et de récupération Web | Acceptés lorsque le fournisseur les exécute ; sinon, utilisez l’outil serveur `phaseo:web_search` de Phaseo. |
| `cache_control` | Pris en charge au niveau supérieur ou par bloc. Consultez [Mise en cache des prompts](../guides/prompt-caching). |
| `metadata.user_id` | Pas utilisé comme identifiant d’utilisateur final. Envoyez `user` ou l’en-tête `X-Phaseo-User-Id` pour les règles de limite de débit par utilisateur final. |
| Message Batches (`/v1/messages/batches`) | Ce chemin n’existe pas. `/v1/batches` accepte des lignes `/v1/messages` dans un format différent. |
| Comptage des jetons (`/v1/messages/count_tokens`) | Pas d’équivalent. Gardez-le sur Anthropic ou faites une estimation côté client. |
| Files API (`client.beta.files`) | Pas d’équivalent. Envoyez les documents en ligne. |
| Clients `AnthropicBedrock`, `AnthropicVertex` | Remplacez-les par le client `Anthropic` standard ; l’authentification cloud et les paramètres de région ne s’appliquent pas. |

## Tester et déployer

Testez les prompts système, le streaming, l’utilisation d’outils, le raisonnement et les sorties structurées avec les identifiants de modèle exacts utilisés par l’application. Comparez ensuite un ensemble de prompts représentatifs entre les deux configurations : format de sortie, latence, utilisation des jetons, erreurs et coût. Avant de déplacer le trafic, vérifiez que :

- la clé Phaseo est définie dans chaque environnement de déploiement ;
- chaque identifiant de modèle de production figure dans `GET /v1/models?format=openai` ;
- les flux de streaming et d’utilisation d’outils passent en préproduction ;
- chaque en-tête `anthropic-beta` et chaque champ réservé aux bêtas a été supprimé ou remplacé ;
- le retour arrière se limite toujours à un changement d’URL de base et de clé.
