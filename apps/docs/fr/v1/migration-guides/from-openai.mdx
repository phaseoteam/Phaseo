Conservez le SDK OpenAI et changez deux choses : l’URL de base et la clé API. Donnez ensuite à chaque modèle son identifiant Phaseo, qui ajoute le préfixe `openai/`.

| Paramètre | OpenAI | Phaseo |
| --- | --- | --- |
| URL de base | Valeur par défaut du SDK (`https://api.openai.com/v1`) | `https://api.phaseo.app/v1` |
| Clé API | `OPENAI_API_KEY` | `PHASEO_API_KEY`, envoyée comme `Authorization: Bearer` |
| Modèle | `gpt-4.1-mini` | `openai/gpt-4.1-mini`, ou tout identifiant de `GET /v1/models` |
| Code des requêtes | `chat.completions.create`, `responses.create` | Inchangé |

## Changer de client

Créez une clé dans [Clés API](https://phaseo.app/settings/keys), et ajoutez-la à chaque environnement qui exécute l’application. Passez-la ensuite, avec l’URL de base, au client existant :

<CodeGroup>
```typescript TypeScript
import OpenAI from "openai";

// Avant : const client = new OpenAI();
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Reply with: migration ready" }],
});
```

```python Python
import os
from openai import OpenAI

# Avant : client = OpenAI()
client = OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
)

response = client.chat.completions.create(
    model="openai/gpt-4.1-mini",
    messages=[{"role": "user", "content": "Reply with: migration ready"}],
)
```

```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-4.1-mini",
    "messages": [{"role": "user", "content": "Reply with: migration ready"}]
  }'
```
</CodeGroup>

Utilisez un nouveau nom de variable plutôt que de placer la clé Phaseo dans `OPENAI_API_KEY`, et supprimez les valeurs `OPENAI_BASE_URL` obsolètes pour qu’aucun autre client du dépôt ne continue d’appeler OpenAI. Les clients `AzureOpenAI` passent au client `OpenAI` standard ; les noms de déploiement Azure correspondent aux identifiants de modèle Phaseo de la même manière.

## Faire correspondre les identifiants de modèle

Listez les identifiants servis par Phaseo au format de liste d’OpenAI et vérifiez chaque modèle de production dans `data[].id` :

```bash
curl "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

Sans `format=openai`, la réponse est la liste paginée `models` de Phaseo et ne contient pas de tableau `data`. Il en va de même pour `client.models.list()` : passez `{ query: { format: "openai" } }` en Node ou `extra_query={"format": "openai"}` en Python. La liste par défaut ne contient que les modèles que vous pouvez appeler maintenant ; ajoutez `availability=all` pour inclure les modèles inactifs et à venir.

## Ce qui fonctionne différemment

| Fonctionnalité OpenAI | Sur Phaseo |
| --- | --- |
| Chat Completions, Responses | Mêmes formats de requête sur `/v1/chat/completions` et `/v1/responses`. Un champ de premier niveau inconnu renvoie `400` `unknown_param`. |
| `previous_response_id`, `conversation` | Renvoient `400` : Phaseo ne stocke pas les réponses. Envoyez l’historique complet dans `input` à chaque requête. |
| Embeddings, modérations, images, synthèse vocale, transcription | `/v1/embeddings`, `/v1/moderations`, `/v1/images/*`, `/v1/audio/*`. Vérifiez que le modèle prend en charge l’opération. |
| Batch API | `/v1/files` et `/v1/batches`. `/v1/files` ne contient que les entrées de batch ; il ne peut pas fournir d’entrées `file_id` à d’autres requêtes. |
| Realtime | `POST /v1/audio/realtime/sessions`, puis un WebSocket vers l’`connect.url` renvoyée. Consultez [Voix en temps réel](../guides/realtime-voice). |
| Prompts stockés (`prompt: { id: "pmpt_…" }`) | Recréez le prompt sous forme de préréglage et appelez-le avec `prompt: { id: "@slug", version, variables }`. Consultez [Modèles de prompt](../guides/prompt-templates). |
| `organization`, `project`, en-tête `OpenAI-Organization` | Pas d’équivalent. Supprimez-les ; utilisez les espaces de travail et les clés Phaseo. |
| Assistants, Threads, vector stores, fine-tuning, ancien `/v1/completions` | Pas d’endpoint Phaseo. Gardez-les sur OpenAI ou portez-les vers `/v1/responses`. |

## Tester et déployer

Exécutez les mêmes prompts représentatifs avec l’ancienne et la nouvelle configuration, et comparez le format de sortie, la latence, l’utilisation des jetons, les erreurs et le coût. Avant de déplacer le trafic, vérifiez que :

- la clé Phaseo est définie en développement, en préproduction et en production ;
- chaque identifiant de modèle de production apparaît dans `GET /v1/models?format=openai` ;
- une requête sans streaming et une requête en streaming passent en préproduction, ainsi que les appels d’outils et les sorties structurées si l’application les utilise ;
- le retour arrière se limite toujours à un changement d’URL de base et de clé.

Déplacez ensuite le trafic progressivement. [Routage et secours](../guides/routing-and-fallbacks) traite des modèles de secours, et [Gestion des erreurs](../api-reference/errors.mdx) liste les corps d’erreur que votre application peut désormais recevoir.
