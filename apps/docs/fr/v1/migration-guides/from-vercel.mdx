---

Dans le code AI SDK, remplacez `@ai-sdk/gateway` par `@phaseo/ai-sdk-provider` et enveloppez chaque identifiant de modèle dans `phaseo(...)`. Dans les clients compatibles OpenAI, changez l’URL de base et la clé. Votre logique de génération reste la même.

| Paramètre | Vercel AI Gateway | Phaseo |
| --- | --- | --- |
| URL de base | `https://ai-gateway.vercel.sh/v1` | `https://api.phaseo.app/v1` |
| Clé API | `AI_GATEWAY_API_KEY` ou OIDC Vercel | `PHASEO_API_KEY`, comme secret côté serveur |
| Fournisseur AI SDK | `@ai-sdk/gateway`, ou modèles sous forme de simple chaîne | `@phaseo/ai-sdk-provider` |
| Options de routage | `providerOptions.gateway` | `providerOptions.phaseo` |

## Changer de fournisseur

<CodeGroup>
```typescript AI SDK
import { generateText } from "ai";
// Avant : import { gateway } from "@ai-sdk/gateway";
import { phaseo } from "@phaseo/ai-sdk-provider";

const { text } = await generateText({
  // Avant : model: gateway("openai/gpt-4.1-mini"),
  model: phaseo("openai/gpt-4.1-mini"),
  prompt: "Generate a migration checklist.",
});
```

```typescript OpenAI SDK
import OpenAI from "openai";

// Avant :
// new OpenAI({ apiKey: process.env.AI_GATEWAY_API_KEY, baseURL: "https://ai-gateway.vercel.sh/v1" });
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});
```

```bash cURL
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role":"user","content":"Hello"}]
  }'
```
</CodeGroup>

L’export `phaseo` par défaut lit `PHASEO_API_KEY` une seule fois, à l’importation du module, et utilise `https://api.phaseo.app/v1`. Si la variable est définie après les importations, comme dans certaines configurations serverless et de test, chaque appel lève une erreur de clé manquante ; appelez plutôt `createPhaseo({ apiKey, baseURL, headers })` dans le gestionnaire.

Installez la ligne du fournisseur qui correspond à votre version majeure de `ai` : `@phaseo/ai-sdk-provider` pour AI SDK 7, `@phaseo/ai-sdk-provider@ai-sdk-v6` pour AI SDK 6 et `@phaseo/ai-sdk-provider@ai-sdk-v5` pour AI SDK 5.

Par défaut, l’AI SDK envoie les modèles sous forme de simple chaîne (`model: "openai/gpt-4.1-mini"`) via la passerelle de Vercel ; une chaîne simple oubliée continue donc de l’appeler. Modifiez une fois la fabrique de modèles partagée, puis recherchez `model: "` dans les appels AI SDK. Les clients du SDK Anthropic pointés vers `ai-gateway.vercel.sh` passent à la configuration décrite dans [Migrer depuis le SDK Anthropic](./from-anthropic).

## Faire correspondre les options de la passerelle

`providerOptions.phaseo` est fusionné dans le corps de la requête. Un `providerOptions.gateway` oublié est ignoré sans erreur.

| Vercel AI Gateway | Sur Phaseo |
| --- | --- |
| `providerOptions.gateway.order`, `.only` | `providerOptions: { phaseo: { provider: { order, only } } }`, ou un [préréglage](../guides/presets) appelé avec `phaseo("@slug")`. |
| `providerOptions.gateway.models` | `providerOptions: { phaseo: { models: [...] } }`, ou des secours dans une route dynamique. |
| `providerOptions.gateway.sort` (`cost`, `ttft`, `tps`) | `provider.sort` (`price`, `latency`, `throughput`). |
| `providerOptions.gateway.zeroDataRetention` | `provider.require_zero_data_retention`, qui limite le routage aux fournisseurs ZDR. |
| `providerOptions.gateway.user`, `.tags` | `user` et [étiquettes](../guides/request-labels) `X-Phaseo-Metadata`. |
| Identifiants `byok` limités à une requête | Pas d’équivalent. Ajoutez les clés de fournisseur à l’espace de travail avec **Paramètres → BYOK**. |
| Texte, streaming, outils, sorties structurées, embeddings, images, transcription, synthèse vocale | Pris en charge par le fournisseur ; les capacités dépendent toujours du modèle. |
| Reranking | `phaseo.rerankingModel(id)` sur les lignes AI SDK 6 et 7. |
| Références de fichiers gérés, outils exécutés par le fournisseur | Non pris en charge. Les parties non prises en charge échouent avec une erreur au lieu d’être ignorées. |
| Tableau de bord d’utilisation de la passerelle | Journaux des requêtes Phaseo et `GET /v1/generations?id=<request_id>`. Les métadonnées de fournisseur des résultats incluent l’identifiant de requête. |

## Tester et déployer

Exécutez le même ensemble de prompts par les deux chemins et comparez la latence, le format de sortie et l’utilisation des jetons. Avant de promouvoir le trafic, vérifiez que :

- `PHASEO_API_KEY` est défini dans chaque environnement d’exécution qui avait la clé de la passerelle, y compris les déploiements edge, serveur et de prévisualisation ;
- le chemin principal de génération de texte et un test en streaming passent sans modification en préproduction ;
- les appels d’outils et les sorties structurées passent si l’application les utilise ;
- la correspondance des erreurs au niveau de l’application fonctionne toujours ;
- une requête de préproduction en échec peut être retrouvée et, lorsque `replay_supported` vaut `true`, relancée depuis `GET /v1/generations?id=<request_id>`.

Publiez derrière un feature flag ou un déploiement par pourcentage, en commençant par le trafic interne. Surveillez la latence, le taux d’erreur et la dérive des jetons et des coûts, et gardez l’ancien fournisseur disponible pendant au moins une publication pour que le retour arrière ne nécessite aucun changement de code.

```bash
curl -s "https://api.phaseo.app/v1/health"
curl -s "https://api.phaseo.app/v1/models?format=openai" -H "Authorization: Bearer $PHASEO_API_KEY"
```

Pour en savoir plus sur le fournisseur, consultez [AI SDK](../guides/integrations/ai-sdk).
