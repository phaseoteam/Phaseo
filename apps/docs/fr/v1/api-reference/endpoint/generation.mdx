Appelez `GET /v1/generations?id=<request_id>` pour récupérer l’enregistrement d’audit stocké d’une requête de votre espace de travail. Il faut le scope `generations:read` ; un `id` manquant renvoie `400` `missing_id`.

Les nouvelles requêtes reçoivent un ID de génération `G-` créé par le serveur, renvoyé dans l’en-tête de réponse `x-request-id` et dans la réponse de génération. Utilisez cet ID pour les journaux de requêtes, la recherche de générations et le support. Un `x-request-id` fourni par l’appelant ne remplace pas l’ID de génération. Les anciens ID de journal au format UUID restent valides pour la recherche.

## Rejouer une requête

Chaque réponse contient `replay_supported`. Lorsque la journalisation des entrées/sorties a stocké le corps de la requête et que vous avez le droit de lire les contenus stockés, `replay_supported` vaut `true` et `replay_request` contient le corps à renvoyer pour une nouvelle exécution contrôlée :

<Steps>
  <Step title="Lire la génération">
    Appelez `GET /v1/generations?id=<request_id>`.
  </Step>
  <Step title="Vérifier qu’elle peut être rejouée">
    Ne continuez que si `replay_supported` vaut `true`.
  </Step>
  <Step title="La renvoyer">
    Envoyez `replay_request` à l’endpoint indiqué dans `endpoint`, par exemple `/v1/chat/completions` ou `/v1/responses`.
  </Step>
</Steps>

Un espace de travail peut réserver les contenus stockés aux propriétaires et aux administrateurs. Les autres appelants, y compris les clés API créées par des membres, reçoivent alors `replay_request: null` et les détails de la requête sans leur contenu.
