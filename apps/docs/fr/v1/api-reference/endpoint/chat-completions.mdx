## Utiliser les outils serveur

Ajoutez un outil `phaseo:` dans `tools` à côté de vos propres outils de fonction : Phaseo l’exécute lorsque le modèle l’appelle. `/v1/chat/completions` accepte tous les outils serveur sauf `phaseo:apply_patch` ; le guide [Outils serveur](../../guides/server-tools) les liste.

```bash
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [
      { "role": "user", "content": "What is the current datetime in Europe/London?" }
    ],
    "tools": [
      { "type": "phaseo:datetime", "parameters": { "timezones": ["Europe/London"] } }
    ],
    "tool_choice": "auto"
  }'
```

Chaque appel d’outil serveur est compté dans `usage.server_tool_use` :

```json
{
  "usage": {
    "prompt_tokens": 12,
    "completion_tokens": 34,
    "total_tokens": 46,
    "server_tool_use": {
      "datetime_requests": 1
    }
  }
}
```

`phaseo:web_search` ajoute `web_search_requests`, `web_search_results` et `web_search_extra_results` ; `phaseo:web_fetch` ajoute `web_fetch_requests`. L’ancien type `gateway:datetime` fonctionne toujours.

Avec `stream: true`, Phaseo exécute lui-même les tours d’outils, puis vous transmet la suite de la réponse en un seul flux.

## Raisonnement dans les boucles d’outils

Les modèles de raisonnement renvoient leur raisonnement dans deux champs du message de l’assistant :

- `reasoning_content` : le texte du raisonnement, lorsque le fournisseur en renvoie un.
- `reasoning_details` : un tableau de blocs de raisonnement. Chaque entrée possède un `type` (`reasoning.text`, `reasoning.summary` ou `reasoning.encrypted`), un `index` et un `format` qui indique la famille du fournisseur, par exemple `anthropic-claude-v1` ou `google-gemini-v1`.

Les entrées peuvent contenir un état du fournisseur dont le modèle a besoin à l’étape suivante d’une boucle d’outils :

| État du fournisseur | Emplacement |
| --- | --- |
| Signatures de thinking de Claude | `signature` sur les entrées `reasoning.text` |
| Thinking masqué de Claude, raisonnement chiffré d’OpenAI | `data` sur les entrées `reasoning.encrypted` |
| Signatures de pensée de Gemini | `data` sur les entrées `reasoning.encrypted` dont l’`id` est l’appel d’outil auquel elles appartiennent |

En streaming, un delta `reasoning_details` arrive dès qu’un bloc de raisonnement est terminé.

Pour que le modèle conserve son raisonnement entre les étapes, renvoyez le message de l’assistant avec son `reasoning_details` inchangé. Les valeurs de `signature` et de `data` sont opaques et enregistrent le fournisseur et le modèle qui les ont produites. Phaseo ne les envoie qu’à cette famille de fournisseurs et à ce modèle : un fallback vers un autre fournisseur les abandonne au lieu d’échouer. Les modèles Claude en mode de thinking manuel doivent récupérer leur thinking pour continuer à réfléchir pendant une boucle d’outils ; s’il manque, cette étape s’exécute sans thinking.
