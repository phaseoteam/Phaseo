## Outils serveur

`/v1/chat/completions` prend en charge les outils de fonction classiques ainsi que les outils serveur gérés par le Gateway suivants :

- `gateway:datetime`
- `phaseo:web_search`
- `phaseo:web_fetch`
- `phaseo:advisor`
- `phaseo:image_generation`

### Exemple de date et heure

```bash
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5-nano",
    "stream": false,
    "messages": [
      { "role": "user", "content": "What is the current datetime in Europe/London?" }
    ],
    "tools": [
      {
        "type": "gateway:datetime",
        "parameters": { "timezone": "Europe/London" }
      }
    ],
    "tool_choice": "auto"
  }'
```

Lorsqu’un outil serveur est utilisé, les données d’utilisation comprennent :

```json
{
  "usage": {
    "prompt_tokens": 12,
    "completion_tokens": 34,
    "total_tokens": 46,
    "server_tool_use": {
      "datetime_requests": 1
    }
  }
}
```

`phaseo:web_search` ajoute `server_tool_use.web_search_requests`, `server_tool_use.web_search_results` et `server_tool_use.web_search_extra_results`. `phaseo:web_fetch` ajoute `server_tool_use.web_fetch_requests`.

## À propos du streaming

`stream: true` est également pris en charge. Avec les outils serveur gérés par le Gateway, Phaseo peut matérialiser le tour d’appel d’outil amont, poursuivre la boucle, puis réémettre un flux synthétique.

## Raisonnement dans les boucles d’outils

Les modèles de raisonnement renvoient leur raisonnement dans deux champs du message de l’assistant :

- `reasoning_content` : le texte du raisonnement, lorsque le fournisseur en renvoie un.
- `reasoning_details` : un tableau de blocs de raisonnement au format utilisé par OpenRouter. Chaque entrée possède un `type` (`reasoning.text`, `reasoning.summary` ou `reasoning.encrypted`), un `index` et un `format` qui indique la famille du fournisseur, par exemple `anthropic-claude-v1` ou `google-gemini-v1`.

Les entrées peuvent contenir un état du fournisseur dont le modèle a besoin à l’étape suivante d’une boucle d’outils :

- Les signatures de thinking de Claude, dans `signature` sur les entrées `reasoning.text`.
- Le thinking masqué de Claude et le raisonnement chiffré d’OpenAI, dans `data` sur les entrées `reasoning.encrypted`.
- Les signatures de pensée de Gemini, dans `data` sur les entrées `reasoning.encrypted` dont l’`id` est l’appel d’outil auquel elles appartiennent.

En streaming, un delta `reasoning_details` arrive dès qu’un bloc de raisonnement est terminé.

Pour que le modèle conserve son raisonnement entre les étapes, renvoyez le message de l’assistant avec son `reasoning_details` inchangé. Les valeurs de `signature` et de `data` sont opaques et enregistrent le fournisseur et le modèle qui les ont produites. Phaseo ne les envoie qu’à cette famille de fournisseurs et à ce modèle : un fallback vers un autre fournisseur les abandonne au lieu d’échouer. Les modèles Claude en mode de thinking manuel doivent récupérer leur thinking pour continuer à réfléchir pendant une boucle d’outils ; s’il manque, cette étape s’exécute sans thinking.
