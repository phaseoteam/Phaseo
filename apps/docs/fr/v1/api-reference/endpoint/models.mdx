Appelez `GET /v1/models` pour lister les modèles vers lesquels vous pouvez router dès maintenant. Définissez `availability=all` pour inclure les modèles connus mais pas disponibles actuellement.

```bash
curl "https://api.phaseo.app/v1/models?limit=50" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

Chaque modèle liste une entrée dans `offers` par route de fournisseur (extrait, valeurs données à titre indicatif) :

```json
{
  "ok": true,
  "availability_mode": "active",
  "limit": 50,
  "offset": 0,
  "total": 412,
  "models": [
    {
      "id": "anthropic/claude-sonnet-5.5",
      "name": "Claude Sonnet 5.5",
      "organization": { "id": "anthropic", "name": "Anthropic", "color": "#d97757" },
      "lifecycle": { "status": "active", "released_at": "2026-09-28", "replacement_id": null },
      "modalities": { "input": ["text", "image"], "output": ["text"] },
      "capabilities": { "endpoints": ["chat.completions", "messages", "responses"] },
      "availability": { "status": "active", "provider_count": 3, "active_provider_count": 3 },
      "offers": [
        {
          "provider": { "id": "anthropic", "name": "Anthropic" },
          "model": "claude-sonnet-5-5",
          "status": "active",
          "status_reason": null,
          "routable": true,
          "service_tiers": ["standard"],
          "routing": { "provider": "active", "model": "active", "capability": "active" }
        }
      ]
    }
  ]
}
```

N’envoyez du trafic de production que vers une offre dont `routable` vaut `true`. `status_reason` indique pourquoi une offre est en aperçu uniquement ou inactive. Le schéma complet figure ci-dessous.

`GET /models/me` est réservé à un futur filtrage des modèles tenant compte des garde-fous de l’appelant actuel. Il renvoie aujourd’hui `501 not implemented` : utilisez donc `GET /models`.

## Filtrer la liste

Les filtres qui acceptent plusieurs valeurs prennent des paramètres répétés ou une liste séparée par des virgules.

| Paramètre | Filtre par |
| --- | --- |
| `availability` | `active` (par défaut) pour les modèles routables publiquement, ou `all` pour ajouter les modèles et fournisseurs `coming_soon`, `inactive` et pas encore routables |
| `endpoints` | Noms d’endpoints publics, comme `chat.completions`, `responses` et `messages` |
| `status` | Cycle de vie du modèle, comme `active`, `deprecated` ou `retired` |
| `organisation` | Préfixe de l’ID du modèle, comme `anthropic` dans `anthropic/claude-3-haiku` |
| `provider` | ID public du fournisseur, comme `openai`, `anthropic` ou `google_vertex` |
| `provider_status` | Niveau de déploiement du fournisseur, comme `active`, `beta`, `alpha` ou `not_ready` |
| `provider_routing_status` | État de routage au niveau du fournisseur |
| `model_routing_status` | État de routage au niveau du modèle |
| `capability_status` | État de la capacité du fournisseur pour l’association d’endpoint demandée |
| `provider_availability_status` | Disponibilité côté fournisseur, comme `active`, `coming_soon` ou `inactive` |
| `provider_availability_reason` | Raison de l’indisponibilité d’un fournisseur, comme `preview_only`, `provider_not_ready`, `gated`, `access_limited` ou `region_limited` |
| `input_types` (alias `input_modalities`) | Modalités d’entrée |
| `output_types` (alias `output_modalities`) | Modalités de sortie |
| `params` (alias `supported_parameters`) | Paramètres de requête pris en charge |

Pour examiner les routes de fournisseurs, le détail des paramètres et les tarifs d’un modèle, appelez [`GET /models/{author}/{slug}/endpoints`](./model-endpoints.mdx).

## Vérifier les niveaux de service par offre

Chaque entrée de `offers` contient `service_tiers`, les [niveaux de service](../../guides/service-tiers.mdx) acceptés par cette offre du fournisseur. C’est un sous-ensemble trié par ordre alphabétique de `flex`, `priority`, `standard` et `ultrafast`, où `priority` correspond au niveau Fast. Un niveau est listé lorsque la route du fournisseur a pour lui une tarification active et en vigueur, et une route qui ne sert qu’un niveau ne liste que celui-ci. Certains niveaux sont aussi disponibles via des routes de fournisseur propres à un niveau, qui ne sont pas listées. Les prix sous `pricing` restent ceux du niveau standard.

## Obtenir la liste au format OpenAI

Utilisez `GET /v1/models?format=openai` pour les clients qui attendent la réponse de liste de modèles d’OpenAI. Le `format=json` par défaut renvoie les métadonnées de modèles plus riches de Phaseo.

```bash
curl "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

```json
{
  "object": "list",
  "data": [
    { "id": "openai/gpt-6-astra", "object": "model", "created": 1788393600, "owned_by": "openai" }
  ]
}
```

Le format OpenAI utilise la même authentification, la même disponibilité régionale, les mêmes modèles privés de l’espace de travail et les mêmes filtres que le JSON natif. Il renvoie tous les modèles correspondants, sauf si vous fournissez `limit` ; `offset` s’applique toujours. Les ID restent sous la forme canonique de Phaseo pour l’inférence. `created` reprend la date de sortie du catalogue, ou `0` si elle est inconnue ; `owned_by` reprend l’organisation du catalogue, `private` pour les modèles de l’espace de travail, ou `phaseo` si elle est inconnue.

## Mettre en cache la liste des modèles

Les réponses du catalogue sont mises en cache pendant cinq minutes et peuvent être servies pendant cinq minutes de plus pendant la revalidation du cache. Cela s’applique aux représentations JSON, RSS et Atom du catalogue actuel ; le flux des sorties a son propre cache d’interrogation, plus court.

Les réponses JSON et au format OpenAI contiennent un en-tête `ETag` faible (`W/"…"`). Il change lorsque les modèles de la page, `limit`, `offset`, `total` ou le format changent. Il ignore `gateway_region` : le même catalogue servi depuis une autre région a donc le même `ETag`. C’est pourquoi il est faible : les réponses qui le partagent sont équivalentes, mais leurs octets peuvent différer. Les réponses RSS, Atom et d’erreur n’en contiennent pas.

Renvoyez la valeur enregistrée telle quelle dans `If-None-Match`. Si le catalogue n’a pas changé, la réponse est `304 Not Modified`, sans corps, et reprend les en-têtes `ETag`, `Cache-Control` et `Vary`. Sinon, vous recevez un `200` normal avec la nouvelle liste et un nouvel `ETag`. `If-None-Match` accepte aussi une liste séparée par des virgules et `*`, et la comparaison est faible : la valeur correspond donc avec ou sans son préfixe `W/`.

```ts
let etag: string | null = null;
let models: unknown[] = [];

async function refreshModels() {
  const response = await fetch("https://api.phaseo.app/v1/models?limit=250", {
    headers: {
      Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
      ...(etag ? { "If-None-Match": etag } : {}),
    },
  });
  if (response.status === 304) return models; // Inchangé ; un 304 n’a pas de corps.
  if (!response.ok) throw new Error(`Model list request failed: ${response.status}`);
  etag = response.headers.get("ETag");
  models = (await response.json()).models;
  return models;
}
```

Un `304` économise le transfert et l’analyse. Le serveur évalue quand même la requête : il charge le catalogue et recalcule l’`ETag`. Une interrogation toutes les 15 minutes environ suffit, en ne téléchargeant de nouveau la liste que lorsque le catalogue change. Conservez un `ETag` par URL de requête, car chaque page, ensemble de filtres et format a sa propre valeur.
