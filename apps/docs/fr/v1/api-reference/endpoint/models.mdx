Par défaut, ce point de terminaison renvoie uniquement les modèles actuellement routables. Définissez `availability=all` pour inclure les modèles connus mais indisponibles pour le moment.

Les réponses du catalogue sont mises en cache pendant cinq minutes et peuvent être servies pendant cinq minutes supplémentaires lors de la revalidation du cache. Cela s’applique aux représentations JSON, RSS et Atom du catalogue actuel ; le flux des nouvelles versions dispose de son propre cache de consultation, plus court.

`GET /models/me` est réservé à un futur filtrage des modèles adapté aux garde-fous de l’appelant actuel. Il renvoie actuellement `501 not implemented` ; utilisez donc `GET /models` pour accéder au catalogue Gateway partagé.

## Format OpenAI

Utilisez `GET /v1/models?format=openai` pour les clients qui attendent la réponse de liste de modèles d’OpenAI. La valeur par défaut, `format=json`, renvoie les métadonnées de modèle plus détaillées de Phaseo.

```bash
curl 'https://api.phaseo.app/v1/models?format=openai' \
  -H 'Authorization: Bearer YOUR_PHASEO_API_KEY'
```

```json
{
  "object": "list",
  "data": [
    { "id": "openai/gpt-4o-mini", "object": "model", "created": 1721260800, "owned_by": "openai" }
  ]
}
```

Le format OpenAI applique la même authentification, la même disponibilité régionale, les mêmes modèles privés de l’espace de travail et les mêmes filtres que le JSON natif. Il renvoie tous les modèles correspondants, sauf si vous fournissez `limit` ; `offset` reste applicable. Les identifiants restent sous la forme canonique de Phaseo, utilisable pour l’inférence. `created` correspond à la date de publication dans le catalogue, ou à `0` si elle est inconnue ; `owned_by` correspond à l’organisation du catalogue, à `private` pour les modèles de l’espace de travail, ou à `phaseo` si elle est inconnue.

## Mettre en cache la liste des modèles

Les réponses au format JSON et OpenAI incluent un en-tête `ETag` faible (`W/"…"`). Il change lorsque les modèles de la page, `limit`, `offset`, `total` ou le format changent. Il ignore `gateway_region` : le même catalogue servi depuis une autre région a donc le même `ETag`. C’est pourquoi il est faible : les réponses qui le partagent sont équivalentes, mais leurs octets peuvent différer. Les réponses RSS, Atom et d’erreur n’en contiennent pas.

Renvoyez la valeur enregistrée, telle quelle, dans `If-None-Match`. Si le catalogue n’a pas changé, la réponse est `304 Not Modified`, sans corps, et reprend les en-têtes `ETag`, `Cache-Control` et `Vary`. Sinon, vous recevez une réponse `200` normale avec la nouvelle liste et un nouvel `ETag`. `If-None-Match` accepte aussi une liste séparée par des virgules et `*`, et la comparaison est faible : la valeur correspond avec ou sans son préfixe `W/`.

```ts
let etag: string | null = null;
let models: unknown[] = [];

async function refreshModels() {
  const response = await fetch("https://api.phaseo.app/v1/models?limit=250", {
    headers: {
      Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
      ...(etag ? { "If-None-Match": etag } : {}),
    },
  });
  if (response.status === 304) return models; // Unchanged; a 304 has no body.
  if (!response.ok) throw new Error(`Model list request failed: ${response.status}`);
  etag = response.headers.get("ETag");
  models = (await response.json()).models;
  return models;
}
```

Une réponse `304` économise le transfert et l’analyse, car elle n’a pas de corps. Le serveur évalue tout de même la requête : il charge le catalogue et recalcule l’`ETag`. Une vérification toutes les 15 minutes environ est donc appropriée, en ne retéléchargeant la liste que lorsque le catalogue change. Conservez un `ETag` par URL de requête, car chaque page, ensemble de filtres et format a sa propre valeur.

### Niveaux de service par offre

Chaque entrée de `offers` inclut `service_tiers`, les [niveaux de service](../../guides/service-tiers.mdx) acceptés par cette offre du fournisseur. Il s’agit d’un sous-ensemble trié par ordre alphabétique de `flex`, `priority`, `standard` et `ultrafast`, où `priority` correspond au niveau Fast. Un niveau est listé lorsque la route du fournisseur dispose pour lui d’une tarification active et en vigueur, et une route qui ne sert qu’un niveau ne liste que celui-ci. Certains niveaux peuvent aussi être disponibles via des routes de fournisseur distinctes, propres à chaque niveau, qui ne figurent pas ici. Les prix sous `pricing` restent ceux du niveau standard.

## Filtres utiles

- `endpoints` accepte des noms publics comme `chat.completions`, `responses` et `messages`
- `status` filtre le cycle de vie du modèle, par exemple `active`, `deprecated` ou `retired`
- `provider` filtre l’identifiant public du fournisseur, par exemple `openai`, `anthropic` ou `google_vertex`
- `provider_status` filtre le niveau de déploiement du fournisseur, par exemple `active`, `beta`, `alpha` ou `not_ready`
- `provider_routing_status` filtre l’état de routage du fournisseur
- `model_routing_status` filtre l’état de routage du modèle
- `capability_status` filtre l’état des capacités du fournisseur pour la correspondance de point de terminaison demandée
- `provider_availability_status` filtre la disponibilité du fournisseur, par exemple `active`, `coming_soon` ou `inactive`
- `provider_availability_reason` filtre le motif de disponibilité du fournisseur, par exemple `preview_only`, `provider_not_ready`, `gated`, `access_limited` ou `region_limited`
- `organisation` filtre le préfixe de l’identifiant public du modèle, par exemple `anthropic` dans `anthropic/claude-3-haiku`
- `availability=active` est la valeur par défaut
- `availability=all` inclut les modèles ou fournisseurs `coming_soon`, `inactive` ou pas encore routables publiquement
- `input_modalities` est un alias de `input_types`
- `output_modalities` est un alias de `output_types`
- `supported_parameters` est un alias de `params`

Pour consulter le contrat de point de terminaison d’un modèle, appelez `GET /models/{author}/{slug}/endpoints`. La réponse sépare les routes de chaque fournisseur et indique, pour chaque ligne, le chemin public, les modalités, le détail des paramètres pris en charge, la disponibilité, l’état du routage, le slug du modèle du fournisseur et un récapitulatif des tarifs.

Les entrées de fournisseur peuvent aussi inclure :

- `availability_status`
- `availability_reason`
- `provider_status`
- `provider_routing_status`
- `model_routing_status`
- `capability_status`
