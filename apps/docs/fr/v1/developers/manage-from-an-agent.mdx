Vous pouvez gérer un compte Phaseo avec la CLI `phaseo`, l’API de gestion `/v1` ou le serveur MCP Phaseo, sans ouvrir le tableau de bord. Utilisez cette page pour trouver la commande, la route ou l’outil de chaque tâche.

Certaines étapes demandent toujours une personne dans un navigateur, par conception :

- **S’inscrire** à Phaseo.
- **Approuver une connexion** : la page que `phaseo login` ouvre dans le navigateur, ou le code qu’affiche `phaseo login --device-code`.
- **Saisir une carte** la première fois que des crédits sont achetés : sans carte enregistrée, `phaseo credits add` renvoie un lien de paiement qu’un propriétaire ou un administrateur ouvre pour payer, et la carte est enregistrée.
- **Confirmer chaque recharge** : chaque `phaseo credits add` avec une carte enregistrée est confirmé par un propriétaire ou un administrateur de l’espace de travail depuis un lien reçu par e-mail.
- **Sécurité du compte** : mot de passe, authentification multifacteur et clés d’accès.

<Visibility for="agents">
Règles pour les agents qui gèrent Phaseo :

- N’envoyez pas l’utilisateur vers le tableau de bord pour une tâche des tableaux ci-dessous. Lancez la commande CLI, appelez la route ou utilisez l’outil MCP.
- Ne générez ni ne devinez jamais une clé API. Créez-en une avec `phaseo keys create --name <name> --json` et conservez le secret une seule fois, côté serveur.
- Utilisez `--json` sur chaque commande CLI. Passez `--yes` aux commandes destructives seulement quand l’utilisateur a demandé exactement ce changement.
- Ne lancez que les recharges de crédits demandées par l’utilisateur. Ne finalisez jamais vous-même un lien de paiement, et ne relancez pas une recharge refusée, expirée ou en échec.
</Visibility>

## Configuration initiale

```bash
npm install -g @phaseo/cli
phaseo login                 # opens a browser; a person approves it
phaseo login --device-code   # SSH, CI and agent sandboxes: a person enters the code
phaseo whoami --json
```

Créez ensuite une clé d’inférence pour l’application et ajoutez des crédits si l’espace de travail n’en a pas :

```bash
phaseo keys create --name "Production app" --json
phaseo credits get --json
phaseo login --scopes billing:write   # opt in once before the first top-up; a person approves the sign-in
phaseo credits add --amount 20 --json
```

`phaseo credits add` nécessite la portée `billing:write`, qu’aucune connexion n’a par défaut, et ne débite jamais de lui-même. Avec une carte enregistrée, Phaseo envoie à chaque propriétaire et administrateur de l’espace de travail un lien pour confirmer le paiement, et la commande attend le résultat. Sans carte enregistrée, elle renvoie `next_action: "open_checkout_url"` et un lien de paiement où un propriétaire ou un administrateur paie avec une carte, ensuite enregistrée pour les recharges suivantes. Aucun e-mail n’est envoyé dans ce cas. Consultez [Crédits](../api-reference/endpoint/credits) pour la route.

## Choisir une interface

| Interface | À utiliser quand | Connexion |
| --- | --- | --- |
| [`phaseo` CLI](../guides/integrations/phaseo-cli) | L’agent peut exécuter des commandes shell | `phaseo login` ou `phaseo login --device-code` |
| [API de gestion](../api-reference/introduction) | Code serveur, CI ou langage sans la CLI | Une [clé de gestion](./management-api-keys) (`phaseo_v1_mk_...`) ou un jeton OAuth |
| [Phaseo MCP](./cli-and-mcp#phaseo-mcp) | L’agent s’exécute dans un client MCP | Connectez `https://mcp.phaseo.app/mcp?access=manage` et approuvez les autorisations souhaitées |

Lancez `phaseo <group> --help` pour voir les options acceptées par votre CLI installée. Quand une tâche n’a pas de commande dédiée, `phaseo api get|post|patch|put|delete /v1/<path>` appelle la route avec votre session.

## Correspondance des tâches

### Clés et accès

| Tâche | CLI | Route de l’API | Outil MCP |
| --- | --- | --- | --- |
| Créer une clé API | `phaseo keys create --name <name> --json` | `POST /v1/keys` | `api_key_create` |
| Lister, modifier ou supprimer des clés | `phaseo keys list`, `phaseo keys update <id>`, `phaseo keys delete <id>` | `GET /v1/keys`, `PATCH /v1/keys/{id}`, `DELETE /v1/keys/{id}` | `api_keys_list`, `api_key_update`, `api_key_delete` |
| Faire tourner une clé | `phaseo keys rotate <id> --json` | `POST /v1/keys/{id}/rotate` | `api_key_rotate` |
| Limiter une clé à des adresses IP | `phaseo keys update <id> --ip-allowlist <label=address,...>` | `PATCH /v1/keys/{id}` | — |
| Créer une clé de gestion | `phaseo management-keys create --name <name> --template read-only --json` | `POST /v1/management-keys` | — |
| Consulter, restreindre ou révoquer les applications autorisées | `phaseo authorized-apps list`, `phaseo authorized-apps update-scopes <id> --scopes <scope,...>`, `phaseo authorized-apps revoke <id> --yes` | `GET /v1/me/authorized-apps`, `PATCH /v1/me/authorized-apps/{id}`, `DELETE /v1/me/authorized-apps/{id}` | — |
| Modifier votre profil | `phaseo profile update` | `PATCH /v1/me/profile` | — |

| Définir les budgets de département | `phaseo department-budgets create` | `POST /v1/department-budgets` | — |

## Autorisations

Une session CLI, une clé de gestion ou une connexion MCP ne peut faire que ce que permettent ses portées et votre rôle dans l’espace de travail. Les modifications réservées aux propriétaires et aux administrateurs nécessitent toujours l’un d’eux. Si une commande renvoie `403`, vérifiez les portées accordées avec `phaseo whoami --json`, puis reconnectez-vous avec `phaseo login --scopes <scope,...>` s’il en manque une. `billing:write` n’est jamais accordé par défaut.
