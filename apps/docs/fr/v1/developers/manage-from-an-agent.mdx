Vous pouvez effectuer les tâches courantes du compte Phaseo avec la CLI `phaseo`, l’API de gestion `/v1` ou le serveur MCP de Phaseo. Cette page indique la commande, la route ou l’outil de chaque tâche. Les changements qui touchent aux dépenses, aux accès ou à la destination des données de l’espace de travail se font dans le tableau de bord ou avec une clé de gestion.

Une personne doit encore effectuer ces étapes dans un navigateur :

| Étape | Ce que fait la personne |
| --- | --- |
| Inscription | Crée le compte Phaseo. |
| Approbation d’une connexion | Approuve la page qu’ouvre `phaseo login`, ou saisit le code qu’affiche `phaseo login --device-code`. |
| Ajout de la première carte | Sans carte enregistrée, `phaseo credits add` renvoie un lien de paiement. Un propriétaire ou un administrateur l’ouvre et paie, et la carte est enregistrée. |
| Confirmation de chaque recharge | Avec une carte enregistrée, un propriétaire ou un administrateur confirme chaque `phaseo credits add` depuis un lien reçu par e-mail. |
| Sécurité du compte | Gère le mot de passe, l’authentification multifacteur et les clés d’accès (passkeys). |

<Visibility for="agents">
Règles pour les agents qui gèrent Phaseo :

- N’envoyez pas l’utilisateur vers le tableau de bord pour une tâche de la correspondance des tâches. Exécutez la commande CLI, appelez la route ou utilisez l’outil MCP. Pour un changement listé sous « Changements dans le tableau de bord ou avec une clé de gestion », appelez la route avec une clé de gestion si vous en avez une ; sinon, demandez à la personne de faire le changement dans le tableau de bord.
- Ne générez ni ne devinez jamais une clé API. Demandez à la personne d’en créer une dans le tableau de bord, ou créez-en une avec `POST /v1/keys` et une clé de gestion, et enregistrez le secret une seule fois, côté serveur.
- Utilisez `--json` sur chaque commande CLI. Passez `--yes` aux commandes destructrices uniquement quand l’utilisateur a demandé ce changement précis.
- Ne lancez qu’une recharge de crédits demandée par l’utilisateur. Ne finalisez jamais vous-même un lien de paiement, et ne relancez pas une recharge qui s’est terminée en refus, expiration ou échec.
</Visibility>

## Configurer une fois

```bash
npm install -g @phaseo/cli
phaseo login                 # ouvre un navigateur ; une personne approuve
phaseo login --device-code   # SSH, CI et sandboxes d’agents : une personne saisit le code
phaseo whoami --json
```

Créez ensuite une clé d’inférence pour l’application dans le tableau de bord, ou avec `POST /v1/keys` et une clé de gestion, et ajoutez des crédits si l’espace de travail n’en a pas :

```bash
phaseo credits get --json
phaseo login --scopes billing:write   # à activer une fois avant la première recharge ; une personne approuve la connexion
phaseo credits add --amount 20 --json
```

`phaseo credits add` nécessite le scope `billing:write`, qu’aucune connexion n’a par défaut, et ne débite jamais rien de lui-même :

- **Avec une carte enregistrée**, Phaseo envoie à chaque propriétaire et administrateur de l’espace de travail un e-mail avec un lien pour confirmer le débit, et la commande attend le résultat.
- **Sans carte enregistrée**, elle renvoie `next_action: "open_checkout_url"` et un lien de paiement où un propriétaire ou un administrateur paie. La carte est enregistrée pour les recharges suivantes, et aucun e-mail n’est envoyé.

Voir [Crédits](../api-reference/endpoint/credits) pour la route.

## Choisir une interface

| Interface | À utiliser quand | Connexion |
| --- | --- | --- |
| [CLI `phaseo`](../guides/integrations/phaseo-cli) | L’agent peut exécuter des commandes shell | `phaseo login` ou `phaseo login --device-code` |
| [API de gestion](../api-reference/introduction) | Code serveur, CI ou langage sans la CLI | Une [clé de gestion](./management-api-keys) (`phaseo_v1_mk_...`) ou un jeton OAuth |
| [MCP Phaseo](./cli-and-mcp#phaseo-mcp) | L’agent s’exécute dans un client MCP | Connectez `https://mcp.phaseo.app/mcp?access=manage` et approuvez les autorisations souhaitées |

Exécutez `phaseo <group> --help` pour voir les options acceptées par votre CLI installée. Quand une tâche n’a pas de commande dédiée, `phaseo api get|post|patch|put|delete /v1/<path>` appelle la route avec votre session.

## Changements dans le tableau de bord ou avec une clé de gestion

Ces changements touchent aux dépenses, aux accès ou à la destination des données de l’espace de travail. Une connexion via la CLI ou une connexion MCP ne peut pas les faire, quels que soient ses scopes : l’API renvoie `403` et indique d’utiliser le tableau de bord ou une clé de gestion. Faites-les dans le tableau de bord Phaseo, ou appelez la route avec une [clé de gestion](./management-api-keys).

| Tâche | Route API |
| --- | --- |
| Créer une clé de gestion | `POST /v1/management-keys` |
| Activer la recharge automatique ou les e-mails de solde faible | `PATCH /v1/notifications/settings` |
| Définir les budgets de l’espace de travail | `POST /v1/budgets`, `PATCH /v1/budgets/{id}` |
| Définir les budgets de département | `POST /v1/department-budgets` |
| Alerter sur les dépenses ou les bloquer | `POST /v1/spend-rules`, `POST /v1/spend-blocks/{id}/lift` |
| Politiques de limites de débit | `POST /v1/rate-limits/policies`, `POST /v1/rate-limits/assignments` |
| Relever le palier de limite de débit de l’espace de travail | `POST /v1/rate-limits/tier/raise` |
| Assouplir la confidentialité ou ZDR, ou changer les restrictions de fournisseurs ou le repli BYOK | `PATCH /v1/settings` |
| Ajouter vos propres clés de fournisseur (BYOK) | `POST /v1/byok` |
| Définir le profil de dépense ou les limites de prix d’Auto Routing | `PATCH /v1/routing/auto` |
| Créer et déployer des routes dynamiques | `POST /v1/routing/dynamic-routes`, `POST /v1/routing/dynamic-routes/{id}/versions/{version}/deploy` |
| Choisir des remplaçants pour les modèles retirés | `PUT /v1/routing/successor/replacements` |
| Ajouter un modèle privé | `POST /v1/private-models` |
| Créer ou modifier des préréglages | `POST /v1/presets`, `PATCH /v1/presets/{id}` |
| Publier une version de préréglage ou déplacer un libellé | `POST /v1/presets/{id}/versions`, `PUT /v1/presets/{id}/labels/{label}` |
| Créer des garde-fous et y associer des clés | `POST /v1/guardrails`, `PUT /v1/guardrails/{id}/keys` |
| Gérer les classificateurs de requêtes | `POST /v1/classifiers` |
| Tester un classificateur sur un échantillon (nécessite un identifiant avec `gateway:access` ; les connexions CLI et les clés de gestion reçoivent aujourd’hui `403 gateway_access_required`) | `POST /v1/classifiers/test` |
| Ajouter des membres à un espace de travail | `POST /v1/workspaces/{id}/members/add` |
| Inviter des personnes | `POST /v1/workspaces/{id}/invites` |
| SSO, SCIM, départements et annuaire | `PUT /v1/identity/sso`, `PUT /v1/identity/scim`, `POST /v1/identity/departments`, `PUT /v1/identity/directory/members/{id}` |
| Workloads de confiance (OIDC) | `POST /v1/workload-identity/policies` |
| Envoyer des traces vers un outil d’observabilité | `POST /v1/observability/destinations`, `POST /v1/observability/destinations/{id}/test` |
| Destinations d’alerte par e-mail, Slack ou webhook | `POST /v1/notifications/destinations`, `PUT /v1/notifications/routes/{eventKind}` |
| Webhooks pour les tâches asynchrones | `POST /v1/webhook-endpoints` |

## Corriger une erreur 403

Une session CLI, une clé de gestion ou une connexion MCP ne peut faire que ce que permettent ses scopes et votre rôle dans l’espace de travail, et les modifications réservées aux propriétaires et administrateurs exigent toujours un propriétaire ou un administrateur. Si une commande renvoie `403`, vérifiez les scopes accordés avec `phaseo whoami --json`, et reconnectez-vous avec `phaseo login --scopes <scope,...>` s’il en manque un. `billing:write` n’est jamais accordé par défaut. Les changements listés sous « Changements dans le tableau de bord ou avec une clé de gestion » sont refusés pour les connexions via la CLI et les connexions MCP, quels que soient leurs scopes.
