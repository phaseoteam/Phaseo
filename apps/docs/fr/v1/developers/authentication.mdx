Créez une clé dans le [tableau de bord](https://phaseo.app/settings/keys) ou avec `POST /v1/keys` et une clé de gestion, stockez-la sur votre serveur et envoyez-la comme jeton Bearer avec chaque requête au Gateway. Les agents doivent utiliser la CLI ; voir [Gérer Phaseo depuis un agent](./manage-from-an-agent).

```http
Authorization: Bearer phaseo_v1_sk_<kid>_<secret>
```

Définissez l’en-tête une seule fois sur votre client. Par exemple, avec `fetch` :

```ts
const response = await fetch("https://api.phaseo.app/v1/chat/completions", {
	method: "POST",
	headers: {
		Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
		"Content-Type": "application/json",
	},
	body: JSON.stringify({
		model: "openai/gpt-6-astra",
		messages: [
			{ role: "system", content: "You are a helpful assistant." },
			{ role: "user", content: "Summarize the drawbacks to AI." },
		],
	}),
});
```

<Note>
Vous pouvez appeler les modèles `:free` sans déposer de crédits. Les modèles payants nécessitent un solde de portefeuille disponible.
</Note>

## Choisir un identifiant

| Identifiant | Format | À utiliser pour |
| --- | --- | --- |
| Clé API Gateway | `phaseo_v1_sk_<kid>_<secret>` | Les endpoints de modèles, de fournisseurs et de génération disponibles pour votre espace de travail. |
| [Clé API de gestion](./management-api-keys.mdx) | `phaseo_v1_mk_<kid>_<secret>` | Les API d’administration. |
| [Workload de confiance](./trusted-workloads.mdx) (bêta) | Un jeton OIDC de courte durée fourni par la plateforme | Les déploiements et jobs CI sur Vercel, GitHub Actions, GitLab, Google Cloud, Buildkite, CircleCI, AWS ou votre propre émetteur OIDC, sans clé stockée. |

Traitez les clés comme des mots de passe : gardez-les hors du code côté client et des dépôts publics.

## Gérer les clés en toute sécurité

- **Une clé par application et par environnement**, pour pouvoir en faire tourner une sans affecter les autres services.
- **Stockez les clés dans un gestionnaire de secrets**, qui les tient à l’écart des journaux et du suivi des erreurs.
- **Surveillez l’utilisation par clé** dans le tableau de bord pour repérer les anomalies.
- **Supprimez les clés que vous n’utilisez plus.**

Pour faire tourner une clé, passez votre application sur la clé de remplacement avant d’invalider l’ancienne. Voir l’[endpoint de rotation des clés](../api-reference/endpoint/keys-rotate.mdx).

## Corriger les erreurs d’authentification

| Statut | Cause | Que faire |
| --- | --- | --- |
| `401` | La clé est absente, invalide ou appartient à un espace de travail désactivé. Le champ `reason` du corps précise lequel. | Vérifiez l’en-tête et la clé. |
| `403` | La clé est valide mais ne peut pas utiliser le fournisseur ou le modèle demandé. | Vérifiez les garde-fous de la clé et les réglages de fournisseurs de l’espace de travail. |
| `429` | La clé ou l’espace de travail a atteint une limite. | Voir [Limites de débit](../api-reference/limits.mdx). |
| `5xx` | Phaseo ou le fournisseur a échoué. | Réessayez avec un backoff exponentiel, et contactez le [support](https://phaseo.app/help) si le problème persiste. |

Voir [Erreurs et débogage](../api-reference/errors.mdx) pour tous les codes d’erreur.
