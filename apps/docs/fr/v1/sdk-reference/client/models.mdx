## Filtrer la liste

Tous les filtres sont facultatifs et portent le même nom dans tous les SDK : ce sont les paramètres de requête.

| Filtre | Filtre par |
| --- | --- |
| `provider`, `organisation` | Fournisseur ou organisation du modèle |
| `endpoints`, `input_types`, `output_types`, `params` | Endpoints, modalités et paramètres de requête pris en charge |
| `status`, `provider_status`, `provider_routing_status`, `model_routing_status`, `capability_status`, `provider_availability_status`, `provider_availability_reason` | État du cycle de vie et du routage |
| `availability` | Définissez `all` pour inclure les modèles qui ne peuvent pas être routés |
| `limit`, `offset` | Pagination |

Par défaut, la liste ne contient que les modèles routables. Définissez `availability` à `all` pour inclure les autres, puis affinez :

- `provider_availability_reason` sélectionne des états de déploiement comme `preview_only`, `provider_not_ready`, `gated`, `access_limited`, `region_limited`, `project_limited`, `paused` ou `soft_blocked`.
- `capability_status` sélectionne les correspondances d’endpoint qui ne sont pas encore routables, comme `coming_soon` ou `internal_testing`.

## Vérifier un modèle

`checkParameters` et ses équivalents lisent les métadonnées en direct des routes de fournisseur, marquent chaque paramètre `supported`, `partial`, `unsupported` ou `unknown`, vérifient les valeurs et plages annoncées, et renvoient les routes de fournisseur qui acceptent l’ensemble des paramètres. `preflight` fait de même pour tout un corps de requête et y ajoute la vérification du cycle de vie du modèle, avec un `ok` global.

| Langage | Capacités | Vérifier les paramètres | Preflight | Cycle de vie |
| --- | --- | --- | --- | --- |
| TypeScript | `models.capabilities(modelId)` | `models.checkParameters(modelId, values, { endpoint, provider })` | `models.preflight(request, { endpoint, provider })` | `models.validate(modelId)` renvoie `{ ok, info, reason }` ; `models.getDeprecationInfo(modelId)` |
| Python | `models.capabilities(model_id)` | `models.check_parameters(model_id, values, endpoint=..., provider=...)` | `models.preflight(request, endpoint=..., provider=...)` | `models.validate(model_id)`, `models.get_deprecation_info(model_id)` |
| Go (prochaine version) | `GetModelEndpointCapabilities` | `CheckModelParameters` | `PreflightRequest` | `ValidateModel`, `GetModelDeprecationInfo` (publiées) |
| C# (prochaine version) | `GetModelEndpointCapabilities(modelId)` | `CheckModelParameters(modelId, values)` | `PreflightRequest` | `ValidateModel`, `GetModelDeprecationInfo` (publiées) |
| PHP (prochaine version) | `getModelEndpointCapabilities` | `checkModelParameters(...)` | `preflightRequest` | `validateModel`, `getModelDeprecationInfo` (publiées) |
| Ruby (prochaine version) | `model_endpoint_capabilities` | `check_model_parameters(model_id, values)` | `preflight_request` | `validate_model`, `get_model_deprecation_info` (publiées) |
| Java (compilation depuis la source) | `getModelEndpointCapabilities(modelId, query)` | `checkModelParameters(modelId, values, options)` | `preflightRequest(request, options)` | `validateModel`, `getModelDeprecationInfo` |
| Rust (absent de `0.2.0`) | `Phaseo::model_endpoint_capabilities(...)` | `Phaseo::check_model_parameters(...)` | Aucune | Aucune |

« Prochaine version » signifie que la méthode est dans la source du SDK, mais pas dans le paquet publié ; voir [Vérifier ce que contient chaque paquet](./overview#check-what-each-package-ships). Les méthodes d’informations de dépréciation renvoient l’état du modèle (`active`, `deprecated` ou `retired`), ses dates de dépréciation et de retrait, et l’identifiant du modèle de remplacement.
