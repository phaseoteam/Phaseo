## Ce que vous envoyez et ce que vous recevez

Les corps de requête utilisent les noms de champs JSON de l’API dans tous les SDK. [Utilisation](./usage) donne un exemple par endpoint.

| Langage | Corps de la requête | Renvoie |
| --- | --- | --- |
| TypeScript | Des objets typés générés à partir de la spécification OpenAPI | Des objets typés |
| Python | Des dicts ; les types se trouvent dans `phaseo.models` | Des dicts `APIResponse` avec `output_text`, `request_id` et `trace_url` |
| Go | `map[string]interface{}`, ou les types `phaseo.ChatCompletionsRequest` et `phaseo.ResponsesRequest` (champs de struct en PascalCase comme `Model`, `Messages`, `Input`) | Le JSON décodé |
| C# | `Dictionary<string, object>` | `Dictionary<string, object>?` |
| PHP | Des tableaux | Des tableaux |
| Ruby | Des Hash (arguments nommés) | Des Hash |
| Java | Une `Map` ou un `JsonNode` Jackson ; analysez d’abord les chaînes JSON | `JsonNode` |
| Rust | `&serde_json::Value` | `PhaseoResponse` avec `status`, `body` et `request_id` |

Une clé manquante provoque une erreur dès la création du client. Python lève `ValueError`, `NewFromEnv()` en Go renvoie une erreur, C# et PHP lèvent `Missing API key. Pass apiKey or set PHASEO_API_KEY.`, Ruby lève `ArgumentError: Missing API key. Pass api_key or set PHASEO_API_KEY.`, et `Phaseo::from_env()` en Rust renvoie une `PhaseoError`.

<span id="wait-for-music-video-or-batches"></span>
## Attendre la musique, la vidéo ou les lots

Les assistants d’attente existent en TypeScript et en Python. Les autres SDK renvoient la tâche dès l’appel de création ; interrogez-la avec la méthode de lecture ou ouvrez son [URL WebSocket de tâche](#find-the-method-for-each-endpoint).

<CodeGroup>

```typescript TypeScript
const music = await client.music.generateAndWait(
  { model: process.env.PHASEO_MUSIC_MODEL!, prompt: "Gentle instrumental piano" },
  { timeoutMs: 600_000, onPoll: (job) => console.log(job.id, job.status) },
);
```

```python Python
import os

music = client.music.generate_and_wait(
    {"model": os.environ["PHASEO_MUSIC_MODEL"], "prompt": "Gentle instrumental piano"},
    timeout=600,
    on_poll=lambda job: print(job["id"], job["status"]),
)
```

</CodeGroup>

Utilisez `videos.generateAndWait` / `videos.generate_and_wait` pour la vidéo et `batches.createAndWait` / `batches.create_and_wait` pour les lots. Chaque assistant soumet la tâche une seule fois. Si la première réponse est déjà terminée, il la renvoie sans interroger l’API ; sinon, il interroge la même tâche jusqu’à ce qu’elle se termine et renvoie la réponse complète. Les tâches en échec, annulées ou expirées lèvent `JobFailedError`, dont le champ `response` contient les détails. Un lot terminé peut quand même contenir des requêtes individuelles en échec.

`wait(id, options)`, sur chaque ressource, reprend une tâche existante et renvoie toute réponse finale, y compris les échecs. En Python, la musique propose aussi `create(request)` et `retrieve(id)`.

| TypeScript | Python | Par défaut | Remarques |
| --- | --- | --- | --- |
| `intervalMs` | `interval` | `5000` ms / `5` secondes | Minimum `250` ms / `0.25` seconde. |
| `timeoutMs` | `timeout` | `1800000` ms / `1800` secondes (30 minutes) | Démarre après le retour de la soumission ; la requête de soumission garde son propre délai d’expiration. |
| `signal` | `cancel_event` | aucun | Arrête l’attente. En Python, un `threading.Event`. |
| `onPoll` | `on_poll` | aucun | Reçoit la première réponse et chaque interrogation. |

`JobTimeoutError` et `JobCancelledError` conservent l’identifiant de la tâche et la dernière réponse (`jobId`/`lastResponse` en TypeScript, `job_id`/`last_response` en Python) : vous pouvez donc reprendre avec `.wait(error.jobId)` ou `.wait(error.job_id)`. Arrêter une attente n’annule pas la tâche distante. En TypeScript, cela annule l’interrogation en cours ; le client Python synchrone vérifie l’annulation et l’échéance entre les requêtes et les callbacks, et ne peut donc pas interrompre un appel HTTP déjà en cours. Les échecs HTTP sont levés tels quels, et les soumissions ne sont jamais réessayées. Ces assistants interrogent l’API depuis votre processus ; ils n’ajoutent aucune exécution en arrière-plan au gateway.

### Conserver un handle d’un processus à l’autre

`music.start`, `videos.start` et `batches.start` renvoient un handle avec `result()`, `events()` et `cancel()`, plus `toJSON()` (TypeScript) ou `to_dict()` (Python). Stockez le type et l’identifiant qu’il renvoie, puis reconstruisez le handle plus tard avec `resume(id)`. `result()` lève une exception en cas d’échec final. Seules les tâches vidéo et les lots prennent en charge `cancel()`. Sur `AsyncPhaseo`, utilisez `await` sur les méthodes et itérez sur les événements avec `async for`.

| Tâche | TypeScript | Python |
| --- | --- | --- |
| Diffuser le contenu vidéo | `videos.streamContent(id)`, écrit avec `downloadTo(stream, writable)` | `videos.stream_content(id)`, écrit avec la fonction synchrone `download_to(chunks, binary_file)`, qui ne garde pas tout le téléchargement en mémoire |
| Diffuser les résultats d’un lot | `batchResults(await client.batches.streamResults(id))` analyse le JSONL une ligne à la fois ; `matchBatchResult(row, inputsByCustomId)` associe chaque ligne à son entrée et conserve les erreurs par ligne | `batches.results(id)` |
| Préparer des envois de fichiers | `toFile(bytes, filename, contentType)` | Passez des bytes, des objets `Path`, des objets fichier ou des tuples de fichiers HTTPX |

## Contrôles de requête et erreurs

Les nouvelles tentatives valent `0` par défaut en TypeScript, en Python et en Java, et ne s’appliquent qu’aux requêtes `GET` et `HEAD`. Les soumissions payantes, les écritures et les requêtes en streaming ne sont jamais réessayées.

<CodeGroup>

```typescript TypeScript
const fast = client.withOptions({ timeoutMs: 30_000, signal, maxRetries: 2 });
```

```python Python
fast = client.with_options(timeout=30, max_retries=2)
```

```java Java
Phaseo client = new Phaseo(System.getenv("PHASEO_API_KEY"))
    .setTimeout(Duration.ofSeconds(30))
    .setMaxRetries(2);
```

</CodeGroup>

<Tabs>
<Tab title="TypeScript">

`withOptions(...)` renvoie un nouveau client qui applique ces contrôles à chaque appel de ressource, de streaming et de média ; le client d’origine reste inchangé. Les nouvelles tentatives respectent `Retry-After`. `timeoutMs` inclut la lecture du corps de la réponse.

`responseMetadata(result)` renvoie l’identifiant de requête du gateway et l’URL de la trace dans le tableau de bord. Les erreurs HTTP sont des `PhaseoHttpError`, avec le `status` HTTP, le `code` d’erreur de l’API, `requestId`, `traceUrl`, le délai avant nouvelle tentative, le corps et `headers`.

</Tab>
<Tab title="Python">

`with_options(...)` renvoie un nouveau client et accepte aussi `headers=...` ; il fonctionne sur `Phaseo` comme sur `AsyncPhaseo`. Les nouvelles tentatives ont lieu avant la lecture de la réponse, jusqu’à `10` au maximum. Les délais d’expiration sont des délais HTTPX en secondes : ils limitent l’inactivité réseau plutôt que la durée totale.

Les réponses JSON sont des dicts `APIResponse` avec `output_text`, `request_id` et `trace_url`. Les erreurs HTTP sont des `PhaseoHTTPError`, avec `status`, `code`, `request_id`, `trace_url`, le délai avant nouvelle tentative et le corps.

Si vous mettez à jour depuis une ancienne version, remplacez les interceptions de `urllib.error.HTTPError` par `PhaseoHTTPError` (ou `httpx.HTTPStatusError`), et celles des erreurs de connexion par `httpx.TransportError`.

</Tab>
<Tab title="Java">

Les erreurs HTTP sont des `Client.ApiException` (`app.phaseo.gen.Client`), avec `getStatusCode()`, `getRequestId()`, `getResponseBody()` et les en-têtes. `requestWithResponse(...)` renvoie les données avec leur `requestId()`.

</Tab>
<Tab title="Rust">

Chaque appel renvoie `Result<PhaseoResponse, PhaseoError>`. `PhaseoError` implémente `std::error::Error` et `Display` ; les échecs de transport et de configuration n’ont pas de `status`.

| Type | Champ | Signification |
| --- | --- | --- |
| `PhaseoResponse` | `status: u16` | Code de statut HTTP. |
| `PhaseoResponse` | `body: serde_json::Value` | La réponse JSON analysée, ou une chaîne JSON si la réponse n’était pas du JSON valide. |
| `PhaseoResponse` | `request_id: Option<String>` | L’en-tête de réponse `x-request-id`, s’il est présent. |
| `PhaseoError` | `message: String` | Message d’erreur de configuration, de transport ou du Gateway. |
| `PhaseoError` | `status: Option<u16>` | Statut HTTP du Gateway, si une réponse a été reçue. |
| `PhaseoError` | `body: Option<serde_json::Value>` | Corps d’erreur du Gateway analysé, s’il est disponible. |

</Tab>
</Tabs>

[Utilisation](./usage#handle-errors) montre un gestionnaire d’erreurs complet dans chaque langage.

## Appeler un endpoint sans wrapper

Chaque SDK inclut aussi le client généré à partir de la spécification OpenAPI de Phaseo :

| Langage | Client généré |
| --- | --- |
| TypeScript | `client.rawClient()` ; les opérations générées sont exportées sous le nom `operations`. |
| Python | `client.raw_client()` ; les opérations générées se trouvent dans `phaseo.ops`. |
| Go | `client.RawClient()`, issu de `src/gen`. `client.Request(ctx, method, path, query, headers, body)` envoie n’importe quelle requête. |
| Java | `client.rawClient()`, avec `requestLines` pour les flux et `requestBytes` pour les réponses binaires. |
| Rust | `phaseo::gen` contient le client, les modèles et les opérations générés, réexportés sous `phaseo::client`, `phaseo::models` et `phaseo::operations`. `phaseo::model_ids` contient les identifiants de modèles générés. `client.post(path, body)` envoie du JSON vers n’importe quel chemin sous l’URL de base. Voir [docs.rs](https://docs.rs/phaseo). |

Les opérations générées sont de plus bas niveau que les méthodes wrapper ; préférez le wrapper quand il existe.

## Analyser la sortie et collecter les flux

Ces assistants existent en TypeScript et en Python. `responses.parse(request, schema)` valide une réponse JSON terminée. En TypeScript, `schema` est un analyseur compatible Zod ; en Python, un modèle Pydantic. Définissez aussi le format de sortie structurée dans la requête : l’analyseur ne fait que valider.

`collectStream(client.streamResponses(request))` (TypeScript), ou `collect_stream` et `collect_async_stream` (Python), rassemblent le texte et l’usage diffusés.

## Vérifier un modèle avant de l’appeler

`checkModelCapabilities` / `check_model_capabilities` (TypeScript et Python) vérifie les capacités annoncées et les contraintes scalaires (`inputTypes`, `outputTypes`, `endpoints`, `parameters`, `parameterValues`, ou leurs noms en snake_case en Python) sur une offre de fournisseur active. Il ne change jamais le modèle et ne supprime aucun paramètre, et il ne peut pas garantir qu’un fournisseur en direct acceptera la requête. Les métadonnées manquantes sont traitées différemment : TypeScript les signale comme inconnues, et Python fait échouer la vérification.

Pour les sélecteurs de modèles et les éditeurs de paramètres, utilisez les métadonnées des endpoints en direct :

<CodeGroup>

```typescript TypeScript
const support = await client.models.checkParameters(
  "anthropic/claude-haiku-4.5",
  { temperature: 0.7, top_p: 0.9 },
  { endpoint: "responses" },
);
```

```python Python
support = client.models.check_parameters(
    "anthropic/claude-haiku-4.5",
    {"temperature": 0.7, "top_p": 0.9},
    endpoint="responses",
)
```

</CodeGroup>

Chaque paramètre revient avec l’état `supported`, `partial`, `unsupported` ou `unknown`, accompagné des routes de fournisseur correspondantes et des problèmes de contraintes que vous pouvez signaler directement dans l’interface. Ces vérifications sont des appels explicites ; elles n’ajoutent aucune consultation aux requêtes de génération. [Modèles](./models#check-one-model) indique la méthode dans chaque SDK.

## Tester sans réseau

<Tabs>
<Tab title="TypeScript">

Importez `createMockTransport` et `jobFixtures` depuis `@phaseo/sdk/testing`, puis passez le `fetchImpl` du mock au client. Les fixtures sont strictes et ordonnées : un appel inattendu échoue localement et n’atteint jamais le réseau. Appelez `mock.assertDone()` pour vérifier que chaque requête attendue a bien eu lieu.

</Tab>
<Tab title="Python">

Passez `phaseo.testing.MockTransport(fixtures)` à un `httpx.Client` ou `httpx.AsyncClient`, puis donnez celui-ci au client Phaseo via `http_client`. Une requête inattendue échoue localement ; appelez `assert_done()` pour vérifier que chaque fixture a été utilisée. `phaseo.testing.job_fixtures(path, job_id)` construit les fixtures de soumission et d’interrogation d’une tâche. Les fixtures ne vérifient pas le comportement réel des fournisseurs.

</Tab>
</Tabs>
