Un préréglage enregistre le modèle, le prompt système, les paramètres et les règles de fournisseur d’une tâche sous un nom tel que `@support-triage`. Les appelants envoient ce nom comme `model`, avec seulement l’entrée ; le Gateway complète le reste avant de choisir un fournisseur.

Activez ou désactivez les champs de la requête pour voir quelle valeur l’emporte :

<PresetMergeExplorer locale="fr" />

Les règles sont les suivantes :

- **Les paramètres comblent les manques.** Les paramètres par défaut d’un préréglage ne s’appliquent qu’aux champs absents de la requête. Une valeur présente dans la requête l’emporte toujours.
- **Les prompts système s’empilent.** Le prompt du préréglage vient en premier. Si la requête a son propre prompt système ou ses propres `instructions`, ils suivent après une ligne vide.
- **Les réglages de fournisseur de la requête l’emportent.** Des champs tels que `provider.order` ou `provider.max_price` dans la requête remplacent la valeur du préréglage pour ce champ.
- **Les listes d’autorisation restreignent, sans jamais élargir.** Les listes de fournisseurs autorisés et ignorés du préréglage sont appliquées avant la sélection du fournisseur ; elles limitent donc aussi les fournisseurs utilisables en secours. Un modèle hors des modèles autorisés du préréglage échoue avec une `validation_error` dont le mot-clé de détail est `preset_model_not_allowed` ; il n’est pas réacheminé.

## Créer et utiliser un préréglage

<Steps>
<Step title="Créer le préréglage">

Ouvrez **Tableau de bord -> Paramètres -> Préréglages** et créez un préréglage avec un slug tel que `support-triage`. N’ajoutez que les valeurs par défaut que tous les appelants doivent partager.

Pour le créer depuis un script, appelez `POST /v1/presets` avec une clé de gestion.

</Step>

<Step title="L’appeler par son nom">

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "@support-triage",
    "input": "Customer says the invoice total is wrong."
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "@support-triage",
  input: "Customer says the invoice total is wrong.",
});
```

```python Python
from phaseo import Phaseo

client = Phaseo(api_key="YOUR_API_KEY")

response = client.generate_response({
    "model": "@support-triage",
    "input": "Customer says the invoice total is wrong.",
})
```
</CodeGroup>

</Step>

## Ce qu’un préréglage peut contenir

| Réglage | Effet |
| --- | --- |
| Modèle | Utilisé lorsque la requête est envoyée avec le nom du préréglage. |
| Modèles autorisés | Identifiants de modèles ou motifs tels que `anthropic/*`. Les autres modèles sont refusés. |
| Prompt système | Ajouté au début de chaque requête. |
| [Modèle de prompt](./prompt-templates) | Messages avec des `{{variables}}` que chaque requête renseigne. |
| Paramètres par défaut | `temperature`, `top_p`, `max_tokens`, réglages de raisonnement et similaires. |
| Règles de fournisseur | Listes d’autorisation et d’exclusion, ordre des fournisseurs, régions, plafonds de prix. |

Gardez la logique propre à chaque appelant dans votre application, et utilisez des préréglages distincts lorsque des workflows ont besoin de prompts, de routage ou de mise en cache différents.

## Nommer un préréglage

Envoyez un préréglage via le champ `model`, ou via `prompt.id` lorsqu’il a un [modèle de prompt](./prompt-templates). Il n’existe pas de champ `preset` distinct.

| Forme | Résolu dans |
| --- | --- |
| `@support-triage` | L’espace de travail de la clé API (préréglages privés et d’espace de travail). |
| `@octavia/support-triage` | N’importe quel espace de travail (préréglages publics, publiés par l’utilisateur `octavia`). |
| `@support-triage@v3` | Cette version publiée. |
| `@support-triage@production` | La version vers laquelle pointe le libellé `production`. |

Publier un préréglage public nécessite un profil public activé et un nom d’utilisateur. Les noms d’utilisateur sont uniques dans tout Phaseo ; les slugs n’ont besoin d’être uniques que pour un même éditeur. Les slugs sont mis en minuscules et peuvent contenir des lettres, des chiffres, `-`, `_`, `.` et `:`.

## Versionner et revenir en arrière

Enregistrer modifie un brouillon privé. **Publier une nouvelle version** transforme le brouillon en une version numérotée immuable et conserve toutes les précédentes.

Choisissez l’apparence des libellés de version :

| Format | Exemple |
| --- | --- |
| Séquentiel | `v1`, `v2`, `v3` |
| Semantic Versioning | `1.2.0`, `2.0.0-beta.1`, `1.4.2+build.7` |
| Date | `2026.08.02`, puis `2026.08.02.2` pour une deuxième version le même jour |

Faites pointer un libellé nommé tel que `production` vers une version, et ramenez-le vers une version antérieure pour revenir en arrière. Consultez [Versions et libellés](/fr/v1/guides/prompt-templates#versions-and-labels).

Depuis un script, publiez avec `POST /v1/presets/{id}/versions` et déplacez les étiquettes avec `PUT /v1/presets/{id}/labels/{label}`, avec une clé de gestion. Une connexion via la CLI ou une app qui utilise Se connecter avec Phaseo peut lire les préréglages, mais pas les modifier.

## Dupliquer un préréglage de la marketplace

Une copie d’un préréglage de la marketplace reste épinglée à la version que vous avez copiée. Lorsque l’éditeur publie une mise à jour, votre copie affiche un avis. L’appliquer ne modifie que votre brouillon : rien n’atteint la production tant que vous ne le publiez pas vous-même.

Phaseo enregistre la source et l’ascendance complète de chaque copie, afin qu’une page de la marketplace puisse afficher les copies directes séparément de tous les descendants.

Pour recueillir des évaluations sur les réponses d’un préréglage, consultez [Recueillir des commentaires sur les préréglages](./preset-feedback).
