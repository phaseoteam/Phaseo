Traitez chaque appel d’outil comme une entrée non fiable : vérifiez le nom de l’outil par rapport à une liste d’autorisation et validez les arguments avant toute exécution.

```typescript
import { z } from "zod";

const WeatherArgs = z.object({
  city: z.string().min(1),
});

function executeToolCall(name: string, rawArgs: string) {
  if (name !== "get_weather") {
    throw new Error(`Unsupported tool: ${name}`);
  }

  const parsed = WeatherArgs.parse(JSON.parse(rawArgs));
  return getWeather(parsed.city);
}
```

## Liste de contrôle

- **Gardez des schémas petits et explicites.** Des champs moins nombreux et typés laissent au modèle moins de marge pour envoyer quelque chose d’inattendu.
- **Validez les arguments analysés** avant l’exécution, comme ci-dessus.
- **Rejetez les noms d’outils inconnus** au lieu de deviner ce que le modèle voulait dire.
- **Ajoutez des délais d’attente et des nouvelles tentatives** aux appels qui atteignent des systèmes externes.
- **Journalisez** l’ID d’appel, le nom de l’outil et tout échec de validation.

## Quand la validation échoue

N’exécutez pas l’outil. Envoyez une erreur courte et maîtrisée comme résultat de l’outil au tour suivant, et demandez au modèle de réessayer avec des arguments corrigés.

## Streaming

Avec `stream: true`, les arguments arrivent par morceaux. Rassemblez tous les fragments d’arguments d’un appel avant de l’analyser, de le valider ou de l’exécuter. Le fait que les appels d’outils soient diffusés ou non dépend du modèle et du fournisseur. Consultez [Diffusion en continu](./streaming.mdx).
