Placez un identifiant de fournisseur suivi de deux-points devant l’identifiant du modèle, par exemple `baseten:thinking-machines/inkling-small`, pour exécuter la requête uniquement chez ce fournisseur, sans repli vers un autre fournisseur.

| Vous voulez | À envoyer comme `model` |
| --- | --- |
| Que Phaseo choisisse un fournisseur et se replie d’un fournisseur à l’autre | `thinking-machines/inkling-small` |
| Baseten uniquement, sans repli vers un autre fournisseur | `baseten:thinking-machines/inkling-small` |
| Une route gratuite vérifiée chez un seul fournisseur | `google-ai-studio:google/gemma-4-26b-a4b:free` |

Le format est `<provider-id>:<canonical-model-id>`. Le premier deux-points sépare le fournisseur ; les deux-points situés après l’espace de noms du modèle font partie de l’identifiant du modèle. Dans `google-ai-studio:google/gemma-4-26b-a4b:free`, le fournisseur est `google-ai-studio` et le modèle est `google/gemma-4-26b-a4b:free`.

Si vous voulez seulement privilégier un fournisseur et conserver un repli en cas d’échec, utilisez plutôt l’identifiant de modèle simple avec les [contrôles de routage et de repli](./routing-and-fallbacks.mdx).

## Envoyer une requête

Utilisez l’identifiant qualifié partout où l’endpoint accepte un identifiant de modèle.

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "baseten:thinking-machines/inkling-small",
    "input": "Explain mixture-of-experts routing in two sentences."
  }'
```

```javascript JavaScript
const response = await fetch("https://api.phaseo.app/v1/responses", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "baseten:thinking-machines/inkling-small",
    input: "Explain mixture-of-experts routing in two sentences.",
  }),
});

const result = await response.json();
```

```python Python
import os
import requests

response = requests.post(
    "https://api.phaseo.app/v1/responses",
    headers={
        "Authorization": f"Bearer {os.environ['PHASEO_API_KEY']}",
        "Content-Type": "application/json",
    },
    json={
        "model": "baseten:thinking-machines/inkling-small",
        "input": "Explain mixture-of-experts routing in two sentences.",
    },
)

result = response.json()
```
</CodeGroup>

## Ce que le fournisseur doit toujours respecter

Le qualificatif restreint le routage à un seul fournisseur ; il ne contourne aucun autre contrôle. Le fournisseur doit toujours :

- servir le modèle canonique sur l’endpoint demandé, avec cette capacité activée
- respecter les restrictions de l’espace de travail, de la clé API, du préréglage et de confidentialité
- prendre en charge le niveau de service et les paramètres demandés
- avoir une tarification configurée

Si un contrôle échoue, la requête est refusée. Phaseo ne choisit jamais discrètement un autre fournisseur.

## Combiner avec les champs `provider` ou `routing`

Le qualificatif et les champs de routage explicites doivent concorder. Un `provider.only` ou `routing.only` correspondant est accepté :

```json
{
  "model": "baseten:thinking-machines/inkling-small",
  "provider": { "only": ["baseten"] }
}
```

Une liste d’autorisation qui nomme d’autres fournisseurs, ou une liste d’exclusion qui contient le fournisseur qualifié, est refusée avec `provider_qualified_model_conflict` :

```json
{
  "model": "baseten:thinking-machines/inkling-small",
  "provider": { "only": ["deepinfra"] }
}
```

## Demander une route gratuite chez un seul fournisseur

Un modèle `:free` qualifié n’est accepté que si ce fournisseur dispose d’une route gratuite éligible pour le modèle et l’endpoint. Un modèle `:free` canonique ne signifie pas que tous les fournisseurs du modèle sous-jacent le proposent gratuitement.

```json
{
  "model": "google-ai-studio:google/gemma-4-26b-a4b:free",
  "input": "Hello"
}
```

La fiche tarifaire de la route doit être non vide, et chacune de ses règles tarifaires actuelles doit porter le libellé `free` avec un prix exactement nul. Une tarification absente, payante, mixte ou négative, ou une règle à prix nul sans le libellé `free`, fait refuser la requête avant qu’elle n’atteigne le fournisseur.

## Identifiants et alias de fournisseur

Utilisez un identifiant de fournisseur du catalogue des fournisseurs de Phaseo (consultez [Fournisseurs d’API](../exploring/api-providers)). Les identifiants sont mis en minuscules, et les alias historiques ou de marque connus sont convertis en identifiant canonique : `NovitaAI` et `novita-ai` deviennent tous deux `novita`. Les identifiants mal formés ou inconnus sont refusés avant la sélection du fournisseur ; ils ne sont jamais envoyés en amont dans le nom du modèle.

## Erreurs de validation

Un identifiant qualifié incorrect renvoie HTTP `400` avec le code d’erreur `validation_error`. `reason` et `details[].keyword` indiquent la cause :

| Motif | Signification |
| --- | --- |
| `invalid_provider_slug` | La partie fournisseur est vide ou contient des caractères non pris en charge. |
| `unknown_provider_slug` | L’identifiant de fournisseur est bien formé, mais ne correspond à aucun fournisseur Phaseo. |
| `invalid_provider_qualified_model` | L’identifiant ne correspond pas à `<provider>:<publisher>/<model>`. |
| `provider_qualified_model_conflict` | `provider.only`, `provider.ignore`, `routing.only` ou `routing.ignore` contredit le qualificatif. |
| `qualified_provider_unavailable` | Le fournisseur existe, mais ne sert pas ce modèle sur l’endpoint demandé. |
| `qualified_free_provider_unavailable` | La route du fournisseur n’est pas vérifiée comme gratuite avec une tarification entièrement nulle. |

```json
{
  "error": "validation_error",
  "status_code": 400,
  "reason": "unknown_provider_slug",
  "description": "Unknown provider slug \"not-a-provider\" in provider-qualified model \"not-a-provider:publisher/model\". Use a provider slug returned by Phaseo's provider catalogue.",
  "provider": "not-a-provider",
  "model": "publisher/model",
  "details": [
    {
      "path": ["model"],
      "keyword": "unknown_provider_slug"
    }
  ]
}
```

Pour les autres formes d’erreur, consultez [Erreurs et débogage](../api-reference/errors.mdx).
