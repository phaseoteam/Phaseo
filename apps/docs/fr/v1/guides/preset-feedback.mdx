Envoyez chaque évaluation d’utilisateur à `POST /v1/feedback` avec l’identifiant de requête et le [préréglage](./presets.mdx) qui a répondu, puis comparez les préréglages selon la fréquence à laquelle leurs réponses ont été bien notées, et pas seulement selon la latence et le coût.

<Note>
Les commentaires sur les préréglages sont en Alpha : l’API et le tableau de bord peuvent encore changer. Utilisez le bouton **Commentaires** de la [page Commentaires sur les préréglages](https://phaseo.app/settings/presets/experiments) pour nous dire ce qui la rendrait plus utile.
</Note>

## Enregistrer une évaluation

Vous avez besoin d’une clé API dotée de la capacité `feedback:write`, de l’identifiant de requête renvoyé par Phaseo et de l’UUID du préréglage. C’est l’identifiant du préréglage qui fait entrer l’événement dans les comparaisons de préréglages et l’analyse par cohorte.

```bash cURL
curl https://api.phaseo.app/v1/feedback \
  -X POST \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "requestId": "gen_01K...",
    "presetId": "8f54b2d9-9ba3-4ced-8a7f-9bb70a44dbea",
    "rating": "thumbs_up",
    "score": 1,
    "comment": "The answer resolved the customer question.",
    "metadataDimensions": {
      "plan": "pro",
      "surface": "support_chat"
    }
  }'
```

Un événement de commentaire doit cibler au moins une requête, une session, un préréglage ou une exécution de test. `score` est facultatif et doit être compris entre `0` et `1`.

Placez dans `metadataDimensions` les valeurs à faible cardinalité, comme le forfait, le déploiement, la langue ou la surface de l’application, afin de pouvoir filtrer selon elles. Placez plutôt le contexte arbitraire ou à forte cardinalité dans `metadata`.

## Choisir une évaluation

| Signal | `rating` |
| --- | --- |
| Une simple réaction de l’utilisateur | `thumbs_up`, `thumbs_down` |
| Une réponse évaluée | `correct`, `partly_correct`, `incorrect` |
| Un problème opérationnel | `bad_format`, `too_slow`, `too_expensive` |
| Un résultat lié à la sécurité | `unsafe`, `refused_incorrectly` |
| Tout autre cas | `not_helpful`, `other` |

Préférez une évaluation explicite à un simple score numérique : les comparaisons de préréglages reposent sur les évaluations, et les scores sont affichés en complément.

## Comparer les préréglages

Ouvrez [Paramètres → Préréglages → Retours](https://phaseo.app/settings/presets/experiments) pour :

- comparer les taux d’évaluations positives, partielles et négatives
- sélectionner un préréglage de référence
- filtrer par date, évaluation et dimensions de métadonnées
- examiner la requête, la session, les commentaires et les tags associés à un événement

Le tableau de bord analyse au maximum les 10 000 lignes de commentaires correspondantes les plus récentes dans la période sélectionnée.

## Lire les commentaires via l’API

La lecture nécessite `feedback:read`. Les résultats sont limités à l’espace de travail authentifié et aux préréglages visibles par l’appelant.

Lister les événements récents :

```bash
curl "https://api.phaseo.app/v1/feedback?preset_id=PRESET_UUID&limit=100" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

Obtenir un résumé calculé côté serveur :

```bash
curl "https://api.phaseo.app/v1/feedback/summary?group_by=preset&since=2026-08-01T00:00:00Z" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

Les API des exécutions de test et des événements de résultat personnalisés sont disponibles, mais leurs vues dans le tableau de bord évoluent encore. Pour déployer progressivement une modification de préréglage, consultez [Déployer des préréglages et déboguer le routage](../cookbook/preset-rollout-and-routing-debug).
