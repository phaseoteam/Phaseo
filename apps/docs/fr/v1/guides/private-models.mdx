Ajoutez un déploiement dédié ou auto-hébergé à votre espace de travail : votre équipe l’appelle via l’API Phaseo habituelle avec un identifiant de modèle tel que `acme/legal-assistant`. Seul votre espace de travail peut le voir ou l’appeler, et il fonctionne partout où un identifiant de modèle public fonctionne.

Les sources typiques sont les déploiements dédiés sur Baseten, Modal, RunPod, Fireworks ou Together, et les serveurs exécutant vLLM ou un autre serveur compatible OpenAI.

## Avant de commencer

Votre déploiement doit fournir :

- une URL de base HTTPS publique ;
- un endpoint `/chat/completions` compatible OpenAI ;
- une authentification par jeton Bearer ; et
- un identifiant de modèle ou de déploiement amont accepté par cet endpoint.

La prise en charge de `/responses` est facultative. Laissez-la désactivée, sauf si le déploiement implémente explicitement cet endpoint.

<Warning>
Les modèles privés n’adaptent pas les protocoles propres à un fournisseur ni les schémas d’authentification personnalisés. Placez une couche compatible OpenAI devant ces déploiements ou utilisez une intégration de fournisseur prise en charge par Phaseo.
</Warning>

## Connecter un déploiement

<Steps>
<Step title="Ouvrir Modèles privés">

Ouvrez **Tableau de bord → Paramètres → Espace de travail → Modèles privés**, puis sélectionnez **Ajouter un modèle**. Vous devez être propriétaire ou administrateur de l’espace de travail. Depuis la CLI, exécutez `phaseo private-models create` avec les mêmes champs et passez l’identifiant avec `--credential-stdin`.

</Step>

<Step title="Nommer le modèle">

Choisissez un modèle existant du catalogue pour ajouter ce déploiement à sa liste de fournisseurs, ou saisissez un slug de modèle court tel que `legal-assistant`. Si aucun modèle du catalogue n’a ce slug unique, Phaseo le combine avec l’espace de noms de confiance de l’espace de travail :

```text
acme/legal-assistant
```

Vous ne pouvez ni choisir ni remplacer l’espace de noms de l’espace de travail. Les identifiants exacts du catalogue se rattachent à ce modèle sans changer son identité publique.

</Step>

<Step title="Configurer l’endpoint">

Saisissez l’URL de base, avant le chemin d’inférence. Par exemple :

```text
https://model.example.com/v1
```

N’incluez pas `/chat/completions` ni `/responses`. Saisissez séparément l’identifiant exact du modèle ou du déploiement amont ; Phaseo le substitue lors du transfert des requêtes.

</Step>

<Step title="Enregistrer l’identifiant">

Saisissez la clé API du déploiement. Phaseo chiffre l’identifiant et ne le renvoie jamais après l’enregistrement. Vous pouvez le remplacer plus tard depuis la page de paramètres du modèle.

</Step>

<Step title="Appeler le modèle">

Utilisez l’identifiant de modèle généré avec l’endpoint Chat Completions habituel :

```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "acme/legal-assistant",
    "messages": [{"role": "user", "content": "Summarize this contract."}]
  }'
```

La clé API appelante doit appartenir au même espace de travail que le modèle privé.

</Step>
</Steps>

## Fonctionnement du routage

Un modèle autonome d’espace de travail n’est routé que vers son endpoint configuré. Un endpoint rattaché à un modèle du catalogue rejoint la liste de fournisseurs de ce modèle selon sa politique de routage :

| Tableau de bord | `routing_policy` de l’API | Effet |
| --- | --- | --- |
| **Préféré** (par défaut) | `preferred` | Votre déploiement est essayé avant les fournisseurs publics du modèle. |
| **Groupe normal** | `balanced` | Votre déploiement est classé avec les fournisseurs publics. |
| **Repli uniquement** | `fallback` | Votre déploiement n’est essayé qu’après les fournisseurs publics. |

Phaseo envoie l’identifiant enregistré comme jeton Bearer et substitue l’identifiant de modèle amont configuré.

Un modèle privé ne devient jamais une route de fournisseur publique et n’est pas visible par les autres espaces de travail. Les modèles privés activés figurent dans le catalogue de modèles authentifié et apparaissent sous le filtre **Privé**.

<Note>
Après avoir ajouté, modifié ou activé un déploiement privé, attendez jusqu’à une minute avant de tester son routage. D’ici là, certaines requêtes peuvent encore utiliser la configuration précédente, par exemple les fournisseurs publics du modèle. Les requêtes déjà en cours ne sont pas réacheminées.
</Note>

## Exemples par fournisseur

| Déploiement | À saisir |
| --- | --- |
| Endpoint dédié Baseten | Son URL de base compatible OpenAI, l’identifiant de modèle du déploiement et la clé API |
| Endpoint web Modal | Un endpoint HTTPS public qui implémente le contrat OpenAI Chat Completions |
| Endpoint serverless RunPod | Une URL de proxy compatible OpenAI et un identifiant Bearer |
| Déploiement dédié Fireworks ou Together | L’URL dédiée compatible OpenAI et l’identifiant de modèle du fournisseur |
| vLLM | L’URL publique se terminant par `/v1` et le nom du modèle servi par vLLM |

Les produits et formats d’URL des fournisseurs peuvent changer. Vérifiez l’URL de base, l’identifiant de modèle, la méthode d’authentification et les endpoints pris en charge dans la documentation de déploiement actuelle du fournisseur.

## Gérer les modèles privés via l’API

L’administration côté serveur peut utiliser l’[API Private Models](../api-reference/endpoint/private-models-list) avec une clé de gestion portant `private_models:read`, `private_models:write` ou `private_models:delete` selon les besoins.

Les requêtes de création et de mise à jour acceptent `model_reference`, soit un identifiant exact de modèle du catalogue, soit un slug court. Phaseo dérive `model_id` ; les clients ne peuvent pas l’envoyer directement. Utilisez `host_provider_id` pour un fournisseur Phaseo existant, ou `custom_provider_name` et éventuellement `custom_provider_url` pour un autre opérateur.

## Dépannage

- **404 du fournisseur :** vérifiez que l’URL de base s’arrête avant le chemin d’inférence.
- **Modèle inconnu :** copiez l’identifiant de déploiement amont du fournisseur dans **Identifiant du modèle amont**. N’y mettez pas l’identifiant de modèle de l’espace de travail Phaseo.
- **Requête amont non autorisée :** remplacez l’identifiant enregistré et vérifiez que le fournisseur accepte l’authentification Bearer.
- **Chat fonctionne mais Responses échoue :** désactivez **Responses API**, sauf si le fournisseur implémente `/responses` nativement.
- **Modèle absent du catalogue :** vérifiez que le modèle est activé et que l’appelant est authentifié dans le même espace de travail.
