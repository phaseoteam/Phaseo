Envoyez les requêtes texte à `eu.api.phaseo.app` ou `us.api.phaseo.app` pour n’utiliser que les routes de fournisseur qui exécutent le modèle et traitent les données de prompt et de complétion dans cette région. Les identifiants de modèle et les clés API restent les mêmes. Chat Completions, Responses et Messages sont pris en charge.

| Région | URL de base | Routes de fournisseur utilisées |
| --- | --- | --- |
| Union européenne | `https://eu.api.phaseo.app/v1` | Uniquement les routes qui déclarent une exécution et un traitement des données dans l’UE |
| États-Unis | `https://us.api.phaseo.app/v1` | Uniquement les routes qui déclarent une exécution et un traitement des données aux États-Unis |
| Mondiale | `https://api.phaseo.app/v1` | La politique de routage mondiale standard |

<Warning>
Le routage régional n’est pas encore une garantie de résidence des données de bout en bout. Phaseo restreint la sélection des fournisseurs et place le Gateway près de la région, mais les systèmes partagés de compte, de facturation, de cache et d’exploitation peuvent traiter des données hors de celle-ci. Consultez [Ce qui reste hors de la région](#what-stays-outside-the-region).
</Warning>

## Envoyer une requête régionale

<CodeGroup>
```ts TypeScript
import { Phaseo } from "@phaseo/sdk";

const phaseo = new Phaseo({
  apiKey: process.env.PHASEO_API_KEY!,
  region: "eu",
});

const response = await phaseo.responses.create({
  model: "openai/gpt-5.6-luna",
  input: "Summarize this note in one sentence.",
});

console.log(response.output_text);
```

```python Python
import os
from phaseo import Phaseo

phaseo = Phaseo(
    api_key=os.environ["PHASEO_API_KEY"],
    region="eu",
)

response = phaseo.responses.create({
    "model": "openai/gpt-5.6-luna",
    "input": "Summarize this note in one sentence.",
})

print(response.get("output_text"))
```

```bash Chat Completions
curl https://eu.api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5.6-luna",
    "messages": [
      {"role": "user", "content": "Write a two-line status update."}
    ]
  }'
```

```bash Responses
curl https://eu.api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5.6-luna",
    "input": "Extract the three most important actions from this note."
  }'
```

```bash Messages
curl https://us.api.phaseo.app/v1/messages \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -H "anthropic-version: 2023-06-01" \
  -d '{
    "model": "anthropic/claude-sonnet-5.5",
    "max_tokens": 256,
    "messages": [
      {"role": "user", "content": "Summarize this incident report."}
    ]
  }'
```
</CodeGroup>

Dans les SDK, définissez `region` sur `"eu"` ou `"us"` ; omettez-le, ou utilisez `"global"`, pour le routage mondial. Le SDK lève une erreur si vous définissez à la fois `region` et une `baseUrl` personnalisée (`base_url` en Python), car ils désignent des hôtes différents.

Le nom d’hôte fait office de politique. Un `required_execution_region` ou `required_data_region` dans la requête ou dans un préréglage qui nomme une autre région échoue avec `400 validation_error`, motif `deployment_region_conflict`. Les préréglages et les règles de routage dynamique sont appliqués en premier et la règle régionale en dernier : ils ne peuvent donc pas l’affaiblir. Phaseo ne relance jamais une requête via un fournisseur hors de la région.

## Ce qu’une requête régionale peut contenir

| Pris en charge | Refusé |
| --- | --- |
| Entrée et sortie texte | Images, audio, vidéo, documents, fichiers et pièces jointes |
| Streaming et non-streaming | Modalités de sortie autres que le texte |
| Instructions système et développeur | Outils hébergés par le fournisseur, tels que la recherche web, la recherche de fichiers, l’exécution de code, l’utilisation d’ordinateur et la génération d’images, ainsi que `web_search_options` |
| Vos propres outils `function` et `custom`, et les résultats d’outils au format texte | Les [outils serveur](./server-tools) Phaseo (types `phaseo:`) |
| Sortie texte structurée et JSON, lorsque le modèle la prend en charge | Endpoints d’image, d’audio, de vidéo, d’embedding, de modération, de lots, de fichiers, de webhooks et temps réel |
| Préréglages, ordre des fournisseurs, solutions de repli et limites de prix qui n’entrent pas en conflit avec la région | |

Vos propres outils sont autorisés, car ils s’exécutent dans votre application. Les outils hébergés et les outils serveur s’exécutent à un endroit que la règle régionale ne peut pas contrôler.

## Trouver les modèles disponibles dans une région

Appelez `/v1/models` sur le même nom d’hôte que celui auquel vous envoyez les requêtes. La disponibilité diffère entre les endpoints UE, États-Unis et mondial.

```bash
curl https://eu.api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

La liste ne contient que les modèles disposant d’une route de fournisseur active dont les régions d’exécution et de données déclarées incluent toutes deux la région, et n’annonce que Chat Completions, Responses et Messages avec entrée et sortie texte. Chaque offre indique ses régions :

```json
{
  "provider": { "id": "example-eu", "name": "Example EU" },
  "residency": {
    "execution_regions": ["eu"],
    "data_regions": ["eu"]
  }
}
```

## Vérifier quel Gateway a traité une requête

Les réponses régionales portent `X-Phaseo-Gateway-Region: eu` (ou `us`). L’en-tête nomme la politique régionale qui a traité la requête ; il ne prouve pas où Cloudflare l’a exécutée. Les détails de la requête enregistrent aussi les régions d’exécution et de données exigées, le fournisseur sélectionné et les régions déclarées par ce fournisseur.

## Erreurs

Les violations de la règle régionale renvoient `400 not_supported` avec l’une de ces valeurs de `reason` :

| `reason` | Cause | Correction |
| --- | --- | --- |
| `regional_endpoint_not_supported` | Le chemin n’est pas disponible en régional | Utilisez Chat Completions, Responses ou Messages, ou l’API mondiale |
| `regional_non_text_content` | Un média, un fichier ou une pièce jointe dans la requête | Retirez-le, ou utilisez l’API mondiale |
| `regional_non_text_output` | Une modalité de sortie autre que le texte a été demandée | Demandez du texte, ou utilisez l’API mondiale |
| `regional_hosted_tool_not_supported` | Un outil autre que `function` ou `custom` | Utilisez votre propre outil de fonction, ou l’API mondiale |

`400 validation_error` avec le motif `deployment_region_conflict` signifie que la requête ou un préréglage nomme une autre région ; retirez ce réglage. Si aucune route de fournisseur saine ne satisfait à la fois le modèle et la région, la requête s’arrête avant tout appel à un fournisseur ; choisissez un modèle listé par le `/v1/models` régional.

## Ce qui reste hors de la région

La règle régionale couvre le fournisseur qui exécute le modèle et traite les données de prompt et de complétion. Elle ne couvre pas encore tout le cycle de vie de la requête :

- Le placement Cloudflare met le Gateway près de la région, mais ne constitue pas une frontière de conformité.
- Les données de compte, d’authentification, de facturation et les métadonnées des requêtes résident sur une infrastructure Supabase partagée.
- Cloudflare KV et les journaux d’invocation des Workers ne sont pas liés à une région.
- Les appels au fournisseur vont vers l’endpoint régional de ce fournisseur, quel que soit l’endroit où Cloudflare a placé le Gateway.
- Les équipes de support et d’exploitation ne sont pas limitées à la région.

Phaseo ne parlera de résidence des données de bout en bout qu’une fois que le Gateway, le stockage, la journalisation, les fournisseurs et les chemins d’exploitation disposeront tous de contrôles régionaux applicables.
