Lancez `phaseo kilo` pour démarrer une session de la CLI Kilo Code via Phaseo, ou créez une clé avec `phaseo kilo-code` et ajoutez un fournisseur personnalisé dans l’extension Kilo Code.

## Exécuter la CLI Kilo Code via Phaseo

```bash
phaseo login
phaseo kilo --model openai/gpt-5.6-terra
```

Le lanceur écrit un fichier `KILO_CONFIG` temporaire, lance `kilo`, puis supprime ce fichier quand Kilo se ferme : votre configuration Kilo Code ou VS Code existante reste intacte. Si Kilo n’est pas installé, une exécution interactive propose de l’installer. Placez les options propres à Kilo après `--`.

| Option | Effet |
| --- | --- |
| `--model <id>` | Modèle à utiliser. Par défaut : `openai/gpt-5.6-terra`. |
| `--catalog all` | Affiche dans Kilo tous les modèles texte Phaseo actifs, pas seulement celui sélectionné. |
| `--dry-run --json` | Affiche le plan d’installation et de lancement sans créer de clé ni démarrer Kilo. |
| `--skip-install` | Ignore la vérification de l’installation. |

`phaseo run kilo ...` est la forme longue de la même commande.

## Configurer l’extension Kilo Code

Créez une clé pour l’extension :

```bash
phaseo login
phaseo kilo-code --model anthropic/claude-sonnet-5.5
```

Ensuite, dans VS Code :

1. Ouvrez Kilo Code, sélectionnez l’icône des paramètres, ouvrez **Providers**, puis sélectionnez **Add custom provider**.
2. Saisissez :

| Champ Kilo Code | Valeur |
| --- | --- |
| Provider ID | `phaseo` |
| Display name | `Phaseo` |
| Provider API | **OpenAI Compatible** |
| Base URL | `https://api.phaseo.app/v1` |
| API key | Sortie de `phaseo integrations credential kilo-code` |

3. Si aucun modèle n’est découvert, ajoutez vous-même l’ID `anthropic/claude-sonnet-5.5`.
4. Sélectionnez **Submit**, puis choisissez le modèle Phaseo.

Kilo affiche la sélection sous la forme `phaseo/anthropic/claude-sonnet-5.5`. `phaseo` est l’ID local du fournisseur ; le reste est l’ID du modèle envoyé à Phaseo. Consultez la documentation de Kilo sur les [modèles personnalisés](https://kilo.ai/docs/code-with-ai/agents/custom-models) pour le formulaire complet.

## Vérifier que tout fonctionne

Demandez à Kilo Code de répondre `PHASEO_KILO_OK`, puis vérifiez que la requête apparaît dans **Paramètres → Utilisation → Journaux**.

## Retirer Phaseo

Supprimez le fournisseur personnalisé dans Kilo Code, puis exécutez :

```bash
phaseo integrations remove kilo-code
```

Cette commande révoque la clé. La CLI ne peut pas vider le stockage de l’extension.

## Résoudre les problèmes courants

### Aucun modèle n’est découvert

Ajoutez le modèle vous-même. Kilo n’a pas besoin de la découverte via `/models`.

### L’authentification échoue

Remplacez la clé enregistrée par la sortie de `phaseo integrations credential kilo-code`, et conservez la Base URL exactement telle qu’indiquée.

### Le nom du modèle est différent

Sélectionnez `phaseo/<Phaseo model ID>` dans Kilo, mais n’ajoutez pas `phaseo/` dans le champ de l’ID du modèle.
