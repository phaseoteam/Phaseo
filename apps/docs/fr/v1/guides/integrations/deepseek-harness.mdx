Lancez `phaseo deepseek-harness` pour ajouter Phaseo au sélecteur de modèle de DeepSeek Harness, ou ajoutez un fournisseur personnalisé dans l’interface de Harness ou dans `settings.yaml`. Harness envoie des requêtes Chat Completions compatibles avec OpenAI directement à Phaseo ; aucun adaptateur n’est nécessaire.

## Configurer avec la CLI Phaseo

```bash
phaseo login
phaseo deepseek-harness
```

Si Harness n’est pas installé, la CLI affiche la commande d’installation officielle et demande confirmation avant de l’exécuter. La configuration ensuite :

- écrit le fournisseur, la Base URL, le protocole, le catalogue de modèles et le modèle par défaut dans `$DSH_HOME/cordis.patch.yml` (`DSH_HOME` vaut `~/.dsh` par défaut), à l’intérieur d’un bloc balisé, afin de pouvoir plus tard mettre à jour ou retirer uniquement ses propres réglages ;
- ajoute tous les modèles texte Phaseo actifs compatibles avec Chat Completions. Utilisez `--catalog default` pour n’ajouter que le modèle par défaut ;
- crée une clé `Phaseo CLI: DeepSeek Harness API Key` qui expire au bout de 90 jours et dispose d’une limite de dépenses mensuelle de $100, et l’écrit dans le fichier protégé de Harness `$DSH_HOME/.credentials.yaml`. Relancez `phaseo deepseek-harness` pour remplacer une clé expirée.

Le modèle par défaut est `anthropic/claude-sonnet-4.6`. Pour en choisir un autre :

```bash
phaseo deepseek-harness --model YOUR_PHASEO_MODEL_ID
```

## Ajouter Phaseo dans l’interface de Harness

1. Ouvrez **Settings > Models** et choisissez **Add a custom provider**.
2. Saisissez :

| Champ | Valeur |
| --- | --- |
| Provider ID | `phaseo` |
| Display name | `Phaseo` |
| Base URL | `https://api.phaseo.app/v1` |
| API protocol | `OpenAI Completions` |
| API key | Une clé API Phaseo |

3. Sous **Model catalog**, choisissez **Fetch available models**.
4. Sélectionnez un modèle Chat Completions qui prend en charge les outils, par exemple `anthropic/claude-sonnet-5.5`, puis enregistrez le fournisseur.
5. Dans le compositeur, choisissez le modèle Phaseo et démarrez une nouvelle session.

Les sessions enregistrées et les références d’identifiants conservent l’ID du fournisseur ; considérez donc `phaseo` comme définitif. Vous pourrez modifier plus tard le nom affiché, l’URL, la clé et la liste des modèles.

## Configurer Phaseo dans settings.yaml

Vous pouvez configurer le même fournisseur dans `$DSH_HOME/settings.yaml`. Ne mettez pas la clé dans ce fichier : `apiKeyEnv` indique la variable dans laquelle Harness la lit.

```yaml $DSH_HOME/settings.yaml
llm-pi-ai:
  providers:
    phaseo:
      displayName: Phaseo
      apiKeyEnv: PHASEO_API_KEY
      api: openai-completions
      baseURL: https://api.phaseo.app/v1
      models:
        - id: YOUR_PHASEO_MODEL_ID
```

Définissez `PHASEO_API_KEY` dans l’environnement qui lance Harness, ou enregistrez la clé sur la page Models. Remplacez `YOUR_PHASEO_MODEL_ID` par un ID exact de Phaseo ; pour les agents de code, commencez par `anthropic/claude-sonnet-5.5`. La liste `models` est un catalogue enregistré, pas une requête en direct : mettez-la à jour quand vous voulez plus de modèles Phaseo dans Harness.

## Vérifier que tout fonctionne

Vérifiez d’abord la clé et la découverte des modèles :

```bash
curl https://api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

Sélectionnez ensuite un modèle Phaseo dans une nouvelle session Harness et envoyez `Reply with exactly: Phaseo is connected.` Une réponse confirme tout le chemin, de Harness au fournisseur du modèle en passant par Phaseo. La requête apparaît aussi dans **Paramètres → Utilisation → Journaux**. Les requêtes réelles sont facturées comme une utilisation normale.

## Retirer Phaseo

```bash
phaseo integrations remove deepseek-harness
```

Cette commande retire uniquement la configuration appartenant à Phaseo et révoque la clé.

## Résoudre les problèmes courants

| Problème | Solution |
| --- | --- |
| La récupération des modèles renvoie `401` | Vérifiez que la clé est valide et que la Base URL inclut `/v1`. |
| Le modèle n’apparaît pas dans le sélecteur | Récupérez à nouveau le catalogue, ou ajoutez l’ID exact du modèle sous `models` dans `settings.yaml`. |
| Harness signale `MISSING_CREDENTIAL` | Enregistrez la clé sur la page Models, ou rendez `PHASEO_API_KEY` disponible pour le processus Harness. |
| Les requêtes partent vers le mauvais endpoint | Sélectionnez `OpenAI Completions` (`openai-completions`). Ce fournisseur utilise `/v1/chat/completions` de Phaseo. |
| Un modèle refuse les outils de fonction quand le raisonnement est activé | Choisissez un modèle qui prend en charge les outils sur Chat Completions. Les modèles qui exigent l’API Responses pour raisonner avec des outils ne fonctionnent pas avec ce protocole. |
| Une session garde son ancien modèle | Démarrez une nouvelle session. Harness enregistre le fournisseur et le modèle dans les sessions qui ont déjà envoyé une requête. |
