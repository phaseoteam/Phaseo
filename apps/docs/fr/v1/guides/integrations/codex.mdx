Lancez `phaseo codex` pour ajouter un profil Phaseo à Codex, ou ajoutez vous-même un fournisseur `phaseo` à `config.toml`. La même configuration fonctionne dans Codex CLI, Codex App et l’extension IDE Codex.

## Configurer avec la CLI Phaseo

```bash
phaseo login
phaseo codex --model openai/gpt-5.6-terra
codex --profile phaseo
```

Si Codex n’est pas installé, la CLI affiche la commande d’installation officielle et demande confirmation avant de l’exécuter. La configuration ouvre ensuite une page du tableau de bord où vous approuvez une clé `Phaseo CLI: Codex API Key` qui expire au bout de 90 jours et dispose d’une limite de dépenses mensuelle de $100. La CLI conserve la clé dans le magasin d’identifiants du système d’exploitation et écrit le profil dans `~/.codex/phaseo.config.toml` (ou sous `CODEX_HOME`). Codex récupère la clé auprès de la CLI : aucune clé en clair n’est écrite dans la configuration. Quand la clé expire, relancez `phaseo codex` pour en approuver une nouvelle. Sans `--model`, le profil utilise `openai/gpt-5.6-terra`.

## Configurer Codex manuellement

Ajoutez ceci à `~/.codex/config.toml`, ou à `.codex/config.toml` dans un projet approuvé :

```toml
model = "openai/gpt-6-astra"
model_provider = "phaseo"

[model_providers.phaseo]
name = "Phaseo"
base_url = "https://api.phaseo.app/v1"
env_key = "PHASEO_API_KEY"
wire_api = "responses"
```

Exportez ensuite `PHASEO_API_KEY` et démarrez Codex. Les fournisseurs personnalisés de Codex utilisent le protocole Responses, qui est la valeur par défaut ; vous pouvez donc aussi omettre `wire_api`. Dans l’extension IDE, ouvrez le fichier depuis **Codex Settings → Open config.toml**.

## Vérifier que tout fonctionne

Envoyez un court prompt et vérifiez que la requête apparaît dans **Paramètres → Utilisation → Journaux**. Codex appelle [Responses](../../api-reference/endpoint/responses.mdx) ; le modèle doit donc prendre en charge cet endpoint.

## Retirer Phaseo

```bash
phaseo integrations remove codex
```

Cette commande supprime `phaseo.config.toml` si Phaseo l’a créé, et révoque la clé. Pour une configuration manuelle, retirez le fournisseur `phaseo` de `config.toml`.

## Résoudre les problèmes courants

| Erreur | Solution |
| --- | --- |
| `401 Unauthorized` | Exécutez `phaseo whoami`, puis relancez `phaseo codex`. |
| `model_not_found` | Récupérez un ID actuel dans [Modèles](../../api-reference/endpoint/models.mdx) et mettez à jour `model`. |
| Un fournisseur échoue | Consultez [Routage et solutions de repli](../routing-and-fallbacks.mdx) pour le basculement. |

## Ajouter les skills et la documentation Phaseo

Pour que Codex lise la documentation Phaseo en direct pendant qu’il travaille, ajoutez le serveur [Docs MCP](./docs-mcp.mdx). Pour installer les [skills Phaseo](https://phaseo.app/docs/.well-known/agent-skills/index.json) publiques pour Codex :

```bash
npx skills add https://phaseo.app/docs --agent codex --skill '*'
```

Le même workflow de la CLI lance [Cline](./cline.mdx), [Kilo Code](./kilo-code.mdx), [oh-my-pi](./oh-my-pi.mdx), [Muse Code](./muse-code.mdx) et [MiniMax Code](./minimax-code.mdx) avec des réglages temporaires.
