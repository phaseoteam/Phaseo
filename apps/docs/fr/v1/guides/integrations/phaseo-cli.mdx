Installez `@phaseo/cli` et exécutez `phaseo login` pour connecter des agents de code à Phaseo et gérer les clés, les espaces de travail, les préréglages, les réglages et les garde-fous depuis le terminal. La CLI lit aussi les modèles, les fournisseurs, les tarifs, les crédits, l’activité, les analyses et les générations.

## Installer

<CodeGroup>

```bash npm
npm install -g @phaseo/cli
```

```bash pnpm
pnpm add -g @phaseo/cli
```

```bash yarn
yarn global add @phaseo/cli
```

```bash bun
bun add -g @phaseo/cli
```

</CodeGroup>

Vérifiez la version :

| Commande | Affiche |
| --- | --- |
| `phaseo --version` | La version installée. |
| `phaseo version` | La version et la commande de mise à jour pour votre gestionnaire de paquets. Ajoutez `--json` pour une sortie structurée. |

Les exécutions interactives affichent aussi un message lorsqu’une version plus récente est publiée.

## Se connecter

```bash
phaseo login
```

| Méthode | Option | À utiliser pour |
| --- | --- | --- |
| Connexion avec Phaseo | `--browser` | OAuth dans le navigateur avec code d’autorisation et PKCE. |
| Connexion avec un code d’appareil | `--device-code` | SSH, CI, shells sans interface graphique et environnements d’agents. |

Les environnements distants et non interactifs utilisent automatiquement le code d’appareil. Vérifiez sous quelle identité vous êtes connecté, avec vos scopes, votre espace de travail actif et vos autres espaces de travail :

```bash
phaseo whoami
phaseo whoami --json
```

## Gérer votre espace de travail

```bash
phaseo keys list
phaseo keys current

phaseo workspaces list
phaseo workspaces members <workspace-id-or-slug>

phaseo guardrails list
```

Utilisez `--json` lorsqu’un agent ou un script lit la sortie. La CLI couvre les tâches courantes du compte ; les limites des clés, les budgets, le BYOK, les règles de routage, les préréglages et l’identité se modifient dans le tableau de bord ou avec une clé de gestion. Consultez [Gérer Phaseo depuis un agent](../../developers/manage-from-an-agent) pour savoir quelles tâches la CLI couvre.

## Connecter un agent de code

Utilisez le nom de l’agent comme commande. La CLI demande une clé dédiée, que vous approuvez dans votre navigateur, et écrit la configuration de l’agent :

```bash
phaseo codex
phaseo claude-code
phaseo opencode
phaseo fx
phaseo deepseek-harness
phaseo pi
phaseo prime-agent
phaseo openclaw
phaseo hermes
phaseo aider
phaseo continue
phaseo zed
phaseo roo-code
phaseo kilo-code
phaseo cursor
```

Utilisez `--model`, `--catalog all|default` ou `--dry-run` selon vos besoins. `phaseo setup <agent>` et `phaseo integrations setup <agent>` fonctionnent aussi.

### Approuver la clé dans le navigateur

La première fois que vous configurez un agent, la CLI ouvre une page du tableau de bord Phaseo et affiche son lien. La page indique l’espace de travail, le nom de la clé, sa limite de dépenses mensuelle de $100 et son expiration au bout de 90 jours, ainsi que le fait que la CLI Phaseo l’a demandée. Choisissez **Approuver et créer la clé** : la CLI récupère la clé une seule fois et termine la configuration. Si vous choisissez **Refuser**, ou laissez la demande expirer au bout de 10 minutes, rien n’est créé.

Approuvez en étant connecté au tableau de bord avec le compte utilisé dans la CLI, en tant que propriétaire ou administrateur de l’espace de travail, et avec votre second facteur si vous en avez configuré un. En SSH ou en CI, ouvrez le lien affiché sur n’importe quel appareil où vous êtes connecté.

Pour utiliser plutôt une clé créée dans le tableau de bord, transmettez-la avec `--key <key>`, ou avec `--key-stdin` pour qu’elle n’apparaisse pas dans l’historique du shell. La CLI vérifie la clé et l’enregistre, et ne la révoque pas quand vous retirez l’agent.

Pour exécuter Cline, Kilo Code, oh-my-pi, Muse Code ou MiniMax Code avec des réglages temporaires supprimés à leur fermeture, utilisez le lanceur de session. Les options Phaseo se placent avant `--`, celles de l’agent après :

```bash
phaseo cline --model openai/gpt-5.6-terra -- --tui
phaseo kilo --model openai/gpt-5.6-terra
phaseo omp --model openai/gpt-5.6-terra
phaseo muse --model meta/muse-spark-1.3
phaseo minimax --model openai/gpt-5.6-terra
```

`phaseo run <cline|kilo|omp|muse|minimax>` est la forme longue. Ajoutez `--catalog all` pour lister tous les modèles texte Phaseo actifs, ou `--dry-run --json` pour prévisualiser sans créer de clé. Dans un terminal interactif, les lanceurs proposent d’installer un agent manquant (MiniMax Code utilise son installateur PowerShell officiel sous Windows ; Muse Code doit être installé à la main sous Windows). Utilisez `--skip-install` lorsque vous gérez l’agent vous-même.

[Agents de code](./coding-assistants.mdx) liste chaque agent, ce que fait sa commande et son guide.

## Écrire des scripts avec la CLI

Les commandes avec `--json` affichent une sortie structurée simple, sans couleurs ni indicateurs de progression. Ailleurs, les indicateurs de progression s’écrivent sur `stderr` et effacent leur ligne une fois terminés.

| Variable | Effet |
| --- | --- |
| `NO_COLOR` | Désactive les couleurs. |
| `TERM=dumb` | Désactive les animations. Un `stderr` qui n’est pas un TTY a le même effet. |
| `FORCE_COLOR=1` | Force les couleurs lorsqu’un terminal intermédiaire les prend en charge sans signaler de TTY. |

## Comment la CLI protège les identifiants

- Les sessions sont stockées dans le magasin d’identifiants du système d’exploitation. Ne définissez `PHASEO_SESSION_BACKEND=file` que si aucun magasin d’identifiants n’est disponible ; les jetons d’actualisation sont alors conservés dans un fichier en clair aux permissions restreintes.
- `phaseo logout` révoque le jeton d’actualisation stocké avant d’effacer l’état local.
- Les clés de gestion exigent des capacités explicites. Les clés d’inférence sont limitées par les garde-fous, les politiques de routage et les réglages de l’espace de travail, et non par des scopes.

## Applications OAuth

Phaseo utilise un seul serveur d’autorisation OAuth pour la CLI, les applications créées par les utilisateurs et les clients MCP enregistrés dynamiquement. La CLI utilise la connexion par navigateur ou par appareil, avec des jetons d’actualisation renouvelés à chaque usage. Les clients tiers utilisent le code d’autorisation avec PKCE, des scopes explicites, le consentement par espace de travail et, en option, la liaison à une ressource protégée. Ils reçoivent un jeton d’accès révocable valable 7 jours et un jeton d’actualisation renouvelé à chaque usage, valable 90 jours après sa dernière utilisation ; consultez [Créer un Workbench Next.js avec OAuth](../../cookbook/build-an-oauth-nextjs-workbench) pour le fonctionnement de l’actualisation. Approuver à nouveau la même application renouvelle sa clé au lieu d’en ajouter une deuxième.

OAuth pour les tiers est activé sur l’API Phaseo hébergée. Les déploiements de l’API auto-hébergés et de préversion le laissent désactivé, sauf si `PHASEO_THIRD_PARTY_OAUTH_ENABLED` a une valeur vraie : `1`, `true`, `yes` ou `on`, sans distinction de casse et en ignorant les espaces autour.

```bash .env
PHASEO_THIRD_PARTY_OAUTH_ENABLED=true
```

L’activer expose la gestion des applications OAuth créées par les utilisateurs et l’enregistrement dynamique des clients ; vérifiez donc d’abord vos réglages d’URI de redirection, de consentement, de secret client, de limite de débit et d’autorisation des espaces de travail.

## Mettre à jour

```bash
phaseo update
```

Cette commande lance la mise à jour avec le gestionnaire de paquets qui a servi à installer la CLI. Pour mettre à jour à la main :

<CodeGroup>

```bash npm
npm install -g @phaseo/cli@latest
```

```bash pnpm
pnpm add -g @phaseo/cli@latest
```

```bash yarn
yarn global add @phaseo/cli@latest
```

```bash bun
bun add -g @phaseo/cli@latest
```

</CodeGroup>
