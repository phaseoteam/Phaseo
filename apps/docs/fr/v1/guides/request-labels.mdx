Envoyez un en-tête `X-Phaseo-Metadata` pour étiqueter une requête avec des libellés clé/valeur tels que `team=support`, puis filtrez les dépenses et les journaux selon ces libellés. Utilisez les libellés lorsque vous avez besoin d’une dimension de coût plus fine qu’une clé API ou qu’une application. Ils ne modifient pas la requête au modèle et ne sont pas transmis aux fournisseurs.

```bash
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -H 'X-Phaseo-Metadata: {"labels":[{"key":"team","value":"support"},{"key":"environment","value":"production"}]}' \
  -d '{
    "model": "openai/gpt-6-astra",
    "input": "Summarize this ticket."
  }'
```

Les SDK TypeScript et Python acceptent les en-têtes personnalisés : vous pouvez donc définir le même en-tête une seule fois sur le client.

Pour étiqueter automatiquement les requêtes selon leur contenu, utilisez les [classificateurs de requêtes](/fr/v1/guides/request-classifiers). Leurs réponses sont enregistrées comme libellés de requête et se filtrent de la même façon.

## Règles des libellés

| Règle | Limite |
| --- | --- |
| Libellés par requête | Jusqu’à 32, chacun avec une clé unique |
| Clé | 1 à 64 caractères : lettres, chiffres, `_`, `.`, `:`, `-` |
| Valeur | Chaîne de 1 à 256 caractères, sans caractères de contrôle |
| Taille de l’en-tête | Jusqu’à 8 Kio |
| Clé réservée | `phaseo.classifier` n’est définie que par les appels de classificateur de Phaseo |

Les espaces en début et en fin des clés et des valeurs sont supprimés. Un en-tête mal formé, une clé en double ou un libellé qui enfreint ces règles fait échouer la requête avec `400 validation_error`, motif `invalid_request_metadata`, avant l’appel d’un modèle.

Ne placez pas de prompts, de secrets, d’adresses e-mail ni d’autres données personnelles dans les libellés.

## Filtrer les dépenses par libellé

Passez à la fois `label_key` et `label_value` à l’endpoint d’analyse :

```text
GET /v1/analytics?label_key=team&label_value=support
```

La réponse a le même format de dépenses regroupées que les analyses non filtrées, mais ne compte que les requêtes portant exactement cette paire de libellés. N’envoyer qu’un seul des deux paramètres renvoie `400 invalid_request`.
