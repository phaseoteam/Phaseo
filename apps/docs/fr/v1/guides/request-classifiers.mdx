Définissez une taxonomie, par exemple le service, le public ou le type de tâche, ainsi qu’un modèle pour l’appliquer : Phaseo étiquette chaque requête terminée avec les réponses de ce modèle. Chaque réponse est enregistrée comme [libellé de requête](/fr/v1/guides/request-labels) ; vous filtrez et regroupez donc les journaux, l’utilisation et les analyses selon elle, exactement comme les libellés envoyés par votre code. Utilisez un classificateur lorsque votre code ne connaît pas la catégorie : à qui un prompt s’adresse, quel type de travail un agent effectue, ou si une requête touche un sujet réglementé.

<Note>
Les classificateurs de requêtes sont en bêta. Les propriétaires et les administrateurs les gèrent dans **Paramètres → Classificateurs** ou avec l’API de gestion `/v1/classifiers`, à l’aide d’une [clé de gestion](/fr/v1/developers/management-api-keys) dotée des portées `classifiers:*`.
</Note>

## Comment une requête est classée

1. La requête se termine et sa réponse est renvoyée à votre application. La classification n’ajoute jamais de latence.
2. Phaseo construit une transcription de la requête : instructions système, messages, noms des outils (pas leurs schémas) et résultats des outils. Chaque tour est limité à 4 000 caractères, et les secrets tels que les clés API sont masqués. Si le classificateur inclut la réponse, la sortie générée est aussi ajoutée.
3. Le modèle de classification choisit parmi vos valeurs. Toute réponse en dehors de celles-ci est écartée (consultez [Choisir un modèle](#choose-a-model)).
4. Les réponses sont enregistrées comme libellés sur la requête, avec le niveau de confiance de chaque réponse, avant que la requête n’apparaisse dans vos journaux.

Les classificateurs s’exécutent sur les requêtes `chat/completions`, `responses` et `messages` réussies. Si la classification échoue ou expire, la requête est tout de même journalisée, simplement sans ces libellés.

## Créer un classificateur

Partez d’un préréglage dans le tableau de bord ou envoyez vous-même la taxonomie :

```bash
curl https://api.phaseo.app/v1/classifiers \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Department",
    "model": "google/gemini-2.5-flash-lite",
    "dimensions": [{
      "key": "department",
      "name": "Department",
      "allow_other": true,
      "values": [
        { "value": "engineering", "description": "Writing, reviewing, or debugging code" },
        { "value": "legal", "description": "Contracts, policies, and compliance" },
        { "value": "sales" },
        { "value": "support" }
      ]
    }],
    "sample_rate": 0.25,
    "monthly_budget_usd": 20
  }'
```

| Champ | Signification |
| --- | --- |
| `dimensions` | 1 à 12 questions. Chaque `key` devient la clé du libellé ; chaque dimension liste 2 à 50 valeurs (1 avec `allow_other`). |
| `multiple` | Autorise plusieurs valeurs pour une dimension. Chaque valeur devient un libellé distinct avec la même clé. |
| `allow_other` | Permet au modèle de répondre `other` lorsque rien ne convient. |
| `instructions` | Consignes supplémentaires ajoutées au prompt de classification, jusqu’à 8 000 caractères. |
| `sample_rate` | Part des requêtes éligibles à classer, de `0.0001` à `1`. |
| `sample_by` | `request` échantillonne chaque requête. `session` inclut ou exclut une session en bloc et réutilise ses réponses pendant une heure : une longue exécution d’agent n’est donc classée qu’une fois. |
| `input_scope` | `prompt` classe la requête. `prompt_and_response` montre aussi la réponse au modèle. |
| `scope` | Ne classe que les requêtes provenant de ces `key_ids`, `app_ids` ou `models`, jusqu’à 50 de chaque. |
| `monthly_budget_usd` | Met le classificateur en pause pour le reste du mois UTC une fois ce montant dépensé. |

Un espace de travail peut avoir jusqu’à cinq classificateurs. Les modifications atteignent le Gateway en une minute environ.

## Choisir un modèle

N’importe quel modèle texte ou [modèle de décision](/fr/v1/api-reference/endpoint/decisions) peut classer. Phaseo choisit comment l’interroger selon ce que prennent en charge les fournisseurs du modèle :

| Modèle | Comment il est interrogé |
| --- | --- |
| Modèle texte avec sorties structurées | Une requête `responses` avec un schéma JSON strict, de sorte que chaque réponse soit l’une de vos valeurs. |
| Modèle de décision | Une requête `decisions` avec une question à choix par dimension. Une dimension avec `multiple` pose une question oui/non par valeur et conserve chaque valeur dont la probabilité est d’au moins 0,5 (si un classificateur nécessitait plus de 128 questions, une telle dimension reçoit à la place sa seule meilleure valeur). La confiance est la probabilité propre du modèle. |
| Autres modèles texte | Une requête `responses` qui demande le même JSON dans le prompt. Les réponses hors de vos valeurs sont écartées, si bien qu’une dimension peut rester plus souvent sans libellé. C’est aussi la solution de repli lorsqu’un fournisseur refuse le schéma. |

Un petit modèle rapide suffit généralement. Utilisez **Essayer sur un exemple** dans l’éditeur de classificateur pour vérifier un modèle avant d’enregistrer.

## Filtrer et regrouper selon les résultats

Les réponses des classificateurs sont des libellés de requête ordinaires :

- Dans **Journaux** et **Utilisation**, filtrez selon un libellé tel que `department` = `legal`.
- Avec l’API, utilisez `label_key` et `label_value` :

```text
GET /v1/analytics?label_key=department&label_value=legal
```

- Les destinations [Diffusion](/fr/v1/guides/integrations/observability) reçoivent les libellés comme attributs de span `phaseo.label.<key>`.

Si votre code envoie déjà un libellé avec la clé d’une dimension, Phaseo conserve votre valeur et ignore cette dimension. Lorsque deux classificateurs utilisent la même clé, celui créé en premier l’emporte.

## Coût et confidentialité

- Chaque classification est une requête distincte au modèle de classification, effectuée avec la même clé API ou le même jeton OAuth que la requête d’origine. Elle est facturée au prix normal de ce modèle et suit les paramètres de fournisseur, de conservation des données et BYOK de votre espace de travail.
- Les requêtes de classification portent le libellé `phaseo.classifier` défini sur l’identifiant du classificateur, ce qui vous permet de voir leurs dépenses dans **Utilisation**. Elles ne sont pas elles-mêmes classées et ne comptent pas dans vos politiques de limite de débit.
- Limitez les coûts avec un petit modèle rapide, un taux d’échantillonnage, l’échantillonnage par session, une portée ou un budget mensuel.
- La transcription n’est envoyée qu’au modèle de classification. La requête de classification est journalisée comme toute autre requête : la conservation de son entrée suit donc les paramètres de journalisation de votre espace de travail.
