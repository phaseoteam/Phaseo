Consultez cette page si votre première intégration Phaseo concrète est en Python et que vous cherchez un point de départ pratique pour une CLI, un worker ou un service backend.

**Objectif :** Exécuter les routes de contrôle et de génération de Phaseo depuis une petite application en ligne de commande écrite en Python.

**Résultat :** Une CLI avec peu de dépendances, que vous pouvez adapter à un worker, un script ou une intégration backend.

## Projet d’exemple

- GitHub : [examples/gateway-python-quickstart](https://github.com/phaseoteam/Phaseo/tree/main/examples/gateway-python-quickstart)
- Chemin local dans le dépôt : `examples/gateway-python-quickstart`

## Fonctionnement de l’application

- prend en charge des routes de contrôle telles que :
  - `GET /v1/health`
  - `GET /v1/models`
  - `GET /v1/providers`
- prend en charge des routes de génération telles que :
  - `POST /v1/responses`
  - `POST /v1/chat/completions`
  - `POST /v1/embeddings`
  - ainsi que plusieurs autres points de terminaison

## Pourquoi cet exemple est utile

Il fournit :

- une référence orientée Python sans dépendances tierces
- des corps de requête et un traitement des réponses explicites
- un modèle pratique pour les workers, les scripts et les outils internes

## Prérequis

- Python 3
- une clé API Phaseo

## Exécuter l’exemple

```bash
cd examples/gateway-python-quickstart
cp .env.example .env.local
```

Définissez :

- `PHASEO_API_KEY`

Puis essayez :

```bash
python quickstart.py smoke
python quickstart.py responses --prompt "Return exactly: integration_ok"
python quickstart.py --help
```

## Vérifier le résultat

- Le mode de test rapide confirme que l’API est accessible.
- La commande Responses affiche `integration_ok`.
- `--help` répertorie les commandes disponibles sans envoyer de requête.
- Les erreurs d’authentification et de l’API sont clairement affichées dans le terminal.

## Éléments à examiner dans le code

- le chargement des variables d’environnement
- la façon dont la CLI distribue les commandes
- la construction des différents corps de requête
- la gestion séparée des routes asynchrones de vidéo et de musique et des routes de texte à réponse unique

## Adapter l’exemple

- supprimez les points de terminaison dont votre service n’a pas besoin
- conservez un seul utilitaire de requête au lieu de dupliquer les en-têtes
- passez au SDK Python si vous souhaitez ensuite utiliser un client de plus haut niveau
