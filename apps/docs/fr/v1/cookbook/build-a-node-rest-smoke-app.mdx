Exécutez un script Node.js sans dépendance qui appelle Phaseo avec un simple `fetch`, pour voir chaque requête et chaque réponse. À la fin, vous disposez d’un test rapide à lancer avant un déploiement : il vérifie que l’API répond, liste les modèles et envoie une requête à Responses, Chat Completions et Embeddings.

Le script est illustratif : il affiche chaque statut HTTP mais se termine toujours avec `0`. Ajoutez donc la vérification du code de sortie décrite dans [Utiliser le script comme contrôle de déploiement](#use-it-as-a-deploy-check) avant de vous y fier en CI.

Pour qu’un agent de codage crée le même script de zéro, collez ce prompt :

Create a script-based app that:

## Ce que le script appelle

L’exemple est [examples/gateway-node-quickstart](https://github.com/phaseoteam/Phaseo/tree/main/examples/gateway-node-quickstart) : un seul fichier, `index.mjs`, sans dépendance.

| Mode | Appels | Consomme des crédits |
| --- | --- | --- |
| `npm run smoke` | `GET /v1/health`, `GET /v1/models` | Non |
| `npm run start` | Les deux précédents, puis `POST /v1/responses`, `POST /v1/chat/completions`, `POST /v1/embeddings` | Oui |

Les appels texte envoient `Return exactly: integration_ok` à `PHASEO_MODEL` (par défaut `openai/gpt-5.6-sol`). L’appel d’embeddings utilise `google/gemini-embedding-2`.

## Lancer le script

Il vous faut Node.js 18 ou plus récent, pour le `fetch` intégré, et une clé API Phaseo.

<Steps>
<Step title="Créer .env.local">

Le script charge `.env.local` depuis le dossier où vous le lancez, sans aucun package. L’exemple ne fournit pas de `.env.example` ; créez donc le fichier :

```bash .env.local
PHASEO_API_KEY=phaseo_v1_sk_...
# Facultatif
PHASEO_MODEL=openai/gpt-6-astra
PHASEO_BASE_URL=https://api.phaseo.app/v1
PHASEO_APP_TITLE=My smoke test
PHASEO_HTTP_REFERER=https://myapp.example
```

Les variables déjà définies dans votre shell l’emportent sur le fichier.

</Step>
<Step title="Lancer le mode rapide">

```bash
cd examples/gateway-node-quickstart
npm run smoke
```

</Step>
<Step title="Lancer le mode complet">

```bash
npm run start
```

</Step>
</Steps>

## Vérifier que tout fonctionne

Chaque appel affiche un bloc comme celui-ci :

```text
=== Health ===
HTTP 200
{ ... }
```

- `Health` et `Models` affichent `HTTP 200`, et `Models` liste au moins un modèle.
- Lors de l’exécution complète, les blocs Responses et Chat Completions contiennent `integration_ok`.
- Avec une clé erronée, les blocs de génération affichent `HTTP 401` et le corps de l’erreur au lieu de la masquer.
- Les requêtes apparaissent dans **Paramètres → Utilisation → Journaux**.

## Utiliser le script comme contrôle de déploiement

`request()` renvoie `{ status, ok, payload }`, mais rien ne vérifie `ok`. Ajoutez une ligne au début de `print()` pour que le script se termine avec `1` dès qu’un appel a échoué :

```js index.mjs
function print(title, result) {
  if (!result.ok) process.exitCode = 1;
  console.log(`\n=== ${title} ===`);
  // ...le reste est inchangé
}
```

Réduisez le script aux routes qu’utilise votre service, et passez au [SDK TypeScript](../sdk-reference/client/overview) si vous préférez ne pas construire les payloads à la main.
