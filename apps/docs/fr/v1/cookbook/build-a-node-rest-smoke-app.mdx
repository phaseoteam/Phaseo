Utilisez cette page pour créer une intégration Node minimale et voir clairement chaque requête HTTP.

**Objectif:** Vérifier l’état de Phaseo, la découverte des modèles et une requête de génération en HTTP direct.

**Résultat:** Un script avec peu de dépendances que vous pouvez conserver comme test rapide de déploiement ou d’intégration.

## Projet d’exemple

- GitHub : [examples/gateway-node-quickstart](https://github.com/phaseoteam/Phaseo/tree/main/examples/gateway-node-quickstart)
- Chemin du dépôt local : `examples/gateway-node-quickstart`

## Fonctionnement de l’application

- appelle `GET /v1/health`
- appelle `GET /v1/models`
- teste des routes de génération comme `POST /v1/responses`
- fournit une référence HTTP directe pour les tests rapides, les scripts et les vérifications backend

## Quand utiliser cet exemple

Commencez ici si :

- vous voulez déboguer directement les appels API bruts
- vous ne voulez pas encore d’abstraction SDK
- vous créez un script, un worker ou une CLI plutôt qu’une interface Web

## Prérequis

- Node.js avec la prise en charge intégrée de `fetch`
- une clé API Phaseo

## Exécuter l’exemple

```bash
cd examples/gateway-node-quickstart
cp .env.example .env.local
```

Définissez :

- `PHASEO_API_KEY`

Exécutez ensuite l’une de ces commandes :

```bash
npm run smoke
```

or:

```bash
npm run start
```

## Vérifier le résultat

- Le mode de test rapide confirme que l’API est accessible.
- La découverte des modèles renvoie au moins un modèle.
- L’exécution complète affiche une réponse de génération réussie.
- Les erreurs d’authentification et les réponses autres que 200 génèrent des messages clairs dans le terminal.

## Points à examiner dans le code

- comment le script charge `.env.local`
- comment l’en-tête d’autorisation est ajouté
- comment chaque requête est construite explicitement
- comment les réponses autres que 200 sont affichées au lieu d’être ignorées

## Personnaliser l’exemple

- limitez le script aux routes réellement nécessaires à votre service
- regroupez le code de requête partagé dans une fonction si plusieurs scripts en ont besoin
- passez au SDK TypeScript si les requêtes HTTP directes deviennent répétitives
