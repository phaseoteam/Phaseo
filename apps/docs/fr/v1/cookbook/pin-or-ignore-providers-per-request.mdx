---
title: "Épingler ou ignorer des fournisseurs pour une requête"
icon: "pin"
description: "Utilisez les paramètres fournisseur d’une requête pour imposer un ordre de préférence, limiter le groupe de fournisseurs ou en écarter un."
---

Ajoutez un objet `provider` à une requête pour changer les fournisseurs qui la servent, sans toucher aux valeurs par défaut de l’espace de travail ni aux préréglages. À la fin, vous savez préférer un ordre, garder une requête dans une liste d’autorisation ou ignorer un fournisseur, et voir dans la réponse quel fournisseur a répondu.

Ces formes de requête sont prêtes pour la production. Les slugs de fournisseur sont des exemples réels ; consultez la page du modèle pour connaître les fournisseurs qui servent votre modèle.

| Champ | Effet | Exemple |
| --- | --- | --- |
| `order` | Essaie ces fournisseurs d’abord, puis le reste du groupe éligible | `["anthropic-us", "anthropic"]` |
| `only` | Garde la requête dans cette liste | `["openai", "openai-eu"]` |
| `ignore` | Écarte ces fournisseurs pour cette requête | `["novita"]` |
| `sort` | Classe les fournisseurs restants par `price`, `latency` ou `throughput` | `"price"` |

Pour utiliser exactement un fournisseur et désactiver le repli vers d’autres fournisseurs, placez-le plutôt devant l’ID du modèle : voir [Épingler un fournisseur](../guides/routing-and-fallbacks#pin-one-provider).

## Essayer les fournisseurs dans un ordre défini

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-sonnet-5.5",
    "input": "Write a concise launch summary.",
    "provider": {
      "order": ["anthropic-us", "anthropic"]
    },
    "meta": true
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "anthropic/claude-sonnet-5.5",
  input: "Write a concise launch summary.",
  provider: {
    order: ["anthropic-us", "anthropic"],
  },
  meta: true,
});

console.log(response.meta?.routing); // { selected_provider: "anthropic-us", ... }
```

```python Python
import os

from phaseo import Phaseo

client = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

response = client.generate_response(
    {
        "model": "anthropic/claude-sonnet-5.5",
        "input": "Write a concise launch summary.",
        "provider": {
            "order": ["anthropic-us", "anthropic"],
        },
        "meta": True,
    }
)

print(response["meta"]["routing"]["selected_provider"])
```
</CodeGroup>

`meta: true` ajoute `meta.routing.selected_provider` à la réponse, ce qui permet de vérifier le résultat sans ouvrir les journaux.

## Garder une requête dans une liste d’autorisation

Envoyez `only`, et éventuellement `sort` pour classer les fournisseurs de cette liste :

```json
{
  "model": "openai/gpt-5.6-luna",
  "input": "Extract the action items.",
  "provider": {
    "only": ["openai", "openai-eu"],
    "sort": "price"
  }
}
```

Si aucun des fournisseurs listés ne sert le modèle, la requête échoue au lieu de sortir de la liste.

## Ignorer un fournisseur

Envoyez `ignore` quand un fournisseur est dégradé, ou pendant que vous testez un autre chemin :

```json
{
  "model": "meta/llama-4-maverick",
  "input": "Summarize the transcript.",
  "provider": {
    "ignore": ["novita"]
  }
}
```

## Les combiner

Utilisez `only` pour le groupe, `order` pour la préférence à l’intérieur, et `sort` pour le reste. Cet exemple garde une requête sur Google Vertex, essaie d’abord la région UE, puis classe par latence :

```json
{
  "model": "anthropic/claude-sonnet-5.5",
  "input": "Summarize the incident in one sentence.",
  "provider": {
    "only": ["google-vertex", "google-vertex-eu"],
    "order": ["google-vertex-eu"],
    "sort": "latency"
  }
}
```

## Vérifier où la requête est allée

Ouvrez la requête dans **Paramètres → Utilisation → Journaux** et dépliez **Observabilité du routage**. Vous y voyez les fournisseurs exclus avant le classement et la raison, ainsi que les candidats classés avec leurs scores ; [Expliquer une décision de routage](../guides/routing-and-fallbacks#explain-a-routing-decision) décrit chaque champ.

Utilisez les règles au niveau de la requête pour des ajustements temporaires, propres à un appelant ou liés à un parcours utilisateur. Dès que les mêmes règles apparaissent dans plusieurs services, déplacez-les dans un [préréglage](../guides/presets), où elles limitent aussi les fournisseurs qu’un repli peut utiliser. Pour comparer les classements, voir [Trier les fournisseurs](./sort-providers-by-price-latency-or-throughput).
