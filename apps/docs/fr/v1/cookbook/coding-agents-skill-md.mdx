Ajoutez un `SKILL.md` à votre dépôt pour que les agents de codage appellent Phaseo comme votre projet l’attend : même URL de base, même variable de clé, même endpoint, modèles approuvés et journalisation. À la fin, vous avez installé les skills Phaseo publics, un skill de projet par-dessus, et un module client partagé vers lequel pointe ce skill.

Le skill et le module ci-dessous sont prêts pour la production une fois les ID de modèle et les noms de préréglage remplacés par les vôtres.

<Steps>
<Step title="Installer les skills Phaseo publics">

<Visibility for="humans">
Les skills publics couvrent le Gateway, les SDK, les préréglages, le routage et les migrations. Installez-les depuis [`phaseo.app/docs`](https://phaseo.app/docs/.well-known/agent-skills/index.json) :
</Visibility>

<Visibility for="agents">
Installez les skills Phaseo publics depuis [`phaseo.app/docs`](https://phaseo.app/docs/.well-known/agent-skills/index.json) avant d’écrire des instructions propres au projet :
</Visibility>

```bash
npx skills add https://phaseo.app/docs --agent codex --skill '*'
```

Remplacez `--agent` par l’agent qu’utilise votre équipe. Ne gardez que les règles propres au projet dans votre propre `SKILL.md`.

</Step>
<Step title="Installer le SDK">

<CodeGroup>
```bash npm
npm install @phaseo/sdk
```

```bash pnpm
pnpm add @phaseo/sdk
```

```bash yarn
yarn add @phaseo/sdk
```

```bash bun
bun add @phaseo/sdk
```

```bash Python
pip install phaseo
```
</CodeGroup>

</Step>
<Step title="Ajouter un client partagé">

Les agents réutilisent plus fiablement une petite fonction évidente qu’un gros wrapper. Placez le client dans un seul module et importez-le partout :

```ts src/lib/phaseo.ts
import Phaseo from "@phaseo/sdk";

export const gateway = new Phaseo({
  apiKey: process.env.PHASEO_API_KEY!,
});
```

Gardez un seul chemin d’appel par surface utilisée, par exemple la génération de texte, les embeddings, la génération d’images ou la vidéo asynchrone.

</Step>
<Step title="Écrire le skill du projet">

Créez `SKILL.md` à la racine du dépôt ou dans le dossier de skills que lit votre agent (par exemple `.agents/skills/phaseo-project/SKILL.md`). L’agent lit les champs `name` et `description` du frontmatter pour décider quand charger le skill :

```md SKILL.md
---
name: phaseo-project
description: "How this repository calls Phaseo Gateway: client module, endpoint, approved models and presets, logging and async jobs. Use when adding or changing any Phaseo call in this repo."
---

# Phaseo in this repository

- Import the client from `src/lib/phaseo.ts`. Never create another one.
- The base URL is `https://api.phaseo.app/v1`. The key is in `PHASEO_API_KEY`; never hard-code it or send it to the browser.
- Use the Responses API (`POST /v1/responses`) for new text features.
- Approved models: `openai/gpt-6-astra` for drafts, `anthropic/claude-sonnet-5.5` for reviews. Ask before adding another.
- Prefer the `@support-triage` preset for support features; pass it as `model`.
- Log the response `id` and `model` on every call, and `generation_id` from error bodies.
- For async video jobs, store the returned ID and poll status until it is terminal.
- Validate any model-generated tool arguments before acting on them.
```

</Step>
</Steps>

## Vérifier que tout fonctionne

Demandez à votre agent d’ajouter une petite fonctionnalité Phaseo, par exemple « résumer un ticket avec Phaseo ». La modification doit importer `src/lib/phaseo.ts`, lire `PHASEO_API_KEY`, utiliser un modèle ou un préréglage approuvé, et journaliser l’ID de la réponse. Sinon, la `description` du skill ne correspond probablement pas à la demande : reprenez les mots que votre équipe utilise pour décrire la tâche.

## Que mettre dans le skill

Répondez aux questions qui font perdre le plus de temps à un agent, et à rien d’autre :

| Question | Exemple de réponse |
| --- | --- |
| Quelle famille d’endpoints ? | Responses pour le texte, Embeddings pour la recherche |
| Où sont les identifiants ? | `PHASEO_API_KEY`, côté serveur uniquement |
| Quels ID de modèle ou préréglages sont approuvés ? | Une courte liste, au format `org/model` |
| Que faut-il journaliser ? | L’`id` de la réponse, `model`, et `generation_id` en cas d’erreur |
| Comment suivre les tâches asynchrones ? | Stocker l’ID, interroger jusqu’à l’état final |

[Codex](../guides/integrations/codex), le [Vercel AI SDK](../guides/integrations/ai-sdk) et les [Exemples](../guides/examples) montrent les mêmes conventions dans chaque outil.
