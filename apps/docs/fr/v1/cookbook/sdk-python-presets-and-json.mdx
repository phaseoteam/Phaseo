Appelez un préréglage du tableau de bord depuis Python avec un JSON Schema, puis validez la réponse et journalisez les ID nécessaires pour la déboguer. À la fin, vous avez un script qui envoie `"model": "@release-summary"`, reçoit `{"summary": ..., "risk_level": ...}`, et affiche les détails du fournisseur et des plugins pour cette requête.

Le script est prêt pour la production une fois le préréglage et le schéma remplacés par les vôtres. Gardez l’étape de validation : la réparation corrige la syntaxe, pas le contenu.

## Le construire

<Steps>
<Step title="Créer le préréglage">

Dans **Paramètres → Préréglages**, créez `release-summary` avec le prompt système, le modèle ou les modèles autorisés, les préférences de fournisseur, les réglages de raisonnement et la `temperature` que tous les appelants doivent partager. Le code Python n’envoie alors que ce qui varie. [Préréglages](../guides/presets) explique comment le préréglage se fusionne avec la requête.

</Step>
<Step title="Installer le SDK">

```bash
pip install phaseo
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="Écrire le script">

```python release_summary.py
import json
import os

from phaseo import Phaseo

# Créez un seul client et réutilisez-le.
gateway = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

SCHEMA = {
    "type": "object",
    "properties": {
        "summary": {"type": "string"},
        "risk_level": {"type": "string", "enum": ["low", "medium", "high"]},
    },
    "required": ["summary", "risk_level"],
    "additionalProperties": False,
}


def output_text(response: dict) -> str:
    return "".join(
        part.get("text", "")
        for item in response.get("output", [])
        if item.get("type") == "message"
        for part in item.get("content", [])
        if part.get("type") == "output_text"
    )


def validate(payload: dict) -> dict:
    if set(payload) != {"summary", "risk_level"}:
        raise ValueError(f"unexpected keys: {sorted(payload)}")
    if not isinstance(payload["summary"], str) or not payload["summary"]:
        raise ValueError("summary must be a non-empty string")
    if payload["risk_level"] not in ("low", "medium", "high"):
        raise ValueError("risk_level must be low, medium or high")
    return payload


response = gateway.generate_response(
    {
        "model": "@release-summary",
        "input": "Summarize the last 24 hours of deployment activity.",
        "text": {
            "format": {
                "type": "json_schema",
                "name": "release_summary",
                "strict": True,
                "schema": SCHEMA,
            }
        },
        "plugins": [{"id": "response-healing"}],
        "meta": True,
    }
)

if response.get("status") != "completed":
    raise RuntimeError(f"response {response.get('id')} ended as {response.get('status')}")

payload = validate(json.loads(output_text(response)))
meta = response.get("meta", {})

print("response_id:", response.get("id"))
print("model:", response.get("model"))
print("selected_provider:", meta.get("routing", {}).get("selected_provider"))
print("plugin_executions:", meta.get("plugin_executions"))
print(payload)
```

| Champ | Effet |
| --- | --- |
| `"model": "@release-summary"` | Utilise le préréglage. Il n’existe pas de champ `preset` séparé. |
| `text.format` | Demande ce JSON Schema. Avec Chat Completions, il se place dans `response_format` ; voir [Sorties structurées](../guides/structured-outputs). |
| `plugins` | Répare le JSON presque valide ; voir [réparation de réponse](./response-healing-for-structured-json). |
| `meta: true` | Ajoute `meta.routing` et `meta.plugin_executions` à la réponse. |

</Step>
<Step title="Le lancer">

```bash
python release_summary.py
```

</Step>
</Steps>

## Vérifier que tout fonctionne

Le script affiche l’ID de la réponse, le modèle et le fournisseur qui ont répondu, l’enregistrement du plugin, et un dict avec `summary` et l’une des valeurs `low`, `medium` ou `high`. Recherchez l’ID de la réponse dans **Paramètres → Utilisation → Journaux** pour voir la même requête avec le détail de son routage.

Un modèle hors des modèles autorisés du préréglage échoue avec `validation_error` (mot-clé `preset_model_not_allowed`). Une `ValueError` levée par `validate()` signifie que le JSON a été analysé mais que son contenu était incorrect : resserrez le schéma ou le prompt plutôt que d’ajouter des nouvelles tentatives.

## Déboguer avant de remplacer

Si une requête est routée autrement que prévu, ouvrez-la dans les journaux, lisez **Observabilité du routage** et l’enregistrement du plugin, et ne modifiez le préréglage qu’une fois que les journaux montrent ce qui s’est passé. Empiler des remplacements en ligne sur une requête va à l’encontre du préréglage ; si un appelant a vraiment besoin d’un autre comportement, donnez-lui son propre préréglage.
