Utilisez cette recette lorsque le modèle reste le même, mais que vous souhaitez que le gateway classe différemment les offres des fournisseurs pour une requête.

## Objectif

- Privilégiez le fournisseur le moins cher pour une requête.
- Privilégiez le fournisseur ayant la latence la plus faible pour les parcours interactifs.
- Privilégiez le fournisseur au débit le plus élevé pour la génération en masse.

## 1. Ajoutez `provider.sort` à la requête

Pour les requêtes textuelles, définissez le tri souhaité directement dans l’objet `provider`.

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "google/gemini-3.1-flash-lite",
    "input": "Give me one release-note bullet for the last deploy.",
    "provider": {
      "sort": "price"
    }
  }'
```

```typescript TypeScript SDK

  input: "Give me one release-note bullet for the last deploy.",
  provider: {
    sort: "price",
  },

```

Les tris de routage disponibles pour ce workflow sont :

- `price`
- `latency`
- `throughput`

## 2. Choisissez le tri adapté à la charge de travail

Utilisez :

- `price` lorsque le coût compte davantage que la latence de queue
- `latency` pour le chat, les copilotes et les outils avec intervention humaine
- `throughput` pour la génération à grande échelle ou les traitements de rattrapage

## 3. Comprenez ce que compare le gateway

Lorsque vous indiquez un tri explicite au niveau de la requête, le gateway classe les candidats de façon déterministe au lieu d’utiliser le mélange pondéré équilibré habituel.

Pour les modèles textuels :

- `price` compare les tarifs sur une base commune entre les fournisseurs admissibles
- si des compteurs de texte communs existent, le gateway privilégie les correspondances entre `input_text_tokens` et `output_text_tokens`
- `latency` utilise les données de latence les plus récentes des fournisseurs
- `throughput` utilise les mesures de débit les plus récentes

## 4. Gardez un ensemble de fournisseurs réaliste

Le tri fonctionne mieux lorsque vous réduisez d’abord le nombre de candidats, si nécessaire.

Par exemple, triez uniquement parmi un ensemble approuvé de fournisseurs :

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \

    "input": "Summarize the incident in one sentence.",
    "provider": {
      "only": ["google-vertex", "google-vertex-eu"],
      "sort": "latency"
```

## 5. Vérifiez le résultat du classement

Pour le débogage, examinez la requête dans **Gateway -> Utilisation** et recherchez :

- fournisseurs pris en compte
- fournisseurs classés
- les facteurs de score du routage liés au prix, à la latence ou au débit

Cela permet de vérifier facilement si le gateway a effectué le tri attendu.
