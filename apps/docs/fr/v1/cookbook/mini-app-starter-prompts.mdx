---
title: "Prompts de démarrage pour mini-applications"
icon: "code"
description: "Prompts à copier pour que des agents de codage créent de petites applications Phaseo avec HTTP direct, des SDK ou des runtimes d’agents."
---

Collez l’un de ces prompts dans Cursor, Claude Code, Codex ou un agent de codage similaire : il crée une petite application Phaseo qui fonctionne, puis indique ce qu’il a exécuté et ce qu’il n’a pas pu vérifier. Chaque prompt précise la surface d’intégration, les règles de sécurité et la vérification attendue.

Les applications obtenues sont des points de départ : relisez le code, en particulier la gestion des secrets et la validation des outils, avant de le déployer.

## Utiliser un prompt

<Steps>
  <Step title="Choisir la surface d’intégration">
    | Prompt | Appelle Phaseo avec |
    | --- | --- |
    | HTTP direct | `fetch` sur `https://api.phaseo.app/v1` |
    | SDK TypeScript | `@phaseo/sdk` |
    | SDK Python | `phaseo` |
    | Vercel AI SDK | `@phaseo/ai-sdk-provider` |
    | Agent SDK | `@phaseo/agent-sdk`, `phaseo-agent-sdk` ou l’Agent SDK de votre langage |
  </Step>
  <Step title="Remplacer les variables entre crochets">
    Renseignez les valeurs comme `[APP IDEA]`, `[FRAMEWORK]`, `[MODEL]` et `[LANGUAGE]` avant de coller le prompt dans votre agent de codage.
  </Step>
  <Step title="Demander une vérification, pas seulement du code">
    Gardez les lignes de vérification dans le prompt. Elles obligent l’agent à indiquer ce qu’il a réellement exécuté, ce qu’il a supposé et ce qui demande encore une configuration manuelle.
  </Step>
</Steps>

## Prompts prêts à l’emploi

<AccordionGroup>
  <Accordion title="Mini-application en HTTP direct" icon="globe">
    <Prompt
      description="Créer une petite application qui appelle Phaseo en **HTTP direct** plutôt qu’avec un SDK."
      icon="globe"
      actions={["copy", "cursor"]}
    >
{`You are implementing a small production-style demo app with Phaseo Gateway.

Build a [FRAMEWORK] mini app for [APP IDEA].

Requirements:
- Use raw HTTP requests, not a Phaseo SDK.
- Use the base URL https://api.phaseo.app/v1 and the Phaseo endpoint [ENDPOINT].
- Use model [MODEL].
- Read the API key from an environment variable named PHASEO_API_KEY and send it as Authorization: Bearer.
- Keep the app intentionally small: one main page, one server route or handler, and minimal styling.
- Show the user input, the request submission state, the model output, and any gateway error state.
- Add one example request payload in comments or docs so the integration is easy to audit later.

Implementation details:
- Use fetch.
- Keep the request body explicit instead of hiding fields behind abstractions.
- Add basic validation for empty input before making the API request.
- Handle non-200 responses cleanly and surface the response body when useful.
- Keep secrets server-side only.

Deliverables:
- The app code.
- A short README section explaining how to run it.
- A .env.example entry for PHASEO_API_KEY.

Verification:
- Run the local app if possible.
- Verify one successful request path.
- Report exactly what you verified, what you could not verify, and any remaining assumptions.`}
    </Prompt>
  </Accordion>

## Rendre les prompts plus efficaces

- Remplacez `[APP IDEA]` par une seule tâche utilisateur précise, pas par un pitch produit général.
- Remplacez `[MODEL]` par l’ID de modèle exact que l’agent doit utiliser.
- Indiquez si la sortie doit être du texte libre, du JSON strict, un chat ou un seul fichier généré.
- Mentionnez le framework d’interface et la cible de déploiement si vous les connaissez.
- Ajoutez une ou deux contraintes importantes, comme `EU-only providers`, `use streaming` ou `keep all secrets server-side`.

Les références du [SDK TypeScript et Python](../sdk-reference/client/overview) et de l’[Agent SDK](../sdk-reference/agent/overview) listent ce que fournit chaque package, pour que vous puissiez comparer le code de l’agent avec elles.
