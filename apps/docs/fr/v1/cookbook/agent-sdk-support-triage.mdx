Créez un agent de tri TypeScript dont le modèle, le prompt et les règles de fournisseur viennent d’un préréglage du tableau de bord, pour que le code ne gère que le flux de travail. À la fin, il renvoie une décision de tri en JSON strict, met en pause les cas qui nécessitent une personne, relance les appels au modèle un nombre limité de fois et journalise les échecs du Gateway avec les identifiants nécessaires pour les retrouver.

Le script est prêt pour la production une fois le préréglage créé et à condition de stocker les exécutions en pause, comme dans la [boucle durable](./agent-sdk-durable-loop). Une version packagée se trouve dans `packages/sdk/agent-sdk-ts/examples/support-triage-agent.ts`.

## Le construire

<Steps>
<Step title="Créer le préréglage">

Dans **Paramètres → Préréglages**, créez `support-triage` avec le modèle routé, les préférences de fournisseur, le prompt système du support et des paramètres de décodage stables. Le modèle doit prendre en charge la sortie JSON Schema. [Préréglages](../guides/presets) explique comment un préréglage se combine avec chaque requête.

</Step>
<Step title="Installer">

```bash
npm install @phaseo/agent-sdk zod
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="Écrire l’agent">

```ts triage-agent.ts
import { z } from "zod";
import { AgentGatewayError, createAgent, createGatewayAgentClient } from "@phaseo/agent-sdk";

const SupportTriageDecision = z
  .object({
    queue: z.enum(["billing", "reliability", "product", "security"]),
    severity: z.enum(["low", "medium", "high"]),
    needsHumanReview: z.boolean(),
    summary: z.string().min(1),
  })
  .strict();
type SupportTriageDecision = z.infer<typeof SupportTriageDecision>;

// `preset` devient le modèle `@support-triage` à chaque tour.
const supportTriageAgent = createAgent<string, SupportTriageDecision>({
  id: "support-triage-agent",
  preset: "support-triage",
  maxSteps: 3,
  parseOutput: (text) => JSON.parse(text),
  outputSchema: SupportTriageDecision,
  humanReview: ({ parsedOutput }) =>
    parsedOutput?.needsHumanReview
      ? { reason: "support_triage_review_required", payload: parsedOutput }
      : null,
});

const client = createGatewayAgentClient({
  clientOptions: { apiKey: process.env.PHASEO_API_KEY! },
  responseFormat: {
    type: "json_schema",
    name: "support_triage_decision",
    schema: {
      type: "object",
      properties: {
        queue: { type: "string", enum: ["billing", "reliability", "product", "security"] },
        severity: { type: "string", enum: ["low", "medium", "high"] },
        needsHumanReview: { type: "boolean" },
        summary: { type: "string" },
      },
      required: ["queue", "severity", "needsHumanReview", "summary"],
      additionalProperties: false,
    },
  },
  plugins: [{ id: "response-healing", mode: "strict" }],
});

try {
  const result = await supportTriageAgent.run({
    input: "Customer says webhook deliveries failed overnight and asks whether data was lost.",
    client,
    modelRetry: { maxRetries: 2, backoffMs: 250 },
    onEvent(event) {
      if (event.type === "model.retrying") console.log("retrying", event.attempt, event.error);
    },
  });

  if (result.run.status === "waiting_for_human") {
    // Stockez `result`, puis continuez une fois qu’un agent du support l’a examiné.
    console.log("Needs review:", result.run.pause?.payload);
  } else {
    console.log(result.output);
  }
} catch (error) {
  if (error instanceof AgentGatewayError) {
    console.error("Gateway request failed", {
      status: error.status,
      requestId: error.requestId,
      generationId: error.generationId,
      reason: error.reason,
      providerFailureDiagnostics: error.providerFailureDiagnostics,
      routingDiagnostics: error.routingDiagnostics,
    });
  }
  throw error;
}
```

</Step>
<Step title="L’exécuter">


</Step>

Pour terminer un cas en pause, continuez-le avec la décision du relecteur :

```ts
const continued = await supportTriageAgent.continueRun({
  run: storedResult,
  client,
  humanInput: "Approved. Finalize the triage decision.",
});
```

## Vérifier que ça fonctionne

Exécutez un ticket courant et un ticket à risque, puis vérifiez que :

- Dans **Paramètres → Utilisation → Journaux**, le modèle de la requête montre que le préréglage a été utilisé.
- Le cas à risque se termine sur `waiting_for_human`, avec la décision dans `pause.payload`.
- Un appel au modèle relancé est enregistré sur l’étape dans `modelAttempts`, et chaque nouvelle tentative journalise `model.retrying`.
- Une requête bloquée est journalisée avec son `requestId` et sa `reason`, et la même requête dans les journaux en indique la raison.

## Garder visibles les échecs du Gateway

N’absorbez pas les erreurs dans les callbacks de l’agent. Interceptez `AgentGatewayError` en bordure, journalisez ses identifiants et relancez l’erreur. Une fois qu’une exécution échoue, son état enregistré conserve les mêmes détails dans `run.errorDetails` et `steps[n].errorDetails`, pour qu’une tâche de reprise ultérieure puisse les lire une fois l’exception disparue.

Ces échecs viennent de la politique du Gateway, pas de l’agent : c’est donc dans la requête des journaux qu’il faut regarder :

| Échec | Où il apparaît |
| --- | --- |
| Un garde-fou bloque la requête | La section **Application des règles de protection** de la requête |
| Les modèles autorisés du préréglage rejettent le modèle | `validation_error` avec le mot-clé `preset_model_not_allowed` |
| Les identifiants ou l’activation des fournisseurs ne laissent aucun fournisseur | `providerFailureDiagnostics` et **Observabilité du routage** |
| La réparation ne parvient pas à produire du JSON conforme au schéma | L’enregistrement des plugins, puis `AgentSchemaValidationError` levée par `outputSchema` |
