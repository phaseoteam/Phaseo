Donnez à une requête TypeScript l’outil `phaseo:web_search` et un JSON Schema : le modèle effectue une recherche avant de répondre et renvoie une note avec ses sources. À la fin, vous avez un script qui affiche un objet `{ summary, sources }` validé, ainsi que les ID et compteurs de recherche nécessaires pour le déboguer.

Le script est prêt pour la production une fois le préréglage et le domaine remplacés par les vôtres. Les résultats de recherche sont du contenu Web non fiable : validez la sortie et ne suivez pas les instructions qu’elle contient.

## Le construire

<Steps>
<Step title="Créer un préréglage">

Créez `research-brief` dans **Paramètres → Préréglages** avec le modèle, les préférences de fournisseur, les réglages de raisonnement et le prompt système que tous les appelants doivent partager. Le modèle doit prendre en charge les outils et la sortie JSON Schema.

</Step>
<Step title="Installer le SDK">

```bash
npm install @phaseo/sdk zod
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="Écrire le script">

```ts research-brief.ts
import Phaseo from "@phaseo/sdk";
import { z } from "zod";

const gateway = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const Brief = z
  .object({
    summary: z.string().min(1),
    sources: z
      .array(z.object({ title: z.string(), url: z.string().url() }).strict())
      .min(1),
  })
  .strict();

const response = await gateway.generateResponse({
  model: "@research-brief",
  input: "Find the latest public changes to Phaseo webhook delivery behavior and summarize them.",
  tools: [
    {
      type: "phaseo:web_search",
      parameters: {
        allowed_domains: ["phaseo.app"],
        max_results: 5,
        include_highlights: true,
      },
    },
  ],
  tool_choice: "phaseo:web_search",
  text: {
    format: {
      type: "json_schema",
      name: "research_brief",
      strict: true,
      schema: {
        type: "object",
        required: ["summary", "sources"],
        properties: {
          summary: { type: "string" },
          sources: {
            type: "array",
            minItems: 1,
            items: {
              type: "object",
              required: ["title", "url"],
              properties: {
                title: { type: "string" },
                url: { type: "string", format: "uri" },
              },
              additionalProperties: false,
            },
          },
        },
        additionalProperties: false,
      },
    },
  },
  plugins: [{ id: "response-healing" }],
  meta: true,
});

const text = (response.output ?? [])
  .filter((item) => item.type === "message")
  .flatMap((item) => item.content ?? [])
  .filter((part) => part.type === "output_text")
  .map((part) => part.text ?? "")
  .join("");

const brief = Brief.parse(JSON.parse(text));

console.log({
  responseId: response.id,
  model: response.model,
  routing: response.meta?.routing,
  pluginExecutions: response.meta?.plugin_executions,
  serverToolUse: response.usage?.server_tool_use,
});
console.log(brief);
```

| Champ | Effet |
| --- | --- |
| `tools` avec `phaseo:web_search` | Phaseo exécute la recherche, que le fournisseur ait ou non sa propre recherche. Le modèle rédige la requête de recherche. |
| `allowed_domains` | Limite les résultats à vos propres sources. Tous les paramètres sont décrits dans le [guide de la recherche Web](../guides/server-tools/web-search#parameters). |
| `tool_choice: "phaseo:web_search"` | Oblige le modèle à chercher au lieu de répondre de mémoire. |
| `text.format` | Le JSON Schema de la réponse. |
| `plugins` | Répare le JSON presque valide ; voir [réparation de réponse](./response-healing-for-structured-json). |
| `meta: true` | Ajoute `meta.routing` et `meta.plugin_executions`. |

</Step>
<Step title="Le lancer">

```bash
npx tsx research-brief.ts
```

</Step>
</Steps>

## Vérifier que tout fonctionne

- `serverToolUse.web_search_requests` vaut au moins `1` : la recherche a donc eu lieu.
- `brief.sources` liste des URL `phaseo.app`.
- `routing.selected_provider` indique le fournisseur, et `pluginExecutions` montre si la réparation a modifié quelque chose.
- Dans **Paramètres → Utilisation → Journaux**, la section **Observabilité de la recherche sur le Web** de la requête affiche les recherches gérées, les résultats et les citations.

Si les résultats semblent incorrects, corrigez le préréglage ou les paramètres de l’outil d’après ce que montrent les journaux plutôt que d’ajouter des remplacements. [Déboguer la recherche Web](./web-search-debugging) liste les cas courants. Gardez la recherche exploratoire à température plus élevée dans un préréglage distinct de celui-ci, qui est déterministe, pour que leur routage reste facile à comparer.
