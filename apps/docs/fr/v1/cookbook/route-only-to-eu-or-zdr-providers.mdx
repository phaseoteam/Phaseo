Ajoutez des exigences de résidence et de <Tooltip tip="Conservation zéro des données : le fournisseur ne conserve ni les prompts ni les sorties.">ZDR</Tooltip> à l’objet `provider` d’une requête, et Phaseo retire toutes les offres fournisseurs qui n’y répondent pas avant de classer les autres. À la fin, un workflow ne s’exécute que sur des fournisseurs de l’UE ou compatibles ZDR, sans changer la règle de tout l’espace de travail.

La requête est prête pour la production. Si aucun fournisseur du modèle ne remplit toutes les exigences, la requête échoue avant qu’un fournisseur soit appelé ; vérifiez donc d’abord la disponibilité.

| Champ | Ne garde que les fournisseurs qui |
| --- | --- |
| `required_execution_region: "eu"` | Exécutent le modèle dans l’UE |
| `required_data_region: "eu"` | Traitent les données des prompts et des complétions dans l’UE |
| `require_zero_data_retention: true` | Respectent les exigences de conservation zéro des données |

## Envoyer une requête restreinte

<Steps>
<Step title="Vérifier qu’un fournisseur est éligible">

Sur la page du modèle, les cartes des fournisseurs affichent les offres régionales comme **OpenAI EU** ou **Google Vertex EU**, la prise en charge de ZDR, ainsi que les notes et sources sur la politique de données de chaque fournisseur. Pour l’UE, vous pouvez aussi lister ce que sert le gateway UE :

```bash
curl https://eu.api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

</Step>
<Step title="N’ajouter que les exigences nécessaires">

Chaque exigence réduit le groupe de fournisseurs : la requête peut alors être routée vers une offre régionale plus chère, ou ne trouver aucun fournisseur. N’envoyez que ce que votre règle impose :

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5.6-luna",
    "input": "Summarize the ticket in one line.",
    "provider": {
      "required_execution_region": "eu",
      "required_data_region": "eu"
    },
    "meta": true
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "openai/gpt-5.6-luna",
  input: "Summarize the ticket in one line.",
  provider: {
    required_execution_region: "eu",
    required_data_region: "eu",
  },
  meta: true,
});

console.log(response.meta?.routing);
```

```python Python
import os

from phaseo import Phaseo

client = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

response = client.generate_response(
    {
        "model": "openai/gpt-5.6-luna",
        "input": "Summarize the ticket in one line.",
        "provider": {
            "required_execution_region": "eu",
            "required_data_region": "eu",
        },
        "meta": True,
    }
)

print(response["meta"]["routing"]["selected_provider"])
```
</CodeGroup>

Pour exiger aussi ZDR, ajoutez `"require_zero_data_retention": true`. Avec les trois, un modèle doit avoir au moins un fournisseur de l’UE qui respecte aussi ZDR.

</Step>
<Step title="Vérifier où elle s’est exécutée">

`meta.routing.selected_provider` indique le fournisseur qui l’a servie, par exemple `openai-eu`. La requête dans **Paramètres → Utilisation → Journaux** enregistre les régions exigées et le fournisseur sélectionné.

</Step>
</Steps>

## Choisir entre les champs de requête, le gateway UE et les réglages de l’espace de travail

| Utiliser | Quand |
| --- | --- |
| Ces champs de requête sur `api.phaseo.app` | La règle s’applique à un workflow, un client ou une requête. Tous les endpoints et fonctionnalités restent disponibles. |
| [`eu.api.phaseo.app`](../guides/regional-routing) | Toutes les requêtes texte d’un service doivent rester dans l’UE. Le nom d’hôte impose la région et refuse aussi les entrées média, les outils serveur Phaseo et les outils hébergés par les fournisseurs. Y envoyer un `required_execution_region` ou un `required_data_region` pour une autre région renvoie `400 validation_error` avec la raison `deployment_region_conflict`. |
| **Paramètres → Confidentialité** | La règle s’applique à toutes les requêtes de l’espace de travail. |

Le routage régional restreint les fournisseurs qui traitent l’appel au modèle. Ce n’est pas encore une garantie de résidence des données de bout en bout ; [Ce qui reste hors de la région](../guides/regional-routing#what-stays-outside-the-region) liste les systèmes partagés. Pour restreindre les fournisseurs sans règle de résidence, voir [Épingler ou ignorer des fournisseurs](./pin-or-ignore-providers-per-request).
