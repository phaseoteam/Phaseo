لا يفرض Gateway حاليًا حدًا منفصلًا للطلبات على مستوى المنصة. يأتي معظم تقييد المعدل من المزوّدين في المنبع.

## آلية عمل الحدود

- قد يفرض المزوّد الذي اختير للنموذج حدًا على معدل الطلبات.
- تخضع حركة BYOK للحدود المرتبطة بحسابك لدى المزوّد.
- يمكن للتوجيه والبدائل الاحتياطية في Gateway تقليل الإخفاقات، لكن قد تظل استجابات `429` واردة.

## التعامل مع استجابات `429`

- التزم بقيمة `Retry-After` إذا كانت موجودة.
- استخدم تراجعًا أسيًا مع إضافة عشوائية (jitter).
- حدّد عددًا أقصى للمحاولات وتعامل مع الإخفاق النهائي بسلاسة.

يمرّر Phaseo قيمة `Retry-After` بعد التحقق منها عندما يرسلها المزوّد الذي جرى التوجيه إليه. وفي طلبات BYOK، قد تُعاد تفاصيل حصة المزوّد أيضًا ضمن ترويسات `X-Phaseo-Upstream-RateLimit-*`. تُحذف ترويسات الحصة هذه عمدًا في الطلبات التي تستخدم مزوّدين مُدارين، لأنها تصف السعة المشتركة لـ Phaseo لا حصة عميل بعينه. ولا تُمرّر ترويسات المنبع الأخرى.

```ts
async function retryWithBackoff(run: () => Promise<Response>, maxRetries = 4) {
  for (let attempt = 0; attempt <= maxRetries; attempt += 1) {
    const response = await run();
    if (response.status !== 429) return response;

    const retryAfterHeader = response.headers.get("retry-after");
    const retryAfterMs = retryAfterHeader
      ? Number(retryAfterHeader) * 1000
      : Math.min(1000 * 2 ** attempt, 8000);

    await new Promise((resolve) => setTimeout(resolve, retryAfterMs));
  }

  throw new Error("Rate limit retries exhausted");
}
```

## المراقبة

- تتبّع معدّل استجابات `429` بحسب نقطة النهاية والنموذج.
- راقب تكرار التحويل إلى البدائل لاكتشاف الضغط على المزوّدين.
- استخدم مقاييس لوحة التحكم وسجلات تطبيقك معًا لتحليل الحوادث.
