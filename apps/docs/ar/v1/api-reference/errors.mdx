اعتمد في منطقك على `error.code` وحالة HTTP، لا على نص الرسالة. لكل أخطاء Phaseo جسم JSON واحد في جميع نقاط النهاية، وكائن `error` فيه (`code` و`message` و`type` و`param`) هو الشكل الذي تقرؤه حزم SDK المتوافقة مع OpenAI، لذا تحمل استثناءاتها رسالة Phaseo.

## الحقول الموجودة في كل خطأ

| الحقل | المحتوى |
| --- | --- |
| `error.code` | رمز قابل للقراءة آليًا، مثل `validation_error`. راجع [رموز الأخطاء](#error-codes). |
| `error.message` | شرح بلغة واضحة. |
| `error.type` | فئة الخطأ، وتُحدَّد من حالة HTTP. راجع [أنواع الأخطاء](#error-types). |
| `error.param` | حقل الطلب الذي سبّب الخطأ إن عرفه Phaseo، وإلا فالقيمة `null`. |
| `error.metadata` | اختياري. تفاصيل منظّمة مثل `reason` أو `failed_providers` أو `failed_statuses` أو `retry_after_seconds`. وتوجد القيم نفسها أيضًا في المستوى الأعلى. |
| `code` | مثل `error.code`. كانت الاستجابات القديمة تُرجع هذه السلسلة في `error`؛ اقرأ `code` إذا كان عميلك يتوقع سلسلة هناك. |
| `message` و`description` | النص نفسه الموجود في `error.message`. |
| `generation_id` | معرّف الطلب الذي تسجّله وتشاركه مع الدعم. |
| `status_code` | حالة HTTP. |
| `error_type` | `user` أو `system`. |
| `error_origin` | مصدر المشكلة: المتصل (`user`) أو Phaseo (`gateway`) أو مزوّد (`upstream`). |
| `details` | اختياري. تفاصيل التحقق عندما يكون جسم الطلب غير صالح. |

تضيف بعض الأخطاء سياقًا إضافيًا:

| الحقل | متى يظهر |
| --- | --- |
| `reason` | سبب فرعي محدد، مثل `all_candidates_failed` أو `no_provider_pricing`. |
| `provider_failure_diagnostics` | وصل الطلب إلى مزوّد وفشل. راجع [عندما يفشل مزوّد](#when-a-provider-fails). |
| `upstream_error` و`failure_sample` | ملخص بأفضل جهد لأول إخفاق لدى مزوّد. |
| `failed_providers` و`failed_statuses` و`attempt_count` | المزوّدون الذين جُرّبوا وما أعادوه. |
| `provider_candidate_diagnostics` و`provider_enablement` و`routing_diagnostics` | لم يتمكن أي مزوّد من خدمة النموذج على نقطة النهاية هذه. راجع [عندما لا يتوفر نموذج أو نقطة نهاية](#when-a-model-or-endpoint-is-not-available). |

<span id="error-types"></span>
## أنواع الأخطاء

يتبع `error.type` [أنواع الأخطاء الموثّقة لدى OpenAI](https://platform.openai.com/docs/guides/error-codes) ويُحدَّد من حالة HTTP:

| الحالة | `error.type` |
| --- | --- |
| `401` | `authentication_error` |
| `402` | `insufficient_quota` |
| `403` | `permission_error` |
| `404` | `not_found_error` |
| `429` | `rate_limit_error` |
| `408` و`500` و`502` ورموز 5xx الأخرى | `server_error` |
| `503` | `service_unavailable` |
| `529` | `overloaded` |
| `400` و`409` و`410` و`413` و`422` ورموز 4xx الأخرى | `invalid_request_error` |

تستخدم أخطاء `/v1/messages` الجسم نفسه، لذا تجد حزم SDK من Anthropic أيضًا `error.type` و`error.message`.

<span id="error-codes"></span>
## رموز الأخطاء

| `error.code` | الحالة | المعنى | ما الذي تفعله |
| --- | --- | --- | --- |
| `validation_error` | `400` | معامل أو جسم الطلب غير صالح. يسمّي `error.param` أول حقل غير صالح. | أصلح الطلب. |
| `invalid_json` | `400` | الجسم ليس JSON صالحًا. | أصلح الطلب. |
| `model_required` | `400` | لا يتضمن الطلب `model`. | أضف `model`. |
| `unsupported_model_or_endpoint` | `400` | لا يستطيع أي مزوّد خدمة هذا النموذج على نقطة النهاية هذه. | راجع [القسم أدناه](#when-a-model-or-endpoint-is-not-available). |
| `unsupported_modalities` | `400` | لا يقبل أي مسار أنواع الإدخال أو الإخراج الموجودة في الطلب. | غيّر النموذج أو المدخلات. |
| `byok_credentials_required` | `400` | لا يعمل المسار إلا بمفتاح المزوّد الخاص بك. | أضف [مفتاح مزوّد](./endpoint/provider-credentials-create.mdx) مؤهّلًا. |
| `upstream_error` | `400` أو `413` أو `422` | رفض كل المزوّدين الطلب بالحالة نفسها (السبب `upstream_rejected_request`). | أصلح الطلب؛ لن تفيد إعادة المحاولة. |
| `unauthorised` | `401` | المفتاح مفقود أو غير صالح. يوضح `reason` السبب. | تحقق من الترويسة `Authorization`. |
| `insufficient_funds` | `402` | لا تملك مساحة العمل رصيدًا كافيًا. | أضف رصيدًا. |
| `pricing_not_configured` | `402` | لا يوجد مزوّد لهذا النموذج لديه تسعير (السبب `no_provider_pricing`). | اختر نموذجًا آخر. |
| `guardrail_blocked` | `403` | حظر حاجز حماية أو سياسة وصول الطلب. | غيّر الطلب أو حاجز الحماية. |
| `model_region_unavailable` | `403` | لا يخدم أي مزوّد النموذج في المنطقة المطلوبة، أو من موقع المتصل. | خفّف شرط المنطقة أو اختر نموذجًا آخر. |
| `not_found` | `404` | نقطة النهاية أو المورد غير موجود. | تحقق من المسار والمعرّف. |
| `not_ready` | `409` | نتائج المهمة غير جاهزة بعد. | استطلع حالة المهمة. |
| `model_retired` | `410` | النموذج متقاعد ولا يخدمه أي مزوّد. | انتقل إلى `replacement_model`. راجع [القسم أدناه](#when-a-model-is-retired). |
| `payload_too_large` | `413` | الجسم أكبر مما تقبله نقطة النهاية. يعطي `max_bytes` الحد. | أرسل جسمًا أصغر أو ارفع ملفًا. |
| `key_limit_exceeded` | `429` | بلغ الطلب حدًا للمفتاح أو ميزانية أو حد الـ Gateway في الدقيقة. | راجع [حدود المعدل](./limits.mdx#key-limits-and-budgets). |
| `phaseo_free_model_limit_exceeded` | `429` | استُهلكت الحصة اليومية للنماذج المجانية (1,500 طلب افتراضيًا). | التزم بـ `Retry-After`، أو انتظر إعادة الضبط عند 00:00 UTC، أو استخدم نموذجًا مدفوعًا. |
| `rate_limit_exceeded` | `429` | استُنفدت [سياسة حد معدل](./limits.mdx#rate-limit-policies) لمساحة العمل. يحددها `policy_id` و`limit_scope`. | التزم بـ `Retry-After`، أو اطلب من مسؤول تغيير السياسة. |
| `spend_rule_blocked` | `429` | توجد [قاعدة إنفاق](../guides/spend-alerts.mdx) مضبوطة على الحظر ونشطة. | التزم بـ `Retry-After`، أو اطلب من مالك أو مسؤول رفع الحظر. |
| `upstream_error` | `429` | فرض كل مزوّد جُرّب حد معدل على الطلب. | التزم بـ `Retry-After`. تحمل طلبات BYOK أيضًا ترويسات `X-Phaseo-Upstream-RateLimit-*`. |
| `provider_capacity_exhausted` | `429` | كل مزوّد مؤهّل بلغ سعته القصوى (السبب `all_candidates_rate_limited`). | التزم بـ `Retry-After` عند وجوده، وإلا فتراجع قبل إعادة المحاولة. |
| `gateway_error` | `500` | فشل شيء داخل Phaseo. | أعد المحاولة مع تراجع تدريجي. |
| `not_implemented_yet` | `501` | العملية غير متاحة بعد. | لا تُعد المحاولة. |
| `upstream_error` | `502` | لم يستجب المزوّد استجابة صحيحة. | أعد المحاولة مع تراجع تدريجي. |
| `upstream_stream_failure` | `502` | طلب غير متدفق فشل مزوّده بعد أن بدأ التوليد. لا يُعاد أي إخراج جزئي ولا يُحتسب الطلب. | أعد المحاولة. |
| `provider_payment_required` | `502` | يحتاج حساب Phaseo لدى المزوّد إلى معالجة. | أعد المحاولة لاحقًا أو أبلغ عن المشكلة. |

## أعد المحاولة للأخطاء الصحيحة

| الحالة | إعادة المحاولة؟ |
| --- | --- |
| `400`–`499` باستثناء `429` | لا. أصلح الطلب أو المفتاح أو الوصول أولًا. |
| `429` | نعم. انتظر `Retry-After` (بالثواني أو تاريخ HTTP)، وإلا فاستخدم تراجعًا أُسّيًا مع تذبذب عشوائي. خطأ `key_limit_exceeded` بلا `Retry-After` لا يُعاد ضبطه من تلقاء نفسه، فلا تُعد المحاولة. |
| `500`–`599` | فقط عندما يكون تكرار العملية آمنًا. قد يكون إرسال غامض النتيجة قد أنشأ مهمة أو رسومًا بالفعل؛ ابحث عن المهمة المقبولة بدلًا من إرسالها مجددًا. |

حدّد عددًا أقصى للمحاولات ومهلة إجمالية. راجع [حدود المعدل](./limits.mdx) لمعرفة ترويسات حدود المعدل.

<span id="when-a-provider-fails"></span>
## عندما يفشل مزوّد

عندما يصل Phaseo إلى مزوّد ويفشل الطلب مع ذلك، يحتوي `provider_failure_diagnostics` على `category` و`hint` و`provider`. الفئات:

| `category` | المعنى |
| --- | --- |
| `credentials_not_configured` | لم تُعدّ بيانات اعتماد لهذا المسار. |
| `credentials_invalid_or_forbidden` | رُفضت بيانات الاعتماد. |
| `provider_access_missing` | لا يملك حساب المزوّد وصولًا إلى النموذج أو الميزة. |
| `region_or_project_restriction` | رفض المزوّد بسبب المنطقة أو المشروع. |
| `model_unavailable_for_endpoint` | لا يتيح المزوّد النموذج على نقطة النهاية هذه. |
| `rate_limited` | فرض المزوّد حد معدل على الطلب. |
| `server_error` | فشل المزوّد أو انتهت مهلته. |

<span id="when-a-model-or-endpoint-is-not-available"></span>
## عندما لا يتوفر نموذج أو نقطة نهاية

يمكن أن تتضمن أخطاء `unsupported_model_or_endpoint` الحقول `provider_candidate_diagnostics` و`provider_enablement` و`missing_pricing_providers` و`routing_diagnostics`. وتميّز معًا بين نموذج لم يُفعَّل بعد، ونموذج لا يدعم نقطة النهاية، وتسعير مفقود، وقيود الإطلاق التدريجي.

| الحقل | المعنى |
| --- | --- |
| `provider_candidate_diagnostics.totalProviders` | المزوّدون المعروفون للنموذج قبل تصفية نقاط النهاية. |
| `provider_candidate_diagnostics.supportsEndpointCount` | المزوّدون الذين يدعمون نقطة النهاية المطلوبة. |
| `provider_candidate_diagnostics.candidateCount` | المزوّدون المتبقون بعد فحوص المحوّلات. |
| `provider_candidate_diagnostics.droppedUnsupportedEndpoint` | المزوّدون المستبعدون لأنهم لا يدعمون نقطة النهاية. |
| `provider_candidate_diagnostics.droppedMissingAdapter` | أزواج المزوّد ونقطة النهاية المستبعدة لأن Phaseo لا يملك محوّلًا لنقطة النهاية تلك بعد. |
| `provider_enablement.capability` | القدرة المفروضة، مثل `video_generation`. |
| `provider_enablement.providersBefore` و`providersAfter` | المزوّدون قبل تصفية القدرات وبعدها. |
| `provider_enablement.dropped[].reason` | سبب استبعاد مزوّد، مثل `pricing_missing`. |
| `routing_diagnostics.filterStages[].stage` | مرحلة توجيه، مثل تصفية القدرات أو الإطلاق التدريجي أو حالة التوجيه. |
| `routing_diagnostics.filterStages[].beforeCount` و`afterCount` | المزوّدون قبل تلك المرحلة وبعدها. |
| `routing_diagnostics.filterStages[].droppedProviders[].reason` | سبب استبعاد مزوّد في تلك المرحلة. |

```json
{
  "error": {
    "code": "unsupported_model_or_endpoint",
    "message": "No provider is currently routable for endpoint \"responses\" on model \"example/model\".",
    "type": "invalid_request_error",
    "param": null
  },
  "code": "unsupported_model_or_endpoint",
  "generation_id": "G-unsupported123",
  "status_code": 400,
  "description": "No provider is currently routable for endpoint \"responses\" on model \"example/model\".",
  "provider_candidate_diagnostics": {
    "totalProviders": 3,
    "supportsEndpointCount": 2,
    "candidateCount": 1,
    "droppedUnsupportedEndpoint": ["provider-a"],
    "droppedMissingAdapter": [
      {
        "providerId": "provider-b",
        "endpoint": "responses"
      }
    ]
  },
  "provider_enablement": {
    "capability": "responses",
    "providersBefore": ["provider-b", "provider-c"],
    "providersAfter": ["provider-c"],
    "dropped": [
      {
        "providerId": "provider-b",
        "reason": "pricing_missing"
      }
    ]
  },
  "routing_diagnostics": {
    "filterStages": [
      {
        "stage": "provider_routing_status",
        "beforeCount": 1,
        "afterCount": 0,
        "droppedProviders": [
          {
            "providerId": "provider-c",
            "reason": "provider_status_not_ready"
          }
        ]
      }
    ]
  }
}
```

<span id="when-a-model-is-retired"></span>
## عندما يتقاعد نموذج

يظل النموذج المتقاعد متاحًا ما دام أي مزوّد يخدمه. وعندما لا يخدمه أي مزوّد، تفشل الطلبات بالحالة `410` والرمز `model_retired`:

```json
{
  "error": {
    "code": "model_retired",
    "message": "Model \"lab/old-model\" was retired on 2026-09-30 and no provider serves it any more. Use \"lab/new-model\" instead.",
    "type": "invalid_request_error",
    "param": null,
    "metadata": {
      "retired_at": "2026-09-30T00:00:00Z",
      "replacement_model": "lab/new-model"
    }
  },
  "code": "model_retired",
  "generation_id": "G-retired123",
  "status_code": 410,
  "reason": "model_retired_without_providers",
  "description": "Model \"lab/old-model\" was retired on 2026-09-30 and no provider serves it any more. Use \"lab/new-model\" instead.",
  "model": "lab/old-model",
  "retired_at": "2026-09-30T00:00:00Z",
  "replacement_model": "lab/new-model"
}
```

`model` هو النموذج الذي طلبته، و`retired_at` هو وقت تقاعده (أو `null`)، و`replacement_model` هو البديل المقترح (أو `null`).

لا تفيد إعادة المحاولة؛ غيّر معرّف النموذج. لإبقاء هذه الطلبات تعمل أثناء الترحيل، أضف البديل إلى قائمة `models` في الطلب أو فعّل توجيه النماذج المتقاعدة لمساحة العمل. راجع [إيقاف النماذج وتقاعدها](../guides/model-retirement.mdx).

## الأخطاء أثناء البث

إذا فشل الطلب قبل بدء البث، تتلقى جسم خطأ JSON الموضح أعلاه. وإذا فشل في منتصف البث، ينتهي البث بحدث الإخفاق الخاص بنقطة النهاية بدلًا من الإنهاء العادي:

| نقطة النهاية | حدث الإخفاق |
| --- | --- |
| Chat Completions | إطار `error` |
| Responses | `response.failed` (أو `error`) |
| Messages | حدث `error` |

تعامل مع الإخراج الجزئي على أنه غير مكتمل واعرض إعادة المحاولة. يحمل إطار `error` في Chat Completions كائن الخطأ نفسه، مع ضبط `error.type` بناءً على الرمز:

```json
{
  "object": "error",
  "message": "The upstream stream ended before the response completed.",
  "code": "upstream_stream_failure",
  "error": {
    "code": "upstream_stream_failure",
    "message": "The upstream stream ended before the response completed.",
    "type": "server_error",
    "param": null
  }
}
```

الطلب غير المتدفق الذي يفشل مزوّده في منتصف العمل يُرجع `502` مع `upstream_stream_failure`، لا استجابة جزئية. راجع [البث](../guides/streaming.mdx).

<span id="debug-a-request"></span>
## تصحيح طلب

أرسل كائن `debug` للحصول على تتبعات التوجيه والحمولات المتبادلة مع المزوّد:

```json
{
  "debug": {
    "enabled": true,
    "return_upstream_request": true,
    "return_upstream_response": false,
    "trace": true,
    "trace_level": "summary"
  }
}
```

قيمة `trace_level` هي `summary` أو `full`. قد تحتوي حمولات التصحيح على محتوى طلبك، لذا استخدمها فقط في التطوير أو في بيئات خاضعة لرقابة مشددة. راجع [`debug`](./parameters.mdx#parameter-debug).

عندما يفشل طلب، تحقق من [صفحة الحالة](https://status.phaseo.app) بحثًا عن حوادث، وقارن حمولتك بصفحة المرجع الخاصة بنقطة النهاية، وسجّل `generation_id` مع نقطة النهاية والنموذج. أرفق `generation_id` عند التواصل مع [الدعم](https://phaseo.app/help).

قواعد معالجة الأخطاء للوكلاء، تلخّص هذه الصفحة:

- اعتمد على `error.code` (يُرجع أيضًا في `code` على المستوى الأعلى) و`error.type` و`status_code`، لا على نص الرسالة. سجّل `generation_id` مع كل إخفاق.
- `400` و`401` و`403` و`404`: أصلح الطلب أو المفتاح أو الوصول أولًا. لا تُعد الطلب نفسه دون تغيير.
- `410` مع `model_retired`: انتقل إلى `replacement_model` إذا لم يكن `null`؛ وإلا فاختر نموذجًا جديدًا من `GET /v1/models`.
- `429`: عند وجود `Retry-After` (بالثواني أو تاريخ HTTP)، انتظر تلك المدة قبل إعادة المحاولة؛ وإلا فاستخدم تراجعًا أُسّيًا مع تذبذب عشوائي. خطأ `key_limit_exceeded` بلا `Retry-After` لا يُعاد ضبطه من تلقاء نفسه، فلا تُعد المحاولة.
- `500` إلى `599`: أعد المحاولة فقط عندما يكون تكرار الاستدعاء آمنًا، مع حد للمحاولات ومهلة إجمالية وتراجع أُسّي مع تذبذب عشوائي. في المهام غير المتزامنة، ابحث عن المهمة المقبولة بدلًا من إرسالها مجددًا.
- تعامل مع حمولات التصحيح على أنها حساسة، وأخفِ بياناتها قبل كتابة سجلات دائمة.
- لأنماط مُختبرة لإعادة المحاولة وتحليل الأخطاء، ثبّت مهارة `phaseo-gateway`: `npx skills add https://phaseo.app/docs --skill phaseo-gateway`.
