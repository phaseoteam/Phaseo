يسهل اعتماد Gateway في أحمال الإنتاج عند تأسيس قاعدة قوية. اتبع التوصيات التالية لتحسين المرونة والأمان وسهولة الصيانة.

---

## البنية

-   **اعزل منطق المزوّدين.** ضع استدعاءات Gateway داخل خدمة أو حزمة SDK مخصصة لحصر التغييرات.
-   **استخدم بث الاستجابات متى أمكن.** خفّض زمن استجابة المساعدين ببث الرموز إلى الواجهة فور وصولها.
-   **اجمع المهام غير الحرجة.** ضع عمليات التوليد أو التقييم في الخلفية ضمن قائمة انتظار لتخفيف ذروة الحركة.

---

## الأمان

-   خزّن مفاتيح API في الإنتاج داخل مدير أسرار (AWS Secrets Manager أو Doppler أو 1Password) بدلاً من ملفات `.env`.
-   فعّل توقيع الطلبات في واجهات API الخاصة بك حتى لا تكشف تطبيقات العميل مفاتيح Gateway.
-   سجّل المفاتيح بعد اقتطاعها فقط (مثلاً `sk_prod_abcd...`) لتجنب تسريب بيانات الاعتماد.

---

## الموثوقية

-   طبّق تأخيراً أُسّياً مع عشوائية على جميع الأخطاء القابلة لإعادة المحاولة (HTTP 429 أو 5xx).
-   التزم بترويسة [`Retry-After`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Retry-After) قبل إعادة طلبات تجاوزت الحدود.
-   راقب بيانات المزوّدين الوصفية لاكتشاف التحويل التلقائي من مزوّد إلى آخر.

---

## قابلية الملاحظة

| المؤشر        | الإجراء الموصى به                                                |
| ------------- | ----------------------------------------------------------------- |
| زمن الاستجابة       | تابع أزمنة p95 وp99 لاكتشاف التراجعات مبكراً.             |
| استخدام الرموز   | اربط التكاليف بمقاييس الأعمال لتقييم العائد على الاستثمار.            |
| معدل الأخطاء   | أرسل تنبيهاً عندما تتجاوز الإخفاقات 1% لمدة مستمرة.             |
| مزيج المزوّدين  | تحقق من توزيع حركة المرور بين المزوّدين على النحو المتوقع.         |

---

## التعاون

-   وثّق قوالب المطالبات ومعلمات الإدخال ومعالجة المخرجات في الويكي الداخلي.
-   شارك لوحات تعرض تغيرات الاختبارات المرجعية وتأثيرها في منتجك.
-   شجّع المراجعات المنتظمة بمشاركة فرق المنتج والبحث والدعم لضمان اتساق السلوك.
