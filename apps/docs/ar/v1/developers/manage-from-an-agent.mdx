أدِر حساب Phaseo من `phaseo` CLI أو من Management API على `/v1` أو من خادم Phaseo MCP بدلًا من لوحة التحكم. تعطي الجداول أدناه الأمر والمسار والأداة لكل مهمة.

لا يزال على شخص تنفيذ هذه الخطوات في المتصفح:

| الخطوة | ما يفعله الشخص |
| --- | --- |
| التسجيل | ينشئ حساب Phaseo. |
| الموافقة على تسجيل الدخول | يوافق على الصفحة التي يفتحها `phaseo login`، أو يُدخل الرمز الذي يعرضه `phaseo login --device-code`. |
| إضافة أول بطاقة | عند عدم وجود بطاقة محفوظة، يعيد `phaseo credits add` رابط دفع. يفتحه مالك أو مسؤول ويدفع، فتُحفظ البطاقة. |
| تأكيد كل عملية شحن | مع وجود بطاقة محفوظة، يؤكد مالك أو مسؤول كل `phaseo credits add` من رابط يصله بالبريد الإلكتروني. |
| أمان الحساب | يدير كلمة المرور والمصادقة متعددة العوامل ومفاتيح المرور. |

<Visibility for="agents">
قواعد للوكلاء الذين يديرون Phaseo:

- لا ترسل المستخدم إلى لوحة التحكم لمهمة موجودة في الجداول أدناه. شغّل أمر CLI، أو استدعِ المسار، أو استخدم أداة MCP.
- لا تُنشئ مفتاح API أو تخمّنه أبدًا. أنشئ مفتاحًا باستخدام `phaseo keys create --name <name> --json` واحفظ السر مرة واحدة، على جهة الخادم.
- استخدم `--json` في كل أمر CLI. ولا تمرّر `--yes` إلى الأوامر الهدّامة إلا عندما يطلب المستخدم ذلك التغيير بعينه.
- لا تبدأ عملية شحن أرصدة إلا إذا طلبها المستخدم. لا تُكمل رابط الدفع بنفسك أبدًا، ولا تُعِد محاولة شحن انتهى بالرفض أو انتهاء الصلاحية أو الفشل.
</Visibility>

## الإعداد لمرة واحدة

```bash
npm install -g @phaseo/cli
phaseo login                 # opens a browser; a person approves it
phaseo login --device-code   # SSH, CI and agent sandboxes: a person enters the code
phaseo whoami --json
```

ثم أنشئ مفتاح استدلال للتطبيق وأضف أرصدة إذا لم يكن لدى مساحة العمل أي رصيد:

```bash
phaseo keys create --name "Production app" --json
phaseo credits get --json
phaseo login --scopes billing:write   # opt in once before the first top-up; a person approves the sign-in
phaseo credits add --amount 20 --json
```

يحتاج `phaseo credits add` إلى النطاق `billing:write`، الذي لا يملكه أي تسجيل دخول افتراضيًا، ولا يُجري أي خصم بمفرده أبدًا:

- **مع بطاقة محفوظة**، يرسل Phaseo بريدًا إلكترونيًا إلى كل مالك ومسؤول في مساحة العمل يتضمن رابطًا لتأكيد الخصم، وينتظر الأمر النتيجة.
- **بدون بطاقة محفوظة**، يعيد `next_action: "open_checkout_url"` ورابط دفع يدفع منه مالك أو مسؤول. تُحفظ البطاقة لعمليات الشحن اللاحقة، ولا يُرسَل أي بريد إلكتروني.

راجع [الأرصدة](../api-reference/endpoint/credits) للمسار.

## اختر واجهة

| الواجهة | استخدمها عندما | تسجيل الدخول |
| --- | --- | --- |
| [`phaseo` CLI](../guides/integrations/phaseo-cli) | يستطيع الوكيل تشغيل أوامر الطرفية | `phaseo login` أو `phaseo login --device-code` |
| [Management API](../api-reference/introduction) | شيفرة خادم أو CI أو لغة بدون CLI | [مفتاح إدارة](./management-api-keys) (`phaseo_v1_mk_...`) أو رمز OAuth |
| [Phaseo MCP](./cli-and-mcp#phaseo-mcp) | يعمل الوكيل داخل عميل MCP | اتصل بـ `https://mcp.phaseo.app/mcp?access=manage` ووافق على الأذونات التي تريدها |

شغّل `phaseo <group> --help` لترى الخيارات التي يقبلها CLI المثبّت لديك. وعندما لا يكون لمهمة أمر مخصص، يستدعي `phaseo api get|post|patch|put|delete /v1/<path>` المسار باستخدام جلستك.

## أصلح خطأ 403

لا تستطيع جلسة CLI أو مفتاح الإدارة أو اتصال MCP إلا ما تسمح به نطاقاتها ودورك في مساحة العمل، ولا تزال التغييرات المقصورة على المالكين والمسؤولين تحتاج إلى مالك أو مسؤول. إذا أعاد أمر ما `403`، فتحقّق من النطاقات الممنوحة باستخدام `phaseo whoami --json`، وسجّل الدخول مجددًا باستخدام `phaseo login --scopes <scope,...>` عندما يكون أحدها مفقودًا. لا يُمنح `billing:write` افتراضيًا أبدًا.
