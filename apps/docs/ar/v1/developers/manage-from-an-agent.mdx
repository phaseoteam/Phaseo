يمكنك تنفيذ المهام اليومية في حساب Phaseo باستخدام `phaseo` CLI أو واجهة الإدارة `/v1` أو خادم Phaseo MCP. استخدم هذه الصفحة لتعرف الأمر أو المسار أو الأداة لكل مهمة. أما التغييرات التي تمس الإنفاق أو الوصول أو وجهة بيانات مساحة العمل فتُجرى من لوحة التحكم أو باستخدام مفتاح إدارة.

لا يزال على شخص تنفيذ هذه الخطوات في المتصفح:

| الخطوة | ما يفعله الشخص |
| --- | --- |
| التسجيل | ينشئ حساب Phaseo. |
| الموافقة على تسجيل الدخول | يوافق على الصفحة التي يفتحها `phaseo login`، أو يُدخل الرمز الذي يعرضه `phaseo login --device-code`. |
| إضافة أول بطاقة | عند عدم وجود بطاقة محفوظة، يعيد `phaseo credits add` رابط دفع. يفتحه مالك أو مسؤول ويدفع، فتُحفظ البطاقة. |
| تأكيد كل عملية شحن | مع وجود بطاقة محفوظة، يؤكد مالك أو مسؤول كل `phaseo credits add` من رابط يصله بالبريد الإلكتروني. |
| أمان الحساب | يدير كلمة المرور والمصادقة متعددة العوامل ومفاتيح المرور. |

<Visibility for="agents">
قواعد للوكلاء الذين يديرون Phaseo:

- لا ترسل المستخدم إلى لوحة التحكم لمهمة موجودة في خريطة المهام. نفّذ أمر CLI أو استدعِ المسار أو استخدم أداة MCP. للتغييرات المدرجة تحت «تغييرات تُجرى من لوحة التحكم أو باستخدام مفتاح إدارة»، استدعِ المسار بمفتاح إدارة إن كان لديك؛ وإلا فاطلب من الشخص إجراء التغيير من لوحة التحكم.
- لا تُنشئ مفتاح API ولا تخمّنه أبدًا. اطلب من الشخص إنشاءه من لوحة التحكم، أو أنشئه باستخدام `POST /v1/keys` ومفتاح إدارة، واحفظ السر مرة واحدة على الخادم.
- استخدم `--json` في كل أمر CLI. ولا تمرّر `--yes` إلى الأوامر الهدّامة إلا عندما يطلب المستخدم ذلك التغيير بعينه.
- لا تبدأ عملية شحن أرصدة إلا إذا طلبها المستخدم. لا تُكمل رابط الدفع بنفسك أبدًا، ولا تُعِد محاولة شحن انتهى بالرفض أو انتهاء الصلاحية أو الفشل.
</Visibility>

## الإعداد لمرة واحدة

```bash
npm install -g @phaseo/cli
phaseo login                 # opens a browser; a person approves it
phaseo login --device-code   # SSH, CI and agent sandboxes: a person enters the code
phaseo whoami --json
```

بعد ذلك أنشئ مفتاح استدلال للتطبيق من لوحة التحكم، أو باستخدام `POST /v1/keys` ومفتاح إدارة، وأضف رصيدًا إذا لم يكن لدى مساحة العمل رصيد:

```bash
phaseo credits get --json
phaseo login --scopes billing:write   # opt in once before the first top-up; a person approves the sign-in
phaseo credits add --amount 20 --json
```

يحتاج `phaseo credits add` إلى النطاق `billing:write`، الذي لا يملكه أي تسجيل دخول افتراضيًا، ولا يُجري أي خصم بمفرده أبدًا:

- **مع بطاقة محفوظة**، يرسل Phaseo بريدًا إلكترونيًا إلى كل مالك ومسؤول في مساحة العمل يتضمن رابطًا لتأكيد الخصم، وينتظر الأمر النتيجة.
- **بدون بطاقة محفوظة**، يعيد `next_action: "open_checkout_url"` ورابط دفع يدفع منه مالك أو مسؤول. تُحفظ البطاقة لعمليات الشحن اللاحقة، ولا يُرسَل أي بريد إلكتروني.

راجع [الأرصدة](../api-reference/endpoint/credits) للمسار.

## اختر واجهة

| الواجهة | استخدمها عندما | تسجيل الدخول |
| --- | --- | --- |
| [`phaseo` CLI](../guides/integrations/phaseo-cli) | يستطيع الوكيل تشغيل أوامر الطرفية | `phaseo login` أو `phaseo login --device-code` |
| [Management API](../api-reference/introduction) | شيفرة خادم أو CI أو لغة بدون CLI | [مفتاح إدارة](./management-api-keys) (`phaseo_v1_mk_...`) أو رمز OAuth |
| [Phaseo MCP](./cli-and-mcp#phaseo-mcp) | يعمل الوكيل داخل عميل MCP | اتصل بـ `https://mcp.phaseo.app/mcp?access=manage` ووافق على الأذونات التي تريدها |

شغّل `phaseo <group> --help` لترى الخيارات التي يقبلها CLI المثبّت لديك. وعندما لا يكون لمهمة أمر مخصص، يستدعي `phaseo api get|post|patch|put|delete /v1/<path>` المسار باستخدام جلستك.

## خريطة المهام

### المفاتيح والوصول

| المهمة | CLI | مسار API | أداة MCP |
| --- | --- | --- | --- |
| عرض المفاتيح أو إعادة تسميتها أو حذفها | `phaseo keys list`, `phaseo keys update <id> --name <name>`, `phaseo keys delete <id>` | `GET /v1/keys`, `PATCH /v1/keys/{id}`, `DELETE /v1/keys/{id}` | `api_keys_list`, `api_key_update`, `api_key_delete` |
| مراجعة التطبيقات التي فوّضتها أو تضييق صلاحياتها أو إلغاؤها | `phaseo authorized-apps list`، `phaseo authorized-apps update-scopes <id> --scopes <scope,...>`، `phaseo authorized-apps revoke <id> --yes` | `GET /v1/me/authorized-apps`، `PATCH /v1/me/authorized-apps/{id}`، `DELETE /v1/me/authorized-apps/{id}` | — |
| تحديث ملفك الشخصي | `phaseo profile update` | `PATCH /v1/me/profile` | — |

| المهمة | CLI | مسار API | أداة MCP |

## تغييرات تُجرى من لوحة التحكم أو باستخدام مفتاح إدارة

تمس هذه التغييرات الإنفاق أو الوصول أو وجهة بيانات مساحة العمل. لا يمكن لتسجيل الدخول عبر CLI أو اتصال MCP إجراؤها مهما كانت نطاقاته: تعيد الواجهة `403` وتطلب استخدام لوحة التحكم أو مفتاح إدارة. أجرِها من لوحة تحكم Phaseo، أو استدعِ المسار باستخدام [مفتاح إدارة](./management-api-keys).

| المهمة | مسار API |
| --- | --- |
| إنشاء مفتاح API | `POST /v1/keys` |
| تغيير حدود المفتاح أو حالته أو تاريخ انتهائه | `PATCH /v1/keys/{id}` |
| تدوير مفتاح | `POST /v1/keys/{id}/rotate` |
| قصر مفتاح على عناوين IP | `PATCH /v1/keys/{id}` |
| إنشاء مفتاح إدارة | `POST /v1/management-keys` |
| تفعيل الشحن التلقائي أو رسائل انخفاض الرصيد | `PATCH /v1/notifications/settings` |
| تعيين ميزانيات مساحة العمل | `POST /v1/budgets`، `PATCH /v1/budgets/{id}` |
| تعيين ميزانيات الأقسام | `POST /v1/department-budgets` |
| التنبيه على الإنفاق أو حظره | `POST /v1/spend-rules`، `POST /v1/spend-blocks/{id}/lift` |
| سياسات حدود المعدل | `POST /v1/rate-limits/policies`، `POST /v1/rate-limits/assignments` |
| رفع مستوى حد المعدل لمساحة العمل | `POST /v1/rate-limits/tier/raise` |
| تخفيف الخصوصية أو ZDR، أو تغيير قيود المزوّدين أو بديل BYOK | `PATCH /v1/settings` |
| إضافة مفاتيح المزوّدين الخاصة بك (BYOK) | `POST /v1/byok` |
| ضبط ملف الإنفاق أو حدود الأسعار في Auto Routing | `PATCH /v1/routing/auto` |
| إنشاء المسارات الديناميكية ونشرها | `POST /v1/routing/dynamic-routes`، `POST /v1/routing/dynamic-routes/{id}/versions/{version}/deploy` |
| اختيار بدائل للنماذج المتقاعدة | `PUT /v1/routing/successor/replacements` |
| إضافة نموذج خاص | `POST /v1/private-models` |
| إنشاء الإعدادات المسبقة أو تحديثها | `POST /v1/presets`، `PATCH /v1/presets/{id}` |
| نشر إصدار من إعداد مسبق أو نقل تسمية | `POST /v1/presets/{id}/versions`، `PUT /v1/presets/{id}/labels/{label}` |

| إدارة مصنِّفات الطلبات | `POST /v1/classifiers` |
| اختبار مصنِّف على عيّنة (يحتاج إلى بيانات اعتماد مع `gateway:access`؛ تحصل جلسات CLI ومفاتيح الإدارة حاليًا على `403 gateway_access_required`) | `POST /v1/classifiers/test` |
| إضافة أعضاء إلى مساحة عمل | `POST /v1/workspaces/{id}/members/add` |
| دعوة الأشخاص | `POST /v1/workspaces/{id}/invites` |
| SSO وSCIM والأقسام والدليل | `PUT /v1/identity/sso`، `PUT /v1/identity/scim`، `POST /v1/identity/departments`، `PUT /v1/identity/directory/members/{id}` |
| أحمال العمل الموثوقة (OIDC) | `POST /v1/workload-identity/policies` |
| إرسال التتبعات إلى أداة قابلية رصد | `POST /v1/observability/destinations`، `POST /v1/observability/destinations/{id}/test` |
| وجهات التنبيه عبر البريد الإلكتروني أو Slack أو خطافات الويب | `POST /v1/notifications/destinations`، `PUT /v1/notifications/routes/{eventKind}` |

## أصلح خطأ 403

لا تستطيع جلسة CLI أو مفتاح الإدارة أو اتصال MCP إلا ما تسمح به نطاقاتها ودورك في مساحة العمل، ولا تزال التغييرات المقصورة على المالكين والمسؤولين تحتاج إلى مالك أو مسؤول. إذا أعاد أمر ما `403`، فتحقّق من النطاقات الممنوحة باستخدام `phaseo whoami --json`، وسجّل الدخول مجددًا باستخدام `phaseo login --scopes <scope,...>` عندما يكون أحدها مفقودًا. لا يُمنح `billing:write` افتراضيًا أبدًا. تُرفض التغييرات المدرجة تحت «تغييرات تُجرى من لوحة التحكم أو باستخدام مفتاح إدارة» لتسجيلات الدخول عبر CLI واتصالات MCP مهما كانت نطاقاتها.
