راجع [صفحة الحالة](https://status.phaseo.app) و`GET /v1/health` لمعرفة ما إذا كان Phaseo سليمًا، و`GET /v1/models` لمعرفة ما إذا كان النموذج قابلًا للتوجيه الآن، وتشغيلك التجريبي الخاص لمعرفة ما إذا كان المسار يحقق هدف الموثوقية لديك.

## تحقّق من صحة الخدمة الحالية

1. افتح [صفحة حالة Phaseo](https://status.phaseo.app) للاطلاع على الحوادث الحالية وسجلها.
2. استدعِ `GET /v1/health` لإجراء فحص أدنى لصحة الـ Gateway.
3. إذا فشل طلب واحد، فاحتفظ بمعرّف الطلب وافحص سجل النشاط أو التوليد الخاص به قبل أن تفترض أن الخدمة كلها متوقفة.

```bash
curl https://api.phaseo.app/v1/health
```

```json
{
  "status": "ok"
}
```

<Note>
تعرض صفحة الحالة العامة صحة الخدمة. لا يقدّم Phaseo حاليًا اتفاقية مستوى خدمة (SLA) عامة وتعاقدية لوقت التشغيل.
</Note>

## تأكد من أن النموذج قابل للتوجيه

يضم كتالوج Phaseo نماذج أكثر مما يستطيع الـ Gateway توجيهه: وجود النموذج في الكتالوج يعني أن Phaseo يتتبعه، لا أن له مسارًا عامًا. يعيد `GET /v1/models` افتراضيًا النماذج القابلة للتوجيه حاليًا فقط:

```bash
curl https://api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

أضف `availability=all` لترى أيضًا الربطات القادمة قريبًا وغير النشطة. لا ترسل حركة الإنتاج إلى صف مزوّد إلا عندما تكون `availability_status` بقيمة `active` و`is_active_gateway` بقيمة `true`. راجع [حالات المزوّد وPhaseo](../guides/provider-statuses.mdx) لمعرفة معنى أيقونات الحالة في صفحات النماذج.

| الحالة | المعنى |
| --- | --- |
| `active` | يتوفر الآن مسار عام واحد على الأقل عبر الـ Gateway. |
| `coming_soon` | يتتبع Phaseo مسارًا مخططًا له أو تجريبيًا، لكنه غير قابل للتوجيه علنًا. |
| `inactive` | مسار معروف لكنه معطّل أو غير متاح أو منتهٍ أو غير قابل للتوجيه لسبب آخر. |
| `not_listed` | لا يوجد حاليًا ربط مزوّد في الـ Gateway مدرج لهذا النموذج. |

لا تضمن `active` وقت التشغيل، ولا الوصول في كل منطقة، ولا الشروط التجارية نفسها لكل مساحة عمل.

## افهم مقاييس الأداء

تلخّص بيانات الأداء في Phaseo الطلبات الحقيقية الموجّهة عبر الـ Gateway؛ وهي ليست اختبارًا معياريًا مخبريًا مضبوطًا.

| المقياس | التعريف |
| --- | --- |
| Gateway TTFT | من بدء الطلب في الـ Gateway حتى أول مخرج مولَّد يحمل محتوى. |
| Provider TTFT | من إرسال الطلب إلى المزوّد حتى أول مخرج مولَّد يحمل محتوى. |
| مدة المزوّد | من إرسال الطلب إلى المزوّد حتى الاستجابة النهائية. |
| Gateway E2E | من بدء الطلب في الـ Gateway حتى اكتماله. |
| الحمل الإضافي لـ Phaseo | الفرق غير السالب بين Gateway E2E ومدة المزوّد. |
| الإنتاجية الفعلية | جميع رموز المخرجات مقسومة على مدة المزوّد الكاملة. |
| سرعة الإخراج | رموز المخرجات بعد الأول مقسومة على وقت المزوّد بعد TTFT. |

يحتاج TTFT وسرعة الإخراج إلى استجابة متدفقة يكون أول مخرج فيها حاملًا لمحتوى. ويظل الطلب غير المتدفق يسهم في المدة والإنتاجية الفعلية، لكن دون TTFT.

اقرأ كل مقياس مع نافذته الزمنية والمسار والمنطقة ووضع التدفق والمئين. فحِمل المزوّد وطول الموجّه وطول المخرجات وإعادات المحاولة وظروف الشبكة كلها تغيّر النتيجة.

للاطلاع على التعريفات الكاملة، راجع [الأسعار والأداء](../exploring/pricing-performance) و[كيف يقيس Phaseo زمن الاستجابة والإنتاجية](https://phaseo.app/how-phaseo-measures-latency-throughput).

## تحقّق باستخدام عبء العمل لديك

تُظهر المقاييس العامة الاتجاه؛ لكنها لا تثبت أن المسار يحقق هدفك في الإنتاج. شغّل اختبارًا صغيرًا قابلًا لإعادة الإنتاج قبل الطرح:

1. أزل بيانات الإنتاج الحساسة واحتفظ بمزيج تمثيلي من الموجّهات.
2. سجّل معرّف النموذج ونقطة النهاية وقيود المزوّد والمنطقة ووضع التدفق ومستوى التزامن.
3. شغّل عددًا كافيًا من التكرارات لمقارنة التوزيعات بدلًا من طلب واحد.
4. سجّل معدل النجاح وGateway TTFT ومدة المزوّد وGateway E2E ورموز المخرجات والتكلفة النهائية.
5. اختبر المفاتيح غير الصالحة والنماذج غير الصالحة وحدود المعدل وإخفاقات المزوّد غير المتاح.
6. احفظ معرّفات الطلبات والنافذة الزمنية الدقيقة ليتمكن مهندس آخر من إعادة إنتاج النتيجة.

لا تنشر اسم عميل أو اقتباسًا أو نتيجة عبء عمل أو نسبة موثوقية دون إذن ومنهجية موثّقة.

## افرز طلبًا فاشلًا

1. راجع [حالة الخدمة](https://status.phaseo.app).
2. تأكد من أن النموذج لا يزال يظهر في الاستجابة الافتراضية لـ [`GET /v1/models`](../api-reference/endpoint/models)، وراجع [نقاط النهاية](../api-reference/endpoint/model-endpoints) الخاصة به.
3. ابحث عن رمز حالة HTTP ورمز الخطأ في [الأخطاء وتصحيحها](../api-reference/errors).
4. أعد محاولة استجابات `429` و`5xx` العابرة باستخدام تراجع أُسّي محدود؛ راجع [حدود المعدل](../api-reference/limits.mdx).
5. احتفظ بمعرّف الطلب عند التواصل مع [الدعم](https://phaseo.app/help).

لإبقاء الطلبات تعمل عند فشل أحد المزوّدين، اضبط [التوجيه والبدائل](../guides/routing-and-fallbacks).
