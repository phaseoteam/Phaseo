استخدم هذا الدليل للإجابة عن أحد الأسئلة التالية: هل Phaseo يعمل بشكل سليم؟ هل يمكن توجيه نموذج الآن؟ وهل يحقق المسار هدف الموثوقية لتطبيقك؟

## تحقّق من صحة الخدمة الحالية

1. افتح [صفحة حالة Phaseo](https://status.phaseo.app) للاطلاع على الحوادث الحالية وسجلها.
2. استدعِ `GET /v1/health` لإجراء فحص أساسي لصحة Gateway.
3. إذا فشل طلب واحد، فاحتفظ بمعرّف الطلب وافحص سجل النشاط أو الإنشاء قبل افتراض أن الخدمة بأكملها غير متاحة.

```bash
curl https://api.phaseo.app/v1/health
```

```json
{
  "status": "ok"
}
```

<Note>
تعرض صفحة الحالة العامة صحة الخدمة. ولا تقدم Phaseo حاليًا ضمان SLA تعاقديًا عامًا لوقت التشغيل.
</Note>

## تأكد من إمكانية توجيه النموذج

كتالوج Phaseo أوسع من مجموعة النماذج المتاحة عبر Gateway. ووجود نموذج في الكتالوج يعني أن Phaseo يتتبعه، ولا يعني وجود مسار عام له.

`GET /v1/models` يعيد افتراضيًا النماذج القابلة للتوجيه حاليًا فقط:

```bash
curl https://api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

استخدم `availability=all` فقط عندما تريد عمدًا فحص التعيينات القادمة أو غير النشطة. لا ترسل حركة مرور الإنتاج إلى صف مزوّد إلا إذا كانت قيمة `availability_status` هي `active` وقيمة `is_active_gateway` هي `true`.

| الحالة | المعنى |
| --- | --- |
| `active` | يتوفر الآن مسار Gateway عام واحد على الأقل. |
| `coming_soon` | تتتبع Phaseo مسارًا مخططًا أو تجريبيًا، لكنه غير متاح للتوجيه العام. |
| `inactive` | المسار المعروف معطّل أو غير متاح أو منتهي الصلاحية أو غير قابل للتوجيه لسبب آخر. |
| `not_listed` | لا يوجد حاليًا تعيين مزوّد Gateway مدرج لهذا النموذج. |

لا يضمن التوفر استمرار التشغيل أو الوصول من جميع المناطق أو تطابق الشروط التجارية لكل مساحة عمل.

## تفسير مقاييس الأداء

بيانات أداء Phaseo رصدية؛ فهي تلخص الطلبات التي تمر عبر Gateway وليست نتائج معيار مختبري مضبوط.

| المقياس | التعريف |
| --- | --- |
| Gateway TTFT | من بدء طلب Gateway إلى أول مخرجات مُنشأة تتضمن محتوى. |
| Provider TTFT | من إرسال الطلب إلى المزوّد حتى أول مخرجات مُنشأة تتضمن محتوى. |
| مدة المزوّد | من إرسال الطلب إلى المزوّد حتى الرد النهائي. |
| Gateway E2E | من بدء طلب Gateway حتى اكتماله. |
| العبء الإضافي لـPhaseo | الفرق غير السالب بين مدة Gateway E2E ومدة المزوّد. |
| معدل النقل الفعلي | إجمالي رموز المخرجات مقسومًا على مدة المزوّد الكاملة. |
| سرعة الإخراج | رموز المخرجات بعد الأولى مقسومة على زمن المزوّد بعد TTFT. |

يتطلب قياس TTFT وسرعة المخرجات استجابة متدفقة يكون أول مخرجاتها حاويًا على محتوى. ويمكن للطلب غير المتدفق المساهمة في قياس المدة ومعدل النقل الفعلي دون اختلاق قيمة TTFT.

اقرأ المقياس دائمًا مع نافذته الزمنية ومساره ومنطقته ووضع البث والنسبة المئوية. وقد يؤثر حمل المزوّد وطول المطالبة والمخرجات وإعادة المحاولات وظروف النقل في النتيجة.

للتعريفات الكاملة، راجع [الأسعار والأداء](../exploring/pricing-performance.mdx) و[كيفية قياس Phaseo لزمن الاستجابة ومعدل النقل](https://phaseo.app/how-phaseo-measures-latency-throughput).

## تحقّق باستخدام عبء العمل لديك

توفر بيانات القياس العامة مؤشرات، لكنها لا تثبت أن المسار يحقق هدف الإنتاج لديك. أجرِ دراسة صغيرة قابلة للتكرار قبل الإطلاق:

1. أزل بيانات الإنتاج الحساسة واحتفظ بمزيج مطالبات ممثل.
2. سجّل معرّف النموذج ونقطة النهاية وقيود المزوّد والمنطقة ووضع البث والتزامن.
3. كرّر التشغيل مرات كافية لمقارنة التوزيعات بدلًا من طلب واحد.
4. سجّل معدل النجاح وGateway TTFT ومدة المزوّد وGateway E2E ورموز المخرجات والتكلفة النهائية.
5. اختبر المفاتيح والنماذج غير الصالحة وحدود المعدل وأخطاء عدم توفر المزوّد.
6. احفظ معرّفات الطلبات والنافذة الزمنية الدقيقة ليتمكن مهندس آخر من إعادة إنتاج النتيجة.

لا تنشر اسم عميل أو اقتباسًا أو نتيجة عبء عمل أو نسبة موثوقية دون إذن ومنهج موثق.

## فرز الطلب الفاشل وتشخيصه

- تحقّق من [حالة الخدمة](https://status.phaseo.app).
- تأكد من استمرار ظهور النموذج في الاستجابة الافتراضية لـ`GET /v1/models`.
- راجع حالة HTTP ورمز الخطأ في [معالجة الأخطاء](../api-reference/errors.mdx).
- أعد المحاولة عند أخطاء `429` و`5xx` المؤقتة مع تراجع أسي محدود.
- دوّن معرّف الطلب عند التواصل مع [الدعم](https://phaseo.app/help).
