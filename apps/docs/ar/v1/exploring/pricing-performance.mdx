استخدم هذا الدليل لمقارنة التكلفة والسرعة بين المسارات وفهم المقاييس التي يعرضها Phaseo وتصميم دراسة للأعباء قبل تحويل حركة الإنتاج.

## ابدأ بتحديد القرار

اختر المقياس الذي يناسب تجربة المستخدم التي تريد الحفاظ عليها.

| عبء العمل | ابدأ بـ | السبب |
| --- | --- | --- |
| المحادثة والمساعدات الصوتية | Gateway TTFT | يلاحظ المستخدمون سرعة بدء المخرجات المفيدة. |
| الإجابات الطويلة وتوليد الشيفرات | Output speed | تكون سرعة التوليد المستمرة هي العامل الأهم في الإجابات الطويلة. |
| الأدوات وسير العمل المنظم | Gateway E2E | يؤثر التوجيه وإعادة المحاولة والتنسيق في النتيجة الكاملة. |
| المعالجة الدفعية أو غير المتصلة | التكلفة ومعدل النقل الفعلي | قد يكون البدء الأبطأ مقبولًا عندما يكون إجمالي الإنتاجية والإنفاق أهم. |

لا تثبت نتيجة واحدة أن نموذجًا ما هو الخيار الأفضل لكل عبء عمل.

## قارن الأسعار

تستخدم قوائم أسعار مزودي الخدمة وحدات مختلفة: لكل رمز أو مليون رمز أو صورة أو ثانية أو دقيقة أو طلب. يحتفظ Phaseo بالوحدة الأصلية ويوحّد الأسعار القابلة للمقارنة لعرضها في الكتالوج وحاسبة الأسعار.

في النماذج النصية، قارن بشكل منفصل أسعار الإدخال والإدخال المخزن مؤقتًا وكتابة الذاكرة المؤقتة والاستدلال والإخراج عند توفرها. أما نماذج الوسائط، فأبقِ وحدة الفوترة الأصلية ظاهرة؛ ولا تعرض سعر الفيديو لكل ثانية كما لو كان سعرًا لكل رمز.

<Note>
أسعار الكتالوج تقديرية لحساب تكلفة الطلب وليست عرض سعر لكل حمولة محتملة. وقد تغير مستويات مزود الخدمة والعروض الإقليمية وتسعير الدفعات وسلوك الذاكرة المؤقتة وعدادات الطلب المحددة المبلغ النهائي.
</Note>

استخدم [حاسبة الأسعار](https://phaseo.app/tools/pricing-calculator) لحمولة ممثلة، ثم تحقق من المبلغ المفوتر ضمن استخدام Gateway بعد طلب تجريبي.

## فهم مقاييس الأداء

يسجل Phaseo توقيت المعالجة التشغيلي للطلبات التي تمر عبر Gateway.

| المقياس | التعريف |
| --- | --- |
| **Gateway TTFT** | من بدء طلب Gateway حتى أول مخرجات مولدة تحتوي على محتوى. |
| **Provider TTFT** | من إرسال الطلب إلى مزود الخدمة المحدد حتى أول مخرجات مولدة تحتوي على محتوى. |
| **Provider duration** | من إرسال الطلب إلى مزود الخدمة المحدد حتى الاستجابة النهائية. |
| **Gateway E2E** | من بدء طلب Gateway حتى اكتماله. |
| **Phaseo overhead** | `max(0, Gateway E2E - provider duration)`. |
| **Effective throughput** | إجمالي رموز الإخراج مقسومًا على مدة مزود الخدمة الكاملة. |
| **Output speed** | رموز الإخراج بعد الرمز الأول مقسومة على وقت مزود الخدمة بعد TTFT. |
| **TPOT / ITL** | متوسط الوقت لكل رمز على مستوى الطلب بعد أول مخرجات. |

يتطلب قياس TTFT وسرعة الإخراج وTPOT وITL استجابة متدفقة يكون أول مخرجاتها محتويًا على محتوى. لا تُحتسب إطارات التدفق التي تحتوي على بيانات وصفية فقط. يمكن أن تسهم الاستجابات غير المتدفقة في مدة مزود الخدمة وGateway E2E والإنتاجية الفعلية دون اختلاق قيمة TTFT.

يعزل حمل Phaseo الزائد الوقت المستغرق خارج استدعاء مزود الخدمة المحدد. قد يشمل معالجة Gateway والتوجيه وإعادة المحاولة وتأثيرات الشبكة. ليست قيمة ثابتة للمنصة، وينبغي قراءتها كتوزيع ضمن فترة زمنية محددة.

## قراءة البيانات التشغيلية بشكل صحيح

تلخص صفحات الأداء حركة Gateway المباشرة. إنها قياسات رصدية وليست اختبارات معيارية مضبوطة ولا خصائص جوهرية للنموذج.

قد تتغير النتائج بسبب:

- اختيار مزود الخدمة والمسار
- موقع تنفيذ Cloudflare ومسار الشبكة
- الانتظار لدى مزود الخدمة أو الحمل الإقليمي
- طول الموجّه والمخرجات
- سلوك البث مقابل عدم البث
- إعادة المحاولة والإلغاء واستدعاء الأدوات
- تحديثات النموذج أو مزود الخدمة خلال الفترة المحددة

قد تعرض الرسوم البيانية العامة نسبًا مئوية مثل P50 وP90 وP95 وP99. في زمن الاستجابة، الأقل أفضل. الإنتاجية الأعلى أفضل، لذا تصف النسبة المئوية المنخفضة للإنتاجية الطرف الأبطأ من التوزيع.

سجّل دائمًا بجانب النتيجة الفترة والمسار والمنطقة وفلاتر العينة والنسبة المئوية المحددة. لا تقارن لقطتي شاشة بفترتين مختلفتين كما لو كانتا للدراسة نفسها.

## إجراء دراسة أعباء عمل قابلة للتكرار

استخدم بيانات القياس العامة لتضييق الخيارات، ثم تحقق من المرشحين النهائيين بمزيج الموجّهات الخاص بك.

1. اختر نموذجين أو ثلاثة قابلة للتوجيه من استجابة `GET /v1/models` الافتراضية.
2. أنشئ مجموعة موجّهات منقحة تمثل الطلبات القصيرة والنموذجية والطويلة.
3. ثبّت نقطة النهاية والمنطقة ووضع البث وقيود مزودي الخدمة والتزامن.
4. أرسل طلبات متكررة لكل موجّه بدلًا من الاعتماد على عينة واحدة.
5. سجّل معرّف الطلب ومزود الخدمة المحدد وحالة النجاح أو الخطأ ورموز الإخراج وGateway TTFT ومدة مزود الخدمة وGateway E2E وحمل Phaseo الزائد والتكلفة.
6. قارن التوزيعات وأنماط الإخفاق، ثم احتفظ بالنتائج الخام مع إعدادات الاختبار.

مثال على مخطط النتيجة:

```json
{
  "study_id": "support-summary-v1",
  "model": "<verified-model-id>",
  "endpoint": "responses",
  "stream": true,
  "region": "<execution-region>",
  "request_id": "req_...",
  "gateway_ttft_ms": 0,
  "provider_duration_ms": 0,
  "gateway_e2e_ms": 0,
  "phaseo_overhead_ms": 0,
  "output_tokens": 0,
  "cost_usd": 0,
  "status": "completed"
}
```

القيم الصفرية عناصر نائبة. لا تنشر القيم المقاسة إلا مع تعريف عبء العمل وعدد العينات والفترة الزمنية وإذن الإفصاح عن البيانات.

## ما لا يدّعيه Phaseo

- وجود النموذج في الكتالوج لا يعني إمكانية توجيهه. استخدم عامل تصفية التوفر النشط الافتراضي.
- لا تضمن بيانات التشغيل العامة زمن الاستجابة أو مدة التشغيل مستقبلًا.
- لا تثبت نتيجة المعيار جودة النموذج في الإنتاج مع مزيج الموجّهات الخاص بك.
- ملف واجهة المستخدم التوضيحي ليس قياسًا مباشرًا للنموذج.
- لا تنشر اقتباسًا أو شعارًا أو نتيجة عبء عمل لعميل دون إذن وأدلة داعمة.
