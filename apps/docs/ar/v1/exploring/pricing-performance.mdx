قارن تكلفة النموذج لدى كل مزوّد مع سرعة تقديمه لحركة الـ Gateway، ثم تحقّق من المرشحين النهائيين باستخدام موجّهاتك الخاصة قبل نقل حركة الإنتاج.

## اختر المقياس المهم لعبء عملك

| عبء العمل | ابدأ بـ | السبب |
| --- | --- | --- |
| المحادثة والمساعدات البرمجية والصوت | Gateway TTFT | يلاحظ المستخدمون مدى سرعة بدء المخرجات المفيدة. |
| الإجابات الطويلة وتوليد الشيفرة | سرعة الإخراج | تهيمن سرعة التوليد المستمرة على الاستجابات الأطول. |
| الأدوات وسير العمل المنظَّم | Gateway E2E | يؤثر التوجيه وإعادات المحاولة والتنسيق في النتيجة الكاملة. |
| العمل الدفعي أو غير المتصل | التكلفة والإنتاجية الفعلية | قد تكون البداية الأبطأ مقبولة عندما تكون الإنتاجية الإجمالية والإنفاق أهم. |

لا توجد نتيجة واحدة تثبت أن نموذجًا ما هو الخيار الأفضل لكل أعباء العمل.

## قارن الأسعار

تستخدم جداول أسعار المزوّدين وحدات مختلفة: لكل رمز، أو لكل مليون رمز، أو لكل صورة، أو لكل ثانية، أو لكل دقيقة، أو لكل طلب. يحتفظ Phaseo بكل سعر بوحدته الأصلية، ويحوّل أسعار النص القابلة للمقارنة إلى سعر لكل مليون رمز في عروض الكتالوج وحاسبة الأسعار.

لنماذج النص، قارن عدّادات الإدخال والإدخال المخزّن مؤقتًا وكتابة ذاكرة التخزين المؤقت والاستدلال والإخراج كلًّا على حدة عندما تكون موجودة. تحتفظ نماذج الوسائط بوحدة الفوترة الخاصة بها؛ قارن سعر الفيديو لكل ثانية فقط بأسعار أخرى لكل ثانية.

<Note>
تقدّر أسعار الكتالوج تكلفة الطلب؛ وليست عرض سعر لكل حمولة. تغيّر مستويات المزوّدين والعروض الإقليمية وأسعار المعالجة الدفعية وسلوك ذاكرة التخزين المؤقت والعدّادات الخاصة بالطلب المبلغ النهائي.
</Note>

استخدم [حاسبة الأسعار](https://phaseo.app/tools/pricing-calculator) لحمولة تمثيلية، ثم تحقّق من المبلغ المحتسب في استخدام الـ Gateway بعد طلب تجريبي.

## افهم مقاييس الأداء

يسجّل Phaseo التوقيت التشغيلي للطلبات الموجّهة عبر الـ Gateway.

| المقياس | التعريف |
| --- | --- |
| **Gateway TTFT** | من بدء الطلب في الـ Gateway حتى أول مخرج مولَّد يحمل محتوى. |
| **Provider TTFT** | من إرسال الطلب إلى المزوّد المختار حتى أول مخرج مولَّد يحمل محتوى. |
| **مدة المزوّد** | من إرسال الطلب إلى المزوّد المختار حتى الاستجابة النهائية. |
| **Gateway E2E** | من بدء الطلب في الـ Gateway حتى اكتماله. |
| **الحمل الإضافي لـ Phaseo** | `max(0, Gateway E2E - provider duration)`. |
| **الإنتاجية الفعلية** | جميع رموز المخرجات مقسومة على مدة المزوّد الكاملة. |
| **سرعة الإخراج** | رموز المخرجات بعد الأول، دون احتساب الاستدلال المخفي الذي يسبقه، مقسومة على وقت المزوّد بعد TTFT. لا تظهر عندما تصل الإجابة كاملة في قراءة شبكة واحدة. |
| **TPOT / ITL** | متوسط الوقت لكل رمز بعد أول مخرج، على مستوى الطلب. |

تتطلب TTFT وسرعة الإخراج وTPOT وITL استجابة متدفقة يكون أول مخرج فيها حاملًا لمحتوى. لا تُحتسب إطارات التدفق التي تحمل بيانات وصفية فقط. ويظل بإمكان الاستجابات غير المتدفقة الإسهام في مدة المزوّد وGateway E2E والإنتاجية الفعلية دون TTFT مختلَق.

الحمل الإضافي لـ Phaseo هو الوقت الواقع خارج استدعاء المزوّد المختار: معالجة الـ Gateway وعمل التوجيه وإعادات المحاولة وتأثيرات الشبكة. ويختلف من طلب لآخر، لذا اقرأه كتوزيع على نافذة زمنية محددة، لا كرقم ثابت.

## اقرأ البيانات التشغيلية بشكل صحيح

تلخّص صفحات الأداء حركة الـ Gateway الحية. وهي ملاحظات، لا تشغيلات معيارية مضبوطة، وتصف مسارًا خلال نافذة زمنية لا النموذج نفسه. لا يضمن زمن الاستجابة ووقت التشغيل في الماضي النتائج المستقبلية.

تتغير النتائج بسبب:

- اختيار المزوّد والمسار
- موقع التنفيذ في Cloudflare ومسار الشبكة
- طوابير المزوّد أو الحِمل الإقليمي
- طول الموجّه والمخرجات
- سلوك التدفق مقابل عدم التدفق
- إعادات المحاولة والإلغاءات واستدعاءات الأدوات
- تحديثات النموذج أو المزوّد خلال النافذة المختارة

يمكن أن تعرض المخططات العامة مئينات مثل P50 وP90 وP95 وP99. في زمن الاستجابة، الأقل أفضل. وفي الإنتاجية، الأعلى أفضل، لذا يصف مئين الإنتاجية الأدنى الطرف البطيء.

سجّل دائمًا النافذة الزمنية المختارة والمسار والمنطقة وعوامل تصفية العينة والمئين بجانب أي نتيجة. لا تقارن لقطتي شاشة بنافذتين مختلفتين كأنهما الدراسة نفسها.

## شغّل دراسة عبء عمل قابلة لإعادة الإنتاج

استخدم القياسات العامة لتضييق قائمة المرشحين، ثم تحقّق من المرشحين النهائيين باستخدام مزيج الموجّهات الخاص بك.

1. اختر نموذجين أو ثلاثة قابلة للتوجيه من الاستجابة الافتراضية لـ `GET /v1/models`.
2. أنشئ مجموعة موجّهات منقّاة تمثّل الطلبات القصيرة والنموذجية والطويلة.
3. ثبّت نقطة النهاية والمنطقة ووضع التدفق وقيود المزوّد ومستوى التزامن.
4. شغّل طلبات متكررة لكل موجّه بدلًا من الاعتماد على عينة واحدة.
5. سجّل معرّف الطلب والمزوّد المختار والنجاح أو الخطأ ورموز المخرجات وGateway TTFT ومدة المزوّد وGateway E2E والحمل الإضافي لـ Phaseo والتكلفة.
6. قارن التوزيعات وأنماط الفشل، ثم احتفظ بالنتائج الخام مع إعدادات الاختبار.

مثال على مخطط النتائج:

```json
{
  "study_id": "support-summary-v1",
  "model": "<verified-model-id>",
  "endpoint": "responses",
  "stream": true,
  "region": "<execution-region>",
  "request_id": "req_...",
  "gateway_ttft_ms": 0,
  "provider_duration_ms": 0,
  "gateway_e2e_ms": 0,
  "phaseo_overhead_ms": 0,
  "output_tokens": 0,
  "cost_usd": 0,
  "status": "completed"
}
```

القيم الصفرية عناصر نائبة. لا تنشر القيم المقيسة إلا مع تعريف عبء العمل وعدد العينات والنافذة الزمنية وإذن بالإفصاح عن البيانات.

وجود النموذج في الكتالوج لا يعني أنه قابل للتوجيه، لذا ابدأ من الاستجابة الافتراضية لـ `GET /v1/models`. ونتيجة المعيار لا تثبت الجودة على مزيج موجّهاتك؛ راجع [منهجية المعايير](../research/benchmark-methodology) لمعرفة مصادر النتائج، بمعزل عن قياسات الـ Gateway. لفحص كل مسار مزوّد وقدراته وسعره لنموذج واحد، استخدم [واجهة نقاط نهاية النموذج](../api-reference/endpoint/model-endpoints) أو [المقارنة](https://phaseo.app/compare). وللحوادث وفرز الإخفاقات، راجع [الموثوقية والحالة](../developers/reliability-and-status).
