استخدم هذه الوصفة لإعادة استخدام إعداد مسبق واحد عبر خدمات متعددة بدلًا من نسخ الطلب والنموذج والقيم الافتراضية للتوجيه في كل مكان.

## الهدف

- توحيد القيم الافتراضية للطلبات والمعلمات.
- تقييد المزوّدين المسموح بهم أثناء الإطلاق أو ضمن متطلبات الامتثال.
- الاحتفاظ بسياق كافٍ للطلب لتفسير سبب توجيهه بهذه الطريقة.

## 1. إنشاء الإعداد المسبق

أنشئ إعدادًا مسبقًا ضمن **لوحة التحكم -> الإعدادات -> الإعدادات المسبقة** مع:

- اسمًا وslug واضحين
- طلب نظام
- نماذج معتمدة
- تفضيلات المزوّد
- قيم المعلمات الافتراضية مثل `temperature`

استخدم slug الإعداد المسبق في كود الاستدعاء لإعادة استخدام سياسة الطلب نفسها عبر البيئات المختلفة.

## 2. إبقاء نص الطلب صغيرًا

الميزة الأساسية للإعدادات المسبقة هي أن جهة الاستدعاء لا تحتاج إلى تكرار قيم التوجيه والطلبات الافتراضية نفسها في كل طلب.

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-sonnet-4-5",
    "input": "Generate a release summary for the last 24 hours.",
    "preset": "release-summary"
  }'
```

```typescript TypeScript SDK
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "anthropic/claude-sonnet-4-5",
  input: "Generate a release summary for the last 24 hours.",
  preset: "release-summary",
});

console.log(response.output_text);
```

```python Python SDK
from phaseo import Phaseo

client = Phaseo(api_key="YOUR_API_KEY")

response = client.generate_response(
    {
        "model": "anthropic/claude-sonnet-4-5",
        "input": "Generate a release summary for the last 24 hours.",
        "preset": "release-summary",
    }
)

print(response.get("output_text"))
```
</CodeGroup>

## 3. فهم ما الذي يغيّره الإعداد المسبق

يُطبّق الإعداد المسبق قبل توجيه المزوّدين:

- تُملأ معلمات الطلب الناقصة من الإعداد المسبق
- يُضاف طلب الإعداد المسبق قبل طبقة النظام
- تقلّل تفضيلات المزوّدين قائمة المزوّدين المتاحين قبل ترتيبهم
- تُفحص قيود النموذج مبكرًا بدلًا من إعادة التوجيه بصمت

## 4. تصحيح نتيجة التوجيه

عندما لا يُوجّه الطلب كما توقعت، افتحه في **Gateway -> Usage** وافحص:

- المزوّدون الذين أُخذوا في الاعتبار
- المرشحون المرتبون
- عوامل التوجيه المرتبطة بكل مرشح
- حالات الحظر بسبب سياسة مساحة العمل أو الضوابط

هذه أسرع طريقة لمعرفة:

- سبب تخطي أحد المزوّدين
- سبب حظر الطلب
- سبب تصدّر وجهة أقل تكلفة أو زمن استجابة للترتيب

## 5. نمط التشغيل

استخدم نمط الإطلاق هذا عند تغيير سلوك التوجيه:

1. أنشئ slug جديدًا للإعداد المسبق الخاص بالسياسة الجديدة.
2. انقل مستدعيًا منخفض المخاطر إلى الإعداد المسبق الجديد.
3. افحص تفاصيل الطلبات واتجاهات النشاط.
4. وسّع الإطلاق فقط بعد أن تطابق نتائج التوجيه التوقعات.
