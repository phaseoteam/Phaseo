انقل عدة خدمات إلى إعداد مسبق واحد لكي تتشارك المطالبة والنموذج وقواعد المزوّدين، ثم استخدم سجلات الطلبات لتفسير المكان الذي ذهب إليه كل طلب. في النهاية يرسل المستدعون `"model": "@release-summary"` ومدخلاتهم، ويمكنك طرح تغيير في السياسة على مستدعٍ واحد في كل مرة.

شكل الطلب جاهز للإنتاج. تشرح صفحة [الإعدادات المسبقة](../guides/presets) كيف تُدمج إعدادات الإعداد المسبق مع الطلب؛ أما هذه الوصفة فتتناول الطرح.

## انقل مستدعيًا إلى إعداد مسبق

<Steps>
<Step title="أنشئ الإعداد المسبق">

في **الإعدادات → الإعدادات المسبقة**، أنشئ `release-summary` مع مطالبة نظام، والنماذج المعتمدة، وتفضيلات المزوّدين، والمعاملات الافتراضية مثل `temperature`. أو باستخدام مفتاح إدارة:

```bash
curl https://api.phaseo.app/v1/presets \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name":"@release-summary","config":{"model":"anthropic/claude-sonnet-5.5"}}'
```

</Step>
<Step title="استدعِه بالاسم">

أرسل الإعداد المسبق في `model`. لا يوجد حقل `preset` منفصل.

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "@release-summary",
    "input": "Generate a release summary for the last 24 hours.",
    "meta": true
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "@release-summary",
  input: "Generate a release summary for the last 24 hours.",
  meta: true,
});

console.log(response.model, response.meta?.routing);
```

```python Python
import os

from phaseo import Phaseo

client = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

response = client.generate_response(
    {
        "model": "@release-summary",
        "input": "Generate a release summary for the last 24 hours.",
        "meta": True,
    }
)

print(response.get("model"), response["meta"]["routing"]["selected_provider"])
```
</CodeGroup>

الحقل `model` في الرد هو النموذج الذي أجاب، و`meta.routing.selected_provider` هو المزوّد.

</Step>
<Step title="تحقّق مما طبّقه الإعداد المسبق">

افتح الطلب في **الإعدادات → الاستخدام → السجلات**. يعرض الإعدادات الافتراضية التي طُبّقت من الإعداد المسبق. أما النموذج الذي يقع خارج النماذج المسموح بها في الإعداد المسبق فيفشل بالخطأ `validation_error` (الكلمة المفتاحية `preset_model_not_allowed`) بدلًا من إعادة توجيهه.

</Step>
</Steps>

## فسّر قرار توجيه

عندما لا يُوجَّه طلب بالطريقة التي توقعتها، وسّع **قابلية رصد التوجيه** في الطلب ضمن **الإعدادات → الاستخدام → السجلات**. يجيب هذا القسم عن ثلاثة أسئلة:

| السؤال | انظر إلى |
| --- | --- |
| لماذا تُخطّي مزوّد ما؟ | المزوّدون المستبعدون قبل الترتيب مع السبب، والمزوّدون الذين خُفّض ترتيبهم بسبب حالة الطرح أو التوجيه |
| لماذا حُظر الطلب؟ | حظر سياسة مساحة العمل أو ضابط الحماية على الطلب |
| لماذا فاز هذا المزوّد؟ | الدرجة النهائية لكل مزوّد مرتّب والعوامل التي تقف وراءها |

يشرح [فسّر قرار توجيه](../guides/routing-and-fallbacks#explain-a-routing-decision) كل حقل.

## اطرح تغييرًا في السياسة

1. انشر التغيير كإصدار جديد من الإعداد المسبق، أو أنشئ معرّفًا جديدًا لسياسة مختلفة جدًا.
2. انقل مستدعيًا واحدًا منخفض المخاطر إليه، مثلًا بتوجيهه إلى `@release-summary@v4` أو إلى تسمية `canary`.
3. قارن تفاصيل طلباته واتجاهات استخدامه مع المستدعين الآخرين.
4. انقل بقية المستدعين بمجرد أن يطابق التوجيه ما تتوقعه. وللتراجع، وجّه التسمية إلى الإصدار السابق.

يتناول [الإصدارات والتراجع](../guides/presets#version-and-roll-back) الإصدارات والتسميات. وللتجاوزات على مستوى الطلب التي لا ينبغي أن تكون في إعداد مسبق، راجع [ثبّت المزوّدين أو تجاهلهم](./pin-or-ignore-providers-per-request).
