استدعِ إعدادًا مسبقًا من لوحة التحكم عبر Python مع JSON Schema، ثم تحقّق من الإجابة وسجّل المعرّفات التي تحتاجها لتصحيحها. في النهاية يصبح لديك سكربت واحد يرسل `"model": "@release-summary"`، ويستلم `{"summary": ..., "risk_level": ...}`، ويطبع تفاصيل المزوّد والإضافة لذلك الطلب.

السكربت جاهز للإنتاج بمجرد أن تستبدل الإعداد المسبق والمخطط بما يخصك. احتفظ بخطوة التحقق: الإصلاح يعالج البنية، لا المحتوى.

## ابنِه

<Steps>
<Step title="أنشئ الإعداد المسبق">

في **الإعدادات → الإعدادات المسبقة**، أنشئ `release-summary` مع مطالبة النظام، والنموذج أو النماذج المسموح بها، وتفضيلات المزوّدين، وإعدادات الاستدلال، و`temperature` التي يجب أن يتشاركها كل المستدعين. عندها لا ترسل شيفرة Python إلا ما يتغير. تشرح صفحة [الإعدادات المسبقة](../guides/presets) كيف يُدمج الإعداد المسبق مع الطلب.

</Step>
<Step title="ثبّت SDK">

```bash
pip install phaseo
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="اكتب السكربت">

```python release_summary.py
import json
import os

from phaseo import Phaseo

# Create one client and reuse it.
gateway = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

SCHEMA = {
    "type": "object",
    "properties": {
        "summary": {"type": "string"},
        "risk_level": {"type": "string", "enum": ["low", "medium", "high"]},
    },
    "required": ["summary", "risk_level"],
    "additionalProperties": False,
}


def output_text(response: dict) -> str:
    return "".join(
        part.get("text", "")
        for item in response.get("output", [])
        if item.get("type") == "message"
        for part in item.get("content", [])
        if part.get("type") == "output_text"
    )


def validate(payload: dict) -> dict:
    if set(payload) != {"summary", "risk_level"}:
        raise ValueError(f"unexpected keys: {sorted(payload)}")
    if not isinstance(payload["summary"], str) or not payload["summary"]:
        raise ValueError("summary must be a non-empty string")
    if payload["risk_level"] not in ("low", "medium", "high"):
        raise ValueError("risk_level must be low, medium or high")
    return payload


response = gateway.generate_response(
    {
        "model": "@release-summary",
        "input": "Summarize the last 24 hours of deployment activity.",
        "text": {
            "format": {
                "type": "json_schema",
                "name": "release_summary",
                "strict": True,
                "schema": SCHEMA,
            }
        },
        "plugins": [{"id": "response-healing"}],
        "meta": True,
    }
)

if response.get("status") != "completed":
    raise RuntimeError(f"response {response.get('id')} ended as {response.get('status')}")

payload = validate(json.loads(output_text(response)))
meta = response.get("meta", {})

print("response_id:", response.get("id"))
print("model:", response.get("model"))
print("selected_provider:", meta.get("routing", {}).get("selected_provider"))
print("plugin_executions:", meta.get("plugin_executions"))
print(payload)
```

| الحقل | ما يفعله |
| --- | --- |
| `"model": "@release-summary"` | يستخدم الإعداد المسبق. لا يوجد حقل `preset` منفصل. |
| `text.format` | يطلب JSON Schema هذا. في Chat Completions يوضع في `response_format`؛ راجع [المخرجات المنظَّمة](../guides/structured-outputs). |
| `plugins` | يصلح الـ JSON شبه الصالح؛ راجع [إصلاح الردود](./response-healing-for-structured-json). |
| `meta: true` | يضيف `meta.routing` و`meta.plugin_executions` إلى الرد. |

</Step>
<Step title="شغّله">

```bash
python release_summary.py
```

</Step>
</Steps>

## تحقّق من نجاحه

يطبع السكربت معرّف الرد، والنموذج والمزوّد اللذين أجابا، وسجل الإضافة، وقاموسًا يحتوي على `summary` وإحدى القيم `low` أو `medium` أو `high`. ابحث عن معرّف الرد في **الإعدادات → الاستخدام → السجلات** لترى الطلب نفسه مع تفاصيل توجيهه.

النموذج الذي يقع خارج النماذج المسموح بها في الإعداد المسبق يفشل بالخطأ `validation_error` (الكلمة المفتاحية `preset_model_not_allowed`). أما `ValueError` الصادر من `validate()` فيعني أن الـ JSON حُلّل لكن المحتوى كان خاطئًا: شدّد المخطط أو المطالبة بدلًا من إضافة إعادات محاولة.

## صحّح قبل أن تتجاوز

إذا وُجّه طلب بشكل مختلف عمّا توقعته، فافتحه في السجلات، واقرأ **قابلية رصد التوجيه** وسجل الإضافة، ولا تغيّر الإعداد المسبق إلا بعد أن تُظهر السجلات ما حدث. تكديس التجاوزات المضمّنة في طلب واحد يُفقد الإعداد المسبق فائدته؛ وإذا احتاج مستدعٍ واحد فعلًا إلى سلوك مختلف، فخصّص له إعدادًا مسبقًا خاصًا به.
