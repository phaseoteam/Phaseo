استخدم هذه الوصفة عندما يبقى النموذج نفسه لكنك تريد من البوابة ترتيب عروض مزودي الخدمة بشكل مختلف لطلب واحد.

## الهدف

- فضّل مزود الخدمة الأقل تكلفة لطلب واحد.
- فضّل مزود الخدمة الأقل زمنًا للاستجابة للمسارات التفاعلية.
- فضّل مزود الخدمة الأعلى إنتاجية للتوليد بالجملة.

## 1. أضف `provider.sort` إلى الطلب

في الطلبات النصية، عيّن الترتيب المطلوب مباشرةً في كائن `provider`.

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "google/gemini-3.1-flash-lite",
    "input": "Give me one release-note bullet for the last deploy.",
    "provider": {
      "sort": "price"
    }
  }'
```

```typescript TypeScript SDK
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "google/gemini-3.1-flash-lite",
  input: "Give me one release-note bullet for the last deploy.",
  provider: {
    sort: "price",
  },
});

console.log(response.output_text);
```

```python Python SDK
from phaseo import Phaseo

client = Phaseo(api_key="YOUR_API_KEY")

response = client.generate_response(
    {
        "model": "google/gemini-3.1-flash-lite",
        "input": "Give me one release-note bullet for the last deploy.",
        "provider": {
            "sort": "price",
        },
    }
)

print(response.get("output_text"))
```

```go Go SDK
package main

import (
  "context"
  "fmt"

  phaseo "github.com/phaseoteam/Phaseo/packages/sdk/sdk-go/v3"
)

func main() {
  client := phaseo.New("YOUR_API_KEY", "https://api.phaseo.app/v1")

  response, err := client.GenerateResponse(context.Background(), phaseo.ResponsesRequest{
    Model: "google/gemini-3.1-flash-lite",
    Input: "Give me one release-note bullet for the last deploy.",
    Provider: map[string]interface{}{
      "sort": "price",
    },
  })
  if err != nil {
    panic(err)
  }

  fmt.Println(response)
}
```

أنواع ترتيب التوجيه المدعومة في هذا المسار:

- `price`
- `latency`
- `throughput`

## 2. اختر الترتيب المناسب لعبء العمل

استخدم:

- `price` عندما تكون التكلفة أهم من زمن الاستجابة في الطرف البطيء
- `latency` للمحادثة والمساعدات والأدوات التي تتطلب تدخّلًا بشريًا
- `throughput` للتوليد بكميات كبيرة أو ملء البيانات السابقة

## 3. افهم ما الذي تقارنه البوابة

عند تحديد الترتيب صراحةً على مستوى الطلب، ترتب البوابة المرشحين بطريقة حتمية بدلًا من الخلط الموزون والمتوازن المعتاد.

للنماذج النصية:

- يقارن `price` أساسًا سعريًا مشتركًا بين مزودي الخدمة المؤهلين
- إذا توفرت مقاييس نصية مشتركة، تفضّل البوابة الخيارات المطابقة لـ`input_text_tokens` و`output_text_tokens`
- يستخدم `latency` أحدث بيانات زمن الاستجابة لمزودي الخدمة
- يستخدم `throughput` أحدث قياسات الإنتاجية

## 4. أبقِ مجموعة مزودي الخدمة واقعية

يعمل الترتيب بأفضل شكل بعد تضييق مجموعة المرشحين عند الحاجة.

على سبيل المثال، رتّب مجموعة معتمدة واحدة من مزودي الخدمة فقط:

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \

    "input": "Summarize the incident in one sentence.",
    "provider": {
      "only": ["google-vertex", "google-vertex-eu"],
```

## 5. تحقق من نتيجة الترتيب

عند تصحيح الأخطاء، افحص الطلب في **Gateway -> الاستخدام** وابحث عن:

- مزودي الخدمة الذين جرى النظر فيهم
- مزودي الخدمة المرتبين
- عوامل نقاط التوجيه المتعلقة بالسعر أو زمن الاستجابة أو الإنتاجية

يسهل ذلك التأكد مما إذا كانت البوابة قد رتبت الخيارات كما توقعت.
