فعّل [إصلاح الردود](./response-healing-for-structured-json) مرة واحدة لمساحة العمل كلها أو لإعداد مسبق واحد، بدلًا من تفعيله في كل طلب. في النهاية يحصل كل مستدعٍ يستخدم المخرجات المنظَّمة على سياسة الإصلاح نفسها، ويمكنك قفلها كي لا يوقفها أي إعداد مسبق أو طلب.

هذا إجراء من لوحة التحكم؛ ومثال الطلب في النهاية جاهز للإنتاج.

## كيف تتجمّع الطبقات

يبني Phaseo قائمة الإضافات لكل طلب من ثلاث طبقات. تستبدل الطبقة اللاحقة إعدادات الطبقة السابقة للإضافة نفسها، ما لم تكن السابقة مقفلة:

```mermaid
flowchart LR
  ws["الإعداد الافتراضي لمساحة العمل"] --> pr["إضافات الإعداد المسبق"]
  pr --> rq["إضافات الطلب"]
  rq --> eff["الإضافات التي تعمل"]
  lock["قفل مساحة العمل مفعّل"] -.->|"لا تستطيع الطبقات اللاحقة تغيير response-healing"| pr
```

| الطبقة | تُعيَّن في | تتجاوز |
| --- | --- | --- |
| مساحة العمل | **الإعدادات → التوجيه → إصلاح الاستجابات** | لا شيء |
| الإعداد المسبق | **الإعدادات → الإعدادات المسبقة → (الإعداد المسبق) → إصلاح الاستجابة** | مساحة العمل، ما لم تكن مقفلة |
| الطلب | `plugins` في محتوى الطلب | الإعداد المسبق ومساحة العمل، ما لم تكن مساحة العمل مقفلة |

## أعدّه

<Steps>
<Step title="فعّل الإعداد الافتراضي لمساحة العمل">

في **الإعدادات → التوجيه → إصلاح الاستجابات**، فعّل **التفعيل افتراضيًا** واختر **وضع الإصلاح**: `safe` لإصلاح محدود للبنية، أو `strict` لاستخراج JSON الذي كان صالحًا أصلًا فقط. استخدم هذا للإعدادات الافتراضية العامة التي تشترك فيها جميع مفاتيح API في مساحة العمل.

</Step>
<Step title="اقفله إذا لم يكن قابلًا للتفاوض">

فعّل **قفل سياسة مساحة العمل**. عندها لا تستطيع الإعدادات المسبقة ولا الطلبات إيقاف الإصلاح أو تغيير وضعه. وتظل السجلات تُظهر ما إذا طُبّق أو تُخطّي.

</Step>
<Step title="عيّن إعدادات افتراضية للإعداد المسبق لسير عمل واحد">

في محرر الإعداد المسبق، فعّل **إصلاح الاستجابة** واختر وضعه عندما يجب أن تحمل عائلة من الطلبات تنسيق مخرجات منظَّمة وإصلاحًا معًا. عندها لا يرسل مستدعو ذلك الإعداد المسبق إلا مدخلاتهم.

</Step>
</Steps>

## تجاوزه لطلب واحد

عندما لا تكون مساحة العمل مقفلة، يمكن للطلب تعيين الإضافة بنفسه. يوقفها `"enabled": false` لذلك الطلب:

```json
{
  "model": "openai/gpt-6-astra",
  "input": "Return the summary as JSON.",
  "text": {
    "format": {
      "type": "json_schema",
      "name": "answer",
      "schema": {
        "type": "object",
        "properties": { "summary": { "type": "string" } },
        "required": ["summary"],
        "additionalProperties": false
      }
    }
  },
  "plugins": [{ "id": "response-healing", "enabled": true, "mode": "strict" }],
  "meta": true
}
```

## تحقّق من السياسة التي عملت

افتح الطلب في **الإعدادات → الاستخدام → السجلات**، أو اقرأ `meta.plugin_executions` عندما ترسل `meta: true`. يعرض الحالة (`applied` أو `skipped` أو `failed`)، والوضع الذي عمل فعليًا، وأي `validation_errors` عندما لا يطابق المرشح المُصلَح المخطط.

إذا تصرّفت خدمتان بشكل مختلف، فقارن إعداد مساحة العمل وقفلها، وإضافات الإعداد المسبق، و`plugins` في كل طلب قبل أن تعدّ الأمر مشكلة في النموذج.
