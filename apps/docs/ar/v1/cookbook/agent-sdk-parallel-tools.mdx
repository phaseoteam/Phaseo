اضبط `toolExecution.toolConcurrency` كي يشغّل TypeScript Agent SDK عدة استدعاءات أدوات مستقلة من دور واحد للنموذج في الوقت نفسه بدلًا من تشغيلها واحدًا تلو الآخر. في النهاية يكون لديك وكيل يجمع سياق الوثائق والحالة والحوادث بالتوازي، ويسجّل النتائج مع ذلك بالترتيب الذي طلبها به النموذج.

تُرجع الأدوات بيانات عيّنة ثابتة، لذا فالسكربت توضيحي؛ استبدلها بعمليات بحث خاصة بك للقراءة فقط. توجد نسخة جاهزة في `packages/sdk/agent-sdk-ts/examples/parallel-tool-agent.ts`.

## أنشئه

<Steps>
<Step title="التثبيت">

```bash
npm install @phaseo/agent-sdk zod
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="اكتب الوكيل">

```ts parallel-agent.ts
import { z } from "zod";
import { createAgent, createGatewayAgentClient, defineTool } from "@phaseo/agent-sdk";

const fetchDocs = defineTool({
  id: "fetch-docs",
  description: "Return a short summary of one Phaseo docs page by slug.",
  parameters: {
    type: "object",
    properties: { slug: { type: "string" } },
    required: ["slug"],
    additionalProperties: false,
  },
  inputSchema: z.object({ slug: z.string().regex(/^[a-z0-9/-]{1,80}$/) }).strict(),
  parallelSafe: true,
  timeoutMs: 5_000,
  async execute({ slug }) {
    return { slug, summary: `Docs summary for ${slug}` };
  },
});

const fetchStatus = defineTool({
  id: "fetch-status",
  description: "Return the status of one Phaseo component.",
  parameters: {
    type: "object",
    properties: { component: { type: "string", enum: ["gateway", "dashboard", "async-jobs"] } },
    required: ["component"],
    additionalProperties: false,
  },
  inputSchema: z.object({ component: z.enum(["gateway", "dashboard", "async-jobs"]) }).strict(),
  parallelSafe: true,
  timeoutMs: 5_000,
  async execute({ component }) {
    return { component, status: "operational" };
  },
});

const fetchIncidents = defineTool({
  id: "fetch-incidents",
  description: "Return the open incident count for one service.",
  parameters: {
    type: "object",
    properties: { service: { type: "string", enum: ["gateway", "dashboard", "async-jobs"] } },
    required: ["service"],
    additionalProperties: false,
  },
  inputSchema: z.object({ service: z.enum(["gateway", "dashboard", "async-jobs"]) }).strict(),
  parallelSafe: true,
  timeoutMs: 5_000,
  async execute({ service }) {
    return { service, openIncidents: 0 };
  },
});

const agent = createAgent({
  id: "parallel-tool-agent",
  model: "openai/gpt-6-astra",
  instructions:
    "Use the available tools to gather context, then return one concise operational summary.",
  tools: [fetchDocs, fetchStatus, fetchIncidents],
  toolExecution: { toolConcurrency: 3 },
  maxSteps: 4,
});

const result = await agent.run({
  input:
    "Fetch the presets docs, the gateway status, and the async-jobs incident digest, then summarize the current state.",
  client: createGatewayAgentClient({
    clientOptions: { apiKey: process.env.PHASEO_API_KEY! },
    parallelToolCalls: true,
  }),
  onEvent(event) {
    if (event.type === "tool.started" || event.type === "tool.completed") {
      console.log(event.type, event.toolName, event.timestamp);
    }
  },
});

console.log(result.output);
```

</Step>

## تحقّق من نجاحه

- عندما يطلب النموذج الأدوات الثلاث في دور واحد، تُطبع أسطر `tool.started` الثلاثة قبل أسطر `tool.completed` المقابلة، مع طوابع زمنية متقاربة.
- تسرد `result.messages` نتائج الأدوات بترتيب استدعاءات النموذج للأدوات، أيًا كان ترتيب انتهائها.
- ينتهي التشغيل بملخص واحد في `result.output`.

## ما الذي يعمل معًا

| الإعداد | الأثر |
| --- | --- |
| `toolExecution.toolConcurrency` | يعمل حتى هذا العدد من استدعاءات الأدوات من دور واحد في آن واحد. القيمة الافتراضية `1`. |
| `parallelSafe: true` على كل أداة في الدور | يعمل حتى 8 في آن واحد، أو `toolConcurrency` إن كانت أعلى. استخدمه للأدوات التي للقراءة فقط وحدها. |
| `timeoutMs` على أداة | يفشل ذلك الاستدعاء بعد هذه المدة، كي لا تحجز تبعية عالقة واحدة جميع الخانات. |
| `parallelToolCalls` على عميل الـ Gateway | يسمح للنموذج بطلب عدة استدعاءات أدوات في دور واحد؛ وما إذا كان يفعل ذلك يعتمد على النموذج. |

لا تزال `tool.started` و`tool.completed` تُطلقان لكل استدعاء، ويحفظ التشغيل نقطة تحقق بعد انتهاء مرحلة الأدوات.

## حافظ على أمانه

استخدم التزامن فقط للأدوات التي لا تعتمد على مخرجات بعضها ولا تغيّر حالة مشتركة. ابدأ بـ `2` أو `3`، واجعل الأدوات متساوية القوى (idempotent) وقليلة الآثار الجانبية، وتحقّق من كل وسيط باستخدام `inputSchema` كما في الأعلى. أضف موصّل `state`، كما في [حلقة الوكيل المستدامة](./agent-sdk-durable-loop)، فقط عندما تحتاج إلى استئناف التشغيلات. قبل الاعتماد عليه، شغّل اختباراتك التي تغطي الأدوار متعددة الأدوات وتحقّق من ترتيب النتائج.
