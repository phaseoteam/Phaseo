أضف متطلبات الإقامة و<Tooltip tip="عدم الاحتفاظ بالبيانات: لا يحتفظ المزوّد بالمطالبات أو المخرجات.">ZDR</Tooltip> إلى كائن `provider` في طلب واحد، وسيستبعد Phaseo كل عرض مزوّد لا يستوفيها قبل أن يرتّب البقية. في النهاية يعمل سير عمل واحد فقط على مزوّدي الاتحاد الأوروبي أو المزوّدين الداعمين لـ ZDR، دون تغيير السياسة لمساحة العمل كلها.

الطلب جاهز للإنتاج. إذا لم يستوفِ أي مزوّد للنموذج كل المتطلبات، يفشل الطلب قبل استدعاء أي مزوّد، لذا تحقّق من التوفر أولًا.

| الحقل | يُبقي فقط المزوّدين الذين |
| --- | --- |
| `required_execution_region: "eu"` | يشغّلون النموذج في الاتحاد الأوروبي |
| `required_data_region: "eu"` | يعالجون بيانات المطالبة والإكمال في الاتحاد الأوروبي |
| `require_zero_data_retention: true` | يستوفون متطلبات عدم الاحتفاظ بالبيانات |

## أرسل طلبًا مقيّدًا

<Steps>
<Step title="تحقّق من أن مزوّدًا مؤهَّل">

في صفحة النموذج، تعرض بطاقات المزوّدين العروض الإقليمية مثل **OpenAI EU** أو **Google Vertex EU**، ودعم ZDR، وملاحظات سياسة البيانات لكل مزوّد ومصادرها. وبالنسبة إلى الاتحاد الأوروبي، يمكنك أيضًا سرد ما يقدّمه Gateway الاتحاد الأوروبي:

```bash
curl https://eu.api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

</Step>
<Step title="أضف فقط المتطلبات التي تحتاجها">

كل متطلب يقلّص المجموعة، لذا قد يوجّه الطلب إلى عرض إقليمي أغلى أو لا يترك أي مزوّد على الإطلاق. أرسل فقط ما تفرضه سياستك:

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5.6-luna",
    "input": "Summarize the ticket in one line.",
    "provider": {
      "required_execution_region": "eu",
      "required_data_region": "eu"
    },
    "meta": true
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "openai/gpt-5.6-luna",
  input: "Summarize the ticket in one line.",
  provider: {
    required_execution_region: "eu",
    required_data_region: "eu",
  },
  meta: true,
});

console.log(response.meta?.routing);
```

```python Python
import os

from phaseo import Phaseo

client = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

response = client.generate_response(
    {
        "model": "openai/gpt-5.6-luna",
        "input": "Summarize the ticket in one line.",
        "provider": {
            "required_execution_region": "eu",
            "required_data_region": "eu",
        },
        "meta": True,
    }
)

print(response["meta"]["routing"]["selected_provider"])
```
</CodeGroup>

لاشتراط ZDR أيضًا، أضف `"require_zero_data_retention": true`. مع المتطلبات الثلاثة، يحتاج النموذج إلى مزوّد واحد على الأقل في الاتحاد الأوروبي يستوفي ZDR كذلك.

</Step>
<Step title="تحقّق من مكان التشغيل">

يذكر `meta.routing.selected_provider` المزوّد الذي خدم الطلب، مثل `openai-eu`. ويسجّل الطلب في **الإعدادات → الاستخدام → السجلات** المناطق المطلوبة والمزوّد المختار.

</Step>
</Steps>

## اختر بين حقول الطلب وGateway الاتحاد الأوروبي وإعدادات مساحة العمل

| استخدم | عندما |
| --- | --- |
| حقول الطلب هذه على `api.phaseo.app` | تنطبق القاعدة على سير عمل أو عميل أو طلب واحد. وتبقى جميع نقاط النهاية والميزات متاحة. |
| [`eu.api.phaseo.app`](../guides/regional-routing) | يجب أن يبقى كل طلب نصي من خدمة ما داخل الاتحاد الأوروبي. يفرض اسم المضيف المنطقة، ويرفض أيضًا مدخلات الوسائط وأدوات خادم Phaseo والأدوات المستضافة لدى المزوّد. وإرسال `required_execution_region` أو `required_data_region` لمنطقة أخرى هناك يعيد `400 validation_error` مع السبب `deployment_region_conflict`. |
| **الإعدادات → الخصوصية** | تنطبق القاعدة على كل طلب في مساحة العمل. |

يقيّد التوجيه الإقليمي المزوّدين الذين يعالجون استدعاء النموذج. وهو ليس بعدُ ضمانًا كاملًا لإقامة البيانات من البداية إلى النهاية؛ تسرد صفحة [ما يبقى خارج المنطقة](../guides/regional-routing#what-stays-outside-the-region) الأنظمة المشتركة. لتقييد المزوّدين دون قاعدة إقامة، راجع [ثبّت المزوّدين أو تجاهلهم](./pin-or-ignore-providers-per-request).
