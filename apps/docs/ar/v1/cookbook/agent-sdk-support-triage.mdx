أنشئ وكيل فرز بلغة TypeScript يأتي نموذجه ومطالبته وقواعد مزوّديه من إعداد مسبق في لوحة التحكم، كي لا يتولى الكود إلا سير العمل. في النهاية يُرجع قرار فرز بصيغة JSON صارمة، ويوقف الحالات التي تحتاج إلى شخص، ويعيد محاولة استدعاءات النموذج عددًا محدودًا من المرات، ويسجّل إخفاقات الـ Gateway مع المعرّفات التي تحتاج إليها للعثور عليها.

يصبح السكربت جاهزًا للإنتاج بمجرد وجود الإعداد المسبق وتخزينك للتشغيلات المتوقفة، كما في [حلقة الوكيل المستدامة](./agent-sdk-durable-loop). توجد نسخة جاهزة في `packages/sdk/agent-sdk-ts/examples/support-triage-agent.ts`.

## أنشئه

<Steps>
<Step title="أنشئ الإعداد المسبق">

في **الإعدادات → الإعدادات المسبقة**، أنشئ `support-triage` مع النموذج الموجَّه وتفضيلات المزوّدين ومطالبة النظام الخاصة بالدعم ومعاملات فك ترميز ثابتة. يجب أن يدعم النموذج مخرجات JSON Schema. تشرح صفحة [الإعدادات المسبقة](../guides/presets) كيف يُدمج الإعداد المسبق مع كل طلب.

</Step>
<Step title="التثبيت">

```bash
npm install @phaseo/agent-sdk zod
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="اكتب الوكيل">

```ts triage-agent.ts
import { z } from "zod";
import { AgentGatewayError, createAgent, createGatewayAgentClient } from "@phaseo/agent-sdk";

const SupportTriageDecision = z
  .object({
    queue: z.enum(["billing", "reliability", "product", "security"]),
    severity: z.enum(["low", "medium", "high"]),
    needsHumanReview: z.boolean(),
    summary: z.string().min(1),
  })
  .strict();
type SupportTriageDecision = z.infer<typeof SupportTriageDecision>;

// يصبح `preset` النموذج `@support-triage` في كل دور.
const supportTriageAgent = createAgent<string, SupportTriageDecision>({
  id: "support-triage-agent",
  preset: "support-triage",
  maxSteps: 3,
  parseOutput: (text) => JSON.parse(text),
  outputSchema: SupportTriageDecision,
  humanReview: ({ parsedOutput }) =>
    parsedOutput?.needsHumanReview
      ? { reason: "support_triage_review_required", payload: parsedOutput }
      : null,
});

const client = createGatewayAgentClient({
  clientOptions: { apiKey: process.env.PHASEO_API_KEY! },
  responseFormat: {
    type: "json_schema",
    name: "support_triage_decision",
    schema: {
      type: "object",
      properties: {
        queue: { type: "string", enum: ["billing", "reliability", "product", "security"] },
        severity: { type: "string", enum: ["low", "medium", "high"] },
        needsHumanReview: { type: "boolean" },
        summary: { type: "string" },
      },
      required: ["queue", "severity", "needsHumanReview", "summary"],
      additionalProperties: false,
    },
  },
  plugins: [{ id: "response-healing", mode: "strict" }],
});

try {
  const result = await supportTriageAgent.run({
    input: "Customer says webhook deliveries failed overnight and asks whether data was lost.",
    client,
    modelRetry: { maxRetries: 2, backoffMs: 250 },
    onEvent(event) {
      if (event.type === "model.retrying") console.log("retrying", event.attempt, event.error);
    },
  });

  if (result.run.status === "waiting_for_human") {
    // خزّن `result`، ثم تابع بعد أن يراجعه موظف دعم.
    console.log("Needs review:", result.run.pause?.payload);
  } else {
    console.log(result.output);
  }
} catch (error) {
  if (error instanceof AgentGatewayError) {
    console.error("Gateway request failed", {
      status: error.status,
      requestId: error.requestId,
      generationId: error.generationId,
      reason: error.reason,
      providerFailureDiagnostics: error.providerFailureDiagnostics,
      routingDiagnostics: error.routingDiagnostics,
    });
  }
  throw error;
}
```

</Step>

## تحقّق من نجاحه

شغّل تذكرة روتينية واحدة وتذكرة خطرة واحدة، ثم تحقّق مما يلي:

- في **الإعدادات → الاستخدام → السجلات**، يُظهر نموذج الطلب أن الإعداد المسبق قد استُخدم.
- تنتهي الحالة الخطرة عند `waiting_for_human` مع وجود القرار في `pause.payload`.
- يُسجَّل استدعاء النموذج المُعاد على الخطوة بوصفه `modelAttempts`، وتسجّل كل إعادة محاولة `model.retrying`.
- يُسجَّل الطلب المحظور مع `requestId` و`reason` الخاصين به، ويُظهر الطلب نفسه في السجلات سبب حظره.

## أبقِ إخفاقات الـ Gateway ظاهرة

لا تبتلع الأخطاء داخل دوال رد النداء الخاصة بالوكيل. التقط `AgentGatewayError` عند الحافة، وسجّل معرّفاته، ثم أعد رميه. بمجرد فشل التشغيل، تحتفظ حالته المحفوظة بالتفاصيل نفسها في `run.errorDetails` و`steps[n].errorDetails`، كي تتمكن مهمة استرداد لاحقة من قراءتها بعد زوال الاستثناء.

تأتي هذه الإخفاقات من سياسة الـ Gateway، لا من الوكيل، لذا فالطلب في السجلات هو المكان الذي تبحث فيه:

| الإخفاق | أين يظهر |
| --- | --- |
| ضابط حماية يحظر الطلب | قسم **تطبيق ضوابط الحماية** في الطلب |
| النماذج المسموح بها في الإعداد المسبق ترفض النموذج | `validation_error` مع الكلمة المفتاحية `preset_model_not_allowed` |
| بيانات اعتماد المزوّدين أو تفعيلهم لا تترك أي مزوّد | `providerFailureDiagnostics` و**قابلية رصد التوجيه** |
| الإصلاح لا يستطيع إنتاج JSON صالح وفق المخطط | سجل الإضافة، ثم `AgentSchemaValidationError` من `outputSchema` |
