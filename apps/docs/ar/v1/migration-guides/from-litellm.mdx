وجّه العملاء الذين يستدعون وكيل LiteLLM إلى `https://api.phaseo.app/v1` باستخدام مفتاح Phaseo، ثم طابق كل اسم مستعار `model_name` وكل إعداد في الوكيل بعناية. للإبقاء على LiteLLM واستخدام Phaseo كمصدر upstream له بدلًا من ذلك، راجع [تكامل LiteLLM](../guides/integrations/litellm).

| الإعداد | وكيل LiteLLM | Phaseo |
| --- | --- | --- |
| عنوان URL الأساسي | وكيلك، وغالبًا `http://localhost:4000` | `https://api.phaseo.app/v1` |
| مفتاح API | `LITELLM_MASTER_KEY` أو مفتاح افتراضي | `PHASEO_API_KEY` |
| النموذج | اسم مستعار `model_name` من `config.yaml` | معرّف نموذج Phaseo، أو إعداد مسبق (`"model": "@slug"`)، أو دالة مطابقة واحدة |
| التوجيه والإعدادات الافتراضية | `router_settings` و`litellm_settings` | [الإعدادات المسبقة](../guides/presets) و[التوجيه والاحتياط](../guides/routing-and-fallbacks) |

## تبديل العميل

<CodeGroup>
```typescript TypeScript
import OpenAI from "openai";

// قبل:
// new OpenAI({ apiKey: process.env.LITELLM_API_KEY, baseURL: process.env.LITELLM_BASE_URL });
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-6-astra",
  messages: [{ role: "user", content: "Reply with: migration ready" }],
});
```

```python Python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
)
```

```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role": "user", "content": "Reply with: migration ready"}]
  }'
```
</CodeGroup>

يحتاج كل اسم مستعار إلى مطابقة صريحة مع معرّف موجود في `GET /v1/models?format=openai`. إذا كان المستدعون يستخدمون أسماء مستعارة داخلية، فترجمها في دالة واحدة عند حدود العميل بدلًا من تعديل كل طلب.

## مطابقة إعدادات الوكيل

اجرد الاستدعاءات الراجعة والميزانيات وإعادات المحاولة قبل إزالة الوكيل: فهي تتوقف بصمت عند إزالته.

| LiteLLM | على Phaseo |
| --- | --- |
| `fallbacks` | مصفوفة `models` أو احتياطات المسار الديناميكي، تُجرَّب عند `429` و`500` و`502` و`503` و`504`، ولا تُجرَّب أبدًا عند أخطاء الطلب. |
| `context_window_fallbacks` و`content_policy_fallbacks` | لا يوجد مقابل: لا يلجأ Phaseo أبدًا إلى الاحتياط عند `400`. تعامل معها في التطبيق. |
| `routing_strategy` | وضع التوجيه لمساحة العمل أو `provider.sort` (`price` أو `latency` أو `throughput`). |
| اختيار المزوّد لكل عملية نشر | `provider.order` أو `provider.only` أو `provider.ignore`، أو [معرّف مؤهَّل بالمزوّد](../guides/provider-qualified-models) مثل `provider:org/model`، الذي لا يلجأ إلى مزوّدين آخرين. |
| عمليات النشر المستضافة ذاتيًا (vLLM وما شابه) | [النماذج الخاصة](../guides/private-models)، التي تحتاج إلى نقطة نهاية `/chat/completions` عامة عبر HTTPS ومتوافقة مع OpenAI مع مصادقة bearer. |
| ذاكرة التخزين المؤقت للاستجابات (`litellm_settings.cache`) | لا توجد ذاكرة تخزين مؤقت للاستجابات. خزّن مؤقتًا في التطبيق عند الحاجة؛ ولا يزال [التخزين المؤقت للمطالبات](../guides/prompt-caching) يخفّض تكلفة الإدخال. |
| المفاتيح الافتراضية (`max_budget` و`rpm_limit` و`tpm_limit` و`max_parallel_requests` و`models`) | مفاتيح API مع حدود إنفاق ونماذج مسموح بها، وميزانيات، وسياسات حدود المعدّل للطلبات في الدقيقة والرموز في الدقيقة والطلبات المتزامنة. راجع [الحدود](../api-reference/limits). |
| ميزانيات الفرق و`metadata.tags` | ميزانيات الأقسام و[تسميات](../guides/request-labels) `X-Phaseo-Metadata`. تُطابق ميزانيات المستخدم النهائي مع سياسة حد المعدّل للمستخدم النهائي فقط؛ ولا يوجد حد إنفاق للمستخدم النهائي. |
| `guardrails` (Presidio وLakera وما شابه) | تفحص ضوابط الحماية للمفاتيح الطلبات بحثًا عن حقن المطالبات والمعلومات الشخصية (PII). لا تُفحص الاستجابات. |
| الاستدعاءات الراجعة (`success_callback` وLangfuse وDatadog وOpenTelemetry) | [وجهات المراقبة](../guides/integrations/observability) أو التتبّع في جهة العميل. تُصدَّر `metadata` في الجسم بوصفها `phaseo.metadata.<key>`. |
| مفاتيح API للمزوّدين في الإعدادات | BYOK (`phaseo byok create --provider <id> --name <name> --key-stdin` أو `POST /v1/byok`)، أو أرصدة Phaseo. اضبط `byok_fallback_enabled` باستخدام `phaseo settings update` للرجوع إلى الأرصدة. |

يرسل الوكيل حركة فريق كامل عبر مالك مفتاح واحد، لذا يتشارك حصة الطلبات في الدقيقة الخاصة بذلك المستخدم، وهي 10 لمساحة العمل الجديدة. راجع [حدود Gateway](../api-reference/limits#gateway-limits) ورتّب حدًا أعلى قبل التحويل.

## الاختبار والنشر

اختبر البث والأدوات والمخرجات المنظّمة وإعادات المحاولة ومطابقة الأخطاء وأي بيانات قياس عن بُعد تعتمد على الاستدعاءات الراجعة كان الوكيل يتولاها. قارن زمن الاستجابة والمخرجات واستخدام الرموز والتكلفة قبل نقل الحركة تدريجيًا. قبل التحويل، تأكد من أن:

- كل عنوان URL ومفتاح ومتغير `LITELLM_*` خاص بـ LiteLLM قد حُدّد؛
- لكل اسم مستعار إنتاجي مطابقة صريحة في Phaseo؛
- الإعدادات الافتراضية المشتركة موجودة في إعدادات مسبقة أو في دالة حدود واحدة؛
- للاستدعاءات الراجعة وبيانات القياس المطلوبة بديل؛
- قررت ما إذا كان LiteLLM أو Phaseo أو كلاهما هو السجل المعتمد للإنفاق؛
- التراجع لا يزال مجرد تغيير لعنوان URL الأساسي والمفتاح.
