احتفظ بـ OpenAI SDK وغيّر أمرين: عنوان URL الأساسي ومفتاح API. ثم امنح كل نموذج معرّفه في Phaseo، الذي يضيف البادئة `openai/`.

| الإعداد | OpenAI | Phaseo |
| --- | --- | --- |
| عنوان URL الأساسي | القيمة الافتراضية في SDK (`https://api.openai.com/v1`) | `https://api.phaseo.app/v1` |
| مفتاح API | `OPENAI_API_KEY` | `PHASEO_API_KEY`، يُرسل بوصفه `Authorization: Bearer` |
| النموذج | `gpt-4.1-mini` | `openai/gpt-4.1-mini`، أو أي معرّف من `GET /v1/models` |
| شيفرة الطلب | `chat.completions.create` و`responses.create` | دون تغيير |

## تبديل العميل

أنشئ مفتاحًا في [مفاتيح API](https://phaseo.app/settings/keys)، وأضفه إلى كل بيئة تشغّل التطبيق. ثم مرّره مع عنوان URL الأساسي إلى العميل الحالي:

<CodeGroup>
```typescript TypeScript
import OpenAI from "openai";

// قبل: const client = new OpenAI();
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Reply with: migration ready" }],
});
```

```python Python
import os
from openai import OpenAI

# قبل: client = OpenAI()
client = OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
)

response = client.chat.completions.create(
    model="openai/gpt-4.1-mini",
    messages=[{"role": "user", "content": "Reply with: migration ready"}],
)
```

```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-4.1-mini",
    "messages": [{"role": "user", "content": "Reply with: migration ready"}]
  }'
```
</CodeGroup>

استخدم اسم متغير جديدًا بدلًا من وضع مفتاح Phaseo في `OPENAI_API_KEY`، وأزل قيم `OPENAI_BASE_URL` القديمة حتى لا يواصل أي عميل آخر في المستودع استدعاء OpenAI. تنتقل عملاء `AzureOpenAI` إلى عميل `OpenAI` العادي؛ وتُطابق أسماء عمليات النشر في Azure مع معرّفات نماذج Phaseo بالطريقة نفسها.

## مطابقة معرّفات النماذج

اعرض المعرّفات التي يقدّمها Phaseo بتنسيق القائمة الخاص بـ OpenAI، وتحقّق من كل نموذج إنتاجي مقابل `data[].id`:

```bash
curl "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

دون `format=openai`، تكون الاستجابة قائمة `models` المقسّمة إلى صفحات الخاصة بـ Phaseo، ولا تحتوي على مصفوفة `data`. وينطبق الأمر نفسه على `client.models.list()`: مرّر `{ query: { format: "openai" } }` في Node أو `extra_query={"format": "openai"}` في Python. تضم القائمة الافتراضية النماذج التي يمكنك استدعاؤها الآن فقط؛ أضف `availability=all` لتضمين النماذج غير النشطة والقادمة قريبًا.

## ما الذي يعمل بشكل مختلف

| ميزة OpenAI | على Phaseo |
| --- | --- |
| Chat Completions وResponses | أشكال الطلبات نفسها على `/v1/chat/completions` و`/v1/responses`. يعيد الحقل غير المعروف في المستوى الأعلى `400` `unknown_param`. |
| `previous_response_id` و`conversation` | يعيدان `400`: لا يخزّن Phaseo الاستجابات. أرسل السجل الكامل في `input` مع كل طلب. |
| التضمينات والإشراف والصور والكلام والنسخ الصوتي | `/v1/embeddings` و`/v1/moderations` و`/v1/images/*` و`/v1/audio/*`. تحقّق من أن النموذج يدعم العملية. |
| Batch API | `/v1/files` و`/v1/batches`. يحتفظ `/v1/files` بمدخلات الدُفعات فقط؛ ولا يمكنه توفير مدخلات `file_id` لطلبات أخرى. |
| Realtime | `POST /v1/audio/realtime/sessions`، ثم اتصال WebSocket بعنوان `connect.url` المُعاد. راجع [الصوت في الوقت الفعلي](../guides/realtime-voice). |
| المطالبات المخزّنة (`prompt: { id: "pmpt_…" }`) | أعد إنشاء المطالبة كإعداد مسبق واستدعها باستخدام `prompt: { id: "@slug", version, variables }`. راجع [قوالب المطالبات](../guides/prompt-templates). |
| `organization` و`project` وترويسة `OpenAI-Organization` | لا يوجد مقابل. أزلها؛ واستخدم مساحات العمل والمفاتيح في Phaseo. |
| Assistants وThreads ومخازن المتجهات والضبط الدقيق و`/v1/completions` القديمة | لا توجد نقطة نهاية في Phaseo. أبقِها على OpenAI أو انقلها إلى `/v1/responses`. |

## الاختبار والنشر

شغّل المطالبات التمثيلية نفسها على الإعدادين القديم والجديد، وقارن شكل المخرجات وزمن الاستجابة واستخدام الرموز والأخطاء والتكلفة. قبل نقل الحركة، تأكد من أن:

- مفتاح Phaseo مضبوط في بيئات التطوير والاختبار المرحلي والإنتاج؛
- كل معرّف نموذج إنتاجي يظهر في `GET /v1/models?format=openai`؛
- طلبًا غير متدفق وطلبًا متدفقًا ينجحان في بيئة الاختبار المرحلية، إضافة إلى استدعاءات الأدوات والمخرجات المنظّمة إذا كان التطبيق يستخدمها؛
- التراجع لا يزال مجرد تغيير لعنوان URL الأساسي والمفتاح.

ثم انقل الحركة تدريجيًا. يشرح [التوجيه والاحتياط](../guides/routing-and-fallbacks) النماذج الاحتياطية، ويسرد [معالجة الأخطاء](../api-reference/errors.mdx) أجسام الأخطاء التي قد يراها تطبيقك الآن.
