استخدم هذه المراجعة قبل التخطيط للتحويل إلى بوابة أخرى. فهي تركّز على السلوكيات التي قد تتغير حتى عندما تقبل المنصتان طلبات متوافقة مع OpenAI.

## 1. احصر حدود التكامل

سجّل كل المواضع التي تظهر فيها البوابة الحالية:

- عناوين URL الأساسية ومتغيرات البيئة لمفاتيح API
- تهيئة SDK والرؤوس المخصصة
- معرّفات النماذج ونماذج الرجوع الاحتياطية
- ترتيب المزوّدين وقوائم السماح ومتطلبات الخصوصية
- شيفرة البث واستدعاء الأدوات والمخرجات المنظّمة
- مهام الدُفعات والملفات وخطافات الويب واستقصاء الحالة غير المتزامن
- إسناد الطلب وبيانات المستخدم أو الجلسة الوصفية

احتفظ بهذا الجرد مع خطة الإطلاق كي يتمكن المراجعون من التأكد من أن الترحيل لم يترك مسار إعداد ثانٍ مخفيًا.

## 2. صنّف كل قدرة

عيّن حالة لكل سلوك مستخدم في الإنتاج:

| الحالة | المعنى |
| --- | --- |
| دون تغيير | تم التحقق من استخدام حقل الطلب نفسه وسلوك الاستجابة نفسه. |
| معيّن | تدعم Phaseo النتيجة عبر حقل أو إعداد مختلف. |
| يحتاج إلى تكييف | تترجم طبقة التوافق الطلب أو الاستجابة. |
| غير مدعوم | يجب على حمل العمل إزالة الاعتماد أو البقاء على مساره الحالي. |
| غير متحقق منه | قد يكون الدعم متاحًا، لكن لا تزال الأدلة في ظروف قريبة من الإنتاج غير كافية. |

استخدم [قائمة التحقق من ميزات الترحيل](./feature-parity-matrix.mdx) لتغطية الطلبات الأساسية والتوجيه والإسناد والمهام غير المتزامنة والتشغيل.

## 3. تحقّق من حركة مرور تمثيلية

أنشئ مجموعة اختبارات صغيرة من أنماط حمل العمل الفعلية، من دون نسخ بيانات إنتاج حساسة.

اختبر ما يلي:

1. طلبًا عاديًا واحدًا لكل نقطة نهاية مستخدمة.
2. البث عبر مسار العميل نفسه المستخدم في الإنتاج.
3. استدعاءات الأدوات والمخرجات المنظّمة باستخدام مخططات واقعية.
4. كل قيود المزوّد أو الخصوصية.
5. المفاتيح والنماذج غير الصالحة وحدود المعدل وأخطاء عدم توفر المزوّد.
6. مهام الدُفعات أو المهام غير المتزامنة حتى حالات النجاح أو الفشل أو الإلغاء النهائية.

قارن جودة المخرجات وزمن الاستجابة واستخدام الرموز والمزوّد المختار والتكلفة النهائية. سجّل معرّف الطلب لكل نتيجة كي تتمكن من فحصها ضمن استخدام Gateway.

## 4. حافظ على الإسناد وقابلية الرصد

أبقِ رؤوس إسناد التطبيق عندما تصف التطبيق الذي أجرى الاستدعاء. تدعم Phaseo معرّفات التطبيقات وأسماءها وعناوين URL وفئاتها المستقرة؛ وإزالتها أثناء الترحيل تصعّب مقارنة التكلفة والاستخدام.

راجع [إسناد التطبيقات](../guides/app-attribution.mdx) للاطلاع على الرؤوس وقيم الفئات المدعومة.

## 5. أطلق التغيير مع إمكانية الرجوع عنه

ابدأ بحركة مرور التطوير والاختبار الداخلي. حوّل نسبة صغيرة من حركة مرور الإنتاج بعد اجتياز مجموعة الاختبارات، واجعل التراجع مقتصرًا على إعدادات نقطة النهاية وبيانات الاعتماد إلى أن تستقر النتائج.

لا تجمع التحويل الأولي مع تحسينات غير مرتبطة للمطالبات أو النماذج أو التوجيه. أجرِ تلك التغييرات بعد التحقق من حدود البوابة.
