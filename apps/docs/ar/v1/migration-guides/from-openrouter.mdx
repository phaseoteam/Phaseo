غيّر عنوان URL الأساسي إلى `https://api.phaseo.app/v1` والمفتاح إلى `PHASEO_API_KEY`. تظل حمولات الطلبات وترويسة `Authorization: Bearer` وكائن `provider` ومصفوفة الاحتياط `models` تعمل؛ تحقّق من معرّفات النماذج ومن الحقول القليلة في الجدول أدناه.

| الإعداد | OpenRouter | Phaseo |
| --- | --- | --- |
| عنوان URL الأساسي | `https://openrouter.ai/api/v1` | `https://api.phaseo.app/v1` |
| مفتاح API | `OPENROUTER_API_KEY` (`sk-or-v1-…`) | `PHASEO_API_KEY` |
| المصادقة | `Authorization: Bearer <key>` | دون تغيير |
| حمولة الطلب | متوافقة مع OpenAI | دون تغيير |
| معرّفات النماذج | `<org>/<model>` | `<org>/<model>`؛ معظمها متطابق، وتختلف بعض الجهات |
| ترويسات الإسناد | `HTTP-Referer` و`X-Title` | دون تغيير؛ أضف `X-App-Id` لتجميع ثابت |

## تبديل العميل

<CodeGroup>
```typescript قبل
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.OPENROUTER_API_KEY,
  baseURL: "https://openrouter.ai/api/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Summarize our migration plan." }],
});
```

```typescript بعد
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Summarize our migration plan." }],
});
```

```bash cURL
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role":"user","content":"Say hello"}]
  }'
```
</CodeGroup>

أبقِ الحمولة دون تغيير في المرحلة الأولى، وحقّق التكافؤ قبل التحسين. أزل `OPENROUTER_BASE_URL` والمفتاح القديم من الشيفرة وإعدادات CI والاستضافة. يصبح `@openrouter/ai-sdk-provider` هو `@phaseo/ai-sdk-provider` (راجع [الترحيل من Vercel AI Gateway](./from-vercel))؛ أما حِزم SDK الخاصة بـ OpenRouter (`@openrouter/sdk` و`openrouter` على PyPI) فتحتاج إلى تغيير العميل، لا مجرد عنوان URL أساسي جديد.

## التحقق من معرّفات النماذج

معظم المعرّفات متطابقة، لكن بعض الجهات تختلف: `x-ai/` تصبح `spacex-ai/`، و`meta-llama/` تصبح `meta/`، و`mistralai/` تصبح `mistral/`. اعرض معرّفات Phaseo وتحقّق من كل نموذج إنتاجي مقابلها:

```bash
curl -s "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY" | jq -r '.data[].id'
```

تحتوي القائمة الافتراضية على النماذج التي يمكنك استدعاؤها الآن فقط؛ أضف `availability=all` لرؤية النماذج غير النشطة أو القادمة قريبًا. دون `format=openai` تكون الاستجابة قائمة `models` المقسّمة إلى صفحات الخاصة بـ Phaseo، ولا تحتوي على مصفوفة `data`.

## مطابقة حقول الطلب

| OpenRouter | على Phaseo |
| --- | --- |
| `provider.order` و`only` و`ignore` و`allow_fallbacks` و`require_parameters` و`max_price` | الحقول نفسها. استخدم معرّفات المزوّدين الأساسية، لا معرّفات نقاط النهاية المختصرة. |
| `provider.sort` | الحقل نفسه: `price` أو `latency` أو `throughput`. |
| `provider.zdr` | مقبول كاسم بديل لـ `provider.require_zero_data_retention`. |
| `provider.data_collection: "deny"` | يعيد `400`. استخدم `zdr: true` بدلًا منه. |
| مصفوفة الاحتياط `models` | الأمر نفسه، من 1 إلى 25 إدخالًا. الحقل `model` مطلوب، لذا انقل `models[0]` إليه. |
| اللاحقة `:nitro` | الأمر نفسه (الإنتاجية). يوفّر Phaseo أيضًا `:cheap` و`:fast`؛ وتصبح `:floor` هي `:cheap`. أزل `:online` و`:thinking` واستخدم البحث على الويب و`reasoning` بدلًا منهما. |
| `openrouter/auto` و`openrouter/free` | `phaseo/auto` ([التوجيه التلقائي](../guides/auto-routing)، ألفا، ولا يمكن دمجه مع `models`) و`phaseo/free`. |
| `plugins` بقيم `web` و`web-fetch` و`response-healing` | معرّفات الإضافات نفسها. تعيد الإضافات الأخرى، مثل `file-parser`، الخطأ `400`. |
| `transforms` و`usage: { include: true }` | غير مقبولة. أزلها؛ إذ يُعاد الاستخدام والتكلفة دائمًا. |
| `X-OpenRouter-Title` | أعد تسميتها إلى `X-Title`. راجع [إسناد التطبيق](../guides/app-attribution). |
| الإعدادات المسبقة `@preset/<slug>` | أعد إنشاءها بوصفها [إعدادات مسبقة](../guides/presets) واستدعها بصيغة `"model": "@slug"`. |
| `usage.cost` و`reasoning_details` و`provider` في الاستجابات | تُعاد. أما `native_finish_reason` و`is_byok` فلا تُعاد؛ وحّدها في طبقة واحدة إذا كان المستدعون يقرؤونها. |

يوفّر Phaseo أيضًا `provider.required_execution_region` و`provider.required_data_region`، وليس لهما مقابل في OpenRouter. راجع [تثبيت المزوّدين أو تجاهلهم](../cookbook/pin-or-ignore-providers-per-request) و[التوجيه فقط إلى مزوّدين في الاتحاد الأوروبي أو يدعمون ZDR](../cookbook/route-only-to-eu-or-zdr-providers) للاطلاع على طلبات كاملة.

أبقِ أي حقول متبقية خاصة بـ OpenRouter في محوّل واحد بدلًا من كل موضع استدعاء، حتى يبقى التراجع مجرد تغيير لعنوان URL الأساسي والمفتاح.

## التحقق قبل التحويل

شغّل هذه الطلبات على Phaseo، ثم الفحوصات نفسها عبر مسار العميل الخاص بتطبيقك:

```bash
curl -s "https://api.phaseo.app/v1/health"

curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"openai/gpt-6-astra","messages":[{"role":"user","content":"Say hello"}]}'

# البث
curl -N "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"openai/gpt-6-astra","stream":true,"messages":[{"role":"user","content":"Reply with: stream works"}]}'

# نموذج غير صالح: يجب أن يعالج التطبيق الخطأ دون كشف بيانات الاعتماد
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"invalid/migration-test","messages":[{"role":"user","content":"test"}]}'
```

قبل نقل حركة ذات شأن، تأكد من أن:

- `OPENROUTER_API_KEY` قد استُبدل بـ `PHASEO_API_KEY` في كل بيئة؛
- كل معرّف نموذج إنتاجي موجود في `GET /v1/models?format=openai`؛
- طلبًا غير متدفق وطلبًا متدفقًا ينجحان عبر `/v1/chat/completions` أو `/v1/responses`، باستخدام مسار العميل نفسه المستخدم في الإنتاج؛
- مسارات استدعاء الأدوات والمخرجات المنظّمة تنجح بمطالبات حقيقية؛
- حالات فشل المفتاح غير الصالح والنموذج غير الصالح تُعالَج؛
- يمكن البحث عن طلب فاشل باستخدام `GET /v1/generations?id=<request_id>`، وعندما تكون قيمة `replay_supported` هي `true`، يمكن إعادة تشغيله من `replay_request`؛
- الترويسات وحقول الاستجابة الخاصة بـ OpenRouter قد أُزيلت أو وُحّدت، والإعدادات الافتراضية المشتركة موجودة في الإعدادات المسبقة.

## النشر

1. ابدأ بالحركة الداخلية.
2. انقل 5-10% من حركة الإنتاج وقارن الجودة وزمن الاستجابة والتكلفة.
3. ارفع النسبة إلى 100% بعد تأكيد التكافؤ.
4. أبقِ التراجع مجرد تبديل لعنوان URL الأساسي والمفتاح حتى يستقر التحويل.

## تسليم الترحيل إلى وكيل برمجة

امنح الوكيل هذا التسلسل المحدد، أو ثبّت [مهارة الترحيل من OpenRouter إلى Phaseo](https://github.com/phaseoteam/Phaseo/tree/main/.agents/skills/openrouter-to-phaseo-migration)، التي تجمع خطوات الجرد والمطابقة والتحقق والتراجع نفسها:

1. ابحث في شيفرة التشغيل وإعدادات النشر عن `openrouter.ai` و`OPENROUTER_API_KEY` و`sk-or-v1` و`HTTP-Referer` و`X-Title`.
2. غيّر حدود العميل إلى `https://api.phaseo.app/v1` و`PHASEO_API_KEY` دون إضافة أي قيمة سرية إلى نظام التحكم في الإصدارات.
3. استعلم عن `GET /v1/models?format=openai` وسجّل كل مطابقة من نموذج قديم إلى نموذج جديد.
4. كيّف خيارات التوجيه أو حقول الاستجابة الخاصة بـ OpenRouter في وحدة توافق واحدة.
5. شغّل فحوصات الصحة والطلبات غير المتدفقة والمتدفقة ومسارات الفشل أعلاه.
6. أبلغ عن الملفات المتغيرة وتغييرات أسماء الأسرار ومطابقات النماذج وأدلة الاختبار وفجوات التكافؤ ومفتاح التراجع.

للحصول على نسخة موجّهة، افتح [دليل الترحيل التفاعلي من OpenRouter](https://phaseo.app/migrate/openrouter)، أو اطّلع على [المقارنة](https://phaseo.app/compare/openrouter) بين المنصتين، أو [احصل على مساعدة مجانية في الترحيل](https://phaseo.app/contact).
