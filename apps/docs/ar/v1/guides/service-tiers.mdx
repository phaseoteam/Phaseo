اضبط `service_tier` في طلب نصي لتدفع مقابل تسليم أسرع (`fast`، `ultrafast`) أو لتقبل وضعًا أرخص وأقل أولوية (`flex`). عندئذٍ لا يوجّه Phaseo إلا إلى المزوّدين الذين يقدّمون تلك الفئة للنموذج. يعمل الحقل بالطريقة نفسها على `/v1/chat/completions` و`/v1/responses` و`/v1/messages`.

```json
{
  "model": "openai/gpt-5.5",
  "input": "Summarise this incident report.",
  "service_tier": "fast"
}
```

| الفئة | اطلبها بـ | استخدمها لـ |
| --- | --- | --- |
| Standard | لا شيء، أو `"standard"` / `"default"` | حركة الإنتاج العامة |
| Fast | `"fast"`، أو اسمها البديل `"priority"` | العرض المميز أو الأعلى أولوية لدى المزوّد |
| Ultrafast | `"ultrafast"` | العرض الأعلى سرعة |
| Flex | `"flex"` | عرض أقل تكلفة، حيث يتوفر لدى المزوّد |
| Batch | [Batch API](../api-reference/endpoint/batches-create.mdx)، لا `service_tier` | أحمال العمل الكبيرة المؤجلة |

لا تتوفر الفئات إلا لنماذج النص، وفقط حيث يدعمها النموذج والمزوّد. تعرض صفحات النماذج الأسعار الخاصة بكل فئة حيث تتوفر لدى Phaseo.

## ما الذي يحدث عندما لا تُعرض فئة

لا يحتفظ Phaseo إلا بمسارات المزوّدين التي تقدّم الفئة المطلوبة؛ ولا يرجع أبدًا إلى فئة أخرى. إذا لم يقدّمها أي مسار، يفشل الطلب بالخطأ `400 unsupported_model_or_endpoint` والسبب `service_tier_not_supported`.

تفشل القيم الأخرى بالخطأ `400 validation_error`:

- `service_tier: "batch"` في طلب متزامن (الكلمة المفتاحية `batch_service_tier_not_supported`). استخدم Batch API بدلًا من ذلك.
- أي قيمة غير `standard` أو `default` أو `fast` أو `ultrafast` أو `priority` أو `flex` أو `batch` (الكلمة المفتاحية `unsupported_service_tier`).

ترسل دائمًا قيم الـ Gateway هذه. يترجمها Phaseo إلى عناصر التحكم الخاصة بكل مزوّد، فيتلقى مسار Anthropic، على سبيل المثال، حقول الفئات الخاصة بـ Anthropic.

## اطلب فئة على كل نقطة نهاية

<CodeGroup>
```json Responses
{
  "model": "openai/gpt-5.5",
  "input": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "flex"
}
```

```json Chat Completions
{
  "model": "openai/gpt-5.5",
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "flex"
}
```

```json Messages
{
  "model": "anthropic/claude-opus-5.5",
  "max_tokens": 512,
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "fast"
}
```
</CodeGroup>

لـ `ultrafast`، استخدم نموذجًا تسرد صفحته أسعار Ultrafast.

## Mistral Priority والتوجيه في الاتحاد الأوروبي

تتطلب فئة Mistral Priority حساب مؤسسة مؤهلًا لدى Mistral. يربط Phaseo `priority` بوضع الأولوية التلقائي لدى Mistral ويحتسب الفئة التي تبلغ عنها Mistral: إذا رجعت Mistral إلى Standard، تدفع أسعار Standard.

وجود سعر في الكتالوج لا يجعل الفئة قابلة للتوجيه. تبقى Priority معطّلة ما لم يعلن مسار Mistral المحدد عن دعم Priority، ويظل التأهل معتمدًا على حساب Mistral والنموذج.

يمكن تثبيت GLM 5.2 على نقطة النهاية الإقليمية الأوروبية لدى Mistral باستخدام عرض المزوّد `mistral-eu`:

```json
{
  "model": "z-ai/glm-5.2",
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "priority",
  "provider": {
    "only": ["mistral-eu"],
    "required_execution_region": "eu"
  }
}
```

يكلّف الاستدلال الإقليمي لدى Mistral أكثر بنسبة 10%. لا يتوفر تسعير Batch إلا على عرض Mistral العالمي عبر Batch API؛ إذ لا تدعم Mistral الدفعات على نقاط النهاية الإقليمية.

المرجع الكامل للحقول موجود في [المعاملات](../api-reference/parameters.mdx)؛ ولمعرفة كيف تتلاءم الفئات مع ترتيب المزوّدين والبدائل، راجع [التوجيه والبدائل](./routing-and-fallbacks.mdx).
