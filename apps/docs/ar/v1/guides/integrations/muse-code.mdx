شغّل `phaseo muse` لبدء جلسة Muse Code عبر Phaseo. هذا المشغّل هو الطريقة الوحيدة المدعومة لاستخدام Phaseo مع Muse Code.

## تشغيل Muse Code عبر Phaseo CLI

```bash
phaseo login
phaseo muse --model meta/muse-spark-1.3
```

ينشئ المشغّل مفتاحًا مخصصًا، ويكتب إعدادات Muse داخل `XDG_CONFIG_HOME` مؤقت، ويشغّل `muse`، ثم يحذف الإعدادات عند خروج Muse Code. ضع خيارات Muse Code الخاصة بعد `--`.

| الخيار | الأثر |
| --- | --- |
| `--model <id>` | النموذج المستخدم. القيمة الافتراضية `openai/gpt-5.6-terra`. |
| `--catalog all` | يعرض كل نماذج النص النشطة في Phaseo، لا النموذج المحدد فقط. |
| `--dry-run --json` | يعرض خطة التشغيل دون إنشاء مفتاح أو بدء Muse Code. |
| `--skip-install` | يتخطى فحص التثبيت. |

`phaseo run muse ...` هو الصيغة الطويلة للأمر نفسه.

على macOS وLinux، يعرض أول تشغيل تفاعلي تثبيت Muse Code بمثبّت Meta. على Windows، ثبّت Muse Code بنفسك، وتحقق من `muse --version`، واستخدم `--skip-install`.

## لماذا لا يوجد إعداد يدوي

بُني Muse Code حول [Model API](https://ai.meta.com/llama) الخاصة بـ Meta وتسجيل الدخول لديها. لا توثّق Meta إعدادًا ثابتًا لتوجيهه إلى نقطة نهاية أخرى متوافقة مع OpenAI، لذا استخدم المشغّل. لا تنسخ الإعدادات المؤقتة للمشغّل إلى ملف تعريف Muse المعتاد؛ فهي تفصيل داخلي وتُحذف عند خروج المشغّل.

لاستدعاء نموذج Phaseo من كودك الخاص بدلًا من ذلك، استخدم [OpenAI SDK](./openai-sdk.mdx) مع `https://api.phaseo.app/v1` ومفتاح API من Phaseo.

## التحقق من أنه يعمل

أرسل موجّهًا قصيرًا وتأكد من ظهور الطلب في **الإعدادات → الاستخدام → السجلات**.

## إصلاح المشكلات الشائعة

### Muse Code غير مثبت

ثبّت Muse Code بنفسك، وتحقق من `muse --version`، وأعد التشغيل باستخدام `--skip-install`.

### النموذج غير مدرج

استخدم `--catalog all`، أو مرّر معرّف النموذج باستخدام `--model`. لا يحتاج Phaseo إلى اكتشاف النماذج.
