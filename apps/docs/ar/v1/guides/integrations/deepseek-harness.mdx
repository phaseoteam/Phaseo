شغّل `phaseo deepseek-harness` لإضافة Phaseo إلى منتقي النماذج في DeepSeek Harness، أو أضف مزوّدًا مخصّصًا من واجهة Harness أو من `settings.yaml`. يرسل Harness طلبات Chat Completions متوافقة مع OpenAI مباشرةً إلى Phaseo، لذا لا حاجة إلى محوّل.

## الإعداد باستخدام Phaseo CLI

```bash
phaseo login
phaseo deepseek-harness
```

إذا لم يكن Harness مثبتًا، تعرض CLI أمر التثبيت الرسمي وتطلب موافقتك قبل تشغيله. ثم يقوم الإعداد بما يلي:

- يكتب المزوّد وBase URL والبروتوكول وكتالوج النماذج والنموذج الافتراضي في `$DSH_HOME/cordis.patch.yml` (القيمة الافتراضية لـ `DSH_HOME` هي `~/.dsh`)، داخل كتلة معلَّمة حتى يتمكن لاحقًا من تحديث إعداداته فقط أو إزالتها؛
- يضيف كل نماذج النص النشطة في Phaseo التي تعمل مع Chat Completions. استخدم `--catalog default` لإضافة النموذج الافتراضي فقط؛
- ينشئ مفتاحًا باسم `Phaseo CLI: DeepSeek Harness API Key` تنتهي صلاحيته بعد 90 يومًا وله حد إنفاق شهري قدره $100، ويكتبه في الملف المحمي `$DSH_HOME/.credentials.yaml` الخاص بـ Harness. شغّل `phaseo deepseek-harness` مرة أخرى لاستبدال مفتاح منتهي الصلاحية.

النموذج الافتراضي هو `anthropic/claude-sonnet-4.6`. لاختيار نموذج آخر:

```bash
phaseo deepseek-harness --model YOUR_PHASEO_MODEL_ID
```

## إضافة Phaseo من واجهة Harness

1. افتح **Settings > Models** واختر **Add a custom provider**.
2. أدخل:

| الحقل | القيمة |
| --- | --- |
| Provider ID | `phaseo` |
| Display name | `Phaseo` |
| Base URL | `https://api.phaseo.app/v1` |
| API protocol | `OpenAI Completions` |
| API key | مفتاح API من Phaseo |

3. تحت **Model catalog**، اختر **Fetch available models**.
4. اختر نموذج Chat Completions يدعم الأدوات، مثل `anthropic/claude-sonnet-5.5`، واحفظ المزوّد.
5. في محرر الرسائل، اختر نموذج Phaseo وابدأ جلسة جديدة.

تحتفظ الجلسات المحفوظة ومراجع بيانات الاعتماد بمعرّف المزوّد، لذا اعتبر `phaseo` معرّفًا دائمًا. يمكنك تعديل اسم العرض وURL والمفتاح وقائمة النماذج لاحقًا.

## إعداد Phaseo في settings.yaml

يمكنك إعداد المزوّد نفسه في `$DSH_HOME/settings.yaml`. لا تضع المفتاح في هذا الملف: يحدد `apiKeyEnv` اسم المتغير الذي يقرأ منه Harness المفتاح.

```yaml $DSH_HOME/settings.yaml
llm-pi-ai:
  providers:
    phaseo:
      displayName: Phaseo
      apiKeyEnv: PHASEO_API_KEY
      api: openai-completions
      baseURL: https://api.phaseo.app/v1
      models:
        - id: YOUR_PHASEO_MODEL_ID
```

اضبط `PHASEO_API_KEY` في البيئة التي تشغّل Harness، أو احفظ المفتاح في صفحة Models. استبدل `YOUR_PHASEO_MODEL_ID` بمعرّف دقيق من Phaseo؛ ولوكلاء البرمجة، ابدأ بـ `anthropic/claude-sonnet-5.5`. قائمة `models` كتالوج محفوظ وليست استعلامًا مباشرًا، لذا حدّثها عندما تريد المزيد من نماذج Phaseo في Harness.

## التحقق من أنه يعمل

تحقق أولًا من المفتاح واكتشاف النماذج:

```bash
curl https://api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

ثم اختر نموذج Phaseo في جلسة Harness جديدة وأرسل `Reply with exactly: Phaseo is connected.`. يؤكد الرد المسار كاملًا من Harness عبر Phaseo إلى مزوّد النموذج. يظهر الطلب أيضًا في **الإعدادات → الاستخدام → السجلات**. تُحتسب الطلبات الحية كاستخدام عادي.

## إزالة Phaseo

```bash
phaseo integrations remove deepseek-harness
```

يزيل هذا الأمر الإعداد الذي يملكه Phaseo فقط ويلغي المفتاح.

## إصلاح المشكلات الشائعة

| المشكلة | الحل |
| --- | --- |
| جلب النماذج يعيد `401` | تأكد من أن المفتاح ساري وأن Base URL يتضمن `/v1`. |
| النموذج غير موجود في المنتقي | اجلب الكتالوج مرة أخرى، أو أضف معرّف النموذج الدقيق تحت `models` في `settings.yaml`. |
| يبلّغ Harness عن `MISSING_CREDENTIAL` | احفظ المفتاح في صفحة Models، أو اجعل `PHASEO_API_KEY` متاحًا لعملية Harness. |
| تذهب الطلبات إلى نقطة نهاية خاطئة | اختر `OpenAI Completions` (`openai-completions`). يستخدم هذا المزوّد `/v1/chat/completions` في Phaseo. |
| يرفض نموذج أدوات الدوال عند تفعيل الاستدلال | اختر نموذجًا يدعم الأدوات على Chat Completions. النماذج التي تحتاج إلى Responses API للاستدلال مع الأدوات لا تعمل مع هذا البروتوكول. |
| تحتفظ الجلسة بنموذجها القديم | ابدأ جلسة جديدة. يحفظ Harness المزوّد والنموذج في الجلسات التي أرسلت طلبًا. |
