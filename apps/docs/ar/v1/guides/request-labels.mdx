أرسل الترويسة `X-Phaseo-Metadata` لوسم طلب بتسميات مفتاح/قيمة مثل `team=support`، ثم صفِّ الإنفاق والسجلات حسب تلك التسميات. استخدم التسميات عندما تحتاج إلى بُعد تكلفة أدق من مفتاح API أو التطبيق. لا تغيّر طلب النموذج ولا تُمرَّر إلى المزوّدين.

```bash
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -H 'X-Phaseo-Metadata: {"labels":[{"key":"team","value":"support"},{"key":"environment","value":"production"}]}' \
  -d '{
    "model": "openai/gpt-6-astra",
    "input": "Summarize this ticket."
  }'
```

تقبل حزمتا SDK لـ TypeScript وPython ترويسات مخصصة، لذا يمكنك ضبط الترويسة نفسها مرة واحدة على العميل.

لوسم الطلبات تلقائيًا بناءً على محتواها، استخدم [مصنِّفات الطلبات](/ar/v1/guides/request-classifiers). تُخزَّن إجاباتها كتسميات طلبات وتُصفّى بالطريقة نفسها.

## قواعد التسميات

| القاعدة | الحد |
| --- | --- |
| التسميات لكل طلب | حتى 32، لكل منها مفتاح فريد |
| المفتاح | من 1 إلى 64 حرفًا: أحرف وأرقام و`_` و`.` و`:` و`-` |
| القيمة | سلسلة نصية، من 1 إلى 256 حرفًا، دون أحرف تحكم |
| حجم الترويسة | حتى 8 KiB |
| مفتاح محجوز | لا يضبط `phaseo.classifier` إلا استدعاءات المصنِّف في Phaseo |

تُزال المسافات من أطراف المفاتيح والقيم. تؤدي الترويسة المشوّهة، أو المفتاح المكرر، أو التسمية التي تخالف هذه القواعد إلى فشل الطلب بالخطأ `400 validation_error` والسبب `invalid_request_metadata`، قبل استدعاء أي نموذج.

لا تضع الموجّهات أو الأسرار أو عناوين البريد الإلكتروني أو أي بيانات شخصية أخرى في التسميات.

## صفِّ الإنفاق حسب التسمية

مرّر كلًا من `label_key` و`label_value` إلى نقطة نهاية التحليلات:

```text
GET /v1/analytics?label_key=team&label_value=support
```

للاستجابة صيغة الإنفاق المجمّع نفسها في التحليلات غير المصفّاة، لكنها لا تحتسب إلا الطلبات التي تحمل زوج التسمية ذاك تمامًا. يعيد إرسال أحد المعاملين فقط `400 invalid_request`.
