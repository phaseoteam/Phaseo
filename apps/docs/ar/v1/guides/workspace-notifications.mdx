أضف وجهة في **الإعدادات ← الإشعارات** لإرسال تنبيهات مساحة عملك إلى البريد الإلكتروني أو Slack أو Discord أو Microsoft Teams أو webhook خاص بك عبر HTTPS. تنتمي الوجهات إلى مساحة العمل، ويمكنك إرسال اختبار قبل الاعتماد على أي منها.

| الوجهة | ما تقدّمه | الإشارات |
| --- | --- | --- |
| البريد الإلكتروني | عناوين أو قوائم توزيع | لا شيء |
| Slack | عنوان URL لـ webhook وارد | معرّفات المستخدمين ومعرّفات مجموعات المستخدمين |
| Discord | قناة ورمز bot، أو عنوان URL لـ webhook | معرّفات المستخدمين ومعرّفات الأدوار |
| Microsoft Teams | عنوان URL لسير عمل | عناوين بريد Microsoft 365 أو معرّفات كائنات Entra |
| webhook مخصص | عنوان URL عبر HTTPS | لا شيء؛ عمليات التسليم [موقّعة](#verify-webhook-signatures) |

تُشفَّر بيانات الاعتماد وعناوين webhook قبل تخزينها. اجعل بيانات اعتماد القنوات مقصورة على إرسال الإشعارات، وبدّلها إذا انكشفت.

## إضافة وجهة

<Steps>
<Step title="أنشئها">
افتح **الإعدادات ← الإشعارات**، واختر **إضافة وجهة**، وأدخل اسمًا، واختر قناة واحدة أو أكثر. أضف تفاصيل الوجهة وأي إشارات.
</Step>
<Step title="اختبر كل قناة">
اختر **إرسال اختبار** لكل قناة، ثم أنشئ الوجهات بعد نجاح كل الاختبارات.
</Step>
<Step title="احفظ سر التوقيع">
يحصل الـ webhook المخصص على سر توقيع عند إنشائه. انسخه من مربع الحوار الذي يُفتح؛ فهو يُعرض مرة واحدة فقط.
</Step>
</Steps>

للأتمتة، أنشئ الوجهة باستخدام `POST /v1/notifications/destinations`، واختبرها باستخدام `POST /v1/notifications/destinations/{id}/test`، ثم اختر التنبيهات التي تتلقاها باستخدام `PUT /v1/notifications/routes/{eventKind}`، مع مفتاح إدارة.

استخدم الإشارات باعتدال: أرسل التنبيهات الكثيرة إلى قناة مراقَبة بدلًا من استدعاء مجموعة واسعة.

<span id="enable-product-alerts"></span>
## تفعيل تنبيهات المنتج

تسرد صفحة الإشعارات أنواع التنبيهات المتاحة لمساحة عملك. تتلقى الوجهات التنبيه إضافةً إلى أي مستلمين مدمجين يظهرون في لوحة التحكم.

تُرسل **تنبيهات إيقاف النماذج** إشعارًا قبل إيقاف نموذج تستخدمه مساحة العمل.

تُرسل **إشعارات النموذج البديل** عندما يكون [توجيه النماذج المتوقفة](./model-retirement.mdx#route-requests-to-a-replacement-automatically) مفعّلًا ويجيب نموذج بديل عن طلبات مساحة العمل لنموذج لم يعد أي مزوّد يقدّمه. يُرسل إشعار واحد لكل نموذج وبديله، في المرة الأولى التي يجيب فيها بديل بنجاح. يتلقى مالك مساحة العمل رسالة بريد إلكتروني دائمًا؛ اختر وجهات لإرسال الإشعار إلى فريقك أيضًا.

<span id="spend-reports"></span>
## تقارير الإنفاق

يتلقى مالكو مساحة العمل كل يوم اثنين الساعة 09:00، وفق المنطقة الزمنية للفوترة في مساحة العمل، بريدًا إلكترونيًا بتقرير الإنفاق يغطي الأسبوع السابق من الاثنين إلى الأحد. غيّر ذلك من **تنبيهات الإنفاق ← إعدادات إنفاق مساحة العمل** في صفحة الإشعارات: يومي (الساعة 09:00، عن اليوم السابق)، أو أسبوعي، أو شهري (في اليوم الأول، عن الشهر السابق)، أو إيقاف، وما إذا كان المسؤولون يتلقونه أيضًا. تُتخطّى الفترات التي لا إنفاق فيها.

يعرض كل تقرير الإنفاق والتغيّر مقارنةً بالفترة السابقة، وأعلى المفاتيح والنماذج والأعضاء والأقسام، وتوقّع هذا الشهر، والمدة المتبقية للرصيد، وتنبيهات الإنفاق وحالات الحظر خلال الفترة. يمكن لكل من يتلقاه إلغاء الاشتراك من الرابط الموجود في البريد؛ وهذا يوقف نسخته فقط من تقرير مساحة العمل تلك. تتلقى الوجهات الموجّهة إلى **تقارير الإنفاق** ملخصًا واحدًا لكل تقرير.

الإعدادات نفسها هي `spend.report_cadence` و`spend.report_include_admins` في [API إعدادات الإشعارات](../api-reference/endpoint/notifications-settings-update.mdx).

للحصول على تنبيهات بشأن الإنفاق والميزانيات والتوقعات والارتفاعات المفاجئة وانخفاض الرصيد، ولحظر الطلبات بعد تجاوز الإنفاق حدًا معيّنًا، راجع [تنبيهات الإنفاق](./spend-alerts.mdx).

<Note>يجري طرح رسائل تقارير الإنفاق تدريجيًا. وإلى أن تُفعَّل، يُحفظ اختيارك لكن لا يُرسَل أي تقرير.</Note>

## إبقاء الوجهات تعمل

استخدم **إرسال اختبار** بجانب وجهة موجودة بعد تدوير بيانات الاعتماد أو تغيير قناتها. أزِل الوجهات التي لا يراقبها أحد، حتى لا تبدو التنبيهات مُسلَّمة وهي تصل إلى قناة مهجورة.

يجب على مستقبِل الـ webhook المخصص التحقق من كل طلب قبل معالجته، وإرجاع استجابة نجاح بسرعة، ونقل العمل الأبطأ إلى مهمة في الخلفية.

## التحقق من توقيعات webhook

يوقّع Phaseo كل عملية تسليم لـ webhook مخصص، بما فيها الاختبارات المرسلة من وجهة محفوظة، بالمخطط نفسه المستخدم في [webhooks الفيديو والدفعات](./async-video-and-batch.mdx#receive-updates). يحمل كل طلب هذه الترويسات:

```http
POST /your/endpoint HTTP/1.1
content-type: application/json
user-agent: Phaseo-Notifications/1.0
x-phaseo-event-id: 6f1c0f5e-3f0b-4a39-9a51-2f4f2c1d9e10
x-phaseo-event-type: rate_limit_throttled
x-phaseo-timestamp: 1792569600
x-phaseo-signature: 5d2a…e41f
```

`x-phaseo-signature` هو HMAC-SHA256 بالصيغة الست عشرية لقيمة `x-phaseo-timestamp`، ثم نقطة حرفية (`.`)، ثم **نص الطلب دون تعديل**، باستخدام سر توقيع الوجهة (`whsec_…`) مفتاحًا. و`x-phaseo-timestamp` بثواني Unix.

للتحقق من عملية تسليم:

1. اقرأ نص الطلب الخام قبل تحليله بصفته JSON.
2. أعد حساب التوقيع وقارنه في زمن ثابت.
3. ارفض الطوابع الزمنية التي تبعد أكثر من خمس دقائق عن ساعتك.
4. أزل التكرار بناءً على `x-phaseo-event-id`. تُعاد محاولة عمليات التسليم الفاشلة، وتُوقَّع كل محاولة مجددًا بطابع زمني جديد.

<CodeGroup>
```js Node.js
import crypto from "node:crypto";

// rawBody هو نص الطلب كما استُلم تمامًا، في صورة سلسلة نصية.
export function verifyPhaseoSignature(rawBody, headers, secret, toleranceSeconds = 300) {
  const timestamp = headers["x-phaseo-timestamp"];
  const signature = headers["x-phaseo-signature"];
  if (!timestamp || !signature) return false;
  if (Math.abs(Date.now() / 1000 - Number(timestamp)) > toleranceSeconds) return false;
  const expected = crypto
    .createHmac("sha256", secret)
    .update(`${timestamp}.${rawBody}`)
    .digest("hex");
  const a = Buffer.from(expected, "hex");
  const b = Buffer.from(signature, "hex");
  return a.length === b.length && crypto.timingSafeEqual(a, b);
}
```

```python Python
import hashlib
import hmac
import time

# raw_body هو نص الطلب كما استُلم تمامًا، في صورة بايتات.
def verify_phaseo_signature(raw_body: bytes, headers, secret: str, tolerance_seconds: int = 300) -> bool:
    timestamp = headers.get("x-phaseo-timestamp", "")
    signature = headers.get("x-phaseo-signature", "")
    if not timestamp.isdigit() or not signature:
        return False
    if abs(time.time() - int(timestamp)) > tolerance_seconds:
        return False
    expected = hmac.new(secret.encode(), timestamp.encode() + b"." + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)
```
</CodeGroup>

### إنشاء سر أو تدويره

يُعرض السر مرة واحدة، عند إنشاء الوجهة. لاستبداله، اختر **تدوير السر** بجانب الوجهة في **الإعدادات ← الإشعارات**، أو استدعِ [`POST /v1/notifications/destinations/{id}/rotate-secret`](/ar/v1/api-reference/endpoint/notifications-destination-rotate-secret). تُوقَّع عملية التسليم التالية بالسر الجديد ويتوقف السر القديم عن العمل، لذا حدّث المستقبِل فورًا.

الـ webhooks المخصصة التي أُنشئت قبل توفر التوقيع ليس لها سر وما زالت تُسلَّم دون توقيع. تظهر في الإعدادات بعلامة **غير موقّع**. اختر **إنشاء سر**، وأضف السر إلى المستقبِل، ثم أرسل اختبارًا للتحقق من التحقق. الاختبارات المرسلة من لوحة **إضافة وجهة**، قبل حفظ الوجهة، غير موقّعة لأنه لا يوجد سر بعد.

لا تُوقَّع وجهات البريد الإلكتروني وSlack وDiscord وMicrosoft Teams: فهذه الخدمات تصادق على عنوان webhook أو رمز bot بنفسها.
