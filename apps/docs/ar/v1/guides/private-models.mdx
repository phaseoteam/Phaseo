تتيح النماذج الخاصة لفريقك استدعاء نشر مخصص أو مستضاف ذاتيًا عبر واجهة Phaseo API المعتادة. يظهر النموذج فقط للأعضاء المصادق عليهم في مساحة العمل، ويمكن استخدامه حيث تستخدم معرّف نموذج عام.

تشمل المصادر المعتادة عمليات النشر المخصصة على Baseten أو Modal أو RunPod أو Fireworks أو Together، إضافةً إلى خدمات تشغّل vLLM أو خادمًا آخر متوافقًا مع OpenAI.

## قبل البدء

يجب أن يوفر النشر:

- عنوان URL أساسي عام عبر HTTPS؛
- نقطة نهاية `/chat/completions` متوافقة مع OpenAI؛
- مصادقة برمز Bearer؛ و
- معرّف نموذج أو نشر لدى المزود تقبله تلك النقطة.

دعم `/responses` اختياري. أبقه معطّلًا ما لم ينفّذ النشر هذه النقطة صراحةً.

<Warning>
لا تكيّف النماذج الخاصة بروتوكولات المزود الأصلية فقط أو أنظمة المصادقة المخصصة. ضع طبقة متوافقة مع OpenAI أمام تلك العمليات أو استخدم تكامل مزود يدعمه Phaseo.
</Warning>

## ربط عملية نشر

<Steps>
<Step title="فتح النماذج الخاصة">

افتح **لوحة التحكم ← الإعدادات ← مساحة العمل ← النماذج الخاصة**، ثم اختر **إضافة نموذج**. يجب أن تكون مالك مساحة العمل أو مسؤولًا فيها.

</Step>

<Step title="تسمية النموذج">

اختر نموذجًا موجودًا في الكتالوج لإضافة هذا النشر إلى قائمة مزوديه، أو أدخل اسمًا مختصرًا مثل `legal-assistant`. إذا لم يوجد نموذج بهذا الاسم الفريد في الكتالوج، يجمعه Phaseo مع نطاق الأسماء الموثوق لمساحة العمل:

```text
acme/legal-assistant
```

لا يمكنك اختيار نطاق أسماء مساحة العمل أو استبداله. ترتبط معرّفات الكتالوج الدقيقة بذلك النموذج دون تغيير هويته العامة.

</Step>

<Step title="تهيئة نقطة النهاية">

أدخل عنوان URL الأساسي دون مسار الاستدلال. مثلًا:

```text
https://model.example.com/v1
```

لا تضمّن `/chat/completions` أو `/responses`. أدخل معرّف النموذج أو النشر الدقيق لدى المزود بشكل منفصل؛ ويستبدله Phaseo عند تمرير الطلبات.

</Step>

<Step title="حفظ بيانات الاعتماد">

أدخل مفتاح API الخاص بالنشر. يشفّر Phaseo بيانات الاعتماد ولا يعرضها مجددًا بعد الحفظ. يمكنك استبدالها لاحقًا من صفحة إعدادات النموذج.

</Step>

<Step title="استدعاء النموذج">

استخدم معرّف النموذج الذي تم إنشاؤه مع نقطة نهاية Chat Completions المعتادة:

```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "acme/legal-assistant",
    "messages": [{"role": "user", "content": "Summarize this contract."}]
  }'
```

يجب أن ينتمي مفتاح API المستخدم للاستدعاء إلى مساحة العمل نفسها التي ينتمي إليها النموذج الخاص.

</Step>
</Steps>

## كيفية عمل التوجيه

تستخدم النماذج الخاصة واجهة طلبات Phaseo نفسها التي تستخدمها نماذج الكتالوج. يُوجّه النموذج المستقل لمساحة العمل إلى نقطة نهايته المهيأة فقط. تنضم النقطة المرتبطة بنموذج كتالوج إلى قائمة مزوديه وفق سياسة **مفضّل** أو **المجموعة العادية** أو **احتياطي فقط**. يرسل Phaseo بيانات الاعتماد المحفوظة كرمز Bearer ويستبدل معرّف النموذج المهيأ لدى المزود.

لا يصبح النموذج الخاص مسار مزود عامًا ولا يظهر لمساحات العمل الأخرى. تُدرج النماذج الخاصة المفعّلة في كتالوج النماذج المصادق عليه وتظهر تحت مرشح **خاص**.

<Note>
بعد إضافة نشر خاص أو تفعيله على نموذج كتالوج موجود، انتظر 5–10 ثوانٍ لانتشار التغيير عبر طبقة API قبل اختبار التوجيه. خلال هذه الفترة قد تستمر الطلبات باستخدام المزودين العامين الحاليين للنموذج. لا تُعاد توجيه الطلبات الجارية بالفعل.
</Note>

## أمثلة المزودين

| النشر | ما يجب إدخاله |
| --- | --- |
| نقطة نهاية مخصصة على Baseten | عنوان URL الأساسي المتوافق مع OpenAI ومعرّف نموذج النشر ومفتاح API |
| نقطة نهاية ويب على Modal | نقطة نهاية HTTPS عامة تنفّذ عقد OpenAI Chat Completions |
| نقطة نهاية بلا خادم على RunPod | عنوان URL لوكيل متوافق مع OpenAI وبيانات اعتماد Bearer |
| نشر مخصص على Fireworks أو Together | عنوان URL مخصص متوافق مع OpenAI ومعرّف نموذج المزود |
| vLLM | عنوان URL العام المنتهي بـ `/v1` واسم النموذج الذي يقدّمه vLLM |

قد تتغير منتجات المزودين وصيغ عناوين URL. تحقّق من عنوان URL الأساسي ومعرّف النموذج وطريقة المصادقة والنقاط المدعومة في وثائق النشر الحالية لدى المزود.

## إدارة النماذج الخاصة عبر API

يمكن للإدارة من جهة الخادم استخدام [واجهة النماذج الخاصة](../api-reference/endpoint/private-models-list) بمفتاح إدارة يحمل `private_models:read` أو `private_models:write` أو `private_models:delete` حسب الحاجة.

تقبل طلبات الإنشاء والتحديث `model_reference` كمعرّف نموذج كتالوج دقيق أو اسم مختصر. يستنتج Phaseo قيمة `model_id` ولا يمكن للعملاء إرسالها مباشرةً. استخدم `host_provider_id` لمزود موجود في Phaseo، أو `custom_provider_name` و`custom_provider_url` الاختياري لمشغّل آخر.

## استكشاف الأخطاء وإصلاحها

- **خطأ 404 من المزود:** تأكد من أن عنوان URL الأساسي ينتهي قبل مسار الاستدلال.
- **نموذج غير معروف:** انسخ معرّف نشر المزود إلى **معرّف النموذج لدى المزود**. لا تستخدم معرّف نموذج مساحة عمل Phaseo هناك.
- **طلب غير مصرح به لدى المزود:** استبدل بيانات الاعتماد المحفوظة وتأكد من قبول المزود لمصادقة Bearer.
- **Chat يعمل لكن Responses يفشل:** عطّل **Responses API** ما لم ينفّذ المزود `/responses` بشكل أصلي.
- **النموذج غير ظاهر في الكتالوج:** تأكد من تفعيل النموذج ومصادقة المستدعي في مساحة العمل نفسها.
