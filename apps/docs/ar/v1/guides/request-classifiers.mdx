<Note>
مصنِّفات الطلبات في مرحلة تجريبية. يديرها المالكون والمسؤولون من **الإعدادات → المصنِّفات** أو عبر واجهة الإدارة `/v1/classifiers` باستخدام [مفتاح إدارة](../developers/management-api-keys.mdx) يملك النطاقات `classifiers:*`.
</Note>

يصف المصنِّف تصنيفًا، مثل القسم أو الجمهور أو نوع المهمة، ويحدد النموذج الذي يطبقه. بعد انتهاء كل طلب مؤهل، يرسل Phaseo الطلب إلى هذا النموذج، فيختار قيمة لكل بُعد. تُضاف كل إجابة إلى الطلب بوصفها [تسمية طلب](./request-labels.mdx)، لذا يمكنك تصفية السجلات والاستخدام والتحليلات وتجميعها حسبها تمامًا مثل التسميات التي يرسلها الكود.

استخدم المصنِّفات عندما لا يعرف الكود الفئة: لمن كُتب الموجّه، أو نوع العمل الذي يؤديه الوكيل، أو ما إذا كان الطلب يتناول موضوعًا خاضعًا للتنظيم.

## كيف يُصنَّف الطلب

1. ينتهي الطلب وتُعاد استجابته إلى تطبيقك. لا يضيف التصنيف أي تأخير أبدًا.
2. ينشئ Phaseo نصًا للطلب يتضمن تعليمات النظام والرسائل وأسماء الأدوات (دون مخططاتها) ونتائج الأدوات. تُحدَّد كل جولة بـ 4,000 حرف، وتُخفى الأسرار مثل مفاتيح API. إذا كان المصنِّف يتضمن الاستجابة، فيُضاف الناتج المُنشأ أيضًا.
3. يختار نموذج المصنِّف من قيمك. تُستبعد أي إجابة خارجها (راجع «اختيار نموذج» أدناه).
4. تُحفظ الإجابات بوصفها تسميات على الطلب مع درجة الثقة لكل إجابة، قبل أن يظهر الطلب في سجلاتك.

تعمل المصنِّفات على الطلبات الناجحة إلى `chat/completions` و`responses` و`messages`. إذا فشل التصنيف أو انتهت مهلته، يُسجَّل الطلب مع ذلك، ولكن دون تلك التسميات.

## إنشاء مصنِّف

ابدأ من قالب جاهز في لوحة التحكم أو أرسل التصنيف بنفسك:

```bash
curl https://api.phaseo.app/v1/classifiers \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Department",
    "model": "google/gemini-2.5-flash-lite",
    "dimensions": [{
      "key": "department",
      "name": "Department",
      "allow_other": true,
      "values": [
        { "value": "engineering", "description": "Writing, reviewing, or debugging code" },
        { "value": "legal", "description": "Contracts, policies, and compliance" },
        { "value": "sales" },
        { "value": "support" }
      ]
    }],
    "sample_rate": 0.25,
    "monthly_budget_usd": 20
  }'
```

| الحقل | المعنى |
| --- | --- |
| `dimensions` | من 1 إلى 12 سؤالًا. يصبح كل `key` مفتاح التسمية، ويسرد كل بُعد من 2 إلى 50 قيمة (1 مع `allow_other`). |
| `multiple` | يسمح بأكثر من قيمة واحدة للبُعد. تصبح كل قيمة تسمية مستقلة بالمفتاح نفسه. |
| `allow_other` | يسمح للنموذج بالإجابة `other` عندما لا تناسب أي قيمة. |
| `instructions` | إرشادات إضافية تُضاف إلى موجّه التصنيف. |
| `sample_rate` | نسبة الطلبات المؤهلة التي تُصنَّف، من `0.0001` إلى `1`. |
| `sample_by` | يختار `request` كل طلب على حدة. ويُبقي `session` الجلسة كاملةً ضمن العينة أو خارجها ويعيد استخدام إجاباتها لمدة ساعة، فيُصنَّف تشغيل الوكيل الطويل مرة واحدة فقط. |
| `input_scope` | يصنِّف `prompt` الطلب. ويعرض `prompt_and_response` الاستجابة على النموذج أيضًا. |
| `scope` | يصنِّف فقط الطلبات الواردة من `key_ids` أو `app_ids` أو `models` هذه. |
| `monthly_budget_usd` | يوقف المصنِّف مؤقتًا لبقية الشهر وفق UTC بعد أن ينفق هذا المبلغ. |

يمكن أن تضم مساحة العمل خمسة مصنِّفات كحد أقصى. تصل التغييرات إلى البوابة خلال دقيقة تقريبًا.

## اختيار نموذج

يمكن لأي نموذج نصوص أو [نموذج قرارات](../api-reference/endpoint/decisions.mdx) أن يصنِّف. تحدد Phaseo طريقة سؤاله بناءً على ما يدعمه مزوّدو النموذج:

| النموذج | طريقة سؤاله |
| --- | --- |
| نموذج نصوص يدعم المخرجات المنظَّمة | طلب `responses` بمخطط JSON صارم، لذا تكون كل إجابة إحدى قيمك. |
| نموذج قرارات | طلب `decisions` فيه سؤال اختيار واحد لكل بُعد. البُعد الذي يحمل `multiple` يطرح سؤال نعم/لا لكل قيمة ويحتفظ بكل قيمة احتمالها 0.5 على الأقل (إذا احتاج المصنِّف إلى أكثر من 128 سؤالًا، يحصل هذا البُعد على أفضل قيمة واحدة فقط). الثقة هي احتمال النموذج نفسه. |
| نماذج النصوص الأخرى | طلب `responses` يطلب JSON نفسه في الموجّه. تُستبعد الإجابات الخارجة عن قيمك، لذا قد يبقى بُعدٌ بلا تسمية أكثر من غيره. وهي أيضًا الطريقة البديلة عندما يرفض مزوّدٌ المخطط. |

يكفي عادةً نموذج صغير وسريع. استخدم **جرِّبه على عيّنة** في محرر المصنِّف للتحقق من نموذج قبل الحفظ.

## التصفية والتجميع حسب النتائج

إجابات المصنِّفات تسميات طلبات عادية:

- في **السجلات** و**الاستخدام**، صفِّ حسب تسمية مثل `department` = `legal`.
- في الواجهة البرمجية، استخدم `label_key` و`label_value`:

```text
GET /v1/analytics?label_key=department&label_value=legal
```

- تتلقى وجهات [Broadcast](./integrations/observability.mdx) التسميات بوصفها سمات span باسم `phaseo.label.<key>`.

إذا كان الكود يرسل بالفعل تسمية بمفتاح أحد الأبعاد، يحتفظ Phaseo بقيمتك ويتخطى ذلك البُعد. وعندما يستخدم مصنِّفان المفتاح نفسه، يُعتمد المصنِّف الذي أُنشئ أولًا.

## التكلفة والخصوصية

- كل تصنيف طلب منفصل إلى نموذج المصنِّف، يُرسل باستخدام مفتاح API أو رمز OAuth نفسه الذي استخدمه الطلب الأصلي. تُحتسب تكلفته بالسعر العادي لذلك النموذج، ويتبع إعدادات المزوّدين والاحتفاظ بالبيانات وBYOK في مساحة عملك.
- تحمل طلبات المصنِّف التسمية `phaseo.classifier` بقيمة معرّف المصنِّف، لذا يمكنك رؤية إنفاقها في **الاستخدام**. ولا تُصنَّف هي نفسها ولا تُحتسب ضمن سياسات حدود المعدل لديك.
- حافظ على انخفاض التكلفة باستخدام نموذج صغير وسريع، أو نسبة عينة، أو أخذ العينات حسب الجلسة، أو نطاق، أو ميزانية شهرية.
- لا يُرسل النص إلا إلى نموذج المصنِّف. ويُسجَّل طلب المصنِّف مثل أي طلب آخر، لذا يتبع تخزين مدخلاته إعدادات التسجيل في مساحة عملك.
