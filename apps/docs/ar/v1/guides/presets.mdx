يخزّن الإعداد المسبق النموذج وموجّه النظام والمعاملات وقواعد المزوّدين لمهمة واحدة تحت اسم مثل `@support-triage`. يرسل المستدعون هذا الاسم في `model` مع المدخلات فقط، ويملأ الـ Gateway الباقي قبل أن يختار مزوّدًا.

بدّل حقول الطلب لترى أي قيمة تفوز:

<PresetMergeExplorer locale="ar" />

القواعد هي:

- **المعاملات تملأ الفراغات.** لا تنطبق المعاملات الافتراضية للإعداد المسبق إلا على الحقول التي يتركها الطلب. القيمة الموجودة في الطلب تفوز دائمًا.
- **موجّهات النظام تتراكم.** يأتي موجّه الإعداد المسبق أولًا. إذا كان للطلب موجّه نظام خاص به أو `instructions`، فإنه يليه بعد سطر فارغ.
- **إعدادات المزوّد في الطلب تفوز.** تستبدل حقول مثل `provider.order` أو `provider.max_price` في الطلب قيمة الإعداد المسبق لذلك الحقل.
- **قوائم السماح تضيّق ولا توسّع أبدًا.** تُطبَّق قوائم السماح والتجاهل للمزوّدين في الإعداد المسبق قبل اختيار المزوّد، لذا فهي تحدّ أيضًا من المزوّدين الذين يمكن أن يستخدمهم الاحتياط. يفشل النموذج الواقع خارج النماذج المسموح بها في الإعداد المسبق بخطأ `validation_error` كلمته المفتاحية في التفاصيل هي `preset_model_not_allowed`، ولا يُعاد توجيهه.

## أنشئ إعدادًا مسبقًا واستخدمه

<Steps>
<Step title="أنشئ الإعداد المسبق">

افتح **لوحة التحكم ← الإعدادات ← الإعدادات المسبقة** وأنشئ إعدادًا مسبقًا بمعرّف نصي (slug) مثل `support-triage`. أضف فقط القيم الافتراضية التي يجب أن يتشاركها كل المستدعين.

من CLI: `phaseo presets create --name @support-triage --model <model-id>`.

</Step>

<Step title="استدعِه بالاسم">

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "@support-triage",
    "input": "Customer says the invoice total is wrong."
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "@support-triage",
  input: "Customer says the invoice total is wrong.",
});
```

```python Python
from phaseo import Phaseo

client = Phaseo(api_key="YOUR_API_KEY")

response = client.generate_response({
    "model": "@support-triage",
    "input": "Customer says the invoice total is wrong.",
})
```
</CodeGroup>

</Step>

<Step title="تحقّق مما طُبِّق">

افتح الطلب في **Gateway ← الاستخدام** لترى أي قيم افتراضية من الإعداد المسبق طُبِّقت وأي مزوّد خدم الطلب.

</Step>
</Steps>

## ما الذي يمكن أن يحمله الإعداد المسبق

| الإعداد | الأثر |
| --- | --- |
| النموذج | يُستخدم عندما يُرسَل الطلب باسم الإعداد المسبق. |
| النماذج المسموح بها | معرّفات نماذج أو أنماط مثل `anthropic/*`. تُرفض النماذج الأخرى. |
| موجّه النظام | يُضاف في بداية كل طلب. |
| [قالب الموجّه](./prompt-templates) | رسائل تحتوي على `{{variables}}` يملؤها كل طلب. |
| المعاملات الافتراضية | `temperature` و`top_p` و`max_tokens` وإعدادات الاستدلال وما شابه. |
| قواعد المزوّدين | قوائم السماح والتجاهل، وترتيب المزوّدين، والمناطق، وسقوف الأسعار. |

أبقِ المنطق الخاص بكل مستدعٍ في تطبيقك، واستخدم إعدادات مسبقة منفصلة عندما تحتاج مسارات العمل إلى موجّهات أو توجيه أو تخزين مؤقت مختلف.

## سمِّ إعدادًا مسبقًا

أرسل الإعداد المسبق عبر الحقل `model`، أو عبر `prompt.id` عندما يحتوي على [قالب موجّه](./prompt-templates). لا يوجد حقل `preset` منفصل.

| الصيغة | يُحلّ في |
| --- | --- |
| `@support-triage` | مساحة عمل مفتاح API (الإعدادات المسبقة الخاصة وإعدادات مساحة العمل). |
| `@octavia/support-triage` | أي مساحة عمل (إعدادات مسبقة عامة نشرها المستخدم `octavia`). |
| `@support-triage@v3` | ذلك الإصدار المنشور. |
| `@support-triage@production` | الإصدار الذي تشير إليه التسمية `production` حاليًا. |

يتطلب نشر إعداد مسبق عام ملفًا شخصيًا عامًا مفعّلًا واسم مستخدم. أسماء المستخدمين فريدة على مستوى Phaseo، أما المعرّفات النصية فيكفي أن تكون فريدة لدى ناشر واحد. تُحوَّل المعرّفات النصية إلى أحرف صغيرة ويمكن أن تحتوي على أحرف وأرقام و`-` و`_` و`.` و`:`.

## أدِر الإصدارات وتراجع عنها

يحرّر الحفظ مسودة خاصة. يحوّل **نشر إصدار جديد** المسودة إلى إصدار مرقّم غير قابل للتغيير، ويحتفظ بكل الإصدارات السابقة.

اختر شكل تسميات الإصدارات:

| الصيغة | مثال |
| --- | --- |
| تسلسلي | `v1`، `v2`، `v3` |
| الإصدار الدلالي (Semantic Versioning) | `1.2.0`، `2.0.0-beta.1`، `1.4.2+build.7` |
| التاريخ | `2026.08.02`، ثم `2026.08.02.2` لإصدار ثانٍ في اليوم نفسه |

وجّه تسمية مسماة مثل `production` إلى إصدار، وأعِدها إلى إصدار سابق للتراجع. راجع [الإصدارات والتسميات](/ar/v1/guides/prompt-templates#versions-and-labels).

من CLI: `phaseo presets versions create` و`phaseo presets labels set`، أو عبر واجهة `/v1/presets`.

## انسخ إعدادًا مسبقًا من السوق

تبقى نسخة الإعداد المسبق المأخوذة من السوق مثبّتة على الإصدار الذي نسخته. عندما يطرح الناشر تحديثًا، تعرض نسختك إشعارًا. تطبيقه يغيّر مسودتك فقط، لذا لا يصل شيء إلى الإنتاج حتى تنشره بنفسك.

يسجّل Phaseo مصدر كل نسخة وسلسلة أصولها الكاملة، لذا يمكن لصفحة في السوق أن تعرض النسخ المباشرة بشكل منفصل عن جميع النسخ المتفرعة منها.

لجمع التقييمات على إجابات إعداد مسبق، راجع [جمع الملاحظات حول الإعدادات المسبقة](./preset-feedback).
