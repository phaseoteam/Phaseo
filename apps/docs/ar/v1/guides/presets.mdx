الإعدادات المسبقة هي تكوينات قابلة لإعادة الاستخدام تساعد الفِرق على توحيد المطالبات وتفضيلات النماذج وقيم التوجيه الافتراضية. تُدار من لوحة Phaseo ويمكن مشاركتها مع الفريق.

## البدء السريع

<Steps>
<Step title="إنشاء إعداد مسبق">

افتح **لوحة التحكم -> الإعدادات -> الإعدادات المسبقة** وأنشئ إعدادًا باسم واضح مثل `release-summary`. أضف القيم الافتراضية التي ينبغي مشاركتها بين الجهات المستدعية فقط.

</Step>

<Step title="الإشارة إلى الإعداد المسبق في طلب">

دع الجهة المستدعية تركز على إدخال المستخدم بينما يوفر الإعداد المسبق قيمًا ثابتة للمطالبة والمعلمات والتوجيه.

<CodeGroup>

```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
	  -d '{
	    "model": "@release-summary",
	    "input": "Generate a release summary for the last 24 hours."
	  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
	  model: "@release-summary",
	  input: "Generate a release summary for the last 24 hours.",
});
```

```python Python
from phaseo import Phaseo

client = Phaseo(api_key="YOUR_API_KEY")

response = client.generate_response({
	    "model": "@release-summary",
	    "input": "Generate a release summary for the last 24 hours.",
})
```

</CodeGroup>

</Step>

<Step title="التحقق من نتيجة التوجيه">

افتح الطلب في **Gateway -> الاستخدام** للتأكد من القيم الافتراضية التي طُبّقت والمزوّد الذي نفّذه.

</Step>
</Steps>

## ما الذي يمكن أن يتضمنه الإعداد المسبق

- مطالبة نظام تُضاف قبل كل طلب.
- نماذج أو عائلات نماذج مسموح بها.
- قوائم مزوّدين للسماح أو التجاهل ضمن تفضيلات التوجيه.
- معلمات افتراضية مثل temperature وtop_p وmax_tokens والإعدادات المشابهة.
- قيم استدلال افتراضية اختيارية للنماذج المدعومة.

تبدأ أسماء الإعدادات المسبقة بـ `@` لتسهيل تمييزها.

استدعِ الإعداد المسبق من خلال حقل `model` في الطلب فقط. لا توفر Phaseo حقل طلب منفصلًا باسم `preset`.

- تستخدم الإعدادات الخاصة وإعدادات مساحة العمل `@{slug}` وتُحل ضمن مساحة العمل الخاصة بمفتاح API.
- تستخدم الإعدادات العامة `@{username}/{slug}` ويمكن حلها من أي مساحة عمل. مثال: `@octavia/release-summary`.

يتطلب النشر العام ملفًا عامًا مفعّلًا واسم مستخدم. وتُحصر تعارضات الأسماء العامة ضمن الناشر الواحد؛ لذا يمكن لناشرين اثنين استخدام الاسم نفسه من دون التباس. أسماء المستخدمين فريدة على مستوى المنصة. وتُحوّل الأسماء إلى أحرف صغيرة وتدعم الأحرف والأرقام والواصلات والشرطات السفلية والنقاط والنقطتين.

## الإصدارات وتفرعات السوق

يؤدي حفظ التغييرات إلى تحديث مسودة خاصة. عند جاهزية التغييرات، استخدم **نشر إصدار جديد**؛ فتنشئ Phaseo إصدارًا مرقّمًا غير قابل للتغيير مع الاحتفاظ بالإصدارات السابقة للمراجعة.

يمكن لمالكي الإعدادات اختيار طريقة عرض تسميات الإصدارات:

- **تسلسلي:** `v1` و`v2` و`v3`.
- **الإصدار الدلالي:** تسميات SemVer صريحة مثل `1.2.0` أو `2.0.0-beta.1` أو `1.4.2+build.7`.
- **حسب التاريخ:** `YYYY.MM.DD` مع لاحقة رقمية عند نشر عدة إصدارات في اليوم نفسه، مثل `2026.08.02.2`.

تحتفظ Phaseo داخليًا برقم إصدار متزايد منفصل، بحيث يظل التسلسل الزمني والمقارنة مع المصدر والنسب محددًا بغض النظر عن تنسيق التسمية العامة المختار.

تظل نسخ السوق مثبتة على إصدار المصدر الدقيق الذي نُسخت منه. وعندما ينشر الناشر تحديثًا، تعرض النسخة إشعارًا بالتحديث. يؤدي تطبيقه إلى تحديث مسودة النسخة فقط، حتى يتمكن مالك مساحة العمل من مراجعتها ونشرها صراحةً دون أن يغيّر مؤلف المصدر سلوك الإنتاج.

تحتفظ Phaseo بالمصدر المباشر والنسب الكامل لكل تفرع. وبذلك تستطيع صفحات السوق التمييز بين التفرعات المباشرة وجميع الأجيال اللاحقة حتى عند نسخ الإعداد المسبق وإعادة نشره مرات عدة.

## كيفية دمج الإعدادات المسبقة

عندما يُحل الطلب بإعداد مسبق ضمن سياق Gateway، يُطبّق الإعداد قبل توجيه المزوّد:

- تملأ المعلمات الافتراضية الحقول الغائبة عن جسم الطلب فقط، ولا تستبدل القيم التي أرسلتها الجهة المستدعية.
- إذا احتوى الطلب على رسالة نظام، تُضاف مطالبة الإعداد المسبق قبلها. وإذا استخدم حقل `system` بأسلوب Anthropic، تُضاف المطالبة في ذلك الحقل.
- تُطبّق قوائم السماح والتجاهل للمزوّدين قبل اختيار المزوّد، فتضيّق مجموعة البدائل بدل أن تكون مجرد تسمية شكلية.
- تُرفض مبكرًا الطلبات التي تستخدم نموذجًا خارج قائمة النماذج المسموح بها بدل توجيهها بصمت إلى نموذج آخر.

هذا يجعل الإعدادات المسبقة الواجهة العامة الأساسية لقيم الطلب الافتراضية القابلة لإعادة الاستخدام وتحويلات التوافق البسيطة، دون إجبار كل جهة مستدعية على تكرار منطق المطالبة أو المعلمات نفسه.

## النطاق العام الحالي للإعدادات المسبقة

يقتصر مسار الإعدادات المسبقة في لوحة التحكم عمدًا على مجموعة فرعية مستقرة وصريحة من تشكيل الطلب:

- حقن مطالبة النظام
- قوائم النماذج المسموح بها
- قيود التوجيه عبر قوائم السماح أو التجاهل للمزوّدين
- قيم فك الترميز والتوليد الافتراضية
- قيم الاستدلال الافتراضية

إذا احتجت إلى تحويلات أعقد خاصة بالجهة المستدعية، فاجمعها في طبقة حدود واحدة للتطبيق واستخدم الإعدادات المسبقة للقيم الافتراضية القابلة لإعادة الاستخدام على مستوى الفريق.

## إدارة الإعدادات المسبقة

أنشئ الإعدادات المسبقة وأدِرها من **لوحة التحكم -> الإعدادات -> الإعدادات المسبقة**. استخدم أسماء مختلفة عندما تختلف المطالبات أو سلوكيات التوجيه أو التخزين المؤقت بوضوح بين تدفقات العمل.

## متى تستخدم الإعدادات المسبقة

- توحيد مطالبات النظام عبر خدمات متعددة.
- قصر التوجيه على المزوّدين المعتمدين للامتثال.
- الحفاظ على اتساق المعلمات الافتراضية بين البيئات.
- توفير مكان دائم لمشروعات الترحيل لحفظ قيم المطالبات والتوجيه والمعلمات الافتراضية مع إبقاء شيفرة التطبيق دون تغيير تقريبًا.
