يمكن للمزوّدين المعتمدين تحديث العروض الخاصة بالنماذج المرجعية العامة الموجودة عبر تغذية الكتالوج الخاصة بهم أو من إعدادات المزوّد. تتطلب النماذج المرجعية الجديدة موافقة. كل كتالوج لقطة كاملة: تؤدي إزالة عرض إلى إيقاف ذلك العرض المُدار عبر التغذية، مع الاحتفاظ بسجل أسعاره.

## اختيار التنسيق

تستمر تغذيات V1 الحالية في العمل دون تغييرات. يستخدم المستند `{"data": [...]}` الذي لا يحدد إصدارًا، أو المستند الذي يعلن `"schema_version": "1.0"`، تنسيقَ المستوى القياسي الحالي.

يعلن V1.1 عن `"schema_version": "1.1"` وينشر `service_tiers` داخل كل نموذج. يختار المستورِد التنسيق من المستند. معلمات الاستعلام في عنوان URL مثل `?format=phaseo-v1.1` هي اصطلاحات اختيارية لنقطة النهاية الخاصة بك؛ ولا يستنتج Phaseo الإصدار من عنوان URL.

نزّل [مخطط V1](https://phaseo.app/api/internal/provider-catalog/schema) أو [مخطط V1.1](https://phaseo.app/api/internal/provider-catalog/schema?version=1.1). تُرفض الإصدارات غير المدعومة صراحةً.

## نشر المستويات الموحّدة

| المستوى | المعنى |
| --- | --- |
| `standard` | تنفيذ متزامن عادي؛ مطلوب لكل نموذج. |
| `fast` | عرض أسرع أو ذو أولوية. تبقى أسماء المزوّد مثل HighSpeed ضمن معرّف النموذج لدى المزوّد. |
| `ultrafast` | عرض منفصل بسرعة أعلى عند دعمه. |
| `flex` | عرض متزامن مرن بأولوية أقل. |
| `batch` | تنفيذ غير متزامن عبر Batch API. يتطلب قدرة التنفيذ على دفعات. |

لا تستخدم أسماء المستويات الخاصة بالمزوّد كمعرّفات موحّدة. يظل `priority` اسمًا بديلًا مدعومًا للمتصلين يشير إلى Fast؛ أما الكتالوجات فتنشر `fast`.

يُدعم اختيار Fast وUltrafast وFlex في طلبات توليد النصوص. يعمل Batch عبر Batch API المنفصلة، ولا يزال يتطلب تكامل Batch مثبّتًا لدى المزوّد؛ ولا يؤدي نشر مستوى إلى تثبيت ذلك التكامل. بالنسبة إلى الملفات المرفوعة بالتنسيق الأصلي للمزوّد، استخدم معرّف نموذج Batch المُعلن أو أرسل الطلبات مضمّنة حتى يتمكن Phaseo من تحويله.

استخدم معرّف النموذج المرجعي نفسه لجميع مستويات خدمته. تحتاج النماذج المختلفة إلى هويات مرجعية منفصلة. ترث المستويات قدرات النموذج وحدوده وجدول إصداره. يعلن كل مستوى معرّف النموذج الخاص به لدى المزوّد وتوفره وتسعيره الفعلي.

```json
{
  "schema_version": "1.1",
  "data": [{
    "id": "your-provider/example-model",
    "name": "Example model",
    "capabilities": ["chat.completions"],
    "service_tiers": [{
      "service_tier": "standard",
      "provider_model_slug": "example-model",
      "availability": "ready",
      "pricing": [{
        "meter_key": "input_text_tokens",
        "modality": "text",
        "direction": "input",
        "unit": "token",
        "unit_quantity": 1000000,
        "price_nanos": 100000000,
        "display_label": "Input",
        "display_unit": "1M tokens"
      }, {
        "meter_key": "output_text_tokens",
        "modality": "text",
        "direction": "output",
        "unit": "token",
        "unit_quantity": 1000000,
        "price_nanos": 200000000,
        "display_label": "Output",
        "display_unit": "1M tokens"
      }]
    }]
  }]
}
```

لإضافة Fast، أضف كائن مستوى آخر يتضمن `"service_tier": "fast"` وأسعاره الفعلية ومعرّف نموذج مميزًا لدى المزوّد لهذا العرض. أما إذا كان المزوّد يختار المسار باستخدام معلمة أصلية بدلًا من ذلك، فاستخدم معرّف النموذج نفسه لدى المزوّد وأعلن `"upstream_service_tier": "priority"` أو `"fast"`. احذف هذا الحقل عندما يحدد معرّف النموذج المسار. يقبل Standard القيمة `default` أو `standard`؛ ويقبل Flex وUltrafast القيم المقابلة لهما. يرفض Phaseo المستويات المتزامنة غير القياسية التي لا تملك معرّف نموذج مميزًا أو محدِّدًا أصليًا.

يحتاج كل مستوى إلى أسعار صريحة، بما في ذلك الإخراج وأي وحدات فوترة للتخزين المؤقت أو الوسائط تحاسب عليها. الأسعار الصفرية صالحة؛ وتُرفض الأسعار السالبة والوحدات غير المعروفة والمستويات المكررة والأسعار المشروطة. يظل `price_nanos` السعر الفعلي بعد العروض الترويجية. انشر لقطة جديدة عند تغيّر الأسعار؛ ويحتفظ Phaseo بالأسعار الفعلية السابقة.

## تعريف حدود المعدل

عرّف حدود الطلبات والرموز التي تطبقها منصتك على حساب Phaseo في مصفوفة `rate_limits` اختيارية في المستوى الأعلى. تعمل بالطريقة نفسها في مستندات V1 وV1.1. احذف `model` لحدّ يشمل جميع نماذجك، أو اضبطه على قيمة `provider_model_slug` لدى المزوّد لأي نموذج أو مستوى في المستند نفسه.

```json
{
  "schema_version": "1.1",
  "data": [{ "id": "your-provider/example-model", "...": "..." }],
  "rate_limits": [
    { "requests_per_minute": 600, "tokens_per_minute": 2000000 },
    { "model": "example-model", "requests_per_day": 100000, "tokens_per_day": 500000000 }
  ]
}
```

يقبل كل إدخال `requests_per_minute` و`requests_per_day` و`tokens_per_minute` و`tokens_per_day`. كل قيمة عدد صحيح موجب أو `null`، ويحتاج كل إدخال إلى قيمة واحدة على الأقل. يحتسب Phaseo كل حد على مستوى عام عبر كل حركة المرور التي يرسلها إليك. يُطبَّق حد النموذج بالإضافة إلى الحد الذي يشمل جميع النماذج.

لا تحظر الحدود الطلبات أبدًا. كلما اقتربت حركة مرور العرض من أحد الحدود، يرسل إليه Phaseo حصة أصغر تدريجيًا. وعند بلوغ الحد، يرتّب Phaseo العرض بعد المزوّدين الآخرين حتى يُعاد ضبط الحد. لا تؤدي القيمة المنخفضة جدًا إلا إلى تقليل حصتك أنت من حركة المرور. لذلك تُطبَّق الحدود دون مراجعة بمجرد الموافقة على طلب انضمامك كمزوّد، عادةً خلال دقيقة.

عند وجود المصفوفة، تستبدل حدودك المُعلنة في كل مرة تُستورد فيها تغذية متغيّرة بنجاح. وتزيلها المصفوفة الفارغة. احذف `rate_limits` للإبقاء على الحدود التي تديرها في إعدادات المزوّد. يرفض Phaseo اللقطة كاملة، ويحتفظ بالكتالوج والحدود الحالية، إذا ذكر إدخالٌ نموذجًا غير موجود في المستند، أو كرر نطاقًا، أو استخدم قيمة ليست عددًا صحيحًا موجبًا. يظهر الرفض بالحالة **التعديلات مطلوبة**.

يمكنك أيضًا تعديل الحدود من **إعدادات المزوّد ← نماذجك ← حدود المعدل**. تُحفظ هذه التعديلات بشكل منفصل عن تغييرات الكتالوج. لا يقبل محرر الكتالوج `rate_limits`.

## التحديث والتحقق

يقبل الاستطلاع وخطافات الويب الموقّعة لتغييرات الكتالوج كلا الإصدارين عبر سير عمل الانضمام والتحديث نفسه. في إعدادات المزوّد، اختر مستوى قبل تعديل معرّفه لدى المزوّد أو توفره أو أسعاره. تؤدي إضافة مستوى آخر إلى تحويل الكتالوج المحفوظ إلى V1.1.

لا يضيف الكتالوج محوّل استدلال أو بيانات اعتماد. يجب دمج المزوّد وقدراته المُعلنة قبل تفعيل التوجيه. لا يجعل تسعير Batch خدمة Batch متاحة على نقاط نهاية المحادثة المتزامنة.

يظهر النموذج المرجعي غير المتاح أو ربط الناشر غير المعروف بالحالة **التعديلات مطلوبة** دون أن يمنع استيراد النماذج الصالحة. راجع لوحة تحكم المزوّد لمعرفة الأسباب الخاصة بكل نموذج.

في الكتالوجات التي تُغذّى عبر API، تكون تعديلات لوحة التحكم تجاوزات دائمة. تحدّث عمليات الاستيراد الحقول التي لا تحمل تجاوزات. اختر **استخدام قيمة التغذية** لإزالة التجاوز واستئناف متابعة ذلك الحقل. تعرض لوحة التحكم أحدث قيمة في التغذية والقيمة الفعلية والمحرر والوقت؛ ويسجّل نشاط الكتالوج التعديلات وعمليات التراجع عنها. تبقى النماذج المضافة يدويًا عروضًا محلية. تؤدي إزالة نموذج من التغذية إلى إيقاف عرض التغذية الخاص به حتى إن عُدّلت بعض حقوله. تظل الكتالوجات الحالية اليدوية بالكامل مدعومة.
