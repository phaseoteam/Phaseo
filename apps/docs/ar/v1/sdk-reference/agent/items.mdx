بدّل حسب نوع كل حدث أو عنصر مبثوث لعرض النص والاستدلال واستدعاءات الأدوات والتقدّم لحظة وصولها، ثم أعد بناء الخط الزمني نفسه لاحقًا من نتيجة التشغيل المحفوظة. تُنتج TypeScript اتحادًا محدد النوع من العناصر؛ أما اللغات الأخرى فتُنتج الأحداث الخام بوصفها خرائط أو قواميس أو Hashes.

const stream = agent.stream({ input, client });

for await (const item of stream.getItemsStream()) {
  switch (item.type) {

      break;

  }
}

## أنواع العناصر في TypeScript

`AgentItem<TOutput>` اتحاد مميَّز، وتضيّق TypeScript نوع كل عنصر بناءً على `type`:

| `type` | الحقول المهمة | يمثّل |
| --- | --- | --- |
| `message` | `role` (دائمًا `assistant`)، `content` | نص المساعد |
| `reasoning` | `text` | الاستدلال الذي يقدّمه النموذج |
| `tool_call` | `toolCallId`، `name`، `input` | استدعاء أداة مقترح |
| `tool_result` | `toolCallId`، `name`، `output` | استدعاء أداة مكتمل |
| `error` | `message`، وتفاصيل اختيارية عن الأداة | خطأ من المزوّد أو الأداة |
| `output` | `value` | المخرجات النهائية للوكيل بعد تحليلها |

تحتفظ العناصر المبنية من مخرجات المزوّد أيضًا بالحمولة الأصلية في `rawProviderItem`، للحقل النادر الذي لا تحمله الأنواع المحمولة. ابنِ منطق المنتج على الحقول المحمولة، لأن `rawProviderItem` يختلف حسب المزوّد.

## أنواع الأحداث في اللغات الأخرى

تقدّم Go وC# وPHP وRuby وJava أنواع الأحداث نفسها. وتُنتج `item_stream()` في Python عناصر المزوّد ووقت التشغيل بوصفها قواميس تحتوي على المفتاح `type`.

| نوع الحدث | الحقول |
| --- | --- |
| `response.output_text.delta` | `delta` (سلسلة نصية) |
| `response.reasoning.delta` | `delta` (سلسلة نصية) |
| `response.item` | `item` (عنصر مخرجات المزوّد، دون نوع محدد) |
| `tool.started`، `tool.completed`، `tool.failed`، `tool.preliminary_result` | `tool_call_id`، `tool_name`، إضافة إلى `output` أو `error` أو `result` |

يختلف موضع الحقول حسب اللغة:

| اللغة | شكل الحدث |
| --- | --- |
| Python | قواميس؛ اقرأ `item.get("type")` |
| Go | `AgentEvent` يتضمن `Type` و`Details map[string]any` |
| C# | `AgentEvent` يتضمن `Type` وقاموس `Details` بقيم `object?` |
| PHP | مصفوفات مسطّحة. تحمل أحداث دورة الحياة `type` و`run_id` و`agent_id` و`timestamp` و`status`؛ وتحمل أحداث النموذج `type` والحقول أعلاه في المستوى الأعلى. |
| Ruby | Hashes مسطّحة بمفاتيح رمزية (`:type` و`:delta` وغيرها)، بالتخطيط نفسه لمصفوفات PHP |
| Java | `AgentEvent` يتضمن `type()` وخريطة `details()` بقيم `Object` |

لا يمثّل أيٌّ منها اتحادًا محدد النوع، لذا تحقّق من الحقول التي تستخدمها واجهتك، وأبقِ تحليل ما يخص المزوّد خلف محوّل واحد، واحتفظ بمسار احتياطي للأنواع غير المعروفة. في Go وC# وJava، تحمل أحداث بث النموذج معرّف التشغيل `"stream"`؛ استخدم أحداث دورة الحياة للحصول على معرّف التشغيل الحقيقي. القائمة الكاملة لأحداث دورة الحياة موجودة في [خطافات دورة الحياة](./lifecycle-hooks).

## أعد بناء الخط الزمني بعد التشغيل

يبقى سجل الأحداث قابلًا للقراءة بعد انتهاء التشغيل، لذا يمكن لمستهلك أن يعرض بينما يحفظ آخر الأحداث، دون طلب ثانٍ إلى النموذج. للحصول على خط زمني دائم، خزّن نتيجة التشغيل المكتملة:

<Tabs>
<Tab title="TypeScript">

تحتوي النتيجة المكتملة على العناصر المرتّبة نفسها الموجودة في البث، في `items`:

```typescript
const completed = await stream.getResult();

for (const item of completed.items) {
  saveTimelineItem(completed.run.id, item);
}
```

</Tab>
<Tab title="Python">

| الحقل | المحتوى |
| --- | --- |
| `run` | الحالة الدائمة: `id` و`status` و`input` و`context` و`pause` و`stop_reason` و`error` و`usage` و`next_turn_params` |
| `steps` | سجل `AgentStepRecord` واحد لكل دور للنموذج، يتضمن `request_id` و`native_response_id` و`provider` و`model` و`model_attempts` و`usage` و`finish_reason` و`warnings` و`tool_calls` |
| `messages` | المحادثة كاملة، بما فيها نتائج الأدوات |
| `output` | المخرجات النهائية، بعد `parse_output` و`output_schema` |
| `usage` | الإجماليات في `AgentUsageSummary`: رموز الإدخال والإخراج والمخزّنة مؤقتًا والإجمالية، والتكلفة |

</Tab>
<Tab title="Go">

يحتوي `result.Messages` على كل رسائل النموذج والأدوات، ويحتوي `result.Steps` على استدعاءات الأدوات ومعرّف الطلب والمزوّد والنموذج والاستخدام لكل دور.

</Tab>
<Tab title="C#">

يحتوي `result.Messages` على كل رسائل النموذج والأدوات، ويحتوي `result.Steps` على استدعاءات الأدوات ومعرّف الطلب والمزوّد والنموذج وسبب الانتهاء والتحذيرات والاستخدام لكل دور.

</Tab>
<Tab title="PHP">

يحتوي `$result->messages` على كل رسائل النموذج والأدوات، ويحتوي `$result->steps` على استدعاءات الأدوات ومعرّف الطلب والمزوّد والنموذج وسبب الانتهاء والتحذيرات والاستخدام لكل دور.

</Tab>
<Tab title="Ruby">

يحتوي `result.messages` على كل رسائل النموذج والأدوات، ويحتوي `result.steps` على استدعاءات الأدوات ومعرّف الطلب والمزوّد والنموذج وسبب الانتهاء والتحذيرات والاستخدام لكل دور.

</Tab>
<Tab title="Java">

تعيد `fullStream()` سجل الأحداث الكامل بعد انتهاء التشغيل. يحتوي `messages()` على كل رسائل النموذج والأدوات، ويحتوي `steps()` على استدعاءات الأدوات ومعرّف الطلب والمزوّد والنموذج وسبب الانتهاء والتحذيرات والاستخدام لكل دور.

</Tab>
<Tab title="Rust">

يتضمن `RunResult` الحقل `run` (الحالة والمعرّفات والنموذج الفعلي وحد الخطوات والسياق وحالة التوقف المؤقت)، و`steps` (معرّف الطلب والمزوّد والنموذج وسبب الانتهاء واستدعاءات الأدوات والاستخدام لكل دور للنموذج)، و`messages` (السجل الكامل لرسائل النموذج والأدوات)، و`output`، و`usage`.

</Tab>
</Tabs>
