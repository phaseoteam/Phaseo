## أنشئ وكيلًا

تنشئ وكيلًا من تعريف. ينطبق حد الخطوات في التعريف على كل استدعاء تشغيل أو متابعة.

| اللغة | الاسم | حد الخطوات الافتراضي |
| --- | --- | --- |
| TypeScript | `createAgent(definition)` | 12 |
| Python | `create_agent(definition)`، من قاموس أو `AgentDefinition` | 12 |
| Go | `CreateAgent(AgentDefinition) *Agent` | 8 |
| C# | `AgentSdk.CreateAgent(AgentDefinition)` | 12 |
| PHP | `AgentSdk::createAgent(AgentDefinition)` | 12 |
| Ruby | `PhaseoAgentSdk.create_agent(definition)`، من `AgentDefinition` أو حقول بالكلمات المفتاحية | 12 |
| Java | `AgentSdk.createAgent(AgentDefinition)` | 12 (تصبح قيمة `maxSteps` الأقل من 1 مساوية لـ 12) |
| Rust | `create_agent(AgentDefinition::new(id, model))` | 8 (تُقيَّد القيم بحد أدنى 1) |

### حقول التعريف

تبني Rust التعريف بدوال بدلًا من الحقول: `AgentDefinition::new(id, model)`، ثم `.instructions(text)` و`.tool(tool)` (مرة لكل أداة) و`.max_steps(limit)` و`.model_retries(count, backoff)` و`.human_review(callback)`. أما `AgentDefinition` في Java فسجل بمُنشئات ذات 10 و13 و19 وسيطًا.

| الحقل | camelCase (TypeScript، PHP، Java) | snake_case (Python، Ruby) | PascalCase (Go، C#) | غير موجود في |
| --- | --- | --- | --- | --- |
| معرّف الوكيل (مطلوب) | `id` | `id` | `ID` (Go)، `Id` (C#) | |
| النموذج أو الإعداد المسبق | `model`، `preset` | `model`، `preset` | `Model`، `Preset` | لا يوجد `preset` في Rust |
| قائمة النماذج (لا يُستخدم إلا الأول، عندما لا يكون `model` مضبوطًا؛ دون بديل احتياطي) | `models` | | | الكل عدا TypeScript |
| التعليمات | `instructions` | `instructions` | `Instructions` | |
| الأدوات | `tools` | `tools` | `Tools` | |
| الأدوات المعروضة في خطوة | `activeTools` | | | الكل عدا TypeScript |
| إعادة كتابة السجل قبل كل طلب للنموذج | `prepareMessages` | | | الكل عدا TypeScript |
| حد الخطوات وشروط الإيقاف | `maxSteps`، `stopWhen` | `max_steps`، `stop_when` | `MaxSteps`، `StopWhen` | لا يوجد `stop_when` في Rust |
| إعادة محاولة النموذج وتزامن الأدوات | `modelRetry`، `toolExecution` | `model_retry`، `tool_execution` | `ModelRetry`، `ToolExecution` | لا يوجد تزامن للأدوات في Rust |
| أخذ العينات والطول | `temperature`، `maxOutputTokens`، `topP` | `temperature`، `max_output_tokens`، `top_p` | | Go، C#، Java، Rust |
| تحليل المخرجات النهائية والتحقق منها | `parseOutput`، `outputSchema` | `parse_output`، `output_schema` | `ParseOutput`، `OutputSchema` | Rust |
| الموافقة على كل استدعاء أداة | `requireApproval` | `require_approval` | `RequireApproval` | Rust (الموافقة لكل أداة) |
| المراجعة بعد كل استجابة من النموذج | `humanReview` | `human_review` | `HumanReview` | |
| تغيير الأدوات أو الإعدادات بين الأدوار | `dynamicTools` (PHP) ودوال رد النداء الخاصة بـ [الأدوار الديناميكية](./dynamic-turns) | `dynamic_tools` (Ruby) | دوال رد النداء الخاصة بالأدوار الديناميكية | Rust |

في TypeScript، يمكن أن تكون `model` و`instructions` وقيم أخذ العينات ثابتة أو ديناميكية.

### خيارات التشغيل

تأخذ PHP وRuby هذه الخيارات بوصفها وسائط مسمّاة أو بالكلمات المفتاحية؛ أما `RunOptions` في Java فسجل موضعي بالترتيب `input, client, context, model, preset, maxSteps, modelRetry, toolExecution, onEvent, devtools`، ثم `state` اختياريًا.

| الخيار | camelCase (TypeScript، PHP، Java) | snake_case (Python، Ruby، Rust) | PascalCase (Go، C#) | غير موجود في |
| --- | --- | --- | --- | --- |
| الإدخال | `input` | `input` | `Input` | |
| المحادثة كاملة بدلًا من الإدخال | `messages` | | | الكل عدا TypeScript |
| عميل النموذج | `client` | `client` | `Client` | تمرّره Rust وسيطًا منفصلًا |
| سياق التطبيق | `context` | `context` | `Context` | |
| تجاوزات النموذج والإعداد المسبق وحد الخطوات | `model`، `preset`، `maxSteps` | `model`، `preset`، `max_steps` | `Model`، `Preset`، `MaxSteps` | لدى Rust `model` و`max_steps` فقط |
| تجاوزات إعادة المحاولة وتزامن الأدوات | `modelRetry`، `toolExecution` | `model_retry`، `tool_execution` | `ModelRetry`، `ToolExecution` | Rust |
| تجاوزات أخذ العينات | `temperature`، `maxOutputTokens`، `topP` (TypeScript) | | | الكل عدا TypeScript |

تأخذ خيارات المتابعة تجاوزات التشغيل أعلاه، إضافة إلى:

| سبب الانتهاء | `finishReason` | `finish_reason` | `FinishReason` |
| التحذيرات | `warnings` | `warnings` (ليس في Rust) | `Warnings` |

النوع هو `RunStep` في كل مكان باستثناء TypeScript وPython (`AgentStepRecord`).

### ملخص الاستخدام

`inputTokens` و`outputTokens` و`cachedTokens` و`totalTokens` و`cost` (TypeScript وJava)؛ و`input_tokens` و`output_tokens` و`cached_tokens` و`total_tokens` و`cost` (مفاتيح Python وPHP وRuby، وRust)؛ و`InputTokens` و`OutputTokens` و`CachedTokens` و`TotalTokens` و`Cost` (Go وC#). النوع هو `AgentUsageSummary` في TypeScript وPython و`UsageSummary` في Go وC# وJava وRust. وتستخدم PHP وRuby مصفوفة أو Hash. راجع [المراقبة](./observability) لمعرفة التنبيهات المتعلقة بـ `cost`.

## عملاء النموذج

نفّذ عميل نموذج لإرسال أدوار النموذج عبر وسيلة نقل أخرى، أو لتغليف عميل Gateway.

| اللغة | الواجهة | الدوال |
| --- | --- | --- |
| Go | `ModelClient`، `StreamingModelClient` | `Generate(ctx, ModelRequest)`؛ `Stream(ctx, ModelRequest)` |
| C# | `IModelClient`، `IStreamingModelClient` | `Generate(ModelRequest)`؛ `Stream(ModelRequest)` |
| PHP | `ModelClient`، `StreamingModelClient` (واجهات) | `generate(ModelRequest)`؛ `stream(ModelRequest)` |
| Java | `ModelClient`، `StreamingModelClient` | `generate(ModelRequest)`؛ `stream(ModelRequest)` |
| Rust | `ModelClient` (trait) | `fn generate(&mut self, request: &ModelRequest) -> Result<ModelResponse, AgentError>` |

في Rust، يحتوي `ModelRequest` على معرّف الوكيل والنموذج الفعلي والتعليمات والرسائل الحالية ومواصفات الأدوات (`ToolSpec`: `id` و`description` و`parameters` بصيغة JSON Schema) وسياق التطبيق. ويحتوي `ModelResponse` على `message` و`usage` و`request_id` و`provider` و`model` و`finish_reason`. ويتضمن `Message` الحقول `role` و`content` و`tool_calls` و`tool_call_id` و`name` و`is_error`، مع المُنشئين `Message::user(content)` و`Message::assistant(content)`؛ ويتضمن `ToolCall` الحقول `id` و`name` و`input` بصيغة JSON.
