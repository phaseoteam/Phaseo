ثبّت حزمة Phaseo الخاصة بلغتك، وأنشئ عميلًا باستخدام مفتاح API الخاص بك، واستدعِ دالة واحدة لكل نقطة نهاية في Gateway. تقرأ كل حزمة SDK المتغير `PHASEO_API_KEY` عندما لا تمرّر مفتاحًا.

| اللغة | الحزمة | السجلّ | الإصدار المنشور |
| --- | --- | --- | --- |
| TypeScript | [`@phaseo/sdk`](https://www.npmjs.com/package/@phaseo/sdk) | npm | `3.0.0` |
| Python | [`phaseo`](https://pypi.org/project/phaseo/) | PyPI | `3.0.0` |
| Go | [`github.com/phaseoteam/Phaseo/packages/sdk/sdk-go/v4`](https://pkg.go.dev/github.com/phaseoteam/Phaseo/packages/sdk/sdk-go/v4) | Go modules | `v3.0.0` |
| C# | [`Phaseo.Sdk`](https://www.nuget.org/packages/Phaseo.Sdk) | NuGet | `3.0.0` |
| PHP | [`phaseo/sdk`](https://packagist.org/packages/phaseo/sdk) | Packagist | `v3.0.0` |
| Ruby | [`phaseo_sdk`](https://rubygems.org/gems/phaseo_sdk) | RubyGems | `3.0.0` |
| Java | `app.phaseo:phaseo-sdk` | Maven Central (واجهة برمجية أقدم)؛ ابنِ المصدر الحالي بدلًا من ذلك | `3.0.0` |
| Rust | [`phaseo`](https://crates.io/crates/phaseo) | crates.io | `0.2.0` |

تحتوي صفحة [التثبيت](./installation) على أمر التثبيت والمتطلبات لكل لغة. لم تُطرح بعد حزمة SDK للغة C++.

## ما ترسله وما تحصل عليه

تستخدم أجسام الطلبات أسماء حقول JSON الخاصة بالواجهة البرمجية في كل حزمة SDK. تحتوي صفحة [الاستخدام](./usage) على مثال واحد لكل نقطة نهاية.

| اللغة | جسم الطلب | القيمة المُعادة |
| --- | --- | --- |
| TypeScript | كائنات ذات أنواع محددة مولَّدة من مواصفة OpenAPI | كائنات ذات أنواع محددة |
| Python | قواميس (dicts)؛ والأنواع موجودة في `phaseo.models` | قواميس `APIResponse` تحتوي على `output_text` و`request_id` و`trace_url` |
| Go | `map[string]interface{}`، أو النوعان `phaseo.ChatCompletionsRequest` و`phaseo.ResponsesRequest` (بحقول بنية بأسلوب PascalCase مثل `Model` و`Messages` و`Input`) | JSON مفكوك الترميز |
| C# | `Dictionary<string, object>` | `Dictionary<string, object>?` |
| PHP | مصفوفات | مصفوفات |
| Ruby | Hashes (وسائط الكلمات المفتاحية) | Hashes |
| Java | `Map` أو `JsonNode` من Jackson؛ حلّل سلاسل JSON أولًا | `JsonNode` |
| Rust | `&serde_json::Value` | `PhaseoResponse` يحتوي على `status` و`body` و`request_id` |

يفشل إنشاء العميل عند غياب المفتاح. تطلق Python الخطأ `ValueError`، وتعيد `NewFromEnv()` في Go خطأً، وتطلق C# وPHP الخطأ `Missing API key. Pass apiKey or set PHASEO_API_KEY.`، وتطلق Ruby الخطأ `ArgumentError: Missing API key. Pass api_key or set PHASEO_API_KEY.`، وتعيد `Phaseo::from_env()` في Rust قيمة `PhaseoError`.

## العثور على الدالة لكل نقطة نهاية

تسبق الحزم المنشورة بعض الميزات الموجودة في مصدر حزم SDK:

| اللغة | ما ليس في الحزمة المنشورة بعد |
| --- | --- |
| Go | الدوال `GetModelEndpointCapabilities` و`CheckModelParameters` و`PreflightRequest` ليست في `v3.0.0`؛ وستُطرح مع الإصدار القادم. |
| C# | الدوال `GetModelEndpointCapabilities` و`CheckModelParameters` و`PreflightRequest` ليست في `3.0.0`؛ وستُطرح مع الإصدار القادم. |
| PHP | الدوال `getModelEndpointCapabilities` و`checkModelParameters` و`preflightRequest` ليست في `v3.0.0`؛ وستُطرح مع الإصدار القادم. |
| Ruby | الدوال `model_endpoint_capabilities` و`check_model_parameters` و`preflight_request` ليست في الحزمة (gem) `3.0.0`؛ وستُطرح مع الإصدار القادم. |
| Java | يفتقر العنصر `3.0.0` على Maven Central إلى عناصر التحكم في إعادة المحاولة، والبيانات الوصفية للاستجابة، والتحقق من المعاملات. ابنِ المصدر المثبّت على إصدار محدد من صفحة [التثبيت](./installation) للحصول عليها. |

| `on_request`، `on_response`، `on_retry` | خطافات تُستدعى في كل محاولة. |

استخدم `AsyncPhaseo` مع asyncio:

```python Python
import asyncio
from phaseo import AsyncPhaseo

async def main():
    async with AsyncPhaseo() as client:
        response = await client.responses.create({"model": "openai/gpt-6-astra", "input": "Hello"})
        print(response.output_text, response.request_id, response.trace_url)

asyncio.run(main())
```

استخدم `async for event in client.responses.stream(request)` لأحداث النص المحلَّلة. يؤدي إلغاء مهمة asyncio إلى إيقاف طلب HTTP وأي استطلاع. يتضمن `AsyncPhaseo` مساحات أسماء للموارد تشمل النصوص، والصور، والصوت، والوقت الفعلي، والموسيقى، والفيديو، والدفعات، والملفات، والنماذج، والتضمينات، وOCR، وإعادة الترتيب، والتحليل، والإشراف على المحتوى، والقرارات، والاستخراج؛ واستخدم `await client.request(...)` لأي عملية HTTP أخرى.

## انتظار الموسيقى أو الفيديو أو الدفعات

دوال الانتظار المساعدة موجودة في TypeScript وPython. تعيد حزم SDK الأخرى المهمة من استدعاء الإنشاء؛ استطلعها باستخدام دالة الجلب أو افتح [عنوان WebSocket للمهمة](#find-the-method-for-each-endpoint).

<CodeGroup>

```typescript TypeScript
const music = await client.music.generateAndWait(
  { model: process.env.PHASEO_MUSIC_MODEL!, prompt: "Gentle instrumental piano" },
  { timeoutMs: 600_000, onPoll: (job) => console.log(job.id, job.status) },
);
```

```python Python
import os

music = client.music.generate_and_wait(
    {"model": os.environ["PHASEO_MUSIC_MODEL"], "prompt": "Gentle instrumental piano"},
    timeout=600,
    on_poll=lambda job: print(job["id"], job["status"]),
)
```

</CodeGroup>

استخدم `videos.generateAndWait` / `videos.generate_and_wait` للفيديو و`batches.createAndWait` / `batches.create_and_wait` للدفعات. ترسل كل دالة مساعدة الطلب مرة واحدة. إذا كانت الاستجابة الأولى مكتملة بالفعل، تعيدها دون استطلاع؛ وإلا فإنها تستطلع المهمة نفسها حتى تنتهي وتعيد الاستجابة كاملة. تطلق المهام الفاشلة أو الملغاة أو المنتهية الصلاحية الخطأ `JobFailedError`، الذي يحتوي `response` الخاص به على التفاصيل. قد تحتوي الدفعة المكتملة مع ذلك على طلبات فردية فاشلة.

تستأنف `wait(id, options)` على كل مورد مهمة موجودة وتعيد أي استجابة نهائية، بما في ذلك الإخفاقات. في Python، تتضمن الموسيقى أيضًا `create(request)` و`retrieve(id)`.

| TypeScript | Python | الافتراضي | ملاحظات |
| --- | --- | --- | --- |
| `intervalMs` | `interval` | `5000` ms / `5` ثوانٍ | الحد الأدنى `250` ms / `0.25` ثانية. |
| `timeoutMs` | `timeout` | `1800000` ms / `1800` ثانية (30 دقيقة) | تبدأ بعد عودة الإرسال؛ ويحتفظ طلب الإرسال بمهلته الخاصة. |
| `signal` | `cancel_event` | لا يوجد | يوقف الانتظار. في Python، كائن `threading.Event`. |
| `onPoll` | `on_poll` | لا يوجد | يستقبل الاستجابة الأولى وكل استطلاع. |

يحتفظ `JobTimeoutError` و`JobCancelledError` بمعرّف المهمة وآخر استجابة (`jobId`/`lastResponse` في TypeScript، و`job_id`/`last_response` في Python)، لذا يمكنك الاستئناف باستخدام `.wait(error.jobId)` أو `.wait(error.job_id)`. لا يؤدي إيقاف الانتظار إلى إلغاء المهمة البعيدة. في TypeScript، يُلغي الاستطلاع الجاري؛ أما عميل Python المتزامن فيتحقق من الإلغاء والمهلة النهائية بين الطلبات والاستدعاءات الراجعة، لذا لا يمكنه مقاطعة استدعاء HTTP قيد التنفيذ. تُطلق إخفاقات HTTP كما هي، ولا يُعاد إرسال الطلبات أبدًا. تستطلع هذه الدوال المساعدة من عمليتك؛ ولا تضيف تنفيذًا في الخلفية إلى البوابة.

### الاحتفاظ بمقبض عبر العمليات

تعيد `music.start` و`videos.start` و`batches.start` مقبضًا يتضمن `result()` و`events()` و`cancel()`، إضافة إلى `toJSON()` (في TypeScript) أو `to_dict()` (في Python). خزّن النوع والمعرّف اللذين يعيدهما وأعد بناء المقبض لاحقًا باستخدام `resume(id)`. تطلق `result()` خطأً عند الإخفاقات النهائية. لا تدعم `cancel()` إلا مهام الفيديو والدفعات. على `AsyncPhaseo`، استخدم await مع الدوال وكرّر على الأحداث باستخدام `async for`.

| المهمة | TypeScript | Python |
| --- | --- | --- |
| بث محتوى الفيديو | `videos.streamContent(id)`، ويُكتب باستخدام `downloadTo(stream, writable)` | `videos.stream_content(id)`، ويُكتب باستخدام الدالة المتزامنة `download_to(chunks, binary_file)`، التي لا تحتفظ بالتنزيل كاملًا في الذاكرة |
| بث نتائج الدفعات | تحلّل `batchResults(await client.batches.streamResults(id))` بيانات JSONL صفًا تلو الآخر؛ وتطابق `matchBatchResult(row, inputsByCustomId)` كل صف مع مُدخله وتحتفظ بأخطاء كل صف | `batches.results(id)` |
| تحضير عمليات الرفع | `toFile(bytes, filename, contentType)` | مرّر بايتات، أو كائنات `Path`، أو كائنات ملفات، أو صفوف ملفات (tuples) من HTTPX |

## عناصر التحكم في الطلب والأخطاء

القيمة الافتراضية لإعادة المحاولة `0` في TypeScript وPython وJava، ولا تنطبق إلا على طلبات `GET` و`HEAD`. لا يُعاد أبدًا إرسال الطلبات المدفوعة ولا عمليات الكتابة ولا طلبات البث.

<CodeGroup>

```typescript TypeScript
const fast = client.withOptions({ timeoutMs: 30_000, signal, maxRetries: 2 });
```

```python Python
fast = client.with_options(timeout=30, max_retries=2)
```

```java Java
Phaseo client = new Phaseo(System.getenv("PHASEO_API_KEY"))
    .setTimeout(Duration.ofSeconds(30))
    .setMaxRetries(2);
```

</CodeGroup>

<Tabs>
<Tab title="TypeScript">

تعيد `withOptions(...)` عميلًا جديدًا تُطبَّق فيه عناصر التحكم تلك على كل استدعاء للموارد والبث والوسائط؛ ويبقى العميل الأصلي دون تغيير. تحترم إعادة المحاولة `Retry-After`. تشمل `timeoutMs` قراءة جسم الاستجابة.

تعيد `responseMetadata(result)` معرّف طلب البوابة وعنوان URL للتتبّع في لوحة التحكم. أخطاء HTTP من النوع `PhaseoHttpError`، وتتضمن `status` الخاص بـ HTTP، و`code` الخاص بخطأ الواجهة البرمجية، و`requestId`، و`traceUrl`، ومهلة إعادة المحاولة، والجسم، و`headers`.

</Tab>
<Tab title="Python">

تعيد `with_options(...)` عميلًا جديدًا وتقبل أيضًا `headers=...`؛ وتعمل على `Phaseo` و`AsyncPhaseo` كليهما. تحدث إعادة المحاولة قبل قراءة الاستجابة، بحد أقصى `10`. المهلات هي مهلات HTTPX بالثواني، لذا فهي تحدّ من خمول الشبكة وليس من المدة الإجمالية.

استجابات JSON هي قواميس `APIResponse` تحتوي على `output_text` و`request_id` و`trace_url`. أخطاء HTTP من النوع `PhaseoHTTPError`، وتتضمن `status` و`code` و`request_id` و`trace_url` ومهلة إعادة المحاولة والجسم.

عند الترقية من إصدار أقدم، استبدل التقاط `urllib.error.HTTPError` بـ `PhaseoHTTPError` (أو `httpx.HTTPStatusError`)، والتقاط أخطاء الاتصال بـ `httpx.TransportError`.

</Tab>
<Tab title="Java">

أخطاء HTTP من النوع `Client.ApiException` (`app.phaseo.gen.Client`)، وتتضمن `getStatusCode()` و`getRequestId()` و`getResponseBody()` والترويسات. تعيد `requestWithResponse(...)` البيانات مع `requestId()` الخاص بها.

</Tab>
<Tab title="Rust">

يعيد كل استدعاء `Result<PhaseoResponse, PhaseoError>`. ينفّذ `PhaseoError` السمتين `std::error::Error` و`Display`؛ وليس لإخفاقات النقل والإعداد `status`.

| النوع | الحقل | المعنى |
| --- | --- | --- |
| `PhaseoResponse` | `status: u16` | رمز حالة HTTP. |
| `PhaseoResponse` | `body: serde_json::Value` | استجابة JSON المحلَّلة، أو سلسلة JSON عندما لا تكون الاستجابة JSON صالحًا. |
| `PhaseoResponse` | `request_id: Option<String>` | ترويسة الاستجابة `x-request-id`، عند وجودها. |
| `PhaseoError` | `message: String` | رسالة خطأ الإعداد أو النقل أو Gateway. |
| `PhaseoError` | `status: Option<u16>` | حالة HTTP من Gateway، عند استلام استجابة. |
| `PhaseoError` | `body: Option<serde_json::Value>` | جسم خطأ Gateway المحلَّل، عند توفره. |

</Tab>
</Tabs>

تعرض صفحة [الاستخدام](./usage#handle-errors) معالج أخطاء كاملًا في كل لغة.

## استدعاء نقطة نهاية دون مغلّف

تتضمن كل حزمة SDK أيضًا العميل المولَّد من مواصفة Phaseo OpenAPI:

| اللغة | العميل المولَّد |
| --- | --- |
| TypeScript | `client.rawClient()`؛ وتُصدَّر العمليات المولَّدة باسم `operations`. |
| Python | `client.raw_client()`؛ والعمليات المولَّدة موجودة في `phaseo.ops`. |
| Go | `client.RawClient()`، من `src/gen`. ترسل `client.Request(ctx, method, path, query, headers, body)` أي طلب. |
| Java | `client.rawClient()`، مع `requestLines` للبث و`requestBytes` للاستجابات الثنائية. |
| Rust | يحتوي `phaseo::gen` على العميل والنماذج والعمليات المولَّدة، ويُعاد تصديرها باسم `phaseo::client` و`phaseo::models` و`phaseo::operations`. يحتوي `phaseo::model_ids` على معرّفات النماذج المولَّدة. ترسل `client.post(path, body)` بيانات JSON إلى أي مسار ضمن عنوان URL الأساسي. راجع [docs.rs](https://docs.rs/phaseo). |

العمليات المولَّدة أدنى مستوى من دوال المغلّف؛ فضّل المغلّف حيثما وُجد.

## تحليل المخرجات وتجميع البث

هذه الدوال المساعدة موجودة في TypeScript وPython. تتحقق `responses.parse(request, schema)` من استجابة JSON مكتملة. في TypeScript، يكون `schema` محلّلًا متوافقًا مع Zod؛ وفي Python، نموذج Pydantic. عيّن تنسيق المخرجات المنظَّمة في الطلب أيضًا؛ فالمحلّل يتحقق فقط.

تجمع `collectStream(client.streamResponses(request))` (في TypeScript)، أو `collect_stream` و`collect_async_stream` (في Python)، النص المبثوث والاستخدام.

## التحقق من نموذج قبل استدعائه

تتحقق `checkModelCapabilities` / `check_model_capabilities` (في TypeScript وPython) من القدرات المعلنة والقيود العددية (`inputTypes` و`outputTypes` و`endpoints` و`parameters` و`parameterValues`، أو الأسماء بأسلوب snake_case في Python) على عرض مزوّد نشط واحد. لا تغيّر النموذج أبدًا ولا تحذف معاملات، ولا يمكنها ضمان أن يقبل المزوّد الحي الطلب. تختلف معالجة البيانات الوصفية المفقودة: تُبلغ TypeScript عنها بوصفها غير معروفة، وتُفشل Python الفحص.

لمنتقيات النماذج ومحررات المعاملات، استخدم البيانات الوصفية الحية لنقاط النهاية:

<CodeGroup>

```typescript TypeScript
const support = await client.models.checkParameters(
  "anthropic/claude-haiku-4.5",
  { temperature: 0.7, top_p: 0.9 },
  { endpoint: "responses" },
);
```

```python Python
support = client.models.check_parameters(
    "anthropic/claude-haiku-4.5",
    {"temperature": 0.7, "top_p": 0.9},
    endpoint="responses",
)
```

</CodeGroup>

يعود كل معامل بالقيمة `supported` أو `partial` أو `unsupported` أو `unknown`، مع مسارات المزوّدين المطابقة ومشكلات القيود التي يمكنك إبرازها مباشرة في الواجهة. هذه الفحوص استدعاءات صريحة؛ ولا تضيف بحثًا إلى طلبات التوليد. تسرد صفحة [النماذج](./models#check-one-model) الدالة في كل حزمة SDK.
