تنتج إخفاقات الوكلاء عادةً عن طلب النموذج أو أداة محلية أو التحقق من المخطط أو الإلغاء أو قرار بشري غير مكتمل. أظهر هذه المسارات في السجلات وأعِد أخطاء آمنة إلى المستدعين.

## التعافي من أخطاء الأدوات

اضبط `OnError: "return-to-model"` على أداة عندما يستطيع النموذج التعافي من الإخفاق بصورة معقولة. يحوّل SDK الخطأ إلى نتيجة أداة ويسمح للجولة التالية باختيار إجراء آخر. أبقِ السلوك الافتراضي الذي ينهي التشغيل عند الإخفاقات غير الآمنة أو غير القابلة للتعافي.

## مراعاة الإلغاء

مرّر سياق الطلب إلى `Run` أو `Continue` أو `Stream`. يؤدي إلغاؤه إلى إيقاف بث النموذج ومنع بدء أعمال أدوات جديدة.

```go
ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
defer cancel()

result, err := agent.Run(ctx, options)
if errors.Is(err, context.DeadlineExceeded) {
  // Persist enough application state to retry or report the timeout.
}
```

## تشخيص أخطاء المتابعة

عندما تنتظر عملية التشغيل شخصًا، يحتاج كل استدعاء معلّق إلى موافقة أو رفض أو نتيجة مقدمة خارجيًا مرتبطة بمعرّف استدعاء الأداة. احفظ سجل التشغيل المعاد كاملًا؛ فالرسالة البشرية وحدها لا تغني عن هذه القرارات.

## تسجيل سياق مفيد

سجّل معرّف التشغيل وفهرس الخطوة ومعرّف الطلب والمزوّد والنموذج وسبب الإنهاء ومعرّف استدعاء الأداة وسبب الإيقاف. تعرض خطافات دورة الحياة وDevTools هذه الحقول دون الحاجة إلى تسجيل مستوى النقل.
