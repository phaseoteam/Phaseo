تنتج إخفاقات الوكيل عادةً عن طلب النموذج أو أداة محلية أو التحقق من المخطط أو انتهاء المهلة أو غياب قرار بشري.

## التعافي من أخطاء الأدوات

اضبط `onError: "return-to-model"` عندما يستطيع النموذج التعافي من خطأ الأداة. يتحول الخطأ إلى نتيجة أداة منظّمة ويمكن للتشغيل اختيار إجراء آخر. وأبقِ سلوك fail-run للعمليات غير الآمنة أو التي يتعذر التعافي منها.

## فهم تنفيذ PHP

تُنفّذ عمليات رد نداء أدوات PHP بصورة متزامنة. لذلك يقيّد وقت تشغيل PHP وعميل الإدخال/الإخراج الأساسي توازي الأدوات ومقاطعتها. عيّن مهلات صريحة لأدوات الشبكة والعمليات، ولا تفترض إمكان إيقاف رد النداء المنتهي وقته قسرًا دائمًا.

## تشخيص أخطاء الاستكمال

يحتاج كل استدعاء معلّق إلى موافقة أو رفض أو مخرجات مقدّمة خارجيًا، مرتبطة بمعرّف استدعاء الأداة. احفظ حالة التشغيل المُعادة كاملة قبل عرض واجهة الموافقة.

## تسجيل الحقول المفيدة

سجّل معرّف التشغيل وفهرس الخطوة ومعرّف الطلب والمزوّد والنموذج وسبب الإنهاء ومعرّف استدعاء الأداة وسبب التوقف. استخدم خطافات دورة الحياة أو DevTools بدلًا من تسجيل المطالبات وبيانات الاعتماد الخام.
