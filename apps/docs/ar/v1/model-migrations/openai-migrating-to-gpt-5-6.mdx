اختر فئة GPT-5.6 التي تناسب عبء العمل، وبدّل معرّف النموذج فقط، وأعد اختبار جهد الاستدلال والأدوات وزمن الاستجابة والتكلفة. أبقِ نموذج GPT-5 السابق لديك كنموذج احتياطي حتى تنجح تقييماتك.

## اختيار الفئة

| النموذج | استخدمه من أجل | جهد الاستدلال |
| --- | --- | --- |
| `openai/gpt-5.6-sol` | الاستدلال بأعلى قدرة، والبرمجة بالوكلاء، والتحليل العلمي، والعمل المهني المعقد | `none` و`low` و`medium` و`high` و`xhigh` و`max` |
| `openai/gpt-5.6-terra` | الاستدلال اليومي المتوازن، والبرمجة، وعمل المساعد | `none` و`low` و`medium` و`high` و`xhigh` و`max` |
| `openai/gpt-5.6-luna` | العمل الأقل زمنًا للاستجابة والحساس للتكلفة | `none` و`low` و`medium` و`high` و`xhigh` و`max` |

تمتلك الفئات الثلاث نافذة سياق بحجم 1,050,000 رمز و128K رمز للمخرجات. ولكل منها أيضًا معرّف Pro (`openai/gpt-5.6-sol-pro` و`-terra-pro` و`-luna-pro`)، يرسل `reasoning.mode: "pro"` نيابة عنك.

يشير الاسم المستعار `gpt-5.6` الخاص بـ OpenAI إلى `gpt-5.6-sol`؛ أما على Phaseo فاستدعِ معرّفات الفئات مباشرة. تتبع الأسماء المستعارة للفئات `openai/gpt-sol-latest` و`openai/gpt-terra-latest` و`openai/gpt-luna-latest` أحدث نموذج في كل فئة، ويشير `openai/gpt-sol-latest` بالفعل إلى ما بعد GPT-5.6. لا تستخدمها إلا عندما تريد أن تنتقل الإصدارات المستقبلية تلقائيًا.

## تحديث طلبك

يضيف GPT-5.6 المستوى `max`، وهو أعلى ميزانية استدلال، في كل الفئات. لا تستخدمه إلا حيث يستحق زمن الاستجابة والتكلفة الإضافيان ذلك.

<CodeGroup>
```json Responses
{
  "model": "openai/gpt-5.6-sol",
  "input": "Review this multi-service incident report and propose a rollback plan.",
  "reasoning": { "effort": "max" }
}
```

```json Chat Completions
{
  "model": "openai/gpt-5.6-terra",
  "messages": [
    { "role": "user", "content": "Design a test plan for this agent workflow." }
  ],
  "reasoning_effort": "medium"
}
```
</CodeGroup>

يضيف GPT-5.6 أيضًا:

- **`reasoning.mode: "pro"`** للمهام الأصعب، دون تبديل النموذج؛
- **`reasoning.context`** (`auto` أو `current_turn` أو `all_turns`) للتحكم في الاستدلال الذي يُحتفظ به؛
- دعمًا تجريبيًا لتعدد الوكلاء واستدعاء الأدوات البرمجي (Programmatic Tool Calling) لمسارات العمل كثيفة الأدوات؛
- تخزينًا مؤقتًا صريحًا للمطالبات باستخدام `prompt_cache_options` ونقاط توقف التخزين المؤقت. على GPT-5.6، يحل `prompt_cache_options.ttl` محل `prompt_cache_retention`، الذي لا يرسله Phaseo إلى نماذج GPT-5.6.

## مراجعة التسعير

الأسعار لكل 1M رمز في الفئة القياسية لدى OpenAI، للطلبات حتى 272K رمز إدخال:

| النموذج | الإدخال | قراءة من ذاكرة التخزين المؤقت | كتابة في ذاكرة التخزين المؤقت (30 دقيقة) | كتابة في ذاكرة التخزين المؤقت (12 ساعة) | الإخراج |
| --- | ---: | ---: | ---: | ---: | ---: |
| Sol | $5.00 | $0.50 | $6.25 | $12.50 | $30.00 |
| Terra | $2.00 | $0.20 | $2.50 | $5.00 | $12.00 |
| Luna | $0.20 | $0.02 | $0.25 | $0.50 | $1.20 |

الطلبات التي تتجاوز 272K رمز إدخال تكلّف أكثر: Sol بسعر $10.00 للإدخال و$45.00 للإخراج، وTerra بسعر $4.00 و$18.00، وLuna بسعر $0.40 و$1.80، مع تحجيم أسعار التخزين المؤقت بالطريقة نفسها. حتى 30 نوفمبر 2026، يُطبَّق السعر الترويجي لـ Sol من OpenAI: $4.00 للإدخال و$20.00 للإخراج حتى 272K رمز. راجع صفحة النموذج للاطلاع على الأسعار الحالية في الفئات والمزوّدين الآخرين.

تكلّف القراءة من ذاكرة التخزين المؤقت 10% من سعر الإدخال، والكتابة لمدة 30 دقيقة 1.25×، والكتابة لمدة 12 ساعة 2.5×. يُحتسب كل رمز إدخال بسعر واحد فقط من هذه الأسعار. يحتسب الاستخدام القراءات والكتابات في ذاكرة التخزين المؤقت ضمن `input_tokens` (`prompt_tokens` في Chat Completions) ويبلغ عن الكتابات في `cache_write_tokens`؛ راجع [حقول الاستخدام والتسعير](../guides/prompt-caching.mdx#usage-and-pricing-fields).

## التخزين المؤقت للسياق المتكرر

ضع الجزء الثابت من المطالبة في كتلة قابلة للتخزين المؤقت، واترك النص الخاص بالطلب بعدها:

```json
{
  "model": "openai/gpt-5.6-sol",
  "input": [
    {
      "role": "user",
      "content": [
        {
          "type": "input_text",
          "text": "Stable policy document...",
          "prompt_cache_breakpoint": { "mode": "explicit" }
        },
        {
          "type": "input_text",
          "text": "Apply the policy to this new customer request."
        }
      ]
    }
  ],
  "prompt_cache_options": { "mode": "explicit", "ttl": "30m" }
}
```

- يخزّن `prompt_cache_breakpoint` مؤقتًا كل شيء حتى كتلته وما يشملها. في الوضع `explicit` لا تخزّن OpenAI مؤقتًا إلا نقاط التوقف التي تضعها.
- تعمل أيضًا كتلة `cache_control` مثل `{"type": "ephemeral"}`؛ إذ يرسلها Phaseo إلى GPT-5.6 بوصفها `prompt_cache_breakpoint`. وتصل أي من العلامتين إلى Claude كنقطة توقف للتخزين المؤقت، لذا يظل الاحتياط إلى Claude يستفيد من التخزين المؤقت.
- قيمة `ttl` هي `30m` (الافتراضية) أو `12h`. راجع [التخزين المؤقت لمدة 12 ساعة على OpenAI](../guides/prompt-caching.mdx#12-hour-cache-on-openai) لمعرفة المسارات التي تقبلها، و[الاحتفاظ والخيارات في OpenAI](../guides/prompt-caching.mdx#openai-retention-and-options) للحقول الأخرى.

## ما الذي يجب اختباره

- **الاستدلال وجودة المخرجات:** كل فئة عند مستويات الجهد التي ستتيحها، بما في ذلك `max` حيث تأتي الجودة أولًا؛ والوضع القياسي مقابل `reasoning.mode: "pro"` في المهام الصعبة؛ ومعدل نجاح المخطط وجودة استدعاءات الأدوات عند كل مستوى.
- **التكلفة وزمن الاستجابة:** زمن الاستجابة عند كل مستوى جهد، ونمو رموز الإخراج مقارنة بخط الأساس الحالي لديك، ومزيج القراءات والكتابات في ذاكرة التخزين المؤقت في المطالبات المتكررة، والتكلفة لكل مهمة ناجحة بدلًا من السعر لكل رمز.

## النشر

1. أبقِ نموذج GPT-5 السابق لديك كنموذج احتياطي في `models`.
2. أبقِ `max` خلف علامة إعداد أو [إعداد مسبق](../guides/presets) حتى يثبت جدواه على مطالبات شبيهة بالإنتاج.
3. راقب حجم الكتابة في ذاكرة التخزين المؤقت بشكل منفصل عن القراءات منها.
4. لا تجعل GPT-5.6 النموذج الافتراضي إلا بعد أن تؤكد تقييماتك نجاح المهام والتكلفة وزمن الاستجابة.
