غيّر النموذج إلى `mistral/mistral-small-4` وقرّر لكل مسار ما إذا كان الاستدلال مفعّلًا. لدى Mistral Small 4 وضعا استدلال، متوقف ومرتفع، ويطابق Phaseo كل قيمة جهد مع أحدهما.

```json
{
  "model": "mistral/mistral-small-4",
  "messages": [
    { "role": "user", "content": "Why is fast inference important?" }
  ],
  "reasoning": { "effort": "high" }
}
```

## تفعيل الاستدلال أو إيقافه

يكون الاستدلال متوقفًا ما لم يطلبه الطلب. على API الخاصة بـ Mistral، يرسل Phaseo `reasoning_effort` على النحو التالي:

| الطلب | ما يُرسل إلى Mistral |
| --- | --- |
| لا يوجد إعداد استدلال | `reasoning_effort: "none"` |
| `reasoning.effort: "none"` أو `reasoning.enabled: false` | `reasoning_effort: "none"` |
| أي قيمة أخرى لـ `reasoning.effort`، أو `reasoning.enabled: true` | `reasoning_effort: "high"` |

تكون الأولوية لـ `reasoning_effort` المسطّح في الطلب على `reasoning.effort`. استخدم `none` للمسارات الخفيفة و`high` للاستدلال العميق؛ إذ يتصرف `low` و`medium` تمامًا مثل `high`.

## قراءة الإجابة والاستدلال

قد تعيد Mistral كتل محتوى مختلطة، مثل `thinking` تليها `text`. يقسّمها Phaseo إلى حقول بنمط OpenAI، لذا تستمر الشيفرة اللاحقة التي تقرأ Chat Completions في العمل:

- الإجابة موجودة في `choices[0].message.content`؛
- نص الاستدلال موجود في `choices[0].message.reasoning_content` و`reasoning_details`.

## النشر

1. غيّر معرّف النموذج من Mistral Small 3.2 إلى `mistral/mistral-small-4`.
2. اختبر الاستدلال باستخدام `none` و`high` فقط.
3. أعد تشغيل اختبارات جودة المخرجات والمخطط على المسارات التي تستخدم `high`.
4. قارن زمن الاستجابة والتكلفة لـ `none` و`high` قبل التحويل الكامل.
