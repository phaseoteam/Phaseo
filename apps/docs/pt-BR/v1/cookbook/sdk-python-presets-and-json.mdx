Chame uma predefinição do painel a partir do Python com um JSON Schema, depois valide a resposta e registre os IDs de que você precisa para depurá-la. No fim, você tem um script que envia `"model": "@release-summary"`, recebe `{"summary": ..., "risk_level": ...}` e imprime os detalhes de provedor e de plugin dessa solicitação.

O script fica pronto para produção depois que você substituir a predefinição e o schema pelos seus. Mantenha a etapa de validação: o reparo corrige a sintaxe, não o conteúdo.

## Crie

<Steps>
<Step title="Crie a predefinição">

Em **Configurações → Predefinições**, crie `release-summary` com o prompt de sistema, o modelo ou os modelos permitidos, as preferências de provedor, as configurações de raciocínio e a `temperature` que todos os chamadores devem compartilhar. Assim, o código Python só envia o que varia. [Predefinições](../guides/presets) explica como a predefinição se combina com a solicitação.

</Step>
<Step title="Instale o SDK">

```bash
pip install phaseo
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="Escreva o script">

```python release_summary.py
import json
import os

from phaseo import Phaseo

# Create one client and reuse it.
gateway = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

SCHEMA = {
    "type": "object",
    "properties": {
        "summary": {"type": "string"},
        "risk_level": {"type": "string", "enum": ["low", "medium", "high"]},
    },
    "required": ["summary", "risk_level"],
    "additionalProperties": False,
}


def output_text(response: dict) -> str:
    return "".join(
        part.get("text", "")
        for item in response.get("output", [])
        if item.get("type") == "message"
        for part in item.get("content", [])
        if part.get("type") == "output_text"
    )


def validate(payload: dict) -> dict:
    if set(payload) != {"summary", "risk_level"}:
        raise ValueError(f"unexpected keys: {sorted(payload)}")
    if not isinstance(payload["summary"], str) or not payload["summary"]:
        raise ValueError("summary must be a non-empty string")
    if payload["risk_level"] not in ("low", "medium", "high"):
        raise ValueError("risk_level must be low, medium or high")
    return payload


response = gateway.generate_response(
    {
        "model": "@release-summary",
        "input": "Summarize the last 24 hours of deployment activity.",
        "text": {
            "format": {
                "type": "json_schema",
                "name": "release_summary",
                "strict": True,
                "schema": SCHEMA,
            }
        },
        "plugins": [{"id": "response-healing"}],
        "meta": True,
    }
)

if response.get("status") != "completed":
    raise RuntimeError(f"response {response.get('id')} ended as {response.get('status')}")

payload = validate(json.loads(output_text(response)))
meta = response.get("meta", {})

print("response_id:", response.get("id"))
print("model:", response.get("model"))
print("selected_provider:", meta.get("routing", {}).get("selected_provider"))
print("plugin_executions:", meta.get("plugin_executions"))
print(payload)
```

| Campo | Função |
| --- | --- |
| `"model": "@release-summary"` | Usa a predefinição. Não existe um campo `preset` separado. |
| `text.format` | Pede este JSON Schema. No Chat Completions, ele vai em `response_format`; veja [Saídas estruturadas](../guides/structured-outputs). |
| `plugins` | Repara JSON quase válido; veja [reparo de respostas](./response-healing-for-structured-json). |
| `meta: true` | Adiciona `meta.routing` e `meta.plugin_executions` à resposta. |

</Step>
<Step title="Execute">

```bash
python release_summary.py
```

</Step>
</Steps>

## Confira se funcionou

O script imprime o ID da resposta, o modelo e o provedor que responderam, o registro do plugin e um dict com `summary` e um dos valores `low`, `medium` ou `high`. Procure o ID da resposta em **Configurações → Uso → Registros** para ver a mesma solicitação com os detalhes de roteamento.

Um modelo fora dos modelos permitidos da predefinição falha com `validation_error` (palavra-chave `preset_model_not_allowed`). Um `ValueError` vindo de `validate()` significa que o JSON foi analisado, mas o conteúdo estava errado: restrinja o schema ou o prompt em vez de adicionar novas tentativas.

## Depure antes de substituir

Se uma solicitação for roteada de um jeito diferente do esperado, abra-a nos registros, leia **Observabilidade do roteamento** e o registro do plugin, e só mude a predefinição quando os registros mostrarem o que aconteceu. Acumular substituições inline em uma solicitação acaba com o propósito da predefinição; se um chamador realmente precisa de outro comportamento, dê a ele uma predefinição própria.
