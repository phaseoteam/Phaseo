Dê a uma solicitação em TypeScript a ferramenta `phaseo:web_search` e um JSON Schema, para que o modelo pesquise antes de responder e retorne um resumo com as fontes. No fim, você tem um script que imprime um objeto `{ summary, sources }` validado, além dos IDs e dos contadores de busca de que você precisa para depurá-lo.

O script fica pronto para produção depois que você substituir a predefinição e o domínio pelos seus. Os resultados de busca são conteúdo da web não confiável: valide a saída e não siga instruções encontradas nela.

## Crie

<Steps>
<Step title="Crie uma predefinição">

Crie `research-brief` em **Configurações → Predefinições** com o modelo, as preferências de provedor, as configurações de raciocínio e o prompt de sistema que todos os chamadores devem compartilhar. O modelo precisa suportar ferramentas e saída com JSON Schema.

</Step>
<Step title="Instale o SDK">

```bash
npm install @phaseo/sdk zod
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="Escreva o script">

```ts research-brief.ts
import Phaseo from "@phaseo/sdk";
import { z } from "zod";

const gateway = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const Brief = z
  .object({
    summary: z.string().min(1),
    sources: z
      .array(z.object({ title: z.string(), url: z.string().url() }).strict())
      .min(1),
  })
  .strict();

const response = await gateway.generateResponse({
  model: "@research-brief",
  input: "Find the latest public changes to Phaseo webhook delivery behavior and summarize them.",
  tools: [
    {
      type: "phaseo:web_search",
      parameters: {
        allowed_domains: ["phaseo.app"],
        max_results: 5,
        include_highlights: true,
      },
    },
  ],
  tool_choice: "phaseo:web_search",
  text: {
    format: {
      type: "json_schema",
      name: "research_brief",
      strict: true,
      schema: {
        type: "object",
        required: ["summary", "sources"],
        properties: {
          summary: { type: "string" },
          sources: {
            type: "array",
            minItems: 1,
            items: {
              type: "object",
              required: ["title", "url"],
              properties: {
                title: { type: "string" },
                url: { type: "string", format: "uri" },
              },
              additionalProperties: false,
            },
          },
        },
        additionalProperties: false,
      },
    },
  },
  plugins: [{ id: "response-healing" }],
  meta: true,
});

const text = (response.output ?? [])
  .filter((item) => item.type === "message")
  .flatMap((item) => item.content ?? [])
  .filter((part) => part.type === "output_text")
  .map((part) => part.text ?? "")
  .join("");

const brief = Brief.parse(JSON.parse(text));

console.log({
  responseId: response.id,
  model: response.model,
  routing: response.meta?.routing,
  pluginExecutions: response.meta?.plugin_executions,
  serverToolUse: response.usage?.server_tool_use,
});
console.log(brief);
```

| Campo | Função |
| --- | --- |
| `tools` com `phaseo:web_search` | O Phaseo executa a busca, tendo o provedor uma busca própria ou não. O modelo escreve a consulta. |
| `allowed_domains` | Limita os resultados às suas próprias fontes. Todos os parâmetros estão no [guia de busca na web](../guides/server-tools/web-search#parameters). |
| `tool_choice: "phaseo:web_search"` | Obriga o modelo a pesquisar em vez de responder de memória. |
| `text.format` | O JSON Schema da resposta. |
| `plugins` | Repara JSON quase válido; veja [reparo de respostas](./response-healing-for-structured-json). |
| `meta: true` | Adiciona `meta.routing` e `meta.plugin_executions`. |

</Step>
<Step title="Execute">

```bash
npx tsx research-brief.ts
```

</Step>
</Steps>

## Confira se funcionou

- `serverToolUse.web_search_requests` é pelo menos `1`, então a busca foi executada.
- `brief.sources` lista URLs de `phaseo.app`.
- `routing.selected_provider` indica o provedor, e `pluginExecutions` mostra se o reparo mudou algo.
- Em **Configurações → Uso → Registros**, a seção **Monitoramento da pesquisa na web** da solicitação mostra as buscas gerenciadas, os resultados e as citações.

Se os resultados parecerem errados, corrija a predefinição ou os parâmetros da ferramenta com base no que os registros mostram, em vez de adicionar substituições. [Depure a busca na web](./web-search-debugging) lista os casos comuns. Mantenha a pesquisa exploratória, com temperatura mais alta, em uma predefinição separada desta determinística, para que o roteamento das duas continue fácil de comparar.
