<Warning>
O cache de respostas ainda não está disponível. Uma predefinição aceita `response_caching.enabled` e `response_caching.ttl_seconds`, mas hoje o Gateway não armazena nem reproduz nenhuma resposta, então toda solicitação vai para um provedor e é cobrada normalmente.
</Warning>

Para reduzir agora o custo e a latência de solicitações repetidas, use o [cache de prompts](../guides/prompt-caching): os provedores reutilizam um prefixo de prompt longo e estável e cobram a parte em cache a uma taxa menor. O Phaseo mantém uma conversa no provedor que guarda o cache dela; veja [Afinidade de provedor](../guides/prompt-caching#provider-affinity).

## Prepare uma predefinição para o cache

Estes hábitos ajudam o cache de prompts hoje e vão importar para o cache de respostas quando ele for lançado, porque os dois dependem de as solicitações continuarem idênticas:

| Mantenha estável | Por quê |
| --- | --- |
| O texto do prompt de sistema | Qualquer mudança cria uma nova entrada no cache |
| O modelo, as opções de provedor e as configurações de raciocínio | Fazem parte do que torna duas solicitações iguais |
| `temperature` e outros parâmetros | Idem |
| O formato da resposta, as ferramentas e a escolha de ferramenta | Idem |

Coloque tudo isso em uma [predefinição](../guides/presets) para que todos os chamadores enviem a mesma solicitação, e dê aos chamadores exploratórios ou com temperatura alta uma predefinição própria, para que não se misturem com o tráfego que pode ir para o cache.

## Quando não usar cache

Não planeje usar cache em prompts que dependem de estado externo em tempo real, em respostas específicas de um usuário cujo contexto muda rápido, em solicitações com saída de ferramenta volátil nem em gerações em que você quer uma resposta nova a cada vez.
