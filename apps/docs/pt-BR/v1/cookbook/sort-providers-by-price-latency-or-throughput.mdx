Use esta receita quando o modelo permanecer o mesmo, mas você quiser que o gateway classifique as ofertas dos provedores de outra forma para uma solicitação.

## Objetivo

- Priorize o provedor mais barato para uma solicitação.
- Priorize o provedor com menor latência para fluxos interativos.
- Priorize o provedor com maior throughput para geração em lote.

## 1. Adicione `provider.sort` à solicitação

Para solicitações de texto, defina a classificação desejada diretamente no objeto `provider`.

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "google/gemini-3.1-flash-lite",
    "input": "Give me one release-note bullet for the last deploy.",
    "provider": {
      "sort": "price"
    }
  }'
```

```typescript TypeScript SDK
import Phaseo from "@phaseo/sdk";

const response = await client.generateResponse({

  input: "Give me one release-note bullet for the last deploy.",
  provider: {
    sort: "price",
  },

```

As classificações de roteamento disponíveis neste fluxo são:

- `price`
- `latency`
- `throughput`

## 2. Escolha a classificação adequada para a carga de trabalho

Use:

- `price` quando o custo importa mais que a latência de cauda
- `latency` para chat, copilotos e ferramentas com intervenção humana
- `throughput` para geração em grande volume ou preenchimentos retroativos

## 3. Entenda o que o gateway compara

Ao definir uma classificação explícita por solicitação, o gateway classifica os candidatos de forma determinística, em vez de usar a combinação ponderada e equilibrada padrão.

Para modelos de texto:

- `price` compara uma base de preços comum entre os provedores elegíveis
- se houver medidores de texto compartilhados, o gateway prioriza aqueles que correspondem a `input_text_tokens` e `output_text_tokens`
- `latency` usa os dados de latência mais recentes dos provedores
- `throughput` usa as medições de throughput mais recentes

## 4. Mantenha um conjunto realista de provedores

A classificação funciona melhor quando você restringe o conjunto de candidatos, se necessário.

Por exemplo, classifique apenas um conjunto aprovado de provedores:

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "google/gemini-3.1-flash-lite",
    "input": "Summarize the incident in one sentence.",
    "provider": {
      "only": ["google-vertex", "google-vertex-eu"],
      "sort": "latency"
    }
  }'
```

## 5. Verifique o resultado da classificação

Ao depurar, inspecione a solicitação em **Gateway -> Uso** e procure:

- provedores considerados
- provedores classificados
- os fatores de pontuação do roteamento para preço, latência ou throughput

Assim, fica fácil confirmar se o gateway classificou os resultados como esperado.
