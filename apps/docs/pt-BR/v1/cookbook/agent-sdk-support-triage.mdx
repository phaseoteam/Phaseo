Crie um agente de triagem em TypeScript cujo modelo, prompt e regras de provedor vêm de uma predefinição do painel, para que o código cuide apenas do fluxo de trabalho. Ao final, ele retorna uma decisão de triagem em JSON estrito, pausa os casos que precisam de uma pessoa, repete chamadas ao modelo um número limitado de vezes e registra as falhas do gateway com os IDs de que você precisa para encontrá-las.

O script está pronto para produção depois que a predefinição existir e você armazenar as execuções pausadas, como no [loop persistente](./agent-sdk-durable-loop). Uma versão empacotada está em `packages/sdk/agent-sdk-ts/examples/support-triage-agent.ts`.

## Crie o agente

<Steps>
<Step title="Crie a predefinição">

Em **Configurações → Predefinições**, crie `support-triage` com o modelo roteado, as preferências de provedor, o prompt de sistema de suporte e parâmetros de decodificação estáveis. O modelo precisa suportar saída com JSON Schema. [Predefinições](../guides/presets) explica como uma predefinição se combina com cada solicitação.

</Step>
<Step title="Instale">

```bash
npm install @phaseo/agent-sdk zod
export PHASEO_API_KEY="phaseo_v1_sk_..."
```

</Step>
<Step title="Escreva o agente">

```ts triage-agent.ts
import { z } from "zod";
import { AgentGatewayError, createAgent, createGatewayAgentClient } from "@phaseo/agent-sdk";

const SupportTriageDecision = z
  .object({
    queue: z.enum(["billing", "reliability", "product", "security"]),
    severity: z.enum(["low", "medium", "high"]),
    needsHumanReview: z.boolean(),
    summary: z.string().min(1),
  })
  .strict();
type SupportTriageDecision = z.infer<typeof SupportTriageDecision>;

// `preset` vira o modelo `@support-triage` em todos os turnos.
const supportTriageAgent = createAgent<string, SupportTriageDecision>({
  id: "support-triage-agent",
  preset: "support-triage",
  maxSteps: 3,
  parseOutput: (text) => JSON.parse(text),
  outputSchema: SupportTriageDecision,
  humanReview: ({ parsedOutput }) =>
    parsedOutput?.needsHumanReview
      ? { reason: "support_triage_review_required", payload: parsedOutput }
      : null,
});

const client = createGatewayAgentClient({
  clientOptions: { apiKey: process.env.PHASEO_API_KEY! },
  responseFormat: {
    type: "json_schema",
    name: "support_triage_decision",
    schema: {
      type: "object",
      properties: {
        queue: { type: "string", enum: ["billing", "reliability", "product", "security"] },
        severity: { type: "string", enum: ["low", "medium", "high"] },
        needsHumanReview: { type: "boolean" },
        summary: { type: "string" },
      },
      required: ["queue", "severity", "needsHumanReview", "summary"],
      additionalProperties: false,
    },
  },
  plugins: [{ id: "response-healing", mode: "strict" }],
});

try {
  const result = await supportTriageAgent.run({
    input: "Customer says webhook deliveries failed overnight and asks whether data was lost.",
    client,
    modelRetry: { maxRetries: 2, backoffMs: 250 },
    onEvent(event) {
      if (event.type === "model.retrying") console.log("retrying", event.attempt, event.error);
    },
  });

  if (result.run.status === "waiting_for_human") {
    // Guarde `result` e continue depois que um atendente o revisar.
    console.log("Needs review:", result.run.pause?.payload);
  } else {
    console.log(result.output);
  }
} catch (error) {
  if (error instanceof AgentGatewayError) {
    console.error("Gateway request failed", {
      status: error.status,
      requestId: error.requestId,
      generationId: error.generationId,
      reason: error.reason,
      providerFailureDiagnostics: error.providerFailureDiagnostics,
      routingDiagnostics: error.routingDiagnostics,
    });
  }
  throw error;
}
```

</Step>
<Step title="Execute">

```bash
npx tsx triage-agent.ts
```

</Step>
</Steps>

Para concluir um caso pausado, continue-o com a decisão do revisor:

```ts
const continued = await supportTriageAgent.continueRun({
  run: storedResult,
  client,
  humanInput: "Approved. Finalize the triage decision.",
});
```

## Verifique se funcionou

Execute um ticket rotineiro e um arriscado e depois confira:

- Em **Configurações → Uso → Registros**, o modelo da solicitação mostra que a predefinição foi usada.
- O caso arriscado termina em `waiting_for_human`, com a decisão em `pause.payload`.
- Uma chamada ao modelo repetida fica registrada na etapa como `modelAttempts`, e cada nova tentativa registra `model.retrying`.
- Uma solicitação bloqueada é registrada com seu `requestId` e `reason`, e a mesma solicitação nos registros mostra o motivo.

## Mantenha as falhas do gateway visíveis

Não engula erros dentro dos callbacks do agente. Capture `AgentGatewayError` na borda, registre os IDs e lance o erro de novo. Quando uma execução falha, o estado salvo dela guarda os mesmos detalhes em `run.errorDetails` e `steps[n].errorDetails`, para que um job de recuperação posterior possa lê-los depois que a exceção já tiver passado.

Essas falhas vêm da política do Gateway, não do agente, então a solicitação nos registros é onde você deve olhar:

| Falha | Onde aparece |
| --- | --- |
| Um guardrail bloqueia a solicitação | A seção **Guardrail enforcement** da solicitação |
| Os modelos permitidos da predefinição rejeitam o modelo | `validation_error` com a palavra-chave `preset_model_not_allowed` |
| Credenciais ou ativação de provedores não deixam nenhum provedor disponível | `providerFailureDiagnostics` e **Routing observability** |
| A recuperação não consegue produzir JSON válido pelo esquema | O registro de plugins e, em seguida, `AgentSchemaValidationError` vindo de `outputSchema` |
