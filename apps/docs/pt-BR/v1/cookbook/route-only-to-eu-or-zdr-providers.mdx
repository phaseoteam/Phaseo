icon: "globe"
description: "Aplique requisitos de residência e de retenção zero de dados no nível da solicitação para que um modelo só seja roteado para ofertas de provedores em conformidade."
---

Adicione requisitos de residência e de <Tooltip tip="Retenção zero de dados: o provedor não guarda prompts nem saídas.">ZDR</Tooltip> ao objeto `provider` de uma solicitação, e o Phaseo remove todas as ofertas de provedor que não os atendem antes de classificar as restantes. No fim, um fluxo de trabalho roda só em provedores na UE ou compatíveis com ZDR, sem mudar a política de todo o espaço de trabalho.

A solicitação está pronta para produção. Se nenhum provedor do modelo atender a todos os requisitos, a solicitação falha antes de qualquer provedor ser chamado, então confira a disponibilidade primeiro.

| Campo | Mantém só os provedores que |
| --- | --- |
| `required_execution_region: "eu"` | Executam o modelo na UE |
| `required_data_region: "eu"` | Tratam os dados de prompt e de resposta na UE |
| `require_zero_data_retention: true` | Atendem aos requisitos de retenção zero de dados |

## Envie uma solicitação restrita

<Steps>
<Step title="Confira se um provedor se qualifica">

Na página do modelo, os cards de provedor mostram ofertas regionais como **OpenAI EU** ou **Google Vertex EU**, o suporte a ZDR e as notas e fontes sobre a política de dados de cada provedor. Para a UE, você também pode listar o que o Gateway da UE atende:

```bash
curl https://eu.api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

</Step>
<Step title="Adicione só os requisitos de que você precisa">

Cada requisito reduz o conjunto, então a solicitação pode ser roteada para uma oferta regional mais cara ou ficar sem nenhum provedor. Envie só o que a sua política exige:

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5.6-luna",
    "input": "Summarize the ticket in one line.",
    "provider": {
      "required_execution_region": "eu",
      "required_data_region": "eu"
    },
    "meta": true
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "openai/gpt-5.6-luna",
  input: "Summarize the ticket in one line.",
  provider: {
    required_execution_region: "eu",
    required_data_region: "eu",
  },
  meta: true,
});

console.log(response.meta?.routing);
```

```python Python
import os

from phaseo import Phaseo

client = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

response = client.generate_response(
    {
        "model": "openai/gpt-5.6-luna",
        "input": "Summarize the ticket in one line.",
        "provider": {
            "required_execution_region": "eu",
            "required_data_region": "eu",
        },
        "meta": True,
    }
)

print(response["meta"]["routing"]["selected_provider"])
```
</CodeGroup>

Para exigir também ZDR, adicione `"require_zero_data_retention": true`. Com os três, o modelo precisa de pelo menos um provedor na UE que também atenda ao ZDR.

</Step>
<Step title="Veja onde foi executada">

`meta.routing.selected_provider` indica o provedor que atendeu a solicitação, por exemplo `openai-eu`. A solicitação em **Configurações → Uso → Registros** registra as regiões exigidas e o provedor selecionado.

</Step>
</Steps>

## Escolha entre campos da solicitação, o Gateway da UE ou as configurações do espaço de trabalho

| Use | Quando |
| --- | --- |
| Estes campos da solicitação em `api.phaseo.app` | A regra vale para um fluxo de trabalho, um cliente ou uma solicitação. Todos os endpoints e recursos continuam disponíveis. |
| [`eu.api.phaseo.app`](../guides/regional-routing) | Todas as solicitações de texto de um serviço precisam ficar na UE. O hostname aplica a região e também rejeita entrada de mídia, ferramentas de servidor do Phaseo e ferramentas hospedadas pelo provedor. Enviar ali um `required_execution_region` ou `required_data_region` de outra região retorna `400 validation_error` com o motivo `deployment_region_conflict`. |
| **Configurações → Privacidade** | A regra vale para todas as solicitações do espaço de trabalho. |

O roteamento regional restringe quais provedores tratam a chamada ao modelo. Ele ainda não é uma garantia de residência de dados de ponta a ponta; [O que fica fora da região](../guides/regional-routing#what-stays-outside-the-region) lista os sistemas compartilhados. Para restringir provedores sem uma regra de residência, veja [Fixe ou ignore provedores](./pin-or-ignore-providers-per-request).
