title: "Fixe ou ignore provedores por solicitação"
icon: "pin"
description: "Use os controles de provedor no nível da solicitação para preferir uma ordem de provedores, restringir o conjunto ou tirar um provedor da disputa."
---

Adicione um objeto `provider` a uma solicitação para mudar quais provedores a atendem, sem mexer nos padrões do espaço de trabalho nem nas predefinições. No fim, você consegue preferir uma ordem, manter uma solicitação dentro de uma lista de permitidos ou pular um provedor, e ver na resposta qual provedor respondeu.

Estes formatos de solicitação estão prontos para produção. Os slugs de provedor são exemplos reais; confira na página do modelo quais provedores atendem o seu modelo.

| Campo | Função | Exemplo |
| --- | --- | --- |
| `order` | Tenta estes provedores primeiro e depois o restante do conjunto elegível | `["anthropic-us", "anthropic"]` |
| `only` | Mantém a solicitação dentro desta lista | `["openai", "openai-eu"]` |
| `ignore` | Remove estes provedores nesta solicitação | `["novita"]` |
| `sort` | Classifica o que sobrou por `price`, `latency` ou `throughput` | `"price"` |

Para usar exatamente um provedor e desativar o fallback entre provedores, coloque-o na frente do ID do modelo: veja [Fixe um provedor](../guides/routing-and-fallbacks#pin-one-provider).

## Tente os provedores em uma ordem definida

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-sonnet-5.5",
    "input": "Write a concise launch summary.",
    "provider": {
      "order": ["anthropic-us", "anthropic"]
    },
    "meta": true
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "anthropic/claude-sonnet-5.5",
  input: "Write a concise launch summary.",
  provider: {
    order: ["anthropic-us", "anthropic"],
  },
  meta: true,
});

console.log(response.meta?.routing); // { selected_provider: "anthropic-us", ... }
```

```python Python
import os

from phaseo import Phaseo

client = Phaseo(api_key=os.environ["PHASEO_API_KEY"])

response = client.generate_response(
    {
        "model": "anthropic/claude-sonnet-5.5",
        "input": "Write a concise launch summary.",
        "provider": {
            "order": ["anthropic-us", "anthropic"],
        },
        "meta": True,
    }
)

print(response["meta"]["routing"]["selected_provider"])
```
</CodeGroup>

`meta: true` adiciona `meta.routing.selected_provider` à resposta, para você conferir o resultado sem abrir os registros.

## Mantenha uma solicitação dentro de uma lista de permitidos

Envie `only` e, se quiser, `sort` para classificar dentro dessa lista:

```json
{
  "model": "openai/gpt-5.6-luna",
  "input": "Extract the action items.",
  "provider": {
    "only": ["openai", "openai-eu"],
    "sort": "price"
  }
}
```

Se nenhum dos provedores listados atender o modelo, a solicitação falha em vez de sair da lista.

## Pule um provedor

Envie `ignore` quando um provedor estiver degradado ou enquanto você testa outro caminho:

```json
{
  "model": "meta/llama-4-maverick",
  "input": "Summarize the transcript.",
  "provider": {
    "ignore": ["novita"]
  }
}
```

## Combine os campos

Use `only` para o conjunto, `order` para a preferência dentro dele e `sort` para o restante. Isto mantém a solicitação no Google Vertex, tenta primeiro a região da UE e depois classifica por latência:

```json
{
  "model": "anthropic/claude-sonnet-5.5",
  "input": "Summarize the incident in one sentence.",
  "provider": {
    "only": ["google-vertex", "google-vertex-eu"],
    "order": ["google-vertex-eu"],
    "sort": "latency"
  }
}
```

## Veja para onde ela foi

Abra a solicitação em **Configurações → Uso → Registros** e expanda **Observabilidade do roteamento**. Ali aparecem os provedores excluídos antes da classificação e o motivo, além dos candidatos classificados com as suas pontuações; [Explique uma decisão de roteamento](../guides/routing-and-fallbacks#explain-a-routing-decision) descreve cada campo.

Use regras no nível da solicitação para substituições temporárias, específicas de um chamador ou ligadas a um fluxo de usuário. Quando as mesmas regras aparecerem em vários serviços, leve-as para uma [predefinição](../guides/presets), onde elas também limitam quais provedores um fallback pode usar. Para comparar classificações, veja [Ordene provedores](./sort-providers-by-price-latency-or-throughput).
