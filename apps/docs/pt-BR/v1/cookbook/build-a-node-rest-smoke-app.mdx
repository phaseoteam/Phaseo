Execute um script Node.js sem dependências que chama o Phaseo com `fetch` simples, para ver cada solicitação e cada resposta. No fim, você tem um smoke test para rodar antes de uma implantação: ele verifica se a API está acessível, lista os modelos e envia uma solicitação para cada um dos endpoints Responses, Chat Completions e Embeddings.

O script é ilustrativo: ele mostra o status HTTP de cada chamada, mas sempre termina com `0`. Adicione a verificação do código de saída descrita em [Use como verificação de implantação](#use-it-as-a-deploy-check) antes de depender dele na CI.

Para que um agente de programação crie o mesmo script do zero, cole este prompt:

Create a script-based app that:

## O que o script chama

O exemplo é [examples/gateway-node-quickstart](https://github.com/phaseoteam/Phaseo/tree/main/examples/gateway-node-quickstart): um único arquivo, `index.mjs`, sem dependências.

| Modo | Chamadas | Consome créditos |
| --- | --- | --- |
| `npm run smoke` | `GET /v1/health`, `GET /v1/models` | Não |
| `npm run start` | As duas acima e, depois, `POST /v1/responses`, `POST /v1/chat/completions`, `POST /v1/embeddings` | Sim |

As chamadas de texto enviam `Return exactly: integration_ok` para `PHASEO_MODEL` (padrão `openai/gpt-5.6-sol`). A chamada de embeddings usa `google/gemini-embedding-2`.

## Execute

Você precisa do Node.js 18 ou mais recente, por causa do `fetch` nativo, e de uma chave de API do Phaseo.

<Steps>
<Step title="Crie o .env.local">

O script carrega o `.env.local` da pasta em que você o executa, sem nenhum pacote. O exemplo não tem `.env.example`, então crie o arquivo:

```bash .env.local
PHASEO_API_KEY=phaseo_v1_sk_...
# Optional
PHASEO_MODEL=openai/gpt-6-astra
PHASEO_BASE_URL=https://api.phaseo.app/v1
PHASEO_APP_TITLE=My smoke test
PHASEO_HTTP_REFERER=https://myapp.example
```

As variáveis já definidas no seu shell têm prioridade sobre o arquivo.

</Step>
<Step title="Execute o modo smoke">

```bash
cd examples/gateway-node-quickstart
npm run smoke
```

</Step>
<Step title="Execute o modo completo">

```bash
npm run start
```

</Step>
</Steps>

## Confira se funcionou

Cada chamada imprime um bloco como este:

```text
=== Health ===
HTTP 200
{ ... }
```

- `Health` e `Models` mostram `HTTP 200`, e `Models` lista pelo menos um modelo.
- Na execução completa, os blocos de Responses e Chat Completions contêm `integration_ok`.
- Com uma chave errada, os blocos de geração mostram `HTTP 401` e o corpo do erro, em vez de ocultá-lo.
- As solicitações aparecem em **Configurações → Uso → Registros**.

## Use como verificação de implantação

`request()` retorna `{ status, ok, payload }`, mas nada verifica `ok`. Adicione uma linha no início de `print()` para que o script termine com `1` quando alguma chamada falhar:

```js index.mjs
function print(title, result) {
  if (!result.ok) process.exitCode = 1;
  console.log(`\n=== ${title} ===`);
  // ...rest unchanged
}
```

Reduza o script às rotas que o seu serviço usa e passe para o [SDK de TypeScript](../sdk-reference/client/overview) quando preferir não montar os payloads manualmente.
