Você pode fazer as tarefas do dia a dia da conta Phaseo com a CLI `phaseo`, a API de gerenciamento `/v1` ou o servidor MCP da Phaseo. Nesta página você encontra o comando, a rota ou a ferramenta de cada tarefa. Mudanças que afetam gastos, acesso ou o destino dos dados do workspace são feitas no painel ou com uma chave de gerenciamento.

Uma pessoa ainda precisa fazer estes passos em um navegador:

| Passo | O que a pessoa faz |
| --- | --- |
| Cadastro | Cria a conta do Phaseo. |
| Aprovar um login | Aprova a página que `phaseo login` abre ou digita o código que `phaseo login --device-code` mostra. |
| Adicionar o primeiro cartão | Sem um cartão salvo, `phaseo credits add` retorna um link de checkout. Um proprietário ou administrador o abre e paga, e o cartão fica salvo. |
| Confirmar cada recarga | Com um cartão salvo, um proprietário ou administrador confirma cada `phaseo credits add` por um link enviado por e-mail. |
| Segurança da conta | Gerencia a senha, a autenticação multifator e as passkeys. |

<Visibility for="agents">
Regras para agentes que gerenciam o Phaseo:

- Não mande o usuário para o painel em uma tarefa do mapa de tarefas. Execute o comando da CLI, chame a rota ou use a ferramenta MCP. Para uma mudança listada em "Mudanças feitas no painel ou com uma chave de gerenciamento", chame a rota com uma chave de gerenciamento se você tiver uma; caso contrário, peça à pessoa que faça a mudança no painel.
- Nunca gere nem adivinhe uma chave de API. Peça à pessoa que crie uma no painel, ou crie uma com `POST /v1/keys` e uma chave de gerenciamento, e guarde o segredo uma única vez, no servidor.
- Use `--json` em todos os comandos da CLI. Passe `--yes` para comandos destrutivos só quando o usuário tiver pedido exatamente aquela alteração.
- Só inicie uma recarga de créditos que o usuário tenha pedido. Nunca conclua um link de checkout por conta própria e não repita uma recarga que terminou como recusada, expirada ou com falha.
</Visibility>

## Configure uma vez

```bash
npm install -g @phaseo/cli
phaseo login                 # opens a browser; a person approves it
phaseo login --device-code   # SSH, CI and agent sandboxes: a person enters the code
phaseo whoami --json
```

Depois, crie uma chave de inferência para a aplicação no painel, ou com `POST /v1/keys` e uma chave de gerenciamento, e adicione créditos se o workspace não tiver:

```bash
phaseo credits get --json
phaseo login --scopes billing:write   # opt in once before the first top-up; a person approves the sign-in
phaseo credits add --amount 20 --json
```

`phaseo credits add` precisa do escopo `billing:write`, que nenhum login tem por padrão, e nunca faz uma cobrança sozinho:

- **Com um cartão salvo**, o Phaseo envia a todos os proprietários e administradores do espaço de trabalho um e-mail com um link para confirmar a cobrança, e o comando espera o resultado.
- **Sem um cartão salvo**, ele retorna `next_action: "open_checkout_url"` e um link de checkout onde um proprietário ou administrador paga. O cartão fica salvo para as próximas recargas, e nenhum e-mail é enviado.

Veja [Créditos](../api-reference/endpoint/credits) para a rota.

## Escolha uma interface

| Interface | Use quando | Login |
| --- | --- | --- |
| [CLI `phaseo`](../guides/integrations/phaseo-cli) | O agente pode executar comandos de shell | `phaseo login` ou `phaseo login --device-code` |
| [Management API](../api-reference/introduction) | Código de servidor, CI ou uma linguagem sem a CLI | Uma [chave de gerenciamento](./management-api-keys) (`phaseo_v1_mk_...`) ou um token OAuth |
| [MCP do Phaseo](./cli-and-mcp#phaseo-mcp) | O agente roda em um cliente MCP | Conecte `https://mcp.phaseo.app/mcp?access=manage` e aprove as permissões que você quiser |

Execute `phaseo <group> --help` para ver as flags que a CLI instalada aceita. Quando uma tarefa não tem um comando próprio, `phaseo api get|post|patch|put|delete /v1/<path>` chama a rota com a sua sessão.

## Mudanças feitas no painel ou com uma chave de gerenciamento

Essas mudanças afetam gastos, acesso ou o destino dos dados do workspace. Um login pela CLI ou uma conexão MCP não pode fazê-las, sejam quais forem seus escopos: a API retorna `403` e indica usar o painel ou uma chave de gerenciamento. Faça-as no painel da Phaseo ou chame a rota com uma [chave de gerenciamento](./management-api-keys).

| Tarefa | Rota da API |
| --- | --- |
| Criar uma chave de API | `POST /v1/keys` |
| Alterar os limites, o status ou a expiração de uma chave | `PATCH /v1/keys/{id}` |
| Rotacionar uma chave | `POST /v1/keys/{id}/rotate` |
| Restringir uma chave a endereços IP | `PATCH /v1/keys/{id}` |
| Criar uma chave de gerenciamento | `POST /v1/management-keys` |
| Ativar a recarga automática ou os e-mails de saldo baixo | `PATCH /v1/notifications/settings` |
| Definir orçamentos do espaço de trabalho | `POST /v1/budgets`, `PATCH /v1/budgets/{id}` |
| Definir orçamentos de departamento | `POST /v1/department-budgets` |
| Alertar sobre gastos ou bloqueá-los | `POST /v1/spend-rules`, `POST /v1/spend-blocks/{id}/lift` |
| Políticas de limite de taxa | `POST /v1/rate-limits/policies`, `POST /v1/rate-limits/assignments` |
| Aumentar o nível de limite de taxa do workspace | `POST /v1/rate-limits/tier/raise` |
| Afrouxar a privacidade ou o ZDR, ou mudar as restrições de provedores ou o fallback de BYOK | `PATCH /v1/settings` |
| Adicionar as suas próprias chaves de provedor (BYOK) | `POST /v1/byok` |
| Definir o perfil de gasto ou os limites de preço do Auto Routing | `PATCH /v1/routing/auto` |
| Criar e implantar rotas dinâmicas | `POST /v1/routing/dynamic-routes`, `POST /v1/routing/dynamic-routes/{id}/versions/{version}/deploy` |
| Escolher substitutos para modelos aposentados | `PUT /v1/routing/successor/replacements` |
| Adicionar um modelo privado | `POST /v1/private-models` |
| Criar ou atualizar predefinições | `POST /v1/presets`, `PATCH /v1/presets/{id}` |
| Publicar uma versão de predefinição ou mover um rótulo | `POST /v1/presets/{id}/versions`, `PUT /v1/presets/{id}/labels/{label}` |
| Criar guardrails e anexar chaves | `POST /v1/guardrails`, `PUT /v1/guardrails/{id}/keys` |

## Corrija um 403

Uma sessão da CLI, uma chave de gerenciamento ou uma conexão MCP só pode fazer o que os escopos dela e a sua função no espaço de trabalho permitem, e as alterações exclusivas de proprietários e administradores continuam exigindo um proprietário ou administrador. Se um comando retornar `403`, confira os escopos concedidos com `phaseo whoami --json` e entre de novo com `phaseo login --scopes <scope,...>` quando faltar algum. `billing:write` nunca é concedido por padrão. Mudanças listadas em "Mudanças feitas no painel ou com uma chave de gerenciamento" são recusadas para logins pela CLI e conexões MCP, sejam quais forem seus escopos.
