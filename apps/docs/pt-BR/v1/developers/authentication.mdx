title: "Autenticação"
description: "Use chaves de API para autenticar cada solicitação ao Phaseo Gateway."
icon: "key-round"
---

Crie uma chave no [painel](https://phaseo.app/settings/keys) ou com `POST /v1/keys` e uma chave de gerenciamento, guarde-a no seu servidor e envie-a como token bearer em cada solicitação ao Gateway. Agentes devem usar a CLI; veja [Gerencie o Phaseo a partir de um agente](./manage-from-an-agent).

```http
Authorization: Bearer phaseo_v1_sk_<kid>_<secret>
```

Defina o cabeçalho uma vez no seu cliente. Por exemplo, com `fetch`:

```ts
const response = await fetch("https://api.phaseo.app/v1/chat/completions", {
	method: "POST",
	headers: {
		Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
		"Content-Type": "application/json",
	},
	body: JSON.stringify({
		model: "openai/gpt-6-astra",
		messages: [
			{ role: "system", content: "You are a helpful assistant." },
			{ role: "user", content: "Summarize the drawbacks to AI." },
		],
	}),
});
```

<Note>
Você pode chamar modelos `:free` sem depositar créditos. Os modelos pagos precisam de saldo disponível na carteira.
</Note>

## Escolha uma credencial

| Credencial | Formato | Use para |
| --- | --- | --- |
| Chave de API do Gateway | `phaseo_v1_sk_<kid>_<secret>` | Os endpoints de modelos, provedores e geração disponíveis para o seu espaço de trabalho. |
| [Chave de API de gerenciamento](./management-api-keys.mdx) | `phaseo_v1_mk_<kid>_<secret>` | APIs de administração. |
| [Carga de trabalho confiável](./trusted-workloads.mdx) (beta) | Um token OIDC de curta duração fornecido pela plataforma | Implantações e jobs de CI no Vercel, GitHub Actions, GitLab, Google Cloud, Buildkite, CircleCI, AWS ou no seu próprio emissor OIDC, sem nenhuma chave armazenada. |

Trate as chaves como senhas: mantenha-as fora do código no cliente e de repositórios públicos.

## Lide com as chaves com segurança

- **Uma chave por aplicativo e ambiente**, para poder rotacionar uma sem afetar outros serviços.
- **Guarde as chaves em um gerenciador de segredos**, que as mantém fora dos logs e do rastreamento de erros.
- **Acompanhe o uso por chave** no painel para identificar anomalias.
- **Exclua as chaves que você não usa mais.**

Para rotacionar uma chave, migre o seu aplicativo para a substituta antes de invalidar a antiga. Veja o [endpoint de rotação de chaves](../api-reference/endpoint/keys-rotate.mdx).

## Corrija erros de autenticação

| Status | Causa | O que fazer |
| --- | --- | --- |
| `401` | A chave está ausente, é inválida ou pertence a um espaço de trabalho desativado. O `reason` no corpo diz qual. | Confira o cabeçalho e a chave. |
| `403` | A chave é válida, mas não pode usar o provedor ou o modelo solicitado. | Confira os guardrails da chave e as configurações de provedor do espaço de trabalho. |
| `429` | A chave ou o espaço de trabalho atingiu um limite. | Veja [Limites de taxa](../api-reference/limits.mdx). |
| `5xx` | O Phaseo ou o provedor falhou. | Tente de novo com backoff exponencial e fale com o [suporte](https://phaseo.app/help) se persistir. |

Veja [Erros e depuração](../api-reference/errors.mdx) para todos os códigos de erro.
