Consulte a [página de status](https://status.phaseo.app) e `GET /v1/health` para saber se o Phaseo está saudável, `GET /v1/models` para saber se um modelo pode ser roteado agora e o seu próprio teste para saber se uma rota atende à sua meta de confiabilidade.

## Verifique a saúde atual do serviço

1. Abra a [página de status do Phaseo](https://status.phaseo.app) para ver os incidentes atuais e o histórico de incidentes.
2. Chame `GET /v1/health` para uma verificação mínima de saúde do Gateway.
3. Se uma única solicitação falhou, guarde o ID dela e inspecione o registro de atividade ou de geração antes de presumir que o serviço inteiro está fora do ar.

```bash
curl https://api.phaseo.app/v1/health
```

```json
{
  "status": "ok"
}
```

<Note>
A página de status pública informa a saúde do serviço. No momento, o Phaseo não oferece um SLA público contratual de disponibilidade.
</Note>

## Confirme se um modelo pode ser roteado

O catálogo do Phaseo lista mais modelos do que o Gateway consegue rotear: uma entrada no catálogo significa que o Phaseo acompanha o modelo, não que exista uma rota pública. Por padrão, `GET /v1/models` retorna apenas os modelos roteáveis no momento:

```bash
curl https://api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

Adicione `availability=all` para ver também os mapeamentos em breve e inativos. Envie tráfego de produção para a linha de um provedor somente quando `availability_status` for `active` e `is_active_gateway` for `true`. Consulte [Status do provedor e do Phaseo](../guides/provider-statuses.mdx) para entender o que significam os ícones de status nas páginas de modelos.

| Estado | O que significa |
| --- | --- |
| `active` | Pelo menos uma rota pública do Gateway está disponível agora. |
| `coming_soon` | O Phaseo acompanha uma rota planejada ou em prévia, mas ela não pode ser roteada publicamente. |
| `inactive` | Uma rota conhecida está desativada, indisponível, expirada ou, por outro motivo, não pode ser roteada. |
| `not_listed` | Nenhum mapeamento de provedor do Gateway está listado no momento para o modelo. |

`active` não garante disponibilidade, acesso em todas as regiões nem as mesmas condições comerciais para todos os espaços de trabalho.

## Interprete as métricas de desempenho

Os dados de desempenho do Phaseo resumem solicitações reais roteadas pelo Gateway; não são um benchmark controlado de laboratório.

| Métrica | Definição |
| --- | --- |
| TTFT do Gateway | Do início da solicitação no Gateway até a primeira saída gerada com conteúdo. |
| TTFT do provedor | Do envio ao provedor até a primeira saída gerada com conteúdo. |
| Duração no provedor | Do envio ao provedor até a resposta final. |
| E2E do Gateway | Do início da solicitação no Gateway até a conclusão. |
| Overhead do Phaseo | A diferença não negativa entre o E2E do Gateway e a duração no provedor. |
| Vazão efetiva | Todos os tokens de saída divididos pela duração total no provedor. |
| Velocidade de saída | Os tokens de saída após o primeiro divididos pelo tempo no provedor após o TTFT. |

TTFT e velocidade de saída exigem uma resposta em streaming com uma primeira saída com conteúdo. Uma solicitação sem streaming ainda contribui com a duração e a vazão efetiva, mas não com o TTFT.

Leia cada métrica junto com a janela de tempo, a rota, a região, o modo de streaming e o percentil. A carga do provedor, o tamanho do prompt, o tamanho da saída, as novas tentativas e as condições de rede alteram o resultado.

Para as definições completas, consulte [Preços e desempenho](../exploring/pricing-performance) e [Como o Phaseo mede latência e vazão](https://phaseo.app/how-phaseo-measures-latency-throughput).

## Valide com a sua carga de trabalho

As métricas públicas indicam uma tendência; elas não provam que uma rota atende à sua meta de produção. Faça um teste pequeno e reproduzível antes de um lançamento:

1. Remova os dados sensíveis de produção e mantenha uma combinação representativa de prompts.
2. Registre o ID do modelo, o endpoint, as restrições de provedor, a região, o modo de streaming e a concorrência.
3. Faça repetições suficientes para comparar distribuições em vez de uma única solicitação.
4. Capture a taxa de sucesso, o TTFT do Gateway, a duração no provedor, o E2E do Gateway, os tokens de saída e o custo final.
5. Teste falhas de chaves inválidas, modelos inválidos, limites de taxa e provedores indisponíveis.
6. Salve os IDs das solicitações e a janela de tempo exata para que outra pessoa da engenharia consiga reproduzir o resultado.

Não publique o nome de um cliente, uma citação, o resultado de uma carga de trabalho nem um percentual de confiabilidade sem permissão e sem um método documentado.

## Investigue uma solicitação com falha

1. Verifique o [status do serviço](https://status.phaseo.app).
2. Confirme se o modelo ainda aparece na resposta padrão de [`GET /v1/models`](../api-reference/endpoint/models) e verifique os [endpoints](../api-reference/endpoint/model-endpoints) dele.
3. Procure o status HTTP e o código de erro em [Erros e depuração](../api-reference/errors).
4. Repita respostas transitórias `429` e `5xx` com backoff exponencial limitado; consulte [Limites de taxa](../api-reference/limits.mdx).
5. Guarde o ID da solicitação quando entrar em contato com o [suporte](https://phaseo.app/help).

Para manter as solicitações funcionando quando um provedor falha, configure [roteamento e fallbacks](../guides/routing-and-fallbacks).
