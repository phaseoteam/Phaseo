## Crie um agente

Cria um agente a partir de uma definição. O limite de etapas da definição vale para cada chamada de run ou de continuação.

| Linguagem | Nome | Limite padrão de etapas |
| --- | --- | --- |
| TypeScript | `createAgent(definition)` | 12 |
| Python | `create_agent(definition)`, a partir de um dict ou de um `AgentDefinition` | 12 |
| Go | `CreateAgent(AgentDefinition) *Agent` | 8 |
| C# | `AgentSdk.CreateAgent(AgentDefinition)` | 12 |
| PHP | `AgentSdk::createAgent(AgentDefinition)` | 12 |
| Ruby | `PhaseoAgentSdk.create_agent(definition)`, a partir de um `AgentDefinition` ou de campos nomeados | 12 |
| Java | `AgentSdk.createAgent(AgentDefinition)` | 12 (um `maxSteps` abaixo de 1 vira 12) |
| Rust | `create_agent(AgentDefinition::new(id, model))` | 8 (os valores são limitados a no mínimo 1) |

### Campos da definição

O Rust monta a definição com métodos em vez de campos: `AgentDefinition::new(id, model)`, depois `.instructions(text)`, `.tool(tool)` (uma vez por ferramenta), `.max_steps(limit)`, `.model_retries(count, backoff)` e `.human_review(callback)`. O `AgentDefinition` do Java é um record com construtores de 10, 13 e 19 argumentos.

| Campo | camelCase (TypeScript, PHP, Java) | snake_case (Python, Ruby) | PascalCase (Go, C#) | Ausente em |
| --- | --- | --- | --- | --- |
| ID do agente (obrigatório) | `id` | `id` | `ID` (Go), `Id` (C#) | |
| Modelo ou predefinição | `model`, `preset` | `model`, `preset` | `Model`, `Preset` | O Rust não tem `preset` |
| Lista de modelos (só o primeiro é usado, quando `model` não está definido; sem fallback) | `models` | | | Todas, menos TypeScript |
| Instruções | `instructions` | `instructions` | `Instructions` | |
| Ferramentas | `tools` | `tools` | `Tools` | |
| Ferramentas oferecidas em uma etapa | `activeTools` | | | Todas, menos TypeScript |
| Reescrever o histórico antes de cada requisição ao modelo | `prepareMessages` | | | Todas, menos TypeScript |
| Limite de etapas e condições de parada | `maxSteps`, `stopWhen` | `max_steps`, `stop_when` | `MaxSteps`, `StopWhen` | O Rust não tem `stop_when` |
| Novas tentativas do modelo e concorrência de ferramentas | `modelRetry`, `toolExecution` | `model_retry`, `tool_execution` | `ModelRetry`, `ToolExecution` | O Rust não tem concorrência de ferramentas |
| Amostragem e tamanho | `temperature`, `maxOutputTokens`, `topP` | `temperature`, `max_output_tokens`, `top_p` | | Go, C#, Java, Rust |

## Execute e continue

| Finalidade | TypeScript | Python | Go | C# | PHP | Ruby | Java | Rust |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Executar | `run(options)` | `run(...)` | `Run(ctx, RunOptions)` | `Run(RunOptions)` | `run(...)` | `run(...)` | `run(RunOptions)` | `run(&mut client, options)`, `run_with_events(&mut client, options, callback)` |
| Executar com stream | `stream(options)` | `stream(...)` | `Stream(ctx, RunOptions)` | `Stream(RunOptions)` | `stream(...)` | `stream(...)` | `stream(RunOptions)` | Nenhum |
| Continuar | `continueRun(options)` | `continue_run(...)` | `Continue(ctx, ContinueOptions)` | `ContinueRun(ContinueOptions)` | `continueRun(...)`, `continueRunById(...)` | `continue_run(...)` | `continueRun(ContinueOptions)` | `continue_run(&mut client, options)`, `continue_with_events(...)` |
| Continuar com stream | `continueStream(options)` | `continue_stream(...)` | `ContinueStream(ctx, ContinueOptions)` | `ContinueStream(ContinueOptions)` | `continueStream(...)` | `continue_stream(...)` | `continueStream(ContinueOptions)` | Nenhum |

Executar e continuar retornam um resultado de execução: uma `Promise<AgentRunResult>` no TypeScript, `(RunResult, error)` no Go, `Task<RunResult>` no C#, `Result<RunResult, AgentError>` no Rust e o próprio resultado da execução nas demais. Os métodos de stream retornam um resultado de stream imediatamente.

### Opções de execução

PHP e Ruby as recebem como argumentos nomeados; o `RunOptions` do Java é um record posicional na ordem `input, client, context, model, preset, maxSteps, modelRetry, toolExecution, onEvent, devtools`, seguido de um `state` opcional.

| Opção | camelCase (TypeScript, PHP, Java) | snake_case (Python, Ruby, Rust) | PascalCase (Go, C#) | Ausente em |
| --- | --- | --- | --- | --- |
| Entrada | `input` | `input` | `Input` | |
| Conversa inteira em vez da entrada | `messages` | | | Todas, menos TypeScript |
| Cliente do modelo | `client` | `client` | `Client` | O Rust o passa como argumento separado |
| Contexto do aplicativo | `context` | `context` | `Context` | |
| Substituições de modelo, predefinição e limite de etapas | `model`, `preset`, `maxSteps` | `model`, `preset`, `max_steps` | `Model`, `Preset`, `MaxSteps` | O Rust só tem `model` e `max_steps` |
| Substituições de novas tentativas e concorrência de ferramentas | `modelRetry`, `toolExecution` | `model_retry`, `tool_execution` | `ModelRetry`, `ToolExecution` | Rust |
| Substituições de amostragem | `temperature`, `maxOutputTokens`, `topP` (TypeScript) | | | Todas, menos TypeScript |
| Cancelamento | `signal` (TypeScript) | | `CancellationToken` (C#) | O Go usa `ctx`; as demais cancelam pelo stream |
| Handler de eventos | `onEvent` | `on_event` | `OnEvent` | O Rust usa `run_with_events` |
| Captura local | `devtools` | `devtools` | `Devtools` | Rust |
| Acessor de estado | `state` | `state` | `State` | Rust |
| Adicionar mensagens antes da próxima requisição ao modelo | `takeMessages` (TypeScript) | | | Todas, menos TypeScript |

O `run()` do Python também aceita `stop_when`, mas o ignora; defina as condições de parada na definição. O `stream()` do PHP e o `stream` do Ruby só recebem `input`, `client`, `context` e `state`. O Rust cria os padrões com `RunOptions::new(input)`.

### Opções de continuação

As opções de continuação aceitam as substituições de execução acima, mais:

| Opção | camelCase (TypeScript, PHP, Java) | snake_case (Python, Ruby, Rust) | PascalCase (Go, C#) | Ausente em |
| --- | --- | --- | --- | --- |
| A execução salva | `run` | `run` (Rust: `result`) | `Run` | |
| Carregar a execução pelo ID via `state` | `runId` | `run_id` | `RunID` (Go), `RunId` (C#) | Rust; o PHP usa `continueRunById($runId, $state, $client, ...)` |
| Entrada humana | `humanInput` | `human_input` | `HumanInput` | |
| Mensagens humanas estruturadas | `humanMessages` (TypeScript) | | | Todas, menos TypeScript |
| Aprovações | `approvals` (alias no TypeScript: `approveToolCalls`) | `approvals` | `Approvals` | |
| Rejeições | `rejections` (alias no TypeScript: `rejectToolCalls`) | `rejections` | `Rejections` | Rust |
| Saídas de ferramentas | `toolOutputs` | `tool_outputs` | `ToolOutputs` | |

A ordem do `ContinueOptions` do Java é `run, client, context, model, preset, maxSteps, humanInput, modelRetry, toolExecution, onEvent, devtools`, depois `approvals, rejections, toolOutputs` e depois `runId, state`. Além dessa forma de 16 argumentos, há construtores que recebem só os 11 primeiros ou os 14 primeiros argumentos; o restante assume listas vazias ou `null` por padrão. O Rust cria os padrões com `ContinueOptions::new(result)`.

## Resultado do stream

| Finalidade | TypeScript | Python | Go | C# | PHP | Ruby | Java |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Resultado concluído | `getResult()`, ou `await` no stream | `result()` | `Result()` | `GetResult()` | `getResult()` | `result` | `getResult()` |
| Texto final completo | `getText()` | | | | | | |
| Deltas de texto | `getTextStream()` | `text_stream()` | `Text()` | `TextStream()` | `textStream()` | `text_stream` | `textStream()` |
| Deltas de raciocínio | `getReasoningStream()` | `reasoning_stream()` | | | `reasoningStream()` | `reasoning_stream` | |
| Itens | `getItemsStream()` | `item_stream()` | | | `itemStream()` | `item_stream` | |
| Eventos de ferramentas | `getToolStream()` | `tool_stream()` | | | | | |
| Todos os eventos | `getFullStream()` | `full_stream()` | `Events()` | `FullStream()` | `fullStream()` | `full_stream` | `fullStream()` |
| Cancelar | `cancel(reason?)` | `cancel()` | `Cancel()` | `Cancel()` | `cancel()` | `cancel` | `cancel()` |

Os consumidores reproduzem desde o início, então vários podem ler a mesma execução. O comportamento deles varia:

| Linguagem | Tipo do resultado de stream | Comportamento |
| --- | --- | --- |
| TypeScript | `AgentStreamResult` | `getFullStream()` termina com um evento `result` |
| Python | `AgentStreamResult` | Roda em uma thread em segundo plano; `result()` bloqueia até terminar |
| Go | `*StreamResult` | `Text()` e `Events()` são channels; `Cancel()` cancela o contexto da execução |
| C# | `AgentStreamResult` | Consumidores `IAsyncEnumerable`; `Cancel()` cancela o token vinculado da execução |
| PHP | `AgentStreamResult` | Roda em uma Fiber; `$result` guarda o `RunResult` depois que o stream é consumido, senão `null` |
| Ruby | `StreamResult` | Roda em uma thread de trabalho; `result` faz join nela e `cancel` a encerra |
| Java | `StreamResult` | `textStream()` e `fullStream()` retornam uma `List` depois que a execução termina; `cancel()` interrompe a thread de trabalho |
| Rust | Nenhum | Sem streaming na `0.2` |

## Resultado da execução

| Campo | camelCase (TypeScript, PHP, Java) | snake_case (Python, Ruby, Rust) | PascalCase (Go, C#) |
| --- | --- | --- | --- |
| Registro da execução | `run` | `run` | `Run` |
| Registros das etapas | `steps` | `steps` | `Steps` |
| Saída final | `output` | `output` | `Output` |
| Conversa completa | `messages` | `messages` | `Messages` |
| Uso acumulado | `usage` | `usage` | `Usage` |

O tipo é `AgentRunResult` no TypeScript e no Python e `RunResult` nas demais. O TypeScript adiciona `stepResults` (resultados normalizados das etapas) e `items` (mensagens, raciocínio, atividade de ferramentas, erros e saída final em ordem; veja [Itens](./items)). No Rust, `output` é um `serde_json::Value`, e `RunResult`, `RunRecord`, `RunStep`, `Message`, `ToolCall`, `HumanPause`, `PendingToolCall`, `ToolDecision`, `ToolOutput` e `UsageSummary` são serializados com Serde.

| --- | --- | --- | --- |

| Motivo de parada | `stopReason` | `stop_reason` | `StopReason` |

### Resumo de uso

`inputTokens`, `outputTokens`, `cachedTokens`, `totalTokens`, `cost` (TypeScript, Java); `input_tokens`, `output_tokens`, `cached_tokens`, `total_tokens`, `cost` (chaves no Python, PHP e Ruby, e Rust); `InputTokens`, `OutputTokens`, `CachedTokens`, `TotalTokens`, `Cost` (Go, C#). Veja em [Observabilidade](./observability) as ressalvas sobre `cost`.

## Clientes de modelo

Implemente um cliente de modelo para enviar os turnos do modelo por outro transporte ou para envolver o cliente de gateway.

| Linguagem | Interface | Métodos |
| --- | --- | --- |
| Go | `ModelClient`, `StreamingModelClient` | `Generate(ctx, ModelRequest)`; `Stream(ctx, ModelRequest)` |
| C# | `IModelClient`, `IStreamingModelClient` | `Generate(ModelRequest)`; `Stream(ModelRequest)` |
| PHP | `ModelClient`, `StreamingModelClient` (interfaces) | `generate(ModelRequest)`; `stream(ModelRequest)` |
| Java | `ModelClient`, `StreamingModelClient` | `generate(ModelRequest)`; `stream(ModelRequest)` |
| Rust | `ModelClient` (trait) | `fn generate(&mut self, request: &ModelRequest) -> Result<ModelResponse, AgentError>` |

No Rust, `ModelRequest` guarda o ID do agente, o modelo efetivo, as instruções, as mensagens atuais, as especificações das ferramentas (`ToolSpec`: `id`, `description`, `parameters` em JSON Schema) e o contexto do aplicativo. `ModelResponse` guarda `message`, `usage`, `request_id`, `provider`, `model` e `finish_reason`. `Message` tem `role`, `content`, `tool_calls`, `tool_call_id`, `name` e `is_error`, com os construtores `Message::user(content)` e `Message::assistant(content)`; `ToolCall` tem `id`, `name` e `input` em JSON.

## Eventos e erros

| Linguagem | Tipo de evento | Tipos de erro |
| --- | --- | --- |
| TypeScript | Objetos de evento com `type` | `AgentGatewayError` (`isAgentGatewayError()`), `AgentStreamError`, `AgentSchemaValidationError` |
| Python | Dicts com `"type"` | Exceções nativas e `phaseo.PhaseoHTTPError` |
| Go | `AgentEvent` | Valores `error` |
| C# | `AgentEvent` | Exceções |
| PHP | Arrays com `"type"` | `RuntimeException` |
| Ruby | Hashes com `:type` | Exceções |
| Java | `AgentEvent` | Exceções |
| Rust | `AgentEvent` (`event_type`, `run_id`, `agent_id`, `timestamp_ms`, `details`) | `AgentError` (`AgentError::new(...)`, `message()`; implementa `std::error::Error` e `Display`) |

O TypeScript também exporta `agentErrorIsRetryable()`, `agentRetryAfterMs()` e `agentErrorIsContextOverflow()` para classificar erros, `repairToolHistory(messages)` para responder a chamadas de ferramenta que ficaram sem resultado e descartar resultados que não respondem a nenhuma chamada, e `truncateToolOutput(text, limit)` para manter o início e o fim de um texto longo com um aviso do que foi cortado.
