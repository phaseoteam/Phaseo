Falhas do agente normalmente vêm de uma solicitação ao modelo, ferramenta local, validação de esquema, timeout ou ausência de decisão humana.

## Recuperar de erros de ferramentas

Defina `onError: "return-to-model"` quando o modelo puder se recuperar de uma falha de ferramenta. O erro vira um resultado estruturado de ferramenta e a execução pode escolher outra ação. Mantenha o comportamento fail-run para operações inseguras ou irrecuperáveis.

## Entender a execução do PHP

Callbacks de ferramentas PHP são executados de forma síncrona. Por isso, a concorrência e a interrupção de ferramentas são limitadas pelo runtime do PHP e pelo cliente de E/S subjacente. Defina timeouts explícitos para ferramentas de rede e processos e não suponha que um callback expirado sempre possa ser interrompido à força.

## Diagnosticar erros de continuação

Cada chamada pendente precisa de aprovação, rejeição ou saída fornecida externamente, identificada pelo ID da chamada da ferramenta. Persista todo o estado de execução retornado antes de exibir uma interface de aprovação.

## Registrar campos úteis

Registre o ID da execução, índice da etapa, ID da solicitação, provedor, modelo, motivo de conclusão, ID da chamada de ferramenta e motivo da parada. Use hooks do ciclo de vida ou o DevTools em vez de registrar prompts e credenciais sem tratamento.
