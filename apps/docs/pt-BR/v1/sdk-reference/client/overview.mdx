## O que você envia e recebe

Os corpos de solicitação usam os nomes de campo JSON da API em todos os SDKs. [Uso](./usage) tem um exemplo por endpoint.

| Linguagem | Corpo da solicitação | Retorna |
| --- | --- | --- |
| TypeScript | Objetos tipados gerados a partir da especificação OpenAPI | Objetos tipados |
| Python | Dicts; os tipos ficam em `phaseo.models` | Dicts `APIResponse` com `output_text`, `request_id` e `trace_url` |
| Go | `map[string]interface{}`, ou os tipos `phaseo.ChatCompletionsRequest` e `phaseo.ResponsesRequest` (campos de struct em PascalCase, como `Model`, `Messages`, `Input`) | JSON decodificado |
| C# | `Dictionary<string, object>` | `Dictionary<string, object>?` |
| PHP | Arrays | Arrays |
| Ruby | Hashes (argumentos nomeados) | Hashes |
| Java | Um `Map` ou um `JsonNode` do Jackson; interprete strings JSON antes | `JsonNode` |
| Rust | `&serde_json::Value` | `PhaseoResponse` com `status`, `body` e `request_id` |

A falta da chave gera falha quando você cria o cliente. O Python gera `ValueError`, o `NewFromEnv()` do Go retorna um erro, C# e PHP lançam `Missing API key. Pass apiKey or set PHASEO_API_KEY.`, o Ruby gera `ArgumentError: Missing API key. Pass api_key or set PHASEO_API_KEY.`, e o `Phaseo::from_env()` do Rust retorna um `PhaseoError`.

Use `AsyncPhaseo` com asyncio:

```python Python
import asyncio

async def main():
    async with AsyncPhaseo() as client:
        response = await client.responses.create({"model": "openai/gpt-6-astra", "input": "Hello"})
        print(response.output_text, response.request_id, response.trace_url)

```

<span id="wait-for-music-video-or-batches"></span>
## Aguarde música, vídeo ou lotes

Os helpers de espera existem em TypeScript e Python. Os outros SDKs retornam a tarefa na chamada de criação; faça polling dela com o método get ou abra a [URL de WebSocket da tarefa](#find-the-method-for-each-endpoint).

<CodeGroup>

```typescript TypeScript
const music = await client.music.generateAndWait(
  { model: process.env.PHASEO_MUSIC_MODEL!, prompt: "Gentle instrumental piano" },
  { timeoutMs: 600_000, onPoll: (job) => console.log(job.id, job.status) },
);
```

```python Python
import os

music = client.music.generate_and_wait(
    {"model": os.environ["PHASEO_MUSIC_MODEL"], "prompt": "Gentle instrumental piano"},
    timeout=600,
    on_poll=lambda job: print(job["id"], job["status"]),
)
```

</CodeGroup>

Use `videos.generateAndWait` / `videos.generate_and_wait` para vídeo e `batches.createAndWait` / `batches.create_and_wait` para lotes. Cada helper envia uma única vez. Se a primeira resposta já estiver concluída, ele a retorna sem fazer polling; caso contrário, faz polling da mesma tarefa até ela terminar e retorna a resposta completa. Tarefas com falha, canceladas ou expiradas geram `JobFailedError`, cujo `response` traz os detalhes. Um lote concluído ainda pode conter solicitações individuais com falha.

`wait(id, options)` em cada recurso retoma uma tarefa existente e retorna qualquer resposta terminal, incluindo falhas. Em Python, música também tem `create(request)` e `retrieve(id)`.

| TypeScript | Python | Padrão | Observações |
| --- | --- | --- | --- |
| `intervalMs` | `interval` | `5000` ms / `5` segundos | Mínimo de `250` ms / `0.25` segundos. |
| `timeoutMs` | `timeout` | `1800000` ms / `1800` segundos (30 minutos) | Começa depois que o envio retorna; a solicitação de envio mantém o próprio timeout. |
| `signal` | `cancel_event` | nenhum | Para a espera. Em Python, um `threading.Event`. |
| `onPoll` | `on_poll` | nenhum | Recebe a primeira resposta e cada polling. |

`JobTimeoutError` e `JobCancelledError` guardam o ID da tarefa e a última resposta (`jobId`/`lastResponse` em TypeScript, `job_id`/`last_response` em Python), então você pode retomar com `.wait(error.jobId)` ou `.wait(error.job_id)`. Parar uma espera não cancela a tarefa remota. Em TypeScript, isso cancela o polling em andamento; o cliente síncrono de Python verifica o cancelamento e o prazo entre as solicitações e os callbacks, então não consegue interromper uma chamada HTTP que já está em andamento. Falhas HTTP são geradas como estão, e os envios nunca são repetidos. Esses helpers fazem polling a partir do seu processo; eles não acrescentam execução em segundo plano ao gateway.

### Mantenha um handle entre processos

`music.start`, `videos.start` e `batches.start` retornam um handle com `result()`, `events()` e `cancel()`, além de `toJSON()` (TypeScript) ou `to_dict()` (Python). Guarde o tipo e o ID que ele retorna e reconstrua o handle depois com `resume(id)`. `result()` lança um erro em falhas terminais. Só tarefas de vídeo e de lote aceitam `cancel()`. Em `AsyncPhaseo`, use await nos métodos e itere os eventos com `async for`.

| Tarefa | TypeScript | Python |
| --- | --- | --- |
| Transmitir o conteúdo do vídeo | `videos.streamContent(id)`, gravado com `downloadTo(stream, writable)` | `videos.stream_content(id)`, gravado com o `download_to(chunks, binary_file)` síncrono, que não mantém o download inteiro na memória |
| Transmitir os resultados do lote | `batchResults(await client.batches.streamResults(id))` interpreta o JSONL uma linha por vez; `matchBatchResult(row, inputsByCustomId)` associa cada linha à sua entrada e mantém os erros por linha | `batches.results(id)` |
| Preparar uploads | `toFile(bytes, filename, contentType)` | Passe bytes, objetos `Path`, objetos de arquivo ou tuplas de arquivo do HTTPX |

## Controles de solicitação e erros

As retentativas têm padrão `0` em TypeScript, Python e Java e se aplicam apenas a solicitações `GET` e `HEAD`. Envios pagos, escritas e solicitações de streaming nunca são repetidos.

<CodeGroup>

```typescript TypeScript
const fast = client.withOptions({ timeoutMs: 30_000, signal, maxRetries: 2 });
```

```python Python
fast = client.with_options(timeout=30, max_retries=2)
```

```java Java
Phaseo client = new Phaseo(System.getenv("PHASEO_API_KEY"))
    .setTimeout(Duration.ofSeconds(30))
    .setMaxRetries(2);
```

</CodeGroup>

<Tabs>
<Tab title="TypeScript">

`withOptions(...)` retorna um novo cliente com esses controles aplicados a todas as chamadas de recursos, streams e mídia; o cliente original não muda. As retentativas respeitam `Retry-After`. `timeoutMs` inclui a leitura do corpo da resposta.

`responseMetadata(result)` retorna o ID da solicitação no gateway e a URL do rastreamento no painel. Os erros HTTP são `PhaseoHttpError`, com o `status` HTTP, o `code` de erro da API, `requestId`, `traceUrl`, o atraso de retentativa, o corpo e `headers`.

</Tab>
<Tab title="Python">

`with_options(...)` retorna um novo cliente e também aceita `headers=...`; funciona tanto em `Phaseo` quanto em `AsyncPhaseo`. As retentativas acontecem antes da leitura da resposta, até um máximo de `10`. Os timeouts são timeouts do HTTPX em segundos, então limitam a inatividade da rede, e não a duração total.

As respostas JSON são dicts `APIResponse` com `output_text`, `request_id` e `trace_url`. Os erros HTTP são `PhaseoHTTPError`, com `status`, `code`, `request_id`, `trace_url`, o atraso de retentativa e o corpo.

Ao atualizar de uma versão mais antiga, substitua as capturas de `urllib.error.HTTPError` por `PhaseoHTTPError` (ou `httpx.HTTPStatusError`) e as capturas de erros de conexão por `httpx.TransportError`.

</Tab>
<Tab title="Java">

Os erros HTTP são `Client.ApiException` (`app.phaseo.gen.Client`), com `getStatusCode()`, `getRequestId()`, `getResponseBody()` e os headers. `requestWithResponse(...)` retorna os dados com o `requestId()` deles.

</Tab>
<Tab title="Rust">

Toda chamada retorna `Result<PhaseoResponse, PhaseoError>`. `PhaseoError` implementa `std::error::Error` e `Display`; falhas de transporte e de configuração não têm `status`.

| Tipo | Campo | Significado |
| --- | --- | --- |
| `PhaseoResponse` | `status: u16` | Código de status HTTP. |
| `PhaseoResponse` | `body: serde_json::Value` | A resposta JSON interpretada, ou uma string JSON quando a resposta não era um JSON válido. |
| `PhaseoResponse` | `request_id: Option<String>` | O header de resposta `x-request-id`, quando presente. |
| `PhaseoError` | `message: String` | Mensagem de erro de configuração, de transporte ou do Gateway. |
| `PhaseoError` | `status: Option<u16>` | Status HTTP do Gateway, quando uma resposta foi recebida. |
| `PhaseoError` | `body: Option<serde_json::Value>` | Corpo de erro do Gateway interpretado, quando disponível. |

</Tab>
</Tabs>

[Uso](./usage#handle-errors) mostra um tratador de erros completo em cada linguagem.

## Chame um endpoint sem wrapper

Cada SDK também inclui o cliente gerado a partir da especificação OpenAPI do Phaseo:

| Linguagem | Cliente gerado |
| --- | --- |
| TypeScript | `client.rawClient()`; as operações geradas são exportadas como `operations`. |
| Python | `client.raw_client()`; as operações geradas ficam em `phaseo.ops`. |
| Go | `client.RawClient()`, de `src/gen`. `client.Request(ctx, method, path, query, headers, body)` envia qualquer solicitação. |
| Java | `client.rawClient()`, com `requestLines` para streams e `requestBytes` para respostas binárias. |
| Rust | `phaseo::gen` contém o cliente, os modelos e as operações gerados, reexportados como `phaseo::client`, `phaseo::models` e `phaseo::operations`. `phaseo::model_ids` tem os IDs de modelo gerados. `client.post(path, body)` envia JSON para qualquer caminho abaixo da URL base. Veja o [docs.rs](https://docs.rs/phaseo). |

As operações geradas são de nível mais baixo que os métodos wrapper; prefira o wrapper quando houver um.

## Interprete a saída e reúna streams

Esses helpers existem em TypeScript e Python. `responses.parse(request, schema)` valida uma resposta JSON concluída. Em TypeScript, `schema` é um parser compatível com Zod; em Python, um modelo Pydantic. Defina também o formato de saída estruturada na solicitação; o parser apenas valida.

`collectStream(client.streamResponses(request))` (TypeScript), ou `collect_stream` e `collect_async_stream` (Python), reúnem o texto e o uso transmitidos.

## Verifique um modelo antes de chamá-lo

`checkModelCapabilities` / `check_model_capabilities` (TypeScript e Python) verifica as capacidades anunciadas e as restrições escalares (`inputTypes`, `outputTypes`, `endpoints`, `parameters`, `parameterValues`, ou os nomes em snake_case no Python) em uma oferta de provedor ativa. Ele nunca muda o modelo nem descarta parâmetros, e não consegue garantir que um provedor em produção vá aceitar a solicitação. Metadados ausentes são tratados de forma diferente: o TypeScript os informa como desconhecidos, e o Python reprova a verificação.

Para seletores de modelo e editores de parâmetros, use os metadados de endpoint em tempo real:

<CodeGroup>

```typescript TypeScript
const support = await client.models.checkParameters(
  "anthropic/claude-haiku-4.5",
  { temperature: 0.7, top_p: 0.9 },
  { endpoint: "responses" },
);
```

```python Python
support = client.models.check_parameters(
    "anthropic/claude-haiku-4.5",
    {"temperature": 0.7, "top_p": 0.9},
    endpoint="responses",
)
```

</CodeGroup>

Cada parâmetro volta como `supported`, `partial`, `unsupported` ou `unknown`, com as rotas de provedor correspondentes e os problemas de restrição que você pode destacar na interface. Essas verificações são chamadas explícitas; elas não acrescentam uma consulta às solicitações de geração. [Modelos](./models#check-one-model) lista o método em cada SDK.

## Teste sem rede

<Tabs>
<Tab title="TypeScript">

Importe `createMockTransport` e `jobFixtures` de `@phaseo/sdk/testing` e passe o `fetchImpl` do mock ao cliente. Os fixtures são estritos e ordenados: uma chamada inesperada falha localmente e nunca chega à rede. Chame `mock.assertDone()` para verificar se todas as solicitações esperadas aconteceram.

</Tab>
<Tab title="Python">

Passe `phaseo.testing.MockTransport(fixtures)` para um `httpx.Client` ou `httpx.AsyncClient` e entregue-o ao cliente do Phaseo como `http_client`. Uma solicitação inesperada falha localmente; chame `assert_done()` para verificar se todos os fixtures foram usados. `phaseo.testing.job_fixtures(path, job_id)` monta os fixtures de envio e polling de uma tarefa. Os fixtures não verificam o comportamento real dos provedores.

</Tab>
</Tabs>

## Exporte código de uma sala

Depois de enviar uma solicitação em uma sala do Phaseo, **Obter código** exporta o modelo e as configurações dela como TypeScript ou Python, e **Ver solicitação** abre o rastreamento dela no painel quando há um ID de solicitação disponível. Execute o código exportado no seu servidor com `PHASEO_API_KEY` definida.
