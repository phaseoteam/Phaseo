| Linguagem | Método | Filtros com vários valores |
| --- | --- | --- |
| TypeScript | `client.getModels(filters)` ou `client.models.list(filters)` | Arrays |
| Python | `client.get_models(filters)` ou `client.models.list(filters)` | Listas |
| Go | `client.GetModels(ctx, query)` com um `map[string]string` | Strings separadas por vírgula |

| Ruby | `client.list_models(...)` | Strings separadas por vírgula |
| Java | `client.listModels(query)` com um `Map<String, String>` | Strings separadas por vírgula |
| Rust | Não há helper; chame `client.request("GET", "/models?<filters>", None, &RequestOptions::default())` | Strings separadas por vírgula na query string |

## Filtre a lista

Todos os filtros são opcionais e têm os mesmos nomes em todos os SDKs: são os parâmetros de consulta.

| Filtro | Filtra por |
| --- | --- |
| `provider`, `organisation` | Provedor ou organização do modelo |
| `endpoints`, `input_types`, `output_types`, `params` | Endpoints, modalidades e parâmetros de solicitação aceitos |
| `status`, `provider_status`, `provider_routing_status`, `model_routing_status`, `capability_status`, `provider_availability_status`, `provider_availability_reason` | Estado de ciclo de vida e de roteamento |
| `availability` | Defina `all` para incluir modelos que não podem ser roteados |
| `limit`, `offset` | Paginação |

Por padrão, a lista contém apenas modelos roteáveis. Defina `availability` como `all` para incluir os demais e depois restrinja a lista:

- `provider_availability_reason` seleciona estados de lançamento como `preview_only`, `provider_not_ready`, `gated`, `access_limited`, `region_limited`, `project_limited`, `paused` ou `soft_blocked`.
- `capability_status` seleciona mapeamentos de endpoint que ainda não são roteáveis, como `coming_soon` ou `internal_testing`.

## Verifique um modelo

`checkParameters` e os equivalentes leem os metadados das rotas de provedor em tempo real, marcam cada parâmetro como `supported`, `partial`, `unsupported` ou `unknown`, verificam os valores e intervalos anunciados e retornam as rotas de provedor que aceitam o conjunto inteiro. `preflight` faz o mesmo para um corpo de solicitação inteiro e acrescenta a verificação do ciclo de vida do modelo, com um `ok` geral.

| Linguagem | Capacidades | Verificar parâmetros | Preflight | Ciclo de vida |
| --- | --- | --- | --- | --- |
| TypeScript | `models.capabilities(modelId)` | `models.checkParameters(modelId, values, { endpoint, provider })` | `models.preflight(request, { endpoint, provider })` | `models.validate(modelId)` retorna `{ ok, info, reason }`; `models.getDeprecationInfo(modelId)` |
| Python | `models.capabilities(model_id)` | `models.check_parameters(model_id, values, endpoint=..., provider=...)` | `models.preflight(request, endpoint=..., provider=...)` | `models.validate(model_id)`, `models.get_deprecation_info(model_id)` |
| Go (próxima versão) | `GetModelEndpointCapabilities` | `CheckModelParameters` | `PreflightRequest` | `ValidateModel`, `GetModelDeprecationInfo` (publicados) |
| C# (próxima versão) | `GetModelEndpointCapabilities(modelId)` | `CheckModelParameters(modelId, values)` | `PreflightRequest` | `ValidateModel`, `GetModelDeprecationInfo` (publicados) |
| PHP (próxima versão) | `getModelEndpointCapabilities` | `checkModelParameters(...)` | `preflightRequest` | `validateModel`, `getModelDeprecationInfo` (publicados) |
| Ruby (próxima versão) | `model_endpoint_capabilities` | `check_model_parameters(model_id, values)` | `preflight_request` | `validate_model`, `get_model_deprecation_info` (publicados) |
| Java (build a partir do código-fonte) | `getModelEndpointCapabilities(modelId, query)` | `checkModelParameters(modelId, values, options)` | `preflightRequest(request, options)` | `validateModel`, `getModelDeprecationInfo` |
| Rust (não está na `0.2.0`) | `Phaseo::model_endpoint_capabilities(...)` | `Phaseo::check_model_parameters(...)` | Nenhum | Nenhum |

"Próxima versão" significa que o método está no código-fonte do SDK, mas não no pacote publicado; veja [Confira o que cada pacote inclui](./overview#check-what-each-package-ships). Os métodos de informações de descontinuação retornam o status do modelo (`active`, `deprecated` ou `retired`), as datas de descontinuação e de desativação e o ID do modelo substituto.
