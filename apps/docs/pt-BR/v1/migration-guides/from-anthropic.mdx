Mantenha o SDK da Anthropic e a chamada Messages. Aponte o cliente para `https://api.phaseo.app`, passe sua chave do Phaseo como `authToken` e dê a cada modelo o ID dele no Phaseo.

| Configuração | Anthropic | Phaseo |
| --- | --- | --- |
| URL base | Padrão do SDK (`https://api.anthropic.com`) | `https://api.phaseo.app` (o SDK acrescenta `/v1/messages`) |
| Chave de API | `ANTHROPIC_API_KEY`, enviada como `x-api-key` | `PHASEO_API_KEY` como `authToken` / `auth_token`, enviada como `Authorization: Bearer` |
| Modelo | `claude-sonnet-5-5` | `anthropic/claude-sonnet-5.5`, ou qualquer ID de `GET /v1/models` |
| Chamada Messages | `messages.create` | Inalterada |

## Troque o cliente

Crie uma chave em [Chaves de API](https://phaseo.app/settings/keys) e disponibilize-a para o app como `PHASEO_API_KEY`.

<CodeGroup>
```typescript TypeScript
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic({
  apiKey: null,
  authToken: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app",
});

const response = await client.messages.create({
  model: "anthropic/claude-sonnet-5.5",
  max_tokens: 256,
  messages: [{ role: "user", content: "Reply with: migration ready" }],
});
```

```python Python
import os
import anthropic

client = anthropic.Anthropic(
    auth_token=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app",
)

response = client.messages.create(
    model="anthropic/claude-sonnet-5.5",
    max_tokens=256,
    messages=[{"role": "user", "content": "Reply with: migration ready"}],
)
```

```bash cURL
curl https://api.phaseo.app/v1/messages \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-sonnet-5.5",
    "max_tokens": 256,
    "messages": [{"role": "user", "content": "Reply with: migration ready"}]
  }'
```
</CodeGroup>

Três detalhes quebram esta etapa com mais frequência:

- **Use o host raiz.** `baseURL: "https://api.phaseo.app/v1"` gera `/v1/v1/messages`. Clientes compatíveis com OpenAI no mesmo repositório continuam usando `/v1`.
- **Envie a chave como bearer token.** O gateway lê apenas `Authorization: Bearer`; um cabeçalho `x-api-key` recebe `401` `missing_or_invalid_authorization_header`. `authToken` envia Bearer em todas as versões do SDK. `apiKey` só faz isso a partir do `@anthropic-ai/sdk` 1.0 e do `anthropic` 2.0.
- **Remova `ANTHROPIC_API_KEY`** dos ambientes que agora chamam o Phaseo. `apiKey: null` impede que SDKs TypeScript mais antigos a leiam, e SDKs Python anteriores à 0.98 a leem mesmo quando `auth_token` está definido.

Ferramentas configuradas por variáveis de ambiente, como o Claude Code, usam `ANTHROPIC_BASE_URL=https://api.phaseo.app`, `ANTHROPIC_AUTH_TOKEN` definido com a chave do Phaseo e `ANTHROPIC_API_KEY` vazio.

## Mapeie os IDs de modelo

Confira cada modelo de produção em `data[].id` de `GET /v1/models?format=openai`. Os IDs do Phaseo usam pontos na versão: `claude-sonnet-5-5` vira `anthropic/claude-sonnet-5.5`. Se o modelo também estiver mudando, leia o [guia de migração de modelos](../model-migrations) correspondente.

## O que funciona de forma diferente

| Recurso da Anthropic | No Phaseo |
| --- | --- |
| Cabeçalho `anthropic-version` | Qualquer valor é aceito; o Phaseo chama o Claude com a própria versão. |
| Cabeçalhos `anthropic-beta` | Não são repassados. O Phaseo adiciona os betas de que os recursos com suporte precisam; campos de corpo exclusivos de beta, como `mcp_servers`, retornam `400`. |
| `temperature`, `top_p`, `top_k` | Descartados quando o modelo ou a rota não os aceita, e listados em `X-Phaseo-Dropped-Params`. |
| `speed: "fast"` | Retorna `400`. Use `service_tier: "fast"`. |
| Ferramentas nativas de pesquisa e busca na web | Aceitas quando o provedor as executa; ou use a ferramenta de servidor `phaseo:web_search` do Phaseo. |
| `cache_control` | Com suporte no nível superior ou por bloco. Veja [Cache de prompts](../guides/prompt-caching). |
| `metadata.user_id` | Não é usado como ID do usuário final. Envie `user` ou o cabeçalho `X-Phaseo-User-Id` para políticas de limite de taxa por usuário final. |
| Message Batches (`/v1/messages/batches`) | Esse caminho não existe. `/v1/batches` aceita linhas de `/v1/messages` em outro formato. |
| Contagem de tokens (`/v1/messages/count_tokens`) | Sem equivalente. Mantenha-a na Anthropic ou estime no cliente. |
| Files API (`client.beta.files`) | Sem equivalente. Envie os documentos inline. |
| Clientes `AnthropicBedrock` e `AnthropicVertex` | Substitua pelo cliente `Anthropic` simples; as configurações de autenticação e região da nuvem não se aplicam. |

## Teste e faça o rollout

Teste prompts de sistema, streaming, uso de ferramentas, thinking e saída estruturada com os IDs de modelo exatos que o app usa. Depois compare um conjunto representativo de prompts nas duas configurações quanto ao formato da saída, latência, uso de tokens, erros e custo. Antes de mover o tráfego, confirme que:

- a chave do Phaseo está definida em todos os ambientes de implantação;
- cada ID de modelo de produção está em `GET /v1/models?format=openai`;
- os fluxos de streaming e de uso de ferramentas passam em staging;
- cada cabeçalho `anthropic-beta` e campo exclusivo de beta foi removido ou substituído;
- o rollback ainda é só uma troca de URL base e chave.
