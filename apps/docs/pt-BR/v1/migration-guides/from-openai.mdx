Mantenha o SDK da OpenAI e mude duas coisas: a URL base e a chave de API. Depois dê a cada modelo o ID dele no Phaseo, que acrescenta o prefixo `openai/`.

| Configuração | OpenAI | Phaseo |
| --- | --- | --- |
| URL base | Padrão do SDK (`https://api.openai.com/v1`) | `https://api.phaseo.app/v1` |
| Chave de API | `OPENAI_API_KEY` | `PHASEO_API_KEY`, enviada como `Authorization: Bearer` |
| Modelo | `gpt-4.1-mini` | `openai/gpt-4.1-mini`, ou qualquer ID de `GET /v1/models` |
| Código da solicitação | `chat.completions.create`, `responses.create` | Inalterado |

## Troque o cliente

Crie uma chave em [Chaves de API](https://phaseo.app/settings/keys) e adicione-a a todos os ambientes que executam o app. Depois passe a chave e a URL base ao cliente existente:

<CodeGroup>
```typescript TypeScript
import OpenAI from "openai";

// Antes: const client = new OpenAI();
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Reply with: migration ready" }],
});
```

```python Python
import os
from openai import OpenAI

# Antes: client = OpenAI()
client = OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
)

response = client.chat.completions.create(
    model="openai/gpt-4.1-mini",
    messages=[{"role": "user", "content": "Reply with: migration ready"}],
)
```

```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-4.1-mini",
    "messages": [{"role": "user", "content": "Reply with: migration ready"}]
  }'
```
</CodeGroup>

Use um novo nome de variável em vez de colocar a chave do Phaseo em `OPENAI_API_KEY`, e remova valores antigos de `OPENAI_BASE_URL` para que nenhum outro cliente do repositório continue chamando a OpenAI. Clientes `AzureOpenAI` passam para o cliente `OpenAI` simples; os nomes de implantação do Azure são mapeados para IDs de modelo do Phaseo da mesma forma.

## Mapeie os IDs de modelo

Liste os IDs que o Phaseo atende no formato de lista da OpenAI e confira cada modelo de produção em `data[].id`:

```bash
curl "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

Sem `format=openai`, a resposta é a lista paginada `models` do Phaseo, sem array `data`. O mesmo vale para `client.models.list()`: passe `{ query: { format: "openai" } }` no Node ou `extra_query={"format": "openai"}` no Python. A lista padrão contém apenas os modelos que você pode chamar agora; adicione `availability=all` para incluir os inativos e os que estão por vir.

## O que funciona de forma diferente

| Recurso da OpenAI | No Phaseo |
| --- | --- |
| Chat Completions, Responses | Os mesmos formatos de solicitação em `/v1/chat/completions` e `/v1/responses`. Um campo de nível superior desconhecido retorna `400` `unknown_param`. |
| `previous_response_id`, `conversation` | Retornam `400`: o Phaseo não armazena respostas. Envie o histórico completo em `input` em cada solicitação. |
| Embeddings, moderações, imagens, fala, transcrição | `/v1/embeddings`, `/v1/moderations`, `/v1/images/*`, `/v1/audio/*`. Confira se o modelo oferece suporte à operação. |
| Batch API | `/v1/files` e `/v1/batches`. `/v1/files` guarda apenas entradas de lote; não pode fornecer entradas `file_id` para outras solicitações. |
| Realtime | `POST /v1/audio/realtime/sessions` e, em seguida, um WebSocket para o `connect.url` retornado. Veja [Voz em tempo real](../guides/realtime-voice). |
| Prompts armazenados (`prompt: { id: "pmpt_…" }`) | Recrie o prompt como uma predefinição e chame-a com `prompt: { id: "@slug", version, variables }`. Veja [Templates de prompt](../guides/prompt-templates). |
| `organization`, `project`, cabeçalho `OpenAI-Organization` | Sem equivalente. Remova-os; use espaços de trabalho e chaves do Phaseo. |
| Assistants, Threads, vector stores, fine-tuning, o legado `/v1/completions` | Sem endpoint no Phaseo. Mantenha-os na OpenAI ou migre-os para `/v1/responses`. |

## Teste e faça o rollout

Execute os mesmos prompts representativos na configuração antiga e na nova e compare o formato da saída, a latência, o uso de tokens, os erros e o custo. Antes de mover o tráfego, confirme que:

- a chave do Phaseo está definida em desenvolvimento, staging e produção;
- cada ID de modelo de produção aparece em `GET /v1/models?format=openai`;
- uma solicitação sem streaming e uma com streaming passam em staging, além de chamadas de ferramentas e saídas estruturadas, se o app as usa;
- o rollback ainda é só uma troca de URL base e chave.

Depois mova o tráfego aos poucos. [Roteamento e fallbacks](../guides/routing-and-fallbacks) explica os modelos de fallback, e [Tratamento de erros](../api-reference/errors.mdx) lista os corpos de erro que o seu app pode receber agora.
