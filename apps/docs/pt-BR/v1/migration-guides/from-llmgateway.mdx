Troque a URL base e a chave, mantenha os payloads das solicitações e mapeie cada ID de modelo: no LLM Gateway, o prefixo indica o provedor que atende, enquanto no Phaseo indica o criador do modelo.

| Configuração | LLM Gateway | Phaseo |
| --- | --- | --- |
| URL base | `https://api.llmgateway.io/v1` | `https://api.phaseo.app/v1` |
| Clientes no estilo Anthropic | `ANTHROPIC_BASE_URL=https://api.llmgateway.io` | `https://api.phaseo.app`; veja [Migração do SDK da Anthropic](./from-anthropic) |
| Chave de API | `LLM_GATEWAY_API_KEY` (`llmgtwy_…`) | `PHASEO_API_KEY` |
| IDs de modelo | `gpt-4o`, `<provider>/<model>`, `auto` | `<org>/<model>` de `GET /v1/models?format=openai` |
| Payload da solicitação | Compatível com OpenAI | Inalterado |

## Troque o cliente

<CodeGroup>
```typescript TypeScript
import OpenAI from "openai";

// Antes:
// new OpenAI({ apiKey: process.env.LLM_GATEWAY_API_KEY, baseURL: "https://api.llmgateway.io/v1" });
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});
```

```python Python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["PHASEO_API_KEY"],
    base_url="https://api.phaseo.app/v1",
)
```

```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```
</CodeGroup>

Mapeie ou remova cada variável `LLM_GATEWAY_*`, inclusive nas configurações de CI e de hospedagem. Se o app usa `@llmgateway/ai-sdk-provider`, troque para `@phaseo/ai-sdk-provider` como em [Migração do Vercel AI Gateway](./from-vercel).

## Mapeie os IDs de modelo

Liste os IDs do Phaseo e confira cada modelo de produção com eles:

```bash
curl -s "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY" | jq -r '.data[].id'
```

`alibaba/<model>` no LLM Gateway não é um ID do Phaseo. Mapeie cada ID para o `<org>/<model>` do Phaseo e mantenha uma fixação de provedor com `provider.only` ou um ID `provider:org/model`. Traduza aliases sem prefixo, como `gpt-4o`, em uma única função na fronteira do cliente, e não em cada ponto de chamada.

## Mapeie os recursos do gateway

| LLM Gateway | No Phaseo |
| --- | --- |
| Roteador `auto` | `phaseo/auto` ([Roteamento automático](../guides/auto-routing), alfa); não pode ser combinado com `models`. |
| Cadeias de fallback | Array `models` ou rotas dinâmicas, tentados em `429`, `500`, `502`, `503` e `504`, nunca em erros da solicitação. |
| `X-No-Fallback` | `provider.allow_fallbacks: false` ou um ID `provider:org/model`. |
| Lógica de permissão e bloqueio de provedores | `provider.only`, `provider.ignore` ou [Predefinições](../guides/presets). Mantenha pelo menos um provedor elegível. |
| Cabeçalhos `X-LLMGateway-<Key>` | [Rótulos](../guides/request-labels) `X-Phaseo-Metadata`, até 32. |
| Cabeçalhos de sessão (`x-session-id`) | Campo de corpo `session_id`; o Phaseo ignora cabeçalhos de sessão. |
| `X-Source` | `HTTP-Referer` ou `X-App-Name`. Veja [Atribuição de apps](../guides/app-attribution). |
| Cache de respostas | Sem cache de respostas. |
| Chaves de provedores | BYOK (**Configurações → BYOK** ou `POST /v1/byok`) ou créditos do Phaseo. O fallback para créditos é a configuração de espaço de trabalho `byok_fallback_enabled`. |
| Logs de solicitações | Logs de solicitações, destinos de observabilidade e `GET /v1/generations?id=<request_id>`. Quando `replay_supported` é `true`, refaça uma solicitação com falha a partir do payload `replay_request` dela. |

## Teste e faça o rollout

Execute seus prompts de referência nos dois gateways e compare qualidade, latência e custo. Confira os endpoints primeiro:

```bash
curl -s "https://api.phaseo.app/v1/health"
curl -s "https://api.phaseo.app/v1/models?format=openai" -H "Authorization: Bearer $PHASEO_API_KEY"
```

Antes de mover o tráfego, confirme que:

- `PHASEO_API_KEY` está definida em todos os ambientes;
- cada ID de modelo de produção está mapeado e listado;
- uma solicitação sem streaming e uma com streaming passam em staging;
- os erros de chave inválida e de modelo inválido são tratados; os corpos deles podem ser diferentes dos do LLM Gateway;
- uma solicitação de staging com falha pode ser recuperada com `GET /v1/generations`;
- os padrões compartilhados de prompt e roteamento ficam em predefinições, onde devem ficar.

Lance atrás de uma flag canário, passe de uma pequena parte do tráfego para todo ele quando estiver estável e acompanhe as métricas de produção por pelo menos um ciclo de release antes de remover a configuração antiga.
