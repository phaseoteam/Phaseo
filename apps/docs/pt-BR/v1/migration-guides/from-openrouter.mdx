Troque a URL base para `https://api.phaseo.app/v1` e a chave para `PHASEO_API_KEY`. Os payloads das solicitações, o cabeçalho `Authorization: Bearer`, o objeto `provider` e o array de fallback `models` continuam funcionando; confira os IDs de modelo e os poucos campos da tabela abaixo.

| Configuração | OpenRouter | Phaseo |
| --- | --- | --- |
| URL base | `https://openrouter.ai/api/v1` | `https://api.phaseo.app/v1` |
| Chave de API | `OPENROUTER_API_KEY` (`sk-or-v1-…`) | `PHASEO_API_KEY` |
| Autenticação | `Authorization: Bearer <key>` | Inalterada |
| Payload da solicitação | Compatível com OpenAI | Inalterado |
| IDs de modelo | `<org>/<model>` | `<org>/<model>`; a maioria coincide, algumas orgs são diferentes |
| Cabeçalhos de atribuição | `HTTP-Referer`, `X-Title` | Inalterados; adicione `X-App-Id` para um agrupamento estável |

## Troque o cliente

<CodeGroup>
```typescript Antes
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.OPENROUTER_API_KEY,
  baseURL: "https://openrouter.ai/api/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Summarize our migration plan." }],
});
```

```typescript Depois
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});

const response = await client.chat.completions.create({
  model: "openai/gpt-4.1-mini",
  messages: [{ role: "user", content: "Summarize our migration plan." }],
});
```

```bash cURL
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role":"user","content":"Say hello"}]
  }'
```
</CodeGroup>

Mantenha o payload inalterado na primeira rodada e alcance a paridade antes de otimizar. Remova `OPENROUTER_BASE_URL` e a chave antiga do código, da CI e das configurações de hospedagem. `@openrouter/ai-sdk-provider` vira `@phaseo/ai-sdk-provider` (veja [Migração do Vercel AI Gateway](./from-vercel)); os SDKs próprios do OpenRouter (`@openrouter/sdk`, `openrouter` no PyPI) exigem uma troca de cliente, não apenas uma nova URL base.

## Confira os IDs de modelo

A maioria dos IDs coincide, mas algumas orgs são diferentes: `x-ai/` é `spacex-ai/`, `meta-llama/` é `meta/` e `mistralai/` é `mistral/`. Liste os IDs do Phaseo e confira cada modelo de produção com eles:

```bash
curl -s "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY" | jq -r '.data[].id'
```

A lista padrão contém apenas os modelos que você pode chamar agora; adicione `availability=all` para ver os inativos ou os que estão por vir. Sem `format=openai`, a resposta é a lista paginada `models` do Phaseo, que não tem array `data`.

## Mapeie os campos da solicitação

| OpenRouter | No Phaseo |
| --- | --- |
| `provider.order`, `only`, `ignore`, `allow_fallbacks`, `require_parameters`, `max_price` | Os mesmos campos. Use IDs de provedor base, não slugs de endpoint. |
| `provider.sort` | O mesmo campo: `price`, `latency` ou `throughput`. |
| `provider.zdr` | Aceito como alias de `provider.require_zero_data_retention`. |
| `provider.data_collection: "deny"` | Retorna `400`. Use `zdr: true` no lugar. |
| Array de fallback `models` | Igual, de 1 a 25 entradas. `model` é obrigatório, então passe `models[0]` para ele. |
| Sufixo `:nitro` | Igual (throughput). O Phaseo também tem `:cheap` e `:fast`; `:floor` vira `:cheap`. Remova `:online` e `:thinking` e use pesquisa na web e `reasoning` no lugar. |
| `openrouter/auto`, `openrouter/free` | `phaseo/auto` ([Roteamento automático](../guides/auto-routing), alfa, não pode ser combinado com `models`) e `phaseo/free`. |
| `plugins` `web`, `web-fetch`, `response-healing` | Os mesmos IDs de plugin. Outros plugins, como `file-parser`, retornam `400`. |
| `transforms`, `usage: { include: true }` | Não são aceitos. Remova-os; uso e custo são sempre retornados. |
| `X-OpenRouter-Title` | Renomeie para `X-Title`. Veja [Atribuição de apps](../guides/app-attribution). |
| Predefinições `@preset/<slug>` | Recrie-as como [Predefinições](../guides/presets) e chame-as como `"model": "@slug"`. |
| `usage.cost`, `reasoning_details`, `provider` nas respostas | Retornados. `native_finish_reason` e `is_byok` não são; normalize-os em uma única camada se os chamadores os leem. |

O Phaseo também tem `provider.required_execution_region` e `provider.required_data_region`, que não têm equivalente no OpenRouter. Veja [Fixe ou ignore provedores](../cookbook/pin-or-ignore-providers-per-request) e [Roteie apenas para provedores na UE ou com ZDR](../cookbook/route-only-to-eu-or-zdr-providers) para solicitações completas.

Mantenha os campos exclusivos do OpenRouter que restarem em um único adaptador, e não em cada ponto de chamada, para que o rollback continue sendo uma troca de URL base e chave.

## Valide antes da virada

Execute estes comandos contra o Phaseo e depois as mesmas verificações pelo caminho de cliente do seu app:

```bash
curl -s "https://api.phaseo.app/v1/health"

curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"openai/gpt-6-astra","messages":[{"role":"user","content":"Say hello"}]}'

# Streaming
curl -N "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"openai/gpt-6-astra","stream":true,"messages":[{"role":"user","content":"Reply with: stream works"}]}'

# Modelo inválido: o app deve tratar o erro sem expor credenciais
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -d '{"model":"invalid/migration-test","messages":[{"role":"user","content":"test"}]}'
```

Antes de mover uma parte relevante do tráfego, confirme que:

- `OPENROUTER_API_KEY` foi substituída por `PHASEO_API_KEY` em todos os ambientes;
- cada ID de modelo de produção está em `GET /v1/models?format=openai`;
- uma solicitação sem streaming e uma com streaming passam por `/v1/chat/completions` ou `/v1/responses`, usando o mesmo caminho de cliente da produção;
- os fluxos de chamada de ferramentas e de saída estruturada passam com prompts reais;
- as falhas de chave inválida e de modelo inválido são tratadas;
- uma solicitação com falha pode ser consultada com `GET /v1/generations?id=<request_id>` e, quando `replay_supported` é `true`, refeita a partir de `replay_request`;
- os cabeçalhos e campos de resposta exclusivos do OpenRouter foram removidos ou normalizados, e os padrões compartilhados ficam em predefinições.

## Faça o rollout

1. Comece pelo tráfego interno.
2. Mova de 5% a 10% do tráfego de produção e compare qualidade, latência e custo.
3. Passe para 100% quando a paridade estiver confirmada.
4. Mantenha o rollback como uma troca de URL base e chave até a virada ficar estável.

## Entregue a migração a um agente de código

Dê ao agente esta sequência delimitada, ou instale a [skill de migração do OpenRouter para o Phaseo](https://github.com/phaseoteam/Phaseo/tree/main/.agents/skills/openrouter-to-phaseo-migration), que reúne as mesmas etapas de inventário, mapeamento, validação e rollback:

1. Procure no código de runtime e na configuração de implantação por `openrouter.ai`, `OPENROUTER_API_KEY`, `sk-or-v1`, `HTTP-Referer` e `X-Title`.
2. Troque a fronteira do cliente para `https://api.phaseo.app/v1` e `PHASEO_API_KEY` sem adicionar nenhum valor secreto ao controle de versão.
3. Consulte `GET /v1/models?format=openai` e registre cada mapeamento de modelo antigo para novo.
4. Adapte as opções de roteamento ou os campos de resposta exclusivos do OpenRouter em um único módulo de compatibilidade.
5. Execute as verificações de saúde, sem streaming, com streaming e de caminho de falha acima.
6. Relate os arquivos alterados, as mudanças de nomes de secrets, os mapeamentos de modelos, as evidências de teste, as lacunas de paridade e a chave de rollback.

Para uma versão guiada, abra o [guia interativo de migração do OpenRouter](https://phaseo.app/migrate/openrouter), veja como os dois se [comparam](https://phaseo.app/compare/openrouter) ou [receba ajuda gratuita na migração](https://phaseo.app/contact).
