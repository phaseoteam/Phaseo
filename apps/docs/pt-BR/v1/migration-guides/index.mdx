Escolha o guia de acordo com o que você está mudando: a plataforma que o app chama (abaixo) ou o modelo que ele usa ([migrações de modelo](../model-migrations)). Se você vai mudar os dois, migre a plataforma primeiro e mantenha o mesmo modelo até verificar o novo caminho.

Para uma lista de verificação personalizada, use o [Assistente de migração](https://phaseo.app/migrate).

<span id="platform-migrations"></span>
## Migrações de plataforma

Todo guia de plataforma segue a mesma ordem: troque a URL base e a chave, mapeie os IDs de modelo, mapeie os recursos da plataforma e, por fim, teste e faça o rollout mantendo o rollback como uma troca de URL base e chave.

| Você chama | Sinais no código | Guia |
| --- | --- | --- |
| A OpenAI diretamente | `api.openai.com`, `OPENAI_API_KEY`, `AzureOpenAI` | [SDK da OpenAI](./from-openai) |
| A Anthropic diretamente | `api.anthropic.com`, `ANTHROPIC_API_KEY`, `@anthropic-ai/sdk` | [SDK da Anthropic](./from-anthropic) |
| OpenRouter | `openrouter.ai`, `OPENROUTER_API_KEY`, chaves `sk-or-v1` | [OpenRouter](./from-openrouter) |
| Vercel AI Gateway | `ai-gateway.vercel.sh`, `@ai-sdk/gateway`, modelos como string simples em chamadas do AI SDK | [Vercel AI Gateway](./from-vercel) |
| LLM Gateway | `api.llmgateway.io`, `LLM_GATEWAY_API_KEY` | [LLM Gateway](./from-llmgateway) |
| Um proxy LiteLLM | `config.yaml` com `model_list`, variáveis `LITELLM_*`, porta 4000 | [LiteLLM](./from-litellm) |
| Cloudflare AI Gateway | `gateway.ai.cloudflare.com`, cabeçalhos `cf-aig-*` | [Cloudflare AI Gateway](./from-cloudflare) |
| Helicone | `*.helicone.ai`, `Helicone-Auth` | [Helicone](./from-helicone) |

Para planejar e conferir o rollout, use a [Lista de verificação de recursos para migração](./feature-parity-matrix).

## Migrações de modelo

Use um [guia de migração de modelo](../model-migrations) quando a integração continua a mesma, mas o modelo muda. Cada guia aborda mudanças nos parâmetros da solicitação, alterações no comportamento de prompts e de raciocínio, diferenças em saída estruturada e chamada de ferramentas, e como fazer o rollout com um fallback.

Em qualquer tipo de migração, confira os parâmetros da solicitação e o comportamento do endpoint antes de comparar a qualidade da saída, e execute avaliações parecidas com a produção antes de mover tráfego real.
