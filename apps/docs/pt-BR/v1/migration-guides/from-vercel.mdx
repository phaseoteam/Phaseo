No código com AI SDK, troque `@ai-sdk/gateway` por `@phaseo/ai-sdk-provider` e envolva cada ID de modelo com `phaseo(...)`. Em clientes compatíveis com OpenAI, troque a URL base e a chave. A lógica de geração continua a mesma.

| Configuração | Vercel AI Gateway | Phaseo |
| --- | --- | --- |
| URL base | `https://ai-gateway.vercel.sh/v1` | `https://api.phaseo.app/v1` |
| Chave de API | `AI_GATEWAY_API_KEY` ou OIDC da Vercel | `PHASEO_API_KEY`, como secret do lado do servidor |
| Provedor do AI SDK | `@ai-sdk/gateway` ou modelos como string simples | `@phaseo/ai-sdk-provider` |
| Opções de roteamento | `providerOptions.gateway` | `providerOptions.phaseo` |

## Troque o provedor

<CodeGroup>
```typescript AI SDK
import { generateText } from "ai";
// Antes: import { gateway } from "@ai-sdk/gateway";
import { phaseo } from "@phaseo/ai-sdk-provider";

const { text } = await generateText({
  // Antes: model: gateway("openai/gpt-4.1-mini"),
  model: phaseo("openai/gpt-4.1-mini"),
  prompt: "Generate a migration checklist.",
});
```

```typescript OpenAI SDK
import OpenAI from "openai";

// Antes:
// new OpenAI({ apiKey: process.env.AI_GATEWAY_API_KEY, baseURL: "https://ai-gateway.vercel.sh/v1" });
const client = new OpenAI({
  apiKey: process.env.PHASEO_API_KEY,
  baseURL: "https://api.phaseo.app/v1",
});
```

```bash cURL
curl -s "https://api.phaseo.app/v1/chat/completions" \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-6-astra",
    "messages": [{"role":"user","content":"Hello"}]
  }'
```
</CodeGroup>

O export padrão `phaseo` lê `PHASEO_API_KEY` uma única vez, quando o módulo é importado, e usa `https://api.phaseo.app/v1`. Se a variável for definida depois dos imports, como em algumas configurações serverless e de testes, toda chamada lança um erro de chave ausente; nesse caso, chame `createPhaseo({ apiKey, baseURL, headers })` dentro do handler.

Instale a linha do provedor que corresponde à versão principal do seu `ai`: `@phaseo/ai-sdk-provider` para o AI SDK 7, `@phaseo/ai-sdk-provider@ai-sdk-v6` para o AI SDK 6 e `@phaseo/ai-sdk-provider@ai-sdk-v5` para o AI SDK 5.

Por padrão, o AI SDK envia modelos como string simples (`model: "openai/gpt-4.1-mini"`) pelo gateway da Vercel, então uma string simples esquecida continua chamando esse gateway. Altere uma vez a fábrica de modelos compartilhada e depois procure `model: "` nas chamadas do AI SDK. Clientes do SDK da Anthropic apontados para `ai-gateway.vercel.sh` passam para a configuração descrita em [Migração do SDK da Anthropic](./from-anthropic).

## Mapeie as opções do gateway

`providerOptions.phaseo` é mesclado ao corpo da solicitação. Um `providerOptions.gateway` esquecido é ignorado sem erro.

| Vercel AI Gateway | No Phaseo |
| --- | --- |
| `providerOptions.gateway.order`, `.only` | `providerOptions: { phaseo: { provider: { order, only } } }` ou uma [predefinição](../guides/presets) chamada como `phaseo("@slug")`. |
| `providerOptions.gateway.models` | `providerOptions: { phaseo: { models: [...] } }` ou fallbacks em uma rota dinâmica. |
| `providerOptions.gateway.sort` (`cost`, `ttft`, `tps`) | `provider.sort` (`price`, `latency`, `throughput`). |
| `providerOptions.gateway.zeroDataRetention` | `provider.require_zero_data_retention`, que limita o roteamento a provedores com ZDR. |
| `providerOptions.gateway.user`, `.tags` | `user` e [rótulos](../guides/request-labels) `X-Phaseo-Metadata`. |
| Credenciais `byok` por solicitação | Sem equivalente. Adicione chaves de provedores ao espaço de trabalho com `phaseo byok create`. |
| Texto, streaming, ferramentas, saída estruturada, embeddings, imagens, transcrição, fala | Com suporte no provedor; os recursos ainda dependem do modelo. |
| Reranking | `phaseo.rerankingModel(id)` nas linhas do AI SDK 6 e 7. |
| Referências a arquivos gerenciados, ferramentas executadas pelo provedor | Sem suporte. Partes sem suporte falham com um erro em vez de serem descartadas. |
| Painel de uso do gateway | Logs de solicitações do Phaseo e `GET /v1/generations?id=<request_id>`. Os metadados do provedor nos resultados incluem o ID da solicitação. |

## Teste e faça o rollout

Execute o mesmo conjunto de prompts pelos dois caminhos e compare latência, formato da saída e uso de tokens. Antes de promover o tráfego, confirme que:

- `PHASEO_API_KEY` está definida em todo runtime que tinha a chave do gateway, incluindo edge, servidor e implantações de preview;
- o caminho principal de geração de texto e um teste de streaming passam sem alterações em staging;
- chamadas de ferramentas e saídas estruturadas passam, se o app as usa;
- o mapeamento de erros no nível da aplicação continua funcionando;
- uma solicitação de staging com falha pode ser encontrada e, quando `replay_supported` é `true`, refeita a partir de `GET /v1/generations?id=<request_id>`.

Lance atrás de uma feature flag ou de um rollout por porcentagem, começando pelo tráfego interno. Acompanhe a latência, a taxa de erros e os desvios de tokens e custo, e mantenha o provedor antigo disponível por pelo menos uma release para que o rollback não exija mudança de código.

```bash
curl -s "https://api.phaseo.app/v1/health"
curl -s "https://api.phaseo.app/v1/models?format=openai" -H "Authorization: Bearer $PHASEO_API_KEY"
```

Para saber mais sobre o provedor, veja [AI SDK](../guides/integrations/ai-sdk).
