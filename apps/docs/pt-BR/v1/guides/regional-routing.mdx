title: "Rotear solicitações de texto por região"
description: "Restrinja a geração de texto do Phaseo a rotas de provedores na UE ou nos EUA."
---

Envie solicitações de texto para `eu.api.phaseo.app` ou `us.api.phaseo.app` para usar apenas rotas de provedores que executam o modelo e tratam os dados de prompt e de resposta nessa região. Os IDs de modelo e as chaves de API continuam os mesmos. Chat Completions, Responses e Messages são aceitos.

| Região | URL base | Rotas de provedores usadas |
| --- | --- | --- |
| União Europeia | `https://eu.api.phaseo.app/v1` | Apenas rotas que declaram execução na UE e tratamento de dados na UE |
| Estados Unidos | `https://us.api.phaseo.app/v1` | Apenas rotas que declaram execução nos EUA e tratamento de dados nos EUA |
| Global | `https://api.phaseo.app/v1` | A política de roteamento global padrão |

<Warning>
O roteamento regional ainda não é uma garantia de residência de dados de ponta a ponta. O Phaseo restringe a seleção de provedores e posiciona o gateway perto da região, mas os sistemas compartilhados de conta, cobrança, cache e operações podem processar dados fora dela. Veja [O que fica fora da região](#what-stays-outside-the-region).
</Warning>

## Enviar uma solicitação regional

<CodeGroup>
```ts TypeScript
import { Phaseo } from "@phaseo/sdk";

const phaseo = new Phaseo({
  apiKey: process.env.PHASEO_API_KEY!,
  region: "eu",
});

const response = await phaseo.responses.create({
  model: "openai/gpt-5.6-luna",
  input: "Summarize this note in one sentence.",
});

console.log(response.output_text);
```

```python Python
import os
from phaseo import Phaseo

phaseo = Phaseo(
    api_key=os.environ["PHASEO_API_KEY"],
    region="eu",
)

response = phaseo.responses.create({
    "model": "openai/gpt-5.6-luna",
    "input": "Summarize this note in one sentence.",
})

print(response.get("output_text"))
```

```bash Chat Completions
curl https://eu.api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5.6-luna",
    "messages": [
      {"role": "user", "content": "Write a two-line status update."}
    ]
  }'
```

```bash Responses
curl https://eu.api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5.6-luna",
    "input": "Extract the three most important actions from this note."
  }'
```

```bash Messages
curl https://us.api.phaseo.app/v1/messages \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -H "anthropic-version: 2023-06-01" \
  -d '{
    "model": "anthropic/claude-sonnet-5.5",
    "max_tokens": 256,
    "messages": [
      {"role": "user", "content": "Summarize this incident report."}
    ]
  }'
```
</CodeGroup>

Nos SDKs, defina `region` como `"eu"` ou `"us"`; omita-o, ou use `"global"`, para o roteamento global. O SDK lança um erro se você definir `region` e uma `baseUrl` personalizada (`base_url` em Python) ao mesmo tempo, porque eles escolhem hosts diferentes.

O hostname é a política. Um `required_execution_region` ou `required_data_region` na solicitação ou em uma predefinição que indique outra região falha com `400 validation_error`, motivo `deployment_region_conflict`. As predefinições e as regras de roteamento dinâmico são aplicadas primeiro e a regra regional por último, então elas não conseguem enfraquecê-la. O Phaseo nunca tenta de novo por um provedor fora da região.

## O que uma solicitação regional pode conter

| Aceito | Rejeitado |
| --- | --- |
| Entrada e saída de texto | Imagens, áudio, vídeo, documentos, arquivos e anexos |
| Com e sem streaming | Modalidades de saída que não sejam texto |
| Instruções de sistema e de desenvolvedor | Ferramentas hospedadas pelo provedor, como pesquisa na web, pesquisa em arquivos, execução de código, uso do computador e geração de imagens, e `web_search_options` |
| Suas próprias ferramentas `function` e `custom`, e resultados de ferramentas em texto | [Ferramentas de servidor](./server-tools) do Phaseo (tipos `phaseo:`) |
| Saída de texto estruturado e JSON, quando o modelo aceita | Endpoints de imagem, áudio, vídeo, embedding, moderação, lote, arquivo, webhook e tempo real |
| Predefinições, ordem de provedores, alternativas e limites de preço que não entrem em conflito com a região | |

Suas próprias ferramentas são permitidas porque são executadas no seu aplicativo. As ferramentas hospedadas e de servidor são executadas em lugares que a regra regional não controla.

## Encontrar os modelos disponíveis em uma região

Chame `/v1/models` no mesmo hostname para o qual você envia as solicitações. A disponibilidade muda entre os endpoints da UE, dos EUA e global.

```bash
curl https://eu.api.phaseo.app/v1/models \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

A lista contém apenas modelos com uma rota de provedor ativa cujas regiões de execução e de dados declaradas incluem a região, e anuncia apenas Chat Completions, Responses e Messages com entrada e saída de texto. Cada oferta mostra suas regiões:

```json
{
  "provider": { "id": "example-eu", "name": "Example EU" },
  "residency": {
    "execution_regions": ["eu"],
    "data_regions": ["eu"]
  }
}
```

## Verificar qual gateway tratou uma solicitação

As respostas regionais trazem `X-Phaseo-Gateway-Region: eu` (ou `us`). O cabeçalho indica a política regional que tratou a solicitação; ele não prova onde a Cloudflare a executou. Os detalhes da solicitação também registram as regiões de execução e de dados exigidas, o provedor selecionado e as regiões declaradas por esse provedor.

## Erros

Violações da regra regional retornam `400 not_supported` com um destes valores de `reason`:

| `reason` | Causa | Correção |
| --- | --- | --- |
| `regional_endpoint_not_supported` | O caminho não está disponível regionalmente | Use Chat Completions, Responses ou Messages, ou a API global |
| `regional_non_text_content` | Mídia, arquivo ou anexo na solicitação | Remova-o ou use a API global |
| `regional_non_text_output` | Foi solicitada uma modalidade de saída que não é texto | Peça texto ou use a API global |
| `regional_hosted_tool_not_supported` | Uma ferramenta que não é `function` nem `custom` | Use a sua própria ferramenta de função ou a API global |

`400 validation_error` com o motivo `deployment_region_conflict` significa que a solicitação ou uma predefinição indica outra região; remova essa configuração. Se nenhuma rota de provedor saudável atender ao modelo e à região, a solicitação para antes de qualquer provedor ser chamado; escolha um modelo listado pelo `/v1/models` regional.

## O que fica fora da região

A regra regional cobre qual provedor executa o modelo e trata os dados de prompt e de resposta. Ela ainda não cobre todo o ciclo de vida da solicitação:

- O posicionamento da Cloudflare coloca o gateway perto da região, mas isso não é uma fronteira de conformidade.
- Os metadados de conta, autenticação, cobrança e solicitações ficam na infraestrutura compartilhada do Supabase.
- O Cloudflare KV e os logs de invocação do Worker não ficam restritos à região.
- As chamadas ao provedor vão para o endpoint regional desse provedor, independentemente de onde a Cloudflare posicionou o gateway.
- As equipes de suporte e operações não ficam restritas à região.

O Phaseo só vai chamar isso de residência de dados de ponta a ponta quando o gateway, o armazenamento, os registros, o provedor e os caminhos operacionais tiverem controles regionais aplicáveis.
