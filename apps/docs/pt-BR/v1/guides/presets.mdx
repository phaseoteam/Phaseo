Uma predefinição guarda o modelo, o prompt de sistema, os parâmetros e as regras de provedor de uma tarefa sob um nome como `@support-triage`. Quem chama envia esse nome como `model` e apenas a entrada; o Gateway preenche o resto antes de escolher um provedor.

Ative e desative os campos da solicitação para ver qual valor prevalece:

<PresetMergeExplorer locale="pt-BR" />

As regras são:

- **Os parâmetros preenchem lacunas.** Os parâmetros padrão de uma predefinição só se aplicam aos campos que a solicitação omite. Um valor na solicitação sempre prevalece.
- **Os prompts de sistema se somam.** O prompt da predefinição vem primeiro. Se a solicitação tiver o próprio prompt de sistema ou `instructions`, ele vem depois de uma linha em branco.
- **As configurações de provedor da solicitação prevalecem.** Campos como `provider.order` ou `provider.max_price` na solicitação substituem o valor da predefinição para aquele campo.
- **As listas de permissão restringem, nunca ampliam.** As listas de provedores permitidos e ignorados da predefinição são aplicadas antes da seleção do provedor, então também limitam quais provedores uma alternativa pode usar. Um modelo fora dos modelos permitidos da predefinição falha com um `validation_error` cuja palavra-chave de detalhe é `preset_model_not_allowed`; ele não é redirecionado.

## Criar e usar uma predefinição

<Steps>
<Step title="Crie a predefinição">

Abra **Painel -> Configurações -> Predefinições** e crie uma predefinição com um slug como `support-triage`. Adicione apenas os padrões que todos os solicitantes devem compartilhar.

Para criar por um script, chame `POST /v1/presets` com uma chave de gerenciamento.

</Step>

<Step title="Chame-a pelo nome">

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "@support-triage",
    "input": "Customer says the invoice total is wrong."
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const response = await client.generateResponse({
  model: "@support-triage",
  input: "Customer says the invoice total is wrong.",
});
```

```python Python
from phaseo import Phaseo

client = Phaseo(api_key="YOUR_API_KEY")

response = client.generate_response({
    "model": "@support-triage",
    "input": "Customer says the invoice total is wrong.",
})
```
</CodeGroup>

</Step>

Abra a solicitação em **Gateway -> Uso** para ver quais padrões da predefinição foram aplicados e qual provedor a atendeu.

## O que uma predefinição pode conter

| Configuração | Efeito |
| --- | --- |
| Modelo | Usado quando a solicitação é enviada com o nome da predefinição. |
| Modelos permitidos | IDs de modelo ou padrões como `anthropic/*`. Outros modelos são rejeitados. |
| Prompt de sistema | Inserido no início de cada solicitação. |
| [Template de prompt](./prompt-templates) | Mensagens com `{{variables}}` que cada solicitação preenche. |
| Parâmetros padrão | `temperature`, `top_p`, `max_tokens`, configurações de raciocínio e semelhantes. |
| Regras de provedor | Listas de permitidos e ignorados, ordem dos provedores, regiões, tetos de preço. |

Mantenha a lógica específica de cada solicitante no seu aplicativo e use predefinições separadas quando os fluxos de trabalho precisarem de prompts, roteamento ou cache diferentes.

## Referenciar uma predefinição pelo nome

Envie uma predefinição pelo campo `model` ou, quando ela tiver um [template de prompt](./prompt-templates), por `prompt.id`. Não existe um campo `preset` separado.

| Forma | Onde é resolvida |
| --- | --- |
| `@support-triage` | No espaço de trabalho da chave de API (predefinições privadas e do espaço de trabalho). |
| `@octavia/support-triage` | Em qualquer espaço de trabalho (predefinições públicas, publicadas pelo usuário `octavia`). |
| `@support-triage@v3` | Naquela versão publicada. |
| `@support-triage@production` | Na versão para a qual o rótulo `production` aponta. |

Publicar uma predefinição pública exige um perfil público habilitado e um nome de usuário. Os nomes de usuário são únicos em todo o Phaseo; os slugs só precisam ser únicos para cada publicador. Os slugs são convertidos para minúsculas e podem conter letras, números, `-`, `_`, `.` e `:`.

## Versionar e reverter

Salvar edita um rascunho privado. **Publicar nova versão** transforma o rascunho em uma versão numerada e imutável e mantém todas as anteriores.

Escolha como os rótulos de versão aparecem:

| Formato | Exemplo |
| --- | --- |
| Sequencial | `v1`, `v2`, `v3` |
| Versionamento semântico | `1.2.0`, `2.0.0-beta.1`, `1.4.2+build.7` |
| Data | `2026.08.02` e, depois, `2026.08.02.2` para uma segunda versão no mesmo dia |

Aponte um rótulo com nome, como `production`, para uma versão e mova-o de volta para uma versão anterior para reverter. Veja [Versões e rótulos](/pt-BR/v1/guides/prompt-templates#versions-and-labels).

Por um script, publique com `POST /v1/presets/{id}/versions` e mova rótulos com `PUT /v1/presets/{id}/labels/{label}`, usando uma chave de gerenciamento. Um login pela CLI ou um app que usa Entrar com Phaseo pode ler predefinições, mas não alterá-las.

## Fazer fork de uma predefinição do marketplace

Uma cópia de uma predefinição do marketplace fica fixada na versão que você copiou. Quando o publicador lança uma atualização, sua cópia mostra um aviso. Aplicá-la altera apenas o seu rascunho, então nada chega à produção até que você mesmo publique.

O Phaseo registra a origem e toda a ancestralidade de cada fork, para que a página do marketplace possa mostrar os forks diretos separados de todos os descendentes.

Para coletar avaliações das respostas de uma predefinição, veja [Coletar feedback de predefinições](./preset-feedback).
