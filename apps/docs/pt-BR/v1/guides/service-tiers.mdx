Defina `service_tier` em uma solicitação de texto para pagar por uma entrega mais rápida (`fast`, `ultrafast`) ou aceitar um modo mais barato e de prioridade menor (`flex`). O Phaseo então roteia apenas para provedores que oferecem esse nível para o modelo. O campo funciona da mesma forma em `/v1/chat/completions`, `/v1/responses` e `/v1/messages`.

```json
{
  "model": "openai/gpt-5.5",
  "input": "Summarise this incident report.",
  "service_tier": "fast"
}
```

| Nível | Como solicitar | Use para |
| --- | --- | --- |
| Standard | Nada, ou `"standard"` / `"default"` | Tráfego de produção em geral |
| Fast | `"fast"`, ou o alias `"priority"` | A oferta premium ou de prioridade maior do provedor |
| Ultrafast | `"ultrafast"` | A oferta de maior velocidade |
| Flex | `"flex"` | Uma oferta de custo menor, quando o provedor tem uma |
| Batch | A [Batch API](../api-reference/endpoint/batches-create.mdx), não `service_tier` | Grandes cargas de trabalho adiadas |

Os níveis só estão disponíveis para modelos de texto, e apenas onde o modelo e o provedor os aceitam. As páginas dos modelos mostram preços específicos por nível quando o Phaseo os tem.

## O que acontece quando um nível não é oferecido

O Phaseo mantém apenas as rotas de provedores que oferecem o nível solicitado; ele nunca passa para outro nível. Se nenhuma rota o oferecer, a solicitação falha com `400 unsupported_model_or_endpoint`, motivo `service_tier_not_supported`.

Outros valores falham com `400 validation_error`:

- `service_tier: "batch"` em uma solicitação síncrona (palavra-chave `batch_service_tier_not_supported`). Use a Batch API.
- Qualquer valor diferente de `standard`, `default`, `fast`, `ultrafast`, `priority`, `flex` ou `batch` (palavra-chave `unsupported_service_tier`).

Você sempre envia esses valores do gateway. O Phaseo os traduz para os controles de cada provedor; uma rota da Anthropic, por exemplo, recebe os campos de nível da Anthropic.

## Solicitar um nível em cada endpoint

<CodeGroup>
```json Responses
{
  "model": "openai/gpt-5.5",
  "input": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "flex"
}
```

```json Chat Completions
{
  "model": "openai/gpt-5.5",
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "flex"
}
```

```json Messages
{
  "model": "anthropic/claude-opus-5.5",
  "max_tokens": 512,
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "fast"
}
```
</CodeGroup>

Para `ultrafast`, use um modelo cuja página liste preços Ultrafast.

## Mistral Priority e roteamento na UE

O Priority Tier da Mistral exige uma conta enterprise elegível da Mistral. O Phaseo mapeia `priority` para o modo de prioridade automática da Mistral e cobra o nível que a Mistral informa: se a Mistral recorrer ao Standard, você paga os preços do Standard.

Um preço no catálogo não torna um nível roteável. O Priority fica desativado, a menos que a rota específica da Mistral anuncie suporte a Priority, e a elegibilidade continua dependendo da conta e do modelo da Mistral.

O GLM 5.2 pode ser fixado no endpoint regional da Mistral na UE com a oferta de provedor `mistral-eu`:

```json
{
  "model": "z-ai/glm-5.2",
  "messages": [
    { "role": "user", "content": "Summarise this incident report." }
  ],
  "service_tier": "priority",
  "provider": {
    "only": ["mistral-eu"],
    "required_execution_region": "eu"
  }
}
```

A inferência regional da Mistral custa 10% a mais. Os preços de Batch só estão disponíveis na oferta global da Mistral pela Batch API; a Mistral não oferece Batch nos endpoints regionais.

A referência completa dos campos está em [Parâmetros](../api-reference/parameters.mdx); para saber como os níveis se combinam com a ordem de provedores e as alternativas, veja [Roteamento e alternativas](./routing-and-fallbacks.mdx).
