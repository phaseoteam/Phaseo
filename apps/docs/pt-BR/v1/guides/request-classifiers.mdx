Defina uma taxonomia, como departamento, público ou tipo de tarefa, e um modelo para aplicá-la, e o Phaseo rotula cada solicitação concluída com as respostas desse modelo. Cada resposta é armazenada como um [rótulo de solicitação](/pt-BR/v1/guides/request-labels), então você filtra e agrupa registros, uso e análises por ela exatamente como faz com os rótulos que o seu código envia. Use um classificador quando o seu código não souber a categoria: para quem um prompt foi escrito, que tipo de trabalho um agente está fazendo ou se uma solicitação envolve um tema regulado.

<Note>
Os classificadores de solicitações estão em beta. Proprietários e administradores os gerenciam em **Configurações → Classificadores** ou com a API de gerenciamento `/v1/classifiers`, usando uma [chave de gerenciamento](/pt-BR/v1/developers/management-api-keys) com os escopos `classifiers:*`.
</Note>

## Como uma solicitação é classificada

1. A solicitação termina e a resposta dela é devolvida ao seu aplicativo. A classificação nunca adiciona latência.
2. O Phaseo monta uma transcrição da solicitação: instruções de sistema, mensagens, nomes de ferramentas (não os esquemas delas) e resultados de ferramentas. Cada turno é limitado a 4.000 caracteres, e segredos como chaves de API são ocultados. Se o classificador incluir a resposta, a saída gerada também é adicionada.
3. O modelo classificador escolhe entre os seus valores. Qualquer resposta fora deles é descartada (veja [Escolher um modelo](#choose-a-model)).
4. As respostas são armazenadas como rótulos na solicitação, com a confiança de cada resposta, antes de a solicitação aparecer nos seus registros.

Os classificadores são executados em solicitações bem-sucedidas de `chat/completions`, `responses` e `messages`. Se a classificação falhar ou exceder o tempo limite, a solicitação continua sendo registrada, só que sem esses rótulos.

## Criar um classificador

Comece a partir de uma predefinição no painel ou envie você mesmo a taxonomia:

```bash
curl https://api.phaseo.app/v1/classifiers \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Department",
    "model": "google/gemini-2.5-flash-lite",
    "dimensions": [{
      "key": "department",
      "name": "Department",
      "allow_other": true,
      "values": [
        { "value": "engineering", "description": "Writing, reviewing, or debugging code" },
        { "value": "legal", "description": "Contracts, policies, and compliance" },
        { "value": "sales" },
        { "value": "support" }
      ]
    }],
    "sample_rate": 0.25,
    "monthly_budget_usd": 20
  }'
```

| Campo | Significado |
| --- | --- |
| `dimensions` | De 1 a 12 perguntas. Cada `key` vira a chave do rótulo; cada dimensão lista de 2 a 50 valores (1 com `allow_other`). |
| `multiple` | Permite mais de um valor para uma dimensão. Cada valor vira um rótulo próprio com a mesma chave. |
| `allow_other` | Deixa o modelo responder `other` quando nada se encaixa. |
| `instructions` | Orientações extras adicionadas ao prompt de classificação, com até 8.000 caracteres. |
| `sample_rate` | Parcela das solicitações elegíveis a classificar, de `0.0001` a `1`. |
| `sample_by` | `request` faz a amostragem de cada solicitação. `session` mantém uma sessão inteira dentro ou fora e reutiliza as respostas dela por uma hora, então uma execução longa de agente é classificada uma única vez. |
| `input_scope` | `prompt` classifica a solicitação. `prompt_and_response` também mostra a resposta ao modelo. |
| `scope` | Classifica apenas solicitações destes `key_ids`, `app_ids` ou `models`, com até 50 de cada. |
| `monthly_budget_usd` | Pausa o classificador pelo resto do mês UTC quando ele gastar esse valor. |

Um espaço de trabalho pode ter até cinco classificadores. As alterações chegam ao gateway em cerca de um minuto.

## Escolher um modelo

Qualquer modelo de texto ou [modelo de decisão](/pt-BR/v1/api-reference/endpoint/decisions) pode classificar. O Phaseo escolhe como fazer a pergunta com base no que os provedores do modelo aceitam:

| Modelo | Como a pergunta é feita |
| --- | --- |
| Modelo de texto com saídas estruturadas | Uma solicitação `responses` com um esquema JSON estrito, para que cada resposta seja um dos seus valores. |
| Modelo de decisão | Uma solicitação `decisions` com uma pergunta de escolha por dimensão. Uma dimensão com `multiple` faz uma pergunta de sim/não por valor e mantém todos os valores com probabilidade de pelo menos 0.5 (se um classificador precisasse de mais de 128 perguntas, essa dimensão recebe apenas o melhor valor). A confiança é a probabilidade do próprio modelo. |
| Outros modelos de texto | Uma solicitação `responses` que pede o mesmo JSON no prompt. Respostas fora dos seus valores são descartadas, então uma dimensão pode ficar sem rótulo com mais frequência. Este também é o caminho alternativo quando um provedor recusa o esquema. |

Um modelo pequeno e rápido normalmente é suficiente. Use **Testar com um exemplo** no editor do classificador para verificar um modelo antes de salvar.

## Filtrar e agrupar pelos resultados

As respostas dos classificadores são rótulos de solicitação comuns:

- Em **Registros** e **Uso**, filtre por um rótulo como `department` = `legal`.
- Na API, use `label_key` e `label_value`:

```text
GET /v1/analytics?label_key=department&label_value=legal
```

- Os destinos de [Broadcast](/pt-BR/v1/guides/integrations/observability) recebem os rótulos como atributos de span `phaseo.label.<key>`.

Se o seu código já enviar um rótulo com a chave de uma dimensão, o Phaseo mantém o seu valor e pula essa dimensão. Quando dois classificadores usam a mesma chave, prevalece o que foi criado primeiro.

## Custo e privacidade

- Cada classificação é uma solicitação separada ao modelo classificador, feita com a mesma chave de API ou o mesmo token OAuth da solicitação original. Ela é cobrada pelo preço normal desse modelo e segue as configurações de provedor, retenção de dados e BYOK do seu espaço de trabalho.
- As solicitações do classificador levam o rótulo `phaseo.classifier` com o ID do classificador, para que você veja o gasto delas em **Uso**. Elas não são classificadas e não contam para as suas políticas de limite de taxa.
- Mantenha os custos baixos com um modelo pequeno e rápido, uma taxa de amostragem, amostragem por sessão, um escopo ou um orçamento mensal.
- A transcrição vai apenas para o modelo classificador. A solicitação do classificador é registrada como qualquer outra, então o armazenamento da entrada dela segue as configurações de registro do seu espaço de trabalho.
