Crie um espaço de trabalho para cada equipe, produto ou ambiente para manter separados as chaves de API, as configurações de roteamento, as predefinições, os guardrails e o acesso administrativo de cada um. Toda conta começa com um espaço de trabalho pessoal, que basta para uma integração pequena.

Espaços de trabalho separados ajudam quando você quer:

- isolar as credenciais de desenvolvimento, staging e produção
- manter produtos ou projetos de clientes separados
- dar a uma integração administrativa acesso só aos recursos de que ela precisa
- aplicar políticas diferentes de roteamento, predefinições ou guardrails

Os espaços de trabalho não mudam o seu preço: todo o uso continua no faturamento padrão de pagamento conforme o uso, descrito em [Preços e faturamento](../pricing/tiers). Espaços de trabalho adicionais são liberados depois do seu primeiro depósito de créditos; até lá, criar um falha com `403 workspace_upgrade_required`.

## Gerenciar espaços de trabalho pela API

Gerencie os espaços de trabalho no painel ou com a API de gerenciamento. A API precisa de uma [chave de gerenciamento](../developers/management-api-keys); as chaves de API comuns do Gateway servem para inferência e não podem chamar esses endpoints.

| Tarefa | Endpoint | Capacidade |
| --- | --- | --- |
| Listar espaços de trabalho | [`GET /workspaces`](../api-reference/endpoint/workspaces-list) | `workspaces:read` |
| Ler um espaço de trabalho | [`GET /workspaces/{id}`](../api-reference/endpoint/workspaces-get) | `workspaces:read` |
| Criar um espaço de trabalho | [`POST /workspaces`](../api-reference/endpoint/workspaces-create) | `workspaces:write` |
| Atualizar um espaço de trabalho | [`PATCH /workspaces/{id}`](../api-reference/endpoint/workspaces-update) | `workspaces:write` |
| Excluir um espaço de trabalho | [`DELETE /workspaces/{id}`](../api-reference/endpoint/workspaces-delete) | `workspaces:delete` |

Dê à chave só as capacidades de que ela precisa. O Phaseo também verifica a participação e o papel no espaço de trabalho, então uma capacidade sozinha nunca dá acesso a outro espaço de trabalho. O `slug` de um novo espaço de trabalho precisa ter de 1 a 50 letras minúsculas, números ou hifens.

Guarde as chaves de gerenciamento em um armazenamento de segredos no servidor, nunca em código de navegador, registros do app de desktop, controle de versão ou chat.

<Note>
Os endpoints de espaços de trabalho estão em beta. Faça com que a sua automação possa ser repetida com segurança e confira cada resposta antes de fazer uma alteração seguinte.
</Note>

## Renomear ou excluir um espaço de trabalho

O espaço de trabalho pessoal (padrão) não pode ser renomeado nem excluído; as duas operações retornam `400 bad_request`. Antes de excluir outro espaço de trabalho, remova ou mova as chaves de API ativas dele para que nenhuma solicitação aponte para um espaço de trabalho que não existe mais.
