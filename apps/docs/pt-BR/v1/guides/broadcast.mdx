Adicione um destino em **Configurações → Transmissão** e o Phaseo envia a ele um rastreamento de cada solicitação do Gateway, sem alterações no código. O rastreamento segue as convenções GenAI do OpenTelemetry: um span para a solicitação e um span para cada tentativa em um provedor, com o modelo, o provedor, o uso de tokens, o custo, os tempos e (a menos que você desative) o prompt e a saída.

O Broadcast é gratuito. Proprietários e administradores gerenciam os destinos em **Configurações → Transmissão**, ou com a [API de destinos de observabilidade](/pt-BR/v1/api-reference/endpoint/observability-destinations-create) e uma [chave de gerenciamento](/pt-BR/v1/developers/management-api-keys) com `settings:write`. Um espaço de trabalho pode ter até cinco destinos de cada tipo. Para rastrear a partir do seu próprio cliente, consulte [Integrações de observabilidade](./integrations/observability.mdx).

## Adicione um destino

1. Abra **Configurações → Transmissão** e escolha um destino.
2. Informe as credenciais dele. Elas são criptografadas antes do armazenamento e nunca são exibidas novamente.
3. Escolha o que enviar (consulte [Escolha o que é enviado](#choose-what-is-sent)).
4. Selecione **Testar conexão**. O Phaseo envia um rastreamento de exemplo da mesma forma que as entregas reais, então uma falha aqui mostra o erro do próprio destino.
5. Salve. As solicitações concluídas a partir daí são enviadas em cerca de um minuto.

| Tipo | Destinos |
| --- | --- |
| Ferramentas OpenTelemetry | Arize AI, Axiom, Braintrust, Comet Opik, Datadog, Dynatrace, Elastic, Grafana Cloud, Honeycomb, Langfuse, LangSmith, New Relic, PostHog, Respan, Sentry, W&B Weave |
| Qualquer endpoint OTLP | OpenTelemetry Collector (OTLP/HTTP, JSON ou protobuf, gzip opcional) |
| Seu próprio serviço | Webhook |
| Armazenamento de objetos | Amazon S3 e armazenamentos compatíveis com S3, Cloudflare R2, Google Cloud Storage |
| Bancos de dados e data warehouses | ClickHouse, Google BigQuery, Snowflake |

Cada formulário pede apenas o que a ferramenta precisa, como uma chave de API e um projeto ou região. As ferramentas OpenTelemetry recebem os mesmos spans; o Phaseo preenche o endpoint, os cabeçalhos e a codificação de cada fornecedor.

<span id="choose-what-is-sent"></span>
## Escolha o que é enviado

Cada destino tem as próprias configurações:

- **Modo de Privacidade** deixa prompts, saídas, instruções de sistema e definições de ferramentas fora de todos os rastreamentos. Solicitações feitas com uma chave de API que nunca armazena conteúdo nunca são encaminhadas com conteúdo, seja qual for essa configuração.
- **Metadados de geração**, **Custo**, **Identidade** e **Contexto da solicitação** ativam ou desativam, cada um, um grupo de atributos de span. Desativar **Contexto da solicitação** também remove os [metadados da solicitação](#add-your-own-trace-context).
- **Taxa** envia uma parcela das solicitações elegíveis, de 0 a 1. A escolha é estável para cada solicitação e destino, então uma entrega repetida nunca é amostrada de forma diferente.
- **Filter by API key** inclui ou exclui solicitações feitas com chaves específicas.
- **Regras de filtro** enviam apenas as solicitações que correspondem. As regras comparam campos como modelo, provedor, ID do usuário, motivo de término, custo ou contagem de tokens, e podem ser agrupadas com **e** e **ou**. **Matches regex** usa um mecanismo de tempo linear: referências retroativas e lookaround não são compatíveis, e um padrão grande demais é rejeitado ao salvar.

## Adicione seu próprio contexto de rastreamento

Coloque um objeto `metadata` no corpo da solicitação para nomear os rastreamentos e anexar os seus próprios campos. O Phaseo o lê para o Broadcast:

```json
{
  "model": "openai/gpt-6-astra",
  "messages": [{ "role": "user", "content": "Summarise this ticket" }],
  "metadata": {
    "trace_id": "ticket-48213",
    "trace_name": "support-summary",
    "generation_name": "summarise",
    "customer_tier": "enterprise"
  }
}
```

| Chave | Efeito |
| --- | --- |
| `trace_id` | O rastreamento ao qual a solicitação pertence. Um ID hexadecimal de 32 caracteres ou um UUID é usado como está; qualquer outra string passa por hash, então todas as solicitações com o mesmo valor entram no mesmo rastreamento. |
| `parent_span_id` | Um ID de span hexadecimal de 16 caracteres sob o qual a solicitação será aninhada. Usado com `trace_id`. |
| `trace_name`, `span_name` | Nome do span da solicitação. `span_name` prevalece se os dois forem definidos. |
| `generation_name` | Nome do span de cada tentativa em um provedor. |
| Qualquer outra chave | Enviada como um atributo de span chamado `phaseo.metadata.<key>`. |

Os valores podem ser strings, números ou booleanos; objetos aninhados são ignorados. O Phaseo mantém até 64 chaves de no máximo 64 caracteres e corta os valores em 512 caracteres. Um cabeçalho W3C `traceparent`, quando presente, decide o rastreamento no lugar de `trace_id` e `parent_span_id`.

Não coloque segredos nem dados pessoais em `metadata`: ele é enviado a todos os destinos com **Contexto da solicitação** ativado.

Os [rótulos de solicitação](./request-labels.mdx) também são enviados, como atributos de span chamados `phaseo.label.<key>`.

## Entregas por webhook

Um webhook recebe um `POST` (ou `PUT`, se você escolher) por solicitação. O corpo é uma exportação OTLP/JSON, `{"resourceSpans": [...]}`, com os spans dessa solicitação. Use **Headers JSON** para adicionar os seus próprios cabeçalhos, como um cabeçalho `Authorization` que o seu endpoint espera.

Adicione um **Signing Secret** (de 16 a 256 caracteres, sem espaços) para que todas as entregas, testes e exemplos sejam assinados. O Phaseo adiciona então dois cabeçalhos:

```http
x-phaseo-timestamp: 1792569600
x-phaseo-signature: 5d2a…e41f
```

`x-phaseo-signature` é o HMAC-SHA256 em hexadecimal do timestamp, um ponto (`.`) e o corpo da solicitação sem modificações, usando o seu segredo como chave. É o mesmo esquema dos webhooks de notificação, então você pode reutilizar o [código de verificação](./workspace-notifications.mdx#verify-webhook-signatures) deles. As entregas do Broadcast não têm cabeçalho de ID de evento: elimine duplicados com base nos IDs de span do corpo.

**Testar conexão** envia `{"resourceSpans": []}` com um cabeçalho `X-Test-Connection: true`. Uma resposta `400` conta como acessível, então um receptor que rejeita exportações vazias ainda passa no teste.

## Linhas em armazenamento de objetos e data warehouses

O armazenamento de objetos, o ClickHouse, o BigQuery e o Snowflake recebem uma linha por span em vez de rastreamentos. Cada lote é gravado em uma única solicitação: um objeto ou uma inserção.

| Coluna | Tipo | Conteúdo |
| --- | --- | --- |
| `event_id` | string | O ID de evento da solicitação. Todos os spans de uma solicitação o compartilham. |
| `trace_id` | string | ID de rastreamento hexadecimal de 32 caracteres. |
| `span_id` | string | ID de span hexadecimal de 16 caracteres. |
| `parent_span_id` | string ou null | O span pai, ou null para o span da solicitação. |
| `name` | string | Nome do span. |
| `kind` | string | `server` para a solicitação, `client` para as tentativas em provedores. |
| `start_time`, `end_time` | timestamp | RFC 3339 em UTC, com precisão de microssegundos. |
| `duration_ms` | number | Fim menos início, em milissegundos. |
| `status_code` | string | `unset`, `ok` ou `error`. |
| `status_message` | string ou null | A mensagem de erro, se houver. |
| `service_name` | string ou null | `phaseo-gateway`. |
| `attributes` | object | Atributos do span por nome, como `gen_ai.request.model` ou `gen_ai.usage.input_tokens`, com os tipos preservados. |
| `resource_attributes` | object | Atributos do recurso, como `service.name`. |

Uma linha tem no máximo 512 KB. Quando um span carrega mais do que isso, como uma imagem inline, os maiores valores de atributos são cortados para dividir o espaço, cada um mantendo o início e terminando em `…[truncated]`, e os nomes deles são listados no atributo `phaseo.truncated_attributes`.

Um lote que falha é repetido. Se o destino o salvou mas a resposta se perdeu, a nova tentativa pode gravar algumas linhas duas vezes; use `event_id` e `span_id` para eliminar duplicados. O BigQuery e o Snowflake usam IDs de solicitação que evitam a maior parte dessas duplicações.

### Armazenamento de objetos

Cada lote é um arquivo JSON lines compactado com gzip. **Path Template** define a chave dele, por padrão `phaseo/{year}/{month}/{day}/{hour}/{uuid}`, e o Phaseo acrescenta `.jsonl.gz`. O modelo pode usar `{year}`, `{month}`, `{day}`, `{hour}`, `{date}` (`YYYY-MM-DD`) e `{uuid}`, e precisa incluir `{uuid}` para que os arquivos nunca se sobrescrevam. Os horários são em UTC.

- **Amazon S3**: uma chave de acesso com permissão `s3:PutObject` no bucket, e a região do bucket. Para um armazenamento compatível com S3, defina **S3-Compatible Endpoint**.
- **Cloudflare R2**: o ID da chave de acesso e o segredo de um token de API do R2, o ID da sua conta e a jurisdição, se o bucket estiver em uma (`eu` ou `fedramp`).
- **Google Cloud Storage**: uma chave HMAC de uma conta de serviço que possa criar objetos no bucket.

Os objetos são armazenados compactados, sem cabeçalho `Content-Encoding`, então as tabelas externas do Athena, do BigQuery e do Snowflake os leem pela extensão `.gz`.

### ClickHouse

As linhas são inseridas como `JSONEachRow` pela interface HTTPS, com inserções assíncronas. Colunas que a tabela não tem são ignoradas, então você pode manter apenas as que precisa:

```sql
CREATE TABLE phaseo_traces (
  event_id String, trace_id String, span_id String, parent_span_id Nullable(String),
  name String, kind LowCardinality(String),
  start_time DateTime64(6, 'UTC'), end_time DateTime64(6, 'UTC'), duration_ms Float64,
  status_code LowCardinality(String), status_message Nullable(String), service_name Nullable(String),
  attributes String, resource_attributes String
) ENGINE = MergeTree ORDER BY (start_time, trace_id);
```

Use o endpoint na porta 8443 para o ClickHouse Cloud. `attributes` e `resource_attributes` também podem ser colunas `JSON`.

### BigQuery

As linhas são enviadas em streaming com `insertAll`, usando os IDs de evento e de span como IDs de inserção. Crie uma conta de serviço com **BigQuery Data Editor** na tabela e cole o arquivo de chave JSON dela no formulário. `attributes` e `resource_attributes` precisam ser colunas `JSON`:

```sql
CREATE TABLE observability.phaseo_traces (
  event_id STRING, trace_id STRING, span_id STRING, parent_span_id STRING,
  name STRING, kind STRING, start_time TIMESTAMP, end_time TIMESTAMP, duration_ms FLOAT64,
  status_code STRING, status_message STRING, service_name STRING,
  attributes JSON, resource_attributes JSON
) PARTITION BY DATE(start_time) CLUSTER BY trace_id;
```

### Snowflake

Cada lote é um único `INSERT` pela SQL API, autenticado com par de chaves, então ele é executado no warehouse que você indicar. Crie um usuário para o Phaseo e atribua a ele uma chave RSA:

```sql
CREATE TABLE PHASEO.OBSERVABILITY.PHASEO_TRACES (
  EVENT_ID STRING, TRACE_ID STRING, SPAN_ID STRING, PARENT_SPAN_ID STRING,
  NAME STRING, KIND STRING, START_TIME TIMESTAMP_TZ, END_TIME TIMESTAMP_TZ, DURATION_MS FLOAT,
  STATUS_CODE STRING, STATUS_MESSAGE STRING, SERVICE_NAME STRING,
  ATTRIBUTES VARIANT, RESOURCE_ATTRIBUTES VARIANT
);
-- openssl genrsa 2048 | openssl pkcs8 -topk8 -nocrypt -out phaseo_key.p8
-- openssl rsa -in phaseo_key.p8 -pubout
ALTER USER PHASEO_BROADCAST SET RSA_PUBLIC_KEY = 'MIIBIjANBgkqh...';
```

Cole a chave privada (`BEGIN PRIVATE KEY`, sem criptografia) no formulário e use o identificador org-account, como `myorg-myaccount`. A função do usuário precisa de `INSERT` na tabela e de `USAGE` no warehouse, no banco de dados e no schema.

## Entrega, saúde e alertas

Entregas que falham por timeout, limite de taxa ou erro do servidor são repetidas com backoff, em até oito tentativas. Outros erros, como uma chave rejeitada ou uma tabela inexistente, não são repetidos.

**Configurações → Transmissão** mostra a saúde de cada destino: **Funcionando**, **Com falhas**, **Nenhuma entrega ainda** ou **Desativado**, com o último erro e as solicitações entregues e com falha nas últimas 24 horas.

Para ser avisado quando um destino parar de funcionar, encaminhe os **Alertas de Transmissão** para um [destino de notificação](./workspace-notifications.mdx). Um alerta é enviado quando um destino falhou em pelo menos cinco solicitações seguidas e não entregou nada por 15 minutos. Ele é enviado uma vez por sequência de falhas, e novamente só depois que o destino se recuperar e se passarem pelo menos seis horas.
