Coloque um ID de provedor e dois-pontos antes do ID do modelo, como `baseten:thinking-machines/inkling-small`, para executar a solicitação apenas nesse provedor, sem alternativa em outro provedor.

| Você quer | Envie como `model` |
| --- | --- |
| Que o Phaseo escolha um provedor e alterne entre provedores em caso de falha | `thinking-machines/inkling-small` |
| Apenas o Baseten, sem alternativa entre provedores | `baseten:thinking-machines/inkling-small` |
| Uma rota gratuita verificada em um único provedor | `google-ai-studio:google/gemma-4-26b-a4b:free` |

O formato é `<provider-id>:<canonical-model-id>`. Os primeiros dois-pontos separam o provedor; os dois-pontos depois do namespace do modelo continuam fazendo parte do ID do modelo. Em `google-ai-studio:google/gemma-4-26b-a4b:free`, o provedor é `google-ai-studio` e o modelo é `google/gemma-4-26b-a4b:free`.

Se você só prefere um provedor e quer uma alternativa quando ele falhar, use o ID de modelo simples com os [controles de roteamento e alternativas](./routing-and-fallbacks.mdx).

## Enviar uma solicitação

Use o ID qualificado em qualquer lugar onde o endpoint aceite um ID de modelo.

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "baseten:thinking-machines/inkling-small",
    "input": "Explain mixture-of-experts routing in two sentences."
  }'
```

```javascript JavaScript
const response = await fetch("https://api.phaseo.app/v1/responses", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "baseten:thinking-machines/inkling-small",
    input: "Explain mixture-of-experts routing in two sentences.",
  }),
});

const result = await response.json();
```

```python Python
import os
import requests

response = requests.post(
    "https://api.phaseo.app/v1/responses",
    headers={
        "Authorization": f"Bearer {os.environ['PHASEO_API_KEY']}",
        "Content-Type": "application/json",
    },
    json={
        "model": "baseten:thinking-machines/inkling-small",
        "input": "Explain mixture-of-experts routing in two sentences.",
    },
)

result = response.json()
```
</CodeGroup>

## O que o provedor ainda precisa atender

O qualificador restringe o roteamento a um provedor; ele não pula nenhuma outra verificação. O provedor ainda precisa:

- servir o modelo canônico no endpoint solicitado, com essa capacidade ativada
- atender às restrições do espaço de trabalho, da chave de API, da predefinição e de privacidade
- aceitar o nível de serviço e os parâmetros solicitados
- ter preços configurados

Se alguma verificação falhar, a solicitação é rejeitada. O Phaseo nunca escolhe outro provedor sem avisar.

## Combinar com os campos `provider` ou `routing`

O qualificador e os campos de roteamento explícitos precisam concordar. Um `provider.only` ou `routing.only` correspondente é aceito:

```json
{
  "model": "baseten:thinking-machines/inkling-small",
  "provider": { "only": ["baseten"] }
}
```

Uma lista de permitidos que indica outros provedores, ou uma lista de ignorados que contém o provedor qualificado, é rejeitada com `provider_qualified_model_conflict`:

```json
{
  "model": "baseten:thinking-machines/inkling-small",
  "provider": { "only": ["deepinfra"] }
}
```

## Solicitar uma rota gratuita em um provedor

Um modelo `:free` qualificado só é aceito quando esse provedor tem uma rota gratuita elegível para o modelo e o endpoint. Um modelo `:free` canônico não significa que todos os provedores do modelo subjacente o ofereçam de graça.

```json
{
  "model": "google-ai-studio:google/gemma-4-26b-a4b:free",
  "input": "Hello"
}
```

A tabela de preços da rota não pode estar vazia, e todas as regras de preço atuais dela precisam ter o rótulo `free` e preço exatamente zero. Preços ausentes, pagos, mistos ou negativos, ou uma regra com preço zero sem o rótulo `free`, rejeitam a solicitação antes de ela chegar ao provedor.

## IDs e aliases de provedores

Use um ID de provedor do catálogo de provedores do Phaseo (veja [Provedores de API](../exploring/api-providers)). Os IDs são convertidos para minúsculas, e aliases conhecidos de nomes antigos ou de marca são mapeados para o ID canônico: `NovitaAI` e `novita-ai` viram `novita`. IDs malformados e desconhecidos são rejeitados antes da seleção do provedor; eles nunca são enviados upstream como parte do nome do modelo.

## Erros de validação

Um ID qualificado inválido retorna HTTP `400` com o código de erro `validation_error`. `reason` e `details[].keyword` indicam a causa:

| Motivo | Significado |
| --- | --- |
| `invalid_provider_slug` | A parte do provedor está vazia ou contém caracteres não aceitos. |
| `unknown_provider_slug` | O ID do provedor está bem formado, mas não é um provedor do Phaseo. |
| `invalid_provider_qualified_model` | O ID não corresponde a `<provider>:<publisher>/<model>`. |
| `provider_qualified_model_conflict` | `provider.only`, `provider.ignore`, `routing.only` ou `routing.ignore` contradiz o qualificador. |
| `qualified_provider_unavailable` | O provedor existe, mas não serve esse modelo no endpoint solicitado. |
| `qualified_free_provider_unavailable` | A rota do provedor não está verificada como gratuita com todos os preços zerados. |

```json
{
  "error": "validation_error",
  "status_code": 400,
  "reason": "unknown_provider_slug",
  "description": "Unknown provider slug \"not-a-provider\" in provider-qualified model \"not-a-provider:publisher/model\". Use a provider slug returned by Phaseo's provider catalogue.",
  "provider": "not-a-provider",
  "model": "publisher/model",
  "details": [
    {
      "path": ["model"],
      "keyword": "unknown_provider_slug"
    }
  ]
}
```

Para outros formatos de erro, veja [Erros e depuração](../api-reference/errors.mdx).
