Salve suas mensagens com `{{variables}}` em uma [predefinição](/pt-BR/v1/guides/presets), e seu aplicativo envia apenas a referência da predefinição e os valores das variáveis. O Phaseo verifica os valores, preenche as mensagens e envia a solicitação ao modelo da predefinição. Alterar o prompt no painel não exige deploy, e todos os solicitantes recebem o mesmo texto, as mesmas ferramentas e o mesmo formato de resposta.

Os templates funcionam em `POST /v1/chat/completions`, `POST /v1/responses` e `POST /v1/messages`.

## Criar e chamar um template

<Steps>
<Step title="Escreva o template">

Abra **Configurações -> Predefinições**, crie ou abra uma predefinição, escolha o modelo e abra a aba **Template de prompt**. Adicione mensagens e escreva as variáveis entre chaves duplas:

```text
System: You triage support tickets for {{company}}. Reply in a {{tone}} tone.
User:   Ticket: {{ticket}}
```

O editor lista cada variável que encontra. Defina o tipo, se é obrigatória, um padrão e uma descrição. Preencha o painel **Experimente** para ver exatamente as mensagens que o gateway enviará e, depois, salve.

Depois que a predefinição estiver salva, **Executar a predefinição salva** envia uma solicitação real com seus valores de teste e mostra a resposta, o modelo e as contagens de tokens. Isso usa os créditos do seu espaço de trabalho. O mesmo painel tem código cURL, TypeScript e Python para a solicitação, preenchido com seus valores de teste.

</Step>

<Step title="Envie as variáveis">

Referencie a predefinição em `prompt.id` e coloque os valores em `prompt.variables`. Omita `model` ou defina-o com a mesma referência.

<CodeGroup>
```bash cURL
curl https://api.phaseo.app/v1/chat/completions \
  -H "Authorization: Bearer $PHASEO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "prompt": {
      "id": "@support-triage",
      "variables": {
        "company": "Acme",
        "tone": "friendly",
        "ticket": "I was charged twice this month."
      }
    }
  }'
```

```typescript TypeScript
import Phaseo from "@phaseo/sdk";

const client = new Phaseo({ apiKey: process.env.PHASEO_API_KEY! });

const completion = await client.generateText({
	model: "@support-triage",
	messages: [],
	prompt: {
		id: "@support-triage",
		variables: {
			company: "Acme",
			tone: "friendly",
			ticket: "I was charged twice this month.",
		},
	},
});
```

```python Python
from phaseo import Phaseo

client = Phaseo(api_key="YOUR_API_KEY")

completion = client.generate_text({
    "prompt": {
        "id": "@support-triage",
        "variables": {
            "company": "Acme",
            "tone": "friendly",
            "ticket": "I was charged twice this month.",
        },
    },
})
```
</CodeGroup>

</Step>

<Step title="Confira a solicitação">

Abra **Gateway -> Registros** para ver a solicitação, o modelo que a atendeu e o custo. Os metadados da solicitação registram a predefinição, os nomes das variáveis e o número de mensagens renderizadas, mas não os valores das variáveis.

</Step>
</Steps>

## Usar templates em cada endpoint

O mesmo objeto `prompt` funciona nos três endpoints. As mensagens de sistema e de desenvolvedor do template viram as instruções de sistema do endpoint, e as outras mensagens vêm antes de qualquer conversa que a sua solicitação envie.

| Endpoint | As mensagens de sistema do template vão para | A conversa do template vem antes de |
| --- | --- | --- |
| `/v1/chat/completions` | `messages` (mantidas como mensagens de sistema) | suas `messages` |
| `/v1/responses` | `instructions` | seu `input` |
| `/v1/messages` | `system` | suas `messages` |

Você pode enviar uma conversa junto com o template. Por exemplo, uma solicitação de chat pode adicionar os turnos seguintes do usuário depois das mensagens do template:

```json
{
  "prompt": { "id": "@support-triage", "variables": { "company": "Acme", "ticket": "Refund request" } },
  "messages": [
    { "role": "assistant", "content": "Can you share the order number?" },
    { "role": "user", "content": "It is 10482." }
  ]
}
```

## Sintaxe dos templates

Os templates usam um subconjunto pequeno e sem lógica do Mustache. Nada em um template é executado como código.

| Sintaxe | O que faz |
| --- | --- |
| `{{name}}` | Insere um valor. Texto é inserido como está, números e booleanos como texto, e listas e objetos como JSON. Um valor opcional ausente não insere nada. |
| `{{customer.name}}` | Insere um campo de uma variável do tipo objeto. |
| `{{#name}}...{{/name}}` | Renderiza o bloco uma vez quando o valor está definido e não é `false`, ou uma vez para cada item de uma lista. Dentro dele, `{{.}}` é o item atual e seus campos podem ser usados pelo nome. |
| `{{^name}}...{{/name}}` | Renderiza o bloco quando o valor está ausente, é `false`, texto vazio ou uma lista vazia. |
| `{{! note }}` | Um comentário. É removido. |
| `\{{` | Um `{{` literal. |

Os valores são inseridos como texto simples, sem escape de HTML. Um valor pode mudar o texto de uma mensagem, mas nunca a estrutura da solicitação.

Se uma mensagem renderizar apenas espaços em branco, ela é descartada. Use isso para tornar uma mensagem inteira opcional:

```text
{{#notes}}Notes from the account manager: {{notes}}{{/notes}}
```

Para repetir um texto para cada item de uma lista, abra uma seção na lista e use `{{.}}` para o item atual:

```text
Examples of good replies:
{{#examples}}- {{.}}
{{/examples}}
```

Parciais (`{{> name}}`), tags sem escape (`{{{name}}}` e `{{& name}}`), mudanças de delimitador e lambdas não são aceitos, e o editor e a API recusam templates que os usem.

## Variáveis

Cada variável tem um tipo. Você só precisa declarar uma variável para mudar os padrões dela; variáveis usadas nas mensagens, mas não declaradas, são texto obrigatório.

| Tipo | Aceita |
| --- | --- |
| `string` | Texto. Defina `max_length` para limitar o tamanho. |
| `number` | Um número. |
| `boolean` | `true` ou `false`. |
| `enum` | Uma das strings listadas em `enum`. |
| `array` | Uma lista. |
| `object` | Um objeto JSON. |
| `any` | Qualquer valor JSON. |
| `image` | Uma imagem para uma mensagem de usuário. Veja [Variáveis de imagem](#image-variables). |

Cada variável também pode ter:

- `required`: a solicitação falha quando o valor está ausente. Uma variável obrigatória não pode ter padrão.
- `default`: usado quando a solicitação omite o valor. Precisa corresponder ao tipo.
- `description`: mostrada no editor e nas mensagens de erro, com até 500 caracteres.

Um nome usado só para abrir seções, como `notes` e `examples` acima, é opcional e aceita qualquer valor.

As solicitações são verificadas de forma estrita. Um valor obrigatório ausente, um valor do tipo errado ou um nome que o template não tem retorna um `400` que lista todos os problemas de uma vez, para que um erro de digitação não descarte silenciosamente parte de um prompt.

<span id="image-variables"></span>
## Variáveis de imagem

Uma variável de imagem preenche uma parte de conteúdo inteira de uma mensagem de usuário, então é o template que decide onde a imagem fica. No editor, escolha **Adicionar imagem** dentro de uma mensagem de usuário. Na API, use uma parte `variable`:

```json
{
  "role": "user",
  "content": [
    { "type": "text", "text": "Before:" },
    { "type": "variable", "name": "before" },
    { "type": "text", "text": "After:" },
    { "type": "variable", "name": "after" },
    { "type": "text", "text": "What changed?" }
  ]
}
```

A solicitação pode enviar cada imagem como uma URL `https`, uma URL `data:image/...` ou uma parte de imagem no formato de Chat Completions, Responses ou Messages. O Phaseo a converte para o formato do endpoint que você chamou. O modelo selecionado precisa aceitar entrada de imagem.

## Ferramentas e formato de resposta

Um template pode incluir `tools`, `tool_choice` e `response_format`, escritos no formato de Chat Completions (veja [Chamada de ferramentas](./tool-calling.mdx) e [Saídas estruturadas](./structured-outputs.mdx)). O Phaseo os converte para os endpoints Responses e Messages.

A solicitação sempre prevalece quando as duas definem a mesma coisa:

- As ferramentas são combinadas pelo nome da função. Se a solicitação definir uma ferramenta com o mesmo nome, a definição da solicitação é usada.
- O `tool_choice` e o formato de resposta da solicitação (`response_format`, `text.format` ou `output_config.format`) substituem os do template.

Parâmetros da solicitação, como `temperature` e `max_tokens`, funcionam normalmente. Os padrões da própria predefinição preenchem apenas os campos que a solicitação omite.

## Criar um template pela API

Os templates ficam armazenados em `config.prompt` da predefinição. Crie ou atualize a predefinição com uma [chave de API de gerenciamento](/pt-BR/v1/developers/management-api-keys) que tenha `presets:write`:

```bash
curl https://api.phaseo.app/v1/presets \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "@support-triage",
    "visibility": "team",
    "config": {
      "models": ["anthropic/claude-haiku-5.5"],
      "prompt": {
        "messages": [
          { "role": "system", "content": "You triage support tickets for {{company}}. Reply in a {{tone}} tone." },
          { "role": "user", "content": "Ticket: {{ticket}}" }
        ],
        "variables": {
          "company": { "type": "string", "required": true },
          "tone": { "type": "enum", "enum": ["formal", "friendly"], "default": "formal" },
          "ticket": { "type": "string", "required": true, "max_length": 4000 }
        }
      }
    }
  }'
```

O Phaseo verifica o template ao salvá-lo. Um template com erro de sintaxe, tipo desconhecido ou um padrão que não corresponde ao tipo é recusado com `400 invalid_prompt_template` e a localização de cada problema, tanto aqui quanto no editor.

As alterações salvas chegam às solicitações em cerca de dois minutos.

<span id="versions-and-labels"></span>
## Versões e rótulos

Cada vez que você publica uma predefinição, o Phaseo salva uma versão imutável (veja [Predefinições](/pt-BR/v1/guides/presets#version-and-roll-back)). As solicitações executam a versão publicada mais recente, a menos que fixem uma. Uma solicitação fixada usa juntos os modelos, os parâmetros e o template daquela versão.

Fixe uma versão com `prompt.version`:

```json
{
  "prompt": {
    "id": "@support-triage",
    "version": "production",
    "variables": { "company": "Acme", "ticket": "My invoice is wrong" }
  }
}
```

`prompt.version` aceita um rótulo de versão, como `v3`, `1.2.0` ou `2026.10.27`, ou um rótulo como `production`. Você também pode colocar a versão no ID do modelo, com ou sem template:

```json
{
  "model": "@support-triage@production",
  "messages": [{ "role": "user", "content": "My invoice is wrong" }]
}
```

Predefinições públicas usam `@publisher/support-triage@production`. Se `model` e `prompt.version` fixarem uma versão, os dois precisam indicar a mesma.

### Rótulos

Um rótulo é um nome, como `production` ou `staging`, que aponta para uma versão publicada. Os rótulos têm de 1 a 32 letras minúsculas, números, hifens ou sublinhados, começam com uma letra e não podem parecer um rótulo de versão (`v1`, `v2`).

Em **Configurações -> Predefinições**, abra a predefinição. **Publicar**, ao lado de **Salvar rascunho**, salva suas alterações e as publica como a próxima versão. Abra **Versões e rótulos** para gerenciar os rótulos: cada rótulo tem um seletor de versão, então escolher outra versão move o rótulo e escolher uma anterior reverte. Use **Adicionar rótulo** para criar um novo. Abra uma versão para ver seus modelos e as mensagens do template e como eles diferem da versão padrão (a que as solicitações executam quando não fixam uma versão), e use **Executar** para testar essa versão com os valores de teste de **Template de prompt**. O criador da predefinição pode alterar os rótulos, assim como os proprietários e administradores do espaço de trabalho quando a predefinição é compartilhada. Com uma [chave de API de gerenciamento](/pt-BR/v1/developers/management-api-keys) que tenha `presets:write`:

```bash
curl -X PUT https://api.phaseo.app/v1/presets/support-triage/labels/production \
  -H "Authorization: Bearer $PHASEO_MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "version": "v3" }'
```

O corpo aceita `version` (um rótulo de versão, ou outro rótulo para copiar para onde ele aponta) ou `version_id`. `GET /v1/presets/{id}/labels` lista os rótulos, e `DELETE /v1/presets/{id}/labels/{label}` remove um. Solicitações que fixam um rótulo removido falham até que ele seja adicionado de novo.

### Reverter

Para reverter, mova o rótulo para a versão anterior: escolha essa versão no seletor de versão do rótulo em **Versões e rótulos**, ou envie a mesma solicitação com `"version": "v2"`. As solicitações que fixam `production` voltam a executar a v2 sem nenhuma alteração no seu aplicativo.

As mudanças de rótulo chegam às solicitações em cerca de dois minutos, assim como as outras alterações de predefinição.

## Erros

Problemas de template em uma solicitação retornam `400` com o código `validation_error`. `reason` contém o código do primeiro problema e `details` lista todos eles com o caminho:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Template \"@support-triage\" needs variable \"ticket\" (string)",
    "type": "invalid_request_error"
  },
  "code": "validation_error",
  "reason": "template_variable_required",
  "description": "Template \"@support-triage\" needs variable \"ticket\" (string)",
  "details": [
    {
      "message": "Template \"@support-triage\" needs variable \"ticket\" (string)",
      "path": ["prompt", "variables", "ticket"],
      "keyword": "template_variable_required"
    }
  ]
}
```

| Motivo | Causa |
| --- | --- |
| `template_variable_required` | Falta uma variável obrigatória. |
| `template_variable_type` | Um valor não corresponde ao tipo, à lista do enum ou ao `max_length`. |
| `template_variable_unknown` | A solicitação enviou uma variável que o template não tem, ou a predefinição não tem template. |
| `template_variables_invalid` | `prompt.variables` não é um objeto. |
| `template_limit_exceeded` | As variáveis ou o texto renderizado ultrapassam os limites abaixo. |
| `template_rendered_empty` | O template não renderizou nenhuma mensagem de usuário ou assistente e a solicitação não enviou nenhuma. |
| `template_endpoint_unsupported` | A predefinição tem um template e foi chamada de um endpoint diferente dos três acima. |
| `prompt_model_conflict` | `model` indica uma predefinição ou modelo diferente de `prompt.id`, ou fixa uma versão diferente de `prompt.version`. |
| `prompt_version_invalid` | `prompt.version` está vazio, tem mais de 64 caracteres ou contém caracteres além de letras, números, `.`, `_`, `+` e `-`. |
| `prompt_model_fallbacks_unsupported` | A solicitação definiu alternativas em `models`. Liste os modelos alternativos na predefinição. |

Um `prompt.id` que não indica nenhuma predefinição do seu espaço de trabalho retorna `404`.

Uma versão ou um rótulo fixado que não existe, ou que a chave não pode usar, retorna `404` com o motivo `preset_version_not_found`.

## Limites

| Limite | Valor |
| --- | --- |
| Mensagens por template | 64 |
| Variáveis por template | 64 |
| Tamanho do nome da variável | 64 caracteres |
| Texto do template em todas as mensagens | 48.000 caracteres |
| Profundidade de aninhamento de seções | 8 |
| Repetições de seção por solicitação | 1.000 |
| Texto renderizado por solicitação | 1.000.000 caracteres |
| Tamanho de `prompt.variables` | 256 KB |
| Valores por `enum` | 100 |

## Guardrails e registros

Os [guardrails](/pt-BR/v1/cookbook/guardrails-for-api-keys) verificam os valores das variáveis como conteúdo do usuário, mesmo quando o template os coloca em uma mensagem de sistema. Um guardrail que oculta um valor o oculta em todos os lugares onde o template o inseriu, e um que bloqueia um valor bloqueia a solicitação.

Os metadados da solicitação registram a predefinição, os nomes das variáveis e o número de mensagens renderizadas. Os próprios valores só são mantidos onde o corpo da solicitação é mantido, de acordo com as configurações normais de registro do seu espaço de trabalho.
