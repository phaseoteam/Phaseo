Adicione um destino em **Configurações → Notificações** para enviar os alertas do seu espaço de trabalho por e-mail, Slack, Discord, Microsoft Teams ou o seu próprio webhook HTTPS. Os destinos pertencem ao espaço de trabalho, e você pode enviar um teste antes de confiar em um deles.

| Destino | O que você informa | Menções |
| --- | --- | --- |
| E-mail | Endereços ou listas de distribuição | Nenhuma |
| Slack | Uma URL de incoming webhook | IDs de usuário e IDs de grupo de usuários |
| Discord | Um canal e um token de bot, ou uma URL de webhook | IDs de usuário e IDs de cargo |
| Microsoft Teams | Uma URL de fluxo de trabalho | Endereços de e-mail do Microsoft 365 ou IDs de objeto do Entra |
| Webhook personalizado | Uma URL HTTPS | Nenhuma; as entregas são [assinadas](#verify-webhook-signatures) |

As credenciais e as URLs de webhook são criptografadas antes de serem armazenadas. Restrinja as credenciais dos canais à entrega de notificações e rotacione-as se forem expostas.

## Adicionar um destino

<Steps>
<Step title="Crie o destino">
Abra **Configurações → Notificações**, selecione **Adicionar destino**, informe um nome e escolha um ou mais canais. Adicione os detalhes do destino e as menções que quiser.
</Step>
<Step title="Teste cada canal">
Selecione **Enviar teste** em cada canal e crie os destinos depois que todos os testes tiverem sucesso.
</Step>
<Step title="Guarde o segredo de assinatura">
Um webhook personalizado recebe um segredo de assinatura quando você o cria. Copie-o da caixa de diálogo que se abre; ele é exibido só uma vez.
</Step>
</Steps>

Pela CLI, execute `phaseo notifications destinations create`, teste o destino com `phaseo notifications destinations test <id>` e depois escolha quais alertas ele recebe com `phaseo notifications routes set <event-kind> --destination-ids <id>`.

Use menções com moderação: envie alertas de alto volume para um canal monitorado em vez de acionar um grupo grande.

<span id="enable-product-alerts"></span>
## Ativar alertas de produto

A página de notificações lista os tipos de alerta disponíveis para o seu espaço de trabalho. Os destinos recebem um alerta além dos destinatários integrados mostrados no painel.

**Alertas de descontinuação de modelos** avisam antes que um modelo usado pelo espaço de trabalho seja aposentado.

**Avisos de modelo substituto** são enviados quando o [roteamento de modelos aposentados](./model-retirement.mdx#route-requests-to-a-replacement-automatically) está ativado e um modelo substituto responde às solicitações do espaço de trabalho para um modelo que nenhum provedor atende mais. Um aviso é enviado por modelo e substituto, na primeira vez que um substituto responde com sucesso. O proprietário do espaço de trabalho sempre recebe um e-mail; escolha destinos para enviar o aviso também à sua equipe.

<span id="spend-reports"></span>
## Relatórios de gastos

Os proprietários do espaço de trabalho recebem um e-mail com o relatório de gastos toda segunda-feira às 09:00, no fuso horário de faturamento do espaço de trabalho, cobrindo a semana anterior, de segunda a domingo. Altere isso em **Alertas de gastos → Configurações de gastos do espaço de trabalho**, na página de notificações: diário (às 09:00, sobre o dia anterior), semanal, mensal (no dia 1º, sobre o mês anterior) ou desativado, e se os administradores também o recebem. Períodos sem gastos são pulados.

Cada relatório mostra os gastos e a variação em relação ao período anterior, as principais chaves, modelos, membros e departamentos, a previsão deste mês, a autonomia do saldo e os alertas e bloqueios por gastos do período. Quem recebe o relatório pode cancelar a inscrição pelo link no e-mail; isso interrompe só a própria cópia do relatório daquele espaço de trabalho. Os destinos encaminhados para **Relatórios de gastos** recebem um resumo por relatório.

As mesmas configurações são `spend.report_cadence` e `spend.report_include_admins` na [API de configurações de notificações](../api-reference/endpoint/notifications-settings-update.mdx).

Para alertas sobre gastos, orçamentos, previsões, picos e saldo baixo, e para bloquear solicitações quando os gastos passam de um limite, veja [Alertas de gastos](./spend-alerts.mdx).

<Note>Os e-mails de relatório de gastos estão sendo liberados aos poucos. Até serem ativados, a sua escolha é salva, mas nenhum relatório é enviado.</Note>

## Manter os destinos funcionando

Use **Enviar teste** ao lado de um destino existente depois de rotacionar as credenciais ou mudar o canal dele. Remova os destinos que ninguém monitora, para que os alertas não pareçam entregues quando caem em um canal abandonado.

Um receptor de webhook personalizado deve verificar cada solicitação antes de processá-la, retornar uma resposta de sucesso rapidamente e passar o trabalho mais lento para uma tarefa em segundo plano.

<span id="verify-webhook-signatures"></span>
## Verificar assinaturas de webhook

O Phaseo assina todas as entregas de webhooks personalizados, incluindo os testes enviados de um destino salvo, com o mesmo esquema dos [webhooks de vídeo e de lote](./async-video-and-batch.mdx#receive-updates). Cada solicitação traz estes cabeçalhos:

```http
POST /your/endpoint HTTP/1.1
content-type: application/json
user-agent: Phaseo-Notifications/1.0
x-phaseo-event-id: 6f1c0f5e-3f0b-4a39-9a51-2f4f2c1d9e10
x-phaseo-event-type: rate_limit_throttled
x-phaseo-timestamp: 1792569600
x-phaseo-signature: 5d2a…e41f
```

`x-phaseo-signature` é o HMAC-SHA256 hexadecimal do valor de `x-phaseo-timestamp`, de um ponto literal (`.`) e do **corpo da solicitação sem alterações**, com o segredo de assinatura do destino (`whsec_…`) como chave. `x-phaseo-timestamp` está em segundos Unix.

Para verificar uma entrega:

1. Leia o corpo bruto da solicitação antes de interpretá-lo como JSON.
2. Calcule a assinatura de novo e compare-a em tempo constante.
3. Rejeite horários com mais de cinco minutos de diferença do seu relógio.
4. Elimine duplicatas pelo `x-phaseo-event-id`. As entregas que falham são tentadas de novo, e cada tentativa é assinada outra vez com um novo horário.

<CodeGroup>
```js Node.js
import crypto from "node:crypto";

// rawBody é o corpo da solicitação exatamente como foi recebido, como string.
export function verifyPhaseoSignature(rawBody, headers, secret, toleranceSeconds = 300) {
  const timestamp = headers["x-phaseo-timestamp"];
  const signature = headers["x-phaseo-signature"];
  if (!timestamp || !signature) return false;
  if (Math.abs(Date.now() / 1000 - Number(timestamp)) > toleranceSeconds) return false;
  const expected = crypto
    .createHmac("sha256", secret)
    .update(`${timestamp}.${rawBody}`)
    .digest("hex");
  const a = Buffer.from(expected, "hex");
  const b = Buffer.from(signature, "hex");
  return a.length === b.length && crypto.timingSafeEqual(a, b);
}
```

```python Python
import hashlib
import hmac
import time

# raw_body é o corpo da solicitação exatamente como foi recebido, em bytes.
def verify_phaseo_signature(raw_body: bytes, headers, secret: str, tolerance_seconds: int = 300) -> bool:
    timestamp = headers.get("x-phaseo-timestamp", "")
    signature = headers.get("x-phaseo-signature", "")
    if not timestamp.isdigit() or not signature:
        return False
    if abs(time.time() - int(timestamp)) > tolerance_seconds:
        return False
    expected = hmac.new(secret.encode(), timestamp.encode() + b"." + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)
```
</CodeGroup>

### Gerar ou rotacionar um segredo

O segredo é exibido uma vez, quando o destino é criado. Para substituí-lo, selecione **Rotacionar segredo** ao lado do destino em **Configurações → Notificações**, ou chame [`POST /v1/notifications/destinations/{id}/rotate-secret`](/pt-BR/v1/api-reference/endpoint/notifications-destination-rotate-secret). A próxima entrega é assinada com o novo segredo e o antigo deixa de funcionar, então atualize o seu receptor na hora.

Os webhooks personalizados criados antes de a assinatura existir não têm segredo e continuam sendo entregues sem assinatura. Eles aparecem como **Sem assinatura** nas configurações. Selecione **Gerar segredo**, adicione o segredo ao seu receptor e depois envie um teste para conferir a verificação. Os testes enviados pelo painel **Adicionar destino**, antes de o destino ser salvo, não são assinados porque ainda não existe segredo.

Os destinos de e-mail, Slack, Discord e Microsoft Teams não são assinados: esses serviços autenticam a URL do webhook ou o token do bot por conta própria.
