Mova o tráfego do Claude Opus 4.1 para `anthropic/claude-opus-4.8`: troque o ID do modelo, remova os parâmetros de amostragem e substitua os orçamentos de pensamento por um nível de esforço.

A Anthropic descontinuou o Opus 4.1 em 5 de junho de 2026 e o aposentou em 5 de agosto de 2026. O Phaseo continua atendendo `anthropic/claude-opus-4.1` enquanto algum provedor o oferecer e, quando nenhum oferecer mais, roteia essas solicitações para o Opus 4.8 (veja [Descontinuação e aposentadoria de modelos](../guides/model-retirement)). Migre antes que isso aconteça, para que a mudança seja testada em vez de automática.

As orientações da Anthropic são cumulativas: aplique as mudanças no formato da solicitação do Opus 4.7 e depois revise as mudanças de comportamento do Opus 4.8.

| | Claude Opus 4.1 | Claude Opus 4.8 |
| --- | --- | --- |
| ID do modelo no Phaseo | `anthropic/claude-opus-4.1` | `anthropic/claude-opus-4.8` |
| Janela de contexto | 200K tokens | 1M tokens |
| Saída máxima | 32K tokens | 128K tokens |
| `temperature`, `top_p`, `top_k` | Enviados | Omitidos pelo Phaseo |
| Pensamento | `budget_tokens` | Adaptativo, orientado pelo esforço (padrão `high`) |
| Mensagens de sistema no meio da conversa | Não | Sim |

## Atualize a solicitação

**1. Troque o ID do modelo** para `anthropic/claude-opus-4.8`.

**2. Remova os parâmetros de amostragem.** A Anthropic rejeita valores não padrão de `temperature`, `top_p` e `top_k` no Opus 4.7 e posteriores com `400`. O Phaseo os omite em vez de falhar, então eles não têm mais efeito; ajuste o comportamento com instruções.

**3. Substitua os orçamentos de pensamento por um nível de esforço.** O Phaseo não repassa `budget_tokens` ao Opus 4.8. Qualquer configuração de raciocínio é enviada como `thinking: {"type": "adaptive", "display": "summarized"}`, e `reasoning.effort` (ou `output_config.effort` em `/v1/messages`) define a profundidade:

```json
{
  "model": "anthropic/claude-opus-4.8",
  "max_tokens": 4096,
  "thinking": { "type": "adaptive" },
  "output_config": { "effort": "high" },
  "messages": [{ "role": "user", "content": "Plan the schema migration." }]
}
```

Sem nenhuma configuração de raciocínio, o Opus 4.8 não pensa. `reasoning.effort: "none"` envia `thinking: {"type": "disabled"}`.

**4. Refaça a linha de base de esforço e contexto longo.** O Opus 4.8 usa `high` como esforço padrão e tem uma janela de contexto muito maior que a do Opus 4.1. Teste novamente os orçamentos de latência, o uso de tokens, o cache de prompts e os traces de documentos longos e de agentes de longa duração. No Microsoft Foundry, a Anthropic documenta uma janela de contexto de 200K para o Opus 4.8 no lançamento.

**5. Simplifique as atualizações de instruções em conversas longas.** O Opus 4.8 aceita mensagens `role: "system"` no meio da conversa. Se o loop do seu agente reescreve todo o prompt de sistema a cada turno, adicione uma mensagem de sistema no lugar e mantenha mais acertos de cache.

## O que testar

- solicitações que ainda enviam `temperature`, `top_p` ou `top_k`, já que esses parâmetros deixaram de ter efeito;
- rotas com pensamento que dependiam de `budget_tokens`;
- fluxos de agentes e ferramentas de longo horizonte;
- saídas sensíveis ao esquema em cada nível de `effort`;
- custo de tokens e latência nas classes de prompt do Opus 4.1 com maior volume.

## Faça o rollout

1. Remova os parâmetros de amostragem e os orçamentos de pensamento antes de mover o tráfego.
2. Rode o Opus 4.8 em modo sombra com prompts e fluxos de ferramentas parecidos com os de produção.
3. Faça um canário com o Opus 4.1 como fallback em `models` enquanto os provedores ainda o atenderem.
4. Promova quando as mudanças de latência, custo e conclusão de tarefas estiverem dentro da meta.
