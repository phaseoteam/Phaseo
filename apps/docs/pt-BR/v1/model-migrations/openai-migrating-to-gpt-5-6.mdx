Escolha o nível do GPT-5.6 que combina com a carga de trabalho, troque apenas o ID do modelo e teste de novo o esforço de raciocínio, as ferramentas, a latência e o custo. Mantenha o seu modelo GPT-5 anterior como fallback até as avaliações passarem.

## Escolha um nível

| Modelo | Use para | Esforço de raciocínio |
| --- | --- | --- |
| `openai/gpt-5.6-sol` | Raciocínio de maior capacidade, programação com agentes, análise científica e trabalho profissional complexo | `none`, `low`, `medium`, `high`, `xhigh`, `max` |
| `openai/gpt-5.6-terra` | Raciocínio equilibrado do dia a dia, programação e trabalho de assistente | `none`, `low`, `medium`, `high`, `xhigh`, `max` |
| `openai/gpt-5.6-luna` | Trabalho com menor latência e sensível a custo | `none`, `low`, `medium`, `high`, `xhigh`, `max` |

Os três têm janela de contexto de 1.050.000 tokens e 128K tokens de saída. Cada um também tem um ID Pro (`openai/gpt-5.6-sol-pro`, `-terra-pro`, `-luna-pro`), que envia `reasoning.mode: "pro"` por você.

O alias `gpt-5.6` da própria OpenAI aponta para `gpt-5.6-sol`; no Phaseo, chame os IDs dos níveis diretamente. Os aliases de nível `openai/gpt-sol-latest`, `openai/gpt-terra-latest` e `openai/gpt-luna-latest` acompanham o modelo mais recente de cada nível, e `openai/gpt-sol-latest` já aponta para além do GPT-5.6. Use-os apenas quando quiser que futuros lançamentos sejam adotados automaticamente.

## Atualize a solicitação

O GPT-5.6 adiciona `max`, o maior orçamento de raciocínio, em todos os níveis. Use-o só onde a latência e o custo extras compensam.

<CodeGroup>
```json Responses
{
  "model": "openai/gpt-5.6-sol",
  "input": "Review this multi-service incident report and propose a rollback plan.",
  "reasoning": { "effort": "max" }
}
```

```json Chat Completions
{
  "model": "openai/gpt-5.6-terra",
  "messages": [
    { "role": "user", "content": "Design a test plan for this agent workflow." }
  ],
  "reasoning_effort": "medium"
}
```
</CodeGroup>

O GPT-5.6 também adiciona:

- **`reasoning.mode: "pro"`** para tarefas mais difíceis, sem trocar de modelo;
- **`reasoning.context`** (`auto`, `current_turn` ou `all_turns`) para controlar qual raciocínio persiste;
- suporte multiagente em beta e Programmatic Tool Calling para fluxos com uso intenso de ferramentas;
- cache de prompts explícito com `prompt_cache_options` e pontos de interrupção de cache. No GPT-5.6, `prompt_cache_options.ttl` substitui `prompt_cache_retention`, que o Phaseo não envia aos modelos GPT-5.6.

## Revise os preços

Preços por 1M tokens no nível padrão da OpenAI, para solicitações de até 272K tokens de entrada:

| Modelo | Entrada | Leitura de cache | Gravação de cache (30 min) | Gravação de cache (12 h) | Saída |
| --- | ---: | ---: | ---: | ---: | ---: |
| Sol | $5.00 | $0.50 | $6.25 | $12.50 | $30.00 |
| Terra | $2.00 | $0.20 | $2.50 | $5.00 | $12.00 |
| Luna | $0.20 | $0.02 | $0.25 | $0.50 | $1.20 |

Solicitações acima de 272K tokens de entrada custam mais: Sol $10.00 de entrada e $45.00 de saída, Terra $4.00 e $18.00, Luna $0.40 e $1.80, com os preços de cache ajustados na mesma proporção. Até 30 de novembro de 2026, vale o preço promocional do Sol da OpenAI: $4.00 de entrada e $20.00 de saída até 272K tokens. Consulte a página do modelo para os preços atuais em outros níveis e provedores.

Uma leitura de cache custa 10% da tarifa de entrada, uma gravação de 30 minutos 1.25× e uma gravação de 12 horas 2.5×. Cada token de entrada é cobrado em exatamente uma dessas tarifas. O uso conta leituras e gravações de cache dentro de `input_tokens` (`prompt_tokens` em Chat Completions) e informa as gravações em `cache_write_tokens`; veja [campos de uso e preço](../guides/prompt-caching.mdx#usage-and-pricing-fields).

## Faça cache do contexto repetido

Coloque a parte estável do prompt em um bloco que pode ir para o cache e deixe o texto específico da solicitação depois dele:

```json
{
  "model": "openai/gpt-5.6-sol",
  "input": [
    {
      "role": "user",
      "content": [
        {
          "type": "input_text",
          "text": "Stable policy document...",
          "prompt_cache_breakpoint": { "mode": "explicit" }
        },
        {
          "type": "input_text",
          "text": "Apply the policy to this new customer request."
        }
      ]
    }
  ],
  "prompt_cache_options": { "mode": "explicit", "ttl": "30m" }
}
```

- `prompt_cache_breakpoint` coloca em cache tudo até o bloco dele, inclusive. No modo `explicit`, a OpenAI só faz cache dos pontos de interrupção que você define.
- Um `cache_control` de bloco, como `{"type": "ephemeral"}`, também funciona; o Phaseo o envia ao GPT-5.6 como `prompt_cache_breakpoint`. As duas marcações chegam ao Claude como ponto de interrupção de cache, então um fallback para o Claude continua usando cache.
- `ttl` é `30m` (o padrão) ou `12h`. Veja [Cache de 12 horas na OpenAI](../guides/prompt-caching.mdx#12-hour-cache-on-openai) para saber quais rotas o aceitam, e [Retenção e opções da OpenAI](../guides/prompt-caching.mdx#openai-retention-and-options) para os outros campos.

## O que testar

- **Raciocínio e qualidade da saída:** cada nível nos esforços que você vai expor, incluindo `max` onde a qualidade vem primeiro; modo padrão em comparação com `reasoning.mode: "pro"` em tarefas difíceis; taxa de aprovação do esquema e qualidade das chamadas de ferramentas em cada nível.
- **Custo e latência:** latência em cada esforço, aumento de tokens de saída em relação à sua linha de base atual, a proporção entre leituras e gravações de cache em prompts repetidos e o custo por tarefa bem-sucedida, em vez do preço por token.

## Faça o rollout

1. Mantenha o seu modelo GPT-5 anterior como fallback em `models`.
2. Deixe `max` atrás de uma flag de configuração ou de uma [predefinição](../guides/presets) até ele se provar em prompts parecidos com os de produção.
3. Monitore o volume de gravações de cache separadamente das leituras.
4. Torne o GPT-5.6 o padrão só depois que as avaliações confirmarem o sucesso nas tarefas, o custo e a latência.
