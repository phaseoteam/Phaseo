Troque o modelo para `anthropic/claude-opus-5` e mantenha o Claude Opus 4.8 como fallback enquanto você o avalia. O preço é o mesmo do Opus 4.8, então a diferença de custo vem do uso de tokens.

```json
{
  "model": "anthropic/claude-opus-5",
  "models": ["anthropic/claude-opus-4.8"],
  "messages": [
    {
      "role": "user",
      "content": "Review this implementation plan and identify the highest-risk assumptions."
    }
  ]
}
```

| | Claude Opus 4.8 | Claude Opus 5 |
| --- | --- | --- |
| ID do modelo no Phaseo | `anthropic/claude-opus-4.8` | `anthropic/claude-opus-5` |
| Janela de contexto | 1M tokens | 1M tokens |
| Saída máxima | 128K tokens | 128K tokens |
| Preço por 1M tokens (entrada / saída) | $5.00 / $25.00 | $5.00 / $25.00 |
| Pensamento quando a solicitação não define raciocínio | Desativado | Adaptativo |

Os preços são do nível padrão da Anthropic no catálogo; consulte a página do modelo para outros níveis e provedores.

## Como o Phaseo envia a solicitação

O Opus 5 aceita o mesmo formato de solicitação do Opus 4.7 e do 4.8:

- **Os parâmetros de amostragem são omitidos.** `temperature`, `top_p` e `top_k` não são enviados ao modelo.
- **Qualquer configuração de raciocínio ativa o pensamento adaptativo.** O Phaseo envia `thinking: {"type": "adaptive", "display": "summarized"}`, e `reasoning.effort` vira `output_config.effort`. Os orçamentos de pensamento não são repassados.
- **`reasoning.effort: "none"` ou `reasoning.enabled: false` desativa o pensamento** (`thinking: {"type": "disabled"}`).
- **Sem nenhuma configuração de raciocínio, o Phaseo não envia o campo `thinking`,** então vale o padrão do Opus 5, que é o pensamento adaptativo. O Opus 4.8 só pensa quando solicitado, então a mesma solicitação pode usar mais tokens de saída no Opus 5.

## O que testar

- **Prompts e saídas:** cumprimento de instruções nos seus prompts de sistema mais longos, taxas de aprovação do esquema, tamanho e encerramento das respostas, e prompts ajustados para o Opus 4.8.
- **Ferramentas e agentes:** seleção de ferramentas e argumentos, recuperação após erros de ferramentas ou resultados parciais, taxa de conclusão em tarefas de longo horizonte e limites de permissão em fluxos de alta autonomia.
- **Operações:** latência e uso de tokens em cada nível de esforço que você expõe, uso de contexto em documentos longos e traces de agentes, custo por tarefa bem-sucedida e fallback quando a rota principal excede o tempo limite ou falha.

## Faça o rollout

1. Rode em modo sombra com tráfego de produção representativo antes de atender usuários.
2. Faça o canário por carga de trabalho em vez de mover todas as rotas do Opus de uma vez.
3. Promova só depois que as verificações de qualidade, latência, custo e segurança de ferramentas atingirem as suas metas.
