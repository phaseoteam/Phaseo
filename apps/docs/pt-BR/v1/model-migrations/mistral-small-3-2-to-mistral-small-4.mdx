Troque o modelo para `mistral/mistral-small-4` e decida, rota por rota, se o raciocínio fica ativado. O Mistral Small 4 tem dois modos de raciocínio, desativado e alto, e o Phaseo mapeia cada valor de esforço para um deles.

```json
{
  "model": "mistral/mistral-small-4",
  "messages": [
    { "role": "user", "content": "Why is fast inference important?" }
  ],
  "reasoning": { "effort": "high" }
}
```

## Ative ou desative o raciocínio

O raciocínio fica desativado, a menos que a solicitação o peça. Na API da própria Mistral, o Phaseo envia `reasoning_effort` assim:

| Solicitação | Enviado à Mistral |
| --- | --- |
| Nenhuma configuração de raciocínio | `reasoning_effort: "none"` |
| `reasoning.effort: "none"` ou `reasoning.enabled: false` | `reasoning_effort: "none"` |
| Qualquer outro `reasoning.effort`, ou `reasoning.enabled: true` | `reasoning_effort: "high"` |

Um `reasoning_effort` simples na solicitação tem precedência sobre `reasoning.effort`. Use `none` em rotas leves e `high` para raciocínio profundo; `low` e `medium` se comportam exatamente como `high`.

## Leia a resposta e o raciocínio

A Mistral pode retornar blocos de conteúdo mistos, como `thinking` seguido de `text`. O Phaseo os separa em campos no estilo da OpenAI, para que o código downstream que lê Chat Completions continue funcionando:

- a resposta fica em `choices[0].message.content`;
- o texto do raciocínio fica em `choices[0].message.reasoning_content` e em `reasoning_details`.

## Faça o rollout

1. Troque o ID do modelo do Mistral Small 3.2 para `mistral/mistral-small-4`.
2. Teste o raciocínio apenas com `none` e `high`.
3. Execute de novo os testes de qualidade da saída e de esquema nas rotas que usam `high`.
4. Compare a latência e o custo de `none` e `high` antes da virada completa.
