O streaming permite que a interface exiba tokens enquanto são gerados, sem esperar a resposta completa.

## Endpoints compatíveis

- `POST /v1/responses`
- `POST /v1/chat/completions`
- `POST /v1/messages`

## Ativar o streaming

Defina `stream: true` no corpo da solicitação.

```bash
curl https://api.phaseo.app/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5-nano",
    "input": "Write a short greeting.",
    "stream": true
  }'
```

## Formato dos quadros SSE

Os streams são retornados como quadros SSE:

```text
data: {"id":"resp_...","status":"in_progress",...}
data: {"type":"response.output_text.delta","delta":"Hello"}
data: {"type":"response.completed",...}
data: [DONE]
```

## Como lidar com erros durante o streaming

- Se uma solicitação falhar antes do início do stream, você receberá uma resposta de erro JSON normal.
- Se falhar depois de parte da saída, trate o stream como incompleto e ofereça uma opção de nova tentativa na interface.
- Sempre registre `generation_id` quando estiver presente para facilitar o suporte e a correlação.

## Cancelamento

Use controles de cancelamento (`AbortController` em JavaScript ou timeout de solicitação nos workers de backend) para evitar que streams abandonados consumam recursos sem necessidade.

## Limitação conhecida

A camada atual de validação de solicitações do Gateway rejeita `stream: true` com chamadas de ferramentas. Use o modo sem streaming nos ciclos que chamam ferramentas.
