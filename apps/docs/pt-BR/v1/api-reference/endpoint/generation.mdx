Chame `GET /v1/generations?id=<request_id>` para buscar o registro de auditoria armazenado de uma solicitação do seu espaço de trabalho. É preciso o escopo `generations:read`; sem `id`, a chamada retorna `400` `missing_id`.

Novas solicitações recebem um ID de geração `G-` criado pelo servidor, retornado no cabeçalho de resposta `x-request-id` e na resposta da geração. Use esse ID para registros de solicitações, consulta de gerações e suporte. Um `x-request-id` enviado pelo cliente não substitui o ID de geração. IDs UUID de registros antigos continuam funcionando para consultas.

## Repetir uma solicitação

Toda resposta inclui `replay_supported`. Quando o registro de E/S armazenou o corpo da solicitação e você pode ler conteúdos armazenados, `replay_supported` é `true` e `replay_request` contém o corpo a ser reenviado para uma nova execução controlada:

<Steps>
  <Step title="Leia a geração">
    Chame `GET /v1/generations?id=<request_id>`.
  </Step>
  <Step title="Confirme que ela pode ser repetida">
    Continue somente se `replay_supported` for `true`.
  </Step>
  <Step title="Envie de novo">
    Envie `replay_request` ao endpoint indicado em `endpoint`, como `/v1/chat/completions` ou `/v1/responses`.
  </Step>
</Steps>

Um espaço de trabalho pode restringir os conteúdos armazenados a proprietários e administradores. Os demais chamadores, incluindo chaves de API criadas por membros, recebem então `replay_request: null` e os detalhes da solicitação sem os conteúdos.
