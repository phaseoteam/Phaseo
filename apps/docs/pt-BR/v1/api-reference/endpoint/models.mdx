Chame `GET /v1/models` para listar os modelos para os quais você pode rotear agora. Defina `availability=all` para incluir modelos conhecidos, mas que não estão disponíveis no momento.

```bash
curl "https://api.phaseo.app/v1/models?limit=50" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

Cada modelo lista uma entrada em `offers` por rota de provedor (resumido, valores ilustrativos):

```json
{
  "ok": true,
  "availability_mode": "active",
  "limit": 50,
  "offset": 0,
  "total": 412,
  "models": [
    {
      "id": "anthropic/claude-sonnet-5.5",
      "name": "Claude Sonnet 5.5",
      "organization": { "id": "anthropic", "name": "Anthropic", "color": "#d97757" },
      "lifecycle": { "status": "active", "released_at": "2026-09-28", "replacement_id": null },
      "modalities": { "input": ["text", "image"], "output": ["text"] },
      "capabilities": { "endpoints": ["chat.completions", "messages", "responses"] },
      "availability": { "status": "active", "provider_count": 3, "active_provider_count": 3 },
      "offers": [
        {
          "provider": { "id": "anthropic", "name": "Anthropic" },
          "model": "claude-sonnet-5-5",
          "status": "active",
          "status_reason": null,
          "routable": true,
          "service_tiers": ["standard"],
          "routing": { "provider": "active", "model": "active", "capability": "active" }
        }
      ]
    }
  ]
}
```

Só envie tráfego de produção para uma oferta em que `routable` seja `true`. `status_reason` explica por que uma oferta está apenas em prévia ou inativa. O esquema completo está abaixo.

`GET /models/me` retorna a mesma lista com as proteções da sua chave aplicadas: as regras de privacidade e de provedores do seu workspace e as proteções dos departamentos da chave, do membro dela e da própria chave. Ficam de fora os modelos bloqueados por uma regra de modelos e os modelos sem nenhum provedor permitido, e cada modelo mantém apenas as ofertas para as quais as solicitações podem ser roteadas. Aceita os mesmos filtros que `GET /models`.

## Filtrar a lista

Os filtros que aceitam vários valores aceitam parâmetros repetidos ou uma lista separada por vírgulas.

| Parâmetro | Filtra por |
| --- | --- |
| `availability` | `active` (padrão) para modelos roteáveis publicamente, ou `all` para incluir modelos e provedores `coming_soon`, `inactive` e ainda não roteáveis |
| `endpoints` | Nomes de endpoints públicos, como `chat.completions`, `responses` e `messages` |
| `status` | Ciclo de vida do modelo, como `active`, `deprecated` ou `retired` |
| `organisation` | Prefixo do ID do modelo, como `anthropic` em `anthropic/claude-3-haiku` |
| `provider` | ID público do provedor, como `openai`, `anthropic` ou `google_vertex` |
| `provider_status` | Nível de lançamento do provedor, como `active`, `beta`, `alpha` ou `not_ready` |
| `provider_routing_status` | Estado de roteamento no nível do provedor |
| `model_routing_status` | Estado de roteamento no nível do modelo |
| `capability_status` | Estado do recurso do provedor para o mapeamento de endpoint solicitado |
| `provider_availability_status` | Disponibilidade no provedor, como `active`, `coming_soon` ou `inactive` |
| `provider_availability_reason` | Por que um provedor está indisponível, como `preview_only`, `provider_not_ready`, `gated`, `access_limited` ou `region_limited` |
| `input_types` (alias `input_modalities`) | Modalidades de entrada |
| `output_types` (alias `output_modalities`) | Modalidades de saída |
| `params` (alias `supported_parameters`) | Parâmetros de solicitação suportados |

Para inspecionar as rotas de provedor, os detalhes de parâmetros e os preços de um modelo, chame [`GET /models/{author}/{slug}/endpoints`](./model-endpoints.mdx).

## Verificar os níveis de serviço de cada oferta

Cada entrada em `offers` inclui `service_tiers`, os [níveis de serviço](../../guides/service-tiers.mdx) que aquela oferta do provedor aceita. É um subconjunto, em ordem alfabética, de `flex`, `priority`, `standard` e `ultrafast`, em que `priority` é o nível Fast. Um nível aparece quando a rota do provedor tem preços ativos e vigentes para ele, e uma rota que atende um único nível lista apenas esse nível. Alguns níveis também estão disponíveis por rotas de provedor separadas, específicas do nível, que não são listadas. Os preços em `pricing` continuam sendo os do nível padrão.

## Obter a lista no formato da OpenAI

Use `GET /v1/models?format=openai` para clientes que esperam a resposta de lista de modelos da OpenAI. O padrão `format=json` retorna os metadados de modelo mais completos do Phaseo.

```bash
curl "https://api.phaseo.app/v1/models?format=openai" \
  -H "Authorization: Bearer $PHASEO_API_KEY"
```

```json
{
  "object": "list",
  "data": [
    { "id": "openai/gpt-6-astra", "object": "model", "created": 1788393600, "owned_by": "openai" }
  ]
}
```

O formato da OpenAI usa a mesma autenticação, disponibilidade regional, modelos privados do espaço de trabalho e filtros que o JSON nativo. Ele retorna todos os modelos correspondentes, a menos que você informe `limit`; `offset` continua valendo. Os IDs permanecem no formato canônico do Phaseo para inferência. `created` usa a data de lançamento do catálogo, ou `0` quando ela é desconhecida; `owned_by` usa a organização do catálogo, `private` para modelos do espaço de trabalho, ou `phaseo` quando é desconhecida.

## Armazenar a lista de modelos em cache

As respostas do catálogo ficam em cache por cinco minutos e podem ser servidas por mais cinco minutos enquanto o cache é revalidado. Isso vale para as representações JSON, RSS e Atom do catálogo atual; o feed de lançamentos tem seu próprio cache de consulta, mais curto.

As respostas em JSON e no formato da OpenAI incluem um cabeçalho `ETag` fraco (`W/"…"`). Ele muda quando os modelos da página, `limit`, `offset`, `total` ou o formato mudam. Ele ignora `gateway_region`, então o mesmo catálogo servido de outra região tem o mesmo `ETag`. Por isso ele é fraco: respostas que o compartilham são equivalentes, mas seus bytes podem ser diferentes. Respostas RSS, Atom e de erro não incluem esse cabeçalho.

Envie o valor salvo de volta, sem alterações, em `If-None-Match`. Se o catálogo não mudou, a resposta é `304 Not Modified`, sem corpo, e repete os cabeçalhos `ETag`, `Cache-Control` e `Vary`. Caso contrário, você recebe um `200` normal com a nova lista e um novo `ETag`. `If-None-Match` também aceita uma lista separada por vírgulas e `*`, e a comparação é fraca, então o valor corresponde com ou sem o prefixo `W/`.

```ts
let etag: string | null = null;
let models: unknown[] = [];

async function refreshModels() {
  const response = await fetch("https://api.phaseo.app/v1/models?limit=250", {
    headers: {
      Authorization: `Bearer ${process.env.PHASEO_API_KEY}`,
      ...(etag ? { "If-None-Match": etag } : {}),
    },
  });
  if (response.status === 304) return models; // Sem alterações; um 304 não tem corpo.
  if (!response.ok) throw new Error(`Model list request failed: ${response.status}`);
  etag = response.headers.get("ETag");
  models = (await response.json()).models;
  return models;
}
```

Um `304` economiza transferência e análise. O servidor ainda avalia a solicitação: ele carrega o catálogo e recalcula o `ETag`. Consultar mais ou menos a cada 15 minutos basta, baixando a lista de novo só quando o catálogo muda. Mantenha um `ETag` por URL de solicitação, porque cada página, conjunto de filtros e formato tem seu próprio valor.
