# @phaseo/mobile

## 0.1.1

### Patch Changes

- [#3502](https://github.com/phaseoteam/Phaseo/pull/3502) [`c392d26`](https://github.com/phaseoteam/Phaseo/commit/c392d26695b594f780dad727dcf1b9716d39e8b8) Thanks [@DanielButler1](https://github.com/DanielButler1)! - Deranking is now a single last-resort level. A deranked provider is tried only after every other healthy provider, ahead of providers at their quota limit and providers with an open breaker. The model catalogue reports it as `deranked`; `deranked_lvl1`, `deranked_lvl2` and `deranked_lvl3` are no longer returned, and filters that use them still match. Model pages, the models list and the admin editor show one "Lower priority" status.

- [#3443](https://github.com/phaseoteam/Phaseo/pull/3443) [`e744ce7`](https://github.com/phaseoteam/Phaseo/commit/e744ce7e0a7d552f2e8f07316988c6aa484e92cc) Thanks [@DanielButler1](https://github.com/DanielButler1)! - Fix the benchmark rows on the mobile compare screen. They showed each model's lowest score and highlighted the worst one as best, because "higher is better" was read backwards. Each model now shows its best score, the highest (or, for ranks and costs, the lowest) is highlighted, and lab-reported scores, ties and single scores get no highlight.

- [#3556](https://github.com/phaseoteam/Phaseo/pull/3556) [`5c4c012`](https://github.com/phaseoteam/Phaseo/commit/5c4c012f065fb7d63e14c32945602a4e0ec21592) Thanks [@DanielButler1](https://github.com/DanielButler1)! - The mobile model page shows provider uptime the way the website does. Model uptime now shows three per-attempt rates, Reachable, Accepted and Completed, as a 24-hour line each, with the share of attempts that failed each step ("0.6% of attempts couldn't reach the provider", "No failures this hour", "<0.1%" for tiny shares). Tap a rate to see what it measures. Older data without these rates keeps the single uptime line.
  
  Provider rows and the provider sheet use per-attempt uptime too. The sheet adds daily uptime for the last three days and the Reachable, Accepted and Completed breakdown.
  
  The page no longer shows request counts: the uptime chart says what share of requests failed in an hour, and the location picker lists locations without their request counts. The performance empty state now says when a location has too little traffic to publish, as on the website.

- [#3569](https://github.com/phaseoteam/Phaseo/pull/3569) [`05a6934`](https://github.com/phaseoteam/Phaseo/commit/05a69345489af8456bc13b864e84daa580d55f24) Thanks [@DanielButler1](https://github.com/DanielButler1)! - Model uptime headline figures (Reachable, Accepted and Completed) are now the true share of all provider attempts in the last 24 hours, not an average of 24 hourly rates. The average counted idle hours as 100%, so a model could read "Completed 96.7%" while two in three of its accepted attempts failed. The failure share in each explanation comes from the same rates, so the figure and its explanation always agree. With no attempts in 24 hours, every step reads 100% with "No failures". The chart lines still show hours without data at 100%. The mobile app matches.
  
  Metric explanations on model pages open on tap and click as well as hover, and from the keyboard. This covers the three uptime labels and the Performance charts' help icons. The provider table's daily uptime bars now show their day and rate on hover, focus or tap, and a day with no traffic says so instead of "--".
  
  The explanations are more precise. Reachable now lists 502, 504, Cloudflare 520–527 and 503s without an overload signal, matching how the gateway classifies attempts. Accepted lists 429s on Phaseo's own key, 529s and overloaded responses. The failure lines are shorter, for example "66.7% failed after the provider accepted them". The Uptime column header explains what the 3-day uptime measures. Throughput, Latency and E2E latency now use the documented definitions: effective throughput, time to first token and full request time.

- [#3461](https://github.com/phaseoteam/Phaseo/pull/3461) [`32a90cd`](https://github.com/phaseoteam/Phaseo/commit/32a90cd24f95783050da2929016a384d1db960d4) Thanks [@DanielButler1](https://github.com/DanielButler1)! - Security hardening from the November review. Signed-in users can no longer write OAuth app records directly, move presets into workspaces they don't belong to, or change extended-log billing state. Internal cache actions check for an admin before doing anything. Forged OAuth tokens can no longer force repeated key refreshes, and workload-identity policies from workspaces outside the rollout no longer make a token ambiguous. Transcription and web-fetch downloads are size- and time-limited, more IPv6 private ranges are blocked, and web-api webhook URLs get the same checks as the gateway. Secret comparisons are constant-time. The web app sends HSTS and a report-only content security policy. Factory marks issue text as untrusted in agent prompts, the desktop update feed is fixed at build time, and mobile chat only opens web and email links.

- [#3565](https://github.com/phaseoteam/Phaseo/pull/3565) [`f41075a`](https://github.com/phaseoteam/Phaseo/commit/f41075a47a3fb4e15d271557dbf2acebeaf3310f) Thanks [@DanielButler1](https://github.com/DanielButler1)! - Model uptime always shows the three per-attempt rates, Reachable, Accepted and Completed, on the website and in the mobile app. The single request-level uptime line is gone. A model with no traffic in the last 24 hours used to fall back to that line; it now shows three flat 100% lines with "No failures", because hours without data count as 100%.
  
  Provider uptime is per attempt only. The provider table, the provider card's daily and hourly bars, and the mobile provider rows and sheet no longer fall back to request-level uptime. A provider with traffic but no rated attempts shows 100%, and so does any day or hour without attempts. A provider with no traffic in the last three days still shows no uptime.
