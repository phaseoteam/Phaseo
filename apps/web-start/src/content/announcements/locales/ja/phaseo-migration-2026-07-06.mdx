AI Stats は **Phaseo** へと変わります。チームに必要なのは、モデルの一覧だけではないからです。

どのモデルを使うか、どのプロバイダーにリクエストを送るか、ルートごとの料金はいくらか、市場が動いたときにどう切り替えるかを判断する必要があります。

**Phaseo はそうした作業を一か所にまとめます。**モデルの検索、プロバイダーの対応状況、ゲートウェイルーティング、コストの把握、SDK、本番 AI システムのオブザーバビリティを提供します。

製品が進化したため、名前も変わります。Phaseo は、AI 市場が変化するたびにスタック全体を作り直すことなく、モデルを理解し、比較し、切り替え、利用できるようチームを支援します。

## なぜ今、名前を変えるのか

AI は実験や個別の連携を超え、製品の中核となるインフラへと変わりつつあります。

モデルの情報を固定的に記載するだけでも役立ちますが、モデルが製品の一部になると、それだけでは不十分です。本番環境を運用するチームは、どのプロバイダーがモデルを提供しているか、各ルートの料金はいくらか、エンドポイントを呼び出せるか、最近何が変わったか、来月さらに優れたモデルが登場した場合にどれほど簡単に移行できるかを把握する必要があります。

市場はさらに大きく、細分化しています。[Gartner は、2026 年の世界の AI 支出が 2 兆 5,200 億ドルに達すると予測しています](https://www.gartner.com/en/newsroom/press-releases/2026-1-15-gartner-says-worldwide-ai-spending-will-total-2-point-5-trillion-dollars-in-2026)。前年比で 44 % の増加です。

Stanford の [2026 AI Index](https://hai.stanford.edu/ai-index/2026-ai-index-report) によると、2025 年には組織での AI 導入率が 88 % に達し、米国の民間 AI 投資は 2,859 億ドルに達しました。

こうした数字が重要なのは、AI 支出が研究予算や試作段階の数回の API 呼び出しだけではなくなったからです。継続的に発生する運用コストになりつつあります。コストの全体像が見えにくくなる前に、ルーティング、料金、オブザーバビリティ、モデル選択をより適切に管理する必要があります。

**Phaseo は、そうした判断をチームが把握し続けられるようにします。**モデルのメタデータ、プロバイダーの利用可否、ルートの料金、ゲートウェイの挙動をつなぎ、モデル層が高額で不透明になる前に確認できるようにします。

## AI のサブスクリプションが期待を変えている

AI は、消費者や職場向けのサブスクリプション分野にもなりつつあります。

[OpenAI は、2026 年 2 月に ChatGPT の週間アクティブユーザーが 9 億人、有料登録者が 5,000 万人に達したと発表しました](https://techcrunch.com/2026/02/27/chatgpt-reaches-900m-weekly-active-users/)。Sensor Tower の[2026 State of AI レポート](https://sensortower.com/blog/state-of-ai-2026)では、さらに 2026 年 5 月の ChatGPT 月間アクティブユーザーが 10 億人に達したとされています。

この広がりによって、人々の AI 体験も変化しています。サブスクリプション、利用制限、製品プラン、頻繁に変わる既定値を通じてモデルに触れる人が増えています。SemiAnalysis はコストの面からも同じ変化を追っており、[20 ドルと 200 ドルの AI サブスクリプション](https://newsletter.semianalysis.com/p/claude-code-is-the-inflection-point)の経済性から[企業との議論](https://newsletter.semianalysis.com/p/tokenbudgeting-our-conversations)まで、トークン予算、プレミアムモデルへのアクセス、従業員一人あたりの AI 支出が具体的な運用課題になっています。

モデルの品質向上も同じように速く進んでいます。Phaseo が追跡する [Claude Fable 5](https://phaseo.app/models/anthropic/claude-fable-5) や [Claude Mythos 5](https://phaseo.app/models/anthropic/claude-mythos-5) などのリリースを見ると、品質、利用可否、料金、プロバイダーの対応状況をチームがどれほど頻繁に見直す必要があるかがわかります。

開発者にとって、結論は明確です。AI は一度だけ決める単一プロバイダーの問題ではありません。サブスクリプション、利用量、コスト、機能が変化し続ける課題です。

**Phaseo はそのサイクルに対応するために作られています。**モデルを比較し、プロバイダーの対応状況を把握し、意図を持ってトラフィックをルーティングし、コストや品質の変化に合わせて切り替えられます。

## モデルの選択がインフラになりつつある

モデル層の変化は、ほとんどのアプリケーション層よりも速く進みます。

推論に最適だと考え、最初はクローズドモデルを選ぶチームがあるかもしれません。1 か月後には、分類や情報抽出なら、より低コストのモデルで十分になっていることもあります。別のワークロードでは、データ主権、ファインチューニング、レイテンシ、管理された環境でのデプロイのために、オープンウェイトモデルが必要になる場合があります。

リアルタイム音声機能では、ベンチマークの点数よりもレイテンシや分単位の料金が重要かもしれません。コーディングアシスタントには、顧客サポートの問い合わせを振り分ける処理とは別のモデルが必要になることもあります。

一つのモデルを永久に使い続ける前提は、たいてい適切ではありません。

**Phaseo は、より長く使える方法を支援します。**チームが意図を持って移行できるよう、アプリケーションの移植性を保ちます。

**Phaseo を使うと、チームは次のことができます。**

- タスクに最適なモデルを使う
- トラフィックを移す前にプロバイダーを比較する
- 利用が増える前に料金を把握する
- 障害やプロバイダーの制限を別のルートで回避する
- オープン、クローズド、ホスト型、セルフホスト型の選択肢を試す
- モデルを切り替えてもオブザーバビリティを維持する

Phaseo はモデルの検索と、その周辺にある本番運用のワークフローをつなぎます。カタログで選択肢を比較し、ゲートウェイと SDK で本番環境に導入できます。料金やプロバイダーの対応状況から選択に伴う違いを把握でき、ゲートウェイのオブザーバビリティからリクエストのルーティング後に起きたことを確認できます。

## AI 支出の増加とともにオープン技術の重要性が高まる

クローズドな最先端モデルが一部の分野をリードしている一方で、オープンソースやオープンウェイトの AI は戦略的に重要になっています。

Stanford の 2026 AI Index は、オープンソース開発が AI への参加を広げていることを示しています。GitHub では、その他の地域からの貢献がヨーロッパを上回り、米国に近づいています。

同時に、オープンウェイトモデルの性能は急速に向上しています。[Artificial Analysis](https://artificialanalysis.ai/models/open-source) などのサービスでは、品質、速度、コンテキストウィンドウ、パラメーター数、ライセンスに基づいてオープンモデルを確認できます。

これは本番環境で重要です。

オープン技術を使うことで、どこで処理を実行するか、データをどう扱うか、長期的なコストをどう組み立てるかについて、チームの選択肢が広がります。また、製品が一社のモデル、料金、ポリシー、利用可否に強く依存するリスクも抑えられます。

状況によっては、クローズドなホスト型モデルが最適です。別の状況では、オープンウェイトモデル、セルフホスト、または複数の方法を組み合わせたルーティングが適しています。

**Phaseo はそのような混在環境を想定しています。**オープン、クローズド、ホスト型、セルフホスト型のモデルを別々の世界や専用ツールとして扱うのではなく、チームが組み合わせて使える選択肢として扱います。

チームが「最新のホスト型最先端モデルを使う」か「すべての層を自分たちで管理する」かの二択を迫られるべきではありません。多くの本番システムはその中間に位置し、時間とともに複数のプロバイダー、モデルファミリー、デプロイ方法を使うようになります。

**Phaseo はその中間を管理しやすくします。**比較、ルーティング、料金、オブザーバビリティを一つのワークフローにまとめます。

## Phaseo がモデル選びを支援する方法

**Phaseo はモデル情報と実行時のツールを一つの製品にまとめます。**

**Phaseo を使うと、チームは次のことができます。**

- モデル、プロバイダー、リリース、ステータス、メタデータを検索する
- モデルやプロバイダーのページで、利用可否、料金、ライフサイクルの状態、ルーティング方法を確認する
- OpenAI 互換の方法やプロバイダー固有の方法でリクエストをルーティングする
- SDK やサンプルを使ってゲートウェイと連携する
- トラフィックが増える前にプロバイダーとルートの料金を比較する
- モデルのリリース、プロバイダーの変更、SDK のリリース、製品の改善を追う
- 本番環境でのゲートウェイの挙動を理解する

モデルの切り替えは、運用上の判断であるべきで、書き直しではありません。

プロバイダーが料金を変更した場合、モデルが終了した場合、より優れたオープンウェイトモデルが登場した場合、または低レイテンシのルートへ移行する必要がある場合でも、選択肢を調べ、判断を下し、周辺のアプリケーションを安定させたまま切り替えられるべきです。

## Phaseo への移行で変わること

公開製品、ドキュメント、SDK のサンプル、製品の文章表現は Phaseo ブランドへ移行しています。

変更点は次のとおりです。

- メインサイトが `phaseo.app` に移行します
- ドキュメント、SDK の案内、変更履歴、製品内の文章に Phaseo の名称を使います
- 新しい開発者向けサンプルでは `PHASEO_*` を使います
- 新たに発行される API キーには `phaseo_v1_sk_` の接頭辞が付きます
- ローカル、プレビュー、本番環境のビルドで異なるファビコンを使い、テスト中の環境をすぐに見分けられるようにします

今回の変更では新しい名称をそのまま使います。新規プロジェクトでは Phaseo の名称を使ってください。既存のデプロイで環境変数の名前を一斉に変更する必要はありません。準備ができるまで現在の名前を維持し、値だけを更新できます。

## API キーについて開発者が知っておくこと

移行中も既存の API キーは引き続き使えます。ブランド名が変わったからといって、現在動作しているキーをすぐにローテーションする必要はありません。

移行後に新しく発行される API キーには Phaseo の接頭辞が付きます。

```bash
PHASEO_API_KEY=phaseo_v1_sk_...
PHASEO_BASE_URL=https://api.phaseo.app/v1
```

旧形式の `aistats` API キーは 6 か月の移行期間中も有効で、**2027 年 1 月 1 日**に利用できなくなる予定です。それまでに Phaseo の接頭辞が付いた新しいキーを作成し、ご自身のスケジュールに合わせてデプロイ環境で置き換えてください。

SDK のサンプル、Webhook 検証のコード例、CLI の設定、管理キーの例は Phaseo の名称に更新されています。変更を減らしたい場合は、アプリケーション内で現在の環境変数名を使い続けることもできます。新しいプロジェクト向けのサンプルでは `PHASEO_*` を使い、現在の命名で始められるようにしています。

ローカルまたはプレビュー環境でビルドを実行する場合、ファビコンは環境ごとに変わります。

- ローカル開発では開発用ファビコンを表示
- Vercel のプレビュー環境ではプレビュー用ファビコンを表示
- 本番環境では本番用ファビコンを表示

テスト中にローカルビルド、プレビュー環境、公開中のサイトを取り違えにくくなります。

## メインサイトは phaseo.app へ移行します

今後、製品、ドキュメント、ブログ、モデル検索はこのサイトを公式の拠点とします。移行に伴って旧 AI Stats のリンクも処理しますが、新しいリンクは Phaseo を参照してください。

## 製品の目標は変わりません

Phaseo はこれからも、わかりやすいモデル情報、実用的なゲートウェイツール、プロバイダーの可視化、透明性の高い料金、SDK、AI 製品の判断を明確にするワークフローに取り組みます。

名前が変わるのは、製品が成長したからです。

その背景にあるニーズも、より明確になっています。AI チームには移植性、コストの把握、オープン技術の選択肢、市場の変化に合わせてモデルを切り替える方法が必要です。

今回の名称変更で、ブランドが製品に追いつきます。
