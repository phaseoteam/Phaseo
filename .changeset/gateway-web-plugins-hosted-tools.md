Add the `web` and `web-fetch` plugins: `plugins: [{ "id": "web" }]` gives any model web search and `{ "id": "web-fetch" }` page fetching, running exactly as the `phaseo:web_search` and `phaseo:web_fetch` server tools do, including how searches and fetches are counted and billed. The web plugin accepts `engine`, `max_results`, `max_uses`, `search_context_size`, `include_domains` and `exclude_domains`; the web-fetch plugin accepts `engine`, `max_uses`, `max_content_tokens`, `allowed_domains` and `blocked_domains`. Invalid option values return 400 `invalid_gateway_plugin_config`; other plugin ids still return 400 `unknown_gateway_plugin`.

OpenAI hosted tools are no longer sent to providers that cannot run them. OpenAI's `web_search` / `web_search_preview` tool runs natively on OpenAI, Azure OpenAI (Responses) and xAI, and as `phaseo:web_search` on every other model, including with `require_parameters`. `phaseo:web_search` with `engine: "native"`, and the web plugin with that engine, are routed the same way on Chat Completions and Responses: to providers with their own web search, or to our search when the model has none. Chat Completions requests that carry it on OpenAI now go to OpenAI's Responses API, which defines it. Other hosted tools (`file_search`, `code_interpreter`, `computer_use_preview`, `mcp`, `image_generation`, `shell`, `local_shell`, `apply_patch`) route only to providers that run them, and fail with 400 `unsupported_hosted_tool` naming the tool when none can.

Responses input items such as `shell_call`, `apply_patch_call`, `local_shell_call`, `computer_call`, their outputs, `mcp_*`, `compaction`, `item_reference` and hosted `*_call` items are now passed to OpenAI unchanged and in place, so tool loops keep their history. On other providers they are removed and reported in `X-Phaseo-Dropped-Params` and `meta.routing.dropped_params` as `input.<type>`.
