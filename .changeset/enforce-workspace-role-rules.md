Enforce workspace role rules in the database and the control API, not only in Settings. Only the owner changes roles, makes someone an admin (directly, through an invite's role, a directory override or a group mapping), removes other members, deletes the workspace, manages SCIM provisioning and its tokens, or deletes a department that group mappings use; anyone can leave. SCIM requests are accepted only with a token the current owner created, so tokens an admin or a previous owner created stop working until the owner creates a new one. Admins can still change members' departments without touching role overrides. People join only through an invite and an approved join request. A management key now acts with its creator's current role. Turning on or changing auto top-up through the API needs `billing:write`, is refused for apps that use Sign in with Phaseo, and no longer accepts the two-factor bypass. An enabled identity provider can be connected to one workspace only. Accepting an invite and approving the join request work again, including through the management API. A role the owner set for a member is no longer reset by SCIM group changes, and each SCIM group create, update or replace is applied in one transaction. SCIM Group PATCH now removes every member for a `remove` on `members` without a value, accepts attribute names in any case, and applies every attribute of a request without a path, such as a new name together with new members. Read-only attributes a client sends back (`id`, `meta`, `schemas`) are ignored.
